“Retrieve MSI Product Codes and Upgrade Codes Programmatically and via Tools”

Extracting the unique identifiers, such as the Product Code (often referred to as IdentifyingNumber in WMI) and the Upgrade Code, for installed Microsoft Installer (MSI) packages is a frequent requirement in system administration and deployment scripting. If you are looking for the Upgrade Code specifically, referencing methods that directly query installed product data is generally more reliable than inspecting cached MSI files, especially when installation transforms might have altered properties.

What are the fastest and safest ways to retrieve the MSI Product Code for currently installed software on a Windows system?

Several distinct approaches exist, ranging from native command-line utilities to specialized scripts and graphical interfaces.

Four Approaches for Swiftly Obtaining MSI Product Codes

1. Employing PowerShell for WMI Queries

A straightforward method involves leveraging Windows Management Instrumentation (WMI) via PowerShell.

Initial PowerShell One-Liner (WMI)

This command lists the identifying number (Product Code), name, and the path to the local cached MSI package:

Get-WmiObject Win32_Product | Sort-Object -Property Name | Format-Table IdentifyingNumber, Name, LocalPackage -AutoSize

Note on WMI Risk: Direct querying of Win32_Product is known to trigger a validation of the entire package estate. This process can be slow and, in rare instances, might initiate an MSI self-repair sequence for an installed application, which could interrupt workflow or cause unexpected delays.

Faster COM-Based PowerShell Alternative

A more performant option bypasses WMI by interacting directly with the Windows Installer COM object, reducing the risk associated with Win32_Product:

$Installer = New-Object -ComObject WindowsInstaller.Installer; 
$InstallerProducts = $Installer.ProductsEx("", "", 7); 
$InstalledProducts = ForEach($Product in $InstallerProducts){
    [PSCustomObject]@{
        ProductCode = $Product.ProductCode()
        LocalPackage = $Product.InstallProperty("LocalPackage")
        VersionString = $Product.InstallProperty("VersionString")
        ProductName = $Product.InstallProperty("ProductName")
    }
}
$InstalledProducts

Pro-Tip: Changing the flag 7 to 3 in $Installer.ProductsEx("", "", 3) targets per-user installations instead of machine-wide installations.

Remote Retrieval via WMI

For administration across a network, you can target a remote machine, provided firewall rules and permissions allow WMI communication:

Get-WmiObject Win32_Product -ComputerName "RemoteMachineName" | Format-Table IdentifyingNumber, Name, LocalPackage -AutoSize

Remote WMI connections are subject to restrictions imposed by the Windows Firewall and DCOM settings. Configuration adjustments, sometimes involving registry tweaks to suppress UAC prompts on workgroup environments, may be necessary for success Connecting to WMI Remotely with PowerShell .

2. VBScript Access via MSI COM API (Faster and Safer)

VBScript utilizing the WindowsInstaller.Installer COM object provides a speed advantage over the WMI approach and avoids triggering MSI self-repairs. This method is effective for generating detailed reports, including the Upgrade Code if the script is adapted.

Here is a streamlined VBScript example that outputs key information to a CSV file named msiinfo.csv in the script’s execution directory:

' Retrieve all ProductCodes (with ProductName and ProductVersion)
Set fso = CreateObject("Scripting.FileSystemObject")
Set output = fso.CreateTextFile("msiinfo.csv", True, True)
Set installer = CreateObject("WindowsInstaller.Installer")

On Error Resume Next ' Ignore potential errors during enumeration

output.writeline "ProductCode,ProductName,ProductVersion"

For Each product In installer.ProductsEx("", "", 7)
   productcode = product.ProductCode
   name = product.InstallProperty("ProductName")
   version= product.InstallProperty("VersionString")
   output.writeline (productcode & ", " & name & ", " & version)
Next

output.Close
' Optional: Alert user completion (remove if running silently)
WScript.Echo "Data written to msiinfo.csv"

This output file (msiinfo.csv) can then be easily opened in a spreadsheet application, where you can reliably sort and search the installed products.

3. Registry Inspection

Some administrators prefer direct access to the registry hives where installation information is stored. While direct, this method is often discouraged over using official APIs because it might miss edge cases or newly registered entries not yet fully propagated.

Check these locations:

  • HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall
  • HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall (for 32-bit apps on 64-bit OS)
  • HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall (for per-user installs)

A PowerShell example filtering by display name using registry lookups:

$filter = "*core*sdk*"; 
(Get-ChildItem HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall).Name | 
    ForEach-Object { $path = "Registry::$_"; Get-ItemProperty $path } | 
    Where-Object { $_.DisplayName -like $filter } | 
    Select-Object -Property DisplayName, PsChildName

In this context, PsChildName often corresponds to the Product Code GUID.

4. Inspecting the Original MSI File or Using Dedicated Tools

If the product is not installed, or if you need to verify the original source data, the Product Code is embedded within the MSI file itself in the Property table.

Tools Required: You need an MSI editor or viewer, such as Orca (part of the Windows SDK) or the simpler SuperOrca.

  1. Locate the cached MSI file (e.g., in C:\WINDOWS\Installer\ with a hexadecimal name).
  2. Open the file using the chosen tool.
  3. Navigate to the Property table.
  4. Search for the row labeled ProductCode.

Security Note: Always scan downloaded tools like SuperOrca using services like VirusTotal before execution.

Utilizing the Found Product Code for Uninstallation

Once a Product Code (GUID) is identified, the standard way to manage the installation via the command line is using msiexec.exe from an elevated command prompt.

Basic Interactive Uninstall:

msiexec.exe /x {YOUR-PRODUCT-CODE-GUID}

Silent Uninstall with Verbose Logging (Ideal for Scripts):

This command executes silently (/QN) and generates a detailed log file (/L*V), suppressing any automatic reboot:

msiexec.exe /x {YOUR-PRODUCT-CODE-GUID} /QN /L*V "C:\UninstallLog.log" REBOOT=ReallySuppress

Retrieving Associated MSI Properties (e.g., Upgrade Code)

If the UpgradeCode is required for an installed package, the most dependable method involves programmatic retrieval via the Installer COM interface, as manually inspecting the cached MSI file can sometimes yield an overridden value if transforms were applied during the original installation. The VBScript method shown in section 2, or the improved PowerShell COM method in section 1, can be adapted to fetch properties beyond the basic code and version. For deeper property viewing, specialized GUI tools are highly effective.

Recommended GUI Tool for Exploration:

The Product Browser tool, reportedly available on GitHub, offers a user-friendly interface to navigate installed application details, often making it simple to locate GUIDs without scripting.

If you seek a dedicated utility focused purely on MSI management, MSI Finder allows searching by name or GUID and offers built-in repair or uninstall capabilities.

FAQs on Locating Installation Identifiers

Q: How do I find the Upgrade Code of an installed MSI package

ANS: For installed packages, the most reliable way to find the Upgrade Code is programmatically using the Windows Installer COM API via methods like the VBScript or the refined PowerShell COM example provided, which query the live system state rather than the cached MSI file.

Q: What is the risk associated with using Get-WmiObject Win32_Product

ANS: The primary risk is that querying Win32_Product forces Windows Installer to validate the integrity of all installed packages, which can be slow and might unintentionally trigger a self-repair sequence for complex applications.

Q: What command should I use to silently uninstall an application using its Product Code

ANS: Use the msiexec.exe /x {PRODUCT-CODE} /QN command in an elevated prompt. For better diagnostics, include verbose logging: msiexec.exe /x {PRODUCT-CODE} /QN /L*V "C:\LogFile.log" REBOOT=ReallySuppress.

Q: Where does PowerShell store the Product Code information when using WMI

ANS: In WMI queries against Win32_Product, the MSI Product Code is reported under the property name IdentifyingNumber.
