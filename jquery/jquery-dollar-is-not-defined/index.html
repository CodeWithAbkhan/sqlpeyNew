Solved: How to Fix jQuery ‘$ is not defined’ Error

Encountering the dreaded jQuery is not defined or $ is not defined error can halt your front-end development in its tracks. This common JavaScript issue typically arises when your code attempts to use jQuery functions before the library has been successfully loaded and initialized on your web page.

This comprehensive guide explores various causes and provides practical solutions to ensure your jQuery code runs smoothly.

Common Causes and Solutions

The root of this error can be traced to a few primary culprits:

  • Improper Script Loading: Your JavaScript file containing jQuery code isn’t being correctly included in your HTML document.
  • Corrupted jQuery File: The jQuery library itself might be corrupted, or an incorrect version is being used.
  • Execution Order Issues: JavaScript code that relies on jQuery is being executed before jQuery has fully loaded.
  • Namespace Collisions: Other JavaScript libraries might be interfering with jQuery’s $ alias.
  • Typos and Incorrect Paths: Simple mistakes in script tags or file paths can prevent jQuery from loading.

Let’s delve into specific strategies to tackle these issues.

Solution 1: Verify jQuery Script Inclusion

Ensure that the jQuery script is properly referenced in your HTML, preferably within the <head> section or just before your custom scripts.

Correct Inclusion:

<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.6.0/jquery.min.js" type="text/javascript"></script>
  • Avoid async or defer: For jQuery itself, avoid using async or defer attributes on the script tag, as these can alter the loading and execution order.
  • Check Network Tab: Use your browser’s developer tools (e.g., Firebug’s Net panel or Chrome DevTools Network tab) to confirm the jQuery file is loading successfully. A “404 Not Found” error indicates a path issue.

Solution 2: Ensure Correct Script Execution Order

Your custom JavaScript code that uses jQuery must execute after the jQuery library has loaded.

Recommended Structure:

<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.6.0/jquery.min.js" type="text/javascript"></script>
<script type="text/javascript">
$(document).ready(function () {
  // Your jQuery code here
  console.log('jQuery is ready!');
});
</script>
  • $(document).ready(): Wrap your jQuery code within $(document).ready() or its shorthand $(function() { ... });. This ensures your code runs only after the Document Object Model (DOM) is fully loaded.

Solution 3: Load jQuery Before Plugins and Custom Scripts

If you’re using jQuery plugins, always load the main jQuery library before any plugins that depend on it, and then load your custom scripts last.

Correct Sequence:

<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.6.0/jquery.min.js" type="text/javascript"></script>
<script src="path/to/your/plugin.js" type="text/javascript"></script>
<script type="text/javascript">
$(document).ready(function() {
  // Your code using jQuery and plugins
});
</script>

Solution 4: Utilize window.onload for Deferred Execution

If your scripts are placed at the end of the <body> and might execute before all page assets are loaded, window.onload is a robust alternative.

window.onload = function() {
  // Your jQuery code here
  // This will run only after the entire page, including all assets, has loaded.
  $('.some-element').css('color', 'blue');
};

  • Decorator Pattern: To avoid overwriting existing window.onload logic, you can decorate it:

    var originalOnload = window.onload;
window.onload = function() {
  if (originalOnload) {
    originalOnload();
  }
  // Your jQuery code here
};

Solution 5: Use jQuery.noConflict() for Namespace Collisions

If you’re using other JavaScript libraries that also utilize the $ symbol, you can reclaim it for jQuery.

// Store jQuery in a new variable, $j
var $j = jQuery.noConflict();

// Use $j instead of $ for your jQuery code
$j(document).ready(function() {
  $j('button').click(function() {
    alert('Button clicked using $j!');
  });
});

Solution 6: Check for Typos in Script Tags

A simple typo in type="text/javascript" can prevent script execution.

Incorrect: type="text/javacsript" Correct: type="text/javascript"

Solution 7: Verify jQuery Library Source

Ensure you are referencing the actual jQuery library and not a plugin like jQuery UI.

Incorrect Reference (jQuery UI):

<script src="http://ajax.googleapis.com/ajax/libs/jqueryui/1.10.0/jquery-ui.min.js"></script>

Correct Reference (jQuery Core):

<script src="http://ajax.googleapis.com/ajax/libs/jquery/1.10.0/jquery.min.js"></script>

Solution 8: Explicitly Define $ in Specific Environments

In certain frameworks or build processes (like Create React App without ejecting), you might need to explicitly provide jQuery.

Using craco.config.js (for React Apps):

Install craco:

npm install @craco/craco --save

Modify package.json scripts:

"scripts": {
  "start": "craco start",
  "build": "craco build",
  "test": "craco test"
}

Create craco.config.js in your project root:

const webpack = require('webpack');

module.exports = {
  webpack: {
    plugins: [
      new webpack.ProvidePlugin({
        $: 'jquery',
        jQuery: 'jquery',
      }),
    ],
  },
};

This makes jQuery globally available.

Solution 9: The $ Alias Method

A quick fix for some scenarios involves directly assigning jQuery to the $ variable.

<script>
$=jQuery;
</script>
<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.6.0/jquery.min.js"></script>
<script>
$(document).ready(function() {
  console.log('Directly assigned $ works!');
});
</script>

Solution 10: Using DOMContentLoaded

An alternative to $(document).ready() that works natively in browsers.

document.addEventListener('DOMContentLoaded', function() {
  // Your jQuery code here, ensure jQuery is loaded before this.
  console.log('DOMContentLoaded event fired.');
});

For this to work with jQuery, ensure jQuery is loaded beforehand.

Solution 11: Ensure HTTPS/HTTP Consistency

If you’re loading jQuery from a CDN, ensure the protocol matches your page’s protocol. Loading an HTTP resource on an HTTPS page might be blocked.

Correct: If your page is HTTPS, use the HTTPS CDN link for jQuery.

Solution 12: File Corruption Check

In rare cases, the jQuery file itself might become corrupted. Replacing it with a fresh copy from a reliable source can resolve the issue.

Solution 13: Folder Permissions and Paths

Ensure that your web server or local development environment has the correct permissions to access the folders containing your JavaScript files. Also, double-check that the src path in your <script> tag accurately points to the jQuery file’s location.

Solution 14: Master Page Script Placement (ASP.NET MVC)

In ASP.NET MVC projects using master pages, the placement of the jQuery script reference relative to ContentPlaceHolders is crucial. Ensure jQuery is loaded before any Header content placeholders that might execute client-side scripts.

Correct Master Page Structure:

<head runat="server">
    <script src="~/Scripts/jquery-3.6.0.min.js" type="text/javascript"></script>
    <asp:ContentPlaceHolder ID="Header" runat="server"></asp:ContentPlaceHolder>
</head>

Solution 15: Bundling and Rendering Scripts (ASP.NET MVC)

Leverage script bundling in ASP.NET MVC to manage script order and dependencies effectively. Define your bundles in BundleConfig.cs and render them in your master layout.

Example _Layout.cshtml:

<!DOCTYPE html>
<html>
<head>
    <title>My Page</title>
    @Styles.Render("~/Content/css")
</head>
<body>
    @RenderBody()

    @Scripts.Render("~/bundles/jquery")
    @Scripts.Render("~/bundles/bootstrap")
    @RenderSection("scripts", required: false)
</body>
</html>

Example MyView.cshtml:

@section Scripts {
    @Scripts.Render("~/bundles/myCustomBundle")
    <script type="text/javascript">
        $(document).ready(function() {
            // Custom view-specific jQuery code
        });
    </script>
}

When rendering sections, ensure that jQuery is bundled and rendered before your custom script sections.

Solution 16: Restarting Development Server and Browser

Sometimes, transient issues with local development servers or browser caching can cause unexpected behavior. Restarting your development server and clearing your browser cache can resolve these issues.

Solution 17: CDN Protocol Mismatch

If you’re using a Content Delivery Network (CDN) for jQuery, ensure the protocol (HTTP vs. HTTPS) matches your website. Loading an insecure resource on a secure page will likely fail.

Solution 18: Moving Script Tags to the <head>

While placing scripts at the end of the <body> is often recommended for performance, in some cases, especially during initial setup or with specific frameworks, moving the jQuery script tag to the <head> section can resolve loading order conflicts.

Solution 19: Using Url.Content or ResolveUrl in ASP.NET

When referencing local jQuery files in ASP.NET, use Url.Content or ResolveUrl to ensure correct path resolution.

Example:

<script src="<%= Url.Content("~/Scripts/jquery-3.6.0.min.js") %>" type="text/javascript"></script>

Solution 20: The webpack.ProvidePlugin Approach

For modern JavaScript build tools like Webpack, ProvidePlugin can inject jQuery globally, making it available without explicit imports in every file. This is particularly useful in projects managed with tools like Create React App, Next.js, or Vue CLI, especially when using configurations like craco or react-app-rewired to customize Webpack.

FAQs on Solved How to Fix jQuery is not defined Error

Q: What is the most common reason for the '$ is not defined' error in jQuery

ANS: The most common reason is that your JavaScript code is trying to use the $ symbol (which is an alias for jQuery) before the jQuery library itself has been fully loaded and processed by the browser. This often happens when the script tag referencing jQuery is placed after your custom script, or if there’s an issue with the script’s path or loading mechanism.

Q: Should I place jQuery script tags in the head or the body

ANS: While placing scripts in the <head> ensures they are available early, it can block page rendering. Best practice is often to place script tags just before the closing </body> tag. However, for jQuery, placing it in the <head> or very early in the <body> and then using $(document).ready() is generally recommended to avoid the “not defined” error for subsequent scripts that depend on it.

Q: How can I ensure my jQuery code runs after the page loads

ANS: Wrap your jQuery code within $(document).ready(function() { ... }); or its shorthand $(function() { ... });. This ensures the code executes only after the DOM is fully parsed and ready. For even later execution, window.onload can be used, which waits for all page assets (images, stylesheets) to load.

Q: What if I use other JavaScript libraries that also use the '$' symbol

ANS: You can use jQuery.noConflict() to prevent conflicts. This method releases the $ alias, allowing you to use jQuery directly or assign a different alias to it, like var $j = jQuery.noConflict();.

Q: How can I check if jQuery is loaded correctly

ANS: Open your browser’s developer console. If jQuery is loaded, typing $ or jQuery into the console should reveal its version or a function definition. If you get an error, it indicates it’s not loaded or defined. You can also check the “Network” tab in your developer tools to see if the jQuery script file successfully loaded without a 404 error.
