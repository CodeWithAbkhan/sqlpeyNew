Fixing Uncaught ReferenceError $ is not defined in JavaScript

“Fixing Uncaught ReferenceError $ is not defined in JavaScript”

The prevalent Uncaught ReferenceError: $ is not defined in JavaScript typically arises when your code attempts to use the jQuery library’s shorthand ($) before the library itself has been loaded into the browser. This is fundamentally an issue of script execution order and proper inclusion. Your custom scripts, which rely on jQuery, are running before the browser has a chance to download and parse the jQuery library.

This error can be frustrating, especially when developing dynamic web pages that leverage the power and convenience of jQuery for DOM manipulation, event handling, and AJAX requests. Understanding the root cause is the first step towards a swift resolution.

Common Scenarios and Solutions

Several factors can lead to this error, and multiple effective strategies exist to address it.

How to Resolve ‘Uncaught ReferenceError: $ is not defined’

The primary solutions revolve around ensuring the jQuery library is loaded before any scripts that depend on it.

Solution 1: Correct Script Placement

Ensure your jQuery script references are placed before any custom JavaScript files or inline scripts that utilize the $ or jQuery object.

<!-- Include jQuery first -->
<script src="/js/jquery-1.2.6.min.js"></script>
<script src="/js/jquery-ui-personalized-1.5.2.packed.js"></script>
<!-- Then include your custom script -->
<script src="/js/sprinkle.js"></script>

Solution 2: Reference jQuery Before Calling Ready Functions

You might be invoking jQuery’s ready() function (or its shorthand $(function() { ... });) before the jQuery JavaScript file is even referenced. Always make sure the jQuery library is loaded first.

Solution 3: Using Full Protocol for CDNs

When using Content Delivery Networks (CDNs) for jQuery, ensure you include the protocol (http: or https:) in the src attribute, especially if your page is served over HTTPS. Browsers might block mixed content requests.

Original (Potentially problematic):

<script src="//ajax.googleapis.com/ajax/libs/jquery/1.9.1/jquery.min.js"></script>

Improved (with protocol):

<script src="http://ajax.googleapis.com/ajax/libs/jquery/1.9.1/jquery.min.js"></script>
<!-- Or preferably, for HTTPS pages -->
<script src="https://ajax.googleapis.com/ajax/libs/jquery/1.9.1/jquery.min.js"></script>

Solution 4: Order of Plugin and Custom Scripts

If you’re using jQuery plugins, always load the core jQuery library first, followed by the plugin files, and then your custom scripts that utilize both.

<!-- jQuery library -->
<script src="//ajax.googleapis.com/ajax/libs/jquery/1.9.1/jquery.min.js"></script>
<!-- Your custom script -->
<script src="js/custom.js"></script>

Solution 5: Local Hosting vs. CDN

If you encounter issues with CDNs (e.g., network connectivity problems, SSL mismatches), consider downloading jQuery from jquery.com/download/ and hosting it locally on your server.

<!-- Locally hosted jQuery -->
<script src="http://code.jquery.com/jquery-1.10.2.js"></script>
<!-- Other libraries -->
<script src="http://code.jquery.com/ui/1.11.2/jquery-ui.js"></script>
<script src="http://maxcdn.bootstrapcdn.com/bootstrap/3.2.0/js/bootstrap.min.js"></script>
<!-- Your custom script -->
<script src="exponential.js"></script>

Solution 6: Using CDN Links Effectively

You can utilize various CDN providers. Here are examples for Google and Microsoft:

Google CDN:

<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.2.1/jquery.min.js"></script>

Microsoft CDN:

<script src="https://ajax.aspnetcdn.com/ajax/jQuery/jquery-3.2.1.min.js"></script>

After including the CDN link, your script execution should follow:

$(function(){
    // your stuff
});
// or
$(document).ready(function(){
    // your stuff
});

For WordPress environments, you might need to alias jQuery:

var $ = jQuery;
jQuery(document).ready(function($){
     // your stuff
});

Solution 7: Addressing Document Security Models (Chrome/HTTPS)

When accessing content over HTTPS, ensure that any scripts loaded from CDNs also use https://. Mismatched protocols can cause security warnings or prevent scripts from loading.

<!-- Ensure all CDNs use HTTPS -->
<script src="https://ajax.googleapis.com/ajax/libs/jquery/1.11.2/jquery.min.js"></script>
<!-- your other scripts -->

Solution 8: ASP.NET MVC Script Rendering

In ASP.NET MVC projects, you can control script rendering order using @section directives. Place your custom JavaScript within a scripts section in your view and render that section at the end of your _Layout.cshtml file, after the jQuery reference.

In your View (.cshtml):

@section scripts {
    <script>
        // Your JavaScript code...
    </script>
}

In your _Layout.cshtml:

@RenderSection("Scripts", required: false)

Solution 9: Script Placement in the Body

Consider moving script references from the <head> to the end of the <body> tag. This ensures the HTML document is fully parsed before your JavaScript executes.

<body>
    <!-- Your HTML content -->

    <script src="http://code.jquery.com/jquery-1.11.0.min.js"></script>
    <script>
    /*global $ */
    $(document).ready(function(){
        // your code
    });
    </script>
</body>

Solution 10: WordPress Specifics

In WordPress, if you’re encountering issues with the $ alias, use jQuery directly or define the alias correctly within the document ready function.

// Using jQuery directly
jQuery(document).ready(function() {
    // your code
});

// Or using the alias within the ready function
jQuery(document).ready(function($){
    // your code using $
});

// If needed, define the alias explicitly
var $ = jQuery;
$(document).ready(function() {
    // your code
});

Solution 11: CSS and JS File Order

While less common for this specific error, sometimes the order of linking CSS and JS files can indirectly influence script execution. Ensure your CSS links are also correctly placed.

Solution 12: Fixing Reference Errors Due to Order

If your custom script runs before jQuery, the $ will be undefined. Correct this by ensuring jQuery is loaded first.

<!-- Incorrect order -->
<script src="js/index.js"></script>
<script src="js/jquery-1.10.2.js"></script>

<!-- Correct order -->
<script src="js/jquery-1.10.2.js"></script>
<script src="js/index.js"></script>

Solution 13: Asynchronous Loading Considerations

Using the async attribute on script tags can lead to unpredictable loading orders. For scripts that depend on others (like jQuery), avoid async or ensure proper dependency management.

<!-- Avoid async for dependent scripts -->
<script async src="js/script.js"></script>

<!-- Standard loading -->
<script src="js/script.js"></script>

Solution 14: Centralizing Script References

Placing all your script references, especially jQuery, at the top of your HTML or within a dedicated script block at the end of the <body> can prevent order-related issues.

<script src="https://code.jquery.com/jquery-3.3.1.js"></script>
<script src="https://maxcdn.bootstrapcdn.com/bootstrap/4.0.0/js/bootstrap.min.js"></script>
<script src="js/app.js"></script>
<script src="js/form.js"></script>
<script src="js/create.js"></script>
<script src="js/tween.js"></script>

Solution 15: Placing jQuery CDN at the Top

For simple HTML pages, directly embedding the jQuery CDN link at the very top of the <head> section is a straightforward way to ensure it’s available.

<!DOCTYPE html>
<html>
<head>
<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.5.1/jquery.min.js"></script>
<script>
$(document).ready(function(){
  $("button").click(function(){
    $("h2").hide();
  });
});
</script>
</head>
<body>

<h2>This will hide me</h2>
<button>Click me</button>

</body>
</html>

Solution 16: Checking for Typos in src Attribute

A simple typo, like a missing backslash in a file path, can prevent the script from loading correctly. Double-check your src attributes.

Incorrect: src="/scripts/jquery.js" Correct: src="scripts/jquery.js"

Solution 17: Referencing jQuery via CDN

Always ensure a jQuery library reference is present. Using a CDN is a common and efficient method.

<script src="https://ajax.googleapis.com/ajax/libs/jquery/3.1.1/jquery.min.js"></script>

Refer to tutorialrepublic.com/faq/how-to-fix-dollar-is-not-defined-error-in-jquery.php for more insights.

Solution 18: ASP.NET Web.config Permissions

In ASP.NET projects, ensure your web.config file allows anonymous users access to your script directories if necessary.

<location path="Scripts">
  <system.web>
    <authorization>
      <allow users="*"/>
    </authorization>
  </system.web>
</location>

Solution 19: Correct src Path and Execution Timing

Verify the src path for your jQuery file is accurate and that your jQuery commands execute only after the file has loaded.

<script src="/js/jquery-1.2.6.min.js"></script>
<script>
$(document).ready(function() {
    // your code
});
</script>

Solution 20: Including Missing JavaScript Files

Ensure all necessary JavaScript files, including jQuery, are included. Sometimes, a missing jQuery reference is the sole cause.

<!-- Include jQuery if missing -->
<script src="http://ajax.googleapis.com/ajax/libs/jquery/1.9.1/jquery.min.js"></script>
<!-- Your custom script -->
<script src="js/sample.js"></script>
<link href="css/sample.css" rel="stylesheet" type="text/css" />

Solution 21: Parameter Formatting in WebViews (e.g., Android)

When bridging JavaScript and native code (like in Android WebViews), ensure parameters passed to JavaScript functions are correctly formatted, including quotes for strings.

Incorrect: js.sayHello(hello); Correct: js.sayHello('hello');

Solution 22: Three Key Checks

  1. Script Inclusion: Confirm all required jQuery scripts are referenced.
  2. Script Order: Verify jQuery is loaded before your custom scripts.
  3. Syntax Errors: Check your JavaScript for syntax mistakes, including missing dots (.) for class selectors (e.g., $('.js-toggle') instead of $('js-toggle')).

Solution 23: HTTPS vs. HTTP in WordPress

When migrating to production with SSL (HTTPS), ensure your WordPress script registration uses https:// for CDNs, while http:// might suffice for testing environments.

Test (HTTP):

wp_register_script( 'jquery', 'http://ajax.googleapis.com/ajax/libs/jquery/1.11.2/jquery.min.js', array(), null, false );
wp_register_script( 'custom-script', plugins_url( '/js/custom.js', __FILE__ ), array( 'jquery' ) );

Production (HTTPS):

wp_register_script( 'jquery', 'https://ajax.googleapis.com/ajax/libs/jquery/1.11.2/jquery.min.js', array(), null, false );
wp_register_script( 'custom-script', plugins_url( '/js/custom.js', __FILE__ ), array( 'jquery' ) );

Solution 24: Including Core jQuery

If you are using jQuery Mobile or other jQuery-dependent libraries, ensure the core jquery.js file is included separately.

<script src ="jquery-2.1.1.js"></script>

Solution 25: Saving Changes

It sounds basic, but always ensure you’ve saved your code modifications after reordering scripts or changing file paths.

Solution 26: Checking for Mixed Quotes

Ensure consistency in quote usage within your script tags. Mismatched quotes can break the src attribute. Use your browser’s developer tools (Inspect Element) to see how the script is being parsed.

Solution 27: Network Connectivity

For mobile or embedded webviews, a disconnected network can prevent CDN-based jQuery files from loading, leading to this error.

<script src="https://ajax.googleapis.com/ajax/libs/jquery/2.1.4/jquery.min.js"></script>
<script type="text/javascript" src="local_xxx.js"></script>

Solution 28: Missing Closing Tag

A missing closing > on a <link> tag for stylesheets, while seemingly unrelated, could potentially cause parsing issues that affect subsequent script loading.

Solution 29: Laravel Blade File Structure

In Laravel, if you are placing JavaScript within Blade files, ensure it’s properly wrapped within @section directives if you intend to render it in a specific layout section.

@section('scripts')
    {{-- Your JavaScript code --}}
@endsection

FAQs on Fixing ‘Uncaught ReferenceError $ is not defined’

Q Is it always about the order of script tags

ANS: While script order is the most common cause, ensure your jQuery files are correctly linked and haven’t been corrupted during download or transfer. Typos in the src path are also frequent culprits.

Q Can I use jQuery without the dollar sign

ANS: Yes, you can always use jQuery instead of $ to reference the library, which can be helpful if other libraries also use $ as a namespace. For example, jQuery(document).ready(function() { ... });.

Q What if I'm using a JavaScript framework

ANS: Frameworks like React, Vue, or Angular often have their own ways of managing dependencies and DOM manipulation. While you can sometimes integrate jQuery, it’s generally recommended to use the framework’s built-in methods to avoid conflicts and maintain best practices.

Q How does SSL affect jQuery loading

ANS: If your page is loaded over HTTPS, any scripts loaded from CDNs must also use the https:// protocol. Loading HTTP resources on an HTTPS page can trigger mixed content warnings and prevent scripts from executing.

Q Should I put scripts in the head or at the end of the body

ANS: Placing scripts at the end of the <body> tag is often preferred because it ensures the HTML content is fully rendered before the JavaScript executes, preventing the $ not defined error related to DOM availability and improving perceived page load speed.
