Summary

In this article, we’ll explore effective methods for integrating Blazor components into ASP.NET Razor Pages, covering practical examples and configuration tips. This guide includes solutions to address routing issues, code explanations, and a detailed approach for embedding Blazor components seamlessly.

How to Integrate Blazor Components into Razor Pages - Top-5-Ways

Integrating Blazor components into Razor Pages allows you to enhance your application without restructuring existing Razor pages. Here’s a step-by-step guide on achieving seamless integration, addressing common issues, and understanding alternative solutions.

1. Adding the Required Services in Startup.cs

To start, configure the necessary services in the Startup.cs file. This setup enables Blazor support in your Razor Pages app.

public void ConfigureServices(IServiceCollection services)
{
    // Enables cookie policy
    services.Configure<CookiePolicyOptions>(options =>
    {
        options.CheckConsentNeeded = context => true;
    });

    // Adds Razor Pages with Newtonsoft JSON support
    services.AddRazorPages()
            .AddNewtonsoftJson();

    // Enables Server-side Blazor
    services.AddServerSideBlazor();
}

In this code:

  • services.Configure<CookiePolicyOptions>** sets up a cookie policy.
  • services.AddRazorPages() configures Razor Pages with JSON handling.
  • services.AddServerSideBlazor() enables server-side Blazor.

2. Configuring Routing and Endpoints

Next, configure endpoints in Startup.cs to map both Razor Pages and Blazor hubs for routing.

public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    if (env.IsDevelopment())
    {
        app.UseDeveloperExceptionPage();
    }
    else
    {
        app.UseExceptionHandler("/Error");
        app.UseHsts();
    }

    app.UseHttpsRedirection();
    app.UseStaticFiles();
    app.UseCookiePolicy();

    app.UseRouting();
    app.UseAuthorization();

    app.UseEndpoints(endpoints =>
    {
        endpoints.MapRazorPages();
        endpoints.MapBlazorHub(); // Maps the Blazor server hub
    });
}

This setup:

  • Maps Razor Pages and Blazor components to their respective routes.
  • Note: Mapping Blazor components within Razor Pages can lead to routing conflicts.

3. Adding Blazor Components in Razor Pages

To embed a Blazor component like Counter.razor in your Razor Page, follow this example in Index.cshtml:

<a asp-page="./Index">Home</a><br />
<div id="Counter"> 
    @(await Html.RenderComponentAsync<Counter>()) 
</div>
<script src="~/_framework/blazor.server.js"></script>

Explanation:

  • @(await Html.RenderComponentAsync<Counter>()) injects the Counter component.
  • The Blazor script (blazor.server.js) allows client-server communication.

4. Solving Common Routing Issues with Blazor and Razor

Once Blazor components are integrated, routing may encounter issues, with URLs updating without navigating. This issue often arises when Blazor takes control of routing, causing conflicts with Razor Pages.

To resolve:

  1. Verify the Blazor Hub endpoint (endpoints.MapBlazorHub()).
  2. Ensure Razor Pages links use the correct asp-page attributes to avoid being overridden.

5. Alternative Approach: Create a Standalone Blazor App and Embed in Razor Pages

For larger applications, creating a standalone Blazor app and embedding it in Razor Pages can simplify management.

Steps:

  1. Create a Components folder with shared layouts and components.
  2. Add _ViewImports.cshtml in Components and Pages folders for namespace and layout configurations.

Practical Example: Embedding Blazor App in Razor Pages

For a fully integrated Blazor component experience, add Components.cshtml to the Pages folder, which hosts the embedded Blazor app.

@page
@model WebApplication1.Pages.ComponentsModel
@{
    Layout = null;
}
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>WebApplication1 - Components</title>
    <base href="~/" />
</head>
<body>
    <app>@(await Html.RenderComponentAsync<WebApplication1.Components.App>())</app>
    <script src="_framework/components.server.js"></script>
</body>
</html>

In Components.cshtml.cs, include:

using Microsoft.AspNetCore.Mvc.RazorPages;

namespace WebApplication1.Pages
{
    public class ComponentsModel : PageModel
    {
        public void OnGet() { }
    }
}

Alternative Solution for Resharper Users

For Resharper users, adjust inspection severity to reduce error notifications:

  1. Go to Resharper Options > Code Inspection > CSS > Unknown CSS symbol.
  2. Lower the severity to Warning to minimize disruptions.

FAQs on Integrating Blazor Components in Razor Pages

Q: Why do Blazor components override Razor Pages routing?

ANS: Blazor’s SignalR routing interferes with Razor Pages when mapped together, requiring specific configurations to avoid conflicts.

Q: How to fix links not working after adding Blazor?

ANS: Review Startup.cs configurations, ensuring both Razor Pages and Blazor hubs are correctly mapped.

Q: Is there a way to use Blazor without impacting existing Razor Pages?

ANS: Yes, consider embedding Blazor as a standalone app or carefully configure Blazor components in isolated sections.

Q: Can Blazor components work client-side in Razor Pages?

ANS: Yes, but you need RenderComponentAsync to enable prerendering on the server-side in Razor Pages.

Q: How can Resharper users avoid ::deep errors?

ANS: In Resharper settings, reduce severity for CSS unknown symbol inspections to minimize these warnings.
