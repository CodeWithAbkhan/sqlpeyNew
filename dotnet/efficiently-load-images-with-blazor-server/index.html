Top 5 Steps to Efficiently Load Images with Blazor Server

When developing a Blazor Server application, you might encounter scenarios where you need to load images from a remote storage and display them efficiently. This post guides you through a robust approach to handle image loading in Blazor Server, ensuring the application performs smoothly without unnecessary resource usage.

Top 5 Steps to Efficiently Load Images in Blazor Server

1. Utilize OnAfterRenderAsync Wisely

Blazor’s OnAfterRenderAsync lifecycle method allows you to perform tasks after the component has rendered. However, unlike other lifecycle methods, it does not trigger StateHasChanged() automatically. Use the firstRender flag to ensure the image loading logic only runs once during the first render.

protected override async Task OnAfterRenderAsync(bool firstRender)
{
    if (firstRender)
    {
        foreach (var imageSrc in ImageSources)
        {
            using var stream = await Http.GetStreamAsync(imageSrc.Url);
            await SetImage(imageSrc.Id.ToString(), stream);
            imageSrc.Loaded = true;
            StateHasChanged(); // Trigger a re-render to update the UI
        }
    }
}

This approach prevents the endless loop that can occur if StateHasChanged() is called without control, and ensures images are loaded only when necessary.

2. Encapsulate Image Logic into a Separate Component

To make your code modular and reusable, encapsulate the image loading logic into a dedicated Blazor component. This separation of concerns not only improves maintainability but also makes the component easier to test and reuse across different pages.

@inject IJSRuntime JS
@inject IHttpClientFactory ClientFactory

<div>
    <img hidden="@(!_loaded)" id="@_uid" />
    @if (!_loaded)
    {
        <span>Loading...</span>
    }
</div>

@code {
    [Parameter] public string? Url { get; set; }

    private bool _loaded;
    private bool _imageToRender;
    private string _uid = Guid.NewGuid().ToString();
    private Stream? _stream;
    private string? _currentUrl;

    protected async override Task OnParametersSetAsync()
    {
        if (_currentUrl != this.Url)
        {
            _loaded = false;
            using var http = this.ClientFactory.CreateClient();
            _stream = await http.GetStreamAsync(this.Url);
            _loaded = true;
            _currentUrl = this.Url;
            _imageToRender = true;
        }
    }

    protected async override Task OnAfterRenderAsync(bool firstRender)
    {
        if (_imageToRender && _stream is not null)
        {
            var streamRef = new DotNetStreamReference(_stream);
            await JS.InvokeVoidAsync("setImage", _uid, streamRef);
            _stream.Dispose();
            streamRef.Dispose();
            _imageToRender = false;
        }
    }
}

3. Implement Proper Resource Management

Ensure you are disposing of Stream and DotNetStreamReference objects to prevent memory leaks. This is crucial when dealing with resources that require cleanup, like streams.

public async Task SetImage(string imageElementId, Stream imageStream)
{
    using var dotnetImageStream = new DotNetStreamReference(imageStream);
    await JS.InvokeVoidAsync("setImage", imageElementId, dotnetImageStream);
}

By using using statements, the resources are disposed of automatically once they are no longer needed.

4. Optimize Performance with HttpClientFactory

Instead of directly injecting HttpClient, use IHttpClientFactory to create HttpClient instances. This helps in managing the lifetime of HttpClient more effectively and avoids common pitfalls like socket exhaustion.

@inject IHttpClientFactory ClientFactory

// Usage in component
using var http = this.ClientFactory.CreateClient();
_stream = await http.GetStreamAsync(this.Url);

5. Leverage Asynchronous Operations for Smooth User Experience

Blazor rendering is synchronous, but you can perform asynchronous operations within lifecycle methods like OnParametersSetAsync. This ensures that heavy tasks, such as loading images, do not block the UI thread and degrade the user experience.

protected async override Task OnParametersSetAsync()
{
    if (_currentUrl != this.Url)
    {
        _loaded = false;
        using var http = this.ClientFactory.CreateClient();
        _stream = await http.GetStreamAsync(this.Url);
        _loaded = true;
        _currentUrl = this.Url;
        _imageToRender = true;
    }
}

Practical Example Code

Here’s a practical example of a Blazor component that encapsulates image loading logic, with proper resource management and performance optimization:

@page "/images"

@foreach (var imageSrc in ImageSources)
{
    <Image Url="@imageSrc.Url" />
}

@code {
    private List<ImageSource> ImageSources = new(){
        new("https://picsum.photos/200/300"),
        new("https://picsum.photos/200/300"),
        new("https://picsum.photos/200/300"),
        new("https://picsum.photos/200/300")
    };

    public record ImageSource(string Url) { }
}

This example demonstrates how to create a robust and reusable component in a Blazor Server application.

Alternative Ways

Alternatively, you can consider using libraries like MudBlazor for advanced UI components, which handle some of the complex image loading scenarios out-of-the-box. However, writing your own component provides flexibility and a deeper understanding of how Blazor works.

FAQs on “Top 5 Steps to Efficiently Load Images with Blazor Server”

Q: Why is `OnAfterRenderAsync` important for image loading?

ANS: OnAfterRenderAsync is crucial because it allows you to perform actions after the UI has rendered, such as loading images. It ensures the UI is ready before you manipulate DOM elements.

Q: How can I prevent memory leaks when loading images?

ANS: By using using statements with Stream and DotNetStreamReference, you ensure that resources are disposed of properly, preventing memory leaks.

Q: What is the benefit of using `IHttpClientFactory` over `HttpClient`?

ANS: IHttpClientFactory provides better resource management and avoids issues like socket exhaustion, making it a preferred choice in modern .NET applications.

Q: Can I use third-party libraries for image loading?

ANS: Yes, third-party libraries like MudBlazor offer components that simplify image loading, though building your component provides more control.

Q: How does asynchronous code improve Blazor's performance?

ANS: Asynchronous operations prevent the UI from being blocked, ensuring a smoother user experience, especially during tasks like image loading.
