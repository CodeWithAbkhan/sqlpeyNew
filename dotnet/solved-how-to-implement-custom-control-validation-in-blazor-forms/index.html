Solved: How to Implement Custom Control Validation in Blazor Forms

Blazor

In Blazor, form validation is typically carried out using built-in input components like InputText or InputSelect. However, in certain scenarios, you may create custom components that do not use traditional input tags, such as a directory locator or other specialized controls. These custom components can present challenges when trying to integrate them into a Blazor form with validation. This post explains how to implement custom validation for such controls in Blazor forms, even if your control doesn’t use standard input fields.

Summary

Blazor forms are designed to validate user input using standard form elements. However, when working with custom controls, you need to implement validation manually. This tutorial walks you through the process of creating custom components that can be validated in Blazor forms, including overriding the TryParseValueFromString method and using InputBase<T> to integrate validation functionality. The example demonstrates how to create a custom button control that changes its value, with validation to ensure the value isn’t empty when the form is submitted.

What Is the Challenge of Validating Custom Controls in Blazor?

In Blazor, input validation typically relies on the use of EditForm and input components like InputText, which can automatically track changes and trigger validation. However, when you create custom controls that do not utilize the standard HTML input tags, you need a way to integrate them into Blazor’s form validation system.

How do we go about implementing validation for a custom control, such as a directory browser or a toggle button, which does not have the traditional form input fields?

How Can We Enable Custom Controls to Be Validated in a Blazor Form?

To validate custom controls in Blazor forms, you can extend the InputBase<T> class, which is a base class for Blazor’s input components. This class allows you to create your own controls that behave like built-in input components but with custom logic.

Step-by-Step Example of Custom Control Validation

Let’s create a simple custom control, a toggle button that changes its value between empty and non-empty, and implement validation to ensure that it has a value when the form is submitted.

@using System.Diagnostics.CodeAnalysis
@inherits InputBase<string>

<div class="directoryBrowserContainer">
    <button class="btn btn-primary" @onclick=ChangeValue>Change Value</button>
    <div>
        @CurrentValue
    </div>
</div>

@code {
    string newValue = string.Empty;

    // Override TryParseValueFromString to handle validation
    protected override bool TryParseValueFromString(string? value, [MaybeNullWhen(false)] out string result, [NotNullWhen(false)] out string validationErrorMessage)
    {
        result = value;
        var isValid = value != string.Empty;

        // If the value is empty, return an error message
        validationErrorMessage = isValid
            ? string.Empty
            : "Value can't be empty";

        return isValid;
    }

    // Change the value when the button is clicked
    private void ChangeValue()
    {
        if (this.newValue == string.Empty)
            this.newValue = "Hello";
        else
            this.newValue = string.Empty;

        // Update the current value for validation
        this.CurrentValueAsString = newValue;
    }
}
Code Explanation:

  1. Inheriting from InputBase<string>: We inherit from InputBase<string> to create a custom input component that Blazor can treat like any other input. This gives us access to the form validation system.

  2. TryParseValueFromString Method: This method is overridden to handle the conversion of the string input (from CurrentValueAsString) to the appropriate type and to implement validation. We check if the value is empty and return a validation error if it is.

  3. Value Change Logic: The ChangeValue method toggles the newValue between an empty string and "Hello". This simulates user input and updates the control’s value. The CurrentValueAsString property is set to the new value, triggering the validation logic.

  4. Validation Error Message: If the value is empty, the validationErrorMessage is set to "Value can't be empty", and this message will be shown in the form if the control is invalid.

How Does This Integration with the Form Validation Work?

In Blazor, the validation logic is tied to the form’s EditContext. The InputBase<T> class automatically integrates with the Blazor form validation system, so when the form is submitted, any invalid controls will display error messages.

For the custom control to be validated, you simply need to wire up the InputBase class properly and implement the necessary validation logic (like checking for empty values).

Can I Use This Approach for More Complex Custom Controls?

Yes, the approach described here works for more complex custom controls. For example, instead of using a simple string, you can handle more complex data types and even add custom parsing and validation logic for those types.

Alternative Approach for Complex Controls

If you need to manage more complex input or data types, you can replace CurrentValueAsString with a custom property that holds the actual value of your control, and manually implement the logic to parse and validate the value.

@using System.Diagnostics.CodeAnalysis
@inherits InputBase<MyComplexType>

<div class="custom-control">
    <button class="btn btn-primary" @onclick=ChangeValue>Change Value</button>
    <div>
        @CurrentValue.Property
    </div>
</div>

@code {
    private MyComplexType newValue = new MyComplexType();

    // Overriding parsing and validation for a complex data type
    protected override bool TryParseValueFromString(string? value, [MaybeNullWhen(false)] out MyComplexType result, [NotNullWhen(false)] out string validationErrorMessage)
    {
        // Custom parsing logic for MyComplexType
        result = new MyComplexType { Property = value };
        validationErrorMessage = string.IsNullOrEmpty(value)
            ? "Value can't be empty"
            : string.Empty;

        return !string.IsNullOrEmpty(value);
    }

    private void ChangeValue()
    {
        // Toggle complex value
        newValue.Property = string.IsNullOrEmpty(newValue.Property) ? "New Value" : string.Empty;
        this.CurrentValue = newValue;
    }
}

In this example, we handle a complex type (MyComplexType) and implement custom parsing and validation. This allows you to create sophisticated custom controls that work seamlessly with Blazor’s form validation system.

FAQs on Custom Control Validation in Blazor Forms

Q: How do I validate custom controls in Blazor?

ANS: You can validate custom controls by inheriting from the InputBase<T> class and overriding methods like TryParseValueFromString to implement custom validation logic.

Q: Can custom controls be integrated with Blazor’s form validation system?

ANS: Yes, by using InputBase<T> and implementing the necessary validation methods, custom controls can integrate smoothly with Blazor’s form validation system.

Q: How do I handle complex data types in custom controls?

ANS: You can replace CurrentValueAsString with custom properties and handle the parsing and validation logic for complex data types manually.

Q: Can I create non-input custom controls that are validated in Blazor?

ANS: Yes, any custom control, even non-input types, can be validated by extending InputBase<T> and handling validation in the overridden methods.

Q: How do I display error messages for custom controls?

ANS: When validation fails in a custom control, an error message is stored in validationErrorMessage, and this will automatically be shown when the form is submitted if the control is invalid.
