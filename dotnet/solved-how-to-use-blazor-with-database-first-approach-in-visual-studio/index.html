Summary

Building a Blazor app connected to an existing database can seem complex, but it’s straightforward with Entity Framework Core and Visual Studio. This guide will walk you through the process of using Blazor with the Database First approach to connect an existing SQL Server database to a Blazor application. We’ll cover configuring Entity Framework, generating models from an existing database, and provide answers to common questions.

Can I Connect a Blazor App to an Existing Database?

Yes, Blazor applications can connect to existing databases through the Database First approach using Entity Framework Core. This is ideal when you have an established database schema and need to generate models and context classes directly from the database.

Step-by-Step Setup of Blazor with Database First Approach

Step 1: Add Required NuGet Packages

To begin, add the following NuGet packages to your Blazor project. These packages provide the necessary tools for database connectivity and model generation.

<PackageReference Include="Microsoft.AspNetCore.Diagnostics.EntityFrameworkCore" Version="3.1.1" />
<PackageReference Include="Microsoft.AspNetCore.Identity.EntityFrameworkCore" Version="3.1.1" />
<PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" Version="3.1.1" />
<PackageReference Include="Microsoft.EntityFrameworkCore.Tools" Version="3.1.1" />
<PackageReference Include="Microsoft.EntityFrameworkCore.Design" Version="3.1.1" />

Each of these packages serves a role in establishing and managing the connection to SQL Server and generating database models.

Step 2: Define the Database Connection String

Add your database connection string to appsettings.json to specify the server, database, and authentication details.

{
  "ConnectionStrings": {
    "MyConnection": "Server=tcp:<yourServer>,1433;Initial Catalog=<yourDatabase>;Persist Security Info=False;User ID=<yourDatabaseUserName>;Password=<yourDatabaseUserPassword>;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=True;Connection Timeout=30;"
  }
}

Replace <yourServer>, <yourDatabase>, <yourDatabaseUserName>, and <yourDatabaseUserPassword> with your specific database details.

Step 3: Scaffold the Database Context and Models

Use the Package Manager Console to generate the database context and entity models. This step allows Entity Framework Core to create C# classes that map to the tables in your database.

Scaffold-DbContext -Connection name=MyConnection -Provider Microsoft.EntityFrameworkCore.SqlServer -OutputDir Models -Context MyDbContext -Force
  • -Connection name=MyConnection: Refers to the connection string defined in appsettings.json.
  • -Provider Microsoft.EntityFrameworkCore.SqlServer: Specifies SQL Server as the database provider.
  • -OutputDir Models: Creates a folder named Models for your entity classes.
  • -Context MyDbContext: Generates a DbContext class named MyDbContext.
  • -Force: Optional, used if you re-run scaffolding to refresh models after database changes.

Step 4: Reviewing Generated Files

After scaffolding, the Models folder will contain:

  1. MyDbContext.cs: The context class, representing the database connection and access.
  2. <TableName>.cs for each database table: Entity classes mapping to tables.

Example of Generated Context Class

Here’s a breakdown of a typical DbContext generated by scaffolding.

public partial class MyDbContext : DbContext
{
    public MyDbContext(DbContextOptions<MyDbContext> options) : base(options)
    {
    }

    public virtual DbSet<TableName> TableNames { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<TableName>(entity =>
        {
            entity.HasKey(e => e.Id);
            entity.Property(e => e.Name).IsRequired().HasMaxLength(50);
        });
    }
}

Explanation of Key Parts

  • DbContextOptions<MyDbContext>: Configuration options for the database context.
  • DbSet<TableName>: Represents each table in your database.
  • OnModelCreating: Configures specific properties or relationships within each table.

Alternative Way: Using EF Core Power Tools

For an alternative to manual scaffolding, EF Core Power Tools can be used to reverse engineer and generate models with a user-friendly GUI in Visual Studio.

Advantages of EF Core Power Tools

  1. GUI-based approach, with simplified configuration and updating.
  2. Automatically regenerates models if database changes.

Practical Example: Querying Data in Blazor with Database First

Here’s a basic example of using the DbContext to fetch and display data from your existing database in a Blazor component:

@page "/fetch-data"
@inject MyDbContext DbContext

<h3>Database Table Data</h3>
<table class="table">
    <thead>
        <tr>
            <th>ID</th>
            <th>Name</th>
        </tr>
    </thead>
    <tbody>
        @foreach (var item in data)
        {
            <tr>
                <td>@item.Id</td>
                <td>@item.Name</td>
            </tr>
        }
    </tbody>
</table>

@code {
    private List<TableName> data;

    protected override async Task OnInitializedAsync()
    {
        data = await DbContext.TableNames.ToListAsync();
    }
}

Explanation of Example Code

  • @inject MyDbContext DbContext: Injects the database context into the component.
  • data = await DbContext.TableNames.ToListAsync(): Fetches all rows in TableNames.
  • @foreach (var item in data): Renders each row in the table.

FAQs on Using Blazor with Database First

Q: Can I connect Blazor to multiple databases?

ANS: Yes, multiple DbContext instances can be set up to connect to different databases, each with its own connection string.

Q: Is the Database First approach ideal for Blazor?

ANS: Database First is effective when you have an existing database structure; otherwise, Code First is often preferred for flexible database design.

Q: Can EF Core Power Tools update models if the database changes?

ANS: Yes, EF Core Power Tools make it easy to refresh models as the database structure evolves.

Q: Is Database First approach only for SQL Server?

ANS: No, Database First works with any EF Core-supported database, such as MySQL, PostgreSQL, etc.

Q: How do I secure the database connection string?

ANS: Use environment variables or Azure Key Vault to securely store connection strings, avoiding exposure in source code.
