In this post, we will address a common issue faced while using CodeMirror in a Blazor App, particularly related to data binding between the CodeMirror editor and a C# field. If you’ve encountered difficulties with the editor not updating the bound data, follow these steps to ensure the proper integration of CodeMirror and Blazor using JavaScript Interop.

We’ll cover how to:

  • Set up the CodeMirror editor in a Blazor app.
  • Correctly bind data from CodeMirror back to C#.
  • Handle JavaScript Interop to reflect changes in the editor to the C# field.

Let’s dive into the solution with an example and detailed explanation of the process.

How Does CodeMirror Work with Blazor?

Blazor provides powerful data binding capabilities, but it doesn’t automatically detect changes made in JavaScript-based editors like CodeMirror. When you use CodeMirror in your Blazor Server application, you need to establish JavaScript Interop to communicate between the Blazor component and the JavaScript editor.

Initial Setup

In this example, we are using Blazor Server to create a simple app where a CodeMirror editor is integrated into a Blazor page. Below are the steps for setting up the editor and ensuring proper data binding.

  1. _Host.cshtml file:

    The _Host.cshtml file is responsible for loading the necessary JavaScript and CSS files for CodeMirror and setting up the initial editor.

    @page "/"
@namespace BlazorApp1.Pages
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

    Layout = null;

  2. Blazor Page Setup:

    In the Blazor Page, we define a textarea for the CodeMirror editor and bind it to a C# property. We use the @bind directive to establish a two-way data binding between the textarea and the C# field.

    @page "/"
@inject IJSRuntime JSRuntime;

<h1>Hello, world!</h1>
<textarea id="codearea" rows="20" @bind="UserCodeInput" @bind:event="oninput" style="height:100px;"></textarea>

<SurveyPrompt Title="How is Blazor working for you?" />

Input Code: @UserCodeInput

@code{
    public string UserCodeInput { get; set; }

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (firstRender)
        {
            await JSRuntime.InvokeVoidAsync("loadCodeEditor");
        }
    }
}

What Causes the Binding Issue?

In the scenario above, when the CodeMirror editor is initialized, the C# property is not automatically updated when the text is modified in the editor. The issue arises because Blazor’s data binding system doesn’t know when the JavaScript editor content changes unless you explicitly notify it via JavaScript Interop.

How to Fix the Data Binding Issue?

To solve this, we need to invoke a JavaScript function that listens for changes in the CodeMirror editor and updates the C# property accordingly. Here’s the solution using JavaScript Interop.

Updated _Host.cshtml

Modify the JavaScript function to include the JavaScript Interop call and pass the DotNet object reference.

<script>
    function loadCodeEditor(dontNetObjRef) {
        var codemirrorEditor = CodeMirror.fromTextArea(document.getElementById('codearea'), {
            lineNumbers: true,
            styleActiveLine: true,
            matchBrackets: true,
            mode: "text/x-csharp",
            theme: "monokai",
            extraKeys: {
                "F11": function (cm) {
                    cm.setOption("fullScreen", !cm.getOption("fullScreen"));
                },
                "Esc": function (cm) {
                    if (cm.getOption("fullScreen")) cm.setOption("fullScreen", false);
                }
            }
        });
        
        codemirrorEditor.setSize(900, 500);
        codemirrorEditor.on("change", editor => {
            dontNetObjRef.invokeMethodAsync("UpdateField", editor.getValue());
            console.log(editor.getValue());
        });
    }
</script>

Updated Razor Page

In the Razor Page, we use the DotNetObjectReference to pass the Blazor component to the JavaScript function, enabling us to invoke C# methods when the content of the editor changes.

@page "/"
@inject IJSRuntime JSRuntime;

<h1>Hello, world!</h1>
<textarea id="codearea"></textarea>

<SurveyPrompt Title="How is Blazor working for you?" />

<br />
<br />

Input Code: @UserCodeInput

@code{
    public string UserCodeInput { get; set; }

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (firstRender)
        {
            await JSRuntime.InvokeVoidAsync("loadCodeEditor", DotNetObjectReference.Create(this));
        }
    }

    [JSInvokable("UpdateField")]
    public Task UpdateField(string codeValue)
    {
        UserCodeInput = codeValue;
        StateHasChanged();
        return Task.CompletedTask;
    }
}

Practical Example Code

Here’s a complete example that fixes the data binding issue using JavaScript Interop:

  1. _Host.cshtml - Includes the necessary JavaScript and stylesheets.
  2. Razor Page - Uses @bind to bind the textarea to a C# property, and invokes the JavaScript function via JSRuntime.

This will allow the content in the CodeMirror editor to be reflected in the C# property when the user types or modifies the text.

Alternative Ways to Solve the Binding Issue

While the above solution uses JavaScript Interop, another approach is to manually trigger Blazor’s default event handling by updating the textarea’s value from JavaScript. Here’s an alternative JavaScript solution:

window.initCodeMirror = function () {
    var textArea = document.getElementById('codemirror');
    var editor = CodeMirror.fromTextArea(textArea);

    editor.on('change', function () {
        textArea.value = editor.getValue();
        textArea.dispatchEvent(new Event('change', { bubbles: true }));
    });
}

In this case, the textarea’s value is updated in JavaScript, and the Blazor binding should automatically update.

FAQs on Solving CodeMirror Binding in Blazor

Q: How can I fix CodeMirror binding issues in Blazor?

ANS: To fix the binding issue, use JavaScript Interop to notify Blazor when the content in CodeMirror changes. Pass a DotNetObjectReference to the JavaScript function and use it to invoke a C# method that updates the bound property.

Q: Why doesn't Blazor automatically detect changes in CodeMirror?

ANS: Blazor’s data binding system only detects changes to DOM elements it manages. Code

Mirror, being a JavaScript-based editor, operates outside of Blazor’s built-in change tracking, so you need to use JavaScript Interop to manually trigger updates.

Conclusion

Integrating CodeMirror with Blazor can be tricky due to the nature of the editor and Blazor’s data binding system. Using JavaScript Interop and invoking C# methods from JavaScript is the best solution for synchronizing content between CodeMirror and C#. By following this guide, you should be able to set up Blazor with CodeMirror and properly bind data back to the C# code.
