Summary

Blazor WebAssembly apps may encounter an integrity attribute error when hosted on GitHub Pages. This detailed guide explores the common causes and solutions, such as modifying git line-ending normalization and other practical fixes, ensuring your Blazor app runs smoothly.

Solved: How-to-Fix-Integrity-Attribute-Issues-for-Blazor-Apps

Encountering the integrity attribute error in your Blazor WebAssembly app hosted on GitHub Pages? This guide dives deep into the problem, its causes, and provides step-by-step solutions.

Example Error:

Failed to find a valid digest in the 'integrity' attribute for resource 'https://yourdomain.github.io/blazor/_framework/wasm/dotnet.js' with computed SHA-256 integrity 'XYZ='. The resource has been blocked.

What Causes the Error?

The error typically arises when GitHub Pages modifies file line endings during commits, breaking the integrity hash.

Solution 1: Add a .gitattributes File

To prevent git from altering file line endings, add a .gitattributes file to your Blazor project folder.

Step-by-Step Guide:

  1. Create a .gitattributes file in the root of your Blazor project.

  2. Add the following line to the file:

    * binary

  3. Save the file and commit it to your repository.

  4. Delete the _framework folder in your project.

  5. Rebuild and redeploy your Blazor app.

Explanation:

  • The * binary directive instructs git to treat all files as binary, avoiding line-ending normalization.

Solution 2: Clean and Rebuild Your Solution

If the integrity error persists, try cleaning and rebuilding the project.

Steps:

  1. Open your Blazor project in Visual Studio.
  2. Go to the Build menu and select Clean Solution.
  3. Then, choose Rebuild Solution.
  4. Redeploy the app to GitHub Pages.

Why This Works: Cleaning removes intermediate files, while rebuilding regenerates the required assets with accurate hashes.

Solution 3: Check the Target Framework

Ensure the correct target framework is selected for your Blazor WebAssembly app.

Steps:

  1. Open the project settings in Visual Studio.
  2. Verify that the target framework is set to browser-wasm.
  3. Redeploy the app.

Note: Using an incorrect target framework, such as win-x64, can interfere with response handling, causing integrity errors.

Alternative Way: Use no-cache for Service Worker Requests

If you’re using a service worker, cached files can cause integrity mismatches. Adjust the cache settings to avoid conflicts.

Code Example:

async function onInstall(event) {
    console.info('Service worker: Install');

    const assetsRequests = self.assetsManifest.assets
        .map(asset => new Request(asset.url, { integrity: asset.hash, cache: "no-cache" }));

    await caches.open(cacheName).then(cache => cache.addAll(assetsRequests));
}

Practical Example: Cleaning Bin and Obj Folders

Deleting intermediate directories like bin and obj often resolves the issue for projects using .NET 5 or higher.

Steps:

  1. Close Visual Studio.
  2. Navigate to the project directory.
  3. Delete the bin and obj folders manually.
  4. Open the project in Visual Studio and rebuild.

Supported Environments:

  • .NET 5 and 6
  • Visual Studio 2019 and 2022

FAQs on Fixing Integrity Attribute Issues in Blazor

Q: What is the integrity attribute error in Blazor?

ANS: This error occurs when the integrity hash for a resource does not match the expected value, often due to git altering file line endings.

Q: How do I fix the Blazor integrity attribute error?

ANS: Add a .gitattributes file with * binary and rebuild the project to prevent git from altering file integrity.

Q: Can cleaning and rebuilding fix the integrity error?

ANS: Yes, cleaning and rebuilding removes corrupted intermediate files and regenerates accurate integrity hashes.

Q: Why is the target framework important?

ANS: An incorrect framework, like win-x64, may cause server responses to break, leading to integrity issues. Always select browser-wasm.

Q: Can cached files cause integrity errors?

ANS: Yes, outdated cached files can conflict with the latest hashes. Use cache: "no-cache" to resolve this.
