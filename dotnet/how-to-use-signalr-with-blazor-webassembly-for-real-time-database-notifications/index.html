Transitioning from an ASP.NET MVC application to Blazor can raise challenges, particularly when implementing real-time database notifications. This guide explores how to use SignalR with Blazor WebAssembly (WASM) to notify users of database updates dynamically, ensuring seamless user experiences.

The Problem: Real-Time Notifications in Blazor

The Challenge

You may have an existing ASP.NET MVC app using a SignalR hub to notify users about database changes. When moving to Blazor WebAssembly or Server, replicating this functionality requires adapting to Blazor’s architecture.

Solution: Using SignalR in Blazor

Why SignalR?

SignalR is a library for ASP.NET that enables real-time communication between servers and clients. By integrating SignalR with Blazor, you can refresh components dynamically without a full-page reload.

Step-by-Step Implementation

1. Set Up SignalR in the Blazor WebAssembly Project

Server-Side: Configure SignalR in Startup.cs

Add the SignalR service and map the hub endpoint.

public void ConfigureServices(IServiceCollection services)
{
    services.AddSignalR();
}

public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    app.UseEndpoints(endpoints =>
    {
        endpoints.MapHub<NotificationHub>("/notificationHub");
    });
}
Explanation:
  • AddSignalR(): Registers the SignalR services.
  • MapHub<NotificationHub>: Maps the SignalR hub to a specific route.

2. Create the SignalR Hub

Define the SignalR hub for managing notifications.

using Microsoft.AspNetCore.SignalR;

public class NotificationHub : Hub
{
    public async Task SendUpdate(string message)
    {
        await Clients.All.SendAsync("RefreshTable", message);
    }
}
Explanation:
  • SendUpdate: Sends a message to all connected clients, triggering the RefreshTable event.

3. Connect Blazor WebAssembly to SignalR

Install the SignalR Client Package

Run the following command:

dotnet add package Microsoft.AspNetCore.SignalR.Client
Implement the SignalR Client in the Razor Component

Create a connection and subscribe to the RefreshTable event.

@inject NavigationManager Navigation

<h3>Real-Time Database Updates</h3>
<ul>
    @foreach (var item in Notifications)
    {
        <li>@item</li>
    }
</ul>

@code {
    private HubConnection? hubConnection;
    private List<string> Notifications = new();

    protected override async Task OnInitializedAsync()
    {
        hubConnection = new HubConnectionBuilder()
            .WithUrl(Navigation.ToAbsoluteUri("/notificationHub"))
            .Build();

        hubConnection.On<string>("RefreshTable", (message) =>
        {
            Notifications.Add(message);
            StateHasChanged();
        });

        await hubConnection.StartAsync();
    }

    public async ValueTask DisposeAsync()
    {
        if (hubConnection is not null)
        {
            await hubConnection.StopAsync();
            await hubConnection.DisposeAsync();
        }
    }
}
Explanation:
  • HubConnection: Manages the connection to the SignalR hub.
  • On<string>("RefreshTable"): Subscribes to the RefreshTable event to refresh the UI dynamically.
  • StateHasChanged(): Notifies the Blazor rendering engine to update the UI.

Alternative Method: Blazor Server

If you opt for Blazor Server, SignalR is integrated natively, simplifying the setup. However, Blazor WASM is preferred for client-heavy applications or offline capabilities.

Practical Example: Refreshing a Data Table

Suppose you want to display a table that updates in real-time when the database changes.

Razor Component:

<h3>Live Data Table</h3>
<table>
    <thead>
        <tr>
            <th>Record ID</th>
            <th>Value</th>
        </tr>
    </thead>
    <tbody>
        @foreach (var record in Records)
        {
            <tr>
                <td>@record.Id</td>
                <td>@record.Value</td>
            </tr>
        }
    </tbody>
</table>

@code {
    private List<Record> Records = new();

    protected override async Task OnInitializedAsync()
    {
        await LoadData();
        hubConnection.On("RefreshTable", async () =>
        {
            await LoadData();
        });
    }

    private async Task LoadData()
    {
        // Fetch updated data from the database
        Records = await HttpClient.GetFromJsonAsync<List<Record>>("api/records");
        StateHasChanged();
    }
}

FAQs on How-to-Use-SignalR-with-Blazor-WebAssembly-for-Real-Time-Database-Notifications

Q: Can I use SignalR with Blazor WebAssembly?

ANS: Yes, SignalR can be integrated into Blazor WebAssembly for real-time communication.

Q: What is the difference between Blazor Server and WASM for real-time updates?

ANS: Blazor Server supports SignalR natively, while Blazor WASM requires configuring SignalR with an API.

Q: How does StateHasChanged work in Blazor?

ANS: StateHasChanged informs the rendering engine to refresh the UI with updated data.

Q: Is SignalR necessary for real-time updates?

ANS: Yes, SignalR is the recommended library for real-time server-client communication in ASP.NET.

Q: Can SignalR handle large-scale connections?

ANS: Yes, SignalR can manage numerous connections, especially when scaled with Azure SignalR Service.
