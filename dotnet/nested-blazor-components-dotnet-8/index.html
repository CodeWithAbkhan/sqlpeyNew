Handling validation within nested Blazor components can be tricky, especially when dealing with complex forms. This guide outlines a step-by-step process to ensure that each nested component properly validates its data, resulting in a smooth user experience.

Top 5 Steps to Validate Nested Blazor Components in .NET 8

1. Setting Up FluentValidation

Start by setting up FluentValidation in your project to handle complex validation scenarios. Install the FluentValidation package if you haven’t already.

dotnet add package FluentValidation

Create a custom validator class for your model:

using FluentValidation;

public class CustomerValidator : AbstractValidator<Customer>
{
    public CustomerValidator()
    {
        RuleFor(customer => customer.FirstName).NotEmpty().WithMessage("First Name is required");
        RuleFor(customer => customer.LastName).NotEmpty().WithMessage("Last Name is required");
        RuleFor(customer => customer.Address.Line1).NotEmpty().WithMessage("Address Line 1 is required");
    }
}
  • RuleFor: Specifies the validation rule for a particular property.
  • WithMessage: Customizes the validation error message.

2. Creating the FluentValidator Component

Create a FluentValidator component to integrate FluentValidation with Blazor’s EditContext.

using FluentValidation;
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Forms;

public class FluentValidator<TValidator> : ComponentBase where TValidator : IValidator, new()
{
    private TValidator validator;
    [CascadingParameter] private EditContext EditContext { get; set; }

    protected override void OnInitialized()
    {
        validator = new TValidator();
        var messages = new ValidationMessageStore(EditContext);

        EditContext.OnFieldChanged += (sender, eventArgs) => ValidateModel((EditContext)sender, messages);
        EditContext.OnValidationRequested += (sender, eventArgs) => ValidateModel((EditContext)sender, messages);
    }

    private void ValidateModel(EditContext editContext, ValidationMessageStore messages)
    {
        var context = new ValidationContext<object>(editContext.Model);
        var validationResult = validator.Validate(context);
        messages.Clear();

        foreach (var error in validationResult.Errors)
        {
            var fieldIdentifier = ToFieldIdentifier(editContext, error.PropertyName);
            messages.Add(fieldIdentifier, error.ErrorMessage);
        }

        editContext.NotifyValidationStateChanged();
    }

    private static FieldIdentifier ToFieldIdentifier(EditContext editContext, string propertyPath)
    {
        var obj = editContext.Model;
        while (true)
        {
            var nextTokenEnd = propertyPath.IndexOfAny(new[] { '.', '[' });
            if (nextTokenEnd < 0) return new FieldIdentifier(obj, propertyPath);

            var nextToken = propertyPath.Substring(0, nextTokenEnd);
            propertyPath = propertyPath.Substring(nextTokenEnd + 1);

            object newObj;
            if (nextToken.EndsWith("]"))
            {
                nextToken = nextToken.Substring(0, nextToken.Length - 1);
                var prop = obj.GetType().GetProperty("Item");
                var indexerType = prop.GetIndexParameters()[0].ParameterType;
                var indexerValue = Convert.ChangeType(nextToken, indexerType);
                newObj = prop.GetValue(obj, new object[] { indexerValue });
            }
            else
            {
                var prop = obj.GetType().GetProperty(nextToken);
                if (prop == null) throw new InvalidOperationException($"Could not find property named {nextToken}.");
                newObj = prop.GetValue(obj);
            }

            if (newObj == null) return new FieldIdentifier(obj, nextToken);
            obj = newObj;
        }
    }
}
  • EditContext: Manages the state of the form.
  • ValidationMessageStore: Stores validation messages.

3. Implementing the EditForm

Use the FluentValidator component in your EditForm.

Alternative Ways

For simpler projects, consider using data annotations for validation:

public class Customer
{
    [Required(ErrorMessage = "First Name is required")]
    public string FirstName { get; set; }

    [Required(ErrorMessage = "Last Name is required")]
    public string LastName { get; set; }

    [Required(ErrorMessage = "Address Line 1 is required")]
    public string Address { get; set; }
}

Data annotations provide a straightforward way to implement validation but may lack the flexibility of FluentValidation for complex scenarios.

FAQs on Validating Nested Blazor Components in .NET 8

Q: How do I handle validation in nested Blazor components?

ANS: Use FluentValidation with a custom FluentValidator component and ensure each nested component has its own EditContext.

Q: Can I use data annotations for validation?

ANS: Yes, data annotations can be used for simpler validation scenarios, but FluentValidation offers more flexibility for complex validations.

Q: Where do I place the JavaScript code for validation?

ANS: You don’t need JavaScript for server-side validation in Blazor; use C# and FluentValidation for efficient validation handling.
