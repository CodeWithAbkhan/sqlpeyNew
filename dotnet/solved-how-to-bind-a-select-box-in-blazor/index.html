Solved: How to Bind a Select Box in Blazor

Why does binding a select box in Blazor throw errors sometimes?

When trying to bind a select box in Blazor using <InputSelect> or <select>, developers often encounter issues like missing constructor errors or type mismatches. For instance, a common error message might be:

WASM: System.MissingMethodException: Constructor on type 'System.ComponentModel.ByteConverter' not found.

This issue typically arises due to type mismatch or improper model binding, especially when dealing with byte types. But how do we fix these issues and properly bind a <select> element?

How can you bind a <select> element to a Blazor model?

Let’s start with a simple example where we bind a country ID to a model using Blazor’s <InputSelect> component. The basic approach is to use the @bind-Value directive.

<InputSelect @bind-Value="model.ByCountryId" class="form-control">
    @if (model?.Countries != null)
    {
        @foreach (var country in model.Countries)
        {
            <option value="@country.Id">@country.Name</option>
        }
    }
</InputSelect>

What does the code do, line by line?

  • <InputSelect @bind-Value="model.ByCountryId">: This binds the selected value from the dropdown to the ByCountryId property of the model.
  • @if (model?.Countries != null): Checks if the list of countries is not null before iterating through them.
  • @foreach (var country in model.Countries): Iterates through the list of countries to populate the dropdown options.
  • <option value="@country.Id">@country.Name</option>: Creates each <option> element, binding the value to the country ID and displaying the country name.

Now, here’s the backend code that sets up the model:

@code {
    BrandModel model = new BrandModel();

    protected override async Task OnInitializedAsync()
    {
        model = new BrandModel
        {
            Id = 19,
            ByCountryId = 1,
            Countries = new List<Country>
            {
                new Country { Id = 1, Name = "Azerbaijan" },
                new Country { Id = 2, Name = "Turkey" }
            },
            IsActive = true,
            Name = "Brand"
        };
    }
}

What could go wrong with this code?

A common issue is receiving the following error:

WASM: System.InvalidOperationException: Microsoft.AspNetCore.Components.Forms.InputSelect`1[System.Byte] does not support the type 'System.Byte'.

The problem here is that Blazor’s <InputSelect> cannot handle byte types well, which causes the error.

What is the solution for byte-type binding in Blazor?

The easiest solution is to either:

  1. Use a different type for the bound property. For example, change byte to int for the ByCountryId property.
  2. Use a plain <select> element instead of <InputSelect>. Here’s an example:
<select @bind="model.ByCountryId" class="form-control">
    @if (model?.Countries != null)
    {
        @foreach (var country in model.Countries)
        {
            <option value="@country.Id">@country.Name</option>
        }
    }
</select>

This is simpler and avoids the binding issues with the <InputSelect> component.

Are there any alternatives for handling this in Blazor?

Yes, you can disable Blazor linking, which might resolve some issues with missing assemblies or references. Here’s how you can modify your .csproj file:

<PropertyGroup>
   <BlazorLinkOnBuild>false</BlazorLinkOnBuild>
</PropertyGroup>

This disables the linking process during the build, which might solve problems related to missing methods or types.

Practical Example of Dropdown Binding

To make things clearer, let’s see a practical example of a cascading dropdown experience. In this case, we bind a list of countries and then display a second dropdown for cities based on the selected country.

<select class="form-control" @bind="@SelectedCountryID">
    <option value=""></option>
    @foreach(var country in CountryList)
    {
        <option value = "@country.Code"> @country.Name </option>
    }
</select>

<p>Selected Country: @SelectedCountryID</p>

@code {
    string selectedCountryID;

    string SelectedCountryID
    {
        get => selectedCountryID;
        set
        {
            selectedCountryID = value;
            // Load cities based on selected country
        }
    }

    List<Country> CountryList = new List<Country>() 
    { 
        new Country ("USA", "United States"),
        new Country ("UK", "United Kingdom") 
    };

    public class Country
    {
        public Country(string code, string name)
        {
            Code = code;
            Name = name;
        }
        public string Code { get; set; }
        public string Name { get; set; }
    }
}

How can I bind and validate a select input using EditForm?

Using <EditForm> ensures that all form inputs are correctly validated. Here’s how you can implement it:

<EditForm Model="model">
    <InputSelect @bind-Value="model.ByCountryId" class="form-control">
        <option value=""></option>
        @foreach (var country in model.Countries)
        {
            <option value="@country.Id">@country.Name</option>
        }
    </InputSelect>
</EditForm>

In this approach, the form automatically binds to model.ByCountryId and provides validation.

FAQs on How to Bind a Select Box in Blazor

Q: Why is my Blazor select box not binding correctly?

ANS: The most common issue is a mismatch between the type of the property being bound and the expected input type.

Q: How do I bind a dropdown list to a model in Blazor?

ANS: Use either <InputSelect> or a standard <select> element with the @bind directive to connect the selected value to a property in your model.

Q: What’s the difference between InputSelect and select in Blazor?

ANS: <InputSelect> is part of Blazor’s forms and input components designed for model binding and validation, while <select> is a standard HTML element.

Q: How do I bind a byte type in Blazor dropdowns?

ANS: It’s recommended to avoid using byte types with <InputSelect>, as it often leads to binding errors. Using int or a standard <select> is a better approach.

Q: Can I disable Blazor’s linking process?

ANS: Yes, you can disable linking by setting <BlazorLinkOnBuild>false</BlazorLinkOnBuild> in your .csproj file.
