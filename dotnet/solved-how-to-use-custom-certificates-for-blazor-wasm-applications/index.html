Summary:
When developing a Blazor WebAssembly (WASM) application that runs on an Intranet, it becomes essential to secure the communication channel with a custom certificate. While the app will be hosted locally, using HTTPS with a valid TLS certificate ensures that the communication remains encrypted. This post will walk you through how to configure a custom certificate for Blazor WASM applications and explore a practical solution to secure your app’s communication in a local network environment.

What is Blazor WebAssembly (WASM) and Why is Secure Communication Important?

Blazor WebAssembly allows you to run .NET code directly in the browser. For applications that are hosted on an Intranet or local network, securing the connection using SSL/TLS certificates is crucial to ensure data privacy and integrity. When your application runs as a Windows service, accessed from various machines within a network, it must use HTTPS for secure communication.

How Can I Secure My Blazor WebAssembly Application with a Custom TLS Certificate?

The main challenge here is using a self-signed certificate or a custom certificate for the Blazor WASM app. Since the application will not be exposed to the internet, typical certificate authorities like Let’s Encrypt are not an option. You need to ensure that your Blazor application communicates securely using a certificate that is trusted within your network.

Practical Example: Setting up Custom Certificates for Blazor WASM

You can configure a custom certificate by modifying the Kestrel server settings in your Blazor application. Below is a step-by-step guide to setting this up:

builder.WebHost.ConfigureKestrel(serverOptions =>
{
  // Listen on port 443 for secure communication
  serverOptions.ListenAnyIP(443, listenOptions =>
  {
    listenOptions.UseHttps(httpsOptions =>
    {
      // Load the custom certificate from the store
      var customCert = CertificateLoader.LoadFromStoreCert(
          "test", "My", StoreLocation.CurrentUser,
          allowInvalid: true);

      // Create a dictionary to map the certificate name to the certificate itself
      var certificates = new Dictionary<string, X509Certificate2>(
          StringComparer.OrdinalIgnoreCase)
      {
        ["test"] = customCert
      };

      // Select the certificate based on the requested connection name
      httpsOptions.ServerCertificateSelector = (connectionContext, name) =>
      {
        if (name is not null && certificates.TryGetValue(name, out var cert))
        {
          return cert;  // Return the custom certificate
        }

        return customCert;  // Fallback to the default certificate
      };
    });
  });
});

Breakdown of the Code:

  1. ConfigureKestrel: The Blazor application uses the Kestrel web server, and here we are configuring it to listen on port 443, which is the standard HTTPS port.
  2. UseHttps: This method ensures that the server uses SSL/TLS for encrypted communication.
  3. Load Custom Certificate: The certificate is loaded from the store with CertificateLoader.LoadFromStoreCert. It specifies the certificate’s name (test), the store (My), and the location (CurrentUser).
  4. ServerCertificateSelector: This delegate selects which certificate to use for the current connection. If a certificate name is provided in the request, it looks up the corresponding certificate from the dictionary. If not, it defaults to the customCert.

Alternative Ways to Handle Certificates in Blazor WASM

While the above method works well for self-hosted Blazor applications, you might prefer using IIS for simpler management of certificates. IIS provides an easier interface for managing SSL certificates, and you can proxy your Blazor app through IIS to handle SSL settings more conveniently.

If your application is not accessible by IIS or you prefer not to use it, you can stick with the Kestrel configuration shown above, where you control the certificate loading process within the application itself.

Key Considerations When Using Self-Signed Certificates

  • Trust within the Network: Since your certificate is self-signed, it will not be trusted by default in most browsers. You need to ensure that all client machines have the certificate installed in their trusted root certificate store.
  • Intranet-Only Usage: Self-signed certificates are a viable option for applications that will only be accessed within a controlled environment, like an Intranet.

Practical Example with IIS (Alternative Method)

If you decide to use IIS as a reverse proxy for your Blazor WASM application, follow these steps to set it up:

  1. Install your SSL certificate on IIS.
  2. Configure the IIS site to bind to port 443 and use the installed certificate.
  3. Set the Blazor application to listen on an internal port (e.g., 5000), and use IIS to route the traffic securely.

By using IIS, you offload the responsibility of certificate management to IIS, which simplifies the process for non-technical users.

FAQs on Using Custom Certificates for Blazor WASM

Q: How do I secure a Blazor WASM application with a custom TLS certificate?

ANS:
To secure a Blazor WASM application with a custom TLS certificate, you can modify the Kestrel server settings in your Blazor app to use a self-signed or custom certificate. The process involves loading the certificate from the certificate store and configuring the ServerCertificateSelector to choose the appropriate certificate for the connection.

Q: Can I use IIS for managing SSL certificates for Blazor WASM?

ANS:
Yes, you can use IIS to manage SSL certificates for your Blazor WASM application. By using IIS as a reverse proxy, you can easily configure SSL settings and offload the certificate management to IIS, which simplifies the process.

Q: How do I ensure that my custom certificate is trusted by all users on the network?

ANS:
To ensure your custom certificate is trusted by all users, you need to install it into the trusted root certificate store on each client machine within your network. This step is necessary because self-signed certificates are not trusted by default.

Q: What is the default port for HTTPS communication in Blazor?

ANS:
The default port for HTTPS communication is 443. When configuring your Blazor application, you should set the server to listen on this port to ensure secure communication.

Q: Can I use a certificate from Let's Encrypt for my Blazor WASM app in a local network?

ANS:
No, Let’s Encrypt certificates are only valid for publicly accessible domains. If your Blazor WASM app is hosted within a local network, you will need to use a self-signed certificate or obtain a certificate from a trusted internal certificate authority.
