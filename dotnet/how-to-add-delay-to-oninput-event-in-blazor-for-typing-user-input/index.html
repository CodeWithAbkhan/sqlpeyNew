How to Add Delay to OnInput Event in Blazor for Typing User Input

In Blazor, handling real-time user input is a common scenario, especially when it comes to reducing the number of requests sent to the backend as the user types. But how can we add a delay or throttle the input event so that we wait until the user finishes typing before executing the logic? This is a problem that is often referred to as “debouncing” or “throttling” the input. In this article, we will explore several ways to introduce such a delay to improve user experience and system efficiency in Blazor.

Summary

When dealing with user input in real-time scenarios, a common requirement is to introduce a delay to avoid unnecessary backend requests or updates as the user types. In Blazor, this can be achieved using a timer to delay the processing of the input until the user finishes typing. In this article, we’ll go over practical examples and alternatives, including using the built-in System.Timers library, Reactive Extensions (Rx), and JavaScript Interop to add delays to the OnInput event.

What Is the OnInput Event in Blazor?

In Blazor, the OnInput event is triggered whenever the content of an input field changes. This event is typically used to capture user input in real-time. However, in scenarios where we don’t want to perform an action on every keystroke, adding a delay between the input and the action is useful. This is particularly beneficial when interacting with backend APIs to avoid making requests for every keystroke.

How Can You Add a Delay to OnInput Event in Blazor?

There are several ways to achieve this. Let’s go over three approaches:

  1. Using System.Timers to Handle Delay
  2. Using Reactive Extensions (Rx)
  3. Using JavaScript Interop to Avoid UI Freezes

1. Using System.Timers to Handle Delay

A simple approach is to use the System.Timers.Timer class to create a delay between the user’s input and the logic execution.

Example Code:

@page "/"
<input type="text" @bind="Data" @oninput="OnInputHandler" />
<p>@Data</p>

@code {
    public string Data { get; set; }   

    private Timer _inputTimer = new Timer(1000); // 1 second delay
    private string _backendData;

    protected override void OnInitialized()
    {
        _inputTimer.Elapsed += OnUserFinishedTyping;
        _inputTimer.AutoReset = false; // Ensure the timer doesn't restart automatically
    }

    private void OnInputHandler(UIChangeEventArgs e)
    {
        _inputTimer.Stop(); // Stop the timer on every input
        _inputTimer.Start(); // Start a new timer
    }

    private async void OnUserFinishedTyping(object sender, ElapsedEventArgs e)
    {
        _backendData = await FetchFromBackend(Data);
        StateHasChanged(); // Refresh the UI with updated data
    }

    private Task<string> FetchFromBackend(string input)
    {
        // Simulating an API call
        return Task.FromResult(input + " from backend");
    }

    public void Dispose()
    {
        _inputTimer?.Dispose();
    }
}

Code Explanation:

  • Timer Initialization: We create a timer that triggers after 1 second of inactivity.
  • OnInputHandler: This method is called every time the user types. It resets the timer each time, effectively delaying the event handling.
  • OnUserFinishedTyping: This method is invoked after the delay, fetching data from the backend.
  • Dispose Method: Properly disposes of the timer when the component is disposed.

Use Case: This approach is particularly useful when you want to avoid multiple backend requests as the user types. Only the last keystroke (after the delay) will trigger the backend request.

2. Using Reactive Extensions (Rx)

Another powerful approach is using the Reactive Extensions (Rx) library. Rx allows you to create observable streams of data that can be easily throttled or debounced.

Example Code:

@using System.Reactive.Subjects
@using System.Reactive.Linq

<input type="text" @oninput="OnInputChanged" class="form-control" />
<p>@Data</p>

@code {
    private Subject<ChangeEventArgs> _inputSubject = new();
    public string Data { get; set; } = string.Empty;

    protected override async Task OnInitializedAsync()
    {
        _inputSubject
            .Throttle(TimeSpan.FromMilliseconds(300)) // 300ms debounce
            .Select(e => (string)e.Value)
            .DistinctUntilChanged() // Avoid duplicate requests
            .SelectMany(SearchResults)
            .Subscribe(results =>
            {
                Data = results;
                StateHasChanged();
            });
    }

    private Task<string> SearchResults(string query)
    {
        // Simulating a search query result
        return Task.FromResult($"Search result for: {query}");
    }

    private void OnInputChanged(ChangeEventArgs e)
    {
        _inputSubject.OnNext(e);
    }
}

Code Explanation:

  • Reactive Subject: We use a Subject to track input events and react to them asynchronously.
  • Throttle: We apply a Throttle operator to debounce the input. It only triggers after 300ms of inactivity.
  • DistinctUntilChanged: This ensures that we only perform an action when the input changes, avoiding redundant actions.
  • SelectMany: We use this to perform an asynchronous action like an API call when the user finishes typing.

Use Case: This method provides a more scalable and reactive approach, especially for real-time data handling and complex UI interactions.

3. Using JavaScript Interop to Avoid UI Freezes

In some cases, using Blazor’s JavaScript Interop might be necessary to solve issues like input lag or UI freezing, especially in Blazor Server apps where every input triggers a full component render.

Example Code:

<input id="textInput" @oninput="OnInputChanged" />
<p>@Data</p>

@code {
    public string Data { get; set; }

    public void OnInputChanged(ChangeEventArgs e)
    {
        Data = e.Value.ToString();
        InvokeAsync(StateHasChanged);
    }

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (firstRender)
        {
            await JSRuntime.InvokeVoidAsync("setInitialValueById", "textInput", Data);
        }
    }
}

Use Case: This approach may be useful if you’re experiencing UI lag in Blazor Server-side apps due to constant re-renders triggered by input changes.

Alternative Ways:

  • Using Blazor Component Libraries: Some Blazor component libraries like BlazorHero or BlazorBoilerplate offer built-in solutions for handling user input with debouncing or throttling.

FAQs on How to Add Delay to OnInput Event in Blazor for Typing User Input

Q: How can I add delay in Blazor to throttle user input?

ANS: You can add delay using a System.Timers.Timer or by utilizing the Reactive Extensions library. Both methods allow you to control when to trigger an action after a set delay.

Q: Why should I add delay to OnInput event?

ANS: Adding delay helps in optimizing user experience and backend performance by reducing the frequency of requests or updates triggered by every keystroke.

Q: How does throttling work in Blazor?

ANS: Throttling limits the rate at which an event is triggered. In Blazor, this can be done using timers or Rx to ensure actions are performed only after the user has stopped typing for a set amount of time.

Q: Can I use Rx in Blazor for event handling?

ANS: Yes, using Rx in Blazor is a powerful way to handle input events reactively. You can throttle, debounce, and handle asynchronous actions efficiently.

Q: How can I reduce UI freezing in Blazor Server?

ANS: You can use JavaScript Interop or throttle the input event to avoid unnecessary re-renders in Blazor Server applications, improving performance and responsiveness.
