How to Integrate Okta Authentication into Blazor Server-Side App

In this guide, we’ll walk through the steps required to integrate Okta authentication into a Blazor Server-Side application. You’ll be able to manage user authentication and easily connect your Blazor app to Okta for secure authentication using OpenID Connect. Below, we will explore the configuration of Okta and Blazor, explain each part of the code, and suggest practical tips along the way.

Overview

When implementing Okta authentication in your Blazor Server-Side app, the main goal is to authenticate users via Okta and manage their session securely. This process includes setting up authentication middleware, handling authorization and logout, and managing the user’s session flow within the app.

To do this, we use Okta’s OpenID Connect for authentication, along with Cookie Authentication to store the user’s session on the server.

Step-by-Step Setup of Okta Authentication in Blazor Server-Side

1. Configure Services for Authentication (Startup.cs)

In the Startup.cs file, under the ConfigureServices method, you will set up authentication and authorization services.

public void ConfigureServices(IServiceCollection services)
{
    services.AddAuthorizationCore();
    services.AddAuthentication(sharedOptions =>
        {
            sharedOptions.DefaultAuthenticateScheme = CookieAuthenticationDefaults.AuthenticationScheme;
            sharedOptions.DefaultSignInScheme = CookieAuthenticationDefaults.AuthenticationScheme;
            sharedOptions.DefaultChallengeScheme = OpenIdConnectDefaults.AuthenticationScheme;
        })
        .AddCookie()
        .AddOpenIdConnect(options =>
        {
            options.ClientId = Configuration["Okta:ClientId"];
            options.ClientSecret = Configuration["Okta:ClientSecret"];
            options.Authority = Configuration["Okta:Issuer"];
            options.CallbackPath = "/authorization-code/callback";
            options.ResponseType = "code";
            options.SaveTokens = true;
            options.UseTokenLifetime = false;
            options.GetClaimsFromUserInfoEndpoint = true;
            options.Scope.Add("openid");
            options.Scope.Add("profile");
            options.TokenValidationParameters = new TokenValidationParameters
            {
                NameClaimType = "name"
            };
        });
}

Explanation of the code:

  • AddAuthorizationCore() enables basic authorization functionality.
  • AddAuthentication() sets up the authentication middleware with Okta’s OpenID Connect and Cookie Authentication.
  • AddCookie() ensures that user session data is stored in cookies.
  • AddOpenIdConnect() configures OpenID Connect authentication with Okta, where:
    • ClientId and ClientSecret are retrieved from your Okta app settings.
    • Authority points to your Okta issuer URL.
    • CallbackPath handles the redirect after a successful authentication.
    • Scope defines the access granted, including openid and profile.

2. Configure the HTTP Request Pipeline (Startup.cs)

Next, configure the app’s HTTP request pipeline to include authentication and authorization:

public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    if (env.IsDevelopment())
    {
        app.UseDeveloperExceptionPage();
    }
    else
    {
        app.UseExceptionHandler("/Error");
        app.UseHsts();
    }

    app.UseHttpsRedirection();
    app.UseStaticFiles();
    app.UseRouting();
    app.UseAuthentication();
    app.UseAuthorization();

    app.UseEndpoints(endpoints =>
    {
        endpoints.MapBlazorHub();
        endpoints.MapFallbackToPage("/_Host");
    });
}

This ensures that every HTTP request goes through the authentication and authorization processes before any page is served.

3. Setup Main Layout for User Authentication (MainLayout.razor)

In the MainLayout.razor file, define the components to show when the user is authorized or not. This allows your Blazor app to react dynamically based on the user’s authentication status.

<div class="top-row px-4">
    <AuthorizeView>
        <Authorized>
            <a href="Identity/Account/Manage">Hello, @context.User.Identity.Name!</a>
            <a href="Identity/Account/LogOut">Log out</a>
        </Authorized>
        <NotAuthorized>
            <a href="Identity/Account/Register">Register</a>
            <a href="Identity/Account/Login">Log in</a>
        </NotAuthorized>
    </AuthorizeView>

    <a href="https://learn.microsoft.com/en-us/aspnet/" target="_blank">About</a>
</div>

This code uses the AuthorizeView component to display different content depending on whether the user is authenticated. If the user is logged in, they see a greeting with their name and a logout option. If they are not authenticated, they are shown login and registration links.

4. Add Authentication State to the App (App.razor)

In the App.razor file, use CascadingAuthenticationState to propagate the authentication state throughout your application:

<CascadingAuthenticationState>
    <Router AppAssembly="@typeof(Program).Assembly">
        <Found Context="routeData">
            <AuthorizeRouteView RouteData="@routeData" DefaultLayout="@typeof(MainLayout)" />
        </Found>
        <NotFound>
            <LayoutView Layout="@typeof(MainLayout)">
                <p>Sorry, there's nothing at this address.</p>
            </LayoutView>
        </NotFound>
    </Router>
</CascadingAuthenticationState>

This ensures that your routes are aware of the user’s authentication status, and if the user is unauthorized, they will be redirected to the login page.

Practical Example Code for Custom Login and Logout Handling

To implement login and logout handling for Okta, create Razor pages like Login.cshtml and Logout.cshtml. These pages will handle the actual authentication logic.

Login.cshtml.cs:

public class LoginModel : PageModel
{
    public async Task OnGet(string redirectUri)
    {
        await HttpContext.ChallengeAsync(OpenIdConnectDefaults.AuthenticationScheme, 
        new AuthenticationProperties { RedirectUri = redirectUri });
    }
}

This code initiates the authentication challenge with Okta and redirects the user to Okta’s login page.

Logout.cshtml.cs:

public class LogoutModel : PageModel
{
    public async Task<IActionResult> OnGetAsync()
    {
        await HttpContext.SignOutAsync();
        return Redirect("/");
    }
}

Here, the logout process is handled by clearing the authentication session and redirecting the user to the home page.

Alternative Ways to Handle Okta Authentication in Blazor

If you’re looking for a simpler alternative to full Okta integration, you could consider using built-in authentication providers in Blazor or ASP.NET Core, like using IdentityServer4 or Auth0 for authentication purposes. These can simplify integration depending on your app’s complexity and authentication needs.

FAQs on Integrating Okta Authentication into Blazor Server-Side App

Q: How do I configure Okta for authentication?

ANS: In your Startup.cs, use AddOpenIdConnect to configure Okta by providing your ClientId, ClientSecret, and Authority. This will enable OpenID Connect authentication and allow the app to interact with Okta.

Q: What is the role of `CallbackPath`?

ANS: CallbackPath is the URL that Okta will redirect to after successful authentication. It is necessary for processing the authentication code and completing the login process.

Q: How can I manage user login status in Blazor?

ANS: Use the AuthorizeView component in Blazor to show different content based on the user’s authentication status. This allows you to display a greeting, logout button, or login and register options dynamically.

Q: How do I secure specific pages with Okta authentication?

ANS: You can use the [Authorize] attribute at the top of any Blazor page to ensure that only authenticated users can access that page.

Q: How do I handle logout in Blazor?

ANS: Create a Logout.cshtml Razor page to sign out the user and redirect them to the home page or a custom URL after logout.
