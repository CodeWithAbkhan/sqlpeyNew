If you’re working with Blazor and trying to invoke Blazor methods from JavaScript (e.g., with the Plaid API or other callbacks), you may encounter issues where the Blazor method doesn’t seem to get called from JavaScript. This could be due to several common pitfalls such as incorrect method definitions, lack of component references, or issues with the state updates. Here’s how to resolve these problems step by step.

What Could Be Causing the JSInvokable Method Not to Be Called in Blazor?

You may be encountering a problem where your Blazor method, defined with the [JSInvokable] attribute, is not being called by the JavaScript code. This issue can arise in scenarios where you use a third-party API (like the Plaid API), and your JavaScript code needs to invoke a method within Blazor’s C# component.

Here’s a breakdown of how you might be encountering this issue and the necessary steps to solve it.

Step 1: Reviewing the JavaScript Code for Plaid API Integration

In Blazor, calling JavaScript functions from C# is possible via JavaScript Interoperability (JSInterop). To invoke a Blazor method inside a JavaScript callback, you need to first ensure that your JavaScript is structured correctly. Here’s an example where a Plaid API callback triggers the Blazor method:

async function InitializePlaidLink(objRef, linkToken) {
    const handler = Plaid.create({
        token: linkToken,
        onSuccess: (public_token, metadata) => {
            objRef.invokeMethodAsync('OnPlaidLinkSuccess', public_token);
        },
        onLoad: () => {},
        onExit: (err, metadata) => {},
        onEvent: (eventName, metadata) => {},
    });

    handler.open();
}

In this code:

  • objRef.invokeMethodAsync is calling the OnPlaidLinkSuccess Blazor method with the public_token from Plaid’s onSuccess callback.

Step 2: Setting Up the Blazor Method to Handle JavaScript Calls

Your Blazor method is the one being called by JavaScript via invokeMethodAsync. Here’s how the C# Blazor method should look:

private string LinkToken { get; set; } = string.Empty;
private string PublicToken { get; set; } = string.Empty;

private async Task InitializePlaid()
{
    this.LinkToken = await this.apiService.GetPlaidLinkToken();
    var dotNetReference = DotNetObjectReference.Create(this);
    
    await this.jsRuntime.InvokeVoidAsync("InitializePlaidLink", dotNetReference, this.LinkToken);
}

[JSInvokable]
public void OnPlaidLinkSuccess(string publicToken)
{
    this.PublicToken = publicToken;
}

In this code:

  • The InitializePlaid method retrieves the LinkToken from an API service and then passes it along with the DotNetObjectReference to JavaScript.
  • OnPlaidLinkSuccess is the method that should be invoked when the JavaScript code triggers it with the public_token value.

Step 3: Fixing the Non-Static Method Issue

In Blazor, a common mistake when using JSInterop is failing to make the Blazor method static. When defining your Blazor method with [JSInvokable], ensure that it’s a static method if you don’t need an instance-specific state:

[JSInvokable]
public static void OnPlaidLinkSuccess(string publicToken)
{
    this.PublicToken = publicToken;
}

If you must use a non-static method, you need to pass a reference to the current component. Below is a more complex, but correct, example of how to handle this scenario:

@page "/js-sample"
@implements IDisposable
@inject IJSRuntime jsRuntime

<button class="btn btn-primary" @onclick="CallInstanceMethod">Invoke Instance Method</button>

@code {
    private DotNetObjectReference<JsSample> objectReference;

    [JSInvokable]
    public string GetAddress() => "123 Main Street";

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if(firstRender)
        {
            objectReference = DotNetObjectReference.Create(this);
        }
    }

    private async Task CallInstanceMethod()
    {
        await jsRuntime.InvokeVoidAsync("JsFunctionHelper.invokeDotnetInstanceFunction", objectReference);
    }

    public void Dispose()
    {
        objectReference?.Dispose();
    }
}

This solution ensures that your non-static method works by creating a DotNetObjectReference for the component and passing it to the JavaScript runtime.

Step 4: Ensuring the DOM is Updated After Method Call

Once the Blazor method is successfully invoked and the property is updated (e.g., this.PublicToken = publicToken;), you need to ensure that the UI reflects the change. Sometimes, the DOM doesn’t automatically update after the method is invoked, and calling StateHasChanged() will solve this:

[JSInvokable]
public void OnPlaidLinkSuccess(string publicToken)
{
    this.PublicToken = publicToken;
    this.StateHasChanged();  // Ensure the UI is updated
}

This explicitly tells Blazor to re-render the component, which is crucial if the updated state affects the UI directly.

Practical Example: Calling JS Function from Blazor

Here’s a complete example combining everything:

Blazor C# Code:

@page "/plaid"
@inject IJSRuntime jsRuntime
@implements IDisposable

<button @onclick="InitializePlaid">Initialize Plaid</button>

@code {
    private string LinkToken { get; set; }
    private string PublicToken { get; set; }

    private DotNetObjectReference<YourComponent> dotNetRef;

    private async Task InitializePlaid()
    {
        this.LinkToken = await this.apiService.GetPlaidLinkToken();
        dotNetRef = DotNetObjectReference.Create(this);
        await jsRuntime.InvokeVoidAsync("InitializePlaidLink", dotNetRef, this.LinkToken);
    }

    [JSInvokable]
    public void OnPlaidLinkSuccess(string publicToken)
    {
        this.PublicToken = publicToken;
        StateHasChanged();
    }

    public void Dispose()
    {
        dotNetRef?.Dispose();
    }
}

Alternative Ways to Solve JSInvokable Method Issues

  1. Use Static Methods: If you don’t need to reference component state, static methods can be simpler and avoid the need for DotNetObjectReference.
  2. Ensure Asynchronous Calls Are Handled Correctly: Sometimes the issue lies in handling asynchronous calls properly. Ensure all async methods are awaited.
  3. Verify JSInterop Setup: Double-check that the JavaScript function is properly loaded, and ensure there are no errors in the browser’s developer tools.

FAQs on Fixing Blazor JSInvokable Method Not Being Called

Q: What if my Blazor method is not static? How can I handle it?

ANS:
If your Blazor method is non-static, you can pass a reference to your component using DotNetObjectReference.Create(this) and pass it to JavaScript to invoke instance methods properly.

Q: What should I do if the public token is being received but the UI doesn’t update?

ANS:
Call StateHasChanged() to explicitly request a re-render of the component to reflect the updated state in the UI.

Q: Can I use JSInvokable with an async method?

ANS:
Yes, you can, but make sure to properly await the asynchronous operations in both the Blazor and JavaScript code to avoid race conditions.

Q: How can I make sure my JavaScript function is properly loaded?

ANS:
Ensure that the JavaScript file is correctly included in your project and there are no errors in the browser’s console during execution.

Q: What happens if my component reference isn’t disposed?

ANS:
Not disposing of the DotNetObjectReference can cause memory leaks. Always ensure that you dispose of the reference when the component is disposed of.
