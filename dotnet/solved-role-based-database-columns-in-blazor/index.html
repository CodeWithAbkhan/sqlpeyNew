Solved: Role-Based Database Columns in Blazor

Are you struggling to manage role-specific database columns in your Blazor Server app? This guide offers a step-by-step approach to implement role-based views using Azure AD authentication and AuthorizeView. We’ll explore how to access user roles in Razor components like Index.razor and dynamically display fields based on those roles.

Quick Summary

  • Objective: Dynamically display database columns for different user roles in a Blazor Server app.
  • Prerequisite: Azure AD authentication configured with role-based access.
  • Tools: AuthenticationStateProvider, AuthorizeView, and Claims.

What’s the Challenge?

You’ve already implemented a role-based access policy using AuthorizeView in Blazor, and it works great for determining access. However, when you need to display database columns based on specific roles, the question arises:

How do you retrieve and use the roles inside Razor components like Index.razor?

Step-by-Step Implementation

1. Add Policies in Startup.cs

Ensure your policies are defined for role-based access:

services.AddAuthorization(options =>
{
    options.AddPolicy("AppAdmins", policy => 
        policy.RequireRole("Admin", "SuperAdmin", "Owner"));
});

This policy grants access to users with any of the specified roles.

2. AuthorizeView in Main Page

Wrap the main content of your app in an AuthorizeView to control general access:

<AuthorizeView Policy="AppAdmins">
    <Authorized>
        @Body
    </Authorized>
    <NotAuthorized>
        You are not authorized to use this application.
    </NotAuthorized>
</AuthorizeView>

This ensures only users with the specified roles can access the application.

3. Inject AuthenticationStateProvider in Razor Component

Use the AuthenticationStateProvider service to retrieve user roles in Razor components:

Import Required Namespaces

@using System.Security.Claims
@using Microsoft.AspNetCore.Components.Authorization
@inject AuthenticationStateProvider AuthenticationStateProvider

Retrieve User Roles

Inside your component or page (Index.razor):

@code {
    private IEnumerable<string> UserRoles { get; set; }

    protected override async Task OnInitializedAsync()
    {
        var authState = await AuthenticationStateProvider.GetAuthenticationStateAsync();
        var user = authState.User;

        if (user.Identity.IsAuthenticated)
        {
            var claimsIdentity = (ClaimsIdentity)user.Identity;
            var roleClaims = claimsIdentity.FindAll(claimsIdentity.RoleClaimType);
            UserRoles = roleClaims.Select(claim => claim.Value);

            // Display logic based on roles
            foreach (var role in UserRoles)
            {
                Console.WriteLine($"User has role: {role}");
            }
        }
        else
        {
            Console.WriteLine("User is not authenticated.");
        }
    }
}

Explanation:

  • AuthenticationStateProvider.GetAuthenticationStateAsync(): Fetches the current user’s authentication state.
  • user.Identity.IsAuthenticated: Checks if the user is logged in.
  • claimsIdentity.FindAll(claimsIdentity.RoleClaimType): Retrieves all role claims for the user.
  • UserRoles: Holds the list of roles, which can be used to conditionally display content.

4. Display Role-Specific Columns

Using the retrieved roles, filter and display database columns:

@if (UserRoles.Contains("Admin"))
{
    <div>Admin-only Column</div>
}
@if (UserRoles.Contains("SuperAdmin"))
{
    <div>SuperAdmin-only Column</div>
}
@if (UserRoles.Contains("Owner"))
{
    <div>Owner-only Column</div>
}

Practical Example

Here’s a working example of dynamic role-based column filtering:

@if (UserRoles != null)
{
    <table>
        <thead>
            <tr>
                <th>General Column</th>
                @if (UserRoles.Contains("Admin")) <th>Admin Column</th>
                @if (UserRoles.Contains("SuperAdmin")) <th>SuperAdmin Column</th>
                @if (UserRoles.Contains("Owner")) <th>Owner Column</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <td>Common Data</td>
                @if (UserRoles.Contains("Admin")) <td>Admin Data</td>
                @if (UserRoles.Contains("SuperAdmin")) <td>SuperAdmin Data</td>
                @if (UserRoles.Contains("Owner")) <td>Owner Data</td>
            </tr>
        </tbody>
    </table>
}

Alternative Approaches

  1. Custom Claims in Azure AD: Define custom claims in Azure AD to handle complex role-based requirements. Learn more .

  2. External API for Role Validation: Query an external API to validate roles instead of relying solely on claims.

FAQs on Solved: Role-Based Database Columns in Blazor

Q: How do I secure the database access for roles?

ANS: Use server-side validation in addition to client-side role checks.

Q: Can I use other identity providers instead of Azure AD?

ANS: Yes, Blazor supports multiple authentication providers, including IdentityServer.

Q: What happens if a user is not authenticated?

ANS: The application will render the <NotAuthorized> content in AuthorizeView.

Q: Can roles be dynamically updated?

ANS: Yes, roles can be updated in the Azure AD portal and will reflect upon user reauthentication.

Q: Is AuthenticationStateProvider thread-safe?

ANS: Yes, it is designed to handle concurrent operations safely.
