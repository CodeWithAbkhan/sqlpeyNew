We’ll break down the code, explain the logic behind each line, and introduce some alternative methods where applicable. Whether you’re new to Blazor or have some experience, this guide will provide valuable insights to help you manage state and event handling in your Blazor applications.

1. Separate Data and State from the Component

Start by isolating your data and state from the component logic. This separation ensures that your components are focused on UI rendering, while data handling is managed elsewhere.

public class CountryData
{
    public string? Country { get; private set; }

    // Event to notify when the country changes
    public event EventHandler? CountryChanged;

    // Method to update the country and trigger the event
    public void SetCountry(string? value)
    {
        this.Country = value;
        this.CountryChanged?.Invoke(this, EventArgs.Empty);
    }
}

Explanation:

  • CountryData class: Holds the country data and manages its state.
  • CountryChanged event: Triggers whenever the country is updated.
  • SetCountry method: Updates the country and invokes the CountryChanged event.

2. Register the Data Class as a Scoped Service

Register your data class as a scoped service in the dependency injection container. This ensures that the same instance of the service is used across components within the same request.

builder.Services.AddScoped<CountryData>();

Explanation:

  • AddScoped<CountryData>: Registers CountryData as a scoped service, meaning it’s created once per request.

3. Create a Display Component to Show the Data

Next, create a component to display the selected country. This component will listen to changes in the CountryData and update the UI accordingly.

@implements IDisposable
@inject CountryData CountryData

<div class="alert alert-primary m-2">@this.CountryData.Country</div>

@code {

    protected override void OnInitialized()
    {
        // Subscribe to the CountryChanged event
        this.CountryData.CountryChanged += OnCountryChanged;
    }

    private void OnCountryChanged(object? sender, EventArgs e)
    {
        // Refresh the component when the country changes
        this.StateHasChanged();
    }

    public void Dispose()
    {
        // Unsubscribe from the event to prevent memory leaks
        this.CountryData.CountryChanged -= OnCountryChanged;
    }
}

Explanation:

  • OnInitialized method: Subscribes to the CountryChanged event.
  • OnCountryChanged method: Invokes StateHasChanged to refresh the UI when the country changes.
  • Dispose method: Unsubscribes from the event to avoid memory leaks.

4. Implement a Selector Component to Modify the Data

Finally, create a component that allows the user to select a country, which will modify the CountryData.

@inject CountryData CountryData

<div class="bg-light m-2 pt-2 p-4 border border-1">

    <h3>Country Selector</h3>

    <InputSelect class="form-select" @bind-Value:get="this.CountryData.Country" @bind-Value:set="this.CountryData.SetCountry">
        @if (this.CountryData.Country is null)
        {
            <option selected disabled value=""> -- Select a Country -- </option>
        }
        @foreach (var country in CountryProvider.CountryList)
        {
            <option value="@country">@country</option>
        }
    </InputSelect>

</div>

Explanation:

  • InputSelect component: Binds the selected value to CountryData.Country and uses SetCountry to update it.
  • CountryProvider.CountryList: Provides a list of available countries.

Practical Examples

If you’d like to see this pattern in action, consider building a small Blazor app that tracks user selections across different pages. Use the components and patterns described above to manage state and update the UI dynamically.

Alternative Ways

Instead of using a scoped service, you could manage state locally within each component, but this approach might become cumbersome as your application grows. Another alternative is to use a singleton service, but this could lead to issues with shared state across users in a server-side Blazor app.

FAQs on “Top 4 Steps to Implement a Blazor Notification Pattern”

Q: What is a Blazor Notification Pattern?

ANS: A pattern in Blazor used to handle state changes and notify components about these changes efficiently.

Q: Why use scoped services in Blazor?

ANS: Scoped services ensure that the same instance of a service is used within a request, making it ideal for managing per-user or per-session data.

Q: Can I use singleton services instead of scoped services?

ANS: While possible, singleton services may introduce shared state issues in server-side Blazor apps, so scoped services are generally recommended.

Q: How do I avoid memory leaks in Blazor components?

ANS: By unsubscribing from events in the Dispose method, you can prevent memory leaks.

Q: What are some alternatives to the Blazor Notification Pattern?

ANS: You can manage state locally within components or use a singleton service, but these approaches have their trade-offs.
