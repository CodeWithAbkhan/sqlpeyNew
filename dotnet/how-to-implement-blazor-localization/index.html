Localization in Blazor allows your application to support multiple languages and cultural settings seamlessly. This guide explains the step-by-step process to implement localization in Blazor applications, covering resource file organization, dependency injection, and practical examples.

Why Localization is Crucial in Blazor Applications?

Localization is essential for creating user-friendly and globally accessible applications. In Blazor, the IStringLocalizer interface simplifies the management of localized strings. Let’s dive into the following questions to understand and implement Blazor localization effectively:

What Are the Prerequisites for Blazor Localization?

Before starting, ensure you have:

  1. A Blazor Server project.
  2. Basic knowledge of Razor syntax.
  3. A resources directory to store .resx files.

How Do You Configure Localization in Blazor?

Code Walkthrough: Startup.cs

The Startup.cs file plays a vital role in setting up localization. Here’s the code:

public void ConfigureServices(IServiceCollection services)
{
    services.AddLocalization(options => { options.ResourcesPath = "Resources"; });

    services.Configure<RequestLocalizationOptions>(options =>
    {
        var supportedCultures = new List<CultureInfo>
        {
            new CultureInfo("bg-BG"),
            new CultureInfo("en-US")
        };

        options.DefaultRequestCulture = new RequestCulture("bg-BG");
        options.SupportedCultures = supportedCultures;
        options.SupportedUICultures = supportedCultures;
    });

    services.AddRazorPages();
    services.AddServerSideBlazor().AddCircuitOptions(options => { options.DetailedErrors = true; });
}

Explanation:

  1. AddLocalization: Registers localization services with a specified ResourcesPath.
  2. RequestLocalizationOptions: Configures default and supported cultures.
  3. Default Culture: Ensures the application defaults to bg-BG.
  4. AddRazorPages: Enables Razor Pages and Blazor components.

Configuring Middleware in Configure Method

public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    app.UseRequestLocalization(app.ApplicationServices.GetService<IOptions<RequestLocalizationOptions>>().Value);

    if (env.IsDevelopment())
    {
        app.UseDeveloperExceptionPage();
    }
    else
    {
        app.UseExceptionHandler("/Error");
        app.UseHsts();
    }

    app.UseHttpsRedirection();
    app.UseStaticFiles();
    app.UseRouting();

    app.UseEndpoints(endpoints =>
    {
        endpoints.MapRazorPages();
        endpoints.MapBlazorHub();
        endpoints.MapFallbackToPage("/_Host");
    });
}

Key Points:

  • The middleware UseRequestLocalization ensures proper culture settings are applied.

How Do You Use Resource Files for Localization in Blazor?

Resource File Structure

Organize .resx files under the Resources folder:

Project
│-- Resources
│   │-- Pages
│   │   │-- Account
│   │       │-- Login.bg-BG.resx

How to Use IStringLocalizer in Razor Components?

Here’s an example of using IStringLocalizer in a Razor page:

Login.razor

@page "/login"
@using Microsoft.Extensions.Localization
@inject IStringLocalizer<Login> Localizer

<button type="submit" class="btn btn-primary w-100">@Localizer["LoginButtonText"]</button>

Explanation:

  1. @inject: Injects IStringLocalizer for the Login component.
  2. @Localizer["Key"]: Accesses localized strings.

How to Dynamically Change Culture in Blazor?

Change the culture programmatically using the CultureInfo class:

CultureInfo.DefaultThreadCurrentUICulture = new CultureInfo("cs-CZ");

This ensures the UI reflects the desired culture.

Are There Alternative Ways to Implement Localization?

Using Libraries

Consider libraries like Blazored.Localisation to streamline localization setup and usage.

Practical Examples: Localized Razor Page

Index.razor Example

@page "/"
@using System.Globalization
@inject Microsoft.Extensions.Localization.IStringLocalizer<Index> Localizer

<h1>Localization Test</h1>
<p>Localized Field: @(Localizer["Field1"])</p>

@code {
    [Inject]
    public IStringLocalizer<Index> Localizer { get; set; }
}

Store the .resx files as follows:

  • Resources\Pages\Index.resx
  • Resources\Pages\Index.bg-BG.resx

Key Takeaways

  • Use IStringLocalizer<T> for accessing localized strings.
  • Organize .resx files under a centralized Resources folder.
  • Use CultureInfo for dynamic culture changes.
  • Middleware in Startup.cs ensures proper culture settings.

FAQs on How-to-Implement-Blazor-Localization

Q: What is the purpose of the `Resources` folder?

ANS: It stores .resx files containing localized strings for the application.

Q: How do I inject a localizer into a Razor page?

ANS: Use the @inject IStringLocalizer<T> directive to access localized strings in a component.

Q: How can I change the culture dynamically in Blazor?

ANS: Use CultureInfo.DefaultThreadCurrentUICulture = new CultureInfo("desired-culture").

Q: Can I use localization libraries in Blazor?

ANS: Yes, libraries like Blazored.Localisation can simplify localization.

Q: Is it necessary to use `RequestLocalizationOptions`?

ANS: Yes, it configures default and supported cultures for the application.
