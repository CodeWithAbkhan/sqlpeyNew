When developing a Blazor app, you might find yourself in a situation where you need to share global objects—such as a CUSTOMER object—across multiple pages or components. In this article, we’ll explore several methods for persisting and passing global data between different components in your Blazor app. Whether you’re using Blazor WebAssembly (WASM) or Blazor Server, we’ll cover the most effective strategies to store and share global objects while ensuring a seamless user experience.

Summary

This article delves into different strategies for persisting and passing global objects in a Blazor application, including the use of:

  • SessionStorage to persist state even after browser refreshes.
  • StateManager service for easy state management across pages and components.
  • StateContainer for shared state in both Blazor WebAssembly and Blazor Server.
  • Browser storage (localStorage) and how it differs from sessionStorage.
  • Data binding across multiple components, allowing for a fluid one-way data flow.

We will also discuss practical examples for each of these approaches and provide code snippets to illustrate how to implement them in your Blazor project.

1. Should I Use SessionStorage for Persisting Global Objects in Blazor?

SessionStorage is a good option if you need to persist state even after a browser refresh. It’s especially useful for applications that do not require persistent data across sessions, but rather just for the duration of the user’s session.

How does SessionStorage work in Blazor?

You can use SessionStorage to save a global object like the CUSTOMER object. In Blazor WebAssembly, you can directly interact with SessionStorage using JavaScript Interop or a third-party package. Here’s how you can do it:

Example:

@inject IJSRuntime JSRuntime

<button @onclick="SaveToSessionStorage">Save Customer to SessionStorage</button>
<button @onclick="RetrieveFromSessionStorage">Retrieve Customer from SessionStorage</button>

@code {
    private string customerName;

    private async Task SaveToSessionStorage()
    {
        var customer = new { Name = "John Doe", Age = 30 };
        await JSRuntime.InvokeVoidAsync("sessionStorage.setItem", "customer", JsonSerializer.Serialize(customer));
    }

    private async Task RetrieveFromSessionStorage()
    {
        var customerJson = await JSRuntime.InvokeAsync<string>("sessionStorage.getItem", "customer");
        var customer = JsonSerializer.Deserialize<dynamic>(customerJson);
        customerName = customer?.Name ?? "No customer found!";
    }
}

In this example, we are saving a CUSTOMER object to SessionStorage and retrieving it using JavaScript Interop. This allows us to persist the object across pages during the user’s session.

Note: SessionStorage persists only for the duration of the session and the data is cleared when the browser is closed.

2. Can I Use a Service Like StateManager for Persistent Global Objects?

Yes, you can use a StateManager service to easily manage and persist global objects across multiple components or pages. This approach is particularly useful in Blazor Server-side and Blazor WebAssembly applications.

In this approach, the StateManager keeps track of global data in a service, and components can inject and modify the state as needed.

Example of Implementing a StateManager:

public class StateManager
{
    public string CustomerName { get; set; } = "John Doe";
    public event Action OnChange;

    public void SetCustomerName(string name)
    {
        CustomerName = name;
        NotifyStateChanged();
    }

    private void NotifyStateChanged() => OnChange?.Invoke();
}

You can register this service in Program.cs (for WebAssembly) or Startup.cs (for Server-side) as follows:

builder.Services.AddSingleton<StateManager>();

Then, inject and use it in your components:

@page "/component1"
@inject StateManager StateManager

<p>Customer Name: @StateManager.CustomerName</p>
<button @onclick="ChangeCustomerName">Change Name</button>

@code {
    private void ChangeCustomerName()
    {
        StateManager.SetCustomerName("Jane Smith");
    }
}

Key Points:

  • Singleton Service: This will persist state across multiple components and pages. Make sure to validate the user if you use Singleton for user-specific data.
  • Scoped Service: If you only need the state to persist during the session, you can use a Scoped Service, but it will not survive a browser refresh.

3. Is localStorage a Good Alternative to SessionStorage?

localStorage offers a persistent storage option that lasts even after the user closes the browser or navigates away. If your app requires persistence across sessions, localStorage is a good option.

However, be cautious, as localStorage is accessible by JavaScript on the client side, and users can tamper with its contents. For sensitive data, consider encrypting the stored objects.

Example of Using localStorage:

@inject IJSRuntime JSRuntime

<button @onclick="SaveToLocalStorage">Save Customer to localStorage</button>
<button @onclick="RetrieveFromLocalStorage">Retrieve Customer from localStorage</button>

@code {

    {
        var customer = new { Name = "Alice", Age = 25 };

    }

    private async Task RetrieveFromLocalStorage()
    {
        var customerJson = await JSRuntime.InvokeAsync<string>("localStorage.getItem", "customer");
        var customer = JsonSerializer.Deserialize<dynamic>(customerJson);
        customerName = customer?.Name ?? "No customer found!";
    }
}

4. How to Use an In-Memory State Container for Global Object Persistence?

An In-Memory State Container is a simple service you can use to hold global state in your Blazor app. It is ideal for passing state between components without relying on browser storage. This method is often the simplest and most straightforward for managing state.

Example of In-Memory State Container:

public class StateContainer
{
    public string Property { get; set; } = "Initial value";

    public event Action OnChange;

    public void SetProperty(string value)
    {
        Property = value;
        NotifyStateChanged();
    }

    private void NotifyStateChanged() => OnChange?.Invoke();
}

Register this service in Program.cs (WebAssembly) or Startup.cs (Server-side):

builder.Services.AddSingleton<StateContainer>();

In components:

@inject StateContainer StateContainer

<p>Current Value: @StateContainer.Property</p>
<button @onclick="ChangeValue">Change Value</button>

@code {
    private void ChangeValue()
    {
        StateContainer.SetProperty("Updated Value");
    }
}

5. Can I Bind Data Across Multiple Components in Blazor?

Blazor supports two-way data binding across multiple components, allowing you to share data easily between parent and child components. This is a great way to propagate changes from one component to another.

Example of Two-Way Binding:

@page "/parent"
@inject StateContainer StateContainer

<h3>Parent Component</h3>
<p>Current Value: @StateContainer.Property</p>
<ChildComponent @bind-ChildMessage="StateContainer.Property" />

@code {
    // Parent component's code
}

In the child component:

@code {
    [Parameter] public string ChildMessage { get; set; }
    [Parameter] public EventCallback<string> ChildMessageChanged { get; set; }

    private async Task ChangeMessage()
    {
        await ChildMessageChanged.InvokeAsync($"Changed at {DateTime.Now}");
    }
}

In this example, the child component’s state is automatically reflected in the parent component via two-way binding.

FAQs on Persisting Global Objects in Blazor

Q: What is the best method to persist a global object in a Blazor WebAssembly app?

ANS:
For Blazor WebAssembly, using a service like StateManager is often the easiest and most scalable solution. If you need persistence across browser refreshes, consider using SessionStorage or localStorage, although these have limitations such as potential tampering by the client.

Q: How do I pass data between multiple components in Blazor?

ANS:
You can pass data between components using two-way data binding. For more advanced state management, consider using a service like StateManager or StateContainer to share state across components.

Q: Can I use `SessionStorage` and `localStorage` in Blazor?

ANS:
Yes, you can use both SessionStorage and localStorage in Blazor, but you’ll need to utilize JavaScript Interop to interact with these browser storage options. Be sure to handle data securely, as users can modify the content stored in these storage options.

Q: When should I use an In-Memory State Container?

ANS:
An In-Memory State Container is ideal when you need to manage application state within a session or a specific user context, without relying on browser storage. It’s simple and fast for passing data between components.
