New Capabilities of .NET 8 with Aspire Integration

Cloud-native applications have become a key focus in modern software development due to their ability to leverage the scalability, reliability, and flexibility that the cloud provides. However, for many .NET developers, the journey to creating fully cloud-native applications has traditionally been fraught with complexity and challenges.

.NET 8 introduces Aspire, a powerful new integration that simplifies the process of building, deploying, and managing cloud-native applications. Aspire offers a streamlined developer experience by providing pre-configured templates, orchestration tools, and resilient services for cloud environments, allowing developers to focus more on application logic and less on infrastructure.

In this article, we’ll explore the steps involved in transforming a full-stack .NET application into a cloud-native solution using .NET Aspire.

What is Cloud Native?

To better understand how Aspire fits into the cloud-native ecosystem, let’s first define what “cloud-native” means.

A cloud-native application is an app specifically designed to run in cloud environments, maximizing the benefits of distributed computing, such as elasticity, scalability, and fault tolerance. Unlike traditional monolithic applications, cloud-native apps are typically microservices-based, stateless, and containerized, making them easy to deploy and manage across various environments.

For example, imagine a basic e-commerce platform with the following architecture:

  1. Frontend UI: Accessible through a web browser.
  2. Backend API: Powers the frontend by handling data requests and updates.
  3. Database: Stores product information.
  4. File Storage: Manages product images or other static assets.

Transitioning such an application into a cloud-native environment involves addressing several key challenges:

  • Service Discovery: Ensuring that services (frontend, backend, etc.) can dynamically discover and communicate with each other.
  • Resilience: Implementing fault-tolerant mechanisms to recover from server or network failures.
  • Scalability: Automatically scaling resources up or down based on load to maintain performance.
  • Observability: Providing insights into the health and performance of the app in production.
  • Deployment: Streamlining deployment pipelines to make app updates faster and more reliable.

.NET Aspire simplifies these tasks by offering built-in support for service orchestration, observability, and configuration management, helping developers build cloud-native applications with ease.

Introducing .NET Aspire

.NET Aspire is an opinionated framework within .NET 8 that provides a consistent, cloud-ready stack designed for building observable, resilient, and production-ready cloud-native applications. Aspire helps developers overcome the traditional challenges of building cloud-native solutions by offering:

  • Orchestration: Efficiently manages and connects multiple projects within your solution.
  • Pre-built Components: Simplifies integration with cloud services like databases, storage, and more, via pre-configured components.
  • Tooling & Templates: Project templates and CLI tooling that set up cloud-native features, such as health checks and observability, from the start.

With these features, developers no longer need to worry about service discovery, manual configurations, or complex infrastructure setups, as Aspire handles much of the heavy lifting.

Step 1: Installing .NET Aspire

To start, ensure you have the .NET 8 SDK and Docker Desktop installed, as Docker is essential for containerizing and running services locally. Next, install Aspire with the following commands:

dotnet workload update
dotnet workload install aspire

This will install all the necessary Aspire components and tooling.

Step 2: Adding Aspire Projects

Aspire introduces two core projects to your solution:

  1. App Host: Orchestrates the various services in your application.
  2. Service Defaults: Provides configurations for cloud-native features like resilience, telemetry, and health checks.

Create these projects using Aspire’s CLI:

dotnet new aspire-apphost -n MyApp.AppHost
dotnet new aspire-servicedefaults -n MyApp.ServiceDefaults

Step 3: Enabling Cloud-Native Features

The Service Defaults project contains pre-configured settings that enable health checks, telemetry, and service discovery. To apply these settings, add a reference from your frontend and backend projects to the Service Defaults project and update the Program.cs files with the following:

builder.AddServiceDefaults();
app.MapDefaultEndpoints();

This ensures your application benefits from resilient, cloud-native configurations automatically.

Step 4: Defining Your Application Model

In .NET Aspire, the App Model defines the structure of your cloud-native app, including dependencies between components. Update your AppHost project by referencing both the frontend and backend services:

var builder = DistributedApplication.CreateBuilder(args);

// Configure PostgreSQL and Blob Storage
var postgres = builder.AddPostgres("postgres").AddDatabase("MyAppDB");
var blobs = builder.AddAzureStorage("storage").AddBlobs("myblobs");

// Add backend and frontend projects
builder.AddProject<MyApp_Api>("backend").WithReference(postgres);
builder.AddProject<MyApp_Frontend>("frontend").WithReference(backend).WithReference(blobs);

builder.Build().Run();

This setup orchestrates your cloud-native app, ensuring that services such as databases and storage are provisioned and configured.

Step 5: Utilizing Cloud Services with Aspire Components

Aspire provides out-of-the-box components that allow you to seamlessly integrate cloud services into your application. For instance, the backend API can be configured to use PostgreSQL with just a few lines of code:

dotnet add package Aspire.Npgsql.EntityFrameworkCore.PostgreSQL --prerelease

And in your Program.cs:

builder.AddNpgsqlDbContext<MyAppContext>("MyAppDB");

Similarly, for Azure Blob Storage integration on the frontend:

dotnet add package Aspire.Azure.Storage.Blobs --prerelease

builder.AddAzureBlobService("myblobs");

Step 6: Running Your Cloud-Native Application

Once your services are set up, you can run your cloud-native application locally with Docker support:

dotnet run --project .\MyApp.AppHost

You’ll be greeted with the Aspire dashboard, which displays all the running services, health checks, and dependencies in real time. From here, you can monitor and manage your entire cloud-native solution effortlessly.

Conclusion

.NET Aspire in .NET 8 represents a significant leap forward in simplifying the development of cloud-native applications. By offering built-in tools for orchestration, resiliency, and service integration, Aspire allows developers to focus on building business functionality while the framework handles the complexities of cloud-native architecture. This streamlined approach not only reduces development time but also ensures that your applications are ready for modern cloud environments.

If you’re looking to modernize your .NET applications and tap into the power of the cloud, Aspire is the perfect tool to guide your transformation.
