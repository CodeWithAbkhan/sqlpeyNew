Summary

Is Blazor WebAssembly suitable for production use? In this post, we will dive deep into the current state of Blazor WebAssembly and discuss its suitability for production environments. We will also explore the differences between “hosted” and “non-hosted” Blazor WebAssembly apps, and provide advice on when it’s best to use each version. If you’re considering Blazor for your next web application, this detailed analysis will guide you through the process.

Can Blazor WebAssembly Be Used for Production?

Since its initial launch, Blazor WebAssembly has seen multiple changes and updates, with different support levels. So, can you use Blazor WebAssembly for production applications, or is it too early to adopt for business-critical systems? Let’s explore the options and when it’s best to use Blazor WebAssembly in production.

What Is Blazor WebAssembly?

Blazor WebAssembly allows you to build interactive web applications using C# instead of JavaScript. It runs client-side in the browser via WebAssembly. Since its initial release, Blazor has been in continuous development, with multiple preview versions. But is it production-ready yet? Let’s find out.

What Does “Production Ready” Mean for Blazor WebAssembly?

Microsoft has stated that Blazor WebAssembly was in preview up until ASP.NET Core 3.1, which means it was not fully supported for production use during its early stages. The official support was expected to arrive around May 2020. However, it’s important to note that just because a technology is “not officially supported,” doesn’t mean it can’t be used in a limited production environment.

How do you know if Blazor WebAssembly is appropriate for your production system?

  1. Understand its limitations – Blazor WebAssembly in its earlier versions faced breaking changes, including method name modifications and namespace changes, which required constant updates.

  2. Compatibility and Testing – When using Blazor WebAssembly, you must be prepared for frequent updates and modifications as the technology evolves. If you rely on a pre-release version, keep in mind that breaking changes might still occur.

Can Blazor WebAssembly Be Used for Production Apps?

In its current state, Blazor WebAssembly is usable for small-scale production applications, but not recommended for mission-critical business applications. For example, you could deploy a Blazor WebAssembly application with a limited user base to gather feedback, or use it for projects with a narrow scope where breaking changes are manageable. Here are a few points to consider when deploying Blazor WebAssembly:

  • Small-Scale Production: If you only need Blazor WebAssembly for a small group of users or for non-critical applications, it could work.
  • Lean Startup Approach: Consider using Blazor WebAssembly for early-stage prototypes or MVP (Minimum Viable Products) to gather real-world user feedback.
  • Flexibility: Make sure you have the flexibility to adapt your app based on frequent updates to the framework.

Practical Example of a Blazor WebAssembly App

@page "/counter"

<h3>Counter</h3>

<p>Current count: @count</p>

<button class="btn btn-primary" @onclick="IncrementCount">Increment</button>

@code {
    private int count = 0;

    private void IncrementCount()
    {
        count++;
    }
}

This simple Blazor WebAssembly counter app works client-side, meaning the logic runs entirely in the browser using WebAssembly. While this is a small-scale application, larger, more complex systems might face challenges with performance or compatibility in production.

What Are the Differences Between Hosted and Non-Hosted Blazor WebAssembly Apps?

When creating a Blazor WebAssembly app, you’ll encounter two types of setups:

  1. Blazor WebAssembly (non-hosted) – In this configuration, the Blazor WebAssembly app runs independently in the browser, without relying on a server-side ASP.NET Core backend. It’s ideal for simple apps that don’t require server-side interactions.

  2. Blazor WebAssembly (ASP.NET Core hosted) – This version includes both a Blazor WebAssembly client app and an ASP.NET Core WebAPI backend, allowing for more complex scenarios where the Blazor client app needs to interact with server-side data.

Why choose ASP.NET Core hosted?

  • It integrates seamlessly with APIs and can handle more complex scenarios where data from a backend server is necessary.
  • You can handle both client-side logic and server-side API calls within a single project structure.

Alternative Ways to Deploy Blazor WebAssembly Apps

If you decide to use Blazor WebAssembly in production, here are some alternative deployment methods that may suit your needs:

  1. Self-Hosted Blazor WebAssembly – For smaller, less complex applications where an API is not required, consider using a standalone Blazor WebAssembly app. It can be deployed on static web hosting platforms like GitHub Pages or Netlify.

  2. Azure Hosting – Azure supports both Blazor WebAssembly and Blazor Server apps. For production use, Azure offers powerful tools and services that can ensure reliability, scalability, and performance.

Code Syntax and Explanation

Here’s a breakdown of the Blazor WebAssembly code example provided earlier:

@page "/counter"

<h3>Counter</h3>

<p>Current count: @count</p>

<button class="btn btn-primary" @onclick="IncrementCount">Increment</button>

@code {
    private int count = 0;

    private void IncrementCount()
    {
        count++;
    }
}

Code Breakdown:

  • @page "/counter": This defines the route for the page, i.e., the counter page.
  • @count: This is a dynamic C# expression that binds the count value to the UI, updating the count whenever it changes.
  • @onclick="IncrementCount": This binds the button click event to the IncrementCount method.
  • The IncrementCount method increases the count value by 1 each time the button is clicked.

FAQs on How to Use Blazor WebAssembly for Production

Q: Is Blazor WebAssembly fully production-ready?

ANS: No, Blazor WebAssembly was initially in preview and is only fully supported for production use in later versions. For the most stable experience, consider using it for small-scale or non-critical apps in the meantime.

Q: What is the difference between hosted and non-hosted Blazor WebAssembly?

ANS: A hosted Blazor WebAssembly app includes both the client-side Blazor WebAssembly code and an ASP.NET Core WebAPI backend. A non-hosted version is a standalone Blazor app that doesn’t rely on server-side functionality.

Q: Can I use Blazor WebAssembly for MVPs?

ANS: Yes, Blazor WebAssembly is a great option for MVPs or early-stage prototypes. You can deploy it in production with a limited user base to gather feedback and iterate.

Q: Will there be any breaking changes in future Blazor WebAssembly updates?

ANS: Yes, Blazor WebAssembly has gone through several breaking changes, especially in earlier versions. You should be prepared to update your application when new versions are released.

Q: How does Blazor WebAssembly compare to Blazor Server?

ANS: Blazor Server runs on the server, and UI updates are sent to the client over a SignalR connection. Blazor WebAssembly runs entirely in the browser, which can reduce server load but requires more resources on the client side.
