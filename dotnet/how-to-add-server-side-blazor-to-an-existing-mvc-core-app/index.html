How to Add Server-Side Blazor to an Existing MVC Core App

Integrating Server-Side Blazor components into an existing MVC Core application can enhance functionality by leveraging Blazor’s interactive UI capabilities. However, many developers face challenges when trying to make button clicks and events trigger within an MVC app. In this post, we will walk through the essential steps required to successfully add Server-Side Blazor to an MVC Core 3.0 project.

Summary

If you are working with a Blazor server-side project and an MVC application, both within the same solution, and wish to integrate Blazor components into your MVC pages, follow these steps. We’ll cover the necessary code changes, important configurations, and troubleshooting tips for a smooth integration.

Practical Example: Integrating Blazor Components

Step 1: Referencing the Blazor Project in MVC

In order to use Blazor components in an MVC application, you need to reference your Blazor project. This can be done by modifying the .csproj file of your MVC project:

<ProjectReference Include="..\MyClient.Web.Blazor\MyClient.Web.Blazor.csproj" />

Step 2: Modify the MVC Layout File

To ensure Blazor works correctly in the MVC environment, include the base URL and the Blazor JavaScript file in the _Layout.cshtml file:

<head>
  <meta charset="utf-8" />
  <base href="~/" />
  <script src="_framework/blazor.server.js"></script>
</head>

This sets the base URL for your application and loads the Blazor JavaScript necessary for SignalR communication.

Step 3: Update the Startup Configuration

Add Server-Side Blazor support in the ConfigureServices method of Startup.cs. This step is essential for enabling Blazor components in your MVC app.

services.AddServerSideBlazor();
services.AddControllersWithViews()
        .AddNewtonsoftJson(options =>
        {
            options.SerializerSettings.ContractResolver = new DefaultContractResolver();
        });

services.AddRazorPages();

Next, modify the Configure method to enable endpoint routing:

app.UseRouting();

app.UseEndpoints(endpoints =>
{
    endpoints.MapControllerRoute(
        name: "default",
        pattern: "{controller=Home}/{action=Index}/{id?}");
    endpoints.MapRazorPages();
    endpoints.MapBlazorHub();
});

The key here is adding endpoints.MapBlazorHub() which enables communication between the Blazor server and the browser via SignalR.

Step 4: Add Blazor Components to MVC Pages

Now that the Blazor server-side support is set up, you can add a Blazor component to any MVC page. In your index.cshtml or any other Razor page, use the following syntax:

<div id="Counter">
  @(await Html.RenderComponentAsync<Counter>())
</div>

This will render the Counter component from your Blazor project on the MVC page.

Troubleshooting Common Issues

  1. Button Clicks Not Working
    If the Blazor component renders but button clicks do not trigger actions, it’s likely that endpoints.MapBlazorHub() was not added in the Configure method. Ensure that the Blazor hub is mapped correctly.

  2. Missing JavaScript File
    The blazor.server.js file must be loaded in the browser. You can check this by using developer tools (F12 in Chrome) to confirm that the file is not missing.

  3. Routing Issues
    In some cases, there may be issues with routing, especially in Core 3 Preview versions. Ensure you’re using the updated endpoint routing model. If you’re experiencing 404 errors after navigating between pages with Blazor components, this may be fixed by upgrading to a later version of ASP.NET Core (like Core 5).

Alternative Methods

While the approach discussed here works well for integrating Blazor components into an MVC project, you may also consider the following alternatives:

  1. Single Page Application (SPA) Setup
    If your application grows more complex, you might want to consider switching to a full SPA setup using Blazor WebAssembly instead of server-side Blazor. This involves running Blazor entirely in the browser, providing better performance and scalability.

  2. Use of Blazor as a Standalone Application
    Another approach could involve isolating your Blazor project as a standalone application with its own routing and entry points, rather than embedding it into an MVC app. This would be a more modular approach, where both applications are loosely coupled.

Final Thoughts

Integrating Server-Side Blazor into an MVC Core application can seem like a daunting task, but by following these steps, you can have a working solution in place with minimal effort. Whether you’re using MVC or Blazor components, both technologies can complement each other seamlessly if set up properly.

If you encountered any challenges while following the guide or have suggestions for improvements, feel free to leave your comments below!

FAQs on Adding Server-Side Blazor to MVC Core

Q: What is the first step to integrate Blazor into an MVC Core app?

ANS:
The first step is to add a project reference to your Blazor project within the MVC application’s .csproj file.

Q: Why do I need to include `blazor.server.js` in my MVC layout?

ANS:
The blazor.server.js script is essential for establishing a SignalR connection between the Blazor server and the browser, allowing real-time updates and interactions with Blazor components.

Q: Can I integrate Blazor components on existing MVC pages without converting them into full SPAs?

ANS:
Yes, you can integrate Blazor components directly into MVC pages by rendering them using @(await Html.RenderComponentAsync<YourComponent>()) without needing to convert your application into a SPA.

Q: What should I do if my Blazor component’s button click does not work?

ANS:
Ensure that endpoints.MapBlazorHub() is correctly added to the Configure method in Startup.cs, as this is necessary for handling events and interactions within the Blazor component.

Q: Do I need to add separate NuGet packages for Blazor in my MVC project?

ANS:
No, if you’ve already set up your Blazor project in the solution and are referencing it correctly, you don’t need to add separate NuGet packages for Blazor in the MVC project.
