What’s the Issue with Cryptography in Blazor WASM?

Have you encountered the following error while trying to run a Blazor WebAssembly app?

Unhandled exception rendering component: System.Security.Cryptography.Algorithms is not supported on this platform.
System.PlatformNotSupportedException: System.Security.Cryptography.Algorithms is not supported on this platform.

This error appears because certain cryptographic operations, such as AES (Advanced Encryption Standard), are not supported in Blazor WASM due to limitations of WebAssembly. WebAssembly doesn’t have access to all .NET APIs that are available on server-side or desktop applications.

So, how can you address this issue and still generate secure JWT tokens for your API calls?

Solving the Cryptography Algorithms Error

Why Is the Error Occurring?

The issue occurs because the Blazor WebAssembly platform, running in the browser, doesn’t support certain cryptographic operations such as AES encryption. This means APIs that depend on the System.Security.Cryptography namespace might not function as expected.

Can We Use AES on Blazor WASM?

No, you cannot use AES encryption directly in Blazor WASM as it would expose sensitive cryptographic keys on the client side. It’s important to remember that client-side code cannot securely store or manage encryption keys. This could lead to vulnerabilities where keys are exposed to anyone inspecting the web page or requests.

How Should We Handle JWT Creation in Blazor WASM?

Although generating a JWT on the client side is technically possible, it’s not recommended due to security concerns. In the Blazor WebAssembly application, we cannot safely store secret keys in the browser. Here’s why:

  1. Exposing the Secret Key: If you generate a JWT on the client side, the secret key will need to be stored in the browser, which is a serious security risk.
  2. Access Control: The client should not have access to sensitive operations like signing JWTs. It’s best practice to do this on the server-side.

What’s the Best Way to Handle JWT Creation?

Instead of creating the JWT directly on the client, you should delegate the task to your server. The Blazor WebAssembly app will make a request to your server, and the server will generate and send the JWT back to the client.

How Do We Implement This?

  1. Server-Side JWT Creation: The server will generate the JWT using a secret key and then send it back to the client. The client can then use this token to authenticate API requests.

  2. Client-Side Request: The Blazor WebAssembly client can send the JWT token to the server in the Authorization header for authenticated requests.

Here’s an example of how you can implement JWT creation securely on the server side using C#.

Example: JWT Token Creation on the Server

public class OpenAPISample 
{
    public static void Main() 
    {
        // Define the payload for the JWT
        var payload = new JwtPayload
        {
            { "access_key", "Access Key" },
            { "nonce", Guid.NewGuid().ToString() },
            { "query_hash", queryHash },
            { "query_hash_alg", "SHA512" }
        };

        // Convert the secret key to a byte array
        byte[] keyBytes = Encoding.Default.GetBytes("Secret Key");
        var securityKey = new Microsoft.IdentityModel.Tokens.SymmetricSecurityKey(keyBytes);

        // Create the credentials using HS256 algorithm
        var credentials = new Microsoft.IdentityModel.Tokens.SigningCredentials(securityKey, "HS256");

        // Create the JWT header
        var header = new JwtHeader(credentials);

        // Generate the JWT token
        var secToken = new JwtSecurityToken(header, payload);

        // Write the token to a string
        var jwtToken = new JwtSecurityTokenHandler().WriteToken(secToken);

        // Construct the Authorization header
        var authorizationToken = "Bearer " + jwtToken;
    }
}

Key Explanation of Code

  • JwtPayload: This contains the claims (e.g., access keys, timestamps) that will be included in the JWT.
  • SigningCredentials: This object is used to sign the JWT using the HS256 algorithm and a symmetric security key.
  • JwtSecurityToken: This represents the JWT, combining the header and payload.
  • JwtSecurityTokenHandler: This is used to convert the JWT into a string format that can be used in an HTTP request.

How to Use the JWT Token in HTTP Requests?

Once the JWT is generated, it should be sent to the API in the Authorization header:

request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", jwtToken);

The API will then verify the JWT and grant access to the protected resources.

How Can We Securely Use AES?

Although you can’t use AES directly in Blazor WASM, you can use secure cryptographic methods on the server. The server can encrypt sensitive data and send it to the Blazor client, where it can be decrypted using a public key.

Alternative Ways to Handle JWT in Blazor

If you absolutely must generate the JWT token on the client side, one alternative is to use an external service or server-side proxy that handles the JWT generation securely. This way, the secret key is never exposed to the client.

  • Use an Authentication Proxy: You can route requests through a secure server that generates the JWT tokens on behalf of the client.
  • Implement OAuth 2.0: This allows for secure handling of tokens using authorization servers and avoids the need for the client to handle sensitive keys directly.

FAQs on How to Solve the Blazor WebAssembly Cryptography Algorithms Error

Q: Why can't I use AES encryption in Blazor WASM?

ANS: Blazor WebAssembly runs in the browser, which limits access to certain cryptographic APIs like AES. This is because WebAssembly does not have the ability to securely store or manage cryptographic keys on the client side.

Q: What is the best way to create JWT tokens in a Blazor app?

ANS: It’s best to generate JWT tokens on the server side, not in the Blazor client. The client should request the token from the server and use it for API authentication.

Q: Can I create a JWT token with my secret key in Blazor WASM?

ANS: No, creating a JWT on the client side with a secret key is insecure. The secret key should never be exposed to the client. You should create the JWT on the server.

Q: How can I securely handle encryption keys in Blazor?

ANS: Encryption keys should be managed securely on the server. The client should never have direct access to sensitive keys. Use server-side encryption and token generation instead.

Q: When will Blazor WebAssembly support AES encryption?

ANS: Blazor WebAssembly does not currently support AES encryption, and there is no official timeline for adding this support. It is advised to handle cryptography on the server side.
