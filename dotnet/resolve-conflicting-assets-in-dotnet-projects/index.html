Top 4 Steps to Resolve Conflicting Assets in .NET Projects

When working on multiple .NET projects, such as Blazor and MAUI, you may encounter issues with conflicting assets, particularly CSS files. This can prevent your project from building successfully. In this guide, we’ll walk through the top four steps to resolve these conflicts, ensuring a smooth build process. We’ll provide unique code examples, explain each step in detail, and offer practical examples and alternative methods.

Top 4 Steps to Resolve Conflicting Assets

in .NET Projects

Step 1: Identify Conflicting Assets

Start by identifying the conflicting assets in your projects. Usually, this occurs when two projects try to publish files with the same name to the same location in the output directory.

<ItemGroup>
  <Content Update="wwwroot\css\app.css">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </Content>
</ItemGroup>

Explanation: In this .csproj file, the app.css file is marked to be copied to the output directory. If both Blazor and MAUI projects have similar configurations, a conflict arises.

Step 2: Rename CSS Files

Rename one of the conflicting CSS files to avoid duplication. Ensure that all references to this file in your code are updated accordingly.

<ItemGroup>
  <Content Update="wwwroot\css\client-app.css">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </Content>
</ItemGroup>

Explanation: Here, we rename app.css to client-app.css in the Blazor project. Update all references to this file in your Razor components.

Step 3: Use Preprocessor Directives

Use preprocessor directives to conditionally include different CSS files based on the build configuration. This allows you to maintain separate styles for different projects without conflicts.

#if CLIENT
    <link href="css/client-app.css" rel="stylesheet" />
#elif MOBILE
    <link href="css/mobile-app.css" rel="stylesheet" />
#endif

Explanation: In your Razor components or MAUI views, use preprocessor directives to include the appropriate CSS file based on the build configuration.

Step 4: Exclude Unnecessary Files

If the secondary project does not need certain CSS files, configure the project to exclude these files from the output directory.

<ItemGroup>
  <Content Update="wwwroot\css\app.css" Exclude="**" />
</ItemGroup>

Explanation: In the MAUI project’s .csproj file, exclude app.css from being copied to the output directory. This prevents conflicts with the Blazor project.

Practical Example

Let’s put the above steps into practice with a real example:

Blazor Project (Client)

Update the Blazor project’s .csproj file:

<ItemGroup>
  <Content Update="wwwroot\css\client-app.css">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </Content>
</ItemGroup>

In your Blazor components:

#if CLIENT
    <link href="css/client-app.css" rel="stylesheet" />
#endif

MAUI Project (Mobile)

Update the MAUI project’s .csproj file:

<ItemGroup>
  <Content Update="wwwroot\css\mobile-app.css">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </Content>
  <Content Update="wwwroot\css\app.css" Exclude="**" />
</ItemGroup>

In your MAUI views:

#if MOBILE
    <link href="css/mobile-app.css" rel="stylesheet" />
#endif

Alternative Methods

If renaming and excluding files isn’t feasible, consider these alternatives:

  • Use Different Output Directories: Configure projects to publish their output to separate directories, avoiding conflicts altogether.
  • External Identity Providers: Utilize external identity providers like Azure AD B2C or Auth0 that support managing different assets efficiently.
