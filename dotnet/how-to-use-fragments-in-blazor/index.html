In Blazor, a fragment is a small piece or “chunk” of HTML content that can be passed from one component to another. These fragments are handled using a special type of delegate called RenderFragment. This article dives deep into how fragments work in Blazor, how to use RenderFragment, and practical examples demonstrating its power in creating reusable and dynamic components.

What are Fragments in Blazor?

A fragment in Blazor is essentially a chunk of HTML, Razor markup, or even other components, that can be passed around and rendered dynamically. The concept is enabled by a RenderFragment, which acts like a delegate that contains the code to render a piece of UI content. This allows you to pass HTML or Razor markup from a parent component to a child component.

Why Are Fragments Useful in Blazor?

Fragments are a powerful tool in Blazor for making components more flexible and reusable. Instead of hardcoding content inside components, you can pass fragments as parameters and render them in the component’s view. This can make your components more dynamic, allowing you to customize the content without altering the component’s logic.

How to Use RenderFragment in Blazor

Let’s explore how you can implement fragments in Blazor using the RenderFragment delegate.

Step-by-Step Code Example:

1. Parent Component: Index.razor

In this example, we have a parent component Index.razor that passes HTML content to a child component TestComponent.

@page "/"

<h1>Hello, world!</h1>

<TestComponent>
    <p>Get ready for a new era in Web development</p>
</TestComponent>
  • The @page "/" directive defines the route for the page.
  • The parent Index.razor includes a child component <TestComponent>.
  • The content inside <TestComponent> (i.e., <p>Get ready for a new era in Web development</p>) is passed as a fragment to the TestComponent.
2. Child Component: TestComponent.razor

In the child component TestComponent.razor, we define a parameter of type RenderFragment that will hold the passed fragment content.

<div>@ChildContent</div>

@code
{
    [Parameter]
    public RenderFragment ChildContent { get; set; }
}
  • The ChildContent parameter is of type RenderFragment. This is where the parent component’s content is passed.
  • Inside the TestComponent, the fragment is rendered within a <div> element, which allows the parent content (like the <p> tag) to be displayed inside this <div>.

Explanation of the Code:

  1. Parent Component (Index.razor):

    • The parent defines a <TestComponent> and passes HTML content (the <p> tag) inside the component tags.
    • This content is not directly handled by the parent but is passed as a fragment for dynamic rendering in the child component.

  2. Child Component (TestComponent.razor):

    • The ChildContent parameter is declared to accept a RenderFragment, which is a delegate type for rendering UI content.
    • The fragment passed from the parent is rendered inside the <div> in the child component using @ChildContent.

  3. Rendered Output:

    • When the Blazor app runs, the HTML content passed from the parent (<p>Get ready for a new era in Web development</p>) is dynamically rendered inside the <div> in the child component.

Practical Example: Customizing Components with Fragments

Fragments allow you to create highly customizable components. Let’s see a scenario where you create a reusable component that takes dynamic content as a fragment.

Example: Reusable Card Component

Create a reusable card component that accepts dynamic content for the card body.

  1. CardComponent.razor:
<div class="card">
    <div class="card-header">
        <h3>@Title</h3>
    </div>
    <div class="card-body">
        @CardContent
    </div>
</div>

@code
{
    [Parameter] public string Title { get; set; }
    [Parameter] public RenderFragment CardContent { get; set; }
}
  1. Using the CardComponent in a Parent Component:
@page "/cards"

<CardComponent Title="Blazor Introduction">
    <p>This is a powerful UI framework built on .NET.</p>
</CardComponent>

<CardComponent Title="Advanced Blazor">
    <p>Learn how to build dynamic and responsive web applications with Blazor.</p>
</CardComponent>
  • The CardComponent accepts dynamic content for its body using the RenderFragment CardContent parameter.
  • In the parent component, you pass different content inside each <CardComponent>.

Alternative Ways to Use Fragments

  1. Fragment as a Delegate: You can pass fragments as delegates to invoke specific behavior when rendering, allowing for even more flexibility. This is useful when you need to pass entire components as fragments.

  2. Nested Fragments: You can nest fragments inside other fragments, creating hierarchical layouts that can be dynamically customized by parent components.

FAQs on How to Use Fragments in Blazor

Q: What is a `RenderFragment` in Blazor?

ANS: A RenderFragment in Blazor is a delegate that represents a chunk of UI content. It can contain HTML, Razor markup, or even other components, and it allows content to be dynamically passed between components.

Q: How do I pass dynamic content to a Blazor component?

ANS: You can pass dynamic content to a Blazor component using the RenderFragment parameter. The content is provided by the parent component and rendered in the child component.

Q: Can I nest `RenderFragment` elements in Blazor?

ANS: Yes, RenderFragment elements can be nested within each other, allowing for complex and reusable layouts that can be customized dynamically by parent components.

Q: How do I create a reusable component with `RenderFragment`?

ANS: To create a reusable component with RenderFragment, define a RenderFragment parameter in the component, and pass the content to it when using the component. This enables dynamic content rendering within the component.

Q: What is the difference between `RenderFragment` and `RenderFragment<T>`?

ANS: RenderFragment is used to pass a simple fragment of UI, while RenderFragment<T> allows you to pass a fragment that is parameterized, making it more flexible for different data types.
