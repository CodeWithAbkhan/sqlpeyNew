“Handle ASP.NET MVC MaxJsonLength Exceeded Errors with Diverse Solutions”

Encountering the “Error during deserialization using the JSON JavaScriptSerializer. The length of the string exceeds the value set on the maxJsonLength property” in ASP.NET MVC can halt your application’s data flow. This typically occurs when attempting to serialize or deserialize JSON data that exceeds the default size limit configured for the JavaScriptSerializer. This question explores various solutions to overcome this limitation, ensuring your application can handle larger JSON payloads effectively.

Solution 1: Modifying web.config for Global JSON Length Limit

A common approach involves adjusting the MaxJsonLength property within your application’s web.config file. This setting influences the JavaScriptSerializer instances used for asynchronous communication with web services.

If you are returning JSON from a Controller method and facing this issue, consider this web.config adjustment:

<configuration>
   <system.web.extensions>
       <scripting>
           <webServices>
               <jsonSerialization maxJsonLength="50000000"/>
           </webServices>
       </scripting>
   </system.web.extensions>
</configuration>

This configuration sets the maxJsonLength to 50MB. For situations where the “Unrecognized configuration section system.web.extensions” error occurs, ensure the relevant section group is defined in your web.config:

<configuration>
    <configSections>
        <sectionGroup name="system.web.extensions" type="System.Web.Extensions, System.Web.Extensions, Version=4.0.0.0, Culture=neutral, PublicKeyToken=31bf3856ad364e35">
          <sectionGroup name="scripting" type="System.Web.Extensions, System.Web.Extensions, Version=4.0.0.0, Culture=neutral, PublicKeyToken=31bf3856ad364e35">
                <sectionGroup name="webServices" type="System.Web.Extensions, System.Web.Extensions, Version=4.0.0.0, Culture=neutral, PublicKeyToken=31bf3856ad364e35">
                      <section name="jsonSerialization" type="System.Web.Extensions, System.Web.Extensions, Version=4.0.0.0, Culture=neutral, PublicKeyToken=31bf3856ad364e35"/>
                </sectionGroup>
          </scripting>
        </sectionGroup>
    </configSections>
    <system.web.extensions>
        <scripting>
            <webServices>
                <jsonSerialization maxJsonLength="50000000"/>
            </webServices>
        </scripting>
    </system.web.extensions>
</configuration>

Solution 2: Programmatic Control of MaxJsonLength

When the web.config settings aren’t sufficient or you need more granular control, you can set MaxJsonLength directly within your Controller actions. This is particularly useful if you’re not using a web service method for JavaScript serialization or if your MVC action methods are the source of the issue.

You can instantiate a JavaScriptSerializer and set its MaxJsonLength property:

var serializer = new JavaScriptSerializer();
// Use Int32.MaxValue for the largest possible value
serializer.MaxJsonLength = Int32.MaxValue;

var resultData = new { Value = "sampleValue", Text = "sampleText" };
var result = new ContentResult
{
    Content = serializer.Serialize(resultData),
    ContentType = "application/json"
};
return result;

Alternatively, if you are returning a JsonResult or ContentResult, you can assign the MaxJsonLength directly to the result object:

public ActionResult GetData()
{
   var superLargeData = GetSuperLargeData(); // Your large data object
   var jsonResult = Json(superLargeData, JsonRequestBehavior.AllowGet);
   jsonResult.MaxJsonLength = int.MaxValue; // Set to maximum possible value
   return jsonResult;
}

For MVC 4 and later, you can override the Json method in your controller to set MaxJsonLength:

protected override JsonResult Json(object data, string contentType, System.Text.Encoding contentEncoding, JsonRequestBehavior behavior)
{
    return new JsonResult()
    {
        Data = data,
        ContentType = contentType,
        ContentEncoding = contentEncoding,
        JsonRequestBehavior = behavior,
        MaxJsonLength = Int32.MaxValue // Set to maximum allowed value
    };
}

// Example usage:
// Json(new { field1 = true, field2 = "value" }, "application/json", Encoding.UTF8, JsonRequestBehavior.AllowGet);

Solution 3: Custom ValueProviderFactory for Large JSON Inputs

If the error occurs during JSON deserialization of incoming requests (e.g., when binding model properties), you might need a custom ValueProviderFactory. This approach intercepts the incoming JSON, allows for a larger MaxJsonLength during deserialization, and then integrates it back into the MVC pipeline.

Here’s an example of a LargeJsonValueProviderFactory:

using System;
using System.Collections;
using System.Collections.Generic;
using System.Configuration;
using System.Globalization;
using System.IO;
using System.Web;
using System.Web.Mvc;
using System.Web.Script.Serialization;

public sealed class LargeJsonValueProviderFactory : ValueProviderFactory
{
    private static void AddToBackingStore(EntryLimitedDictionary backingStore, string prefix, object value)
    {
        IDictionary<string, object> dictionary = value as IDictionary<string, object>;
        if (dictionary != null)
        {
            foreach (KeyValuePair<string, object> keyValuePair in dictionary)
                LargeJsonValueProviderFactory.AddToBackingStore(backingStore, LargeJsonValueProviderFactory.MakePropertyKey(prefix, keyValuePair.Key), keyValuePair.Value);
        }
        else
        {
            IList list = value as IList;
            if (list != null)
            {
                for (int index = 0; index < list.Count; ++index)
                    LargeJsonValueProviderFactory.AddToBackingStore(backingStore, LargeJsonValueProviderFactory.MakeArrayKey(prefix, index), list[index]);
            }
            else
                backingStore.Add(prefix, value);
        }
    }

    private static object GetDeserializedObject(ControllerContext controllerContext)
    {
        if (!controllerContext.HttpContext.Request.ContentType.StartsWith("application/json", StringComparison.OrdinalIgnoreCase))
            return null;

        string end = new StreamReader(controllerContext.HttpContext.Request.InputStream).ReadToEnd();
        if (string.IsNullOrEmpty(end))
            return null;

        var serializer = new JavaScriptSerializer { MaxJsonLength = Int32.MaxValue };
        return serializer.DeserializeObject(end);
    }

    public override IValueProvider GetValueProvider(ControllerContext controllerContext)
    {
        if (controllerContext == null)
            throw new ArgumentNullException("controllerContext");

        object deserializedObject = LargeJsonValueProviderFactory.GetDeserializedObject(controllerContext);
        if (deserializedObject == null)
            return null;

        var dictionary = new Dictionary<string, object>(StringComparer.OrdinalIgnoreCase);
        LargeJsonValueProviderFactory.AddToBackingStore(new EntryLimitedDictionary(dictionary), string.Empty, deserializedObject);
        return new DictionaryValueProvider<object>(dictionary, CultureInfo.CurrentCulture);
    }

    private static string MakeArrayKey(string prefix, int index)
    {
        return prefix + "[" + index.ToString(CultureInfo.InvariantCulture) + "]";
    }

    private static string MakePropertyKey(string prefix, string propertyName)
    {
        if (!string.IsNullOrEmpty(prefix))
            return prefix + "." + propertyName;
        return propertyName;
    }

    private class EntryLimitedDictionary
    {
        private static int _maximumDepth = EntryLimitedDictionary.GetMaximumDepth();
        private readonly IDictionary<string, object> _innerDictionary;
        private int _itemCount;

        public EntryLimitedDictionary(IDictionary<string, object> innerDictionary)
        {
            this._innerDictionary = innerDictionary;
        }

        public void Add(string key, object value)
        {
            if (++this._itemCount > EntryLimitedDictionary._maximumDepth)
                throw new InvalidOperationException("JsonValueProviderFactory_RequestTooLarge");
            this._innerDictionary.Add(key, value);
        }

        private static int GetMaximumDepth()
        {
            NameValueCollection appSettings = ConfigurationManager.AppSettings;
            if (appSettings != null)
            {
                string[] values = appSettings.GetValues("aspnet:MaxJsonDeserializerMembers");
                int result;
                if (values != null && values.Length > 0 && int.TryParse(values[0], out result))
                    return result;
            }
            return 1000;
        }
    }
}

Register this factory in your Global.asax.cs Application_Start method:

protected void Application_Start()
{
    // ... other configurations

    // Replace the default JsonValueProviderFactory
    var jsonFactoryToRemove = ValueProviderFactories.Factories.OfType<System.Web.Mvc.JsonValueProviderFactory>().Single();
    ValueProviderFactories.Factories.Remove(jsonFactoryToRemove);
    ValueProviderFactories.Factories.Add(new LargeJsonValueProviderFactory());
}

Solution 4: Using Int32.MaxValue Directly

A straightforward method, especially for specific instances, is to directly set the MaxJsonLength to Int32.MaxValue. This bypasses any configuration limits for that particular serializer instance.

JavaScriptSerializer serializer = new JavaScriptSerializer();
serializer.MaxJsonLength = Int32.MaxValue;
// Use the serializer to deserialize or serialize your large JSON object

This can also be applied directly to a JsonResult:

public JsonResult GetBigJson()
{
    var someBigObject = GetBigObject(); // Your large data
    var jsonResult = Json(someBigObject, JsonRequestBehavior.AllowGet);
    jsonResult.MaxJsonLength = int.MaxValue; // Set to maximum possible value
    return jsonResult;
}

Solution 5: Custom Attribute for MaxJsonLength

For a more reusable solution, you can create an ActionFilterAttribute to control MaxJsonLength. This allows you to apply the setting to specific actions or controllers.

[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, Inherited = true, AllowMultiple = false)]
public class MaxJsonSizeAttribute : ActionFilterAttribute
{
    // Default to 10MB for example
    private int maxLength = 10 * 1024 * 1024;

    public int MaxLength
    {
        set
        {
            if (value < 0) throw new ArgumentOutOfRangeException("value", "Value must be at least 0.");
            maxLength = value;
        }
        get { return maxLength; }
    }

    public override void OnActionExecuted(ActionExecutedContext filterContext)
    {
        var jsonResult = filterContext.Result as JsonResult;
        if (jsonResult != null)
        {
            jsonResult.MaxJsonLength = (maxLength == 0) ? int.MaxValue : maxLength;
        }
    }
}

Apply this attribute to your actions or controllers:

[MaxJsonSize(MaxLength = 20000000)] // Set to 20MB
public ActionResult MyActionWithLargeJson()
{
    // ... return large JSON data
}

Solution 7: Paging Large Datasets

A more fundamental approach, and often a better design practice, is to avoid sending excessively large amounts of data in a single request. Implement paging on your server-side data retrieval.

public JsonResult GetPagedObjects(int pageNumber = 0, int pageSize = 1000)
{
    var data = _repository.MyObjects
                          .OrderBy(obj => obj.ID)
                          .Skip(pageSize * pageNumber)
                          .Take(pageSize)
                          .ToList();
    return Json(data, JsonRequestBehavior.AllowGet);
}

In your JavaScript, you would then make subsequent requests to fetch the next pages of data as needed.

// Assuming 'request' is the Kendo UI DataSource request object

Solution 13: WebForms UpdatePanel Specific Settings

For ASP.NET WebForms applications using UpdatePanel, the aspnet:UpdatePanelMaxScriptLength setting in appSettings can be critical:

<configuration>
  <appSettings>
    <add key="aspnet:UpdatePanelMaxScriptLength" value="2147483647" />
  </appSettings>
</configuration>

This setting impacts how the JavaScriptSerializer handles script blocks generated by UpdatePanel.

FAQs on ASP.NET MVC MaxJsonLength Exceeded Errors

Q: What is the default MaxJsonLength in ASP.NET MVC

ANS: The default MaxJsonLength for JavaScriptSerializer is 102,400 characters, which is approximately 2MB of Unicode string data.

Q: Can I set MaxJsonLength to unlimited

ANS: There isn’t an “unlimited” value. The maximum practical value is Int32.MaxValue, which represents the maximum value for a 32-bit signed integer.

Q: Why does web.config setting not work for MVC action methods

ANS: The web.config setting for maxJsonLength primarily affects the JavaScriptSerializer instances used by the asynchronous communication layer for web services. Direct use in MVC action methods or controllers might not automatically pick up this setting, necessitating programmatic adjustments.

Q: How to handle extremely large datasets from a database

ANS: For very large datasets, it’s generally recommended to implement server-side paging, filtering, and sorting to reduce the amount of data transferred in a single request. This improves performance and user experience.

Q: What happens if MaxJsonLength is set too high

ANS: Setting MaxJsonLength excessively high can lead to performance issues, increased memory consumption, and potential denial-of-service vulnerabilities if not managed carefully. It’s advisable to set it to the minimum value required for your application’s needs.
