“SQL Ranking Techniques: Generate Row Numbers and Ranks Efficiently”

Generating sequential numbers or ranks for rows in a SQL table is a common requirement for analysis and reporting. This can involve assigning a simple row number, a rank that accounts for ties (like RANK() or DENSE_RANK()), or applying these rankings within specific partitions of the data. Different database systems offer various methods, from user-defined variables to dedicated window functions.

SQL Ranking Techniques

Here are several methods to achieve row numbering and ranking in SQL, with explanations and examples.

Solution 1: Using User-Defined Variables for Sequential Ranking

This approach uses a user-defined variable to increment a counter as rows are processed. It’s a common technique, especially in older MySQL versions.

Sample Data Setup
CREATE TABLE person (
    id INT PRIMARY KEY,
    first_name VARCHAR(20),
    age INT,
    gender CHAR(1)
);

INSERT INTO person (id, first_name, age, gender) VALUES
(1, 'Bob', 25, 'M'),
(2, 'Jane', 20, 'F'),
(3, 'Jack', 30, 'M'),
(4, 'Bill', 32, 'M'),
(5, 'Nick', 22, 'M'),
(6, 'Kathy', 18, 'F'),
(7, 'Steve', 36, 'M'),
(8, 'Anne', 25, 'F');
Query to Generate Rank
SELECT
    first_name,
    age,
    gender,
    @curRank := @curRank + 1 AS rank
FROM
    person p,
    (SELECT @curRank := 0) r
ORDER BY
    age;

Explanation: The (SELECT @curRank := 0) r clause initializes the user-defined variable @curRank before the main query execution. The ORDER BY age clause ensures the ranking is applied based on the age in ascending order. Each row processed increments the @curRank variable.

Solution 2: Partitioned Ranking with User Variables (Dense Rank Emulation)

This method uses user variables to achieve a rank that accounts for ties and partitions the data by gender. It emulates the behavior of DENSE_RANK() or RANK() with partitioning.

Query to Generate Partitioned Rank
SELECT
    p.id,
    p.firstname,
    p.gender,
    p.age,
    @rank := CASE
        WHEN @partval = p.gender AND @rankval = p.age THEN @rank
        WHEN @partval = p.gender AND (@rankval := p.age) IS NOT NULL THEN @rank + 1
        WHEN (@partval := p.gender) IS NOT NULL AND (@rankval := p.age) IS NOT NULL THEN 1
    END AS rnk
FROM
    person p,
    (SELECT @rank := NULL, @partval := NULL, @rankval := NULL) AS x
ORDER BY
    p.gender, p.age;

Explanation: This query uses multiple user variables (@rank, @partval, @rankval) to keep track of the current rank, the previous partition value, and the previous value within the partition. The CASE statement updates the rank based on changes in gender and age, effectively creating a dense rank within each gender group.

Solution 3: Self-Join for Partitioned Ranking

This method uses a LEFT JOIN with the table itself to count preceding rows based on the desired ordering and partitioning criteria.

Sample Data Setup
CREATE TABLE person (
    id INT PRIMARY KEY,
    first_name VARCHAR(20),
    age INT,
    gender CHAR(1)
);

INSERT INTO person (id, first_name, age, gender) VALUES
(1, 'Bob', 25, 'M'),
(2, 'Jane', 20, 'F'),
(3, 'Jack', 30, 'M'),
(4, 'Bill', 32, 'M'),
(5, 'Nick', 22, 'M'),
(6, 'Kathy', 18, 'F'),
(7, 'Steve', 36, 'M'),
(8, 'Anne', 25, 'F');
Query to Generate Rank
SELECT
    a.first_name,
    a.age,
    a.gender,
    COUNT(b.age) + 1 AS rank
FROM
    person a
LEFT JOIN
    person b ON a.age > b.age AND a.gender = b.gender
GROUP BY
    a.first_name, a.age, a.gender;

Explanation: The query joins person to itself (a and b). The LEFT JOIN condition a.age > b.age AND a.gender = b.gender counts how many rows (b) have a lesser age within the same gender. Adding 1 to this count provides the rank.

Solution 4: Ranking with Percentile Calculation

This advanced technique, building upon user variable methods, calculates both rank and percentile, correctly handling ties by assigning the same rank and percentile to identical scores.

Sample Data Setup

Assume a marksheets table with id and score columns.

Query to Calculate Rank and Percentile
SET @totalStudents = 0;
SELECT COUNT(*) INTO @totalStudents FROM marksheets;

SELECT
    id,
    score,
    @curRank := IF(@prevVal = score, @curRank, @studentNumber) AS rank,
    @percentile := IF(@prevVal = score, @percentile, (@totalStudents - @studentNumber + 1) / @totalStudents * 100) AS percentile,
    @studentNumber := @studentNumber + 1 AS studentNumber,
    @prevVal := score
FROM
    marksheets,
    (SELECT @curRank := 0, @prevVal := NULL, @studentNumber := 1, @percentile := 100) r
ORDER BY
    score DESC;

Explanation: This query first determines the total number of students. Then, it iterates through the marksheets table ordered by score in descending order. User variables are used to:

  • Track the current rank (@curRank), assigning the same rank to tied scores.
  • Calculate the percentile (@percentile).
  • Count the total number of students processed (@studentNumber).
  • Store the previous score (@prevVal) to detect ties.

Example Result:

          @_sequence:=@_sequence+1,@_last_age:=age
FROM      person p, (SELECT @curRank := 1, @_sequence:=1, @_last_age:=0) r
ORDER BY  age;
