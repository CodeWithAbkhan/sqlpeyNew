“MySQL Date Range Population: Stored Procedures vs Set-Based Queries”

How can database professionals efficiently populate a table column with a sequence of dates spanning a specific interval, like an entire year, without relying on external application logic? Several robust methods exist for this common requirement in SQL environments, particularly MySQL. These techniques range from procedural loops within stored procedures to purely set-based mathematical constructions.

Method 1: Utilizing MySQL Stored Procedures for Iterative Insertion

A procedural approach involves creating a stored procedure that iterates day-by-day between a start date and an end date, inserting each date into the target table (tablename with a column _date).

Basic Procedure for Simple Insertion

This initial procedure inserts dates regardless of existing entries:

DROP PROCEDURE IF EXISTS filldates_simple;
DELIMITER |
CREATE PROCEDURE filldates_simple(dateStart DATE, dateEnd DATE)
BEGIN
  WHILE dateStart <= dateEnd DO
    INSERT INTO tablename (_date) VALUES (dateStart);
    SET dateStart = DATE_ADD(dateStart, INTERVAL 1 DAY);
  END WHILE;
END;
|
DELIMITER ;

CALL filldates_simple('2011-01-01','2011-12-31');

Enhanced Procedure to Prevent Duplicate Dates

If the requirement mandates that dates already present in a table (e.g., MyDates with a column mydate) should be skipped, the procedure must incorporate a check:

DROP PROCEDURE IF EXISTS filldates_check;
DELIMITER |
CREATE PROCEDURE filldates_check(dateStart DATE, dateEnd DATE)
BEGIN
    DECLARE adate DATE;
    WHILE dateStart <= dateEnd DO
        SET adate = (SELECT mydate FROM MyDates WHERE mydate = dateStart);
        IF adate IS NULL THEN 
            INSERT INTO MyDates (mydate) VALUES (dateStart);
        END IF;
        SET dateStart = DATE_ADD(dateStart, INTERVAL 1 DAY);
    END WHILE;
END;
|
DELIMITER ;

Alternative: Using a Dedicated Calendar Table and Procedure

Another procedural variation involves creating a permanent calendar table first and using INSERT IGNORE within the procedure to safely handle subsequent calls for overlapping date ranges:

DROP PROCEDURE IF EXISTS FillCalendar;
DROP TABLE IF EXISTS calendar;
CREATE TABLE IF NOT EXISTS calendar(calendar_date DATE NOT NULL PRIMARY KEY);

DELIMITER $$
    CREATE PROCEDURE FillCalendar(start_date DATE, end_date DATE)
    BEGIN
    DECLARE crt_date DATE;
    SET crt_date = start_date;
    WHILE crt_date <= end_date DO
        -- INSERT IGNORE skips insertion if primary key violation occurs (date exists)
        INSERT IGNORE INTO calendar VALUES(crt_date);
        SET crt_date = ADDDATE(crt_date, INTERVAL 1 DAY);
    END WHILE;
    END$$
DELIMITER ;

CALL FillCalendar('2013-01-01', '2013-01-07');

Method 2: Set-Based Date Generation Using Number Tables (Tally Tables)

For environments where stored procedures or user permissions limit procedural execution, set-based solutions are favored. These methods generate a sequence of integers (0, 1, 2, 3, …) and use arithmetic operations combined with date functions to derive the required date range. This avoids external dependencies like calendar tables.

Generating a Fixed Range (e.g., Last 365 Days from Today) in MySQL

This popular technique constructs a large integer from combinations of smaller numbers (singles, tens, hundreds) to create a range of numbers efficiently using UNION ALL and JOINs:

SELECT 
    (CURDATE() - INTERVAL c.number DAY) AS date_generated
FROM 
    (
        SELECT 
            singles + tens + hundreds number 
        FROM 
            (
                SELECT 0 singles UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9
            ) singles 
        JOIN 
            (
                SELECT 0 tens UNION ALL SELECT 10 UNION ALL SELECT 20 UNION ALL SELECT 30 UNION ALL SELECT 40 UNION ALL SELECT 50 UNION ALL SELECT 60 UNION ALL SELECT 70 UNION ALL SELECT 80 UNION ALL SELECT 90
            ) tens  
        JOIN 
            (
                SELECT 0 hundreds UNION ALL SELECT 100 UNION ALL SELECT 200 UNION ALL SELECT 300 UNION ALL SELECT 400 UNION ALL SELECT 500 UNION ALL SELECT 600 UNION ALL SELECT 700 UNION ALL SELECT 800 UNION ALL SELECT 900
            ) hundreds
    ) c  
WHERE 
    c.number BETWEEN 0 AND 364
ORDER BY 
    date_generated DESC;

SQL Server Equivalent for Set-Based Generation

The logic remains similar for other SQL dialects, requiring adaptation for date functions (e.g., DATEADD in SQL Server instead of MySQL’s interval arithmetic):

SELECT 
    DATEADD(day, -1 * c.number, CAST(GETDATE() AS DATE)) AS date_generated
FROM 
    (
        SELECT 
            singles + tens + hundreds number 
        FROM 
            (
                SELECT 0 as singles UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9
            ) singles 
        CROSS JOIN 
            (
                SELECT 0 tens UNION ALL SELECT 10 UNION ALL SELECT 20 UNION ALL SELECT 30 UNION ALL SELECT 40 UNION ALL SELECT 50 UNION ALL SELECT 60 UNION ALL SELECT 70 UNION ALL SELECT 80 UNION ALL SELECT 90
            ) tens 
        CROSS JOIN 
            (
                SELECT 0 hundreds UNION ALL SELECT 100 UNION ALL SELECT 200 UNION ALL SELECT 300 UNION ALL SELECT 400 UNION ALL SELECT 500 UNION ALL SELECT 600 UNION ALL SELECT 700 UNION ALL SELECT 800 UNION ALL SELECT 900
            ) hundreds
    ) c  
WHERE 
    c.number BETWEEN 0 AND 364
ORDER BY 
    date_generated ASC;

Generating Dates Based on Date Difference (MySQL)

If you know the exact start and end dates, you can calculate the required range size using DATEDIFF and use a number generator up to that difference:

-- Example: Generating dates between '2015-10-21' and '2016-10-08'
SELECT 
    DATE_ADD('2015-10-21', INTERVAL c.number DAY) AS DATE
FROM 
    (
        SELECT singles + tens + hundreds + thousands number FROM 
        ( 
            SELECT 0 singles UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9
        ) singles JOIN 
        (
            SELECT 0 tens UNION ALL SELECT 10 UNION ALL SELECT 20 UNION ALL SELECT 30 UNION ALL SELECT 40 UNION ALL SELECT 50 UNION ALL SELECT 60 UNION ALL SELECT 70 UNION ALL SELECT 80 UNION ALL SELECT 90
        ) tens  JOIN 
        (
            SELECT 0 hundreds UNION ALL SELECT 100 UNION ALL SELECT 200 UNION ALL SELECT 300 UNION ALL SELECT 400 UNION ALL SELECT 500 UNION ALL SELECT 600 UNION ALL SELECT 700 UNION ALL SELECT 800 UNION ALL SELECT 900
        ) hundreds
         JOIN 
        (
            SELECT 0 thousands UNION ALL SELECT 1000 UNION ALL SELECT 2000 UNION ALL SELECT 3000 UNION ALL SELECT 4000 UNION ALL SELECT 5000 UNION ALL SELECT 6000 UNION ALL SELECT 7000 UNION ALL SELECT 8000 UNION ALL SELECT 9000
        ) thousands
        ORDER BY number DESC
    ) c  
WHERE 
    c.number BETWEEN 0 AND DATEDIFF('2016-10-08', '2015-10-21');

Method 3: Mathematical Generation Without Stored Procedures (MySQL)

This technique relies on base-10 number construction (similar to Method 2) but uses mathematical combinations of digits (0-9) across five dimensions (t0 to t4) to generate up to 99,999 days, starting from the Unix epoch (1970-01-01):

SELECT 
    * 
FROM 
    (
        SELECT 
            ADDDATE('1970-01-01', t4*10000 + t3*1000 + t2*100 + t1*10 + t0) gen_date 
        FROM
            (SELECT 0 t0 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) t0,
            (SELECT 0 t1 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) t1,
            (SELECT 0 t2 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) t2,
            (SELECT 0 t3 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) t3,
            (SELECT 0 t4 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) t4
    ) v
WHERE 
    gen_date BETWEEN '2017-01-01' AND '2017-12-31';

Method 4: Utilizing Session Variables for Sequential Generation (MySQL)

For a compact, set-based approach that generates dates sequentially starting from a reference point, user-defined variables can track the increment:

-- Requires setting the initial variable value appropriately before execution
-- Example targets a range from '2011-01-01' to '2011-12-31'
INSERT INTO my_dates (`_date`) 
SELECT 
    DATE_ADD('2011-01-01', INTERVAL @_tmp:=@_tmp+1 day) `_date`
FROM 
    (SELECT @_tmp:=-1 d UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) a /*10^1*/
JOIN 
    (SELECT 0 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) b /*10^2*/
JOIN 
    (SELECT 0 UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) c /*10^3*/
WHERE 
    @_tmp+1 BETWEEN 0 AND DATEDIFF('2011-12-31', '2011-01-01');

Method 5: Leveraging Existing Data Tables

If a table already exists with a sufficiently large, contiguous range of numeric IDs (e.g., an auto-incrementing primary key), this ID sequence can substitute for a dedicated number table:

INSERT INTO tablename (_date)
SELECT 
    '2011-01-01' + INTERVAL (id - 1) DAY
FROM 
    some_table_with_lots_of_ids
WHERE 
    id BETWEEN 1 AND 365;

Caveat: Care is needed here regarding leap years, as a fixed range like 365 might miss a day in a leap year.

Method 6: External Application Logic (PHP Example)

When database manipulation is restricted, application code like PHP can generate the dates and issue individual INSERT statements.

PHP Iterative Approach

This uses the strtotime function to step through dates:

<?php
$db = /* Database Connection */; 
$originalDate = "01/01/2011";
// Loop 366 times for a potential leap year coverage
for($i = 0; $i <= 365; $i++){ 
    $date_to_insert = date('Y-m-d', strtotime($originalDate . "+".$i." day"));
    mysqli_query($db, "INSERT INTO table (date) VALUES ('$date_to_insert')");
}
?>

PHP Date Stepping Loop

A more direct approach that updates the date variable within the loop condition:

<?php
$db = /* Database Connection */;
for ($startdate = strtotime("2011-01-01"); $startdate <= strtotime("2011-12-31"); $startdate = strtotime("+1 day", $startdate)) {
    $date= date("Y-m-d", $startdate);
    mysqli_query($db, "INSERT INTO tracking (date) VALUES ('$date')");
}
?>

Method 7: Populating a Rich Calendar Table (MySQL)

For comprehensive data requirements (date, day of year, month, year), a more complex set-based generation spanning decades can be employed, using nested number generation to map increments against years:

CREATE TABLE `calendar_date` (
    `id` INT NOT NULL AUTO_INCREMENT,
    `date` DATE NOT NULL,
    `day` SMALLINT NOT NULL,
    `month` TINYINT NOT NULL,
    `year` SMALLINT NOT NULL,
    PRIMARY KEY (`id`)
);

INSERT INTO `calendar_date` (`date`, `day`, `month`, `year`)
SELECT
    DATE
    , INCREMENT + 1
    , MONTH(DATE)
    , YEAR(DATE)
FROM
    (
        -- Subquery generating date offsets (INCREMENT)
        SELECT
            DATE_ADD(CONCAT(YEAR, '-01-01'), INTERVAL INCREMENT DAY) DATE,
            INCREMENT
        FROM
            (
                -- Generates 0 up to 999
                SELECT (UNITS + TENS + HUNDREDS) INCREMENT
                FROM
                    (SELECT 0 UNITS UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) UNITS
                CROSS JOIN
                    (SELECT 0 TENS UNION SELECT 10 UNION SELECT 20 UNION SELECT 30 UNION SELECT 40 UNION SELECT 50 UNION SELECT 60 UNION SELECT 70 UNION SELECT 80 UNION SELECT 90) TENS
                CROSS JOIN
                    (SELECT 0 HUNDREDS UNION SELECT 100 UNION SELECT 200 UNION SELECT 300 UNION SELECT 400 UNION SELECT 500 UNION SELECT 600 UNION SELECT 700 UNION SELECT 800 UNION SELECT 900) HUNDREDS
            ) INCREMENT
        -- Subquery to find the actual day count for the specific year
        , (
            SELECT
                YEAR, 
                DAYOFYEAR(CONCAT(YEAR, '-12-31')) - DAYOFYEAR(CONCAT(YEAR, '-01-01')) + 1 DAYS
            FROM
                (
                    -- Generates years from 2001 to 2100
                    SELECT (2000 + UNITS + TENS) YEAR
                    FROM
                        (SELECT 0 UNITS UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION SELECT 8 UNION SELECT 9) UNITS
                    CROSS JOIN
                        (SELECT 0 TENS UNION SELECT 10 UNION SELECT 20 UNION SELECT 30 UNION SELECT 40 UNION SELECT 50 UNION SELECT 60 UNION SELECT 70 UNION SELECT 80 UNION SELECT 90) TENS
                ) YEAR
            WHERE
                YEAR BETWEEN 2001 AND 2100
        ) YEAR
      WHERE
          INCREMENT BETWEEN 0 AND DAYS - 1
      ORDER BY
          YEAR, INCREMENT
    ) DATE;

FAQs on MySQL Date Range Population

Q: What is the main benefit of set-based date generation over stored procedures

ANS: Set-based queries generally execute faster in relational database engines as they avoid procedural overhead and are often optimized better for large data volume operations.

Q: How do I adapt the SQL Server date generation query for PostgreSQL

ANS: You would replace DATEADD(day, -1 * c.number, CAST(GETDATE() AS DATE)) with ('2024-01-01'::date - c.number * INTERVAL '1 day') or similar syntax common to PostgreSQL date arithmetic.

Q: Can I use an existing sequence table for date generation

ANS: Yes, if you have a table with a column containing sequential numbers (like an ID column), you can join or directly use the sequence value against your start date using date interval functions.
