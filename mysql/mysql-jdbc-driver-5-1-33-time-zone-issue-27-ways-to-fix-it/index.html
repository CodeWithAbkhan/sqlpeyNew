When running a Java web application on Tomcat with MySQL as the backend, it’s common to encounter time zone issues, especially after upgrading to newer versions of the MySQL JDBC driver. One particularly frustrating issue that arises with MySQL 5.1.33 and higher versions is the “server timezone value ‘UTC’ is unrecognized” error. This can disrupt your application’s database connectivity, and resolving it requires a deep dive into MySQL’s timezone configurations.

In this post, we will walk through 27 possible solutions to fix the time zone mismatch issue between MySQL and JDBC drivers, specifically for MySQL JDBC 5.1.33. From tweaking the MySQL configuration files to adjusting your connection string, you’ll find multiple ways to ensure proper time zone synchronization between your MySQL server and Java application.

Why is this Time Zone Error Happening?

The error occurs because the MySQL server is using a time zone that the JDBC driver cannot recognize, such as ‘UTC’. The issue is more prevalent when upgrading from an older MySQL JDBC driver (like 5.1.23) to newer versions (5.1.33 or beyond). This discrepancy leads to a failure in the conversion of date-time values between the application and the database.

To solve this, the serverTimezone parameter must be explicitly defined in the JDBC connection string. Let’s look at the various ways to fix this issue.

Solution 1: Set Global Time Zone on MySQL Server

One straightforward method to solve this issue is by setting the global time zone directly on the MySQL server.

SET GLOBAL time_zone = '+3:00';

This command sets the global time zone to UTC+3. Adjust the time zone offset based on your local time zone.

Solution 2: Modify the Connection String

Starting with MySQL 5.1, the JDBC driver requires explicit time zone configuration. This can be achieved by adding the serverTimezone parameter to your connection string.

Example connection string:

jdbc:mysql://localhost:3306/myschema?serverTimezone=UTC

This tells the JDBC driver to expect the server in UTC time zone, eliminating the error.

Solution 3: Update Your MySQL JDBC Driver Version

If you’re using an outdated MySQL JDBC driver, upgrading to a newer version may resolve the issue. For example, changing your Maven pom.xml dependency to version 5.1.39 or higher can solve time zone compatibility issues:

<dependency>
  <groupId>mysql</groupId>
  <artifactId>mysql-connector-java</artifactId>
  <version>5.1.39</version>
</dependency>

If the problem persists, try upgrading to 6.0.3 or higher.

Solution 4: Specify useLegacyDatetimeCode and useJDBCCompliantTimezoneShift in the Connection String

If you are still encountering issues, explicitly define both useLegacyDatetimeCode and useJDBCCompliantTimezoneShift in the connection string:

jdbc:mysql://localhost:3306/db?useUnicode=true&useJDBCCompliantTimezoneShift=true&useLegacyDatetimeCode=false&serverTimezone=UTC

These options help the driver handle the date-time conversion in a way that works across various time zones.

Solution 5: Use Spring Boot’s application.properties File

If you are working with a Spring Boot application, the simplest way to fix the issue is by adding the time zone directly in the application.properties file.

spring.datasource.url=jdbc:mysql://localhost:3306/db?serverTimezone=UTC

This ensures that the Spring Boot application connects to MySQL with the correct time zone.

Solution 6: Fix the JDBC Connection String

Ensure your connection string is correctly set up to resolve the time zone mismatch:

jdbc:mysql://localhost:3306/db?useUnicode=true&useJDBCCompliantTimezoneShift=true&useLegacyDatetimeCode=false&serverTimezone=UTC

Remember to escape & if you are placing this string in an XML file like persistence.xml:

<property name="hibernate.connection.url" value="jdbc:mysql://localhost:3306/db?useUnicode=true&amp;useJDBCCompliantTimezoneShift=true&amp;useLegacyDatetimeCode=false&amp;serverTimezone=UTC"/>

Solution 7: Adjust Time Zone in MySQL Configuration Files

If you’re working in a Linux environment, you can adjust MySQL’s default time zone directly in the MySQL configuration file (my.cnf or mysqld.cnf).

default-time-zone = '+00:00'

Then restart the MySQL server:

sudo service mysql restart

Solution 8: Set Time Zone in the TimeZoneMapping.properties File

For more advanced users, you can modify the TimeZoneMapping.properties file. This approach is helpful when you need to manage time zone mappings manually.

## Add a new time zone mapping for MySQL
CET=Central European Time

Solution 9: Set Time Zone on AWS MySQL Database

If your MySQL database is hosted on AWS, the default time zone is UTC. You can explicitly configure the connection string to include the serverTimezone parameter.

jdbc:mysql://localhost:3306/db?serverTimezone=UTC

Solution 10: Manually Set the Time Zone Using SQL

For environments where you can directly access the MySQL database, you can set the time zone on both the global and session levels:

SET @@global.time_zone = '+00:00';
SET @@session.time_zone = '+00:00';

This ensures that both global and session-level time zone settings are aligned.

Solution 11: Time Zone Adjustment in DBeaver

If you’re using DBeaver, set the server time zone directly in the connection settings:

  1. Go to Connection Settings.
  2. In Driver Properties, select Server Time Zone.
  3. Set it to UTC.

Solution 12: Use the Correct Maven Version

Ensure that you’re using the correct version of the MySQL JDBC driver in your pom.xml file.

<dependency>
  <groupId>mysql</groupId>
  <artifactId>mysql-connector-java</artifactId>
  <version>8.0.14</version>
</dependency>

Solution 13: Set Time Zone Dynamically in Code

If you need to set the time zone dynamically in your code, you can use the following approach:

String url = "jdbc:mysql://localhost:3306/db?serverTimezone=" + TimeZone.getDefault().getID();

This ensures the time zone is automatically set based on the system’s default time zone.

Solution 14: Configure Time Zone for MySQL on Windows

For Windows-based environments, ensure that the connection string is correctly formatted to avoid time zone errors:

spring.datasource.url=jdbc:mysql://localhost:3306/db?serverTimezone=UTC

Solution 15: Use the Correct Time Zone for Your Application

Make sure that the time zone in the connection string matches your application’s time zone. For example, for European time zones, you can set:

spring.datasource.url=jdbc:mysql://localhost:3306/db?serverTimezone=Europe/Berlin

FAQs on Solved: MySQL JDBC Driver 5.1.33 Time Zone Issue

Q: What does the serverTimezone property do?

A: The serverTimezone property is used to specify the time zone for your MySQL server in the JDBC connection string. This helps to synchronize the time zone between the MySQL server and the Java application, preventing errors related to time zone mismatches.

Q: What should I do if I’m using AWS MySQL?

A: AWS MySQL databases use UTC as the default time zone. Ensure that your JDBC connection string includes serverTimezone=UTC, which ensures synchronization between your application and the AWS MySQL instance.
