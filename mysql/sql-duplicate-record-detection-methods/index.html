“SQL Techniques for Identifying Duplicate Records Across Multiple Columns or Single Fields”

When managing relational data, finding and handling duplicate records is a frequent requirement. Whether you need to list the duplicated values, retrieve the full rows associated with them, or simply count the occurrences, SQL provides several powerful mechanisms to achieve this goal. This exploration presents various accepted methods, ranging from traditional aggregation to modern window functions.

Isolating Values That Appear More Than Once

The most direct way to identify which values in a specific column are duplicated is by using aggregation with the HAVING clause.

Method 1: Basic Aggregation for Value Counts

This standard technique groups records by the target column (name in this case) and filters groups where the record count exceeds one.

SELECT 
    target_column_name, 
    COUNT(*) AS occurrence_count 
FROM 
    your_table 
GROUP BY 
    target_column_name 
HAVING 
    COUNT(*) > 1;

For instance, if checking the varchar_col in a generic table:

SELECT 
    varchar_col, 
    COUNT(*) AS frequency 
FROM 
    data_source_table 
GROUP BY 
    varchar_col 
HAVING 
    frequency > 1;

Method 2: Combining Aggregation with ID Retrieval (If IDs Exist)

If you need the primary keys associated with the duplicates, some SQL dialects support functions like GROUP_CONCAT (MySQL/SQLite) or STRING_AGG (PostgreSQL/SQL Server) to list them alongside the count.

If using a table named documents and checking for duplicate name values:

SELECT 
    GROUP_CONCAT(document_id) AS duplicate_ids, 
    name, 
    COUNT(*) AS repetition_count
FROM 
    documents 
GROUP BY 
    name
HAVING 
    repetition_count > 1;

Retrieving Full Duplicate Rows Based on a Single Column

Often, merely seeing the duplicate value isn’t enough; you need all the original row details to investigate or clean the data.

Method 3: Correlated Subquery with EXISTS and LIMIT (Efficiency Focus)

This approach seeks to find a second (or subsequent) matching row for every row being examined, which can be more efficient than calculating the full count for every row when only existence matters.

To return all records where varchar_column is duplicated in mytable, avoiding the high cost of COUNT(*) across all duplicates:

SELECT  
    mto.*
FROM    
    mytable mto
WHERE   
    EXISTS
    (
        SELECT  
            1
        FROM    
            mytable mti
        WHERE   
            mti.varchar_column = mto.varchar_column
        LIMIT 1, 1 -- Attempts to find the second instance (offset 1, limit 1)
    )
ORDER BY 
    varchar_column;

Note: The LIMIT 1, 1 syntax targets the second matching row; performance benefits significantly with an index on varchar_column.

Method 4: Using IN with a Subquery Based on COUNT

A common and highly readable method involves finding the set of duplicated values first and then selecting all rows whose target column matches any value in that set.

Retrieving all rows from a table where the field value appears more than once:

SELECT 
    * 
FROM 
    main_table
WHERE   
    field IN (
        SELECT 
            field 
        FROM 
            main_table 
        GROUP BY 
            field 
        HAVING 
            COUNT(*) > 1
    ) 
ORDER BY 
    field;

Method 5: Self-Join to Compare Distinct Keys

A self-join compares a table against itself. This method is excellent for exposing the relationship between duplicate records, particularly if you need the primary keys of both matching rows. Assuming a primary key named Key and the column being checked is Col in TableABC:

SELECT 
    a.Key AS primary_key_1, 
    b.Key AS primary_key_2, 
    a.Col 
FROM 
    TableABC a, 
    TableABC b
WHERE 
    a.Col = b.Col  -- Match on the duplicated value
    AND a.Key <> b.Key -- Ensure they are different rows
ORDER BY a.Col;

Method 6: Using INNER JOIN with Aggregated Duplicates

This strategy first generates the list of duplicate values (using GROUP BY/HAVING) and then joins the original table back to this derived list. This fetches all complete records corresponding to the values flagged as duplicates.

If looking for duplicates in DupliactedData within TableName:

SELECT 
    T.* 
FROM 
    TableName T 
INNER JOIN
    (
        SELECT 
            DupliactedData 
        FROM 
            TableName 
        GROUP BY 
            DupliactedData 
        HAVING 
            COUNT(DupliactedData) > 1 
        ORDER BY 
            DupliactedData
    ) AS Temp_Duplicates 
ON 
    T.DupliactedData = Temp_Duplicates.DupliactedData;

Advanced Techniques for Full Row Retrieval

Method 7: Utilizing Window Functions (MySQL 8.0+, SQL Server, PostgreSQL)

Window functions, like COUNT(*) OVER (PARTITION BY ...) are highly effective as they calculate aggregate data without collapsing rows, allowing you to see the count alongside every record.

To retrieve all columns from table where col_name is duplicated, ordered by a secondary column col_name2:

WITH Dupe_CTE AS (
  SELECT 
    *,
    COUNT(*) OVER(PARTITION BY col_name) AS group_count,
    ROW_NUMBER() OVER(PARTITION BY col_name ORDER BY col_name2) AS row_position
  FROM 
    table
)
SELECT 
    *
FROM 
    Dupe_CTE
WHERE 
    group_count > 1;

Method 8: Correlated Subquery for Row Details and Count Display

This method keeps the full record structure while calculating the frequency for that specific row’s value via a correlated subquery in the SELECT and WHERE clauses.

Example targeting duplicates in the name column of the city table:

SELECT 
    t.*,
    (
        SELECT COUNT(*) 
        FROM city AS tt
        WHERE tt.name = t.name
    ) AS value_occurrence
FROM 
    `city` AS t
WHERE  
    (
        SELECT COUNT(*) 
        FROM city AS tt
        WHERE tt.name = t.name
    ) > 1 
ORDER BY 
    value_occurrence DESC;

Checking Duplicates Across Multiple Columns

When duplication depends on the unique combination of several fields (e.g., matching name AND email), you must aggregate over all relevant columns.

Method 9: Concatenating Columns for Composite Key Check

Concatenating the fields into a single string creates a composite key, allowing standard GROUP BY to check for identical combinations.

If checking for duplicates based on the combination of name and email in the users table:

SELECT 
    COUNT(CONCAT(name, email)) AS total_matches,
    name,
    email
FROM 
    users
GROUP BY 
    CONCAT(name, email)
HAVING 
    total_matches > 1;

Method 10: Advanced Duplicate Matching (Transactional Data Example)

For complex scenarios like pairing financial transactions where records are duplicates of each other but stored distinctly (e.g., a transfer and its corresponding reversal), a complex self-join combined with ordering functions can isolate the pairs precisely.

Identifying matched transfer pairs based on account, date, and opposing amounts:

SELECT 
    LEAST(primaryid, secondaryid) AS canonical_id_1,
    GREATEST(primaryid, secondaryid) AS canonical_id_2
FROM (
    SELECT 
        table1.transactionid AS primaryid, 
        table2.transactionid AS secondaryid
    FROM 
        financial_transactions table1
    INNER JOIN 
        financial_transactions table2 
    ON 
        table1.accountid = table2.accountid
        AND table1.transactionid <> table2.transactionid 
        AND table1.transactiondate = table2.transactiondate
        AND table1.sourceref = table2.destinationref
        AND table1.amount = (0 - table2.amount)
) AS MatchedPairs
GROUP BY 
    canonical_id_1
ORDER BY 
    canonical_id_1;

This query uses LEAST and GREATEST to ensure that the pair (A, B) is treated identically to (B, A) before grouping.

Alternative: Temporary Tables for Multi-Column De-duplication

For very large datasets or when performing multi-step cleaning, using temporary tables to build a unique key can simplify the final selection process.

-- Step 1: Create a temporary table with a concatenated unique key (cfs)
CREATE TEMPORARY TABLE temp_unique_key_table 
SELECT 
    CONCAT(field1, field2, field3) AS composite_key, 
    t1.* 
FROM 
    original_table t1;

-- Step 2: Index the key for fast grouping
CREATE INDEX idx_temp_key ON temp_unique_key_table(composite_key);

-- Step 3: Select the distinct rows based on the new key
CREATE TABLE de_duplicated_data 
SELECT 
    field1, field2, field3, ... 
FROM 
    temp_unique_key_table 
GROUP BY 
    composite_key;

-- Clean up
DROP TEMPORARY TABLE temp_unique_key_table;

FAQs on SQL Duplicate Record Detection Methods

Q: What is the most efficient query to list only the values that are duplicated

ANS: The most common and generally efficient method to list only the duplicated values and their counts is using GROUP BY on the target column and filtering with HAVING COUNT(*) > 1.

Q: Can I find duplicates based on two columns simultaneously

ANS: Yes, you can check combinations by concatenating the two columns within the GROUP BY clause, such as GROUP BY CONCAT(name, email).

Q: Which technique retrieves the original primary keys of all duplicate rows

ANS: Techniques involving GROUP_CONCAT(id) within an aggregation, or using EXISTS/IN subqueries or self-joins on the primary key, will expose the IDs associated with the duplicate values.

Q: Are window functions better than self-joins for finding duplicates

ANS: Window functions (like COUNT() OVER (...)) are often clearer and can be faster as they scan the data only once to calculate the count per partition, whereas traditional self-joins might involve multiple comparisons per row depending on the data distribution.

SELECT name, COUNT(*) c FROM table GROUP BY name HAVING c &gt; 1;
