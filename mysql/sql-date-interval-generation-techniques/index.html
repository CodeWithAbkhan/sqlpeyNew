“SQL Date Interval Generation: Stored Procedures vs. Recursive CTEs”

Generating a series of temporal bins (intervals) is a common requirement in analytical SQL queries, often necessary to group transactional data accurately regardless of whether data points exist for every interval. Below are several expert-proposed methods, ranging from procedural logic to modern recursive Common Table Expressions (CTEs).

Solution 1: MySQL Stored Procedure for Flexible Interval Generation

A robust approach involves creating a stored procedure that dynamically generates the required time intervals into a temporary table, which can then be joined against the primary data set. This is highly flexible as it accepts start time, end time, interval magnitude, and unit type.

The procedure make_intervals creates a temporary table named time_intervals populated with interval_start and interval_end columns.

Stored Procedure Code (MySQL/MariaDB Flavor):

-- DROP PROCEDURE IF EXISTS make_intervals;

CREATE PROCEDURE make_intervals(
    startdate TIMESTAMP,
    enddate TIMESTAMP,
    intval INTEGER,
    unitval VARCHAR(10)
)
BEGIN
-- Drops and recreates the temporary table for fresh execution
    DROP TEMPORARY TABLE IF EXISTS time_intervals;
    CREATE TEMPORARY TABLE IF NOT EXISTS time_intervals
    (
        interval_start TIMESTAMP,
        interval_end TIMESTAMP
    );

    DECLARE thisDate TIMESTAMP DEFAULT startdate;
    DECLARE nextDate TIMESTAMP;

    -- Loop to generate intervals
    REPEAT
        SELECT
            CASE unitval
                WHEN 'MICROSECOND' THEN TIMESTAMPADD(MICROSECOND, intval, thisDate)
                WHEN 'SECOND'      THEN TIMESTAMPADD(SECOND, intval, thisDate)
                WHEN 'MINUTE'      THEN TIMESTAMPADD(MINUTE, intval, thisDate)
                WHEN 'HOUR'        THEN TIMESTAMPADD(HOUR, intval, thisDate)
                WHEN 'DAY'         THEN TIMESTAMPADD(DAY, intval, thisDate)
                WHEN 'WEEK'        THEN TIMESTAMPADD(WEEK, intval, thisDate)
                WHEN 'MONTH'       THEN TIMESTAMPADD(MONTH, intval, thisDate)
                WHEN 'QUARTER'     THEN TIMESTAMPADD(QUARTER, intval, thisDate)
                WHEN 'YEAR'        THEN TIMESTAMPADD(YEAR, intval, thisDate)
            END INTO nextDate;

        -- Insert interval: end is one microsecond before the next start
        INSERT INTO time_intervals 
        SELECT thisDate, TIMESTAMPADD(MICROSECOND, -1, nextDate);
        
        SET thisDate = nextDate;
    UNTIL thisDate >= enddate
    END REPEAT;

END;

Execution Examples:

  1. Generating Daily Intervals (Jan 1 to Jan 10, 2009):

    CALL make_intervals('2009-01-01 00:00:00', '2009-01-10 00:00:00', 1, 'DAY');
SELECT * FROM time_intervals;
-- Result example: (2009-01-01 00:00:00, 2009-01-01 23:59:59)

  2. Generating 10-Minute Intervals (Over 2 Hours):

    CALL make_intervals('2009-01-01 00:00:00', '2009-01-01 02:00:00', 10, 'MINUTE');
SELECT * FROM time_intervals;
-- Result example: (2009-01-01 00:00:00, 2009-01-01 00:09:59)

This temporary table is then used with a standard BETWEEN or range join against the data timestamps.

Solution 2: SQL Server / T-SQL Recursive CTE for Date Generation

For Microsoft SQL Server environments, recursive Common Table Expressions (CTEs) offer a concise and fast method to generate sequences, avoiding procedural code overhead.

T-SQL Date Generation Example (Daily):

DECLARE @startDate DATETIME = '2011-01-01';
DECLARE @endDate DATETIME = '2011-01-31';

WITH DateSeries (DateValue) AS 
(
    SELECT @startDate AS DateValue
    UNION ALL
    SELECT DATEADD(DAY, 1, [DateValue])
    FROM DateSeries 
    WHERE [DateValue] < @endDate
)
SELECT DateValue
FROM DateSeries
OPTION (MAXRECURSION 0); -- Allows recursion depth beyond default limit

Solution 3: Modern MySQL/MariaDB Recursive CTE for Pure Date Lists

Since MySQL 8.0 and MariaDB 10.3, recursive CTEs are available, offering a cleaner, set-based alternative to older user-variable tricks or stored procedures for simple date iteration.

MySQL 8.0+ Recursive CTE Example:

-- Define boundary dates
SET @start_dt := '2019-01-01';
SET @end_dt := '2019-04-30';

WITH RECURSIVE DateSequence (dt) AS
(
    -- Anchor member
    SELECT @start_dt AS dt
    UNION ALL
    -- Recursive member
    SELECT DATE_ADD(dt, INTERVAL 1 DAY) 
    FROM DateSequence 
    WHERE DATE_ADD(dt, INTERVAL 1 DAY) <= @end_dt
)
SELECT dt
FROM DateSequence;

Solution 4: Using a Permanent Auxiliary Table (Numbers or Date Dimension)

For scenarios requiring extreme performance or complex joins across many queries, populating a physical all_dates table is often the simplest and most effective method. This pre-calculates all necessary dates, minimizing runtime computation.

Auxiliary Table Creation:

CREATE TABLE all_dates (
    dt DATE PRIMARY KEY
);
-- This table should be populated in a scheduled maintenance job, perhaps years in advance.

Querying with a Pre-populated Table:

This is beneficial when joining to find missing records (gaps), especially when combined with an outer join.

DECLARE @startDate DATE = '2009-01-01';
DECLARE @endDate DATE = '2009-01-13';

SELECT 
    DateRange.dt
FROM (
    -- Select only the required segment from the large table
    SELECT dt
    FROM all_dates
    WHERE dt BETWEEN @startDate AND @endDate
) AS DateRange
LEFT JOIN YourDataTable
    ON DateRange.dt = YourDataTable.DateColumn;

Solution 5: User Variable Iteration (Legacy MySQL)

This method relies on user-defined session variables to track the iteration count, suitable for older MySQL versions where recursive CTEs are unavailable. It requires a table whose row count dictates the maximum number of generated dates.

SET @current_date := DATE_SUB('2011-07-01', INTERVAL 1 DAY);

SELECT
    DATE(@current_date := DATE_ADD(@current_date, INTERVAL 1 DAY)) AS theDate
FROM 
    your_dummy_table_with_enough_rows x, 
    your_dummy_table_with_enough_rows y  -- Cross join to increase row count potential (10x10=100 max here)
GROUP BY 
    theDate
HAVING 
    theDate <= '2011-07-31';

Note: The row generation count depends on the number of tables crossed in the FROM clause.

Solution 6: Date Manipulation with Pre-calculated Number Series (Cross Join)

This technique generates a series of numbers (e.g., 0 to 999) using cross joins on small tables containing digits (0-9), and then adds that sequence number as an interval offset from a starting date. This avoids recursion limits common in some environments.

Example Generating up to 400 Days:

SET @s := CAST('2020-01-01' AS DATE);
SET @e := DATE_ADD(@s, INTERVAL 399 DAY); -- Max range for this specific join structure

WITH Digits AS (
    SELECT 0 AS i UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9
)
SELECT 
    DATE_ADD(@s, INTERVAL (d100.i*100 + d10.i*10 + d1.i) DAY) AS GeneratedDate
FROM 
    Digits d1
CROSS JOIN 
    Digits d10
CROSS JOIN 
    Digits d100
WHERE
    DATE_ADD(@s, INTERVAL (d100.i*100 + d10.i*10 + d1.i) DAY) <= @e
ORDER BY GeneratedDate;

Solution 7: Month-Based Interval Generation (MySQL Procedure)

When the requirement is to bin data by month rather than fixed days, a procedural loop inserting monthly starts into a temporary table is effective.

-- Procedure to generate monthly start dates between min and max subscription dates
CREATE PROCEDURE get_amount_subscription_per_month()
BEGIN
   -- 1. Determine overall month boundaries from data
   SELECT 
       @start_month := MIN(DATE_FORMAT(a.startdate, "%Y-%m-01")), 
       @end_month := MAX(DATE_FORMAT(a.enddate, "%Y-%m-01")) + INTERVAL 1 MONTH
   FROM subscription a;

   -- 2. Create temporary table to hold monthly markers
   DROP TABLE IF EXISTS tmp_months;
   CREATE TEMPORARY TABLE tmp_months (year_month DATE PRIMARY KEY);

   SET @temp_date = @start_month;

   -- 3. Loop and insert monthly start dates
   WHILE @temp_date <= @end_month DO
     INSERT INTO tmp_months (year_month) VALUES (@temp_date);
     SET @temp_date = DATE_ADD(@temp_date, INTERVAL 1 MONTH);
   END WHILE;

   -- 4. Use tmp_months table for aggregation join
   SELECT 
       mnd.year_month, 
       SUM(sub.amount) AS subscription_amount
   FROM tmp_months mnd
   LEFT JOIN subscription sub 
       ON mnd.year_month >= DATE_FORMAT(sub.startdate, "%Y-%m-01") 
       AND mnd.year_month <= DATE_FORMAT(sub.enddate, "%Y-%m-01")
   GROUP BY mnd.year_month;

END;

FAQs on SQL Date Interval Generation Techniques

Q: Which method is generally best for generating date ranges in SQL

ANS: Recursive CTEs (Solution 3) are typically favored in modern databases (MySQL 8+, SQL Server, PostgreSQL) for their declarative syntax and performance on moderate ranges. For highly consistent, very large ranges, a pre-populated auxiliary table (Solution 4) excels in query speed.

Q: How do I handle the end boundary when generating intervals

ANS: In Solution 1 (Stored Procedure), the end boundary is precisely handled by inserting the interval ending one microsecond before the start of the next interval (TIMESTAMPADD(MICROSECOND, -1, nextDate)). For simple date lists, the CTE condition is usually set to <= @endDate.

Q: Can I generate intervals smaller than a day without a procedure

ANS: Yes, recursive CTEs or number generation via cross joins can handle smaller units (hours, minutes) by adjusting the DATEADD or INTERVAL function accordingly, provided the database supports the necessary precision in its date functions.

Q: What is the MAXRECURSION option used for in SQL Server CTEs

ANS: The OPTION (MAXRECURSION N) clause controls how many iterations a recursive CTE can perform before failing to prevent infinite loops. Setting it to 0 allows unbounded recursion up to system limits, necessary for generating long date ranges.
