“MySQL Character Set Conversion: Practical Solutions for UTF-8 Encoding”

Encountering issues with character encoding in your MySQL database, particularly when dealing with international characters or special symbols? Many users face the challenge of converting their databases from older encodings like latin1 to the more robust utf8 or utf8mb4. This post delves into various practical solutions to achieve this conversion, ensuring your data is stored and displayed correctly.

Why Convert to UTF-8?

UTF-8 is the de facto standard for character encoding on the web and in modern applications. It supports a vast range of characters from nearly all writing systems, making it essential for globalized applications. Converting your MySQL database to UTF-8 prevents data corruption, ensures proper display of special characters, and enhances compatibility with various tools and programming languages. For a deeper dive into MySQL’s capabilities, consider this overview of PostgreSQL and MySQL .

Let’s explore the different approaches to tackle this conversion.

Solution 1: Direct ALTER DATABASE and ALTER TABLE Commands

This is often the most straightforward method for converting your database and its tables.

For the more comprehensive utf8mb4 character set, which supports a wider range of characters including emojis, use:

ALTER DATABASE databasename CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE tablename CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

If you are on an older MySQL version (prior to 5.5.2) that might not fully support utf8mb4, or if utf8 suffices for your needs:

ALTER DATABASE databasename CHARACTER SET utf8 COLLATE utf8_unicode_ci;
ALTER TABLE tablename CONVERT TO CHARACTER SET utf8 COLLATE utf8_unicode_ci;

These commands set the database’s default character set and then convert a specific table. You would repeat the ALTER TABLE command for each table that needs conversion.

Solution 2: Setting Defaults and Converting Existing Tables

This approach first sets the default character set for new tables and then addresses existing ones.

  1. Set Default for New Tables:

    ALTER DATABASE dbname CHARACTER SET utf8 COLLATE utf8_general_ci;

    Note: This command only affects newly created tables.

  2. Convert Existing Tables:

    ALTER TABLE tbl_name CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;

    Important: Ensure your existing data is compatible with the target character set before running this. If there’s a mismatch, you might need to consult MySQL documentation for specific data migration strategies.

Combining these for a single table:

ALTER DATABASE dbname CHARACTER SET utf8 COLLATE utf8_general_ci;
ALTER TABLE tbl_name CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;

Solution 3: Command-Line Conversion for All Tables

This method uses a shell script to automate the conversion of all tables within a specified database.

DB="your_database_name"
(
    echo 'ALTER DATABASE `'${DB}'` CHARACTER SET utf8 COLLATE utf8_general_ci;'
    mysql "$DB" -e "SHOW TABLES" --batch --skip-column-names \
    | xargs -I{} echo 'ALTER TABLE `'{}'` CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;'
) \
| mysql "$DB"

Explanation:

  • DB="your_database_name": Sets a variable for your database name.
  • echo 'ALTER DATABASE ...': Sets the database’s default character set.
  • mysql "$DB" -e "SHOW TABLES" --batch --skip-column-names: Retrieves a list of all tables in the database.
  • xargs -I{} echo 'ALTER TABLE ...': Constructs an ALTER TABLE command for each table.
  • | mysql "$DB": Executes the generated SQL commands against the database.

Solution 4: Generating Conversion SQL from information_schema

This approach queries the information_schema database to generate the necessary ALTER statements.

SELECT CONCAT(
    "ALTER TABLE ", TABLE_SCHEMA, ".", TABLE_NAME,
    " CHARACTER SET utf8 COLLATE utf8_general_ci; ",
    "ALTER TABLE ", TABLE_SCHEMA, ".", TABLE_NAME,
    " CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;  "
) AS alter_sql
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = "your_database_name";

After running this query, capture the output (the alter_sql column) and execute it as a batch of SQL commands.

Solution 5: A Step-by-Step Approach with information_schema Queries

This solution provides a more detailed, step-by-step method, also leveraging information_schema.

Step 1: Database Level Changes

  • Identify Database Character Set and Collation: 
    SELECT DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA S
WHERE schema_name = 'your_database_name'
AND (DEFAULT_CHARACTER_SET_NAME != 'utf8' OR DEFAULT_COLLATION_NAME NOT LIKE 'utf8%');
  • Fix Database Collation and Character Set: 
    ALTER DATABASE your_database_name CHARACTER SET utf8 COLLATE utf8_unicode_ci;

Step 2: Table Level Changes

  • Identify Tables with Incorrect Settings: 
    SELECT CONCAT(
'ALTER TABLE ',  table_name, ' CHARACTER SET utf8 COLLATE utf8_general_ci;  ',
'ALTER TABLE ',  table_name, ' CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;  ')
FROM information_schema.TABLES AS T
JOIN information_schema.COLLATION_CHARACTER_SET_APPLICABILITY AS C
ON C.collation_name = T.table_collation
WHERE T.table_schema = 'your_database_name'
AND (C.CHARACTER_SET_NAME != 'utf8' OR C.COLLATION_NAME NOT LIKE 'utf8%');
  • Execute Generated Statements: Copy and run the output from the previous query. Example output: 
    ALTER TABLE rma CHARACTER SET utf8 COLLATE utf8_general_ci;ALTER TABLE rma CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;
ALTER TABLE rma_history CHARACTER SET utf8 COLLATE utf8_general_ci;ALTER TABLE rma_history CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;
-- ... and so on for other tables

Solution 6: Using GUI Tools like HeidiSQL

For users who prefer a graphical interface, tools like HeidiSQL offer a simplified way to manage character sets.

  1. Connect to your MySQL server using HeidiSQL.
  2. Navigate to Tools -> Bulk Table Editor.
  3. Select the database or specific tables you wish to modify.
  4. Choose the option to “Change default collation” and select utf8mb4_general_ci (or utf8_general_ci).
  5. Tick the box for “Convert to charset” and select utf8mb4 (or utf8).
  6. Execute the changes.

Important Consideration with GUI Tools: Ensure your database connection itself is also set to UTF-8 to avoid data corruption during the process. If your PDO connection, for example, is not configured for UTF-8, you might see incorrect characters even after the conversion. Solution 7: Stored Procedure for Automated Table Conversion

If you have a large number of tables, a stored procedure can automate the conversion process.

DELIMITER $$

CREATE PROCEDURE `your_database_name`.`update_char_set`()
BEGIN
 DECLARE done INT DEFAULT 0;
 DECLARE t_sql VARCHAR(256);
 DECLARE tableName VARCHAR(128);
 DECLARE lists CURSOR FOR SELECT table_name FROM `information_schema`.`TABLES` WHERE table_schema = 'your_database_name';
 DECLARE CONTINUE HANDLER FOR SQLSTATE '02000' SET done = 1;

 OPEN lists;
 FETCH lists INTO tableName;
 REPEAT
    SET @t_sql = CONCAT('ALTER TABLE ', tableName, ' CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci');
    PREPARE stmt FROM @t_sql;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
 FETCH lists INTO tableName;
 UNTIL done END REPEAT;
 CLOSE lists;
END$$

DELIMITER ;

CALL your_database_name.update_char_set();

This procedure iterates through all tables in the specified database and applies the CONVERT TO CHARACTER SET command.

Solution 8: Bash Script for Bulk Conversion

This bash script automates the process for multiple databases.

#!/bin/bash

printf "### Converting MySQL character set ###\n\n"

printf "Enter the encoding you want to set (e.g., utf8mb4_unicode_ci): "
read -r CHARSET

printf "Enter mysql username: "
read -r USERNAME

printf "Enter mysql password for user %s:" "$USERNAME"
read -rs PASSWORD

# List of databases to convert
DBLIST=( mydatabase1 mydatabase2 )

printf "\n"

for DB in "${DBLIST[@]}"
do
(
    echo 'ALTER DATABASE `'"$DB"'` CHARACTER SET utf8 COLLATE `'"$CHARSET"'`;'
    mysql "$DB" -u"$USERNAME" -p"$PASSWORD" -e "SHOW TABLES" --batch --skip-column-names \
    | xargs -I{} echo 'ALTER TABLE `'{}'` CONVERT TO CHARACTER SET utf8 COLLATE `'"$CHARSET"'`;'
) \
| mysql "$DB" -u"$USERNAME" -p"$PASSWORD"

echo "$DB database conversion complete..."
done

echo "### All conversions finished ###"
exit

This script prompts for credentials and then loops through a predefined list of databases, applying the character set conversion.

Solution 9: Converting to utf8mb4 with Generated SQL

For a robust conversion to utf8mb4, this solution generates specific SQL statements.

  1. Show database default character sets: 
    SELECT SCHEMA_NAME 'YOUR_DATABASE_NAME',
default_character_set_name 'charset',
DEFAULT_COLLATION_NAME 'collation'
FROM information_schema.SCHEMATA;
  2. Show table status: 
    use YOUR_DATABASE_NAME;
SHOW TABLE STATUS;
  3. Generate conversion SQL for database and tables: 
    USE information_schema;
SELECT CONCAT("ALTER DATABASE `",table_schema,"` CHARACTER SET = utf8mb4 COLLATE = utf8mb4_unicode_ci;") AS _sql
FROM `TABLES` WHERE table_schema LIKE "YOUR_DATABASE_NAME" AND TABLE_TYPE='BASE TABLE' GROUP BY table_schema
UNION
SELECT CONCAT("ALTER TABLE `",table_schema,"`.`",table_name,"` CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;") AS _sql
FROM `TABLES` WHERE table_schema LIKE "YOUR_DATABASE_NAME" AND TABLE_TYPE='BASE TABLE' GROUP BY table_schema, TABLE_NAME;
    Note: The commented-out UNION section can be used to convert individual columns if needed, but is often unnecessary.

Execute the generated SQL statements. Afterward, verify the changes with SHOW TABLE STATUS;.

Solution 10: Converting Columns to Binary Types First

If direct conversion causes issues with specific characters, converting to a binary type first and then back can be a safer approach.

  • Example for a VARCHAR column: 
    -- Convert to a binary type
ALTER TABLE [TABLE_SCHEMA].[TABLE_NAME] MODIFY [COLUMN_NAME] VARBINARY;

-- Convert back to the desired character type and set
ALTER TABLE [TABLE_SCHEMA].[TABLE_NAME] MODIFY [COLUMN_NAME] VARCHAR(140) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

You can generate these statements for all columns using SQL queries like:

SELECT
CONCAT('ALTER TABLE ', TABLE_SCHEMA,'.', TABLE_NAME,' MODIFY ', COLUMN_NAME,' VARBINARY;'),
CONCAT('ALTER TABLE ', TABLE_SCHEMA,'.', TABLE_NAME,' MODIFY ', COLUMN_NAME,' ', COLUMN_TYPE,' CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;')
FROM information_schema.columns
WHERE TABLE_SCHEMA IN ('[TABLE_SCHEMA]')
AND COLUMN_TYPE LIKE 'varchar%'
AND (COLLATION_NAME IS NOT NULL AND COLLATION_NAME NOT LIKE 'utf%');

After column conversion, apply table and database level conversions as shown in other solutions. For more on Python data handling, see articles on Pandas or resolving TypeError: is not JSON serializable .

Solution 11: PHP Script for Database and Table Conversion

A PHP script can also automate this process.

<?php
$host = 'localhost';
$username = 'your_username';
$password = 'your_password';
$database = 'your_database_name';

$conn = mysqli_connect($host, $username, $password, $database);

if ($conn->connect_error) {
  die("Connection failed: " . $conn->connect_error);
}

// Alter database character set
$alter_database_charset_sql = "ALTER DATABASE ".$database." CHARACTER SET utf8 COLLATE utf8_unicode_ci";
if (!mysqli_query($conn, $alter_database_charset_sql)) {
    echo "Error altering database: " . mysqli_error($conn) . "<br>";
} else {
    echo "Database character set altered successfully.<br>";
}

// Get all tables
$show_tables_result = mysqli_query($conn, "SHOW TABLES");
if ($show_tables_result) {
    $tables = mysqli_fetch_all($show_tables_result);

    foreach ($tables as $table) {
      $tableName = $table[0];
      $alter_table_sql = "ALTER TABLE ".$tableName." CONVERT TO CHARACTER SET utf8 COLLATE utf8_unicode_ci";
      if (!mysqli_query($conn, $alter_table_sql)) {
          echo "Error altering table $tableName: " . mysqli_error($conn) . "<br>";
      } else {
          echo "Table $tableName converted successfully.<br>";
      }
    }
} else {
    echo "Error showing tables: " . mysqli_error($conn) . "<br>";
}

mysqli_close($conn);
?>

This script connects to the database, alters the database’s default character set, and then iterates through all tables to convert their character sets.

Solution 12: mysqldump and Manual File Editing

This method involves dumping the database, editing the dump file, and then re-importing.

  1. Dump the database: 
    mysqldump -uusername -ppassword -c -e --default-character-set=utf8 --single-transaction --skip-set-charset --add-drop-database -B dbname > dump.sql
  2. Edit the dump file: Open dump.sql in a text editor (like vim).
    • Replace DEFAULT CHARACTER SET latin1 with DEFAULT CHARACTER SET utf8 COLLATE utf8_general_ci.
    • Replace DEFAULT CHARSET=latin1 with DEFAULT CHARSET=utf8.
  3. Import the modified dump: 
    mysql -uusername -ppassword < dump-fixed.sql

Solution 13: Modifying Columns Safely (Binary Conversion)

Similar to Solution 10, this focuses on individual column modifications using binary types as an intermediary.

  • Generate column modification SQL: 
    SELECT
CONCAT('ALTER TABLE ', TABLE_SCHEMA,'.', TABLE_NAME,' MODIFY ', COLUMN_NAME,' VARBINARY;'),
CONCAT('ALTER TABLE ', TABLE_SCHEMA,'.', TABLE_NAME,' MODIFY ', COLUMN_NAME,' ', COLUMN_TYPE,' CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;')
FROM information_schema.columns
WHERE TABLE_SCHEMA IN ('[TABLE_SCHEMA]')
AND COLUMN_TYPE LIKE 'varchar%'
AND (COLLATION_NAME IS NOT NULL AND COLLATION_NAME NOT LIKE 'utf%');
  • Convert all tables: 
    SELECT
CONCAT('ALTER TABLE ', TABLE_SCHEMA, '.', TABLE_NAME, ' CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;')
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_COLLATION NOT LIKE 'utf8%'
and TABLE_SCHEMA in ('[TABLE_SCHEMA]');
  • Convert the database: 
    ALTER DATABASE [DATA_BASE_NAME] CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci;

Execute the generated SQL statements sequentially.

Solution 14: Recreate Database with UTF-8

If all else fails or for a clean start, recreating the database with the desired character set is an option.

create database your_database_name character set utf8;

Remember to back up your data before dropping and recreating the database.

Solution 19: Command-Line Excluding Views

This solution refines Solution 3 to handle databases with views, preventing errors.

DB="your_database_name"
(
    echo 'ALTER DATABASE `'"$DB"'` CHARACTER SET utf8 COLLATE utf8_general_ci;'
    mysql "$DB" -e "SHOW FULL TABLES WHERE Table_Type = 'BASE TABLE'" --batch --skip-column-names \
    | awk '{print $1 }' \
    | xargs -I{} echo 'ALTER TABLE `'{}'` CONVERT TO CHARACTER SET utf8 COLLATE utf8_general_ci;'
) \
| mysql "$DB"

The SHOW FULL TABLES WHERE Table_Type = 'BASE TABLE' and awk command ensure only actual tables are processed, not views.

Solution 20: PHPMyAdmin Operations Tab

PHPMyAdmin offers a graphical way to manage table collations.

  1. Select your database in PHPMyAdmin.
  2. Go to the Operations tab.
  3. In the “Collation” dropdown, select your desired encoding (e.g., utf8_general_ci).
  4. Check the boxes to “Change all table collations” and “Change all tables columns collations”.
  5. Click Go.

Important Reminders:

  • Backup First: Always perform a full backup of your database before making any significant changes.
  • Test Thoroughly: Test the conversion on a staging or development environment before applying it to a production database.
  • Collation Matters: Choose the correct collation (_unicode_ci, _general_ci, etc.) based on your sorting and comparison needs. utf8mb4_unicode_ci is generally recommended for utf8mb4.
  • Application Compatibility: Ensure your application code correctly handles UTF-8 encoding, especially when querying or displaying data. Issues might arise if your application’s connection encoding doesn’t match the database. For Python, explore resources like fixing Python UnicodeEncodeError .

FAQs on MySQL Character Set Conversion

Q: What is the primary reason for converting MySQL databases to UTF-8

ANS: The primary reason is to support a wider range of characters, including those from different languages and special symbols, preventing data corruption and ensuring global compatibility.

Q: Can I convert a single table to UTF-8 without affecting the entire database

ANS: Yes, you can use the ALTER TABLE tablename CONVERT TO CHARACTER SET utf8 COLLATE utf8_unicode_ci; command for individual tables.

Q: What is the difference between utf8 and utf8mb4 character sets in MySQL

ANS: utf8mb4 is a more comprehensive character set that supports a broader range of Unicode characters, including emojis, whereas utf8 (a MySQL-specific alias for utf8mb3) supports fewer characters.

Q: Is it safe to convert my database character set online

ANS: It is generally recommended to perform character set conversions during low traffic periods and always after a full database backup to mitigate risks. Some solutions might lock tables during conversion.

Q: What steps should I take after converting my database to UTF-8

ANS: After conversion, it’s crucial to test your application thoroughly to ensure all special characters are displayed correctly and that there are no data integrity issues. Check application connection settings for UTF-8 as well.

Q: How can I check the current character set and collation of my MySQL database

ANS: You can use SQL queries like SHOW VARIABLES LIKE 'character_set_server';, SHOW VARIABLES LIKE 'collation_server';, and SELECT DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME FROM information_schema.SCHEMATA WHERE schema_name = 'your_database_name';.

Q: What are the potential issues if my application does not use UTF-8 when interacting with a UTF-8 database

ANS: If your application’s connection encoding is not set to UTF-8, you might encounter errors when inserting or retrieving data containing special characters, leading to mojibake (garbled text) or data loss.

Q: What is a common collation for UTF-8 in MySQL

ANS: Common collations include utf8_general_ci and utf8_unicode_ci for utf8, and utf8mb4_general_ci and utf8mb4_unicode_ci for utf8mb4. _unicode_ci collations generally offer better accuracy for character sorting and comparisons.
