“Fixing MySQL ‘Access Denied’ with auth_socket Plugin”

Encountering the dreaded ERROR 1698 (28000): Access denied for user 'root'@'localhost' often points directly to how your MySQL or MariaDB installation handles authentication on systems like Ubuntu. The culprit is frequently the default use of the auth_socket plugin, which authenticates database users based on the operating system credentials, bypassing traditional password entry. How can experienced system administrators adjust this authentication method or reset access for the root user across different MySQL versions?

This deep dive presents several proven methods to regain access or change authentication mechanisms, ranging from updating user plugins directly to using secure installation scripts.

Core Issue: Authentication Plugin Mismatch

On several Linux distributions, freshly installed MySQL defaults to the auth_socket plugin for the root user. This allows system root to connect without a password via sudo mysql. If you attempt to connect using mysql -u root -p and it fails, it’s likely because the system expects the socket authentication, not a provided password.

To inspect current user configurations, execute the following within the MySQL client (often requiring sudo initially):

sudo mysql -u root

-- Inside MySQL:
USE mysql;
SELECT User, Host, plugin FROM user;

A typical output showing the socket issue might look like this:

| User | Host | plugin | | :

Methods to Re-establish Password-Based Access

Several paths exist to resolve this, primarily focusing on switching the root user to use mysql_native_password or creating a new, password-enabled user.

Strategy A: Switching Root to mysql_native_password (General Fix)

This approach forces the root user to authenticate via a password, allowing standard remote or local password connections.

  1. Access the MySQL shell using system privileges: 
    sudo mysql -u root
  2. Modify the user record in the mysql database: 
    USE mysql;
UPDATE user 
SET plugin='mysql_native_password' 
WHERE User='root' AND Host='localhost';
FLUSH PRIVILEGES;
EXIT;
  3. Restart the service for changes to take effect: 
    sudo service mysql restart
    (Note: For systems where auth_socket is aliased as unix_socket, use 'unix_socket' in the UPDATE statement instead.)

Strategy B: Using ALTER USER (Modern MySQL 5.7+ and 8.0+)

For newer versions, the SQL standard ALTER USER statement offers a cleaner way to redefine authentication.

  1. Access MySQL using sudo:

    sudo mysql -u root -p

    (If you cannot use -p because the password isn’t set, just use sudo mysql -u root.)

  2. Execute the password update:

    ALTER USER 'root'@'localhost' 
IDENTIFIED WITH mysql_native_password BY 'YourSecureNewPassword';

FLUSH PRIVILEGES;
EXIT;

  3. Restart the MySQL service.

For MySQL 8.0.4+ Specifics: MySQL 8 introduced caching_sha2_password as the default. If you are on 8.0.4 or newer and wish to use the older, widely compatible plugin:

-- Inside MySQL shell, after sudo access
UPDATE user 
SET plugin='caching_sha2_password' 
WHERE User='root' AND Host='localhost';

ALTER USER 'root'@'localhost' 
IDENTIFIED WITH caching_sha2_password BY 'your_mysql_password';

FLUSH PRIVILEGES;

Strategy C: Creating a New System-User-Mapped Account

If you prefer to keep root locked to socket authentication, you can create a separate user mapped to your current system user:

  1. Log in with root privileges: 
    sudo mysql -u root
  2. Create the new user, identifying it by your system username: 
    USE mysql;
CREATE USER 'YOUR_SYSTEM_USER'@'localhost' IDENTIFIED BY 'YOUR_PASSWD';
GRANT ALL PRIVILEGES ON *.* TO 'YOUR_SYSTEM_USER'@'localhost';
-- Optional: If you want this new user to use socket auth too:
-- UPDATE user SET plugin='auth_socket' WHERE User='YOUR_SYSTEM_USER'; 
FLUSH PRIVILEGES;
EXIT;
  3. Restart the service and connect using your system login: mysql -u YOUR_SYSTEM_USER -p.

Strategy D: Resetting Password via Safe Mode (Bypassing Authentication)

This involves starting MySQL in a mode that ignores grant tables, allowing direct modification of user data. Use with caution.

  1. Stop the service: 
    sudo service mysql stop
  2. Create necessary runtime directory if missing and set permissions: 
    sudo mkdir /var/run/mysqld
sudo chown mysql: /var/run/mysqld
  3. Start MySQL daemon safely in the background: 
    sudo mysqld_safe --skip-grant-tables --skip-networking &
  4. Log in without a password: 
    mysql -uroot mysql
  5. Update the authentication string (Note: older MySQL versions used password(), newer ones use authentication_string): 
    UPDATE user 
SET authentication_string=PASSWORD('YOURNEWPASSWORD'), 
    plugin='mysql_native_password' 
WHERE User='root' AND Host='%';
EXIT;
  6. Shut down the safe instance gracefully via its socket: 
    sudo mysqladmin -S /var/run/mysqld/mysqld.sock shutdown
  7. Start the service normally: 
    sudo service mysql start

Strategy E: Adjusting Password Validation Policy

Sometimes the access error occurs after you provide a password, due to strict policy settings (common in MySQL 5.7+). You can temporarily relax these policies.

  1. Log in using sudo: 
    sudo mysql -u root -p
  2. Check current settings: 
    SHOW VARIABLES LIKE 'validate_password%';
  3. Set policies to LOW or adjust length/complexity counts to match your intended password. For example, to set policy to lowest level and minimum length to 4: 
    SET GLOBAL validate_password.policy=LOW;
SET GLOBAL validate_password.length=4;
SET GLOBAL validate_password.number_count=0;
SET GLOBAL validate_password.special_char_count=0;

-- Now, attempt to set the password using Strategy B:
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'short4';
FLUSH PRIVILEGES;

Strategy F: Utilizing mysql_secure_installation

If the installation environment supports it (especially common on fresh installs), running the security script is often the recommended path post-installation to set root passwords and enforce security.

sudo mysql_secure_installation

Follow the prompts to set a root password and remove anonymous users.

Addressing MySQL 8.x Column Naming

For users finding that UPDATE user SET plugin='...' or SET PASSWORD = ... fails, inspect the user table structure. In certain MySQL 8 configurations, the password hash column might be renamed from password to authentication_string.

Example adjustment using the string column:

UPDATE user 
SET authentication_string=PASSWORD("mypass") 
WHERE user='root';
FLUSH PRIVILEGES;

Reinstallation as a Last Resort

If persistent issues arise, especially related to repository conflicts (e.g., mixing distribution MySQL packages with Oracle repos), completely purging and reinstalling from the official source can clean the slate.

sudo apt remove mysql-server mysql-client mysql-common mysql-server-core-* mysql-client-core-* --purge --auto-remove
sudo rm -rf /etc/mysql /var/lib/mysql
sudo apt-get update
sudo apt-get install mysql-server # Follow installation prompts carefully for password setting

mysql -u $(whoami)
use mysql;
set password for 'root'@'localhost' = password('YOUR_ROOT_PASSWORD_HERE');
flush privileges;
quit
mysql -u root -p

FAQs on Fixing MySQL Access Denied Auth Socket

Q: What is the auth_socket plugin in MySQL

ANS: The auth_socket plugin authenticates users based on their operating system credentials when connecting locally, eliminating the need for a password if the OS user matches the database user (often applicable to the system root user connecting as MySQL root).

Q: Should I use mysql_native_password or caching_sha2_password

ANS: mysql_native_password is widely compatible across older clients and applications. caching_sha2_password is the more secure default in MySQL 8.0.4+; choose based on client compatibility requirements.

Q: Why do I need sudo to access MySQL initially

ANS: On Linux systems where root uses auth_socket, sudo grants you the necessary system privileges to connect to the database instance without needing the MySQL password.

Q: What happens if I set plugin to empty string

ANS: Setting plugin='' often reverts the user to a system that relies solely on password authentication or a default mechanism supported by the client, effectively disabling the socket check for that user.

sudo mysql # Logs in automatically into MariaDB
use mysql;
update user set plugin='' where user='your_user_name';
flush privileges;
exit;
sudo service mysql restart # Restarts the MySQL service
mysql -u your_user_name -p
