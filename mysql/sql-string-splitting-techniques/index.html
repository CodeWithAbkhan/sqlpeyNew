“SQL String Splitting: Efficient Techniques and Solutions”

When dealing with relational databases, data often resides in a normalized format. However, there are instances where a single column might contain multiple values separated by a delimiter, such as a comma. Extracting these individual values into separate rows is a common data manipulation task. This post delves into several SQL-based techniques to achieve this, offering alternatives for different database versions and scenarios.

The Challenge of Delimited Strings

Solution 1: Using a Numbers Table or Generated Sequence

One effective approach involves a “numbers table” – a table containing a sequence of integers. If such a table isn’t available, a temporary sequence can be generated. This allows us to iterate through potential split points.

The core idea is to use SUBSTRING_INDEX to extract parts of the string based on the delimiter.

Option 1a: With a Pre-existing Numbers Table

If you have a numbers table (let’s call it numbers with a column n starting from 1), the query looks like this:

SELECT
  t.id,
  SUBSTRING_INDEX(SUBSTRING_INDEX(t.name, ',', num.n), ',', -1) AS extracted_name
FROM
  tablename t
INNER JOIN
  numbers num ON CHAR_LENGTH(t.name) - CHAR_LENGTH(REPLACE(t.name, ',', '')) >= num.n - 1
ORDER BY
  t.id, num.n;

This query works by joining the tablename with the numbers table. The join condition ensures that we only generate numbers up to the count of delimiters in the name column, effectively creating a row for each potential split.

Option 1b: Generating a Sequence On-the-Fly

If creating a persistent numbers table is not feasible, you can generate a sequence within your query:

SELECT
  t.id,
  SUBSTRING_INDEX(SUBSTRING_INDEX(t.name, ',', seq.sequence_number), ',', -1) AS extracted_name
FROM
  tablename t
INNER JOIN
  (SELECT 1 AS sequence_number UNION ALL
   SELECT 2 UNION ALL SELECT 3 UNION ALL
   SELECT 4 UNION ALL SELECT 5) AS seq ON CHAR_LENGTH(t.name) - CHAR_LENGTH(REPLACE(t.name, ',', '')) >= seq.sequence_number - 1
ORDER BY
  t.id, seq.sequence_number;

This version unions a set of numbers directly in the query. You’d extend the UNION ALL clause to accommodate the maximum number of expected values in your delimited strings.

Optimized Sequence Generation

A more scalable way to generate sequences, especially for a larger range, involves a technique that leverages cross joins to build a number series efficiently.

SELECT
  t.id,
  SUBSTRING_INDEX(SUBSTRING_INDEX(t.name, ',', num.n), ',', -1) AS extracted_name
FROM
  tablename t
INNER JOIN
  (SELECT @row := @row + 1 AS n
   FROM
     (SELECT 0 UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) AS t1,
     (SELECT 0 UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) AS t2,
     (SELECT 0 UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) AS t3,
     (SELECT @row := 0) AS initial_row
  ) AS num ON CHAR_LENGTH(t.name) - CHAR_LENGTH(REPLACE(t.name, ',', '')) >= num.n - 1
ORDER BY
  t.id, num.n;

This approach is particularly useful as it can generate a large number of sequence values with fewer explicit UNION ALL statements.

Solution 2: Leveraging JSON Functions (MySQL 8.0.4+)

If your database system supports JSON functions, particularly JSON_TABLE (available in MySQL 8.0.4 and later), this can be a very clean and efficient method.

Scenario 1: Data is already in JSON Array Format

If your column name already contains a JSON array, like ["apple", "banana", "cherry"], you can use JSON_TABLE:

SELECT
  t.id,
  jt.split_value
FROM
  mytable t
JOIN
  JSON_TABLE(
    t.name,
    '$[*]' COLUMNS (split_value VARCHAR(50) PATH '$')
  ) AS jt;

This directly parses the JSON array and creates a row for each element.

Scenario 2: Converting CSV to JSON for Splitting

If your data is in a CSV format within the column, you can first convert it to a JSON array before using JSON_TABLE.

SELECT
  t.id,
  jt.split_value
FROM
  mytable t
JOIN
  JSON_TABLE(
    REPLACE(JSON_ARRAY(t.name), ',', '","'), -- Converts 'a,b,c' to '["a","b","c"]'
    '$[*]' COLUMNS (split_value VARCHAR(50) PATH '$')
  ) AS jt;

This method offers a concise way to handle string splitting when JSON capabilities are available.

Solution 3: Recursive Common Table Expressions (CTE)

Recursive CTEs provide a powerful, standard SQL way to handle iterative processes, including string splitting. This method is generally available in modern SQL databases like PostgreSQL, SQL Server, and newer versions of MySQL.

MySQL 8.0.16+ Recursive CTE Example

For MySQL 8.0.16 and later, you can use a recursive CTE as follows:

WITH RECURSIVE input_data AS (
    SELECT 1 AS id, 'apple,banana,cherry' AS names
    UNION ALL
    SELECT 2, 'date,fig'
),
recursive_split AS (
    SELECT
        id,
        1 AS position,
        names AS remaining_string,
        SUBSTRING_INDEX(names, ',', 1) AS name
    FROM input_data
    UNION ALL
    SELECT
        id,
        position + 1,
        SUBSTRING(remaining_string, CHAR_LENGTH(name) + 2),
        SUBSTRING_INDEX(SUBSTRING(remaining_string, CHAR_LENGTH(name) + 2), ',', 1)
    FROM recursive_split
    WHERE CHAR_LENGTH(remaining_string) > CHAR_LENGTH(name)
)
SELECT id, name
FROM recursive_split
ORDER BY id, position;

This CTE iteratively breaks down the string by finding the delimiter, extracting the first part, and then processing the remainder.

Another Recursive CTE Approach

Here’s another variation demonstrating a similar recursive CTE pattern:

WITH RECURSIVE SplitValues AS (
    SELECT
        id,
        SUBSTRING_INDEX(name, ',', 1) AS split_value,
        IF(LOCATE(',', name) > 0, SUBSTRING(name, LOCATE(',', name) + 1), NULL) AS remaining_values
    FROM temporary_number_table -- Assumes a table with id and comma-separated name
    UNION ALL
    SELECT
        id,
        SUBSTRING_INDEX(remaining_values, ',', 1) AS split_value,
        IF(LOCATE(',', remaining_values) > 0, SUBSTRING(remaining_values, LOCATE(',', remaining_values) + 1), NULL)
    FROM
        SplitValues
    WHERE
        remaining_values IS NOT NULL
)
SELECT
    id,
    split_value
FROM
    SplitValues
ORDER BY id;

This example highlights the pattern of extracting the first part, then passing the rest of the string to the next iteration.

Solution 4: Using Stored Procedures and Functions

For more complex or reusable logic, stored procedures and functions can be employed.

Custom Split Function

A user-defined function (UDF) can encapsulate the splitting logic.

DELIMITER $$

CREATE FUNCTION SplitString(
    input_string TEXT,
    delimiter_char VARCHAR(5),
    occurrence INT
)
RETURNS VARCHAR(65535)
DETERMINISTIC
BEGIN
    DECLARE output_value VARCHAR(65535);
    SET output_value = REPLACE(SUBSTRING(SUBSTRING_INDEX(input_string, delimiter_char, occurrence),
                               LENGTH(SUBSTRING_INDEX(input_string, delimiter_char, occurrence - 1)) + 1),
                               delimiter_char, '');
    IF output_value = '' THEN
        SET output_value = NULL;
    END IF;
    RETURN output_value;
END $$

DELIMITER ;

You would then use this function in a procedure or directly in queries.

Stored Procedure for Normalization

A stored procedure can iterate through a table and insert split values into a new, normalized table.

DELIMITER $$

CREATE PROCEDURE NormalizeDelimitedData()
BEGIN
    DECLARE i INT DEFAULT 1;
    REPEAT
        INSERT INTO NormalizedTable (id, split_value)
        SELECT id, SplitString(original_column, ',', i)
        FROM OriginalTable
        WHERE SplitString(original_column, ',', i) IS NOT NULL;
        SET i = i + 1;
    UNTIL ROW_COUNT() = 0
    END REPEAT;
END $$

DELIMITER ;

This procedure repeatedly calls the SplitString function for increasing occurrences until no more values are found.

Dynamic Stored Procedure

A more advanced stored procedure can be designed to handle different table names and column names dynamically.

DELIMITER $$

DROP PROCEDURE IF EXISTS ProcessAndSplitColumn $$
CREATE PROCEDURE ProcessAndSplitColumn(
    IN tableName VARCHAR(64),
    IN idColumnName VARCHAR(64),
    IN valueColumnName VARCHAR(64),
    IN delimiterChar CHAR(1)
)
BEGIN
    SET @sqlQuery = CONCAT('
        SELECT ', idColumnName, ' AS record_id, ', valueColumnName, ' AS raw_value FROM ', tableName);

    DROP TEMPORARY TABLE IF EXISTS temp_split_data;
    CREATE TEMPORARY TABLE temp_split_data (record_id INT, split_value VARCHAR(255));

    SET @splitLogic = '
        DECLARE current_id INT;
        DECLARE current_value TEXT;
        DECLARE occurrences INT;
        DECLARE splitter INT DEFAULT 1;
        DECLARE done INT DEFAULT FALSE;
        DECLARE split_cursor CURSOR FOR SELECT record_id, raw_value FROM temp_source_data;
        DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;

        OPEN split_cursor;
        read_loop: LOOP
            FETCH split_cursor INTO current_id, current_value;
            IF done THEN LEAVE read_loop; END IF;

            SET occurrences = (SELECT CHAR_LENGTH(current_value) - CHAR_LENGTH(REPLACE(current_value, \'', delimiterChar, '\', \'\')) + 1);
            SET splitter = 1;
            WHILE splitter <= occurrences DO
                INSERT INTO temp_split_data VALUES (current_id, TRIM(SUBSTRING_INDEX(SUBSTRING_INDEX(current_value, \'', delimiterChar, splitter), \'', delimiterChar, -1)));
                SET splitter = splitter + 1;
            END WHILE;
        END LOOP;
        CLOSE split_cursor;';

    SET @createTempTable = CONCAT('CREATE TEMPORARY TABLE temp_source_data (record_id INT, raw_value VARCHAR(255)) ENGINE=Memory SELECT ', idColumnName, ' AS record_id, ', valueColumnName, ' AS raw_value FROM ', tableName);
    PREPARE stmt1 FROM @createTempTable;
    EXECUTE stmt1;
    DEALLOCATE PREPARE stmt1;

    PREPARE stmt2 FROM @splitLogic;
    EXECUTE stmt2;
    DEALLOCATE PREPARE stmt2;

    SELECT * FROM temp_split_data;
    DROP TEMPORARY TABLE temp_source_data;
    DROP TEMPORARY TABLE temp_split_data;
END $$
DELIMITER ;

This procedure orchestrates the splitting process by dynamically building and executing SQL statements.

Solution 5: Database-Specific Functions (e.g., PostgreSQL)

Some databases offer built-in functions for string splitting. For instance, PostgreSQL has string_to_array and unnest.

SELECT
    dt.id,
    unnest(string_to_array(dt.name, ',')) AS split_item
FROM
    your_data_table dt;

This is a highly efficient and readable method if your database supports it.

Solution 6: Tricks for Limited Splits or Specific Scenarios

For scenarios where you know the maximum number of splits or have particular constraints, certain “tricks” can be employed.

Limiting Splits with a Fixed Number

This method uses a generated sequence but limits it to a predefined number of splits.

SELECT
    t.id,
    SUBSTRING_INDEX(SUBSTRING_INDEX(t.name, ',', seq.sequence_num), ',', -1) AS split_element
FROM
    tablename t
INNER JOIN
    (SELECT @seq_num := @seq_num + 1 AS sequence_num
     FROM
       (SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5) AS x1,
       (SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5) AS x2,
       (SELECT @seq_num := -1) AS initial_seq
    ) AS seq ON seq.sequence_num <= LENGTH(t.name) - LENGTH(REPLACE(t.name, ',', '')) + 1
WHERE seq.sequence_num <= 20 -- Limit to max 20 elements
ORDER BY t.id, seq.sequence_num;

The WHERE seq.sequence_num <= 20 clause controls the maximum number of elements extracted.

Extracting Specific Occurrences

This technique focuses on extracting a specific, Nth occurrence of a value.

SELECT
    SUBSTRING_INDEX(SUBSTRING_INDEX('value1,value2,value3', ',', sequence_id + 1), ',', -1) AS extracted_value
FROM
    (
        SELECT @sequence := @sequence + 1 AS sequence_id
        FROM
            (SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5) AS seq1,
            (SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION SELECT 4 UNION SELECT 5) AS seq2,
            (SELECT @sequence := -1) AS init_seq
    ) AS sequence_generator
WHERE
    sequence_id < LENGTH('value1,value2,value3') - LENGTH(REPLACE('value1,value2,value3', ',', '')) + 1;

This is useful when you need a single element rather than all split elements.

Solution 7: Stored Procedure for General Splitting

A versatile stored procedure can handle splitting values from a specified column in a given table.

DELIMITER $$

CREATE PROCEDURE GetSplitValues(
    IN source_table VARCHAR(64),
    IN source_id_col VARCHAR(64),
    IN source_value_col VARCHAR(64),
    IN delimiter_val CHAR(1)
)
BEGIN
    DECLARE record_id INT;
    DECLARE raw_string TEXT;
    DECLARE num_occurrences INT;
    DECLARE split_index INT DEFAULT 1;
    DECLARE done INT DEFAULT FALSE;

    DECLARE split_cursor CURSOR FOR
        SELECT CAST(src.source_id_col AS UNSIGNED), src.source_value_col
        FROM (SELECT CAST(@source_id_col AS UNSIGNED) AS source_id_col, @source_value_col AS source_value_col FROM (SELECT @source_id_col:=NULL, @source_value_col:=NULL) AS vars) AS src
        JOIN (SELECT @source_id_col := `source_id_col`, @source_value_col := `source_value_col` FROM `source_table`) AS dynamic_src
        ON src.source_id_col IS NOT NULL;

    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;

    SET @query = CONCAT('CREATE TEMPORARY TABLE IF NOT EXISTS tmp_split_results (id INT, value VARCHAR(255) NOT NULL) ENGINE=MEMORY;');
    PREPARE stmt FROM @query;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;

    SET @dynamic_select = CONCAT('SELECT ', source_id_col, ', ', source_value_col, ' FROM ', source_table);
    PREPARE stmt FROM @dynamic_select;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;

    OPEN split_cursor;

    read_loop: LOOP
        FETCH split_cursor INTO record_id, raw_string;
        IF done THEN
            LEAVE read_loop;
        END IF;

        SET num_occurrences = (SELECT CHAR_LENGTH(raw_string) - CHAR_LENGTH(REPLACE(raw_string, delimiter_val, '')) + 1);
        SET split_index = 1;

        WHILE split_index <= num_occurrences DO
            SET @split_val = TRIM(SUBSTRING_INDEX(SUBSTRING_INDEX(raw_string, delimiter_val, split_index), delimiter_val, -1));
            SET @insert_query = CONCAT('INSERT INTO tmp_split_results (id, value) VALUES (', record_id, ', \'', @split_val, '\');');
            PREPARE insert_stmt FROM @insert_query;
            EXECUTE insert_stmt;
            DEALLOCATE PREPARE insert_stmt;
            SET split_index = split_index + 1;
        END WHILE;
    END LOOP;

    SELECT * FROM tmp_split_results;
    DROP TEMPORARY TABLE tmp_split_results;
    CLOSE split_cursor;
END $$

DELIMITER ;

This procedure dynamically constructs SQL to fetch data and then processes it row by row.

Solution 8: Dynamic SQL with String Splitting Logic

This approach uses dynamic SQL to build a query that splits strings, often for normalization purposes.

DELIMITER $$

CREATE PROCEDURE NormalizeTableColumn(
    IN tableName VARCHAR(64),
    IN idColumn VARCHAR(64),
    IN columnToSplit VARCHAR(64),
    IN delimiterSeparator CHAR(1)
)
BEGIN
    DECLARE recordId INT;
    DECLARE stringToSplit VARCHAR(65000);
    DECLARE splitCount INT;
    DECLARE i INT;
    DECLARE resultValue VARCHAR(65000);
    DECLARE done INT DEFAULT FALSE;

    DECLARE cursor_split CURSOR FOR
        SELECT CAST(t.idColumn AS UNSIGNED), t.columnToSplit FROM (SELECT CAST(@idColumn AS UNSIGNED) AS idColumn, @columnToSplit AS columnToSplit FROM (SELECT @idColumn := NULL, @columnToSplit := NULL) AS vars) AS t JOIN (SELECT @idColumn := `idColumn`, @columnToSplit := `columnToSplit` FROM `tableName`) AS dynamic_t ON t.idColumn IS NOT NULL;

    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;

    CREATE TEMPORARY TABLE IF NOT EXISTS SplitResultTable (
        original_id INT,
        split_value VARCHAR(65000)
    ) ENGINE=MEMORY;

    OPEN cursor_split;

    process_rows: LOOP
        FETCH cursor_split INTO recordId, stringToSplit;
        IF done THEN
            LEAVE process_rows;
        END IF;

        SET i = 1;
        SET splitCount = (SELECT CHAR_LENGTH(stringToSplit) - CHAR_LENGTH(REPLACE(stringToSplit, delimiterSeparator, '')) + 1);

        WHILE i <= splitCount DO
            SET resultValue = TRIM(SUBSTRING_INDEX(SUBSTRING_INDEX(stringToSplit, delimiterSeparator, i), delimiterSeparator, -1));
            INSERT INTO SplitResultTable (original_id, split_value) VALUES (recordId, resultValue);
            SET i = i + 1;
        END WHILE;
    END LOOP;

    CLOSE cursor_split;

    SELECT * FROM SplitResultTable;
    DROP TEMPORARY TABLE SplitResultTable;
END $$

DELIMITER ;

This procedure illustrates a robust way to handle string splitting and normalization using dynamic SQL and temporary tables.

Solution 9: Best Practice and Considerations

The most appropriate solution often depends on your specific database system, version, and performance requirements.

  • Recursive CTEs and JSON functions are generally preferred for their readability and often better performance in modern databases.
  • Stored procedures/functions offer reusability and encapsulation but can add complexity.
  • Numbers tables or generated sequences are reliable but might require careful management or optimization for very large datasets.

It’s important to note that a universally compatible SQL query for string splitting across all database systems is challenging due to variations in function availability (e.g., SUBSTRING_INDEX is MySQL-specific, while string_to_array is common in PostgreSQL).

For instance, a query optimized for MySQL might not work on SQL Server or Oracle without adjustments. The use of Common Table Expressions (CTEs) in Solution 9, for example, is well-supported in PostgreSQL and SQL Server but requires specific syntax or is not available in older MySQL versions.

Example of Best Practice with CTEs (MySQL 8.0+):

WITH RECURSIVE ValueSplitter AS (
    SELECT
        id,
        SUBSTRING_INDEX(name, ',', 1) AS split_val,
        IF(LOCATE(',', name) > 0, SUBSTRING(name, LOCATE(',', name) + 1), NULL) AS remaining_vals
    FROM your_data_table_with_names -- Replace with your actual table name
    UNION ALL
    SELECT
        id,
        SUBSTRING_INDEX(remaining_vals, ',', 1) AS split_val,
        IF(LOCATE(',', remaining_vals) > 0, SUBSTRING(remaining_vals, LOCATE(',', remaining_vals) + 1), NULL)
    FROM
        ValueSplitter
    WHERE
        remaining_vals IS NOT NULL
)
SELECT
    id,
    split_val
FROM
    ValueSplitter
ORDER BY id;

This query is concise and leverages the power of recursive CTEs for a clean split.

FAQs on SQL String Splitting

Q: How to split a comma separated string in SQL without a numbers table

ANS: You can generate a sequence of numbers on the fly using UNION ALL or more advanced techniques involving session variables and cross joins to create temporary number series for splitting strings.

Q: Can JSON functions be used to split strings in SQL

ANS: Yes, if your database supports JSON functions like JSON_TABLE (e.g., MySQL 8.0.4+), you can convert delimited strings to JSON arrays and then use JSON_TABLE to split them into rows.

Q: What is a recursive CTE for string splitting

ANS: A recursive CTE is a query construct that iteratively processes data. For string splitting, it repeatedly extracts the next delimited value and passes the remainder of the string to the next iteration until the string is fully processed.

Q: How to split a string into multiple rows in PostgreSQL

ANS: In PostgreSQL, you can efficiently split strings using string_to_array to convert the string into an array and then unnest to expand the array elements into separate rows.

Q: Are stored procedures effective for string splitting in SQL

ANS: Stored procedures are effective for creating reusable logic, handling complex splitting scenarios, or performing data normalization tasks involving string splitting. They can encapsulate the splitting mechanism for repeated use.

CREATE FUNCTION strSplit(x VARCHAR(65000), delim VARCHAR(12), pos INTEGER) 
RETURNS VARCHAR(65000)
BEGIN
  DECLARE output VARCHAR(65000);
  SET output = REPLACE(SUBSTRING(SUBSTRING_INDEX(x, delim, pos)
                 , LENGTH(SUBSTRING_INDEX(x, delim, pos - 1)) + 1)

  IF output = '' THEN SET output = null; END IF;
  RETURN output;
END $$
