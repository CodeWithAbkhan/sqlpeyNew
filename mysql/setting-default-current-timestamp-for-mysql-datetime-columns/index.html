“Setting Default Current Timestamp for MySQL DATETIME Columns: Methods and Caveats”

Achieving a default value of the current time for a DATETIME column in MySQL has historically presented challenges, especially in versions prior to 5.6.5, which primarily supported this behavior for the TIMESTAMP data type. Different database versions and requirements necessitate varying approaches, including leveraging TIMESTAMP properties, utilizing triggers, or employing specific ALTER TABLE statements.

The Modern Approach: MySQL 5.6.5+ and 8.x Compatibility

For recent MySQL versions (5.6.5 and later, including 8.x), native support for setting CURRENT_TIMESTAMP as the default for DATETIME is available, providing cleaner schema definitions.

Creating a Table with Creation and Update Timestamps:

You can specify both a creation time that remains static upon insertion and an update time that changes on every row modification.

CREATE TABLE foo_records (
    record_id INT PRIMARY KEY AUTO_INCREMENT,
    data_field VARCHAR(100),
    creation_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    modification_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

This syntax allows creation_time to be set once upon insertion, while modification_time automatically updates. For MySQL 8.x, this is generally straightforward as seen in a user example:

CREATE TABLE `users` (
      `id` INT(11) NOT NULL AUTO_INCREMENT,
      `dateCreated` DATETIME DEFAULT CURRENT_TIMESTAMP,
      `dateUpdated` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
      PRIMARY KEY (`id`)
    ) ENGINE=InnoDB;

Utilizing the TIMESTAMP Data Type (Historical or Specific Use Cases)

Before DATETIME supported default functions natively, TIMESTAMP was the standard choice, although it has its own significant limitations, notably the year 2038 cutoff.

Example using TIMESTAMP:

CREATE TABLE timestamp_test (
    data_entry VARCHAR(50),
    record_ts TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO timestamp_test (data_entry) VALUES ('Initial entry');
SELECT * FROM timestamp_test;
-- Output ts field will show current time, e.g., 2008-10-03 22:59:52

Important Caveat with TIMESTAMP Default: If you define a TIMESTAMP column with DEFAULT CURRENT_TIMESTAMP, any subsequent UPDATE operation on that row must explicitly provide a value for that column, or MySQL will reset it to the current time (NOW()), even if you intended the original value to remain untouched. To prevent this accidental reset during an update when no explicit value is provided, you must include the column in the update statement, setting it equal to itself (e.g., UPDATE my_table SET data_field = 'new_value', record_ts = record_ts WHERE id = 1;).

Workaround Solutions for Older Versions or DATETIME Necessity

When the DATETIME type is required or when running MySQL versions that don’t support function defaults for DATETIME, database triggers offer a reliable alternative.

1. Implementing BEFORE INSERT Triggers

A BEFORE INSERT trigger allows you to inject the current time just before the record is written, overriding any null or unset value.

Basic Trigger Example:

DELIMITER //
CREATE TRIGGER table_name_on_insert 
BEFORE INSERT ON `your_table`
FOR EACH ROW 
    SET NEW.date_field = NOW();
DELIMITER ;

Handling Manual Overrides with Triggers: A significant drawback of the basic trigger above is that it overwrites any user-specified date during an INSERT. To allow for manual date specification while defaulting to NOW() otherwise, use the IFNULL function:

DELIMITER //
CREATE TRIGGER myTable_OnInsert BEFORE INSERT ON `tblMyTable`
    FOR EACH ROW 
    SET NEW.dateAdded = IFNULL(NEW.dateAdded, NOW());
DELIMITER ;

This permits: INSERT INTO tblMyTable(name, dateAdded) VALUES('Alice', '2010-01-03 04:30:43'); to succeed with the specified date, or use NOW() if dateAdded is omitted.

Triggers for Updates: You can also use a BEFORE UPDATE trigger to ensure an update timestamp column is always refreshed:

DELIMITER $$
CREATE TRIGGER update_timestamp_before_update 
    BEFORE UPDATE ON `your_table` 
    FOR EACH ROW 
    BEGIN
        SET NEW.update_date_field = NOW();
    END $$
$$
DELIMITER ;

Note: Remember to change the delimiter when defining multi-line triggers. (See Solution 14 for delimiter syntax )

2. Using ALTER TABLE Statements

If the table already exists, you can modify the column definition.

Modifying an Existing Column (MySQL 5.6.5+ Syntax):

ALTER TABLE <TABLE_NAME> 
    CHANGE COLUMN <COLUMN_NAME> <COLUMN_NAME> DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP;

Alternative Default Values for Older Systems: In some environments (like MariaDB 5.5.56 mentioned in one report), setting a zero date might be required if CURRENT_TIMESTAMP is problematic, though this is not standard practice for current time logging:

ALTER TABLE `table_name` CHANGE `column_name` DATETIME NOT NULL DEFAULT '0000-00-00 00:00:00';

One user noted that in specific MySQL 5.7 versions, using '1000-01-01 00:00:00' worked when '0000-00-00 00:00:00' failed as a default for DATETIME.

Switching Existing Columns to TIMESTAMP Defaults:

If you decide to use TIMESTAMP retrospectively:

ALTER TABLE `table_name` 
    CHANGE COLUMN `column_name` `column_name` 
    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP;

3. Inserting via Subquery (Pre-Function Default Support)

Before function defaults were widely accepted for DATETIME, one could dynamically set the value during the INSERT statement itself:

INSERT INTO Yourtable (Field1, YourDateField) 
    VALUES('val1', (SELECT NOW()));

FAQs on Setting Default Current Timestamp for MySQL DATETIME Columns

Q: Why does my DATETIME column default not work in older MySQL versions

ANS: In MySQL versions prior to 5.6.5, the DATETIME type generally did not permit function calls like NOW() or CURRENT_TIMESTAMP as default values; only the TIMESTAMP type supported this behavior natively.

Q: Can I use NOW() directly as a default for a DATETIME column

ANS: While some users attempt DATETIME default now(), MySQL documentation suggests that for DATETIME, you should use DEFAULT CURRENT_TIMESTAMP in supported versions (5.6.5+). NOW() is often treated like a function, which is usually disallowed for defaults on non-TIMESTAMP types until modern releases.

Q: How do I stop an automatic TIMESTAMP column from changing on UPDATE

ANS: If you use TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP, the field updates every time. To prevent this while allowing it to be set on insert, you need to explicitly include the column in your UPDATE statement, setting it equal to its current value: SET your_timestamp_column = your_timestamp_column.
ALTER TABLE `test_table`
  CHANGE COLUMN `created_dt` `created_dt` TIMESTAMP NOT NULL DEFAULT '0000-00-00 00:00:00',
  CHANGE COLUMN `updated_dt` `updated_dt` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP;
CREATE TRIGGER trig_test_table_insert BEFORE INSERT ON `test_table`
    FOR EACH ROW SET NEW.created_dt = NOW();
