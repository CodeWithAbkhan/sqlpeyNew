“Nodejs MySQL Bulk Insert Strategies Using Array Values”

Performing numerous individual INSERT statements in Node.js against a MySQL database introduces significant overhead due to repeated network round trips. A highly performant approach involves leveraging the driver’s capability to handle arrays of values for multi-row insertion, often using the VALUES ? syntax. How can one correctly structure data to utilize these bulk insert mechanisms effectively with various Node.js MySQL packages?

Core Technique: Utilizing Nested Arrays for Bulk Insertion

The established method, particularly with packages like mysql, involves formatting the SQL query to expect a placeholder for a group of values (VALUES ?) and providing the data as a nested array structure.

Method 1: Simple Nested Array Formatting (Accepted Solution)

When inserting into columns (col1, col2, col3), the data needs to be structured where the outermost array wraps the entire set of rows, and each inner array represents a single row’s values.

Example using mysql package:

const mysql = require('mysql');
const conn = mysql.createConnection({
    // connection details...
    host: 'localhost',
    user: 'root',
    password: 'pwd',
    database: 'test_db'
});

const sql = "INSERT INTO Test (name, email, n) VALUES ?";
const values = [
    ['demian', 'demian@example.com', 1],
    ['john', 'john@example.com', 2],
    ['mark', 'mark@example.com', 3],
    ['pete', 'pete@example.com', 4]
];
// Note the required double wrapping: [values]
conn.query(sql, [values], function(err, res) {
    if (err) throw err;
    console.log(`Inserted ${res.affectedRows} rows.`);
    conn.end();
});

This structure transforms the input [['a', 'b'], ['c', 'd']] internally into ('a', 'b'), ('c', 'd') for the SQL execution.

Crucial Insight: As noted in several confirmations, the structure passed to conn.query for the value set must be an array containing the array of rows: [ [row1_values], [row2_values], ... ].

Method 2: Adapting Object Arrays to Array Tuples

Often, data originates as an array of JavaScript objects. To use the VALUES ? syntax, these objects must first be mapped to the required array-of-arrays format, ensuring column order alignment.

If we have:

const items = [
    {name: 'alpha', description: 'describes alpha', value: 1},
    {name: 'beta', description: 'describes beta', value: 2}
];

We transform it before insertion:

// Using mysql2 or mysql package
db.query(
    'INSERT INTO my_table (name, description, value) VALUES ?',
    [items.map(item => [item.name, item.description, item.value])], // Mapping objects to arrays
    (error, results) => { /* handle results */ }
);

Method 3: Ensuring Column Order Safety with Object Mappings

Relying on dynamic Object.keys() order can be risky depending on the JavaScript engine version, although modern engines generally maintain insertion order for non-integer keys. For absolute safety, explicitly define the column order:

import mysql from 'mysql2';

function constructMultipleInsertSqlStatement(tableName, objects) {
    // Explicitly define columns to guarantee order across JS environments
    const columnNames = ['name', 'email', 'n']; 
    
    // Map objects respecting the defined column order
    const valuesArray = objects.map(o => columnNames.map(s => o[s]));
    
    // Use mysql.format for safe query construction
    return mysql.format(`INSERT INTO ?? (??) VALUES ?;`, [tableName, columnNames, valuesArray]);
}

const myObjects = [
    { name:'demian', email:'d@test.com', n:1 },
    { email:'j@test.com', name:'john', n:2 }, // Different property order
];

const safeSql = constructMultipleInsertSqlStatement('Test', myObjects);
// safeSql will now correctly order values for each row according to columnNames array.
// Example output: INSERT INTO `Test` (`name`, `email`, `n`) VALUES ('demian', 'd@test.com', 1), ('john', 'j@test.com', 2);

Retrieving Inserted IDs Sequentially

For auto-incremented primary keys, MySQL returns the ID of the first inserted row (result.insertId) and the total number of affected rows (result.affectedRows). You can reconstruct the subsequent IDs:

// Assuming 'values' contained N rows
db.connection.query(sql, [valuesArray], function(err, result) {
    if (err) { /* error handling */ }
    
    const startingId = result.insertId;
    const rowIds = [];
    for (let i = 0; i < result.affectedRows; i++) {
      rowIds.push(startingId + i);
    }
    // rowIds now contains the sequential primary keys for all inserted rows
});

Alternative: Using Named Parameters (If ? Fails with Specific Package)

If the standard ? placeholder syntax causes issues, especially when mixing packages (e.g., using node-mysql instead of mysql), substituting named parameters might resolve the conflict, though this is less common for standard bulk inserts.

// Requires 'node-mysql' package and explicit named substitution
var sql = "INSERT INTO Test (name, email, n) VALUES :params";
var values = [
    ['demian', 'd@test.com', 1],
    // ... other rows
];
conn.query(sql, { params: values}, function(err) {
    // ...
});

High-Speed File Processing Bulk Insert

For extreme throughput (e.g., loading 250k rows from a file), an asynchronous, buffered approach using streams is advisable.

'use strict';
const mysql = require('promise-mysql');
const fs = require('fs');
const readline = require('readline');

async function streamInsert() {
  const connection = await mysql.createConnection({ /* ... details ... */ });
  const rl = readline.createInterface({ input: fs.createReadStream('data_file.txt') });

  let total = 0;
  let buffer = [];
  const BATCH_SIZE = 2000;

  for await (const line of rl) {
    buffer.push([line]); // Assuming one column 'Number' from file line
    total++;
    if (buffer.length >= BATCH_SIZE) {
      await connection.query('INSERT INTO Phone (Number) VALUES ?', [buffer]);
      console.log(`Processed ${total} records.`);
      buffer = [];
    }
  }

  if (buffer.length > 0) {
    await connection.query('INSERT INTO Phone (Number) VALUES ?', [buffer]);
    console.log(`Final batch processed. Total: ${total}`);
  }

  connection.end();
}

streamInsert().catch(console.error);

Specialized ORM/Library Approach

External libraries abstract this complexity entirely. For instance, the object_mysql package allows passing an array of objects directly:

import db from 'object_mysql';
const { Test } = await db();

const values = [
    { name:'demian', email:'d@test.com', n:1 },
    { name:'john', email:'j@test.com', n:2 }
];

await Test.add(values); // Library handles the conversion internally

FAQs on Nodejs MySQL Bulk Insert Strategies

Q: What is the required array format for bulk INSERT using VALUES ?

ANS: The data must be provided as an array containing one element, which is the array of row tuples. Example: [[val1_row1, val2_row1], [val1_row2, val2_row2]] should be passed as [ [ [val1_row1, val2_row1], [val1_row2, val2_row2] ] ] to the query function’s parameters.

Q: Can I use INSERT INTO table (col1, col2) VALUES (v1, v2), (v3, v4)

ANS: While this SQL format is valid, standard Node.js drivers prefer the parameterized form INSERT INTO table (col1, col2) VALUES ? when passing structured arrays to prevent SQL injection vulnerabilities easily.

Q: How do I get the IDs back after a bulk insert

ANS: Check the result object from the query execution. It typically contains insertId (the ID of the first inserted row) and affectedRows (the total count of inserted rows). You can calculate the rest sequentially: ID = insertId + offset.

Q: Does using object mapping guarantee column insertion order

ANS: Relying solely on Object.keys(obj) might be inconsistent across older JS environments. It is best practice to explicitly define the desired columnNames array and map object values based on that fixed order when constructing the array of arrays.
