“Optimizing MySQL Geo Distance Queries: Strategies and Examples”

When dealing with geographical data in MySQL, efficiently querying for locations within a certain radius is a common challenge. This post explores several approaches to accurately and performantly calculate distances between points and filter results, aiming to provide a robust solution for your location-based applications.

Understanding the Core Problem

The fundamental task is to find all records in a database table that are within a specified distance from a given geographical point (latitude and longitude). This involves calculating the distance between the central point and all other points and then filtering based on that distance.

Solution 1: Leveraging SPATIAL Indexes and MBRContains

This approach utilizes MySQL’s native support for spatial data types and indexing.

  • For MySQL 5.7.5 and later: Both MyISAM and InnoDB tables support SPATIAL indexes on GEOMETRY data types.
  • Key Functions:
    • Point(x, y): Creates a point geometry.
    • LineString(point1, point2, ...): Creates a linestring geometry.
    • LineFromText('LINESTRING(...)'): Converts a WKT string to a linestring.
    • MBRContains(mbr, geometry): Checks if a Minimum Bounding Rectangle (MBR) contains a given geometry.

This method involves creating a bounding box around your target point and using MBRContains with a spatial index to quickly narrow down potential candidates. Subsequent filtering can refine these results for exact distances.

Example Query (MySQL 5.7.5+):

SELECT *
FROM your_table
WHERE MBRContains(
    LineFromText(CONCAT(
        '(',
        @target_lon + 10 / (111.1 / COS(RADIANS(@target_lat))), ' ', @target_lat + 10 / 111.1,
        ',',
        @target_lon - 10 / (111.1 / COS(RADIANS(@target_lat))), ' ', @target_lat - 10 / 111.1,
        ')'
    )),
    your_point_column
);

For MySQL 5.1 and above:

SELECT *
FROM your_table
WHERE MBRContains(
    LineString(
        Point(
            @target_lon + 10 / (111.1 / COS(RADIANS(@target_lat))),
            @target_lat + 10 / 111.1
        ),
        Point(
            @target_lon - 10 / (111.1 / COS(RADIANS(@target_lat))),
            @target_lat - 10 / 111.1
        )
    ),
    your_point_column
);

This query selects points within an approximate 10km radius. The calculation forms a spherical rectangle, which is a close approximation to a circular area for many use cases.

Further Refinement:

To account for the spherical nature of the Earth and ensure precision for larger distances, additional filtering based on the precise distance calculation (like the Haversine formula) is often applied to the results from MBRContains.

SELECT
    *,
    (6371 * ACOS(COS(RADIANS(56.946285)) * COS(RADIANS(Y(coordinates)))
    * COS(RADIANS(X(coordinates)) - RADIANS(24.105078)) + SIN(RADIANS(56.946285))
    * SIN(RADIANS(Y(coordinates))))) AS distance
FROM places
WHERE MBRContains
    (
    LineString
        (
        Point (
            24.105078 + 15 / (111.320 * COS(RADIANS(56.946285))),
            56.946285 + 15 / 111.133
        ),
        Point (
            24.105078 - 15 / (111.320 * COS(RADIANS(56.946285))),
            56.946285 - 15 / 111.133
        )
    ),
    coordinates
    )
HAVING distance < 15
ORDER By distance;

This query uses MBRContains for initial filtering and then a HAVING clause with the Haversine formula to precisely select points within 15 kilometers.

Solution 2: Pre-filtering with a Bounding Box

An effective strategy to speed up distance calculations is to first filter the dataset using a simple bounding box based on latitude and longitude ranges. This pre-filtering significantly reduces the number of records that require more complex distance computations.

  1. Define the Box: Calculate the minimum and maximum latitude and longitude values that encompass your target radius. For a radius of 10 units:
    • Top-Left: (target_lat + 10 / 111.1, target_lon - 10 / (111.1 / cos(radians(target_lat))))
    • Bottom-Right: (target_lat - 10 / 111.1, target_lon + 10 / (111.1 / cos(radians(target_lat))))
  2. Apply the Filter: Use these calculated bounds in your WHERE clause.

Example Query:

SELECT
    name,
    ( 3959 * acos( cos( radians(42.290763) )
            * cos( radians(locations.lat) )
            * cos( radians(locations.lng) - radians(-71.35368) )
            + sin( radians(42.290763) )
            * sin( radians(locations.lat) ) ) ) AS distance
FROM locations
WHERE active = 1
AND locations.lat BETWEEN X1 AND X2  -- Replace X1, X2 with calculated bounds
AND locations.Long BETWEEN y1 AND y2; -- Replace y1, y2 with calculated bounds
HAVING distance < 10
ORDER BY distance;

This query first filters by latitude and longitude ranges, then calculates the precise distance for the remaining records, applying a final filter for distances less than 10. This “thinking inside the box” approach drastically improves performance.

Solution 3: Using the Haversine Formula Directly

The Haversine formula is a standard method for calculating the great-circle distance between two points on a sphere given their longitudes and latitudes.

MySQL Function for Distance:

A custom MySQL function can encapsulate the Haversine calculation for reusability.

DELIMITER $$

DROP FUNCTION IF EXISTS `get_distance_in_miles_between_geo_locations` $$
CREATE FUNCTION get_distance_in_miles_between_geo_locations(
  geo1_latitude decimal(10,6), geo1_longitude decimal(10,6),
  geo2_latitude decimal(10,6), geo2_longitude decimal(10,6))
returns decimal(10,3) DETERMINISTIC
BEGIN
  return ((ACOS(SIN(geo1_latitude * PI() / 180) * SIN(geo2_latitude * PI() / 180)
    + COS(geo1_latitude * PI() / 180) * COS(geo2_latitude * PI() / 180)
    * COS((geo1_longitude - geo2_longitude) * PI() / 180)) * 180 / PI())
    * 60 * 1.1515);
END $$

DELIMITER ;

Sample Usage:

SELECT get_distance_in_miles_between_geo_locations(-34.017330, 22.809500,
latitude, longitude) AS distance_from_input FROM places;

This function calculates distance in miles. For kilometers, adjust the multiplier (e.g., use 6371 instead of 60 * 1.1515).

Direct Calculation in a Query:

You can also embed the Haversine calculation directly into your SQL queries.

SELECT
    *,
    (((acos(sin((@latitude * pi()/180)) * sin((`lat` * pi()/180)) + cos((@latitude * pi()/180))
    * cos((`lat` * pi()/180)) * cos(((@longitude - `lng`) * pi()/180))))*180/pi())*60*1.1515)
    AS distance
FROM your_table
HAVING distance < 22;

Solution 4: Using ST_Distance_Sphere (MySQL 5.7+)

For versions of MySQL 5.7 and newer, the ST_Distance_Sphere function provides a convenient way to calculate the distance between two points on a sphere.

Example:

SELECT ST_Distance_Sphere(POINT(-2.997065, 53.404146), POINT(58.615349, 23.56676)) / 1000 AS distance_in_km;

This function returns the distance in meters, so dividing by 1000 converts it to kilometers.

Solution 5: Approximated Distance Calculation

For scenarios where extreme precision is not critical and performance is paramount, a simpler spherical projection can offer a significant speed boost. This approximation is particularly useful for smaller distances.

Java Example (Illustrative):

public double approxDistKm(double fromLat, double fromLon, double toLat, double toLon) {
    double dLat = Math.toRadians(toLat - fromLat);
    double dLon = Math.toRadians(toLon - fromLon);
    double tmp = Math.cos(Math.toRadians((fromLat + toLat) / 2)) * dLon;
    double d = dLat * dLat + tmp * tmp;
    return R * Math.sqrt(d); // R is Earth's radius
}

While this is a Java example, the principle can be applied to optimize SQL calculations if a suitable approximation function is available or implemented.

Solution 6: Using Pre-calculated Bounding Box Variables

This method utilizes session variables to define the latitude and longitude boundaries for a search radius, making the query more readable and manageable.

Example:

SET @latitude = 53.754842;
SET @longitude = -2.708077;
SET @radius = 20; -- Radius in approximate miles or kilometers depending on factors

SET @lng_min = @longitude - @radius / ABS(COS(RADIANS(@latitude)) * 69);
SET @lng_max = @longitude + @radius / ABS(COS(RADIANS(@latitude)) * 69);
SET @lat_min = @latitude - (@radius / 69);
SET @lat_max = @latitude + (@radius / 69);

SELECT * FROM postcode
WHERE (longitude BETWEEN @lng_min AND @lng_max)
AND (latitude BETWEEN @lat_min AND @lat_max);

This approach first establishes the bounding box coordinates using session variables and then queries for records within that box. For precise distance filtering, a subsequent step involving the Haversine formula would be necessary.

FAQs on Optimizing MySQL Geo Distance Queries

Q: What is the best way to store geographical data in MySQL

ANS: For efficient spatial queries, store latitude and longitude in columns with appropriate data types (like DECIMAL or FLOAT). For advanced spatial operations, consider using MySQL’s POINT or GEOMETRY data types and ensure you have a SPATIAL index on these columns. Refer to https://www.sqlpey.com/sql/what-is-sql/ for SQL basics.

Q: How can I find locations within a specific radius using MySQL

ANS: You can use the Haversine formula directly in your SQL queries or create a custom MySQL function for it. Alternatively, for MySQL 5.7+, ST_Distance_Sphere is a convenient option. Pre-filtering with a bounding box can significantly improve performance for large datasets. See https://www.sqlpey.com/python/top-4-ways-to-resolve-syntaxwarning-invalid-escape-sequence-in-python/ for related concepts in Python.

Q: What is a SPATIAL index in MySQL

ANS: A SPATIAL index is a type of index used for columns with spatial data types. It optimizes queries that involve spatial relationships, such as finding points within a certain area or distance, by organizing the data in a way that allows for faster retrieval of relevant spatial objects.

Q: Does MySQL support the Haversine formula

ANS: Yes, MySQL does not have a built-in Haversine function, but you can implement the formula directly in your SQL queries or create a user-defined function (UDF) to perform the calculation. Many of the provided solutions demonstrate how to do this.

Q: What is MBRContains in MySQL

ANS: MBRContains(mbr, geometry) is a spatial function that checks if a Minimum Bounding Rectangle (MBR) contains a given geometry. It’s often used with SPATIAL indexes to quickly filter out rows that are outside the specified rectangular area, thereby improving query performance.
