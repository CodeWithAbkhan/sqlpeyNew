“SQL: Select Oldest Person Per Group”

Several approaches exist to tackle this common database task. The core challenge lies in identifying the maximum Age within each distinct Group and then retrieving the corresponding record(s). Let’s explore various accepted solutions.

Solution 1: Using LEFT JOIN and WHERE NULL

This method relies on a self-join to find records where no “older” person exists within the same group.

Query:

SELECT o.*
FROM `Persons` o                   # 'o' for 'oldest in group'
  LEFT JOIN `Persons` b            # 'b' for 'bigger age'
      ON o.Group = b.Group AND o.Age < b.Age
WHERE b.Age IS NULL                # 'bigger age not found'

How it works: This query joins the Persons table to itself. For each row in o, it looks for any row in b that belongs to the same Group but has a strictly greater Age. If no such row exists in b (meaning b.Age is NULL for that join), it implies that the row from o represents the oldest person in its group.

Solution 2: MySQL Specific - Subquery and GROUP BY

This approach leverages MySQL’s flexibility in GROUP BY clauses.

Query:

SELECT *
FROM (
    SELECT * FROM mytable
    ORDER BY `Group`, age DESC, Person
) x
GROUP BY `Group`;

How it works: The inner query first sorts all records by Group, then by Age in descending order, and finally by Person (to ensure consistent results if ages are tied). MySQL’s non-standard GROUP BY behavior then selects the first row encountered for each Group after this ordering, effectively giving you the oldest person.

Note: This is a MySQL-specific solution and might not work on other database systems due to the ONLY_FULL_GROUP_BY SQL mode.

Solution 3: Using INNER JOIN with a Subquery for MAX Age

This is a widely portable method that joins the main table with a derived table containing the maximum age for each group.

Query:

SELECT t1.*
FROM yourTable t1
INNER JOIN (
    SELECT `Group`, MAX(Age) AS max_age
    FROM yourTable
    GROUP BY `Group`
) t2
    ON t1.`Group` = t2.`Group` AND t1.Age = t2.max_age;

How it works: The subquery t2 calculates the maximum Age for each Group. The main query then joins yourTable (t1) with t2 on both Group and Age, effectively filtering for only those rows that match the maximum age within their respective groups.

Solution 4: PostgreSQL Specific - DISTINCT ON

PostgreSQL offers a convenient DISTINCT ON clause for this purpose.

Query:

SELECT DISTINCT ON ("group") * FROM "mytable" ORDER BY "group", "age" DESC;

How it works: DISTINCT ON ("group") tells PostgreSQL to return only one row for each unique value in the "group" column. The ORDER BY "group", "age" DESC clause is crucial here; it ensures that for each group, the row with the highest age is considered first, and thus selected by DISTINCT ON.

Solution 5: Using ROW_NUMBER() Window Function

Window functions, available in many modern SQL databases (like SQL Server, PostgreSQL, Oracle, and recent MySQL versions), provide an elegant solution.

Query:

SELECT
  t.person, t.gp, t.age
FROM (
  SELECT *,
         ROW_NUMBER() OVER (PARTITION BY gp ORDER BY age DESC) row
  FROM p
) t
WHERE t.row = 1;

How it works: ROW_NUMBER() OVER (PARTITION BY gp ORDER BY age DESC) assigns a sequential rank to each row within its gp partition, based on age in descending order. The oldest person in each group will receive a row number of 1. The outer query then filters for these rows.

Solution 6: Refined LEFT JOIN for Ties

This approach refines Solution 1 to handle ties by adding a secondary condition.

Query:

SELECT o.*
FROM `Persons` o
  LEFT JOIN `Persons` b
      ON o.Group = b.Group AND o.Age < b.Age
  LEFT JOIN `Persons` c
      ON o.Group = c.Group AND o.Age = c.Age AND o.id < c.id  # Assuming 'id' is a unique identifier
WHERE b.Age IS NULL AND c.id IS NULL;

How it works: It first applies the logic from Solution 1. Then, it adds a second LEFT JOIN (c) to identify duplicate oldest ages within a group. If multiple people share the maximum age, this join helps select a single one (based on id in this example).

Solution 7: User-Defined Variables (MySQL)

This method uses session variables for tracking.

Query:

SELECT @rn := CASE WHEN @prev_grp <> groupa THEN 1 ELSE @rn + 1 END AS rn,
   @prev_grp := groupa,
   person, age, groupa
FROM   users, (SELECT @rn := 0) r
HAVING rn = 1
ORDER BY groupa, age DESC, person;

How it works: It initializes a row counter (@rn) and a previous group tracker (@prev_grp). As it iterates through the sorted data, it resets the counter when a new group is encountered. The HAVING rn = 1 clause filters for the first row (oldest) of each group.

Solution 8: INNER JOIN with Subquery (Alternative Syntax)

A variation of Solution 3, using a different alias structure.

Query:

SELECT a.Person, a.Group, a.Age FROM [TABLE_NAME] a
INNER JOIN
(
  SELECT `Group`, MAX(Age) AS oldest FROM [TABLE_NAME]
  GROUP BY `Group`
) b ON a.Group = b.Group AND a.Age = b.oldest;

How it works: Similar to Solution 3, this query first finds the maximum age per group in the subquery b and then joins it back to the main table a to retrieve the full records.

Solution 9: GROUP_CONCAT for Single Column Retrieval (MySQL)

This is a performance-oriented solution for specific cases, especially when only one column value is needed.

Query:

SELECT SUBSTRING_INDEX(GROUP_CONCAT(column_x ORDER BY column_y), ',', 1) AS xyz,
   column_z
FROM table_name
GROUP BY column_z;

How it works: GROUP_CONCAT concatenates values from column_x (ordered by column_y) into a single string for each column_z. SUBSTRING_INDEX then extracts the first element from this comma-separated string, giving you the desired value from the “oldest” record.

Solution 10: Nested LEFT JOIN for Multiple Criteria

An extension of Solution 1 for scenarios with secondary sorting criteria (e.g., height).

Query:

SELECT o1.*
FROM (
    SELECT o.*
    FROM `Persons` o
    LEFT JOIN `Persons` b
    ON o.Group = b.Group AND o.Age < b.Age
    WHERE b.Age IS NULL
) o1
LEFT JOIN (
    SELECT o.*
    FROM `Persons` o
    LEFT JOIN `Persons` b
    ON o.Group = b.Group AND o.Age < b.Age
    WHERE b.Age IS NULL
) o2
ON o1.Group = o2.Group AND o1.Height < o2.Height -- Secondary sorting on Height
WHERE o2.Height IS NULL;

How it works: This solution nests the logic of finding the oldest person. If there’s a tie in age, it applies a second condition (e.g., Height) to select the appropriate record.

Solution 11: Oracle Specific - ROWNUMBER (Should be ROW_NUMBER)

Query:

SELECT group, person, Age,
  ROW_NUMBER() OVER (PARTITION BY "group" ORDER BY age DESC, person ASC) as rankForEachGroup
  FROM tablename WHERE rankForEachGroup = 1;

How it works: This uses the ROW_NUMBER() window function, similar to Solution 5, partitioning by group and ordering by age to assign ranks. It then selects rows where the rank is 1. (Note: The original provided query incorrectly used ROWNUMBER(); ROW_NUMBER() is the standard syntax).

Solution 12: CTE with MAX PKID

This uses Common Table Expressions (CTEs) to first identify the maximum primary key for a given column and then joins back.

Query:

WITH MyCTE AS (
    SELECT MAX(a.MyTablePKID) AS MaxPKID, a.SomeColumn1
    FROM MyTable1 a
    GROUP BY a.SomeColumn1
)
SELECT b.MyTablePKID, b.SomeColumn1, b.SomeColumn2, MAX(b.NumEstado)
FROM MyTable1 b
INNER JOIN MyCTE c ON c.MaxPKID = b.MyTablePKID
GROUP BY b.MyTablePKID, b.SomeColumn1, b.SomeColumn2;

How it works: The CTE MyCTE finds the MAX(MyTablePKID) for each SomeColumn1. The main query then joins MyTable1 (b) with MyCTE (c) on this MaxPKID to retrieve the relevant records.

Solution 13: CTE with ROW_NUMBER()

Another CTE-based solution, utilizing ROW_NUMBER().

Query:

WITH CTE AS (
    SELECT Person,
           [Group],
           Age,
           ROW_NUMBER() OVER(PARTITION BY [Group] ORDER BY Age DESC) AS RN
    FROM yourtable
)
SELECT Person, Age
FROM CTE
WHERE RN = 1;

How it works: This CTE assigns a rank (RN) to each person within their group based on age (descending). The outer query then selects only those records where RN is 1.

Solution 14: MySQL Specific - Correlated Subquery for N Max Rows

This solution uses a correlated subquery to count how many rows are “greater” within the same group.

Query:

SELECT co.id, co.person, co.country
FROM person co
WHERE (
    SELECT COUNT(*)
    FROM person ci
    WHERE co.country = ci.country AND co.id < ci.id  -- Or ci.id < co.id for MIN
) < 1; -- Adjust '< 1' for N max rows, e.g., '< 3' for top 3

How it works: For each row in person co, the subquery counts how many rows in person ci share the same country but have a “greater” id (or meet another criterion for “older”). If this count is less than 1, it means no other record in the group is considered “greater,” thus selecting the “oldest.”

Solution 15: Using IN with MAX and GROUP BY

A concise approach if only the Age column is needed directly from the MAX aggregation.

Query:

SELECT * FROM mytable WHERE age IN (SELECT MAX(age) FROM mytable GROUP BY `Group`);

How it works: The subquery finds the maximum age for each Group. The outer query then selects all rows from mytable where the age matches any of these maximum ages. This might return multiple rows per group if there are age ties.

Solution 16: GROUP_CONCAT for Ordered Lists

This displays all ages for a group in a comma-separated, ordered list.

Query:

SELECT person, `group`,
    GROUP_CONCAT(
        DISTINCT age
        ORDER BY age DESC SEPARATOR ', follow up: '
    )
FROM sql_table
GROUP BY `group`;

How it works: GROUP_CONCAT concatenates distinct age values for each group, ordered from highest to lowest, using “, follow up: " as a separator. This doesn’t directly select the oldest person but presents the age distribution.

Solution 17: Subquery in WHERE Clause

This uses a subquery directly in the WHERE clause to find the maximum age.

Query:

select O.*
from people O, people T
where O.grp = T.grp and
O.Age =
(select max(T.age) from people T where O.grp = T.grp
  group by T.grp)
group by O.grp;

How it works: The subquery finds the maximum age for each group. The main query then joins people O with people T and filters where O.Age equals the maximum age for that group. The final GROUP BY O.grp is intended to ensure one row per group, but might behave inconsistently with ties compared to other methods.

Solution 18: Using NOT IN with a Self-Join

This approach excludes records that have a “greater” counterpart in the same group.

Query:

SELECT
    *
FROM
    mytable
WHERE
    id NOT IN (
        SELECT
            A.id
        FROM
            mytable AS A
        JOIN mytable AS B ON A. Group = B. Group
        AND A.age < B.age
    );

How it works: The subquery identifies the ids of all people who are not the oldest in their group (i.e., they have a greater age in the same group). The outer query then selects all rows whose id is not in this list.

Solution 19: LEFT JOIN, WHERE NULL, and GROUP BY

A variation of Solution 1, adding a GROUP BY at the end.

Query:

SELECT o.*
FROM `Persons` o
  LEFT JOIN `Persons` b
      ON o.Group = b.Group AND o.Age < b.Age
WHERE b.Age IS NULL
GROUP BY o.Group;

How it works: This first finds the oldest individuals using the LEFT JOIN method. The GROUP BY o.Group clause is then applied. Note that if multiple people share the maximum age within a group, the GROUP BY might return only one of them, depending on the specific SQL implementation and data.

Solution 20: Simple MAX and GROUP BY (Common Practice)

A straightforward query often used for simple cases.

Query:

SELECT xref, MAX(change_time) AS last_change
FROM ug_change
GROUP BY xref;

How it works: This query directly uses MAX() with GROUP BY to find the maximum value of change_time for each xref. This is suitable if you only need the maximum value itself, not the entire record.

Solution 21: MySQL 8+ with DENSE_RANK()

Leveraging window functions in newer MySQL versions.

Query:

SELECT
  Person, `Group`, Age
FROM (
  SELECT
    *,
    DENSE_RANK() OVER ( PARTITION BY `Group` ORDER BY Age DESC ) AS rank
  FROM People
) _
WHERE
  rank = 1;

How it works: Similar to Solution 5, this uses DENSE_RANK() to assign a rank within each group based on age (descending). Records with rank = 1 are the oldest.

FAQs on SQL: Select Oldest Person Per Group

Q: How do I select the oldest person from each group?

ANS: Several methods exist, including using LEFT JOIN where the right side is NULL, DISTINCT ON in PostgreSQL, window functions like ROW_NUMBER() or DENSE_RANK(), or specific MySQL features like GROUP_CONCAT or subqueries with MAX. The best method depends on your specific database system and handling of ties.

Q: What is the most portable SQL method to find the oldest person per group?

ANS: Using an INNER JOIN with a subquery that calculates MAX(Age) per group is generally the most portable across different SQL database systems.

Q: How do I handle ties if multiple people have the same maximum age in a group?

ANS: For ties, methods using ROW_NUMBER() or DENSE_RANK() allow you to specify secondary sorting criteria (e.g., by person’s name or ID) to pick a single oldest person. The LEFT JOIN method might return multiple rows for a group if there are ties.

Q: Can I use GROUP BY directly to get the oldest person?

ANS: While you can use MAX(Age) with GROUP BY, it typically only returns the maximum age itself, not the full record of the oldest person. To get the full record, you usually need to join the aggregated result back to the original table or use window functions.
