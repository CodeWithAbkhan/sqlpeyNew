“How to Install Specific Older Homebrew Package Versions”

Encountering situations where you need to revert to a precise older version of a software package installed via Homebrew is common. This might be due to compatibility issues with newer versions, specific project requirements, or regressions found in recent releases. Homebrew, while primarily focused on providing the latest software, offers several strategies to manage and install specific historical versions of formulas.

The core challenge lies in Homebrew’s design, which typically points to the latest stable version. Older versions might not be directly available through standard brew install commands unless explicitly maintained in separate taps or historical commits. Let’s explore the various approaches to tackle this.

Solution 1: Using Versioned Taps (Deprecated but Informative)

Historically, Homebrew provided a homebrew/versions tap that housed older versions of many popular packages. While this tap is now deprecated, understanding its mechanism offers insight into how version management was handled.

For instance, to install an older PostgreSQL version, one might have used:

# Tap the versions repository (if it were still active)
# brew tap homebrew/versions

# Install a specific version (e.g., PostgreSQL 8.4.8)
brew install https://raw.github.com/Homebrew/homebrew-versions/master/postgresql8.rb

Similarly, for MySQL:

brew install https://raw.github.com/Homebrew/homebrew-versions/master/mysql51.rb

This method relied on the availability of specific formula files within the homebrew/versions repository.

Solution 2: Leveraging Versioned Formulae in Homebrew Core

As homebrew/versions was deprecated, Homebrew core started supporting multiple versions directly using a new naming convention, often with an @ symbol.

To install a specific version, like PostgreSQL 9.5:

brew install postgresql@9.5

To discover available versioned formulae:

brew search postgresql@

This will list formulae like postgresql@9.6, postgresql@10, etc.

Solution 3: Utilizing Git Commits for Formula Versions

A robust method involves directly installing a formula from a specific commit in the Homebrew core repository. This allows pinpoint accuracy to any historical version.

Step 1: Identify the Formula’s Git History

First, find the formula file for your desired package. For example, for postgresql:

brew info postgresql

This will show a line like From: https://github.com/Homebrew/homebrew/commits/master/Library/Formula/postgresql.rb. Navigate to this URL or use git log locally if you have cloned the Homebrew core repository.

Alternatively, you can use brew log <formula> to see the commit history directly.

# Example: viewing logs for the 'bash' formula
brew log bash

This output will list commits with their SHAs, authors, and dates. Identify the commit SHA corresponding to the version you need.

Step 2: Construct the Raw Git URL

Once you have the commit SHA, construct a URL to the raw formula file at that specific commit. The pattern is generally:

https://raw.githubusercontent.com/Homebrew/homebrew-core/<commit-sha>/Formula/<formula-name>.rb

For example, to install a specific older bash version associated with a commit:

# Replace <commit-sha> with the actual SHA found in brew log
BREW_VERSION_SHA="abcdef1234567890abcdef1234567890abcdef12" # Example SHA
BREW_FORMULA_NAME="bash"

brew install "https://raw.githubusercontent.com/Homebrew/homebrew-core/${BREW_VERSION_SHA}/Formula/${BREW_FORMULA_NAME}.rb"

Step 3: Unlink and Switch (If Necessary)

If you have a newer version already installed, you might need to unlink it before installing the older version:

brew unlink <formula>

After installing the older version, you can switch between installed versions using brew switch if the versions were installed in separate “kegs” (directories within /usr/local/Cellar).

# Check available versions
brew info <formula>

# Switch to an older version
brew switch <formula> <version>

Important Note on brew switch: brew switch functionality has been deprecated and removed in newer Homebrew versions. The Git commit method is the primary way to install specific historical versions.

Solution 4: Using brew extract and Custom Taps

You can use brew extract to copy a specific version of a formula to a new, local tap. This is useful for creating your own curated versions or for managing specific requirements.

Step 1: Create a New Tap

brew tap-new <your-username>/local-tap

Step 2: Extract the Formula Version

Use brew extract with the desired version.

# Example: Extracting htop version 3.3.0
brew extract --version=3.3.0 htop <your-username>/local-tap

Step 3: Install from Your Custom Tap

Now, install the extracted formula from your newly created tap. The naming convention will typically be formula@version.

brew install <your-username>/local-tap/htop@3.3.0

Caveats:

  • This process clones the entire homebrew-core repository, which can consume significant disk space.
  • It often builds from source, which may take longer.
  • Manually managed taps won’t be automatically updated by brew update.

Solution 5: Manual Formula Editing

For very specific needs or when other methods fail, you can manually edit a formula file.

Step 1: Edit the Formula

brew edit <formula>

This command opens the formula file in your default text editor.

Step 2: Modify Version Details

Locate the version, url, sha256, and potentially mirror attributes. Update these to point to the specific older version you need. You’ll need to find the correct download URL and its corresponding SHA-256 checksum.

# Example modification within a formula file
url "https://ssl.icu-project.org/files/icu4c/62.1/icu4c-62_1-src.tgz"
mirror "https://github.com/unicode-org/icu/releases/download/release-62-1/icu4c-62_1-src.tgz"
version "62.1"
sha256 "3dd9868d666350dda66a6e305eecde9d479fb70b30d5b55d78a1deffb97d5aa3"

Step 3: Reinstall the Formula

After saving the changes, reinstall the formula:

brew reinstall <formula>

Solution 6: Scripted Approaches for Automation

Several community-contributed scripts and functions aim to simplify this process. These often automate the Git log searching and raw URL construction. For example, a brew-switch function can be added to your shell’s configuration file (.zshrc, .bashrc) to manage specific versions.

# Example usage of a hypothetical brew-switch function
brew-switch <formula> <version>
# e.g., brew-switch argocd 2.8.6

These scripts typically leverage the GitHub CLI (gh) to find the correct commit SHAs and then proceed with downloading and installing the formula.

Solution 7: Pinning and Unpinning

If you need to temporarily use an older version and prevent it from being upgraded by brew upgrade, you can pin it.

# Install the desired older version
# ... (using one of the methods above) ...

# Pin the installed version
brew pin <formula>

Later, when you want to allow upgrades again:

brew unpin <formula>

Solution 8: Using Versioned Package Names (e.g., python@3.9)

Homebrew directly supports certain versioned packages using the @ notation. This is the most straightforward method when available.

# Install a specific Python version
brew install python@3.9

Check brew search <package> to see if versioned formulae are available.

Important Considerations

  • Dependencies: When installing older versions, ensure that their dependencies are also compatible or available. You may need to install specific versions of dependent packages as well.
  • Security: Older software versions might have unpatched security vulnerabilities. Use them with caution, especially if the system is exposed to the internet.
  • Homebrew Updates: brew update can sometimes interfere with manually installed or pinned older versions. Be mindful of how brew update and brew upgrade interact with your managed versions.
  • Formula Changes: Over time, Homebrew formula files themselves evolve. A formula from years ago might rely on different Homebrew features or syntax that may no longer be directly supported.

By employing these methods, you can effectively manage specific versions of software packages installed via Homebrew, ensuring compatibility and stability for your projects.

FAQs on Installing Specific Older Homebrew Package Versions

Q: How can I check which versions of a package are installed via Homebrew

ANS: You can use the brew info <formula> command. It lists all installed versions of a formula, typically marked with an asterisk (*) if it’s the currently linked version.

Q: What if the version I need isn't listed in Homebrew's history

ANS: If a specific version isn’t easily found via brew log or brew search, you might need to search for the formula’s source code history on the Homebrew core GitHub repository directly. You can then manually construct the raw URL for that specific commit.

Q: Can I install an older version of a cask using similar methods

ANS: Yes, similar principles apply to Homebrew Casks. You can often find older versions of Cask files in the homebrew/cask-versions repository or by inspecting the Git history of Cask files in the main homebrew-cask repository. The process usually involves finding the correct .rb file for the desired version and installing it locally.

Q: What does 'pinning' a formula do in Homebrew

ANS: Pinning a formula prevents brew upgrade from updating it to a newer version. This is useful if you have a specific older version installed that you do not want to be automatically replaced. You can unpin it later to allow upgrades again.

Q: Is it safe to use very old versions of software

ANS: Using very old software versions can pose security risks, as they may contain unpatched vulnerabilities. It’s generally recommended to use the oldest version that meets your compatibility needs while considering security implications.

Q: Why was `brew switch` deprecated

ANS: brew switch was removed because Homebrew’s internal structure changed, making it more difficult to manage multiple linked versions of the same formula efficiently and reliably. The recommended approach now involves installing specific versions via versioned taps or Git commits.

Q: How do I find the correct SHA for a specific version

ANS: Use brew log <formula> to view the commit history. Look for commits that mention the version you need. The output provides commit SHAs which you can use to construct the raw URL for installation.

Q: Can I install an older version of Python using Homebrew

ANS: Yes, Homebrew often provides versioned Python formulae like python@3.9 or python@3.10. If the specific version you need isn’t available this way, you can fall back to using Git commit methods or community scripts.
