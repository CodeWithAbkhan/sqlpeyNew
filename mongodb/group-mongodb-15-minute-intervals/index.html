“Group MongoDB Documents by 15-Minute Intervals”

How can I efficiently group MongoDB documents into 15-minute intervals using the aggregation framework, and what are the various approaches available across different MongoDB versions?

This question explores methods for aggregating documents based on time-based intervals, specifically 15-minute chunks. We’ll examine how to achieve this using date aggregation operators, date math with epoch timestamps, and newer features introduced in later MongoDB releases. The goal is to group documents by their created_at field or similar date fields into distinct 15-minute buckets and count the occurrences within each bucket.

Methods for Grouping by 15-Minute Intervals

Several strategies exist to achieve this temporal grouping. The choice often depends on the MongoDB version you are utilizing and the desired output format of your grouped intervals.

Solution 1: Using Date Aggregation Operators

One primary method involves leveraging MongoDB’s date aggregation operators within the $group stage. This approach breaks down the date field into its constituent parts (year, day, hour) and then calculates the specific interval.

db.collection.aggregate([
  {
    $group: {
      _id: {
        year: { $year: "$created_at" },
        dayOfYear: { $dayOfYear: "$created_at" },
        hour: { $hour: "$created_at" },
        interval: {
          $subtract: [
            { $minute: "$created_at" },
            { $mod: [{ $minute: "$created_at" }, 15] }
          ]
        }
      },
      count: { $sum: 1 }
    }
  }
])

This query groups documents by year, day of the year, hour, and then calculates the start of the 15-minute interval by subtracting the remainder of the minute divided by 15 from the minute itself.

Solution 2: Date Math with Epoch Timestamps

An alternative approach utilizes date math. When subtracting one date object from another, MongoDB returns the difference in milliseconds since the Unix epoch. This numeric representation can then be manipulated to define intervals.

db.collection.aggregate([
  {
    $group: {
      _id: {
        $subtract: [
          { $subtract: ["$created_at", new Date("1970-01-01")] },
          {
            $mod: [
              { $subtract: ["$created_at", new Date("1970-01-01")] },
              1000 * 60 * 15
            ]
          }
        ]
      },
      count: { $sum: 1 }
    }
  }
])

In this method, the created_at field is converted to its epoch millisecond representation. Then, modulo arithmetic is applied with the interval size (15 minutes in milliseconds) to find the start of each interval.

Solution 3: Type Casting with $toLong and $toDate (MongoDB 4.x+)

For MongoDB versions 4.0 and later, more direct type casting is available, simplifying interval calculations. The $toLong and $toDate operators facilitate easier manipulation of date values.

db.collection.aggregate([
  {
    $group: {
      _id: {
        $toDate: {
          $subtract: [
            { $toLong: "$created_at" },
            { $mod: [{ $toLong: "$created_at" }, 1000 * 60 * 15] }
          ]
        }
      },
      count: { $sum: 1 }
    }
  }
])

This approach is more concise as it directly converts the date to a long integer (epoch milliseconds) and then uses the modulo operation before converting back to a Date object.

Solution 4: Using ObjectId for Time Information (MongoDB 4.x+)

A more advanced technique, applicable from MongoDB 4.x, involves extracting time information directly from the _id field if it’s an ObjectId. The ObjectId contains a timestamp component.

db.collection.aggregate([
  {
    $group: {
      _id: {
        $toDate: {
          $subtract: [
            { $toLong: { $toDate: "$_id" } },
            { $mod: [{ $toLong: { $toDate: "$_id" } }, 1000 * 60 * 15] }
          ]
        }
      },
      count: { $sum: 1 }
    }
  }
])

Important Note: While this method is possible, ObjectId timestamps are precise only to the second. For finer-grained precision, it’s recommended to use a dedicated BSON Date field.

Solution 5: Returning Native Date Objects

To ensure the aggregated interval is returned as a native Date object (compatible with various programming languages), you can use a combination of date math and addition.

db.collection.aggregate([
  {
    "$group": {
      "_id": {
        "$add": [
          {
            "$subtract": [
              { "$subtract": ["$created_at", new Date(0)] },
              {
                "$mod": [
                  { "$subtract": ["$created_at", new Date(0)] },
                  1000 * 60 * 15
                ]
              }
            ]
          },
          new Date(0)
        ]
      },
      "count": { "$sum": 1 }
    }
  }
])

Here, new Date(0) represents the Unix epoch. By adding this back after the interval calculation, the result is cast to a BSON Date type.

Solution 6: Using $dateToString and $trunc (Alternative Interval Formatting)

For more flexible formatting of the interval, you can use $dateToString combined with $trunc for custom interval calculations.

db.collection.aggregate([
  {
    $group: {
      _id: {
        overallTime: {
          $dateToString: { format: "%Y-%m-%dT%H", date: "$created_at" }
        },
        interval: { $trunc: { $divide: [{ $minute: "$created_at" }, 15] } }
      },
    }
  }
])

You can customize the format string for different granularities, such as minutes (%Y-%m-%dT%H:%M) or days (%Y-%m-%d).

Solution 7: $dateTrunc for Time Truncation (MongoDB 5.x+)

MongoDB 5.0 and later introduces $dateTrunc, a dedicated operator for truncating dates to a specified unit and bin size.

db.collection.aggregate([
  {
    $group: {
      _id: { $dateTrunc: { date: "$created_at", unit: "minute", binSize: 15 } },
      count: { $sum: 1 }
    }
  }
])

This is a highly readable and efficient method for grouping by fixed time intervals.

Solution 8: $setWindowFields for Temporal Window Calculations (MongoDB 5.x+)

For more advanced scenarios involving calculations across documents within a temporal window, $setWindowFields is available from MongoDB 5.0+. This allows you to count documents within a defined range around the current document.

db.collection.aggregate([
  {
    $setWindowFields: {
      partitionBy: null, // Process all documents together
      sortBy: { created_at: 1 }, // Order documents by creation time
      output: {
        count: {
          $count: {}, // Count documents within the window
          window: {
            range: [-15, 15], // Window of -15 to +15 minutes
            unit: "minute"
          }
        }
      }
    }
  }
])

This approach calculates a running count of documents within a sliding window, which can be useful for different types of temporal analysis.

Frequently Asked Questions

FAQs on Group MongoDB Documents by 15-Minute Intervals

Q: What is the most efficient way to group documents by 15-minute intervals in MongoDB

ANS: For MongoDB 5.0+, using the $dateTrunc operator within the $group stage is generally the most efficient and readable method. For older versions, date math with epoch timestamps or date aggregation operators are effective alternatives.

Q: Can I extract time information from ObjectIds for grouping

ANS: Yes, you can extract the timestamp component from ObjectId using $toDate and then apply date math. However, be aware that ObjectId timestamps are only precise to the second, so a dedicated date field is preferable for greater accuracy.

Q: How do I ensure the grouped interval is a Date object

ANS: When using date math, add new Date(0) back to the calculated epoch timestamp. In MongoDB 4.0+, $toDate can be used for direct conversion. For MongoDB 5.0+, $dateTrunc naturally returns a Date object.

Q: What if I need to group by different interval sizes

ANS: You can adjust the binSize parameter in $dateTrunc or the divisor in modulo operations for date math to accommodate different interval lengths (e.g., 5 minutes, 30 minutes, 1 hour).
