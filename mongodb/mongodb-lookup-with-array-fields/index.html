“MongoDB $lookup with Array Fields: Techniques and Modern Solutions”

The MongoDB $lookup aggregation stage is designed to perform a left outer join from one collection to another, typically matching a single field value. A common challenge arises when the localField on the source document contains an array of values (like product IDs in an order document) that needs to be joined against the foreignField in the destination collection.

This post examines various techniques to resolve this, ranging from necessary pre-2017 de-normalization patterns to modern pipeline-based joins.

Historical Context: The Need for De-Normalization Before 2017

Before specific MongoDB updates, $lookup fundamentally expected the localField to hold a singular value, mirroring traditional relational join concepts where one side of the join is “one-to-many.” If your local field was an array, direct joining was impossible, necessitating data transformation.

The $unwind and $group Pattern (Pre-Update Method)

To bridge this gap, the accepted method involved de-normalizing the array elements temporarily using $unwind, performing the join, and then re-grouping the results back into arrays.

Consider an orders collection with a products array of IDs, joining against a products collection:

db.orders.aggregate([
    // Step 1: Deconstruct the array field into separate documents
    { "$unwind": "$products" }, 
    
    // Step 2: Perform the lookup matching on the now-singular product ID
    { "$lookup": {
       "from": "products",
       "localField": "products", // Now a single ID after $unwind
       "foreignField": "_id",
       "as": "productObjects"
    }},
    
    // Step 3: Unwind the result array (which usually contains one match or none)
    { "$unwind": "$productObjects" },
    
    // Step 4: Reconstruct the original array structure
    { "$group": {
        "_id": "$_id",
        "products": { "$push": "$products" }, // Push the original IDs back
        "productObjects": { "$push": "$productObjects" } // Push the resolved objects
    }}
])

Important Note on Behavior: If a left join match in $lookup is not found, the resulting array (productObjects in this example) is empty. The subsequent $unwind on an empty array will negate that specific document from the output stream concerning that array element.

Modern Approach: Direct Array Matching with $lookup and Pipelines (Post MongoDB v3.4)

Starting with MongoDB version 3.4 (released around 2016), the $lookup stage gained the capability to process arrays directly, specifically when used in conjunction with the pipeline option. This avoids the costly $unwind/$group cycle.

Solution Using $lookup with pipeline and $expr

This approach utilizes the let parameter to hold the array from the local document and the $expr operator within the pipeline to perform an $in comparison against the foreign collection’s ID field.

If your source collection (orders) has an array of ObjectIds in the products field, you can match them directly:

db.orders.aggregate([
  {
    $lookup: {
      from: "products",
      let: { productIdsArray: "$products" }, // Store the local array as a variable
      pipeline: [
        { 
          $match: { 
            $expr: { 
              $in: ["$_id", "$$productIdsArray"] // Check if the foreign _id is IN the local array
            } 
          } 
        }
        // Further stages like $project can refine the result here
      ],
      as: "productObjects" // The array of matching documents
    }
  }
])

This is generally the preferred method when dealing with array lookups in recent MongoDB versions as it keeps processing within the aggregation pipeline efficiently.

Direct Array Match (Simplified Syntax in Newer Versions)

In some contexts, if the structure is simple (joining an array of IDs to an array of IDs), a more direct syntax might suffice if the version supports it without needing the full pipeline structure, although the pipeline method is more universally robust for array joins across versions that support it.

If you simply need to join an array of IDs (localField) to the target collection’s IDs (foreignField):

db.products.aggregate([
    { $match: { products : { $exists: true } } }, // Ensure the array exists
    {
        $lookup: {
            from: "products",
            localField: "products", // The array of IDs
            foreignField: "_id",    // The ID field in the 'products' collection
            as: "productObjects"    // Resulting array of documents
        }
    }
])

Self-correction Note: While this simplified syntax works for arrays in newer versions, especially if the array elements are ObjectIDs matching the foreign ID, the $lookup with the pipeline and $expr approach offers greater control and handles complex relational logic during the join better, often resolving ambiguity.

Alternative: Data Modeling Strategy Shift

MongoDB generally favors embedding data over relational joins. If frequent, complex joins on large arrays are necessary, consider adjusting the data model.

  1. Pre-Joining Data: Embed necessary product details directly into the order document. This eliminates the lookup entirely but introduces redundancy and update complexities.
  2. Reverse Referencing: If possible, structure references so the “many” side points to the “one” side. $lookup works optimally when referencing documents contain the reference ID, as it often avoids the need to de-normalize the parent document’s array first.

For example, if product documents contained an array orderIds pointing back to the order document, the lookup structure would be more natural for the $lookup stage’s original design intent.

Handling String IDs and Conversion

If your source array stores IDs as strings but the foreign field is an ObjectId, you must convert them prior to matching. Solution 7 demonstrates how to use $addFields with $map to convert string IDs to ObjectIds for a successful join:

db.users.aggregate([
  { $match: { _id: ObjectId(userId) } },
  {
    $addFields: {
      // Convert array of string IDs to array of ObjectIds
      productIds: { $map: { input: "$productids", in: { $toObjectId: "$$this" } } }
    }
  },
  {
    $lookup: {
      from: "products",
      localField: "productIds", // Use the newly converted ObjectId array
      foreignField: "_id",
      as: "products"
    }
  },
  { $project: { "products.name": 1, _id: 0 } }
])

Third-Party Library Solutions (Mongoose Example)

If you are operating within a Node.js environment using Mongoose, the .populate() method offers a higher-level abstraction that handles array population seamlessly, abstracting away the underlying aggregation complexity:

// Mongoose Schema Setup
var productSchema = Schema({ /* ... product fields ... */ });

var orderSchema = Schema({
  _id     : Number,
  // Defines 'products' as an array referencing the 'Product' model
  products: [ { type: Schema.Types.ObjectId, ref: "Product" } ] 
});

var Product = mongoose.model("Product", productSchema);
var Order   = mongoose.model("Order", orderSchema);

// Execution
Order
    .find({ /* query criteria */ })
    .populate("products") // Mongoose handles the join internally
    // ... other operations

FAQs on MongoDB Lookup With Array Fields

Q: Is the $unwind and $group method still necessary for array lookups

ANS: No, for MongoDB versions supporting the pipeline option in $lookup (v3.4+), using $lookup with $expr and $in is the preferred, more performant alternative.

Q: What is the primary benefit of using $lookup with a pipeline

ANS: It allows for dynamic conditional joining logic within the lookup stage itself, directly comparing array contents without flattening and re-grouping the main document structure.

Q: If the local field array is empty, what happens after $lookup

ANS: The resulting as field in the output document will be an empty array [].
