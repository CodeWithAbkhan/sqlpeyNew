Filtering Embedded Array Elements in MongoDB

When working with documents that contain arrays of sub-documents, isolating only the desired elements based on criteria within those sub-documents is a common requirement. Here are the principal approaches accepted for achieving this selective return.

Method 1: Deconstructing, Filtering, and Reconstructing with $unwind and $group

For scenarios requiring filtering and subsequent restructuring, the traditional aggregation pipeline utilizing $unwind before filtering proves effective. This method is suitable when you need to filter individual elements and then reassemble the resulting array.

The process involves:

  1. $match: Pinpointing the target document by its _id.
  2. $unwind: Deconstructing the array field, creating a separate document for each array element.
  3. $match: Applying the filtering condition to the newly exposed element fields (e.g., elements where list.a is greater than 3).
  4. $group: Re-collecting the matching elements back into an array structure, keyed by the original document’s _id.

Example Implementation (Filtering where list.a > 3):

db.test.aggregate([
    { $match: { _id: ObjectId("512e28984815cbfcb21646a7") } },
    { $unwind: '$list' },
    { $match: { 'list.a': { $gt: 3 } } },
    { $group: { _id: '$_id', list: { $push: '$list.a' } } }
])

Resulting Output:

{
  "result": [
    {
      "_id": ObjectId("512e28984815cbfcb21646a7"),
      "list": [
        4,
        5
      ]
    }
  ],
  "ok": 1
}

If you need to apply multiple conditions, like filtering for values between 0 and 5 (exclusive of 5):

// Using $and within the $match stage after $unwind
{ 
    $match: {
        $and: [
            { 'list.a': { $gt: 0 } },
            { 'list.a': { $lt: 5 } }
        ]
    }
}

(Note: In the context of the $unwind example above, applying $and directly within the second $match stage is straightforward, targeting 'list.a'.)

Method 2: Leveraging $filter Operator (MongoDB 3.2+)

For efficiency, especially in newer MongoDB versions, the $filter aggregation operator within a $project stage is often preferred. This avoids the resource-intensive $unwind and subsequent $group operations by filtering the array in place.

The $filter operator takes an input array, defines an alias (as), and applies a conditional (cond) expression to each element.

Example Implementation (Filtering where item.a > 3):

db.test.aggregate([
    { $match: { _id: ObjectId("512e28984815cbfcb21646a7") } },
    { 
        $project: {
            list: {
                $filter: {
                    input: '$list',
                    as: 'item',
                    cond: { $gt: ['$$item.a', 3] }
                }
            }
        }
    }
])

If you need to filter based on multiple criteria (e.g., value between 0 and 5, exclusive):

// Defining an $and condition for $filter
cond: { 
    $and: [
        { $gt: [ "$$item.a", 0 ] },
        { $lt: [ "$$item.a", 5 ] }
    ]
}

This approach preserves the original array structure but only populates it with matching sub-elements. It is critical to first use a $match stage targeting the existence of a matching element ({$match: {"list.a": {$gt:3}}}) if you only want to process documents that contain at least one match, as described in Solution 3 below.

Method 3: Pre-filtering Documents with Existence Check before Projection

When using $filter, you can first restrict the pipeline to only those documents that possess at least one array element meeting the criterion, and then use $filter to refine the output array.

Example (Document Match followed by $filter):

db.test.aggregate([
    // First, match documents where *any* element in 'list' satisfies list.a > 3
    { $match: { "list.a": { $gt: 3 } } }, 
    { 
        $project: {
            list: {
                $filter: {
                    input: "$list",
                    as: "listElement", // Renaming 'as' for clarity
                    cond: { $gt: ["$$listElement.a", 3] } // Filter sub-array based on condition
                }
            }
        }
    }
]);

This ensures that documents without any matching elements are excluded early from the processing stream. The resulting array maintains the original order of elements.

Alternative Query: Selecting a Single Matching Sub-Document with $elemMatch

If the goal is not to return a modified array containing all matching elements, but rather to retrieve the parent document along with only the first matching element found in the array, the $elemMatch projection operator in a standard find query is the most direct method.

This is best suited when you only need confirmation of a match or the first instance of a match, rather than a filtered array output.

Example Implementation (Finding the document and projecting only the first matching list item where a: 1):

db.test.find(
    { list: { $elemMatch: { a: 1 } } }, 
    { 'list.$': 1 }
)

Result Structure:

{
  "_id": ObjectId("..."),
  "list": [{a: 1}] // Contains only the first matching element
}

This technique differs significantly from the aggregation methods as it only returns one element in the array slice, even if multiple elements satisfy the query predicate.

FAQs on MongoDB Array Filtering Techniques

Q: What is the main difference between using $unwind and $filter for array operations

ANS: The $unwind method deconstructs the array into multiple documents for processing, requiring a subsequent $group stage to reconstruct the array. The $filter operator processes the array within a single document structure, generally leading to better performance as it avoids duplication and merging of documents.

Q: Can $filter be used without a preceding $match stage in aggregation

ANS: Yes, $filter can be used directly in $project. If no preceding $match restricts the documents, $filter will run on all documents, returning an empty array for documents where no elements meet the criteria.

Q: When should I use $elemMatch projection over aggregation

ANS: Use $elemMatch projection in a find() query when you need to return the parent document along with only the first element in the array that satisfies the query criteria. Use aggregation ($filter) when you need all matching array elements returned within a modified array.
