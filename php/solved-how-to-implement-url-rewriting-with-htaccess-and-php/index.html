“Solved: How to Implement URL Rewriting with .htaccess and PHP”

Creating user-friendly and search engine optimized URLs is a common goal in web development. Instead of dealing with lengthy URLs containing query parameters like picture.php?id=123, developers often aim for cleaner formats such as /picture/some-text/123. This is achieved through URL rewriting, a powerful technique supported by web servers like Apache through modules such as mod_rewrite, and can also be managed within your PHP application.

This post explores several effective methods for implementing URL rewriting, catering to different needs and levels of complexity. Whether you need a simple redirection or a robust routing system akin to Content Management Systems (CMS), we’ve got you covered.

Method 1: Direct .htaccess RewriteRule

For straightforward URL transformations, directly manipulating your .htaccess file with mod_rewrite is an efficient approach. This method is ideal when you have specific, predictable URL patterns to manage.

How it works:

You can add rules to your .htaccess file, located in your website’s root directory. These rules instruct the Apache server on how to interpret and rewrite incoming URLs before they are processed by your PHP scripts.

Example:

To rewrite a URL like /Some-text-goes-here/123 to picture.php?id=123, you would use the following directive:

RewriteEngine on
RewriteRule ^/?Some-text-goes-here/([0-9]+)$ /picture.php?id=$1
  • RewriteEngine on: This enables the mod_rewrite module.
  • RewriteRule: This directive defines the rewriting rule.
  • ^/?Some-text-goes-here/([0-9]+)$: This is a regular expression that matches URLs starting with an optional slash, followed by Some-text-goes-here/, and then one or more digits (captured in group ([0-9]+)). The $ ensures it matches the end of the URL.
  • /picture.php?id=$1: This is the target URL. $1 is a backreference to the first captured group in the RewriteRule pattern, which is the numeric ID in this case.

This method is simple and effective for specific cases, but it can become cumbersome to manage as the number of URL patterns grows.

Method 2: Implementing a Front Controller Pattern with PHP and .htaccess

A more scalable and flexible approach involves using a front controller pattern. In this setup, a single PHP file (typically index.php) acts as the entry point for all requests, and the application logic then determines how to handle the request based on the URL. This is how many popular CMS platforms and frameworks operate.

Folder Structure:

A common structure for this pattern is:

root/
  inc/              # Folder for included PHP files
  .htaccess         # Apache rewrite rules
  index.php         # The front controller

.htaccess Configuration:

The .htaccess file is configured to redirect most requests to index.php, while allowing direct access to static assets.

RewriteEngine On
# Redirect requests for the inc folder to index.php
RewriteRule ^inc/.*$ index.php

# If the requested file is not a file or a symbolic link, redirect to index.php
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-l
RewriteRule ^(.*)$ index.php [QSA,L]
  • RewriteRule ^inc/.*$ index.php: This rule specifically redirects requests starting with inc/ to index.php. This might be used to handle internal includes or specific assets.
  • RewriteCond %{REQUEST_FILENAME} !-f: This condition checks if the requested path does not correspond to an existing file.
  • RewriteCond %{REQUEST_FILENAME} !-l: This condition checks if the requested path does not correspond to an existing symbolic link.
  • RewriteRule ^(.*)$ index.php [QSA,L]: This is the core of the front controller. It captures any URL that doesn’t match the previous conditions (^(.*)$) and redirects it to index.php. [QSA] appends the original query string, and [L] makes it the last rule to be processed.

index.php (Front Controller Logic):

Inside index.php, you’ll parse the $_SERVER['REQUEST_URI'] to determine the intended action and pass parameters.

<?php
define( 'INCLUDE_DIR', dirname( __FILE__ ) . '/inc/' );

// Define your routing rules
$rules = array(
    'picture'   => "/picture/(?'text'[^/]+)/(?'id'\d+)",    // e.g., /picture/some-text/51
    'album'     => "/album/(?'album'[\w\-]+)",              // e.g., /album/album-slug
    'category'  => "/category/(?'category'[\w\-]+)",        // e.g., /category/category-slug
    'page'      => "/page/(?'page'about|contact)",          // e.g., /page/about, /page/contact
    'post'      => "/(?'post'[\w\-]+)",                     // e.g., /post-slug
    'home'      => "/",                                    // The homepage
);

// Prepare the request URI
$uri = rtrim( dirname($_SERVER["SCRIPT_NAME"]), '/' );
$uri = '/' . trim( str_replace( $uri, '', $_SERVER['REQUEST_URI'] ), '/' );
$uri = urldecode( $uri );

// Match the URI against the defined rules
foreach ( $rules as $action => $rule ) {
    if ( preg_match( '~^'.$rule.'$~i', $uri, $params ) ) {
        // Match found: include appropriate template file or handle logic
        // The $params array will contain captured segments from the URL
        // Example: $_GET['id'] = $params['id']; $_GET['text'] = $params['text'];

        // For demonstration, let's assume separate PHP files for actions
        if (file_exists(INCLUDE_DIR . $action . '.php')) {
            include INCLUDE_DIR . $action . '.php';
        } else {
            // Handle cases where the action file doesn't exist
            header('HTTP/1.1 500 Internal Server Error');
            echo "Error: Missing handler for action '{$action}'.";
        }
        exit; // Exit after handling the request
    }
}

// If no rule matched, handle as a 404 Not Found error
include INCLUDE_DIR . '404.php';
?>

This PHP code defines a set of regular expression rules to match different URL patterns. When a match occurs, it extracts parameters and can then include the relevant PHP file or execute the appropriate logic. This offers immense flexibility for complex routing needs.

Method 3: Simplified .htaccess for All Requests to index.php

A slightly more aggressive .htaccess rule redirects nearly all requests to index.php, with exceptions for existing files and directories. This is a common strategy for routing all application requests through a central handler.

.htaccess Configuration:

# If a directory or a file exists, use it directly
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-l
# Also check if the request is not for a directory (though !-f often covers this)
# RewriteCond %{REQUEST_FILENAME} !-d

# Exclude common static asset file extensions
RewriteCond %{REQUEST_FILENAME} !\.(ico|css|png|jpg|gif|js)$ [NC]

# Otherwise, forward it to index.php
RewriteRule . index.php [L]
  • The RewriteCond directives ensure that requests for actual files (like images, CSS, JavaScript) or directories are served directly by the server and not processed by index.php.
  • The final RewriteRule . index.php [L] catches everything else and sends it to index.php for processing.

The logic within index.php would then parse $_SERVER["REQUEST_URI"] to determine the action, similar to Method 2.

<?php
// Extract URL parts, filter out empty segments
$uri_parts = array_values(array_filter(explode("/", $_SERVER["REQUEST_URI"])));

// Example of processing parts
if (empty($uri_parts)) {
    // Handle homepage request
    echo "Welcome to the homepage!";
} else {
    $first_segment = $uri_parts[0];

    if ($first_segment === 'picture' && isset($uri_parts[1]) && isset($uri_parts[2])) {
        // Handle picture route, e.g., /picture/some-text/51
        $text = $uri_parts[1];
        $id = $uri_parts[2];
        echo "Displaying picture: {$text} with ID: {$id}";
        // In a real app, you'd fetch and display the picture
    } else {
        // Handle other routes or show 404
        echo "Page not found or invalid route.";
    }
}
?>

Method 4: Direct RewriteRule for Specific URL Structures

If you only need to rewrite a specific type of URL without implementing a full front controller, a targeted RewriteRule can suffice. This is for scenarios where you want a clean URL for a particular resource, like an image or a specific page, without redirecting all traffic.

.htaccess Configuration:

This example rewrites a URL structure like /picture/some-text/51 directly to a PHP script that expects parameters.

RewriteEngine On
RewriteRule ^([^/]+)/([^/]+)/([\d]+)$ /picture.php?$1=$2&id=$3 [L]
  • ^([^/]+)/([^/]+)/([\d]+)$: This captures three parts:
    • ([^/]+): Captures the first segment (e.g., picture).
    • ([^/]+): Captures the second segment (e.g., some-text).
    • ([\d]+): Captures the third segment, ensuring it’s digits (e.g., 51).
  • /picture.php?$1=$2&id=$3: This rewrites the URL to picture.php, passing the captured segments as query parameters. $1 is the first capture group, $2 is the second, and $3 is the third.

This is a direct mapping, useful for specific, well-defined URL patterns.

Method 5: Simplified URL Parsing with explode

Another approach to parsing URLs within your index.php (when using a front controller) involves using PHP’s explode function to break down the REQUEST_URI into manageable parts.

PHP Snippet:

<?php
// Retrieve and clean the request URI
$uri_parts = array_values(array_filter(explode("/", $_SERVER["REQUEST_URI"])));

// Example processing:
if (empty($uri_parts)) {
    echo "Homepage content";
} elseif ($uri_parts[0] === 'about') {
    echo "About Us page";
} elseif ($uri_parts[0] === 'contact') {
    echo "Contact Page";
} else {
    echo "404 Not Found";
}
?>

This method relies on the .htaccess file to route all relevant requests to index.php, after which the PHP script dissects the URL.

FAQs on Solved How to Implement URL Rewriting with Htaccess and Php

Q: What is the primary benefit of URL rewriting

ANS: URL rewriting makes URLs more human-readable and SEO-friendly, improving user experience and search engine rankings by creating cleaner, descriptive addresses.

Q: Can .htaccess rewrite URLs without involving PHP

ANS: Yes, .htaccess can perform direct URL rewrites using RewriteRule for specific patterns without needing PHP. However, for dynamic routing, PHP is typically used in conjunction with .htaccess.

Q: What is a front controller pattern in web development

ANS: A front controller pattern uses a single script, usually index.php, as the entry point for all application requests. This script then handles request routing and processing, providing a centralized control point for the application.

Q: How does Apache's mod_rewrite work for URL rewriting

ANS: Apache’s mod_rewrite module uses rules defined in .htaccess or server configuration files to interpret incoming URLs and rewrite them internally to a different path or file. It employs regular expressions for pattern matching and replacement.

Q: What are named subpatterns in regular expressions used for routing

ANS: Named subpatterns, like (?'name'pattern), allow you to assign a name to a captured group in a regular expression. This makes your code more readable and simplifies accessing matched URL segments by name (e.g., $params[‘id’]) instead of numerical indices.
