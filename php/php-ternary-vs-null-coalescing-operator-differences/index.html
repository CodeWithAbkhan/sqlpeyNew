“PHP Ternary ?: vs Null Coalescing ?? Operator Key Differences”

When writing modern PHP code, developers frequently encounter situations where they need to assign a default value to a variable if the primary source is missing or null. Two syntactic shortcuts often come to mind: the shorthand ternary operator (?:), sometimes called the Elvis operator, and the more recent Null Coalescing operator (??). While they look similar, their underlying logic dictates distinct behaviors, particularly concerning variable existence and truthiness.

What are the precise mechanisms behind $var ?: $default versus $var ?? $default?

Core Operational Differences

The fundamental divergence lies in what each operator tests for:

Elvis Operator (?:) - Testing for Truthiness

The expression $var ?: $default is precisely equivalent to the standard ternary operation:

$result = $var ? $var : $default;

This means $var is returned only if it evaluates to a “truthy” value in a boolean context. Falsy values—which include false, null, 0, empty strings (""), and empty arrays ([])—will cause the second operand ($default) to be returned.

Null Coalescing Operator (??) - Testing for Existence and Null

Introduced in PHP 7.0, the expression $var ?? $default is syntactic sugar for:

$result = isset($var) ? $var : $default;

This operator specifically checks if $var is set (declared) AND not null. It bypasses this check for falsy values like 0 or "", returning the left operand if it meets the isset() criteria.

A significant advantage of ?? is that it does not emit an E_NOTICE if the variable on the left-hand side is undefined, unlike ?:.

Chaining Operators

Both operators support chaining, but they follow different association rules:

  • Null Coalescing (??) is right-associative: $a ?? $b ?? $c is evaluated as $a ?? ($b ?? $c). It searches for the first defined and non-null value from left to right.
  • Ternary (?:) is left-associative: (A ?: B) ?: C. This evaluates truthiness sequentially.

Chained Example:

If you need to pull a value from multiple sources, ?? provides a cleaner structure:

// Returns $_GET['name'] if set and not null, otherwise $_POST['name'] if set and not null, otherwise 'anonymous'.
$final_name = $_GET['name'] ?? $_POST['name'] ?? 'anonymous';

Alternative Scenarios and Solutions

When Truthiness is Required

If the intent is truly to check for any truthy value (e.g., you want 0 or "" to be replaced by the default), the ?: operator remains the correct tool.

Handling Empty Strings from Superglobals

If you are dealing with user input (like $_GET or $_POST) where an empty string ("") should be treated as “missing” (i.e., default to 'nobody'), the ?? operator falls short because "" is set and not null. In this specific case, a standard empty() check within a traditional ternary operator is required:

// If $_GET['user'] is "", this returns 'nobody'.
$username = !empty($_GET['user']) ? $_GET['user'] : 'nobody';

Mimicking ?: Behavior with ?? (Advanced)

If you desire the behavior of ?: (treating false/0/empty string as fallback) but wish to suppress the E_NOTICE that ?: throws on undefined variables, you must combine isset() with a logical OR (||) check:

// Alternative to $var ?: $default that avoids notices for undefined $var
$result = (isset($var) || !$var) ? $var : $default;

This complex ternary explicitly checks for existence (isset($var)) or if the value is falsy (!$var), ensuring no notice is raised if $var is absent.

Object Property Access

The ?? operator is invaluable for safely accessing nested or potentially non-existent object properties, preventing runtime errors that the standard ternary or direct access might cause:

class Configuration
{
    public $settings = ['timeout' => 30];
}

$config = new Configuration();
// Safely retrieves the value or returns a fallback without throwing errors for missing structure
$timeout = $config->settings['timeout'] ?? 60;
$log_level = $config->logging ?? 'WARN'; // If $config->logging is missing, it returns 'WARN' safely.

FAQs on PHP Ternary vs Null Coalescing Operator Differences

Q: What is the primary functional difference between ?? and ?:

ANS: The null coalescing operator (??) tests if the left operand is set and not null, equivalent to isset(). The shorthand ternary operator (?:) tests if the left operand evaluates to a truthy value, like a standard ternary operator.

Q: Does the ?: operator produce errors on undefined variables

ANS: Yes, the shorthand ternary operator (?:) will emit an E_NOTICE if the variable on the left-hand side is not defined or set. The null coalescing operator (??) does not produce this notice.

Q: Which operator should I use if I want 0 to return the default value

ANS: You should use the shorthand ternary operator (?:) because it evaluates 0 as falsy, causing the default value to be returned. The null coalescing operator (??) treats 0 as a valid, set value and will return 0.

Q: Can I use ?? to check for both null and undefined array indexes

ANS: Yes, the null coalescing operator (??) is functionally equivalent to checking isset($array['key']) and will safely return the default if the key does not exist or its value is explicitly null.

Q: Is ?? associative like the standard ternary operator

ANS: No, the null coalescing operator (??) is right-associative, meaning $a ?? $b ?? $c is grouped as $a ?? ($b ?? $c).
class a
{
    public $a = 'aaa';
}

$a = new a();

echo $a-&gt;a;  // Writes 'aaa'
echo $a-&gt;b;  // Notice: Undefined property: a::$b
