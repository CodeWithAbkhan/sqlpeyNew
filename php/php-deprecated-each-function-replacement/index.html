“PHP Deprecated each() Function Replacement Strategies for Modern Codebases”

The each() function in PHP is deprecated, meaning developers need robust strategies to migrate legacy code that relies on it. This discussion explores several accepted methodologies for iterating over arrays while correctly extracting both keys and values, adapting to different structural needs.

How to Substitute each() for Simple Key/Value Retrieval?

When you need the current key and value from an array immediately after assignment or initialization, utilizing built-in array pointer functions is efficient.

For array structures where you only require the first element’s key and value (like $ar = $o->me;), manual pointer manipulation offers a direct fix:

// Original concept: $typ, $val derived from $ar
$ar = $o->me;
// No need to call reset() if $ar was just created and the pointer is at the start
$current_key = key($ar);
$current_value = current($ar);

If an array $out is pre-defined and you need its initial key and value pair:

$out = ['me' => [], 'mytype' => 2, '_php_class' => null];
$expected_pair = [key($out), current($out)]; // [ 'me', [] ]
// Subsequent operations might require advancing the pointer: next($out);

Replacing each() in Loops (Iterating to the End)

The most common use case for each() involves iterating through an entire array until completion. The foreach construct is the preferred modern replacement.

Scenario 1: Retrieving Both Key and Value

When the deprecated loop structure was:

// Deprecated
while (list($key, $value) = each($array)) {
    // Process $key and $value
    next($array); // Often called inside or implied, but not needed with foreach
}

The direct replacement using foreach is cleaner and avoids manual pointer management:

reset($array); // Ensure pointer is at the start if needed, though foreach handles positioning.
foreach($array as $key => $value) {
    // Process $key and $value
}

This is also applicable when handling assignments like $kv = [$k, $v]; from a loop over $broken:

$broken_data = ['item1' => 100, 'item2' => 200];
$kv = [];
foreach ($broken_data as $k => $v) {
     $kv = [$k, $v]; // $kv will hold the last iterated pair
}

Scenario 2: Retrieving Only the Key

If only the key was needed, as suggested by while (list($key,) = each($array)):

reset($array);
foreach(array_keys($array) as $key) {
    // Use $key
}

Scenario 3: Retrieving Only the Value

If only the value was needed, as suggested by while (list(, $value) = each($array)):

foreach($array as $value) {
    // Use $value
}

Handling Specific Offsets or Fixed Iterations (e.g., 30 times)

For cases requiring a fixed iteration count while checking array bounds, a for loop combined with pointer functions can emulate the behavior, though this is less idiomatic than foreach for general array traversal:

// Emulating an iteration limit of 30 elements or until the array ends
reset($array);
for ($i = 0; $i < 30 && isset($array[$i]); $i++) {
    $id = key($array);
    $item = current($array);
    // Process $id and $item
    next($array); // Manually advance pointer
}

Automated Migration Using Rector

For large projects with hundreds of uses of each(), manual replacement is tedious. The Rector tool provides automated code refactoring for PHP upgrades.

To implement this automatically for cases targeting PHP 7.2 compatibility (which removed each()):

  1. Install Rector: 
    composer require rector/rector --dev
  2. Initialize Configuration: 
    vendor/bin/rector init
  3. Configure Sets: In rector.php, include the PHP_72 set to handle each() replacements: 
    use Rector\Core\Configuration\Option;
use Rector\Set\ValueObject\SetList;
use Symfony\Component\DependencyInjection\Loader\Configurator\ContainerConfigurator;

return static function (ContainerConfigurator $containerConfigurator): void {
    $parameters = $containerConfigurator->parameters();
    $parameters->set(Option::SETS, [
        SetList::PHP_72,
    ]);
};
  4. Run Rector on Source Code: 
    vendor/bin/rector process src --set php72

Rector handles common patterns, such as converting while (list($k, $v) = each($arr)) to foreach ($arr as $k => $v). See the official Rector documentation for advanced configurations.

Custom Emulation of each()

If preserving the exact return signature of each() is critical, a custom function can be written, though this is generally discouraged in favor of foreach.

A function mimicking the behavior, advancing the internal pointer afterward:

/**
 * Emulates the deprecated each() function behavior, advancing the internal array pointer.
 * @param array|object $arr The array (passed by reference implicitly via pointer functions)
 * @return array|false The [key, value] pair or false if array is exhausted.
 */
function custom_emulated_each(&$arr) {
    $key = key($arr);
    if ($key === null) {
        return false;
    }
    $value = current($arr);
    next($arr);
    
    // Return structure matching list() assignment expectations: [0 => key, 1 => value]
    return [$key, $value];
}

// Usage Example:
$data_source = ['A' => 10, 'B' => 20];
reset($data_source); // Start pointer at beginning
while ($pair = custom_emulated_each($data_source)) {
    list($typ, $val) = $pair;
    // echo "Key: $typ, Value: $val\n";
}

For PHP 8 compatibility hacks (though strongly advised against for active development), a function can be defined to return the associative array structure that the old list() assignment expected:

// PHP 8 Compatibility Fallback (Use with caution)
if (!function_exists('each')) {
    function each(&$arr) {
        $key = key($arr);
        if ($key === null) return false;
        $val = current($arr);
        next($arr);
        // Returns structure that supported list($key, $value) assignment previously
        return [1 => $val, 'value' => $val, 0 => $key, 'key' => $key];
    }
}

Functional Programming Approaches

For aggregation tasks, functional methods offer concise alternatives that naturally avoid the pointer management issues of each():

If calculating a sum based on array contents where the input is structured like [['id' => 1], ['id' => 2]]:

// Assuming $this->contents is an array of arrays where the desired ID is the first element in the inner array
// Example: $this->contents = [[101], [102]]
$total_items = array_reduce($this->contents, function($accumulator, $item) {
    // $item here is the inner array, e.g., [101]
    $products_id = $item[0]; 
    return $accumulator + $this->get_quantity($products_id);
}, 0); // Start accumulator at 0

Alternatively, using array_map and array_sum:

// Extracts the first element of each inner array (the ID) and then sums the results of get_quantity
$total_items = array_sum(array_map([$this, 'get_quantity'], array_column($this->contents, 0)));

For loops where you only need the key to access another array (like iterating keys from $this->contents):

// If you only need the key (which corresponds to the product ID index):
foreach(array_keys($this->contents) as $products_id) {
  $total_items += $this->get_quantity($products_id);
}

If you need to use list($products_id) structure inside a foreach (assuming inner elements are numeric arrays):

foreach($this->contents as list($products_id)) {
    $total_items += $this->get_quantity($products_id);
}

Dynamic Array Element Count Considerations

One point raised is that foreach might not work well with dynamically changing array counts during iteration. Generally, modifying an array while iterating over it with foreach can lead to unpredictable results or iteration skips. If the array structure must change based on operations within the loop, a custom function that strictly controls the pointer (key, current, next) might offer more control, as detailed in Solution 4 (custom myEach). However, for standard, static iteration, foreach is robust and correct.

If you are facing tricky dynamic array modifications, review how pointers are managed. For instance, see techniques for managing environment settings or complex data structures that might interact poorly with standard iteration in related topics like fixing external configuration issues .
