“PHP PDO LIKE Clause: Securely Implement Wildcard Searches”

When working with databases in PHP, particularly when filtering data based on partial string matches, the SQL LIKE clause is essential. However, integrating LIKE with PHP Data Objects (PDO) requires careful handling to prevent security vulnerabilities and ensure correct functionality. This post explores various methods for implementing LIKE searches with PDO, focusing on security and best practices.

The Challenge of Wildcards and Prepared Statements

The core of the challenge lies in how the LIKE operator uses wildcard characters (% for any sequence of zero or more characters, and _ for any single character). When these wildcards are directly embedded in user input, they can be exploited for SQL injection. Prepared statements are the standard defense, but applying wildcards correctly within them needs specific approaches.

Solutions for Implementing LIKE with PDO

Here are several effective ways to use the LIKE clause with PDO, along with explanations and code examples:

1. Using Positional Placeholders (?) with Wildcards in execute()

This is a common and straightforward method. You prepare the query with a positional placeholder and then provide the wildcard-enclosed search term directly within the execute() array.

<?php
// Assuming $database is a PDO connection object
$searchTerm = 'value'; // User input or variable

$query = $database->prepare('SELECT * FROM your_table WHERE your_column LIKE ?');
$query->execute([$searchTerm . '%']); // Appends % for "starts with"

while ($results = $query->fetch()) {
    echo htmlspecialchars($results['your_column']) . "<br />\n";
}
?>

2. Using Positional Placeholders (?) with bindValue()

bindValue() offers more explicit control over how parameters are bound. You can construct the wildcard string separately and then bind it as a string parameter.

<?php
// Assuming $database is a PDO connection object
$value = 'partial_string'; // User input or variable

$query = $database->prepare('SELECT * FROM your_table WHERE your_column LIKE ?');
$query->bindValue(1, "%{$value}%", PDO::PARAM_STR); // For "contains"
$query->execute();

if (!$query->rowCount() == 0) {
    while ($results = $query->fetch()) {
        echo htmlspecialchars($results['your_column']) . "<br />\n";
    }
} else {
    echo 'No matching records found.';
}
?>

3. Using Named Placeholders with Wildcards

Named placeholders (:parameter_name) enhance readability. You can construct the wildcard string before passing it to execute().

<?php
// Assuming $pdo_connection is a PDO connection object
$search_term = 'data'; // User input or variable

$query = $pdo_connection->prepare('SELECT * FROM your_table WHERE your_column LIKE :search');
$query->execute([':search' => "%{$search_term}%"]); // For "contains"

$results = $query->fetchAll(PDO::FETCH_ASSOC);
print_r($results);
?>

4. Database-Specific Concatenation with Named Parameters

For scenarios where you want the wildcards to be part of the SQL logic itself, you can use the database’s concatenation function.

  • MySQL:

    WHERE your_column LIKE CONCAT('%', :dangerousstring, '%')

  • Oracle:

    WHERE your_column LIKE '%' || :dangerousstring || '%'

    When using this approach, ensure the parameter passed to :dangerousstring is sanitized if it might contain literal wildcard characters that you don’t want interpreted as wildcards.

5. Preparing the Wildcard String Before Binding

This method involves creating the complete wildcard string, including the % characters, before passing it to the prepared statement.

<?php
// Assuming $pdo is a PDO connection object
$search = "%" . $search_term . "%"; // Construct the wildcard string first
$stmt = $pdo->prepare("SELECT * FROM your_table WHERE your_column LIKE ?");
$stmt->execute([$search]);
$data = $stmt->fetchAll();

// Process $data...
?>

6. Escaping Literal Wildcard Characters for Robust Searches

A critical consideration arises when your search term might legitimately contain % or _ characters that you want to match literally, not as wildcards. PDO itself doesn’t have a built-in function for this, but you can create a helper function.

Database systems like MySQL and PostgreSQL allow specifying an escape character. For example, in MySQL, you can use \ as the escape character by default, or specify it explicitly.

-- Example with default escape character '\'
SELECT * FROM your_table WHERE your_column LIKE 'some\_prefix\_%';

-- Example with custom escape character '|'
SELECT * FROM your_table WHERE your_column LIKE 'some|%_prefix|_%' ESCAPE '|';

To handle this within PDO, you can create a utility function:

<?php
use InvalidArgumentException; // Ensure this is imported if not in global scope

/**
 * Escapes characters for use in SQL LIKE clauses.
 *
 * @param string $text The text to escape.
 * @param string $escapeCharacter The character to use for escaping (defaults to '\').
 * @return string The escaped string.
 * @throws InvalidArgumentException If escape character is not a single character.
 */
function escapeLike(string $text, string $escapeCharacter = '\\'): string
{
    if (mb_strlen($escapeCharacter) !== 1) {
        throw new InvalidArgumentException('Escape character must be a single character.');
    }

    // Characters to escape: %, _, and the escape character itself
    return strtr($text, [
        '%' => $escapeCharacter . '%',
        '_' => $escapeCharacter . '_',
        $escapeCharacter => $escapeCharacter . $escapeCharacter,
    ]);
}

//

Usage Examples

$query = $database->prepare(‘SELECT * FROM table WHERE column LIKE ?’); $query->execute(array(‘value%’));

while ($results = $query->fetch()) { echo $results[‘column’]; }


// Assuming $database is a PDO connection object and $some_untrusted_input contains user data

// 1. Using the default escape character ('\')
$sanitized_input = escapeLike($some_untrusted_input);
$search_pattern = $sanitized_input . '%'; // Example: starts with sanitized input

$query = $database->prepare('SELECT * FROM your_table WHERE your_column LIKE ?');
$query->execute([$search_pattern]);

// 2. Specifying a custom escape character
const SQL_LIKE_ESCAPE_CHAR = '|';
$sanitized_input_custom = escapeLike($some_untrusted_input, SQL_LIKE_ESCAPE_CHAR);
$search_pattern_custom = $sanitized_input_custom . '%';

// Note: The ESCAPE clause needs to be part of the query if using a custom escape character
$query_custom = $database->prepare('SELECT * FROM your_table WHERE your_column LIKE ? ESCAPE ?');
$query_custom->execute([$search_pattern_custom, SQL_LIKE_ESCAPE_CHAR]);

?>

Important Considerations:

  • Database Compatibility: While % and _ are standard SQL wildcards, specific database systems might have variations or different escape mechanisms. Always consult your database’s documentation.
  • Character Encoding: Ensure your database connection and your PHP script use consistent character encoding (e.g., UTF-8) to avoid issues with multi-byte characters, especially when using functions like mb_strlen in the escapeLike function.
  • Security First: Always prioritize prepared statements to prevent SQL injection. Never directly embed user input into SQL queries.

FAQs on PHP PDO LIKE Clause

Q: How do I perform a 'starts with' search using PDO LIKE

ANS: Use the wildcard character % at the end of your search term when preparing the LIKE clause. For example: LIKE ? with execute(['your_prefix%']) or CONCAT(:prefix, '%') where :prefix is your value.

Q: What is the correct way to search for values containing literal percent signs

ANS: You need to escape the literal % character using the database’s specified escape mechanism, often a backslash \ or a custom character defined in the query using the ESCAPE keyword. Use a helper function like escapeLike to preprocess your search term.

Q: Can I use named parameters with PDO LIKE

ANS: Yes, named parameters are fully supported. You construct your LIKE pattern, potentially including wildcards, and bind it to a named placeholder like :search_term. Example: WHERE column LIKE :search_term and execute([':search_term' => '%' . $userInput . '%']).

Q: What are the security risks of using PDO LIKE with user input

ANS: The primary risk is SQL injection if user input containing wildcards or other SQL metacharacters is not properly handled. Using prepared statements with correctly escaped or bound parameters mitigates this risk by separating code from data.

Q: How does the ESCAPE clause work in SQL LIKE

ANS: The ESCAPE clause specifies a character that, when placed before a wildcard (%, _) or the escape character itself, causes it to be treated as a literal character rather than a wildcard. This is crucial when searching for values that might naturally contain these symbols.
