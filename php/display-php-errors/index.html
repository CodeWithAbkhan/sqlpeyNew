“How to Display PHP Errors: Essential Settings and Solutions”

Encountering errors in your PHP applications is a normal part of the development process. However, by default, many PHP installations are configured to suppress error messages to avoid exposing sensitive information on live production servers. This can make debugging challenging. This post explores various methods to enable and configure PHP error display, ensuring you can identify and resolve issues effectively.

When developing or troubleshooting, seeing specific error messages is crucial for pinpointing the root cause of problems. PHP provides directives within its configuration files (php.ini) and functions that can be called directly within your scripts to control error reporting behavior.

Core PHP Error Handling Directives

Two primary directives control how PHP handles and displays errors:

  • display_errors: When set to On or 1, PHP will output error messages directly to the browser. When set to Off or 0, errors are suppressed and typically logged to a file instead.
  • error_reporting: This directive determines the severity of errors that PHP will report. It accepts a bitwise OR of predefined constants (e.g., E_ALL, E_ERROR, E_WARNING).

Let’s examine different approaches to enable and configure these settings.

Solution 1: Script-Level Error Display Activation

You can override PHP’s default error display settings directly within your PHP script. This is particularly useful for development environments where immediate feedback is needed.

  • Activate all error reporting: This ensures you see every type of error, notice, and warning.

    <?php
// Report all PHP errors, warnings, and notices
error_reporting(E_ALL);

// Display all errors, warnings, and notices on the screen
ini_set('display_errors', '1');

// Your PHP code follows...
?>

    This snippet sets error_reporting to E_ALL, which includes all error levels, and display_errors to 1 to show them.

  • Alternative for comprehensive reporting: Another common way to capture a wide range of errors is by using -1, which is equivalent to E_ALL in many PHP versions.

    <?php
// Display all errors, including startup errors
ini_set('display_startup_errors', 1);
ini_set('display_errors', 1);

// Report all errors, warnings, and notices (equivalent to E_ALL)
error_reporting(-1);

// Your PHP code follows...
?>

    This approach ensures you capture errors that occur during PHP’s startup phase as well.

Solution 2: Configuring php.ini

For a more persistent change, you can modify the php.ini file. This file is the main configuration file for PHP. The exact location varies by operating system and installation method.

  • Development-Focused php.ini Settings:

    In a development environment, you’ll typically want to see all errors. The php.ini-development file, often provided with PHP installations, usually has error_reporting set to E_ALL.

    ; php.ini settings for development
error_reporting = E_ALL
display_errors = On
display_startup_errors = On
html_errors = On

  • Production-Focused php.ini Settings:

    On a production server, it’s generally recommended to log errors rather than display them directly to users. However, if you need to enable display errors for a short period for debugging, you might use:

    ; php.ini settings for production (with display_errors temporarily on for debugging)
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT
display_errors = Off
log_errors = On
error_log = /var/log/php/error.log ; Specify your log file path

    For specific debugging on production, you might temporarily set display_errors = On and then revert it.

  • Custom Error Reporting Levels:

    You can tailor the error reporting level using bitwise operators. For example, to report all errors except notices and warnings:

    ; Custom error reporting level
error_reporting = E_ALL ^ E_NOTICE ^ E_WARNING
display_errors = On

    After modifying php.ini, you must restart your web server (e.g., Apache or Nginx) for the changes to take effect. For Apache on Ubuntu:

    sudo /etc/init.d/apache2 restart

Solution 3: Controlling Specific Error Types

PHP allows you to filter specific error types. This can be helpful to focus on critical issues while ignoring less severe ones like notices.

  • Reporting Errors and Warnings Only:

    <?php
// Report only fatal running errors, warnings, and parse errors
error_reporting(E_ERROR | E_WARNING | E_PARSE);

// Display errors
ini_set('display_errors', 1);

// Your PHP code follows...
?>

  • Reporting All Errors Except Notices:

    <?php
// Report all errors except notices
error_reporting(E_ALL & ~E_NOTICE);

// Display errors
ini_set('display_errors', 1);

// Your PHP code follows...
?>

    This is a common setting for development as it helps catch potential issues without being overwhelmed by minor notices.

Solution 4: Understanding Error Reporting Constants

PHP provides a rich set of constants to define the types of errors to report. Using these allows for precise control.

  • Commonly Used Constants:

    • E_ERROR: Fatal run-time errors.
    • E_WARNING: Run-time warnings (non-fatal errors).
    • E_PARSE: Compile-time parse errors.
    • E_NOTICE: Run-time notices (e.g., using an uninitialized variable).
    • E_STRICT: Suggests changes for better interoperability and forward compatibility.
    • E_ALL: All errors and warnings (includes E_STRICT from PHP 5.4.0).

  • Example using E_ALL:

    <?php
// Set error reporting to E_ALL and display errors
ini_set('error_reporting', E_ALL);
ini_set('display_errors', 1);

// Your PHP code
?>

    This is equivalent to error_reporting(E_ALL);.

Solution 5: Configuring php.ini for Startup and HTML Errors

You can also control whether errors that occur during PHP’s startup phase are displayed and whether errors are formatted as HTML.

  • Enabling Startup Errors and HTML Formatting:

    In php.ini:

    display_startup_errors = On
display_errors = On
html_errors = On

    And in your script, you might set:

    <?php
// Set specific error reporting, e.g., E_ALL
error_reporting(E_ALL);

// Optionally, you can also define filters like E_ALL | E_STRICT
// error_reporting(E_ALL | E_STRICT);

// Your PHP code
?>

    html_errors = On formats error messages with HTML tags, making them more readable in a browser.

Best Practices for Error Display

  • Development: Always set display_errors to On and error_reporting to E_ALL during development to catch all issues.
  • Production: Set display_errors to Off. Enable log_errors to On and configure error_log to a secure file path. This prevents sensitive error details from being shown to users and ensures errors are recorded for later analysis.
  • Temporary Debugging on Production: If you absolutely need to see errors on a live server, temporarily enable display_errors, perform your debugging, and then immediately disable it.

By correctly configuring these settings, you can significantly improve your ability to diagnose and fix problems in your PHP applications, leading to more robust and stable code. For more details on PHP’s error handling, refer to the official PHP documentation on error reporting .

FAQs on Display PHP Errors

Q: How do I enable all PHP errors to be displayed?

ANS: You can enable all PHP errors by setting error_reporting(E_ALL); and ini_set('display_errors', '1'); within your PHP script. Alternatively, ensure error_reporting = E_ALL and display_errors = On are set in your php.ini file.

Q: What is the difference between display_errors and error_reporting in PHP?

ANS: display_errors controls whether error messages are shown on the screen (On) or suppressed (Off). error_reporting determines which types of errors PHP should actually report or log, using constants like E_ALL, E_WARNING, etc.

Q: Should I enable display_errors on a production server?

ANS: No, it is generally not recommended to have display_errors enabled on a production server as it can expose sensitive system information to users. Instead, configure log_errors to On to write errors to a log file.

Q: How can I see errors that happen during PHP script startup?

ANS: To see errors that occur during PHP’s startup phase, set ini_set('display_startup_errors', 1); in your script, along with ini_set('display_errors', 1); and error_reporting(-1);.

Q: What does error_reporting(-1) do in PHP?

ANS: error_reporting(-1) is a shorthand in PHP that sets the error_reporting directive to include all currently available error reporting constants, effectively reporting all errors and warnings.

Q: How do I fix 'display_errors' not working in PHP?

ANS: If display_errors isn’t working, ensure you are editing the correct php.ini file, restarting your web server after changes, and that no other configuration (like .htaccess files or server settings) is overriding your display_errors setting. Also, verify that the display_errors directive is not commented out.
