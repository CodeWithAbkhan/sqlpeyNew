“PHP Deprecated create_function Replacement Strategies”

The usage of create_function() in PHP is widely deprecated, posing significant challenges during upgrades, especially to PHP 8+. How can developers securely and efficiently substitute this construct with modern, safer alternatives like anonymous functions, arrow functions, or automated tooling?

Here are several proven methods to replace instances of create_function().

Solution 1: Utilizing Closures with Scope Binding

When working with callbacks that need access to variables from the surrounding scope, an Anonymous Function (Closure) paired with the use keyword offers a direct replacement. This is crucial for scenarios where a parent-scoped variable, like $delimiter, must be referenced inside the new function.

Consider the original context where $delimiter was needed:

// Replacing create_function structure
$callbacks[$delimiter] = function($matches) use ($delimiter) {
    return $delimiter . strtolower($matches[1]);
};

This closure explicitly imports $delimiter, ensuring the function operates correctly within its context.

Solution 2: Simple Callback Substitution in Filter Hooks

For straightforward filter or action hooks often seen in frameworks like WordPress, where create_function() returned the input variable unchanged, a basic anonymous function suffices.

A deprecated structure might look like this:

add_filter(
  'option_page_capability_' . ot_options_id(),
  create_function( '$caps', "return '$caps';" ),
  999
);

The replacement involves defining a simple anonymous function that accepts $caps and returns it immediately:

add_filter(
  'option_page_capability_' . ot_options_id(),
  function($caps) {return $caps;},
  999
);

This demonstrates replacing the old create_function syntax with the modern syntax, avoiding deprecated features entirely. For more on hooks, review documentation on WordPress Action and Filter Hooks .

Solution 3: Automated Refactoring with Rector

Manually replacing many instances of create_function() across a large codebase can be tedious and error-prone. The Rector tool automates this process by analyzing code statically and performing 1:1 replacements with appropriate anonymous functions.

Installation via Composer:

composer require rector/rector --dev

Configuration (rector.php): Configure Rector to target the necessary rule, specifically CreateFunctionToAnonymousFunctionRector.

<?php

use Rector\Core\Configuration\Option;
use Symfony\Component\DependencyInjection\Loader\Configurator\ContainerConfigurator;
use Rector\Php72\Rector\FuncCall\CreateFunctionToAnonymousFunctionRector;

return static function (ContainerConfigurator $containerConfigurator) {
    $parameters = $containerConfigurator->parameters();
    $parameters->set(Option::PATHS, [
        __DIR__ . '/src', // Specify directories containing legacy code
    ]);

    $services = $containerConfigurator->services();
    // Ensure the relevant rector rule is enabled
    $services->set(CreateFunctionToAnonymousFunctionRector::class);
};

Execution:

First, run a dry-run to see what changes will occur:

vendor/bin/rector process --config rector.php --dry-run

Then, apply the changes directly to the code:

vendor/bin/rector process --config rector.php

For standard execution without explicitly pointing to the config file:

vendor/bin/rector process

Solution 4: Leveraging PHP 7.4+ Arrow Functions

For concise operations where the function body consists of a single expression, Arrow Functions (introduced in PHP 7.4) provide the shortest syntax. Crucially, arrow functions automatically capture variables from the parent scope, meaning you do not need an explicit use clause for variables present in scope.

In the context of the first example:

// Arrow function replacement (PHP 7.4+)
$callbacks[$delimiter] = fn($matches) => $delimiter . strtolower($matches[1]);

This is cleaner than the standard anonymous function syntax when the logic is simple. Arrow functions are excellent for performance-sensitive mapping or filtering operations.

Solution 5: Creating Dynamic Anonymous Functions within Arrays

If the requirement is to dynamically populate an array with named or keyed functions that rely on outer variables, you can structure this using standard anonymous functions and the use keyword to inject necessary external data.

This example shows how to define two distinct functions dynamically within an array $dynamicAnonFunctions, using $outerVariable and $outerVariableTwo:

$dynamic_name = 'process_handler';
$outerVariable = 'Scope Data A';
$outerVariableTwo = 'Scope Data B';

$dynamicAnonFunctions = [];

// Function One Definition
$dynamicAnonFunctions[($dynamic_name . "_func_one")] = function () use ($outerVariable, $dynamic_name) { 
    echo "Running: function <b>" . $dynamic_name . "_func_one()</b><br><br>";
    echo $outerVariable;
    echo "<br><br>Success in func one!"; 
    echo "<br><br>";
};

// Function Two Definition
$dynamicAnonFunctions[($dynamic_name . "_func_two")] = function () use ($outerVariableTwo, $dynamic_name) { 
    echo '- - - - - - - - - - - - - - - - - - - <br><br>';
    echo "Running: function <b>" . $dynamic_name . "_func_two()</b><br><br>";
    echo $outerVariableTwo;
    echo "<br><br>Success in func two!"; 
    echo "<br><br>";
};

// Invoking the dynamic functions
$dynamicAnonFunctions[($dynamic_name . "_func_one")]();
$dynamicAnonFunctions[($dynamic_name . "_func_two")]();
// Execution halts for demonstration purposes
exit();

Solution 6: Providing a PHP 8+ Polyfill for create_function

If immediate, widespread refactoring is impossible (e.g., during a temporary maintenance window on PHP 8+), a temporary drop-in polyfill can restore functionality using eval. Note: Relying on eval introduces security considerations and should be removed promptly.

<?php
// Polyfill check for environments running PHP 8 or higher
if (!function_exists('create_function')) {
    function create_function($args, $code) {
        $args = trim($args);
        if ($args === '') {
            $args = '';
        }
        // Warning: Using eval is generally discouraged
        return eval('return function(' . $args . ') { ' . $code . ' };');
    }
}

This snippet verifies if the function exists and defines a custom implementation using eval to construct and return a closure based on the input arguments and code string.

Solution 7: Using eval for String-Based Return Expressions

If the logic being replaced relies on a dynamic string expression that must evaluate to a return value, using eval within an anonymous function declaration can maintain behavior, although this approach carries significant security risks (see Solution 6 warning).

// If the return value is constructed entirely as a string expression:
$callbacks[$delimiter] = eval('return function($matches){return '.$delimiter.' . strtolower($matches[1]);};');

This dynamically builds the function definition string before executing eval to return the resulting callable.

FAQs on PHP Deprecated createFunction Replacement Strategies

Q: What PHP versions mandate replacing create_function

ANS: create_function() was officially deprecated in PHP 7.2 and entirely removed in PHP 8.0, meaning PHP 8+ environments will fail if this function is called.

Q: Are arrow functions a complete replacement for closures

ANS: Arrow functions are suitable replacements for simple, single-expression closures. They automatically inherit the parent scope’s variables without needing the explicit use keyword, unlike traditional anonymous functions.

Q: Is using eval to create a function safe

ANS: No, using eval() to execute arbitrary code strings is inherently risky due to potential injection vulnerabilities. It should only be used as a temporary fallback if the input string content is absolutely trusted and verified.

Q: How does Rector simplify this migration

ANS: Rector uses static analysis to identify all uses of create_function() and automatically substitutes them with modern anonymous function syntax, validating scope handling where necessary, thus automating large codebase updates.
