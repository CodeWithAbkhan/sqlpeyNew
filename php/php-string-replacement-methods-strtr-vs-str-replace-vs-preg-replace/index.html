“PHP String Replacement Methods: strtr vs str_replace vs preg_replace”

When performing string manipulations in PHP, developers frequently encounter scenarios requiring the substitution of substrings. Several built-in functions offer distinct approaches to this task, each with specific behaviors regarding case sensitivity, array handling, and binary safety. How do we select the appropriate function for a given replacement requirement?

Evaluating Substitution Functions in PHP

Several powerful PHP functions facilitate text substitution. We will examine the primary candidates: strtr, str_replace, and preg_replace, alongside a fundamental loop-based approach.

The str_replace() Method: Binary Safe, Case-Sensitive Substitution

The str_replace() function performs a straightforward, binary-safe, case-sensitive replacement. Its signature involves up to four arguments:

mixed str_replace ( mixed $search , mixed $replace , mixed $subject [, int &$count ] )

This function is versatile as both $search and $replace can accept strings or arrays:

  • String Search, String Replace: A single occurrence is substituted. 
    echo str_replace("search", "REPLACED", "text search text");
// Output: text REPLACED text
  • Array Search, String Replace: Every element in the search array is replaced by the single replacement string. 
    echo str_replace(["t", "a"], "X", "text search text");
// Output: XexX seXrch XexX
  • String Search, Array Replace: This generates a “Notice: Array to string conversion” because a single search term cannot sensibly map to multiple replacements unless contextually managed (e.g., using preg_replace_callback).
  • Array Search, Array Replace: Replacements are matched positionally; array keys are disregarded. If the replace array is shorter than the search array, missing replacements default to an empty string.

A critical behavior, often termed a “Gotcha,” is that str_replace() processes replacements sequentially from left to right. This means a previously substituted value might be re-substituted in a later step.

For instance, comparing expected versus actual output:

echo str_replace(["a", "b"], ["b", "c"], "aabb");
// Actual output: cccc (because 'a' becomes 'b', then the new 'b' becomes 'c')

For case-insensitive needs, str_ireplace() provides an equivalent function. However, neither function natively handles replacements within multidimensional arrays; a recursive helper function like the provided str_ireplace_deep is necessary for deep array processing.

The strtr() Method: Character-by-Character or Paired Substitution

strtr() offers two primary modes based on the argument count:

  1. Two Arguments (string $str, array $replace_pairs): Performs literal, case-sensitive substring replacement based on key/value pairs in the array. It prioritizes the longest matching key first, offering binary safety in this mode. 
    echo strtr("text search text", ["search" => "REPLACEMENT_TEXT"]);
// Output: text REPLACEMENT_TEXT text
  2. Three Arguments (string $str, string $from, string $to): Substitutes characters byte-by-byte from $from to $to. This mode is not binary safe. If $from and $to strings are unequal in length, replacement halts at the shorter string’s end.

Example using the three-argument form:

echo strtr("text search text", "ax", "XY");
// Output: teYt seXrch teYt (a->X, x->Y)

Crucially, unlike str_replace(), strtr() does not re-process substituted strings in the two-argument array mode.

echo strtr("aabb", ["a" => "b", "b" => "c"]);
// Actual output: bbcc (The first 'a' becomes 'b', the second 'a' becomes 'b'. The original 'b's become 'c's. No cascading replacements occur.)

strtr() lacks a built-in case-insensitive variant, though custom implementations like stritr exist to extend its functionality for case-insensitive or deep array operations.

The preg_replace() Method: Regular Expression Power

When substitution logic requires pattern matching, preg_replace() becomes the tool of choice. It utilizes Perl Compatible Regular Expressions (PCRE).

mixed preg_replace ( mixed $pattern , mixed $replacement , mixed $subject [, int $limit = -1 [, int &$count ]] )

Similar to str_replace(), $pattern and $replacement can be arrays for bulk operations. Remember that $pattern must use delimiters (e.g., /pattern/i) and special regex characters require escaping.

A common pattern replacement example:

echo preg_replace("/search/", "REPLACED", "text search text");
// Output: text REPLACED text

The left-to-right processing issue observed in str_replace() also applies here when using array patterns.

To achieve case-insensitivity, append the i modifier to the regex pattern: /pattern/i.

For dynamic replacements based on matched content, use preg_replace_callback(), as the /e modifier is deprecated due to security concerns. preg_replace() also fails to process multidimensional arrays directly, necessitating a recursive wrapper similar to preg_replace_deep.

Alternative: Manual Iteration with Loops

For ultimate control, or when performance profiling suggests function call overhead is a bottleneck (though rare), direct iteration is possible, although it usually sacrifices binary safety and complexity management.

Replacing ‘a’ with ‘&’ using a for loop:

$str = "a string containing many 'a's";
for ($i = 0; $i < strlen($str); $i++) {
    if ($str[$i] == 'a') {
        $str[$i] = '&';
    }
}
echo $str;
// Output: & string cont&ining m&ny '&'s

This approach is tedious for complex, multi-term substitutions and requires careful handling of character encoding if not dealing purely with ASCII.

Targeted Substitution: Limiting Replacement Scope

All functions discussed typically operate on the entire string subject. If only a segment needs alteration, functions like substr_replace() are useful, or one might tailor the regular expression pattern in preg_replace() to match only the desired bounds.
