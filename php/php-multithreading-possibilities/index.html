“PHP Multithreading: Is it Possible and How?”

PHP, by its nature as a web scripting language, isn’t inherently designed for true multithreading in the same way compiled languages are. However, achieving parallel execution and simulating multi-threaded behavior is possible through various methods. This exploration delves into these techniques, from dedicated extensions to process management.

The primary challenge with PHP threading stems from its typical execution environment within a web server (like Apache or Nginx). These environments often run PHP as a single-process, multi-threaded server (like Apache’s prefork or worker MPMs) or as a FastCGI process manager, where each worker process handles requests independently. Introducing true threads within a single PHP process can lead to complexities and potential instability in these architectures.

Warning about pthreads

It’s crucial to note that the pthreads extension, historically a significant player in PHP threading, is now considered unmaintained and dead. Furthermore, pthreads (v3) is restricted to PHP 7.2+ and cannot be used in a web server environment, limiting its applicability to CLI-based applications. The PHP manual itself states: “The pthreads extension cannot be used in a web server environment. Threading in PHP is therefore restricted to CLI-based applications only.”

Methods for Achieving Parallel Execution in PHP

While true native threads within a web server context are problematic, several approaches allow for concurrent task execution:

1. The pthreads PECL Extension (CLI Only)

For Command Line Interface (CLI) applications, the pthreads extension provides an object-oriented API for multi-threading. It allows PHP applications to create, manage, and synchronize threads, workers, and Threaded objects.

Key Features:

  • Object-oriented threading API.
  • Supports creation, reading, writing, execution, and synchronization of threads.

Example (CLI Usage):

<?php
class AsyncOperation extends Thread {
    public function __construct($arg) {
        $this->arg = $arg;
    }

    public function run() {
        if ($this->arg) {
            $sleep = mt_rand(1, 10);
            printf('%s: %s -start -sleeps %d' . "\n", date("g:i:sa"), $this->arg, $sleep);
            sleep($sleep);
            printf('%s: %s -finish' . "\n", date("g:i:sa"), $this->arg);
        }
    }
}

// Create an array of threads
$stack = [];

// Initiate Multiple Threads
foreach (range("A", "D") as $i) {
    $stack[] = new AsyncOperation($i);
}

// Start The Threads
foreach ($stack as $t) {
    $t->start();
}

// Wait for threads to complete (optional, but good practice)
foreach ($stack as $t) {
    $t->join();
}
?>

Expected Output (will vary due to random sleeps):

12:00:06pm: A -start -sleeps 5
12:00:06pm: B -start -sleeps 3
12:00:06pm: C -start -sleeps 10
12:00:06pm: D -start -sleeps 2
12:00:08pm: D -finish
12:00:09pm: B -finish
12:00:11pm: A -finish
12:00:16pm: C -finish

Real-World Example (Web Request):

<?php
error_reporting(E_ALL);

class AsyncWebRequest extends Thread {
    public $url;
    public $data;

    public function __construct($url) {
        $this->url = $url;
    }

    public function run() {
        if ($url = $this->url) {
            /*
             * If a large amount of data is being requested, you might want to
             * fsockopen and read using usleep in between reads
             */
            $this->data = file_get_contents($url);
        } else {
            printf("Thread #%lu was not provided a URL\n", $this->getThreadId());
        }
    }
}

$t = microtime(true);
$g = new AsyncWebRequest(sprintf("http://www.google.com/?q=%s", rand() * 10));

/* starting synchronization */
if ($g->start()) {
    printf("Request took %f seconds to start ", microtime(true) - $t);
    while ($g->isRunning()) {
        echo ".";
        usleep(100);
    }
    if ($g->join()) {
        printf(" and %f seconds to finish receiving %d bytes\n", microtime(true) - $t, strlen($g->data));
    } else {
        printf(" and %f seconds to finish, request failed\n", microtime(true) - $t);
    }
}
?>

2. Using popen() for Process Creation

The popen() function allows you to open a process file pointer, enabling communication with external scripts. This can be used to run other PHP scripts in parallel without blocking the main script’s execution.

Example:

<?php
for ($i = 0; $i < 10; $i++) {
    // Open ten processes
    for ($j = 0; $j < 10; $j++) {
        // 'script2.php' is the script to be executed in parallel
        $pipe[$j] = popen('php script2.php', 'w');
    }

    // Wait for them to finish
    for ($j = 0; $j < 10; ++$j) {
        pclose($pipe[$j]);
    }
}
?>

3. Simulating Concurrency with HTTP Requests and Sessions

This method uses HTTP requests (often with curl) to trigger external PHP scripts, allowing them to run asynchronously. Session management can be used to maintain state and communicate between these concurrent processes.

startprocess.php:

<?php
$request = "http://localhost/test/process1.php?sessionid=" . $_REQUEST["PHPSESSID"];
$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, $request);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_TIMEOUT, 1); // Set a short timeout
curl_exec($ch);
curl_close($ch);
echo $_REQUEST["PHPSESSID"];
?>

process1.php:

<?php
set_time_limit(0); // Allow the script to run indefinitely

if ($_REQUEST["sessionid"]) {
   session_id($_REQUEST["sessionid"]);
}

function checkclose() {
   global $_SESSION;
   if ($_SESSION["closesession"]) {
       unset($_SESSION["closesession"]);
       die(); // Terminate the process
   }
}

while (true) { // Loop indefinitely until closed
   session_start();
   $_SESSION["test"] = rand(); // Example: perform some work
   checkclose();
   session_write_close(); // Release session lock
   sleep(5); // Wait for 5 seconds
}
?>

verifysession.php:

<?php
if ($_REQUEST["sessionid"]) {
    session_id($_REQUEST["sessionid"]);
}
session_start();
var_dump($_SESSION);
?>

closeprocess.php:

<?php
if ($_REQUEST["sessionid"]) {
    session_id($_REQUEST["sessionid"]);
}
session_start();
$_SESSION["closesession"] = true; // Signal the process to close
var_dump($_SESSION);
?>

4. Process Control Functions (pcntl and posix)

PHP provides process control functions through the pcntl and posix extensions. These allow for process forking, signal handling, and inter-process communication, offering a more robust way to manage child processes.

Key Functions:

  • pcntl_fork(): Creates a child process.
  • pcntl_wait(): Waits for a child process to change state.
  • posix_kill(): Sends a signal to a process.
  • pcntl_signal(): Sets up a signal handler.

Example using pcntl_fork():

<?php
$pid = pcntl_fork();

if ($pid == -1) {
    die('Could not fork process');
} else if ($pid) {
    // Parent process
    pcntl_wait($status); // Wait for the child process to complete
} else {
    // Child process
    // Code to be executed by the child process
    echo "This is the child process.\n";
}
?>

Note: pcntl_fork() is typically only available and functional in the CLI version of PHP and may not work if safe_mode is enabled on the server.

5. The Parallel Extension (PHP 7.2+ ZTS)

The Parallel extension is a modern successor to pthreads, offering a more stable and actively developed solution for concurrency in PHP. It requires PHP to be compiled with ZTS (Zend Thread Safety).

Example:

<?php
// Run two simple tasks in parallel
\parallel\run(
    function() {
        sleep(5);
        echo " la mouche\n"; // The fly
    }
);

\parallel\run(
    function() {
        sleep(2);
        echo "Zobi\n"; // A name
    }
);

echo "Bzz ! "; // Buzz!

// Expected Output: "Bzz ! Zobi la mouche" (order of echo might vary slightly)
?>

Docker Setup for Parallel Extension:

To use the Parallel extension, you might need a ZTS-enabled PHP environment, which can be easily set up with Docker:

FROM php:8.3-zts-alpine

RUN apk update

# Install necessary packages for PECL extensions
RUN apk add --no-cache --virtual .phpize-deps-configure $PHPIZE_DEPS

# Install PHP/parallel extension
RUN pecl install parallel-1.2.3 \
  && docker-php-ext-enable parallel

# You can then build and run your container
# docker build --tag php:concurrency .
# docker run --rm -v ${pwd}:/app/ php:concurrency php /app/your-script.php

6. Using exec() and Background Processes

The exec() function can be used to execute external commands, including running other PHP scripts in the background. By redirecting output and using the ampersand (&), you can prevent the main script from waiting for the background process to complete.

Example:

<?php
$phpPath = '/usr/bin/php'; // Adjust path to your PHP executable
$scriptPath = 'path/to/your/script.php';

// Execute script in the background without output
exec("$phpPath $scriptPath > /dev/null 2>&1 &");

// Execute script with arguments in the background
$args = 'argument1';
exec("$phpPath $scriptPath $args > /dev/null 2>&1 &");
?>

Note: exec() may be disabled on some shared hosting environments for security reasons.

7. proc_open() for Enhanced Process Control

Similar to popen(), proc_open() offers more granular control over external processes, including managing stdin, stdout, and stderr streams. This is particularly useful for inter-process communication and handling asynchronous output.

Example:

<?php
// sleep.php
// This script simply sleeps for a given duration and echoes the duration.
set_error_handler(function ($severity, $error, $file, $line) {
    throw new ErrorException($error, -1, $severity, $file, $line);
});
$sleep = $argv[1];
sleep($sleep);
echo $sleep . PHP_EOL;
exit(0);

// run.php
$procs = [];
$pipes = [];
$cmd = 'php %cd%/sleep.php';

$desc = [
    0 => ['pipe', 'r'], // stdin
    1 => ['pipe', 'w'], // stdout
    2 => ['pipe', 'a'], // stderr
];

for ($i = 0; $i < 10; $i++) {
    $iCmd = $cmd . ' ' . (10 - $i); // Arguments: 10, 9, ...
    $procs[$i] = proc_open($iCmd, $desc, $pipes[$i], __DIR__);
}

$stdins = array_column($pipes, 0);
$stdouts = array_column($pipes, 1);
$stderrs = array_column($pipes, 2);

while ($procs) {
    foreach ($procs as $i => $proc) {
        $read = [$stdins[$i]];
        $write = [$stdouts[$i], $stderrs[$i]];
        $except = [];

        // Use stream_select for non-blocking reads
        if (stream_select($read, $write, $except, 0, 1000)) {
            foreach ($write as $stream) {
                echo stream_get_contents($stream);
            }
        }

        $status = proc_get_status($proc);
        if (false === $status['running']) {
            proc_close($proc);
            unset($procs[$i]);
        }
    }
    usleep(1); // Prevent busy-waiting
}
?>

8. Leveraging External Tools or Services

For more complex scenarios or when PHP’s capabilities are insufficient, consider delegating heavy lifting to external tools or services that have robust multi-threading support (e.g., Python scripts, compiled C++ applications). Your PHP application can then orchestrate these external processes.

9. curl_multi for Parallel HTTP Requests

If your concurrency needs involve making multiple HTTP requests, curl_multi is an efficient way to perform these requests in parallel, significantly speeding up I/O-bound operations.

10. Symfony Process Component

The Symfony Process component offers a high-level abstraction for running external commands, including features like timeouts, disabling output, and starting processes asynchronously.

Example:

<?php
use Symfony\Component\Process\Process;
use Symfony\Component\Process\Exception\ProcessFailedException;

$process = Process::fromShellCommandline("php " . __DIR__ . "/script.php");
$process->setTimeout(0);     // No timeout
$process->disableOutput();     // Don't capture output
$process->start();            // Start the process asynchronously
?>

Considerations for PHP Concurrency

  • Web Server Environment: True threading is generally discouraged or impossible within standard web server configurations. Focus on CLI or asynchronous request handling.
  • Resource Management: Be mindful of server resources (CPU, memory) when launching multiple processes or threads, as they can consume significant resources.
  • Error Handling: Implement robust error handling for both your PHP scripts and any external processes you manage.
  • Inter-Process Communication (IPC): If your concurrent tasks need to share data, explore IPC mechanisms like shared memory, message queues, or databases.
  • Zend Thread Safety (ZTS): For extensions like Parallel that rely on threading, ensure your PHP installation is compiled with ZTS enabled.

FAQs on PHP Multithreading

Q: Is PHP truly multithreaded?

ANS: PHP is not inherently multithreaded in the same way as compiled languages. While extensions like pthreads and Parallel allow for threading in CLI contexts, web server environments typically use process-based concurrency or asynchronous execution rather than true threads within a single PHP process.

Q: What are the limitations of PHP threading?

ANS: The primary limitation is that extensions like pthreads are generally not suitable for web server environments due to potential instability and the way web servers manage PHP processes. Threading in PHP is best suited for CLI applications.

Q: Which PHP extensions support threading?

ANS: The pthreads extension (now unmaintained) and the Parallel extension are the primary PECL extensions that provide threading capabilities in PHP, primarily for CLI.

Q: How can I achieve concurrency without extensions?

ANS: You can achieve concurrency using mechanisms like popen(), exec() to run background processes, proc_open(), curl_multi for parallel network requests, or by simulating asynchronous behavior with HTTP requests and session management.

Q: When should I use process forking in PHP?

ANS: Process forking using pcntl_fork() is useful for CLI applications where you need to spawn child processes to handle tasks independently. It’s a more stable approach than trying to force threading into a web server context.

Q: What is the difference between threading and multiprocessing in PHP?

ANS: Threading involves multiple execution paths within a single process, sharing the same memory space. Multiprocessing involves creating separate processes, each with its own memory space. PHP’s concurrency methods often lean towards multiprocessing (using popen, exec, pcntl_fork) due to the limitations of true threading in web environments.
