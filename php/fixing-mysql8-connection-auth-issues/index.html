“Fixing MySQL 8 Connection Issues: Downgrading Authentication to mysql_native_password”

How do various environments allow us to revert the MySQL authentication method to mysql_native_password to ensure compatibility with legacy clients?

Altering User Authentication via SQL Command

A direct method involves modifying the specific user account causing the issue to utilize the older authentication protocol via an ALTER USER SQL statement. This approach bypasses server-wide configuration changes if only certain users need compatibility.

For an existing user:

ALTER USER 'existingUser'@'connectionHost' IDENTIFIED WITH mysql_native_password BY 'securePasswordHere';

If you are provisioning a new user that requires legacy support:

CREATE USER 'newUser'@'localhost' IDENTIFIED WITH mysql_native_password BY 'initialPassword';

Note: Some reports suggest syntax sensitivity, where removing surrounding quotes from the username/hostname parts, but keeping them around the password clause, might be necessary depending on the client environment, though standard SQL syntax usually prevails.

Server Configuration Adjustments

For a system-wide fallback to the legacy method, modifying the MySQL configuration file is often required. The location and exact directive vary by operating system and installation method (e.g., standard package, Homebrew, WAMP/MAMP).

General Configuration File Edits

You can set the global default plugin in the configuration file (e.g., my.cnf or my.ini):

[mysqld]
default-authentication-plugin=mysql_native_password

After applying this change, a service restart is mandatory: service mysql restart or equivalent.

Platform-Specific Configuration Locations & Steps:

  1. Ubuntu/Linux (General): Locate the relevant configuration file, sometimes /etc/mysql/conf.d/mysql.cnf or within /etc/mysql/mysql.conf.d/mysqld.cnf. Insert the directive above under the [mysqld] section. Then restart the service.
  2. Mac (Homebrew): Determine the location using $mysql --verbose --help | grep my.cnf. Then edit the file (e.g., /usr/local/etc/my.cnf): 
    [mysqld]
# Only allow connections from localhost
bind-address = 127.0.0.1
default-authentication-plugin=mysql_native_password
    Restart via Homebrew services: $brew services restart mysql.
  3. Windows (MySQL Installer Reconfigure): If you used the official installer, re-running the installer and selecting the “Reconfigure” option for the MySQL Server component allows switching the “Authentication Method” to “Use Legacy Authentication Method (Retain MySQL 5.X Compatibility).”

MySQL 8.4 Specific Configuration Note

For very recent versions (like MySQL 8.4), some users report that the default-authentication-plugin directive is deprecated or superseded. An alternative directive might be required in the [mysqld] section:

[mysqld]
mysql_native_password=ON

This must be paired with the user alteration command mentioned previously.

Client-Side Considerations (PHP/Frameworks)

While server-side changes are common, the client’s capability matters:

  • PHP Version: PHP 7.4+ generally includes support for caching_sha2_password via mysqlnd. If you are stuck on PHP 7.3 or earlier, server modification is necessary.
  • PDO vs. mysqli: If using mysqli, check for updates. In some cases, trying the connection via PHP’s PDO extension might yield different results, as support parity differs between extensions.
  • Framework Configuration (.env): Frameworks like Laravel sometimes abstract connection details. Ensure your .env file specifies the correct connection parameters, including socket paths if needed, particularly in MAMP/WAMP setups where the socket location may differ from the default expectation. If using MAMP, explicitly setting DB_SOCKET to /Applications/MAMP/tmp/mysql/mysql.sock has resolved issues for some users.
  • Port Conflicts: In rare scenarios involving switching between MariaDB and MySQL versions on the same machine, ensure the port number in your connection object creation is correct (e.g., mysqli_connect(host, user, pass, db, 3308) if 3308 is being used).

Achieving Compatibility Without Changing Server Defaults

One approach seeks to establish a standard user connection without altering the global server security settings. This involves creating a user configured specifically for older authentication:

// Example for PHP using mysqli, assuming server is using caching_sha2_password by default
$server_name = "localhost";
$mysql_username = "secure_user"; // A user created specifically for this
$mysql_password = "aStandardPassword"; // A password that works with the default server setting if possible, or one that you explicitly set to mysql_native_password via SQL on that user.

$conn = mysqli_connect($server_name, $mysql_username, $mysql_password, $db_name);
// ... check connection ...

While this confirms functionality, it is acknowledged that relying on mysql_native_password reduces security compared to SHA-256 hashing.

After implementing any server configuration changes (like adding directives to .cnf or .ini), always restart the MySQL service for the new default authentication plugin to take effect. Subsequently, ensure the targeted user account’s authentication method aligns with the server’s requirement (either by setting it explicitly via ALTER USER or relying on the new server default).

FAQs on Fixing MySQL 8 Connection Auth Issues

Q: What is the primary reason MySQL 8 fails to connect with older PHP applications

ANS: MySQL 8 defaults to the more secure caching_sha2_password plugin, which older PHP extensions (pre-7.4) often lack native support for.

Q: Should I always revert to mysql_native_password

ANS: Reverting to mysql_native_password is a workaround for legacy clients. The best long-term solution is to upgrade the client application (e.g., PHP version) to support caching_sha2_password.

Q: How do I check my current MySQL configuration file location on Mac

ANS: Run the command $mysql --verbose --help | grep my.cnf in your terminal to locate the active configuration file path used by the installed client.

Q: Does using phpMyAdmin help change the authentication plugin

ANS: Yes, you can often use the phpMyAdmin User Accounts tab to manually change an individual user’s ‘Authentication plugin’ from ‘Caching sha2 authentication’ to ‘Native MySQL authentication’ and save the changes.

Q: After editing my ini file what service must be restarted

ANS: You must restart the MySQL server service for the changes in the configuration file (like my.ini or my.cnf) to become effective.
