“Configuring Apache to Process .html Files as PHP via .htaccess”

How does one instruct the Apache web server, typically via the .htaccess file located at the website’s root (like public_html or htdocs), to process files with .html or .htm extensions using the PHP interpreter instead of serving them as static HTML? This often requires setting the correct MIME type or handler configuration, which varies significantly depending on the server setup (e.g., shared hosting like GoDaddy, dedicated Ubuntu installs, or Plesk environments).

Core Directives for MIME Type Association

The most direct approach involves using the AddType directive in .htaccess to associate file extensions with a specific content handler.

Solution 1: Standard AddType Directives

For standard Apache configurations, associating .html and .htm with the standard PHP type often suffices:

# Standard PHP handler mapping
AddType application/x-httpd-php .html .htm

Some environments might require specifying a versioned handler, such as php5:

# Alternative versioned handler mapping
AddType application/x-httpd-php5 .html .htm

If PHP is running under CGI, the AddHandler directive might be necessary instead:

# Handler for PHP running as CGI
AddHandler application/x-httpd-php .html .htm

Solution 8: A Common Working Configuration

Many users find this specific combination effective for general use:

AddType application/x-httpd-php5 .html .htm

Utilizing Handlers for Specific Environments

Different hosting providers or specific PHP modes (like FPM or CGI) demand distinct handler declarations.

Solution 6: GoDaddy Specific Handler

For some older or specific GoDaddy setups, this handler configuration provided a resolution:

AddHandler x-httpd-php5-cgi .html

Solution 7: Alternative GoDaddy Handler

If the issue persists on GoDaddy, switching to the LiteSpeed PHP handler might be the required fix:

AddHandler application/x-httpd-lsphp .html

Solution 9: Handling PHP-FPM on Plesk

Environments using PHP as an FPM application often require more involved configuration, potentially involving both FPM pool settings and an Apache handler rule:

  1. Plesk Panel Configuration (PHP Settings): Adjust security.limit_extensions to include .html and .inc. 
    [php-fpm-pool-settings]
security.limit_extensions = .php .phar .html .inc
  2. .htaccess Configuration: Set a handler that proxies requests to the FPM socket: 
    <Files ~ .(?i:inc|html|htm)$>
SetHandler proxy:unix:///var/www/vhosts/system/EXAMPLE.com/php-fpm.sock|fcgi://127.0.0.1:9000
</Files>

Dynamic Handler Detection

If the correct handler name is unknown, a dynamic method can be employed:

Solution 3: Discovering the Correct Handler

  1. Create a test PHP file (e.g., check_handler.php) with the content: 
    <?php echo $_SERVER['REDIRECT_HANDLER']; ?>
  2. Access this file via the browser to retrieve the specific output string (e.g., application/x-httpd-php70).
  3. Use this output in your .htaccess: 
    AddType [[THE OUTPUT FROM ABOVE FILE]] .html .htm
    Example based on discovery: AddType application/x-httpd-php70 .html .htm

If this results in a blank page or an “Undefined index” notice, reverting to a common fallback is advised: AddHandler application/x-httpd-php .html.

Using mod_rewrite for Forced Parsing

Instead of setting MIME types, mod_rewrite can intercept requests for .html files and force them to be processed by the PHP engine, often using the Handler (H) or Type (T) flag.

Solution 4: Rewrite Rule Flags

The Handler flag forces the content type processing:

RewriteEngine on
# Force .html and .htm to be processed by handler 'application/x-httpd-php5'
RewriteRule \.(html|htm)$ - [H=application/x-httpd-php5]

The Type flag sets the MIME type dynamically:

RewriteEngine on
# Set the MIME type to PHP handler
RewriteRule \.(html|htm)$ - [T=application/x-httpd-php5]

# Including other extensions like .txt or .foo
RewriteRule \.(html|htm|txt|foo)$ - [T=application/x-httpd-php5]

Note: On some systems, php5 must be replaced with php.

Solution 18: Simple Rewriting to .php

A declarative rewrite can transparently map .html requests to a .php execution flow:

RewriteEngine on
# Rewrites request for 'file.html' to execute 'file.php' internally
RewriteRule ^(.+)\.html$ $1.php [L]

Server-Level Configuration and Overrides

In non-shared hosting scenarios (like a local Ubuntu setup), direct Apache configuration file edits might be needed, in addition to ensuring .htaccess overrides are permitted.

Solution 5: Enabling Overrides and Restarting Services

  1. Enable AllowOverride All: In the virtual host or directory configuration file (e.g., /etc/apache2/sites-available/000-default.conf), ensure the site directory allows overrides:

    <Directory "/var/www/html">
    AllowOverride All
</Directory>

  2. Enable Rewrite Module: Activate the necessary Apache module:

    sudo a2enmod rewrite

  3. Restart Apache: Apply changes by restarting the service:

    sudo service apache2 restart

Solutions 15 & 17: Addressing File Permissions and Root Configuration

Sometimes the failure stems from Apache not being permitted to read the .htaccess file or the directory configurations being too restrictive.

  • Permissions Check (Solution 15): Ensure the Apache user (e.g., www-data) owns the .htaccess file:

    chown www-data:www-data .htaccess

  • Configuration Modification (Solution 17): Modify /etc/apache2/apache2.conf to set AllowOverride All for the main document root directory (/var/www/):

    <Directory /var/www/>
    Options Indexes FollowSymLinks
    AllowOverride All  # Changed from None
    Require all granted
</Directory>
sudo systemctl restart apache2

Specific Hosting/OS Variants

Solution 14: Dreamhost Configuration

Dreamhost users often require specific FastCGI or CGI wrappers based on their PHP version:

  • PHP 7.2 (FastCGI): 
    AddHandler fcgid-script .html
FcgidWrapper "/dh/cgi-system/php72.cgi" .html
  • PHP 5 (CGI): 
    AddHandler php5-cgi .html

Solution 13: Including Non-Web File Types

On a Raspberry Pi setup editing the PHP configuration file (/etc/apache2/mods-enabled/php7.1.conf), one user successfully added .html and other static types to be parsed by PHP:

AddType application/x-httpd-php .html .htm .png .jpg .gif

FAQs on Configuring Apache HTML as PHP

Q: What is the primary role of AddType in .htaccess for this purpose

ANS: The AddType directive explicitly tells the Apache server that files ending with the specified extensions should be treated as the given MIME type, which, in this case, forces the PHP handler to process the file content.

Q: Why would using RewriteRule be preferable over AddType

ANS: RewriteRule offers greater flexibility, allowing complex conditional logic or mapping one extension to another internal execution path (like mapping .html requests to a .php script execution transparently), whereas AddType is a direct MIME association.

Q: What causes the error 'Notice Undefined index REDIRECT_HANDLER' when debugging handlers

ANS: This notice typically appears when the server environment or configuration does not populate the REDIRECT_HANDLER server variable, often indicating that the mechanism designed to pass handler information failed or was not invoked correctly.

Q: If my .htaccess changes don't work what is the first thing to check

ANS: Verify that the AllowOverride directive is set to All or FileInfo for the relevant directory in your main Apache configuration files, as this governs whether .htaccess directives are honored.
