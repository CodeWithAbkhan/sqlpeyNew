PHP preg_replace /e Modifier Deprecation: Modern Alternatives and Safest Practices

PHP Regular Expressions
8 min read · Jul 22, 2025

Table of Contents

    • Leveraging preg_replace_callback
    • Gotchas and Considerations
    • Shim for Temporary Compatibility (preg_replace_eval)
    • Code Generation for Migration Assistance

The preg_replace function in PHP, when combined with the /e modifier, offered a powerful way to dynamically modify matched strings using arbitrary PHP code. However, this feature has been deprecated due to security concerns associated with its eval()-like behavior. This poses a challenge for developers migrating older code or encountering existing implementations that rely on this functionality. How can we safely and effectively replace the preg_replace /e modifier with modern, secure practices?

The core issue with the /e modifier is its inherent security risk. By allowing the replacement string to be interpreted as executable PHP code, it opens the door to various vulnerabilities if not handled with extreme care, especially with user-supplied input. The recommended and secure alternative is preg_replace_callback.

Leveraging preg_replace_callback

preg_replace_callback provides a structured and secure approach. Instead of evaluating a string, it passes the matched substrings as an array to a specified callback function. This function then returns the desired replacement.

Original Approach (using /e - Deprecated):

Consider a scenario where you want to convert the first letter of words following a pattern to uppercase.

// Original, deprecated code
$string = 'this is a test string';
$pattern = '/(^|_)([a-z])/';
$replacement = 'strtoupper("\\2")'; // Using \2 for the captured lowercase letter
$result = preg_replace($pattern . 'e', $replacement, $string);
echo $result; // Output: This Is A Test String

In this example:

  • (^|_) captures either the start of the string or an underscore. This is back-reference \1.
  • ([a-z]) captures a lowercase letter. This is back-reference \2.
  • The /e modifier tells preg_replace to evaluate the replacement string as PHP code. strtoupper("\\2") would then be executed, applying strtoupper to the captured letter. The double backslash \\ is necessary within a PHP string to represent a literal backslash for the regex engine.

Modern Approach (using preg_replace_callback):

To achieve the same result securely, we use preg_replace_callback:

// Secure, recommended code
$string = 'this is a test string';
$pattern = '/(^|_)([a-z])/';

$result = preg_replace_callback($pattern, function($matches) {
    // $matches[0] is the full match
    // $matches[1] is the first captured group (^|_)
    // $matches[2] is the second captured group ([a-z])
    return $matches[1] . strtoupper($matches[2]);
}, $string);

echo $result; // Output: This Is A Test String

Here:

  • The callback function receives an array $matches, where $matches[2] holds the captured lowercase letter.
  • The function returns the modified string, concatenating the first capture group ($matches[1]) with the uppercased second capture group (strtoupper($matches[2])).

Handling Function References and Callables

The callback can be an anonymous function (as shown above), a string representing a global function name, or an array representing an object method.

Using a Global Function:

function convertToUpper($matches) {
    return $matches[1] . strtoupper($matches[2]);
}

$string = 'another example string';
$pattern = '/(^|_)([a-z])/';
$result = preg_replace_callback($pattern, 'convertToUpper', $string);
echo $result; // Output: Another Example String

Using First-Class Callable Syntax (PHP 8.1+):

function convertToUpper($matches) {
    return $matches[1] . strtoupper($matches[2]);
}

$string = 'php 8.1 example';
$pattern = '/(^|_)([a-z])/';
$result = preg_replace_callback($pattern, convertToUpper(...), $string);
echo $result; // Output: Php 8.1 Example

Managing Variable Scope in Callbacks

If your callback needs access to variables from the surrounding scope, you can use the use keyword with anonymous functions.

Original (Conceptual, not actual code):

Imagine the original replacement was 'do_stuff("\\1", $external_var)'.

Using preg_replace_callback with use:

$external_var = 'some_context';
$string = 'process this input';
$pattern = '/(^|_)([a-z])/';

$result = preg_replace_callback($pattern, function($matches) use ($external_var) {
    // Accessing $external_var within the callback
    return do_stuff($matches[1] . strtoupper($matches[2]), $external_var);
}, $string);

// Assuming do_stuff is defined elsewhere or you'd replace it.
// For demonstration, let's imagine do_stuff prepends the context:
function do_stuff($text, $context) {
    return "[{$context}] " . $text;
}

echo $result; // Output: [some_context] This Is A Test String

Gotchas and Considerations

When migrating from the /e modifier:

  1. Remove the /e flag: Ensure the /e flag is removed from your regex pattern. For example, /blah(.*)blah/mei becomes /blah(.*)blah/mi.
  2. stripslashes(): The /e modifier used an internal variant of addslashes(). You might need to remove stripslashes() calls from your new callback logic if they were previously used to counteract this.
  3. Back-reference Syntax: Replace \1, \2, etc., in your replacement string with $matches[1], $matches[2], etc., within the callback function.
  4. eval() Security: Avoid constructing replacement strings that are then evaluated. preg_replace_callback offers a safer path.

Shim for Temporary Compatibility (preg_replace_eval)

For a transitional period, or in situations where immediate refactoring is not feasible, a shim function can be implemented. This preg_replace_eval function aims to replicate the behavior of preg_replace with the /e flag. However, using eval() is strongly discouraged due to its inherent security risks, especially with user-provided input.

<?php
/**
 * Shim for preg_replace() with /e flag support. Use with extreme caution.
 * @param string $pattern The regular expression pattern.
 * @param string $replacement The replacement string or callback.
 * @param string $subject The input string.
 * @param int $limit The maximum replacements.
 * @return string|false The modified string or false on error.
 */
function preg_replace_eval($pattern, $replacement, $subject, $limit = -1) {
    // Remove the /e flag
    $pattern = preg_replace('/(\W[a-df-z]*)e([a-df-z]*)$/i', '$1$2', $pattern);

    // Basic warning for potentially dangerous patterns
    if (preg_match('/\(\.[+*]/', $pattern)) {
        trigger_error("preg_replace_eval(): Regex contains (.*) or (.+) placeholders. This is a security risk with user input. Use preg_replace_callback() instead.", E_USER_WARNING);
    }

    return preg_replace_callback(
        $pattern,
        function ($matches) use ($replacement) {
            // Substitute back-references ($1, $2) with actual matches
            $processed_replacement = preg_replace_callback(
                '/(?<!\\\\)(?:[$]|\\\\)(\d+)/', // Matches $1, \1 etc.
                function ($m) use ($matches) {
                    if (!isset($matches[$m[1]])) {
                        trigger_error("No capture group for '{$m[0]}' placeholder in replacement.", E_USER_WARNING);
                        return $m[0]; // Return placeholder if group doesn't exist
                    }
                    // Escape characters that have special meaning in eval'd strings
                    return addcslashes($matches[$m[1]], '\"\'\`\$\\\0');
                },
                $replacement
            );
            // Execute the replacement as PHP code
            return eval("return {$processed_replacement};");
        },
        $subject,
        $limit
    );
}

// Example usage of the shim (demonstrative, NOT recommended for production)
$string_shim = 'example with shim';
$pattern_shim = '/(^|_)([a-z])/e'; // Note the /e flag here
$replacement_shim = 'strtoupper("\\2")';
$result_shim = preg_replace_eval($pattern_shim, $replacement_shim, $string_shim);
echo "Shim result: " . $result_shim . "\n";
// Output: Shim result: Example With Shim
?>

Important Note: This preg_replace_eval function is provided for illustrative purposes to demonstrate how one might attempt to bridge the gap. It is highly inadvisable to use eval() in production code. Always prioritize preg_replace_callback.
