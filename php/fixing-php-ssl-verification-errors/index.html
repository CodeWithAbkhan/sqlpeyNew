“Fixing PHP SSL Verification Errors When Using file_get_contents”

When utilizing PHP functions like file_get_contents() to access remote resources over HTTPS, developers frequently encounter SSL/TLS verification failures, particularly after updates (like moving to PHP 5.6 or later) or when dealing with self-signed certificates. This occurs because PHP’s OpenSSL extension cannot validate the remote server’s certificate chain against a trusted Certificate Authority (CA) bundle.

How can one successfully fetch content from an HTTPS URL when faced with these persistent SSL verification challenges?

Approaches to Mitigate SSL Certificate Verification Issues

Several methods exist to address this, ranging from less secure quick fixes to robust, secure configuration adjustments.

Option 1: Explicitly Disabling Peer Verification (Use with Caution)

The quickest, albeit highly discouraged due to security risks like Man-in-the-Middle (MITM) attacks, is to instruct the stream context to ignore certificate checks. This mirrors behavior often seen in older PHP versions or when quick debugging is essential.

For PHP versions where OpenSSL changes were introduced (e.g., PHP 5.6+), both verify_peer and verify_peer_name must be explicitly set to false.

Example using file_get_contents with disabled verification:

<?php
$contextOptions = array(
    "ssl" => array(
        "verify_peer"      => false,
        "verify_peer_name" => false, // Essential for some endpoint names
    ),
);

$streamContext = stream_context_create($contextOptions);

$secureUrl = "https://maps.co.weber.ut.us/arcgis/rest/services/SDE_composite_locator/GeocodeServer/findAddressCandidates?Street=&SingleLine=3042+N+1050+W&outFields=*&outSR=102100&searchExtent=&f=json";

$response = file_get_contents($secureUrl, false, $streamContext);

echo $response;
?>

Alternative structure for context creation (PHP 7.2+ style):

<?php
    $stream_context = stream_context_create([
        "ssl" => [
            "verify_peer"      => false,
            "verify_peer_name" => false
        ]
    ]);  
    
    $response = file_get_contents("https://maps.co.weber.ut.us/arcgis/rest/services/SDE_composite_locator/GeocodeServer/findAddressCandidates?Street=&SingleLine=3042+N+1050+W&outFields=*&outSR=102100&searchExtent=&f=json", false, $stream_context);
    
    echo $response;
?>

This approach was also successfully employed when accessing Google Maps APIs with specific API keys, requiring disabling verification for self-signed environments:

<?php
$arrContextOptions = array(
    "ssl" => array(
         "verify_peer"      => false,
         "verify_peer_name" => false,
    ),
);  
$latitude = "40.7128";
$longitude = "-74.0060";
$apiKey = "YOUR_GOOGLE_API_KEY"; // Replace with actual key or Yii param fetching

$url = "https://maps.googleapis.com/maps/api/geocode/json?latlng={$latitude},{$longitude}&sensor=false&key={$apiKey}";

$data = file_get_contents($url, false, stream_context_create($arrContextOptions));

echo $data;
?>

Option 2: Configuring the CA Certificate Bundle (Recommended Secure Path)

The superior method involves configuring PHP to use a valid CA certificate bundle file, such as the one provided by cURL (cacert.pem).

2a. Specifying cafile in the Stream Context

You can point the ssl context directly to a downloaded certificate bundle.

<?php
$contextOptions = [
    'ssl' => [
        'cafile'         => '/path/to/your/downloaded/cacert.pem', // Must be an absolute path
        'verify_peer'    => true,
        'verify_peer_name' => true,
    ],
];

$response = file_get_contents(
    'https://example.com/api/endpoint',
    false,
    stream_context_create($contextOptions)
);
?>

2b. Configuring php.ini Globally

For a system-wide fix (if permissions allow), adjust the php.ini file:

  1. Download the certificate bundle (e.g., from curl.haxx.se/ca/cacert.pem ).
  2. Set the openssl.cafile directive in php.ini to the file’s absolute path: 
    openssl.cafile=/usr/local/etc/openssl/cert.pem
    After editing php.ini, restart your web server (e.g., Apache/Nginx).

2c. Using openssl_get_cert_locations and System Trust Stores

On CentOS/Linux systems, you might need to refresh the trust store after placing a new certificate:

# 1. Determine the default certificate file location
php -r "print_r(openssl_get_cert_locations()['default_cert_file']);"

# 2. Download the CA bundle and place it at the location found above
wget http://curl.haxx.se/ca/cacert.pem -O /path/to/default/cert.pem

# 3. Or, update the system trust store (CentOS/RHEL example)
sudo yum reinstall ca-certificates
sudo update-ca-trust force-enable 
sudo update-ca-trust extract

For macOS users with Homebrew installations (e.g., MAMP/PHP 7+ on Apple Silicon), the configuration points to the specific Homebrew OpenSSL directory:

; In php.ini for MAMP/Homebrew setup
openssl.cafile=/opt/homebrew/etc/openssl@3/cert.pem

Option 3: Using cURL as an Alternative to file_get_contents

If stream contexts remain troublesome (especially on older or misconfigured setups), utilizing the cURL extension offers a powerful alternative for HTTPS communication.

3a. Generic cURL Wrapper Function (Disabling Verification)

A custom function can be created to execute cURL requests, bypassing SSL checks if necessary:

function fetchContentViaCurl(string $url): ?string {
    $ch = curl_init();
    curl_setopt($ch, CURLOPT_AUTOREFERER, TRUE);
    curl_setopt($ch, CURLOPT_HEADER, 0);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, 1);
    curl_setopt($ch, CURLOPT_URL, $url);
    curl_setopt($ch, CURLOPT_FOLLOWLOCATION, TRUE);
    
    // Equivalent to verify_peer=false
    curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, FALSE); 
    curl_setopt($ch, CURLOPT_SSL_VERIFYHOST, 0); // Usually set to 0 or 2 depending on PHP version/need

    $data = curl_exec($ch);
    $httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    
    if (curl_errno($ch) || $httpCode >= 400) {
        // Log error or return null
        return null; 
    }
    
    curl_close($ch);
    return $data;
}

// Usage:
$result = fetchContentViaCurl("https://example.com/secure_data.json");

3b. Secure cURL Implementation with CA File

To use cURL securely, specify the CA bundle file:

$ch = curl_init($myHttpsURL);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, 1);
curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, true);
curl_setopt($ch, CURLOPT_SSL_VERIFYHOST, 2);
curl_setopt($ch, CURLOPT_CAINFO, '/path/to/your/chain.pem'); // Path to combined certs
$response = curl_exec($ch);
curl_close($ch);

Option 4: Server-Specific Certificate Management

Sometimes the issue stems from how certificates are presented or combined, especially in NGINX setups or local development environments (like XAMPP).

  1. Certificate Chaining (NGINX/General): If your SSL certificate provider issues an “intermediate certificate,” this often needs to be explicitly concatenated with your main server certificate (server.crt) into a single file for PHP streams or web servers like NGINX to trust the full chain without external CA files.

  2. Localhost Self-Signed Certificates (XAMPP/Windows): If accessing https://localhost/, the standard external CA bundle (curl-ca-bundle.crt) won’t recognize your local self-signed certificate. You must copy the content of your localhost certificate (server.crt from httpd-ssl.conf) and manually append it to the main curl-ca-bundle.crt file referenced in php.ini.

Option 5: System & Environment Checks

If configuration changes fail, the issue might be environmental:

  • ISP Interference: In rare cases, an Internet Service Provider (ISP) might interfere with SSL traffic. Changing local DNS settings (e.g., to Cloudflare 1.1.1.1) can sometimes bypass these blockages.
  • File Permissions: If you are using the cafile method, ensure the user running PHP has read permissions on the certificate file and the directory containing the certificates. For instance, check if the certificate directory needs 755 permissions instead of overly restrictive ones like 700. Use var_dump(openssl_get_cert_locations()); to inspect expected paths.
  • PHP Extension Installation: Ensure the cURL extension is installed if you plan to rely on cURL (e.g., sudo apt-get install php-curl).

FAQs on PHP SSL Verification Fixes

Q: What is the security risk of setting verify_peer to false

ANS: Setting verify_peer to false removes validation of the remote server’s SSL certificate authenticity. This makes your connection vulnerable to MITM attacks where an attacker could substitute a fraudulent certificate to eavesdrop on encrypted data exchange.

Q: How do I find my PHP default certificate location

ANS: Execute the PHP command line instruction: php -r "print_r(openssl_get_cert_locations()['default_cert_file']);" to see where PHP expects to find its trusted CA bundle.

Q: Does disabling verification work on PHP 7 and above

ANS: Yes, disabling verification (verify_peer => false) often works on PHP 7 and 8, but it is strongly recommended to configure a proper cafile instead for secure operation.

Q: What if I need to use file_get_contents with a self-signed certificate locally

ANS: The most robust way is to obtain the self-signed certificate file, combine it with a standard bundle like cacert.pem, and point PHP’s openssl.cafile in php.ini to this combined file, or explicitly set verify_peer and verify_peer_name to false in the stream context.
