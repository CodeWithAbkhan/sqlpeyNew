“Implement Real-time Web Updates: Long Polling Explained”

Implementing real-time features on the web often requires a way for the server to push updates to the client without the client constantly asking. Long polling is a technique that bridges this gap, keeping a connection open until new data is available. This method involves a client sending a request and the server holding it open until there’s information to send back.

Solution 1: Basic PHP and jQuery Long Polling

A straightforward approach involves a PHP script that waits for a random interval before sending a message, with a chance of simulating an error. The client-side JavaScript, using jQuery, repeatedly requests this PHP file, processes the response, and schedules the next request.

PHP Server Script (msgsrv.php)

This script simulates data availability with a random delay and a possibility of returning a 404 error.

<?php
// Simulate a 1 in 3 chance of a server error
if (rand(1, 3) == 1) {
    header("HTTP/1.0 404 Not Found");
    die();
}

// Wait for a random period between 2 and 10 seconds
sleep(rand(2, 10));

// Send a random number as the message
echo "Hi! Have a random number: " . rand(1, 10);
?>

Important Note: Running this directly on a server like Apache can consume significant resources by tying up worker threads. For production environments, consider using asynchronous frameworks like Python’s Twisted or Tornado for better scalability.

JavaScript Client (long_poller.htm)

This HTML file uses jQuery to manage the long polling process.

<html>
<head>
    <title>BargePoller</title>
    <script src="https://ajax.googleapis.com/ajax/libs/jquery/1.12.4/jquery.min.js"></script>
    <style type="text/css" media="screen">
        body { background: #000; color: #fff; font-size: .9em; }
        .msg { background: #aaa; padding: .2em; border-bottom: 1px #000 solid; }
        .old { background-color: #246499; }
        .new { background-color: #3B9957; }
        .error { background-color: #992E36; }
    </style>
    <script type="text/javascript">
        function addmsg(type, msg) {
            $("#messages").append(
                "<div class='msg " + type + "'>" + msg + "</div>"
            );
        }

        function waitForMsg() {
            $.ajax({
                type: "GET",
                url: "msgsrv.php",
                async: true,
                cache: false,
                timeout: 50000, // Timeout in milliseconds

                success: function(data) {
                    addmsg("new", data);
                    setTimeout(waitForMsg, 1000); // Request next message after 1 second
                },
                error: function(XMLHttpRequest, textStatus, errorThrown) {
                    addmsg("error", textStatus + " (" + errorThrown + ")");
                    setTimeout(waitForMsg, 15000); // Try again after 15 seconds
                }
            });
        }

        $(document).ready(function() {
            waitForMsg(); // Initiate the first request
        });
    </script>
</head>
<body>
    <div id="messages">
        <div class="msg old">BargePoller message requester!</div>
    </div>
</body>
</html>

Correction: A user pointed out a small syntax correction for the setTimeout call:

"1000"); /* ..after 1 seconds */

This ensures proper JavaScript execution.

Solution 3: Tornado’s Approach

The Tornado framework in Python is specifically designed for asynchronous operations like long polling. It manages client connections efficiently.

How it works:

  1. Clients send requests indicating the last message ID they received.
  2. The server queues callbacks for clients waiting for updates.
  3. When a new message arrives, the onmessage event triggers, iterating through the callbacks to send messages.
  4. The client receives the message, updates the display, and requests updates starting from the new message ID.

Solution 4: Generic Server Logic

A conceptual outline for server-side long polling logic:

while not hasNewData():
    usleep(50) # Pause briefly

outputNewData() # Send available data

The client would typically send its last update timestamp, allowing the server’s hasNewData() function to check for relevant information.

Solution 10: Abstract LongPoller Class in PHP

This PHP abstract class provides a robust structure for long polling implementations, with configurable sleep and timeout times.

<?php
abstract class LongPoller {

  protected $sleepTime = 5;
  protected $timeoutTime = 30;

  function __construct() {}

  function setTimeout($timeout) {
    $this->timeoutTime = $timeout;
  }

  function setSleep($sleep) {
    $this->sleepTime = $sleep; // Corrected typo: $sleepTime -> $sleep
  }

  public function run() {
    $data = NULL;
    $timeout = 0;

    set_time_limit($this->timeoutTime + $this->sleepTime + 15);

    while ($data == NULL && $timeout < $this->timeoutTime) {
      $data = $this->loadData();
      if ($data == NULL) {
        flush(); // Notify server is still active
        sleep($this->sleepTime);
        $timeout += $this->sleepTime;
      } else {
        echo $data;
        flush();
      }
    }
  }

  protected abstract function loadData();
}
?>

Solution 11: PHP Limitations and Nginx HttpPushStreamModule

PHP’s synchronous nature makes it less ideal for long polling, as it can tie up server resources. For a more efficient PHP solution, using Nginx with the HttpPushStreamModule is recommended. Nginx can handle the persistent connections, allowing PHP to respond with data without maintaining the open connection itself. This approach mitigates the scaling issues inherent in PHP for such tasks.

Solution 17: Simplest NodeJS Long Polling

Node.js offers a concise way to implement long polling.

const http = require('http');

const server = http.createServer((req, res) => {
  SomeVeryLongAction(res);
});

server.on('clientError', (err, socket) => {
  socket.end('HTTP/1.1 400 Bad Request\r\n\r\n');
});

server.listen(8000);

// Simulate a long-running task
function SomeVeryLongAction(response) {
  setTimeout(() => response.end(), 10000); // Respond after 10 seconds
}

For a more structured Node.js/Express application, you can manage responses in an array:

const http = require('http');
var responsesArray = [];

const server = http.createServer((req, res) => {
  // Store the response object to be handled later
  responsesArray.push(res);
});

server.on('clientError', (err, socket) => {
  socket.end('HTTP/1.1 400 Bad Request\r\n\r\n');
});

// Function to resolve pending responses
function resolvePendingResponses() {
  if (responsesArray.length > 0) {
    let localResponse = responsesArray.shift();
    localResponse.end(); // Send response
  }
}

// Simulate an action that triggers a response
setTimeout(resolvePendingResponses, 10000);
server.listen(8000);

This approach allows you to manage and respond to specific requests efficiently.

FAQs on Implement Real-time Web Updates: Long Polling Explained

Q: What is the core concept behind long polling

ANS: Long polling involves a client making a request to the server and the server holding that request open until it has new data to send. Once data is sent, or a timeout occurs, the connection is closed, and the client initiates a new request.

Q: When should I consider using long polling

ANS: Long polling is suitable for scenarios where you need to receive updates from the server in near real-time, but don’t require the constant, bidirectional communication of WebSockets. It’s a viable option when client browser support for WebSockets is a concern or for simpler update mechanisms.

Q: What are the potential drawbacks of long polling

ANS: A primary drawback is the potential for server resource consumption, as each open connection, even if idle, uses server resources. Inefficient implementations can lead to “hanging” connections and a high number of concurrent open requests, impacting server performance.

Q: How does long polling differ from traditional AJAX polling

ANS: Traditional AJAX polling involves the client repeatedly sending requests at fixed intervals (e.g., every few seconds). Long polling, conversely, keeps the connection open until the server has data, reducing unnecessary requests and latency when data is available.

Q: Are there alternatives to long polling for real-time web updates

ANS: Yes, WebSockets are a more efficient and modern solution for real-time, bidirectional communication. Server-Sent Events (SSE) are also an option for server-to-client streaming.
