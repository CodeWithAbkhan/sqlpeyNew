“PHP cURL: Debugging with Verbose Output and Request Metrics”

When working with PHP cURL, obtaining detailed information about a request can be crucial for troubleshooting. This involves leveraging specific cURL options to log verbose output and retrieve performance metrics. Here’s a breakdown of various methods to achieve this.

Solution 1: Utilizing CURLOPT_VERBOSE and CURLOPT_STDERR for Detailed Logging

A primary method for debugging cURL requests in PHP is by enabling the CURLOPT_VERBOSE option. This flag instructs cURL to output detailed information about the transfer process. This output is typically directed to standard error (STDERR). You can redirect this output to a temporary stream for later examination.

This approach allows you to capture a step-by-step log of the entire cURL operation, which is invaluable for diagnosing connection issues, protocol-level problems, or unexpected request/response behaviors.

<?php
// Initialize cURL session
$curlHandle = curl_init();

// Set the URL and other options
curl_setopt($curlHandle, CURLOPT_URL, 'https://example.com/api/data');
curl_setopt($curlHandle, CURLOPT_RETURNTRANSFER, true);

// Enable verbose output
// TRUE to output verbose information.
// Writes output to STDERR, or the file specified using CURLOPT_STDERR.
curl_setopt($curlHandle, CURLOPT_VERBOSE, true);

// Redirect verbose output to a temporary stream
$streamVerboseHandle = fopen('php://temp', 'w+');
curl_setopt($curlHandle, CURLOPT_STDERR, $streamVerboseHandle);

// Execute the cURL request
$result = curl_exec($curlHandle);

// Check for cURL errors
if ($result === false) {
    printf("cUrl error (#%d): %s<br>\n",
           curl_errno($curlHandle),
           htmlspecialchars(curl_error($curlHandle)));
}

// Retrieve and display the verbose log
rewind($streamVerboseHandle);
$verboseLog = stream_get_contents($streamVerboseHandle);

echo "cUrl verbose information:\n";
echo "<pre>" . htmlspecialchars($verboseLog) . "</pre>\n";

// Get more request metrics
$version = curl_version();
$metrics = curl_getinfo($curlHandle);

// Format and display metrics
extract($metrics);
$metricsDisplay = <<<EOD
URL....: $url
Code...: $http_code ($redirect_count redirect(s) in $redirect_time secs)
Content: $content_type Size: $download_content_length (Own: $size_download) Filetime: $filetime
Time...: $total_time Start @ $starttransfer_time (DNS: $namelookup_time Connect: $connect_time Request: $pretransfer_time)
Speed..: Down: $speed_download (avg.) Up: $speed_upload (avg.)
Curl...: v{$version['version']}
EOD;

echo "Request Metrics:\n";
echo "<pre>" . htmlspecialchars($metricsDisplay) . "</pre>\n";

// Close cURL session
curl_close($curlHandle);
?>

Solution 2: Direct CURLOPT_VERBOSE Activation

For a simpler debugging approach, you can directly enable CURLOPT_VERBOSE. When this option is set, output is sent to STDERR or a file specified by CURLOPT_STDERR. The detailed output generated is highly beneficial for diagnosing issues.

<?php
$curlhandle = curl_init();
// Enable verbose output
curl_setopt($curlhandle, CURLOPT_VERBOSE, true);
// The output will be directed to STDERR by default
curl_exec($curlhandle);
curl_close($curlhandle);
?>

Solution 3: Logging to a Specific File Handle

You can also direct the verbose output to a specific file by providing a file handle to CURLOPT_STDERR. This is useful for persistent logging of debugging information.

<?php
$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, 'http://example.com/resource');

// Enable verbose output
curl_setopt($ch, CURLOPT_VERBOSE, 1);

// Specify the file handle for error output
$fp = fopen(dirname(__FILE__).'/curl_debug.log', 'w');
curl_setopt($ch, CURLOPT_STDERR, $fp);

curl_exec($ch);
curl_close($ch);
fclose($fp); // Close the file handle
?>

Solution 4: Outputting Directly to php://stderr

A streamlined method for sending debug output directly to PHP’s standard error stream is by using php://stderr. This avoids the need to manually manage file handles for basic verbose logging.

<?php
$curl = curl_init();
curl_setopt($curl, CURLOPT_URL, 'https://api.example.com/status');

// Enable verbose output
curl_setopt($curl, CURLOPT_VERBOSE, true);

// Direct verbose output to php://stderr
curl_setopt($curl, CURLOPT_STDERR, fopen('php://stderr', 'w'));

curl_exec($curl);
curl_close($curl);
?>

Solution 5: Inspecting Request Information with curl_getinfo

Beyond verbose logs, curl_getinfo provides a wealth of metrics about the last cURL transfer. This includes details like the HTTP status code, content type, transfer times, and speeds.

<?php
$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, 'http://example.com/data');
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);

$response = curl_exec($ch);

// Get all available information
$info = curl_getinfo($ch);
var_dump($info);

curl_close($ch);
?>

Solution 6: Simple Error Logging to Console

For quick debugging, you can capture the cURL error message and output it directly to the browser’s console using a JavaScript snippet. This is a convenient way to see errors during development.

<?php
$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, 'http://nonexistent.example.com'); // Intentionally wrong URL

curl_exec($ch);
$curl_error = curl_error($ch);

// Output the error to the browser's console
echo "<script>console.log('cURL Error: " . $curl_error . "');</script>";

curl_close($ch);
?>

Solution 7: Detailed Debugging with CURLOPT_DEBUGFUNCTION (PHP 8.4+)

For more granular control over debug output, especially from PHP 8.4 onwards, the CURLOPT_DEBUGFUNCTION option is available. This allows you to register a callback function that receives detailed information about different stages of the transfer (headers, data, SSL information).

Output Debug Info to Standard Error:

<?php
$curlHandler = curl_init();

curl_setopt_array($curlHandler, [
    CURLOPT_URL => 'https://postman-echo.com/get?foo=bar',
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_VERBOSE => true, // Still useful for general verbose output
]);

// Set the debug function
curl_setopt($curlHandler, CURLOPT_DEBUGFUNCTION,
    function($curlHandle, $type, $data) {
        switch ($type) {
            case CURLINFO_TEXT:
                echo '(informational text)';
                break;
            case CURLINFO_HEADER_IN:
                echo '(response headers)';
                break;
            case CURLINFO_HEADER_OUT:
                echo '(request headers)';
                break;
            case CURLINFO_DATA_IN:
                echo '(response data)';
                break;
            case CURLINFO_DATA_OUT:
                echo '(request data)';
                break;
            case CURLINFO_SSL_DATA_IN:
                echo '(response SSL data)';
                break;
            case CURLINFO_SSL_DATA_OUT:
                echo '(request SSL data)';
                break;
            default:
                echo '(unknown type ' . $type . ')';
                break;
        }
        echo ' ' . var_export($data, true) . PHP_EOL;
    }
);

$result = curl_exec($curlHandler);

curl_close($curlHandler);
?>

Output Debug Info to a File:

<?php
$curlHandler = curl_init();

curl_setopt_array($curlHandler, [
    CURLOPT_URL => 'https://postman-echo.com/get?foo=bar',
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_VERBOSE => true, // Still useful for general verbose output
    CURLOPT_STDERR => fopen('./curl_detailed.log', 'w+'), // Specify log file
]);

// Set the debug function
curl_setopt($curlHandler, CURLOPT_DEBUGFUNCTION,
    function($curlHandle, $type, $data) {
        switch ($type) {
            case CURLINFO_TEXT:
                fwrite(STDOUT, '(informational text)'); // Example: write to stdout for demo
                break;
            case CURLINFO_HEADER_IN:
                fwrite(STDOUT, '(response headers)');
                break;
            case CURLINFO_HEADER_OUT:
                fwrite(STDOUT, '(request headers)');
                break;
            case CURLINFO_DATA_IN:
                fwrite(STDOUT, '(response data)');
                break;
            case CURLINFO_DATA_OUT:
                fwrite(STDOUT, '(request data)');
                break;
            case CURLINFO_SSL_DATA_IN:
                fwrite(STDOUT, '(response SSL data)');
                break;
            case CURLINFO_SSL_DATA_OUT:
                fwrite(STDOUT, '(request SSL data)');
                break;
            default:
                fwrite(STDOUT, '(unknown type ' . $type . ')');
                break;
        }
        fwrite(STDOUT, ' ' . var_export($data, true) . PHP_EOL);
    }
);

curl_exec($curlHandler);
curl_close($curlHandler);
?>

Solution 8: Network Traffic Inspection with Netcat

A more advanced technique involves using network utilities like netcat (nc) to capture raw network traffic. This is particularly useful for examining exactly what data is being sent over the wire. You can pipe the output to a file for later analysis.

First, start netcat in listening mode:

nc -l -p 8000 -w 3 | tee curldbg.txt

Then, configure your cURL request to connect to this local listener. Note that this setup will likely fail as netcat won’t send proper HTTP responses, but it’s excellent for inspecting outgoing requests.

FAQs on PHP cURL Debugging

Q: How can I get a detailed log of a PHP cURL request

ANS: Enable CURLOPT_VERBOSE and redirect CURLOPT_STDERR to a stream or file. You can also use CURLOPT_DEBUGFUNCTION for finer control over what is logged. See solutions 1, 3, 4, and 7.

Q: What information does curl_getinfo provide

ANS: curl_getinfo returns metrics like the URL, HTTP status code, content type, transfer times (DNS lookup, connection, total time), and download/upload speeds. Refer to solution 5.

Q: Can I log cURL request and response headers separately

ANS: Yes, using CURLOPT_DEBUGFUNCTION with specific types like CURLINFO_HEADER_OUT for requests and CURLINFO_HEADER_IN for responses allows this. Consult solution 7.

Q: Is there a way to see data being sent and received by cURL

ANS: Yes, the CURLOPT_DEBUGFUNCTION can log CURLINFO_DATA_OUT (request data) and CURLINFO_DATA_IN (response data) for detailed inspection. Check solution 7.

Q: How to debug SSL issues with PHP cURL

ANS: Enabling CURLOPT_VERBOSE or using CURLOPT_DEBUGFUNCTION with types like CURLINFO_SSL_DATA_IN and CURLINFO_SSL_DATA_OUT can help diagnose SSL handshake and data transfer problems. You might also find resources on troubleshooting SSL certificate verification relevant.
