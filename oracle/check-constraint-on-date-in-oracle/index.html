Introduction to CHECK constraint on date

In SQL, a CHECK constraint is used to enforce a condition on one or more columns of a table. The CHECK constraint on date is used to ensure that the value in a date column meets certain conditions. For example, it can be used to ensure that the value in a date column is a valid date or falls within a specified range.

Syntax of CHECK constraint on date

The basic syntax for creating a CHECK constraint on a date column is as follows:

ALTER TABLE Orders
ADD CONSTRAINT check_order_date CHECK (order_date IS DATE);

Enforcing Check Constraints in Oracle with SYSDATE

Check constraints must be deterministic, meaning that a particular row must always satisfy the constraint or it must always fail to satisfy the constraint. However, SYSDATE is inherently non-deterministic since the returned value is constantly changing. Thus, you cannot define a CHECK constraint that calls SYSDATE or any other user-defined function .

The following is an example of a trigger in Oracle that can be used to enforce a CHECK constraint-like condition on a date column :


CREATE OR REPLACE TRIGGER check_birth_date
  BEFORE INSERT OR UPDATE ON employee
  FOR EACH ROW
BEGIN
  IF( :new.emp_dob < date '1900-01-01' or :new.emp_dob > sysdate )
  THEN
    RAISE_APPLICATION_ERROR( 
      -20001, 
      'employee date of birth must be later than Jan 1, 1900 and earlier than today' );
  END IF;
END;

By using this trigger , we can ensure that the value of the “emp_dob” column always meets the desired condition and is restricted within the given range.

FAQs of CHECK constraint on date

What is a check constraint and why do we use it?

A check constraint is a rule that is applied to a specific column or set of columns in a database table. It ensures that any data entered into the column(s) meets certain conditions or criteria.

Why is using check constraints a good practice in database design?

Using check constraints is a good practice in database design because it helps to ensure that the data in a database is accurate, consistent, and reliable. Check constraints can be used to enforce business rules or data validation rules, which can help to prevent data errors or inconsistencies. Check constraints can help to improve the performance of a database by reducing the need for complex data validation code in application logic.

Are check constraints only used in relational databases?

No, check constraints can be used in any type of database, including relational, non-relational, and document databases. The syntax and implementation of check constraints may vary depending on the type of database, but the basic concept of enforcing rules on data remains the same.

What is the purpose of a CHECK constraint on a date column in SQL?

The purpose of a CHECK constraint on a date column in SQL is to ensure that the value in that column meets certain conditions. For example, it can be used to ensure that the value is a valid date or falls within a specified range.

Can a CHECK constraint on a date column be used to enforce multiple conditions at once?

Yes, a CHECK constraint on a date column can be used to enforce multiple conditions at once. For example, the following SQL creates a CHECK constraint that ensures the “order_date” column in the “Orders” table is a valid date and falls within the range of ‘2020-01-01’ and ‘2020-12-31’:


  ALTER TABLE Orders
  ADD CONSTRAINT check_order_date CHECK (order_date IS DATE AND order_date >= '2020-01-01' AND order_date <= '2020-12-31');

What happens if a row with a date value that doesn’t meet the conditions specified in the CHECK constraint is inserted or updated?

If a row with a date value that doesn’t meet the conditions specified in the CHECK constraint is inserted or updated, then the query will return an error and the insert or update will not be executed.

Can a CHECK constraint be added to an existing table in SQL?

Yes, a CHECK constraint can be added to an existing table in SQL using the ALTER TABLE statement and the ADD CONSTRAINT clause.

Can a CHECK constraint be dropped or modified in SQL?

Yes, a CHECK constraint can be dropped or modified in SQL using the ALTER TABLE statement with the DROP CONSTRAINT or MODIFY CONSTRAINT clause.
