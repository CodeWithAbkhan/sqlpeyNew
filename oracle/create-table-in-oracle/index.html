Introduction to Create table in Oracle:

Creating tables in Oracle SQL is a fundamental task in database management. Tables are used to store data in a structured format, and can be queried, updated, and deleted as needed. There are several ways to create tables in Oracle, each with its own syntax and use cases. In this tutorial, we will explore 7 ways to create tables in Oracle SQL .

7 ways of Create table in Oracle:

1. Using the “CREATE TABLE” statement

The CREATE TABLE statement is the most common method of creating a table in Oracle SQL. The syntax for this statement is “CREATE TABLE table_name (column_name datatype constraint, column_name datatype constraint, …);” This statement allows you to create a new table with the specified columns and data types.

2. Using the “CREATE TABLE AS SELECT” statement

The CREATE TABLE AS SELECT statement allows you to create a new table based on the columns and data of an existing table. The syntax for this statement is “CREATE TABLE new_table_name AS SELECT * FROM existing_table_name; " This statement can be useful when you want to create a copy of an existing table.

3. Using the “CREATE TABLE LIKE” statement

The CREATE TABLE LIKE statement allows you to create a new table based on the structure of an existing table. The syntax for this statement is “CREATE TABLE new_table_name (LIKE existing_table_name);” This statement can be useful when you want to create a new table with the same structure as an existing table but with different data.

4. Using the “CREATE GLOBAL TEMPORARY TABLE” statement

The CREATE GLOBAL TEMPORARY TABLE statement allows you to create a temporary table that can be accessed by multiple sessions. The syntax for this statement is “CREATE GLOBAL TEMPORARY TABLE table_name (column_name datatype constraint, column_name datatype constraint, …);” This statement can be useful when you need a temporary table for a specific task, but the data in the table is not needed for future use.

5. Using the “CREATE MATERIALIZED VIEW” statement

The CREATE MATERIALIZED VIEW statement allows you to create a pre-calculated table of data based on a SELECT statement. The syntax for this statement is “CREATE MATERIALIZED VIEW view_name AS SELECT … FROM … WHERE …;” This statement can be useful when you have a complex query that is used frequently and you want to improve performance by storing the results in a table.

6. Using the “CREATE EXTERNAL TABLE” statement

The CREATE EXTERNAL TABLE statement allows you to create a table that references data stored in an external location. The syntax for this statement is “CREATE EXTERNAL TABLE table_name (column_name datatype, column_name datatype, …) LOCATION (‘path_to_data’)” This statement can be useful when you want to access data stored in external locations such as a flat file, and query it as if it were stored in the database.

7. Using the “CREATE TEMPORARY TABLE” statement

The CREATE TEMPORARY TABLE statement allows you to create a temporary table that is only accessible to the current session. The syntax for this statement is similar to the CREATE TABLE statement, and is “CREATE TEMPORARY TABLE table_name (column_name datatype constraint, column_name datatype constraint, …);” This statement can be useful when you need a temporary table for a specific task but you don’t want to make it accessible to other sessions.

5th way: Using the “CREATE MATERIALIZED VIEW” statement

Example 1 (JustLee book database):

CREATE MATERIALIZED VIEW top_selling_books
AS
SELECT books.title, SUM(orderitems.quantity) as total_sold
FROM books
INNER JOIN orderitems ON books.isbn = orderitems.isbn
GROUP BY books.title
ORDER BY total_sold DESC;

Example 2 (school sample database):

CREATE MATERIALIZED VIEW top_performing_students
AS
SELECT students.name, SUM(grades.score) as total_score
FROM students
INNER JOIN grades ON students.student_id = grades.student_id
GROUP BY students.name
ORDER BY total_score DESC;

A materialized view is a pre-computed table based on a SELECT statement, it stores the result of the SELECT statement in a physical table, so that the result can be queried without executing the SELECT statement again. Materialized views are particularly useful in situations where the SELECT statement takes a long time to execute or the data is frequently accessed.

Please note that both examples are assuming that the original tables “books”, “orderitems”, “students” and “grades” already exist in the respective databases and have data in them.

A temporary table is a table that is created to store temporary data. The data in a temporary table is only visible to the session that created the table and is deleted when the session ends. Temporary tables can be created as either a global temporary table or a local temporary table. A global temporary table is visible to all sessions and is deleted when all sessions that have referenced the table have ended. A local temporary table is only visible to the session that created it and is deleted when that session ends.

FAQs of Create table in Oracle SQL

What is the difference between a temporary table and a regular table?

Answer: A temporary table is created to store temporary data, visible only to the session that created it and deleted when the session ends. In contrast, a regular table is designed for permanent data storage, visible to all sessions until explicitly dropped.

Can a temporary table be created with constraints?

Answer: Yes, a temporary table can be created with constraints, similar to a regular table. However, constraints on temporary tables are only enforced for the duration of the session and are not maintained when the data is deleted.

Can a temporary table be created with indexes?

Answer: Yes, a temporary table can have indexes, just like a regular table. However, it’s essential to note that indexes on temporary tables are only utilized for the session’s duration and are not applicable when the data is deleted.

Can a temporary table be queried by other sessions?

Answer: A global temporary table can be queried by other sessions, while a local temporary table can only be queried by the session that created it.

Can a temporary table be truncated?

Answer: Yes, a temporary table can be truncated in the same way as a regular table.

What is the difference between a primary key and a unique key in Oracle?

Answer: In Oracle, a primary key is a unique key used to identify each row and define relationships between tables. A unique key is similar but allows multiple null values and is not used to establish relationships.

Can I rename a table after it has been created in Oracle?

Answer: Yes, you can rename a table in Oracle using the ALTER TABLE statement. The syntax for renaming a table is “ALTER TABLE old_table_name RENAME TO new_table_name;”.

Can I add a new column to an existing table in Oracle?

Answer: Yes, you can add a new column to an existing table in Oracle using the ALTER TABLE statement. The syntax for adding a new column is “ALTER TABLE table_name ADD column_name datatype;”.

Can I drop a table in Oracle?

Answer: Yes, you can drop a table in Oracle using the DROP TABLE statement. The syntax for dropping a table is “DROP TABLE table_name;”. Exercise caution when dropping tables, as it can result in data loss.

Can a temporary table be renamed?

Answer: No, a temporary table cannot be renamed. To change the name, you must create a new table with the desired name and copy the data from the old table to the new one.

Can a temporary table be exported?

Answer: Yes, a temporary table can be exported like a regular table. However, the data in a temporary table is only available for the session’s duration and will not be exported after the session ends.

Can a temporary table have a primary key?

Answer: Yes, a temporary table can have a primary key, similar to a regular table. However, primary keys on temporary tables are only enforced for the duration of the session and are not maintained when the data is deleted.
