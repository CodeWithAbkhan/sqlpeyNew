“Angular Object Iteration: Accessing Keys and Values in ngFor”

When working with JavaScript objects in Angular templates, directly iterating using *ngFor is not straightforward as it’s primarily designed for arrays. However, several techniques exist to achieve this, allowing you to access both the keys and their corresponding values. These methods range from built-in Angular features to custom pipe creation and leveraging JavaScript’s native capabilities.

Solution 1: Utilizing the keyvalue Pipe (Angular 6.1.0 and later)

For Angular versions 6.1.0 and above, the framework provides a built-in keyvalue pipe. This pipe is specifically designed to iterate over objects, maps, and arrays, making it a clean and efficient solution.

To maintain the original order of the object’s properties, you can provide a comparison function.

Example Usage:

<div *ngFor="let item of testObject | keyvalue">
    Key: <b>{{item.key}}</b> and Value: <b>{{item.value}}</b>
</div>

To preserve order:

In your component, define a comparison callback:

import { Component, KeyValueDiffer, KeyValueDiffers, KeyValueChangeRecord } from '@angular/common';

@Component(/* ... */)
export class MyComponent {
  testObject = { 'b': 1, 'a': 2 };

  keepOriginalOrder = (a: KeyValueChangeRecord<any, any>, b: KeyValueChangeRecord<any, any>): number => {
    return a.key < b.key ? -1 : (a.key > b.key ? 1 : 0);
  }
}

Template Usage with Order Preservation:

<div *ngFor="let item of testObject | keyvalue: keepOriginalOrder">
    Key: <b>{{item.key}}</b> and Value: <b>{{item.value}}</b>
</div>

For more details on the keyvalue pipe and its evolution, refer to the Angular Changelog and the specific commit .

Solution 2: Using Object.keys() in the Template

You can expose Object.keys() directly in your template by making it a method on your component. This allows you to iterate over the keys and then access the values using bracket notation.

Component Code:

import { Component } from '@angular/core';

@Component({
  selector: 'app-my-view',
  template: `
    <div *ngFor="let key of objectKeys(items)">{{key}} : {{items[key]}}</div>
  `
})
export class MyComponent {
  objectKeys = Object.keys; // Expose Object.keys to the template
  items = { keyOne: 'value 1', keyTwo: 'value 2', keyThree: 'value 3' };

  constructor() {}
}

Solution 3: Creating a Custom Keys Pipe

A flexible approach, especially for older Angular versions or when more control is needed, is to create a custom pipe. This pipe can transform an object into an array of keys, or an array of key-value pairs.

Custom Pipe Implementation:

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({name: 'keys'})
export class KeysPipe implements PipeTransform {
  transform(value: any, returnObject?: boolean): any {
    const keys = [];
    for (const key in value) {
      if (value.hasOwnProperty(key)) {
        if (returnObject) {
          keys.push({ key: key, value: value[key] });
        } else {
          keys.push(key);
        }
      }
    }
    return keys;
  }
}

Template Usage (returning key-value pairs):

<span *ngFor="let entry of content | keys:true">
  Key: {{entry.key}}, value: {{entry.value}}
</span>

Template Usage (returning keys only):

<tr *ngFor="let c of content">
  <td *ngFor="let key of c | keys">{{key}}: {{c[key]}}</td>
</tr>

You can find more information on Angular pipes in this article .

Solution 4: Creating a Custom NgForIn Directive

For a more directive-based approach, you can create a custom directive that mimics *ngFor but works with objects. This involves extending NgForOf and overriding its behavior.

Directive Implementation:

import { Directive, Input, OnChanges, SimpleChanges, TemplateRef, ViewContainerRef, IterableDifferFactory, IterableDiffer, NgIterable, DoCheck } from '@angular/core';
import { NgForOf, NgForOfContext } from '@angular/common';

@Directive({
  selector: '[ngFor][ngForIn]'
})
export class NgForIn<T> extends NgForOf<T> implements OnChanges, DoCheck {

  @Input() ngForIn: { [key: string]: T } | null;
  private _ngForOf: NgIterable<T>;

  constructor(
    _differs: { iterable: IterableDifferFactory },
    _template: TemplateRef<NgForOfContext<T>>,
    _viewContainer: ViewContainerRef
  ) {
    super(_differs, _template, _viewContainer);
  }

  ngOnChanges(changes: SimpleChanges): void {
    if (changes['ngForIn']) {
      const ngForInValue = changes['ngForIn'].currentValue;
      this._ngForOf = ngForInValue ? Object.keys(ngForInValue) : null;
      // Important: Update the input for the base NgForOf class
      // We need to simulate the NgForOf input change
      const ngForOfChanges = {
        ngForOf: {
          previousValue: this.ngForOf,
          currentValue: this._ngForOf,
          firstChange: changes['ngForIn'].firstChange,
          isFirstChange: () => changes['ngForIn'].firstChange
        }
      };
      super.ngOnChanges(ngForOfChanges);
    }
  }

  ngDoCheck(): void {
    // This is crucial for change detection to work with the modified ngForOf
    if (this.ngForIn) {
      const currentKeys = Object.keys(this.ngForIn);
      if (!this.differ || !this.iterableDiffer) {
        this.differ = this._differs.iterable.create(currentKeys);
        this.iterableDiffer = this.differ; // Assign to the correct property name
      }
      const changes = this.differ.diff(currentKeys);
      if (changes) {
        this.applyChanges(changes);
      }
    } else if (this.ngForOf === null) { // Handle case where ngForIn is explicitly null or undefined
      this.applyChanges(null);
    }
  }

  // Helper to call the base class's change application logic
  private applyChanges(changes: any) {
    // Need to call the protected method of NgForOf, this is a bit of a hack
    // In a real-world scenario, consider a more robust approach if possible
    // or if NgForOf offers public methods for this.
    (this as any)._onArrayChanged(changes);
  }

  // Override ngForOf getter to return our processed keys
  get ngForOf(): NgIterable<T> {
    return this._ngForOf;
  }

  // Override ngForOf setter to prevent direct modification
  set ngForOf(value: NgIterable<T>) {
    // Do not allow direct setting of ngForOf, it's derived from ngForIn
  }
}

Module Declaration: Make sure to declare NgForIn in your AppModule or a relevant feature module.

import { NgModule } from '@angular/core';
import { CommonModule } from '@angular/common';
import { NgForIn } from './ng-for-in.directive'; // Adjust path as needed

@NgModule({
  declarations: [NgForIn],
  imports: [CommonModule],
  exports: [NgForIn, CommonModule] // Export common module as well
})
export class SharedModule { } // Or AppModule

Template Usage:

<div *ngFor="let key in myObject" ngForIn>
  <b>{{ key }}</b>: {{ myObject[key] }}
</div>

Solution 6: Leveraging Object.entries() with a Custom Pipe (ECMAScript 2017+)

For modern JavaScript environments, Object.entries() provides a straightforward way to get an array of [key, value] pairs from an object. You can wrap this in a custom pipe for template use.

Custom Pipe (ForObjectPipe):

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'forObject',
  pure: true, // Set to true if the pipe logic doesn't depend on external state changes
})
export class ForObjectPipe implements PipeTransform {
  transform(object: { [key: string]: any }): [string, any][] {
    return Object.entries(object);
  }
}

Module Integration: Ensure ForObjectPipe is declared in your module.

Template Usage:

<h1>Object Details:</h1>
<div *ngFor="let pair of myObject | forObject">
  Key: {{ pair[0] }} - Value: {{ pair[1] }}
</div>

Solution 7: Using Object.keys() with Index (for simple iteration)

Sometimes, you might only need to iterate through the object’s keys, and you can leverage the index as key syntax with *ngFor.

Template Usage:

<div *ngFor="let value of objectArray; index as key">
  {{key}} -> {{value}}
</div>

This requires your object to be converted into an array first, for example, using Object.values() or by pushing key-value pairs into an array as shown in Solution 16 .

Solution 8: Converting Object to Array

Another common pattern is to transform the object into an array of key-value objects, which can then be iterated over with *ngFor.

Component Code:

import { Component } from '@angular/core';

@Component({
  selector: 'app-object-to-array',
  template: `
    <div *ngFor="let item of details">
      <p>Key: {{item.key}}</p>
      <p>Value: {{item.value}}</p>
    </div>
  `
})
export class ObjectToArrayComponent {
  details: { key: string; value: any }[] = [];
  myObject = { 'propertyOne': 'data 1', 'propertyTwo': 'data 2' };

  constructor() {
    Object.keys(this.myObject).forEach(key => {
      this.details.push({ key: key, value: this.myObject[key] });
    });
  }
}

Solution 9: TypeScript Iterators (Advanced)

For highly specialized cases, you can implement the TypeScript iterator protocol using Symbols. This allows an object to be directly iterable in *ngFor.

Component Code:

import { Component } from '@angular/core';

@Component({
  selector: 'app-iterator-example',
  template: `
    <div>
      <h4>Iterating with Symbol Iterator</h4>
      Object: <p>{{ obj | json }}</p>
      Iterated values:
      <div *ngFor="let item of obj">
        {{ item }}
      </div>
    </div>
  `
})
export class IteratorComponent {
  obj: any = {
    "type1": ["A1", "A2"],
    "type2": ["B1"],
    "type3": ["C1"],
  };

  constructor() {
    // Define a custom iterator
    this.obj[Symbol.iterator] = () => {
      let index = 0;
      const keys = Object.keys(this.obj);
      return {
        next: () => {
          if (index < keys.length) {
            return { done: false, value: this.obj[keys[index++]] };
          } else {
            return { done: true, value: undefined };
          }
        }
      };
    };
  }
}

FAQs on Angular Object Iteration

Q: What is the most modern way to iterate an object in Angular?

ANS: For Angular versions 6.1.0 and later, the keyvalue pipe is the recommended and most modern approach. It’s a built-in pipe designed specifically for this purpose.

Q: How do I iterate an object in Angular if I'm using a version older than 6.1.0?

ANS: If you are using an Angular version prior to 6.1.0, creating a custom pipe (like the KeysPipe shown in Solution 3) or using Object.keys() directly in the template (Solution 2) are effective methods.

Q: Does the keyvalue pipe maintain the original order of object properties?

ANS: By default, the keyvalue pipe might sort the properties by key. To maintain the original order, you can provide a custom comparison function to the pipe, as demonstrated in Solution 1.

Q: Can I access both the key and the value of an object property in the template?

ANS: Yes, all the presented solutions allow you to access both the key and the value. The keyvalue pipe and custom pipes that return key-value pairs explicitly provide both. When using Object.keys() or Object.entries(), you can access the value using the key.

Q: Is it efficient to create a custom pipe for object iteration?

ANS: Creating a custom pipe is generally efficient, especially if implemented correctly. For pipes that transform data, consider the pure attribute. Setting pure: false means the pipe runs on every change detection cycle, which can impact performance if not managed carefully. If your transformation logic is stable, pure: true is preferred.

Q: What's the difference between `for...in` and `for...of` when iterating object keys?

ANS: for...in iterates over enumerable property names of an object, including inherited ones. Object.keys() returns an array of an object’s own enumerable property names. When iterating through Object.keys(), use for...of to get the keys themselves. Using for...in on the result of Object.keys() can lead to unexpected behavior, as shown in Solution 18 .
