“Angular Structural Directives Limit: How to Use NgIf and NgFor Together”

A frequent topic in Angular development involves attempts to combine the functionality of structural directives, specifically *ngIf and *ngFor, on a single host element. This scenario often arises when needing to iterate over a list while conditionally displaying each iterated item.

The Core Limitation: One Structural Directive Per Element

A fundamental constraint in Angular since version 2 is the prohibition of applying more than one structural directive (those prefixed with an asterisk, like *ngIf, *ngFor, *ngSwitch) to the same element.

Why this restriction? The Angular team established this rule for simplicity and to prevent ambiguity regarding precedence and side effects when two directives claim control over the host element and its descendants. As stated by the framework maintainers, having both directives on one element leads to complex questions: Which takes precedence? Can one cancel the other? Prohibiting this avoids difficult generalization for future structural directives.

For reference regarding this design choice, one can review the initial discussion thread here .

How can developers achieve the desired combined effect across various Angular releases? Several workarounds exist, primarily relying on element wrapping or leveraging newer control flow features.

Workaround Strategies Across Angular Versions

1. Utilizing <ng-container> for Separation (Pre-Angular v17)

The <ng-container> element is specifically designed to group content without introducing extra nodes into the Document Object Model (DOM). It serves as an excellent container when you need to separate the directives.

The approach: Place *ngIf on the <ng-container> and *ngFor on the inner element, or vice versa.

Example (Older Syntax):

<ng-container *ngIf="show">
  <div *ngFor="let thing of stuff; trackBy: trackById">
    {{ log(thing) }}
    <span>{{ thing.name }}</span>
  </div>
</ng-container>

Note: In older versions, if you needed both on elements that could not be wrapped (like <tr> in a <tbody>), the <template> tag was often used similarly to <ng-container>.

2. Modern Control Flow in Angular v17+

With the introduction of built-in control flow syntax in Angular v17, the need for structural directives like *ngIf and *ngFor is often replaced by cleaner, block-based syntax, which inherently solves this combination issue.

Example (Angular v17+ Syntax):

@if(show) {
  @for(thing of stuff; track thing.id) {
    <div>
      {{ log(thing) }}
      <span>{{ thing.name }}</span>
    </div>
  }
}

This syntax handles the conditional rendering and iteration within the same structural block without violating the single structural directive rule because these are now built-in language constructs, not custom directives applied via attributes.

3. Conditional Array Modification (Pre-v17/Alternative)

Instead of using *ngIf directly on the element being iterated, you can manipulate the data source based on the condition, effectively achieving the same result.

Method A: Ternary Operator within *ngFor:

If the condition (show) controls whether the list should appear at all, you can tell *ngFor to iterate over an empty array when the condition is false.

<div *ngFor="let thing of show ? stuff : []">
  {{ log(thing) }}
  <span>{{ thing.name }}</span>
</div>

Method B: Checking Array Length:

If the goal is just to prevent the outer container from rendering when the list is empty, check the array length explicitly.

<div *ngIf="stuff.length > 0">
  <div *ngFor="let thing of stuff">
    {{ log(thing) }}
    <span>{{ thing.name }}</span>
  </div>
</div>

4. Using a Custom Pipe to Filter Data

For scenarios where you want to control visibility based on a condition applied to the iteration itself, a custom pipe can filter the array before *ngFor processes it.

Custom Pipe Implementation (show.pipe.ts):

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'showFilter' // Renamed for clarity
})
export class ShowPipe implements PipeTransform {    
  transform<T>(values: T[] | null, shouldShow: boolean): T[] {
    if (!shouldShow || !values) {
      return [];
    }
    return values;
  }
}

Usage in Template:

<table>
  <!-- Only iterate if ngIfCondition is true -->
  <tr *ngFor="let arr of anyArray | showFilter : ngIfCondition">
    <td>{{ arr.label }}</td>
  </tr>
</table>

5. Applying Attributes Conditionally (Instead of Hiding)

If the requirement is merely to hide elements while iterating, applying CSS classes or styles conditionally bypasses the structural directive conflict. This keeps the elements in the DOM structure but visually hidden.

Example using [class.hidden]:

.hidden-element {
    display: none;
}

<div 
  [class.hidden-element]="!show" 
  *ngFor="let thing of stuff">
    {{ log(thing) }}
    <span>{{ thing.name }}</span>
</div>

This approach ensures *ngFor runs, and the show boolean controls the CSS class applied to each iterated item.

6. Using <ng-template> for Composite Directives (Advanced/Legacy)

The <ng-template> element, often used interchangeably with <ng-container> in older contexts (or when dealing with specific DOM restrictions like inside <tr>), allows nesting structural directives effectively by applying one directive to the <ng-template> and the other to its direct descendant.

Example nesting <ng-template> with *ngFor and [ngIf]:

<tr *ngFor="let fruit of fruitArray">
    <ng-template [ngIf]="fruit == 'apple'">
        <td> I love apples!</td>
    </ng-template>
</tr>

This pattern ensures that *ngFor controls the creation of the <tr> elements, and then [ngIf] (the attribute form of *ngIf) selectively renders the <td> inside that row based on the loop variable.

FAQs on Angular Structural Directives Limit

Q: Can I use ngIf and ngFor on the same tag in Angular 2+

ANS: No, Angular does not permit applying multiple structural directives like *ngIf and *ngFor to the identical host element.

Q: What replaced the usage of template tag for structural directives

ANS: The <ng-container> tag is the recommended replacement for the <template> tag in modern Angular versions for grouping content without adding extra DOM nodes.

Q: How do I handle conditional iteration in Angular 17

ANS: Angular v17 introduced built-in control flow syntax (@if, @for) which seamlessly handles conditional iteration without applying separate structural directives to one element.

Q: Is there a way to hide elements during ngFor without ngIf

ANS: Yes, you can apply styling or CSS classes conditionally using property binding like [class.hidden]="!show" to hide elements rendered by *ngFor, keeping them present in the DOM but invisible.

This exploration shows multiple robust pathways to manage conditional rendering within loops, catering to different Angular versions and specific template context requirements. Which approach yields the best result often depends on the specific version of Angular in use and the structural constraints of the surrounding HTML, such as within tables.
