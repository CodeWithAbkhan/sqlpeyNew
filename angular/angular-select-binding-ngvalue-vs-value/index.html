“Angular Select Binding: Using [ngValue] vs [value] with ngModel”

When working with Angular forms, accurately binding selected values from an HTML <select> element to a component property—especially when dealing with complex data structures like objects—requires specific directives. How can we ensure the selected option correctly reflects the entire object or a specific property, and what techniques exist for managing object equality in dropdown selections?

This exploration covers several reliable methods for achieving correct data synchronization in Angular selection components, focusing on [(ngModel)], property binding, and custom comparison functions.

Leveraging [ngValue] for Complete Object Binding

The preferred modern approach for binding an entire object to a selection model is utilizing the [ngValue] directive instead of the standard [value].

Why [ngValue]?

  • [value]="..." exclusively supports string representation of the bound data.
  • [ngValue]="..." permits binding any JavaScript type, including complete objects, ensuring selectedValue holds the full object structure from the countries array.

If your component has an array of country objects (countries) and you want selectedValue to hold the selected object:

<h1>My Application</h1>
<select [(ngModel)]="selectedValue">
  <option *ngFor="let c of countries" [ngValue]="c">
    {{c.name}}
  </option>
</select>

For dynamic examples, consult the StackBlitz example demonstrating object binding .

Handling Object Preselection with [ngValue]

When setting an initial selection or updating the bound property (selectedValue), the preselected instance must be identical to one of the options present in the dropdown list for Angular to recognize it as selected.

When object identity matching becomes an issue (e.g., if objects are instantiated separately but represent the same underlying entity), Angular versions 4.0.0-beta.7 and later support a custom comparison function via the [compareWith] input:

<select [(ngModel)]="selectedValue" [compareWith]="compareFn">
  <!-- options using [ngValue] -->
</select>

In your component TypeScript file, you define the comparison logic. This is frequently used to compare unique identifiers rather than object references:

// Component class methods

// Binding the function reference, ensuring 'this' context is maintained
compareFn = this._compareFn.bind(this); 
// OR using arrow function syntax:
// compareFn = (a, b) => this._compareFn(a, b);

_compareFn(a: any, b: any): boolean {
   // Custom comparison logic, often checking unique IDs
   return a?.id === b?.id;
}

Alternative: Binding Only the Identifier ([value])

If you only need the ID or a primitive value from the object to be stored in the model, you can revert to using the standard [value].

This is simpler as it avoids the object identity or custom comparison challenges, but requires you to look up the corresponding object in your component logic if needed later.

<select [(ngModel)]="selectedValueId">
  <option *ngFor="let c of countries" [value]="c.id">
    {{c.name}}
  </option>
</select>

In this setup, selectedValueId will hold the string representation of c.id.

Serialization Method: Storing JSON Strings

A less conventional but workable technique to persist object structure without [ngValue] or custom comparisons is serializing the object to a JSON string and binding that string to the [value].

  1. Serialization in Template: Define a stringifier in the component: 
    toStr = JSON.stringify;
    Use it in the template: 
    <option *ngFor="let v of values;" [value]="toStr(v)">
      {{v}}
</option>
  2. Deserialization on Change: When the value changes, you retrieve the raw string from the event and parse it back into an object: 
    // Accessing the raw event target value
let value = JSON.parse((event.target as HTMLSelectElement).value);

Integrating with ngModelChange and IDs

Sometimes, when binding to an ID ([(ngModel)]="model.myListOptions.id"), external events like form submission or external updates might not correctly map the full object back, requiring manual handling of the selection event.

You can pair two-way binding with the (ngModelChange) event to intercept the selected ID and manually fetch the corresponding object:

<select (ngModelChange)="selectChange($event)" [(ngModel)]="model.myListOptions.id">
    <option *ngFor="let oneOption of listOptions" [ngValue]="oneOption.id">
        {{oneOption.name}}
    </option>
</select>

In the component:

// Example list setup
listOptions = [
    { id: 0, name: "Perfect" },
    { id: 1, name: "Low" },
    // ...
];
model = { myListOptions: { id: 1, name: "Low" } }; // Assume initial state

selectChange($event: any) {
    // $event here is the ID emitted by ngModelChange due to binding to .id
    const selectedId = $event;
    this.model.myListOptions = this.listOptions.find(opt => opt.id === selectedId);
}

Utilizing Custom Comparison with [compareWith] for Object Sync

For robust object synchronization when using [ngValue], the [compareWith] function is essential. This mirrors the functionality often required in components like <mat-select> (Solution 15).

For example, if you bind the full object:

<select [(ngModel)]="model.myListOptions" [compareWith]="compareByOptionId">
    <option *ngFor="let oneOption of listOptions" [ngValue]="oneOption">
        {{oneOption.name}}
    </option>
</select>

The TypeScript comparison function ensures equality based on a key property:

compareByOptionId(idFirst: any, idSecond: any): boolean {
    // Checks existence and compares based on the 'id' property
    return idFirst && idSecond && idFirst.id === idSecond.id;
}

Reactive Forms Alternative

For applications using Reactive Forms, the pattern is cleaner. You bind the control directly using formControlName, and [ngValue] works as expected to store the object reference:

<form [formGroup]="form">
  <select formControlName="country">
    <option *ngFor="let country of countries" [ngValue]="country">
        {{country.name}}
    </option>
  </select>
  <p>Selected Country: {{ country?.value?.name }}</p> <!-- Accessing value via control state -->
</form>

You must ensure ReactiveFormsModule is correctly imported into your application module for this to function.

Final Prerequisite Check

If none of the binding methods yield the expected results, verify that the necessary module is present. For template-driven forms utilizing [(ngModel)], the FormsModule must be imported into the relevant feature module or the root AppModule.

FAQs on Angular Select Binding Using ngModel

Q: What is the main difference between [value] and [ngValue] on an option tag

ANS: The [value] directive only supports binding primitive string values. In contrast, [ngValue] supports binding any data type, including complete JavaScript objects, directly to the model bound via [(ngModel)].

Q: How do I set a default selection when binding objects with ngModel

ANS: When using [ngValue], the object assigned to the model variable (e.g., selectedValue) must be referentially equal or satisfy the criteria defined in the [compareWith] function to the object in the options list.

Q: Can I use a custom function to compare objects selected in a dropdown

ANS: Yes, Angular supports the [compareWith]="customFunction" input on the <select> tag, allowing you to specify logic (like comparing unique IDs) for object equality checks when using [ngValue].

Q: Is it necessary to import FormsModule for ngModel to work

ANS: Yes, for template-driven forms that use [(ngModel)], you must import the FormsModule into your application’s appropriate module (usually AppModule).
