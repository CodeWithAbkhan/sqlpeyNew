“Angular Dynamic Component Creation: A Deep Dive”

When building dynamic applications in Angular, the ability to create and render components on the fly based on runtime conditions or data is a powerful technique. This often involves compiling templates or component definitions dynamically, which requires careful consideration of Angular’s module system and compilation processes. Several approaches exist, each with its own advantages and nuances, particularly when dealing with different Angular versions.

Solution 1: Leveraging JitCompiler and NgModule (Angular RC5+)

This approach, described in detail in a 2016 post, outlines a robust method for dynamic component generation using Angular’s Just-In-Time (JIT) compiler and the NgModule system. The core idea is to dynamically create a component type, wrap it in an NgModule, compile this module, and then use the resulting ComponentFactory to instantiate the component.

Key Steps:

  1. Template Preparation: A template builder creates the HTML structure for the dynamic component.
  2. Component Type Creation: A new component class is defined with a decorator specifying the dynamic template. This component should ideally implement an interface for structured data handling.
  3. Module Creation: The dynamically created component is declared within a new NgModule. This module also imports necessary shared modules (like PartsModule for common directives).
  4. Compilation: The JitCompiler is used to compile the dynamically created NgModule and all its components asynchronously.
  5. Component Factory Retrieval: The ComponentFactory for the specific dynamic component is extracted from the compilation results.
  6. Instance Creation: The ComponentFactory is used to create an instance of the dynamic component, typically hosted within a ViewContainerRef in a parent component.
  7. Input Binding: @Input() properties can be set on the newly created component instance.

Code Snippet Example:

// In your Type Builder service
import { JitCompiler } from '@angular/compiler';
import { ComponentFactory } from '@angular/core';

// Assuming IHaveDynamicData is an interface for your dynamic component's data
// Assuming _cacheOfFactories is a private property for caching

public createComponentFactory(template: string): Promise<ComponentFactory<IHaveDynamicData>> {
    if (this._cacheOfFactories[template]) {
        return Promise.resolve(this._cacheOfFactories[template]);
    }

    const type = this.createNewComponent(template);
    const module = this.createComponentModule(type);

    return new Promise((resolve) => {
        this.compiler.compileModuleAndAllComponentsAsync(module)
            .then((moduleWithFactories) => {
                const factory = moduleWithFactories.componentFactories.find(
                    (compFactory) => compFactory.componentType === type
                );
                this._cacheOfFactories[template] = factory;
                resolve(factory);
            });
    });
}

// Method to create a new component dynamically
protected createNewComponent(tmpl: string): any {
    @Component({
        selector: 'dynamic-component',
        template: tmpl,
    })
    class CustomDynamicComponent implements IHaveDynamicData {
        @Input() public entity: any;
    }
    return CustomDynamicComponent;
}

// Method to create a module for the dynamic component
protected createComponentModule(componentType: any): any {
    @NgModule({
        imports: [PartsModule], // Your shared module
        declarations: [componentType],
    })
    class RuntimeComponentModule {}
    return RuntimeComponentModule;
}

Hosting Component Snippet:

// In your hosting component
import { ComponentRef, ViewContainerRef, ViewChild } from '@angular/core';
import { ComponentFactory } from '@angular/core';
// ... other imports

@ViewChild('dynamicContentPlaceHolder', { read: ViewContainerRef })
protected dynamicComponentTarget: ViewContainerRef;
protected componentRef: ComponentRef<IHaveDynamicData>;
protected entity = { code: 'ABC123', description: 'Sample Entity' };

protected refreshContent(useTextarea: boolean = false): void {
    if (this.componentRef) {
        this.componentRef.destroy();
    }

    const template = this.templateBuilder.prepareTemplate(this.entity, useTextarea);

    this.typeBuilder.createComponentFactory(template)
        .then((factory: ComponentFactory<IHaveDynamicData>) => {
            this.componentRef = this.dynamicComponentTarget.createComponent(factory);
            this.componentRef.instance.entity = this.entity;
        });
}

Considerations:

  • Caching: Caching compiled factories is crucial to prevent memory leaks and performance issues, especially when the same templates are reused.
  • Module Structure: Organizing shared directives and components into a PartsModule and then importing it into the dynamically generated modules is a good practice.
  • Lifecycle Management: Ensure dynamic components are properly destroyed in ngOnDestroy to prevent memory leaks.

Solution 2: Synchronous Compilation with Compiler (Angular 4+)

For simpler scenarios or when asynchronous compilation is not strictly necessary, Angular’s Compiler service (or JitCompilerFactory) can be used for synchronous compilation.

Code Snippet Example:

import { Compiler, Component, NgModule, OnInit, ViewChild, ViewContainerRef } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';

@Component({
  selector: 'my-app',
  template: `<h1>Dynamic template:</h1> <div #container></div>`
})
export class App implements OnInit {
  @ViewChild('container', { read: ViewContainerRef }) container: ViewContainerRef;

  constructor(private compiler: Compiler) {}

  ngOnInit() {
    this.addComponent(
      `<h4>Click to increase: {{ counter }}</h4>`,
      {
        counter: 1,
        increaseCounter: function () { this.counter++; }
      }
    );
  }

  private addComponent(template: string, properties?: any): void {
    // Define component and module dynamically
    @Component({ template })
    class TemplateComponent {}

    @NgModule({ declarations: [TemplateComponent] })
    class TemplateModule {}

    // Compile synchronously
    const module = this.compiler.compileModuleAndAllComponentsSync(TemplateModule);
    const factory = module.componentFactories.find(comp => comp.componentType === TemplateComponent);

    // Create and attach component
    const component = this.container.createComponent(factory);
    Object.assign(component.instance, properties);
    // If properties change later, manual change detection might be needed:
    // component.changeDetectorRef.detectChanges();
  }
}

Solution 3: Using ngComponentOutlet (Angular 4+)

Angular 4 introduced ngComponentOutlet, which provides a more declarative way to render dynamic components. This approach is often cleaner and requires less direct compilation management.

Code Snippet Example:

import { Component, OnInit, Input, NgModule, NgModuleFactory, Compiler } from '@angular/core';

@Component({
  selector: 'my-component',
  template: `<ng-container *ngComponentOutlet="dynamicComponent; ngModuleFactory: dynamicModule;"></ng-container>`,
})
export class MyComponent implements OnInit {
  dynamicComponent: any;
  dynamicModule: NgModuleFactory<any>;

  @Input() text: string = '';

  constructor(private compiler: Compiler) { }

  ngOnInit() {
    this.dynamicComponent = this.createNewComponent(this.text);
    this.dynamicModule = this.compiler.compileModuleSync(this.createComponentModule(this.dynamicComponent));
  }

  private createComponentModule(componentType: any): any {
    @NgModule({
      imports: [],
      declarations: [componentType],
      entryComponents: [componentType]
    })
    class RuntimeComponentModule {}
    return RuntimeComponentModule;
  }

  private createNewComponent(text: string): any {
    const template = `Dynamically created text: ${text}`;

    @Component({
      selector: 'dynamic-component',
      template: template
    })
    class DynamicComponent implements OnInit {
       ngOnInit() { /* ... */ }
    }
    return DynamicComponent;
  }
}

Note: This method might not directly support passing inputs and outputs as easily as other methods, though it’s a good option for simple dynamic rendering.

Solution 4: Utilizing @angular/cdk/portal (Angular 6+ and later)

The Angular Component Dev Kit (CDK) provides a powerful portal module that abstracts away much of the complexity of dynamically attaching components. This is often the recommended approach for more advanced dynamic component scenarios.

Steps:

  1. AppModule Configuration: Import PortalModule and register your dynamic components in entryComponents.
  2. Portal Creation: Use ComponentPortal to define which component to render.
  3. Host Element: Use cdkPortalOutlet directive on a host element (e.g., ng-template or div) to specify where the portal content should be rendered.
  4. Data and Event Handling: For passing data and handling events, you can attach the portal and then interact with the returned ComponentRef.

Code Snippet Example (with data passing):

// App.module.ts
@NgModule({
  imports: [ ..., PortalModule, ... ],
  declarations: [ ..., MyDynamicComponent, ... ],
  entryComponents: [ ..., MyDynamicComponent, ... ]
})
export class AppModule { }

// App.component.ts
import { Component, ViewChild, ElementRef, Injector } from '@angular/core';
import { ComponentPortal, DomPortalHost } from '@angular/cdk/portal';

@Component({
  selector: 'my-app',
  template: `
    <button (click)="onClickAddChild()">Add Child</button>
    <div #portalHost></div>
  `
})
export class AppComponent {
  portalHost: DomPortalHost;
  @ViewChild('portalHost') elRef: ElementRef;

  constructor(readonly injector: Injector) {}

  ngOnInit() {
    this.portalHost = new DomPortalHost(
      this.elRef.nativeElement,
      this.injector.get(ComponentFactoryResolver),
      this.injector.get(ApplicationRef),
      this.injector
    );
  }

  onClickAddChild() {
    const myPortal = new ComponentPortal(MyDynamicComponent);
    const componentRef = this.portalHost.attach(myPortal);
    // Pass data to the dynamic component instance
    componentRef.instance.myInput = 'Data from parent!';
  }
}

// MyDynamicComponent.ts
@Component({
  selector: 'app-child',
  template: `<p>Dynamic content: {{ myInput }}</p>`
})
export class MyDynamicComponent {
  @Input() myInput = '';
}

Solution 5: Using angular-elements (Angular 7+)

Angular Elements allows you to package Angular components as custom HTML elements (Web Components). This is a robust way to create reusable, framework-agnostic components that can be dynamically integrated.

Steps:

  1. Install: npm install @angular/elements -s
  2. Create Service: A service to register and create custom elements.
  3. Register: Call the registration method in your main AppComponent.
  4. Create/Use: Instantiate custom elements programmatically or use them directly in HTML.

Code Snippet Example:

// dynamic-components.service.ts
import { Injectable, Injector } from '@angular/core';
import { createCustomElement } from '@angular/elements';
import { AppUserIconComponent } from 'src/app/shared'; // Example component

const COMPONENTS = {
  'user-icon': AppUserIconComponent
};

@Injectable({ providedIn: 'root' })
export class DynamicComponentsService {
  constructor(private injector: Injector) {}

  public register(): void {
    Object.entries(COMPONENTS).forEach(([key, component]: [string, any]) => {
      const CustomElement = createCustomElement(component, { injector: this.injector });
      customElements.define(key, CustomElement);
    });
  }

  public create(tagName: string, data: any = {}): HTMLElement {
    const customEl = document.createElement(tagName);
    Object.entries(data).forEach(([key, value]: [string, any]) => {
      customEl[key] = value;
    });
    return customEl;
  }
}

// app.component.ts
@Component({ selector: 'app-root', template: '<router-outlet></router-outlet>' })
export class AppComponent {
  constructor(dynamicComponents: DynamicComponentsService) {
    dynamicComponents.register();
  }
}

Solution 6: Dynamic HTML Parsing with Libraries (e.g., ngx-dynamic-hooks)

For scenarios where you need to parse dynamic HTML strings that may contain component tags, libraries like ngx-dynamic-hooks offer a solution without relying on a runtime compiler. This approach is generally safer and compatible with Ahead-of-Time (AOT) compilation.

Code Snippet Example:

<!-- target.component.html -->
<ngx-dynamic-hooks [content]="content" [parsers]="parsers"></ngx-dynamic-hooks>

// target.component.ts
import { Component } from '@angular/core';
import { ExampleComponent } from './example.component'; // Your dynamic component

@Component({
  selector: 'app-target',
  templateUrl: './target.component.html',
})
export class TargetComponent {
  content = 'Load a component here: <app-example></app-example>';
  parsers = [ExampleComponent];
}

This library supports inputs, outputs, nested components, and live data binding.

Other Approaches and Considerations:

  • Directives for Dynamic Component Loading: A custom directive can be created to resolve component factories and create components within its host view, offering a cleaner abstraction.
  • Framework Limitations: Some discussions mention that directly using a template string in @Component({ template: myVariable }) is not supported by Angular, and alternatives like runtime compilation or libraries are necessary.
  • JIT Compiler Factory: When dealing with certain Angular versions or CLI configurations, you might need to explicitly use JitCompilerFactory instead of injecting Compiler.

FAQs on Angular Dynamic Component Creation

Q: How can I pass data to a dynamically created component

ANS: You can pass data by setting the @Input() properties on the dynamically created component instance after it has been instantiated using its ComponentFactory or when using ngComponentOutlet with appropriate bindings. For Angular Elements, data is typically passed as attributes or properties on the custom element.

Q: What is the difference between JitCompiler and Compiler

ANS: JitCompiler is used for Just-In-Time compilation, allowing code to be compiled at runtime. Compiler is a more general interface, and often JitCompiler is used internally or as a specific implementation. For dynamic compilation scenarios, you’ll frequently interact with these. Note that direct JIT compilation might not be suitable for production builds where Ahead-of-Time (AOT) compilation is preferred.

Q: Can I create components from raw HTML strings

ANS: Yes, you can create components from raw HTML strings by using the runtime compilation approach with JitCompiler or by employing libraries like ngx-dynamic-hooks that are designed for parsing HTML and rendering components.

Q: Is it possible to nest dynamic components

ANS: Yes, nesting dynamic components is possible. You may need to ensure that the dynamically generated NgModule includes references to the modules that contain other dynamic components if they are part of a shared module. For instance, adding DynamicModule.forRoot() to the imports of the runtime module can help enable this.

Q: What are the implications of using runtime compilation for performance

ANS: Runtime compilation can have performance implications as it adds overhead during application startup or when components are first created. It’s crucial to cache compiled ComponentFactory instances to mitigate these effects. For production, AOT compilation is generally more performant.
