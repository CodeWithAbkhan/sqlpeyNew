“Android Intents: Launching Google Maps for Directions and Navigation”

How can an Android application reliably invoke the Google Maps application to display specific locations, calculate routes between a source and destination, or start turn-by-turn navigation using different URI schemes and Intent configurations? Developers have several approaches, ranging from simple HTTP links to specialized navigation Intents.

Initiating Standard Map Views and Directions

The fundamental mechanism involves creating an Intent with Intent.ACTION_VIEW and providing a properly formatted Uri.

1. Basic HTTP URL Intent for Directions (Source and Destination)

A common technique uses the standard Google Maps web URL format to request directions between two coordinates, allowing the system to decide whether to open the browser or the dedicated app. If the current location should be the origin, the saddr parameter is omitted.

Java Example (Coordinates with Labels):

This method allows for labeling both the start and end points.

String sourceLat = "20.344";
String sourceLon = "34.34";
String destLat = "20.5666";
String destLon = "45.345";
String sourceLabel = "Origin Point";
String destLabel = "Final Destination";

String uriString = String.format(Locale.ENGLISH,
    "http://maps.google.com/maps?saddr=%1$s,%2$s(%3$s)&amp;daddr=%4$s,%5$s(%6$s)",
    sourceLat, sourceLon, sourceLabel, destLat, destLon, destLabel);

Intent intent = new Intent(android.content.Intent.ACTION_VIEW, Uri.parse(uriString));
startActivity(intent);

If you only provide a destination address as a string, the user might see a prompt to choose between a browser or the Maps app:

String destinationAddress = "an+address+city"; // URL encoded address
Intent intent = new Intent(android.content.Intent.ACTION_VIEW, 
    Uri.parse("http://maps.google.com/maps?daddr=" + destinationAddress));
startActivity(intent);

2. Forcing the Google Maps Application Package

To prioritize opening the native application and gracefully handle cases where it might be missing, you can explicitly set the package name. For robustness, exception handling for ActivityNotFoundException is recommended, falling back to a standard browser intent if the specific app is absent.

Java Example (Forcing Maps App with Fallback):

This solution attempts to open the route within the Google Maps application, providing labels for source and destination.

double sourceLat = 40.7128;
double sourceLon = -74.0060;
double destLat = 34.0522;
double destLon = -118.2437;
String sourceName = "The Starting Spot";
String destName = "LA Central";

String uri = String.format(Locale.ENGLISH,
    "http://maps.google.com/maps?saddr=%f,%f(%s)&amp;daddr=%f,%f (%s)",
    sourceLat, sourceLon, sourceName, destLat, destLon, destName);

Intent intent = new Intent(Intent.ACTION_VIEW, Uri.parse(uri));
intent.setPackage("com.google.android.apps.maps"); // Target the Google Maps package

try {
    startActivity(intent);
} catch(ActivityNotFoundException ex) {
    // Fallback: Open in default web browser if Maps app isn't installed/accessible
    Intent unrestrictedIntent = new Intent(Intent.ACTION_VIEW, Uri.parse(uri));
    startActivity(unrestrictedIntent);
}

3. Using the google.navigation: Scheme for Direct Navigation

For a direct prompt to start navigation from the user’s current location, use the google.navigation: scheme.

Java Example (Navigation to Coordinates):

double targetLat = 12.00f;
double targetLon = 2.00f;

Uri navigationIntentUri = Uri.parse("google.navigation:q=" + targetLat + "," + targetLon);
Intent mapIntent = new Intent(Intent.ACTION_VIEW, navigationIntentUri);
mapIntent.setPackage("com.google.android.apps.maps");
startActivity(mapIntent);

This scheme also supports specifying transportation modes via query parameters (e.g., &mode=d for driving, &mode=w for walking, &mode=b for bicycling), as seen in other examples:

// Example for Bicycling mode to a destination coordinate
Uri gmmIntentUri = Uri.parse("google.navigation:q=" + destLat + "," + destLon + "&mode=b");
// ... proceed with Intent creation and start

Alternative URI Schemes and Specialized Intents

4. Geo URI Scheme for Centering on Coordinates

The geo: scheme is intended to center the map at specific coordinates.

Issues with geo:lat,lon: It often only centers the map without placing a visible pin or label, which can be confusing when seeking directions.

Adding a Label (Historical/Deprecated Approach): An attempt to add a label historically used geo:0,0?q=lat,lon(Label):

String name = "Specific Landmark";
String lat = "37.423156";
String lon = "-122.084917";

// Note: In recent Maps versions (v7+), this often defaults to a search by name only.
Uri geoUri = Uri.parse("geo:0,0?q=" + lat + "," + lon + " (" + name + ")");
Intent intent = new Intent(Intent.ACTION_VIEW, geoUri);
startActivity(intent);

5. Cross-Platform Universal Links (Recommended Modern Approach)

Since May 2017, Google provides a universal link structure that works across platforms and often defaults to the browser if the app is absent, making it highly reliable for showing routes. This utilizes the https://www.google.com/maps/dir/ path.

Java Example (Using Uri.Builder):

This example requests directions between two arbitrary coordinates using the universal API structure, ensuring compatibility.

double originLat = 81.23444;
double originLon = 67.0000;
double destLat = 80.252059;
double destLon = 13.060604;

Uri.Builder builder = new Uri.Builder();
builder.scheme("https")
    .authority("www.google.com")
    .appendPath("maps")
    .appendPath("dir")
    .appendPath("") // Required path segment for correct URL structure
    .appendQueryParameter("api", "1")
    .appendQueryParameter("origin", originLat + "," + originLon) // Origin specified
    .appendQueryParameter("destination", destLat + "," + destLon);
String url = builder.build().toString();

Intent i = new Intent(Intent.ACTION_VIEW);
i.setData(Uri.parse(url));
startActivity(i);

6. Handling Multiple Waypoints

For multi-stop routing, the standard web URL format supports appending subsequent coordinates separated by /. There is an upper limit to the number of waypoints supported (potentially 23, as per Google documentation).

Java Example (Four Waypoints):

String start = "48.8276261,2.3350114";
String wp1 = "48.8476794,2.340595";
String wp2 = "48.8550395,2.300022";
String end = "48.8417122,2.3028844";

String multiStopUri = String.format("https://www.google.com/maps/dir/%s/%s/%s/%s", start, wp1, wp2, end);

Intent intent = new Intent(android.content.Intent.ACTION_VIEW, Uri.parse(multiStopUri));
startActivity(intent);

Platform and Vendor Considerations (HMS/GMS)

When targeting devices that might rely on Huawei Mobile Services (HMS) instead of Google Mobile Services (GMS), specific package names must be managed to ensure the correct map application opens.

Kotlin Example (Checking for HMS vs. GMS Package):

This approach attempts to use the appropriate package name (com.huawei.maps.app or com.google.android.apps.maps) before falling back to an unspecific intent.

const val GOOGLE_MAPS_APP = "com.google.android.apps.maps"
const val HUAWEI_MAPS_APP = "com.huawei.maps.app"

fun openMapSpecific(context: Context, lat: Double, lon: Double) {
    // Logic to determine if HMS-only environment exists (isHmsOnly function implementation omitted for brevity)
    val packageName = if (isHmsOnly(context)) HUAWEI_MAPS_APP else GOOGLE_MAPS_APP

    val uri = Uri.parse("geo:$lat,$lon?q=$lat,$lon")
    val intent = Intent(Intent.ACTION_VIEW, uri)
    intent.setPackage(packageName)
    
    if (intent.resolveActivity(context.packageManager) != null) {
        context.startActivity(intent)
    } else {
        // Fallback to default viewer if specific package fails
        context.startActivity(Intent(Intent.ACTION_VIEW, uri))
    }
}

Displaying Locations Using Address Strings

If you only possess a street address string instead of coordinates, you can encode the address and use a standard geo or web URI.

Java Example (Encoding Address String):

It is critical to use Uri.encode() when constructing URIs from user input or address strings to prevent parsing errors.

String addressString = "1600 Amphitheatre Parkway, CA";

// Building a geo URI using Uri.Builder for robust handling
Uri.Builder builder = new Uri.Builder();
builder.scheme("geo")
        .path("0,0") // Center on map, no specific point priority
        .query(addressString); // The query parameter becomes the search term/location
Uri addressUri = builder.build();

Intent intent = new Intent(Intent.ACTION_VIEW, addressUri);

if (intent.resolveActivity(getPackageManager()) != null) {
    startActivity(intent);
}

FAQs on Android Intents Google Maps Directions

Q: How do I open Google Maps to show directions using only string addresses

ANS: Use the http://maps.google.com/maps?saddr=SourceAddress&daddr=DestinationAddress format within an Intent.ACTION_VIEW intent. Ensure addresses are URL-encoded if they contain spaces or special characters.

Q: What is the best way to ensure the intent opens the native Maps app

ANS: Set the package explicitly using intent.setPackage("com.google.android.apps.maps"). Always wrap this call in a try-catch block to handle ActivityNotFoundException and provide a fallback to a general web browser intent.

Q: Can I specify the mode of transport like driving or walking

ANS: Yes, when using the google.navigation: URI scheme, you can append query parameters like &mode=d for driving, &mode=w for walking, or &mode=b for bicycling.

Q: What if I need to plot several stops between start and end

ANS: Use the cross-platform web URL format and list all waypoints sequentially after the destination by concatenating /latitude,longitude segments in the path, such as in https://www.google.com/maps/dir/Start/WP1/WP2/End.
Intent intent = new Intent(android.content.Intent.ACTION_VIEW, 
    Uri.parse("http://maps.google.com/maps?saddr=20.344,34.34&amp;daddr=20.5666,45.345"));
startActivity(intent);
Intent intent = new Intent(android.content.Intent.ACTION_VIEW,
    Uri.parse("google.navigation:q=an+address+city"));
