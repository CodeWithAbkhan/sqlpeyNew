“Prevent Selenium Detection: Hide ’navigator.webdriver’ Property”

Websites often employ methods to detect automated browser instances, particularly those driven by Selenium. A common detection vector is the navigator.webdriver property, which typically returns true for automated browsers. This question explores various techniques to mask or alter this property, along with other indicators of automation, to enhance the stealth of your Selenium scripts.

The core issue stems from how browsers expose automation status. Historically, navigator.webdriver was a straightforward indicator. However, as automation detection became more sophisticated, new methods emerged to obscure this and other signals.

Solutions to Hide navigator.webdriver

Here are several proven approaches to make your Selenium-controlled browser less detectable:

Solution 1: Utilize execute_cdp_cmd for Fine-Grained Control

The execute_cdp_cmd() function, available in newer Selenium versions, allows direct interaction with the Chrome DevTools Protocol (CDP). This offers powerful capabilities, including overriding the user agent and directly manipulating browser JavaScript properties.

Python Example:

from selenium import webdriver

# Initialize Chrome options
options = webdriver.ChromeOptions()

# Add argument to disable blink features related to automation
options.add_argument('--disable-blink-features=AutomationControlled')

# Initialize the WebDriver
# Ensure you have the correct path to your chromedriver executable
driver = webdriver.Chrome(options=options, executable_path=r'C:\WebDrivers\chromedriver.exe')

# Get the website
driver.get("https://www.example.com")

# Override the user agent using CDP
driver.execute_cdp_cmd('Network.setUserAgentOverride', {"userAgent": 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/91.0.4472.124 Safari/537.36'})

# Modify the navigator.webdriver property via JavaScript execution
driver.execute_script("Object.defineProperty(navigator, 'webdriver', {get: () => undefined})")

# Exclude the 'enable-automation' switch
options.add_experimental_option("excludeSwitches", ["enable-automation"])

# Disable the automation extension
options.add_experimental_option('useAutomationExtension', False)

# Print the current user agent to verify
print(driver.execute_script("return navigator.userAgent;"))

# Navigate to a page that displays headers to check user agent
driver.get('https://www.httpbin.org/headers')

Explanation:

  • --disable-blink-features=AutomationControlled: This argument targets a specific Chrome feature that can be used for detection.
  • Network.setUserAgentOverride: This CDP command allows you to set a custom user agent string, making your browser appear as a standard Chrome instance.
  • Object.defineProperty(navigator, 'webdriver', {get: () => undefined}): This JavaScript snippet directly modifies the navigator.webdriver property to undefined, effectively hiding its automated status.
  • excludeSwitches, useAutomationExtension: These experimental options in ChromeOptions are designed to remove common automation signatures.

Solution 2: The --disable-blink-features=AutomationControlled Flag

This command-line argument for Chrome is a concise way to prevent detection. When applied, it ensures that the navigator.webdriver property does not report true.

Example Usage:

# Command line invocation (conceptual)
# chromedriver --disable-blink-features=AutomationControlled

Solution 3: Direct JavaScript Manipulation of navigator.webdriver

Instead of relying on CDP commands for this specific modification, you can directly inject JavaScript to alter the navigator.webdriver property.

Python Example:

from selenium import webdriver

options = webdriver.ChromeOptions()
options.add_argument("--disable-blink-features=AutomationControlled")

driver = webdriver.Chrome(options=options, executable_path=r'C:\WebDrivers\chromedriver.exe')

# Execute script to redefine the navigator.webdriver property
driver.execute_script("Object.defineProperty(navigator, 'webdriver', {get: () => undefined})")

driver.get("https://www.example.com")

Caution: While direct modification works, some sources suggest that CDP commands might offer more robust or consistent results.

Solution 4: Modifying the enable-automation Switch

For versions of ChromeDriver prior to 79.0.3945.16, excluding the enable-automation switch was a primary method.

Python Example:

from selenium import webdriver

options = webdriver.ChromeOptions()
# Exclude the 'enable-automation' switch
options.add_experimental_option("excludeSwitches", ['enable-automation'])

driver = webdriver.Chrome(options=options, executable_path=r'C:\path\to\chromedriver.exe')
driver.get("https://www.example.com")

# In the browser console, you would see:
# > navigator.webdriver
# undefined

Note: As mentioned, this method may not be effective for newer ChromeDriver and Chrome versions. For alternatives, refer to the release notes.

Solution 6: Page.addScriptToEvaluateOnNewDocument via CDP

This CDP command allows injecting JavaScript that runs before the page’s own scripts execute, providing an early opportunity to modify browser properties.

Python Example:

driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {
  "source": """
    Object.defineProperty(navigator, 'webdriver', {
      get: () => undefined
    })
  """
})
driver.get("https://www.example.com")

Important: Setting the value to undefined is often more effective than false, as false can still be a detectable signal.

Solution 7: Advanced JavaScript Patching with Proxies

For a more sophisticated approach, especially if you need to pass generic regular expression checks that look for {[native code]}, you can use JavaScript Proxies to intercept the getter function. This method aims to leave minimal traces.

Python Example (using CDP):

driver.execute_cdp_cmd('Page.addScriptToEvaluateOnNewDocument', {
    'source': """
    Object.defineProperty(Navigator.prototype, 'webdriver', {
        set: undefined,
        enumerable: true,
        configurable: true,
        get: new Proxy(
            Object.getOwnPropertyDescriptor(Navigator.prototype, 'webdriver').get,
            { apply: (target, thisArg, args) => {
                // emulate getter call validation
                Reflect.apply(target, thisArg, args);
                return false; // Or undefined
            }}
        )
    });
    """
})

This technique involves intercepting the original getter and returning a modified value. It’s a more complex solution but can bypass more stringent detection mechanisms.

Solution 8: Combining CDP and Feature Flags (Java & Python)

This approach merges the use of Page.addScriptToEvaluateOnNewDocument with the --disable-blink-features=AutomationControlled flag for enhanced stealth, particularly for newer Chrome versions.

Solution 15: Headless Mode and User-Agent Modification

When running in headless mode, browsers often append “Headless” to the user agent string. To avoid detection, you can modify the user agent to appear as a standard Chrome browser.

Java Example:

import org.openqa.selenium.JavascriptExecutor;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.chrome.ChromeOptions;

// ... Assume initialDriver is your WebDriver instance

ChromeOptions chromeOptions = new ChromeOptions();
// For older headless versions
chromeOptions.addArguments("--disable-blink-features=AutomationControlled");
chromeOptions.addArguments("--headless");

// For newer headless modes
// chromeOptions.addArguments("--headless=new");

// Get original user agent
String userAgent = (String) ((JavascriptExecutor) initialDriver).executeScript("return navigator.userAgent;");

// Modify user agent if it contains "Headless"
String modifiedUserAgent = userAgent.replace("HeadlessChrome", "Chrome");

// Apply modified user agent or other options as needed
// Note: Direct user agent override might be better done via CDP or options constructor

History and Browser Automation Standards

The navigator.webdriver property is defined by W3C specifications, intended to signal when a user agent is under remote control. The NavigatorAutomationInformation interface, which includes the webdriver attribute, is part of these standards. While the intention is for interoperability, the implementation details and the evolution of detection methods mean that simply checking this flag is not foolproof for websites.

Important Considerations

  • ChromeDriver Version: The effectiveness of certain methods can depend on your ChromeDriver and Chrome browser versions. Always check the release notes for updates.
  • User-Agent: Maintaining a consistent and believable user-agent string is critical.
  • Experimentation: Detection techniques evolve. You may need to experiment with different combinations of the methods described above to find what works best for your specific target websites and browser versions.
  • undetected-chromedriver: For a streamlined experience, consider using this library, which aims to keep up with detection changes.

FAQs on Preventing Selenium Detection

Q: What is the primary indicator websites look for to detect Selenium?

ANS: A common indicator is the navigator.webdriver property, which typically returns true when a browser is controlled by automation tools like Selenium.

Q: Can I change the navigator.webdriver property to false?

ANS: While you can change it to false, it’s often recommended to set it to undefined as false can still be a detectable signal.

Q: Which Chrome argument is most effective for preventing detection?

ANS: The --disable-blink-features=AutomationControlled argument is widely recognized as a highly effective method.

Q: Does the --disable-blink-features=AutomationControlled argument work in headless mode?

ANS: Yes, it generally works in headless mode. However, for newer headless Chrome versions (--headless=new), you might also need to modify the user agent string to remove “HeadlessChrome”.

Q: Is there a Python library that handles Selenium detection automatically?

ANS: Yes, the undetected-chromedriver library is designed to automatically handle many of the common detection methods.
