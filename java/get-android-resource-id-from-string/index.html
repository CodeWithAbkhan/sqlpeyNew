“Get Android Resource ID from String Name: Java & Kotlin Solutions”

While Android’s R class usually provides direct access to these IDs, there are scenarios where you need to fetch them at runtime based on a string identifier. This is particularly useful when resource names are generated dynamically or stored externally.

Several approaches exist, leveraging built-in Android methods or Java reflection. Let’s dive into the most effective ways to achieve this.

Common Methods for Resource ID Retrieval

The core challenge is mapping a string representation of a resource (e.g., "my_icon") to its corresponding integer ID.

1. Using Resources.getIdentifier()

This is the most direct and recommended Android API for this task. It allows you to look up a resource ID by its name, type, and package.

  • How it works: You provide the resource name (e.g., "my_icon"), the resource type (e.g., "drawable", "string", "id"), and the package name of your application.

  • Example (Java):

    public static int getResourceId(Context context, String resourceName, String resourceType) {
    int resourceId = context.getResources().getIdentifier(resourceName, resourceType, context.getPackageName());
    if (resourceId == 0) {
        // Resource not found
        return -1; // Or throw an exception
    }
    return resourceId;
}

// Usage for a drawable:
// int drawableId = getResourceId(this, "my_custom_icon", "drawable");
// imageView.setImageResource(drawableId);

// Usage for a string:
// String appName = context.getString(getResourceId(context, "app_name", "string"));

  • Example (Kotlin):

    fun getResourceId(context: Context, resourceName: String, resourceType: String): Int {
    val resourceId = context.resources.getIdentifier(resourceName, resourceType, context.packageName)
    return if (resourceId == 0) -1 else resourceId
}

// Usage for a drawable:
// val drawableId = getResourceId(this, "my_custom_icon", "drawable")
// imageView.setImageResource(drawableId)

// Usage for a string:
// val appName = context.getString(getResourceId(this, "app_name", "string"))

  • Considerations: The official Android documentation suggests that getIdentifier might be less performant than direct R class access for frequently used resources. However, for dynamic lookups, it’s often the most practical solution. Be mindful of case sensitivity and naming conventions in your resource files. Ensure the resourceType is accurate (e.g., "drawable", "string", "layout", "id").

2. Using Java Reflection (with caveats)

Reflection allows you to inspect and manipulate classes and their members at runtime. You can use it to access the generated R class fields.

  • How it works: You access the static fields within the R.drawable, R.string, or R.id inner classes.

  • Example (Java):

    public static int getResourceReflectively(String resourceName, Class<?> resourceClass) {
    try {
        java.lang.reflect.Field idField = resourceClass.getDeclaredField(resourceName);
        return idField.getInt(idField);
    } catch (NoSuchFieldException | IllegalAccessException e) {
        // Handle error, resource name not found or access issue
        e.printStackTrace();
        return -1;
    }
}

// Usage for a drawable:
// int drawableId = getResourceReflectively("my_icon", R.drawable.class);

// Usage for a view ID:
// int viewId = getResourceReflectively("my_button_id", R.id.class);
// Button myButton = findViewById(viewId);

  • Example (Kotlin):

    inline fun <reified T : Any> getResourceReflectively(resourceName: String): Int {
    return try {
        val idField = T::class.java.getDeclaredField(resourceName)
        idField.getInt(idField)
    } catch (e: Exception) {
        e.printStackTrace()
        -1 // Indicates failure
    }
}

// Usage for a drawable:
// val drawableId = getResourceReflectively<R.drawable>("my_icon")

// Usage for a view ID:
// val viewId = getResourceReflectively<R.id>("my_button_id")
// val myButton: Button = findViewById(viewId)

  • Considerations: This method is generally faster than getIdentifier but comes with a significant drawback: it is prone to breaking with build optimizations like code and resource shrinking (ProGuard/R8). If your resources are minified or renamed, reflection will fail. Use this with caution, especially for release builds. It’s also important to note that resource names in the R class often have underscores (_) instead of dots (.) found in XML resource definitions.

3. Mapping Resource Names to IDs (Predefined Maps)

For a fixed set of known resources, you can create a Map to store the string-to-ID associations.

  • How it works: Initialize a HashMap where keys are resource names (strings) and values are their corresponding resource IDs.

  • Example (Java):

    private static final Map<String, Integer> drawableMap = new HashMap<>();

static {
    drawableMap.put("icon_apple", R.drawable.apple_icon);
    drawableMap.put("icon_banana", R.drawable.banana_icon);
    drawableMap.put("icon_cherry", R.drawable.cherry_icon);
}

public static int getDrawableIdFromString(String iconName) {
    return drawableMap.getOrDefault(iconName, -1); // Returns -1 if not found
}

// Usage:
// int resID = getDrawableIdFromString("icon_apple");
// imageView.setImageResource(resID);

  • Example (Kotlin):

    private val drawableMap = mapOf(
    "icon_apple" to R.drawable.apple_icon,
    "icon_banana" to R.drawable.banana_icon,
    "icon_cherry" to R.drawable.cherry_icon
)

fun getDrawableIdFromString(iconName: String): Int {
    return drawableMap[iconName] ?: -1 // Returns -1 if not found
}

// Usage:
// val resID = getDrawableIdFromString("icon_apple")
// imageView.setImageResource(resID)

  • Considerations: This is the most robust and performant method if you have a controlled, finite list of resources. It avoids the pitfalls of reflection and the potential performance impact of getIdentifier. However, it requires manual maintenance as you add or change resources.

4. Retrieving Resource Name from ID

Sometimes, you might have the resource ID and need to find its string name.

  • How it works: Use getResources().getResourceEntryName(id).

  • Example (Java):

    public static String getResourceNameFromId(Context context, int resourceId) {
    try {
        return context.getResources().getResourceEntryName(resourceId);
    } catch (Resources.NotFoundException e) {
        e.printStackTrace();
        return null;
    }
}

// Usage:
// String drawableName = getResourceNameFromId(this, R.drawable.my_icon);

  • Example (Kotlin):

    fun getResourceNameFromId(context: Context, resourceId: Int): String? {
    return try {
        context.resources.getResourceEntryName(resourceId)
    } catch (e: Resources.NotFoundException) {
        e.printStackTrace()
        null
    }
}

// Usage:
// val drawableName = getResourceNameFromId(this, R.drawable.my_icon)

Specific Use Cases & Examples

Let’s illustrate with more concrete examples.

Dynamically Setting an ImageView’s Source

Imagine you have a list of image filenames stored in a string array and you want to load them into ImageViews.

// Assuming you have an ImageView named 'dynamicImageView'
String imageName = "user_profile_default"; // This name corresponds to a drawable file like user_profile_default.png
int drawableId = getResourceId(this, imageName, "drawable");

if (drawableId != -1) {
    dynamicImageView.setImageResource(drawableId);
} else {
    // Handle case where drawable was not found
    // Maybe set a placeholder image or log an error
}

Accessing String Resources

Retrieving localized strings dynamically is also possible.

String welcomeMessageKey = "welcome_banner_text"; // Corresponds to a string resource like <string name="welcome_banner_text">Hello User!</string>
int stringId = getResourceId(context, welcomeMessageKey, "string");

if (stringId != -1) {
    String welcomeMessage = context.getString(stringId);
    // Use the welcomeMessage string
} else {
    // Handle missing string resource
}

Finding View IDs by Name

This is useful for dynamically inflating layouts or creating complex UIs where element IDs are generated.

// In an Activity or Fragment
String viewIdentifier = "profile_image_view"; // Corresponds to an ID like R.id.profile_image_view
int viewResourceId = getResourceId(this, viewIdentifier, "id");

if (viewResourceId != -1) {
    ImageView profileImageView = findViewById(viewResourceId);
    // Now you can work with profileImageView
} else {
    // Handle case where ID was not found
}

Alternative Approaches & Best Practices

  • Naming Conventions: Always ensure your string resource names precisely match the names in your res/values/strings.xml or the filenames in res/drawable/ (without extensions).
  • Error Handling: Robustly handle cases where a resource might not be found. Returning -1 or null and checking for these values is crucial. Throwing a custom exception can also be beneficial for debugging.
  • Performance: For frequently accessed resources, consider using the Map approach or direct R class access if possible. Reserve getIdentifier for truly dynamic scenarios.
  • Build Shrinking: If using reflection, be aware of ProGuard/R8 rules. You might need to configure rules to prevent shrinking of R class members if you rely heavily on reflection. For example, keep class com.yourpackage.name.R$drawable and keepattributes InnerClasses.
  • XML Layouts: For view IDs, consider using tools:id in your XML layouts if you are just defining IDs for easier reference during design or for certain dynamic loading scenarios, though actual runtime ID retrieval still requires one of the methods above.

FAQs on Get Android Resource ID from String Name

Q What is the primary method to get an Android resource ID from its string name

ANS The primary and recommended method is using Resources.getIdentifier(resourceName, resourceType, packageName).

Q Can I use Java reflection to get resource IDs

ANS Yes, you can use Java reflection to access fields in the R class (e.g., R.drawable.class.getDeclaredField("my_icon")), but be aware that this can be broken by build optimizations like code shrinking.

Q What are the potential issues with using Resources getIdentifier

ANS While convenient, Resources.getIdentifier can be slower than direct access to R class members, especially if called frequently. It’s best suited for dynamic lookups.

Q How does code shrinking affect reflection-based resource ID retrieval

ANS Code and resource shrinking (like ProGuard or R8) can rename or remove classes and fields, causing reflection-based lookups to fail if not properly configured with keep rules.

Q What is the best approach for a fixed set of resources

ANS For a fixed and known set of resources, creating a Map<String, Integer> to store the string-to-ID mappings is the most performant and reliable method.

Q How do I get the string name of a resource from its ID

ANS You can use context.getResources().getResourceEntryName(resourceId) to retrieve the string name of a resource given its integer ID.

Q What are common resource types I can look up

ANS Common resource types include drawable, string, layout, id, color, dimen, array, and more. You pass the type as a string (e.g., “drawable”, “string”).

Q Is there a Kotlin specific way to use reflection for resource IDs

ANS Yes, Kotlin provides inline functions with reified type parameters, making reflection cleaner. For example, T::class.java.getDeclaredField(resourceName) within an inline fun <reified T : Any>.
