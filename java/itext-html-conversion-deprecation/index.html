“Migrating iText HTML to PDF Conversion: HTMLWorker vs. pdfHTML in iText 7”

Why is the established method for generating PDFs from HTML documents in older iText versions no longer effective, and what is the modern, recommended pathway using iText 7 and its specialized add-ons?

The shift away from older iText mechanisms like HTMLWorker and XML Worker toward the modern iText 7 architecture powered by the pdfHTML add-on is a necessary evolution for accurate HTML/CSS rendering.

The Limitations of Legacy iText Conversion Tools

The original HTMLWorker component, introduced in earlier iText versions, was fundamentally limited. It was never designed to process entire HTML documents.

  • Snippet Focus: HTMLWorker was intended only for parsing small HTML fragments, relying on the StyleSheet class for rudimentary styling definitions. Full CSS support was absent.
  • Structural Ignorance: It lacked awareness of standard document structure elements like <head> and <body>, processing all content sequentially without proper context.

Following this, XML Worker emerged as a more generic XML parsing tool. While it served as a proof-of-concept for XHTML to PDF functionality, it introduced significant architectural mismatches:

  • Incomplete Tag Support: Many standard HTML tags, notably forms, were unsupported.
  • CSS Positioning Difficulty: The fundamental differences between how HTML/CSS positions elements and how PDF documents operate made reliable CSS support extremely challenging to implement within that framework.

These limitations led to XML Worker becoming overly complex as developers requested extensions, prompting a complete architectural rewrite. This rewrite culminated in iText 7, built specifically with robust HTML and CSS conversion in mind via the pdfHTML add-on.

Adopting iText 7 and pdfHTML for Modern Conversion

The current best practice involves leveraging iText 7 combined with the pdfHTML add-on (versions 7.1.0+ and 2.0.0+ respectively). This combination drastically simplifies the process and accurately respects CSS directives.

Java Implementation Using HtmlConverter (File Input)

The contemporary approach reduces complex setup to a straightforward static call, as shown below. Note the default font becomes Times-Roman in newer versions, and features like floating images are correctly rendered based on CSS.

import com.itextpdf.html2pdf.HtmlConverter;
import java.io.File;
import java.io.IOException;

public class PdfGeneratorExample {
    
    public static final String SOURCE_FILE = "src/main/resources/html/my_styled_document.html";
    public static final String OUTPUT_FILE = "target/results/modern_output.pdf";

    public void convertHtmlFileToPdf(String sourcePath, String destinationPath) throws IOException {
        // This method handles conversion directly from an input file to an output file.
        HtmlConverter.convertToPdf(new File(sourcePath), new File(destinationPath));
    }
}

Alternative: Converting from an HTML String to a PDF Document

If you are working with an HTML string directly rather than a file, you can use HtmlConverter.convertToDocument. This allows for greater control, such as explicitly setting page dimensions before conversion commences.

import com.itextpdf.kernel.pdf.PdfDocument;
import com.itextpdf.kernel.pdf.PdfWriter;
import com.itextpdf.kernel.geom.PageSize;
import com.itextpdf.html2pdf.HtmlConverter;
import com.itextpdf.layout.Document;
import com.itextpdf.html2pdf.ConverterProperties;
import java.io.FileOutputStream;
import java.io.IOException;

public class StringToPdfConverter {

    public void generatePDFFromString(String htmlContent, String outputFilePath, String baseDirectory) {
        try (FileOutputStream fos = new FileOutputStream(outputFilePath);
             PdfWriter writer = new PdfWriter(fos);
             PdfDocument pdf = new PdfDocument(writer)) {

            ConverterProperties properties = new ConverterProperties();
            // Set base URI if the HTML refers to external resources (like images or linked CSS)
            properties.setBaseUri(baseDirectory); 

            // Configure Page Size explicitly (e.g., A3)
            pdf.setDefaultPageSize(PageSize.A3);
            
            // Convert the HTML string to the Document object
            Document document = HtmlConverter.convertToDocument(htmlContent, pdf, properties);
            
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

Addressing Developer Concerns Regarding Upgrading

Many developers hesitate to transition from older iText versions (like iText 5) to iText 7 due to perceived licensing or maintenance burdens.

Licensing: AGPL vs. Commercial Use

Query: Isn’t iText 7 proprietary, unlike iText 5?

Response: iText 7 adheres to the AGPL license, similar to iText 5 and XML Worker. This means it permits free use in open-source projects. If you are distributing a proprietary or closed-source application (e.g., a SaaS solution), purchasing a commercial license is required, a policy consistent across recent major versions. Crucially, the pdfHTML add-on, which enables superior HTML/CSS handling, is now open-sourced, respecting developer feedback while maintaining licensing compliance for commercial entities.

Legacy System Maintenance

Query: I must support an existing system using an older iText version.

Response: Software maintenance inherently includes necessary upgrades and migrations to newer, better-supported versions. The code required for iText 7 and pdfHTML is significantly cleaner and less prone to errors than its predecessors. Investing time in this migration will yield future-proof, more reliable PDF generation capabilities.

New Projects Started on Older Versions

Query: I started my project before discovering iText 7 and used an outdated version.

Response: Treat this discovery as an opportunity for an immediate refactor. Adopting the modern stack ensures your codebase aligns with current standards, as iText 5 is actively being phased out, with support eventually ceasing entirely, though paying customers receive continued assistance. Starting fresh with iText 7 and pdfHTML requires less effort than patching an obsolete system.

Integrating Dynamic Content (Spring Boot Example)

For environments like Spring Boot that utilize template engines like Thymeleaf, conversion can be integrated directly into request handling to serve downloadable PDFs:

import org.springframework.http.*;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.support.RequestContextUtils;
import org.thymeleaf.TemplateEngine;
import org.thymeleaf.context.Context;
import org.thymeleaf.context.IContext;

// Assume required imports for Order, OrderHelper, ServletContext, etc.

@RestController
public class PdfExportController {

    @Resource // Inject TemplateEngine
    private TemplateEngine templateEngine;
    
    @Resource // Inject ServletContext
    private ServletContext servletContext;

    @GetMapping(path = "/generate/order-report")
    public ResponseEntity<byte[]> getPDFReport(HttpServletRequest request, HttpServletResponse response) throws IOException {
        
        // 1. Business Logic Execution
        Order order = OrderHelper.getOrderDetails(); // Hypothetical retrieval method

        // 2. Dynamic HTML Generation using Thymeleaf
        IContext context = new Context(request.getLocale());
        context.setVariable("orderEntry", order);
        String orderHtmlContent = templateEngine.process("orderTemplateName", context);

        // 3. PDF Conversion Setup
        ByteArrayOutputStream pdfOutput = new ByteArrayOutputStream();
        ConverterProperties props = new ConverterProperties();
        // Set base URI so external resources load correctly in the PDF context
        props.setBaseUri("http://localhost:8080"); 
        
        // Execute Conversion
        HtmlConverter.convertToPdf(orderHtmlContent, pdfOutput, props);

        // 4. Prepare HTTP Response
        byte[] pdfBytes = pdfOutput.toByteArray();

        return ResponseEntity.ok()
                .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=order_document_" + order.getId() + ".pdf")
                .contentType(MediaType.APPLICATION_PDF)
                .body(pdfBytes);
    }
}

FAQs on iText HTML Conversion

Q: What is the main reason HTMLWorker is no longer used

ANS: HTMLWorker was deprecated because it was designed only for small HTML snippets and lacked support for modern CSS and full HTML structure interpretation, unlike the newer pdfHTML add-on.

Q: Which libraries are needed for the modern iText HTML to PDF approach

ANS: You need iText 7 core libraries along with the pdfHTML add-on library.

Q: Can pdfHTML handle external CSS files

ANS: Yes, by setting the ConverterProperties.setBaseUri() method correctly, pdfHTML can reference and apply external CSS linked within the HTML input.
