“Java Stream Distinct by Key: Efficient Filtering Techniques”

When working with Java Streams, a common requirement is to filter out duplicate elements based on a specific property or “key.” While the built-in distinct() operation works on the entire object, there are numerous ways to achieve distinctness based on a particular attribute. This post delves into various strategies, providing practical code examples and considerations for each.

Solution 1: Stateful Predicate with ConcurrentHashMap

This approach leverages a Predicate that maintains state, tracking elements it has encountered. It uses ConcurrentHashMap.newKeySet() for thread-safe tracking.

import java.util.Set;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.concurrent.ConcurrentHashMap;
import java.util.stream.Stream;
import java.util.List;

// Assuming a Person class with a getName() method
// class Person { private String name; public String getName() { return name; } ... }
// List<Person> persons = ...;

public static <T> Predicate<T> distinctByKey(Function<? super T, ?> keyExtractor) {
    Set<Object> seen = ConcurrentHashMap.newKeySet();
    return t -> seen.add(keyExtractor.apply(t));
}

// Example Usage:
// List<Person> distinctByName = persons.stream()
//                                       .filter(distinctByKey(Person::getName))
//                                       .collect(Collectors.toList());

Note: When using parallel streams, this method preserves an arbitrary element from duplicates, not necessarily the first one, unlike the standard distinct().

Solution 2: Using Collectors.toMap

An alternative is to collect the stream elements into a Map where the name serves as the key. If duplicate keys are encountered, the first encountered Person object is retained.

import java.util.stream.Collectors;

This method is effective for retaining the first instance of an object when duplicates of a specific key exist.

Solution 3: Wrapping Objects with a Custom Wrapper Class

You can wrap your objects in a custom class that overrides equals() and hashCode() to consider only the desired key. Then, use the distinct() operation on the stream of wrapped objects.

import java.util.stream.Stream;
import java.util.Objects;

// Assuming a Person class with a getName() method
// List<Person> persons = ...;

static class Wrapper {
    private final Person person;

    public Wrapper(Person person) {
        this.person = person;
    }

    public Person unwrap() {
        return person;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Wrapper wrapper = (Wrapper) o;
        return Objects.equals(person.getName(), wrapper.person.getName());
    }

    @Override
    public int hashCode() {
        return Objects.hash(person.getName());
    }
}

// Example Usage:
// List<Person> distinctPersons = persons.stream()
//                                       .map(Wrapper::new)
//                                       .distinct()
//                                       .map(Wrapper::unwrap)
//                                       .collect(Collectors.toList());

This approach encapsulates the distinctness logic within the Wrapper class, making the stream pipeline cleaner.

Solution 15: Custom Collector with toMap

A custom collector can be crafted using toMap to handle distinctness.

import java.util.stream.Collector;
import java.util.stream.Stream;
import java.util.Map;
import java.util.function.Function;
import java.util.List;

// Assuming a Person class with a getName() method
// Stream<Person> personStream = ...;

public static <T, R> Collector<T, ?, Stream<T>> distinctByKeyCollector(Function<T, R> keyExtractor) {
    return Collectors.collectingAndThen(
            Collectors.toMap(
                    keyExtractor,
                    Function.identity(), // Map element to itself
                    (existing, replacement) -> existing // Keep the first on duplicate
            ),
            Map::values // Get the values (distinct elements) as a stream
    );
}

// Example Usage:
// Stream.of(new Person("Jean"), new Person("Jean"), new Person("Paul"))
//       .collect(distinctByKeyCollector(Person::getName))
//       .forEach(p -> System.out.println(p.getName())); // Outputs: Jean, Paul

This provides a reusable collector for achieving distinctness.

Solution 17: Performance Comparison: Streams vs. For-Each

It’s crucial to consider performance. Benchmarks often show that a traditional for-each loop with a HashSet can outperform stream-based operations for simple distinctness tasks, especially with large datasets.

import java.util.List;
import java.util.Set;
import java.util.HashSet;
import java.util.Arrays;
import java.util.concurrent.TimeUnit;
import org.openjdk.jmh.annotations.*;
import org.openjdk.jmh.infra.Blackhole;
import org.openjdk.jmh.runner.Runner;
import org.openjdk.jmh.runner.RunnerException;
import org.openjdk.jmh.runner.options.Options;
import org.openjdk.jmh.runner.options.OptionsBuilder;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.stream.Collectors;

// Define a simple class for demonstration
class SimpleEvent {
    private String name;
    private String type;

    public SimpleEvent(String name) {
        this.name = name;
        this.type = "type_" + name;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getType() { return type; }
    public void setType(String type) { this.type = type; }
}

@State(Scope.Benchmark)
public class DistinctBenchmark {

    public static final List<SimpleEvent> testList = Arrays.asList(
            new SimpleEvent("Tom"), new SimpleEvent("Dick"), new SimpleEvent("Harry"), new SimpleEvent("Tom"),
            new SimpleEvent("Dick"), new SimpleEvent("Huckle"), new SimpleEvent("Berry"), new SimpleEvent("Tom"),
            new SimpleEvent("Dick"), new SimpleEvent("Moses"), new SimpleEvent("Chiku"), new SimpleEvent("Cherry"),
            new SimpleEvent("Roses"), new SimpleEvent("Moses"), new SimpleEvent("Chiku"), new SimpleEvent("gotya"),
            new SimpleEvent("Gotye"), new SimpleEvent("Nibble"), new SimpleEvent("Berry"), new SimpleEvent("Jibble"));

    // Helper Predicate from Solution 1
    public static <T> Predicate<T> distinctByKey(Function<? super T, ?> keyExtractor) {
        Set<Object> seen = new HashSet<>();
        return t -> seen.add(keyExtractor.apply(t));
    }

    @Benchmark
    @OutputTimeUnit(TimeUnit.SECONDS)
    public void streamBasedUniqueSet(Blackhole blackhole) {
        Set<String> uniqueNames = testList
                .stream()
                .filter(distinctByKey(SimpleEvent::getName))
                .map(SimpleEvent::getName)
                .collect(Collectors.toSet());
        blackhole.consume(uniqueNames);
    }

    @Benchmark
    @OutputTimeUnit(TimeUnit.SECONDS)
    public void forEachBasedUniqueSet(Blackhole blackhole) {
        Set<String> uniqueNames = new HashSet<>();
        for (SimpleEvent event : testList) {
            uniqueNames.add(event.getName());
        }
        blackhole.consume(uniqueNames);
    }

    public static void main(String[] args) throws RunnerException {
        Options opt = new OptionsBuilder()
                .include(DistinctBenchmark.class.getSimpleName())
                .forks(1)
                .mode(Mode.Throughput)
                .warmupBatchSize(3)
                .warmupIterations(3)
                .measurementIterations(3)
                .build();

        new Runner(opt).run();
    }
}

Solution 20: Stateful Predicate Handling Null Keys

To prevent NullPointerException when the key extractor returns null, a slight modification to Solution 1 is needed.

import java.util.Set;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.concurrent.ConcurrentHashMap;
import java.util.Optional;

// Assuming a Person class with a potentially null getName() method
// List<Person> persons = ...;

public static <T, K> Predicate<T> distinctByKeySafe(final Function<? super T, K> getKey) {
    // Use Optional to handle null keys correctly in the Set
    final Set<Optional<K>> seen = ConcurrentHashMap.newKeySet();
    return obj -> seen.add(Optional.ofNullable(getKey.apply(obj)));
}

Solution 24: Stream Gatherers (Java 22+)

With Java 22 and JEP 485, Stream Gatherers offer a new intermediate operation for custom stream transformations, including distinct element filtering.

import java.util.List;
import java.util.Set;
import java.util.HashSet;
import java.util.function.Function;
import java.util.stream.Gatherer;
import java.util.stream.Stream;

// Assuming a Person class with a getName() method
// List<Person> persons = ...;

static <T, R> Gatherer<T, ?, T> distinctBy(Function<T, R> function) {
    Gatherer.Integrator.Greedy<Set<R>, T, T> integrator =
            (state, element, downstream) -> {
                R functionResult = function.apply(element);
                if (state.contains(functionResult)) {
                    return true; // Element already seen, skip
                } else {
                    state.add(functionResult);
                    return downstream.push(element); // Push new distinct element
                }
            };
    return Gatherer.ofSequential(HashSet::new, integrator);
}

// Example Usage:
// List<Person> distinct = persons.stream()
//                                 .gather(distinctBy(Person::getName))
//                                 .toList();
// System.out.println(distinct); // Prints distinct persons based on name

Gatherers provide a flexible and performant way to implement custom stream logic.

Solution 25: Generic Utility for TreeSet

// Helper class C for testing
private static class C {
    public final int value;
    private C(int value) { this.value = value; }
    // It's good practice to implement equals and hashCode if C is intended for Sets/Maps
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;

public static <T> Set<T> removeDuplicates(Collection<T> input, Comparator<T> comparer) {
    return input.stream()
            .collect(Collectors.toCollection(() -> new TreeSet<>(comparer)));
}

Solution 30: Null-Safe Stateful Predicate with Optional

This refined version of Solution 1 uses Optional to handle null keys gracefully within the ConcurrentHashMap.

import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.Optional;
import java.util.stream.Collectors;
import java.util.stream.Stream;
import static java.util.Arrays.asList;
import static java.util.stream.Collectors.toList;

// Mock helper for testing map scenarios
private static Map<String, Integer> hashMapWith(int i, Integer val) {
    return Map.of("i", i, "val", val);
}

public static <T, K> Predicate<T> distinctByKeyOptional(final Function<? super T, K> getKey) {
    final Set<Optional<K>> seen = ConcurrentHashMap.newKeySet();
    return obj -> seen.add(Optional.ofNullable(getKey.apply(obj)));
}

FAQs on Java Stream Distinct by Key

Q: What is the most performant way to get distinct elements by key in Java streams

ANS: For sequential streams, a simple for loop with a HashSet often outperforms stream-based solutions. For parallel streams, the distinctByKey predicate using ConcurrentHashMap (Solution 1) is a good choice. Always benchmark for your specific use case.

Q: How to handle null keys when filtering distinct stream elements

ANS: Use Optional.ofNullable() with your key extractor, as shown in Solution 20 and Solution 30, to safely include or exclude null keys in your distinct set.

Q: Can I get distinct elements based on multiple keys

ANS: Yes, you can create a composite key by combining multiple properties into a single key object (e.g., a List or a custom Pair class) and use that composite key with any of the presented methods. Solution 28 demonstrates grouping by a composite key.

Q: Does the order of distinct elements matter

ANS: Some methods, like using ConcurrentHashMap in parallel streams or certain groupingBy strategies, may not preserve the original encounter order. If order is critical, consider methods that explicitly maintain it or sort the result afterwards. Solution 2 and Solution 5 typically preserve order or allow sorting.
