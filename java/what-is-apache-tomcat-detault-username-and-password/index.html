Top 5 Ways to Secure Your Tomcat Server with Customized User Roles

1. Modify the tomcat-users.xml File for Custom Users and Roles

The tomcat-users.xml file is the central place to manage user roles and credentials in Tomcat. Out of the box, Tomcat doesn’t come with a preconfigured admin user, so we need to create one.

Step-by-step explanation:

  • Step 1: Locate the tomcat-users.xml file. It’s generally found in the /conf directory of your Tomcat installation.
  • Step 2: Open the file in your favorite text editor.
  • Step 3: Add the following lines to create a new user with admin and manager roles.
<?xml version="1.0" encoding="UTF-8"?>
<tomcat-users>
    <role rolename="manager-gui"/>
    <role rolename="admin-gui"/>
    <user username="admin" password="strongpassword" roles="manager-gui,admin-gui"/>
</tomcat-users>

Explanation:

  • <role rolename="manager-gui"/> creates the manager GUI role.
  • <role rolename="admin-gui"/> assigns the admin role.
  • <user username="admin" password="strongpassword" roles="manager-gui,admin-gui"/> creates a new user, assigning both manager and admin roles.

Practical Example: If your Tomcat is installed at /usr/local/tomcat, this file is usually found at /usr/local/tomcat/conf/tomcat-users.xml. Open the file, add the above configuration, and restart Tomcat for the changes to take effect.

3. Create Role-Specific Users

Instead of using a single user with all permissions, create role-specific users to follow the principle of least privilege.

Step-by-step explanation:

  • Step 1: Define different roles such as manager-script, admin-script, and manager-jmx.
  • Step 2: Assign users to these specific roles.
<role rolename="manager-gui"/>
<role rolename="manager-script"/>
<role rolename="admin-gui"/>
<user username="deployUser" password="Deploy123!" roles="manager-script"/>
<user username="adminUser" password="Admin456!" roles="admin-gui"/>

Explanation:

  • deployUser has access to manager scripting features, but not GUI, reducing the attack surface.
  • adminUser is isolated for administrative tasks only, limiting the risk if one account is compromised.

4. Secure the Manager and Host Manager Applications

Restrict access to the manager and host-manager applications by limiting IP addresses that can connect.

Step-by-step explanation:

  • Step 1: Locate the context.xml file for the manager application. Usually found in /webapps/manager/META-INF/context.xml.
  • Step 2: Add restrictions to limit access by IP addresses.
<Context antiResourceLocking="false" privileged="true">
    <Valve className="org.apache.catalina.valves.RemoteAddrValve"
           allow="192.168.0.100"/>
</Context>

Explanation:

  • This ensures that only requests from 192.168.0.100 can access the manager application, adding an extra layer of security.

5. Disable Unnecessary User Accounts

By default, the tomcat-users.xml file may include users that you don’t need. Ensure you remove any unnecessary users to reduce the risk of unauthorized access.

Step-by-step explanation:

  • Step 1: Open the tomcat-users.xml file.
  • Step 2: Remove any unneeded users by deleting their <user> entry.
<user username="guest" password="guest" roles="guest"/>

Explanation:

  • If you no longer need the guest user, simply remove this line from the file. Fewer accounts mean fewer entry points for attackers.

Q: How do I reset the admin password in Tomcat?

ANS: You can reset the admin password by editing the tomcat-users.xml file and changing the password attribute in the relevant <user> tag.

Q: Is it possible to assign multiple roles to a single user?

ANS: Yes, you can assign multiple roles to a user by listing them in the roles attribute of the <user> tag, separated by commas.

Q: How do I restrict access to the Tomcat Manager application?

ANS: You can restrict access by editing the context.xml file and using a RemoteAddrValve to allow only specific IP addresses.

Q: Can I run Tomcat over HTTPS?

ANS: Yes, Tomcat supports HTTPS. You need to configure the server to use SSL by adding the appropriate connector in server.xml.

Q: How do I monitor Tomcat logs for security issues?

ANS: Tomcat logs are found in the /logs directory. Regularly review the access and error logs to identify any suspicious activities.
