“Java: Reading Files from Resources Folder”

Accessing files located within a project’s resources directory is a common requirement in Java development. Whether you’re working with configuration files, data assets, or templates, knowing how to correctly retrieve these resources is essential. This exploration details various techniques for reading files from the resources folder, accommodating different project structures and Java versions.

Accessing Resources with ClassLoaders

A primary method for accessing resources involves using ClassLoader. The ClassLoader is responsible for loading classes and resources into the Java Virtual Machine.

Solution 1: Using Thread.currentThread().getContextClassLoader()

This approach leverages the context ClassLoader of the current thread to locate and read resources.

Solution 19: A Dedicated ResourceLoader Class

This provides a structured way to load resources, including error handling for missing files.

import java.io.InputStream;
import java.nio.file.NoSuchFileException;

public class ResourceLoader {
    private String filePath;

    public ResourceLoader(String filePath) {
        this.filePath = filePath;
        if (filePath.startsWith("/")) {
            throw new IllegalArgumentException("Relative paths may not have a leading slash!");
        }
    }

    public InputStream getResource() throws NoSuchFileException {
        ClassLoader classLoader = this.getClass().getClassLoader();
        InputStream inputStream = classLoader.getResourceAsStream(filePath);

        if (inputStream == null) {
            throw new NoSuchFileException("Resource file not found. Note that the current directory is the source folder!");
        }
        return inputStream;
    }
}

Solution 24: Generic Resource Access

This solution covers accessing resources as InputStream, File, or Path, offering flexibility.

// From non-static context
InputStream is = getClass().getClassLoader().getResourceAsStream("test.txt");

// From static context
InputStream is = MyClass.class.getClassLoader().getResourceAsStream("test.txt");

// To get a File object
// From non-static context
File f1 = new File(getClass().getClassLoader().getResource("test.txt").getPath());
File f2 = new File(getClass().getClassLoader().getResource("test.txt").toURI());

// From static context
File f1 = new File(MyClass.class.getClassLoader().getResource("test.txt").getPath());
File f2 = new File(MyClass.class.getClassLoader().getResource("test.txt").toURI());

// To get a Path object (JDK 11+)
// From non-static context
Path p = Path.of(getClass().getClassLoader().getResource("test.txt").toURI());

// From static context
Path p = Path.of(Main.class.getClassLoader().getResource("test.txt").toURI());

Reading Resources with Class.getResourceAsStream()

Class.getResourceAsStream() is another common method, with nuances regarding path interpretation.

Solution 2: Relative Path Handling

This method reads resources relative to the class’s package. A leading / is crucial for absolute paths from the classpath root.

InputStream is = MyTest.class.getResourceAsStream("/test.csv");

Solution 25: Resource Path Specificity

This example shows a more specific path structure for resource retrieval.

InputStream in = getClass().getResourceAsStream("/main/resources/xxx.xxx");
InputStreamReader streamReader = new InputStreamReader(in, StandardCharsets.UTF_8);
BufferedReader reader = new BufferedReader(streamReader);
String content = "";
for (String line; (line = reader.readLine()) != null;) {
    content += line;
}

Utilizing Spring Framework Utilities

For projects using the Spring Framework, ClassPathResource offers a convenient way to access resources.

This method is ideal for Spring projects. An alternative is provided for non-Spring projects.

Employing Third-Party Libraries (Guava)

External libraries can also simplify resource handling.

Solution 4: Guava’s Resources Class

Guava provides a straightforward utility for reading resource content.

import com.google.common.base.Charsets;
import com.google.common.io.Resources;

public String readResource(final String fileName, Charset charset) throws IOException {
    return Resources.toString(Resources.getResource(fileName), charset);
}

Handling InputStreams and Error Scenarios

Solution 9: Reading Font Files

An example of reading a font file from resources.

Font getCalibriLightFont(int fontSize){
    Font font = null;
    try{
        URL fontURL = OneMethod.class.getResource("/calibril.ttf");
        InputStream fontStream = fontURL.openStream();
        font = new Font(Font.createFont(Font.TRUETYPE_FONT, fontStream).getFamily(), Font.PLAIN, fontSize);
        fontStream.close();
    } catch(IOException | FontFormatException ief){
        font = new Font("Arial", Font.PLAIN, fontSize);
        ief.printStackTrace();
    }
    return font;
}

Solution 10: Utility for Loading File Lines

A reusable method to load file lines into an ArrayList.

import java.io.IOException;
import java.io.FileNotFoundException;
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.InputStream;
import java.util.ArrayList;

public ArrayList<String> loadFile(String filename){
    ArrayList<String> lines = new ArrayList<String>();
    try {
        ClassLoader classloader = Thread.currentThread().getContextClassLoader();
        InputStream inputStream = classloader.getResourceAsStream(filename);
        InputStreamReader streamReader = new InputStreamReader(inputStream, StandardCharsets.UTF_8);
        BufferedReader reader = new BufferedReader(streamReader);
        for (String line; (line = reader.readLine()) != null;) {
            lines.add(line);
        }
    } catch(FileNotFoundException fnfe){
        // process errors
    } catch(IOException ioe){
        // process errors
    }
    return lines;
}

Solution 17: Kotlin for Android Assets

Illustrates reading files from an assets folder in an Android project using Kotlin.

import android.content.Context
import android.util.Log
import java.io.FileNotFoundException

fun loadBook(context: Context) {
   val assetManager = context.assets
   try {
      val inputStream = assetManager?.open("19-Psalms.usfm")
      val lineList = mutableListOf<String>()

      inputStream?.bufferedReader()?.forEachLine { lineList.add(it) }
      lineList.forEach{println(">  $it")}
  } catch (e:FileNotFoundException) {
      Log.e("FileNotFoundException","File not found")
  }
}

FAQs on Java File Reading

Q: How to read a file from Java resources in a non-static method

ANS: Use getClass().getClassLoader().getResourceAsStream("your_file.txt") or getClass().getResourceAsStream("/your_file.txt") depending on the path relative to your class.

Q: How to read a file from Java resources in a static method

ANS: Use MyClass.class.getClassLoader().getResourceAsStream("your_file.txt") or MyClass.class.getResourceAsStream("/your_file.txt").

Q: What's the difference between getResourceAsStream and ClassPathResource

ANS: getResourceAsStream is a core Java method that uses classloaders. ClassPathResource is a Spring Framework utility, often preferred in Spring applications for its additional features and consistent handling of resources.

Q: Why might my resource file not be found when running a JAR

ANS: Ensure your build tool (like Maven or Gradle) is configured to include the resources directory in the artifact. Rebuilding the project can also resolve issues where the IDE might not have picked up new files. See [Solution 7] and [Solution 18].

Q: Can I get a File object for a resource file

ANS: Yes, you can get a File object by first retrieving the resource as a URL using getClass().getClassLoader().getResource("your_file.txt") and then constructing a File from its path or URI, as shown in [Solution 24] and [Solution 15]. However, this might not work correctly when the resource is inside a JAR.

Q: How to read a file from a specific package structure within resources

ANS: When using getResourceAsStream or getResource, ensure the path reflects the package structure. For example, if your file is in src/main/resources/config/settings.properties, you might use "config/settings.properties" or "/config/settings.properties" depending on the method and context. See [Solution 25] for an example.
