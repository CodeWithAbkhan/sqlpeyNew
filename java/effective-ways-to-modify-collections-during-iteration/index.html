Safe Element Removal Techniques During Java List Traversal

When modifying a collection while iterating over it using enhanced for-each loops, Java collections, particularly ArrayList, check for external modifications, resulting in the dreaded ConcurrentModificationException. The following methods provide reliable means to alter the collection content during traversal.

Method 1: Utilizing the Iterator’s remove() Method

The canonical and safest approach for modifying a collection during iteration in a single-threaded context is to use the Iterator interface and exclusively call its remove() method. This method signals the iterator that an element has been legitimately removed, preventing modification checks from failing on the next step.

import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class SafeRemovalDemo {
    public static void main(String[] args) {
        List<String> sampleList = new ArrayList<>(List.of("apple", "banana", "cherry", "date"));
        boolean conditionMet = true; // Replace with actual logic

        Iterator<String> iter = sampleList.iterator();

        while (iter.hasNext()) {
            String currentElement = iter.next();

            if (currentElement.startsWith("b") && conditionMet) {
                System.out.println("Removing: " + currentElement);
                iter.remove(); // Correct way to remove during iteration
            }
        }
        System.out.println("Result after Iterator remove: " + sampleList);
    }
}

Method 2: Collecting Items for Removal and Bulk Removal

An alternative strategy involves iterating normally to identify the elements to be deleted, storing these elements in a separate temporary collection, and then invoking the removeAll() method on the original list after the traversal is complete. This preserves readability but introduces temporary memory overhead for the secondary list.

import java.util.ArrayList;
import java.util.List;

public class BulkRemovalDemo {
    public static void main(String[] args) {
        List<String> primaryList = new ArrayList<>(List.of("red", "green", "blue", "yellow"));
        List<String> itemsToRemove = new ArrayList<>();

        for (String color : primaryList) {
            if (color.length() > 4) {
                itemsToRemove.add(color);
            }
        }
        
        primaryList.removeAll(itemsToRemove);
        System.out.println("List after bulk removal: " + primaryList);
    }
}

Method 3: Java 8+ Functional Approach with removeIf

For environments utilizing Java 8 or newer, the Collection interface offers the highly concise and expressive removeIf(Predicate<? super E> filter) method. This internally handles the iteration and safe removal logic.

import java.util.ArrayList;
import java.util.List;

public class Java8RemovalDemo {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>(List.of(10, 25, 40, 55, 70));
        
        // Remove all elements greater than 50
        numbers.removeIf(n -> n > 50);
        
        System.out.println("List after removeIf: " + numbers);
    }
}

Method 4: Traditional Index-Based Loop with Manual Index Adjustment

If the enhanced for-each loop must be avoided (often due to the hidden iterator mechanism causing exceptions when combining with modification), a standard indexed for loop can be employed. Crucially, when an element is removed, the index i must be decremented (i--) to re-examine the element that shifted into the current position.

import java.util.ArrayList;
import java.util.List;

public class IndexedRemovalDemo {
    public static void main(String[] args) {
        List<String> dataList = new ArrayList<>(List.of("A1", "B2", "C3", "D4"));

        for (int i = 0; i < dataList.size(); i++) {
            String element = dataList.get(i);
            
            if (element.endsWith("3")) {
                dataList.remove(i);
                i--; // Correct for the shift caused by removal
            }
        }
        System.out.println("List after index adjustment removal: " + dataList);
    }
}

Method 5: Handling Multithreading with Specialized Structures

In concurrent environments where multiple threads might access and modify the list, standard ArrayList iteration and removal patterns will fail due to race conditions or concurrent modification checks. The recommended solution is to switch to a thread-safe collection like CopyOnWriteArrayList.

With CopyOnWriteArrayList, modifications (like add or remove) create a fresh copy of the underlying array. Iterators operate on the snapshot they were created from, making concurrent iteration safe, although writes are expensive. Note that iterator.remove() on a CopyOnWriteArrayList iterator often does not function as expected on the underlying list depending on the specific implementation/version, as iterators are snapshot-based.

import java.util.concurrent.CopyOnWriteArrayList;
import java.util.Iterator;
import java.util.List;

public class ThreadSafeRemovalDemo {
    public static void main(String[] args) {
        // Exception prone with ArrayList: List<String> s = new ArrayList<>(); s.add("B");
        List<String> threadSafeList = new CopyOnWriteArrayList<>();
        threadSafeList.add("Item_1");
        threadSafeList.add("Item_2");
        
        Iterator<String> it = threadSafeList.iterator();
        threadSafeList.add("Item_3_New"); // Modification happens concurrently

        // Iteration occurs over the snapshot existing when 'it' was created.
        while (it.hasNext()) {
            String item = it.next();
            System.out.println("Iterating over snapshot item: " + item);
        }
        // The actual removal logic for COWList is often done outside iteration for clarity, 
        // or by creating a new list based on filtering, since iterator.remove() behavior varies.
        
        System.out.println("Final COWList state: " + threadSafeList);
    }
}

Method 6: Synchronized Block with Iterator

For situations requiring synchronization around the list access but using standard List implementation, wrap the iteration and potential modification within a synchronized block, using the iterator for safe removal within that synchronized context. This requires using Collections.synchronizedList() to wrap the list if it wasn’t inherently thread-safe.

import java.util.ArrayList;
import java.util.Collections;
import java.util.Iterator;
import java.util.List;

public class SynchronizedRemovalDemo {
    public static void main(String[] args) {
        List<String> originalList = new ArrayList<>(List.of("X", "Y", "Z"));
        List<String> safeList = Collections.synchronizedList(originalList);

        synchronized(safeList) {
            Iterator<String> i = safeList.iterator(); 
            while (i.hasNext()){
                Object element = i.next();
                if (element.equals("Y")) {
                    i.remove(); // Safe inside synchronized block with iterator
                }
            }
        }
        System.out.println("List after synchronized removal: " + safeList);
    }
}

Method 7: Converting to Array for Iteration

A final technique involves converting the current contents of the list into an array first. Iterating over the static array allows safe removals against the original list using the array elements as references for matching. This is useful when the removal condition depends on the element’s value, not its state during iteration.

import java.util.ArrayList;
import java.util.List;

public class ArrayConversionDemo {
    public static void main(String[] args) {
        List<String> dynamicList = new ArrayList<>(List.of("data1", "test", "data2", "test_extra"));

        Object[] staticSnapshot = dynamicList.toArray();

        for(Object itemObject: staticSnapshot)  {
            String item = itemObject.toString();
            if(item.contains("test")) {
                // Safely remove from the list using the value from the static array iteration
                dynamicList.remove(item); 
            }
        }
        System.out.println("List after array iteration removal: " + dynamicList);
    }
}

FAQs on Safe Collection Modification During Iteration

Q: Why does the enhanced for loop fail when removing elements

ANS: The enhanced for loop utilizes an underlying iterator. If the list structure changes externally (i.e., via list.remove()), the iterator’s internal modification count diverges from the list’s count, triggering a ConcurrentModificationException.

Q: Can I use the iterator.remove method on any collection type

ANS: Yes, but the collection must implement the Collection interface and the iteration must be performed via an iterator obtained from that collection. The specific collection type determines performance implications (e.g., CopyOnWriteArrayList handles it differently).

Q: Is using removeIf the most performant method for Java 8 lists

ANS: Generally, removeIf is highly optimized internally, often performing better than manually constructed iterator loops, especially for large lists, as it leverages internal bulk operations.

Q: What happens if I use list.remove(index) inside a standard for loop

ANS: It works, provided you manually adjust the index (i--) after removal, otherwise you skip checking the element that shifts into the current index. This is less idiomatic than using the iterator.
