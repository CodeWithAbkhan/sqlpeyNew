“Fixing SwingWorker ExecutionException with ArrayIndexOutOfBoundsException in Java”

When utilizing javax.swing.SwingWorker for background operations in Java Swing applications, observing an ExecutionException wrapped around an underlying issue like ArrayIndexOutOfBoundsException in the done() method upon calling get() is a frequently encountered scenario. This behavior stems from how SwingWorker manages exceptions thrown during the execution of doInBackground().

How can we effectively pinpoint and resolve an ArrayIndexOutOfBoundsException that manifests as an ExecutionException when get() is invoked in the done() method of a SwingWorker?

The trace clearly indicates the problem originates within the background thread’s logic:

StartShedule: PENDING -> STARTED
java.util.concurrent.ExecutionException: java.lang.ArrayIndexOutOfBoundsException: Array index out of range: 2

    ...
    Caused by: java.lang.ArrayIndexOutOfBoundsException: Array index out of range: 2
    at java.util.Vector.get(Vector.java:694)

    ...
StartShedule: STARTED -> DONE

The root cause resides in TableWithExecutor.changeTableValues(TableWithExecutor.java:64) (which appears to be called via process or perhaps the exception is thrown before process fully completes, depending on the SwingWorker lifecycle execution flow). Since the error occurs in doInBackground (or processing triggered by it), it gets wrapped by ExecutionException when get() is called in done().

Solution 1: Inspecting the Original Implementation and Execution Flow

The initial approach shown executed get() unconditionally in done():

@Override
protected void done() {
    try {
        get(); // Throws ExecutionException if doInBackground threw an exception
    } catch (Exception e) {
        e.printStackTrace(System.err);
    }
}

This correctly catches the wrapped exception but requires careful inspection of the code where the array access occurs. The exception details point to an array index of 2 being out of range in java.util.Vector.get(Vector.java:694), which suggests the underlying data structure (likely related to model.getRowCount() or row/column indexing) is being accessed incorrectly, possibly due to an initial setup error or faulty loop boundaries in doInBackground or process.

In the provided example structure, the indexing error likely occurs here in MyTask.doInBackground:

@Override
protected List<DateRecord> doInBackground() throws Exception {
    for (int row = 0; row < model.getRowCount(); row++) { // If model.getRowCount() is less than 3, accessing index 2 is fine. If it's 2 or less, it depends on what TableWithExecutor.changeTableValues is doing.
        Date date = new Date();
        date.setTime(date.getTime() + row * 1000);
        publish(new DateRecord(row, date));
    }
    return null;
}

And the call to model.setValueAt(dr.date, dr.rowNumber, 1); inside process might be triggering the internal Vector.get exception if dr.rowNumber exceeds the bounds of the underlying table model structure, especially given the unusual initialization: private Object[][] data = {columnNames, columnNames, columnNames}; which creates 3 rows where the first row contains headers, potentially confusing the row count logic if not handled carefully.

Solution 2: Conditional Exception Retrieval in done()

A refinement suggests checking the task’s state or name before attempting to retrieve results, which can sometimes isolate specific task failures without masking others. If the goal is just to log the exception for a specific task named “StartShedule,” the structure changes to:

@Override
protected void done() {
    // Assuming 'str' holds the task name, though in the provided code it should be 'name'
    // We must check if the task completed exceptionally.
    if (this.name.equals("StartShedule")) { // Using 'name' from the class instance
       try {
          get(); // Retrieve result or re-throw exception
       }
       catch (Exception ex) {
          // This exception was thrown during processing or doInBackground
          ex.printStackTrace();
       }
    }
}

Why this works: done() executes on the Event Dispatch Thread (EDT). Calling get() on the Future associated with the SwingWorker either returns the result or throws the exception that occurred during doInBackground() or exceptions propagated from publish() processing steps. By wrapping get() in a try-catch block within done(), you safely retrieve the exception on the EDT for logging or UI display, preventing application hang or silent failure.

Practical Code Example: Refined done() Method

To implement the suggested improvement using the existing class structure where name is available:

In TableWithExecutor.MyTask:

    @Override
    protected void done() {
        // Check if this specific instance needs result retrieval/exception logging
        if (this.name.equals(STARTSCHEDULE)) {
           try {
               // Calling get() here surfaces the exception if one occurred in doInBackground
               get();
           }
           catch (java.util.concurrent.ExecutionException ex) {
              // The actual exception is wrapped inside ExecutionException
              System.err.println("Task execution failed for " + name + ":");
              ex.getCause().printStackTrace(System.err); // Print the root cause (ArrayIndexOutOfBoundsException)
           }
           catch (Exception ex) {
              // Other exceptions during get() like InterruptedException
              ex.printStackTrace(System.err);
           }
        }
    }

Note: When using get() inside done(), you should explicitly catch ExecutionException to access the original cause using ex.getCause(), which reveals the critical ArrayIndexOutOfBoundsException.

Alternative Approach: Checking isDone() and get() Without Exception Wrapping

If you wish to avoid calling get() if the thread was canceled or if the result retrieval is not strictly necessary to diagnose the error (since the error is already reported via the property change listeners if set up correctly), you might rely more heavily on the PropertyChangeListener added in the constructor:

// In MyTask constructor:
addPropertyChangeListener(new TaskListener(name));

// In TaskListener.propertyChange:
@Override
public void propertyChange(PropertyChangeEvent e) {
    System.out.println(name + ": "
        + e.getOldValue() + " -> " + e.getNewValue());
    
    // The state change to "DONE" with state DONE will trigger here.
    // If an error occurred, the state might transition to "ERROR" depending on the SwingWorker version/implementation detail, 
    // or the final state will simply be DONE with a failure pending retrieval via get().
}

While the listener reports state transitions (PENDING -> STARTED), it usually reports null for values when an unhandled exception occurs. Relying on the explicit try-catch block around get() inside done() remains the most reliable way to capture the full exception stack trace originating from the background thread.

FAQs on Fixing SwingWorker ExecutionException With ArrayIndexOutOfBoundsException

Q: What exception wraps the underlying error when calling get() in SwingWorker done()

ANS: java.util.concurrent.ExecutionException wraps the exception thrown in doInBackground().

Q: How do I see the original error from ExecutionException

ANS: Use ex.getCause() on the caught ExecutionException to access the root cause, like ArrayIndexOutOfBoundsException.

Q: Is it always necessary to call get() in the done method

ANS: Calling get() is the standard way to check for and propagate exceptions that occurred during background execution, although you can alternatively check the SwingWorker state.

import java.awt.BorderLayout;
import java.awt.Dimension;
import java.awt.EventQueue;
import java.awt.event.ActionEvent;
import java.beans.PropertyChangeEvent;
import java.beans.PropertyChangeListener;
import java.text.DateFormat;
import java.util.Date;
import java.util.List;
import java.util.concurrent.Executor;
import java.util.concurrent.Executors;
import javax.swing.*;
import javax.swing.table.*;

/** @see https://stackoverflow.com/questions/7054627 */
public class TableWithExecutor extends JFrame {

    private static final int delay = 1000;
    private static final DateFormat df = DateFormat.getTimeInstance();
    private String[] columnNames = {"Product", "Availability"};
    private Object[][] data = {columnNames, columnNames, columnNames};
    private DefaultTableModel model;
    private JTable table;
    private Executor executor = Executors.newCachedThreadPool();
    private Timer timer;

    public TableWithExecutor() {
        model = new DefaultTableModel(data, columnNames);
        table = new JTable(model) {

            @Override
            public Class getColumnClass(int column) {
                return getValueAt(0, column).getClass();
            }
        };
        table.setDefaultRenderer(Date.class, new DefaultTableCellRenderer() {

            @Override
            protected void setValue(Object value) {
                setText((value == null) ? "" : df.format(value));
            }
        });
        table.setPreferredScrollableViewportSize(new Dimension(200, 100));
        JScrollPane scrollPane = new JScrollPane(table);
        add(scrollPane, BorderLayout.CENTER);
        timer = new Timer(delay, startCycle());
        timer.setRepeats(true);
        timer.start();
    }

    private Action startCycle() {
        return new AbstractAction(MyTask.STARTSCHEDULE) {

            @Override
            public void actionPerformed(ActionEvent e) {
                executor.execute(new MyTask(MyTask.STARTSCHEDULE));
            }
        };
    }

    public static void main(String[] args) {
        EventQueue.invokeLater(new Runnable() {

            @Override
            public void run() {
                TableWithExecutor frame = new TableWithExecutor();
                frame.setDefaultCloseOperation(EXIT_ON_CLOSE);
                frame.pack();
                frame.setLocationRelativeTo(null);
                frame.setVisible(true);
            }
        });
    }

    private class MyTask extends SwingWorker&lt;List&lt;DateRecord&gt;, DateRecord&gt; {

        private static final String STARTSCHEDULE = "StartSchedule";
        private String name = STARTSCHEDULE;

        MyTask(String name) {
            this.name = name;
            addPropertyChangeListener(new TaskListener(name));
        }

        @Override
        protected List&lt;DateRecord&gt; doInBackground() throws Exception {
            for (int row = 0; row &lt; model.getRowCount(); row++) {
                Date date = new Date();
                date.setTime(date.getTime() + row * 1000);
                publish(new DateRecord(row, date));
            }
            return null;
        }

        @Override
        protected void process(List&lt;DateRecord&gt; chunks) {
            for (DateRecord dr : chunks) {
                model.setValueAt(dr.date, dr.rowNumber, 1);
            }
        }

        @Override
        protected void done() {
            try {
                get();
            } catch (Exception e) {
                e.printStackTrace(System.err);
            }
        }
    }

    private static class DateRecord {

        private int rowNumber;
        private Date date;

        public DateRecord(int recordNumber, Date date) {
            this.rowNumber = recordNumber;
            this.date = date;
        }
    }

    private static class TaskListener implements PropertyChangeListener {

        private String name;

        TaskListener(String name) {
            this.name = name;
        }

        @Override
        public void propertyChange(PropertyChangeEvent e) {
            System.out.println(name + ": "
                + e.getOldValue() + " -&gt; " + e.getNewValue());
        }
    }
}
