“Executing Java JAR Files: Essential Command Line Techniques”

How to Properly Configure a JAR for Direct Execution Using java -jar

The most straightforward method to run a JAR file relies on it being designated as executable, which is determined by the contents of its META-INF/MANIFEST.MF file. This manifest must explicitly declare the Main-Class.

Setting up the Main Class and Manifest

To run a program directly, you must specify the fully qualified name of the class containing the public static void main(String[] args) method.

Consider a simple Java source file, Test.java:

public class Test
{
    public static void main(String[] args)
    {
        System.out.println("Hello world");
    }
}

The corresponding manifest file, conventionally named manifest.mf, must include the following structure:

Manifest-version: 1.0
Main-Class: Test

Crucial Detail: The manifest file must terminate with a newline or carriage return character. If the last line lacks this termination, the Java runtime may fail to parse the entry correctly.

Building and Executing the Manifest-Enabled JAR

  1. Compile:

    javac Test.java

  2. Create the JAR with Manifest: The cfm flags are essential here (create, file, manifest):

    jar cfm test.jar manifest.mf Test.class

  3. Run the Executable JAR:

    java -jar test.jar
# Expected Output: Hello world

Alternative JAR Creation (Using cvfe for Simplicity)

For simple, non-packaged applications, some tools allow specifying the main class during JAR creation using the cvfe flags (create, verbose, file, entrypoint):

# Creating and specifying the main class 'HelloWorld'
jar cvfe HelloWorld.jar HelloWorld HelloWorld.class

# Running this type of JAR
java -jar HelloWorld.jar

What If the Manifest Lacks the Main-Class Entry?

If the MANIFEST.MF is missing, incorrect, or you simply choose not to rely on it, the JAR is not inherently executable via java -jar. In these scenarios, you must invoke the Java runtime environment (JRE) explicitly, providing the path to the main class via the classpath (-cp or -classpath).

Invoking via Classpath Specification

You specify the JAR file as part of the classpath, followed by the fully qualified name of the main class.

If your main class is your.package.name.MainClass within Predit.jar:

java -classpath Predit.jar your.package.name.MainClass
# Alternative syntax:
java -cp Predit.jar your.package.name.MainClass

This approach bypasses the need for the Main-Class attribute in the manifest entirely.

How to Handle Package Structures in JAR Execution

When classes are organized into packages, the manifest and command-line invocation must reflect the full path structure.

For a structure like: D:\JavaProjects\OlivePressApp\com\lynda\olivepress\Main.class

  1. The manifest entry must be fully qualified:

    Main-Class: com.lynda.olivepress.Main

  2. When building the JAR, ensure the manifest is placed inside the META-INF directory within the JAR structure, or use the jar cfm command correctly, referencing the class files relative to the directory containing the manifest:

    D:\JavaProjects\OlivePressApp> jar cfm OlivePressApp.jar Manifest.txt com/lynda/olivepress/Main.class com/lynda/olivepress/*

  3. Execution remains:

    java -jar OlivePressApp.jar

Managing Dependencies When Running JARs

A common failure mode, particularly when using java -jar, is dependency omission, often resulting in errors like NoClassDefFoundError. This occurs because java -jar typically ignores the -classpath setting for finding dependent libraries.

To execute a JAR while including external dependencies (other JAR files):

  1. Determine Dependencies: Identify all required external JARs (e.g., dependency1.jar, dependency2.jar).

  2. Construct the Classpath: Combine the target JAR and all dependency JARs using the appropriate path separator:

    • Unix/Linux/macOS: Colon (:)
    • Windows: Semicolon (;)

If the main class is org.diligentsnail.consoleconsumer.Main and its dependencies are in a jars/ directory, the correct command using the classpath approach is:

On Linux/macOS:

java -classpath jars/console-consumer.jar:jars/hello-library.jar org.diligentsnail.consoleconsumer.Main

If the application uses the Java Platform Module System (JPMS), the module path (--module-path) should be used instead:

java --module-path my-jar.jar --module my-module-name/my-main-class

Using IDE Export Features

For developers utilizing Integrated Development Environments (IDEs) like Eclipse or NetBeans, pre-built “Runnable JAR File” export assistants simplify this process, often automatically handling manifest creation and dependency bundling, reducing manual command-line reliance. When creating a runnable JAR via these tools, ensure you select the class containing the entry point.

Executing a JAR and Passing Arguments

If you run a JAR with arguments, these arguments are passed directly to the main method of your entry class.

java -jar myRunnable.jar argument1 argument2

If you need to run the JAR from another Java process (e.g., to capture its output), you can invoke the command line using Runtime.getRuntime().exec():

// Example Java code to spawn an external JAR execution process
String jarfile = "D:\\JarLocation\\myRunnable.jar";
String name = "Yash";
String id = "777";

// Command structure ensuring arguments are space-separated
Process process = Runtime.getRuntime().exec("cmd.exe start /C java -jar "+jarfile+" "+name+" "+id);
// ... (Code to read process output via BufferedReader)

FAQs on Executing Java JAR Files

Q: What is the key requirement for java -jar to work

ANS: The JAR file must contain a META-INF/MANIFEST.MF file specifying the Main-Class attribute, pointing to the class with the main method.

Q: How to run a JAR if the manifest file is missing the main class entry

ANS: Use the classpath invocation: java -cp yourJar.jar your.package.MainClass.

Q: What command line flag is shorthand for -classpath

ANS: The shorthand flag is -cp.

Q: Why is ending the manifest file with a new line important

ANS: The Java JAR parser may not correctly read the final attribute if the last line of the manifest file does not have a terminating newline or carriage return.

Q: What separator is used for multiple paths in the classpath on Windows

ANS: The semicolon (;) is used to separate path entries in the classpath on Windows operating systems.
