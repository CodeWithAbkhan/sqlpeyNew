“Fixing JavaFX Runtime Components Missing Error with JDK 11+”

When upgrading to Java Development Kit (JDK) 11 or later, developers often encounter the persistent error: “JavaFX runtime components are missing, and are required to run this application.” This arises because, unlike previous Java versions, JavaFX is no longer bundled directly within the JDK. Instead, it needs to be explicitly included as a separate dependency. This post delves into the various methods to resolve this issue, whether you’re working with standard JavaFX projects, Maven, or Gradle.

Why is this Happening?

The core of the problem lies in Java’s module system introduced in JDK 9. JavaFX 11 and subsequent versions are distributed as separate modules. Your project needs to be configured to recognize and utilize these modules. This can manifest as IllegalAccessError when classes attempt to use reflection, a common practice within the JavaFX framework, without proper module permissions.

Solutions

Solution 1: Using the JavaFX SDK for Non-Modular Projects

For projects not using build tools like Maven or Gradle, the most straightforward approach is to download the JavaFX SDK and configure your IDE to use it.

Steps:

  1. Download the JavaFX SDK: Obtain the SDK from the official Gluon site . Ensure you download the version corresponding to your operating system.
  2. Create a JavaFX Project: If you don’t have one, create a new JavaFX project in your IDE.
  3. Set JDK 11: Configure your project to use your local JDK 11 installation.
  4. Add JavaFX SDK as a Library:
    • In IntelliJ IDEA: Go to File -> Project Structure -> Libraries. Click the + icon, select Java, and then navigate to the lib folder within your downloaded JavaFX SDK directory (e.g., /Users/<user>/Downloads/javafx-sdk-11/lib/).
    • In other IDEs, the process is similar: add the contents of the lib folder to your project’s libraries.
  5. Configure VM Options: Before running, you must tell the JVM where to find the JavaFX modules.
    • For IntelliJ IDEA: Go to Run -> Edit Configurations. In the VM options field, add the following: 
      --module-path /Users/<user>/Downloads/javafx-sdk-11/lib --add-modules=javafx.controls,javafx.fxml,javafx.graphics
      Replace /Users/<user>/Downloads/javafx-sdk-11/lib with the actual path to your JavaFX SDK’s lib folder.
    • For command-line execution: 
      java --module-path /path/to/your/javafx-sdk-11/lib --add-modules=javafx.controls,javafx.fxml,javafx.graphics -jar YourApplication.jar

This approach makes the JavaFX classes available to your project, resolving the “missing components” error.

Solution 2: Integrating JavaFX with Maven

If you’re using Maven as your build tool, dependency management becomes much simpler.

Steps:

  1. Create a Maven Project with JavaFX Archetype: Start with a Maven project, ideally using a JavaFX archetype if available or configuring your pom.xml manually.

  2. Set JDK 11: Ensure your project uses JDK 11.

  3. Add JavaFX Dependencies: Include the necessary JavaFX dependencies in your pom.xml:

    <dependencies>
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-controls</artifactId>
        <version>11</version>
    </dependency>
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-fxml</artifactId>
        <version>11</version>
    </dependency>
    <!-- Include platform-specific dependencies if needed -->
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-graphics</artifactId>
        <version>11</version>
        <classifier>win</classifier> <!-- Or 'mac' or 'linux' -->
    </dependency>
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-controls</artifactId>
        <version>11</version>
        <classifier>win</classifier> <!-- Or 'mac' or 'linux' -->
    </dependency>
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-fxml</artifactId>
        <version>11</version>
        <classifier>win</classifier> <!-- Or 'mac' or 'linux' -->
    </dependency>
</dependencies>

    Note: Maven automatically resolves the correct classifier (e.g., win, mac, linux) for your platform based on your environment. The javafx-controls and javafx-fxml dependencies implicitly pull in javafx-graphics and javafx-base.

  4. Configure the javafx-maven-plugin: To run your application easily, add the javafx-maven-plugin to your pom.xml:

    <build>
    <plugins>
        <plugin>
            <groupId>org.openjfx</groupId>
            <artifactId>javafx-maven-plugin</artifactId>
            <version>0.0.8</version> <!-- Check for the latest version -->
            <configuration>
                <mainClass>your.package.MainApp</mainClass>
            </configuration>
        </plugin>
    </plugins>
</build>

    Replace your.package.MainApp with the fully qualified name of your main application class.

  5. Run: Execute your application using:

    mvn compile javafx:run

Maven handles the download and inclusion of the necessary JavaFX JARs, including platform-specific versions.

module YourProjectName { 
    requires javafx.fxml;
    requires javafx.controls;
    requires javafx.graphics;
    opens sample;
}

Solution 3: Leveraging Gradle for JavaFX Projects

Similar to Maven, Gradle simplifies JavaFX integration.

Steps:

  1. Create a Gradle Project: Set up a new Gradle project.

  2. Set JDK 11: Configure your project to use JDK 11.

  3. Add JavaFX Dependencies: In your build.gradle file, add the JavaFX dependencies:

    plugins {
    id 'java'
    id 'application'
    id 'org.openjfx.javafxplugin' version '0.0.10' // Check for latest version
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.openjfx:javafx-controls:11:win' // Adjust classifier for your OS: win, mac, linux
    implementation 'org.openjfx:javafx-fxml:11:win'
}

application {
    mainClass = 'your.package.MainApp' // Replace with your main class
}

javafx {
    version = "11"
    // Optionally specify a specific OS if needed, e.g., "win"
    // os = ["win", "mac", "linux"]
}

    Adjust the version and classifier (e.g., win, mac, linux) according to your needs.

  4. Run: Execute your application using:

    gradle javafxRun

    Or, if you haven’t used the plugin:

    gradle run

    (Ensure your application plugin configuration points to your mainClass).

Gradle’s javafxplugin automates much of the setup.

Solution 4: Addressing the IllegalAccessError with module-info.java

A common cause for failure, especially when running directly from an IDE or when the module system is strictly enforced, is the IllegalAccessError. This occurs because the JavaFX runtime needs to use reflection to access your application classes (and vice versa), but the module system prevents this by default for encapsulation.

The Fix: Create a module-info.java file in your src/main/java directory.

For Non-Modular Projects (but still using module system features):

If you’ve added JavaFX as a library (Solution 1) or via Maven/Gradle, you might need a module-info.java to grant reflective access.

module YourProjectName {
    requires javafx.fxml;
    requires javafx.controls;
    requires javafx.graphics; // Often needed as well
    opens your.package.name to javafx.graphics, javafx.fxml;
}
  • Replace YourProjectName with a unique name for your module.
  • Replace your.package.name with the package where your main application class and controllers reside.
  • The opens your.package.name to javafx.graphics, javafx.fxml; line explicitly allows the JavaFX modules to use reflection on your application’s classes.

If you don’t want to explicitly make your project modular, an alternative is to run using Maven/Gradle tasks (as described above), as these build tools often inject necessary runtime parameters to bypass the strict module access checks for simple execution.

module thisIsTheNameOfYourProject {
    requires javafx.fxml;
    requires javafx.controls;
    requires javafx.graphics;
    opens sample;
}

Solution 5: IntelliJ IDEA’s JavaFX Project Wizard

JetBrains has introduced a dedicated JavaFX project wizard in IntelliJ IDEA, which significantly simplifies the setup process.

Recommendation: For new JavaFX projects or if you’re struggling with existing ones, use this wizard.

Benefits:

  • Automated Setup: Creates a properly configured project structure.
  • Includes Dependencies: Automatically adds necessary JavaFX dependencies via Maven or Gradle.
  • Correct Module Configuration: Generates a functional module-info.java file.
  • Resource Handling: Demonstrates correct placement and loading of FXML files.
  • IDE Integration: Allows direct running and debugging from the IDE without manual VM option configuration.

Simply go to File -> New -> Project... and select JavaFX from the project types.

Solution 6: VM Options in IntelliJ IDEA Run Configurations

A common mistake is placing --module-path and --add-modules in the “Program arguments” field instead of “VM options” within IntelliJ’s Run/Debug Configurations.

Correct Placement:

  1. Go to Run -> Edit Configurations...
  2. Select your application’s configuration.
  3. Click on Modify Options (or the + icon).
  4. Select Add VM options.
  5. Enter the JavaFX path and modules: 
    --module-path "C:\path\to\your\javafx-sdk-11\lib" --add-modules=javafx.controls,javafx.fxml,javafx.graphics
    (Adjust the path for your operating system.)

This ensures the JVM correctly processes the JavaFX modules at runtime.

--module-path yourpathwheresdkislocated/lib --add-modules=javafx.controls,javafx.fxml
java --module-path yourpathwheresdkislocated/lib --add-modules=javafx.controls,javafx.fxml -jar YourJar.jar

Solution 7: Running from the Terminal with jpackage

For creating distributable applications, jpackage is the tool to use. While this is more about packaging, ensuring your project is set up correctly is key. If you are building a native executable, you typically won’t need the --module-path and --add-modules flags in the final executable, as jpackage embeds the necessary JVM and modules. However, during development, the configurations mentioned above are crucial.

For more advanced distribution scenarios, consider tools like JPackageScriptFX or Badass JLink Plugin for Gradle, which can help bundle your JavaFX application into a self-contained installer.

module my.project {
    requires javafx.fxml;
    requires javafx.controls;
    opens my.project to javafx.graphics;
    exports my.project;
}
