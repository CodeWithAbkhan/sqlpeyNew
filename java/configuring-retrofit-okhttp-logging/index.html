“Configuring Network Request Logging in Retrofit 2 with OkHttp Interceptors”

When working with the popular networking library Retrofit 2 in Android development, gaining visibility into the actual HTTP requests being sent and the responses received is crucial for debugging and performance tuning. Since Retrofit 2 leverages OkHttp under the hood, the standard approach involves integrating OkHttp’s Interceptor mechanism, specifically the HttpLoggingInterceptor.

This post details various effective methods and configuration patterns to enable detailed logging of network calls.

Integrating HttpLoggingInterceptor for Request and Response Visibility

The primary mechanism for logging in Retrofit 2 environments is the HttpLoggingInterceptor. This requires adding the appropriate dependency to your build.gradle file.

Dependency Setup

Ensure you have the correct version of the logging interceptor. For recent versions (as of the time of this writing, referencing versions like 4.11.0 or similar):

implementation 'com.squareup.okhttp3:logging-interceptor:4.11.0'
// Ensure Retrofit and Gson converters are also present if needed
// implementation 'com.squareup.retrofit2:retrofit:x.x.x'
// implementation 'com.squareup.retrofit2:converter-gson:x.x.x'

Basic Retrofit Configuration with Logging

The interceptor must be built into the OkHttpClient instance before it is passed to the Retrofit.Builder.

Solution Example 1: Direct Configuration

This demonstrates the standard setup where the HttpLoggingInterceptor is initialized and its logging level is set before client construction.

import okhttp3.OkHttpClient;
import okhttp3.logging.HttpLoggingInterceptor;
import retrofit2.Retrofit;
import retrofit2.converter.gson.GsonConverterFactory;

// ... inside your service generator class

HttpLoggingInterceptor interceptor = new HttpLoggingInterceptor();
// Set the desired detail level
interceptor.setLevel(HttpLoggingInterceptor.Level.BODY);

OkHttpClient client = new OkHttpClient.Builder()
    .addInterceptor(interceptor)
    .build();

Retrofit retrofit = new Retrofit.Builder()
    .baseUrl("https://api.dataendpoint.com/")
    .client(client)
    .addConverterFactory(GsonConverterFactory.create())
    .build();

return retrofit.create(YourApiService.class);

// Note: For newer OkHttp versions, you might see deprecation warnings for setLevel(), 
// which can be addressed by using interceptor.level(HttpLoggingInterceptor.Level.BODY);

Handling Deprecated Methods and Log Levels

Older documentation or samples might reference setLevel or setLogLevel(RestAdapter.LogLevel.FULL) from older libraries. In Retrofit 2/OkHttp 3+, use the specific levels provided by HttpLoggingInterceptor.Level:

  • Level.BODY: Logs headers, the request body, response headers, and the response body. This is typically the most useful for debugging.
  • Level.HEADERS: Logs only headers for requests and responses.
  • Level.BASIC: Logs only the request line and the response status line (e.g., 200 OK). Useful for quick checks without revealing payload data.
  • Level.NONE: Disables logging.

Alternative Configuration Structure (Solution 2)

When dealing with beta versions or slight API shifts, the confirmation is to add the interceptor to the client’s interceptor list:

import okhttp3.OkHttpClient;
import okhttp3.logging.HttpLoggingInterceptor;
import static okhttp3.logging.HttpLoggingInterceptor.Level.BODY;

HttpLoggingInterceptor logging = new HttpLoggingInterceptor();  
logging.setLevel(BODY);

OkHttpClient httpClient = new OkHttpClient.Builder()
    // Add logging as the final interceptor if order matters relative to others
    .addInterceptor(logging)  
    .build();

Retrofit retrofit = new Retrofit.Builder()  
   .baseUrl("https://mobile.service.net/")
   .addConverterFactory(GsonConverterFactory.create())
   .client(httpClient)
   .build();

Logging with Custom Interceptors or Timber

Sometimes, you require more control over how logs are displayed or need to integrate with specific logging frameworks like Timber, or capture request body information that HttpLoggingInterceptor might omit in certain configurations.

Solution 3: Custom Interceptor for Detailed Timber Logging

This approach creates a dedicated Interceptor that uses Timber to log request timing, headers, and request/response bodies. A crucial point here is that reading the response body consumes the stream, requiring you to clone the response and build a new one to return.

import okhttp3.*;
import okio.Buffer;
import timber.log.Timber;
import java.io.IOException;

public class TimberLoggingInterceptor implements Interceptor {
    @Override
    public Response intercept(Chain chain) throws IOException {
        Request request = chain.request();

        long t1 = System.nanoTime();
        Timber.i("Sending request %s on %s%n%s", request.url(), chain.connection(), request.headers());
        Timber.v("REQUEST BODY BEGIN\n%s\nREQUEST BODY END", bodyToString(request));

        Response response = chain.proceed(request);

        ResponseBody responseBody = response.body();
        String responseBodyString = response.body().string(); // Consumes the original stream

        // Rebuild response with the original body content stream
        Response newResponse = response.newBuilder()
            .body(ResponseBody.create(responseBody.contentType(), responseBodyString.getBytes()))
            .build();

        long t2 = System.nanoTime();
        Timber.i("Received response for %s in %.1fms%n%s", response.request().url(), (t2 - t1) / 1e6d, response.headers());
        Timber.v("RESPONSE BODY BEGIN:\n%s\nRESPONSE BODY END", responseBodyString);

        return newResponse;
    }

    private static String bodyToString(final Request request){
        try {
            final Request copy = request.newBuilder().build();
            final Buffer buffer = new Buffer();
            copy.body().writeTo(buffer);
            return buffer.readUtf8();
        } catch (final IOException e) {
            return "Body read failed";
        }
    }
}

Usage: Add this custom interceptor to the OkHttpClient.Builder.

Interceptor Ordering: Application vs. Network Interceptors

OkHttp processes interceptors in the order they are added, and there’s a distinction between Application Interceptors (addInterceptor) and Network Interceptors (addNetworkInterceptor). Network interceptors run after application interceptors and handle raw network data, which can be significant when dealing with dynamic headers or gzip compression.

Solution 4: Combining Dynamic Headers and Logging via Network Interceptors

If you need to add headers dynamically (like authorization tokens) before logging the final request, adding both as Network Interceptors can be effective, as network interceptors execute later in the chain.

import okhttp3.OkHttpClient;
import okhttp3.Request;
import okhttp3.Response;
import okhttp3.logging.HttpLoggingInterceptor;
import static okhttp3.logging.HttpLoggingInterceptor.Level.BODY;

OkHttpClient httpClient = new OkHttpClient.Builder()
    // Application interceptor (runs first) for pre-network tasks, if needed
    // .addInterceptor(new AppSpecificInterceptor()) 
    
    // Network Interceptor for dynamic header injection
    .addNetworkInterceptor(chain -> {
        Request request = chain.request().newBuilder()
            .addHeader("Authorization-Token", "SecureValueXYZ123")
            .build();
        return chain.proceed(request);
    })
    // Network Interceptor for logging (runs after injection)
    .addNetworkInterceptor(new HttpLoggingInterceptor().setLevel(BODY))
    .build();

// Then build Retrofit using httpClient...

Handling Specific Scenarios

Encapsulating Logging Setup (Solution 5)

For cleaner code separation, especially in large projects, creating a utility class to manage the OkHttpClient setup is beneficial.

public class LoggingClientFactory {

    public static OkHttpClient createLoggingClient() {
        HttpLoggingInterceptor loggingInterceptor = new HttpLoggingInterceptor();
        loggingInterceptor.setLevel(HttpLoggingInterceptor.Level.BODY);

        OkHttpClient okHttpClient = new OkHttpClient.Builder()
                .addInterceptor(loggingInterceptor)
                .build();

        return okHttpClient;
    }
}

// Usage in Retrofit Builder:
Retrofit retrofit = new Retrofit.Builder()
    .baseUrl("https://service.org/")
    .addConverterFactory(GsonConverterFactory.create())
    .client(LoggingClientFactory.createLoggingClient()) // Called here
    .build();

Kotlin Implementation (Solution 10)

The configuration pattern is syntactically different but functionally identical in Kotlin:

        .addConverterFactory(GsonConverterFactory.create())

Filtering Log Output (Solution 15)

If Level.BODY produces too much noise, you can implement a custom Logger within HttpLoggingInterceptor to selectively hide specific headers.

private static final String[] RESPONSE_PATTERNS = {
    "Server", "Set-Cookie", "Content-Length" // Headers to suppress
};

HttpLoggingInterceptor interceptor = new HttpLoggingInterceptor(message -> {
    for (String pattern: RESPONSE_PATTERNS) {
        if (message.startsWith(pattern)) {
            return; // Skip logging this line
        }
    }
    android.util.Log.d("RETROFIT_FILTERED", message);
});
interceptor.setLevel(HttpLoggingInterceptor.Level.BODY);

Alternative Debugging Tools

While interceptors are excellent for in-app logging, external tools offer a desktop-based, persistent view of network traffic, often without requiring code changes for every endpoint.

  1. Facebook Stetho (Solution 12): Integrates with Chrome Developer Tools, allowing inspection of network traffic via chrome://inspect.

    final OkHttpClient.Builder builder = new OkHttpClient.Builder();
if (BuildConfig.DEBUG) {
    // Requires Stetho dependency
    builder.networkInterceptors().add(new StethoInterceptor()); 
}
// Use builder for OkHttpClient construction

FAQs on Configuring Retrofit OkHttp Logging

Q: What is the recommended HttpLoggingInterceptor level for debugging?

ANS: Level.BODY is generally recommended as it reveals the request method, URL, headers, request payload, response status, headers, and the response body, providing the richest debugging context.

Q: Why might I get java lang ClassNotFoundException when using logging interceptors

ANS: This often relates to dependency conflicts or version mismatches between OkHttp, Retrofit, and the logging interceptor library. In some specific cases (like with Dagger), removing an explicit com.squareup.okhttp3:okhttp dependency might resolve conflicts if Retrofit already transitively includes a compatible version.

Q: Should I use addInterceptor or addNetworkInterceptor for logging

ANS: HttpLoggingInterceptor can be used with both. Using addNetworkInterceptor (.addNetworkInterceptor()) ensures logging occurs after application interceptors have modified the request, often providing the most accurate view of what OkHttp sends over the wire. It’s critical to place the logging interceptor last if you chain multiple interceptors.

Q: How do I log request body content if it's not showing with Level BASIC

ANS: Level.BASIC does not log request or response bodies. You must use Level.BODY or implement a custom Interceptor (as shown in Solution 3 or Solution 9) to manually extract and log the request payload.
