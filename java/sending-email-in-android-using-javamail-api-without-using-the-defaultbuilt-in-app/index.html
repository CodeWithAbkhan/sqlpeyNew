Solved: How to Send Emails Programmatically in Android Using Gmail SMTP

Sending emails directly from an Android application can be a powerful feature, enabling features like user feedback, notifications, or automated reports. This guide will walk you through implementing email sending functionality using the JavaMail API with Gmail’s SMTP server. We’ll cover the essential code, required permissions, and address common issues like network operations on the main thread.

Core Implementation: The GMailSender Class

The foundation of sending emails programmatically in Android involves a GMailSender class that leverages the JavaMail API. This class handles the SMTP connection, authentication, and message composition.

MailSenderActivity.java (Activity Logic)

This Java class demonstrates how to initiate the email sending process from an Android activity.

// MailSenderActivity.java
package com.yourpackage.yourapp;

import android.app.Activity;
import android.os.Bundle;
import android.view.View;
import android.widget.Button;
import android.util.Log;

import com.yourpackage.yourapp.GMailSender; // Assuming GMailSender is in the same package

public class MailSenderActivity extends Activity {
    
    @Override
    public void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.main_layout_for_email); // Ensure you have a layout file named main_layout_for_email.xml with a send button
        
        final Button sendButton = findViewById(R.id.send_email_button); // Ensure your layout has a button with this ID
        
        sendButton.setOnClickListener(new View.OnClickListener() {
            public void onClick(View v) {
                // Execute email sending in a background thread or using AsyncTask
                new Thread(new Runnable() {
                    @Override
                    public void run() {
                        try {   
                            // Replace with your actual email and password
                            GMailSender sender = new GMailSender("your_email@gmail.com", "your_password"); 
                            
                            // Subject, Body, Sender email, Recipient email(s)
                            sender.sendMail(
                                "Test Subject from Android",   
                                "This is the body of the email sent from the Android app.",   
                                "your_email@gmail.com",   
                                "recipient_email@example.com" // Can be a comma-separated string for multiple recipients
                            );   
                            Log.d("MailSender", "Email sent successfully!");
                        } catch (Exception e) {   
                            Log.e("MailSender", "Error sending email", e);   
                        } 
                    }
                }).start();
            }
        });
    }
}

GMailSender.java (Email Sending Logic)

This class contains the core logic for connecting to Gmail’s SMTP server and sending emails.

// GMailSender.java
package com.yourpackage.yourapp;

import android.util.Log;
import java.io.ByteArrayInputStream;
import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.security.Security;
import java.util.Properties;
import javax.activation.DataHandler;
import javax.activation.DataSource;
import javax.mail.Message;
import javax.mail.PasswordAuthentication;
import javax.mail.Session;
import javax.mail.Transport;
import javax.mail.internet.InternetAddress;
import javax.mail.internet.MimeMessage;

public class GMailSender extends javax.mail.Authenticator {   
    private String mailhost = "smtp.gmail.com";   
    private String user;   
    private String password;   
    private Session session;   
  
    // Add JSSE provider for SSL support
    static {   
        // This line might require the JSSEProvider class to be available
        // If you encounter 'No provider for SSLContext' errors, ensure you have the JSSEProvider class.
        // See Solution 18 regarding 'No provider for smtp' and potential issues with mail.jar.
        Security.addProvider(new JSSEProvider());   
    }  
  
    public GMailSender(String user, String password) {   
        this.user = user;   
        this.password = password;   
  
        Properties props = new Properties();   
        props.setProperty("mail.transport.protocol", "smtp");   
        props.setProperty("mail.host", mailhost);   
        props.put("mail.smtp.auth", "true");   
        props.put("mail.smtp.port", "465"); // Standard SSL port for Gmail   
        props.put("mail.smtp.socketFactory.port", "465");   
        props.put("mail.smtp.socketFactory.class", "javax.net.ssl.SSLSocketFactory");   
        props.put("mail.smtp.socketFactory.fallback", "false");   
        props.setProperty("mail.smtp.quitwait", "false");   
  
        session = Session.getDefaultInstance(props, this);   
    }   
  
    @Override
    protected PasswordAuthentication getPasswordAuthentication() {   
        return new PasswordAuthentication(user, password);   
    }   
  
    public synchronized void sendMail(String subject, String body, String sender, String recipients) throws Exception {   
        try{
            MimeMessage message = new MimeMessage(session);   
            DataHandler handler = new DataHandler(new ByteArrayDataSource(body.getBytes(), "text/plain"));   
            message.setSender(new InternetAddress(sender));   
            message.setSubject(subject);   
            message.setDataHandler(handler);   
            if (recipients.indexOf(',') > 0)   
                message.setRecipients(Message.RecipientType.TO, InternetAddress.parse(recipients));   
            else  
                message.setRecipient(Message.RecipientType.TO, new InternetAddress(recipients));   
            
            // Send the email
            Transport.send(message);   
            Log.d("GMailSender", "Message sent successfully.");
        } catch(Exception e){
            Log.e("GMailSender", "Failed to send message.", e);
            throw e; // Re-throw to catch in the calling activity
        }
    }   
  
    // Inner class for handling byte array data
    public class ByteArrayDataSource implements DataSource {   
        private byte[] data;   
        private String type;   
  
        public ByteArrayDataSource(byte[] data, String type) {   
            super();   
            this.data = data;   
            this.type = type;   
        }   
  
        public ByteArrayDataSource(byte[] data) {   
            this(data, "application/octet-stream"); // Default type   
        }   
  
        public void setType(String type) {   
            this.type = type;   
        }   
  
        @Override
        public String getContentType() {   
            if (type == null)   
                return "application/octet-stream";   
            else  
                return type;   
        }   
  
        @Override
        public InputStream getInputStream() throws IOException {   
            return new ByteArrayInputStream(data);   
        }   
  
        @Override
        public String getName() {   
            return "ByteArrayDataSource"; // Arbitrary name   
        }   
  
        @Override
        public OutputStream getOutputStream() throws IOException {   
            throw new IOException("Not Supported"); // Read-only data source   
        }   
    }   
}

JSSEProvider.java (SSL Support)

This class provides the necessary JSSE (Java Secure Socket Extension) provider for secure SSL connections.

// JSSEProvider.java
package com.yourpackage.yourapp;

import java.security.AccessController;
import java.security.Provider;

/**
 * Custom JSSE Provider for Android compatibility with JavaMail.
 * This is a simplified version and might require adjustments based on your Android build environment.
 */
public final class JSSEProvider extends Provider {

    public JSSEProvider() {
        // "HarmonyJSSE" is a common identifier for this provider in Android contexts.
        super("HarmonyJSSE", 1.0, "Harmony JSSE Provider for Android");
        AccessController.doPrivileged(new java.security.PrivilegedAction<Void>() {
            public Void run() {
                // Registering SSLContext and Key/Trust Manager Factory implementations
                put("SSLContext.TLS", "org.apache.harmony.xnet.provider.jsse.SSLContextImpl");
                put("Alg.Alias.SSLContext.TLSv1", "TLS");
                put("KeyManagerFactory.X509", "org.apache.harmony.xnet.provider.jsse.KeyManagerFactoryImpl");
                put("TrustManagerFactory.X509", "org.apache.harmony.xnet.provider.jsse.TrustManagerFactoryImpl");
                return null;
            }
        });
    }
}

Handling Network Operations on the Main Thread

Android strictly forbids performing network operations (like sending emails) directly on the main UI thread. Doing so will result in a NetworkOnMainThreadException. You must execute these operations in the background.

Solution 5 (Recommended): Using AsyncTask

AsyncTask provides a simple way to handle background operations and update the UI.

// Inside your Activity or a dedicated class
public void sendEmailOnClick(View view) { // Call this from your button's onClick
    new SendEmailAsyncTask().execute();
}

class SendEmailAsyncTask extends AsyncTask<Void, Void, Boolean> {
    private static final String TAG = "SendEmailTask";
    private GMailSender mailSender;

    @Override
    protected void onPreExecute() {
        super.onPreExecute();
        // Initialize GMailSender with your credentials
        mailSender = new GMailSender("your_email@gmail.com", "your_password"); 
        Log.d(TAG, "Starting email sending task...");
    }

    @Override
    protected Boolean doInBackground(Void... params) {
        try {
            // You can also include subject, body, sender, and recipient details here
            // or pass them as parameters to the AsyncTask.
            mailSender.sendMail(
                "Task Subject", 
                "This email is sent via AsyncTask.", 
                "your_email@gmail.com", 
                "recipient_email@example.com"
            );
            return true; // Indicate success
        } catch (Exception e) {
            Log.e(TAG, "Email sending failed in AsyncTask", e);
            return false; // Indicate failure
        }
    }

    @Override
    protected void onPostExecute(Boolean result) {
        super.onPostExecute(result);
        if (result) {
            Toast.makeText(getApplicationContext(), "Email sent successfully!", Toast.LENGTH_SHORT).show();
        } else {
            Toast.makeText(getApplicationContext(), "Failed to send email.", Toast.LENGTH_SHORT).show();
        }
    }
}

Adding Attachments

To include attachments, you’ll need to modify the GMailSender class or create a separate mechanism. Solution 2 and Solution 13 provide insights into this.

Extending GMailSender for Attachments (Conceptual):

You would typically create a Multipart object, add the text body as a MimeBodyPart, and then add the attachment as another MimeBodyPart using FileDataSource. Finally, set the message content to this Multipart object.

// Inside GMailSender or a similar class
// ...

import javax.mail.BodyPart;
import javax.mail.Multipart;
import javax.mail.internet.MimeBodyPart;
import javax.mail.internet.MimeMultipart;
import javax.activation.FileDataSource; // For attachments

// ...

public void sendMailWithAttachment(String subject, String body, String sender, String recipients, String attachmentPath) throws Exception {
    Properties props = new Properties(); // Same properties as in constructor
    // ... (configure properties) ...
    Session session = Session.getDefaultInstance(props, this);

    MimeMessage message = new MimeMessage(session);
    message.setFrom(new InternetAddress(sender));
    // ... (set recipients) ...
    message.setSubject(subject);

    // Create a multipart message
    Multipart multipart = new MimeMultipart();

    // Text part
    BodyPart messageBodyPart = new MimeBodyPart();
    messageBodyPart.setText(body);
    multipart.addBodyPart(messageBodyPart);

    // Attachment part
    if (attachmentPath != null && !attachmentPath.isEmpty()) {
        messageBodyPart = new MimeBodyPart();
        DataSource source = new FileDataSource(attachmentPath);
        messageBodyPart.setDataHandler(new DataHandler(source));
        messageBodyPart.setFileName(new java.io.File(attachmentPath).getName()); // Extract filename
        multipart.addBodyPart(messageBodyPart);
    }

    // Set the content of the message
    message.setContent(multipart);

    Transport.send(message);
    Log.d("GMailSender", "Message with attachment sent successfully.");
}

Remember to handle file permissions (READ_EXTERNAL_STORAGE) if accessing files outside your app’s private storage.

Authentication and Security Considerations

  • Gmail Security: Google strongly discourages the use of “less secure app access” (Solution 20, Solution 23). The modern and secure approach is to use App Passwords. If you have 2-Factor Authentication enabled for your Google account, you must generate an App Password specifically for your Android application and use that instead of your regular Google account password. You can generate App Passwords here: https://myaccount.google.com/app-passwords .
  • Gmail SMTP Issues: Google may flag repeated SMTP requests from different locations as suspicious activity (Solution 9). Using an App Password can mitigate some of these issues. Consider using alternative SMTP providers if you encounter persistent problems.
  • Hardcoded Credentials: Avoid hardcoding your email address and password directly in the source code. Store them securely, perhaps using Android’s EncryptedSharedPreferences or by fetching them from a secure backend service.
  • Alternative Ports: While port 465 (SSL) is common for Gmail, port 587 (STARTTLS) is also used (Solution 11). Ensure your GMailSender class is configured correctly for the chosen port.

Alternative Approaches

  • Using Libraries: Libraries like it.enricocandino:androidmail (Solution 19) or GmailBackground (Solution 8) abstract away much of the complexity, offering easier integration. Kotlin-based solutions (Solution 21) are also becoming popular.
  • Server-Side Sending: As mentioned, a server-side script (e.g., PHP) that handles email sending via an HTTP request from your Android app is a robust and secure method, keeping your email credentials off the device.
  • Intents (User Interaction): If you want the email to be sent using the user’s default email client (like the Gmail app), you can use an Intent with ACTION_SEND. This requires user interaction to confirm and send.
// Example using Intent for user-initiated email
Intent emailIntent = new Intent(Intent.ACTION_SEND);
emailIntent.putExtra(Intent.EXTRA_EMAIL, new String[]{"recipient@example.com"});
emailIntent.putExtra(Intent.EXTRA_SUBJECT, "Feedback");
emailIntent.putExtra(Intent.EXTRA_TEXT, "I would like to provide feedback...");
emailIntent.setType("message/rfc822"); // For plain text email
startActivity(Intent.createChooser(emailIntent, "Send Email using..."));

Troubleshooting Common Errors

  • NetworkOnMainThreadException: As detailed above, always use background threads or AsyncTask.
  • No provider for smtp or No provider for SSLContext: Ensure you have the correct JavaMail JARs (Solution 12, Solution 18) and potentially the JSSEProvider class correctly implemented and included. Check your dependencies.
  • Authentication Failures: Double-check your email address, password (or App Password), and ensure the SMTP server details (host, port) are correct. Verify Gmail account settings (e.g., “less secure apps” or App Passwords).
  • Connection Issues (Could not connect to SMTP host): Verify your internet connection and that the firewall isn’t blocking the connection. Ensure the SMTP host and port are accurate for Gmail.

FAQs on Sending Emails Programmatically in Android

Q: What are the minimum required JAR files for JavaMail in Android

ANS: Traditionally, you would need mail.jar and activation.jar. For modern Android development, consider using Gradle dependencies or specific Android ports of JavaMail, as manual JAR inclusion can be complex. Refer to Solution 10 for potential Gradle dependencies.

Q: How do I handle Gmail security for sending emails

ANS: For secure sending, especially with 2-Factor Authentication enabled on your Gmail account, generate an “App Password” from your Google account security settings and use that password in your application instead of your regular password.

Q: Can I send emails with attachments

ANS: Yes, you can send emails with attachments. This typically involves using Multipart and MimeBodyPart to add file data to the email message. Refer to Solution 2, Solution 13, and the conceptual example in this guide.

Q: What is the correct SMTP server and port for Gmail

ANS: For Gmail, the standard settings are:

  • SMTP Host: smtp.gmail.com
  • SSL Port: 465
  • STARTTLS Port: 587 Ensure your code uses the correct port and enables SSL/TLS as required.

Q: How to avoid NetworkOnMainThreadException

ANS: Never perform network operations directly on the main UI thread. Use background threads, AsyncTask (Solution 5), IntentService, or coroutines (Kotlin) to execute network tasks off the main thread.

Q: What if I get an error about no provider for smtp

ANS: This error often indicates missing or incompatible JavaMail JAR files or issues with SSL/TLS provider registration. Ensure you have the correct libraries (Solution 12, Solution 18) and that your JSSEProvider class is correctly set up if needed.

Q: Is there a simpler way than writing the GMailSender class myself

ANS: Yes, several libraries and solutions simplify email sending in Android. Libraries like GmailBackground (Solution 8), AndroidMail (Solution 19), or Kotlin-specific approaches (Solution 21) offer more streamlined integration.
