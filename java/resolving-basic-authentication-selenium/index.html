“Resolving Basic Authentication Issues in Selenium WebDriver Across Browsers”

When automating web interactions using Selenium WebDriver, triggering pages protected by Basic HTTP Authentication (the username/password prompt) often presents a hurdle. Recent browser updates, particularly in Chromium, have restricted embedding credentials directly in subresource URLs. How can automation engineers reliably bypass this security feature across different browser environments?

We examine several effective approaches documented by the community to tackle this exact scenario.

Solution Strategies for Selenium Basic Auth Bypass

Method 1: Double Navigation Approach (URL Embedding First)

One technique focuses on leveraging the initial navigation with embedded credentials, even if it only works for the main domain resource and not subsequent subresources.

For the initial domain access:

from selenium import webdriver

# Initialize driver (Example using Chrome)
driver = webdriver.Chrome()

# 1. Access the protected domain with embedded credentials
driver.get("http://user_name:secret_pass@server_host:8080")

# 2. Navigate to the desired subresource path without credentials in the URL
# This step relies on the authorization context established by the first call.
driver.get("http://server_host:8080/project_page")

A related workaround, especially noted for environments like Chrome 62, ChromeDriver 2.33, and Firefox 56, involves using promise chaining (in a JavaScript context, adapted here conceptually for sequence control):

// Conceptual representation for sequential execution in WebDriver context
driver
    .get('http://admin:admin@localhost:8080')
    .then( () => driver.get('http://localhost:8080') );

This sequence is thought to establish the authorization header on the first call, and the second call navigates cleanly, maintaining the established context for subresources.

Method 2: Utilizing Chrome Options for Extension Injection

If direct URL embedding is consistently blocked, injecting a small extension that automatically handles credential relay can be effective. This requires packaging the logic into a ZIP file compatible with Chrome Options.

from selenium import webdriver

options = webdriver.ChromeOptions()
# Ensure 'credentials.zip' contains the logic to intercept auth prompts
options.add_extension(r'C:\dev\credentials.zip')

# Initialize driver with options
driver = webdriver.Chrome(options=options)
driver.get("http://localhost:8080/protected_resource")

Reference material for creating such extensions can be found externally here .

Method 3: Leveraging Selenium 4’s HasAuthentication Interface

Selenium 4 introduced native support for handling various authentication types, including Basic Authentication, via the HasAuthentication interface. This is the most modern and recommended approach if using Selenium 4+.

This method abstracts away browser-specific quirks:

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.devtools.HasAuthentication;
import org.openqa.selenium.devtools.UsernameAndPassword;

WebDriver driver = new ChromeDriver();

// Cast the driver to the interface that supports authentication registration
if (driver instanceof HasAuthentication authenticationDriver) {
    authenticationDriver.register(() -> new UsernameAndPassword("user_name", "secret_pass"));
}

driver.get("http://your-site.com/protected");

This cleanly separates credential management from the URL string.

Method 4: Bypassing via JavaScript Executor for New Tabs (Older Chrome/Driver Versions)

For environments where Chrome Driver updates (like post-version 59) blocked direct authentication via driver.get(), one fallback is using the JavascriptExecutor to open a new window or tab using the authenticated URL, thereby leveraging the browser’s native handling for new windows.

import org.openqa.selenium.JavascriptExecutor;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

WebDriver driver = new ChromeDriver();
driver.get("https://www.google.com"); // Load an initial page first

JavascriptExecutor jse = (JavascriptExecutor) driver;
String authUrl = "https://username:secret_pass@server_host:8080/page";

// Execute JavaScript to open a new tab with the authenticated URL
jse.executeScript("window.open('"+authUrl+"')");

Method 5: Version Compatibility Check (Pre-Selenium 4 Context)

It is important to note that for older setups, Basic Authentication functionality remained operational with specific stable stacks:

  • Selenium 3.4.0
  • geckodriver v0.18.0
  • chromedriver v2.31.488763
  • Google Chrome 60.x / Mozilla Firefox 53.0

For environments using these versions, direct navigation might still succeed:

Java Example for Firefox (Older Stack):

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.firefox.FirefoxDriver;

System.setProperty("webdriver.gecko.driver", "C:\\Utility\\BrowserDrivers\\geckodriver.exe");
WebDriver driver = new FirefoxDriver();
driver.navigate().to("http://admin:pass@the-internet.herokuapp.com/basic_auth");

Java Example for Chrome (Older Stack):

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.chrome.ChromeOptions;

System.setProperty("webdriver.chrome.driver", "C:\\Utility\\BrowserDrivers\\chromedriver.exe");
ChromeOptions options = new ChromeOptions();
options.addArguments("start-maximized");
options.addArguments("--disable-extensions");
WebDriver driver = new ChromeDriver(options);
driver.navigate().to("http://admin:pass@the-internet.herokuapp.com/basic_auth");

Method 6: Inspecting Chrome Remote Debugging Parameters

For advanced debugging scenarios, especially within a Selenium Grid setup, solutions involving Chrome’s remote debugging protocol provide another path for passing authentication details, although this typically requires more intricate configuration outside the standard WebDriver calls.

FAQs on Resolving Basic Authentication Selenium

Q: Does embedding credentials in the URL always work for subresources

ANS: No, recent Chromium updates specifically block embedded credentials in subresource requests, causing them to fail as network errors.

Q: What is the primary benefit of using Selenium 4 HasAuthentication

ANS: Selenium 4’s HasAuthentication standardizes authentication handling, removing the reliance on browser-specific URL parsing tricks or extension hacks.

Q: Can I use the double get method reliably on the newest Chrome versions

ANS: While it worked for some users on older versions (Chrome 62), newer versions are less predictable for this method, making the Selenium 4 approach preferable.
