“Java Design Patterns in JDK: Identification and Examples”

Many fundamental design patterns are not just theoretical concepts but are actively implemented within the Java Standard Edition (SE) and Enterprise Edition (EE) APIs. Recognizing these patterns in the JDK can deepen your appreciation for robust software design and provide valuable insights for your own coding practices. This exploration delves into identifying and illustrating various design patterns as found in the Java JDK.

Creational Patterns

Creational patterns deal with object creation mechanisms, aiming to increase flexibility and reusability.

  • Abstract Factory: Characterized by creational methods that return the factory itself, which then creates other abstract or interface types.
    • javax.xml.parsers.DocumentBuilderFactory#newInstance()
    • javax.xml.transform.TransformerFactory#newInstance()
    • javax.xml.xpath.XPathFactory#newInstance()
    • Example: The java.sql interfaces, where concrete implementations are obtained from JDBC JARs upon driver registration, exemplify Abstract Factory usage.
  • Builder: Recognizable by creational methods that return the instance itself, facilitating fluent construction.
    • java.lang.StringBuilder#append() (unsynchronized)
    • java.lang.StringBuffer#append() (synchronized)
    • java.nio.ByteBuffer#put() (and other Buffer types)
    • java.util.stream.Stream.Builder
    • Example: java.lang.StringBuilder and java.lang.StringBuffer are classic Builder examples.
    StringBuilder sb = new StringBuilder();
sb.append("Hello").append(" ").append("World!");
String result = sb.toString(); // "Hello World!"
  • Factory Method: Identified by creational methods that return an implementation of an abstract or interface type.
    • java.util.Calendar#getInstance()
    • java.util.ResourceBundle#getBundle()
    • java.nio.charset.Charset#forName()
    • java.util.Collection#iterator() – Depending on the concrete Collection subclass, a specific Iterator implementation is created.
    • Example: Calendar.getInstance() returns a Calendar implementation suited to the default locale and time zone.
    import java.util.Calendar;
import java.util.Date;

Calendar calendar = Calendar.getInstance();
calendar.setTime(new Date());
System.out.println(calendar.getTime());
  • Prototype: Recognizable by creational methods that return a different instance of itself with the same properties.
    • java.lang.Object#clone() (requires implementing Cloneable)
    • Note: While clone() can be used as a prototype, its application requires careful consideration of object state and immutability.
  • Singleton: Characterized by creational methods that consistently return the same instance.
    • java.lang.Runtime#getRuntime()
    • java.awt.Desktop#getDesktop()
    • java.lang.System#getSecurityManager()
    • Example: Obtaining the single Runtime instance is a common Singleton use case.
    Runtime runtime = Runtime.getRuntime();
System.out.println("Available processors: " + runtime.availableProcessors());

Structural Patterns

Structural patterns are concerned with object composition and how classes and objects are combined to form larger structures.

  • Adapter: Recognizable by creational methods that accept an instance of a different abstract/interface type and return an implementation of its own or another abstract/interface type, which decorates or overrides the given instance.
    • java.util.Arrays#asList()
    • java.io.InputStreamReader(InputStream) (returns a Reader)
    • javax.xml.bind.annotation.adapters.XmlAdapter
    • Example: InputStreamReader adapts an InputStream to a Reader, allowing character-based reading from byte streams.
    import java.io.ByteArrayInputStream;
import java.io.InputStreamReader;
import java.io.Reader;

byte[] bytes = { 'H', 'e', 'l', 'l', 'o' };
ByteArrayInputStream bais = new ByteArrayInputStream(bytes);
Reader reader = new InputStreamReader(bais);
int data = reader.read(); // Reads 'H'
  • Bridge: Characterized by creational methods that take an instance of a different abstract/interface type and return an implementation of its own abstract/interface type, which delegates to the given instance.
    • While direct JDK examples are scarce, java.util.Collections#newSetFromMap() approaches this concept.
  • Composite: Recognizable by behavioral methods that accept an instance of the same abstract/interface type, organizing them into a tree structure.
    • java.awt.Container#add(Component)
    • javax.faces.component.UIComponent#getChildren()
    • Example: java.awt.Container allows adding multiple Component objects, forming a hierarchical UI structure.
  • Decorator: Recognizable by creational methods that accept an instance of the same abstract/interface type, adding additional behavior.
    • All subclasses of java.io.InputStream, OutputStream, Reader, and Writer often have constructors that take instances of their own type.
    • java.util.Collections provides methods like checkedXXX() and unmodifiableXXX().
    • Example: java.util.zip.GZIPInputStream wraps another InputStream to provide transparent GZIP decompression.
    import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.util.zip.GZIPInputStream;
import java.util.zip.GZIPOutputStream;

// Example of GZIPOutputStream (Decorator)
ByteArrayOutputStream baos = new ByteArrayOutputStream();
try (GZIPOutputStream gzipOut = new GZIPOutputStream(baos)) {
    gzipOut.write("Compressed data example.".getBytes());
}

// Example of GZIPInputStream (Decorator)
ByteArrayInputStream compressedData = new ByteArrayInputStream(baos.toByteArray());
try (GZIPInputStream gzipIn = new GZIPInputStream(compressedData)) {
    int data;
    while ((data = gzipIn.read()) != -1) {
        System.out.print((char) data);
    }
}
  • Facade: Characterized by behavioral methods that internally use instances of different, independent abstract/interface types, simplifying access for the end-user.
    • javax.faces.context.FacesContext
    • javax.faces.context.ExternalContext
    • Example: ExternalContext acts as a facade for operations like managing cookies, sessions, and requests.
  • Flyweight: Recognizable by creational methods returning cached instances, similar to the “multiton” concept.
    • java.lang.Integer#valueOf(int) (and for Boolean, Byte, Character, Short, Long, BigDecimal)
    • Example: Java’s autoboxing for primitive types like Integer reuses instances for values within a certain range.
    Integer i1 = Integer.valueOf(100);
Integer i2 = Integer.valueOf(100);
System.out.println(i1 == i2); // Often true due to caching
  • Proxy: Recognizable by creational methods that return an implementation of a given abstract/interface type, which in turn delegates to a different implementation of the same type.
    • java.lang.reflect.Proxy
    • java.rmi.*
    • javax.inject.Inject (via AOP proxies)
    • Example: The RMI package heavily utilizes proxies to enable remote method invocation.

Behavioral Patterns

Behavioral patterns deal with algorithms and the assignment of responsibilities between objects.

  • Chain of Responsibility: Recognizable by behavioral methods that (indirectly) invoke the same method on another implementation of the same abstract/interface type in a queue.
    • java.util.logging.Logger#log()
    • javax.servlet.Filter#doFilter()
    • Example: Servlet filters form a chain, processing requests sequentially.
  • Command: Characterized by behavioral methods within an abstract/interface type that invoke a method in an implementation of a different abstract/interface type, encapsulated by the command during its creation.
    • All implementations of java.lang.Runnable
    • All implementations of javax.swing.Action
    • Example: Runnable interfaces encapsulate a task to be executed, often by a separate thread or executor.
    Runnable myTask = () -> System.out.println("Executing a command task.");
new Thread(myTask).start();
  • Interpreter: Recognizable by behavioral methods returning a structurally different instance/type from the given instance/type.
    • java.util.Pattern (for regular expressions)
    • java.text.Normalizer
    • All subclasses of java.text.Format
    • Example: java.util.regex.Pattern interprets a regular expression string to perform matching operations.
  • Iterator: Recognizable by behavioral methods that sequentially return instances of a different type from a collection.
    • All implementations of java.util.Iterator
    • All implementations of java.util.Enumeration
    • Example: Iterating over a List using its Iterator.
    import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

List<String> fruits = new ArrayList<>();
fruits.add("Apple");
fruits.add("Banana");

Iterator<String> fruitIterator = fruits.iterator();
while (fruitIterator.hasNext()) {
    System.out.println(fruitIterator.next());
}
  • Mediator: Recognizable by behavioral methods that take an instance of a different abstract/interface type (often using the Command pattern) which delegates to or uses the given instance.
    • java.util.Timer (all scheduleXXX() methods)
    • java.util.concurrent.ExecutorService (e.g., invokeXXX(), submit() methods)
    • Example: ExecutorService mediates the execution of Runnable or Callable tasks.
  • Memento: Recognizable by behavioral methods that internally change the state of the entire instance.
    • All implementations of java.io.Serializable
    • java.util.Date (setter methods modify its internal state)
  • Observer: (Also known as Publish/Subscribe) Recognizable by behavioral methods that invoke a method on an instance of another abstract/interface type, depending on its own state.
    • java.util.Observer/java.util.Observable (though less common in modern Java)
    • All implementations of java.util.EventListener
    • Example: Swing event handling extensively uses the Observer pattern via EventListener interfaces.
  • State: Recognizable by behavioral methods that change their behavior based on the instance’s state, which can be controlled externally.
    • javax.faces.lifecycle.LifeCycle#execute() (behavior depends on the current JSF phase)
  • Strategy: Recognizable by behavioral methods within an abstract/interface type that invoke a method in an implementation of a different abstract/interface type, passed as a method argument to the strategy implementation.
    • java.util.Comparator#compare() (used by Collections#sort())
    • javax.servlet.Filter#doFilter()
    • Example: Collections.sort() uses a Comparator to define the sorting logic.
    import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.List;

List<String> names = new ArrayList<>();
names.add("Charlie");
names.add("Alice");
names.add("Bob");

// Strategy for sorting alphabetically
Collections.sort(names);
System.out.println("Alphabetical: " + names);

// Strategy for sorting by length
Collections.sort(names, Comparator.comparingInt(String::length));
System.out.println("By length: " + names);
  • Template Method: Recognizable by behavioral methods that define a skeleton of an algorithm, deferring some steps to subclasses.
    • All non-abstract methods of java.io.InputStream, OutputStream, Reader, Writer.
    • All non-abstract methods of java.util.AbstractList, AbstractSet, AbstractMap.
    • javax.servlet.http.HttpServlet (the doXXX() methods provide default behavior).
  • Visitor: Recognizable by two distinct abstract/interface types where methods accept each other. One calls a method on the other, which then executes a desired strategy.
    • javax.lang.model.element.Element and ElementVisitor
    • java.nio.file.FileVisitor and SimpleFileVisitor
    • Example: The Java Language Model API uses ElementVisitor for traversing and processing code elements.

FAQs on Java JDK Design Patterns

Q: What is the main purpose of creational design patterns in Java

ANS: Creational patterns focus on efficient and flexible object creation mechanisms, helping to decouple the creation process from the client code.

Q: Can you provide another example of the Singleton pattern in Java

ANS: Yes, java.awt.Toolkit#getDefaultToolkit() is another instance of the Singleton pattern.

Q: How does the Adapter pattern differ from the Decorator pattern in Java

ANS: An Adapter pattern changes the interface of an existing object, while a Decorator pattern adds new responsibilities to an object without altering its interface.

Q: What are some common pitfalls when implementing the Prototype pattern in Java

ANS: A common pitfall is shallow copying when deep copying is intended, leading to shared mutable state between prototypes. Careful implementation of clone() is crucial.

Q: How is the Iterator pattern useful in Java collections

ANS: The Iterator pattern provides a standardized way to traverse elements of a collection sequentially without exposing its underlying representation, promoting loose coupling.
