“Java Reflection: Instantiating Objects with Constructor Arguments Using Class.forName”

When working with Java’s reflection capabilities, a frequent requirement is to instantiate a class whose name is determined at runtime, often requiring specific arguments to be passed to its constructor. How can we effectively use Class.forName() in conjunction with Constructor methods to achieve this dynamic object creation, particularly when dealing with constructors that accept parameters or when accessing non-public constructors?

Here is an exploration of proven techniques for achieving this goal.

Invoking Constructors with Specific Arguments

The core process involves retrieving the Class object, locating the correct Constructor signature, and then invoking it to produce an instance.

Method 1: Direct Invocation for a Single String Parameter

For a class constructor that accepts a single String argument, the following sequence of reflection calls is employed. Note that the constructor must be accessible (public).

// Assume className holds the fully qualified name, e.g., "com.example.ServiceClass"
// Assume ctorArgument holds the String value to pass
Class<?> clazz = Class.forName(className);
Constructor<?> ctor = clazz.getConstructor(String.class);
Object object = ctor.newInstance(new Object[]{ctorArgument});

Handling Nested Classes

When dealing with static nested classes, the class name provided to Class.forName() must use the dollar sign ($) separator, aligning with the compiler’s internal representation.

For a structure like:

package foo;

public class Outer
{
    public static class Nested {}
}

The required fully-qualified name would be "foo.Outer$Nested".

Method 2: A Concise Approach for String-Argument Constructor

This showcases a slightly more compact structure achieving the same result as Method 1, assuming a public constructor accepting a String.

Class<?> c = Class.forName("mypackage.MyClass");
Constructor<?> cons = c.getConstructor(String.class);
Object object = cons.newInstance("MyAttributeValue");

Method 3: Chaining for Maximum Brevity

When familiarity with reflection methods is high, the entire sequence can be chained into a single return statement:

// This assumes 'arg' is the argument value corresponding to the constructor signature
return Class.forName(className).getConstructor(String.class).newInstance(arg);

Method 4: Instantiating Classes with No Arguments (e.g., Android Components)

If the target class (like certain Android Activity or Fragment classes) possesses only a default, parameterless constructor, you can retrieve all available constructors and pick the first one:

Class<?> myClass = Class.forName("com.example.MyClass");
// Gets the array of accessible constructors and selects the first one
Constructor<?> constructor = myClass.getConstructors()[0];
// Note: If this constructor requires arguments, this call will throw an exception
// unless you pass the correct arguments to newInstance()

Important Caveat: If the constructor retrieved via getConstructors()[0] does require arguments, you must supply them to newInstance(), otherwise, a suitable alternative (like Method 1 or 2) should be used based on the required signature.

Controlling Constructor Visibility: Public vs. Declared

The choice between getConstructor() and getDeclaredConstructor() is critical based on visibility:

  • getConstructor(Class... parameterTypes): Only retrieves public constructors whose signatures match the provided types. Using this on a non-public constructor results in a NoSuchMethodException.
  • getDeclaredConstructor(Class... parameterTypes): Retrieves constructors of any visibility (public, protected, package-private, or private) matching the signature.

Method 5: Accessing Non-Public Constructors

If you need to invoke a constructor that is not declared as public, you must use getDeclaredConstructor():

// Example showing the required signature types (e.g., String.class)
// If the constructor is private, follow Method 6 for accessibility control.
// return Class.forName(className).getDeclaredConstructor(String.class).newInstance(arg);

Method 6: Bypassing Private Constructors (e.g., Singleton Instances)

To instantiate an object that uses a private constructor, such as a poorly designed Singleton, you must explicitly grant access after obtaining the private constructor:

Class<?> clazz = Class.forName("myPackage.MyClass");

// Get the constructor matching the signature (e.g., no arguments for a typical private constructor)
Constructor<?> cons = clazz.getDeclaredConstructor(); 

// Crucial step: make the private constructor accessible
cons.setAccessible(true); 

// Create the new object instance
Object obj = cons.newInstance();

Handling Constructors with Complex or Multiple Arguments

Reflection allows precise specification of constructor parameter types and their corresponding argument values.

Method 7: Specifying Multiple Parameter Types

When the constructor signature involves non-primitive types (like WebDriver in this example), you must pass the precise class objects in getConstructor() and the corresponding instances in newInstance():

// Constructor signature is Constructor(WebDriver driver)
return Class.forName("com.page.BillablePage")
    .getConstructor(WebDriver.class)
    .newInstance(this.driver); // 'this.driver' is the instance of WebDriver

Method 8: Detailed Example with String Argument Passing

This detailed example illustrates the setup for a class (Base) with overloaded constructors, showing how to target one specifically by matching argument types (String.class) and providing the argument array in newInstance():

Example Base Class Structure:

public class Base {
    public String data = "default";

    public Base() { /* ... */ }

    public Base(String arg1) {
        this.data = arg1;
        System.out.println("Base(" + arg1 + ")");
    }
}

Reflection Code Targeting the String Constructor:

String myClassName = Base.class.getName();
Class<?> myClass = Class.forName(myClassName);

// Targeting the Base(String) constructor
Constructor<?> ctr = myClass.getConstructor(String.class); 

String arg1 = "My User Data";
Object object = ctr.newInstance(new Object[]{arg1});

Base base = (Base)object;
System.out.println(base.data); // Output: My User Data

Targeting a Three-Argument Constructor: To target a constructor Base(String a, String b, String c):

Constructor<?> ctr = myClass.getConstructor(String.class, String.class, String.class);
Object object = ctr.newInstance(new Object[]{"Arg1", "Arg2", "Arg3"});

Remember to handle potential reflection exceptions (ClassNotFoundException, NoSuchMethodException, IllegalAccessException, InvocationTargetException, etc.).

Method 9: Utilizing Constructor.newInstance(Object...)

This generalizes the parameter passing, emphasizing the use of the varargs feature of newInstance to supply the actual arguments directly.

FAQs on Java Reflection Object Instantiation With Constructor Args

Q: What is the primary requirement for Class forName to succeed

ANS: The class name must be fully qualified, including the entire package path. For static nested classes, use the dollar sign ($) separator.

Q: When should I use getDeclaredConstructor instead of getConstructor

ANS: Use getDeclaredConstructor when you need to access constructors that are not declared as public (e.g., protected, package-private, or private).

Q: How do I create an instance of a class with a private constructor

ANS: Retrieve the private constructor using getDeclaredConstructor(), call setAccessible(true) on the Constructor object, and then call newInstance().

Q: What exception occurs if the constructor signature does not match the arguments provided

ANS: An IllegalArgumentException is usually thrown when the types provided to newInstance() do not match the parameter types defined in the selected constructor.
