“Android SSL ‘Not Trusted’ Error Solutions for HttpClient”

Encountering a javax.net.ssl.SSLException: Not trusted server certificate error when making HTTPS requests on Android using HttpClient can halt your application’s network operations. This common issue arises when the device’s trust store doesn’t recognize the server’s SSL certificate. Fortunately, several strategies exist to address this, ranging from highly secure custom configurations to broader, albeit less secure, trust settings.

The core challenge lies in how HttpClient validates SSL certificates. By default, it relies on the Android system’s pre-installed root certificates. If your server uses a certificate issued by an authority not present in this default list, or a self-signed certificate, the connection will fail.

Understanding the Potential Solutions

There are broadly four main approaches to tackle this problem:

  1. Trust All Certificates (Use with Extreme Caution): This involves configuring your HttpClient to ignore all certificate validation checks. While simple for testing, this severely weakens security, leaving your application vulnerable to Man-in-the-Middle (MITM) attacks. This method should never be used in production environments where security is a concern.
  2. Custom SSLSocketFactory Trusting Specific Certificates: This involves creating a custom SSLSocketFactory that either trusts a predefined set of certificates (like your self-signed certificate) or combines the system’s default trust store with your own. This offers a more controlled and secure approach.
  3. Leveraging a Pre-built Library: Libraries exist that abstract away much of the complexity of SSL configuration, allowing for quicker implementation of custom trust strategies.
  4. System-Level Configuration: In some cases, modifying system properties or using specific JVM arguments can influence certificate validation.

Let’s delve into specific implementations for these strategies.

Solution 1: Custom SSLSocketFactory with Additional Trust Stores

This approach is recommended for its balance of flexibility and security. It allows you to extend the default trust mechanism to include your own certificates, such as self-signed ones or those from less common Certificate Authorities.

The process involves:

  1. Identifying Missing Certificates: Use openssl to inspect the certificate chain of your server.
  2. Creating a Keystore: Generate a .bks (Bouncy Castle Keystore) file containing your specific certificate(s).
  3. Implementing a Custom SSLSocketFactory: This factory will load your custom keystore alongside the system’s default trust store.
  4. Registering the Factory: Integrate the custom factory with your HttpClient’s SchemeRegistry.

Step 1: Inspecting the Certificate Chain

openssl s_client -connect www.yourserver.com:443

Examine the output to identify the root or intermediate certificates in the chain.

Step 2: Creating a Keystore File

First, ensure you have the Bouncy Castle provider library in your classpath. Then, extract the certificate and create the keystore:

# Save the certificate to a file (e.g., mycert.pem)
echo | openssl s_client -connect ${MY_SERVER}:443 2>&1 | \
 sed -ne '/-BEGIN CERTIFICATE-/,/-END CERTIFICATE-/p' > mycert.pem

# Set the Bouncy Castle provider path
export CLASSPATH=/path/to/bouncycastle/bcprov-jdk15on-155.jar

# Define the keystore file path
CERTSTORE=res/raw/mystore.bks

# Remove existing keystore if it exists
if [ -a $CERTSTORE ]; then
    rm $CERTSTORE || exit 1
fi

# Import the certificate into a BKS keystore
keytool \
      -import \
      -v \
      -trustcacerts \
      -alias 0 \
      -file <(openssl x509 -in mycert.pem) \
      -keystore $CERTSTORE \
      -storetype BKS \
      -provider org.bouncycastle.jce.provider.BouncyCastleProvider \
      -providerpath /path/to/bouncycastle/bcprov-jdk15on-155.jar \
      -storepass some-password

Step 3 & 4: Implementing and Registering the Custom Factory

import java.io.InputStream;
import java.net.Socket;
import java.security.KeyStore;
import java.security.cert.CertificateException;
import java.security.cert.X509Certificate;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Enumeration;

import javax.net.ssl.SSLContext;
import javax.net.ssl.TrustManager;
import javax.net.ssl.TrustManagerFactory;
import javax.net.ssl.X509TrustManager;

import org.apache.http.conn.scheme.PlainSocketFactory;
import org.apache.http.conn.scheme.Scheme;
import org.apache.http.conn.scheme.SchemeRegistry;
import org.apache.http.conn.ssl.SSLSocketFactory;
import org.apache.http.impl.client.DefaultHttpClient;
import org.apache.http.impl.conn.tsccm.ThreadSafeClientConnManager;
import org.apache.http.params.BasicHttpParams;
import org.apache.http.params.HttpParams;
import org.apache.http.params.HttpProtocolParams;
import org.apache.http.protocol.HTTP;

public class HttpClientUtils {

    public static DefaultHttpClient getHttpClientWithCustomCerts() {
        try {
            KeyStore ks = KeyStore.getInstance("BKS");

            // Load your custom keystore (mystore.bks) from res/raw
            InputStream in = YourAppContext.context.getResources().openRawResource(R.raw.mystore);
            try {
                // Use the password defined during keystore creation
                ks.load(in, "some-password".toCharArray());
            } finally {
                in.close();
            }

            SSLSocketFactory sf = new AdditionalKeyStoresSSLSocketFactory(ks);
            sf.setHostnameVerifier(SSLSocketFactory.ALLOW_ALL_HOSTNAME_VERIFIER); // Or BROWSER_COMPATIBLE_HOSTNAME_VERIFIER

            HttpParams params = new BasicHttpParams();
            HttpProtocolParams.setVersion(params, org.apache.http.HttpVersion.HTTP_1_1);
            HttpProtocolParams.setContentCharset(params, HTTP.UTF_8);

            SchemeRegistry registry = new SchemeRegistry();
            registry.register(new Scheme("http", PlainSocketFactory.getSocketFactory(), 80));
            registry.register(new Scheme("https", sf, 443));

            ClientConnectionManager ccm = new ThreadSafeClientConnManager(params, registry);

            return new DefaultHttpClient(ccm, params);
        } catch (Exception e) {
            throw new RuntimeException("Error configuring HttpClient with custom certificates", e);
        }
    }

    /**
     * Allows trusting certificates from additional KeyStores in addition to the default KeyStore.
     */
    public static class AdditionalKeyStoresSSLSocketFactory extends SSLSocketFactory {
        protected SSLContext sslContext = SSLContext.getInstance("TLS");

        public AdditionalKeyStoresSSLSocketFactory(KeyStore keyStore) throws Exception {
            super(null, null, null, null, null, null);
            sslContext.init(null, new TrustManager[]{new AdditionalKeyStoresTrustManager(keyStore)}, null);
        }

        @Override
        public Socket createSocket(Socket socket, String host, int port, boolean autoClose) throws java.io.IOException {
            return sslContext.getSocketFactory().createSocket(socket, host, port, autoClose);
        }

        @Override
        public Socket createSocket() throws java.io.IOException {
            return sslContext.getSocketFactory().createSocket();
        }

        /**
         * Based on http://download.oracle.com/javase/1.5.0/docs/guide/security/jsse/JSSERefGuide.html#X509TrustManager
         */
        public static class AdditionalKeyStoresTrustManager implements X509TrustManager {
            protected ArrayList<X509TrustManager> x509TrustManagers = new ArrayList<>();

            protected AdditionalKeyStoresTrustManager(KeyStore... additionalkeyStores) {
                final ArrayList<TrustManagerFactory> factories = new ArrayList<>();

                try {
                    // The default Trustmanager with default keystore
                    final TrustManagerFactory original = TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
                    original.init((KeyStore) null);
                    factories.add(original);

                    for (KeyStore keyStore : additionalkeyStores) {
                        final TrustManagerFactory additionalCerts = TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
                        additionalCerts.init(keyStore);
                        factories.add(additionalCerts);
                    }
                } catch (Exception e) {
                    throw new RuntimeException("Error initializing TrustManagerFactories", e);
                }

                /*
                 * Iterate over the returned trustmanagers, and hold on
                 * to any that are X509TrustManagers
                 */
                for (TrustManagerFactory tmf : factories) {
                    for (TrustManager tm : tmf.getTrustManagers()) {
                        if (tm instanceof X509TrustManager) {
                            x509TrustManagers.add((X509TrustManager) tm);
                        }
                    }
                }

                if (x509TrustManagers.isEmpty()) {
                    throw new RuntimeException("Couldn't find any X509TrustManagers");
                }
            }

            /*
             * Delegate to the default trust manager.
             */
            @Override
            public void checkClientTrusted(X509Certificate[] chain, String authType) throws CertificateException {
                final X509TrustManager defaultX509TrustManager = x509TrustManagers.get(0);
                defaultX509TrustManager.checkClientTrusted(chain, authType);
            }

            /*
             * Loop over the trustmanagers until we find one that accepts our server
             */
            @Override
            public void checkServerTrusted(X509Certificate[] chain, String authType) throws CertificateException {
                for (X509TrustManager tm : x509TrustManagers) {
                    try {
                        tm.checkServerTrusted(chain, authType);
                        return; // Trust accepted by one of the managers
                    } catch (CertificateException e) {
                        // Ignore and try the next manager
                    }
                }
                // If no manager accepted the certificate, throw an exception
                throw new CertificateException("Server certificate not trusted by any configured TrustManager");
            }

            @Override
            public X509Certificate[] getAcceptedIssuers() {
                final ArrayList<X509Certificate> list = new ArrayList<>();
                for (X509TrustManager tm : x509TrustManagers) {
                    list.addAll(Arrays.asList(tm.getAcceptedIssuers()));
                }
                return list.toArray(new X509Certificate[0]);
            }
        }
    }
}

Solution 2: Trusting All Certificates (for Testing Only)

This is the simplest but least secure method. It bypasses all certificate validation.

import java.io.IOException;
import java.net.Socket;
import java.security.KeyManagementException;
import java.security.KeyStore;
import java.security.KeyStoreException;
import java.security.NoSuchAlgorithmException;
import java.security.UnrecoverableKeyException;
import java.security.cert.CertificateException;
import java.security.cert.X509Certificate;

import javax.net.ssl.SSLContext;
import javax.net.ssl.TrustManager;
import javax.net.ssl.X509TrustManager;

import org.apache.http.conn.ssl.SSLSocketFactory;
import org.apache.http.impl.client.DefaultHttpClient;
import org.apache.http.impl.conn.tsccm.ThreadSafeClientConnManager;
import org.apache.http.params.BasicHttpParams;
import org.apache.http.params.HttpParams;
import org.apache.http.params.HttpProtocolParams;
import org.apache.http.protocol.HTTP;
import org.apache.http.conn.scheme.Scheme;
import org.apache.http.conn.scheme.SchemeRegistry;
import org.apache.http.conn.scheme.PlainSocketFactory;
import org.apache.http.client.HttpClient;

public class UnsafeHttpClient {

    public static HttpClient getHttpClient() {
        try {
            KeyStore trustStore = KeyStore.getInstance(KeyStore.getDefaultType());
            trustStore.load(null, null); // Load empty keystore

            SSLSocketFactory sf = new MySSLSocketFactory(trustStore);
            sf.setHostnameVerifier(SSLSocketFactory.ALLOW_ALL_HOSTNAME_VERIFIER); // Trust all hosts

            HttpParams params = new BasicHttpParams();
            HttpProtocolParams.setVersion(params, org.apache.http.HttpVersion.HTTP_1_1);
            HttpProtocolParams.setContentCharset(params, HTTP.UTF_8);

            SchemeRegistry registry = new SchemeRegistry();
            registry.register(new Scheme("http", PlainSocketFactory.getSocketFactory(), 80));
            registry.register(new Scheme("https", sf, 443));

            ClientConnectionManager ccm = new ThreadSafeClientConnManager(params, registry);

            return new DefaultHttpClient(ccm, params);

        } catch (Exception e) {
            throw new RuntimeException("Error creating unsafe HttpClient", e);
        }
    }

    // Custom SSLSocketFactory that trusts all certificates
    private static class MySSLSocketFactory extends SSLSocketFactory {
        SSLContext sslContext = SSLContext.getInstance("TLS");

        public MySSLSocketFactory(KeyStore truststore) throws NoSuchAlgorithmException, KeyManagementException, KeyStoreException, UnrecoverableKeyException {
            super(truststore);
            TrustManager tm = new X509TrustManager() {
                @Override
                public void checkClientTrusted(X509Certificate[] chain, String authType) {}

                @Override
                public void checkServerTrusted(X509Certificate[] chain, String authType) {}

                @Override
                public X509Certificate[] getAcceptedIssuers() {
                    return null;
                }
            };
            sslContext.init(null, new TrustManager[]{tm}, null);
        }

        @Override
        public Socket createSocket(Socket socket, String host, int port, boolean autoClose) throws IOException {
            return sslContext.getSocketFactory().createSocket(socket, host, port, autoClose);
        }

        @Override
        public Socket createSocket() throws IOException {
            return sslContext.getSocketFactory().createSocket();
        }
    }
}

Important Note: The above “trust all” approach is highly insecure and should only be employed for temporary testing on trusted networks. It makes your application vulnerable to MITM attacks.

Solution 3: Using HttpsURLConnection with a Trust-All Approach

If you are using HttpsURLConnection directly instead of HttpClient, you can achieve a similar trust-all behavior:

import java.security.KeyManagementException;
import java.security.NoSuchAlgorithmException;
import java.security.SecureRandom;
import java.security.cert.CertificateException;
import java.security.cert.X509Certificate;

import javax.net.ssl.HostnameVerifier;
import javax.net.ssl.HttpsURLConnection;
import javax.net.ssl.SSLContext;
import javax.net.ssl.SSLSession;
import javax.net.ssl.TrustManager;
import javax.net.ssl.X509TrustManager;

public class HttpsTrustAll {

    public static void trustAllCertificates() {
        try {
            HttpsURLConnection.setDefaultHostnameVerifier(new HostnameVerifier() {
                public boolean verify(String hostname, SSLSession session) {
                    return true; // Trust all hostnames
                }
            });

            SSLContext context = SSLContext.getInstance("TLS");
            context.init(null, new TrustManager[]{
                    new X509TrustManager() {
                        public void checkClientTrusted(X509Certificate[] chain, String authType) throws CertificateException {}
                        public void checkServerTrusted(X509Certificate[] chain, String authType) throws CertificateException {}
                        public X509Certificate[] getAcceptedIssuers() {
                            return new X509Certificate[0]; // No specific issuers to trust
                        }
                    }
            }, new SecureRandom());

            HttpsURLConnection.setDefaultSSLSocketFactory(context.getSocketFactory());
        } catch (KeyManagementException | NoSuchAlgorithmException e) {
            e.printStackTrace(); // Handle error appropriately
        }
    }
}

You would call HttpsTrustAll.trustAllCertificates(); before making any HTTPS requests.

Solution 4: Specific HttpClient Versions and Alternatives

Different versions of Apache HttpClient might require slightly different configurations. For example, httpclient-4.5 and later often use SSLConnectionSocketFactory.

Here’s an example for httpclient-4.5:

import java.security.cert.CertificateException;
import java.security.cert.X509Certificate;

import org.apache.http.client.HttpClient;
import org.apache.http.conn.ssl.NoopHostnameVerifier;
import org.apache.http.conn.ssl.SSLConnectionSocketFactory;
import org.apache.http.conn.ssl.TrustStrategy;
import org.apache.http.impl.client.CloseableHttpClient;
import org.apache.http.impl.client.HttpClients;
import org.apache.http.ssl.SSLContextBuilder;

public class HttpClient4_5Utils {

    public static HttpClient getHttpClientWithoutSslValidation() {
        try {
            SSLContextBuilder builder = new SSLContextBuilder();
            // Trust all certificates
            builder.loadTrustMaterial(null, new TrustStrategy() {
                @Override
                public boolean isTrusted(X509Certificate[] chain, String authType) throws CertificateException {
                    return true;
                }
            });

            // Use NoopHostnameVerifier to bypass hostname verification
            SSLConnectionSocketFactory sslsf = new SSLConnectionSocketFactory(builder.build(), new NoopHostnameVerifier());
            CloseableHttpClient httpclient = HttpClients.custom().setSSLSocketFactory(sslsf).build();
            return httpclient;
        } catch (Exception e) {
            throw new RuntimeException("Error configuring HttpClient 4.5 without SSL validation", e);
        }
    }
}

Solution 5: Using JVM Arguments

For Java applications (not directly Android apps in the same way), you can sometimes control SSL validation via JVM arguments. This is less common for typical Android development but can be relevant in specific Java environments.

-Djavax.net.ssl.trustStore=/path/to/your/truststore.jks
-Djavax.net.ssl.trustStorePassword=your_password
-Dssl.enableSessionCreation=true

A more direct “trust all” argument might be available in some contexts, like -Dtrust_all_cert=true, but this is not a standard Java property and depends on the JVM implementation or libraries used.

Solution 6: Merging Keystores

An advanced technique involves merging the Android system’s default trust store with your custom keystore programmatically. This provides a robust solution for handling certificates not present in the system’s default store.

import java.io.BufferedInputStream;
import java.io.FileInputStream;
import java.io.InputStream;
import java.security.KeyStore;
import java.util.Enumeration;

import org.apache.http.HttpVersion;
import org.apache.http.client.HttpClient;
import org.apache.http.conn.ClientConnectionManager;
import org.apache.http.conn.scheme.PlainSocketFactory;
import org.apache.http.conn.scheme.Scheme;
import org.apache.http.conn.scheme.SchemeRegistry;
import org.apache.http.conn.ssl.SSLSocketFactory;
import org.apache.http.impl.client.DefaultHttpClient;
import org.apache.http.impl.conn.tsccm.ThreadSafeClientConnManager;
import org.apache.http.params.BasicHttpParams;
import org.apache.http.params.HttpParams;
import org.apache.http.params.HttpProtocolParams;
import org.apache.http.protocol.HTTP;

public class MergedKeystoreHttpClient {

    // Assuming 'context' is your Android application context
    public static HttpClient getHttpClientWithMergedKeystores() {
        try {
            InputStream in = null;
            // Load default system keystore (path may vary on Android versions)
            KeyStore trusted = KeyStore.getInstance(KeyStore.getDefaultType());
            try {
                // The path to the system truststore might be in:
                // System.getProperty("javax.net.ssl.trustStore") or a hardcoded path like "/system/etc/security/cacerts.bks"
                in = new BufferedInputStream(new FileInputStream(System.getProperty("javax.net.ssl.trustStore"))); // Or "/system/etc/security/cacerts.bks"
                trusted.load(in, null); // Default password is often "changeit"
            } finally {
                if (in != null) {
                    in.close();
                    in = null;
                }
            }

            // Load your application keystore & merge with system
            try {
                KeyStore appTrusted = KeyStore.getInstance("BKS"); // Or JKS depending on your keystore type
                in = YourAppContext.context.getResources().openRawResource(R.raw.mykeystore); // Your custom keystore
                appTrusted.load(in, null); // Password for your keystore
                for (Enumeration<String> e = appTrusted.aliases(); e.hasMoreElements();) {
                    final String alias = e.nextElement();
                    final KeyStore.Entry entry = appTrusted.getEntry(alias, null);
                    // Add entries from your keystore to the system keystore, using a unique alias
                    trusted.setEntry(System.currentTimeMillis() + ":" + alias, entry, null);
                }
            } finally {
                if (in != null) {
                    in.close();
                    in = null;
                }
            }

            HttpParams params = new BasicHttpParams();
            HttpProtocolParams.setVersion(params, HttpVersion.HTTP_1_1);
            HttpProtocolParams.setContentCharset(params, HTTP.UTF_8);

            SSLSocketFactory sf = new SSLSocketFactory(trusted);
            // Use a compatible hostname verifier
            sf.setHostnameVerifier(SSLSocketFactory.BROWSER_COMPATIBLE_HOSTNAME_VERIFIER);

            SchemeRegistry registry = new SchemeRegistry();
            registry.register(new Scheme("http", PlainSocketFactory.getSocketFactory(), 80));
            registry.register(new Scheme("https", sf, 443));

            ClientConnectionManager ccm = new ThreadSafeClientConnManager(params, registry);

            return new DefaultHttpClient(ccm, params);
        } catch (Exception e) {
            throw new RuntimeException("Error configuring HttpClient with merged keystores", e);
        }
    }

    // Helper method to convert JKS to BKS if needed
    public static void convertJksToBks(String jksPath, String bksPath, String password, String bcProvPath) {
        // Example command for conversion:
        // keytool -importkeystore -destkeystore cacerts.bks -deststoretype BKS -providerclass org.bouncycastle.jce.provider.BouncyCastleProvider -providerpath bcprov-jdk16-141.jar -deststorepass changeit -srcstorepass changeit -srckeystore $JAVA_HOME/jre/lib/security/cacerts -srcstoretype JKS -noprompt
    }
}

Important Considerations

  • Security Risks: Always prioritize security. Trusting all certificates should be reserved for development or specific, controlled testing environments. For production, use custom SSLSocketFactory instances that trust only verified certificates.
  • Android Version Differences: SSL handling and trust store locations can vary between Android versions. Research specific requirements for the target API levels.
  • Hostname Verification: Alongside certificate validation, hostname verification ensures the certificate matches the domain you are connecting to. SSLSocketFactory.ALLOW_ALL_HOSTNAME_VERIFIER bypasses this, which is also a security risk. BROWSER_COMPATIBLE_HOSTNAME_VERIFIER is generally safer.

By carefully selecting and implementing one of these strategies, you can effectively overcome the Not Trusted SSL certificate errors when using HttpClient in your Android applications.

FAQs on Android SSL ‘Not Trusted’ Error Solutions for HttpClient

Q: What causes the 'Not Trusted' SSL error in Android HttpClient

ANS: This error typically occurs when the SSL certificate presented by the server is not recognized or trusted by the Android device’s default set of trusted Certificate Authorities (CAs). This can happen with self-signed certificates, certificates from less common CAs, or expired certificates.

Q: Is it safe to trust all SSL certificates in Android

ANS: No, it is not safe to trust all SSL certificates in a production environment. Trusting all certificates bypasses crucial security checks, making your application vulnerable to Man-in-the-Middle (MITM) attacks where an attacker can intercept and modify communication. This approach should only be used for development or testing on secure, controlled networks.

Q: How can I trust a specific self-signed certificate

ANS: You can create a custom SSLSocketFactory that includes your self-signed certificate in its trust store. This involves generating a keystore file (e.g., .bks format) containing your certificate and then configuring HttpClient to use this custom factory.

Q: What is the role of openssl in fixing SSL errors

ANS: The openssl s_client command-line tool is useful for inspecting the SSL certificate chain of a remote server. By examining its output, you can identify the specific certificates (root or intermediate) that are missing from your device’s trust store, which helps in creating a custom keystore.

Q: What are BKS and JKS keystore types

ANS: BKS (Bouncy Castle Keystore) and JKS (Java KeyStore) are different formats for storing cryptographic keys and certificates. BKS is often used in Android development, especially when working with the Bouncy Castle cryptography library.

Q: How do I choose between ALLOW_ALL_HOSTNAME_VERIFIER and BROWSER_COMPATIBLE_HOSTNAME_VERIFIER

ANS: ALLOW_ALL_HOSTNAME_VERIFIER bypasses all hostname checks, which is less secure. BROWSER_COMPATIBLE_HOSTNAME_VERIFIER performs checks similar to web browsers, which is generally preferred for better security.

Q: Can I use a library to simplify SSL certificate handling

ANS: Yes, libraries like sslcontext-kickstart can simplify the process of configuring SSL contexts and trust strategies, potentially reducing the amount of custom code you need to write.
