“Fixing WebDriverException: Element Not Clickable at Point in Selenium”

Let’s delve into the various strategies to resolve this common predicament.

Understanding the Root Cause

The exception message itself provides a crucial clue: “Other element would receive the click.” This indicates a visual or functional overlay, or a different element that has focus or is simply positioned to intercept the click. Another primary reason is the element’s state – it might be present in the DOM but not yet interactive due to ongoing animations, loading processes, or JavaScript modifications.

Strategies for Resolving “Element Not Clickable”

Several approaches can circumvent this issue, depending on the specific circumstances of your web page.

Solution 1: Employing the Actions Class

For elements that might not be directly clickable due to their current state or positioning, the Actions class can simulate a more natural user interaction. This involves moving to the element first, then performing the click.

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.interactions.Actions;

// Assuming 'driver' is your initialized WebDriver instance
WebElement elementToClick = driver.findElement(By.id("navigationPageButton"));
Actions actionsBuilder = new Actions(driver);
actionsBuilder.moveToElement(elementToClick).click().build().perform();

Solution 2: Leveraging JavascriptExecutor for Scrolling

If the element is present but not visible within the current viewport, scrolling is necessary. JavascriptExecutor can bring the element into view before the click attempt.

import org.openqa.selenium.By;
import org.openqa.selenium.JavascriptExecutor;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;

// Assuming 'driver' is your initialized WebDriver instance
WebElement elementToScrollTo = driver.findElement(By.id("navigationPageButton"));
JavascriptExecutor jsExecutor = (JavascriptExecutor) driver;
jsExecutor.executeScript("arguments[0].scrollIntoView(true);", elementToScrollTo);
// After scrolling, you might still need to click the element, potentially with a wait.

Solution 3: Implementing Explicit Waits with elementToBeClickable

When an element is present in the DOM but not yet interactable, an explicit wait is the most robust solution. WebDriverWait combined with ExpectedConditions.elementToBeClickable ensures that the script waits until the element is both present and clickable.

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;

// Assuming 'driver' is your initialized WebDriver instance
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10)); // Adjust timeout as needed
WebElement clickableElement = wait.until(ExpectedConditions.elementToBeClickable(By.id("navigationPageButton")));
clickableElement.click();

Solution 4: Handling Temporary Overlays with invisibilityOfElementLocated

Sometimes, a temporary overlay (like a loading spinner or a modal) prevents interaction with the underlying element. Waiting for the overlay’s invisibility is key.

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;

// Assuming 'driver' is your initialized WebDriver instance
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
// Replace "By.xpath("ele_to_inv")" with the actual locator for the overlay element
wait.until(ExpectedConditions.invisibilityOfElementLocated(By.xpath("ele_to_inv")));
// Now, attempt to click the target element
WebElement elementToClick = driver.findElement(By.id("navigationPageButton"));
elementToClick.click();

Solution 5: Direct Click via JavascriptExecutor for Permanent Overlays

For persistent overlays or elements that are difficult to target with standard Selenium methods, JavascriptExecutor can bypass these issues by directly executing a click on the element.

import org.openqa.selenium.By;
import org.openqa.selenium.JavascriptExecutor;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;

// Assuming 'driver' is your initialized WebDriver instance
WebElement elementToClickDirectly = driver.findElement(By.xpath("your_element_xpath")); // Use an appropriate locator
JavascriptExecutor jsExecutor = (JavascriptExecutor) driver;
jsExecutor.executeScript("arguments[0].click();", elementToClickDirectly);

Solution 6: Using elementFromPoint in Python

In Python, document.elementFromPoint(x, y) can be used to identify the element currently at a specific coordinate, which can be helpful if Selenium is consistently misidentifying the clickable element.

from selenium.webdriver.remote.webdriver import WebDriver
from selenium.webdriver.remote.webelement import WebElement

# Assuming 'driver' is your initialized WebDriver instance
# Assume 'element_i_care_about' is a WebElement you want to click
element_i_care_about: WebElement = driver.find_element(By.ID, "some_id") # Replace with actual locator
element_location = element_i_care_about.location
element_to_click = driver.execute_script(
    "return document.elementFromPoint(arguments[0], arguments[1]);",
    element_location['x'],
    element_location['y']
)
element_to_click.click()

Solution 7: Addressing jQuery Animations with a Custom Expected Condition

If animations are causing the timing issue, especially with jQuery, a custom ExpectedCondition can be created to wait for animations to complete.

import org.openqa.selenium.By;
import org.openqa.selenium.JavascriptExecutor;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.WebDriverException;
import org.openqa.selenium.StaleElementReferenceException;
import org.openqa.selenium.support.ui.ExpectedCondition;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;

import java.util.List;
import java.time.Duration;

public class CustomConditions {

    public static ExpectedCondition<Boolean> jquerySelectorNotAnimated(By locator) {
        return new ExpectedCondition<Boolean>() {
            @Override
            public Boolean apply(WebDriver driver) {
                try {
                    List<WebElement> elements = driver.findElements(locator);
                    // This assumes jQuery is available on the page and ':animated' works
                    JavascriptExecutor js = (JavascriptExecutor) driver;
                    return (Boolean) js.executeScript(
                            "return !jQuery(arguments[0]).filter(':animated').length;",
                            elements
                    );
                } catch (StaleElementReferenceException e) {
                    return false;
                } catch (WebDriverException e) {
                    // Handle cases where jQuery might not be loaded or ':animated' is not supported
                    System.err.println("Error checking jQuery animation: " + e.getMessage());
                    return false; // Assume not ready if error
                }
            }

            @Override
            public String toString() {
                return "jQuery elements not animated for locator: " + locator.toString();
            }
        };
    }

    // Example Usage:
    public static void main(String[] args) {
        // Assuming 'driver' is initialized
        WebDriver driver = null; // Initialize your WebDriver
        By animatedElementLocator = By.cssSelector(".animated-element"); // Replace with your locator
        WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));

        try {
            wait.until(jquerySelectorNotAnimated(animatedElementLocator));
            WebElement targetElement = driver.findElement(By.id("target_button_id"));
            targetElement.click();
        } catch (Exception e) {
            System.err.println("Failed to click after waiting for animations: " + e.getMessage());
        }
    }
}

Solution 8: Overriding Click Functionality with Retries

A more defensive approach involves creating a custom click method that retries the click operation if a WebDriverException occurs, indicating a potential transient issue.

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.WebDriverException;

public class RobustClicker {

    public void robustClick(WebElement element) {
        boolean clicked = false;
        int retries = 3; // Number of retry attempts
        for (int i = 0; i < retries; i++) {
            try {
                element.click();
                clicked = true;
                break; // Exit loop if click is successful
            } catch (WebDriverException e) {
                System.err.println("Click attempt failed, retrying... Error: " + e.getMessage());
                // Optional: Add a small delay between retries
                try {
                    Thread.sleep(500); // 500 milliseconds delay
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                }
            }
        }
        if (!clicked) {
            throw new WebDriverException("Failed to click element after multiple retries.");
        }
    }

    // Example Usage:
    public static void main(String[] args) {
        WebDriver driver = null; // Initialize your WebDriver
        WebElement elementToClick = null; // Find your WebElement
        RobustClicker clicker = new RobustClicker();
        try {
            clicker.robustClick(elementToClick);
        } catch (WebDriverException e) {
            System.err.println("Final click failure: " + e.getMessage());
        }
    }
}

Solution 10: Waiting for Element Presence

Sometimes, simply waiting for the element to be present in the DOM is enough, before attempting the click. This is less specific than elementToBeClickable but can resolve timing issues.

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;

// Assuming 'driver' is your initialized WebDriver instance
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement navigationPageButton = wait.until(ExpectedConditions.presenceOfElementLocated(By.id("navigationPageButton")));
navigationPageButton.click();

Solution 14: Using presenceOfElementLocated with invisibilityOfElementLocated

This approach combines waiting for an element to be present with ensuring a related element (like a spinner) is no longer visible.

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;

// Assuming 'driver' is your WebDriver instance
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(30));

// Wait for an overlay to disappear
boolean invisible = wait.until(ExpectedConditions.invisibilityOfElementLocated(By.xpath("//div[@class='navbar-brand']"))); // Replace locator

if (invisible) {
    // Then find and click the target element
    WebElement elementToClick = driver.findElement(By.xpath("//div[@id='button']")); // Replace locator
    elementToClick.click();
}

Other Considerations

  • Browser Zoom Level: Ensure the browser zoom is set to 100%, as other zoom levels can affect element coordinates.
  • Stale Element Reference: If the page dynamically changes, the element reference might become stale. Re-finding the element before clicking can resolve this.
  • Shadow DOM: If the element is within a Shadow DOM, you’ll need specific JavaScript or helper methods to traverse it.

FAQs on WebDriverException Element Not Clickable

Q: What does WebDriverException Element is not clickable at point mean

ANS: This exception typically occurs when Selenium attempts to click an element, but another element is positioned to intercept the click, or the target element is not yet in an interactive state (e.g., due to loading, animation, or JavaScript).

Q: How to fix 'Element is not clickable' in Selenium WebDriver

ANS: You can fix this by using Actions class, JavascriptExecutor to scroll or click directly, explicit waits with elementToBeClickable, or waiting for overlays to disappear using invisibilityOfElementLocated.

Q: When should I use JavascriptExecutor for clicking

ANS: Use JavascriptExecutor when standard click methods fail, especially if there are overlays, fixed headers, or elements that are difficult to interact with through normal Selenium commands.

Q: Is WebDriverWait always necessary for clickable elements

ANS: While not always strictly necessary, using WebDriverWait with ExpectedConditions.elementToBeClickable is highly recommended for robust automation, as it handles dynamic page loads and ensures the element is ready for interaction.

Q: How can I handle elements that are not in the viewport

ANS: Use JavascriptExecutor to scroll the element into view using arguments[0].scrollIntoView(true); before attempting to click it.
