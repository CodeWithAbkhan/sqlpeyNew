“Java Date Formatting: Generate Day of Month with Ordinal Suffix (st, nd, rd, th)”

Generating dates that correctly display the day of the month with its proper ordinal suffix (like 1st, 2nd, 3rd, 4th, 21st, 22nd, etc.) is a common requirement in Java date presentation. While the legacy SimpleDateFormat has limitations, modern APIs like java.time offer more robust solutions. How can we reliably implement this functionality across different Java versions and contexts?

Utilizing External Libraries: The Guava Approach

One effective method involves leveraging external libraries designed for utility, such as Google Guava. This solution provides clear precondition checks, ensuring the input day is valid before applying the suffix logic.

Solution using Guava’s Preconditions:

// Source: https://github.com/google/guava
import static com.google.common.base.Preconditions.*;

String getDayOfMonthSuffix(final int n) {
    checkArgument(n >= 1 && n <= 31, "illegal day of month: " + n);
    if (n >= 11 && n <= 13) {
        return "th";
    }
    switch (n % 10) {
        case 1:  return "st";
        case 2:  return "nd";
        case 3:  return "rd";
        default: return "th";
    }
}
// Example usage: getDayOfMonthSuffix(21) would return "st"

Self-Correction Note: It is noted that relying on complex tables might introduce maintenance issues or bugs for specific edge cases (like 7th, 17th, 27th) if not meticulously managed, as dynamic content sources can change.

Native Java Solutions with SimpleDateFormat and Array Lookups

If external dependencies are avoided, direct array lookups paired with Calendar or SimpleDateFormat provide an accepted route, although it involves manual construction of the date string.

Solution using a Predefined Suffix Array:

This method maps the day number directly to its suffix.

Integrating Suffix Logic into SimpleDateFormat Patterns

It is possible to embed the logic directly into the formatting structure using SimpleDateFormat by escaping the suffix characters within single quotes (').

Solution by embedding suffix logic directly:

private String getCurrentDateInSpecificFormat(Calendar currentCalDate) {
    String dayNumberSuffix = getDayNumberSuffix(currentCalDate.get(Calendar.DAY_OF_MONTH));
    // Note the single quotes around the suffix placement 'd' + suffix + ' MMMM yyyy'
    DateFormat dateFormat = new SimpleDateFormat(" d'" + dayNumberSuffix + "' MMMM yyyy");
    return dateFormat.format(currentCalDate.getTime());
}

private String getDayNumberSuffix(int day) {
    if (day >= 11 && day <= 13) {
        return "th";
    }
    switch (day % 10) {
    case 1:
        return "st";
    case 2:
        return "nd";
    case 3:
        return "rd";
    default:
        return "th";
    }
}

Alternative Manual Formatting with Date Iteration (Solution 5/16):

A different structure uses SimpleDateFormat to define the suffix directly in the pattern, conditional on the day number, specifically avoiding the “teen” numbers (11-13).

public static String getFormattedDate(Date date){
    Calendar cal=Calendar.getInstance();
    cal.setTime(date);
    int day=cal.get(Calendar.DATE);

    // Check for 11, 12, 13 which all take 'th'
    if (!((day > 10) && (day < 19))) {
       switch (day % 10) {
        case 1:  
            return new SimpleDateFormat("d'st' 'of' MMMM yyyy").format(date);
        case 2:  
            return new SimpleDateFormat("d'nd' 'of' MMMM yyyy").format(date);
        case 3:  
            return new SimpleDateFormat("d'rd' 'of' MMMM yyyy").format(date);
        default: 
            return new SimpleDateFormat("d'th' 'of' MMMM yyyy").format(date);
       }
    }
    // Handles 11th, 12th, 13th, and other 'th' cases
    return new SimpleDateFormat("d'th' 'of' MMMM yyyy").format(date);
}

Modern Java Time API (java.time): The Preferred Path

For modern applications, avoiding the legacy date/time classes (Date, Calendar, SimpleDateFormat) is recommended due to their mutability and synchronization issues. java.time offers superior flexibility, especially with DateTimeFormatterBuilder.

Option A: Using DateTimeFormatterBuilder.appendText with a Map

This is the most elegant way to handle localized ordinal formatting in modern Java. It requires building a map of day numbers to their specific ordinal strings.

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeFormatterBuilder;
import java.time.temporal.ChronoField;
import java.time.Month;
import java.util.HashMap;
import java.util.Map;

// Build the map for specific ordinals
Map<Long, String> ordinalNumbers = new HashMap<>(42);
ordinalNumbers.put(1L, "1st");
ordinalNumbers.put(2L, "2nd");
ordinalNumbers.put(3L, "3rd");
ordinalNumbers.put(21L, "21st");
ordinalNumbers.put(22L, "22nd");
ordinalNumbers.put(23L, "23rd");
ordinalNumbers.put(31L, "31st");

// Fill in the rest as 'Nth'
for (long d = 1; d <= 31; d++) {
    ordinalNumbers.putIfAbsent(d, "" + d + "th");
}

DateTimeFormatter dayOfMonthFormatter = new DateTimeFormatterBuilder()
        .appendText(ChronoField.DAY_OF_MONTH, ordinalNumbers)
        .appendPattern(" MMMM") // Append month name
        .toFormatter();

LocalDate date = LocalDate.of(2018, Month.AUGUST, 30);
for (int i = 0; i < 6; i++) {
    System.out.println(date.format(dayOfMonthFormatter));
    date = date.plusDays(1);
}
// Output includes: 30th August, 31st August, 1st September, 2nd September...

Option C: Custom Formatting with switch Expressions (Java 14+)

For newer Java versions, you can format the date partially and then use a helper method with modern switch expressions to insert the suffix.

ZonedDateTime ldt = ZonedDateTime.now();
// Format pattern leaves placeholders for day and suffix
String format = ldt.format(DateTimeFormatter
        .ofPattern("EEEE, MMMM '%s%s,' yyyy hh:mm:ss a zzz"));
int day = ldt.getDayOfMonth();
System.out.println(applyOrdinalDaySuffix(format, day));

public static String applyOrdinalDaySuffix(String format, int day) {
    if (day < 1 || day > 31)
        throw new IllegalArgumentException(
                String.format("Bad day of month (%s)", day));
    String ord = switch (day) { // Java 14+ switch expression
        case 1, 21, 31 -> "st";
        case 2, 22 -> "nd";
        case 3, 23 -> "rd";
        default -> "th";
    };
    
    return String.format(format, day, ord);
}

Advanced Contexts: ICU4J and Parsing Logic

Internationalization with ICU4J

For solutions that strictly adhere to internationalization standards, the ICU4J library’s RuleBasedNumberFormat is recommended, as it handles locale-specific ordinal rules beyond simple English suffixes.

import com.ibm.icu.text.RuleBasedNumberFormat;
import java.util.Locale;
import java.time.ZonedDateTime;
import java.time.ZoneId;

RuleBasedNumberFormat numOrdinalFormat = new RuleBasedNumberFormat(Locale.UK,
    RuleBasedNumberFormat.ORDINAL);
ZonedDateTime zdt = ZonedDateTime.now(ZoneId.of("Pacific/Auckland"));

String dayNumAndOrdinal = numOrdinalFormat.format(zdt.toLocalDate().getDayOfMonth());
// Output: e.g., "3rd"

Reversing the Process: Parsing Dates with Ordinals

If you need to parse a string that already contains an ordinal suffix (e.g., “15th March 2024”), standard formatters fail. One technique involves stripping the suffix before parsing.

public static final SimpleDateFormat sdf = new SimpleDateFormat("d");
public static final Pattern p = Pattern.compile("([0-9]+)(st|nd|rd|th)");

private static Date getDateFromDateString(String dateString) throws ParseException {
     return sdf.parse(deleteOrdinal(dateString));
}

private static String deleteOrdinal(String dateString) {
    Matcher m = p.matcher(dateString);
    while (m.find()) {
        // Replace the full match (e.g., "15th") with just the number part ("15")
        dateString = dateString.replaceAll(Matcher.quoteReplacement(m.group(0)), m.group(1));
    }
    return dateString;
}

Generic Suffix Calculation (Handling Teens Correctly)

A more mathematically robust way to calculate the suffix, particularly important for numbers over 100 (where 111 should be 111th, not 111st), relies on modulo arithmetic against 100 and 10.

public static String getOrdinalSuffix( int value )
{
    int hunRem = value % 100;
    int tenRem = value % 10;

    // Check if the last two digits are 11, 12, or 13 (the 'teen' exceptions)
    if ( hunRem >= 11 && hunRem <= 13 )
    {
        return "th";
    }
    switch ( tenRem )
    {
    case 1:
        return "st";
    case 2:
        return "nd";
    case 3:
        return "rd";
    default:
        return "th";
    }
}
// Usage: String suffix = value + getOrdinalSuffix(value);

FAQs on Java Ordinal Date Suffix Formatting

Q: Which Java API is best for English ordinal dates

ANS: For modern Java, use the java.time API with DateTimeFormatterBuilder and a custom map of ordinal numbers for the most flexible and locale-aware formatting.

Q: Does SimpleDateFormat support ordinal day formatting directly

ANS: No, SimpleDateFormat lacks a built-in pattern character for ordinal suffixes. You must use string concatenation or pattern literal quoting (e.g., ‘st’) combined with custom logic to determine the suffix.

Q: How to handle 11th, 12th, and 13th correctly

ANS: The suffix logic must explicitly check if the day modulo 100 falls between 11 and 13, as these numbers all use “th”, overriding the standard 1st, 2nd, 3rd rules.

Q: What is the benefit of using Guava for this

ANS: Guava provides Preconditions.checkArgument, which validates the day of the month (1-31) immediately, leading to cleaner error handling if invalid data is passed to the suffix generation function.
