“Jackson Serialization Control: How to Omit Null Fields in JSON Output”

When serializing Java objects to JSON using the Jackson library, a common requirement is to suppress properties that hold null values. This practice keeps the resulting JSON payload clean and minimizes unnecessary data transfer. Several techniques exist to achieve this, depending on whether you prefer configuration at the ObjectMapper level, class level, or via application properties.

Configuring Serialization Inclusion Globally via ObjectMapper

You can dictate that all subsequent serialization operations should ignore null values by setting the serialization inclusion on the ObjectMapper instance.

For Jackson versions 2.0 and later, the preferred method uses setSerializationInclusion(Include.NON_NULL):

import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.annotation.JsonInclude.Include;

// Example for Jackson 2.x+
ObjectMapper mapper = new ObjectMapper();
mapper.setSerializationInclusion(Include.NON_NULL);

// Or using the builder pattern in newer versions (like 2.5+)
// mapper.setSerializationInclusion(Include.NON_NULL);

An older approach, still functional in some contexts or earlier versions, involves accessing getSerializationConfig():

// Pre-Jackson 2.5 approach or alternative configuration
mapper.getSerializationConfig().setSerializationInclusion(Inclusion.NON_NULL);

// Or using withSerializationInclusion in Jackson 2.x+
// mapper.getSerializationConfig().withSerializationInclusion(JsonInclude.Include.NON_NULL);

A separate, more granular control is required if you need to ignore nulls specifically within collections (like Maps) during serialization, as noted in documentation references. For instance, to exclude Maps that contain only null values, you might combine settings:

public class Bean {
   // Excludes the map if it's empty or contains only null values
   @JsonInclude(value=Include.NON_EMPTY, content=Include.NON_NULL)
   public Map<String,String> entries;
}

Controlling Null Omission at the Class or Field Level with Annotations

Annotations provide fine-grained control, allowing you to specify behavior per class or per field, even overriding global settings.

Class-Level Annotation for Default Behavior

To make omitting nulls the default behavior for an entire class, apply @JsonInclude(Include.NON_NULL) to the class definition:

import com.fasterxml.jackson.annotation.JsonInclude;

@JsonInclude(JsonInclude.Include.NON_NULL)
public class DataModel {
    private String fieldOne; // Omitted if null
    private String fieldTwo; // Omitted if null
    
    // This field overrides the class default to ALWAYS be included
    @JsonInclude(JsonInclude.Include.ALWAYS)
    private String fieldThree; 
}

The NON_EMPTY inclusion is another option. It suppresses fields that are null or empty (e.g., empty strings, empty lists/arrays).

@JsonInclude(Include.NON_EMPTY)
class AnotherModel {
    String bar; // Omitted if null OR ""
}

Field-Level Annotation for Specific Control

You can apply the annotation directly to fields or their corresponding getter methods to control inclusion on an individual basis. If the class has a default setting, field annotations can override it.

public class FieldSpecificModel {

    @JsonInclude(JsonInclude.Include.NON_NULL) 
    private String fieldOne; // Omitted if null

    private String fieldTwo; // Follows class default (or ALWAYS included if no class default)
}

Jackson Version Compatibility: @JsonSerialize vs. @JsonInclude

It is vital to use the correct annotation based on your Jackson library version:

  1. Jackson 2.x and Newer: Use @JsonInclude.

    @JsonInclude(JsonInclude.Include.NON_NULL)
class MyClass {}

  2. Jackson 1.x (or legacy code): Use @JsonSerialize.

    import org.codehaus.jackson.map.annotate.JsonSerialize;
import org.codehaus.jackson.map.annotate.JsonSerialize.Inclusion;

@JsonSerialize(include=Inclusion.NON_NULL)
public class LegacyModel {
    protected String field1;
}

    If you encounter errors related to deprecated annotations, verify your imports. The newer com.fasterxml.jackson.databind.annotation.JsonSerialize might be deprecated in favor of @JsonInclude.

Spring Boot Application Property Configuration

For applications managed by Spring Boot, you can configure the default Jackson inclusion globally via configuration files, ensuring consistency across all DTOs without modifying code annotations.

In application.properties:

spring.jackson.default-property-inclusion=non_null

In application.yaml:

spring:
  jackson:
    default-property-inclusion: non_null

The possible values for this property include: always, non_null, non_absent, non_default, and non_empty. Consult the Spring Boot reference documentation for deeper configuration details.

Advanced Scenario: Ignoring Nulls in Lists During Serialization

If you have a list containing objects, and some elements within that list are null (e.g., [objectA, null, objectB]), applying NON_NULL to the object class itself will not remove the null placeholder from the JSON array structure: [{"prop":"val"}, null, {"prop":"val2"}].

To explicitly remove these null array elements, you must customize the NullValueSerializer on the ObjectMapper:

import com.fasterxml.jackson.core.JsonGenerator;
import com.fasterxml.jackson.databind.JsonSerializer;
import com.fasterxml.jackson.databind.SerializerProvider;
import java.io.IOException;

// ... after setting NON_NULL globally ...

mapper.getSerializerProvider().setNullValueSerializer(new JsonSerializer<Object>() {
    @Override
    public void serialize(Object obj, JsonGenerator jsonGen, SerializerProvider unused)
            throws IOException
    {
        // This implementation explicitly ignores null values during array serialization
    }
});
// Resulting list serialization: [{"prop":"val"}, {"prop":"val2"}]

Spring Boot Global Configuration via Bean Definition

When working within a Spring @Configuration, you can customize the ObjectMapper bean builder to enforce global serialization rules for all beans:

import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.json.Jackson2ObjectMapperBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class JsonConfigurations {

    @Bean
    public Jackson2ObjectMapperBuilder objectMapperBuilder() {
        Jackson2ObjectMapperBuilder builder = new Jackson2ObjectMapperBuilder();
        
        // Set global non-null inclusion rule
        builder.serializationInclusion(JsonInclude.Include.NON_NULL);
        
        // Optionally combine with NON_EMPTY if needed
        builder.serializationInclusion(JsonInclude.Include.NON_EMPTY);
        
        // Good practice to disable deserialization errors for unknown properties
        builder.failOnUnknownProperties(false);
        return builder;
    }
}

FAQs on Jackson Serialization Control

Q: What is the difference between JsonInclude NON_NULL and NON_EMPTY

ANS: Include.NON_NULL omits properties only if their value is strictly null. Include.NON_EMPTY omits properties if their value is null or if the value is considered empty (e.g., an empty String "" or an empty Collection/Map).

Q: Can I use both NON_NULL and NON_EMPTY annotations

ANS: Yes, you can apply both annotations, for example, on a field. If both are present, the field will only be serialized if its value is neither null nor empty.

Q: What annotation applies for Jackson 1 x versions

ANS: For older Jackson versions, you should use @JsonSerialize(include=JsonSerialize.Inclusion.NON_NULL) instead of @JsonInclude. Ensure you use the correct package imports (often org.codehaus.jackson).

Q: How do I apply this setting globally in Spring Boot

ANS: You can configure the setting via spring.jackson.default-property-inclusion=non_null in your application.properties or YAML file, or by providing a custom Jackson2ObjectMapperBuilder bean in a configuration class.
