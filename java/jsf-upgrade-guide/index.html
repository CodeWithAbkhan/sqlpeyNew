“JSF 1.2 to 2.0 Upgrade: View Technology & Configuration Guide”

Migrating from JavaServer Faces (JSF) 1.2 to JSF 2.0 involves several considerations, primarily revolving around your application’s view technology and configuration files. The “painfulness” of this transition largely correlates with the specific view technologies you’re employing and those you intend to adopt.

Here’s a breakdown of the process and key changes:

Assessing the Effort Based on View Technology

The complexity of the upgrade hinges on your current and target view technologies:

  • JSP 2.x to JSP 2.x: This transition requires minimal effort, with few changes needed beyond core JSF updates.
  • Facelets 1.x to Facelets 2.0: Expect a small amount of work, primarily involving the removal of old Facelets JARs and configuration adjustments.
  • JSP 2.x to Facelets 2.0: This presents the most significant undertaking, potentially doubling the effort if custom components are involved. This scenario requires a fundamental shift in your view rendering approach.

Core Configuration Updates for JSF 2.0

Regardless of your view technology choice, certain fundamental configuration steps are essential:

  1. Library Management:

    • Remove any JSF 1.2 JAR files from your /WEB-INF/lib directory.
    • Introduce JSF 2.0 JAR files into /WEB-INF/lib. If JSF 1.2 was supplied by the servlet container, you might need to adjust classloading policies to prioritize web application libraries. Refer to JSF2 classloading discussions for application server specifics.

  2. faces-config.xml Adjustment:

    • Update the root declaration of your faces-config.xml to conform to the JSF 2.0 specification. For JSF 2.0, this looks like: 
      <faces-config
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-facesconfig_2_0.xsd"
  version="2.0">
</faces-config>
    • Important Note: For JSF 2.2 and later versions, use the http://xmlns.jcp.org namespace domain instead of http://java.sun.com.

  3. web.xml Servlet Specification:

    • Verify that your web.xml is configured for at least Servlet 2.5. JSF 2.0 is not compatible with Servlet 2.4 or earlier. 
      <web-app 
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:web="http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
  id="YourWebappID"
  version="2.5">
</web-app>
    • Important Note: For Servlet 3.0 and later, use the http://xmlns.jcp.org namespace domain.

Migrating View Technologies

JSP 2.x to JSP 2.x Transition

If your application predominantly uses JSP 2.x and you plan to continue this, the core JSF updates are generally sufficient.

  • Gradual Upgrading with URL Patterns: If you’re using a suffix URL pattern (e.g., *.jsf) for your FacesServlet, JSF 2.0 will prioritize .xhtml files but can fall back to .jsp. This allows for a phased migration from JSP to Facelets without immediate URL changes. However, if you use a prefix pattern (e.g., /faces/*) and aim for a JSP to Facelets shift, you’ll likely need to change this to *.jsf and update links within your JSP pages.
  • Navigation Handling: Be aware that JSF 2.0’s implicit navigation doesn’t rely on file existence. If you need to navigate to or from .jsp files, you’ll still need to include the .jsp extension in the viewid as done in JSF 1.x.
Facelets 1.x to Facelets 2.0 Transition

When moving from Facelets 1.x to the JSF 2.0-provided Facelets 2.0, perform these additional steps:

  • Remove the Facelets 1.x JAR from /WEB-INF/lib.
  • Remove the FaceletViewHandler for Facelets 1.x from your faces-config.xml.
  • Any custom FaceletViewHandler implementations should be updated to extend ViewHandlerWrapper.
  • For tidiness, remove obsolete <context-param> values in web.xml related to Facelets 1.x (like javax.faces.DEFAULT_SUFFIX with *.xhtml), as these are defaults in Facelets 2.0.
  • Update the root declaration of your Facelet tag library XML files for Facelets 2.0 compliance: 
    <facelet-taglib 
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-facelettaglibrary_2_0.xsd"
  version="2.0">
</facelet-taglib>
    • Important Note: For JSF 2.2 and later, use the http://xmlns.jcp.org namespace.
JSP 2.x to Facelets 2.0 Transition

Migrating directly from JSP 2.x to Facelets 2.0 requires substantial changes across your application’s views.

  • Master Page Modifications: Every master page needs transformation. A typical JSP template:

    <%@page contentType="text/html" pageEncoding="UTF-8"%>
<%@taglib prefix="f" uri="http://java.sun.com/jsf/core"%>
<%@taglib prefix="h" uri="http://java.sun.com/jsf/html"%>
<!DOCTYPE html>
<f:view>
    <html lang="en">
        <head>
            <title>JSP page</title>
        </head>
        <body>
            <h:outputText value="JSF components here." />
        </body>
    </html>
</f:view>

    Must be converted to a Facelets template:

    <!DOCTYPE html>
<html lang="en"
    xmlns="http://www.w3.org/1999/xhtml"
    xmlns:f="http://java.sun.com/jsf/core"
    xmlns:h="http://java.sun.com/jsf/html"
    xmlns:ui="http://java.sun.com/jsf/facelets">
    <h:head>
        <title>XHTML page</title>
    </h:head>
    <h:body>
        <h:outputText value="JSF components here." />
    </h:body>  
</html>
    • Important Note: For JSF 2.2 and later, use the http://xmlns.jcp.org namespace.

  • Page Includes: Replace JSP’s <jsp:include> with Facelets’ <ui:include>. If your JSP pages are well-structured without scriptlets, this is straightforward.

    • From JSP: 
      <jsp:include page="include.jsp" />
    • To Facelets: 
      <ui:include src="include.xhtml" />
    • The include page templates also require conversion:
      • JSP include template: 
        <%@page contentType="text/html" pageEncoding="UTF-8"%>
<%@taglib prefix="f" uri="http://java.sun.com/jsf/core"%>
<%@taglib prefix="h" uri="http://java.sun.com/jsf/html"%>
<f:subview id="include">
    <h:outputText value="JSF components here." />
</f:subview>
      • Facelets include template: 
        <ui:composition
    xmlns="http://www.w3.org/1999/xhtml"
    xmlns:f="http://java.sun.com/jsf/core"
    xmlns:h="http://java.sun.com/jsf/html"
    xmlns:ui="http://java.sun.com/jsf/facelets">
    <h:outputText value="JSF components here." />
</ui:composition>
        • Important Note: For JSF 2.2 and later, use the http://xmlns.jcp.org namespace.

  • Custom Component Handling: JSP Tag Library Descriptor (TLD) files need to be transformed into Facelets TLD files. Consult the Mojarra Migration Guide for detailed instructions.

Leveraging JSF 2.0 Annotations

JSF 2.0 introduces annotations, allowing you to gradually eliminate faces-config.xml.

  • Managed Beans: Replace <managed-bean> with @ManagedBean: 
    @ManagedBean(name="managedBeanName") // 'name' is optional, defaults to 'someBean'
@RequestScoped // Other scopes: @ViewScoped, @SessionScoped, @ApplicationScoped
public class SomeBean {}
  • Managed Properties: Use @ManagedProperty: 
    @ManagedProperty("#{otherBean}")
private OtherBean otherBean;
  • Validators: Use @FacesValidator: 
    @FacesValidator("someValidator")
public class SomeValidator implements Validator {}
  • Converters: Use @FacesConverter: 
    @FacesConverter("someConverter")
public class SomeConverter implements Converter {}
  • Renderers: Use @FacesRenderer: 
    @FacesRenderer(componentFamily="someComponentFamily", rendererType="someRendererType")
public class SomeRenderer extends Renderer {}
  • Navigation Rules: Implicit navigation handles outcomes matching filenames. You can transition by ensuring outcome values align with target .xhtml filenames.

Scoped Bean Considerations

For session-scoped beans holding data across requests within the same tab/window, consider using @ViewScoped. This prevents data interference when the same page is opened in multiple tabs concurrently, unlike @SessionScoped.

Third-Party Component Libraries

Upgrading third-party libraries (like PrimeFaces, RichFaces, IceFaces) requires consulting their specific migration guides. Generally, this involves updating to a JSF 2.0-compatible version. Thorough unit testing before and after the upgrade is crucial to identify and resolve issues.

  • RichFaces: Refer to their migration guides (e.g., 3.3.x to 4.x).
  • IceFaces: Check their compatibility guides for 1.x to 2.x.
  • PrimeFaces: PrimeFaces 1.x often relies on Facelets 1.x. For PrimeFaces 2.x to 3.x (and higher) migration, specific guides are available.
  • Tomahawk: No specific migration guide exists. Primarily, update JARs. If using request-scoped beans with <t:saveState>, consider switching to view-scoped beans.

JSTL Namespace Update

If your JSF 1.2 application uses JSTL, remember to update the JSTL core namespace from http://java.sun.com/jstl/core to http://java.sun.com/jsp/jstl/core when migrating to JSF 2.0.

Example Configurations and Snippets

Here are some key XML and code snippets illustrating the changes:

<!-- faces-config.xml update for JSF 2.0 -->
<faces-config
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-facesconfig_2_0.xsd"
  version="2.0">
</faces-config>

<!-- web.xml update for Servlet 2.5+ -->
<web-app 
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:web="http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
  id="YourWebappID"
  version="2.5">
  
    <servlet>
            <servlet-name>facesServlet</servlet-name>
            <servlet-class>javax.faces.webapp.FacesServlet</servlet-class>
            <load-on-startup>1</load-on-startup>
    </servlet>

    <servlet-mapping>
        <servlet-name>facesServlet</servlet-name>
        <url-pattern>*.xhtml</url-pattern>
    </servlet-mapping>
    <!-- Other servlet mappings like *.jsf, *.faces might be needed -->
</web-app>

<!-- Facelets taglib declaration for JSF 2.0 -->
<facelet-taglib 
  xmlns="http://java.sun.com/xml/ns/javaee"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-facelettaglibrary_2_0.xsd"
  version="2.0">
</facelet-taglib>

<!-- Example of JSP to Facelets page transformation -->
<jsp:include page="include.jsp" />
<!-- becomes -->
<ui:include src="include.xhtml" />

Potential Challenges with Third-Party Libraries

Libraries like RichFaces and IceFaces have specific migration paths. For instance, RichFaces 3.x to 4.x requires careful attention. PrimeFaces, while not having a direct 1.x to 2.x guide, often aligns with Facelets migration. Tomahawk may primarily necessitate JAR updates and potential adjustments for <t:saveState> on request-scoped beans, moving them to view scope. Writing robust unit tests is the best strategy for validating these library upgrades.

FAQs on JSF 1.2 to 2.0 Upgrade

Q: What is the main factor determining the difficulty of a JSF 1.2 to 2.0 upgrade

ANS: The primary factor is your application’s current and intended view technology. Migrating between JSP versions is typically easier than switching from JSP to Facelets.

Q: Do I need to update my web dot xml file when upgrading JSF

ANS: Yes, you must ensure your web.xml is configured for at least Servlet 2.5, as JSF 2.0 is not compatible with older servlet specifications.

Q: How does JSF 2.0 handle navigation differently from JSF 1.2

ANS: JSF 2.0 features implicit navigation that doesn’t strictly require file existence checks. However, when navigating to or from JSP files, you still need to include the file extension in the view ID, similar to JSF 1.2.

Q: Can I use annotations instead of faces dot config dot xml in JSF 2.0

ANS: Yes, JSF 2.0 supports annotations for managed beans, properties, validators, converters, and renderers, allowing you to phase out faces-config.xml over time.

Q: What should I do with managed properties in faces dot config dot xml during migration

ANS: Managed properties can be transitioned to the @ManagedProperty annotation in your Java beans.

Q: Are there specific steps for migrating custom Facelets ViewHandlers

ANS: Yes, custom FaceletViewHandler implementations need to be updated to extend ViewHandlerWrapper in JSF 2.0.

Q: How do I handle JSTL namespaces when upgrading JSF

ANS: Update the JSTL core namespace from http://java.sun.com/jstl/core to http://java.sun.com/jsp/jstl/core.

Q: What is the recommended approach for third party JSF component libraries

ANS: Upgrade to a JSF 2.0 compatible version of the library and thoroughly test your application. Consult the library’s specific migration documentation.

Q: Should I change scoped beans during JSF 1.2 to 2.0 upgrade

ANS: If you’re using session-scoped beans to maintain state across requests in a single tab, consider switching to @ViewScoped in JSF 2.0 for better behavior with multiple tabs.
