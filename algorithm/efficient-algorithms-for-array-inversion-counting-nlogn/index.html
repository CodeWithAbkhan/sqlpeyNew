The Merge Sort Modification: Counting During Merging

The most frequently cited and effective method involves adapting the Merge Sort procedure. The core insight is that inversions are implicitly counted during the merge step. When merging two sorted subarrays, $Left$ and $Right$, if an element from $Right$ is moved before remaining elements in $Left$, it signifies a set of inversions.

Java Implementation Example (O(n log n))

This Java solution illustrates how the merge function identifies and accumulates inversions:

long merge(int[] arr, int[] left, int[] right) {
    int i = 0, j = 0;
    long count = 0;
    while (i < left.length || j < right.length) {
        if (i == left.length) {
            arr[i+j] = right[j];
            j++;
        } else if (j == right.length) {
            arr[i+j] = left[i];
            i++;
        } else if (left[i] <= right[j]) {
            arr[i+j] = left[i];
            i++;                
        } else {
            // When an element from the right subarray is chosen, it forms
            // an inversion with all remaining elements in the left subarray.
            arr[i+j] = right[j];
            count += left.length - i; // Key inversion counting step
            j++;
        }
    }
    return count;
}

long invCount(int[] arr) {
    if (arr.length < 2)
        return 0;

    int m = (arr.length + 1) / 2;
    int left[] = java.util.Arrays.copyOfRange(arr, 0, m);
    int right[] = java.util.Arrays.copyOfRange(arr, m, arr.length);

    return invCount(left) + invCount(right) + merge(arr, left, right);
}

This logic is echoed across multiple languages:

  • C++ Adaptation: Similar logic is shown in a C++ approach where count = count + size1 - a; performs the crucial addition when an element from the right array is merged before elements remaining in the left array (size1 - a being the count of remaining left elements).
  • Java Solution: A clean recursive Java implementation directly incorporates the inversion addition inversionCount += (medium + 1 - i); in its merge routine.
  • Python Merge Sort Variant: A Python recursive implementation similarly calculates count += left_len - i during the split merge step.

Alternative $O(n \log n)$ Strategies

While Merge Sort is prevalent, other structures also provide the required efficiency by leveraging fast prefix sum queries or relative ordering after sorting.

1. Binary Indexed Tree (Fenwick Tree)

A Binary Indexed Tree (BIT) allows for rapid prefix sum calculations and single-point updates, both in $O(\log n)$ time. To count inversions:

  1. Coordinate Compression/Ranking: Map the array values to their ranks (1 to $n$) since the BIT operates on indices.
  2. Iterate Backwards: Process the array elements from right to left.
  3. Query and Update: For an element $x$ (with rank $r_x$):
    • Query the BIT for the sum of frequencies up to $r_x - 1$. This sum represents elements already processed (to the right of $x$) that are strictly smaller than $x$.
    • Update the BIT at index $r_x$ to mark $x$’s presence.

The approach suggested by Niklas B uses this structure:

def count_inversions_NiklasB(a):
  res = 0
  counts = [0]*(len(a)+1)
  # Rank maps value to 1-based index in sorted array
  rank = { v : i+1 for i, v in enumerate(sorted(a), 1) } 
  for x in reversed(a):
    i = rank[x] - 1
    while i:
      res += counts[i] # Query for elements smaller than x already seen (to the right)
      i -= i &amp; -i
    i = rank[x]
    while i <= len(a):
      counts[i] += 1 # Update count for x
      i += i &amp; -i
  return res

2. Binary Search with List Manipulation

This method, exemplified by Solution 2 (“python” approach) and Solution 21 (Diablo’s answer), involves sorting a copy of the array ($B$) and iteratively finding the current element ($A[i]$) in $B$, adding its index to the count, and removing it from $B$.

For an element $A[i]$, its index $j$ in the sorted list $B$ indicates that $j$ elements smaller than $A[i]$ exist among the elements not yet processed (which were originally to the right of $A[i]$). Handling duplicates requires careful index adjustment (e.g., repeatedly searching backward from the found index until a different element is hit).

If implemented with Python lists where list.pop(j) takes $O(n)$, the total time complexity reverts to $O(n^2)$. However, if list removal/insertion is $O(\log n)$ (e.g., using a balanced BST or specialized structure), the $n$ iterations of $O(\log n)$ steps maintain $O(n \log n)$ overall.

3. Tree-Based Counting (Augmented Binary Tree)

An $O(n \log n)$ solution can be built using an augmented Binary Search Tree (BST), similar to an Order Statistic Tree. Each node stores not only its value but also the size of its right subtree (rightSubTreeSize).

When inserting a new element $p$:

  • If $p$ goes to the left child $q$ ($p \le q.data$): The inversion count for $p$ increases by $1$ plus the size of $q$’s right subtree.
  • If $p$ goes to the right child $q$ ($p > q.data$): Increment $q$’s rightSubTreeSize.

This approach, detailed in Solution 10, yields $O(\log n)$ per insertion, totaling $O(n \log n)$.

Performance Comparisons

Extensive timing tests (like those in Solution 5 and Solution 12) reveal nuances in real-world performance on CPython:

  • For small to moderate lists, highly optimized approaches leveraging built-in functions (like Tim Babych’s bisection method using bisect) often win due to low constant factors, even if the theoretical structure is similar to others.
  • For very large datasets, true $O(n \log n)$ algorithms like specialized Merge Sort variants or Fenwick Trees remain superior to methods relying on linear scans or expensive list removals ($O(n^2)$ structures hidden in the loops).
