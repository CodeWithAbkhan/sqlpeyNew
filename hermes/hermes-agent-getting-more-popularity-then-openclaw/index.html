AI agents have become one of the most transformative technologies in software development, and Hermes Agent by Nous Research stands at the forefront of this revolution. Unlike conventional AI assistants that operate in stateless isolation, Hermes introduces a paradigm shift: the agent that grows with you. With over 150,000 GitHub stars and an active community of thousands of developers, Hermes has rapidly become the most significant open-source AI agent project in existence.

Everything you need to know about Hermes Agent — from its philosophical foundations and architectural innovations to practical installation, configuration, and advanced usage patterns. Whether you are a developer evaluating agent frameworks, a DevOps engineer looking for automation, or a researcher exploring the boundaries of LLM-based agents, this guide will give you a thorough understanding of what makes Hermes unique and how to leverage its full potential.

What is Hermes Agent?

Hermes Agent is an open-source, self-improving AI agent developed by Nous Research , a leading research organization pushing the boundaries of open-source AI. At its core, Hermes is built around a radical idea: an AI agent should not merely respond to queries but should actively learn from every interaction, build upon past experiences, and become increasingly capable over time.

The Core Philosophy

The traditional AI assistant model treats every conversation as isolated. You ask a question, get an answer, and the next conversation starts from a blank slate. This is like having a brilliant colleague who suffers from amnesia — capable of remarkable insights but unable to build on previous work. Hermes rejects this model entirely.

Instead, Hermes maintains a persistent cognitive architecture that includes:

  • Episodic memory: Full-text searchable history of every interaction
  • Semantic memory: Extracted knowledge, facts, and relationships
  • Procedural memory: Reusable skills created and refined through experience
  • User modeling: A deepening understanding of your preferences, communication style, and working patterns

This architecture enables Hermes to exhibit behaviors that feel remarkably human-like in their continuity. Start a conversation about a project on Monday, return on Wednesday, and Hermes remembers not just the facts but the context, decisions, rationale, and even the emotional tone of previous discussions.

Why Hermes Matters Now

The AI agent landscape has bifurcated into two unsatisfying camps. On one side, we have chatbots — ChatGPT, Claude, Gemini — that are incredibly capable in single conversations but forget everything the moment you close the window. On the other side, we have automation frameworks — tools like AutoGPT, LangChain agents — that can execute multi-step tasks but require extensive configuration, prompt engineering, and ongoing maintenance.

Hermes occupies a rare and valuable middle ground. It is both conversational and persistent, adaptable without manual retraining, and capable of operating autonomously while remaining responsive to direction. The project’s 150,000+ GitHub stars and 8,300+ commits reflect a community that recognizes this gap and is actively building the solution.

The Self-Improvement Loop

What truly sets Hermes apart is its closed learning loop. Most AI agents are static — they use the same capabilities they started with. Hermes, by contrast, improves itself continuously:

  1. Execute: Hermes performs a task, possibly using multiple tools and spanning many turns
  2. Reflect: After completing the task, the agent analyzes what it did and identifies reusable patterns
  3. Create: If the task involved a novel or complex workflow, Hermes autonomously generates a skill
  4. Refine: Each time the skill is used, Hermes evaluates its performance and makes improvements
  5. Persist: Important context, decisions, and learnings are stored in long-term memory
  6. Retrieve: In future conversations, relevant memories and skills are surfaced automatically

This loop means that Hermes becomes more capable with every task it completes, without any manual intervention. A Hermes instance that has been running for months is genuinely more useful than a fresh install.

Key Features in Depth

Closed Learning Loop

The closed learning loop is implemented through a combination of systems working together. When Hermes completes a complex multi-step task — say, setting up a Docker Compose deployment with multiple services — it doesn’t just finish and move on. The agent’s reflection phase evaluates what was accomplished, identifies which parts were novel or difficult, and decides whether to create a persistent skill.

The skill creation process is autonomous but can be guided:

# Hermes creates a skill automatically after complex work
# You can also explicitly trigger creation:
/skill create "docker-compose-deploy" "Deploy multi-service apps with Docker Compose"

Skills created this way are not just static templates. Each subsequent use triggers the agent to evaluate what worked, what didn’t, and whether the skill needs updating. This is procedural memory that evolves.

Persistent Memory Architecture

Memory in Hermes operates on multiple levels, each serving a distinct purpose:

Level 1: Conversation History
Every interaction is stored with FTS5 (Full-Text Search version 5) indexing, the same technology that powers SQLite’s full-text search. This enables instant retrieval of any past conversation fragment by keyword, phrase, or semantic similarity.

/search "Docker deployment on Ubuntu"    # Find all related conversations
/search "what did we decide about logging?"  # Surface past decisions

Level 2: Semantic Memory
Beyond raw conversation storage, Hermes extracts and organizes facts, preferences, and decisions. If you tell Hermes you prefer using Podman over Docker, that preference persists across sessions and influences future recommendations.

Level 3: User Model via Honcho
The Honcho dialectic user modeling system builds a nuanced understanding of who you are over time. It tracks not just what you say but how you say it — your communication style, your decision-making patterns, your technical depth. This enables Hermes to adapt its responses to match your preferences increasingly accurately.

Level 4: Cross-Session Recall
LLM-powered summarization runs periodically, distilling long conversation histories into compact, retrievable summaries. This means Hermes can surface relevant context from months-old conversations without needing the full history in its context window.

Scheduled Automations

Hermes ships with a production-grade cron scheduler integrated directly into the agent core. Unlike external scheduling tools (cron, systemd timers, CI/CD pipelines), Hermes’s scheduler is context-aware — it knows what the agent knows and has access to all its tools and memory.

# Natural language scheduling
/cron add "every morning at 8am" "Check my email, summarize yesterday's activity, prepare a daily briefing, and send to Telegram"

# Standard cron expressions
/cron add "0 2 * * 0" "Full system audit: check disk usage, review logs, verify backups, email report"

# Interval-based
/cron add "every 30 minutes" "Monitor server load and alert if CPU exceeds 80%"

# List and manage
/cron list
/cron pause "daily-briefing"
/cron remove "system-audit"

Cron tasks run in the agent’s full context, with access to tools, memory, and skills. A scheduled task can browse the web, run shell commands, query databases, and deliver results to any connected platform — all automatically.

Architecture Deep Dive

Understanding Hermes’s architecture helps explain why it can do things other agents cannot. The system is composed of several layers that work together seamlessly.

Layer 1: User Interface Layer

The top layer handles all user interactions. Each interface is a separate process that communicates with the agent core through a well-defined protocol:

  • CLI: Lightweight command-line interface for quick interactions
  • TUI: Full terminal user interface with ncurses-based rendering, multiline editing, syntax highlighting, and streaming output
  • Web: Browser-based chat interface (requires WSL2 on Windows for POSIX PTY)
  • Messaging Gateway: Multi-platform bridge handling Telegram, Discord, Slack, WhatsApp, and Signal simultaneously

The gateway architecture is particularly noteworthy. Rather than running separate agent instances for each platform, a single gateway process handles all platform connections and routes messages to a shared agent core. This ensures conversation continuity across platforms.

Layer 2: Agent Core

The agent core is the brain of the system, implemented in Python:

Planner Module The planner decomposes user requests into executable steps. It considers:

  • Current conversation context
  • Available tools and their capabilities
  • Relevant memories from past interactions
  • Installed skills that match the request
  • Resource constraints and execution time estimates

Executor Module The executor runs planned steps, managing:

  • Tool call sequencing and dependency resolution
  • Parallel execution when steps are independent
  • Error handling and retry logic
  • Progress reporting and streaming
  • Subagent spawning for complex workflows

Memory Manager The memory manager handles all persistence:

  • FTS5 indexing of conversation history
  • Semantic extraction and organization
  • User model updates via Honcho
  • Periodic summarization and compression
  • Memory retrieval and relevance scoring

Skill System The skill system manages procedural memory:

  • Skill creation (automatic and manual)
  • Skill versioning and evolution tracking
  • Skill search and retrieval
  • Skill sharing via agentskills.io

Cron Scheduler The scheduler manages timed tasks:

  • Natural language and cron expression parsing
  • Task persistence across restarts
  • Execution logging and error handling
  • Multi-platform result delivery
  • Dependency-aware scheduling

Tool Registry The tool registry maintains the inventory of available tools:

  • Tool discovery and loading
  • Capability advertisement to the planner
  • Permission and approval checking
  • Execution sandboxing
  • Result formatting and streaming

The Agent Loop

The Hermes agent loop is the fundamental operating cycle. Understanding it helps explain why the agent behaves the way it does:

Loop iteration:
  1. Receive → Get input from any connected interface
  2. Contextualize → Retrieve relevant memories, skills, user model
  3. Plan → Decompose into steps using LLM
  4. Execute → Run tools, evaluate results
  5. Stream → Send progress updates to user interface
  6. Reflect → Analyze what happened, extract learnings
  7. Store → Persist memories, update skills, refine model
  8. Output → Deliver final result to user
  9. Learn → Create/improve skills if applicable

Context Window Management

One of the hardest problems in agent systems is managing the LLM’s limited context window. Hermes uses trajectory compression to address this:

  1. Real-time compression: As conversations grow, Hermes summarizes older turns while preserving critical information
  2. Selective retention: The agent decides what to keep verbatim (tool outputs, exact commands) vs. what to summarize (discussion, exploration)
  3. External retrieval: When context from past sessions is needed, Hermes queries its FTS5 index and injects relevant excerpts
  4. Skill invocation: Complex procedures are offloaded to skills, which consume minimal context

This compression happens transparently — users typically don’t notice it happening, but they benefit from the agent’s ability to maintain coherent long-running conversations.

Installation Guide

Hermes is designed to run on virtually any Unix-like system, with growing Windows support. The installation process is fully automated.

Linux, macOS, WSL2, Termux

The recommended installation method uses a single shell command:

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

What the installer does:

  1. System detection: Identifies your OS, architecture, and available package managers
  2. Dependency installation: Installs uv (Python package manager), Python 3.11, Node.js, ripgrep, ffmpeg
  3. Virtual environment: Creates an isolated Python venv at ~/.hermes/venv/
  4. Package installation: Installs Hermes and all dependencies via uv
  5. Shell integration: Adds Hermes to your PATH via shell config files (.bashrc, .zshrc)
  6. Symlink setup: Creates ~/.local/bin/hermes symlink

The entire process takes 2-5 minutes depending on your internet connection.

Post-installation:

# Reload your shell configuration
source ~/.bashrc    # or source ~/.zshrc

# Verify installation
hermes --version

# Start the setup wizard (automatic on first run)
hermes

Windows (Native PowerShell) — Early Beta

Native Windows support is in early beta. It installs and runs but hasn’t been tested as broadly as the Linux path:

# Run in PowerShell as your normal user (not admin)
irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1 | iex

What the Windows installer handles:

  1. Python: Installs Python 3.11 if not present (via official Python installer, silent mode)
  2. uv: Installs the Astral uv package manager
  3. Git: Detects existing Git installations or downloads a portable MinGit (~45MB) to %LOCALAPPDATA%\hermes\git
  4. Dependencies: Installs ripgrep, ffmpeg via winget or portable download
  5. Virtual environment: Creates venv at %LOCALAPPDATA%\hermes\venv
  6. Shell integration: Adds to PowerShell profile

The portable MinGit is completely isolated from any system Git installation — no environment changes, no registry modifications, no admin required.

Manual Installation

For advanced users or air-gapped environments:

# Clone the repository
git clone https://github.com/NousResearch/hermes-agent.git
cd hermes-agent

# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create virtual environment
uv venv .venv --python 3.11

# Activate it
source .venv/bin/activate

# Install Hermes with all features
uv pip install -e ".[all,dev]"

# Symlink to PATH
ln -s "$(pwd)/hermes" ~/.local/bin/hermes

# Run tests to verify
scripts/run_tests.sh

Docker Installation

# Pull the official image
docker pull nousresearch/hermes-agent

# Run interactively
docker run -it --rm \
  -v ~/.hermes:/root/.hermes \
  nousresearch/hermes-agent

# Run as a daemon (for gateway mode)
docker run -d \
  --name hermes \
  -v ~/.hermes:/root/.hermes \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --restart unless-stopped \
  nousresearch/hermes-agent

Termux (Android)

Hermes runs on Android via Termux. The installation follows the Linux path but uses a curated .[termux] extras set (the full .[all] extras pull Android-incompatible voice dependencies):

Getting Started

Once installed, Hermes guides you through first-time setup interactively.

First Launch

hermes

On first run, Hermes detects that no configuration exists and launches the setup wizard automatically.

Setup Wizard

The setup wizard (hermes setup) is an interactive menu-driven experience that configures everything in one session:

Step 1: Provider Selection Choose your primary LLM provider. The wizard presents available options based on your region and detected dependencies. You can configure multiple providers and switch between them later.

Step 2: Model Selection Pick the specific model to use. The wizard shows available models for your chosen provider, with information about capabilities, context length, and relative cost.

Step 3: API Key Configuration Enter API keys for your chosen providers. The wizard validates each key before proceeding. Keys are stored securely in ~/.hermes/config.yaml with restricted file permissions (600).

Step 4: Tool Permissions Configure which tools Hermes can use and whether they require approval:

# Conceptual configuration
tools:
  file_system:
    enabled: true
    require_approval: sensitive  # approve writes, not reads
  code_execution:
    enabled: true
    require_approval: always     # always approve code execution
  web:
    enabled: true
    require_approval: never      # allow web access freely

Step 5: Platform Connections Optionally connect messaging platforms. The wizard provides QR codes and setup links for each platform.

Step 6: Memory Preferences Configure memory behavior:

  • Conversation retention period
  • Automatic summarization interval
  • Skill auto-creation preference
  • User modeling depth

Skills System in Depth

The skills system is arguably Hermes’s most distinctive feature. It represents a fundamental departure from how most AI agents handle reusable knowledge.

What Are Skills?

Skills are reusable procedural memories — Python-based modules that capture how to perform specific tasks. Unlike prompts or templates, skills are executable code that the agent can invoke, modify, and improve.

Skill Lifecycle

  1. Creation: Skills are created either automatically (after complex tasks) or manually via /skill create

  2. Storage: Skills are stored in ~/.hermes/skills/ with FTS5 indexing for fast retrieval

  3. Versioning: Each skill tracks its version and modification history

  4. Improvement: When a skill is used, Hermes evaluates the outcome and applies improvements

  5. Sharing: Skills can be exported and shared via agentskills.io

  6. Deprecation: Skills that are no longer useful can be archived or deleted

Memory System in Depth

Hermes’s memory architecture is arguably the most sophisticated in any open-source AI agent.

Memory Layers

Layer 1: Episodic Memory (Conversation History)

Every turn of every conversation is stored in a SQLite database with FTS5 full-text search indexing:

-- Under the hood: Hermes stores conversations in a normalized schema
CREATE TABLE conversations (
    id INTEGER PRIMARY KEY,
    platform TEXT,
    started_at TIMESTAMP,
    ended_at TIMESTAMP
);

CREATE TABLE turns (
    id INTEGER PRIMARY KEY,
    conversation_id INTEGER REFERENCES conversations(id),
    role TEXT,  -- 'user', 'assistant', 'tool'
    content TEXT,
    timestamp TIMESTAMP
);

-- FTS5 virtual table for full-text search
CREATE VIRTUAL TABLE turns_fts USING fts5(
    content,
    content=turns, content_rowid=id
);

This enables instant retrieval:

/search "API rate limiting discussion"         # Find conversations about rate limiting
/search --date "last week" "deployment steps"   # Filter by date
/search --exact "port 5432"                     # Exact phrase match

Layer 2: Semantic Memory (Extracted Knowledge)

Hermes periodically extracts structured knowledge from conversations:

# Example: semantic memory entries
extracted_facts:
  - type: preference
    subject: user
    predicate: prefers_db
    object: PostgreSQL
    confidence: 0.95
    source: conversation_20260514
  
  - type: decision
    subject: project
    predicate: deployment_target
    object: staging-01.internal
    context: "Chose hetzner over digital ocean for better RAM/price ratio"
    date: 2026-05-10

Layer 3: User Model (Honcho Integration)

The Honcho dialectic system builds a sophisticated user model:

  • Communication patterns: Verbosity preference, technical depth, formality
  • Decision style: Risk tolerance, thoroughness, speed preference
  • Knowledge areas: Expertise levels across different domains
  • Value system: Priority of different outcomes (security vs. convenience, for example)

Layer 4: Procedural Memory (Skills)

This is the skills system described above — knowledge of how to do things.

Memory Commands

/memory store "fact"       # Explicitly store a fact
/memory forget "topic"     # Remove memories about a topic
/memory search "query"     # Search across all memory layers
/insights --days 30        # Get AI analysis of recent interactions
/compress                  # Manually trigger context compression
/usage                     # Show token and context usage statistics

# deploy_modal.py
import modal
from pathlib import Path

app = modal.App("hermes-agent")

image = modal.Image.from_registry(
    "nousresearch/hermes-agent:latest",
    add_python="3.11"
)

@app.cls(
    image=image,
    secrets=[modal.Secret.from_name("hermes-config")],
    volumes={
        "/root/.hermes": modal.Volume("hermes-data")
    }
)
class HermesAgent:
    @modal.enter()
    def setup(self):
        import subprocess
        subprocess.run(["hermes", "setup", "--non-interactive"])
    
    @modal.web_endpoint(method="POST")
    def chat(self, message: str):
        import subprocess
        result = subprocess.run(
            ["hermes", "--message", message],
            capture_output=True, text=True
        )
        return {"response": result.stdout}

    @modal.asgi()
    def web_ui(self):
        from hermes.web import app
        return app

modal deploy deploy_modal.py

Security

Hermes can execute arbitrary commands, access files, and make network requests. Security is built into every level.

Command Approval

Three levels of command approval control what Hermes can do autonomously:

# Require approval for every tool call
hermes config set require_approval always

# Require approval only for potentially dangerous operations
# (file writes, code execution, network access)
hermes config set require_approval sensitive

# Allow full autonomy (use with caution)
hermes config set require_approval never

When approval is required, Hermes pauses and presents the operation for confirmation:

Hermes wants to execute:
  $ rm -rf /var/log/old-backups/

Allow? [y]es / [n]o / [a]lways allow this command / [v]iew full context >

Allowlist Configuration

For trusted commands, you can configure an allowlist:

# config.yaml
security:

      description: "Git operations"

    - pattern: "systemctl * hermes*"

Frequently Asked Questions

Q: What is Hermes Agent and how is it different from ChatGPT?

Hermes Agent is an open-source, self-improving AI agent built by Nous Research. Unlike ChatGPT which is a stateless chatbot — each conversation starts from scratch with no memory of past interactions — Hermes maintains full conversation history with FTS5 search, extracts semantic memories, builds a user model over time, creates reusable skills, runs scheduled automations, and operates across multiple platforms simultaneously. ChatGPT runs only on OpenAI’s infrastructure while Hermes runs on your own hardware or serverless compute.

Q: What LLM models can I use with Hermes Agent?

Hermes supports 200+ models through OpenRouter, plus direct integrations with OpenAI, Anthropic, Google, Nous Portal, NVIDIA NIM, Hugging Face, Xiaomi MiMo, z.ai/GLM, Kimi/Moonshot, MiniMax, NovitaAI, and any OpenAI-compatible endpoint. You can switch models mid-conversation with /model — no restart required.

Q: Can I run Hermes Agent for free?

Yes. Run it locally on your own machine at no cost, or use Modal or Daytona for serverless deployment that hibernates when idle and costs nearly nothing between sessions. A VPS for 24/7 operation with messaging gateway typically runs $5-10/month.

Q: How does the Hermes skill system work?

After completing complex multi-step tasks, Hermes autonomously creates reusable Python-based skills that capture the task pattern. These skills self-improve during subsequent use — Hermes evaluates the outcome each time and applies refinements automatically. Skills are searchable via FTS5 full-text index and can be shared through the agentskills.io open standard. You can also create, edit, and delete skills manually using /skill commands.

Q: Does Hermes remember past conversations?

Yes. Hermes maintains multiple layers of persistent memory: conversation history with full FTS5 search, extracted semantic memories (facts, preferences, decisions), a user model built via Honcho that adapts to your communication style, and procedural memory in the form of reusable skills. All memory persists across restarts and is accessible across sessions. This means you can reference something from weeks ago and Hermes will recall it.

Q: What platforms and messaging apps does Hermes support?

Hermes operates on Telegram, Discord, Slack, WhatsApp, Signal, CLI/TUI, web interface, and Home Assistant. All platforms connect through a single gateway process, so you can start a conversation on Telegram and continue it from the CLI with full context preserved.

Q: Is Hermes Agent secure? Can I control what it accesses?

Yes. Hermes includes configurable command approval workflows (always, sensitive-only, or never require approval), Docker container isolation for filesystem protection, DM-only pairing for messaging platforms, and encrypted secret storage. You decide exactly which tools it can use and whether each operation needs explicit confirmation.

Q: What hardware do I need to run Hermes?

For cloud-based models (the recommended configuration), any modern system with 200MB RAM and 500MB storage works — including a $5 VPS. For running local models, you need GPU hardware with at least 8GB VRAM for 7B parameter models.

Q: Can Hermes browse the web and execute code?

Yes. Through its web browsing toolset, Hermes can make HTTP requests, scrape pages with JavaScript rendering, interact with APIs, and follow RSS feeds. It can also write, test, execute, and debug code in Python, JavaScript, Go, Rust, and other languages. Code execution runs in isolated subagent processes for safety.

Q: How do I migrate from OpenClaw to Hermes?

Run hermes claw migrate. The tool automatically detects existing OpenClaw installations and imports settings, memories, skills, API keys, and messaging configurations. Use hermes claw migrate --dry-run first to preview everything that will be migrated before applying changes.

Q: Can I schedule automated tasks with Hermes?

Yes. Hermes has a built-in cron scheduler. Use natural language like /cron add "every morning at 8am" "Check email and send summary" or standard cron expressions. Tasks run on schedule and deliver results to any connected platform — Telegram, email, Discord, or wherever you prefer.
