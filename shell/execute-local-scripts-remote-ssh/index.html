“Execute Local Scripts on Remote Servers via SSH”

Successfully running local scripts on remote servers via SSH involves several techniques, from simple command piping to more advanced heredoc syntax and automation tools. The primary goal is to transfer the script’s logic to the remote host and have it executed there without manual intervention on the remote machine.

Here are various approaches to achieve this:

Solution 1: Direct Execution via Piping or Redirection

One of the most straightforward methods is to pipe the script’s content directly to an SSH command that invokes a shell on the remote host.

  • Using cat and pipe: This reads the local script and pipes its content to ssh, which then executes it using a shell (like bash) on the remote server.

    cat ./local_script.sh | ssh <user>@<host> 'bash -s'

  • Using ssh with input redirection: Similar to piping, this redirects the local script’s content as standard input to the ssh command.

    ssh <user>@<host> 'bash -s' < ./local_script.sh

    • Note on --: When passing arguments to the remote script, use -- to separate them from the ssh command’s arguments, ensuring they are directed to the script itself.

      ssh <user>@<host> 'bash -s' -- arg1 arg2 < ./local_script.sh

  • On Windows (cmd.exe): You can use the type command to read the script and pipe it to SSH. Ensure your script uses LF line endings.

    type "C:\path\to\script.sh" | ssh username@hostname

Solution 2: Using plink on Windows

For Windows environments, plink.exe (part of the PuTTY suite) offers similar capabilities.

  • Executing a single-line script or combined lines: For multi-line batch scripts on Windows, you can combine lines using &amp;&amp;.

    # For Unix-like scripts on a Windows target
plink root@MachineB -m local_script.sh

# For Windows batch scripts, combine lines with &&
# Original batch script:
# cd C:\Users\ipython_user\Desktop
# python filename.py
# Combined for plink:
# cd C:\Users\ipython_user\Desktop && python filename.py
plink root@MachineB -m local_script.bat

  • Handling complex batch scripts: For more intricate scripts, consider a wrapper batch file that manages the plink execution, including tunneling and process management.

Solution 3: Heredoc Syntax for Inline Scripting

Heredocs provide a powerful way to embed scripts directly within your SSH command, allowing for complex logic and variable passing.

  • Basic Heredoc: This sends the content between ENDSSH markers to the remote shell.

    ssh user@host <<'ENDSSH'
# commands to run on remote host
ENDSSH

  • Nested Heredocs: You can nest heredocs to execute commands on multiple remote hosts sequentially.

    ssh user@host <<'ENDSSH'
# commands on host1
ssh user@host2 <<'END2'
# commands on host2
END2
ENDSSH

  • Indented Heredocs: Using <<- allows for indentation with tabs within the heredoc, which is cleaner for readability.

    ssh user@host <<-'ENDSSH'
    # commands to run on remote host
ENDSSH

  • Passing Local Variables: You can pass local variables to the remote script by defining them before the bash -s command.

    ssh user@host ARG1="$LOCAL_VAR1" ARG2="$LOCAL_VAR2" 'bash -s' <<'ENDSSH'
  # commands using $ARG1 and $ARG2 on the remote host
  echo "Received: $ARG1, $ARG2"
ENDSSH

  • Transferring Functions and Variables with declare: A robust method involves using declare -p for variables and declare -f for functions to transfer context to the remote shell.

    somevar="with spaces"
my_func() { echo "Executing $1"; }

ssh user@server 'bash -s' <<EOT
$(declare -p somevar)
$(declare -f my_func)
my_func "$somevar"
EOT

Solution 4: Executing Scripts with Environment Variables and Aliases

To ensure local variables, functions, or aliases are correctly interpreted on the remote host, careful handling is required.

  • Escaping Variables: When you want to use remote variables, escape them with a backslash (\).

    ssh user2@host2 "echo \$HOME" # Executes echo $HOME on remote, prints remote user's home
ssh user2@host2 "echo $HOME"  # Prints local user's home (if $HOME is defined locally)

  • Using env_parallel (from GNU Parallel): For more complex scenarios involving local functions, variables, and aliases, env_parallel can be effective.

    # Assuming myscript.sh contains function calls
eval "myfun() { \`cat myscript.sh\`; }"
myvar="value"
alias myalias='echo My alias'

env_parallel -S server --nonall myfun ::: dummy

Solution 5: Sourcing Environment Files

It’s good practice to source environment files like .bashrc or .bash_profile on the remote host before executing scripts to ensure consistent environment variable settings.

ssh user@hostname ". ~/.bashrc; cd /path/to/file; . filename.sh"

Solution 6: Automation Tools

For more sophisticated or repeated tasks, consider automation tools.

  • Fabric (Python Library): Fabric is a Python library designed for streamlining SSH-based application deployment and system administration tasks. It offers higher-level abstractions for managing remote execution.

    # Example snippet using Fabric
from fabric import Connection

c = Connection("user@host")
c.run("ls -l")
c.put("local_script.sh", "/tmp/remote_script.sh")
c.run("bash /tmp/remote_script.sh")

  • Ansible: Ansible is a powerful IT automation engine that uses SSH to execute tasks on remote nodes. It’s excellent for managing multiple hosts and complex workflows.

    # playbook.yml example

Solution 7: runoverssh Utility

The runoverssh utility can simplify running local scripts across multiple remote hosts.

sudo apt install runoverssh
runoverssh -s localscript.sh user host1 host2

Solution 8: Using expect for Interactive Sessions

For scripts requiring interactive input or handling password prompts, expect is a valuable tool.

#!/usr/bin/expect
set username "user"
set password "password"
set hosts "hostname"
spawn ssh $username@$hosts
expect "password:"
send -- "$password\r"
expect "$"
send -- "some_command\r"
sleep 5
expect "$"
send -- "exit\r"

Solution 9: sshpass for Non-Interactive Password Authentication

While generally discouraged for security reasons, sshpass can be used with ssh to provide passwords non-interactively, often in conjunction with piped scripts or heredocs. It’s crucial to install sshpass (e.g., sudo apt install sshpass).

export SSHPASS='your_password'
sshpass -e ssh user@host 'bash -s' < local_script.sh

This can be integrated into heredocs as well, but requires careful handling of the password.

Solution 10: Copying Scripts First

A robust and often cleaner approach is to first copy the script to the remote server using scp, and then execute it.

# Copy the script
scp /path/to/local_script.sh user@remote_host:/home/user/remote_script.sh

# Execute the script on the remote host
ssh user@remote_host "bash /home/user/remote_script.sh" 
# Or if it has execute permissions:
ssh user@remote_host "/home/user/remote_script.sh"

FAQs on Execute Local Scripts Remote SSH

Q: How to run a local shell script on a remote server using ssh

ANS: You can pipe the script’s content to ssh with bash -s: cat ./local_script.sh | ssh user@host 'bash -s'. Alternatively, use input redirection: ssh user@host 'bash -s' < ./local_script.sh. For Windows users, plink or type script.sh | ssh user@host can be used.

Q: Can I pass arguments to a script executed remotely via ssh

ANS: Yes, when using bash -s, arguments can be passed after -- to ensure they are directed to the script and not bash itself. For example: ssh user@host 'bash -s' -- arg1 arg2 < local_script.sh.

Q: How to execute multi-line batch scripts on remote Windows machines via plink

ANS: For plink on Windows, multi-line batch scripts can be executed by concatenating the commands with &amp;&amp; within the script file. For complex scenarios, consider a wrapper batch file.

Q: What is the best way to transfer local variables to a remote script executed via ssh

ANS: Using heredocs with declare -p for variables and declare -f for functions is a highly effective and safe method. You can also define environment variables directly in the SSH command line before executing the script.

Q: How can I handle interactive prompts or passwords when running remote scripts

ANS: The expect command or libraries like sshpass (with caution due to security implications) can be used to automate interactive prompts and password entries.
