“C++ Function Multiple Return Values: Strategies & Best Practices”

Returning multiple values from a C++ function is a common programming challenge. While a function traditionally returns a single value, various techniques allow you to convey multiple pieces of information back to the caller. Let’s examine the prominent methods, their advantages, and practical implementations.

Returning Structs or Classes

One of the most idiomatic and clearest approaches in C++ is to define a struct or class that encapsulates the multiple return values. This method offers self-documenting member names, improving code readability and maintainability.

C++11 and Later Example:

This approach uses std::tuple for returning values. C++17’s structured bindings simplify accessing tuple elements.

#include <tuple>
#include <iostream>

// Function returning a tuple of quotient and remainder
std::tuple<int, int> performDivision(int dividend, int divisor) {
    return {dividend / divisor, dividend % divisor};
}

int main() {
    using namespace std;

    // Using structured bindings (C++17) to unpack the tuple
    auto [quotient, remainder] = performDivision(14, 3);

    cout << "Quotient: " << quotient << ", Remainder: " << remainder << endl;
    return 0;
}

C++11 Example using std::make_tuple and std::tie:

#include <tuple>
#include <iostream>

// Function returning a tuple of quotient and remainder
std::tuple<int, int> performDivision_C11(int dividend, int divisor) {
    return std::make_tuple(dividend / divisor, dividend % divisor);
}

int main() {
    using namespace std;

    int quotient_val, remainder_val;

    // Using std::tie to unpack the tuple
    std::tie(quotient_val, remainder_val) = performDivision_C11(14, 3);

    cout << "Quotient (C++11): " << quotient_val << ", Remainder (C++11): " << remainder_val << endl;
    return 0;
}

Returning Structs for Clarity:

For semantic grouping, a struct is often preferred.

#include <iostream>

struct DivisionResult {
    int quotient;
    int remainder;
};

DivisionResult calculateDivision(int dividend, int divisor) {
    return {dividend / divisor, dividend % divisor};
}

int main() {
    using namespace std;

    DivisionResult result = calculateDivision(14, 3);

    cout << "Struct Quotient: " << result.quotient << ", Struct Remainder: " << result.remainder << endl;

    // Can also use structured bindings with structs in C++17
    auto [q, r] = calculateDivision(14, 3);
    cout << "Struct (C++17 binding) Quotient: " << q << ", Struct Remainder: " << r << endl;

    return 0;
}

Using std::pair

For exactly two return values, std::pair is a convenient option. It’s a simple structure already provided by the C++ Standard Library.

#include <utility> // For std::pair and std::make_pair
#include <iostream>

std::pair<int, int> getQuotientAndRemainder(int dividend, int divisor) {
    return std::make_pair(dividend / divisor, dividend % divisor);
}

int main() {
    std::pair<int, int> division_results = getQuotientAndRemainder(10, 3);

    std::cout << "Pair Quotient: " << division_results.first << std::endl;
    std::cout << "Pair Remainder: " << division_results.second << std::endl;

    return 0;
}

Reference Parameters (Out Parameters)

This classic C-style approach involves passing variables by reference or pointer to be populated by the function.

Using References:

#include <iostream>

void divideWithReference(int dividend, int divisor, int& quotient_out, int& remainder_out) {
    quotient_out = dividend / divisor;
    remainder_out = dividend % divisor;
}

int main() {
    int q, r;
    divideWithReference(15, 4, q, r);
    std::cout << "Ref Quotient: " << q << ", Ref Remainder: " << r << std::endl;
    return 0;
}

Using Pointers:

While less common in modern C++, pointers can also be used.

#include <iostream>

void divideWithPointer(int dividend, int divisor, int* quotient_out, int* remainder_out) {
    if (quotient_out) {
        *quotient_out = dividend / divisor;
    }
    if (remainder_out) {
        *remainder_out = dividend % divisor;
    }
}

int main() {
    int q_ptr, r_ptr;
    divideWithPointer(20, 6, &q_ptr, &r_ptr);
    std::cout << "Ptr Quotient: " << q_ptr << ", Ptr Remainder: " << r_ptr << std::endl;
    return 0;
}

out<T> Template for Type Safety and Intent

A more advanced technique involves a custom out<T> template to explicitly mark output parameters, preventing accidental reads of the output variables.

#include <functional>
#include <optional>
#include <iostream>
#include <memory> // For std::aligned_storage

// Simplified out template for demonstration
template<typename T>
struct out {
    std::function<void(T)> target;

    // Constructor for raw pointers
    out(T* t) : target([t](T&& val) { if (t) *t = std::move(val); }) {}

    // Constructor for optional
    out(std::optional<T>* t) : target([t](T&& val) { if (t) t->emplace(std::move(val)); }) {}

    // Constructor for aligned storage (for placement new)
    out(std::aligned_storage_t<sizeof(T), alignof(T)>* t) :
        target([t](T&& val) { ::new((void*)t) T(std::move(val)); }) {}

    // Emplace function to set the value
    template<typename... Args>
    void emplace(Args&&... args) {
        target(T(std::forward<Args>(args)...));
    }
    // Operator to assign value
    template<typename X>
    void operator=(X&& x) {
        emplace(std::forward<X>(x));
    }
};

void safeDivide(int dividend, int divisor, out<int> quotient, out<int> remainder) {
    quotient.emplace(dividend / divisor);
    remainder.emplace(dividend % divisor);
}

int main() {
    int q_safe, r_safe;
    safeDivide(18, 5, out(&q_safe), out(&r_safe));
    std::cout << "Out<T> Quotient: " << q_safe << ", Out<T> Remainder: " << r_safe << std::endl;
    return 0;
}

Continuation Passing Style (CPS)

CPS involves passing a callback function that accepts the results. This is powerful for asynchronous operations or when the number of return values might vary.

#include <functional>
#include <iostream>

void divideCPS(int dividend, int divisor, std::function<void(int, int)> callback) {
    callback(dividend / divisor, dividend % divisor);
}

int main() {
    divideCPS(21, 7, [](int q, int r) {
        std::cout << "CPS Quotient: " << q << ", CPS Remainder: " << r << std::endl;
    });
    return 0;
}

C++17 Variadic Aggregates and Deduction Guides

C++17 enhances aggregate initialization and introduces deduction guides, which can be combined for elegant multiple returns.

#include <iostream>
#include <string>

// Define a generic aggregate
template<typename T1, typename T2, typename T3>
struct MultiResult {
    T1 val1;
    T2 val2;
    T3 val3;
};

// Deduction guide
template<class T1, class T2, class T3>
MultiResult(T1, T2, T3) -> MultiResult<T1, T2, T3>;

MultiResult<int, double, std::string> getMixedData() {
    return {10, 3.14, "Hello C++17"};
}

int main() {
    auto [num, pi_val, message] = getMixedData();

    std::cout << "Mixed Data 1: " << num << std::endl;
    std::cout << "Mixed Data 2: " << pi_val << std::endl;
    std::cout << "Mixed Data 3: " << message << std::endl;

    return 0;
}

Performance Considerations

  • Structs and Tuples: Modern C++ compilers are excellent at optimizing returns of small aggregates like structs and tuples, often employing Return Value Optimization (RVO) or Named Return Value Optimization (NRVO) to avoid unnecessary copying or moving. This makes them highly efficient. For instance, see how std::make_tuple with structured bindings can optimize out: https://godbolt.org/z/133rT9Pcq .
  • Reference Parameters: While avoiding copies, reference parameters can sometimes hinder compiler optimizations as the compiler must assume the referenced memory can be modified by subsequent calls.
  • std::function: Using std::function for callbacks can introduce overhead due to type erasure and potential heap allocations. For performance-critical scenarios, consider more specialized callback mechanisms like function pointers or std::function_view (if available/appropriate).

Choosing the Right Method

  • Structs/Classes: Best for logically grouped, semantically meaningful return values. Offers excellent readability and maintainability.
  • std::tuple: Ideal for returning a fixed number of unrelated values or when the return values are generic. C++17 structured bindings significantly improve its usability.
  • std::pair: Suitable for returning exactly two values, especially when they are closely related.
  • Reference Parameters: A viable option for C compatibility or when modifying existing objects is intended, but can be less clear about intent than returning values directly. Be mindful of potential optimization impacts.
  • CPS/std::function: Powerful for asynchronous operations, varying return counts, or callback-based architectures.

The Core Guidelines on Function Returns (F.21) recommend preferring returning a struct or tuple for multiple “out” values, emphasizing the self-documenting nature of return values. https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-out-multi

FAQs on C++ Function Multiple Return Values

Q: What is the most readable way to return multiple values from a C++ function

ANS: Returning a struct or class with well-named members is generally the most readable approach, as it clearly conveys the meaning of each returned value.

Q: Can I use std::tuple to return more than two values in C++

ANS: Yes, std::tuple can return any number of values, making it flexible for scenarios where a struct might be overkill or when dealing with generic programming.

Q: How does C++17 structured bindings help with multiple return values

ANS: Structured bindings in C++17 allow you to directly unpack the elements of tuples, pairs, or structs into individual variables, making the code cleaner and more concise.

Q: Are there performance differences between returning structs and using reference parameters

ANS: Modern compilers often optimize struct/tuple returns via RVO/NRVO, making them performant. Reference parameters can sometimes hinder certain optimizations as the compiler must assume potential modifications.

Q: When should I use std::pair versus std::tuple

ANS: Use std::pair when you have exactly two related return values. Use std::tuple when you need to return more than two values or when the values are not strongly related and you want a generic container.
