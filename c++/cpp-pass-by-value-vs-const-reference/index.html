“C++ Pass by Value vs Const Reference: Performance and Best Practices”

When to Opt for Pass by Value

Historically, passing by value was often recommended for all types except built-in types, iterators, and function objects. This was primarily because copying large objects was considerably more expensive than passing by reference.

However, the introduction of C++11 brought move semantics. This feature allows objects, particularly rvalues, to be passed “by value” without creating a copy. Instead, the object is moved, which can be substantially more efficient than a copy-then-move sequence, especially for large, move-aware objects like std::string or std::vector.

Key Scenarios for Pass by Value:

  • Function Takes Ownership: If a function will internally create its own copy or take ownership of the passed argument, passing by value is often more efficient. This is because the compiler can either move the object directly (if it’s an rvalue) or perform a single copy operation, which is then moved internally. This contrasts with passing by reference, where an explicit copy must be made internally.

  • Small, Cheap-to-Copy Types: For fundamental data types (like int, double, char, bool) and small, simple structures, passing by value incurs minimal overhead. In some cases, it can even be faster than passing by reference due to avoiding indirection.

  • Compiler Optimization Potential: When passing by value, the compiler can often assume that the passed object does not alias with other objects. This allows for more aggressive optimizations. For instance, in the following example:

    struct MyStruct { int data; };
MyStruct globalStruct;

void processStruct(MyStruct localStruct) {
    localStruct.data = 10;
    globalStruct.data = 2;
    localStruct.data += 5;
}

    A compiler can potentially optimize processStruct to:

    // Optimized version
void processStructOptimized(MyStruct localStruct) {
    localStruct.data = 15;
    globalStruct.data = 2;
}

    This is possible because localStruct is a distinct copy. If localStruct were a reference (MyStruct& localStruct), the compiler would have to assume globalStruct and localStruct might be the same, preventing this optimization and potentially requiring re-fetching localStruct.data from memory.

  • Returning a Modified Copy: If a function’s purpose is to modify a copy of an argument and return it, passing by value is idiomatic.

    #include <string>

std::string toUpperCase(std::string text) {
    // Logic to convert text to uppercase
    for (char &c : text) {
        c = std::toupper(static_cast<unsigned char>(c));
    }
    return text;
}

    In this scenario, a copy is inevitably needed, so passing by value makes the intent clear and allows for efficient moving.

When to Favor Pass by Constant Reference

Passing by constant reference (const T&) is the default choice for types that are expensive to copy, unless move semantics offer a significant advantage.

Key Scenarios for Pass by Constant Reference:

  • Non-Modification and Expensive Copy: When a function needs to read from an object but not modify it, and the object is large or complex (e.g., large std::vector, custom class with significant data), passing by constant reference avoids an unnecessary copy.

    #include <vector>
#include <numeric> // For std::accumulate

bool areAllPositive(const std::vector<int>& numbers) {
    for (int num : numbers) {
        if (num <= 0) {
            return false;
        }
    }
    return true;
}

    Here, numbers is not modified, and passing by const& avoids copying the entire vector.

  • When NULL is Not a Valid Value: If an argument represents a mandatory value and NULL (or a default-constructed state that signifies absence) is not a valid input, const& is preferred over const T*. This enforces that a valid object must be provided.

Other Parameter Passing Considerations

  • Non-Const Reference: Use a non-const reference (T&) when a function must modify the original object passed by the caller as a side effect.

    #include <string>

bool tryParseInt(const std::string& text, int& outValue) {
    // Attempt to parse text into outValue
    try {
        outValue = std::stoi(text);
        return true;
    } catch (...) {
        return false;
    }
}

    The outValue parameter is modified directly.

  • Pointers (T* and T&): Pointers are often used when an argument might be absent (represented by nullptr) or when working with C-style APIs. const T* is used when the pointer points to data that should not be modified.

  • Template Programming: In generic template programming, where the exact type of the argument is unknown at compile time, passing by const& is often safer. Attempting to pass a large or expensive-to-copy type by value without knowing its characteristics can lead to severe performance degradation.

Practical Rule Set

A pragmatic approach to parameter passing in non-template functions:

  1. Pass by Value: If the function does not modify the parameter and the parameter is a primitive or cheap-to-copy type (e.g., int, double, float, char, bool).
  2. Pass by Value: If the function intends to take ownership of the argument and the type efficiently supports move semantics (e.g., std::string, std::vector).
  3. Pass by Constant Reference (const T&): If the function does not modify the argument, and the argument is expensive to copy, and NULL is not a valid representation of absence for this parameter.
  4. Pass by Non-Const Reference (T&): If the function needs to modify the original argument.
  5. Pass by Constant Pointer (const T*): If the argument is expensive to copy, not modified, and NULL is a valid indicator of absence.
  6. Pass by Non-Const Pointer (T*): If the argument is expensive to copy, needs to be modified, and NULL is a valid indicator of absence.

Historical Context and Compiler Optimizations

While modern compilers are quite sophisticated, relying solely on automatic optimizations can sometimes be risky. Historically, best practices favored const& to avoid performance pitfalls. However, with C++11’s move semantics, pass-by-value for types that can be moved efficiently has become a powerful optimization strategy when ownership is transferred.

Compilers might elide copies in certain inlined functions if they can prove the original object won’t be altered. However, this is not guaranteed, and move semantics provide a more explicit and reliable way to achieve efficiency when appropriate.

Example Scenarios

  • String Uppercasing: As shown earlier, std::string toUpperCase(std::string text) is a good pattern.
  • Checking String Properties: bool all_uppercase(const std::string& s) is efficient for read-only operations.
  • Output Parameters: bool try_parse(const std::string& text, int& outValue) uses a non-const reference for output.

Consider the example of constructing a Person object:

#include <string>
#include <utility> // For std::move

class Person {
public:
    // Using pass-by-value and std::move for efficient initialization
    Person(std::string name) : name_(std::move(name)) {}
private:
    std::string name_;
};

// Calling code
// Person p(std::string("Alice")); // Creates std::string("Alice"), then moves it to name_

In this pattern, std::string("Alice") is an rvalue. Passing it by value to Person’s constructor allows std::move to directly move the contents into name_, avoiding an extra copy. If const std::string& name were used, a copy would be mandatory.

FAQs on C++ Parameter Passing

Q Use pass by value for small types

ANS: Yes, for built-in types and small, cheap-to-copy structures, passing by value is generally efficient and can allow for better compiler optimizations due to no aliasing assumptions.

Q When is pass by const reference preferred

ANS: Pass by const reference is preferred for large or expensive-to-copy objects when the function does not need to modify the argument, as it avoids an unnecessary copy.

Q How do C++11 move semantics affect parameter passing

ANS: C++11 move semantics allow objects to be moved instead of copied when passed by value in certain situations (e.g., with rvalues), significantly improving efficiency for large, move-enabled types when the function takes ownership.

Q Should I always pass by const reference

ANS: Not always. While a good default for complex types not modified, pass by value can be more efficient for types that support cheap moving and when the function takes ownership, thanks to C++11’s move semantics.

Q What is the difference between passing by value and by reference for modification

ANS: Passing by value creates a copy, so modifications to the copy do not affect the original. Passing by non-const reference allows the function to directly modify the original object.
