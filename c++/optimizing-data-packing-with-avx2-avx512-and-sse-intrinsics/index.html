“Optimizing Data Packing with AVX2, AVX-512, and SSE Intrinsics for High-Performance Shuffling”

How can expert programmers perform efficient lane-crossing variable shuffles, particularly for left-packing filtered data, across different generations of x86 CPU instruction sets like AVX2, AVX-512, and SSE? This involves generating dynamic shuffle masks from input bitmasks while considering hardware-specific performance penalties, such as those associated with BMI2 instructions on older AMD Zen CPUs.

The goal is to implement operations similar to std::remove for various data types (chars, shorts, ints, doubles) using vectorization.

Strategy 1: AVX2 with BMI2 (PEXT/PDEP) for 32/64-bit Elements

This method leverages the bit manipulation instructions provided by BMI2, which are generally available alongside AVX2 support.

Core Mechanism: Index Extraction and Permutation

The process relies on using PEXT (Parallel Bits Extract) to convert a selection bitmask into a contiguous sequence of indices, which then drives a vector shuffle instruction like VPERMPS or VPERMD.

  1. Index Generation: Start with a constant representing identity indices (e.g., [7, 6, 5, 4, 3, 2, 1, 0]).
  2. Mask Expansion: Use PDEP to extract the desired indices based on the input mask, packing them contiguously at the lower bits of a register.
    • Initial bit expansion (PDEP) maps each set bit from the mask into a specific byte position.
    • A subsequent multiplication (e.g., by 0xFF or 0x11 depending on the technique) expands these single bits into byte-sized masks.
  3. Index Compaction: Use PEXT again on the identity indices using the expanded mask to pull the required indices into a packed 3-bit (or byte-sized) format.
  4. Shuffling: Convert these indices into a shuffle mask vector and use VPERMPS (for floats) or VPERMD (for integers) to execute the lane-crossing permutation.

Performance Note for AMD CPUs: Be wary of older AMD Zen 1 and Zen 2 CPUs, where PDEP/PEXT exhibit high latency (up to 18 cycles) and large micro-op counts (6 uops). For these architectures, using 128-bit vectors with PSHUFB or VPERMILPS lookup tables (LUTs) might yield superior performance.

Practical Implementation Example (64-bit PDEP/PEXT)

This specific implementation uses 64-bit operations to simplify the unpacking step, which works well for 32-bit or 64-bit elements.

#include <stdint.h>
#include <immintrin.h>

// Uses 64bit pdep / pext to save a step in unpacking.
__m256 compress256(__m256 src, unsigned int mask /* from _mm256_movemask_ps */)
{
  // 1. Unpack each bit to a byte position (0x0101... mask)
  uint64_t expanded_mask = _pdep_u64(mask, 0x0101010101010101ULL); 
  
  // 2. Replicate the bit into the full byte (e.g., 0x01 -> 0xFF)
  // Optimization note: GCC/Clang may replace imul with shifts/subs for 0xFF.
  expanded_mask *= 0xFFU;    

  const uint64_t identity_indices = 0x0706050403020100ULL;    // Identity shuffle indices packed per byte
  
  // 3. Extract the desired indices into contiguous low bits
  uint64_t wanted_indices = _pext_u64(identity_indices, expanded_mask);

  __m128i bytevec = _mm_cvtsi64_si128(wanted_indices);
  // Convert the 8 packed byte indices into 32-bit integer lanes for VPERMPS/VPERMD
  __m256i shufmask = _mm256_cvtepu8_epi32(bytevec);

  // 4. Execute the shuffle. For float vectors, use VPERMPS.
  return _mm256_permutevar8x32_ps(src, shufmask);
}

When compiled on Haswell, the latency for this function is around 16 cycles, with potential throughput limitations due to PDEP/PEXT competing on specific execution ports.

Strategy 2: Alternative for Slow PDEP/PEXT (AMD Zen) using LUTs

When PDEP/PEXT are slow, a pre-calculated Look-Up Table (LUT) approach avoids these instructions entirely, replacing them with memory loads, broadcasting, and shifts. This approach is generally preferred for CPUs where BMI2 integer instructions are penalized.

LUT Mechanism

This method generates the shuffle mask using a small data LUT (768 bytes total) derived from the input movemask.

  1. Mask to Address: Use the 8-bit movemask result to index into a pre-built table (e.g., g_pack_left_table_u8x3).
  2. Broadcast: Broadcast the 4-byte LUT entry containing packed 3-bit indices into all lanes of a 256-bit register.
  3. Shift and Extract: Use vector shift instructions (_mm256_srlv_epi32) with a constant shift vector to isolate the 3-bit indices at the bottom of each lane, forming the final shuffle mask for VPERMPS.
// Data preparation (must be done once)
u8 g_pack_left_table_u8x3[256 * 3 + 1];

u32 get_nth_bits(int a) { /* ... implementation to pack indices based on bits ... */ return out; }

void BuildPackMask() {
    for (int i = 0; i < 256; ++i) {
        *reinterpret_cast<u32*>(&g_pack_left_table_u8x3[i * 3]) = get_nth_bits(i);
    }
}

// Intrinsics for mask generation
__m256i MoveMaskToIndices(u32 moveMask) {
    u8 *adr = g_pack_left_table_u8x3 + moveMask * 3;
    // Load the 4-byte entry and broadcast it
    __m256i indices = _mm256_set1_epi32(*reinterpret_cast<u32*>(adr));

    // Shift to align the 3-bit indices at the bottom of each lane
    __m256i shufmask = _mm256_srlv_epi32 (indices, _mm256_setr_epi32(0, 3, 6, 9, 12, 15, 18, 21));
    return shufmask;
}

The assembly output on MSVC shows efficient use of memory indexing and the VPSRLVD instruction.

Strategy 3: AVX-512 Vector Compression

For processors supporting AVX-512 Feature (AVX512F), the VCOMPRESSPS instruction is specifically designed for this sparse-to-dense packing operation.

VCOMPRESSPS Usage

This instruction takes a source vector and a mask register (__mmask16), writing only the elements corresponding to set mask bits into a dense (contiguous) location.

  • Data Types: VCOMPRESSPS exists for single-precision floats, and integer variants (VPCOMPRESSQ) exist for 32/64-bit integers in VBMI2 extensions (Ice Lake/Zen 4).
  • Memory Destination: Using a memory destination (_mm512_mask_compressstoreu_ps) can be slow on Zen 4. It is often recommended to compress into a register first (_mm512_maskz_compress_ps) and then perform a standard unaligned store.
  • Advancing Pointers: Use _mm_popcnt_u64 on the mask to calculate exactly how many elements were kept, which determines the increment for the destination pointer.
#include <stdint.h>
#include <immintrin.h>

size_t filter_non_negative(float *__restrict__ dst, const float *__restrict__ src, size_t len) {
    const float *endp = src + len;
    float *dst_start = dst;
    const __m512 v_zero = _mm512_setzero_ps();
    
    do {
        __m512 v  = _mm512_loadu_ps(src);
        // Generate mask: true if src element >= 0.0
        __mmask16 keep = _mm512_cmp_ps_mask(v, v_zero, _CMP_GE_OQ); 
        
        // Compress into a register first (avoids slow Zen 4 memory store behavior)
        __m512 packed = _mm512_maskz_compress_ps(keep, v);
        _mm512_storeu_ps(dst, packed);

        src += 16; 
        // Calculate elements kept using popcount
        dst += _mm_popcnt_u64((unsigned)keep); 
    } while (src < endp);
    
    return dst - dst_start;
}

On modern Intel CPUs (like Haswell onwards), this can achieve a throughput close to 1 vector per 3 cycles, bottlenecked by port 5 operations (KMOV and the store). Misaligned 512-bit stores can sometimes impact performance negatively if the destination pointer is not cache-line aligned.

Strategy 4: 128-bit SSE/AVX Implementations

When 256-bit or 512-bit instructions are unavailable or unnecessary, 128-bit methods apply, often involving the PSHUFB instruction or, for older SSE2/SSE3, complex mask generation based on _mm_shuffle_ps.

128-bit Mask Generation with BMI2 (PEXT)

If using 128-bit registers with data types smaller than 4 bytes (e.g., bytes or shorts), you might need to process data in chunks or adapt the PEXT/PDEP index generation. For 16-bit elements, the BMI2 technique can be adapted by using PSHUFB with byte-level indices.

The following code block shows complex mask derivation for _mm_shuffle_epi8 using PEXT/PDEP adapted for 16-bit elements.

// Helper namespace for 128-bit mask generation
namespace _compress_mask {

inline std::pair<__m128i, std::uint8_t> mask128(std::uint16_t mmask) {
    // Expand 16 bits into 64 bits using 0x11... constant, then multiply by 0xF
    const std::uint64_t mmask_expanded = _pdep_u64(mmask, 0x1111111111111111ULL) * 0xF;

    const std::uint8_t offset = static_cast<std::uint8_t>(_mm_popcnt_u32(mmask)); 

    // Generate byte indices based on Peter Cordes's technique
    const std::uint64_t compressed_idxes = _pext_u64(0xfedcba9876543210ULL, mmask_expanded); 

    const __m128i as_lower_8byte = _mm_cvtsi64_si128(compressed_idxes); // Low 8 bytes hold compressed indices
    const __m128i as_16bit = _mm_cvtepu8_epi16(as_lower_8byte);         // Convert 8 bytes to 4 shorts
    
    // Prepare for PSHUFB: Create index mask by spreading and combining bits
    const __m128i shift_by_4 = _mm_slli_epi16(as_16bit, 4);             
    const __m128i combined = _mm_or_si128(shift_by_4, as_16bit);        
    const __m128i filter = _mm_set1_epi16(0x0f0f);                      
    const __m128i res = _mm_and_si128(combined, filter);                

    return {res, offset};
}

}  // namespace _compress_mask

Branchless AVX Simulation of PDEP (Non-BMI2)

If BMI2 is absent but AVX (or SSE4.1) is present, one can simulate the required shifts and merges using a sequence of BLENDV and vector permutations. This technique uses repeated blending operations driven by permute masks to shift and select elements based on the input mask.

This approach targets floating-point data (__m128) or double-precision data (__m256d).

// AVX simulation for float packing (uses _mm_permute_ps and _mm_blendv_ps)
inline __m128 left_pack_avx(__m128 val, __m128i mask) noexcept
{
    // Masks derived to select elements for shifting/blending
    const __m128i shiftMask0 = _mm_shuffle_epi32(mask, 0xA4);
    const __m128i shiftMask1 = _mm_shuffle_epi32(mask, 0x54);
    const __m128i shiftMask2 = _mm_shuffle_epi32(mask, 0x00);
    const int perm_f9 = 0xF9; // Constant for permutation

    __m128 v = val;
    // Iteratively blend the current vector with a permuted version based on mask segments
    v = _mm_blendv_ps(_mm_permute_ps(v, perm_f9), v, shiftMask0);
    v = _mm_blendv_ps(_mm_permute_ps(v, perm_f9), v, shiftMask1);
    v = _mm_blendv_ps(_mm_permute_ps(v, perm_f9), v, shiftMask2);
    return v;
}

FAQs on Optimizing Data Packing with AVX Intrinsics

Q: What is the primary performance drawback of using the BMI2 PEXT/PDEP approach

ANS: On older AMD Zen CPUs (Zen 1/Zen 2), PEXT and PDEP instructions suffer from high latency (around 18 cycles) and high micro-op counts, making them inefficient for tight loops.

Q: Is VCOMPRESSPS always faster on AVX-512 systems

ANS: VCOMPRESSPS is generally the dedicated instruction for this, but performance can suffer if the resulting packed vector store causes cache-line splits (misaligned 512-bit stores), particularly on Zen 4 architectures. Compressing to a register first then storing is often safer.

Q: How do I determine the number of elements kept during compression

ANS: For both VCOMPRESSPS and the BMI2 approach, use the population count instruction (POPCNT) on the source mask generated by the comparison operation (_mm_popcnt_u32 or _mm_popcnt_u64).

Q: Can the AVX blend-based solution work without BMI2

ANS: Yes, the iterative blend and permute approach (Solution 6) simulates the logic of bit extraction without needing the BMI2 instructions, relying only on AVX/SSE instruction sets.

// helper namespace
namespace _compress_mask {

// mmask - result of `_mm_movemask_epi8`, 
// `uint16_t` - there are at most 16 bits with values for __m128i. 
inline std::pair&lt;__m128i, std::uint8_t&gt; mask128(std::uint16_t mmask) {
    const std::uint64_t mmask_expanded = _pdep_u64(mmask, 0x1111111111111111) * 0xf;

    const std::uint8_t offset = 
        static_cast&lt;std::uint8_t&gt;(_mm_popcnt_u32(mmask));  // To compute how many elements were selected

    const std::uint64_t compressed_idxes = 
        _pext_u64(0xfedcba9876543210, mmask_expanded); // Do the @PeterCordes answer

    const __m128i as_lower_8byte = _mm_cvtsi64_si128(compressed_idxes); // 0...0|compressed_indexes
    const __m128i as_16bit = _mm_cvtepu8_epi16(as_lower_8byte);         // From bytes to shorts over the whole register
    const __m128i shift_by_4 = _mm_slli_epi16(as_16bit, 4);             // x &lt;&lt; 4
    const __m128i combined = _mm_or_si128(shift_by_4, as_16bit);        // | x
    const __m128i filter = _mm_set1_epi16(0x0f0f);                      // 0x0f0f
    const __m128i res = _mm_and_si128(combined, filter);                // &amp; 0x0f0f

    return {res, offset};
}

}  // namespace _compress_mask

template &lt;typename T&gt;
std::pair&lt;__m128i, std::uint8_t&gt; compress_mask_for_shuffle_epi8(std::uint32_t mmask) {
     auto res = _compress_mask::mask128(mmask);
     res.second /= sizeof(T);  // bit count to element count
     return res;
}

namespace _compress_mask {

// mmask - result of _mm256_movemask_epi8
inline std::pair&lt;__m256i, std::uint8_t&gt; mask256_epi32(std::uint32_t mmask) {
    const std::uint64_t mmask_expanded = _pdep_u64(mmask, 0x5555'5555'5555'5555) * 3;

    const std::uint8_t offset = static_cast&lt;std::uint8_t(_mm_popcnt_u32(mmask));  // To compute how many elements were selected

    const std::uint64_t compressed_idxes = _pext_u64(0x0706050403020100, mmask_expanded);  // Do the @PeterCordes answer

    // Every index was one byte =&gt; we need to make them into 4 bytes
    const __m128i as_lower_8byte = _mm_cvtsi64_si128(compressed_idxes);  // 0000|compressed indexes
    const __m256i expanded = _mm256_cvtepu8_epi32(as_lower_8byte);  // spread them out
    return {expanded, offset};
}

}  // namespace _compress_mask

template &lt;typename T&gt;
std::pair&lt;__m256i, std::uint8_t&gt; compress_mask_for_permutevar8x32(std::uint32_t mmask) {
    static_assert(sizeof(T) &gt;= 4);  // You cannot permute shorts/chars with this.
    auto res = _compress_mask::mask256_epi32(mmask);
    res.second /= sizeof(T);  // bit count to element count
    return res;
}
