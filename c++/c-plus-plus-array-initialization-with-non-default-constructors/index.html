Solutions for Array Construction with Parameterized Constructors

Several techniques exist to circumvent the requirement for a default constructor when creating arrays of objects.

Solution 1: Manual Memory Allocation with Placement New

This approach involves allocating raw, uninitialized memory and then explicitly constructing each object in that memory using placement new. This method provides granular control over object construction and destruction, often necessary when adhering strictly to Scott Meyers’ advice regarding gratuitous default constructors (as highlighted in More Effective C++).

// Example Class Definition
class Car
{
    int _no;
public:
    Car(int no) : _no(no) {}
    // Intentionally omitting a default constructor
};

constexpr int NUM_CARS = 5;

int main()
{
    // 1. Allocate raw memory block
    void *raw_memory = operator new[](NUM_CARS * sizeof(Car));
    
    // Cast the raw memory to the object pointer type
    Car *ptr = static_cast<Car *>(raw_memory);
    
    // 2. Construct objects using placement new
    for (int i = 0; i < NUM_CARS; ++i) {
        new (&ptr[i]) Car(i); // Calls Car(i) constructor at the memory location ptr[i]
    }

    // 3. Destruct objects in reverse order (essential for manual management)
    for (int i = NUM_CARS - 1; i >= 0; --i) {
        ptr[i].~Car(); // Explicitly call destructor
    }
    
    // 4. Deallocate the raw memory
    operator delete[](raw_memory);

    return 0;
}

Solution 2: Preferring std::vector with Copy Initialization or emplace_back

The idiomatic C++ solution leverages the Standard Library. While you cannot initialize an array of objects using a non-default constructor directly with new Type[size], std::vector offers much safer alternatives.

  1. Initialization via Copy: If you can create an instance of the object to copy from:

    int userInput = 10;
// Creates 'userInput' copies of a Car initialized with ID 5
std::vector<Car> mycars(userInput, Car(5));

  2. In-Place Construction with emplace_back (C++11 and later): This is highly recommended as it constructs the object directly inside the vector’s storage, avoiding temporary object creation and copy/move operations. The constructor arguments are passed directly to the object being constructed.

    std::vector<Car> mycars;
int userInput = 10;

for (int i = 0; i < userInput; ++i) {
    // Arguments (i + 1) are passed directly to Car(int)
    mycars.emplace_back(i + 1); 
}
// Default constructor is never invoked. Cleanup handled by vector's destructor.

Solution 3: Array of Pointers

If direct object construction in a contiguous array is less critical than simply having a collection of initialized objects, an array of pointers provides flexibility.

int userInput = 10;
Car** mycars_ptr_array = new Car*[userInput];

for (int i = 0; i < userInput; i++) {
    // Allocate memory for each object and initialize it
    mycars_ptr_array[i] = new Car(i + 100); 
}

// ... Use objects ...

// Cleanup: Destruct objects first, then the array of pointers
for (int i = 0; i < userInput; i++) {
    delete mycars_ptr_array[i];
}
delete [] mycars_ptr_array;

Solution 4: Using std::allocator for Manual Construction

For situations demanding raw memory allocation with specific alignment guarantees while maintaining object construction control (similar to Solution 1 but using standard allocator utilities), std::allocator can be employed.

#include <iostream>
#include <memory>

class Car { /* ... definition with private default constructor ... */ };

int main() {
    int userInput = 10;
    std::allocator<Car> carAllocator;

    // Allocate space (uninitialized memory)
    Car *myCars = carAllocator.allocate(userInput); 
    Car *myCarsBegin = myCars;

    // Construct objects using construct() and placement semantics
    for(int i = 0; i < userInput; i++) {
        // Calls Car(i) constructor at the allocated memory location
        carAllocator.construct(myCars++, i); 
    }
    
    // Use objects... (e.g., call printNo())

    // Destroy objects
    for( Car *carIterator = myCarsBegin; carIterator != myCars; ++carIterator )
        carAllocator.destroy( carIterator );

    // Deallocate the raw memory block
    carAllocator.deallocate(myCarsBegin, userInput);

    return 0;
}

Solution 5: Factory Method Encapsulation

If the private constructor is intentional to restrict direct instantiation, a static factory method within the class can encapsulate the complex allocation logic (like Solution 1 or 13) and return a correctly initialized array (either raw pointer or managed pointer).

class Car
{
private:
    int _no;
    Car(int no) : _no(no) {} // Private constructor
public:
    // Static factory method to create the array
    static Car* createCarArray(unsigned number)
    {
        if (number == 0) return nullptr;
        
        // Allocate memory using placement new logic
        Car* cars = reinterpret_cast<Car*>(new char[sizeof(Car) * number]);
        
        for(unsigned carId = 0; carId != number; ++carId)
        {
            new(cars + carId) Car(carId); // Construct using private constructor
        }
        return cars;
    }

    // Corresponding destruction logic needed for cleanup...
};

Solution 6: C++17 Aligned Allocation

For modern C++ aiming for the most efficient raw memory layout, you can use std::aligned_alloc (paired with std::free) to secure properly aligned memory, followed by placement new.

#include <cstdlib>
#include <type_traits>

template<class T>
T* allocUninitializedArray(std::size_t len) {
    auto alignment = std::alignment_of<T>();
    // std::aligned_alloc returns memory suitable for T, freeing with std::free
    return static_cast<T*>(std::aligned_alloc(alignment, len * sizeof(T)));
}

int main() {
    int userInput = 10;
    Car *mycars = allocUninitializedArray<Car>(userInput);
    
    for (int i = 0; i < userInput; i++) {
        new (&mycars[i]) Car(i); // Construct
    }
    
    // printCarNumbers(mycars, userInput); 

    // Manual destruction and freeing required
    for (int i = 0; i < userInput; i++) {
        mycars[i].~Car();
    }
    std::free(mycars);
    return 0;
}

Solution 7: Utilizing std::optional<T> (C++17)

std::optional allows storage space to be reserved for an object without constructing it, effectively providing a memory slot that can be filled later using emplace.

#include <optional>

int main() {
    int userInput = 10;
    // Array of optional objects; default constructed (empty)
    std::optional<Car> mycars[userInput]; 

    for (int i = 0; i < userInput; ++i) {
        // Constructs Car(i) in-place inside the optional slot
        mycars[i].emplace(i); 
    }
    
    // Access requires checking if it has a value, or using the pointer access if present
    // e.g., mycars[i]->printNo(); if accessing via pointer interface
    
    return 0; // Destructors are handled automatically when mycars goes out of scope
}

FAQs on C++ Array Initialization

Q: Why does new Type[size] fail when the default constructor is private

ANS: The new Type[size] expression requires the ability to construct ‘size’ default-constructed instances of ‘Type’. If the default constructor is private, inaccessible, or deleted, the compilation fails because the standard mandates this invocation.

Q: What is placement new syntax

ANS: Placement new takes the form new (address) Type(constructor_arguments). It assumes memory already exists at the provided address and calls the specified constructor for that memory location without performing any new memory allocation.

Q: Is std::vector the safest modern alternative

ANS: Yes, for most application scenarios, utilizing std::vector combined with emplace_back is the safest and most idiomatic approach in C++11 and newer, as it automatically manages memory allocation and object lifetime.

Q: When should placement new be considered

ANS: Placement new is typically reserved for low-level programming, custom container implementations, or performance-critical sections where you need precise control over memory layout, such as allocating memory aligned for specific hardware or avoiding overhead associated with standard library containers.
