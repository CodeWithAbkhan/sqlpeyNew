“C++: Custom Keys in std::unordered_map Explained”

When working with std::unordered_map in C++, you’re often required to use built-in types or types for which the Standard Template Library (STL) already provides a hash function and an equality comparison. However, there are many scenarios where you need to use your own custom-defined classes or enumerations as keys. This poses a challenge: how do you inform std::unordered_map how to hash your custom types and compare them for equality?

The core requirements for using a custom type as a key in std::unordered_map are:

  1. A Hash Function: This function takes an object of your key type and returns a std::size_t value representing its hash. This hash value is crucial for determining the bucket an element belongs to.
  2. An Equality Comparison Function: This function takes two objects of your key type and returns true if they are considered equal, and false otherwise. This is used to handle hash collisions and find the exact element.

Let’s explore various methods and best practices for achieving this.

Solution 1: Specializing std::hash and Overloading operator==

The most idiomatic C++ approach is to specialize the std::hash template for your custom key type and overload the operator== for it.

Key Requirements:

  • Hash Function: Define a struct that overloads operator() to compute the hash. Specializing std::hash for your type is the standard way.
  • Equality Comparison: Overload operator== for your key type.

Consider a Key structure with multiple members:

#include <string>
#include <functional> // For std::hash
#include <unordered_map>
#include <iostream>

struct Key {
    std::string first;
    std::string second;
    int third;

    // Equality comparison operator
    bool operator==(const Key& other) const {
        return (first == other.first &&
                second == other.second &&
                third == other.third);
    }
};

// Specialization of std::hash for our Key struct
namespace std {
    template <>
    struct hash<Key> {
        std::size_t operator()(const Key& k) const {
            using std::size_t;
            using std::hash;
            using std::string;

            // Combine hash values of individual members.
            // XOR and bit shifting can be a good starting point.
            // A common pattern is to combine individual hashes like this:
            // (hash(member1) ^ (hash(member2) << 1)) >> 1 ^ (hash(member3) << 1)
            return (hash<string>()(k.first) ^
                    (hash<string>()(k.second) << 1)) >> 1 ^
                   (hash<int>()(k.third) << 1);
        }
    };
}

int main() {
    std::unordered_map<Key, std::string> mapWithCustomKey;

    mapWithCustomKey[{"John", "Doe", 12}] = "Value A";
    mapWithCustomKey[{"Mary", "Sue", 21}] = "Value B";

    std::cout << "Value for {\"John\", \"Doe\", 12}: " << mapWithCustomKey[{"John", "Doe", 12}] << std::endl;

    return 0;
}

Solution 2: Providing a Custom Hash Functor

If you prefer not to specialize std::hash within the std namespace (though it’s perfectly valid for user-defined types), you can define a separate hash functor class and pass it as a template argument to std::unordered_map.

Key Requirements:

  • Hash Functor Class: A class with an overloaded operator() that computes the hash.
  • Equality Comparison: Still requires operator== for your key type, or you can provide a separate equality functor.
#include <string>
#include <functional>
#include <unordered_map>
#include <iostream>

struct Key {
    std::string first;
    std::string second;
    int third;

    // Equality comparison operator
    bool operator==(const Key& other) const {
        return (first == other.first &&
                second == other.second &&
                third == other.third);
    }
};

// Custom hash functor
struct KeyHasher {
    std::size_t operator()(const Key& k) const {
        using std::size_t;
        using std::hash;
        using std::string;

        // Same hash combination logic as before
        return (hash<string>()(k.first) ^
                (hash<string>()(k.second) << 1)) >> 1 ^
               (hash<int>()(k.third) << 1);
    }
};

int main() {
    // Specify the custom hash functor as the third template argument
    std::unordered_map<Key, std::string, KeyHasher> mapWithCustomHasher;

    mapWithCustomHasher[{"Jane", "Smith", 30}] = "Value C";
    mapWithCustomHasher[{"Peter", "Jones", 45}] = "Value D";

    std::cout << "Value for {\"Jane\", \"Smith\", 30}: " << mapWithCustomHasher[{"Jane", "Smith", 30}] << std::endl;

    return 0;
}

Solution 3: Using Lambda Expressions for Hash and Equality

For more dynamic scenarios or when the hashing logic is simple and specific to a particular map instance, lambda expressions can be employed.

Key Requirements:

  • Lambda for Hashing: A lambda capturing the hashing logic.
  • Lambda for Equality: A lambda capturing the equality logic.
#include <unordered_map>
#include <iostream>
#include <functional> // Required for std::hash

// Assuming a 'Node' structure exists with members 'a', 'b', 'c'
struct Node {
    int a;
    int b;
    int c;

    // Equality check for Node
    bool operator==(const Node& other) const {
        return a == other.a && b == other.b && c == other.c;
    }
};

int main() {
    // Define hash and equality lambdas
    auto nodeHash = [](const Node& n) {
        // Reusing a common hashing pattern: multiply by a prime and add hash of member
        std::size_t res = 17;
        res = res * 31 + std::hash<int>()(n.a);
        res = res * 31 + std::hash<int>()(n.b);
        res = res * 31 + std::hash<int>()(n.c);
        return res;
    };

    auto nodeEqual = [](const Node& l, const Node& r) {
        return l.a == r.a && l.b == r.b && l.c == r.c;
    };

    // Create the unordered_map, specifying the types of the lambdas
    // The constructor takes initial bucket count, hash lambda, and equality lambda
    std::unordered_map<Node, int, decltype(nodeHash), decltype(nodeEqual)> nodeMap(8, nodeHash, nodeEqual);

    nodeMap[{1, 2, 3}] = 100;
    nodeMap[{4, 5, 6}] = 200;

    std::cout << "Value for Node{1, 2, 3}: " << nodeMap[{1, 2, 3}] << std::endl;

    return 0;
}

Solution 4: Hashing Enum Types

For enum types, the conversion to an integral type usually suffices for hashing.

Key Requirements:

  • Enum Type: The enumeration to be used as a key.
  • Hash Function: A function that casts the enum value to an integral type.
#include <unordered_map>
#include <iostream>

enum class Color { Red, Green, Blue };
struct ColorInfo { std::string description; };

// Hash function for the enum
struct ColorHash {
    std::size_t operator()(const Color& c) const {
        return static_cast<std::size_t>(c);
    }
};

int main() {
    std::unordered_map<Color, ColorInfo, ColorHash> colorMap;

    colorMap[Color::Red] = {"Bright Red"};
    colorMap[Color::Green] = {"Vibrant Green"};

    if (colorMap.count(Color::Red)) {
        std::cout << "Color Red description: " << colorMap[Color::Red].description << std::endl;
    }

    return 0;
}

Solution 5: Enhancing Hash Function Quality

A good hash function is vital for performance, minimizing collisions. The simple XOR and bit-shifting methods are a starting point. For better distribution, consider more sophisticated techniques.

Boost Library: The Boost library offers boost::hash_value and boost::hash_combine, which are excellent for creating robust hash functions.

#include <boost/functional/hash.hpp>
#include <string>
#include <unordered_map>
#include <iostream>

struct Key {
    std::string first;
    std::string second;
    int third;

    bool operator==(const Key& other) const {
        return first == other.first && second == other.second && third == other.third;
    }
};

struct BoostKeyHasher {
    std::size_t operator()(const Key& k) const {
        using boost::hash_value;
        using boost::hash_combine;

        std::size_t seed = 0;
        hash_combine(seed, hash_value(k.first));
        hash_combine(seed, hash_value(k.second));
        hash_combine(seed, hash_value(k.third));
        return seed;
    }
};

int main() {
    std::unordered_map<Key, std::string, BoostKeyHasher> mapWithBoostHash;
    mapWithBoostHash[{"Alice", "Wonderland", 1}] = "Curious";
    mapWithBoostHash[{"Bob", "Builder", 2}] = "Can Fix It";

    std::cout << "Value for {\"Alice\", \"Wonderland\", 1}: " << mapWithBoostHash[{"Alice", "Wonderland", 1}] << std::endl;

    return 0;
}

Prime Multiplication Method: Another effective technique involves using prime numbers for multiplication.

#include <string>
#include <functional>
#include <unordered_map>
#include <iostream>

struct Key {
    std::string first;
    std::string second;
    int third;

    bool operator==(const Key& other) const {
        return first == other.first && second == other.second && third == other.third;
    }
};

template <>
struct std::hash<Key> {
    std::size_t operator()(const Key& k) const {
        // Prime multiplication method
        std::size_t res = 17;

        res = res * 31 + std::hash<std::string>()(k.second);
        res = res * 31 + std::hash<int>()(k.third);
        return res;
    }

int main() {
    std::unordered_map<Key, std::string> mapWithPrimeHash;
    mapWithPrimeHash[{"Charlie", "Chaplin", 3}] = "Silent Film";
    mapWithPrimeHash[{"Grace", "Hopper", 4}] = "COBOL";

    std::cout << "Value for {\"Charlie\", \"Chaplin\", 3}: " << mapWithPrimeHash[{"Charlie", "Chaplin", 3}] << std::endl;

    return 0;
}

A common challenge arises when the hashing logic needs to be defined in a header file for templates, but compiler warnings or restrictions prevent this.

In such cases, defining the static hash function in a .cpp file and passing it to the map constructor or by specifying its type using decltype can resolve issues, particularly with GCC warnings about anonymous namespaces. Using std::function can help manage the type of the lambda if needed.

Solution 7: Minimizing Collisions and Ordering

A robust hash function should aim to minimize collisions and not be commutative if the order of elements matters in the hash calculation (though for unordered_map keys, commutativity is often acceptable for distinct keys).

Effective Hashing Strategies:

  • Combine Hashes: Use techniques like prime multiplication, XOR, and bit shifts to combine hashes of individual members.
  • Boost’s hash_combine: A widely recommended method for combining hashes.
  • Prime Numbers: Use prime numbers (like 31, 37, or larger primes) in multiplication steps.

Consider these combination methods for two hash values a and b:

  • a ^ (b + 0x9e3779b9 + (a << 6) + (a >> 2)) (similar to Boost)
  • p*p + b where p = a + b
  • a * 31 + b

FAQs on Custom Keys in std::unordered_map

Q: How do I make a custom class usable as a key in C++ std::unordered_map

ANS: You need to provide both an equality comparison operator (operator==) for your class and a hash function. You can do this by specializing std::hash for your class or by providing a custom hash functor as a template argument to std::unordered_map.

Q: What are the requirements for a hash function for std::unordered_map

ANS: The hash function must accept an object of your key type and return a std::size_t. It should distribute keys evenly across buckets and handle potential collisions correctly by ensuring that equal keys always produce the same hash value.

Q: Can I use lambda expressions as hash functions for std::unordered_map

ANS: Yes, you can use lambda expressions. You’ll need to specify the type of the lambda using decltype as a template argument to std::unordered_map and pass the lambda to the map’s constructor.

Q: How do I hash an enum type

ANS: For enum types, you can typically cast the enum value to its underlying integral type (e.g., static_cast<std::size_t>(yourEnum)). This cast result can then be used as the hash value.

Q: What if I cannot modify the custom class's definition

ANS: If you cannot modify the class definition, you can create a wrapper class that inherits from the original class and adds the necessary operator== and hash function, or provide a separate hash functor and potentially an equality functor to std::unordered_map. Alternatively, using lambdas with careful scope management (e.g., defining them in .cpp files) can also work.
