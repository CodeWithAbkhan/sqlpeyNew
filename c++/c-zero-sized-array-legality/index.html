“C Language: Zero-Sized Array Legality and Practical Alternatives”

What is the definitive stance of the C programming language standard regarding arrays declared with a size of zero? Furthermore, how do common compiler extensions and established programming idioms, such as the “struct hack,” interact with this constraint?

The initial assessment, confirmed by the C standard (ISO 9899:2011 6.7.6.2 ), is quite strict:

  1. Constant Expression Size: If an array dimension is a constant expression, its value must be greater than zero.
  2. Variable Length Arrays (VLAs): For VLAs, if the controlling expression evaluates to less than or equal to zero, the behavior is officially undefined. Compilers are obligated to adhere to this normative text. Using strict compilation flags like gcc -std=c99 -pedantic will reliably generate a warning for non-VLA zero-sized declarations.

Alternative Idioms and Compiler Extensions

Despite the strict standard, practical usage often bypasses these rules through compiler extensions or recognized structural patterns.

The Flexible Array Member (FAM) and the Struct Hack

A prevalent technique, often predating C99 standardization, involves using an array with an empty dimension ([]) as the final member of a structure. This is standardized in C99 as the Flexible Array Member (FAM).

The syntax deviates slightly from a strict zero initialization:

// Standard Flexible Array Member (FAM) declaration (C99+)
struct DynamicBuffer {
  size_t payload_count;
  int data[]; // Note: No '0' inside the brackets
};

void allocate_buffer(size_t required_elements) {
  // Allocation requires calculating the size of the header plus the array content
  size_t total_size = sizeof(size_t) + (required_elements * sizeof(int));

  struct DynamicBuffer* buffer_ptr = (struct DynamicBuffer*)malloc(total_size);

  if (buffer_ptr) {
    buffer_ptr->payload_count = required_elements;
    
    // Initialization example
    for (size_t idx = 0; idx < required_elements; ++idx) {
      buffer_ptr->data[idx] = 100 + (int)idx; // Safe indexing due to careful malloc
    }
  }
}

This practice is sometimes referred to as tail-padded structures. Before C99, the reliance on this behavior, especially for static initialization, was non-portable.

Static Initialization Example (GCC Extension):

While strictly non-standard before C99 guaranteed FAM semantics, GCC often permits static initialization resembling a FAM:

// GCC Extension / Pre-C99 "Struct Hack"
struct LegacyBuffer {
  int header;
  char items[]; // Empty brackets used historically
};

// Note: This specific static initialization syntax might be rejected or behave unexpectedly
// based on the compiler version and strictness settings.
struct LegacyBuffer buffer_instance = { 5, { 'a', 'b', 'c' } };

Zero-Length Arrays in GNU C

The GNU C extension explicitly allows zero-length arrays (int contents[0];). This feature is often leveraged when implementing structures that serve as variable-length object headers, similar to the FAM concept but using [0].

Example utilizing GNU C [0] extension:

// Example structure utilizing GNU C's zero-length array extension
struct LogEntry {
   int record_id;
   char message_data[0]; // GNU C extension
};

void setup_log_entry(int id, size_t extra_bytes) {
    // Manual allocation mimicking struct layout
    struct LogEntry* entry = (struct LogEntry*)malloc(sizeof(struct LogEntry) + extra_bytes);
    entry->record_id = id;
    // Memory immediately following 'record_id' is accessible via pointer arithmetic or message_data[i]
}

GCC documentation notes that in older versions (pre-3.0), static initialization of int arr[0] = { 1 }; was permitted, leading to data corruption, illustrating why formal standardization was necessary.

Using Zero-Size Arrays for Compile-Time Checks

One niche application for declarations that should fail compilation (but sometimes don’t due to relaxed compiler settings) is forcing a compile-time error based on a boolean condition.

If condition evaluates to false (resulting in a zero size):

// Attempting to force a compile-time error when 'condition' is false (size 0)
char check_true_only[ condition ];

If the compiler accepts size == 0, this fails to trigger an error. A more robust, though slightly obscure, alternative that often succeeds in forcing a compile error when the size becomes negative is:

// Alternative to force compile error if 'condition' is false (results in size -1)
char robust_check[ 2 * condition - 1 ];

A size of $-1$ is typically illegal across most C/C++ compilers, causing the desired error when condition is false (0).

Behavioral Differences in C++ with Constructors

When zero-length arrays are used within C++ structs, compiler behavior regarding object construction and destruction can become highly unexpected, as demonstrated by the differing outputs from Clang and GCC when creating an array of such structures:

#include <cstdio>

struct ZeroSizedCpp {
    ZeroSizedCpp() { printf("Constructing ZeroSizedCpp\n"); }
    ~ZeroSizedCpp() { printf("Destructing ZeroSizedCpp\n"); }
    int filler[0];
};

int main() {
    ZeroSizedCpp objects[2]; // Declaring an array of two instances
    // ... program exit implicitly calls destructors
}
// GCC Output might show all constructors, then all destructors (if interpreted as C-style array)
// Clang might interleave construction and destruction unexpectedly for each element!

This unpredictable behavior underscores why relying on the [0] syntax in C++ contexts, especially when involving RAII semantics, is strongly discouraged.

Solutions

FAQs on C Zero Sized Array Legality

Q: Is a zero size array legal in ISO C99 standard

ANS: No, the ISO C99 standard mandates that array dimensions specified by a constant expression must have a value greater than zero. For Variable Length Arrays (VLAs), a zero or negative size yields undefined behavior.

Q: What is the difference between int data[] and int data[0]

ANS: In standard C99 and later, int data[] declares a Flexible Array Member (FAM) when it is the last member of a struct, having an incomplete type. int data[0] declares an array of explicit zero size, which is non-standard for plain arrays but allowed as an extension in GNU C.

Q: How do compilers handle zero size arrays when using pedantic flags

ANS: When compiling with strict, pedantic flags (like gcc -pedantic), the compiler will issue a warning or error stating that the ISO C standard forbids zero-size arrays.

Q: Can I use the struct hack safely in modern C

ANS: The “struct hack,” when implemented using the C99 Flexible Array Member syntax (data[]), is now standardized and generally safe for heap allocations requiring variable trailing data. Relying on older forms or non-standard zero initialization risks portability issues.
