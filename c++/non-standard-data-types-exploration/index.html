Deviations in Data Representation Across Architectures

Several established and specialized architectures maintain data representation methods that challenge typical modern expectations.

Unisys ClearPath Dorado Servers and the 2200 Architecture

The Unisys ClearPath Dorado servers, designed to offer backward compatibility for older Univac software, exhibit several distinct characteristics:

  • Word Size: They operate using 36-bit words.
  • Character Size: Crucially, CHAR_BIT is defined as 9 bits.
  • Integer Representation: The architecture employs one’s complement for signed numbers.
  • Floating Point: They feature a 72-bit non-IEEE floating-point format.
  • Memory Model: There is a separation between the address space reserved for code and that for data.
  • Addressing: The system is word-addressed, and it notably lacks a dedicated stack pointer register.

Documentation, such as the referenced Unisys C Compiler Programming Reference Manual (Section 4.5), details data types utilizing 9, 18, 36, and 72 bits. While compiler availability (like C++) isn’t explicitly confirmed, the base architecture dictates these unusual specifications.

Mainframes and Non-Standard Floating Point

Mainframes frequently eschew the IEEE 754 standard for floating-point math:

  • IBM Systems: Often utilize base 16 floating-point representation.
  • Unisys MPS Architecture: This architecture is notably complex, featuring 48-bit tagged words. The interpretation of a word (pointer versus data) is governed by a specific bit within that word. Furthermore, its numeric representation blurs the line between integral and floating-point values:
    • The floating point is base 8 and lacks normalization.
    • The decimal point is positioned to the right of the mantissa, contrary to common conventions.
    • It uses signed magnitude for the exponent.
    • An integral value can share an identical bit representation with a signed magnitude integer.
    • Arithmetic instructions dynamically decide between integral and floating-point operations based on the exponent values (if both are zero, integral math is performed). For a 48-bit int to be treated correctly as an integer, 8 of its bits must be zero, conforming to this tagging philosophy.

VAX and Cray Architectures

Legacy systems continue to see specialized use, bringing their own data format requirements:

  • VAX Systems: These systems typically do not support IEEE floating-point, relying instead on their proprietary formats. Newer Alpha processors, however, often support both VAX and IEEE formats.
  • Cray Vector Machines (e.g., T90): These machines use a distinct floating-point format. While newer Cray systems gravitate towards IEEE, the T90 relied on its own system. Pointers on the T90 could only reference 64-bit words. Although the system ran a Unix variant (Unicos) necessitating CHAR_BIT == 8 for interoperability, byte-level operations required compiler synthesis, with void* or char* storing a byte offset in the upper 3 bits of the 64-bit word. Some integer types also incorporated padding bits.

Other Systems Where CHAR_BIT Deviates from 8

Specific embedded systems also redefine the character size:

  • TI DSPs: Some Digital Signal Processors from Texas Instruments define CHAR_BIT as 16 bits.
  • BlueCore-5 Chip: This Bluetooth chip from Cambridge Silicon Radio also sets CHAR_BIT to 16.
  • DSP Architectures (via GCC inspection): By inspecting GCC source code definitions, one can find further examples: CHAR_TYPE_SIZE being 16 bits for 1750a and dsp16xx, 24 bits for dsp56k, and 32 bits for c4x.

These deviations prompt questions about updating language standards. A possible path forward involves tightening requirements for hosted implementations (e.g., mandating CHAR_BIT==8, IEEE for hardware floats, and two’s complement for signed integers) while maintaining looser constraints for freestanding (embedded) implementations.

The Rarity of Strict IEEE 754 Compliance

Strict adherence to the IEEE 754 standard is often forgone in favor of performance optimizations, even on contemporary hardware:

  1. Subnormal Support: Implementations can differ; for instance, x87 and SSE units may handle subnormal numbers differently.
  2. Optimization Fusing: Combining operations (like multiply-add) might slightly alter results while providing substantial architectural speedups.
  3. x86 Specifics: Achieving strict IEEE compliance on x86 might necessitate extra register transfers to prevent the processor from using its native 80-bit internal floating-point format.
  4. Software Emulation: Systems lacking hardware floats must emulate them in software, where implementing complex IEEE requirements like specific rounding rules can be prohibitively expensive performance-wise.

Because of these trade-offs, few programming languages strictly guarantee IEEE compliance across all platforms.

Relevance of GPU Floating Point

Modern high-performance computing, driven by GPUs for AI, data mining, and simulations, frequently involves non-standard floating-point behavior until recently. Early GPU pioneers often computed data by encoding it into images and using graphics APIs like OpenGL to perform operations (e.g., “gaussian blur” for convolution) before decoding the result. This technique proved faster than CPU-based processing, eventually prompting vendors like NVIDIA to adopt IEEE-compatible binary formats and introduce computation-focused APIs like CUDA.

FAQs on Non-Standard Data Types Exploration

Q: What system specifically uses a 9-bit character size

ANS: The Unisys ClearPath Dorado servers architecture, designed for Univac software compatibility, defines CHAR_BIT as 9.

Q: Do modern mainframes strictly follow IEEE 754

ANS: No, IBM mainframes typically use base 16 floating point, and Unisys mainframes utilize a base 8 format. Strict IEEE compliance is rare due to optimization allowances.

Q: Can I find hardware where CHAR_BIT is 16

ANS: Yes, certain hardware like specific TI DSPs and the Cambridge Silicon Radio BlueCore-5 chip report CHAR_BIT as 16 bits.

Q: What is the integer representation on Unisys MPS machines

ANS: The MPS architecture uses 48-bit tagged words and employs one’s complement or sign and magnitude representations, rather than the common two’s complement.
