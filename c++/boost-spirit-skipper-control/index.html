“Boost Spirit Skipper Control: qi::lexeme vs qi::no_skip vs qi::raw”

When constructing parsers with Boost.Spirit’s Qi library, managing how whitespace and other characters are handled (skipped or consumed) is crucial for accurate input processing. The default behavior typically involves a skipper, often qi::space, which automatically skips whitespace. However, there are scenarios where this default behavior needs to be modified or bypassed to achieve precise parsing. This discussion delves into the distinct functionalities of qi::lexeme, qi::raw, and qi::no_skip, providing practical examples of their application.

Core Skipper Directives in Boost.Spirit Qi

Boost.Spirit’s Qi offers several directives to influence skipper behavior. Understanding these is key to fine-tuning your grammar’s interaction with input:

  • qi::lexeme [ p ]: This directive is instrumental in inhibiting a skipper for a specific parser expression p. This is particularly useful when you need to parse an element without any intervening whitespace being skipped. For instance, parsing an identifier that might contain characters normally skipped. Compare this with qi::no_skip for subtle differences in application.
  • qi::raw [ p ]: This directive parses similarly to the standard approach, including skips. However, its distinct feature is that it returns the raw iterator range of the matched source sequence. This range encompasses the skipped positions, providing more granular control over the parsed segment.
  • qi::skip(s) [ p ]: This directive allows you to replace the current skipper entirely with a new skipper s for the parser expression p. It’s important to note that when using qi::skip, you must employ appropriately declared qi::rule<> instances within the skip[] clause.
  • qi::no_skip [ p ]: This directive, as the name suggests, inhibits skipping for the parser expression p without any pre-skip action. It’s designed for situations where you want a parser to be completely unaffected by the global skipper.

The fundamental difference often lies in when and how skips are handled. qi::lexeme is excellent for preventing skips within a specific token, while qi::no_skip disables skipping entirely for a given rule. qi::raw provides the raw segment including skips.

A Specific Parsing Challenge: Controlling Line Endings

A common problem arises when a default skipper, like qi::space, consumes not only spaces but also newlines (eol), which you might intend to parse explicitly. If your grammar relies on specific line break placements, the default skipper can interfere.

Consider a scenario where you need to parse structured data with specific line endings. The challenge is to parse the data accurately without the skipper indiscriminately consuming newlines.

Solution 1: Utilizing qi::eol and qi::blank

This approach demonstrates how to explicitly require line breaks at certain points while using a skipper that excludes end-of-line characters. This provides more control over the grammar’s structure.

We combine grammars for brevity and clarity. The example below parses a structure starting with “ROW”, followed by a row number, and then multiple rows, each containing a number and a list of numbers.

#define BOOST_SPIRIT_DEBUG // Enables debugging output for Spirit parsers
#include <boost/fusion/adapted.hpp> // For adapting structs to Fusion sequences
#include <boost/spirit/include/qi.hpp> // Core Spirit Qi components
#include <boost/spirit/include/phoenix.hpp> // For Phoenix function objects (for callbacks)
#include <iostream> // For standard input/output
#include <string> // For string manipulation
#include <list> // For std::list
#include <vector> // For std::vector
#include <fstream> // For file stream operations
#include <iterator> // For iterators

// Define namespaces for easier access
namespace qi = boost::spirit::qi;
namespace phx = boost::phoenix;

// Structure to hold a row of data
struct rowType {
    unsigned int number;
    std::list<unsigned int> list;
};

// Structure to hold the overall problem data
struct problemType {
    unsigned int ROW;
    std::vector<rowType> rows;
};

// Adapt the structures for use with Boost.Fusion
BOOST_FUSION_ADAPT_STRUCT(rowType, (unsigned int, number)(std::list<unsigned int>, list))
BOOST_FUSION_ADAPT_STRUCT(problemType, (unsigned int, ROW)(std::vector<rowType>, rows))

// Define the grammar for parsing the problem structure
template<typename Iterator>
struct problem_parser : qi::grammar<Iterator, problemType(), qi::blank_type> // Using qi::blank as the skipper
{
    problem_parser() : problem_parser::base_type(problem)
    {
        using namespace qi;

        // Rule for parsing a list of integers enclosed in square brackets
        // -(int_ % ',') handles an optional, comma-separated list of integers
        list = '[' >> -(int_ % ',') >> ']';

        // Rule for parsing a single row: an integer, followed by a list, and then an end-of-line character
        row = int_ >> list >> eol; // Explicitly requiring end of line

        // Rule for the main problem structure: "ROW", row number, end-of-line, and one or more rows
        problem = "ROW" >> int_ >> eol >> +row;

        // Enable debugging for the defined rules
        BOOST_SPIRIT_DEBUG_NODES((problem)(row)(list));
    }

    // Declare the rules for the grammar
    qi::rule<Iterator, problemType(), qi::blank_type> problem;
    qi::rule<Iterator, rowType(), qi::blank_type> row;
    qi::rule<Iterator, std::list<unsigned int>(), qi::blank_type> list;
};

int main()
{
    // Example input string with specific line breaks
    const std::string input =
        "ROW 1\n"
        "2 [3, 4]\n"
        "5 [6, 7]\n";

    // Get iterators for the input string
    auto f = begin(input), l = end(input);

    // Instantiate the parser and the data structure
    problem_parser<std::string::const_iterator> p;
    problemType data;

    // Attempt to parse the input using qi::blank as the skipper
    bool ok = qi::phrase_parse(f, l, p, qi::blank, data);

    if (ok) {
        std::cout << "Parsing successful.\n";
        // You can now access the parsed data in the 'data' object
        std::cout << "ROW Number: " << data.ROW << "\n";
        for (const auto& r : data.rows) {
            std::cout << "  Row Number: " << r.number << ", List: [";
            for (size_t i = 0; i < r.list.size(); ++i) {
                std::cout << r.list.back(); // Note: list.back() might not be desired, consider list.front() or iterating differently
                if (i < r.list.size() - 1) std::cout << ", ";
            }
            std::cout << "]\n";
        }
    } else {
        std::cout << "Parsing failed.\n";
    }

    // Report any remaining unparsed input
    if (f != l) {
        std::cout << "Remaining unparsed input: '" << std::string(f, l) << "'\n";
    }

    return 0;
}

In this example, qi::blank_type is used as the skipper. qi::blank typically skips horizontal whitespace (spaces, tabs) but does not skip qi::eol (end-of-line characters). By using qi::eol explicitly in the row rule, we ensure that each row must end with a newline, providing stricter parsing control compared to using qi::space as the skipper. This is essential for grammars where line structure is significant. Solution 2: Omitting Explicit Line Breaks with qi::space

If your input does not strictly require line breaks to be parsed explicitly and you want to allow any whitespace (including newlines) to be skipped, you can use qi::space as the skipper.

#define BOOST_SPIRIT_DEBUG
#include <boost/fusion/adapted.hpp>
#include <boost/spirit/include/qi.hpp>
#include <boost/spirit/include/phoenix.hpp>
#include <iostream>
#include <string>
#include <list>
#include <vector>
#include <fstream>
#include <iterator>

namespace qi = boost::spirit::qi;
namespace phx = boost::phoenix;

struct rowType {
    unsigned int number;
    std::list<unsigned int> list;
};

struct problemType {
    unsigned int ROW;
    std::vector<rowType> rows;
};

BOOST_FUSION_ADAPT_STRUCT(rowType, (unsigned int, number)(std::list<unsigned int>, list))
BOOST_FUSION_ADAPT_STRUCT(problemType, (unsigned int, ROW)(std::vector<rowType>, rows))

template<typename Iterator>
struct problem_parser : qi::grammar<Iterator, problemType(), qi::space_type> // Using qi::space as the skipper
{
    problem_parser() : problem_parser::base_type(problem)
    {
        using namespace qi;

        // Rule for parsing a list of integers enclosed in square brackets
        list = '[' >> -(int_ % ',') >> ']';

        // Rule for parsing a single row: an integer, followed by a list
        // No explicit eol here, relying on the skipper (qi::space) to handle whitespace
        row = int_ >> list;

        // Rule for the main problem structure: "ROW", row number, and one or more rows
        problem = "ROW" >> int_ >> +row;

        BOOST_SPIRIT_DEBUG_NODES((problem)(row)(list));
    }

    qi::rule<Iterator, problemType(), qi::space_type> problem;
    qi::rule<Iterator, rowType(), qi::space_type> row;
    qi::rule<Iterator, std::list<unsigned int>(), qi::space_type> list;
};

int main()
{
    // Example input string where whitespace, including newlines, is flexible
    const std::string input =
        "ROW 1 " // Note: whitespace is required between "ROW" and "1", and between rows
        "2 [3, 4]"
        "5 [6, 7]";

    auto f = begin(input), l = end(input);

    problem_parser<std::string::const_iterator> p;
    problemType data;

    // Attempt to parse the input using qi::space as the skipper
    bool ok = qi::phrase_parse(f, l, p, qi::space, data);

    if (ok) {
        std::cout << "Parsing successful.\n";
        std::cout << "ROW Number: " << data.ROW << "\n";
        for (const auto& r : data.rows) {
            std::cout << "  Row Number: " << r.number << ", List: [";
            // Proper iteration for std::list to print elements
            bool first = true;
            for (unsigned int val : r.list) {
                if (!first) std::cout << ", ";
                std::cout << val;
                first = false;
            }
            std::cout << "]\n";
        }
    } else {
        std::cout << "Parsing failed.\n";
    }

    if (f != l) {
        std::cout << "Remaining unparsed input: '" << std::string(f, l) << "'\n";
    }

    return 0;
}

In this second example, qi::space_type is the skipper. qi::space handles spaces, tabs, and newlines. Because the row rule does not explicitly require qi::eol, the qi::space skipper will consume any whitespace, including newlines, between elements. This makes the parser more flexible regarding input formatting but less strict about line endings. This approach is suitable when the exact placement of newlines is not critical to the data’s structure. Reading Input from Files

For larger datasets or persistent storage, reading input from a file is standard practice. Here’s how you can adapt the parsing logic to read from a file stream:

// ... (previous includes and structure definitions) ...

// Inside main() or a dedicated parsing function:
std::ifstream ifs("input.txt", std::ios::binary); // Open file, binary mode often preferred for streams
ifs.unsetf(std::ios::skipws); // Crucial: disable default whitespace skipping for the stream itself

// Use Boost.Spirit's istream_iterator for parsing directly from the file stream
boost::spirit::istream_iterator f(ifs), l;

problem_parser<boost::spirit::istream_iterator> p;
problemType data;

// The phrase_parse function can now work with stream iterators
// The skipper choice (qi::blank or qi::space) depends on your file's format and parsing needs
bool ok = qi::phrase_parse(f, l, p, qi::blank, data); // Using qi::blank as an example

if (ok) {
    std::cout << "Successfully parsed from file.\n";
    // Process parsed data
} else {
    std::cout << "Failed to parse from file.\n";
}

// Note: For file operations, error handling (e.g., checking if ifs.is_open()) is essential.

This snippet demonstrates reading from a file named input.txt. The key is ifs.unsetf(std::ios::skipws), which ensures that the stream itself doesn’t perform its own whitespace skipping, allowing the Spirit parser to manage it. You can select qi::blank or qi::space as the parser’s skipper based on the file’s content and your parsing requirements. FAQs on Boost Spirit Skipper Control

Q: What is the primary difference between qi lexeme and qi no skip

ANS: qi::lexeme inhibits the skipper for a specific parser expression, meaning whitespace won’t be skipped within that expression’s match. qi::no_skip does the same but without any pre-skip actions, essentially disabling skipping entirely for that parser.

Q: Can qi raw include skipped characters in its output

ANS: Yes, qi::raw parses like normal, including skipping, but it returns the entire iterator range of the matched source sequence, which includes the positions of any skipped characters.

Q: How does qi skip s p work

ANS: qi::skip(s) [ p ] replaces the current skipper with a new skipper s specifically for the parser expression p. You need to ensure s is a valid skipper and that p is correctly defined within the skip[] clause.

Q: Why would I use qi blank instead of qi space as a skipper

ANS: qi::blank typically skips horizontal whitespace (spaces, tabs) but not qi::eol (end-of-line characters). qi::space usually skips all whitespace, including newlines. You’d use qi::blank when you need to parse line endings explicitly or maintain line structure.

Q: What happens if the input doesnt match the grammar exactly

ANS: If the input does not match the grammar, qi::phrase_parse will return false. Any remaining unparsed input can be inspected using the end iterator of the parsed range.
