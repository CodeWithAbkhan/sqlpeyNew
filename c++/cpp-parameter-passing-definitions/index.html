“C++ Parameter Passing: Defining ‘Pass By Reference’ vs ‘Pass By Value’”

How can we establish a clear, technically precise definition for “pass by reference” based on language specifications, and how do various function call mechanisms align with this definition?

Let’s examine a scenario using a simple structure in C++:

struct DataObject {
    int value_field;
};

// Scenario 1: Pointer argument
void process_pointer(DataObject* ptr) { // 1
    ptr->value_field++;
}

// Scenario 2: Constant reference argument
void process_const_ref(const DataObject& ref_const) { // 2
    // Modification is generally disallowed/not useful here
}

// Scenario 3: Modifying reference argument
void process_ref(DataObject& ref) { // 3
    ref.value_field++;
}

// Scenario 4: Value argument (copy)
void process_value(DataObject obj_copy) { // 4
    obj_copy.value_field++;
}

int main() {
    DataObject instance = { 10 };
    const DataObject constant_instance = { 10 };

    process_pointer(&instance); // Invokes 1
    process_ref(instance);      // Invokes 3
    process_const_ref(constant_instance); // Invokes 2
    process_value(instance);    // Invokes 4
    
    // After these calls, instance.value_field has been modified by calls 1 and 3.
    return 0;
}

Some developers might classify (1) and (3) as “pass by reference,” while excluding (2). Others might claim everything except (4) is “pass by reference” because the underlying object data isn’t duplicated entirely.

A Rigorous Definition for Pass By Reference

To settle this, a stricter definition rooted in the language specification (like the C++ standard, referencing concepts like argument expressions and reference types) is necessary.

Proposed Strict Definition: An argument is considered passed by reference if and only if the corresponding function parameter possesses a reference type, and this reference parameter binds directly to the argument expression. In all other scenarios involving data transmission, the mechanism defaults to pass by value.

Applying this strict definition:

  • Invoking (1): process_pointer(&instance);

    • Yields a DataObject* (a pointer). The parameter type is a pointer, not a reference type.
    • Result: Pass by Value (A pointer value is copied). Modifying the pointer within the function does not alter the original pointer variable held by the caller.

  • Invoking (3): process_ref(instance);

    • The parameter DataObject& ref has a reference type. The reference directly binds to the argument instance.
    • Result: Pass by Reference. Changes to ref affect instance.

  • Invoking (2): process_const_ref(constant_instance);

    • The parameter const DataObject& ref_const has a reference type and binds directly.
    • Result: Pass by Reference (specifically, by constant reference). Changes are disallowed, but the mechanism of reference binding applies.

  • Invoking (4): process_value(instance);

    • The parameter DataObject obj_copy does not have a reference type. A copy is made.
    • Result: Pass by Value.

Cases Considered Pass By Value Under the Strict Rule

According to the rule, the following are fundamentally pass by value because the parameter type lacks a reference type or the binding is indirect:

  1. void check1(const DataObject& arg); check1(DataObject()); (Pass by Value: A temporary object is created and bound to the reference; the binding is often considered indirect, or conversion occurs).
  2. void check2(const int& i); check2(100); (Pass by Value: A temporary int is initialized from the literal and bound to the reference).
  3. void check3(DataObject arg); check3(DataObject()); (Pass by Value: Parameter is not a reference type).
  4. void check4(DataObject arg); DataObject item; check4(item); (Pass by Value: Parameter is not a reference type, copy construction occurs).
  5. void check5(DataObject* ptr); DataObject item; check5(&item); (Pass by Value: A pointer value is copied).

Cases That Are Strictly Pass By Reference

These examples align with the requirement that the parameter type must be a reference type binding directly:

  1. void modify_ptr_ref(DataObject*& ptr_ref); DataObject data; DataObject* p = &data; modify_ptr_ref(p); (The parameter is a reference to a pointer, directly bound).
  2. void direct_ref(const DataObject& obj_arg); DataObject d; direct_ref(d); (Direct binding to an existing object).
  3. Binding via Conversion: 
    struct Base { };
struct Derived : Base { };
struct Converter { operator Base&() { static Base b_static; return b_static; } };

void consume_base_ref(Base& b);
Derived d_obj;
// If 'd_obj' were convertible to a reference of 'Base' directly, this would apply.
// A more relevant example involves temporary creation via conversion:
Converter conv;
consume_base_ref(conv); // The conversion operator returns a reference to a static object, binding the reference parameter.

Alternative Viewpoints on Modification Visibility

The confusion often lies in whether the modification is visible upon return, which relates more to value semantics versus reference semantics during invocation.

  • Pass by Value (process_value(instance)): A separate obj_copy is created. Changes to obj_copy are localized. The original instance is unaffected by field changes within the function scope.
  • Pass by Reference (process_ref(instance)): ref is an alias for instance. Changes to ref directly alter instance. The modification is visible to the caller.

If the premise suggests that modifications appear in the caller’s scope for both value and reference passing, that statement is inaccurate regarding standard pass-by-value semantics for value types or objects without shared internal state. Pass by value prevents external visibility of changes unless deep copying is manually circumvented (e.g., by passing a pointer by value, as in Scenario 1, where the pointer value changes locally, but the pointed-to data can be mutated).

FAQs on Cpp Parameter Passing Definitions

Q: What is the primary source of confusion regarding pass by reference

ANS: Confusion arises because “pass by reference” is sometimes interpreted as “passing a pointer” (which is technically passing a pointer value), or whether it strictly means the parameter type must be a reference type binding directly to the argument expression.

Q: In C++, is passing a pointer to an object considered pass by reference

ANS: No, passing a raw pointer T* is technically pass by value, as the value of the pointer address is copied. Mutations to the data pointed to are visible, but mutations to the pointer variable itself inside the function are not visible outside.

Q: If a function modifies an object passed by value, are those changes seen by the caller

ANS: Generally no, if the object passed by value is a standard copy. The function works on a distinct copy. The caller only sees changes if the object contains pointers to shared mutable data (shallow copy issues) or if the function returns the modified object.
struct Object {
    int i;
};

void sample(Object* o) { // 1
    o-&gt;i++;
}

void sample(Object const&amp; o) { // 2
    // nothing useful here :)
}

void sample(Object &amp; o) { // 3
    o.i++;
}

void sample1(Object o) { // 4
    o.i++;
}

int main() {
    Object obj = { 10 };
    Object const obj_c = { 10 };

    sample(&amp;obj); // calls 1
    sample(obj) // calls 3
    sample(obj_c); // calls 2
    sample1(obj); // calls 4
}
sample(&amp;obj);
       // yields a `Object*`. Passes a *pointer* to the object by value. 
       // The caller can change the pointer (the parameter), but that 
       // won't change the temporary pointer created on the call side (the argument). 

    sample(obj)
       // passes the object by *reference*. It denotes the object itself. The callee
       // has got a reference parameter.

    sample(obj_c);
       // also passes *by reference*. the reference parameter references the
       // same object like the argument expression. 

    sample1(obj);
       // pass by value. The parameter object denotes a different object than the 
       // one passed in.
void f1(Object const&amp; o);
f1(Object()); // 1

void f2(int const&amp; i);
f2(42); // 2

void f3(Object o);
f3(Object());     // 3
Object o1; f3(o1); // 4

void f4(Object *o);
Object o1; f4(&amp;o1); // 5
void f1(Object *&amp; op);
Object a; Object *op1 = &amp;a; f1(op1); // 1

void f2(Object const&amp; op);
Object b; f2(b); // 2

struct A { };
struct B { operator A&amp;() { static A a; return a; } };
void f3(A &amp;);
B b; f3(b); // passes the static a by reference
