“C++ Pointer Arithmetic Legality: Is &array[N] Well-Defined Behavior?”

A core point of discussion in C and C++ programming revolves around pointer arithmetic and array bounds. Specifically, is the expression &array[N] considered legal and well-defined behavior when array has $N$ elements (i.e., when we are pointing one past the last element)?

Various interpretations of the standard exist, often hinging on the precise definition of lvalues and the behavior of the dereference operator (*) implied by the subscript operator ([]).

Primary Interpretations Based on C++ Standards Evolution

The legality seems to shift depending on the specific version of the C++ standard being referenced.

Argument for Legality (C99 Context / Earlier C++ Views)

One perspective, strongly supported by interpretations referencing C99 standards and early C++ analyses, suggests that obtaining a pointer one element past the array end is permissible if no dereferencing occurs.

The fundamental identity for the subscript operator is: $$E1[E2] \text{ is identical to } *((E1)+(E2))$$

If we consider &array[5] for an array of size 5 (where the last element is index 4), the expression becomes &(*(array + 5)).

  1. Pointer Addition: (array + 5) yields a pointer one past the last element. The standard explicitly allows the result of pointer arithmetic to point one past the end of an array if the original pointer pointed to the last element (Section 6.5.6, paragraph 8 in C99 draft).
  2. Unary Star (*): The expression *(array + 5) applies the unary *. In some readings (Solution 7), this operation yields an lvalue referring to the object at that location, without necessarily causing UB if the address is not subsequently evaluated as an rvalue or dereferenced in a destructive manner.
  3. Address-of (&): The unary & operator takes the address of the resulting lvalue. If *(array + 5) produces a valid lvalue referring to an “unrelated object” (as suggested by notes on pointers past the end), then taking its address, &(*(array + 5)), is deemed legal, resulting in a valid pointer value (one past the end).

Practical Example Demonstrating Pointer Validity (Not Dereferencing):

This construction is often compared to how STL iterators work, where end() points one past the last element:

int data_set[5]; // Indices 0 through 4 are valid objects

// Solution 7 Style Construction (Pretending the UB aspect is avoided)
int* end_iterator_style = &(*((data_set) + 5)); 

// This results in the same address as the standard way to get the end pointer
int* standard_end = data_set + 5;

Argument Against Legality (Modern C++ Views - Post N4835/N4944)

More recent analyses based on modern C++ drafts (like N4835 and N4944) suggest this construction results in ill-formed code because the intermediate result of array[5] is not an lvalue.

  1. Subscript Definition: array[5] still equals *(array + 5).
  2. Lvalue Requirement for &: The C++ standard (e.g., §[expr.unary.op]/3 in N4944) states that the operand of the unary & operator shall be an lvalue of some type T.
  3. Lvalue Definition: An lvalue is a glvalue whose evaluation determines the identity of an object, bit-field, or function. A pointer to one-past-the-end of an array (like the result of array + 5) does not determine the identity of an existing object. Therefore, *(array + 5) is not considered an lvalue.
  4. Ill-Formed Code: Since the operand to & is not an lvalue, the program is ill-formed.

This view emphasizes that while array + 5 produces a valid pointer value (one that can be stored), using that value within an expression that requires an lvalue (like being the operand of & following an implied dereference) violates the type system rules.

Alternative Solution: Conventional Pointer Arithmetic

Regardless of the strict legality debate over &array[5], the conventional and universally accepted way to obtain a pointer to one position past the end of an array is direct pointer addition, which has explicitly defined behavior related to array bounds:

int numeric_array[10];

// Obtain a pointer to the element one past the end (index 10)
int* array_end_ptr = numeric_array + 10; 

// Obtain a pointer to the beginning
int* array_start_ptr = numeric_array; // Equivalent to &numeric_array[0]

This method aligns perfectly with the requirements for iterator arithmetic and avoids the ambiguity associated with the implied dereference of the subscript operator when taking the address of the result.

Key Distinctions in Pointer Operations

It is critical to distinguish between:

  1. Storing a pointer one past the end: int* p = array + N; (Legal, defined behavior if $N$ is the size).
  2. Dereferencing a pointer one past the end: * (array + N); (Undefined Behavior, as noted in §6.5.6, paragraph 8, if the result points one past the last element and is evaluated).
  3. Taking the address of the result of a subscript: &array[N]; (The core debate—illegal in modern C++ because the result is not an lvalue).

If the goal is simply to hold the address one past the last element, use simple addition. If you are dealing with low-level operations where you must use subscript notation, modern standards lean toward marking &array[N] as ill-formed.

FAQs on C Plus Plus Pointer Address Legality

Q: Is it legal to store the address one past the end of an array

ANS: Yes, storing the address one past the end of an array using array + size is explicitly allowed and defined by the standard for pointer arithmetic.

Q: Does &array[5] result in the same pointer as array + 5

ANS: They often result in the same memory address. However, the sequence of operations defined by the standard for obtaining this address differs, making &array[5] potentially ill-formed in modern C++ because array[5] does not yield an lvalue.

Q: Is dereferencing array + 5 undefined behavior

ANS: Yes, dereferencing a pointer that points one past the last element of an array is undefined behavior according to the C++ standard, even though storing the pointer itself is legal.
