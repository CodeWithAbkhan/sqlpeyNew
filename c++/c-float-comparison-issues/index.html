“C Float Comparison Issues: Why 0.7 != 0.7f?”

When working with C, you might encounter situations where comparing floating-point numbers, especially literals, leads to surprising outcomes. Specifically, why does float x = 0.7f; followed by x == 0.7 often evaluate to false, while x == 0.7f works as expected? This behavior stems from how C handles floating-point types and literals.

The Core of the Problem: Type Precision and Literals

In C, floating-point literals like 0.7 are, by default, treated as double. On most systems, double offers greater precision than float. When you assign a double literal to a float variable, a conversion occurs, often involving rounding. This can lead to a loss of precision.

Consider the declaration:

float myFloat = 0.7;

Here, 0.7 is a double literal. This double value is then converted to a float and stored in myFloat. This conversion process may not perfectly represent the original decimal value due to the limited precision of float.

Now, when you compare myFloat == 0.7:

  1. The float value in myFloat is promoted to double to match the type of the double literal 0.7.
  2. This promotion doesn’t magically restore the lost precision from the initial float assignment. The comparison is made between the promoted (but still imprecise) float value and the precise double representation of 0.7.

However, when you compare myFloat == 0.7f:

  1. 0.7f is explicitly a float literal.
  2. The comparison myFloat == 0.7f compares two float values directly. Since myFloat was initialized from a double that was converted to float, and 0.7f is also a float, the comparison is more likely to yield the expected result if the float representation of 0.7f is identical to the float representation derived from 0.7.

Why 0.7 Isn’t Exactly Representable

A key reason for these discrepancies lies in the binary representation of decimal numbers. Just as 1/3 cannot be represented exactly in decimal (0.333…), many decimal fractions, including 0.7, cannot be represented exactly in binary floating-point formats like IEEE 754.

Let’s examine the binary representation of 0.7f (single-precision float): The decimal 0.7 converts to a binary representation that, when limited to 23 bits for the significand of a float, results in a repeating pattern. This pattern doesn’t perfectly match the exact decimal value of 0.7. When this float value is later converted back to a double for comparison with a double literal 0.7, the slight differences become apparent.

Consider the comparison 0.7 > myFloat where myFloat is 0.7f. The output might be “Hi”, indicating 0.7 (as a double) is indeed greater than the float representation of 0.7. Printing with high precision often reveals this: 0.7000000000 vs. 0.6999999881.

Demonstrating the Differences with Code Examples

To illustrate these concepts, let’s look at some C code snippets and their observed behavior.

Example 1: Direct Comparison

#include <stdio.h>

int main() {
    float x = 0.7f; // Explicitly a float literal

    // Comparing float with a double literal
    if (x == 0.7) {
        printf("x == 0.7 (double literal) evaluates to true.\n");
    } else {
        printf("x == 0.7 (double literal) evaluates to false.\n");
    }

    // Comparing float with a float literal
    if (x == 0.7f) {
        printf("x == 0.7f (float literal) evaluates to true.\n");
    } else {
        printf("x == 0.7f (float literal) evaluates to false.\n");
    }

    return 0;
}

Example 2: Illustrating Precision Loss

#include <stdio.h>
#include <math.h> // For fabs

int main() {
    float f_val = 0.7f;
    double d_val = 0.7;

    // Direct comparison after conversion
    double promoted_f_val = f_val;

    printf("Float f_val: %.30f\n", f_val);
    printf("Double d_val: %.30f\n", d_val);
    printf("Promoted f_val (as double): %.30f\n", promoted_f_val);

    if (f_val == d_val) {
        printf("Comparison (float == double): Equal\n");
    } else {
        printf("Comparison (float == double): Not Equal\n");
    }

    return 0;
}

Example 3: The 1.0 Case

Numbers like 1.0 are generally represented exactly in both float and double. When a float value of 1.0 is converted to double, the representation remains exact, leading to a successful comparison.

#include <stdio.h>

int main() {
    float x = 1.0f;

    if (x == 1.0) {
        printf("x == 1.0 (double literal) evaluates to true.\n");
    } else {
        printf("x == 1.0 (double literal) evaluates to false.\n");
    }

    return 0;
}

Safe Floating-Point Comparison Techniques

Given the inherent precision issues, directly comparing floating-point numbers for exact equality (==) is generally discouraged. Instead, use a tolerance-based comparison.

Method 1: Using an Epsilon Value

Compare the absolute difference between the two numbers against a small predefined value (epsilon).

#include <stdio.h>
#include <math.h> // For fabs
#include <float.h> // For FLT_EPSILON

int main() {
    float f = 0.7f;
    float epsilon = FLT_EPSILON; // Smallest value such that 1.0 + epsilon != 1.0

    // Check if the absolute difference is within the epsilon
    if (fabs(f - 0.7f) < epsilon) {
        printf("f is approximately equal to 0.7f\n");
    } else {
        printf("f is not approximately equal to 0.7f\n");
    }

    // Alternatively, compare against the double literal with appropriate casting
    if (fabs(f - 0.7) < epsilon) {
        printf("f is approximately equal to 0.7 (double)\n");
    } else {
        printf("f is not approximately equal to 0.7 (double)\n");
    }

    return 0;
}

Note: FLT_EPSILON is defined in <float.h> and represents the difference between 1.0 and the next representable float value.

Method 2: Relative Difference

For a more robust comparison, especially when dealing with numbers of varying magnitudes, consider the relative difference.

#include <stdio.h>
#include <math.h> // For abs, max
#include <algorithm> // For std::max in C++

// C implementation using manual max
float custom_max(float a, float b) {
    return (a > b) ? a : b;
}

bool areFloatsEqual(float val1, float val2) {
    const float FP32_EPSILON = 1E-7f; // Custom epsilon for single precision
    float abs_diff = fabs(val1 - val2);

    // Handle cases where both values are very close to zero
    if (val1 == 0.0f && val2 == 0.0f) {
        return true;
    }

    // Calculate relative difference
    float larger_val = custom_max(fabs(val1), fabs(val2));
    float rel_diff = abs_diff / larger_val;

    return rel_diff < FP32_EPSILON;
}

int main() {
    float f_val1 = 0.7f;
    float f_val2 = 0.70000001f;
    float f_val3 = 0.6999999f;
    float f_val4 = 0.0000001f;
    float f_val5 = 0.0000002f;


    printf("Comparing %.7f and %.7f: %s\n", f_val1, f_val2, areFloatsEqual(f_val1, f_val2) ? "Equal" : "Not Equal");
    printf("Comparing %.7f and %.7f: %s\n", f_val1, f_val3, areFloatsEqual(f_val1, f_val3) ? "Equal" : "Not Equal");
    printf("Comparing %.7f and %.7f: %s\n", f_val4, f_val5, areFloatsEqual(f_val4, f_val5) ? "Equal" : "Not Equal");


    return 0;
}

Best Practices for Floating-Point Handling in C

  • Suffix Literals: Always use the f suffix for float literals (e.g., 0.7f, 1.0f). This avoids implicit conversions from double to float.
  • Avoid Mixing Types: Minimize mixing float and double in calculations. If you need higher precision, stick with double. If memory is a critical concern and float precision suffices, use float consistently.
  • Use Epsilon Comparison: Never rely on direct equality (==) for floating-point values. Use an epsilon-based comparison for approximate equality.
  • Understand IEEE 754: Familiarize yourself with the IEEE 754 standard for floating-point arithmetic to grasp the underlying reasons for precision differences.

FAQs on C Float Comparison

FAQs on C Float Comparison

Q: Why does comparing a float to a double literal like 0.7 fail in C

ANS: By default, decimal floating-point literals in C are treated as double. When you assign a double literal (like 0.7) to a float variable, a conversion occurs, often losing precision. Comparing this float variable to the original double literal involves a type promotion, and the accumulated precision differences cause the comparison to fail.

Q: What is the correct way to compare two float variables for equality in C

ANS: It’s best to avoid direct equality checks (==) with floating-point numbers. Instead, compare the absolute difference between the two numbers against a small tolerance value, often called an epsilon. For example: if (fabs(float1 - float2) < FLT_EPSILON).

Q: Is it safe to use the equality operator == with float variables in C

ANS: No, it is generally unsafe and can lead to unexpected results due to the way floating-point numbers are represented in binary and potential precision loss during calculations or assignments.

Q: What is FLT_EPSILON in C

ANS: FLT_EPSILON is a macro defined in <float.h>. It represents the smallest representable positive float number such that 1.0f + FLT_EPSILON is not equal to 1.0f. It’s a standard measure of precision for float types.

Q: Why does 1.0 compare correctly between float and double in C

ANS: Numbers like 1.0 can be represented exactly in both float and double binary formats. When a float value of 1.0 is compared to a double literal 1.0, the conversion and comparison process maintains accuracy because there’s no inherent precision loss for this specific value.
