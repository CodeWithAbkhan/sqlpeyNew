How to Check if a C++ Class Has a Specific Member Function

Determining whether a C++ class has a specific member function is a common task in template metaprogramming. This capability is crucial for writing generic code that can adapt its behavior based on the available members of a type. For instance, you might want to call a toString() method if it exists, or fall back to a default string representation if it doesn’t.

This post delves into various techniques, from classical SFINAE (Substitution Failure Is Not An Error) to more modern C++ features, to achieve this. We’ll examine several solutions, each with its own approach and advantages.

Solution 1: SFINAE with decltype

One of the foundational methods involves using SFINAE with decltype to check for the existence of a member function. This approach, demonstrated below, uses a helper class to determine if a decltype expression for a member function is valid.

#include <iostream>

struct Hello
{
    int helloworld() { return 0; }
};

struct Generic {};    

// SFINAE test
template <typename T>
class has_helloworld
{
    typedef char one;
    struct two { char x[2]; };

    template <typename C> static one test( decltype(&C::helloworld) ) ;
    template <typename C> static two test(...);    

public:
    enum { value = sizeof(test<T>(0)) == sizeof(char) };
};
    
int main()
{
    std::cout << std::boolalpha;
    std::cout << "Hello has helloworld: " << has_helloworld<Hello>::value << std::endl;
    std::cout << "Generic has helloworld: " << has_helloworld<Generic>::value << std::endl;
    return 0;
}

This method was tested on Linux with GCC 4.1/4.3 and is generally portable, though compiler implementations can sometimes vary.

Solution 2: C++11 Expression SFINAE

C++11 introduced more powerful SFINAE capabilities, making it easier to check for the existence of functions or other members. This solution employs trailing return types and decltype for a more expressive check.

#include <iostream>
#include <ostream>
#include <type_traits>

template<class T>
auto serialize_imp(std::ostream& os, T const& obj, int)
    -> decltype(os << obj, void())
{
  os << obj;
}

template<class T>
auto serialize_imp(std::ostream& os, T const& obj, long)
    -> decltype(obj.stream(os), void())
{
  obj.stream(os);
}

template<class T>
auto serialize(std::ostream& os, T const& obj)
    -> decltype(serialize_imp(os, obj, 0), void())
{
  serialize_imp(os, obj, 0);
}

namespace detail{
  template<class T, class A0>
  static auto test_stream(int)
      -> std::conditional_t<true, std::true_type, decltype(std::declval<T>().stream(std::declval<A0>()))>;
  template<class, class A0>
  static auto test_stream(long) -> std::false_type;
} // detail::

template<class T, class Arg>
struct has_stream : decltype(detail::test_stream<T, Arg>(0)){};

// Example usage with a dummy class
struct Streamable {
    void stream(std::ostream& os) const { os << "Streamed"; }
};

struct NotStreamable {};

int main() {
    std::cout << std::boolalpha;
    std::cout << "Streamable has stream: " << has_stream<Streamable, std::ostream>::value << std::endl;
    std::cout << "NotStreamable has stream: " << has_stream<NotStreamable, std::ostream>::value << std::endl;
    return 0;
}

This solution also introduces a helper trait has_stream for checking the existence of a stream member function, demonstrating how to generalize the technique. For a live example, you can refer to online C++ compilers .

Solution 3: C++20 Concepts and Requires Expressions

C++20 significantly simplifies trait creation with concepts and requires expressions. This allows for a very clean and readable way to check for member function existence.

#include <string>
#include <iostream>

template<class T>
std::string optionalToString(T* obj)
{
    // C++20 requires expression checks for member function existence
    constexpr bool has_toString = requires(const T& t) {
        t.toString();
    };

    if constexpr (has_toString)
        return obj->toString();
    else
        return "toString not defined";
}

// Example usage
struct HasToString { std::string toString() const { return "I have toString"; } };
struct NoToString {};

int main() {
    HasToString hts;
    NoToString nts;
    std::cout << optionalToString(&hts) << std::endl;
    std::cout << optionalToString(&nts) << std::endl;
    return 0;
}

This example shows a direct check within the function. For pre-C++20 compatibility, the “Detection toolkit” proposal (N4502) and techniques using std::is_detected_v offer similar functionality.

Solution 4: Macros for Member Function Checks

Custom macros can abstract the SFINAE logic, making it more reusable. This approach defines a macro HAS_MEM_FUNC to generate type traits for checking member functions.

#define HAS_MEM_FUNC(func, name)                                        \
    template<typename T, typename Sign>                                 \
    struct name {                                                       \
        typedef char yes[1];                                            \
        typedef char no [2];                                            \
        template <typename U, U> struct type_check;                     \
        template <typename _1> static yes &chk(type_check<Sign, &__1::func> *); \
        template <typename   > static no  &chk(...);                    \
        static bool const value = sizeof(chk<T>(0)) == sizeof(yes);     \
    }

HAS_MEM_FUNC(toString, has_to_string);

template<typename T>
std::string doSomething(T * t) {
   // Using the generated type trait
   if (has_to_string<T, std::string(T::*)()>::value) {
      return t->toString();
   } else {
      return "T::toString() does not exist.";
   }
}

// Example usage
struct MyClass { std::string toString() { return "My Class String"; } };
struct AnotherClass {};

int main() {
    MyClass mc;
    AnotherClass ac;
    std::cout << doSomething(&mc) << std::endl;
    std::cout << doSomething(&ac) << std::endl;
    return 0;
}

This method is powerful for checking specific function signatures and can be extended to handle const member functions and overloads.

Solution 5: Type Traits without typeof

This solution presents an alternative to using the non-standard typeof operator, relying on template specialization and decltype. It’s noted that compiler behavior might vary regarding standard compliance for certain aspects.

#include <string>
#include <iostream>

template <class Type>
class TypeHasToString
{
    template <typename T, T> struct TypeCheck; // Helper to check function signature

    typedef char Yes;
    typedef long No;

    // Helper struct to define the function pointer type
    template <typename T> struct ToStringHelper
    {
        typedef void (T::*fptr)(); // Signature of the function to check
    };

    // Overload for types that have the toString() member
    template <typename T> static Yes HasToString(TypeCheck<typename ToStringHelper<T>::fptr, &T::toString> *);
    // Fallback overload for types that don't
    template <typename T> static No  HasToString(...);

public:
    // value is true if the first overload is selected, false otherwise
    static bool const value = (sizeof(HasToString<Type>(0)) == sizeof(Yes));
};

// Example usage
struct HasStringMethod { void toString() {} };
struct NoStringMethod {};

int main() {
    std::cout << std::boolalpha;
    std::cout << "HasStringMethod has toString: " << TypeHasToString<HasStringMethod>::value << std::endl;
    std::cout << "NoStringMethod has toString: " << TypeHasToString<NoStringMethod>::value << std::endl;
    return 0;
}

This approach aims for clarity and avoids relying on non-standard extensions.

Solution 6: C++17 Detection Idiom (void_t and detect)

The C++17 standard introduced utilities like void_t and a detect idiom that simplify the creation of type traits. This makes checking for member functions cleaner and more efficient.

#include <iostream>
#include <string>
#include <type_traits>

// Helper for the detection idiom
template <typename..., typename = void>
struct void_t {};

// Primary template for non-detectable types
template <typename T, template <typename> class Op>
struct detect : std::false_type {};

// Specialization for detectable types
template <typename T, template <typename> class Op>
struct detect<T, void_t<Op<T>>> : std::true_type {};

// Archetype for the toString operation
template <typename T>
using toString_t = decltype(std::declval<T>().toString());

// Trait to check for toString existence
template <typename T>
using has_toString = detect<T, toString_t>;

// Function that uses the trait
template <class T>
std::string optionalToString(T* obj)
{
    if constexpr (has_toString<T>::value)
        return obj->toString();
    else
        return "toString not defined";
}

// Example usage
struct ToStringAvailable { std::string toString() const { return "Available"; } };
struct ToStringUnavailable {};

int main() {
    ToStringAvailable tsa;
    ToStringUnavailable tsu;
    std::cout << optionalToString(&tsa) << std::endl;
    std::cout << optionalToString(&tsu) << std::endl;
    return 0;
}

This solution is considered efficient and less verbose compared to older SFINAE techniques. A note on GCC compatibility for void_t in earlier versions is relevant here.

Solution 7: C++11 Overload Resolution

Leveraging C++11’s support for defaulted return types and ellipsis in function signatures, we can use overload resolution to conditionally call a member function.

#include <string>
#include <iostream>

// Function that attempts to call obj->toString()
template<class T>
auto optionalToString(T* obj)
 -> decltype( obj->toString() )
{
    return obj->toString();
}

// Fallback function for types that don't have toString()
auto optionalToString(...) -> std::string
{
    return "toString not defined";
}

// Example usage
struct HasToStringMethod { std::string toString() { return "Yes"; } };
struct NoToStringMethod {};

int main() {
    HasToStringMethod htsm;
    NoToStringMethod ntsm;
    std::cout << optionalToString(&htsm) << std::endl;
    std::cout << optionalToString(&ntsm) << std::endl;
    return 0;
}

This solution uses overload resolution to select the appropriate optionalToString function based on the type T.

Solution 9: C++20 requires Clause

C++20’s requires clause offers the most concise syntax for checking member functions within a template.

#include <string>
#include <iostream>

template<class T>
std::string optionalToString(T* obj)
{
  // C++20 'requires' clause for compile-time checking
  if constexpr (requires { obj->toString(); })
    return obj->toString();
  else
    return "toString not defined";
}

// Example usage
struct HasStr { std::string toString() const { return "String Method"; } };
struct NoStr {};

int main() {
    HasStr hs;
    NoStr ns;
    std::cout << optionalToString(&hs) << std::endl;
    std::cout << optionalToString(&ns) << std::endl;
    return 0;
}

This approach is clean and directly expresses the intent of the check. You can see it live on Godbolt .

Solution 10: C++17 has_member Macro

Inspired by Boost.Hana, this solution provides a has_member macro for C++17 that avoids explicit SFINAE trait classes.

// has_something.h
#pragma once
#include <type_traits>

template<typename T, typename F>
constexpr auto has_member_impl(F&& f) -> decltype(f(std::declval<T>()), true) {
  return true;
}
template<typename>
constexpr bool has_member_impl(...) { return false; }

#define has_member(V, EXPR) \
 has_member_impl<decltype(V)>( [](auto&& obj)->decltype(obj.EXPR){} )

// test.cpp
#include "has_something.h" // Assuming has_something.h is in the same directory
#include <iostream>
#include <string>

struct Example {
    int Foo;
    void Bar() {}

This solution is compact and clearly expresses the intention of checking for a member.

Solution 11: Expression SFINAE with type_sink

This C++11 compatible solution uses a type_sink helper and tag dispatching for a robust check.

#include <string>
#include <iostream>
#include <type_traits>

template<class> struct type_sink { typedef void type; }; // Consumes a type, makes it `void`
template<class T> using type_sink_t = typename type_sink<T>::type;

// Trait to check for the existence of a toString method
template<class T, class=void> struct has_to_string : std::false_type {};
template<class T> struct has_to_string<
  T,
  type_sink_t< decltype( std::declval<T>().toString() ) >
>: std::true_type {};

namespace details {
  // Helper for dispatching based on the trait
  template<class T>
  std::string optionalToString_helper(T* obj, std::true_type /*has_to_string*/) {
    return obj->toString();
  }
  template<class T>
  std::string optionalToString_helper(T* obj, std::false_type /*has_to_string*/) {
    return "toString not defined";
  }
}

template<class T>
std::string optionalToString(T* obj) {
  return details::optionalToString_helper( obj, has_to_string<T>{} );
}

// Example usage
struct MethodExists { std::string toString() const { return "Exists"; } };
struct MethodMissing {};

int main() {
    MethodExists me;
    MethodMissing mm;
    std::cout << optionalToString(&me) << std::endl;
    std::cout << optionalToString(&mm) << std::endl;
    return 0;
}

This approach uses tag dispatching, which is often more maintainable than complex SFINAE expressions.

Solution 13: C++20 Concepts for Function Calls

C++20 concepts provide a declarative way to specify requirements for types, including member function calls.

#include <string>
#include <iostream>

// C++20 concept definition
template<typename T>
concept has_toString = requires(const T& t) {
    t.toString(); // Checks if t.toString() is valid
};

template<typename T>
std::string optionalToString(const T& obj)
{
    if constexpr (has_toString<T>)
        return obj.toString();
    else
        return "toString not defined";
}

// Example usage
struct HasToStringConcept { std::string toString() const { return "Concept OK"; } };
struct NoToStringConcept {};

int main() {
    HasToStringConcept hsc;
    NoToStringConcept ntsc;
    std::cout << optionalToString(hsc) << std::endl;
    std::cout << optionalToString(ntsc) << std::endl;
    return 0;
}

This C++20 approach is highly readable and directly expresses the constraints on the template type.

Solution 14: SFINAE for Inherited Member Functions

This advanced technique addresses the scenario where a member function might be inherited from a base class, ensuring that such cases are correctly detected.

#include <string>
#include <iostream>
#include <type_traits> // For std::enable_if_t, std::is_same

// Example classes
struct A{};
struct B{ int foo(int a, int b);}; // Has foo with specific signature
struct C{void foo(int a, int b);}; // Has foo with wrong return type
struct D{int foo();};             // Has foo with wrong arguments
struct E: public B{};             // Inherits foo from B

// Helper for detection (available in C++17 onwards as std::void_t)
template<typename...> using void_t = void;

// Trait to check for a specific member function signature (e.g., int foo(int, int))
template<typename T, typename = void> struct Has_foo : std::false_type{};

template<typename T>
struct Has_foo<T, void_t<
    std::enable_if_t<
        std::is_same<
            int, // Expected return type
            decltype(std::declval<T>().foo((int)0, (int)0)) // Expression to check
        >::value
    >
>> : std::true_type{};

// Function demonstrating the trait usage
template<class T>
std::string callFooIfAvailable(T* obj) {
    if constexpr (Has_foo<T>::value) {
        return "foo called successfully";
    } else {
        return "foo not available or incompatible";
    }
}

int main() {
    A a_obj;
    B b_obj;
    C c_obj;
    D d_obj;
    E e_obj;

    std::cout << std::boolalpha;
    std::cout << "A has foo: " << Has_foo<A>::value << std::endl;
    std::cout << "B has foo: " << Has_foo<B>::value << std::endl;
    std::cout << "C has foo: " << Has_foo<C>::value << std::endl;
    std::cout << "D has foo: " << Has_foo<D>::value << std::endl;
    std::cout << "E has foo: " << Has_foo<E>::value << std::endl;

    std::cout << "Calling foo on E: " << callFooIfAvailable(&e_obj) << std::endl;

    return 0;
}

This solution is robust, handling inheritance and specific return types correctly.

Solution 29: Simple C++14 Type Trait

For default-constructible classes, C++14 allows for a simpler type trait implementation without declval.

#include <string>
#include <iostream>

// Helper to tag values
template <auto v>
struct tag_v
{
    constexpr static auto value = v;
};

// Trait to check for a foo method, assuming default constructibility
template <class T, class = int> // Default argument for decltype
struct has_foo_method : tag_v<false> {};

// Specialization for types that have a foo method
template <class T>
struct has_foo_method <T, decltype(T().foo())> // Checks if T().foo() is valid
    : tag_v<true> {};

// Function using the trait
template<class T>
std::string callFooIfPresent(T* obj) {
    if constexpr (has_foo_method<T>::value) {
        return std::to_string(obj->foo()); // Assuming foo returns int for simplicity
    } else {
        return "foo not present";
    }
}

// Example usage
struct FooPresent { int foo() const { return 42; } };
struct FooMissing {};

int main() {
    FooPresent fp;
    FooMissing fm;
    std::cout << callFooIfPresent(&fp) << std::endl;
    std::cout << callFooIfPresent(&fm) << std::endl;
    return 0;
}

This method simplifies the check when the class can be default-constructed.

Solution 30: C++03 Compatible Member Check

This solution provides a HasMember macro for C++03 compatibility, allowing checks for variables and methods, with an option to specify method types to resolve ambiguities.

#include <iostream>
#include <string>

// Macro to define member checks
#define HasMember(NAME) \
  template<class Class, typename Type = void> \
  struct HasMember_##NAME \
  { \
    typedef char (&yes)[2]; \
    template<unsigned long> struct exists; \
    template<typename V> static yes Check (exists<sizeof(static_cast<Type>(&V::NAME))>*); \
    template<typename> static char Check (...); \
    static const bool value = (sizeof(Check<Class>(0)) == sizeof(yes)); \
  }; \
  template<class Class> \
  struct HasMember_##NAME<Class, void> \
  { \
    typedef char (&yes)[2]; \
    template<unsigned long> struct exists; \
    template<typename V> static yes Check (exists<sizeof(&V::NAME)>*); \
    template<typename> static char Check (...); \
    static const bool value = (sizeof(Check<Class>(0)) == sizeof(yes)); \
  }

// Example class structure
struct S {
  void Foo() const {} // Const method
  int i;
};

// Apply the macro to check for members
HasMember(Foo);
HasMember(i);

int main ()
{
  std::cout << std::boolalpha;
  // Check for Foo with a specific signature (const member function)
  std::cout << "S has Foo (const): " << HasMember_Foo<S, void (S::*) () const>::value << "\n";
  // Check for Foo without signature (might fail if overloaded)
  std::cout << "S has Foo (general): " << HasMember_Foo<S>::value << "\n";
  // Check for member variable 'i' with specific type
  std::cout << "S has i (int): " << HasMember_i<S, int (S::*)>::value << "\n";
  // Check for member variable 'i' generally
  std::cout << "S has i (general): " << HasMember_i<S>::value << "\n";
  return 0;
}

This C++03 solution is versatile, allowing checks for both variables and functions, and can handle ambiguities by specifying the member’s type.
