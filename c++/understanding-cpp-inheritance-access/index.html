“Understanding C++ Inheritance Access: Public, Protected, and Private Explained”

In C++, the way a derived class inherits from a base class significantly impacts how members of the base class are accessed within the derived class and by the outside world. Understanding the roles of public, protected, and private inheritance is crucial for building robust and well-structured object-oriented programs. This post delves into these concepts, offering clear explanations and practical code examples.

The Core Access Specifiers: Public, Protected, and Private

Before diving into inheritance, let’s clarify the fundamental access specifiers for class members:

  • public: Members declared as public are accessible from anywhere – within the class itself, by derived classes, and by any external code.
  • protected: Members declared as protected are accessible within the class itself and by its derived classes. However, they are not accessible from outside the class hierarchy. This offers a middle ground, allowing derived classes to interact with base class members while still maintaining some level of encapsulation.
  • private: Members declared as private are accessible only within the class itself. They cannot be accessed by derived classes or by any external code. This provides the strictest level of encapsulation, hiding implementation details.

How Inheritance Modes Shape Member Access

The type of inheritance used—public, protected, or private—determines how the public and protected members of the base class are exposed in the derived class. private members of the base class are never directly accessible from derived classes, regardless of the inheritance type.

Public Inheritance: The “IS-A” Relationship

When you use public inheritance, the derived class is a specialized version of the base class. The public members of the base class remain public in the derived class, and protected members remain protected.

class BaseClass {
public:
    int publicVar;
protected:
    int protectedVar;
private:
    int privateVar; // Inaccessible to derived classes
};

class DerivedPublic : public BaseClass {
public:
    void accessBaseMembers() {
        publicVar = 10;      // Accessible (public in BaseClass, public inheritance)
        protectedVar = 20;   // Accessible (protected in BaseClass, public inheritance)
        // privateVar = 30;  // Error: privateVar is not accessible
    }
};

int main() {
    DerivedPublic obj;
    obj.publicVar = 5; // Accessible from outside (public in DerivedPublic)
    // obj.protectedVar = 15; // Error: protectedVar is not accessible from outside
    return 0;
}
Protected Inheritance: “Implemented-in-Terms-Of”

Protected inheritance means that the public and protected members of the base class become protected members of the derived class. This is less common and often implies that the derived class uses the base class for its implementation but doesn’t want to expose the base class’s interface publicly.

class BaseClass {
public:
    int publicVar;
protected:
    int protectedVar;
};

class DerivedProtected : protected BaseClass {
public:
    void accessBaseMembers() {
        publicVar = 10;      // Accessible (public in BaseClass, protected inheritance)
        protectedVar = 20;   // Accessible (protected in BaseClass, protected inheritance)
    }
};

int main() {
    DerivedProtected obj;
    // obj.publicVar = 5; // Error: publicVar is now protected in DerivedProtected
    // obj.protectedVar = 15; // Error: protectedVar is now protected in DerivedProtected
    return 0;
}
Private Inheritance: “Implemented-Using”

With private inheritance, the public and protected members of the base class become private members of the derived class. This signifies that the derived class uses the base class for its implementation but does not want to expose any part of the base class’s interface to the outside world. Containment (composition) is often a preferred alternative to private inheritance.

class BaseClass {
public:
    int publicVar;
protected:
    int protectedVar;
};

class DerivedPrivate : private BaseClass {
public:
    void accessBaseMembers() {
        publicVar = 10;      // Accessible (public in BaseClass, private inheritance)
        protectedVar = 20;   // Accessible (protected in BaseClass, private inheritance)
    }
};

int main() {
    DerivedPrivate obj;
    // obj.publicVar = 5; // Error: publicVar is now private in DerivedPrivate
    // obj.protectedVar = 15; // Error: protectedVar is now private in DerivedPrivate
    return 0;
}

Practical Implications and Scenarios

  • Polymorphism: public inheritance is essential for achieving polymorphism. If a derived class is publicly inherited from a base class, you can use a pointer or reference to the base class to refer to objects of the derived class. This allows for dynamic dispatch and flexible function calls. For example, a Dog class publicly inheriting from Animal allows you to treat a Dog object as an Animal. See [what is python] for analogous concepts in Python’s object model.
  • Code Reuse: All inheritance types facilitate code reuse. However, the choice impacts how the inherited functionality is exposed.
  • Design Choices:
    • Use public inheritance for true “IS-A” relationships.
    • Consider private inheritance (or preferably composition) when you want to use the base class’s implementation but do not want to imply an “IS-A” relationship or expose the base’s interface.
    • protected inheritance is rarely used and often signifies a very specific design pattern, such as optimizing memory usage with empty base classes, as seen in some C++ template metaprogramming techniques.

Accessing Private Base Class Members

While private members of a base class are not directly accessible from a derived class, you can still access them indirectly through public or protected member functions of the base class.

Consider this:

class MyClass {
private:
    int myPrivateMember;
protected:
    int myProtectedMember;
public:
    MyClass() : myPrivateMember(0), myProtectedMember(0) {}
    void setPrivateMember(int val) { myPrivateMember = val; }
    int getPrivateMember() const { return myPrivateMember; }
};

class Derived : public MyClass {
public:
    void manipulateBase() {
        // myPrivateMember = 10; // Error: Cannot access private member directly
        myProtectedMember = 20; // Accessible: protected in Base, public inheritance
        setPrivateMember(30); // Accessing private member via public base method
    }
    int getIndirectPrivate() const {
        return getPrivateMember(); // Accessing private member via public base method
    }
};

int main() {
    Derived obj;
    obj.manipulateBase();
    // std::cout << obj.getPrivateMember(); // Error: getPrivateMember is inherited as protected in Derived
    std::cout << obj.getIndirectPrivate(); // Accessing the value set via Base's public method
    return 0;
}

FAQs on C++ Inheritance Access

FAQs on C++ Inheritance Access

Q: What is the primary difference between public and private inheritance

ANS: Public inheritance maintains the base class’s public and protected access levels in the derived class, modeling an “IS-A” relationship. Private inheritance makes all base class public and protected members private in the derived class, indicating an “IMplements-USING” relationship.

Q: Can derived classes access private members of the base class

ANS: No, derived classes cannot directly access private members of their base class. However, they can access them indirectly through public or protected member functions of the base class.

Q: When should I use protected inheritance

ANS: Protected inheritance is rarely used. It makes base class public and protected members protected in the derived class. It might be considered for specialized implementation scenarios where the base class’s interface should not be exposed publicly but remains accessible to derived classes and their descendants.

Q: How does inheritance affect polymorphism

ANS: Public inheritance enables polymorphism. When a class derives publicly, objects of the derived class can be treated as objects of the base class through base class pointers or references, allowing for dynamic method dispatch. Private or protected inheritance breaks this direct polymorphic relationship.

Q: Is private inheritance the same as composition

ANS: No, they are different. Private inheritance is a form of inheritance where the base class implementation is used, but the derived class does not form an “IS-A” relationship with the base. Composition involves a class having a member object of another class, which is generally a looser coupling and often preferred over private inheritance.

Q: What is the meaning of 'protected' in C++ inheritance

ANS: In inheritance, protected means that a member is accessible within the class itself and by its derived classes, but not by the general public outside the class hierarchy.

Q: Can I change the access level of a base class member in the derived class

ANS: Yes, through the inheritance specifier (public, protected, private), you can change the effective access level of the base class’s public and protected members within the derived class. For example, public members can become protected or private in the derived class.

Q: What are the consequences of private inheritance for external code

ANS: With private inheritance, the base class’s public and protected members become private in the derived class. This means external code cannot access these members through objects of the derived class, effectively hiding the base class’s interface.
