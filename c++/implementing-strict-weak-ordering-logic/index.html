“Implementing Strict Weak Ordering in C++: Comparison Logic Explained”

How does one correctly establish the comparison logic necessary for Strict Weak Ordering when implementing relational operators for custom data structures in C++? This ordering is fundamental for containers like std::set and std::map to function correctly.

Defining Equivalence and Ordering

Strict Weak Ordering defines a relationship between two objects, $x$ and $y$, based on a provided less-than operation (usually overloaded as operator<).

The core definition revolves around equivalence:

  • Two objects $x$ and $y$ are considered equivalent if neither $x < y$ nor $y < x$ evaluates to true. (This implies irreflexivity: an object is never less than itself).

For a comparison operator < to satisfy this ordering requirement, the following conditions must hold true for any objects $a$ and $b$:

The specific rules for determining if one object is “less than” another are entirely dependent on the nature of the object’s type and its contained members.

Solution 1: Leveraging std::tie for Lexicographical Comparison

A highly efficient and idiomatic C++ approach, particularly from C++11 onward, involves using std::tie to generate a tuple of references to the object’s components. The standard library provides a built-in operator< for std::tuple which implements lexicographical comparison—precisely what is needed for Strict Weak Ordering based on member fields.

Consider a structure S composed of ThingA and ThingB:

struct S
{
     ThingA   a;
     ThingB   b;
};

// Operator< implementation using std::tie
bool operator<(S const& lhs, S const& rhs)
{
    // Compares members sequentially: a vs a, then b vs b if a's are equal
    return std::tie(lhs.a, lhs.b) < std::tie(rhs.a, rhs.b);
}

// Equality operator (also benefits from std::tie if members support it)
bool operator==(S const& lhs, S const& rhs)
{
    return std::tie(lhs.a, lhs.b) == std::tie(rhs.a, rhs.b);
}

Note: This relies on the assumption that the constituent types (ThingA, ThingB) already implement the necessary comparison operators respecting Strict Weak Ordering.

Solution 2: Sequential Component Comparison

When dealing with structures where comparison needs to cascade through multiple fields (e.g., primary key, secondary key, tertiary key), one can implement the logic manually by checking components sequentially. The first differing component dictates the result.

This establishes a natural order based on significance (e.g., element 1 is most significant).

// Assuming objects have members a1, a2, a3
bool custom_less_than(const X& a, const X& b)
{
  if (a.a1 < b.a1)
    return true;
  if (b.a1 < a.a1) // If a1 is not less than b1, and b1 is less than a1
    return false;

  // a1 == b1: proceed to element 2
  if (a.a2 < b.a2)
    return true;
  if (b.a2 < a.a2)
    return false;

  // a2 == b2: proceed to element 3
  if (a.a3 < b.a3)
    return true;
    
  return false; // If all preceding elements were equal, the result depends on the final comparison or lack thereof.
}

An alternative perspective for this cascading logic is to “skip while equal, then compare”:

// Hypothetical iteration over N elements
size_t i = 0;
const size_t count = elements.size();

while (i < count - 1 && 
       !(a.elements[i] < a.elements[i+1]) && 
       !(a.elements[i+1] < a.elements[i])) // Skip while equivalent
{
  ++i;

// The result is determined by the first non-equivalent pair found, or false if all were equivalent up to the end.
return i < count - 1 && a.elements[i] < a.elements[i+1];

if (a1 != b1)

Solution 3: C++11 std::tuple Operator Overloading Detail

The C++11 std::tuple provides the lexicographical comparison behavior necessary. When defining the operator for a user-defined class, std::tie is the preferred mechanism to delegate the comparison duties.

struct My_Struct
{
    int a_;
    double b_;
    std::string c_;
};

bool operator<(const My_Struct& lhs, const My_Struct& rhs)
{
    // Leverages tuple comparison logic for a_, b_, and c_ in order
    return std::tie(lhs.a_, lhs.b_, lhs.c_) < std::tie(rhs.a_, rhs.b_, rhs.c_);
}

Solution 4: Utilizing Standard Containers

If the structure naturally maps to a sequence of elements (e.g., coordinates or version numbers), using standard containers like std::vector or std::array can provide the desired ordering automatically, as these containers have built-in lexicographical operator<. This approach scales to $N$ elements without manual rewriting of the comparison function.

Solution 5: Pairwise Comparison Pattern (If only first and second are primary)

For structures resembling pairs, the logic often focuses only on the first differing element.

if (lhs.first != rhs.first)
    return lhs.first < rhs.first;                
if (lhs.second != rhs.second)
    return lhs.second < rhs.second;
    
// Fallback to the third element if the first two match
return lhs.third < rhs.third;

Solution 6: Mimicking Standard Library Pair Comparison

If external libraries are avoided but the logic from standard library pairs is desired, one can adapt that structure. Be cautious with names starting with underscores, as those are reserved identifiers.

// Conceptual structure derived from std::pair logic
bool custom_compare(const MyPair& _Left, const MyPair& _Right)
{
    return (_Left.first < _Right.first ||
            (!(_Right.first < _Left.first) && _Left.second < _Right.second));
}

Edge Case: The Trivial Order

It is an interesting mathematical aspect that an operator< implementation that always returns false technically satisfies all the formal constraints of Strict Weak Ordering, as equivalence is established between all pairs. However, this is practically useless for sorting or use within associative containers.

struct My_Struct
{
    int a_;
    double b_;
    std::string c_;
};

bool operator&lt;(const My_Struct&amp; lhs, const My_Struct&amp; rhs)
{
    return std::tie(lhs.a_, lhs.b_, lhs.c_) &lt; std::tie(rhs.a_, rhs.b_, rhs.c_);
}

FAQs on Implementing Strict Weak Ordering Logic

Q: What is the primary use case for Strict Weak Ordering

ANS: It is the required comparison paradigm for standard C++ associative containers such as std::set, std::map, std::multiset, and std::multimap to maintain sorted order and ensure uniqueness properties.

Q: Does std::tie require the underlying members to support equality

ANS: The std::tie comparison for < only relies on the underlying members supporting <. However, if you implement operator== using std::tie, then the underlying members must support operator== as well.
