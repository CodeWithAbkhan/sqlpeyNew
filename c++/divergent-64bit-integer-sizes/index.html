“Divergent 64-bit Integer Sizes Across Platforms: ILP64, LP64, and LLP64 Explained”

Why do seemingly standard platforms present varying arrangements for integer and pointer sizes when moving to 64-bit architectures? Specifically, the differences between ILP64, LP64, and LLP64 models create portability challenges. How are these schemes defined, and what are the recommended practices for writing platform-agnostic code?

ILP64 and LP64: The Unix Path

The ILP64 scheme, where int, long, and pointers are 64-bit, saw very limited adoption (Cray being a notable user). The industry largely settled on LP64 for modern 64-bit Unix-like systems, including Linux and macOS. In LP64, only long and pointers become 64-bit, leaving int at 32 bits. This transition was influenced by recommendations from groups like the Aspen group.

LLP64: The Microsoft Approach

Microsoft opted for the LLP64 arrangement when moving to 64-bit environments. Here, long long and pointers are 64-bit, while int and long remain 32-bit. A stated merit of LLP64 was that 32-bit software could often be recompiled with fewer immediate code revisions necessary for 64-bit exploitation compared to the changes required by the LP64 scheme on Unix platforms. This divergence necessitates careful consideration during cross-platform development.

Achieving Platform Neutrality with Fixed-Width Types

To mitigate the risks associated with relying on the size of native types like int or long, utilizing standard C99 header features is the preferred strategy where specific bit widths are crucial. The <inttypes.h> header (or its C++ equivalent <cstdint>) provides platform-agnostic aliases.

These types ensure consistent sizing regardless of whether the compiler is targeting ILP64, LP64, or LLP64:

  • int8_t: Exactly 8-bit signed integer.
  • int16_t: Exactly 16-bit signed integer.
  • int32_t: Exactly 32-bit signed integer.
  • int64_t: Exactly 64-bit signed integer.
  • uint8_t, uint16_t, uint32_t, uint64_t: Unsigned equivalents.

Furthermore, types related to pointer sizing are available:

  • uintptr_t: An unsigned integer type capable of holding any value a pointer can hold.
  • intmax_t: The largest integer type available on the platform (may exceed 64 bits).

It is generally recommended to avoid direct use of intptr_t unless strictly necessary, such as calculating the difference between two uintptr_t values, in which case ptrdiff_t is the signed counterpart.

Practical Example: Checking Native Type Sizes

You can dynamically check the sizes implemented by your current compiler and architecture using simple C++ code, observing the output differences between systems configured with LP64 versus LLP64.

#include <iostream>
#include <cstdint>

void check_platform_sizes() {
    // Check standard native types (in bytes)
    std::cout << "Size of int: " << sizeof(int) << " bytes" << std::endl;
    std::cout << "Size of long: " << sizeof(long) << " bytes" << std::endl;
    std::cout << "Size of long long: " << sizeof(long long) << " bytes" << std::endl;
    std::cout << "Size of pointer: " << sizeof(void*) << " bytes" << std::endl;
    
    // Check fixed-width types (guaranteed size)
    std::cout << "Size of int32_t: " << sizeof(int32_t) << " bytes" << std::endl;
    std::cout << "Size of int64_t: " << sizeof(int64_t) << " bytes" << std::endl;
}

int main() {
    check_platform_sizes();
    return 0;
}

// Example Output on Linux (LP64):
// Size of int: 4 bytes (32 bit)
// Size of long: 8 bytes (64 bit)
// Size of long long: 8 bytes (64 bit)
// Size of pointer: 8 bytes (64 bit)

// Example Output on Windows (LLP64):
// Size of int: 4 bytes (32 bit)
// Size of long: 4 bytes (32 bit)
// Size of long long: 8 bytes (64 bit)
// Size of pointer: 8 bytes (64 bit)

FAQs on Divergent 64bit Integer Sizes Across Platforms

Q: What does ILP64 mean in the context of 64-bit systems

ANS: ILP64 stands for ‘int, long, pointers are 64-bit’. It was a scheme used minimally, notably by Cray systems, where the integer type, long type, and pointer size were all 64 bits.

Q: Which integer sizing scheme do modern Linux and MacOS use

ANS: Modern 64-bit Unix-like systems, such as Linux and macOS, predominantly adhere to the LP64 scheme, where the ’long’ type and pointers are 64 bits wide, but ‘int’ remains 32 bits.

Q: What is the primary distinction of Microsoft's LLP64 scheme

ANS: LLP64 means ’long long, pointers are 64-bit’. This scheme keeps both ‘int’ and ’long’ at 32 bits, differentiating it from the LP64 model used widely elsewhere.

Q: How can I write C code that avoids platform integer size issues

ANS: Employ platform-neutral integer types defined in <inttypes.h> (or <cstdint> in C++) such as int32_t, int64_t, and uintptr_t for defining variables where a specific size is required.
