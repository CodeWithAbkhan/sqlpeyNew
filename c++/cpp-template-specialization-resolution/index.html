“C++ Template Specialization Resolution with Default Arguments and SFINAE”

How does the C++ compiler determine which template specialization to select when an instantiation omits template arguments that have default values, particularly when dealing with void_t for SFINAE checks? This process involves template argument deduction, matching, and substitution failure rules.

Deconstructing Template Instantiation and Specialization Matching

Consider the pattern for checking the presence of a member, exemplified by a has_member trait:

Scenario 1: Primary Template with Default Argument

When the compiler encounters an instantiation like has_member<A>, and the primary template is defined as:

template< class T, class = void >
struct has_member; // Primary template definition

The template argument list <A> is presented. Since only one argument is supplied, the second parameter defaults to void. The effective instantiation becomes has_member<A, void>.

Scenario 2: Applying Partial Specialization

Next, the compiler inspects defined partial specializations. A specialization designed to detect a member named member might look like this:

template< class T >
struct has_member< T, void_t< decltype( T::member ) > > : true_type
{ };

The compiler attempts template argument deduction by matching the supplied arguments (A, void) against the patterns in the partial specialization.

  1. Deduction for T: The first pattern T successfully deduces T as A.
  2. Pattern Matching with decltype: The second pattern involves void_t< decltype( T::member ) >. Here, template argument deduction halts concerning the template parameters of the specialization itself. The expression inside decltype is explicitly excluded from deduction.

The deduced arguments are then substituted back into the specialization signature:

template<>
struct has_member< A, void_t< decltype( A::member ) > > : true_type
{ };

If A::member is valid (well-formed expression), decltype( A::member ) resolves, void_t constructs a type, and substitution succeeds without failure. If substitution yields a type matching the supplied argument (which is void in this case, due to the deduction result), this specialization is chosen. If substitution fails (SFINAE), this specialization is discarded, and the primary template (defined with a default argument of void) is selected as a fallback.

Contrast: Mismatched Default Argument

If the primary template used int as the default argument instead of void:

template< class T, class = int > // <-- int default
struct has_member : false_type { };

template< class T >
struct has_member< T, void_t< decltype( T::member ) > > : true_type
{ };

If A possesses member, the substitution process still generates a specialization equivalent to has_member<A, void>. However, the instantiation request was for has_member<A>, which resolves to has_member<A, int>. Since <A, void> (specialization signature) does not match <A, int> (instantiation arguments), the specialization is bypassed, and the primary template (false_type) is chosen.

Practical Demonstration with Type Traits

We can illustrate specialization selection using a trait to check for a nested type member, perhaps named type.

We define test structures:

struct TypeA {
    using type = int;
};

struct TypeB {
    using type = void;
};

We test three types against a trait has_type_member<T, DefaultArg>: float (no type), TypeA, and TypeB.

Implementation Option A: Default Argument Unrelated to Specialization

This setup uses int as the default, and a specialization that resolves to void when successful.

#include <type_traits>

// Primary template handles types that have no nested ::type member or failure case
template< class T, class = int >
struct has_type_member : std::false_type { };

// Specialization recognizes types that do have a nested ::type member
template< class T >
struct has_type_member<T, std::void_t<typename T::type>> : std::true_type { };

Testing with has_type_member<Type>::value:

  • has_type_member<float> becomes has_type_member<float, int>. The specialization requires void_t<float::type>, which fails substitution (float::type doesn’t exist). Primary template wins: false.
  • has_type_member<TypeA> becomes has_type_member<TypeA, int>. Specialization substitution yields has_type_member<TypeA, void>. Arguments mismatch (int vs void). Primary template wins: false.
  • has_type_member<TypeB> becomes has_type_member<TypeB, int>. Specialization substitution yields has_type_member<TypeB, void>. Arguments mismatch (int vs void). Primary template wins: false.

Implementation Option B: Explicitly Matching the Default

If the specialization explicitly matches the default argument when successful, it is chosen:

#include <type_traits>

// Primary template handles types that have no nested ::type member
template< class T, class = void >
struct has_type_member : std::false_type { };

// Specialization matches the default argument (void) when type member exists
template< class T>
struct has_type_member<T, void> : std::true_type { };

Testing with has_type_member<Type>::value:

  • has_type_member<float> becomes has_type_member<float, void>. The specialization has_type_member<T, void> matches directly: true (Incorrect for this use case, as it doesn’t check for type).

Implementation Option C: The Standard Approach (Detecting a Member via Alias)

To use SFINAE correctly to detect T::type, the specialization must use void_t on the attempt to access the member, and the primary template must provide the mechanism for the one-argument call:

#include <type_traits>

// Primary template handles all cases by defaulting to false_type
template< class T, class = void >
struct has_type_member : std::false_type { };

// Specialization uses void_t to ensure substitution succeeds only if T::type exists.
// The second argument of the specialization *must* be deduced or explicitly specified.
template< class T >
struct has_type_member<T, std::void_t<typename T::type>> : std::true_type { };

Testing with has_type_member<Type>::value:

  • has_type_member<float> becomes has_type_member<float, void>. Specialization attempt: std::void_t<float::type> fails. Specialization discarded. Primary template wins: false.
  • has_type_member<TypeA> becomes has_type_member<TypeA, void>. Specialization attempt: std::void_t<TypeA::type> resolves to std::void_t<int> which is void. Match found: has_type_member<TypeA, void>. Specialization wins: true.
  • has_type_member<TypeB> becomes has_type_member<TypeB, void>. Specialization attempt: std::void_t<TypeB::type> resolves to std::void_t<void> which is void. Match found: has_type_member<TypeB, void>. Specialization wins: true.

This final approach demonstrates how the combination of the default argument (void) and the SFINAE expression inside void_t dictates which specialization is selected based on the validity of the internal expression.

Alternative: Detecting Member Existence Directly (Not Type Alias)

If we return to the original context of detecting a non-type member named member, the principle is identical:

template< class, class = void >
struct has_member_property;

template< class T >
struct has_member_property< T, std::void_t< decltype( T::member ) > > : std::true_type
{ };

When invoking has_member_property<SomeClass>, the compiler checks if SomeClass::member is accessible and valid within decltype. If it is, the specialization resolves, inheriting true_type. Otherwise, the primary template is used, inheriting false_type (assuming the primary template defaults to false_type).

For more details on template argument deduction rules, refer to the C++ standard references on [temp.class.spec.match] or explore guides on advanced C++ metaprogramming techniques.

FAQs on Cpp Template Specialization Resolution With Default Arguments And Sfinae

Q: Why does substituting T in void_t(decltype(T::member)) prevent deduction

ANS: Template argument deduction for partial specializations is distinct from substitution. The pattern inside decltype prevents the compiler from deducing the template parameter T from that specific slot, as the standard excludes expressions within decltype from being used to deduce template arguments in that context. Deduction happens first based on pattern matching, and then substitution occurs to check for validity.

Q: What happens if the deduced specialization results in a type mismatch with the primary template's default argument

ANS: If the instantiation provides one argument, say MyTrait<Arg1>, it resolves to MyTrait<Arg1, DefaultArgA>. If the specialization resolves to MyTrait<Arg1, ResolvedArgB>, and ResolvedArgB is not equal to DefaultArgA, the specialization is not selected, and the compiler falls back to the primary template definition.

Q: Is void_t necessary when using SFINAE to check for a member

ANS: void_t (or std::enable_if_t) is crucial. It ensures that if the expression inside it (decltype(T::member)) is invalid, the substitution fails silently (SFINAE), allowing the compiler to discard that specialization and potentially check the next available candidate, typically the primary template which returns false_type.
