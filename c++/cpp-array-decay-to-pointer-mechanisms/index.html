“C++ Array Decay to Pointer in Function Calls: Mechanisms and Alternatives”

In C++ when dealing with function parameters that seem to represent arrays, we often encounter the confusing equivalence between declarations like int arg[], int[X], and int*. If you pass an array of a specific size, say int firstarray[3], to a function expecting int arg[] or int* arg, why does it work, and what exactly is happening to the type information?

What are the fundamental rules governing the behavior of array types when they are used as arguments to functions in C++?

The Core Mechanism: Array-to-Pointer Decay

The primary reason these syntaxes become identical within a function parameter list involves two closely related mechanisms: parameter type adjustment and argument conversion.

1. Parameter Declaration Adjustment (The Signature Change)

When defining a function, the C++ standard dictates how array types specified in parameter declarations are treated:

  • A parameter of type “array of T” (e.g., int arg[] or int arg[10]) is adjusted to be “pointer to T” (i.e., int* arg). This adjustment happens before the function is called or compiled for that signature.

This rule directly explains why:

void process_array(int arg[]); // Adjusts to int* arg
void process_array_sized(int arg[100]); // Also adjusts to int* arg
void process_array_pointer(int* arg); // Already a pointer

All three declarations result in the function receiving an int*. The size information (X) specified in the parameter declaration is discarded during this adjustment.

2. Argument Conversion (The Call Site Behavior)

When an actual array object is passed to a function, a standard conversion takes place on the argument itself:

  • An expression representing an array of known or unknown size (like firstarray) is converted to a pointer to its first element. This conversion yields a prvalue (a temporary pointer) of type “pointer to T.”

Therefore, if you have an array declared as int firstarray[3];, passing it to a function expecting a pointer looks like this:

int firstarray[3];
// When calling:
process_array(firstarray); 
// 'firstarray' (type 'int[3]') decays to a pointer to the first element (type 'int*').

Crucially, this decay to a pointer is why the original size information (3 or 5 in examples) is lost. The function only receives a memory address (int*), making it mandatory to pass the array length separately if you intend to iterate over the entire original structure.

Pointer Arithmetic and Subscript Notation

This relationship is further cemented by how pointer and array indexing operates in C and C++:

For any pointer arg and index n:

  • Pointer dereference with addition: *(arg + n)
  • Array subscript syntax: arg[n]

These two expressions yield the same result—an lvalue referring to the element at offset n from the starting address pointed to by arg. Consequently, arg[0] is synonymous with *arg, reinforcing the idea that an array parameter is treated as a pointer to its initial element.

Alternative Viewpoints and Considerations

While the above explains the standard conversion, other perspectives illuminate the topic:

  • C vs. C++: This behavior is not exclusive to C++; C handles array names passed to functions identically.
  • Reference Semantics Misconception: The idea that arrays are “ALWAYS passed by reference” when using int arg[] is misleading. If you explicitly want pass-by-reference semantics that preserve array type information, you must use references, such as void printarray(int (&arg)[N]), though this is less common for simple iteration.

Modern C++ Solution: Preserving Size Information with std::span (C++20)

To combat the inherent problem of losing array size information during decay, C++20 introduced std::span. A std::span provides a non-owning view over a contiguous sequence of objects, carrying both the pointer to the beginning and the size of the sequence.

This offers a far more flexible and type-safe way to handle array-like data from C-style arrays, std::vector, or std::array.

Here is a demonstration of how std::span improves code clarity and safety:

#include <iostream>
#include <vector>
#include <span>
#include <array>

// Function accepting std::span<const int> works with various contiguous containers
void safe_print_data(std::span<const int> data_view)
{
    std::cout << "Data elements (" << data_view.size() << "): ";
    for (const auto& element : data_view) {
        std::cout << element << ", ";
    }
    std::cout << '\n';
}

void demonstrate_span_flexibility()
{
    // 1. C-Style Array
    int c_style_arr[] { 10, 20, 30, 40 };
    safe_print_data(c_style_arr); // Decays safely to span

    // 2. std::vector
    std::vector<int> my_vector { 100, 200, 300 };
    safe_print_data(my_vector); // Works directly with vector

    // 3. std::array
    std::array<int, 2> my_std_array { 5, 6 };
    safe_print_data(my_std_array); // Works directly with std::array

    // 4. Sub-range View (Passing only a portion)
    int large_arr[] { 1, 2, 3, 4, 5, 6, 7 };
    // Create a span over elements from index 2, spanning 3 elements long
    safe_print_data(std::span(large_arr + 2, 3)); // Prints 3, 4, 5
}

// int main() { demonstrate_span_flexibility(); return 0; }

The use of std::span avoids the implicit conversion pitfalls and allows the function to know the exact bounds of the data it is operating on, vastly improving robustness compared to relying solely on decayed pointers. FAQs on C++ Function Parameter Equivalence

Q: Are int[] and int* truly identical in all C++ contexts

ANS: No. In function parameter lists, int arg[] adjusts to int* arg. Outside of parameters, int[X] is a distinct array type, while int* is a pointer type. The equivalence is specific to how array arguments are passed to functions (array decay).

Q: If an array decays, how do I know its original size

ANS: If the array decays to a pointer (int*), the compiler loses the size information. You must explicitly pass the size as a separate argument (e.g., void func(int* arr, size_t size)). Modern C++ prefers std::span which carries the size automatically.

Q: Does array indexing like arr[n] really mean *(arr + n)

ANS: Yes, according to the C++ standard, the subscript operator [] is defined to be equivalent to pointer arithmetic followed by dereferencing: arr[n] is exactly the same as *(arr + n).

Q: Can I use std::span in older C++ versions before C++20

ANS: std::span was standardized in C++20. For pre-C++20 solutions requiring size safety, developers often use techniques involving templates or wrapper structures to pass both the pointer and the size together, or rely on standard library containers like std::vector or std::array which manage size internally.
