“C++ Generating Uniform Random Integers in a Range: Methods Compared”

How does one reliably generate a pseudo-random integer that falls uniformly within a specified inclusive range, say [min, max], in modern or legacy C++? The core challenge is avoiding the statistical bias introduced by simple modulo operations (%) on the output of basic random functions like rand().

Several approaches exist, ranging from the antiquated yet simple to the statistically robust and contemporary.

Modern C++ Approach: Leveraging the <random> Header (C++11 and newer)

For high-quality, verifiable randomness, the C++ standard library’s <random> facilities are strongly recommended. This separation of the engine (the source of randomness, e.g., std::mt19937) and the distribution (which shapes the output, e.g., std::uniform_int_distribution) provides superior control and statistical correctness.

Solution 1: Direct Use of <random> for Unbiased Results

This is often the preferred, simplest, and statistically best C++11/14/17 method for generating an unbiased random integer:

#include <random>

// Assume min and max are defined integers
const int min_val = 10;
const int max_val = 50;

std::random_device rd;     // Provides a non-deterministic seed source
std::mt19937 rng(rd());    // The Mersenne-Twister engine, seeded once
std::uniform_int_distribution<int> uni(min_val, max_val); // Guaranteed unbiased distribution

auto random_integer = uni(rng); // Generate the value

Solution 3: Performance Testing with <random> and <chrono>

When performance is critical, one can benchmark the modern standard library generators. This example demonstrates generating ten million random numbers within [-57, 365] and measuring throughput using std::chrono.

#include <iostream>
#include <random>
#include <chrono>

int main()
{
    typedef std::chrono::high_resolution_clock Clock;
    typedef std::chrono::duration<double> sec;
    Clock::time_point t0 = Clock::now();

    const int N = 10000000;
    // Selecting a high-quality engine
    typedef std::minstd_rand G; 
    G g; // Construct the engine (can be seeded with g(seed))
    
    // Selecting the distribution for the desired range
    typedef std::uniform_int_distribution<> D; 
    D d(-57, 365);                             

    int count_sum = 0;
    for (int i = 0; i < N; ++i)
        count_sum += d(g); // Generate a random number

    Clock::time_point t1 = Clock::now();
    std::cout << N/sec(t1-t0).count() << " random numbers per second.\n";
    
    // Example of swapping generators or types:
    // typedef std::mt19937 G; // Swap to Mersenne Twister
    // typedef std::uniform_int_distribution<long long> D; // Change distribution type

    return count_sum;
}

This setup allows easy swapping of the engine (e.g., from minstd_rand to mt19937) or the distribution type (e.g., to long long) for different needs.

Solution 10: Creating a Reusable Class Wrapper

Encapsulating the C++11 random setup into a class provides a clean interface, especially useful if the distribution parameters need to change during runtime.

#include <random>

// Returns random integer in closed range [low, high].
class UniformRandomIntGenerator {
    std::random_device _rd{};
    std::mt19937 _gen{_rd()};
    std::uniform_int_distribution<int> _dist;

public:
    UniformRandomIntGenerator(int low = 1, int high = 10) {
        set(low, high);
    }

    // Adjust the distribution parameters [low, high] inclusively.
    void set(int low, int high) {
        std::uniform_int_distribution<int>::param_type param(low, high);
        _dist.param(param);
    }

    // Fetch the next random integer.
    int get() {
        return _dist(_gen);
    }
};

Legacy Approaches Using rand()

While discouraged for serious applications due to potential bias, these methods using std::rand() and RAND_MAX are frequently seen.

Solution 2: Simple Modulo (Biased)

This is fast but potentially non-uniform, particularly when the range size (max - min + 1) does not divide RAND_MAX + 1 evenly.

$$ \text{output} = \text{min} + (\text{rand}() \pmod{\text{max} - \text{min} + 1}) $$

// Fast but biased implementation
int random_biased = min + (std::rand() % static_cast<int>(max - min + 1));

Solution 6: Scaling rand() Output with Floating Point

This attempts to distribute the result using floating-point math before casting back to an integer. It’s generally better than pure modulo if RAND_MAX is small (e.g., 32767), but introduces potential precision issues and still relies on the underlying quality of rand().

$$ \text{result} = \text{min} + \lfloor \frac{\text{rand}()}{\text{RAND_MAX} + 1} \times (\text{max} - \text{min} + 1) \rfloor $$

int RandU(int nMin, int nMax)
{
    return nMin + (int)((double)std::rand() / (RAND_MAX + 1.0) * (nMax - nMin + 1.0));
}

Alternative Techniques for Bias Removal (Rejection Sampling)

Rejection sampling is a technique that ensures perfect uniformity when using functions like rand() that may produce bias due to the modulo operation.

Solution 4 & 12: Rejection Sampling (Optimized)

The principle is simple: generate a number, and if it falls into the portion of the output space that causes bias, discard it and try again. Solution 12 provides an optimized version by utilizing powers of two to minimize the rejection rate, especially for smaller intervals.

If the interval length is $L = \text{max} - \text{min} + 1$, find the smallest power of two $P \ge L$. Generate numbers modulo $P$. If the result is less than $L$, accept it; otherwise, reject and re-sample.

#include <cmath> // Required for log2 and ceil

int randInInterval(int min_r, int max_r) {
    int intervalLen = max_r - min_r + 1;
    
    // Calculate the smallest power of 2 greater than or equal to intervalLen
    int ceilingPowerOf2 = static_cast<int>(std::pow(2, std::ceil(std::log2(intervalLen))));

    int randomNumber;
    do {
        // Generate in the power-of-2 range, which is "as uniform as rand()" 
        randomNumber = std::rand() % ceilingPowerOf2; 
    } while (randomNumber >= intervalLen); // Rejection step

    return min_r + randomNumber; // Accept and shift
}

While statistically sound for correcting rand() bias, this iterative process can be slower than the single-pass <random> approach.

Solution 8: Unbiased rand() via Range Adjustment

This older, clever technique modifies the acceptance condition to remove the bias introduced when $\text{RAND_MAX} + 1$ is not a multiple of the desired range size.

int low = 100;
int high = 200;

int range_size = high + 1 - low;
unsigned int bias_threshold = (static_cast<unsigned int>(RAND_MAX) + 1) % range_size;

int r;
do {
  r = std::rand();
} while (r < bias_threshold);

return r % range_size + low;

Solution 5 & 9: Utilizing Boost.Random

Before C++11 standardized <random>, libraries like Boost were the standard for high-quality generation. The Boost Mersenne Twister implementation is highly regarded and offers similar separation of concerns to the modern standard library.

#include <boost/random/mersenne_twister.hpp>
#include <boost/random/uniform_int.hpp>
#include <boost/random/variate_generator.hpp>

boost::mt19937 generator_instance; // Seeded implicitly or explicitly

int roll_die() {
    boost::uniform_int<> dist(1, 6); // Range [1, 6]
    boost::variate_generator<boost::mt19937&, boost::uniform_int<> > die(generator_instance, dist);
    return die();
}

Solution 11: Maximizing Entropy from rand()

This less common method attempts to extract multiple pseudo-random numbers from a single rand() call by treating the rand() output as a large number in base $b = (\text{max}-\text{min}+1)$ and extracting its digits. This is complex and usually unnecessary given modern alternatives.

output = min + (rand() % static_cast&lt;int&gt;(max - min + 1))

FAQs on C++ Uniform Random Integers

Q: Why is rand() % N biased

ANS: The modulo operator % introduces bias when the range size $N$ does not evenly divide the total possible outcomes of rand(), which is $RAND_MAX + 1$. Numbers corresponding to the remainder of $(\text{RAND_MAX} + 1) / N$ get picked slightly more often.

Q: Is C++11 <random> faster than rand

ANS: While rand() is often optimized heavily by compilers, the <random> library generators (like mt19937) are designed for superior statistical quality and are often competitive or faster in high-volume scenarios, as demonstrated by performance tests.

Q: How to seed the mt19937 engine

ANS: You can seed it using std::random_device for non-deterministic seeding (e.g., std::mt19937 rng(std::random_device{}());) or use a fixed integer for reproducible sequences.
