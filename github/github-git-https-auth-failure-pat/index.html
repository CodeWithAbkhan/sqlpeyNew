“GitHub Git HTTPS Authentication Failure: Solved with Personal Access Tokens”

Encountering authentication failures when pushing or pulling to GitHub via HTTPS? Since August 13, 2021, GitHub has deprecated password authentication for Git operations, requiring the use of Personal Access Tokens (PATs) instead. This shift enhances security by allowing tokens with specific scopes, limiting potential damage if compromised, unlike passwords.

This post details how to generate and utilize PATs across various operating systems and development environments to resolve these authentication issues.

Why the Change?

GitHub moved away from password authentication for Git operations over HTTPS to bolster security. Passwords, if leaked, grant broad access. PATs, however, can be scoped with limited permissions, minimizing the impact of a compromised token. This ensures that even if a token is exposed, the damage is contained. For more on GitHub’s security practices, explore their official documentation on PATs .

Generating Your GitHub Personal Access Token (PAT)

The first step is to create a PAT from your GitHub account.

  1. Navigate to Settings: From your GitHub profile, go to Settings.
  2. Developer Settings: In the left-hand menu, scroll down and select Developer settings.
  3. Personal Access Tokens: Choose Personal access tokens from the submenu.
  4. Generate New Token: Click on Tokens (classic) and then Generate new token.
  5. Token Configuration:
    • Note: Give your token a descriptive name (e.g., “Git HTTPS Access”).
    • Expiration: Set an expiration date for your token. It’s a good security practice to set an expiration.
    • Scopes: Select the necessary permissions for your token. For general Git operations, repo scope (which includes public_repo) is usually sufficient.
  6. Create Token: Click Generate token.
  7. Copy Your Token: Crucially, copy the generated token immediately. You will only see it once, and it cannot be retrieved later. Store it securely. It will look similar to ghp_sFhFsSHhTzMDreGRLjmks4Tzuzgthdvfsrta.

Implementing Your PAT Across Different Platforms

Once you have your PAT, you’ll need to use it to authenticate your Git operations. The method varies slightly depending on your operating system and how Git is configured to manage credentials.

For Windows OS

Windows uses the Credential Manager to store credentials.

  • If git:https://github.com exists:

    1. Open Control Panel.
    2. Navigate to User Accounts > Credential Manager.
    3. Select Windows Credentials.
    4. Locate the entry for git:https://github.com.
    5. Click Edit.
    6. In the Password field, replace your old password with your newly generated GitHub PAT.
    7. Click Save.

  • If git:https://github.com does not exist:

    1. In Credential Manager > Windows Credentials, click Add a generic credential.
    2. For Internet address, enter git:https://github.com.
    3. For User name, enter your GitHub username.
    4. For Password, paste your GitHub PAT.
    5. Click OK.
For macOS

macOS utilizes Keychain Access to manage credentials.

  1. Open Spotlight Search (magnifying glass icon) by pressing Cmd + Space.
  2. Type Keychain Access and press Enter.
  3. In Keychain Access, search for github.com.
  4. Identify the entry with the Kind as “Internet password”.
  5. Double-click the entry.
  6. Click Show password. You might need to enter your Mac’s login password.
  7. Replace the existing password with your GitHub PAT.
  8. Click Save Changes.
For Linux-based OS

Linux requires initial Git configuration and then credential management.

  1. Configure Git User: Ensure your Git client is configured with your username and email.

    git config --global user.name "your_github_username"
git config --global user.email "your_github_email"

    You can verify this with git config -l.

  2. Caching Credentials: To avoid entering your PAT every time, you can cache it.

    git config --global credential.helper cache

    This command caches your credentials for a period. For persistent caching, you might use store (though be mindful of security implications as it stores the token in plaintext).

  3. Unsetting Credentials (if needed): If you need to clear cached credentials:

    git config --global --unset credential.helper
# Or for system-wide settings (less common for user Git ops):
# git config --system --unset credential.helper

Alternative Methods for Using PATs

Beyond updating system credential managers, several direct methods can be employed:

  • Modifying Remote URL: You can directly update the remote URL of your repository to include your PAT. This is a quick solution but requires updating per repository.

    git remote set-url origin https://<YOUR_GITHUB_TOKEN>@github.com/<username>/<repositoryname>.git

    When cloning a repository for the first time, you can embed the token:

    git clone https://<YOUR_USERNAME>:<YOUR_GITHUB_TOKEN>@github.com/<username>/<repositoryname>.git

  • Using GitHub CLI (gh): The GitHub CLI offers a streamlined authentication process.

    1. Install GitHub CLI: If you don’t have it, install it using your package manager (e.g., brew install gh on macOS, winget install gh on Windows).
    2. Authenticate: Run gh auth login in your terminal and follow the prompts. Choose HTTPS and paste your PAT when requested.

Handling Specific IDEs and Tools

  • JetBrains IDEs (IntelliJ, PyCharm, etc.):

    1. Open Settings/Preferences (Cmd + , or Ctrl + Alt + 0).
    2. Navigate to Version Control > GitHub.
    3. Click Add and select Log In with Token.
    4. Paste your PAT into the provided field and click Add Account.

  • Sourcetree: For existing repositories, update the remote URL within Sourcetree’s repository settings to include your PAT: https://<YOUR_GITHUB_TOKEN>@github.com/username/repo.git

  • Android Studio: If you encounter issues with newer versions like Arctic Fox:

    1. Generate a new PAT.
    2. Remove your GitHub account from Android Studio’s settings.
    3. Add your GitHub account again, using the PAT as the password.
    4. If the issue persists, try updating the remote URL for your project from the command line: 
      cd <project-directory>
git remote set-url origin https://<TOKEN>@github.com/<user_name>/<repo_name>.git
      Then, attempt the push from Android Studio again.

Important Considerations

  • Token Security: Treat your PAT like a password. Do not share it or commit it to your code repositories.
  • Token Expiration: Regularly review and renew your PATs, especially if they have a short expiration. GitHub automatically removes unused tokens after a year.
  • SSH vs. HTTPS: For frequent operations or automated scripts, consider setting up SSH keys for authentication, which often provides a more seamless experience without needing to manage tokens as frequently. You can configure Git to use SSH by default: 
    git config --global url."git@github.com:".insteadOf "https://github.com/"

Example Code Snippets

Here are some common commands you might use:

# Clone a repository using a PAT
git clone https://<YOUR_USERNAME>:<YOUR_GITHUB_TOKEN>@github.com/<username>/<repositoryname>.git

# Update an existing remote's URL with a PAT
git remote set-url origin https://<YOUR_GITHUB_TOKEN>@github.com/<username>/<repositoryname>.git

# Git pull, prompting for username and PAT as password
git pull

# Git push, using cached credentials or prompting
git push

# Configure Git to use the cache helper
git config --global credential.helper cache

# Unset the credential helper
git config --global --unset credential.helper

FAQs on GitHub Git HTTPS Authentication Failure

Q: Why am I getting a GitHub authentication error for Git operations

ANS: Since August 13, 2021, GitHub no longer accepts passwords for Git operations over HTTPS. You must use a Personal Access Token (PAT) instead.

Q: How do I generate a Personal Access Token on GitHub

ANS: Navigate to your GitHub Settings > Developer settings > Personal access tokens. Click Generate new token, provide a note, set an expiration, select scopes (e.g., repo), and then copy the generated token.

Q: Where do I store my GitHub Personal Access Token on Windows

ANS: On Windows, you can store your PAT in the Credential Manager under Windows Credentials. Find git:https://github.com and edit its password with your PAT.

Q: How can I manage my GitHub PAT on macOS

ANS: Use Keychain Access on macOS. Search for github.com, find the internet password entry, click Show password, and replace the password with your PAT.

Q: What if I don't have a github.com entry in my macOS Keychain

ANS: Perform a Git operation (like git pull). When prompted for credentials, use your GitHub username and your PAT as the password. This action should create the necessary entry in your Keychain Access.

Q: Can I directly include my PAT in the Git URL

ANS: Yes, you can update your Git remote URL or use it during cloning like this: git clone https://<YOUR_USERNAME>:<YOUR_GITHUB_TOKEN>@github.com/<username>/<repositoryname>.git. However, be cautious about where this URL is stored.

Q: Is it safe to store my PAT in a file for Linux

ANS: Using git config --global credential.helper store will save your PAT in plaintext in the ~/.git-credentials file. While convenient, it’s less secure than using OS-integrated credential managers or SSH keys.

Q: How does the GitHub CLI simplify authentication

ANS: The GitHub CLI (gh) allows you to authenticate by running gh auth login. It guides you through the process, including pasting your PAT, and handles the configuration for Git operations.

Q: What happens if my Personal Access Token expires

ANS: If your PAT expires, you will encounter authentication errors again. You will need to generate a new token and update your stored credentials or Git configuration with the new token.

Q: How can I use SSH instead of HTTPS for GitHub authentication

ANS: You can configure Git to prefer SSH by running git config --global url."git@github.com:".insteadOf "https://github.com/" after setting up SSH keys with your GitHub account.
