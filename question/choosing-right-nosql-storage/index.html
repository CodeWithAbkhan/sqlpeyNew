Choosing the Right NoSQL Storage Which NoSQL storage to choose?
When it comes to NoSQL implementations, there are a lot of options available. According to the Wikipedia NoSQL Q&A Session, document-oriented and key-value storages are the most popular choices.

What’s the difference between document-oriented and key-value storages?

At one level, document and key/value are quite similar - both will return an object when you request a key. In pure key/value that object will be a simple string, although it can be a serialized complex object. A document database extends this with functions to work with this object such as partial update functionality or search indexing.

How do I know which NoSQL storage to choose?

The best way to choose a NoSQL storage is to determine your specific requirements. NoSQL covers many different systems, and unlike SQL databases, they all have quite different advantages/disadvantages for a specific scenario. The major differences between some popular NoSQL systems are illustrated in a blog post, “Visual Guide to NoSQL Systems.” The biggest difference between these systems is which of the following two they choose to optimize for: consistency, availability, and partition tolerance.

What is the ACID requirement in NoSQL?

The ACID requirement in NoSQL stands for Atomicity, Consistency, Isolation, and Durability. It is necessary to ensure that the data stored in the database is accurate, consistent, and secure. While traditional SQL databases are designed with ACID compliance in mind, NoSQL databases have various implementations to meet the same requirement.

Regarding consistency in NoSQL databases

One of the challenges in NoSQL databases is achieving consistency. In my opinion, Cassandra can be fully consistent if you make your data model ACID compliant. Instead of using a database transaction, you can do a transaction like banks do it, where the transaction is not a multi-data change but an actual data object. A bank account does not have money in it but has transactions, and your account’s current state is calculated from the transactions. Such transactions are not a database feature but are a part of the data model. They do not need to be instantly available to all nodes to be consistent because they are immutable.

How can a database operation or transaction become consistent in NoSQL databases?

To achieve consistency in NoSQL databases, you can make data immutable, and transactions can become part of the data model as immutable data (write once, read many). This ensures that the ACID requirements are met. An atomic transaction needs to be a unique immutable object/row to become atomic without any complex database object to support it.

Alternative ways to achieve consistency in NoSQL databases

Other ways to achieve consistency in NoSQL databases are:

  • Using a distributed transaction coordinator
  • Using versioned updates to simulate atomicity
  • Using timestamps to resolve conflicts

Use of Distributed transaction coordinator

A distributed transaction coordinator is a middleware layer that coordinates transactions between multiple databases. This can be used to ensure that multiple NoSQL databases are consistent with each other.

Use of versioned updates to simulate atomicity

Versioned updates are used to simulate atomicity by creating a new version of the entire document every time an update is made to the database. This ensures that every update is treated as a new transaction, and older versions can be discarded when no longer needed.

Using timestamps to resolve conflicts

Timestamps can be used to resolve conflicts by assigning each write operation a unique timestamp. When multiple writes occur concurrently, the timestamp can be used to determine the order of the writes and resolve conflicts, ensuring consistency.

Summary

Choosing the right NoSQL database depends on your specific requirements. Document-oriented and key-value databases are the most popular choices. Consistency, atomicity, and security are critical features and can be achieved in different ways, including making data immutable, using distributed transaction coordinators, versioned updates, and timestamps to resolve conflicts.

Overall, NoSQL databases are flexible and offer robust solutions for handling large volumes of data in various formats. Considering all the options and choosing the right NoSQL database is essential for data consistency, security, and scalability. ]]>
