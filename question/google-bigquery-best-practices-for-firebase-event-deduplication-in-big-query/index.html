Firebase events dedup in Big Query - Best practices?
When exporting Firebase analytics events to Big Query, it is common to encounter duplicates of 1-2%. It is essential to develop best practices to remove these duplicates efficiently. This post will address the best practices for removing these duplicates and analyze the use of event_bundle_sequence_id and alternative ways for deduplication.

Best Practices for removing duplicates

It is recommended to identify each event uniquely. The client does not provide a counter with the events (per session). Hence, it becomes challenging to remove duplicate events. Therefore, it is necessary to consider the following fields in removing the duplicates:

  • Event name: One of the most important fields for recognizing an event, and it should always be included in a deduplication process.
  • Event timestamp: It assigns a time when an event occurred, making it a crucial field for recognizing duplicates.
  • User’s pseudo ID: It is used to track a user’s activity and to assign unique IDs; thus, it is a handy field to deduplicate events.

With these fields in mind, one can now quickly evaluate which event records are duplicated and easily extract them. We recommend using Standard SQL to look for duplicates in one day’s events by executing the following code:

with n_dups as
(
SELECT event_name, event_timestamp, user_pseudo_id, count(1)-1 as n_duplicates
FROM `project.dataset.events_20190610`
group by event_name, event_timestamp, user_pseudo_id
)
select n_duplicates, count(1) as n_cases
from n_dups
group by n_duplicates
order by n_cases desc

By using the QUALIFY clause in Big Query, we can wholly remove the duplicates. The following syntax can be used to do this:

SELECT
  *
FROM
  `project.dataset.events_*`
QUALIFY
  ROW_NUMBER() OVER (
    PARTITION BY
      user_pseudo_id,
      event_name,
      event_timestamp,
      TO_TIMESTAMP(CONCAT(CAST(JSON_EXTRACT(event_params, '$.ga_session_id') AS STRING),'000'))) = 1

By using this code, we can remove duplicates with the event name, event timestamp, and userâ€™s pseudo ID as the identifier. The TO_TIMESTAMP() function extracts ga_session_id from the event parameters which is converted to a string and concatenated with ‘000’ to form a timestamp. We then use ROW_NUMBER and PARTITION_BY clauses to return only the first row with repeated event attributes.

Event Bundle Sequence Id â€“ field

The event_bundle_sequence_id attribute is used for grouping all events that are in the same bundle. By studying the data, we see that duplicates are sent in different bundles, meaning we cannot depend on the event_bundle_sequence_id attribute in deduplication. Instead, we recommend using the fields mentioned earlier to remove duplicates from the data.

Alternative ways for Deduplication

With any data cleaning, there are alternative techniques for deduplication. We can use hash functions to identify and remove duplicates based on unique features. It involves calculating hash values of the fields, preferably using the murmur3 hash function. The generated hash values can be used to identify duplicates, making the deduplication process much easier.

Recap

The QUALIFY clause in Big Query provides an efficient and effective way of removing duplicates in Firebase Analytics. Fields such as the event name, timestamp, and user’s pseudo ID should be utilized in identifying duplicates, while the event_bundle_sequence_id should not be relied on. More, alternative methods such as hash functions can be used for deduplication to make the process easier and faster. ]]>
