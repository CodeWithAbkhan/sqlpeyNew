Solved: How-to-Generate-UUID-in-PostgreSQL

Summary:
In PostgreSQL, UUID (Universally Unique Identifier) is often used for unique identifiers in databases. However, creating these identifiers varies between different PostgreSQL versions. This guide will cover multiple methods, including using extensions and functions like gen_random_uuid() and uuid_generate_v4() for generating UUIDs. You’ll also find practical examples, detailed code explanations, and alternatives for older versions of PostgreSQL.

What is a UUID and Why Should You Use It?

UUIDs are 128-bit values that provide a unique identifier that can be used in your database. Unlike traditional integer-based primary keys, UUIDs offer a larger address space and are useful in distributed systems where it’s important to prevent identifier collisions.

How Do You Generate a UUID in PostgreSQL?

For PostgreSQL 13+:

PostgreSQL 13 and newer versions have built-in support for generating UUIDs using the gen_random_uuid() function, which simplifies the process.

Example:

SELECT gen_random_uuid();

This function returns a version 4 UUID (randomly generated UUID). Version 4 UUIDs are appropriate for most use cases as they generate almost collision-proof unique identifiers.

For PostgreSQL 9.1 to 12:

If you’re using a PostgreSQL version between 9.1 and 12, you need to load the uuid-ossp extension first. This extension contains the uuid_generate_v4() function to generate UUIDs.

Step-by-step Process:

  1. Ensure that the uuid-ossp extension is available: 
    SELECT * FROM pg_available_extensions;
  2. Create the extension if it’s not already loaded: 
    CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
  3. Now you can use the uuid_generate_v4() function: 
    SELECT uuid_generate_v4();

Practical Example for Inserting UUID:

INSERT INTO items (id, name, price)
VALUES (uuid_generate_v4(), 'Item 1', 29.99);

For PostgreSQL 8.4 and Older:

In older PostgreSQL versions (like 8.4), the CREATE EXTENSION feature isn’t available. You need to manually run SQL scripts that install the uuid-ossp extension.

  1. Install the postgresql-contrib package: 
    sudo apt-get install postgresql-contrib
  2. Load the extension manually by running the SQL script: 
    psql -d your_database -f /path/to/uuid-ossp.sql
  3. Once loaded, you can use the uuid_generate_v4() function.

Alternative for PostgreSQL 8.4 Without Extensions:

If installing extensions is not an option, you can generate a pseudo-UUID using built-in PostgreSQL functions.

Example:

SELECT uuid_in(md5(random()::text || random()::text)::cstring);

This uses the md5() function to generate a 128-bit hash from random values. Although this doesn’t guarantee the format of a version 4 UUID, it can serve as a workaround in older versions.

What Are the Differences Between gen_random_uuid() and uuid_generate_v4()?

  • gen_random_uuid(): Available in PostgreSQL 13 and above, this function is part of the pgcrypto module and generates random (version 4) UUIDs.

  • uuid_generate_v4(): Provided by the uuid-ossp extension, this is also a version 4 UUID generator. However, you must install the extension manually for PostgreSQL versions prior to 13.

How to Set UUID as Default Value in PostgreSQL

If you want to automatically generate UUIDs when inserting new rows, set the UUID column’s default value to gen_random_uuid() or uuid_generate_v4().

Example Table Definition:

CREATE TABLE users (
    id UUID DEFAULT gen_random_uuid(),
    name VARCHAR(100),
    email VARCHAR(100),
    PRIMARY KEY (id)
);

With this setup, the id column will automatically populate with a new UUID every time a row is inserted.

Common Issues and Troubleshooting:

Error: function uuid_generate_v4() does not exist

This error usually means that the uuid-ossp extension hasn’t been installed.

Solution: Run:

CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

Error: could not open extension control file

You may encounter this if you haven’t installed the postgresql-contrib package.

Solution: Use your package manager to install the contrib package:

sudo apt-get install postgresql-contrib

What are Some Use-Cases for UUIDs in PostgreSQL?

  • Primary Keys: UUIDs are commonly used as primary keys in distributed databases where unique identification across different nodes is important.

  • Reference IDs: UUIDs are ideal for assigning unique IDs to items, orders, or users where the likelihood of collision must be minimized.

For more information on how UUIDs work in PostgreSQL, check the official PostgreSQL UUID documentation .
