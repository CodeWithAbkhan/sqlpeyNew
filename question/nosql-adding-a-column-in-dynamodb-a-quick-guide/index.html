NOSQL: Adding a Column in DynamoDB: A Quick Guide

How to Add a Column in DynamoDB: A Comprehensive Guide

Are you looking to add a new column to an existing table in DynamoDB? If so, you’ve come to the right place. In this guide, we’ll give you a step-by-step process on how to add a new column to your DynamoDB table.

What is DynamoDB?

DynamoDB is a fully managed NoSQL database service provided by Amazon Web Services (AWS). It supports both document and key-value store models and is designed to provide fast and predictable performance with seamless scalability.

Adding a New Column to a DynamoDB Table

Before we get into the process of adding a new column to a DynamoDB table, it’s important to know some key concepts.

Key Concepts in DynamoDB

DynamoDB does not require schema definition, and so there is no such thing as a “column”. You can just add a new item with a new attribute. DynamoDB has “primary partition keys” and “index partition keys”, just like relational databases. Although, unlike relational databases, DynamoDB does not have foreign keys. Therefore, you need to respect these keys when you add data, but aside from these requirements, you don’t have to predefine your fields (except for the partition keys mentioned earlier).

Good Practices in DynamoDB

Assuming that you are new to DynamoDB, here are some good practices to follow:

  • Add a numeric field to each record, to store the time of creation in seconds. DynamoDB has optional cleaning features, which require this type of field in your data.
  • You cannot use dates in DynamoDB, so you have to store those as numeric fields or as strings. Given the previously mentioned remark, you may prefer a numeric type for them.
  • Don’t store big documents in DynamoDB because there is a maximum fetch size of 16MB and a maximum record size of 400KB. Fortunately, AWS has S3 storage and other kinds of databases, such as DocumentDB.

Table Key Strategies in DynamoDB

There are many strategies for table keys in DynamoDB:

  • If you only declare the partition-key, then it acts like a primary key (e.g. partition-key=invoiceId). That’s fine.
  • If your object has a parent reference (e.g. invoices have a customer), then you probably want to add a sort-key. (e.g. partition-key=customerId;sort-key=invoiceId) Together they behave like a composed key. The advantage is that you can do a lookup using both keys

UpdateTable Query in DynamoDB

Now that we have a better knowing of DynamoDB and its key concepts, let’s look at how we can add a new column to a DynamoDB table using the UpdateTable query in DynamoDB.

The UpdateTable query in DynamoDB doesn’t have any information related to adding a new column. Although, you can add a new item with a new attribute to your DynamoDB table. Each item is a collection of attributes, and you can add a new attribute to an item using the PutItem operation.

Example Code

Here is an example of how you can add a new attribute to an existing item in your DynamoDB table:

var params = {
    TableName: 'my-table',
    Key: { 
       'primaryKey': 'primaryValue' 
    },
    UpdateExpression: 'SET #newAttributeName = :newAttributeValue',
    ExpressionAttributeNames: {
       '#newAttributeName': 'newAttribute'
    },
    ExpressionAttributeValues: {
        ':newAttributeValue': 'newAttributeValue'
    }
};

docClient.update(params, function(err, data) {
    if (err) {
        console.log("Error adding new attribute to item: ", err);
    } else {
        console.log("Successfully added new attribute to item: ", data);
    }
});

Let’s go through this code line by line to know what’s happening.

  • var params = { - this initializes a variable named “params” that will hold the parameters for our DynamoDB update request.
  • TableName: 'my-table', - this specifies the name of the DynamoDB table we want to update.
  • Key: { 'primaryKey': 'primaryValue' }, - this specifies the primary key of the item we want to update. Note that you must specify the primary key of the item in order to update it.
  • UpdateExpression: 'SET #newAttributeName = :newAttributeValue', - this is the update expression that specifies the new attribute we want to add to the item. In this case, we’re setting a new attribute with the name “newAttribute” and a value of “newAttributeValue.”
  • ExpressionAttributeNames: { '#newAttributeName': 'newAttribute' }, - this specifies the name of the new attribute we’re adding. We’re using the placeholder “#newAttributeName” to avoid any naming conflicts. We map this placeholder to our desired name “newAttribute” using the ExpressionAttributeNames object.
  • ExpressionAttributeValues: { ':newAttributeValue': 'newAttributeValue' } - this specifies the value of the new attribute we’re adding. We’re using the placeholder “:newAttributeValue” to avoid naming conflicts. We map this placeholder to our desired value “newAttributeValue” using the ExpressionAttributeValues object.

Lastly, we call the update method on our DynamoDB docClient object, passing in our params object as well as a callback function to handle any errors that may occur.

Alternative Ways to Add a New Column

Aside from using the UpdateTable query, there are other ways to add a new column to your DynamoDB table. One such way is to create a new item with the new attribute and then update the existing items with the new attribute.

Another way is to create a new table with the new attribute and then migrate your data to the new table.
