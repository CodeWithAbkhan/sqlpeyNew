NOSQL: Combining MongoDB and Neo4j for Improved Data Management Using MongoDB and Neo4j together: Advantages, Disadvantages, and Alternatives

Introduction

When starting a new project, one may consider using MongoDB as the document storage facility and Neo4j as the mechanism to map relationships between documents and then expose the results of queries via rest API. But, what are the advantages, disadvantages, and alternatives to using these two databases together? Let’s find out.

Advantages of using MongoDB and Neo4j together

The primary advantage of using MongoDB and Neo4j together is that they are both NoSQL databases, designed to handle unstructured and semi-structured data. MongoDB excels at handling large volumes of data, making it ideal for managing documents. On the other hand, Neo4j is a graph database that is optimized for handling interconnected data. By using both databases together, one can benefit from the strengths of each database.

Disadvantages of using MongoDB and Neo4j together

There are a few disadvantages to using both MongoDB and Neo4j together. The first is that it requires additional resources, such as memory and disk space, to manage both databases. This can be a problem for smaller projects or those with limited resources.

Another issue with using both databases is that when you shard your data with MongoDB, you’ll also have to manage your Neo4j data w.r.t. these new shards, which can add an extra layer of complexity to your project. More, the scaling in Neo4j is done through clusters, which is a part of the enterprise edition, which is commercial, adding further expense to the project.

Alternatives to using MongoDB and Neo4j together

If using both databases is not feasible, you may want to consider other alternatives. For example, you could build the relationships in MongoDB itself, write your logic on top of that, and expose this logic through a REST API. This option removes the need for managing two databases and reduces the complexity of the project.

Another alternative to consider is OrientDB, which is a graph database that also stores data as documents. By using OrientDB, you get the benefits of using a graph database, while also being able to store your data as documents.

Lastly, if you like Neo4j, you could have a look at Structr. With Structr, you can define a custom schema on top of Neo4j (in Java or through the UI from version 0.7). It creates a production-grade REST API from the schema with a lot of features like access control, validation rules, computed properties, etc. This eliminates the need to manage multiple databases and reduces complexity.

Real-time synchronization of data from MongoDB to Neo4j

If you still want to use MongoDB and Neo4j together, the Neo4j Doc Manager for Mongo Connector can be of use. It’s an extension to the Mongo Connector project that allows for real-time one-way synchronization of data from MongoDB to Neo4j. Documents inserted in MongoDB are converted to a property graph and automatically inserted into Neo4j. The collection and fields to be synced from Mongo to Neo4j can be configured, simplifying the management of data in both databases.

Recap

Using MongoDB and Neo4j together provides the benefits of working with two NoSQL databases that handle unstructured and semi-structured data. Although, this approach can increase the complexity of the project, require additional resources, and add expenses. Therefore, one should consider alternatives such as building relationships in MongoDB or using another graph database like OrientDB or Structr. If you still want to use both databases, use the Neo4j Doc Manager for Mongo Connector to simplify the management of data in both databases. ]]>
