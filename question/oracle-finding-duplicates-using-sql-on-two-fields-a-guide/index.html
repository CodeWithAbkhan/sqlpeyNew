ORACLE: Finding Duplicates Using SQL on Two Fields - A Guide Finding Duplicates in Oracle Database Table Based on Two Fields Using SQL
If you have rows in an Oracle database table that should be unique for a combination of two fields, but the unique constraint is not set up on the table, you can find all the rows that violate the constraint using SQL. In this Q&A Session, we will show you how to find duplicates based on two fields in a simple step-by-step process.

Step 1: Learn Your Table and Fields

Before you begin, you need to know your table and fields. In this example, our table has three relevant columns:

  • entity_id
  • station_id
  • obs_year

For each row, the combination of station_id and obs_year should be unique, but the unique constraint is not set up on the table. Therefore, you need to find all the rows that violate this constraint yourself using SQL.

Step 2: Use SQL Query to Find Duplicates

Now that you know your table and relevant columns, you can use the following SQL query to find the duplicates:

SELECT t1.entity_id, t1.station_id, t1.obs_year
FROM mytable t1
WHERE EXISTS (
    SELECT 1 FROM mytable t2 
    WHERE t1.station_id = t2.station_id
    AND t1.obs_year = t2.obs_year
    AND t1.RowId  t2.RowId
)

Let’s dive into what this query is doing:

  • We are selecting the entity_id, station_id, and obs_year fields from our table.
  • We are using the EXISTS keyword to check if there are any duplicates in the table.
  • The subquery selects all rows that have the same station_id and obs_year values but different RowId values.
  • We are only returning the rows that exist in the subquery, in other words, the rows that are duplicates.

This SQL query will return all the rows that are duplicates based on the combination of station_id and obs_year fields.

Step 3: Fixing Ambiguous Column Error

If you run the above SQL query, you may encounter an ambiguous column error (ORA-00918). This error occurs when you specify a column name that exists in multiple tables and Oracle cannot determine which table you want to select the column from.

To fix this error, you can rewrite the SELECT statement as follows:

SELECT t1.entity_id, t1.station_id, t1.obs_year
FROM mytable t1
INNER JOIN (
    SELECT entity_id, station_id, obs_year 
    FROM mytable 
    GROUP BY entity_id, station_id, obs_year 
    HAVING COUNT(*) > 1
) dupes 
ON t1.station_id = dupes.station_id AND t1.obs_year = dupes.obs_year

What we’ve done is added an INNER JOIN to a subquery that selects all rows that have the same entity_id, station_id, and obs_year values but with a count greater than 1. Then we used the ON clause to join the tables based on the station_id and obs_year fields.

Step 4: Alternative Ways to Find Duplicates

There are several alternative ways to find duplicates based on two fields in Oracle. Here are two examples:

Example 1:

SELECT t.*
FROM (
    SELECT ROW_NUMBER() OVER (PARTITION BY station_id, obs_year ORDER BY entity_id) rn, t.*
    FROM mytable t
) t
WHERE rn > 1

In this example, we are assigning a row number to each row based on the partition of station_id and obs_year fields. The ROW_NUMBER() function assigns a unique incremental value for each row in the result set. We are then selecting only the rows where the row number is greater than 1, which indicates a duplicate.

Example 2:

CREATE TABLE mytable_temp
  AS SELECT DISTINCT entity_id, station_id, obs_year
  FROM mytable;

DELETE FROM mytable WHERE ROWID NOT IN (
  SELECT MIN(ROWID) FROM mytable GROUP BY station_id, obs_year
);

INSERT INTO mytable (
  SELECT * FROM mytable_temp
);

COMMIT;

DROP TABLE mytable_temp;

In this example, we create a new temporary table with a unique constraint on the entity_id, station_id and obs_year fields. We then copy all the distinct rows from our original table into the temporary table, ignoring all duplicates due to the unique constraint. We then delete all rows from the original table except for the first row with each unique value of station_id and obs_year. Lastly, we copy all the rows from the temporary table back into the original table and commit the changes. This method ensures that the table has a unique constraint on station_id and obs_year fields.

Recap

By knowing your table and fields, you can easily find duplicates and fix errors that may arise.
