Using Arrays in Oracle PLSQL’s IN() Clause Creating and Using String Arrays in Oracle PL/SQL Stored Procedure: Explained Line-by-Line

In this blog post, we will look at how to create and use a string array in an Oracle PL/SQL stored procedure. We will go through the code line-by-line and explain what each line does. We will also provide practical examples and alternative ways to do it.

Summary:

We have a String array plcListchar that we need to use in an IN() clause in an Oracle PL/SQL stored procedure. We will pass this String array as a parameter to the stored procedure and use it in the SELECT statement. We cannot use the array directly in the IN() clause, so we will use the TABLE operator to convert the array into a table that we can use in the IN() clause.

Step-by-Step Explanation:

Let’s start with the Java code that creates the String array and passes it to the stored procedure.

 String array[] = {"o", "l"}; 
 ArrayDescriptor des = ArrayDescriptor.createDescriptor("CHAR_ARRAY", con);
 ARRAY array_to_pass = new ARRAY(des,con,array);            
 callStmtProductSearch.setArray(4, array_to_pass);

				  Here we define a String array with two elements: "o" and "l". We then create an instance of the ArrayDescriptor class that defines the type of the array we want to pass to the stored procedure. We pass this descriptor and the array to the ARRAY constructor to create an instance of the ARRAY class. Lastly, we set this array as a parameter to the stored procedure.  Now let's look at the SQL code that defines the stored procedure.

We define the stored procedure product_search with six parameters. The first three parameters are IN parameters: status, plcList, and i_culture_id. The fourth parameter, plcListchar, is an instance of the CHAR_ARRAY type that we defined earlier. The last two parameters are OUT parameters: status_name and culture_code. Inside the procedure, we define a cursor named search_cursor that selects two columns, status_name and culture_code, from the PRISM_ITEM_cultures table with some conditions. The important part is the IN clause where we want to use the plcListchar string array.

AND p.plc_status IN (SELECT column_value
                       FROM TABLE( plcListchar ))

Here we use the TABLE operator to convert the plcListchar string array into a table that we can use in the IN() clause. The SELECT statement inside the parentheses returns the elements of the array as rows of the table. The column_value is a pseudocolumn that represents the values of the array elements. We then use this table in the IN() clause to select only the rows that have plc_status column values in the array. Practical Example: Let’s assume we have the following plcListchar string array. {“o”, “l”} We pass this array as a parameter to the product_search stored procedure along with other parameters. The stored procedure uses the array in the IN() clause to return the rows that have plc_status column values in the array. CREATE OR REPLACE PROCEDURE product_search_dynamic(
            status IN varchar2, 
            plcList IN varchar2,
            i_culture_id IN number,
            plcListchar IN CHAR_ARRAY,
            status_name OUT  varchar2, 
            culture_code  OUT varchar2)
AS  
  l_sql varchar2(4000);
BEGIN
  l_sql := 'SELECT p.status_name, p.culture_code
                FROM PRISM_ITEM_cultures@prism p
                WHERE p.publishable_flag=1 
                AND p.isroll =0 
                AND status="-1"
                AND p.plc_status IN (';
  for i in 1..plcListchar.count loop
    l_sql := l_sql || '''' || plcListchar(i) || '''' || ',';
  end loop;
  l_sql := rtrim(l_sql, ',') || ')';
  
  open search_cursor for l_sql;
  fetch search_cursor into status_name, culture_code;
  close search_cursor;
END;

Here we define a new stored procedure product_search_dynamic that uses dynamic SQL to construct the SELECT statement. We define a local variable l_sql that holds the SELECT statement as a string. We then loop through the plcListchar array and append the array elements as strings to the l_sql variable. We use rtrim function to remove the trailing comma. Lastly, we open the cursor with the dynamic SQL and fetch the result into the output parameters.
