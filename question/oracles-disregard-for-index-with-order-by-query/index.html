Oracle’s Disregard for Index with ORDER BY Query In this scenario, the Oracle optimizer is ignoring the index because the FIRST_NAME column is nullable. When a column is nullable, the optimizer has to check each value to ensure that it is not a null value, which can make using an index slower than doing a full table scan.

To rewrite the algorithm in a more clear and thorough way, we can break it down:

  1. The outer query is using a WHERE clause to filter the results by row number, between 1 and 20.
  2. The inner query is using the ROW_NUMBER() function to add a sequential row number to each row in the result set, ordered by the FIRST_NAME column.
  3. The inner query is also using the FIRST_ROWS(20) hint to prioritize returning the first 20 rows in the result set quickly.

To make the query use the index, we can modify the outer query to use the indexed column in the ORDER BY clause instead of the row number:

select * from (
  select /*+ FIRST_ROWS(20) */ FIRST_NAME, ROW_NUMBER() over (order by FIRST_NAME) RN
  from CUSTOMER C
)
where RN between 1 and 20
order by FIRST_NAME;

				  This will tell the optimizer to use the index to sort the results, which should improve performance.  Practical example:  Let's say we want to paginate through a large table of customers by their first name. We can use the following query to retrieve the first 20 customers:  
				  

select * from (
  select /*+ FIRST_ROWS(20) */ FIRST_NAME, ROW_NUMBER() over (order by FIRST_NAME) RN
  from CUSTOMER
)
where RN between 1 and 20
order by FIRST_NAME;

If we have an index on the FIRST_NAME column, we can modify the query to use the index:

select * from (
  select /*+ FIRST_ROWS(20) */ FIRST_NAME, ROW_NUMBER() over (order by FIRST_NAME) RN
  from CUSTOMER
)
where RN between 1 and 20
order by FIRST_NAME ASC;

This should improve the query performance when retrieving the paginated results. Alternative ways: Another way to paginate through a result set in Oracle is to use the OFFSET FETCH clause, which was introduced in Oracle 12c:

select *
from CUSTOMER
order by FIRST_NAME
offset 0 rows fetch next 20 rows only;

This query will retrieve the first 20 rows of the result set, ordered by the FIRST_NAME column. We can change the OFFSET value to shift the pagination by a certain number of rows. Summary: When using pagination in Oracle, it’s important to consider the indexed columns in the query and how they are being sorted. If we want the query to use an index, we need to make sure that the indexed column is being used in the ORDER BY clause instead of the ROW_NUMBER() function.
