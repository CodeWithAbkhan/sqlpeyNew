couldn't connect to server 127.0.0.1 shell/mongo.js Troubleshooting MongoDB’s “Couldn’t Connect to Server 127.0.0.1 Shell/Mongo.js” Error
When setting up MongoDB in Ubuntu, you may see the following error when running the command ./mongo:

couldn't connect to server 127.0.0.1 shell/mongo.js

Here are some solutions to this issue:

Manually Remove the Lockfile

Run the following command to manually remove the lockfile:

sudo rm /var/lib/mongodb/mongod.lock

Run the Repair Script

Run the repair script with the following command:

sudo -u mongodb mongod -f /etc/mongodb.conf --repair

Please note:

  • You must run this command as the mongodb user. If you run it as root, then root will own files in /var/lib/mongodb/ that are necessary to run the mongodb daemon, and therefore when the daemon tries to run later as the mongodb user, it won’t have permissions to start. In that case, you’ll get the error:

Unable to create / open lock file for lockfilepath: /var/lib/mongodb/mongod.lock errno:13 Permission denied, terminating.

  • On Ubuntu, you must specify the configuration file /etc/mongodb.conf using the -f flag. Otherwise, it will look for the data files in the wrong place, and you will see the following error:

dbpath (/data/db/) does not exist, terminating.

Start MongoDB Service

To start the mongodb service, run the following commands:

sudo rm /var/lib/mongodb/mongod.lock
sudo -u mongodb mongod -f /etc/mongodb.conf --repair
sudo service mongodb start

It may take a while to start MongoDB after performing these operations.

To test if MongoDB is running, run the command mongod.

If you get an error such as the following, then the MongoDB service is not running:
