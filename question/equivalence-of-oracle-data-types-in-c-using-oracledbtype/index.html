Equivalence of Oracle Data Types in C# using OracleDbType Oracle Data Type Equivalence with OracleDbType

Situation

You are developing a C# application that interacts with an Oracle database using stored procedures. Within the application, you use the Oracle.DataAccess.Client library (11g) which includes the OracleDbType enumeration to represent Oracle data types. Although, you are unsure which Oracle PL/SQL data type corresponds to each enumerated type within the OracleDbType enumeration.

Questions

  1. What is the equivalent Oracle PL/SQL data type for each enumerated type within the OracleDbType enumeration?
  2. How do you determine which of the three integer types (Int16, Int32, Int64) to use within the OracleDbType enumeration?

Answer

The OracleDbType enumeration includes values for the most common Oracle data types. These values are defined in the Oracle documentation provided in the ODP for .NET Developer’s Guide. It is recommended to use the following method to convert C# types to the corresponding OracleDbType enum:

private static OracleDbType GetOracleDbType(object o) 
{
  if (o is string) return OracleDbType.Varchar2;
  if (o is DateTime) return OracleDbType.Date;
  if (o is Int64) return OracleDbType.Int64;
  if (o is Int32) return OracleDbType.Int32;
  if (o is Int16) return OracleDbType.Int16;
  if (o is sbyte) return OracleDbType.Byte;
  if (o is byte) return OracleDbType.Int16;    // Note: unverified
  if (o is decimal) return OracleDbType.Decimal;
  if (o is float) return OracleDbType.Single;
  if (o is double) return OracleDbType.Double;
  if (o is byte[]) return OracleDbType.Blob;

  return OracleDbType.Varchar2;
}

For large character data values, use OracleDbType.Clob instead of OracleDbType.Varchar2.

Regarding the three integer types, all are supported within the OracleDbType enum. Int16 should be used for values between -32768 and 32767. Int32 is suitable for values between -2147483648 and 2147483647. Use Int64 for larger values. Keep in mind that certain conversions between integers and PL/SQL data types may not work as expected. For example, refer to this blog post by Mark Williams for information on converting OracleDecimal to Integer.

Practical Examples

Assume that your stored procedure takes a VARCHAR2 and a DATE value as input parameters. Here is an example of how to declare the parameters using the OracleDbType enum:

using (OracleConnection connection = new OracleConnection(connectionString))
{
    using (OracleCommand command = new OracleCommand("stored_proc_name", connection))
    {
        command.CommandType = CommandType.StoredProcedure;
        
        OracleParameter parameter1 = new OracleParameter("parameter1_name", OracleDbType.Varchar2);
        parameter1.Value = "some_value";
        
        OracleParameter parameter2 = new OracleParameter("parameter2_name", OracleDbType.Date);
        parameter2.Value = DateTime.Now;
        
        command.Parameters.Add(parameter1);
        command.Parameters.Add(parameter2);
        
        try
        {
            connection.Open();
            command.ExecuteNonQuery();
        }
        catch (Exception ex)
        {
            // handle exception
        }
    }
}

Alternative Ways

The recommended approach is to use the OracleDbType enumeration to map between C# and Oracle data types. Although, you can also use the DbType enumeration to specify the parameter type. Keep in mind that DbType is a general-purpose enumeration that is not optimized for Oracle-specific data types.
