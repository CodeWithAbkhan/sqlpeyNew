NOSQL: Cassandra Performance Issues? Consider These Solutions Cassandra vs MongoDB: Learning Performance Differences

When it comes to choosing a NoSQL database for a project with a high volume of inserts, Cassandra and MongoDB are two of the most popular options. Although, recent test results have shown that MongoDB performs better than Cassandra in terms of write performance. This may come as a surprise to those who believe that Cassandra is designed to handle higher volumes of inserts than MongoDB. In this blog post, we’ll explore some of the reasons why this might be the case and suggest ways to improve Cassandra’s performance.

Learning the Code

To know why the write performance of Cassandra is lower than MongoDB, let’s take a closer look at the code used to insert data into each database. The following code is used to insert data into Cassandra:

import time
import os
import random
import string
import pycassa

def get_random_string(string_length):
    return ''.join(random.choice(string.letters) for i in xrange(string_length))

def connect():
    """Connect to a test database"""
    connection = pycassa.connect('test_keyspace', ['localhost:9160'])
    db = pycassa.ColumnFamily(connection,'foo')
    return db

def random_insert(db):
    """Insert a record into the database. The record has the following format
    ID timestamp
    4 random strings
    3 random integers"""
    record = {}
    record['id'] = str(time.time())
    record['str1'] = get_random_string(64)
    record['str2'] = get_random_string(64)
    record['str3'] = get_random_string(64)
    record['str4'] = get_random_string(64)
    record['num1'] = str(random.randint(0, 100))
    record['num2'] = str(random.randint(0, 1000))
    record['num3'] = str(random.randint(0, 10000))
    db.insert(str(time.time()), record)

if __name__ == "__main__":
    db = connect()
    start_time = time.time()
    for i in range(1000000):
        random_insert(db)
    end_time = time.time()
    print "Insert time: %lf " %(end_time - start_time)

As we can see, the code for both inserts is almost identical, with the only difference being the way the records are inserted into the database. In the case of Cassandra, a new key is generated for each record and the record is inserted into the database using the key. In MongoDB, the record is inserted into the database as an object.

Possible Reasons for Differences in Performance

There are several reasons why the performance of Cassandra may be lower than MongoDB:

  1. Single-Threaded Inserts: The code used for testing the insert performance of Cassandra involves single-threaded inserts, while MongoDB uses multithreaded inserts. This means that MongoDB can take advantage of multiple cores to insert records more quickly.

  2. No Equivalent of Unsafe Mode: Cassandra does not have an equivalent to MongoDB’s unsafe mode, which allows bulk inserts without waiting for the response from the server. This means that Cassandra has to wait for a response from the server after each insert, which slows down the insert process.

  3. Differences in Data Models: Cassandra is optimized for storing and retrieving large amounts of data quickly. MongoDB is optimized for creating indexes and querying embedded documents.

Improving Cassandra’s Performance

To improve Cassandra’s performance when handling high volumes of inserts, there are several things you can do:

  1. Use Multithreaded Inserts: Use multithreaded inserts to take advantage of multiple cores and speed up the insert process.

  2. Use Cassandra’s Batch Operations: Use Cassandra’s batch operations to group multiple inserts into a single insert request. This reduces the number of requests sent to the server and improves performance.

  3. Tune Cassandra’s Configuration: Fine-tune Cassandra’s configuration to match your specific use case. This can involve adjusting the number of threads used for reads and writes, increasing the size of the write buffer and commit log, and adjusting the size of the memtable.

Recap

While Cassandra is known for its ability to handle high volumes of data, recent test results have shown that MongoDB performs better than Cassandra when it comes to write performance. This may be due to differences in data models and the fact that MongoDB uses multithreaded inserts, while Cassandra does not have an equivalent of unsafe mode.
