Oracle’s Guide to DDL and Transaction Rollback Is DDL transactional in Oracle?
DDL (Data Definition Language) statements in Oracle, such as Create or Alter, are not transactional. According to Oracle’s official documentation, the database implicitly commits the current transaction before and after every DDL statement. Essentially, DDL statements act as separate transactions to any data modifications that the statement may make. While other transactions may make modifications involving the object being modified in a DDL statement, all these operations will still run in the transaction that includes the DDL statement. If the DDL statement fails or is cancelled, all operations within the transaction including the DDL statement will be rolled back.

Can you roll back multiple DDL statements?

Currently, you cannot start an explicit transaction to roll back multiple DDL statements altogether in Oracle. A way around this limitation is to use the CREATE SCHEMA AUTHORIZATION feature of Oracle which allows bundling several DDL statements in a single transaction, thus avoiding several commits, and guarantees no side-effects, i.e. a rollback, if any one of the DDL statements fails.

The CREATE SCHEMA AUTHORIZATION feature allows wrapping multiple DDL statements in a single transaction.

CREATE SCHEMA AUTHORIZATION schema_name
    CREATE/ALTER/DROP/RENAME statement;

Where:

  • schema_name - is the name of the schema under which you want to execute the DDL statements.
  • CREATE/ALTER/DROP/RENAME statements - are the various DDL statements to execute.

If any one of the wrapped DDL statements fails, the entire transaction, including all wrapped DDL statements, will be rolled back.

Does the rollback apply to the outer transaction?

It’s unclear whether the rollback applies to the outer transaction with possibly some prior DML statement or the wrapped DDL statements only. Although, the wrapped statements are rolled back as if the CREATE SCHEMA AUTHORIZATION command started a save-point.

Are there considerations when running some DDL statements?

Some DDL statements, such as alter table statements, may fail if another session has an open transaction on the object being modified or one of its dependencies. You can set a ddl_lock_timeout to specify how long you want Oracle to wait for the object to become available.

Oracle’s official documentation provides details on the behavior of different types of DDL statements regarding locks and transactions.

Practical Example

To know how CREATE SCHEMA AUTHORIZATION works, consider the following example. We will put together multiple DDL statements into a single transaction using CREATE SCHEMA AUTHORIZATION. If for any reason, any of the DDL statements in this transaction fails, the entire transaction would be rolled back.

CREATE SCHEMA AUTHORIZATION TEST_USER
    CREATE TABLE TEST_USER."Inventory" ("ID" NUMBER(10) NOT NULL, "Product" VARCHAR2(200) NOT NULL, "Quantity" NUMBER(5,2), PRIMARY KEY ("ID"));
    ALTER TABLE TEST_USER."Inventory" ADD CONSTRAINT CHK_QTY CHECK ("Quantity" > 0);
    COMMENT ON TABLE TEST_USER."Inventory" IS 'This table holds Inventory information';

In this example, we group together the creation of the Inventory table, an alteration to add a constraint and a comment statement which comments about our table. By putting these together in one transaction, we avoid the risk of partial changes in case any of the statements fail.

Alternative Ways

Another alternative to creating schema authorization for bundling multiple DDL statements is to use a scripting language like SQL*Plus or SQL Developer.

In SQL*Plus, you can write a batch file that executes multiple DDL statements as a single logical transaction. SQL Developer allows executing multiple SQL statements at a time. These solutions provide the ability to execute multiple statements within a single transaction and to avoid committing changes when any one of the statements fails.

Although, when compared to CREATE SCHEMA AUTHORIZATION, these scripts may require time-consuming data manipulation language (DML) changes to ensure all relevant data changes are included in a single logical transaction.

Recap

Unlike MS SQL, DDL statements are not transactional in Oracle. Oracle implicitly commits the current transaction before and after every DDL statement. While you cannot start an explicit transaction to roll back multiple DDL statements, Oracle’s CREATE SCHEMA AUTHORIZATION feature allows bundling multiple DDL statements in a single transaction.

Rather than facing the risk of partial changes in case any of the statements fail, you can group together the statement to avoid the risk of partial changes. Ensure to read relevant Oracle documentation for further details and considerations when running any DDL statement. ]]>
