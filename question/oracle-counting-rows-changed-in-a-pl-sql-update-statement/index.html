ORACLE: Counting Rows Changed in a PL/SQL UPDATE Statement

Learn how to determine the number of rows affected by an UPDATE statement in PL/SQL using the SQL%ROWCOUNT variable. This guide provides examples and explanations for efficiently obtaining the count of updated rows in Oracle 10g.

Using SQL%ROWCOUNT Variable

In PL/SQL, if you wish to retrieve the count of rows affected by an UPDATE operation, leverage the SQL%ROWCOUNT variable. This variable contains the number of rows processed by the last SQL statement.

Consider the following example:

DECLARE 
    i NUMBER; 
BEGIN 
    UPDATE employees 
    SET    status="fired" 
    WHERE  name LIKE '%Bloggs'; 
    i := SQL%rowcount; 
    COMMIT; 
    dbms_output.Put_line(i); 
END;

In this script, the variable i is declared to store the count of affected rows. It is assigned the value of SQL%ROWCOUNT immediately after the UPDATE statement. Subsequently, the changes are committed, and the value of i is printed using dbms_output.

Retrieving Results from a Plain Command

To obtain results from a plain command, you can use the following code:

BEGIN
  DBMS_OUTPUT.PUT_LINE(TO_Char(SQL%ROWCOUNT)||' rows affected.');
END;

This code snippet prints the number of affected rows as part of a plain command execution.

SQL%ROWCOUNT Without Assignment

The SQL%ROWCOUNT variable can also be used without explicit assignment. If no operation (updates, deletes, or inserts) occurs within the current block, SQL%ROWCOUNT remains null. After the first DML operation, it holds the count of rows affected by that operation.

Consider this illustration with a CLIENT table:

CREATE TABLE client (
  val_cli INTEGER,
  status VARCHAR2(10)
);

BEGIN
  DBMS_OUTPUT.PUT_LINE('Value when entering the block:' || SQL%ROWCOUNT);

  INSERT INTO client 
    SELECT 1, 'void' FROM dual
    UNION ALL SELECT 4, 'void' FROM dual
    UNION ALL SELECT 7, 'void' FROM dual;

  DBMS_OUTPUT.PUT_LINE('Value after the first command:' || SQL%ROWCOUNT);

  UPDATE client SET status = 'done' WHERE val_cli > 2;

  DBMS_OUTPUT.PUT_LINE('Value after the second command:' || SQL%ROWCOUNT);
END;

In this example, we insert three rows into the CLIENT table, affecting SQL%ROWCOUNT. Subsequently, an update operation changes it to reflect the count of affected rows. Finally, we print out the value of SQL%ROWCOUNT after the last update command.

Summary

To recap, for determining the number of rows affected by an UPDATE statement in PL/SQL, use the SQL%ROWCOUNT variable. Call it immediately after the statement you wish to inquire about.

FAQs on ORACLE: Counting Rows Changed in a PL/SQL UPDATE Statement

Q: How can I count the number of rows affected by an UPDATE statement in PL/SQL?

Utilize the SQL%ROWCOUNT variable immediately after the UPDATE statement to retrieve the count of affected rows.

Q: What does the SQL%ROWCOUNT variable represent in PL/SQL?

The SQL%ROWCOUNT variable in PL/SQL holds the number of rows processed by the last SQL statement, making it useful for obtaining the count of affected rows.

Q: Is it necessary to commit changes before using SQL%ROWCOUNT in PL/SQL?

Yes, commit changes using COMMIT; before retrieving the value of SQL%ROWCOUNT to ensure accurate results.

Q: Can SQL%ROWCOUNT be used without explicit assignment in PL/SQL?

Yes, SQL%ROWCOUNT can be used without explicit assignment. It remains null if no DML operation occurs within the current block, and after the first DML operation, it holds the count of affected rows.

Q: Does SQL%ROWCOUNT work for both INSERT and UPDATE operations in PL/SQL?

Yes, SQL%ROWCOUNT is applicable for various DML operations, including INSERT and UPDATE, providing the count of affected rows in PL/SQL.
