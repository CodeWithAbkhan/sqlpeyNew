Learning the New BigQuery Pricing Tiers
The BigQuery pricing model is set to change on January 1st, 2016, and a new tiered pricing model will be introduced. To help customers predict cost implications, the JSON response can be used to see what tier has been assigned to a query and analyze potential costs.

What is the ‘billingTier’ field in BigQuery?

The ‘billingTier’ field in the BigQuery JSON response is a true indicator of the tier assigned to a query according to the upcoming pricing structure. If the field is set to 1 in the response, then the query would be billed at the current (tier 1) rates under the new pricing structure.

Is the ‘billingTier’ field assigned by default or an actual billing tier assigned?

The ‘billingTier’ field represents the actual billing tier assigned to the query under the new pricing structure. Therefore, if the field is equal to 1, then the query is assigned to the first billing tier under the new pricing model.

How to check where a query would fall under the new pricing structure?

The billing tier is computed separately on each invocation of a query. There is no strict guarantee that the same query will always fall in the same billing tier. Therefore, we recommend spot-checking a reasonable sample of queries to get a general sense of where the workload will fall under the new pricing structure.

Practical Examples of BigQuery Pricing Calculation

Suppose you had a query that processed 10GB of data in a single invocation. Under the current pricing model, you would be billed at $5 per TB, resulting in a cost of $0.05 ($5 per TB * 10GB / 1TB) for this query. Under the new pricing model, this query would be billed at the tier 3 rate of $20 per TB, resulting in a cost of $0.20 ($20 per TB * 10GB / 1TB) for this query.

Alternative Ways of Predicting Costs under the New Pricing Model

Alternatively, you can use the Google Cloud Platform Pricing Calculator to estimate potential costs. This tool allows you to enter usage details and the service you are using, and it will generate an estimated cost for that service. This can be useful for predicting costs for a specific use case or workload.
