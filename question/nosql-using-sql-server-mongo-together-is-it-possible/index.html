NOSQL: Using SQL Server and Mongo Together: Is it Possible? Using SQL Server and MongoDB Together for Read Optimization
If you have a high-traffic website with a DB-Repo Layer-Services Layer-Asp.Net MVC architecture, you may be experiencing read performance issues. To solve this problem, you may consider using a NoSQL database like MongoDB as a query database while keeping SQL Server as the database of record. In this Q&A-style post, we will explore whether it is possible to use SQL Server and MongoDB together and how to update updates.

Can SQL Server and Mongo Be Used Together?

Yes, SQL Server and MongoDB can be used together. The approach involves having two databases: one for writing and one for querying. The SQL Server database is used as the primary write store, and the MongoDB database is used for querying. The read database can have denormalized data, where data from different tables are combined into one document to improve the query performance.

What is the CQRS Pattern?

CQRS stands for “Command Query Responsibility Segregation.” It is a design pattern introduced by Greg Young that involves separating the write and read concerns of an application into two separate models. The write model is responsible for updating the database, and the read model is responsible for querying the database. This separation allows for a more scalable and performant architecture.

How is the CQRS Pattern Applied?

In the context of using SQL Server and MongoDB together, the CQRS pattern can be applied as follows:

// Write Database (SQL Server)
public class Q&A SessionRepository : IRepository
{
    public void Save(Q&A Session Q&A Session)
    {
        // Save the Q&A Session to SQL Server
    }
}

// Read Database (MongoDB)
public class Q&A SessionReadModel
{
    public string Id { get; set; }
    public string Title { get; set; }
    public string Author { get; set; }
    // ... other denormalized data
}

The write database is implemented using SQL Server, while the read database is implemented using MongoDB. The Q&A SessionRepository class is responsible for saving Q&A Sessions to the SQL Server database, while the Q&A SessionReadModel class represents the denormalized data stored in MongoDB.

How is Data Synced Between the Write and Read Databases?

In the CQRS pattern, data is synced between the write and read databases asynchronously. A common approach is to use a message queue (such as RabbitMQ or Azure Service Bus) to send messages from the write database to the read database. These messages can contain information about which data has been updated and how it should be denormalized in the read database. The read database can then process these messages and update the denormalized data accordingly.

The sample code above does not show how the data is synced between the write and read databases. Although, a popular open source implementation of the CQRS pattern is NCQRS , which provides a framework for handling message-based communication between different components of a CQRS-based system.

Recap

Using SQL Server and MongoDB together can be an effective way to optimize read performance for a high-traffic website. By applying the CQRS pattern and separating the write and read concerns of the application, it is possible to achieve a more scalable and performant architecture.
