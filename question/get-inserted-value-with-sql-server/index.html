Get Inserted Value with SQL Server In SQL Server, when we insert a record into a table with a generated value, we might want to get that generated value back in the same step. In this Q&A Session, we will explore two ways to achieve this.

First Method:

We can use the OUTPUT clause to extract the generated value from the insert statement. Here is the syntax for the same:

INSERT INTO table (name)
OUTPUT Inserted.ID
VALUES('bob');

Note that this method works for non-IDENTITY columns as well, such as GUIDs.

Second Method:

We can use the SCOPE_IDENTITY() function to retrieve the last identity value inserted into an identity column. Here’s how we can use it:

INSERT INTO table (name) VALUES('bob');

SELECT SCOPE_IDENTITY()

It’s important to note that this method is only applicable to identity columns.

Let’s take a closer look at the two methods.

Using OUTPUT Clause:

In the first method, we use the OUTPUT clause to return the generated value. The OUTPUT clause enables us to retrieve the inserted, updated, or deleted values from a table. In this case, we want to retrieve the inserted value.

The syntax for the OUTPUT clause is:

We use the Inserted table to retrieve the inserted value. The Inserted table is created internally by SQL Server to store the new row that is being inserted. In our case, we want to retrieve the value of the ID column from the Inserted table.

Using SCOPE_IDENTITY Function:

In the second method, we use the SCOPE_IDENTITY() function to retrieve the last identity value inserted into an identity column. This function returns the last identity value generated by the insert statement in the current scope.

The syntax for using SCOPE_IDENTITY() is simply:

SELECT SCOPE_IDENTITY()


After inserting a record into the table, we immediately execute the SELECT statement to retrieve the last generated identity value.

It's important to note that SCOPE_IDENTITY() will only return the last identity value generated within the current scope. Therefore, we should ensure that no other insert statement has been executed in the same scope before calling this function.

Alternative Method:

Along with the above methods, we can also use the OUTPUT clause to store the generated value in a temporary table variable and then select it back to the client. Here's how we can use it:

DECLARE @generated_keys table([Id] uniqueidentifier)

INSERT INTO Customers(FirstName) OUTPUT inserted.CustomerID INTO @generated_keys VALUES(‘bob’);

SELECT t.[CustomerID] FROM @generated_keys AS g JOIN dbo.Customers AS t ON g.Id = t.CustomerID WHERE @@ROWCOUNT > 0


Here we are declaring a table variable @generated_keys to store the output values. We use this table variable in the INSERT statement's OUTPUT clause to store the inserted value. Lastly, we join the table variable with the original table to retrieve the inserted value.

Recap:

In this Q&A Session, we have discussed two methods to retrieve generated values after an insert statement in SQL Server. We can use either the OUTPUT clause or the SCOPE_IDENTITY() function to achieve this.
Although, the OUTPUT clause can have issues with triggers. So, if we expect any triggers to be applied to our table in the future, we should use the SCOPE_IDENTITY() function.]]>
