Streaming Data in BigQuery: Troubleshooting Newly Created Tables
Are you encountering a BigQueryException when trying to stream data into a newly created table? The table exists, yet the exception states that it does not. You’re not alone. This can be a frustrating issue, but fortunately, it has a straightforward resolution.

Learning the Problem

When creating a new table in BigQuery programmatically, there is a delay between when the table is actually created and when it can be used to insert new data. The time for delayed propagation can range from several seconds up to 90 minutes, depending on the circumstances.

This delay is because changing the schema structure of a table requires proper propagation and synchronization throughout the infrastructure. BigQuery requires that tables are in a steady state before accepting requests to insert data or query data from the newly created table.

The error “Not found: Table myProject.myDataset.myNewTableName” appears because the table metadata hasn’t completed propagation. The table cannot be accessed until BigQuery has finished processing the schema changes.

Working Around the Delay

Fortunately, there are a few workarounds to the delay. The first workaround is to wait for the table metadata to propagate fully. This can take several minutes or up to 90 minutes, depending on the table.

If waiting isn’t an option, then another workaround is to use an existing table to insert the data initially. After the table metadata has fully propagated, create a new table with the proper schema changes, then copy the data from the temporary table to the new table. This workaround avoids the need to wait for the schema changes to propagate before inserting data.

Practical Example

Let’s say you want to create a new table called “myNewTable” in the dataset “myDataset” on project “myProject.” The table needs to be created dynamically, as the data has a variable schema structure depending on the source of the data.

Here is an example of how to create a table using the Java API:

TableId tableId = TableId.of("myProject", "myDataset", "myNewTable");
List fields = new ArrayList();
fields.add(Field.of("event_id", StandardSQLTypeName.INT64));
fields.add(Field.of("event_name", StandardSQLTypeName.STRING));
Schema schema = Schema.of(fields);
TableDefinition tableDefinition = StandardTableDefinition.newBuilder().setSchema(schema).build();
bigQuery.create(TableInfo.of(tableId, tableDefinition));

The code above creates a new table called “myNewTable” using the java API. Afterward, you can insert data into your newly created table:

TableId tableId = TableId.of("myProject", "myDataset", "myNewTableName");
Table table = bigQuery.getTable(tableId);
TableDataInsertAllRequest.Builder builder = TableDataInsertAllRequest.newBuilder(tableId);
Map rowContent = new HashMap();
rowContent.put("event_id", "123");
rowContent.put("event_name", "Event 1");
builder.addRow(rowContent);
TableDataInsertAllResponse response = bigQuery.insertAll(builder.build());

Unfortunately, when running the code above, you might encounter a problem. The “Not found: Table myProject.myDataset.myNewTableName” error could appear because of the schema change delay.

To get around this issue, either wait until the schema propagation delay is over, or use an existing table to insert the data temporarily. Afterward, create a new table with the proper schema, then copy the data from the temporary table to the new table.

Alternatives

Another alternative is to use a template table to solve the schema propagation issue. A template table in BigQuery acts as a blueprint for creating new tables. You define the template table once, and then BigQuery generates tables that match the structure of the template using a wildcard table mechanism.

After the template is created, you can insert data into the table even before the data is propagated throughout the infrastructure.]]>
