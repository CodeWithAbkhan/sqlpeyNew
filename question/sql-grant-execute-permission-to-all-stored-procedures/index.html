SQL: Grant Execute Permission to All Stored Procedures Granting EXECUTE Permissions for All Stored Procedures in a SQL Server Database
If you need to grant EXECUTE permissions to a user or role for all the stored procedures in a SQL Server database, you can use the GRANT EXECUTE statement. This statement grants the specified user or role the right to execute all stored procedures in the database.

The GRANT EXECUTE Statement

The syntax for the GRANT EXECUTE statement is:

GRANT EXECUTE TO {user_name | role_name | group_name}

This statement grants the EXECUTE permission to the specified user, role, or group, allowing them to execute all stored procedures in the database. Hereâ€™s an example:

GRANT EXECUTE TO MyDomain\MyUser

This statement grants the EXECUTE permission to the user MyDomainMyUser for all stored procedures in the database.

Creating a New Role

In larger databases, it may be useful to create a new role specifically for granting EXECUTE permissions. This will help keep permissions organized and make it easier to manage access in the future.

To create a new role, use the CREATE ROLE statement:

CREATE ROLE db_executor

This statement creates a new role called db_executor.

Granting Permissions to a Role

Once you have created the new role, you can grant EXECUTE permissions to it using the GRANT EXECUTE statement:

GRANT EXECUTE TO db_executor

This statement grants the EXECUTE permission to the db_executor role, allowing any user or group that is a member of the role to execute all stored procedures in the database.

Granting Permissions to a User

If you need to grant EXECUTE permissions to a specific user, you can do so using the same GRANT EXECUTE statement:

GRANT EXECUTE TO MyDomain\MyUser

This statement grants the EXECUTE permission to the user MyDomainMyUser for all stored procedures in the database.

Granting Permissions to a Schema

If you only want to grant permissions to a specific schema, you can do so using the GRANT EXECUTE statement along with the name of the schema:

GRANT EXECUTE ON SCHEMA ::dbo TO MyDomain\MyUser

This statement grants the EXECUTE permission to the user MyDomainMyUser for all stored procedures in the dbo schema.

Alternative Approaches

In larger databases, you may want to be more granular in your permissions and not grant EXECUTE permissions to all stored procedures. To accomplish this, you can grant EXECUTE permissions to specific stored procedures or create a new schema and grant EXECUTE permissions to that schema.

More, you may want to consider creating a stored procedure to manage permissions. This stored procedure could handle granting or revoking permissions for multiple users or roles, making it easier to manage permissions over time.
