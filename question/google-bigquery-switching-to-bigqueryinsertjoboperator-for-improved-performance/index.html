Using BigQueryInsertJobOperator instead of BigQueryExecuteQueryOperator

Introduction

Recently, Airflow updated and deprecated the use of BigQueryExecuteQueryOperator in favor of BigQueryInsertJobOperator. This post aims to explain how to use the new operator and provide some examples for practical applications.

Learning the Changes

The main difference between the two operators is that BigQueryExecuteQueryOperator executes a SQL query, while BigQueryInsertJobOperator inserts a job configuration into a BigQuery job queue. This job can contain a variety of configurations, including a SQL query, a destination table, write disposition, and other parameters.

One advantage of using the new operator is that it allows for more flexibility and control over the job configuration. Although, it also requires more configuration and setup compared to the previous operator.

Using BigQueryInsertJobOperator

When using BigQueryInsertJobOperator, you need to provide a configuration parameter that contains the job configuration data. This configuration can include a query parameter that contains the SQL query to execute.

You can also include other parameters such as destination_dataset_table to specify the name of the destination table, and write_disposition to specify what should happen if the table already exists.

Here is an example of how you could use BigQueryInsertJobOperator:

# Define the SQL query
sql = "SELECT * FROM `proj.ds.table_1`"

# Define the task using the new operator
BigQueryInsertJobOperator(
    task_id='copy-table-1',
    configuration={
        'query': {
            'query': sql,
            'destination_table': {
                'project_id': 'proj',
                'dataset_id': 'ds',
                'table_id': 'table_2'
            },
            'write_disposition': 'WRITE_EMPTY'
        }
    },

)

In this example, we define the SQL query to select all rows from proj.ds.table_1. We then define the new task using BigQueryInsertJobOperator and specify the query configuration, as well as the destination table and the write disposition.

Passing Query Parameters

If you need to pass parameters to your SQL query, you can do so using the parameters field in the job configuration. For example:

# Define the SQL query that accepts a parameter
sql = "SELECT * FROM `proj.ds.table_1` WHERE date = @date_param"

# Define the task and parameters
BigQueryInsertJobOperator(
    task_id='copy-table-1',
    configuration={
        'query': {
            'query': sql,
            'destination_table': {
                'project_id': 'proj',
                'dataset_id': 'ds',
                'table_id': 'table_2'
            },
            'write_disposition': 'WRITE_EMPTY',
            'parameters': [
                {
                    'name': 'date_param',
                    'parameterType': {'type': 'DATE'},
                    'parameterValue': {'value': '2022-01-01'}
                }
            ]
        }
    },
    dag=dag
)

In this example, we add a parameter to the SQL query by using the @date_param syntax. We then define the parameter in the job configuration using the parameters field, where we specify the name, type, and value of the parameter.
