ORACLE: PL/SQL Unit Testing 101 Overview:

The use of unit testing for PL/SQL code helps ensure its reliability and effectiveness. In this post, we will discuss various tools and techniques for unit testing PL/SQL code.

What are unit tests?

A unit test is a software testing technique where individual elements of code are tested in isolation to check whether they work as intended. It involves creating test cases that cover all possible outcomes and edge cases that could affect the programâ€™s behavior.

Tools for unit testing PL/SQL:

  1. Quest Code Tester:

Quest Code Tester is a tool for testing PL/SQL code that offers a graphical user interface for creating and running tests. It supports data-driven testing and the creation of test data sets. Code Tester is not open-source software, and it requires a license to use.

  1. utPLSQL:

utPLSQL is an open-source PL/SQL unit testing framework that provides a simple and easy-to-use API for creating tests. It stores all test results in database tables, including historical results, which are helpful for gathering statistics. You can also define test groups using utPLSQL, which enables multiple test packages to be called with a single command.

  1. OUnit:

OUnit is a command-line test client for utPLSQL, which enables running tests without the need for a graphical user interface. OUnit is the predecessor to Qute, which is a similar tool but more complex than OUnit. OUnit is a good tool for developers who prefer command-line interfaces.

Techniques for Unit Testing PL/SQL:

  1. Use Test-Driven Development (TDD):

Test-Driven Development (TDD) is a development methodology that emphasizes writing tests before writing code. It involves creating an explicit requirement for a piece of code, writing a test that checks whether it meets the requirement, and then writing the code that fulfills the requirement while also passing the test. TDD helps in reducing the number of bugs and improving the quality of code.

  1. Use a consistent testing approach:

A consistent approach to testing ensures that tests are written in the same way, which simplifies knowing and maintains the code. Define standard test templates and naming conventions for test packages, test procedures, and test cases.

  1. Use mock objects for dependencies:

PL/SQL code often depends on other objects, such as database connections, which are not always easy to test. A mock object is a fake implementation of a code interface that simulates its behavior during testing. By using mock objects for dependencies, you can test the code without dealing with the complexity of the actual object.

Practical Examples:

Consider the following PL/SQL code:

CREATE OR REPLACE PROCEDURE calculate_ages (
    p_birth_date DATE,
    p_current_date DATE,
    p_output OUT VARCHAR2
) AS
BEGIN
    p_output := 'Age is : ' || floor((p_current_date - p_birth_date) / 365.25);
END;

We can write a test package using utPLSQL to test the above function:

CREATE OR REPLACE PACKAGE TEST_CALCULATE_AGES AS

    PROCEDURE test_calculate_ages;

END;

CREATE OR REPLACE PACKAGE BODY TEST_CALCULATE_AGES AS

    PROCEDURE test_calculate_ages AS
        l_output VARCHAR2(200);

    BEGIN
        calculate_ages(TO_DATE('1980/01/01', 'yyyy/mm/dd'), TO_DATE('2022/01/01', 'yyyy/mm/dd'), l_output);
        ut.expect(l_output).to_equal('Age is : 41');
    END;

END;

The test package contains a single test case that checks whether the output from the calculate_ages function is correct. The test compares the output of the function with the expected value using the ut.expect function.

Alternative Ways:

Apart from utPLSQL and OUnit, there are several other tools that can be used for unit testing PL/SQL code, such as Google Test Automation Framework for PL/SQL and PL/Unit. Although, each tool has its own set of features and limitations that should be considered when choosing a testing tool.

Recap:

Unit testing is an essential component of software development that helps ensure code quality, minimize defects, and increase long-term maintainability. Tools like Quest Code Tester, utPLSQL, and OUnit are useful for unit testing PL/SQL code. To achieve higher code quality, developers should consider using test-driven development, a consistent testing approach, and mock objects for dependencies.]]>
