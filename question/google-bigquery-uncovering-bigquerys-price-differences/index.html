Learning BigQuery Pricing Variations
After four months of using BigQuery, we have observed some pricing variations that we find interesting. In this post, we address some of the questions we have regarding BigQuery pricing and attempt to provide answers to these questions.

1. Pricing model is quite unexplained it needs explanations for joins, unions and so on

BigQuery pricing model is based on the amount of data processed, which is calculated by multiplying the total size of data read by the price per GB. The price per GB varies based on the location of the data and the numbers of on-demand processing queries executed.

Regarding joins and unions, the cost is calculated based on the total size of data processed after the join or union. Therefore, foremost to consider that the more tables involved in a query, the more data processed, and hence, the higher the cost.

2. If I run join on small table my data processed will increase for each copy of small table that was multiplied inside bigquery engine?

If a small table is joined with larger tables, BigQuery will first copy the small table multiple times to distribute it across its workers. This operation may, in turn, increase the amount of data that is processed.

3. If I reuse the same sub-query inside a query, is this new data processing regardless of it being the same subquery? Can this be optimized in any way? Doesn’t BigQuery cache its data?

BigQuery does not cache data by default, but it does provide caching mechanisms that can be used to reduce the amount of data processed. If the same sub-query is used multiple times within the same query, BigQuery is optimized to reuse the cached results of the subquery to reduce the amount of data processed. Although, if the same sub-query is used across different queries, BigQuery does not cache the results of the sub-query and will process the data each time.

4. Is there a minimum size that is rounded up for data processing? Our observations think it is 4MB, is this correct?

The minimum amount of data processed is 10 MB per query. Therefore, if a query processes less than 10 MB of data, BigQuery will round it up to the nearest 10 MB. This means that if a query processes 4 MB of data, BigQuery will charge you for 10 MB of data processed.

5. In Google Console, there is a problem with geo locations, it says that most of the queries are done from CA which is incorrect since my company is in Europe and all development is done there. I checked all IP addresses and there is no CA IP. Is it possible to get a more detailed report?

It is possible to get a more detailed report by logging into the Google Cloud Console and navigating to the BigQuery page. On the left-hand side, you will find a “Job History” tab that contains all your queries’ history. You can use this tab to filter queries based on a variety of criteria, including location.

6. Regarding question 5, we would like to get a history of queries and price for each one. How can we do this? Must our software do this, or?

As mentioned in the previous answer, you can use the “Job History” tab in the Google Cloud Console to get a history of your queries. The tab contains detailed information about each query, including the cost of each query. Although, if you want to automate the process of tracking the cost of your queries, you can use the BigQuery API or your software to collect the data and produce reports.
