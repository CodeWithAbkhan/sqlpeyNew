ORACLE: ORACLE’s Sleep Function: Simplifying Your Database Wait Time In this scenario, the goal is to execute an SQL query in ORACLE that takes a certain amount of time. To achieve this, the initial approach is to create a function that utilizes the DBMS_LOCK.sleep function, called TEST_SLEEP.
The TEST_SLEEP function takes a parameter, TIME_, representing the number of seconds to sleep. It then executes the DBMS_LOCK.sleep function with the input parameter of seconds to sleep.

Although, it is necessary to grant access to DBMS_LOCK.sleep to the owner of the procedure for it to work. As an alternative to granting such access, there are a few approaches that can be taken.

Option 1: Without Using DBMS_LOCK.sleep

One way to achieve the same result without using DBMS_LOCK.sleep is to use a loop that runs until the original timestamp plus the amount of time to sleep is less than or equal to the current date. The code for this approach is:

IN_TIME INT; --num seconds
v_now DATE;

-- 1) Get the date & time 
SELECT SYSDATE 
  INTO v_now
  FROM DUAL;

-- 2) Loop until the original timestamp plus the amount of seconds <= current date
LOOP
  EXIT WHEN v_now + (IN_TIME * (1/86400)) <= SYSDATE;
END LOOP;

The first line declares a variable, IN_TIME, which is the number of seconds to sleep. The second line declares a variable, v_now, which is the current date and time.

In the loop, the program checks the condition that the original timestamp plus the amount of time to sleep is less than or equal to the current date. If it is, the loop exits, and the function returns.

Option 2: Creating a Trusted User with DBMS_LOCK Access

Another way to avoid granting access to DBMS_LOCK.sleep is to create a procedure that utilizes DBMS_LOCK.sleep and installs it into a different user, who is trusted with DBMS_LOCK. Then grant that user access to DBMS_LOCK and grant access to the function to the user who needs to execute the query.

First, create a user with DBMS_LOCK access:

CREATE USER usera DEFAULT TABLESPACE users IDENTIFIED BY abc123;
GRANT CREATE SESSION TO usera;
GRANT RESOURCE TO usera;
GRANT EXECUTE ON DBMS_LOCK TO usera;

Next, create a function that uses DBMS_LOCK.sleep:

CREATE OR REPLACE FUNCTION usera.f_sleep(IN_TIME NUMBER) RETURN NUMBER
IS
BEGIN
  DBMS_LOCK.sleep(IN_TIME);
  RETURN 1;
END;
/

Lastly, grant access to this function to the user who needs to execute the query:

GRANT EXECUTE ON usera.f_sleep TO userb;

Now, the userb can execute the f_sleep function to sleep for a certain amount of time without requiring access to DBMS_LOCK.

Code Summary

To summarize, this problem involves executing an SQL query in ORACLE that takes a certain amount of time, without using the DBMS_LOCK.sleep function. One approach is to use a loop that runs until the original timestamp plus the amount of time to sleep is less than or equal to the current date, while another approach involves creating a trusted user with DBMS_LOCK access and granting access to a function that utilizes DBMS_LOCK.sleep to the user who needs to execute the query.

Example Code

As an example, consider the following code, which uses the f_sleep function to sleep for 10.5 seconds:

SELECT usera.f_sleep(10.5) FROM DUAL;

Alternative Ways

Aside from the two options presented above, there may be other ways to achieve the same result without using DBMS_LOCK.sleep, such as using the DBMS_PIPE package or implementing a custom sleep function.
