Implementing Schema Changes in a NOSQL Storage System How to Implement Schema Changes in a NoSQL Storage System: A Practical Guide

Introduction

When using a NoSQL store like SimpleDB, managing major schema changes can be quite tricky. Unlike traditional SQL databases, there are no equivalent update statements and due to the distributed nature of SimpleDB, there is no way to know when changes have filtered out to all nodes running the client software. In this blog post, we will explore some possible solutions to implement schema changes in a NoSQL storage system like SimpleDB.

The Problem

Let’s say we have been using SimpleDB for a few weeks and we need to make a change to a running database. We would like to change one of the object classes to have a unique ID, rather than a business name, and as it is referenced by another object, we will need to update the reference value in these objects. With a traditional SQL database, we would run a set of SQL statements as part of the client software deployment process. Although, this approach will not work with SimpleDB.

Possible Solutions

  • Solution 1

Each domain has a version number. The client software knows which version of the domain it should use. Write some code that copies the data from one domain version to another, making any required changes as you go. You can then install new client software that then accesses the new domain version. This approach will not work unless you can ‘freeze’ all write access during the update process.

  • Solution 2

Each item has a version attribute that indicates the format used when it was stored. The client uses this attribute when loading the object into memory. Objects can then be converted to the latest format when it is written back to SimpleDB. The problem with this is that the new software needs to be deployed to all servers before any writes in the new format occur, or clients running the old software will not know how to read the new format.

Practical Example

Let’s take a closer look at Solution 2 with some code examples. Let’s say we have an object in SimpleDB that looks like this:

{ 
  "id": "123abc", 
  "name": "Company A", 
  "employees": ["456def", "789ghi"]
}

We want to change the ID to be unique rather than a business name. We could update the object to look like this:

{ 
  "id": "uniqueID-123abc", 
  "name": "Company A", 
  "employees": ["uniqueID-456def", "uniqueID-789ghi"]
}

To implement this change in our application, we can create a function to convert the old format to the new format:

function convertToNewFormat(obj) {
  const newID = `uniqueID-${obj.id}`;
  const newEmployees = obj.employees.map(employeeID => `uniqueID-${employeeID}`);
  return {
      ...obj,
      id: newID,
      employees: newEmployees
  };
}

Now, when we fetch an object from SimpleDB, we can check if it is in the old format and convert it if necessary before using it in our application:

function getObjectFromSimpleDB(id) {
  const obj = simpleDB.getObject(id);
  const isObjectInOldFormat = !obj.id.startsWith("uniqueID-");
  
  if (isObjectInOldFormat) {
    const updatedObj = convertToNewFormat(obj);
    simpleDB.saveObject(updatedObj);
    return updatedObj;
  }
  
  return obj;
}

With this approach, we don’t need to worry about deploying the new software to all servers before any writes in the new format occur. The old software can continue to write objects in the old format, and the new software will automatically convert them to the new format when they are read.

Alternative Solutions

There are other possible solutions to this problem, such as using an external tool to perform the schema change, but they are more complex and may not be suitable for all use cases.

Summary

Implementing schema changes in a NoSQL storage system like SimpleDB can be challenging, but with careful planning and the right approach, it is possible to make these changes without disrupting the application. Using an intermediate version of the domain or adding a version attribute to each item are two possible solutions to this problem. We have seen an example of how to implement the second solution in our application, using a function to convert objects from the old format to the new format.
