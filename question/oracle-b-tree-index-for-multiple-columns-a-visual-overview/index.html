ORACLE: B-Tree Index for Multiple Columns: A Visual Overview B-Tree Index on More Than One Column Explained
B-tree indexes are commonly used in databases to improve the performance of queries. Essentially, it’s a data structure that allows a database to efficiently search, insert, and delete records. Although, B-trees can get more complex when there is more than one column indexed on them.

What is a B-Tree Index?

A B-tree is a balanced search tree that is commonly used to index data in databases. It’s an ordered data structure that keeps keys and values in a specific order so that searches and other operations can be performed efficiently.

When you create an index in a database, the index is essentially a data structure that helps to speed up queries. When a query is executed, the database engine searches the index first to find the relevant records quickly. This is much faster than searching the entire table every time a query is run.

Each node in a B-tree index has a fixed size, which means that access to a node is always a fixed number of disk I/O operations away. This is what makes B-trees so efficient - because every node has the same size, accessing and searching the tree is predictable and fast.

Creating a Multiple Column B-Tree Index

In most implementations of B-trees, the key is simply a longer key that includes all of the key values, separated by a delimiter. When you create an index with multiple columns, the key values are concatenated together to form a single key.

Let’s consider the following example:

table customer:
id    number
name   varchar
phone_number   varchar
city   varchar

You can create an index on multiple columns by using the following syntax:

CREATE INDEX idx_customer ON customer (id, name, city);

This creates an index on the id, name, and city columns. When you query the database using this index, the search will be performed using all three columns.

How Multiple Column B-Tree Index Works

When you search the multiple column B-tree index, the key value is a concatenation of all of the indexed columns. For example, the key value for the record with id 123499, name John Doe, and city Conway, NH would be:

"123499|John Doe|Conway, NH"

The database engine uses this concatenated key to search the B-tree. The search begins at the root node of the B-tree and follows the tree structure down to the leaf nodes until it finds the relevant records.

If you run the following query:

SELECT id, name 
FROM customer
WHERE city = 'My City';

The database engine will use the index on the id, name, and city columns to perform the search. It will begin at the root node of the B-tree and follow the tree structure down to the leaf nodes until it finds all of the records where the city is ‘My City’.

The intermediate tree nodes also have the concatenated key values of the indexed columns. This means that the database engine can use these intermediate nodes to “cover” the query. In other words, the database engine can use the intermediate nodes to return the results of the query without having to go to the leaf node.

For example, if the query is to find the Name and City given the ID, since the ID is first in the index, the index can search by this efficiently. Once in the intermediate node, it can “parse” the Name and City, from the key, and doesn’t need to go to the leaf node to read the same.

If you add another column to the SELECT statement, such as:

SELECT id, name, phone_number
FROM customer
WHERE city = 'My City';

The database engine will need to follow the B-tree down to the leaf nodes to retrieve the phone_number value. This is because the intermediate nodes only have the concatenated key values of the indexed columns.

Recap

B-tree indexes are a amazing tool that can be used to improve the performance of database queries. When you create an index on multiple columns, the key is a concatenation of all of the indexed columns. This allows the database engine to efficiently search, insert, and delete records based on the values of multiple columns.
