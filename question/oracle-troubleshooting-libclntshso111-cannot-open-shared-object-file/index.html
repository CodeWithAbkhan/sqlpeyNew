ORACLE: Troubleshooting libclntshso111: Cannot Open Shared Object File Possible blog post:

Title: Dealing with “libclntsh.so.11.1: cannot open shared object file” when using cx_Oracle in Python scripts

Summary: When scheduling a Python script with cx_Oracle module using icrontab, you may encounter the error message “libclntsh.so.11.1: cannot open shared object file” due to missing or incorrect environment variables. This blog post provides solutions to fix the issue, including setting environment variables in cron, adding library paths to ld.so configuration, creating symbolic links for xlibx.so libraries, and including user’s profile in the shell script.

Tags: cx_Oracle, Python, icrontab, environment variables, ld.so, symbolic links, bash profile, shell script.

Introduction: If you work with Oracle databases and need to schedule tasks on Linux using icrontab, you may face some challenges when importing cx_Oracle module in your Python scripts. This module allows you to connect to Oracle databases and execute SQL queries, but it requires specific environment variables and library paths that may not be set correctly in the cron environment. In this blog post, we will explore different solutions to solve the “libclntsh.so.11.1: cannot open shared object file” issue and run cx_Oracle scripts smoothly.

Solution #1: Setting environment variables in cron

One possible cause of the “libclntsh.so.11.1” error is that the ORACLE_HOME and LD_LIBRARY_PATH variables are not set correctly in cron environment. To fix this, we need to modify the crontab file to include these variables before invoking the Python script. For example:

# crontab -e
ORACLE_HOME=/u01/app/oracle/product/11.2.0/xe
LD_LIBRARY_PATH=/u01/app/oracle/product/11.2.0/xe/lib
PATH=/usr/local/bin:/usr/bin:/bin

*/5 * * * * /usr/bin/python /path/to/script.py

Here, we set the ORACLE_HOME and LD_LIBRARY_PATH variables to the correct Oracle installation path, and add them to the PATH variable for good measure. Then, we schedule the Python script to run every 5 minutes using Python interpreter from /usr/bin.

Solution #2: Adding library paths to ld.so configuration

Another possible cause of the issue is that the Oracle libraries are not included in the ld.so configuration, which is used to locate shared libraries at runtime. To fix this, we need to add the library path to ld.so.conf file or a separate file in ld.so.conf.d directory. For example:

# vi /etc/ld.so.conf.d/oracle.conf
/u01/app/oracle/product/11.2.0/xe/lib

# ldconfig

Here, we create a new file oracle.conf in ld.so.conf.d directory, and add the library path to it. Then, we run ldconfig to update the ld.so cache.

Solution #3: Creating symbolic links for xlibx.so libraries

If the solutions above still don’t work, we can try creating symbolic links for all the xlibx.so libraries in Oracle installation directory to /lib directory. This is not the cleanest solution, but it has worked for some users experiencing the same issue. Here’s how to do it:

# cd $ORACLE_HOME/lib
# for f in `ls ./*.so*`; do;
  sudo ln -s $ORACLE_HOME/lib/$f /lib/$f 
  done

Here, we change to the Oracle installation directory and loop through all the xlibx.so shared libraries. We create a symbolic link for each library in /lib directory using the ln -s command.

Solution #4: Including user’s profile in the shell script

Lastly, if none of the solutions above work, we can include user’s profile in the shell script that invokes the Python script. This will ensure that all the necessary environment variables and paths are set correctly. For example:

# shell script scheduled in icrontab
#!/bin/bash
source /home/user/.bash_profile
/usr/bin/python /path/to/script.py

Here, we source the user’s .bash_profile file to load all the environment variables and paths, then we run the Python script using Python interpreter from /usr/bin.

Recap:

When using cx_Oracle module in Python scripts, you may encounter the “libclntsh.so.11.1” error when scheduling tasks in cron using icrontab. This error is caused by missing or incorrect environment variables and library paths. To fix it, we can set environment variables in cron, add library paths to ld.so configuration, create symbolic links for xlibx.so libraries, or include user’s profile in the shell script. By following these solutions, we can ensure that our Python scripts with cx_Oracle module run smoothly and reliably on Linux.
