How to Use SKIP LOCKED to Retrieve TOP N Rows in Oracle In this question, we want to implement a queue-like table in Oracle by selecting a certain number of rows, skipping currently locked rows, and ensuring that we retrieve a specific number of eligible rows.

To achieve this, we can use the FOR UPDATE SKIP LOCKED clause to lock the selected rows and skip any rows that are currently locked by another transaction. Although, this alone does not guarantee that we retrieve a certain number of rows, as Oracle applies the WHERE predicate before skipping locked rows.

To overcome this issue, we can use a subquery to first select a larger number of rows (N + X), where N is the desired number of rows and X is a buffer to ensure we retrieve enough rows after skipping locked ones. We then apply the FOR UPDATE SKIP LOCKED clause to this subquery to lock and skip any locked rows.

Lastly, we use another query to filter and return only the top N rows from the locked rows selected in the subquery. This query can take advantage of Oracle’s ROWNUM pseudo-column to limit the results.

Here’s an example implementation:

-- Select top 5 eligible rows, skipping locked ones
SELECT qt.ID
FROM (
  -- Subquery to select N + X rows and skip locked ones
  SELECT *
  FROM QueueTest
  WHERE Locked IS NULL
  ORDER BY Priority DESC
  FOR UPDATE SKIP LOCKED
) qt
WHERE ROWNUM <= 5 -- Filter top 5 rows
ORDER BY qt.Priority DESC;

In this example, we first select N + X rows from the QueueTest table that have NULL values in the Locked column and are ordered by Priority in descending order. We apply the FOR UPDATE SKIP LOCKED clause to this subquery to lock and skip any rows that are currently locked by another transaction.

In the outer query, we use the ROWNUM pseudo-column to filter and return only the top 5 rows from the locked rows selected in the subquery. We also order the results by Priority in descending order.

Note that the ORDER BY clause in the subquery is important to ensure that we select the highest-priority rows first. Without it, Oracle may select rows in an arbitrary order, which could lead to inconsistent results.

More, it’s important to use a buffer value X that is large enough to ensure we retrieve enough eligible rows after skipping locked ones. The appropriate value for X will depend on the characteristics of the application and the database workload.
