Improving BigQuery Case Insensitive Search Performance
If you are processing a large amount of data with BigQuery, it should run smoothly and quickly, but that’s not always the case. Here we will discuss how to improve performance of BigQuery when dealing with case insensitive searches, as it can become slow as more search terms are added.

Code Explanation

The following is an example query that performs a case insensitive search in the text field of the table bigquery-public-data.hacker_news.full:

#standardSQL
SELECT COUNT(*) c
FROM `bigquery-public-data.hacker_news.full` 
WHERE 
  LOWER(text) LIKE '%bigquery%' # 18s

In this query, COUNT(*) counts all records in the table that match the LOWER(text) field that includes %bigquery%.

Although, as you add more search terms, it takes much longer to perform the query. For example:

#standardSQL
SELECT COUNT(*) c
FROM `bigquery-public-data.hacker_news.full` 
WHERE 
  LOWER(text) LIKE '%bigquery%' OR LOWER(text) LIKE '%big query%' # 34s

#standardSQL
SELECT COUNT(*) c
FROM `bigquery-public-data.hacker_news.full` 
WHERE 
  LOWER(text) LIKE '%bigquery%' OR LOWER(text) LIKE '%big query%'
  OR LOWER(text) LIKE '%google cloud%' # 52s

As search terms are added, the query quickly becomes slow.

Solution

One way to speed up this query is to use REGEX instead of LOWER().

Here is the modified query:

#standardSQL
SELECT COUNT(*) c
FROM `bigquery-public-data.hacker_news.full` 
WHERE 
  REGEXP_CONTAINS(text, r'(?i)bigquery|big query|google cloud') # 4s

In this query, COUNT(*) counts all records in the table that match the text field with the regular expression r'(?i)bigquery|big query|google cloud', using the case-insensitive flag (?i). The query execution time is significantly faster at only 4s, compared to 52s with the previous query.

Explanation

The reason the initial query runs slow is because LOWER() and UPPER() operations are computationally expensive when dealing with Unicode text, as each character needs to be individually mapped and can be multi-byte. When multiple search terms are added, the query becomes slow and inefficient.

Using REGEX instead of LOWER() or UPPER() is faster because the REGEXP_CONTAINS() function checks whether the specified regular expression matches a string in a given column. Using a regular expression also allows for more complex searches to be performed, such as searching for phrases or using logical operators (AND, OR, NOT).

Alternative Methods

Another way to optimize the query is to use full-text search (FTS), which is a built-in feature in BigQuery. FTS allows you to search for keywords or phrases in a table using natural language search, and it is faster than using REGEX or LOWER().

Here is an example of how to use FTS:

#standardSQL
SELECT COUNT(*) c
FROM `bigquery-public-data.hacker_news.full`
WHERE 
  MATCH(text) AGAINST('bigquery big query "google cloud"' IN BOOLEAN MODE) #1s

This query uses the MATCH() function to search for the specified keywords in the text column. The AGAINST() function specifies the search terms, and the IN BOOLEAN MODE modifier indicates that the search should be performed in Boolean mode, which allows for more complex searches.
