Saving a query result into a partitioned bigquery table

Summary This post describes how to save the result of a BigQuery query into a partitioned table. It includes a step-by-step guide on using StandardSQL and DML to insert data, creating a new partitioned table, and using CLI to query and create a table from query results.

Inserting data into a partitioned table

You can insert data into a partitioned BigQuery table similar to a non-partitioned table. Here, we’ll use StandardSQL and DML to write an INSERT statement that will insert the result of a query. If the table already exists and is partitioned, the data will be inserted into an appropriate partition based on the time_partitioning_field’s (column) date value.

Using #standardSQL and DML

INSERT INTO `project.dataset.table` (field1, field2, field3)
SELECT *
FROM `anothertable`
WHERE 'this is my query'

Here, we’re creating an INSERT statement and selecting the fields from another table as the source data. We’re using anothertable to extract the data based on some query. We’re inserting the data into project.dataset.table. Note that your data source and destination tables cannot be the same table. If your table is already partitioned by one of the fields, then everything will work as expected, and the query result will be saved on the same partition of the table.

Creating a new partitioned table

If you want to create a new partitioned table instead of inserting data into an existing partitioned table, you can create a new partitioned table with the CREATE TABLE statement. Suppose you want to create a new partitioned table with the name table, the dataset dataset, and the project_id of project. Here’s how you can execute this in BigQuery:

CREATE TABLE `project.dataset.table`
PARTITION BY DATE(timestamp)
AS
SELECT field1, field2, field3, timestamp
FROM `yourtable`
WHERE 'yourquery'

In this example, we are creating a partitioned table with the name table, a dataset name dataset, and a project id of project. Here, we’re partitioning the data based on the timestamp column. We’re selecting the field1, field2, field3, and timestamp columns from yourtable. The partitions will be created based on the date component of the timestamp column.

Querying data and creating table using CLI

You cannot create a partitioned table using query result in BigQuery web UI. Although, you can use CLI for that. Here’s an example of how to create a table from a query using the CLI:

bq --location=[LOCATION] query --destination_table [PROJECT_ID]:[DATASET].[TABLE] --time_partitioning_field [COLUMN] --use_legacy_sql=false '[QUERY]'

Here, we’re using string substitution to enter the values for LOCATION, PROJECT_ID, DATASET, TABLE, COLUMN, and QUERY. This command connects to the BigQuery service and executes the provided SQL statement.

Alternative ways

If you don’t want to use SQL commands or want an alternative way, you can consider using Dataflow/Apache Beam. Dataflow deals with partitioning for you and allows you to transform the data before it lands on BigQuery. Here is a link to the official Google Cloud documentation of how to Write to partitioned tables using Dataflow for more information on this approach.
