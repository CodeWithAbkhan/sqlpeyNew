ORACLE: Mapping Foreign Keys with Custom Column Names How to map a foreign key in Entity Framework 4.3 code-first with a custom column name?

Problem:

When using Entity Framework 4.3 code-first with Oracle, you may encounter an issue when mapping a foreign key with a custom column name. The following error message may appear:

“System.InvalidOperationException: The ForeignKeyAttribute on property ‘WidgetSequence’ on type ‘WidgetDistributor.WidgetEntity’ is not valid. The foreign key name ‘WIDGETSEQUENCE_ID’ was not found on the dependent type ‘WidgetDistributor.WidgetEntity’. The Name value should be a comma-separated list of foreign key property names.”

Solution:

To fix this issue, you must specify the foreign key property name instead of the foreign key column name. There are several ways to do this using data annotations or fluent syntax.

Data Annotations:

Here are three different ways to implement the reference using data annotations:

  1. ForeignKey with an associated property - version 1:

    [Table(“WIDGETENTITIES”)] public class WidgetEntity {

     [Column("WIDGETENTITY_ID")]
 public int Id { get; set; }

 [Column("WIDGETSEQUENCE_ID")]
 public int WidgetSequenceId { get; set; }

 [ForeignKey("WidgetSequenceId")]
 public WidgetSequence Sequence { get; set; }

 // and other properties that map correctly

    }

    [Table(“WIDGETSEQUENCES”)] public class WidgetSequence {

     [Column("WIDGETSEQUENCE_ID")]
 public int Id { get; set; }

 [Column("NUMBER")]
 public int Number { get; set; }

    }

     			  In this version, the foreign key property name is explicit, and the ForeignKey attribute is used to associate it with the navigation property.  2. ForeignKey with an associated property - version 2:

    [Table(“WIDGETENTITIES”)] public class WidgetEntity {

     [Column("WIDGETENTITY_ID")]
 public int Id { get; set; }

 [ForeignKey("Sequence")]
 [Column("WIDGETSEQUENCE_ID")]
 public int WidgetSequenceId { get; set; }

 public WidgetSequence Sequence { get; set; }

 // and other properties that map correctly

    }

    [Table(“WIDGETSEQUENCES”)] public class WidgetSequence {

     [Column("WIDGETSEQUENCE_ID")]
 public int Id { get; set; }

 [Column("NUMBER")]
 public int Number { get; set; }

    }

In this version, the ForeignKey attribute is associated with the navigation property, and the foreign key property name is inferred from the navigation property name. 3. InverseProperty with an associated property:

[Table("WIDGETENTITIES")]
public class WidgetEntity {

    [Column("WIDGETENTITY_ID")]
    public int Id { get; set; }

    [Column("WIDGETSEQUENCE_ID")]
    public int WidgetSequenceId { get; set; }

    [InverseProperty("Entities")]
    public WidgetSequence Sequence { get; set; }

    // and other properties that map correctly
}

[Table("WIDGETSEQUENCES")]
public class WidgetSequence { 

    [Column("WIDGETSEQUENCE_ID")]
    public int Id { get; set; }

    [Column("NUMBER")]
    public int Number { get; set; }

    public ICollection Entities { get; set; }
}

In this version, the InverseProperty attribute is used to associate the foreign key property with the navigation property. Fluent Syntax: Here’s an example using fluent syntax to specify the foreign key property:

modelBuilder.Entity()
    .HasRequired(e => e.Sequence)
    .WithMany()
    .HasForeignKey(e => e.WidgetSequenceId);

In this example, the HasForeignKey method is used to associate the foreign key property with the navigation property. Alternative Ways: There are no other ways to map a foreign key with a custom column name; data annotations or fluent syntax are the only options.
