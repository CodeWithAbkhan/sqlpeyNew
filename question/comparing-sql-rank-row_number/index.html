Comparing SQL RANK() and ROW_NUMBER() In SQL, the RANK() and ROW_NUMBER() functions are used to assign a unique number to each row in a result set. This is commonly used in cases where you want to rank results based on a certain criteria, such as sorting by ID or date.

Learning RANK() and ROW_NUMBER()

The main difference between these two functions is how they handle tied values. If there are multiple rows with the same value for the ordered column, RANK() will give them all the same ranking, while ROW_NUMBER() will assign them unique numbers arbitrarily.

To make this clear, let’s take a look at an example. Suppose we have a table named SubStyle that contains columns for ID, Description, and StyleID. We can use the following queries to assign a ranking or row number to each row within the partition defined by StyleID:

SELECT ID, [Description], RANK()       OVER(PARTITION BY StyleID ORDER BY ID) as 'Rank'      FROM SubStyle
SELECT ID, [Description], ROW_NUMBER() OVER(PARTITION BY StyleID ORDER BY ID) as 'RowNumber' FROM SubStyle

Here, we are partitioning by the StyleID column, and ordering by the ID column. For any rows that have the same value for ID within the same StyleID, RANK() will give them the same value while ROW_NUMBER() will assign them different arbitrary values.

Example

To illustrate the difference between these two functions, let’s consider a simple example. Suppose we have the following data in our SubStyle table:

ID   | Description | StyleID
---------------------------
1    |  Small      |   1
2    |  Medium     |   1
3    |  Large      |   1
4    |  Small      |   2
5    |  Medium     |   2
6    |  Large      |   2
7    |  Small      |   2

Now, let’s apply the two queries to this table:

SELECT ID, [Description], RANK()       OVER(PARTITION BY StyleID ORDER BY ID) as 'Rank'      FROM SubStyle
SELECT ID, [Description], ROW_NUMBER() OVER(PARTITION BY StyleID ORDER BY ID) as 'RowNumber' FROM SubStyle

This will give us the following results:

ID   | Description | Rank | RowNumber
-----------------------------------------
1    |  Small      | 1    | 1
2    |  Medium     | 2    | 2
3    |  Large      | 3    | 3
4    |  Small      | 1    | 1
5    |  Medium     | 2    | 2
6    |  Large      | 3    | 3
7    |  Small      | 3    | 4

Note that for each partition (i.e. each unique StyleID), the ranking values in the RANK() column are the same for tied values, while the row numbers in the ROW_NUMBER() column are assigned arbitrarily.

Alternative Ways

While these two functions are the most common way to assign rankings in SQL, there are other techniques that can also be used. For example, you can use subqueries to count the number of rows with a lower value, then add 1 to get the ranking:

SELECT ID, [Description], 
       (SELECT COUNT(*) 
        FROM SubStyle s2 
        WHERE s2.ID < s1.ID AND s2.StyleID = s1.StyleID) + 1 AS Rank 
FROM SubStyle s1

This subquery counts the number of rows in the partition that have a lower value for ID, and adds 1 to get the ranking. This approach can be useful in cases where you don’t want to use window functions or want more control over the ranking algorithm.

Recap

Overall, the main difference between RANK() and ROW_NUMBER() in SQL is how they handle tied values. RANK() will assign the same ranking to all tied values, while ROW_NUMBER() will assign arbitrary values.
