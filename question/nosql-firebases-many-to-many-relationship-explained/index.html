NOSQL: Firebase’s Many-to-Many Relationship Explained In this Q&A Session, we will discuss how to model a many-to-many relationship in Firebase. Specifically, we will look at how to answer the questions “Given a Company, who are the current Contractors?” and “Given a Contractor what Companies are they working for?”.

Firstly, let’s consider a straightforward way of modeling this relationship in Firebase. We will create three top-level nodes:

  • contractors
  • companies
  • companyAndContractorsAssignment (the many-to-many connector table)

Under the contractors and companies nodes, we will store the data for each contractor and company, respectively. Within the companyAndContractorsAssignment node, we will create a unique key for each company and associate multiple contractor IDs with each key. An example data structure could look like this:

companyAndContractorsAssignment 
    - companyKey1
        - contractorKey1: true
        - contractorKey3: true
    - companyKey2
        - contractorKey2: true

To answer the question “Given a Company, who are the current Contractors?”, we would retrieve the associated keys within companyAndContractorsAssignment, and then pull the contractor data from the contractors node using those keys.

To answer the question “Given a Contractor what Companies are they working for?”, we would retrieve the contractor’s key, and then pull the company data from the companies node using the company keys associated with the contractor key in companyAndContractorsAssignment.

An alternative structure for modeling this relationship could involve creating four top-level nodes:

  • contractors
  • companies
  • companyContractors
  • contractorCompanies

Under the contractors and companies nodes, we would store data for each contractor and company, respectively. In the companyContractors node, we would create a unique key for each company and associate multiple contractor keys with each key. In the contractorCompanies node, we would create a unique key for each contractor and associate multiple company keys with each key. An example data structure could look like this:

companyContractors 
    - companyKey1
        - contractorKey1: true
        - contractorKey3: true
    - companyKey2
        - contractorKey2: true 
        
contractorCompanies 
    - contractorKey1
        - companyKey1: true
    - contractorKey2
        - companyKey2: true
    - contractorKey3
        - companyKey1: true

This structure allows for bidirectional lookups of “contractors for a company” and “companies for a contractor”, without requiring a query. Although, the choice of structure depends on the specific use-case and data size.

In summary, there are two main ways to model a many-to-many relationship in Firebase: using a single many-to-many connector node or using two separate connector nodes (one for companies to contractors, and the other for contractors to companies). Each structure has its own benefits, and the choice depends on the specific needs of the application.
