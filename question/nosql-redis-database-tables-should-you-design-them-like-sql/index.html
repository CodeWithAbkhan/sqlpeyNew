NOSQL: Redis Database Tables: Should You Design Them Like SQL? How to Design a Redis Database Table Like SQL?
When it comes to designing a Redis database table like SQL, there are a few key elements to consider. Redis, like other NoSQL datastores, has different requirements based on what you’ll be doing, and there are several data structures in Redis that can be useful, depending on your needs. Let’s take a look at how to design a Redis database table like SQL with step-by-step instructions, code examples, and alternative ways to do it.

Step-by-Step Instructions

  1. Don’t be afraid to generate lots of key-value pairs. So feel free to store each row of the table in a different key.
  2. Use Redis’ hash map data type.
  3. Form the key name from primary key values of the table by a separator, such as “:”.
  4. Store the remaining fields as a hash.
  5. When you want to query a single row, directly form the key and retrieve its results.

Let’s take an example of a student database table structure:

id name college address
1  xxx   nnn     xn
2  yyy   nnm     yn
3  zzz   nnz     zn

If you want to get the student details based on the name in SQL like this: select * from student where name="xxx", you can use Redis hash like this:

redis 127.0.0.1:6379> hmset student:xxx id 1 college nnn address xn
OK
redis 127.0.0.1:6379> hgetall student:xxx
1) "id"
2) "1"
3) "college"
4) "nnn"
5) "address"
6) "xn"

If you want to query against college, then you might do something like adding a set in addition to the hashes:

redis 127.0.0.1:6379> sadd college:nnn student:xxx
(integer) 1
redis 127.0.0.1:6379> smembers college:nnn
1) "student:xxx"

With your data structured like this, if you wanted to find all information for names going to college xn, you would first select the set, then select each hash based on the name returned in the set.

Alternative Ways

An alternative way to structure the data in Redis is by using Redis sorted set. If you have a value that needs to be queried quickly, and you want a way to associate that value with other related data, a sorted set might be a better fit. A sorted set is an ordered set, in which each member is associated with a score. This score can be used to ordering the set.

In summary, when designing a Redis database table like SQL:

  • Don’t be afraid to generate lots of key-value pairs.
  • Use Redis’ hash map data type.
  • Form the key name from primary key values of the table by a separator, such as “:”.
  • Store the remaining fields as a hash.
  • When you want to query a single row, directly form the key and retrieve its results.
