Using ActiveRecord and NoSQL for Optimal Data Management Combining ActiveRecord and NoSQL for Optimal Data Storage

Introduction

As a Rails developer, you may have been working with ActiveRecord for years and be used to its ORM capabilities. Although, there are situations where NoSQL data storage may be more advantageous. In this Q&A Session, we will look at ways to combine the two technologies to achieve optimal data storage solutions.

Can You Use ActiveRecord with NoSQL?

Many NoSQL wrappers or gems seem to require the removal of ActiveRecord from the application. Although, this is not the case in every situation. For example, if you look at the Gemfile.lock file of this project, you can see that it uses ActiveRecord with Mongoid, a popular NoSQL datastore for Rails.

gem 'mongoid', '~> 4.0.0'
gem 'bson_ext'

Even if you use other gems that don’t require ActiveRecord, you shouldn’t remove it unless you have a valid reason to do so.

Using MongoDB with ActiveRecord

If you’re looking for a NoSQL datastore to use with ActiveRecord, MongoDB is a popular option. Here’s an example of how you can set up a Rails project with MongoDB:

# In Gemfile
gem 'mongoid', '~> 7.0.0'

# In config/application.rb
config.generators {|g| g.orm :mongoid }

# In config/mongoid.yml
development:
  clients:
    default:
      database: your_database
      hosts:
        - localhost:27017

In this example, we added the ‘mongoid’ gem to our Gemfile, set up the ORM to use Mongoid by default, and put our MongoDB configuration in the mongoid.yml file. To use MongoDB with ActiveRecord, we first need to configure the database connection in our Rails application. Here’s how we can set it up:

require 'mongoid'

# Create a Mongoid database
Mongoid.configure do |config|
  config.clients.default = {
    hosts: ['localhost:27017'],
    database: 'mydb',
    options: {
      read: :primary
    }
  }
end

# Create a MongoDB model
class User
  include Mongoid::Document
  field :name, type: String
  field :email, type: String
end

# Use ActiveRecord with MongoDB
class User < ActiveRecord::Base
  connect_to_mongo
end

In this example, we first require the ‘mongoid’ gem and configure the default client to use localhost on port 27017 and the ‘mydb’ database. Next, we create a User model using Mongoid’s document syntax, specifying two fields using the ‘field’ method. Lastly, we create a User model that inherits from ActiveRecord::Base and adds the ‘connect_to_mongo’ method to establish a connection to the Mongoid database.

Alternative Options

If your data isn’t very complex, you can also consider using Postgres with HStore or JSON datatypes, which can provide similar functionality as NoSQL datastores. Another option to consider is Redis, an in-memory data structure store often used as a database, cache, and message broker. Here’s an example of how to use Redis in a Rails project:

# In Gemfile
gem 'redis'

# In config/initializers/redis.rb
cache = Redis.new(url: ENV["REDIS_URL"])
$redis = Redis::Namespace.new(:your_namespace, redis: cache)

# In controller
def index
  $redis.set('key', 'value')
  value = $redis.get('key')
  render json: value
end

In this example, we first add the ‘redis’ gem to our Gemfile. Next, we create an initializer file that sets up a global variable ‘$redis’ to be a Redis::Namespace object. This object wraps a Redis connection, using the URL provided in the environment variable ‘REDIS_URL’. Lastly, we use ‘$redis’ as a cache in our Rails controller, using the ‘set’ and ‘get’ methods to store and retrieve a value, respectively.

Recap

In recap, while ActiveRecord is often used as the default ORM for Rails, there are situations where NoSQL datastores like MongoDB or Redis can be more beneficial. Although, it is possible to use ActiveRecord with these datastores and achieve optimal data storage solutions by configuring the appropriate libraries and models.]]>
