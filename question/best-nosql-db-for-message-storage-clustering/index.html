Best NoSQL DB for Message Storage Clustering? In this blog post, we will discuss about which clustered NoSQL DB to choose for message storing purpose. We will explore various NoSQL databases like Hbase, Riak and Cassandra, and compare their features against the requirements we have.

To begin with, let’s know the problem statement. We have an Erlang Chat Server that is already using MySQL for storing friend list and JOIN needed information. Now, we want to store the messages that a user has missed when he was offline and retrieve them later.

We have made a pre-selection of NoSQL databases, and we are left with three choices - Hbase, Riak and Cassandra. Out of these three, we have a preference for Riak due to its stable client library for Erlang. Although, we need to evaluate all three options based on the following requirements -

  1. Store from 1 to X messages per registered user.
  2. Get the number of stored messages per user.
  3. Retrieve all messages from a user at once.
  4. Delete all messages from a user at once.
  5. Delete all messages that are older than X months.

Let’s now evaluate each database in terms of these requirements -

Hbase Hbase is a column-oriented NoSQL database based on Google’s Bigtable. It is designed to handle large amounts of data and is usually used for Hadoop-based applications. It supports a schema-less data model and offers strong consistency.

Pros

  • Can handle large amounts of data. - Supports strong consistency. - Can be easily integrated with Hadoop.

Cons

  • Schema design can be tricky. - Not good for ad-hoc queries. - Limited support for secondary indexes.

Riak

Riak is a distributed NoSQL database that is highly available and fault-tolerant. It is based on Amazon’s Dynamo and is designed to store data that is replicated across multiple nodes. It supports a flexible data model and offers eventual consistency.

Pros

  • Highly available and fault-tolerant. - Flexible data model. - Offers eventual consistency. - Stable client library for Erlang.

Cons

  • Querying can be slow. - Limited query support. - Expensive compared to other NoSQL databases.

Cassandra

Cassandra is a distributed NoSQL database that is designed to handle large amounts of data across multiple commodity servers. It is based on Amazon’s Dynamo and supports a flexible data model. It offers high availability and fault-tolerance and is usually used for real-time applications.

Pros

  • Can handle large amounts of data. - Offers high availability and fault-tolerance. - Supports a flexible data model. - Good for real-time applications.

Cons

  • Can be difficult to set up. - Secondary indexes can be slow. - Poor support for ad-hoc queries. Based on the requirements we have and the evaluation of the three databases above, we can conclude that Riak is a good fit for our use case. It is highly available and fault-tolerant, supports a flexible data model, and offers eventual consistency. More, it has a stable client library for Erlang, which is a plus for us. Now, let’s look at how we can implement this using Riak. For storing the messages, we can use the plain Riak Key/Value operations, and for indexing them, we can use either CRDT Sets or Riak Search. If the collection size is small, the CRDT Sets data type would be a good fit. If the collection size is large, Riak Search would be a better option. Here’s a code snippet that shows how to store and retrieve messages from Riak using the plain Key/Value operations - var riak = require('riak-js').getClient(); // Store a message riak.save('messages', 'user1', { message: 'Hello World!' }, function(err, res) { if (err) { console.log('Error:', err); } else { console.log('Message stored:', res); } }); // Retrieve all messages for a user riak.getAll('messages', ['user1'], function(err, res) { if (err) { console.log('Error:', err); } else { console.log('Messages retrieved:', res); } }); // Delete all messages for a user riak.remove('messages', 'user1', function(err, res) { if (err) { console.log('Error:', err); } else { console.log('Messages deleted:', res); } }); In the code snippet above, we first store a message for the user ‘user1’ in the ‘messages’ bucket. We then retrieve all messages for the same user using the getAll() method. Lastly, we delete all messages for the same user using the remove() method. To summarize, based on our evaluation of various NoSQL databases against the requirements we have, Riak is a good fit for our use case. It provides high availability, fault-tolerance, and supports a flexible data model. We can use the plain Key/Value operations for storing messages and CRDT Sets or Riak Search for indexing them.]]>
