List and Order PostgreSQL Tables by Size
Summary:

This Q&A Session explains how to list and order PostgreSQL tables by size using SQL queries. The queries provide useful information about the schema name, table name, size in bytes, and human-readable format. The Q&A Session also includes a list of related functions and offers alternative ways to achieve the same results.

Listing and Ordering PostgreSQL Tables by Size:

To list all tables of a PostgreSQL database and order them by size, one can use the following SQL query:

SELECT  
schema\_name,  
relname,  
pg\_size\_pretty(table\_size) AS size,  
table\_size
    
FROM (  
SELECT  
pg\_catalog.pg\_namespace.nspname AS schema\_name,  
relname,  
pg\_relation\_size(pg\_catalog.pg\_class.oid) AS table\_size
    
FROM pg\_catalog.pg\_class  
JOIN pg\_catalog.pg\_namespace ON relnamespace = pg\_catalog.pg\_namespace.oid  
) t
    
WHERE schema\_name NOT LIKE 'pg\_%'
    
ORDER BY table\_size DESC;

The query starts with a subquery that retrieves the schema name, table name, and table size in bytes using the pg_catalog schema of PostgreSQL. The pg_relation_size function calculates the size of a relation (i.e., a table or index) based on its OID (object identifier).

Then, the main query uses the pg_size_pretty function to convert the table_size column into a human-readable format. The schema_name column is included to provide additional context to the results, and the NOT LIKE 'pg_%' condition excludes system schemas that start with ‘pg_’.

Lastly, the query orders the results by table size in descending order using the ORDER BY clause and the table_size column.

Alternative Ways:

One alternative way to achieve similar results is to use the pg_total_relation_size function instead of pg_relation_size. This function calculates the total size of a table and its indexes, and it can help in identifying tables with large indexes that may be affecting performance.

Another alternative is to filter the results by a specific schema or table name, which can be useful in large databases with many tables. For example:

SELECT  
table\_name,  
pg\_size\_pretty(pg\_total\_relation\_size(quote\_ident(table\_name))) AS total\_size  
FROM information\_schema.tables  
WHERE table\_schema = 'public'  
AND table\_name LIKE 'my\_table%'  
ORDER BY total\_size DESC;

This query lists the tables in the ‘public’ schema that start with ‘my_table’ and orders them by the total size of the table and its indexes.

List of Related Functions:

There are several PostgreSQL functions related to object sizes that can be useful when working with large databases:

  • pg_size_pretty(numeric_value) - Converts the specified number of bytes into a human-readable format, such as ‘123 MB’ or ‘1 GB’.
  • pg_database_size(db_name) - Calculates the size of the specified database in bytes.
  • pg_total_relation_size(relation_name) - Calculates the total size of the specified table and its indexes in bytes.
  • pg_relation_size(relation_name) - Calculates the size of the specified relation (i.e., a table or index) in bytes.
  • pg_indexes_size(relation_name) - Calculates the size of the specified index in bytes.
  • current_database() - Returns the name of the currently connected database.

Practical Examples:

Here are some practical examples of how to use these functions:

  • To get the size of a specific table and its indexes:
SELECT pg\_size\_pretty(pg\_total\_relation\_size('my\_table'));
  • To get the size of a specific index:
SELECT pg\_size\_pretty(pg\_indexes\_size('my\_index'));
  • To get the size of the current database:
SELECT pg\_size\_pretty(pg\_database\_size(current\_database()));
