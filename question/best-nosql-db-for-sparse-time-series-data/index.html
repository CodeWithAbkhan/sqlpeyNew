Best NoSQL DB for Sparse Time Series Data?
In this blog post, we will discuss which NoSQL database to use for storing sparse time series data. We will answer the question by looking at the use case and requirements and then recommending a suitable NoSQL database.

Use Case and Requirements

We have a (growing) set of symbols, and for each symbol, we have a list of (time,value) tuples that increase over time. Not all symbols will be updated, and new symbols may be added. We want a NoSQL database that can:

  • Add symbols with an initial one-element (tuple) list.
  • Update symbols with a new tuple (append that tuple to the list of that symbol).
  • Read the data for a given symbol (ideally, let us specify the time frame for which the data should be returned).
  • Allow atomic create and update operations.
  • Perform well, even when dealing with large amounts of data.

Recommendation

After considering the requirements, we recommend using Apache Cassandra as the NoSQL database for storing sparse time series data. Here’s why:

  • Cassandra has a distributed architecture that allows for high scalability and availability. It can handle large amounts of data with high write and read throughput.
  • Cassandra supports dynamic columns, which allow for flexible data modeling. Each symbol can be a new row, and each time entry can be a new column for that relevant row. Each value (can be more than a single value) is the value part of the time entry. This design translates well to other NoSQL databases that have dynamic columns.
  • Cassandra’s column range queries allow us to read the data for a single symbol and using a range if necessary. All data for any single symbol is by definition sorted (column name sort) and always stored on the same node. There is no cross-node communication for simple queries.
  • Cassandra supports atomicity for write operations. Cassandra’s lightweight transactions allow for atomic writes for a single partition key.
  • Cassandra has good support for time series data with its Time Window Compaction Strategy. This compaction strategy allows data to be automatically expired based on the data’s timestamp.

Example Code

Let’s take a look at how we can use Cassandra for storing sparse time series data. We’ll use the Python driver for Cassandra, called cassandra-driver.

First, we need to create a keyspace and a table.

from cassandra.cluster import Cluster
    
cluster = Cluster(['localhost'])  
session = cluster.connect()
    
session.execute("""  
CREATE KEYSPACE IF NOT EXISTS my\_keyspace  
WITH REPLICATION = { 'class': 'SimpleStrategy', 'replication\_factor': '1' }  
""")  
session.set\_keyspace('my\_keyspace')
    
session.execute("""  
CREATE TABLE IF NOT EXISTS symbol\_data (  
symbol text,  
time timestamp,  
value double,  
PRIMARY KEY (symbol, time)  
) WITH CLUSTERING ORDER BY (time ASC)  
""")

We created a keyspace called my_keyspace and a table called symbol_data. The table has three columns:

  • symbol (text): the symbol identifier
  • time (timestamp): the timestamp for the data point
  • value (double): the value for the data point

The primary key for the table is composed of two columns: symbol and time, and the partition key is symbol. We also specified the clustering order as time ascending.

Now let’s add a symbol with an initial one-element tuple list.

from cassandra.query import SimpleStatement
    
symbol = 'AAPL'  
time = datetime.datetime(2022, 1, 1, 0, 0)  
value = 100.0
    
session.execute(SimpleStatement("""  
INSERT INTO symbol\_data (symbol, time, value) VALUES (%(symbol)s, %(time)s, %(value)s)  
"""), {'symbol': symbol, 'time': time, 'value': value})

This code adds a new row to the symbol_data table with symbol ‘AAPL’, time ‘2022-01-01 00:00:00’ and value 100.0.

Let’s update the symbol with a new tuple.

new\_time = datetime.datetime(2022, 1, 2, 0, 0)  
new\_value = 110.0
    
session.execute(SimpleStatement("""  
INSERT INTO symbol\_data (symbol, time, value) VALUES (%(symbol)s, %(new\_time)s, %(new\_value)s)  
"""), {'symbol': symbol, 'new\_time': new\_time, 'new\_value': new\_value})

This code adds a new column to the row with symbol ‘AAPL’ and adds the new time and value.

Lastly, let’s read the data for a given symbol.

from cassandra.query import BoundStatement
    
symbol = 'AAPL'  
start\_time = datetime.datetime(2022, 1, 1, 0, 0)  
end\_time = datetime.datetime(2022, 1, 2, 0, 0)
    
statement = session.prepare("""  
SELECT time, value FROM symbol\_data WHERE symbol = ? AND time &gt;= ? AND time &lt; ? """) bound\_statement = statement.bind([symbol, start\_time, end\_time]) results = session.execute(bound\_statement) for row in results: print(row.time, row.value) ``` This code executes a SELECT query that reads all columns for a given symbol and within a specified time range. The result is returned as a list of rows, with each row containing a time and value pair. Alternative Ways There are other NoSQL databases that can be used for storing sparse time series data, such as MongoDB and Apache HBase. MongoDB can use its capped collections to ensure a fixed amount of storage is used while maintaining insertion order. HBase can use row keys that include timestamps to enable range queries over a certain time period. Recap When choosing a NoSQL database for storing sparse time series data, Apache Cassandra is a good choice due to its distributed architecture, support for dynamic columns, and time series data features. With Cassandra, we can easily add and update symbols and read data for a given symbol within a certain time frame.
