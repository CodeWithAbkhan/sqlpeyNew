ORACLE: Oracle: Functions vs Procedures Functions vs Procedures in Oracle: What are the differences?

Introduction

When it comes to creating code in Oracle, there are two main types of subprograms: functions and procedures. While both are used to group a section of code to be executed together, they have some differences. In this Q&A Session, we will explore the differences between functions and procedures in Oracle.

Functions vs Procedures: The Main Differences

While functions and procedures serve a similar purpose, they differ in a few key ways:

  1. Return Value

    The main difference between functions and procedures is that functions must return a value by default. Functions usually return a single value, while procedures can return multiple values (out) or no value (void). It is possible to use OUT parameters in functions; however, they are not recommended as they restrict the function’s use in SQL Statements.

  2. Use in SQL

    Functions can be used in SQL statements like SELECT, INSERT, UPDATE, DELETE, and MERGE, while procedures cannot. Functions can be used in typical SQL statements since they return a value while procedures cannot be used in SQL statements.

  3. Business Logic vs Computations

    In general, functions are used for computations, while procedures are used for executing business logic. For example, a function may calculate the average price of all items, while a procedure may execute the business logic of updating the inventory for those items.

Why Use Procedures If Functions Can Do Everything?

While it is true that functions can do most of what procedures can do, there are some cases where it is advisable to use procedures:

  • When you need to insert, update, or delete data, you should use procedures. Procedures help you to encapsulate the business logic related to modifying data in your database.
  • When performing operations that do not need to return a value, for example, creating a new record in a table or sending an email, you should use a procedure. Procedures can take in multiple parameters and perform a series of tasks to achieve a specific goal.
  • When you need to debug a section of code, procedures are often more straightforward to debug than functions. Procedures can have multiple input and output parameters that can help you to identify problem areas quickly.

Function-Based Indexes

One area where functions can improve performance over procedures is with Function-Based Indexes. A Function-Based Index(FFI) is an index built from a function. The advantage of using these indexes is that they allow computations to be performed when retrieving results, which can help in complex analytical queries. The FFI is built from a function that is executed for each row in the table being indexed. The output of the function is used instead of the actual column value, enabling faster data retrieval. Functions can make use of these indexes, and procedures cannot.

Examples:

Here are some examples to help illustrate the differences between functions and procedures:

Example 1: Function

CREATE OR REPLACE FUNCTION average_price
RETURN NUMBER
IS
   total_items NUMBER;
   total_price NUMBER;
   avg_price NUMBER;
BEGIN
   SELECT COUNT(*), SUM(price)
   INTO total_items, total_price
   FROM items;
   
   avg_price := total_price / total_items;
   RETURN(avg_price);
END;

This function calculates the average price of all items in the database.

Example 2: Procedure

CREATE OR REPLACE PROCEDURE update_inventory
   ( p_item_id IN NUMBER, p_qty IN NUMBER, p_type IN VARCHAR2)
IS
BEGIN
   IF p_type = 'ADD' THEN
      UPDATE items
      SET item_qty = item_qty + p_qty 
      WHERE item_id = p_item_id;
   ELSIF p_type = 'REMOVE' THEN
      UPDATE items
      SET item_qty = item_qty - p_qty
      WHERE item_id = p_item_id;
   END IF;
END;

This procedure updates the inventory when an item is added or removed from the database.

Alternative Ways

There are no alternative ways to creating subprograms in Oracle. You can either create a function or a procedure. Although, Oracle does provide a way to create Function-Based Indexes to improve query performance.

Recap

Functions and procedures serve a purpose in Oracle database development. Although functions and procedures can perform some of the same tasks, they differ in various ways. While functions are mainly used for computations, procedures are used for executing business logic. Procedures are often more suited to debugging complex code since they can have multiple parameters. The practicability of both procedures and functions ensures that developers have a range of tools to work with in creating robust, efficient code in Oracle. ]]>
