How to add an identity to an existing column in SQL Server

Suppose you need to change the primary key of a table to an identity column, and there are already a number of rows in the table. In this case, you cannot alter the existing column to have an identity property. Instead, you have two options, which are:

  1. Create a new table with identity and drop the existing table
  2. Create a new column with identity and drop the existing column

You must choose the option that best suits your needs. If you want to retain the existing data values on the newly created identity column, you should create a new table with identity and drop the existing table. Although, if you do not need to retain the existing data values, you can create a new column with identity and drop the existing column.

Option 1: Create a new table with identity and drop the existing table

Here are the steps to create a new table with identity and drop the existing table:

Create a new table

First, you need to create a new table with an identity column:

CREATE TABLE dbo.New_Table
(
  Id INT NOT NULL
     IDENTITY(1, 1),
  Data VARCHAR(50) NULL
)
ON [PRIMARY];
GO

This command creates a new table called ‘New_Table’ with an identity column called ‘Id’. The identity column will start at 1 and increment by 1 for each new row inserted into the table.

Set identity insert on

Next, you need to set identity insert on for the new table:

SET IDENTITY_INSERT dbo.New_Table ON;
GO

This command allows you to insert rows with explicit values into an identity column in the new table. In other words, it allows you to insert rows with the same ‘Id’ values as in the existing table.

Insert existing data into new table

Once identity insert is set on, you can insert the existing data from the old table into the new table:

INSERT INTO dbo.New_Table (Id, Data)
SELECT Id, Data
FROM dbo.Old_Table;
GO

This command inserts the ‘Id’ and ‘Data’ values from the old table into the new table. Note that the ‘Id’ values must be manually specified since identity insert is on.

Set identity insert off

After the data is inserted, you must turn off identity insert:

SET IDENTITY_INSERT dbo.New_Table OFF;
GO

This command turns off identity insert for the new table, so that future inserts will use the automatic value for the ‘Id’ column.

Drop the old table

Lastly, you can drop the old table:

DROP TABLE dbo.Old_Table;
GO

This command drops the old table, since you no longer need it.

Rename the new table

Optionally, you can rename the new table to the old table’s name:

EXEC sp_rename 'dbo.New_Table', 'Old_Table';
GO

This command renames the new table to ‘Old_Table’, which was the name of the old table before it was dropped.

Option 2: Create a new column with identity and drop the existing column

Here are the steps to create a new column with identity and drop the existing column:

Create a new column

First, you need to create a new column with an identity property:

ALTER TABLE dbo.My_Table
ADD New_Id INT IDENTITY(1,1);
GO

This command adds a new column called ‘New_Id’ to the table ‘My_Table’ with an identity property. The identity column will start at 1 and increment by 1 for each new row inserted into the table.

Copy data to new column

Next, you need to copy the existing ‘Id’ values into the new column:

UPDATE dbo.My_Table
SET New_Id = Id;
GO

This command copies the ‘Id’ values into the new column ‘New_Id’.

Drop the old column

Once the data is copied, you can drop the old column:

ALTER TABLE dbo.My_Table
DROP COLUMN Id;
GO

This command drops the old column ‘Id’ from the table ‘My_Table’.

Rename the new column

Lastly, you can rename the new column to ‘Id’, which was the name of the old column:

EXEC sp_rename 'dbo.My_Table.New_Id', 'Id', 'COLUMN';
GO

This command renames the new column ‘New_Id’ to ‘Id’, which was the name of the old column before it was dropped.

Alternative approach: Use ALTER TABLE… SWITCH statement

In SQL Server 2005 and above, you can use the ALTER TABLE… SWITCH statement to add an identity to an existing table without changing the table’s data pages. This is important for large tables, where touching every data page can take minutes or hours, and where cleanup scripts can take a lot of extra disk space.
