ORACLE: Demystifying Database Pagination: An Explanation of How it Works How does pagination of results in databases work?
Pagination of results in databases is a technique that helps to retrieve a subset of data from a database table, in a series of chunks or pages. This approach is often used in web applications where data needs to be displayed to users in a user-friendly format. Instead of retrieving all data at once, pagination queries a subset of data, allowing for quick and efficient data retrieval. This data retrieval technique applies to various databases such as MySQL, Oracle DB, and others.

How does pagination work in MySQL?

In MySQL, pagination is achieved using the LIMIT clause. The LIMIT clause sets how many rows to return and the starting row to return from. To retrieve a specific range of rows, the offset and size are declared in the query. Here is an example:

SELECT column1, column2, ...
FROM table_name
LIMIT offset, size;

The “offset” parameter determines the number of rows to skip and “size” determines the maximum number of rows to retrieve.

How does pagination work in Oracle DB?

In Oracle DB, pagination is achieved using the ROW_NUMBER() function. ROW_NUMBER() is used to assign a unique number to each row retrieved from a table or table expression, based on the ORDER BY clause. Here is an example:

SELECT column1, column2, ...
FROM (SELECT column1, column2, ROW_NUMBER() OVER(ORDER BY column1) AS rn
      FROM table_name)
WHERE rn BETWEEN offset AND (size+offset)-1;

Here, the “offset” parameter determines the number of rows to skip and “size” determines the maximum number of rows to retrieve.

Does the database execute the full query for each page?

No, the database does not execute the full query for each page. Instead, it stores the query results in memory and retrieves subsets of the results based on the offset and size specified in each pagination query. This method allows for faster data retrieval and eliminates the need to execute the full query multiple times.

How does the database engine handle multiple threads executing the same query?

The database engine manages this by creating a snapshot of the database when a query is executed. This snapshot is then used to retrieve subsets of data based on the offset and size requested by each thread. The engine ensures that each thread retrieves a unique subset of data by keeping track of which data has been returned to each thread.

Practical examples

Here is a practical example of a MySQL query that uses pagination to retrieve data from a table:

SELECT customers.*
FROM customers
JOIN orders ON customers.customer_id = orders.customer_id
WHERE orders.order_status = 'shipped'
LIMIT 10 OFFSET 20;

The above query retrieves 10 records starting from the 20th record in the query result set.

Alternative methods

One alternative method to pagination is caching the query result set. Caching allows pages to be retrieved quickly without repeating the same query multiple times. Although, caching can be resource-intensive and may require constant maintenance to ensure that the cache remains efficient. Another alternative method is to use server-side pagination where the pagination logic is handled on the server-side rather than on the client-side. This approach reduces the amount of data transferred to the client and provides more control over the pagination process.

Summary

Pagination of results in databases is a technique used to retrieve data from a database table in chunks or pages. This technique is used to improve data retrieval performance in web applications. MySQL uses the LIMIT clause to set the maximum number of rows to retrieve and the offset for the first row. Oracle DB uses the ROW_NUMBER() function to assign a unique number to each row retrieved from a table. The database stores the query results in memory and retrieves subsets of the results based on the offset and size specified in each pagination query. In this way, the database engine ensures efficient data retrieval and prevents the need to execute the full query multiple times.
