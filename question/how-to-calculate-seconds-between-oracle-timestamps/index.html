How to Calculate Seconds Between Oracle Timestamps How to Get Seconds Between Two Oracle Timestamps?
If you are working on an application that deals with timestamps in Oracle Database, you may need to calculate the difference between two timestamps in seconds. Here is a guide on the best practices to follow and the different methods you can use.

Best Practice

Wrap your code in a function, like seconds_between(from_date, to_date). This makes it easier to use, read and maintain. You can choose the most efficient method to calculate the difference and your code is explicitly clear about its purpose.

Methods to Calculate Timestamp Difference in Seconds

Here are two methods that you can use to calculate the difference between two timestamps:

Method 1: Using Extract Function

Tom Kyte suggests using the EXTRACT function to get the difference between two timestamps. The method involves extracting the time components from the timestamps and then calculating the difference in seconds. Following is the code to compute the difference using this method:

extract(day from (x-y))*24*60*60
+ extract(hour from (x-y))*60*60
+ extract(minute from (x-y))*60
+ extract(second from (x-y));

Here, x and y are the timestamps you want to compare. You extract the number of days, hours, minutes, and seconds that have elapsed between the two timestamps, then convert them to seconds and add them together. Although, this code may be slower than the other method and requires more significant effort to read.

Method 2: Using Cast Operator

This approach is more accessible to read and faster than Method 1. Following is the code to compute the difference using this method:

(CAST(x AS DATE) - CAST(y AS DATE)) * 86400

Here, x and y are the timestamps you want to compare. You cast the timestamps to dates, subtract the smaller date from the larger date, then multiply the result by the number of seconds in a day (86,400) to convert the difference to seconds.

Test Case

You can test the performance of the two methods using the following code:

DECLARE
 x TIMESTAMP := SYSTIMESTAMP;
 y TIMESTAMP := TRUNC(SYSDATE);
 n PLS_INTEGER;
 lc CONSTANT PLS_INTEGER := 1000000;
 t1 PLS_INTEGER;
 t2 PLS_INTEGER;
 t3 PLS_INTEGER;
BEGIN
 t1 := DBMS_UTILITY.get_time;
 FOR i IN 1..lc LOOP
  n := i;
 END LOOP;
 t1 := DBMS_UTILITY.get_time - t1;

 t2 := DBMS_UTILITY.get_time;
 FOR i IN 1..lc LOOP
  n := extract(day from (x-y))*24*60*60
     + extract(hour from (x-y))*60*60
     + extract(minute from (x-y))*60
     + extract(second from (x-y));
 END LOOP;
 t2 := DBMS_UTILITY.get_time - t2;

 t3 := DBMS_UTILITY.get_time;
 FOR i IN 1..lc LOOP
  n := (CAST(x AS DATE) - CAST(y AS DATE)) * 86400;
 END LOOP;
 t3 := DBMS_UTILITY.get_time - t3;
 
 dbms_output.put_line('t1 (nothing) ' || t1);
 dbms_output.put_line('t2 (extract) ' || t2);
 dbms_output.put_line('t3 (cast)    ' || t3);
END;

The output shows the execution time for three cases:

  • t1 (nothing)- baseline for the test
  • t2 (extract)- using the extract method to calculate the difference
  • t3 (cast)- using the cast method to calculate the difference

The output clearly reveals that the cast operator method is faster than the extract function method.

Alternative Method

The following code is a possible alternative way to get the difference between two timestamps in seconds, including milliseconds. More, this method also provides a solution for daylight saving where the previously mentioned methods can sometimes fail:

ROUND((SYSDATE-x)*86400, 2)

Here, x is the timestamp you want to compare. You subtract the timestamp from SYSDATE, multiply the resulting number by the number of seconds in a day (86,400) and round the result to two decimal places to get the answer in seconds with milliseconds.

Recap

Calculating the time difference between two timestamps is an essential function in many applications that work with time data. The two methods discussed in this post have been tested, and their execution time compared. The cast operator method is more accessible to read and faster, whereas the extract function is slower and tougher to read. It is best practice to wrap the function into a callable function, no matter which method you choose, to make your code more concise and easier to maintain. ]]>
