Calculating Running Sum over Partition

To calculate a running sum over a partition in BigQuery, you can use the “SUM() OVER()” function. This function calculates the sum of a column over a partition, which is defined by one or more columns. The “OVER()” clause specifies the partition and the “ORDER BY” clause specifies the order of the data within the partition. Here is an example:

SELECT
  column1,
  column2,
  SUM(column3) OVER (PARTITION BY column1 ORDER BY column2) AS running_sum
FROM
  mytable;

In this example, “column1” is the column used to define the partition, “column2” is the column used to order the data within each partition, and “column3” is the column we want to calculate the running sum of.

Issues with Running Sum over Partition

While calculating a running sum over a partition is straightforward, there are some issues you may encounter. Let’s address the two problems mentioned in the question:

1. Starting with the Most Common Word

The first issue is that the sum may start with the least common word instead of the most common word. This is because the “ORDER BY” clause in the “OVER()” clause only specifies the order of the data within each partition. To start with the most common word, we need to sort the data differently before applying the “SUM() OVER()” function.

One way to achieve this is to use a subquery to group the data by the partition columns and calculate the total word count for each partition. Then, we can join the subquery to the main table and order the data by the total word count in descending order. This will ensure that the sum starts with the most common word. Here is an example:

SELECT
  t.corpus,
  t.corpus_date,
  t.word_count,
  SUM(t.word_count) OVER (
    PARTITION BY t.corpus, t.corpus_date
    ORDER BY s.total_word_count DESC, t.word
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_sum
FROM
  `publicdata.samples.shakespeare` t
JOIN (
  SELECT
    corpus,
    corpus_date,
    SUM(word_count) AS total_word_count
  FROM
    `publicdata.samples.shakespeare`
  GROUP BY
    corpus,
    corpus_date
) s
ON
  t.corpus = s.corpus
  AND t.corpus_date = s.corpus_date
ORDER BY
  t.corpus,
  t.corpus_date,
  running_sum DESC,
  t.word;

In this example, we first calculate the total word count for each partition using a subquery. Then, we join the subquery to the main table and order the data by the total word count in descending order and then by the word count in ascending order. The “ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW” clause in the “OVER()” clause specifies that the running sum should include all rows from the start of the partition to the current row.

2. First Row of Running Sum Yielding 0

The second issue is that the first row of the running sum may yield a sum of 0 even though the sum isn’t 0 for that row. This is because the “ORDER BY” clause in the “OVER()” clause specifies the order of the data within each partition, but it doesn’t specify the order of the partitions themselves. Therefore, the running sum may start with the wrong partition if the data is not sorted correctly.
