Oracle FK Constraint: Insufficient Privileges Insufficient Privileges when Adding FK Constraint in Oracle

Summary:

When adding a foreign key (FK) constraint to a table owned by a different schema, the user adding the constraint may encounter an ‘ORA=01031: insufficient privileges’ error. This error occurs when the user does not have permissions to reference the primary key (PK) table.

What Causes the Error?

The most likely cause of this error is that the user attempting to add the FK constraint (LAB_ADMIN_USER) does not have the necessary permissions to reference the PK table (LAB_ADMIN.TEST_TEMPLATE). This table is owned by a different schema, and the owning user must grant REFERENCES permissions to the user adding the FK constraint.

How to Grant REFERENCES permissions:

To grant REFERENCES permissions to the user adding the FK constraint, the owning schema (LAB_ADMIN) must execute the following command:

GRANT REFERENCES ON LAB_ADMIN.TEST_TEMPLATE TO LAB_ADMIN_USER;

This grants the LAB_ADMIN_USER the ability to reference the TEST_TEMPLATE table. Once this permission has been granted, the LAB_ADMIN_USER can add the FK constraint to their own table using the following command:

ALTER TABLE LAB_ADMIN_USER.TEST_TEMPLATE_ABBR 
ADD CONSTRAINT TEST_TEMPLATE_ABBR_R01 
FOREIGN KEY (test_template_id) 
REFERENCES LAB_ADMIN.TEST_TEMPLATE (test_template_id)
ON DELETE CASCADE;

If the permission has been granted successfully, this command will execute without errors.

Practical Example:

Assume LAB_ADMIN_USER has a table called PERSON with a foreign key column to the LAB_ADMIN owned table, ADDRESS. To add the FK constraint, execute the following:

GRANT REFERENCES ON LAB_ADMIN.ADDRESS TO LAB_ADMIN_USER;

Once permission has been granted, the LAB_ADMIN_USER can successfully add the FK constraint to their table using the following command:

ALTER TABLE LAB_ADMIN_USER.PERSON 
ADD CONSTRAINT PERSON_ADDRESS_FK 
FOREIGN KEY (address_id) 
REFERENCES LAB_ADMIN.ADDRESS (address_id)
ON DELETE CASCADE;

Alternative Method:

A simpler alternative method is to grant all permissions required for the FK constraint using the following command:

GRANT ALL PRIVILEGES ON LAB_ADMIN.TEST_TEMPLATE TO LAB_ADMIN_USER;

Once this permission has been granted, LAB_ADMIN_USER can add the FK constraint to their own table as previously shown. ]]>
