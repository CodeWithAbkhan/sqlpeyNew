Service Account does not have bigquery.jobs.create Permission
In this scenario, the service account being used does not have the necessary permission to create jobs in BigQuery. The service account has been granted the “owner” and “BigQuery admin” roles but still can’t create jobs. Therefore, we will need to specify the credentials of the service account as a parameter of the BigQueryClient constructor and check whether the right permissions have been granted to the service account.

Code Explanation

The code attempts to create a BigQuery Client object with the specified project ID and service account credentials. It then runs a SQL query on a specific table using the query() method and executes the job using the runQuery() method. Although, an error is thrown because the service account does not have the necessary permission to create jobs in BigQuery.

$bigQuery = new BigQueryClient([
    'projectId' => 'project-xxx',
]);

$query = "SELECT * FROM `project-xxxx.analytics_xxx.events_xxx` where event_name="first_open" LIMIT 100";

$jobConfig = $bigQuery->query($query);
$queryResults = $bigQuery->runQuery($jobConfig);
print_r($queryResults);

To solve this error, we need to specify the service account credentials in the BigQueryClient constructor:

$bigQuery = new BigQueryClient([
    'projectId' => 'project-xxx',
    'keyFilePath' => '/path/to/file.json'   
]);

We can also check whether the service account has the necessary permission to create jobs in BigQuery using the following command:

gcloud projects get-iam-policy yourProjectID

Practical Example

Let’s assume the service account email is bigquery@project-xxxx.iam.gserviceaccount.com. We can grant it the required permission using the following command:

gcloud projects add-iam-policy-binding project-xxxx --member='serviceAccount:bigquery@project-xxxx.iam.gserviceaccount.com' --role='roles/bigquery.jobUser'

This will add the bigquery.jobs.create permission to the service account, allowing it to create jobs in BigQuery.

Alternative Way

Instead of granting the bigquery.jobs.create permission to the service account, we can grant it the roles/bigquery.user or roles/bigquery.dataEditor roles, which provide broader access to BigQuery.

The roles/bigquery.user role provides read and write access to datasets and tables in BigQuery, while the roles/bigquery.dataEditor role provides the same access as roles/bigquery.user plus the ability to modify table schemas and some other metadata.

Using the following command, we can grant the roles/bigquery.dataEditor role to the service account:

gcloud projects add-iam-policy-binding project-xxxx --member='serviceAccount:bigquery@project-xxxx.iam.gserviceaccount.com' --role='roles/bigquery.dataEditor'

This will grant the service account access to write to, and modify, tables in BigQuery.

Summary

In summary, we have learned that the service account does not have the necessary permission to create jobs in BigQuery. Therefore, we need to specify the service account credentials in the BigQueryClient constructor and grant it the necessary permission. Alternatively, we can grant the service account broader access to BigQuery using the roles/bigquery.user or roles/bigquery.dataEditor roles. ]]>
