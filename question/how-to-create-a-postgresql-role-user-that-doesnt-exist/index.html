How to Create a PostgreSQL ROLE (User) That Doesn’t Exist How to create a PostgreSQL role (user) if it doesn’t exist

If you need to create a PostgreSQL role (user) in a script but want to avoid raising an error if it already exists, there is no built-in IF NOT EXISTS clause for CREATE ROLE. Although, you can use a DO statement in PL/pgSQL to achieve the desired behavior.

Here is a simple solution that creates the role only if it doesn’t already exist:

DO
$do$
BEGIN
   IF NOT EXISTS (
      SELECT FROM pg_catalog.pg_roles
      WHERE rolname = 'my_user'
   ) THEN
      CREATE ROLE my_user LOGIN PASSWORD 'my_password';
   END IF;
END
$do$;

Let’s analyze the code line by line:

  • DO is a statement that creates an anonymous code block. The code block can contain procedural code in any supported PL. In this case, we are using PL/pgSQL (the default language).
  • $do$ is a delimiter that marks the beginning of the code block.
  • BEGIN starts the procedural code block.
  • IF NOT EXISTS checks if the role already exists. It does so by selecting from the pg_roles system catalog table, which contains information about all roles defined in the current database cluster.
  • The subquery uses the WHERE clause to filter for the role name 'my_user'.
  • END IF closes the IF block.
  • CREATE ROLE creates the role with the desired login properties and password.
  • END ends the procedural code block.
  • $do$ marks the end of the code block.

The advantage of this approach is that it avoids a race condition that can occur if you use a simple CREATE ROLE statement with a IF NOT EXISTS clause. If two script runs simultaneously try to create the same role, the IF NOT EXISTS check may return true for both, and both scripts may attempt to create the role, resulting in an error. The DO statement avoids this issue by creating an atomic code block that prevents simultaneous execution.

Alternatively, you can use a trigger to intercept the CREATE ROLE statement and return a warning if the role already exists. For example:

CREATE OR REPLACE FUNCTION prevent_role_creation()
RETURNS event_trigger
LANGUAGE plpgsql
AS $$
BEGIN
   IF tg_tag = 'CREATE ROLE' THEN
      IF EXISTS (
         SELECT FROM pg_catalog.pg_roles
         WHERE rolname = new.role_name
      ) THEN
         RAISE WARNING 'Role "%" already exists', new.role_name;
         RETURN NULL;
      END IF;
   END IF;
END
$$;

CREATE EVENT TRIGGER prevent_role_creation
ON ddl_command_start
WHEN TAG IN ('CREATE ROLE');

This solution uses an event trigger, which is a PL/pgSQL function that is automatically called when certain types of events occur in the database. In this case, we are defining an event trigger that fires on CREATE ROLE statements.

The trigger function checks if the role already exists and raises a warning if it does. The new.role_name variable contains the name of the role being created. The RETURN NULL; statement aborts the CREATE ROLE statement.

This approach has the advantage of being more general: you can use it to intercept any CREATE ROLE statement regardless of where it comes from. Although, it requires more setup code and incurs a small overhead for checking every CREATE ROLE statement.]]>
