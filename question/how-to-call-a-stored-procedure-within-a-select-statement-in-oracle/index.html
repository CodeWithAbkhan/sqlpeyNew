How to Call a Stored Procedure within a Select Statement in Oracle Oracle: Calling stored procedure inside SELECT statement
Have you ever wondered if it’s possible to call a stored procedure inside a SELECT statement in Oracle? You might have tried to do it and couldn’t achieve it. But don’t worry, in this blog post, we’ll discuss how you can achieve it and some alternatives as well.

The problem

Suppose you want to insert the result of a SELECT statement into a table after performing some validations using a stored procedure. You might think of executing the stored procedure inside the SELECT statement and returning a value if the validation is successful. But unfortunately, it’s not possible.

For instance, consider the following code:

SELECT field1, field2, myproc(field1, field2)
FROM MYTABLE;

The above code won’t work as SQL can only use functions in the projection which returns a value.

The solution

The easiest solution to this problem is to use a PL/SQL loop where you can iterate over the rows of a table and execute the stored procedure for each row. Here’s how you can achieve it:

BEGIN
   FOR c IN (SELECT field1, field2 FROM mytable) LOOP
       my_proc(c.field1, c.field2);
   END LOOP;
END;

Here, we’ve used a cursor to select the required fields from the table and looped through each row using a FOR loop. For each row, the stored procedure my_proc is executed with the respective values of field1 and field2.

But what if you don’t want to use PL/SQL code and want to stick with the SELECT statement? Then you can create a function that calls the stored procedure and returns a value based on the stored procedure’s execution result. Here’s how you can achieve it:

CREATE OR REPLACE FUNCTION validate_salary(p_sal IN emp.sal%type, p_job IN emp.job%type) RETURN emp.sal%type
IS
BEGIN
    -- perform validation using stored procedure
    salary_rule(p_sal, p_job);
    -- return p_sal if validation is successful
    RETURN p_sal;
EXCEPTION
    -- re-raise the exception thrown by the stored procedure
    WHEN OTHERS THEN 
        RAISE_APPLICATION_ERROR(-20000, 'Validation Failed: '||SQLERRM);
END;

In the above code snippet, we’ve created a function validate_salary that accepts two parameters p_sal and p_job. The function passes these two values to the stored procedure salary_rule for validation. If the stored procedure returns without throwing any exceptions, the function returns the value of p_sal. Otherwise, it throws an exception with the error message provided by the stored procedure.

You can now use this function in your SELECT statement like this:

SELECT field1, field2, validate_salary(sal, job)
FROM emp;

The above code snippet will return the required values from the emp table after validating the salary using the validate_salary function.

Alternative ways

If you don’t want to use PL/SQL or a function, you can use a subquery to perform the validation in the SELECT statement itself. Here’s how:

SELECT field1, field2, 
    CASE
        WHEN (SELECT COUNT(*) FROM mytable WHERE field1 = mt.field1 AND field2 = mt.field2) > 0 THEN
            myproc(field1, field2)
        ELSE NULL
    END validation_result
FROM mytable mt;

In the above code snippet, we’ve used a subquery to check whether the values of field1 and field2 exist in the mytable table. If they exist, we call the stored procedure myproc, otherwise, we return NULL.

Summary

We’ve discussed several ways to call a stored procedure inside a SELECT statement in Oracle. You can use a PL/SQL loop, a function that calls the stored procedure, or a subquery to perform the validation. Choose the appropriate method depending on your use case.
