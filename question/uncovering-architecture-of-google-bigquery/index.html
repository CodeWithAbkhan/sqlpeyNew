Google BigQuery Underlying Architecture: A Deep Q&A

What is the underlying architecture used by Google BigQuery to store data?

Google BigQuery stores data in a proprietary columnar format called ColumnIO on Colossus, which is a successor to the Google File System (GFS). Colossus has the ability to replicate data within a datacenter and also across different geographic regions. This ensures that the data remains available even if a Google datacenter fails.

Is BigQuery based on Google’s BigTable infrastructure?

No, BigQuery is not based on Google’s BigTable infrastructure. Although data may be temporarily stored in Bigtable, all data is stored long-term in Colossus.

Does BigQuery use indexes for queries?

No, every query in BigQuery is a table scan. There are no indexes, which implies there are no strategies for rebuilding the index.

How is data encryption maintained in BigQuery?

New data added to BigQuery is encrypted both at rest (when it’s written out to permanent storage) and when it’s sent over the network.

Is it possible to analyze data end-to-end in BigQuery?

Yes, it is possible to analyze data end-to-end in BigQuery. While there may be some black box areas where “things just work,” the query architecture is well documented and can be studied to analyze the process thoroughly.

Can you give an overview of BigQuery’s query architecture?

BigQuery has a distributed SQL engine that works by receiving a SQL query and breaking it down into multiple sub-queries. These sub-queries are then executed in parallel across multiple nodes. The resulting data is then aggregated and sent back to the user.

The query plan is broken down into smaller pieces called “stages,” where each stage represents a sub-query, which is then executed across multiple nodes in parallel.

BigQuery uses a technique called “dynamic pruning” to avoid reading unnecessary column data when executing a query. Dynamic pruning allows BigQuery to skip reading columns that are not needed for a particular query, thus reducing the overall processing time and improving performance.

What are the types of data that BigQuery supports?

BigQuery supports various types of data, including structured, semi-structured, and unstructured data. It can handle JSON, CSV, and AVRO data, among others. It also has built-in support for machine learning models, making it an all-in-one platform for data analytics and machine learning.

Practical Example:

SELECT name, age
FROM myTable
WHERE age >= 18
ORDER BY age DESC

This query selects the name and age of all people in “myTable” where the age is greater than or equal to 18. It then sorts the results in descending order based on age.

Alternative Ways:

BigQuery also has a REST API that allows developers to create, manage and execute queries programmatically. More, there are various interface and visualization tools available for BigQuery, such as Google Data Studio and Google Cloud Console, that can help users analyze their data in real-time.
