ORACLE: Execute or Run: Which is better for scripts? Learning the Difference Between “Run Statement” and “Run Script” in Oracle SQL Developer

Introduction:

Oracle SQL Developer is a graphical tool used to manage and manipulate Oracle databases. While using this tool, you may come across two options called “Run Statement” and “Run Script” when running SQL statements. Here, in this Q&A Session, we will discuss the difference between these two options.

What is the Difference Between “Run Statement” and “Run Script” in Oracle SQL Developer?

The main difference between “Run Statement” and “Run Script” in Oracle SQL Developer is that “Run Statement” only runs the statement that is currently highlighted (or under the cursor), whereas “Run Script” executes all statements present in the worksheet.

Let’s know these two options in-depth:

Run Statement:

“Run Statement” option is used to execute the SQL statement that is currently selected or highlighted. This option gives a list of all the results in a sortable table. Here, you will be prompted for bind variables when you run the statement that has placeholders with : in front of it. You will have to provide a value for these placeholders, to complete the statement execution.

Let’s look at some code to know this better:

select * from customers where customer_id = :id

In the above code, the bind variable :id is present, which means it will prompt for the value of the placeholder when the statement is executed. When you click on “Run Statement,” you will be prompted to enter a value for :id to continue with the execution.

This option is useful when you want to see the results of a particular SQL statement quickly.

Run Script:

When you want to execute multiple SQL statements, you can use the “Run Script” option instead of the “Run Statement” option. This option executes all the SQL statements present in the worksheet (not just the highlighted ones) and gives a text readout of the results.

Let’s look at some code to know this better:

CREATE TABLE employees (
  employee_id    NUMBER(6),
  first_name     VARCHAR2(20),
  last_name      VARCHAR2(25),
  email          VARCHAR2(25),
  phone_number   VARCHAR2(20),
  hire_date      DATE,
  job_id         VARCHAR2(10),
  salary         NUMBER(8,2),
  commission_pct NUMBER(2,2),
  manager_id     NUMBER(6),
  department_id  NUMBER(4)
);

INSERT INTO employees VALUES (1, 'John', 'Doe', 'johndoe@example.com', '123-456-7890', '01-JAN-21', 'CEO', 6000, 0, NULL, 10);

COMMIT;

Here, multiple SQL statements are present. When you click on “Run Script,” all the SQL statements present will be executed. It is important to note that it will not prompt for the values of bind variables (as it executes all the statements present in the worksheet).

This option is helpful when you want to execute multiple SQL statements at once, without having to run them individually.

Practical Example:

Suppose, you have a database table called “products,” and you want to retrieve the details of products whose price is above $100. You can use the following SQL statement:

SELECT * FROM products WHERE price > 100;

Once you execute the above SQL statement, you will see a list of all the products whose price is above $100 in a sortable table.

Now, let’s suppose you want to update the price of some products by increasing it by 10%. You can use the following SQL statement to achieve this:

UPDATE products SET price = price * 1.10 WHERE price > 100;

Once you execute the above SQL statement, you will see the number of rows affected by it.

If you want to execute both SQL statements simultaneously, you can write them in the worksheet and then click “Run Script.” This will execute both statements at once (without having to run them individually).

Alternative Ways:

One alternative way to execute multiple SQL statements is to use a PL/SQL block. PL/SQL blocks are stored procedures that allow you to execute multiple SQL statements within them. Here’s an example:

DECLARE 
  price_threshold NUMBER := 100;
BEGIN 
  SELECT * FROM products WHERE price > price_threshold;
  UPDATE products SET price = price * 1.10 WHERE price > price_threshold;
END;

The above code is a PL/SQL block that contains multiple SQL statements. When you execute this block, all the SQL statements will be executed together.

Summary:

Learning the difference between “Run Statement” and “Run Script” in Oracle SQL Developer is crucial when working with databases. In summary, “Run Statement” executes the SQL statement that is currently highlighted or selected, while “Run Script” executes all the SQL statements present in the worksheet. Use “Run Statement” when you want to quickly see the results of a particular SQL statement, and use “Run Script” when you want to execute multiple SQL statements at once. ]]>
