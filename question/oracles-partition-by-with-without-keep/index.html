Oracle’s Partition By: With and Without KEEP What is the difference between using PARTITION BY with and without KEEP in Oracle?

The queries shown both apply an aggregate function on partitions in Oracle but use different syntax for achieving the same result. The first query uses MIN and MAX functions with the PARTITION BY clause to get the lowest and highest salaries for each department. The second query adds the KEEP and DENSE_RANK clauses to the MIN and MAX functions, respectively, to achieve the same result with a different syntax.

Let’s examine the second query in more detail:

SELECT empno,
   deptno,
   sal,
   MIN(sal) KEEP (DENSE_RANK FIRST ORDER BY sal) OVER (PARTITION BY deptno) "Lowest",
   MAX(sal) KEEP (DENSE_RANK LAST ORDER BY sal) OVER (PARTITION BY deptno) "Highest"
FROM empl

The statement can be interpreted in right-to-left order:

  • OVER (PARTITION BY deptno) partitions rows into distinct groups based on their department number.
  • ORDER BY sal orders the rows within each partition by salary in ascending order.
  • DENSE_RANK FIRST gives consecutive rankings to the ordered rows for each partition and retains only the first-ranked row.
  • MIN(sal) returns the minimum salary for each partition based on the remaining rows.
  • DENSE_RANK LAST gives consecutive rankings to the ordered rows for each partition and retains only the last-ranked row.
  • MAX(sal) returns the maximum salary for each partition based on the remaining rows.

In the given query, the MIN(sal) and DENSE_RANK FIRST are both operating on the sal column, so the KEEP (DENSE_RANK FIRST ORDER BY sal) is redundant.

Although, if we use a different column for the minimum, then the effects become evident. Consider the following example:

CREATE TABLE test (name, sal, deptno) AS
SELECT 'a', 1, 1 FROM DUAL
UNION ALL SELECT 'b', 1, 1 FROM DUAL
UNION ALL SELECT 'c', 1, 1 FROM DUAL
UNION ALL SELECT 'd', 2, 1 FROM DUAL
UNION ALL SELECT 'e', 3, 1 FROM DUAL
UNION ALL SELECT 'f', 3, 1 FROM DUAL
UNION ALL SELECT 'g', 4, 2 FROM DUAL
UNION ALL SELECT 'h', 4, 2 FROM DUAL
UNION ALL SELECT 'i', 5, 2 FROM DUAL
UNION ALL SELECT 'j', 5, 2 FROM DUAL;

SELECT DISTINCT
  MIN(sal) KEEP (DENSE_RANK FIRST ORDER BY name) OVER (PARTITION BY deptno) AS lowest_name,
  MIN(sal) KEEP (DENSE_RANK FIRST ORDER BY sal) OVER (PARTITION BY deptno) AS lowest_sal
FROM test;

In this example, we use the name column instead of the sal column in the ORDER BY clause for DENSE_RANK FIRST. This changes the order of the rows within each partition, resulting in different outcomes for the two KEEP clauses.

The output of the above query would be:

LOWEST_NAME LOWEST_SAL
1           1
4           4

We can see that LOWEST_NAME gives the lowest salary for each department based on the first alphabetically-ranked employee name, while LOWEST_SAL gives the lowest salary based on the actual salary value.

In recap, the syntax using KEEP and DENSE_RANK can be used to achieve the same results as the basic syntax using only PARTITION BY, but with the added flexibility to choose different ranking columns.]]>
