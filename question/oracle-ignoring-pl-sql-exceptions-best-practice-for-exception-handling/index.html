ORACLE: Ignoring PL/SQL Exceptions: Best Practice for Exception Handling PL/SQL Exception Handling: How to Ignore Exceptions

Introduction As a programmer, you know that handling exceptions is a critical part of ensuring the reliability and robustness of your code. Although, there may be specific situations where you want to ignore an exception rather than handle it. For example, you may be dealing with a statement that you know will occasionally fail but don’t want it to interrupt your program flow, or you may want to keep some exceptions from bubbling up and stopping the code execution for the whole block. In this blog post, we will explore how to ignore exceptions in PL/SQL and examine two different scenarios where ignoring exceptions might be desirable. Ignoring Exceptions Generally, it’s not a good practice to silently ignore exceptions without at least logging them somewhere. But, there are some circumstances where it’s perfectly acceptable to ignore exceptions. In PL/SQL, the NULL statement can be used to ignore an exception. The NULL statement is a placeholder that indicates no operation, and it can be used in any context where an expression or statement is expected. Here is an example of how to ignore all exceptions using the NULL statement:

… EXCEPTION WHEN OTHERS THEN NULL; END;

With this implementation, the exception is silently ignored, and the code execution continues without interruption. Now that you know how to ignore exceptions let’s take a look at two scenarios where you might want to use this approach. Scenario 1: Ignore Exceptions when dealing with a statement that is likely to fail Let’s say we have a PL/SQL procedure that retrieves an employee’s name based on their employee ID. If the employee ID does not exist in the database, a NO_DATA_FOUND exception will occur. We may not want this exception to interrupt the program flow, so we need to catch the exception and continue without error.

CREATE OR REPLACE PROCEDURE my_procedure IS l_employee_name employees.employee_name%TYPE; BEGIN BEGIN SELECT employee_name INTO l_employee_name FROM employees WHERE employee_id = 12345;

    EXCEPTION
        WHEN NO_DATA_FOUND THEN
             NULL;
        WHEN OTHERS THEN
             RAISE;
    END;

    do_something_else();

EXCEPTION
    WHEN OTHERS THEN
        RAISE;
END;

In this example, the SELECT statement is enclosed within a nested block. This nesting allows us to catch the NO_DATA_FOUND exception and then ignore it using the NULL statement. If any other exception occurs while executing the SELECT statement, we will raise the exception to the calling block. The do_something_else() function is called outside the nested block and is executed regardless of whether or not the SELECT statement fails. Scenario 2: Ignore Exceptions to prevent their propagation to the calling block In situations where you do not want an exception to propagate to the calling block, ignoring the exception can be an option. When you raise an exception within a PL/SQL block without handling it, it propagates to the next outer block. If the exception makes it to the outermost block and is still unhandled, the program execution will stop. Consider the following code block:

BEGIN – Do something […]

EXCEPTION
    WHEN OTHERS THEN
        RAISE;
END;

If an exception occurs within the “Do something” block, and we don’t handle it, the exception will propagate upwards and eventually be caught by the WHEN OTHERS exception handler. When this happens, we will raise the exception, allowing it to propagate even higher. Although, we may encounter situations where we don’t want an exception to propagate to the outermost block, even if we don’t handle it. In this case, we can ignore the exception using the NULL statement.

BEGIN – Do something […]

EXCEPTION
     WHEN EXCEPTION_NAME THEN
         NULL;
END;

By ignoring the exception, we prevent its propagation to the calling block, allowing the code execution to continue without interruption. Recap Whether you should ignore exceptions or not depends on your specific use case. Remember that exception handling is critical for maintaining the reliability of your code, and ignoring exceptions is usually not a sound practice. But, in some situations, ignoring exceptions using the NULL statement can be a viable option. In this blog post, we explored two scenarios where ignoring exceptions might be desirable and provided code examples that demonstrated how to use the NULL statement to ignore them.
