ORACLE: Securely Managing a Connection Pool

Safely Wrapping a Connection Pool for Row Level Security

In a web environment, enforcing access control is crucial. One of the technologies that can help with this is Oracle’s Virtual Private Database, which allows for row level security by augmenting all queries against specific tables with a where clause predicate. To make this work within a web environment, a special context within Oracle needs to be set up inside a single thread of a request. This may seem daunting, especially when using connection pooling with a service account, but there are ways to safely implement it.

What is the best approach to implement this in a connection pool?

There are several approaches to implementing row level security in a connection pool. One option is to use the events in Eclipse Link and Hibernate. Eclipse Link has events that fit perfectly into this model. Although, migrating from Hibernate to Eclipse Link means being bound to EL for these events. Another option is to implement it at the DataSource level, as Oracle implements it in Web Logic. The context is set and cleared by the WebLogic data source code.

Extending a connection pool could also work. For instance, we could extend org.apache.commons.pool.impl.GenericObjectPool and override both borrowObject() and returnObject(). But foremost to note that rolling one’s own security lifecycle is never a good idea.

What are the events or methods to pay the most attention to?

When implementing this at the DataSource level, the following methods and events should be given attention:

  • getConnection() - allows a connection to be established with the database.
  • releaseConnection() - releases a connection and returns it to the connection pool.
  • destroy() - ends the pool, cleans up available connections and removes the pool from the {@code static Map}.
  • initPool() - initializes the pool by creating a new key in the {@code static Map} if none already exists, creates the pool itself by calling createObjectPool() method and fills the pool with connections using fillObjectPool().
  • createObjectPool() - creates an object pool and sets the configurations needed to manage the pool.
  • fillObjectPool() - fills the pool with numOfConnections connections.
  • validateObject() - validates the state of an object. If the object is not valid, it will be destroyed and removed from the pool.
  • passivateObject() - resets an object to its initial state before being returned to the pool.

How do I safely initialize an Oracle context with some custom data in a connection pool?

We can safely initialize an Oracle context with some custom data by extending some of the Apache components. First, extend org.apache.commons.pool.impl.GenericObjectPool and override both borrowObject() and returnObject(). Then, use the following code:

public synchronized Connection borrowObject() throws Exception {
    Connection conn = (Connection) super.borrowObject();
    initContext(conn); //initializing the Oracle context here
    return conn;
}

public synchronized void returnObject(Object obj) throws Exception {
    super.returnObject(obj);
    closeContext((Connection) obj);
}

private void initContext(Connection conn) {
    //initialize Oracle context here with some custom data
}

private void closeContext(Connection conn) {
    //close Oracle context here
}

Make sure to initialize the Oracle context with some custom data in the initContext() method and close it in the closeContext() method.

Example Code:

Here is an example code for creating a connection pool that initializes an Oracle context with some custom data:

public class CustomConnectionPool extends GenericObjectPool {
    private String username;
    private String password;
    private String url;
    private String customData;

    public CustomConnectionPool(String username, String password, String url, String customData) {
        super();
        this.username = username;
        this.password = password;
        this.url = url;
        this.customData = customData;
        initPool();
    }

    private void initPool() {
        try {
            ConnectionFactory connectionFactory = new DriverManagerConnectionFactory(url, username, password);
            PoolableConnectionFactory poolableConnectionFactory = new PoolableConnectionFactory(connectionFactory, null);
            poolableConnectionFactory.setValidationQuery("SELECT 1");

            ObjectPool connectionPool = new GenericObjectPool(poolableConnectionFactory);

            //initialize the Oracle context with some custom data
            initContext(connection);

            poolableConnectionFactory.setPool(connectionPool);

            DataSource dataSource = new PoolingDataSource(connectionPool);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    private void initContext(Connection conn) {
        //initialize Oracle context here with some custom data
    }

    private void closeContext(Connection conn) {
        //close Oracle context here
    }

    public synchronized Connection borrowObject() throws Exception {
        Connection conn = (Connection) super.borrowObject();
        initContext(conn); //initializing the Oracle context here
        return conn;
    }

    public synchronized void returnObject(Object obj) throws Exception {
        super.returnObject(obj);
        closeContext((Connection) obj);
    }
}

Alternative Ways:

Another way to safely implement row level security in a web environment is to use Spring. Spring Security provides a way to manage security and can be used to implement row level security. Spring’s connection pool abstraction, like HikariCP, can be used to safely initialize an Oracle context with some custom data in a connection pool.
