How to increase allotted memory for BigQuery queries?

Summary

If you encounter a “Resources exceeded during query execution” error when running a query in BigQuery, it means that your query cannot be executed within the allotted memory limit. This post will discuss ways to increase the allotted memory for queries in BigQuery.

Learning the Error

If the query you are running requires more memory than the maximum allowed by your project, you will get a “Resources exceeded during query execution” error. This error indicates that the maximum amount of memory allowed for a single query in BigQuery has been exceeded. By default, this maximum is set to 100 GB.

Increase allotted memory for queries in BigQuery

There are several approaches for increasing the allotted memory for queries in BigQuery. Here are a few that you can try:

Use a larger machine type

BigQuery offers different machine types for running queries. You can try using a larger machine type to increase the allotted memory for queries. To do this, you can specify a different machine type when running the query by including the “–machine-type” flag in your query command:

bq query --machine-type=custom-32-8192 "SELECT * FROM mytable"

This command runs the query using a custom machine type with 32 vCPUs and 8 GB of memory. You can adjust the machine type to best fit your needs.

Partition your data

If your data is too large to fit into memory, consider partitioning your data. By partitioning your data, you can limit the amount of data that needs to be processed at one time, reducing the amount of memory required for the query.

Optimize your query

If your query requires a lot of memory, consider optimizing your query to reduce the amount of data that needs to be processed. This can involve reducing the number of columns being selected, using filters to limit the amount of data being processed, or breaking the query up into smaller pieces.

Code explanation

The original query selects all columns from the table “mediation_time_BASE” and applies the “row_number()” function over all rows. This function assigns a unique sequential number to each row, starting with 1.

SELECT
  row_number() over() as rowNumber,
  game,
  app_version,
  event_date,
  user_pseudo_id,
  event_name,
  event_timestamp,
  country,
  platform
FROM
`mediation_time_BASE`

This query returns an error message because it exceeds the maximum amount of memory allowed for a query. The error message indicates that the “analytic OVER() clauses” are the main memory consumers.

In this case, you can try partitioning your data to reduce the amount of memory required. For example, you can limit the data to a certain date range:

SELECT
  row_number() over() as rowNumber,
  game,
  app_version,
  event_date,
  user_pseudo_id,
  event_name,
  event_timestamp,
  country,
  platform
FROM
  `mediation_time_BASE`
WHERE
  event_date BETWEEN '2022-01-01' AND '2022-01-31'

This query limits the data to the month of January 2022. By reducing the amount of data being processed, this query may require less memory than the original query.

Alternative approaches

If your query is still running out of memory, you can try using a larger machine type as described above or optimizing your query to reduce the amount of data being processed.

You can also try using BigQuery’s “Reservations” feature, which allows you to reserve memory and CPU resources for your queries. This can help ensure that your queries have the necessary resources to run. Although, this feature requires a paid subscription to BigQuery.
