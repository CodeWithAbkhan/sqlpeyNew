ACID Compliant NoSQL Data Stores: Do They Exist?

Is there any NoSQL data store that is ACID compliant?

In the world of databases, there are two main types: SQL and NoSQL.

SQL databases store data in a structured way based on predefined schemas, while NoSQL databases store data in a non-structured or semi-structured way.

NoSQL databases are known for their flexibility and scalability, but they often sacrifice some of the reliability and consistency that comes with using a structured database.

Enter ACID compliance. ACID stands for Atomicity, Consistency, Isolation, and Durability, and it is a set of properties that guarantee that database transactions are processed reliably.

So, is there any NoSQL data store that is ACID compliant?

The Short Answer

Yes, there are NoSQL data stores that are ACID compliant.

The Long Answer

While NoSQL databases were designed to be flexible and scalable, there are instances where consistency and reliability are paramount. For example, in fintech, healthcare or large-scale e-commerce applications, we need absolute consistency and reliability to ensure the protection and integrity of user data.

In response, some NoSQL databases have implemented ACID compliance. Here are a few examples:

1. Couchbase

Couchbase is a distributed NoSQL database that is ACID-compliant. It can handle millions of operations per second with sub-millisecond latency, making it ideal for high-scale, data-intensive applications.

Let’s take a closer look at Couchbase’s atomicity feature:

db.runInTransaction(new TransactionalExecutable() {
    public void execute() {
        Document doc1 = bucket.get("doc1");
        Document doc2 = bucket.get("doc2");
        
        // modify doc1 and doc2
        doc1.setContent(newContent1);
        doc2.setContent(newContent2);
        
        bucket.upsert(doc1);
        bucket.upsert(doc2);
    }
});

The code above shows a sample of how transactions are run in Couchbase. A transaction is a set of read and write operations that are executed as a unit. In the code, a transaction is created using the runInTransaction method.

Within the transaction, two documents (doc1 and doc2) are retrieved and modified. The modified documents are then upserted into the database. The transaction guarantees that either all of the modifications are made, or none of them are made.

2. Google Cloud Datastore

Google Cloud Datastore is a NoSQL document-oriented database that is also ACID-compliant. It can handle high-scale applications and provides automatic scalability without downtime.

Here is an example of how to guarantee atomicity in Google Cloud Datastore:

Transaction txn = datastore.newTransaction();
try {
  Entity accountA = txn.get(accountAKey);
  Entity accountB = txn.get(accountBKey);
  
  // modify accountA and accountB
  accountA.setProperty("balance", accountA.getLong("balance") - debitAmount);
  accountB.setProperty("balance", accountB.getLong("balance") + debitAmount);
  
  txn.put(accountA);
  txn.put(accountB);
  
  // Commit the transaction.
  txn.commit();
} finally {
  if (txn.isActive()) { // Rollback the transaction if it is still active.
    txn.rollback();
  }
}

The code above shows a transaction that retrieves two entities (accountA and accountB) and modifies them before putting them back into the database with the put method. If the transaction completes successfully, it is committed. Otherwise, it is rolled back.

3. RavenDB

RavenDB is a multi-model NoSQL database that supports ACID transactions across its document, graph, and key-value models. It also has a flexible indexing system that can handle complex data structures.

Here is an example of a transaction in RavenDB:

using (var session = store.OpenSession()) {
    using (var transaction = session.Advanced.DocumentStore.BeginTransaction()) {
        var order = session.Load("orders/1");
        order.Status = OrderStatus.Completed;
        session.Store(new OrderAudit {
            OrderId = order.Id,
            Status = order.Status
        });
        session.SaveChanges();
        transaction.Commit();
    }
}

The code above shows a transaction that modifies an order’s status and then saves an audit trail of the modification. The transaction is created using the BeginTransaction method, with the modifications being made within the transaction. If the transaction completes successfully, it is committed.
