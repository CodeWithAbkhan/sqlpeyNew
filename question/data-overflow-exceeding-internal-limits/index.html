Overflow sort stage buffered data usage exceeds internal limit Dealing With MongoDB Sort Overflow
When trying to sort data in MongoDB, you might encounter the error “Overflow sort stage buffered data usage exceeds internal limit”. This is because MongoDB has a 32MB sort limit for in-memory sorting. If you exceed this limit, you will be presented with the error.

To help you understand how to deal with this error, we’ll take a look at an example. Consider a MongoDB instance with a reviews collection. We want to sort the documents in the collection by review date. To do this, we use the following code:

all_reviews = db_handle.find().sort('reviewDate', pymongo.ASCENDING)
print all_reviews.count()

print all_reviews[0]
print all_reviews[2000000]

The count prints 2043484, and it prints all_reviews[0]. However, when printing all_reviews[2000000], we get the error:

pymongo.errors.OperationFailure: database error: Runner error: Overflow sort stage buffered data usage of 33554495 bytes exceeds internal limit of 33554432 bytes

Handling the Error

To handle this error, you need to add an index to the sort field. This allows MongoDB to stream documents to you in sorted order, rather than attempting to load them all into memory on the server and sort them in memory before sending them to the client.

You can view the current buffer usage using the below command over the admin database:

> use admin
switched to db admin
> db.runCommand( { getParameter : 1, "internalQueryExecMaxBlockingSortBytes" : 1 } )
{ "internalQueryExecMaxBlockingSortBytes" : 33554432, "ok" : 1 }

It has a default value of 32 MB (33554432 bytes). In this case, you’re running short of buffer data so you can increase buffer limit with your own defined optimal value, for example, 50 MB as follows:

>  db.adminCommand({setParameter: 1, internalQueryExecMaxBlockingSortBytes:50151432})
{ "was" : 33554432, "ok" : 1 }

We can also set this limit permanently by the below parameter in the MongoDB config file:

setParameter=internalQueryExecMaxBlockingSortBytes=309715200

Note: This command supports only after version 3.0.

Solving the Issue with Indexing

The easiest way to solve this issue is to add an index to the sort field. This can be done with the following code:

db_handle.ensure_index([("reviewDate", pymongo.ASCENDING)])

If you want to avoid creating an index (for example, you just want a quick-and-dirty check to explore the data), you can use aggregation with disk usage:

all_reviews = db_handle.aggregate([{$sort: {'reviewDate': 1}}], {allowDiskUse: true})

(Not sure how to do this in pymongo, though).

JavaScript API Syntax for the Index

The JavaScript API syntax for the index is as follows:

db_handle.ensureIndex({executedDate: 1})
