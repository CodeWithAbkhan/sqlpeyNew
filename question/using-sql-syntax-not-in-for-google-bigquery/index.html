Using NOT IN Syntax for Google BigQuery
When working with Google BigQuery, you may sometimes need to filter data from one table based on values not present in another table. In such cases, you can use the NOT IN syntax in your query. Although, the official Google SQL syntax guide does not seem to address the use of NOT IN terminology.

If you try to run a query using the NOT IN syntax without proper syntax, you may encounter an error message like:

Query Failed
Error: Encountered "" at line 0, column 0. Was expecting one of:

To use the NOT IN syntax in Google BigQuery, you need to use a subquery witing the code. Here’s an example:

SELECT field
FROM table
WHERE field [NOT] IN (SELECT other_field FROM other_table WHERE foo = 'bar')

In the code above, field represents the column name to filter, while table is the table where you want to apply the filter. The NOT keyword is optional and serves to negate the condition. On the other hand, other_field is the column in the other table to compare with, while other_table is the second table that you want to compare values with. Lastly, foo='bar' is a condition that further filters the rows returned by the subquery.

Here’s an example of how to use the NOT IN syntax in your code:

SELECT ageinmonths, amountborrowed, borrowerrate, creationdate, creditgrade,
       debttoincomeratio, groupkey, key, lenderrate, listingkey, modifieddata,
       originationdate, prosperrating, status, term
FROM prosperloans1.loans2 as big
WHERE big.listingkey NOT IN (
    SELECT listingkey FROM prosperloans1.dupelistingkeysinloans2
)

In this query, prosperloans1.loans2 is the table to filter, while prosperloans1.dupelistingkeysinloans2 is another table that you want to compare values with. The subquery selects all the values of the listingkey column from the second table. The main query then filters out all rows from the first table where the listingkey column value is not present in the subquery’s result.

Alternative Approach: Using LEFT JOIN

Another way to filter tables based on values not present in another table is to use a LEFT JOIN statement. Here’s an example:

SELECT t1.id, t1.name
FROM table1 as t1
LEFT JOIN table2 as t2
ON t1.id = t2.id
WHERE t2.id IS NULL

In this example, table1 is the table to filter, while table2 is the other table. The LEFT JOIN statement combines all rows from table1 with matching rows from table2, keeping all rows from table1 even if there is no matching row in table2. The WHERE clause filters out all rows with NULL values in the joined column, i.e., rows not present in the other table.

Ultimately, both approaches work to achieve the same result, so use the one that you find most readable and efficient according to your dataset. ]]>
