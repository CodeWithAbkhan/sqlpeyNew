NOSQL: Validating Presence and Regex Format in Rails Controller: A Guide Validating Email Address in Rails Controller
Validating data is crucial in any web application to ensure its accuracy, consistency, and reliability. Data validation in Rails can be done in the model, view, or controller. In this post, we are going to focus on validating email addresses in the controller using regex.

Problem Statement

We want to validate the email address provided by the user in the controller, whether it is present or not and meets a regex criteria (/xyz/). We do not want to use ActiveRecord for our application as we plan on using a NoSQL database later.

Solution

We can write our custom validation method in the Rails controller to validate the email address. Here’s an example:

class UsersController < ApplicationController
  def create
    user = User.new(user_params)
    if valid_email?(user.email)
      user.save
      redirect_to root_url, notice: 'Good email'
    else
      flash[:error] = 'Bad email!'
      render :new
    end
  end

private
  def user_params
    params.require(:user).permit(:email)
  end

  def valid_email?(email)
    valid_email_regex = /xyz/i
    email.present? && (email =~ valid_email_regex)
  end
end

The above code shows the UsersController class that handles the create action to create a new user with the provided email address. We call a custom validation method called valid_email? to check the email’s presence and format. If the email is valid, we save the user and redirect them to the root URL with a notice message. Otherwise, we set a flash error message and render the new template for creating a new user.

The private user_params method sanitizes the user input with the require and permit methods to guard against mass-assignment vulnerabilities.

The private valid_email? method checks if the email is present and meets the regex criteria. In this case, we’ve used a dummy regex pattern /xyz/ to test if the validation works. Although, you can replace it with a regex pattern that matches your email validation criteria.

Using ActiveModel::Validations in Rails

Although we can write custom validation methods in the controller, it’s not considered best practice. We should keep validation logic in the model, where Rails provides us with a built-in validation framework using ActiveModel::Validations.

We can create a custom model for our user and include ActiveModel::Validations module to validate our user’s email address. Here’s an example:

class User
  include ActiveModel::Model
  include ActiveModel::Validations

  attr_accessor :email

  validates :email, presence: true, format: { with: VALID_EMAIL_REGEX }

  private

  VALID_EMAIL_REGEX = /A[w+-.]+@[a-zd-.]+.[a-z]+z/i
end

The above code shows a custom User class that includes ActiveModel::Model and ActiveModel::Validations modules to provide us with ActiveRecord-like validation capabilities. We declare an email attribute using attr_accessor and validate it with the validates method that ensures its presence and format matches a valid email pattern.

We’ve also declared a private VALID_EMAIL_REGEX constant to handle email validation. This pattern imposes a standard that email addresses should have a valid username, domain name, and top-level domain name.

Recap

Data validation is essential in any web application to ensure the integrity of the data. We’ve shown how to validate email addresses in the Rails controller using regex patterns and ActiveModel::Validations in a custom model. Always remember to keep validation logic in the model and write clean, concise, and maintainable code. ]]>
