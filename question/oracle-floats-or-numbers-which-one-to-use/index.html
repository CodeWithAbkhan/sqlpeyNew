Oracle: Floats or Numbers – Which One to Use? Oracle Floats vs Number

Introduction

When working with Oracle databases, there are several data types that can be used to store numbers with decimal points. Although, there is often confusion about the differences between these data types, particularly when it comes to floats and numbers. This blog post seeks to clarify the distinction between the Oracle FLOAT and NUMBER data types and explain how they store decimal numbers.

What is a FLOAT?

A float is a data type used to represent decimal numbers with precision limitations. For example, in C++, 0.1(base 10) may be approximated as 0.110011001100110011001101(base 2), which is roughly equal to 0.100000001490116119384765625(base 10). This is because floats have accuracy limitations that integer data types do not have.

What is an Oracle FLOAT?

In Oracle, the FLOAT data type has been defined as a synonym for the ANSI SQL NUMERIC data type, which is also called NUMBER in Oracle. This is an exact numeric, scaled decimal data type with no rounding behavior like that of IEEE 754. In other words, FLOATs in Oracle are the same as the NUMBER data type.

What is an Oracle BINARY_FLOAT?

Oracle also has a BINARY_FLOAT data type, which stores data internally using the IEEE 754 floating-point representation. This is similar to the way many languages, including C, store floats internally. Fetching BINARY_FLOATs from the database and storing them in an IEEE 754 data type in the host language will not require any transformation.

What is an Oracle BINARY_DOUBLE?

Oracle’s BINARY_DOUBLE is another data type that stores decimal numbers with double the precision of BINARY_FLOAT. It is also stored internally in the IEEE 754 floating-point representation, but uses 9 bytes of storage instead of the usual 8 bytes used by IEEE 754.

How are floats and numbers stored differently in Oracle?

The main difference between FLOATs and NUMBERs in Oracle is how they store decimal numbers. NUMBERs are exact and scaled, whereas FLOATs may be subject to accuracy limitations. Although, if you fetch values from the database and store them in a C or Java float, you may lose precision during this step. BINARY_FLOATs and BINARY_DOUBLEs, on the other hand, are stored in the IEEE 754 floating-point representation, similar to C.

Practical Examples

To illustrate the differences between FLOATs and NUMBERs in Oracle, consider the following table:

CREATE TABLE decimal_numbers (
    decimal_float FLOAT,
    decimal_number NUMBER
);

If we insert the value 3.123456789 into the table using both data types, we get:

INSERT INTO decimal_numbers VALUES (3.123456789, 3.123456789);

SELECT * FROM decimal_numbers;

-- Output:
--     DECIMAL_FLOAT    DECIMAL_NUMBER
--     3.123456715    3.123456789

Notice how the value stored in the FLOAT column is slightly different from the original value, whereas the value stored in the NUMBER column is exactly the same.

Alternative Ways

If you want to avoid potential precision loss when fetching values from the database, consider using the BINARY_FLOAT or BINARY_DOUBLE data types instead of FLOAT. Otherwise, always use NUMBER when you require exact precision.

Recap

In recap, knowing the differences between the Oracle FLOAT and NUMBER data types is crucial when working with decimal numbers in the database. FLOATs have accuracy limitations, whereas NUMBERs are exact and scaled. Although, if you fetch values from the database and store them in a C or Java float, you may lose precision. To avoid this, consider using the BINARY_FLOAT or BINARY_DOUBLE data types instead of FLOAT.]]>
