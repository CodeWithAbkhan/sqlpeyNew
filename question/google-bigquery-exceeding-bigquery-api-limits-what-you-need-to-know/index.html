BigQuery API Limit Exceeded Error - Troubleshooting

Problem

We are getting the “API limit exceeded: Unable to return a row that exceeds the API limits. To retrieve the row, export the table” error when performing a tabledata.list. We have checked but this error is not listed on the BigQuery Error Table . The error occurs every time and we are only able to retrieve several result pages before the error occurs. Although, we are able to export the table into Google Cloud Storage (GCS) normally without issues.

Solution

The error message is indicating that the API limit has been exceeded for returning rows that exceed the API limits. Google BigQuery has an API limit for the amount of data that can be retrieved via the API in a single request or response. Exporting the table to GCS solves this problem as it does not utilize the BigQuery API to retrieve the data.

To resolve this issue, we can try some of the following solutions:

1. Format the rows to consume less content

The BigQuery API limits the length of a row in bytes to 100MB. Therefore, itâ€™s important to ensure that each row doesn’t exceed the maximum length. You can try formatting the rows to consume less content, and then retry the table.list method.

2. Use pagination for retrieving data

The API limit breached may be related page size or the number of rows to be retrieved through a single API call. Splitting the request into smaller segments can help avoid the limit. Using pagination will allow you to retrieve the data in smaller chunks that won’t exceed the API limit.

3. Increase API quota limits

If using pagination or formatting the rows does not solve the problem, we can try increasing the API quota limits. Although, this may not always be possible, and it depends on your BigQuery pricing plan and the specific quota that has been exceeded.
