ORACLE: Optional WHERE Parameters for Stored Procedures Summary: This Q&A Session discusses how to create a stored procedure with optional “WHERE” parameters. The Q&A Session provides a solution using a dynamic where clause that allows for the selection of one or more fields. This approach eliminates the need for dynamic SQL and minimizes the risk of SQL injection attacks.
Creating a Stored Procedure: The first step is to create a stored procedure that accepts the optional parameters. The following is an example of a stored procedure that accepts @fromDate, @toDate, and @subCode as optional parameters:

CREATE PROCEDURE [dbo].[spXXX]
    @fromDate datetime = null,
    @toDate datetime = null,
    @subCode int = null
as
begin
set NOCOUNT ON
/* NOCOUNT limits the server feedback on select results record count */
SELECT
    fields...
FROM
    source
WHERE
    1=1
--Dynamic where clause for various parameters which may or may not be passed in.
and ( @fromDate is null or [dateField] >= @fromDate)
and ( @toDate is null or [dateField] <= @toDate)
and ( @subCode is null or subCode= @leaveTypeSubCode)
order by fields...

The @fromDate, @toDate, and @subCode parameters are initialized to null. The NOCOUNT option limits the server feedback on select results record count. The SELECT statement retrieves the required fields from the source table. The WHERE clause provides a dynamic where clause that filters records based on the passed-in parameters.
Dynamic Where Clause: The dynamic WHERE clause builds the filter based on the passed-in parameters. If a parameter is null, the filter is ignored. If a parameter is not null, it adds a filter to the WHERE clause. The following is an example of a dynamic WHERE clause:

and ( @fromDate is null or [dateField] >= @fromDate)
and ( @toDate is null or [dateField] <= @toDate)
and ( @subCode is null or subCode= @leaveTypeSubCode)

The WHERE clause returns records if any or all of the parameters are matched.
Alternative Ways: One of the easiest ways to accomplish optional parameters is to use the following query approach:

SELECT * FROM table 
WHERE ((@status_id is null) or (status_id = @status_id))
and ((@date is null) or ([date] = @date))
and ((@other_parameter is null) or (other_parameter = @other_parameter))

This approach uses a NULL check condition for each parameter. If the parameter matches or is null, it returns records.
Practical Example: Consider a table named UserInfo that contains UserID, FirstName, LastName, UserEmail, and UserAge. You want to create a stored procedure that returns records based on the passed-in parameters. The following is an example:

CREATE PROCEDURE [dbo].[spGetUserInfo]
    @firstName varchar(50) = null,
    @lastName varchar(50) = null,
    @userEmail varchar(100) = null,
    @userAge int = null
as
begin
set NOCOUNT ON
SELECT UserID, FirstName, LastName, UserEmail, UserAge
FROM UserInfo
WHERE 
    ( @firstName is null or FirstName = @firstName)
    and ( @lastName is null or LastName = @lastName)
    and ( @userEmail is null or UserEmail = @userEmail)
    and ( @userAge is null or UserAge = @userAge)
end

The stored procedure uses four optional parameters: @firstName, @lastName, @userEmail, and @userAge. The SELECT statement retrieves UserID, FirstName, LastName, UserEmail, and UserAge. The WHERE clause applies filters based on passed-in parameters.
Recap: The stored procedure with the dynamic filter approach provides a way to manage optional parameters. The approach eliminates the need for dynamic SQL, minimizes the risk of SQL injection attacks, and filters data based on one or more filters. The approach is not limited to a specific database system and can be used in MySQL, Oracle, and SQLServer.]]>
