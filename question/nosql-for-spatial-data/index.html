NoSQL for Spatial Data Using NoSQL Databases for Storing Spatial Data
Have you ever used a NoSQL (non-relational) database for storing spatial data? Would there be any benefits to using such databases for holding data for a desktop application when compared to using SpatiaLite or PostGIS?

Along with MongoDB, other graph databases such as Neo4j are also a good fit for storing spatial data, especially as you can add different indexing schemes dynamically as you go. One-dimensional indexing such as Timelines or B-Trees can be added to your base data, or funkier stuff like Hilbert Curves. Even some open source GIS desktop tools such as AWE use indexed graphs, as demonstrated in this video here.

Using MongoDB for Spatial Data

Currently, MongoDB uses geohashing with B-trees which is slower than the R-trees of PostGIS. Although, in these slides, the author talks about adding R-trees to MongoDB and sharding on a geo key. Geo-sharding may not be of interest for desktop use, as sharding’s benefits will be more significant on massive datasets.

If you are interested in storing billions or trillions of spatial objects and just running basic queries such as find all points near/inside this point based on some criteria, then MongoDB is likely an excellent choice. But if you need more advanced functionality such as support for topology, rasters, 3D, or conversions between coordinate systems, then PostGIS would still be the best option.

CouchDB’s Simple Spatial Extension

CouchDB also has a simple extension for spatial data. For more information about using CouchDB for spatial data, take a look at this page.

Recap

In recap, using NoSQL databases for storing spatial data can provide unique benefits such as increased scalability and dynamic indexing schemes. Although NoSQL databases such as MongoDB have less advanced functionality compared to spatial databases such as PostGIS, they can be an excellent option for basic queries with large datasets. Overall, it depends on your use case, and you should choose a database that fits your needs, whether that’s a traditional spatial database or a NoSQL database. ]]>
