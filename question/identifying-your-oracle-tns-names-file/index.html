Identifying Your Oracle Tns Names File

Identifying Your Oracle TNS Names file Summary: This blog post provides various solutions on how to find the TNS Names file being used by an Oracle database client. It includes the use of the tnsping utility, the strace command in Linux, and the registry editor in Windows.

What is a TNS Names file in Oracle?
A TNS Names file is a configuration file used by Oracle clients to connect to a remote database. It contains a list of database hostnames or IP addresses, port number, and database names (SID or Service Name).

How to find the TNS Names file being used by an Oracle client?

Using tnsping utility

Oracle provides a utility called tnsping, which can be used to check the connectivity to a remote Oracle database. It can also show the TNS Names file being used by the client.

$ tnsping

The above command will try to ping the database specified by the <alias> parameter and show the TNS Names file being used by the client.

Example:

$ tnsping orcl
Used parameter files:
C:oracleproduct11.2.0client_1networkadminsqlnet.ora
C:oracleproduct11.2.0client_1networkadmintnsnames.ora

Used TNSNAMES adapter to resolve the alias
Attempting to contact (DESCRIPTION = (ADDRESS = (PROTOCOL = TCP)(HOST = dbhost)(PORT = 1521))(CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))
OK (10 msec)

The above output shows that the client is using the tnsping utility with the orcl alias, and it’s using the tnsnames.ora file located in C:oracleproduct11.2.0client_1networkadmin.

Using strace command in Linux

The strace command in Linux can be used to trace system calls and signals for a running process. We can use it to trace the open system calls and see which TNS Names files are being accessed by the Oracle client.

$ strace sqlplus user/password@dbname 2>&1 | grep -i 'open.*tnsnames.ora'

The above command will start the sqlplus client with the specified user, password, and dbname, and trace the open system calls that contain the string “tnsnames.ora”. The 2>&1 redirects any error messages to the output stream, and the grep command filters the output to only show the relevant lines.

Example:

$ strace sqlplus scott/tiger@orcl 2>&1 | grep -i 'open.*tnsnames.ora'
open("/u01/app/oracle/product/11.2.0/dbhome_1/network/admin/tnsnames.ora", O_RDONLY) = 4

The above output shows that the Oracle client is using the tnsnames.ora file located in /u01/app/oracle/product/11.2.0/dbhome_1/network/admin.

Using Registry Editor in Windows

On Windows, the TNS Names file location can be found in the Windows Registry. We can navigate to the registry editor and check if the TNS_ADMIN key is set in the Oracle home.

Open the Registry Editor by typing “regedit” in the Run command or the search bar in the Start menu.

Navigate to the path:

My HKEY_LOCAL_MACHINESoftwareOracleKEY_OraClient-home

Replace <version> with the Oracle version (e.g., 11.2) and <number> with the Oracle home number (e.g., 1).

If there is a string entry called TNS_ADMIN, then the value will be the path to the TNS Names file being used by the Oracle client.

Example:

If there is a TNS_ADMIN key with the value C:oracleproduct11.2.0client_1networkadmin, then the Oracle client is using the tnsnames.ora file located in that directory.

Recap

Finding the TNS Names file being used by an Oracle database client can be done using various methods. These include using the tnsping utility, the strace command in Linux, and the registry editor in Windows. Knowing the TNS Names file location is essential in troubleshooting connection issues and managing database client configurations.
