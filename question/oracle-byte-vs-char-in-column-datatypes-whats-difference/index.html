ORACLE: BYTE vs CHAR in Column Datatypes: What’s the Difference? Learning the Difference between BYTE and CHAR in Column Datatypes in Oracle
When creating tables in Oracle, there are several datatypes that can be used for defining columns. Two of the most commonly used datatypes include BYTE and CHAR, which are often used for defining the length of character columns in a table. Although, these datatypes are not interchangeable and can have different effects on the amount of data that can be stored in a column, depending on the character set being used.

The Difference between BYTE and CHAR in Oracle

The difference between BYTE and CHAR lies in the way that they define the length of a string field. When defining a column as VARCHAR2(11 BYTE), Oracle will allocate exactly 11 bytes of memory for that field. Although, if multi-byte characters are used in the string, the field may not be able to store 11 characters. On the other hand, defining the same field as VARCHAR2(11 CHAR) will allocate enough memory to store 11 characters, regardless of how many bytes each character takes up.

For instance, the string “été” takes up four bytes in UTF-8, but only three characters in length. If you define a column as VARCHAR2(3 BYTE), this will only allow you to store the first three bytes of the string, which gives you “ét” rather than “été”. Although, if you define the column as VARCHAR2(3 CHAR), the column will have enough space to store the entire string as all three characters will be accounted for.

It’s important to keep in mind that not all character sets have the same number of bytes per character. Some character sets, like UTF-8, use variable-length encoding where characters can take anywhere from 1-4 bytes to store, while others, like UTF-32, use fixed-length encoding so all characters use the same number of bytes. This means that when defining column lengths in Oracle, you need to pay attention to the character set being used and the number of bytes required to store each character.

Examples of the Difference between BYTE and CHAR in Oracle

Let’s say you have an Oracle database using UTF-8 as the character set. You want to create a table to store information about clients, including their name and ID. Here are two examples of how you could define the table:

CREATE TABLE CLIENT
(
 NAME VARCHAR2(11 BYTE),
 ID_CLIENT NUMBER
);

				

				  

CREATE TABLE CLIENT
(
 NAME VARCHAR2(11 CHAR),
 ID_CLIENT NUMBER
);

In the first example, the NAME field is defined as VARCHAR2(11 BYTE), which means it will allocate exactly 11 bytes of memory for the field. This may not be enough to store 11 characters, depending on the character set being used. In contrast, the second example defines the same field as VARCHAR2(11 CHAR), which allocates enough memory to store 11 characters regardless of the number of bytes required for each character.

Suppose you want to insert data into this table. Here’s an example of how you could do it:

INSERT INTO CLIENT (NAME, ID_CLIENT)
VALUES ('John Doe', 1);

In this case, the string ‘John Doe’ takes up 8 bytes in UTF-8, which means it can be stored in a field defined as VARCHAR2(11 BYTE). Although, if you tried to insert a string like ‘好久不见’ (which means ’long time no see’ in Chinese and takes up 12 bytes in UTF-8), it would not fit in a field defined as VARCHAR2(11 BYTE). Instead, you would need to define the field as VARCHAR2(4 CHAR) to allow for the four characters in the string.

Alternative Ways to Define Column Datatypes in Oracle

While BYTE and CHAR are commonly used datatypes for defining column lengths in Oracle, you can also use other datatypes like CLOB, NCLOB, and NVARCHAR2, depending on the type of data you need to store.

CLOB and NCLOB are used for storing large amounts of character data (up to 4 GB), while NVARCHAR2 is used for storing Unicode character data. These datatypes have different size limitations and performance characteristics than BYTE and CHAR, so it’s important to choose the right datatype for the type of data you need to store.

Recap

When defining columns in Oracle tables, it’s important to be mindful of the character set being used and the number of bytes required to store each character. While BYTE and CHAR are both commonly used datatypes for defining column lengths, they have different effects on the amount of data that can be stored in a column. By choosing the right datatype for the data you need to store, you can ensure that your tables are optimized for performance and can handle the data you need to store.
