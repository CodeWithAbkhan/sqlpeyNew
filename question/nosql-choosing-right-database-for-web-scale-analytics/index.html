Database Selection for Web-Scale Analytics Application: Q&A Style

What is the objective of a web-scale analytics application?

A web-scale analytics application collects statistics on end-users’ behavior and provides analysis to the customers based on that data. The objective is to offer insights and actionable information that can help optimize online operations, improve user experience, and enhance business outcomes.

What are the key characteristics of a web-scale analytics application?

A web-scale analytics application should have high scalability, handle large volumes of data, support analytical queries, and be compartmentalized so that queries always run on a single customer’s data. It should also provide real-time or near-real-time data processing capabilities.

What are the recommended database options for a web-scale analytics application?

There are two recommended architectural options for a web-scale analytics application:

1) BI Architecture

The BI architecture involves using an event journaller (such as LWES Journaller) or immutable event store (such as HDFS) to feed into an analytics/column-store database (such as Greenplum, InfiniDB, LucidDB, or Infobright), which in turn feeds into a business intelligence reporting tool (such as Microstrategy or Tableau). This architecture facilitates real-time data processing and is ideal for applications with extremely large volumes of data and complex analytical needs.

2) OLAP Cube Architecture

The OLAP cube architecture involves using an online analytical processing (OLAP) cube to store and analyze data. The cube acts as a multidimensional database that can quickly process analytical queries and provide insights in near-real-time, making it suitable for applications with less complex analytical needs, but still handling large volumes of data. Examples of OLAP cube solutions include Mondrian, Microsoft Analysis Services, and SAP HANA.

What are some recommended databases to use for a web-scale analytics application?

For the BI Architecture, recommended databases include:

  • Greenplum: An open-source data platform that uses a massively parallel processing (MPP) architecture for real-time data analytics and processing.
  • InfiniDB: An open-source column-store database designed for data warehousing and online analytics.
  • LucidDB: Another open-source column-store database that offers high scalability, support for SQL, and real-time data processing capabilities.
  • Infobright: A column-store database optimized for analytical queries and able to handle large volumes of data.

For the OLAP Cube Architecture, recommended databases include:

  • Mondrian: An open-source OLAP server that supports multiple data sources, provides dimensional modeling, and integrates with many business intelligence tools.
  • Microsoft Analysis Services: A commercial product that provides OLAP and data-mining capabilities, as well as integration with Office applications.
  • SAP HANA: A commercial in-memory database that supports OLAP, predictive analytics, and real-time data processing.

Are there any other recommendations for database selection for a web-scale analytics application?

One possible approach is to use a combination of PostgreSQL, LucidDB, and Mondrian. PostgreSQL is used to store the operational data, LucidDB is used as the data warehouse database for retrieving large amounts of data, and Mondrian acts as the OLAP cube for analysis. This approach offers a flexible and cost-effective solution for web-scale analytics applications.

Recap

Building a web-scale analytics application requires careful consideration of the application’s analytical needs, data volumes, and processing capabilities. Choosing the right database architecture is critical for achieving scalable and real-time data processing, supporting analytical queries, and providing actionable insights. The recommended database options for web-scale analytics applications include BI Architecture and OLAP Cube Architecture, with options such as Greenplum, InfiniDB, LucidDB, Infobright, Mondrian, Microsoft Analysis Services, and SAP HANA. Using a combination of PostgreSQL, LucidDB, and Mondrian is also a viable option for a cost-effective and flexible solution. ]]>
