Advice Needed: NoSQL/MongoDb Data and Models Structure
Summary:

This blog post aims to provide advice on how to store data efficiently in a NoSQL database, specifically MongoDB. It uses a simple example of three models - Story, User, and Vote - to demonstrate how to structure the data to optimize queries such as “Who has voted for this Story?” and “What has this User voted for?”. The post also emphasizes the importance of abandoning the traditional approach of data normalization and adopting a more flexible and object-oriented way of thinking in NoSQL databases.

Advices:

  1. Forget the traditional approach of data normalization

In traditional relational databases, data is structured and organized into tables to ensure data consistency and to avoid redundancy. Although, in NoSQL databases like MongoDB, the focus is on flexibility and scalability. Therefore, it is not necessary to follow strict normalization rules as it can result in slower queries and increased complexity.

  1. Let views dictate your models

Instead of designing your data model based on how the data will be stored in the database, start by designing your views and let them dictate your data model. This approach will help you to create a more efficient and flexible database schema that can handle changes in the views without significant changes in the data model.

  1. Store data as objects with shapes

In NoSQL databases, you can store data in a more object-oriented way. So, instead of breaking down your data into multiple tables with different relationships, you can store them as objects with shapes. This approach will make it easier to query the data and to update it without worrying about constraints and data consistency.

  1. Use denormalization to optimize queries

Denormalization is the process of duplicating data across different collections to optimize query performance. In MongoDB, you can use denormalization to store the data in a way that will allow you to query it more efficiently. For example, you can store the votes as a list of story ids in each user to make it easier to find out what stories a user has voted for.

Practical Example:

Let’s say we have the following data models:

Story:  
id  
title
    
User:  
id  
name
    
Vote:  
id  
story\_id  
user\_id

To optimize queries such as “Who has voted for this Story?” and “What has this User voted for?”, we can denormalize the data as follows:

User:  
id  
name  
votes: [{story\_id:...}, {story\_id:...}, ...]
    
Story:  
id  
title  
voters: [{user\_id:...}, {user\_id:...}, ...]

Now, to find out who has voted for a particular story, we can simply query the User collection with the story_id as a filter:

db.users.find({votes: {story\_id:...}})

Similarly, we can find out what a user has voted for by querying the User collection with the user_id as a filter:

db.users.find({id: user\_id}, {votes: 1})

Alternative Ways:

In MongoDB, there are many ways to structure the data to optimize queries. Some other approaches you can try are:

  1. Embed the votes into the Stories collection as an array of user ids:
Story:  
id  
title  
votes: [user\_id, user\_id, ...]

This approach can make it easier to query the Stories collection for voting information, but it can also make the writes more complex and slower.

  1. Use references instead of embedded documents:
User:  
id  
name
    
Story:  
id  
title  
votes: [vote\_id, vote\_id, ...]
    
Vote:  
id  
story\_id  
user\_id

This approach can simplify the writes, but it can also make the reads slower and more complex as you need to run multiple queries to fetch the complete data.

Recap:

In summary, optimizing data storage in NoSQL databases like MongoDB requires a different way of thinking than traditional relational databases. By adopting a flexible and object-oriented approach, denormalizing the data, and using the appropriate indexing and querying techniques, you can achieve better performance and scalability. ]]>
