PostgreSQL’s Equivalent of Oracle’s SYSDATE: Explained What is the PostgreSQL equivalent of SYSDATE from Oracle?
Summary: PostgreSQL does not support the SYSDATE function, which is an Oracle-only function. Although, PostgreSQL provides three functions to obtain the current date and/or time: CURRENT_TIME, CURRENT_DATE, and CURRENT_TIMESTAMP.

Explanation:

In Oracle, SYSDATE returns the current date and time according to the system clock. It is often used in queries to filter results based on today’s date or to calculate the difference between two dates.

Although, PostgreSQL does not support the SYSDATE function. Instead, it provides three functions to obtain the current date and/or time:

  • CURRENT_TIME: Returns the current time without the date.
  • CURRENT_DATE: Returns the current date without the time.
  • CURRENT_TIMESTAMP: Returns the current date and time.

Here’s an example of using the CURRENT_DATE function in a query to filter results based on today’s date:

SELECT up_time 
FROM exam 
WHERE up_time = CURRENT_DATE;

Note that Oracle returns the date and time by default with SYSDATE, while PostgreSQL returns only the date with CURRENT_DATE. If you want to include the time in PostgreSQL, you need to use CURRENT_TIMESTAMP instead.

Here’s an example of using the CURRENT_TIMESTAMP function in a query to filter results based on today’s date and time:

SELECT up_time 
FROM exam 
WHERE up_time = CURRENT_TIMESTAMP::DATE;

This query uses CURRENT_TIMESTAMP to return the current date and time, and then casts it to a date to compare with the up_time column, which should also be a date.

Alternative Ways:

There’s no direct replacement for SYSDATE in PostgreSQL, but you can use the NOW() function as an alternative:

SELECT NOW();

This will return the system timestamp, which includes both the date and time.

Practical Examples:

Here’s an example of using CURRENT_DATE in a query to calculate the number of days between two dates:

SELECT end_date - start_date AS duration_in_days 
FROM project 
WHERE end_date >= CURRENT_DATE;

This query returns the number of days between the start_date and end_date columns in the project table, but only for projects that haven’t yet ended (i.e., where end_date is greater than or equal to today’s date).
