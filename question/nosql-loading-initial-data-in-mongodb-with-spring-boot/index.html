NOSQL: Loading Initial Data in MongoDB with Spring Boot How to Load Initial Data in MongoDB with Spring Boot?
When working with MongoDB and Spring Boot, you may need to load some initial data into the database. While the data.sql file is used for SQL databases, it is not applicable for NoSQL databases like MongoDB. Here, we will explore how we can load initial data into MongoDB using repository populators and other means.

Loading Initial Data Using Repository Populators

Sometimes, you may just need to load some initial data for testing purposes, without using any third-party tool. This can be done by defining the initial data in a JSON or XML format and using a repository populator to load it into the repository.

First, create a configuration class and inject the JSON or XML file containing the data:

@Configuration
class TestApplicationConfig {
  @Value("classpath:test_data.json")
  private lateinit var testData: Resource
}

Next, define a repository populator that uses the object mapper to read the data from the file and populate the repository:

@Bean
@Autowired
fun repositoryPopulator(objectMapper: ObjectMapper): Jackson2RepositoryPopulatorFactoryBean {
  val factory = Jackson2RepositoryPopulatorFactoryBean()
  factory.setMapper(objectMapper)
  factory.setResources(arrayOf(testData))
  return factory
}

Here, we use the Jackson2RepositoryPopulatorFactoryBean to populate the repository with the data in test_data.json. We use the ObjectMapper to deserialize the JSON data into Java objects, which are then inserted into the repository.

Using MongoBee to Load Initial Data

If you prefer using a migration tool to load data into your MongoDB database, you can use MongoBee, a simple, database-agnostic tool for managing database changes:

  1. Add the MongoBee dependency to your pom.xml or build.gradle file:

         com.github.mongobee
     mongobee-core
     0.13

  2. Configure the MongoBee migration:

     @Bean
 fun mongobee() : Mongobee {
     val runner = Mongobee("mongodb://localhost:27017/test")
     runner.setChangeLogsScanPackage("com.example.demo.changelog")
     return runner
 }

    Here, we define a bean of type Mongobee and set the MongoDB connection URL as well as the package to scan for change-logs. The change-logs contain the data migration scripts that add the initial data to the database.

  3. Create the change-log file:

    Create a new file under the package specified in the Mongobee configuration, for example com.example.demo.changelog/V1__initialize_data.js:

     db.products.insertMany([
   {
     "_id": "1",
     "name": "iPhone",
     "description": "Apple iPhone with iOS operating system",
     "price": 999.99
   },
   {
     "_id": "2",
     "name": "Samsung Galaxy",
     "description": "Samsung phone with Android operating system",
     "price": 799.99
   }
 ])

    In the above example, we define two documents to insert into the products collection. These documents will be loaded into the database when the application starts.

Recap

In this Q&A Session, we have explored different ways to load initial data into a MongoDB database using Spring Boot. Depending on your requirements, you can use a repository populator to load data from a JSON or XML file or use a migration tool like MongoBee to manage the database changes. ]]>
