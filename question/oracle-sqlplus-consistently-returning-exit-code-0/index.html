ORACLE: SQL*Plus: Consistently Returning Exit Code 0? How to Make Sql*plus Return a Non-Zero Exit Code

Summary:

Sql*plus always returns exit code 0 even when the script isn’t successful. To make it return a non-zero value when an error occurs, you need to add “WHENEVER SQLERROR EXIT SQL.SQLCODE” or “WHENEVER OSERROR EXIT FAILURE” to your script.

Q&A:

Why does Sql*plus always return an exit code of 0?

Sql*plus always returns exit code 0 because it is designed to indicate only whether there was an error in running the Sql*plus command itself, not whether your script succeeded or failed.

How can I make Sql*plus return a non-zero exit code?

To make Sql*plus return a non-zero exit code when your script errors out, add “WHENEVER SQLERROR EXIT SQL.SQLCODE” or “WHENEVER OSERROR EXIT FAILURE” to your script.

What is the “WHENEVER SQLERROR EXIT SQL.SQLCODE” statement?

The “WHENEVER SQLERROR EXIT SQL.SQLCODE” statement tells Sql*plus to return the Oracle error code returned by the database as the exit code. This will cause Sql*plus to exit with a non-zero value, indicating that your script failed.

Here is an example:

WHENEVER SQLERROR EXIT SQL.SQLCODE
begin
  SELECT COLUMN_DOES_NOT_EXIST FROM DUAL;
END;
/

In this example, the script tries to select a column that doesn’t exist. When the script errors out, Sql*plus will exit with a non-zero value, indicating that the script failed.

What is the “WHENEVER OSERROR EXIT FAILURE” statement?

The “WHENEVER OSERROR EXIT FAILURE” statement tells Sql*plus to exit with a non-zero value if an operating system error occurs, such as if the script fails to find a file it is supposed to read. This can be useful if your script relies on external files or programs.

Here is an example:

WHENEVER OSERROR EXIT FAILURE
START no_such_file

In this example, the script tries to start a file that doesn’t exist. When the script errors out, Sql*plus will exit with a non-zero value, indicating that the script failed.

Are there any other ways to make Sql*plus return a non-zero exit code?

One alternative way to make Sql*plus return a non-zero exit code is to use the “EXIT” statement in your script to explicitly set the exit code to a specific value. For example:

column status_for_exit new_value exitcode noprint
select status_computation (parm, parm) as status_for_exit from dual;

exit &exitcode;

In this example, the script sets the value of “exitcode” based on some computation, and then exits with that value by using the “EXIT” statement.

Practical Example:

Suppose you have a Sql*plus script that does some calculations and outputs the results to a file. You want to make sure that the script exits with a non-zero exit code if any errors occur during the calculations or output. Here is an example of how you could modify your script to do this:

WHENEVER SQLERROR EXIT SQL.SQLCODE
WHENEVER OSERROR EXIT FAILURE

set termout off
set serveroutput on

var output_file varchar2(100) := 'output.txt';

BEGIN
  dbms_output.enable(NULL);
  dbms_output.put_line('Starting calculation...');
  -- Your script goes here
  dbms_output.put_line('Calculation complete.');
  spool &output_file
  -- Your output code goes here
  spool off
  dbms_output.put_line('Output complete.');
END;
/

exit &SQL.EXITCODE;

In this script, the “WHENEVER SQLERROR” and “WHENEVER OSERROR” statements cause Sql*plus to exit with a non-zero exit code if any errors occur during the calculation or output. The “set termout off” statement suppresses terminal output during the execution of the script. The “set serveroutput on” statement enables Oracle server output. The “dbms_output.enable(NULL)” statement enables Oracle client output. The “var output_file varchar2(100) := ‘output.txt’” statement initializes a variable for the output file. The “spool” statement directs output to the file. Lastly, the “exit &SQL.EXITCODE;” statement exits with the Oracle error code, which will be non-zero if any errors occurred.

Alternative Ways:

Another alternative way to handle exit codes in Sql*plus scripts is to use a Unix shell script or a batch file to execute your Sql*plus script and check the exit code. In Unix, you can do something like:

#!/bin/sh

sqlplus -s user/password@instance @script.sql
if [ $? -ne 0 ]; then
  echo "Sql*plus script failed."
  exit 1
fi

# Do other things if script succeeded
