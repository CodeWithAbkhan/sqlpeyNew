Unexpected Keyword Argument Error in Airflow DAG

Introduction

The error message “got an unexpected keyword argument ‘dag’” is a common issue that arises in Airflow when passing arguments to an operator or sensor instance. This error usually occurs when a user is passing an argument that does not exist in the class definition.

Code Explanation

The following is the code where the unexpected keyword argument error occurs:

import json
import decimal
import airflow
from airflow import DAG
from airflow.contrib.operators.mysql_to_gcs import MySqlToGoogleCloudStorageOperator
from airflow.contrib.operators.gcs_to_bq import GoogleCloudStorageToBigQueryOperator
from airflow.contrib.operators.bigquery_operator import BigQueryOperator
from datetime import datetime, timedelta
from airflow.operators.bash_operator import BashOperator
from airflow.models import BaseOperator
from airflow.utils.decorators import apply_defaults
from airflow.contrib.hooks.gcs_hook import GoogleCloudStorageHook
from airflow.hooks.mssql_hook import MsSqlHook
from tempfile import NamedTemporaryFile
import pymssql  
import logging
import os
from google.cloud import bigquery
from oauth2client.client import GoogleCredentials
from airflow.operators.python_operator import PythonOperator

default_args = {
    'owner': 'airflow',
    'start_date': airflow.utils.dat

def function():
    # function code here
dag = DAG(
    'dag_name',
    default_args=default_args,
    schedule_interval=timedelta(days=1),
)

task = PythonOperator(
    task_id='task_name',
    python_callable=function,
    dag=dag,
)

The script imports various libraries such as airflow, PyMSSQL, logging, and others that are required for the specific operations. It defines a function called function which is to be executed in the task. The DAG object is then created with the name “dag_name” and is passed ‘default_args’ as an argument. The ‘default_args’ object contains information about the operator’s behavior such as ‘owner’ and ‘start_date’. It then creates a ‘PythonOperator’ named ’task_name’ which will execute the ‘function’ and be added to the DAG named ‘dag’.

Solution

The error message ‘got an unexpected keyword argument ‘dag’’ indicates that the function/operator does not recognize that argument. In the code above, the error is likely due to the function definition not taking any arguments, and the DAG object is being passed as an argument. One solution to this would be to remove the DAG argument from the ‘function’ definition.

The corrected code for the function would be:

def function(**kwargs):
    # function code here

By adding the ‘**kwargs’ argument to the function definition, it allows the function to accept any additional keyword arguments passed by the caller. This will resolve the unexpected keyword argument error.

Example

Here is an example that shows how to use a PythonOperator to execute a Python function:

def print_hello():
    print('Hello World')

dag = DAG(
    'hello_world',
    default_args=default_args,
    schedule_interval=timedelta(days=1),
)

task = PythonOperator(
    task_id='print_hello_task',
    python_callable=print_hello,
    dag=dag,
)

This example creates a DAG named ‘hello_world’ that executes a Python function called ‘print_hello’ when a task named ‘print_hello_task’ is initiated. The function simply prints ‘Hello World’ to the console. By using a PythonOperator, the user can execute custom Python code within the Airflow environment.

Alternative Methods

Along with using a PythonOperator, Airflow provides several other types of operators for executing different types of tasks. For example, the BashOperator can be used to execute shell commands, while the JDBCOperator can be used to execute SQL statements against a JDBC-compliant database. Each operator has its own set of arguments and methods that can be used to customize its behavior.
