NOSQL: MongoDB: Embedding vs Relationships MongoDB is a popular NoSQL database which offers great performance and scalability compared to traditional relational databases. In this Q&A Session, we will discuss the pros and cons of embedding versus using relationships in MongoDB, with a practical example.

Scenario Let’s assume we are building a simple accounting system where a user has many bills. We need to decide if bills should be a separate collection or nested within the user document.

Embedding vs. Relationships In MongoDB, we have two options to model this relationship: embedding and using references.

Embedding If we choose to embed bills into the user document, we can store all the data in one place, which can improve query performance by reducing the number of queries needed. Although, the maximum document size in MongoDB is 16 MB, and large embedded arrays can slow down write operations, so we need to be careful with the size of the embedded bills array.

Here is an example of an embedded schema:

{
  _id: ObjectId("60962782169b0d0011142a71"),
  name: "John Doe",
  email: "john.doe@example.com",
  bills: [
    {
      name: "Electricity",
      amount: 100,
      date: ISODate("2021-05-06T00:00:00Z")
    },
    {
      name: "Gas",
      amount: 50,
      date: ISODate("2021-05-07T00:00:00Z")
    }
  ]
}

We can see that the user document contains an array of embedded bills with their corresponding name, amount, and date. To retrieve all bills for a user, we can simply query the user document and get the bills array.

Although, the downside of embedding is that it can cause data duplication and inconsistency. For example, if we update the name of a user, we need to update all bills that are embedded within the user document.

Relationships If we choose to use references, we can store the bills in a separate collection and refer to them using the user’s _id. This can reduce data duplication and make updates easier, but it requires additional queries to retrieve the bills for a user.

Here is an example of a reference schema:

// users collection
{
  _id: ObjectId("60962782169b0d0011142a71"),
  name: "John Doe",
  email: "john.doe@example.com",
}

// bills collection
{
  _id: ObjectId("609627b4169b0d0011142a72"),
  user_id: ObjectId("60962782169b0d0011142a71"),
  name: "Electricity",
  amount: 100,
  date: ISODate("2021-05-06T00:00:00Z")
},
{
  _id: ObjectId("609627ca169b0d0011142a73"),
  user_id: ObjectId("60962782169b0d0011142a71"),
  name: "Gas",
  amount: 50,
  date: ISODate("2021-05-07T00:00:00Z")
}

In this schema, the bills are stored in a separate bills collection and referenced by the user_id field. To retrieve all bills for a user, we need to query the bills collection with the user_id field.

This approach can be more flexible and scalable than embedding because we can store the bills collection on a different server or cluster, and we do not have to worry about the size of the user documents. Although, it requires additional queries to retrieve the bills for a user, which can impact performance.

Practical Example Let’s see a practical example of the two approaches. We will use the Mongoose library to define our schemas:

Embedded Schema:

const billSchema = new mongoose.Schema({
  name: String,
  amount: Number,
  date: Date,
});

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  bills: [billSchema],
});

In this schema, we define the bill schema and embed it within the user schema as an array of bills.

We can then create a new user and add some bills as follows:

const User = mongoose.model('User', userSchema);

const user1 = new User({
  name: 'John Doe',
  email: 'john.doe@example.com',
  bills: [
    {
      name: 'Electricity',
      amount: 100,
      date: '2021-05-06',
    },
    {
      name: 'Gas',
      amount: 50,
      date: '2021-05-07',
    },
  ],
});

user1.save();

To retrieve all bills for a user, we can query the user document as follows:

const user = await User.findOne({ name: 'John Doe' });
const bills = user.bills;

Reference Schema:

const billSchema = new mongoose.Schema({
  user_id: { type: mongoose.Schema.Types.ObjectId, ref: 'User' },
  name: String,
  amount: Number,
  date: Date,
});

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
});

const Bill = mongoose.model('Bill', billSchema);
const User = mongoose.model('User', userSchema);

In this schema, we define the bill schema with a user_id field that references the user collection.

We can then create a new user and bills as follows:

const user1 = new User({
  name: 'John Doe',
  email: 'john.doe@example.com',
});

user1.save();

const bill1 = new Bill({
  user_id: user1._id,
  name: 'Electricity',
  amount: 100,
  date: '2021-05-06',
});

bill1.save();

const bill2 = new Bill({
  user_id: user1._id,
  name: 'Gas',
  amount: 50,
  date: '2021-05-07',
});

bill2.save();

To retrieve all bills for a user, we can query the bills collection with the user_id field as follows:

const user = await User.findOne({ name: 'John Doe' });
const bills = await Bill.find({ user_id: user._id });

Recap Choosing between embedding and using relationships in MongoDB depends on several factors such as the size of the documents, the frequency of updates, and the types of queries needed.

Embedding can improve performance by reducing the number of queries needed but it can cause data duplication and inconsistency. Relationships can reduce data duplication and make updates easier, but it requires additional queries to retrieve related data.

In our scenario, we can go with the embedded schema since we do not have to worry about the size of the bills array and we will mostly need to retrieve bills for a user between different date periods.
