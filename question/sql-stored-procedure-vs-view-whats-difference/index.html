SQL: Stored Procedure vs View: What’s the Difference? Differences between Stored Procedures and Views in SQL Server
When working with SQL Server, one might come across the terms “stored procedures” and “views”. Essentially, both of them are database objects that can be accessed and executed within the SQL Server. Although, they have different functionalities, features, and purposes. This Q&A Session aims to explain the differences between stored procedures and views in SQL Server, and when to use which one.

What is a Stored Procedure?

A stored procedure is a pre-written SQL statement or query that is saved in the SQL Server database. It is a compiled code that performs a set of operations or tasks, and can be executed multiple times without having to rewrite the entire code. Stored procedures are used to perform complex queries, data manipulations, data validations, and data retrievals.

What is a View?

A view, on the other hand, is a virtual table that is created based on a set of pre-defined SQL statements or queries. The view does not store any data physically, but rather retrieves data from one or more tables or views. The data in the view is dynamically generated and updated in real-time, based on the data in the underlying tables or views on which they are based.

When to Use Stored Procedures?

Stored procedures should be used when a repetitive set of operations or tasks need to be performed on the SQL Server database. They are also useful when multiple database users need to access the same set of operations or tasks, as stored procedures can be shared, secured, and controlled by the database administrators. Stored procedures can also be used to improve performance, as they are pre-compiled and cached, reducing network traffic and improving response time.

Example of a Stored Procedure

Let us consider a database with two tables: “tbl_user” and “tbl_profile”. Suppose we want to create a stored procedure that retrieves the profile description of a user based on the user id. We can create a stored procedure as follows:

CREATE PROCEDURE dbo.getDesc
    @ID int
AS
BEGIN
    SELECT profile_description 
    FROM tbl_user u 
    JOIN tbl_profile p ON u.user_id = p.user_id 
    WHERE u.user_id = @ID
END
GO

The above stored procedure gets the profile description from the tbl_profile table by joining the tbl_user table based on the user id, which is passed as a parameter to the stored procedure.

When to Use Views?

Views should be used when there is a need to retrieve data from multiple tables in a single query. They are also useful when a specific set of data needs to be displayed to multiple users or applications, as views offer a simplified and unified view of the underlying data. Views can also be used to simplify complex queries by providing a pre-defined set of selectable fields and pre-defined filters.

Example of a View

Consider the previous example with the two tables: “tbl_user” and “tbl_profile”. Suppose we want to create a view that retrieves both the user id and profile description from the two tables. We can create a view as follows:

CREATE VIEW vw_user_profile
AS
  SELECT u.user_id, p.profile_description
  FROM tbl_user u 
  LEFT JOIN tbl_profile p ON u.user_id = p.user_id
GO

The above view gets the user id and profile description from the tbl_user and tbl_profile tables, respectively, by performing a left join on the user id. This view can be used to retrieve the profile description for any user id by just selecting from the view and passing the user id as a parameter.

Do Views Allow the Creation of Dynamic Queries Where We Can Pass Parameters?

Yes, views do allow the creation of dynamic queries where parameters can be passed. The parameters are used in the underlying SQL statements or queries that the view is based on. The view itself does not take any parameters, but rather the SQL statement or query underlying the view can take parameters, which can be passed when the view is queried.

Which One is Faster, and on What Basis is One Faster Than the Other?

The performance of stored procedures and views depends on the specific use case and the complexity of the queries involved. Generally, stored procedures are faster for performing data manipulations, data validations, and data retrievals that involve multiple SQL statements or operations. Although, views are faster for performing data retrievals that involve joining multiple tables, as the data in views is pre-compiled and cached, and the results are retrieved more efficiently than joining tables in real-time.

Do Views or Stored Procedures Allocate Memory Permanently?

Both views and stored procedures allocate memory temporarily for the duration of their execution. They do not allocate memory permanently, and the memory is released once the view or stored procedure completes its execution.

What Does It Mean If Someone Says That Views Create a Virtual Table, While Procedures Create a Materials Table?

When someone says that views create a virtual table, they mean that views do not store any physical data, but rather create a virtual table based on the data in the underlying tables or views. When someone says that procedures create a materials table, they mean that procedures perform a set of operations or tasks on the data in the database and create a temporary table, which is referred to as a materials table, used to store and manipulate the data temporarily.

Recap

In summary, stored procedures and views are two important database objects that are used in SQL Server. Stored procedures are used to perform a set of operations or tasks on the database, and are pre-written, pre-compiled, and pre-cached. Views, on the other hand, are virtual tables that provide a simplified and unified view of the underlying data, without storing any physical data. Both of them have different functionalities, features, and purposes, and choosing one over the other depends on the specific use case and the complexity of the queries involved. ]]>
