SQL Array Flattening: What Happens Behind the Scenes of CROSS JOIN UNNEST?

We often use a common SQL idiom to flatten arrays, but what’s actually happening behind the scenes? Let’s take a closer look at the CROSS JOIN UNNEST pattern and see what’s going on.

The CROSS JOIN

The CROSS JOIN combines rows from two tables by combining each row from the first table with each row from the second table. Let’s consider a simple example of a table called t1 that looks like this:

https://i.stack.imgur.com/mAouG.png

If we run the query SELECT id, flattened.flattened_numbers from t1 CROSS JOIN flattened, we get the following result:

https://i.stack.imgur.com/82KBt.png

As you can see, each of the original values of the id column gets mixed with flattened_numbers from each of the original rows in t1. Everything gets mixed up because we don’t have a WHERE clause that selects only the rows of the CROSS JOIN that we want.

The UNNEST Function

The UNNEST function takes a column of type array and unpacks each of the arrays in that column so that we’re left with one row for each value in each array. If we run SELECT FLATTEN(numbers_array) AS flattened_numbers FROM t1, we’d expect the following result, which we’ll call t2:

https://i.stack.imgur.com/O59l3.png

Combining CROSS JOIN and UNNEST

The pattern people actually use to flatten arrays looks like this: SELECT id, flattened_numbers FROM t1 CROSS JOIN UNNEST(sequences.some_numbers) AS flattened_numbers, which produces the following result:

https://i.stack.imgur.com/ZFkaf.png

But why does this work? How does the CROSS JOIN UNNEST pattern ensure that each row is only joined with its own nested values?

The Magic of CROSS JOIN UNNEST

The secret behind the CROSS JOIN UNNEST pattern is that it relies on a special property of the UNNEST function: each row in the result of UNNEST contains a unique identifier from the original table, which is stored in a column called unnest_id. This column is the key to understanding why CROSS JOIN UNNEST works.

When we combine CROSS JOIN with UNNEST, this unique identifier ensures that each row in the result of the UNNEST is only joined with its own rows from the original table. This prevents us from getting the same result as we did with our imaginary FLATTEN function, where every unnested value gets combined with every row from t1.
