NOSQL: Schemaless Database Serialization using Protocol Buffers Serializing Schemaless Data in MySQL with Protocol Buffers
Storing schemaless data can be a challenge, but with the right tools, it can be done effectively. One approach is using MySQL, as inspired by FriendFeed’s implementation. In this blog post, we’ll look at how we can use Protocol Buffers to serialize structured data in MySQL for a schemaless database.

The Problem with JSON/BSON

One popular option for serializing structured data is using JSON or BSON. These formats are flexible, but they come with a significant overhead for field names in the serialized data, which can be problematic when trying to minimize memory and network footprint. More, shortening field names to make the database faster may compromise the descriptive nature of those field names, which is not an ideal trade-off.

The Solution: Protocol Buffers

The solution to this issue is using Protocol Buffers, a language-agnostic method for serializing structured data developed by Google. Protocol Buffers have a compact binary format that eliminates the need for repeating field names in the serialized data, making it a perfect fit for our needs.

Let’s take a closer look at how we can use Protocol Buffers in our MySQL schemaless database.

Serializing with Protocol Buffers in MySQL

To use Protocol Buffers in our MySQL schemaless database, we’ll need to do a few things:

  • Create a Protocol Buffers schema to define the structure of the data we want to serialize.
  • Add a column to our MySQL table to store the serialized Protocol Buffers data.
  • Modify our database queries to handle the deserialization of the Protocol Buffers data.

Let’s look at each of those steps in more detail.

Creating a Protocol Buffers Schema

The first step is creating a Protocol Buffers schema to define the structure of our data. Here’s an example:

message MyEntity {
  required bytes id = 1;
  optional string name = 2;
  optional int32 age = 3;
}

This schema defines an entity with an ID, name, and age. The ID field is required, while the name and age fields are optional. We can include whatever fields we need in our schema, so it’s flexible enough to handle schemaless data.

Serializing Data in MySQL

Once we have our schema, we can use the Protocol Buffers library in our application code to serialize data to binary format and store it in our MySQL table. Here’s an example:

INSERT INTO entities (id, data) VALUES (?, ?);

In this example, we’re inserting an entity into our schemaless database. The id field is the unique identifier for the entity, and the data field is a binary blob representing the serialized Protocol Buffers data.

Deserializing Data in MySQL

To query the data in our MySQL schemaless database, we’ll need to modify our queries to handle the deserialization of the Protocol Buffers data. Here’s an example:

SELECT id, data FROM entities WHERE id = ?;

In this example, we’re selecting an entity from our schemaless database by its id. The data field is returned as a binary blob, which we can deserialize using the Protocol Buffers library in our application code.

Alternative: Using MessagePack

While Protocol Buffers offer an efficient way to serialize structured data, there are other alternatives, such as MessagePack. MessagePack is a binary serialization format similar to JSON, but with a more compact footprint. It’s also language-agnostic like Protocol Buffers, which makes it another good option to handle schemaless data. Although, for this blog post, we’ve focused on Protocol Buffers as the main solution.

Recap

Storing schemaless data in MySQL can be done effectively by using Protocol Buffers to serialize structured data. By creating a Protocol Buffers schema, serializing data in MySQL, and deserializing data in MySQL queries, we can efficiently manage a schemaless database.
