Maximizing Oracle Efficiency with Trigger Implementation Oracle Triggers and Handling Inserted, Updated, and Deleted Data
Triggers in Oracle are database objects that can be used to automatically execute a set of SQL statements when certain events occur. These events can be the insertion of a new row, an update to an existing row, or the deletion of a row from a table. In this Q&A Session, we will explore how to handle inserted, updated, and deleted data in an Oracle trigger.

Creating an Oracle Trigger

To create a new trigger in Oracle, we can use the CREATE TRIGGER statement. The basic syntax for creating a trigger is as follows:

CREATE TRIGGER trigger_name
AFTER INSERT OR DELETE OR UPDATE ON table_name
FOR EACH ROW
BEGIN
  -- SQL statements to execute when the trigger is fired
END;
/

In the above syntax, “trigger_name” is the name we give to our trigger, “table_name” is the name of the table we want the trigger to act on, and “AFTER INSERT OR DELETE OR UPDATE” specifies the type of events that will cause the trigger to be fired. The “FOR EACH ROW” clause indicates that the SQL statements within the trigger will be executed once for each row affected by the event.

Handling Inserted Data in an Oracle Trigger

To handle inserted data in an Oracle trigger, we can use the :new operator. The :new operator references the newly inserted row in the table that caused the trigger to fire. We can access the columns of the new row by using the :new operator followed by the column name.

For example, if we want to access the value of the “field1” column in the new row, we can use the following syntax:

:new.field1

We can include this syntax in the SQL statements within our trigger to manipulate or store the inserted data.

Handling Updated Data in an Oracle Trigger

To handle updated data in an Oracle trigger, we can use both the :old and :new operators. The :old operator references the original row in the table before it was updated, and the :new operator references the updated row.

If we want to access the value of the “field1” column in the original row, we can use the following syntax:

:old.field1

If we want to access the value of the “field1” column in the updated row, we can use the following syntax:

:new.field1

We can compare the values of the old and new rows to determine if a particular column has changed. For example, if we want to execute SQL statements only if the value of the “field1” column has changed, we can use the following syntax:

IF :new.field1 != :old.field1 THEN
  -- SQL statements to execute when the field1 column has changed
END IF;

Handling Deleted Data in an Oracle Trigger

To handle deleted data in an Oracle trigger, we can use the :old operator. The :old operator references the row that was deleted from the table that caused the trigger to fire. We can access the columns of the deleted row by using the :old operator followed by the column name.

For example, if we want to access the value of the “field1” column in the deleted row, we can use the following syntax:

:old.field1

We can include this syntax in the SQL statements within our trigger to manipulate or store the deleted data.

Putting It All Together

Let’s put what we’ve learned together into a full example:

CREATE OR REPLACE TRIGGER test_trigger
AFTER INSERT OR DELETE OR UPDATE ON test_table
FOR EACH ROW
BEGIN
  IF INSERTING THEN
    -- SQL statements to execute when a row is inserted
    dbms_output.put_line('New row inserted with ID: ' || :new.id);
  END IF;
  
  IF UPDATING THEN
    -- SQL statements to execute when a row is updated
    IF :new.field1 != :old.field1 THEN
      dbms_output.put_line('field1 column has changed for row with ID: ' || :new.id);
    END IF;
  END IF;
  
  IF DELETING THEN
    -- SQL statements to execute when a row is deleted
    dbms_output.put_line('Row with ID ' || :old.id || ' has been deleted.');
  END IF;
END;
/

In the above example, we create an Oracle trigger named “test_trigger” that is fired after an insert, update, or delete event on the “test_table” table. We use conditional statements to execute different SQL statements based on the type of event that caused the trigger to fire.

Recap

Triggers in Oracle can be amazing tools for automatically executing SQL statements when certain events occur. By using the :new and :old operators, we can handle inserted, updated, and deleted data in our triggers. This allows us to perform complex actions on our data without having to manually execute SQL statements. ]]>
