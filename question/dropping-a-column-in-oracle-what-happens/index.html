Dropping a Column in Oracle: What Happens? What Happens When a Column is Dropped in Oracle?
Dropping a column from an Oracle table can have several impacts on the table and its data. Here are some of the key things that happen when a column is dropped:

  • The data stored in the dropped column is lost.
  • Views referencing the dropped column are invalidated, but not dropped. They will remain invalid until they are revised to work with the modified schema.
  • Stored procedures referencing the dropped column are also invalidated.
  • The column ID numbers of following columns are reset.
  • Permissions granted specifically on the dropped column will be removed.
  • Indexes referencing the dropped column are dropped as well.

The following example SQL statement can be used to drop a column from a table:

ALTER TABLE table_name DROP COLUMN column_name;

This statement will physically remove the column and its data from the table, which can be a costly operation for a large table. An alternative is to use the following statement, which flags the column as “unused” in the data dictionary:

ALTER TABLE table_name SET UNUSED (column_name);

This will keep the column structure and metadata in place, but mark the column as unused so it doesn’t take up space or resources. Any references to the column will still work, but attempts to update or select the column’s values will result in an error. To completely remove the unused column and reclaim the space, you can issue the following statement:

ALTER TABLE table_name DROP UNUSED COLUMNS;

This will drop any unused columns from the table, freeing up storage space and resources.

Example:

Let’s say we have a table called “employees” with the following columns: “id”, “name”, “age”, “address”, and “salary”.

To drop the “address” column from the table, we would use the following SQL statement:

ALTER TABLE employees DROP COLUMN address;

This would remove the “address” column and its data from the table, reset the column ID numbers for any columns that follow it, and drop any indexes that reference the column.

If we instead use the following statement:

ALTER TABLE employees SET UNUSED (address);

The “address” column is marked as unused, but its structure and metadata remain in place. Any views or stored procedures that reference the column will still work, but any attempts to select or update values in the column will result in an error.

To completely remove the unused column and free up the space, we would issue the following statement:

ALTER TABLE employees DROP UNUSED COLUMNS;

This would drop the “address” column from the table and reclaim any storage space that was being used by the column.

In summary, dropping a column from an Oracle table can have several impacts on the table and its data. By using the “set unused” command, you can flag the column as unused and avoid the costly operation of physically removing the column from the table. ]]>
