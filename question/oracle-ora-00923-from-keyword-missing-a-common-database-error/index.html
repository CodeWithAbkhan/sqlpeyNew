ORACLE: ORA-00923: FROM keyword missing - A Common Database Error In this error (ORA-00923: FROM keyword not found where expected), the issue seems to be with the SQL query syntax. The error message indicates that the Oracle SQL parser is expecting a “FROM” keyword but it is not found where it is expected.

Let’s take a closer look at the SQL query in question:

select 
  country_olympic_name, 
  SUM(part_gold) as "Number of Gold Medals"
From
  games.country,
  games.participation
where
  participation.country_isocode = country.country_isocode
group by
  country_olympic_name;

				  The SQL query is attempting to retrieve the number of gold medals won by each country in the "games" table. Although, there is an issue with the syntax.  The error message indicates that the problem is with the "FROM" keyword. Looking at the query, we can see that the "FROM" keyword is missing. Instead, there are two tables, "games.country" and "games.participation", separated by a comma. This is causing confusion for the Oracle SQL parser, which is expecting a "FROM" keyword to indicate where the query is retrieving data from.  To fix this error, we need to add a "FROM" keyword to the SQL query. We can also remove the comma and replace it with a join statement, which will make the query easier to read and know:  
				  

select 
  country_olympic_name, 
  SUM(part_gold) as "Number of Gold Medals"
FROM
  games.country
INNER JOIN
  games.participation
ON
  participation.country_isocode = country.country_isocode
GROUP BY
  country_olympic_name;

In the revised SQL query, we have added a “FROM” keyword and replaced the comma with an inner join statement. We have also added an “ON” keyword to specify the join condition between the two tables. To summarize, the ORA-00923 error occurs when the Oracle SQL parser cannot find a “FROM” keyword where it is expected. To fix this error, we need to ensure that our SQL query contains a “FROM” keyword and that the syntax is correct. In this case, we replaced the comma with a join statement to improve the readability and clarity of the query. Practical Example: Suppose we have two tables, “students” and “grades”, and we want to retrieve the average grade for each student. We can use the following SQL query:

SELECT 
  students.name, 
  AVG(grades.grade) as "Average Grade"
FROM 
  students
INNER JOIN 
  grades
ON 
  students.id = grades.student_id
GROUP BY 
  students.name;

This query retrieves the name of each student and the average grade for that student, by joining the “students” and “grades” tables on the student ID and grouping the results by student name. Alternative Ways: There are many ways to join tables in SQL, depending on the specific requirements of the query. Here are a few alternative ways to write the above query: Using a LEFT JOIN instead of an INNER JOIN:

SELECT 
  students.name, 
  AVG(grades.grade) as "Average Grade"
FROM 
  students

  grades
ON 
  students.id = grades.student_id
GROUP BY 
  students.name;

This query retrieves the name of each student and the average grade for that student, even if that student has no grades (in which case the average grade is NULL). Using a subquery instead of a join:

SELECT 
  students.name, 
  (SELECT AVG(grade) FROM grades WHERE student_id = students.id) as "Average Grade"
FROM 
  students;

This query retrieves the name of each student and the average grade for that student, by using a correlated subquery to calculate the average grade for each student. Using a CTE (Common Table Expression) instead of a join:

    student_id,

    grades

    student_id

  student_grades

  students.id = student_grades.student_id;
