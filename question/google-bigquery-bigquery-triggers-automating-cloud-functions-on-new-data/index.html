Triggering a Cloud Function on new data in BigQuery

Introduction

BigQuery doesn’t natively support triggers as of June 2022. Although, a workaround to trigger a Cloud Function when new data has been imported into a BigQuery table can be implemented.

Solution

Using Google Cloud’s Eventarc service, it’s possible to trigger a Cloud Function when new data is added to a BigQuery table. Here’s how the process works step by step: 1. Create a new BigQuery table that will hold the data you want to monitor. 2. Create a sink in Cloud Logging that will capture the BigQuery tables’ insert events. 3. Use Cloud Functions to subscribe to the Cloud Logging sink and get notified when insert events occur. 4. In the Cloud Function code, extract the rows with new data and perform any necessary actions on the data. Most of the work happens in steps 2 and 3, so let’s go into more detail on those.

Creating a sink in Cloud Logging

To create a sink in Cloud Logging that will capture insert events from your BigQuery table, follow these steps: 1. Go to the Cloud Logging console. 2. Select “Sinks” from the left-hand menu. 3. Click “Create Sink”. 4. Give your sink a descriptive name, such as “bigquery-inserts”. 5. In the “Sink destination” section, select “Cloud Pub/Sub” as the sink service. 6. Click the “Select” button next to “Topic”. 7. Click “Create Topic”, and give your topic a descriptive name, such as “bigquery-inserts-topic”. 8. Click “Create” to create your topic and select it as the sink’s destination. 9. In the “Filter” section, enter the following filter expression:

resource.type="bigquery_table"
protoPayload.methodName="tabledata.insertAll"

This filter will capture all insert events on any BigQuery table in your project. 10. Click “Create Sink” to create your new sink.

Subscribing to the Cloud Logging sink with Cloud Functions

To subscribe to your Cloud Logging sink and get notified when insert events occur, follow these steps: 1. Create a Cloud Function that will receive the insert events. You can create a new function or use an existing one. 2. In the Cloud Console, go to the “Cloud Functions” section. 3. Find your function in the list and click on its name to go to its detail page. 4. Click on the “Add Trigger” button in the “Trigger” section. 5. Select “Cloud Pub/Sub” as the trigger type. 6. In the “Topic” field, enter the name of the topic you created in the previous section (“bigquery-inserts-topic” in our example). 7. Click “Create”. 8. In your Cloud Function code, write the logic to extract the rows with new data from the insert event. Here’s an example of how to extract the rows from the insert event in Python:

import base64
import json

def pubsub_trigger(event, context):
    """Triggered from a message on a Cloud Pub/Sub topic."""
    data = event['data']
    if isinstance(data, bytes):
        data = data.decode('utf-8')
    message = json.loads(base64.b64decode(data))
    # Get the list of inserted rows
    rows = message['protoPayload']['serviceData']['jobCompletedEvent']['job']['jobConfiguration']['query']['destinationTableProperties']['table']['rows']
    # Process the rows
    for row in rows:
        # Do something with the row data
        print(row)

This code listens for Pub/Sub events and extracts the rows from the BigQuery insert event. It then loops over the rows and prints them to the console, but you can replace the print statement with any logic you need to process the rows.

Alternative Solutions

Another possible solution is to create a Cloud Function that periodically polls the BigQuery table for new data, instead of relying on Cloud Logging and Pub/Sub. This solution might be less efficient and less timely, but it eliminates the need for a Cloud Logging sink and Pub/Sub topic.
