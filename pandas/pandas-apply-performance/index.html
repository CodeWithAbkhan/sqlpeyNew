When is Pandas apply Too Slow and What Can Replace It?

The DataFrame.apply and Series.apply methods in pandas are convenient functions that allow you to apply a user-defined function across rows or columns. They are incredibly flexible, capable of performing transformations and aggregations that might not have dedicated pandas functions. They can even handle index alignment and broadcast aggregated results. However, this flexibility comes at a cost: performance.

apply operates by iterating over your DataFrame or Series, applying your function to each element, row, or column. Because pandas cannot make assumptions about your custom function, it incurs significant overhead with each iteration. This makes apply a poor choice for performance-critical operations, especially with large datasets, as it consumes more memory and is generally slower than vectorized alternatives.

Pandas 2.2 apply with engine='numba'

A notable development in pandas version 2.2 is the introduction of engine='numba' for apply. This allows for Just-In-Time (JIT) compilation of your function, potentially leading to speedups. You can also pass engine_kwargs like nopython, nogil, and parallel for further optimization. However, it’s generally recommended to use this only when working with raw=True due to internal limitations.

Making Your Code apply-Free

The goal is to replace apply with more efficient methods whenever possible.

Numeric Data Operations

For operations involving numeric data, pandas often provides highly optimized, Cython-compiled functions. If you find yourself using apply for a simple arithmetic operation, it’s almost certain that a built-in, vectorized alternative exists.

Consider summing columns:

import pandas as pd
import numpy as np

df_numeric = pd.DataFrame({"A": [9, 4, 2, 1], "B": [12, 7, 5, 4]})
print("Original DataFrame:")
print(df_numeric)

# Using apply for sum
print("\nUsing df.apply(np.sum):")
print(df_numeric.apply(np.sum))

# Using the vectorized sum
print("\nUsing df.sum():")
print(df_numeric.sum())

# Performance comparison
print("\nPerformance comparison for sum:")
%timeit df_numeric.apply(np.sum)
%timeit df_numeric.sum()

Even with raw=True to pass arrays directly:

print("\nPerformance comparison for sum with raw=True:")
%timeit df_numeric.apply(np.sum, raw=True)

Similarly for range calculations:

print("\nUsing df.apply(lambda x: x.max() - x.min()):")
print(df_numeric.apply(lambda x: x.max() - x.min()))

print("\nUsing df.max() - df.min():")
print(df_numeric.max() - df_numeric.min())

print("\nPerformance comparison for range calculation:")
%timeit df_numeric.apply(lambda x: x.max() - x.min())
%timeit df_numeric.max() - df_numeric.min()

Always prioritize these vectorized operations for numeric tasks. For more on pandas performance, explore what is pandas .

String and Regex Operations

While pandas offers many vectorized string functions, there are instances where they don’t cover all specific needs. A common scenario is checking if a substring from one column exists within a string in another column on the same row.

df_strings = pd.DataFrame({
    'Name': ['mickey', 'donald', 'minnie'],
    'Title': ['wonderland', "welcome to donald's castle", 'Minnie mouse clubhouse'],
    'Value': [20, 10, 86]
})
print("\nString DataFrame:")
print(df_strings)

# Using apply for substring check
print("\nUsing df.apply for substring check:")
result_apply = df_strings.apply(lambda x: x['Name'].lower() in x['Title'].lower(), axis=1)
print(df_strings[result_apply])

# Using list comprehension for better performance
print("\nUsing list comprehension for substring check:")
result_list_comp = [y.lower() in x.lower() for x, y in zip(df_strings['Title'], df_strings['Name'])]
print(df_strings[result_list_comp])

print("\nPerformance comparison for substring check:")
%timeit df_strings[df_strings.apply(lambda x: x['Name'].lower() in x['Title'].lower(), axis=1)]
%timeit df_strings[[y.lower() in x.lower() for x, y in zip(df_strings['Title'], df_strings['Name'])]]

List comprehensions, despite being iterative, often outperform apply for such tasks due to lower overhead. For handling potential NaN or invalid data types, you can incorporate custom logic within the list comprehension. For deeper dives into Python loops and pandas, see Are for-loops in pandas really bad? When should I care? .

Date and datetime operations also have efficient vectorized versions. Prefer pd.to_datetime(df['date']) over df['date'].apply(pd.to_datetime). Refer to the pandas documentation for details.

Exploding Columns of Lists

When dealing with columns containing lists, apply(pd.Series) is a common but inefficient approach.

s_lists = pd.Series([[1, 2]] * 3)
print("\nSeries of lists:")
print(s_lists)

# Inefficient apply(pd.Series)
print("\nUsing s.apply(pd.Series):")
print(s_lists.apply(pd.Series))

# Efficient conversion using tolist() and DataFrame constructor
print("\nUsing pd.DataFrame(s.tolist()):")
print(pd.DataFrame(s_lists.tolist()))

print("\nPerformance comparison for exploding lists:")
%timeit s_lists.apply(pd.Series)
%timeit pd.DataFrame(s_lists.tolist())

Converting the Series to a list and then to a DataFrame is significantly faster.

Situations Where apply Might Be Acceptable

There are specific scenarios where the overhead of apply is minimal, making it a reasonable choice, particularly when dealing with operations not directly vectorized for DataFrames.

Functions Vectorized for Series, Not DataFrames

If you need to apply an operation across multiple columns where the operation is vectorized for a Series but not directly for a DataFrame, apply can be used.

df_dates = pd.DataFrame(
    pd.date_range('2018-12-31','2019-01-31', freq='2D').date.astype(str).reshape(-1, 2),
    columns=['date1', 'date2']
)
print("\nDataFrame with date strings:")
print(df_dates)
print("\nDataFrame dtypes before conversion:")
print(df_dates.dtypes)

# Using apply for date conversion
print("\nUsing df.apply(pd.to_datetime):")
print(df_dates.apply(pd.to_datetime, errors='coerce').dtypes)

# Alternative: concat with pd.to_datetime
print("\nUsing pd.concat with pd.to_datetime:")
print(pd.concat([pd.to_datetime(df_dates[c], errors='coerce') for c in df_dates.columns], axis=1).dtypes)

# Alternative: explicit loop for date conversion
print("\nUsing an explicit loop for date conversion:")
for c in df_dates.columns:
    df_dates[c] = pd.to_datetime(df_dates[c], errors='coerce')
print(df_dates.dtypes)

print("\nPerformance comparison for date conversion:")
%timeit df_dates.apply(pd.to_datetime, errors='coerce')
%timeit pd.to_datetime(df_dates.stack(), errors='coerce').unstack()
%timeit pd.concat([pd.to_datetime(df_dates[c], errors='coerce') for c in df_dates.columns], axis=1)
%timeit for c in df_dates.columns: df_dates[c] = pd.to_datetime(df_dates[c], errors='coerce')

While apply is acceptable here, explicit loops or pd.concat can offer marginal speed improvements. The same logic applies to string operations or type conversions to ‘category’.

GroupBy Operations with Chained Transformations

GroupBy.apply is also an iterative convenience function. While repeating groupby operations to avoid apply can harm performance, GroupBy.apply is generally acceptable, especially if the functions used within are vectorized. If no native pandas method exists for a group-wise aggregation, apply with a custom function might still provide reasonable performance for smaller groups.

Consider a “lagged cumsum” scenario:

df_groupby = pd.DataFrame({"A": list('aabcccddee'), "B": [12, 7, 5, 4, 5, 4, 3, 2, 1, 10]})
print("\nDataFrame for GroupBy operations:")
print(df_groupby)

# Two successive groupby calls
print("\nTwo successive groupby calls:")
result_two_groupby = df_groupby.groupby('A').B.cumsum().groupby(df_groupby.A).shift()
print(result_two_groupby)

# Using GroupBy.apply for a single call
print("\nUsing GroupBy.apply:")
result_groupby_apply = df_groupby.groupby('A').B.apply(lambda x: x.cumsum().shift())
print(result_groupby_apply)

In such cases, apply can be justifiable to simplify complex groupby operations, as the overhead of groupby itself is significant.

Other Caveats of apply

  • Double Application: apply might process the first row (or column) twice to detect side effects. If no side effects are found, it may use a faster path; otherwise, it falls back to a slower implementation.

    df_side_effect = pd.DataFrame({
    'A': [1, 2],
    'B': ['x', 'y']
})

def func_side_effect(row):
    print(f"Processing A: {row['A']}")
    return row

print("\nDataFrame with side effect demonstration:")
df_side_effect.apply(func_side_effect, axis=1)

  • Mutation Bugs: apply(axis=1) passes the same object to the function, which can lead to mutation bugs. The pandas documentation warns against mutating objects passed to apply.

    print("\nDemonstrating mutation issue with apply:")
df_mutation = pd.DataFrame({"A": [9, 4, 2, 1], "B": [12, 7, 5, 4]})
print("IDs before apply:")
print(df_mutation.apply(id, axis=1))

applied_rows = []
def func_collect(row):
    applied_rows.append(row)

df_mutation.apply(func_collect, axis=1)
print("\nCollected rows:")
print(pd.DataFrame(applied_rows))

    Avoid mutation within apply functions.

pd.DataFrame.apply Column-Wise Performance

Column-wise apply (axis=0) can be a mixed bag. For scenarios with many columns and few rows, it’s generally expensive. However, when dealing with many rows and fewer columns (a more common case), apply can sometimes offer performance advantages over vectorized alternatives.

# Scenario 1: Many rows, few columns
np.random.seed(0)
df_many_rows = pd.DataFrame(np.random.random((10**7, 3)))

# Scenario 2: Many columns, few rows
df_many_cols = pd.DataFrame(np.random.random((10**4, 10**3)))

print("\nPerformance comparison (Many Rows vs Many Columns):")
print("\nScenario 1 (Many Rows, Few Columns):")
print("Sum:")
%timeit df_many_rows.sum()
%timeit df_many_rows.apply(pd.Series.sum)
print("Max-Min:")
%timeit df_many_rows.max() - df_many_rows.min()
%timeit df_many_rows.apply(lambda x: x.max() - x.min())
print("Mean:")
%timeit df_many_rows.mean()
%timeit df_many_rows.apply(pd.Series.mean)

print("\nScenario 2 (Many Columns, Few Rows):")
print("Sum:")
%timeit df_many_cols.sum()
%timeit df_many_cols.apply(pd.Series.sum)
print("Max-Min:")
%timeit df_many_cols.max() - df_many_cols.min()
%timeit df_many_cols.apply(lambda x: x.max() - x.min())
print("Mean:")
%timeit df_many_cols.mean()
%timeit df_many_cols.apply(pd.Series.mean)

Alternative Solutions for Row-Wise Operations (axis=1)

For row-wise operations, consider custom functions that might offer better performance than apply.

def faster_df_apply(df, func):
    cols = list(df.columns)
    data, index = [], []
    for row in df.itertuples(index=True):
        row_dict = {f: v for f, v in zip(cols, row[1:])}
        data.append(func(row_dict))
        index.append(row[0])
    return pd.Series(data, index=index)

# Example usage:
# print(faster_df_apply(df_numeric, lambda row: row['A'] + row['B']))

df.to_records() can also be more performant than df.itertuples() if the entire DataFrame needs processing.

Handling Unicode Strings

While list comprehensions are often the best alternative, apply can be useful for tasks like decoding Unicode strings when native pandas or NumPy functions aren’t readily available.

import unidecode

s_unicode = pd.Series(['mañana','Ceñía'])
print("\nSeries with Unicode characters:")
print(s_unicode)

print("\nUsing s.apply(unidecode.unidecode):")
print(s_unicode.apply(unidecode.unidecode))

“Pandas Apply Performance: When to Use and Alternatives”

Q: Why is pandas apply considered slow

ANS: pandas apply iterates through each row or column, applying a user-defined function. This iteration process incurs overhead and makes it slower compared to vectorized operations that operate on entire arrays simultaneously.

Q: When should I avoid using pandas apply

ANS: You should generally avoid pandas apply when performing simple arithmetic operations, string manipulations that have vectorized alternatives, or when processing large datasets where performance is critical. Look for built-in pandas functions or list comprehensions.

Q: What are the alternatives to pandas apply

ANS: Common alternatives include vectorized pandas operations (e.g., df.sum(), df.max()), list comprehensions, df.apply(pd.Series) for exploding lists is inefficient, use pd.DataFrame(s.tolist()) instead, and for grouped operations, explore groupby().agg() or groupby().transform().

Q: Is DataFrame.apply column-wise better than row-wise

ANS: DataFrame.apply column-wise (axis=0) can sometimes be more performant than row-wise (axis=1), especially when dealing with a large number of rows and fewer columns, as it aligns better with internal pandas optimizations for column operations.

Q: Can numba improve pandas apply performance

ANS: Yes, pandas 2.2 introduced support for engine='numba' in apply, which can JIT compile your function and potentially speed up operations, especially when used with raw=True.

Q: Are there any situations where pandas apply is acceptable

ANS: Yes, apply can be acceptable for operations that are vectorized for Series but not DataFrames, complex group-wise transformations where simplifying the groupby chain is beneficial, or for specific tasks like Unicode decoding where alternatives are less straightforward.

Q: What are the risks of using apply with mutable objects

ANS: The primary risk is mutation bugs, where apply might pass the same object to your function multiple times, leading to unexpected side effects or incorrect results if the object is modified within the function.
