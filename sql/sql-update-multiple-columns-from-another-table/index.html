“SQL: Update Multiple Columns from Another Table”

Updating records in one SQL table based on values from another is a common database operation. This often involves matching rows between the two tables using a common identifier and then transferring specific column values. Several methods exist to achieve this, each with its own syntax and suitability depending on the specific SQL dialect and requirements. Let’s look at effective ways to perform this task.

Common Scenarios for Updating Data Between Tables

  • Data Synchronization: Ensuring consistency between a primary table and a backup or staging table.
  • Applying Changes: Updating records with new information derived from another data source.
  • Data Enrichment: Augmenting records in one table with related data from another.

Methods for Updating Multiple Columns

Here are various techniques to update multiple columns in a target table using data from a source table.

Solution 1: Using UPDATE with FROM Clause (SQL Server Syntax)

This approach utilizes the FROM clause within the UPDATE statement to specify the source table and join condition.

UPDATE Table_A
SET
    Table_A.col1 = Table_B.col1,
    Table_A.col2 = Table_B.col2
FROM
    Some_Table AS Table_A
    INNER JOIN Other_Table AS Table_B
        ON Table_A.id = Table_B.id
WHERE
    Table_A.col3 = 'cool';

This is a straightforward way to update specific columns in Table_A where a match is found in Other_Table based on the id column, and an additional condition Table_A.col3 = 'cool' is met.

Solution 2: Using MERGE Statement (SQL Server 2008+)

The MERGE statement is powerful for synchronizing data between two tables. It can perform INSERT, UPDATE, or DELETE operations based on whether rows match between the source and target.

Basic MERGE:

MERGE INTO YourTable T
   USING other_table S
      ON T.id = S.id
         AND S.tsql = 'cool' -- Condition from the source table
WHEN MATCHED THEN
   UPDATE
      SET col1 = S.col1,
          col2 = S.col2;

MERGE with a derived table (subquery):

MERGE INTO YourTable T
   USING (
          SELECT id, col1, col2
            FROM other_table
           WHERE tsql = 'cool'
         ) S
      ON T.id = S.id
WHEN MATCHED THEN
   UPDATE
      SET col1 = S.col1,
          col2 = S.col2;

The MERGE statement is highly efficient for complex synchronization tasks.

Solution 3: Using UPDATE with a Derived Table

This method involves using a subquery (derived table) to select the data from the source table and then joining it with the target table for the update.

UPDATE YourTable
SET Col1 = OtherTable.Col1,
    Col2 = OtherTable.Col2
FROM (
    SELECT ID, Col1, Col2
    FROM other_table
) AS OtherTable
WHERE
    OtherTable.ID = YourTable.ID;

This is a clean way to isolate the source data before applying the update.

Solution 4: UPDATE with Conditional Logic

This solution focuses on updating only when values differ, preventing unnecessary writes and potential trigger firings.

UPDATE Table
SET Table.col1 = other_table.col1,
    Table.col2 = other_table.col2
FROM
    Table
    INNER JOIN other_table ON Table.id = other_table.id
WHERE
    Table.col1 != other_table.col1
    OR Table.col2 != other_table.col2
    OR (
        other_table.col1 IS NOT NULL
        AND Table.col1 IS NULL
    )
    OR (
        other_table.col2 IS NOT NULL
        AND Table.col2 IS NULL
    );

This query is beneficial for optimizing performance and avoiding unintended side effects by only updating rows that actually need changes.

Solution 5: Direct JOIN Syntax (MySQL/MariaDB)

MySQL and MariaDB offer a concise syntax for updating with joins.

UPDATE
    Some_Table AS Table_A
JOIN
    Other_Table AS Table_B USING(id)
SET
    Table_A.col1 = Table_B.col1,
    Table_A.col2 = Table_B.col2
WHERE
    Table_A.col3 = 'cool';

The USING(id) clause simplifies the join condition when the joining column has the same name in both tables. For more general joins, you can use ON Table_A.id = Table_B.id.

Solution 6: Using a Common Table Expression (CTE)

CTEs provide a way to structure complex queries and improve readability.

WITH CTE AS (
    SELECT
        T1.col1,
        T2.col1 AS _Col1,
        T1.col2,
        T2.col2 AS _Col2
    FROM
        T1
    JOIN
        T2 ON T1.id = T2.id
    /*Where clause added to exclude rows that are the same in both tables
      Handles NULL values correctly*/
    WHERE EXISTS (
        SELECT T1.Col1, T1.Col2
        EXCEPT
        SELECT T2.Col1, T2.Col2
    )
)
UPDATE CTE
SET Col1 = _Col1,
    Col2 = _Col2;

This approach first defines a temporary result set (CTE) containing the rows to be updated and then performs the update on this CTE. Be mindful of potential ambiguity if the source table has multiple matching rows for a single target row.

Solution 7: Updating from a Subquery for Each Column

This method uses scalar subqueries to fetch the values for each column to be updated.

UPDATE suppliers
SET supplier_name = (SELECT customers.name
                     FROM customers
                     WHERE customers.customer_id = suppliers.supplier_id)
WHERE EXISTS (SELECT customers.name
              FROM customers
              WHERE customers.customer_id = suppliers.supplier_id);

The WHERE EXISTS clause ensures that the update only occurs if a matching record exists in the customers table, preventing NULL updates where no match is found.

Solution 8: UPDATE with Aliases and FROM

Similar to Solution 1, this clearly defines aliases for tables involved in the update.

UPDATE t
SET t.col1 = o.col1
FROM table1 AS t
INNER JOIN table2 AS o
    ON t.id = o.id;

This syntax is particularly clear when dealing with multiple tables or complex join conditions.

Solution 9: Using a Derived Table for the Source Data

This is another variant of using a subquery as the data source for the update.

UPDATE t
SET t.col1 = a.col1,
    t.col2 = a.col2
FROM (
    SELECT id, col1, col2 FROM @tbl2
) AS a
INNER JOIN @tbl1 AS t ON t.id = a.id;

This example uses table variables (@tbl1, @tbl2) which is common in SQL Server scripts.

Solution 10: UPDATE with SELECT and INNER JOIN

This approach combines a SELECT statement within the UPDATE process, often used for clarity or when a FROM clause is structured differently.

UPDATE A
SET A.col = A.col, B.col1 = B.col1
FROM  first_Table AS A
INNER JOIN second_Table AS B  ON A.id = B.id WHERE A.col2 = 'cool';

Note that the A.col = A.col part might seem redundant, but it’s sometimes included to ensure the row is selected for the update operation in certain SQL dialects or specific scenarios.

Solution 11: UPDATE with JOIN (MySQL Syntax)

MySQL offers a direct JOIN syntax within the UPDATE statement.

UPDATE Table1
INNER JOIN Table2
ON Table1.id = Table2.id
SET Table1.col1 = Table2.col1,
    Table1.col2 = Table2.col2;

This is a more concise alternative to the UPDATE ... FROM syntax for MySQL users.

Solution 12: UPDATE Directly Referencing Table Aliases

This method allows direct referencing of table aliases, making the update statement more readable, especially when joining a table to itself.

update t1
set t1.somevalue = t2.somevalue
from table1 t1
inner join table1 t2
on ... ; -- your join condition

Solution 13: UPDATE with a Derived Table and Aliases

This is a variation of using derived tables, ensuring clarity through aliasing.

UPDATE x
SET    x.col1 = x.newCol1,
       x.col2 = x.newCol2
FROM   (SELECT t.col1,
               t2.col1 AS newCol1,
               t.col2,
               t2.col2 AS newCol2
        FROM   [table] t
               JOIN other_table t2
                 ON t.ID = t2.ID) x;

This constructs a temporary dataset x with the updated values before applying them.

Solution 14: UPDATE with FROM and WHERE Clause (SQL Server Specific)

This syntax is specific to SQL Server, where the source table is specified in the FROM clause, and the link is established in the WHERE clause.

UPDATE Table1
SET Table1.col1 = Table2.col1,
    Table1.col2 = Table2.col2
FROM
    Table2
WHERE
    Table1.id = Table2.id;

Solution 15: UPDATE from SELECT

This approach demonstrates how to update using a SELECT statement with a JOIN.

UPDATE TQ
SET TQ.IsProcessed = 1, TQ.TextName = 'bla bla bla'
FROM TableQueue TQ
INNER JOIN TableComment TC ON TC.ID = TQ.TCID
WHERE TQ.IsProcessed = 0;

For verification, it’s often wise to first run a SELECT statement with the same JOIN and WHERE clauses to preview the changes.

SELECT TQ.IsProcessed, 1 AS NewValue1, TQ.TextName, 'bla bla bla' AS NewValue2
FROM TableQueue TQ
INNER JOIN TableComment TC ON TC.ID = TQ.TCID
WHERE TQ.IsProcessed = 0;

Solution 16: Shortest Method for UPDATE with FROM

This presents a concise way to update using a FROM clause.

UPDATE #DEST
SET #DEST.[Desc] = #SOURCE.[Desc]
FROM #SOURCE
WHERE #DEST.[ID] = #SOURCE.[ID];

This example uses temporary tables (#SOURCE, #DEST), common in SQL Server for staging data.

Solution 17: UPDATE with Subqueries and JOIN

This showcases using subqueries alongside joins for updating.

-- Option 1: Using subqueries for each column
UPDATE uno
SET col1 = (SELECT col1 FROM dos WHERE uno.uid = did AND [sql] = 'cool'),
    col2 = (SELECT col2 FROM dos WHERE uno.uid = did AND [sql] = 'cool');

-- Option 2: Using JOIN with a derived table
UPDATE uno
SET col1=d.col1, col2=d.col2
FROM uno
INNER JOIN dos d ON uno.uid = did
WHERE [sql] = 'cool';

These examples are particularly useful when the relationship between tables might not be a simple one-to-one match or when specific conditions need to be applied within the subquery.

Solution 18: UPDATE with a Scalar Subquery

This is a direct way to update a column using the result of a scalar subquery.

UPDATE table1
SET column1 = (SELECT expression1
               FROM table2
               WHERE conditions)
[WHERE conditions];

This is suitable when updating a single column based on a single value from another table.

Solution 19: UPDATE with OUTPUT Clause

For auditing or validation, the OUTPUT clause can be used to capture changes.

-- Assuming the SET clause is already defined, e.g.:
-- SET Table_A.col1 = Table_B.col1,
--     Table_A.col2 = Table_B.col2
SET
    Table_A.col1 = Table_B.col1,
    Table_A.col2 = Table_B.col2
OUTPUT deleted.*, inserted.*;

This allows you to see the old and new values of the affected rows. It’s often used within a BEGIN TRANSACTION...ROLLBACK block for testing before committing.

Solution 20: UPDATE with Direct JOIN Syntax (MySQL/MariaDB)

Another example of the MySQL/MariaDB JOIN syntax for updates.

UPDATE
    Some_Table AS Table_A
JOIN
    Other_Table AS Table_B USING(id)
SET
    Table_A.col1 = Table_B.col1,
    Table_A.col2 = Table_B.col2
WHERE
    Table_A.col3 = 'cool';

This syntax is highly readable and efficient for database systems that support it.

Considerations for Choosing a Method

  • SQL Dialect: Ensure the syntax is compatible with your specific database system (e.g., SQL Server, MySQL, PostgreSQL).
  • Performance: For large datasets, test different methods to determine the most performant. MERGE and UPDATE with efficient joins are often favored.
  • Readability: CTEs and well-aliased joins can improve code clarity.
  • Error Handling: Consider how to handle cases where multiple source rows match a single target row, or when no match is found. MERGE offers robust options for this.

To learn more about SQL operations, explore resources on What is SQL and different database systems like PostgreSQL or MySQL .

FAQs on SQL Updates

Q: What is the most common way to update rows from another table

ANS: The most common and often efficient method involves using an UPDATE statement with an INNER JOIN clause to link the target and source tables based on a common key. This allows you to specify which columns to update from the source table.

Q: Can I update columns in a table without a direct join if tables share no common field

ANS: Yes, if tables lack a common field for joining, you can use correlated subqueries within the UPDATE statement. The subquery would fetch the necessary value from the source table based on a condition that uniquely identifies the target row. For example, UPDATE Table SET Table.example = a.value FROM TableExample a WHERE Table.field = *key value* AND a.field = *key value*.

Q: How to ensure I only update rows that have changed

ANS: To update only changed rows, include a WHERE clause in your UPDATE statement that compares the values of the columns in the target table with the corresponding columns in the source table. For instance, WHERE Table.col1 != other_table.col1 OR Table.col2 != other_table.col2.

Q: What is the role of MERGE statement in updating

ANS: The MERGE statement is a powerful tool for synchronizing data. It allows you to perform INSERT, UPDATE, or DELETE operations on a target table based on the results of joining it with a source table. It’s particularly useful for upsert (update or insert) scenarios.

Q: How do CTEs help in updating data from another table

ANS: Common Table Expressions (CTEs) can improve the readability and organization of complex update queries. You can define a CTE that selects and potentially transforms the data from the source table, and then use this CTE in your UPDATE statement as if it were a regular table.
