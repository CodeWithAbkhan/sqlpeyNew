“Oracle SQL: Split Comma Delimited String into Rows”

When working with data in Oracle databases, you might encounter situations where a single column contains multiple values separated by a delimiter, such as a comma. This format can hinder analysis and reporting. The challenge lies in efficiently transforming these comma-separated strings into individual rows, making each value accessible for further processing. This post explores various Oracle SQL techniques to achieve this data transformation.

Consider a scenario with a table containing error codes, where each row might have a single error or a list of errors separated by commas. The goal is to unnest these lists so that each error appears on its own row, associated with its original record.

Let’s imagine our source data structure looks like this:

-- Sample Data Setup
WITH temp_data AS (
    SELECT 108 AS name, 'test' AS project, 'Err1, Err2, Err3' AS error FROM dual UNION ALL
    SELECT 109, 'test2', 'Err1' FROM dual
)
SELECT * FROM temp_data;

Output:

The following methods demonstrate how to achieve the desired output, where each error is on its own line.

Solution 1: Using REGEXP_SUBSTR with Hierarchical Queries (CONNECT BY)

This approach leverages Oracle’s powerful regular expression functions combined with hierarchical query capabilities to generate row numbers that correspond to each delimited item.

-- Solution 1: REGEXP_SUBSTR with CONNECT BY
WITH temp_data AS (
    SELECT 108 AS name, 'test' AS project, 'Err1, Err2, Err3' AS error FROM dual UNION ALL
    SELECT 109, 'test2', 'Err1' FROM dual
)
SELECT DISTINCT
    t.name, t.project,
    TRIM(REGEXP_SUBSTR(t.error, '[^,]+', 1, levels.column_value)) AS error
FROM
    temp_data t,
    TABLE(CAST(MULTISET(SELECT LEVEL FROM dual CONNECT BY LEVEL <= LENGTH(REGEXP_REPLACE(t.error, '[^,]+')) + 1) AS SYS.OdciNumberList)) levels
ORDER BY name;

Explanation:

  • LENGTH(REGEXP_REPLACE(t.error, '[^,]+')) + 1: This calculates the number of items by replacing all non-comma characters and then counting the remaining commas, adding one for the total count of delimited items.
  • CONNECT BY LEVEL <= ...: This generates a sequence of numbers from 1 up to the total count of items for each row.
  • REGEXP_SUBSTR(t.error, '[^,]+', 1, levels.column_value): This function extracts the nth occurrence of a substring that is not a comma.
  • TABLE(CAST(MULTISET(...) AS SYS.OdciNumberList)): This converts the generated sequence of numbers into a collection that can be joined with the original data.

Solution 2: Using REGEXP_SUBSTR and CONNECT BY with INSTR

An alternative to counting commas for the CONNECT BY clause is to use the INSTR function to identify the positions of the delimiters.

-- Solution 2: REGEXP_SUBSTR with CONNECT BY and INSTR
WITH temp_data AS (
    SELECT 108 AS name, 'test' AS project, 'Err1, Err2, Err3' AS error FROM dual UNION ALL
    SELECT 109, 'test2', 'Err1' FROM dual
)
SELECT DISTINCT Name, Project, TRIM(REGEXP_SUBSTR(str, '[^,]+', 1, level)) AS str
FROM (SELECT Name, Project, Error AS str FROM temp_data) t
CONNECT BY INSTR(str, ',', 1, level - 1) > 0
ORDER BY Name;

Explanation:

  • INSTR(str, ',', 1, level - 1) > 0: This condition in the CONNECT BY clause ensures that the hierarchical query continues as long as there are more delimiters to find. The level - 1 handles the first occurrence.

Solution 3: Using XMLTABLE

XMLTABLE provides a way to shred XML data, and by converting the string into a pseudo-XML format, we can effectively split it.

-- Solution 3: Using XMLTABLE
CREATE TABLE string_split_example (
    ID          NUMBER GENERATED ALWAYS AS IDENTITY,
    text_data   VARCHAR2(100)
);

INSERT INTO string_split_example (text_data) VALUES ('word1, word2, word3');
INSERT INTO string_split_example (text_data) VALUES ('word4, word5, word6');
INSERT INTO string_split_example (text_data) VALUES ('word7, word8, word9');
COMMIT;

SELECT id,
       TRIM(COLUMN_VALUE) AS split_text
FROM string_split_example,
     XMLTABLE(('"' || REPLACE(text_data, ',', '","') || '"'))
/

Explanation:

  • REPLACE(text_data, ',', '","'): This transforms the comma-separated string into a comma-separated JSON-like array structure, e.g., "word1","word2","word3".
  • XMLTABLE(...): This function then parses this string as if it were XML, extracting each element.

Solution 4: Using REGEXP_COUNT and CONNECT BY

This method, available from Oracle 11g, uses REGEXP_COUNT to determine the number of items.

-- Solution 4: REGEXP_COUNT and CONNECT BY (Oracle 11g+)
SELECT TRIM(REGEXP_SUBSTR('Err1, Err2, Err3', '[^,]+', 1, LEVEL)) AS error_item
FROM dual
CONNECT BY LEVEL <= REGEXP_COUNT('Err1, Err2, Err3', ',') + 1;

-- Alternative using LENGTH and REPLACE
SELECT TRIM(REGEXP_SUBSTR('Err1, Err2, Err3', '[^,]+', 1, LEVEL)) AS error_item
FROM dual
CONNECT BY LEVEL <= LENGTH('Err1, Err2, Err3') - LENGTH(REPLACE('Err1, Err2, Err3', ',', '')) + 1;

Explanation:

  • REGEXP_COUNT('Err1, Err2, Err3', ',') + 1: This directly counts the number of delimiters and adds one to get the total number of items.
  • The second query achieves the same by comparing the string length before and after removing commas.

Solution 5: Using a PIPELINED Table Function

Creating a custom pipelined function offers a reusable and potentially more performant solution, especially when needing optimizer hints for cardinality.

-- Solution 5: Pipelined Table Function
CREATE OR REPLACE TYPE typ_str2tbl_nst AS TABLE OF VARCHAR2(30);
/

CREATE OR REPLACE FUNCTION str2tbl (
  p_string    VARCHAR2,
  p_delimiter CHAR DEFAULT ','
)
RETURN typ_str2tbl_nst PIPELINED
AS
  l_tmp VARCHAR2(32000) := p_string || p_delimiter;
  l_pos NUMBER;
BEGIN
  LOOP
    l_pos := INSTR( l_tmp, p_delimiter );
    EXIT WHEN NVL( l_pos, 0 ) = 0;
    PIPE ROW ( RTRIM( LTRIM( SUBSTR( l_tmp, 1, l_pos - 1) ) ) );
    l_tmp := SUBSTR( l_tmp, l_pos + 1 );
  END LOOP;
END str2tbl;
/

-- Example Usage with Optimizer Statistics
-- First, create the optimizer interface object
CREATE OR REPLACE TYPE typ_str2tbl_stats AS OBJECT (
  dummy NUMBER,
  STATIC FUNCTION ODCIGetInterfaces ( p_interfaces OUT SYS.ODCIObjectList )
  RETURN NUMBER,
  STATIC FUNCTION ODCIStatsTableFunction ( p_function  IN  SYS.ODCIFuncInfo,
                                           p_stats     OUT SYS.ODCITabFuncStats,
                                           p_args      IN  SYS.ODCIArgDescList,
                                           p_string    IN  VARCHAR2,
                                           p_delimiter IN  CHAR DEFAULT ',' )
  RETURN NUMBER
);
/

-- Implement the optimizer interface body
CREATE OR REPLACE TYPE BODY typ_str2tbl_stats
AS
  STATIC FUNCTION ODCIGetInterfaces ( p_interfaces OUT SYS.ODCIObjectList )
  RETURN NUMBER
  AS
  BEGIN
    p_interfaces := SYS.ODCIObjectList ( SYS.ODCIObject ('SYS', 'ODCISTATS2') );
    RETURN ODCIConst.SUCCESS;
  END ODCIGetInterfaces;

  STATIC FUNCTION ODCIStatsTableFunction ( p_function  IN  SYS.ODCIFuncInfo,
                                           p_stats     OUT SYS.ODCITabFuncStats,
                                           p_args      IN  SYS.ODCIArgDescList,
                                           p_string    IN  VARCHAR2,
                                           p_delimiter IN  CHAR DEFAULT ',' )
  RETURN NUMBER
  AS
  BEGIN
    p_stats := SYS.ODCITabFuncStats( CEIL( LENGTH( p_string ) / 2 ) ); -- Heuristic for cardinality
    RETURN ODCIConst.SUCCESS;
  END ODCIStatsTableFunction;
END;
/

-- Associate the statistics with the function
ASSOCIATE STATISTICS WITH FUNCTIONS str2tbl USING typ_str2tbl_stats;

-- Query using the pipelined function
WITH temp_data AS (
    SELECT 108 AS name, 'test' AS project, 'Err1, Err2, Err3' AS error FROM dual UNION ALL
    SELECT 109, 'test2', 'Err1' FROM dual
)
SELECT name, project, TRIM(COLUMN_VALUE) AS error
FROM temp_data, TABLE(str2tbl(error));

Explanation:

  • The str2tbl function iterates through the string, using INSTR to find delimiters and SUBSTR to extract each item.
  • The PIPE ROW statement returns each extracted item as a row.
  • The ASSOCIATE STATISTICS clause is crucial for providing cardinality estimates to the optimizer, preventing potential performance issues with large datasets. This technique is supported in Oracle 10g and later.

Solution 6: Using JSON_TABLE (Oracle 12c+)

For versions 12c and later, JSON_TABLE offers a powerful and concise way to process delimited strings by leveraging JSON capabilities.

-- Solution 6: Using JSON_TABLE (Oracle 12c+)
CREATE TABLE json_split_data (name, project, error) AS
SELECT 108,'test' ,'Err1, Err2, Err3' FROM dual UNION
SELECT 109,'test2','Err1'             FROM dual;

SELECT
    t.name, t.project,
    TRIM(s.p) AS error
FROM json_split_data t
OUTER APPLY (SELECT TRIM(p) AS p
            FROM JSON_TABLE(REPLACE(JSON_ARRAY(t.error), ',', '","'),
           '$[*]' COLUMNS (p VARCHAR2(4000) PATH '$'))) s;

Explanation:

  • JSON_ARRAY(t.error): Converts the string into a JSON array representation.
  • REPLACE(..., ',', '","'): Modifies the array string to be correctly parsable by JSON_TABLE.
  • JSON_TABLE(...): This function parses the JSON string, treating each comma-separated element as an array item and extracting it into a column p.

Solution 7: Using Recursive CTEs (Oracle 11gR2+)

Recursive Common Table Expressions (CTEs) provide an alternative to CONNECT BY for splitting strings, supported from Oracle 11gR2.

-- Solution 7: Recursive CTE (Oracle 11gR2+)
WITH cte0 AS (
    SELECT 'Err1, Err2, Err3' AS phone_number FROM dual UNION ALL
    SELECT 'Err1' FROM dual
),
cte1(xstr, xrest, xremoved) AS (
    SELECT phone_number, phone_number, NULL
    FROM cte0
    UNION ALL
    SELECT xstr,
        CASE WHEN INSTR(xrest, '.', 1) = 0 THEN NULL ELSE SUBSTR(xrest, INSTR(xrest, '.', 1) + 1) END,
        CASE WHEN INSTR(xrest, '.', 1) = 0 THEN xrest ELSE SUBSTR(xrest, 1, INSTR(xrest, '.', 1) - 1) END
    FROM cte1
    WHERE xrest IS NOT NULL
)
SELECT xstr, xremoved FROM cte1
WHERE xremoved IS NOT NULL
ORDER BY xstr;

Explanation:

  • The base CTE (cte0) selects the data.
  • The recursive CTE (cte1) iteratively processes the string, extracting substrings based on the delimiter (here, . is used as an example, but can be changed to ,).

Solution 9: Using DBMS_UTILITY.COMMA_TO_TABLE

This is a procedural approach using a built-in Oracle package.

-- Solution 9: DBMS_UTILITY.COMMA_TO_TABLE
DECLARE
    l_tablen  BINARY_INTEGER;
    l_tab     DBMS_UTILITY.uncl_array;
    -- Assuming a table named 'source_table' with columns 'id', 'data_string'
    CURSOR cur IS SELECT id, data_string FROM source_table;
    rec cur%rowtype;
BEGIN
    OPEN cur;
    LOOP
        FETCH cur INTO rec;
        EXIT WHEN cur%NOTFOUND;

        DBMS_UTILITY.comma_to_table (
            list   => rec.data_string,
            tablen => l_tablen,
            tab    => l_tab
        );

        FOR i IN 1 .. l_tablen LOOP
            -- Process each split item, e.g., insert into another table
            -- For demonstration, we'll output it.
            DBMS_OUTPUT.put_line('ID: ' || rec.id || ', Item: ' || l_tab(i));
        END LOOP;
    END LOOP;
    CLOSE cur;
END;
/

Explanation:

  • This PL/SQL block iterates through rows, uses DBMS_UTILITY.COMMA_TO_TABLE to split the string into a collection (l_tab), and then processes each item.

Solution 10: Using Substring and INSTR without CONNECT BY or REGEXP

This method avoids hierarchical queries and regular expressions, relying purely on string manipulation functions.

-- Solution 10: SUBSTR and INSTR without CONNECT BY or REGEXP
WITH mytable AS (
    SELECT 108 AS name, 'test' AS project, 'Err1,Err2,Err3' AS error FROM dual UNION ALL
    SELECT 109, 'test2', 'Err1' FROM dual
),
x AS (
    SELECT name, project, ',' || error || ',' AS error_padded
    FROM mytable
),
iter AS (
    SELECT ROWNUM AS pos
    FROM all_objects -- Used to generate a sequence of numbers
)
SELECT x.name, x.project,
    SUBSTR(x.error_padded,
        INSTR(x.error_padded, ',', 1, iter.pos) + 1,
        INSTR(x.error_padded, ',', 1, iter.pos + 1) - INSTR(x.error_padded, ',', 1, iter.pos) - 1
    ) AS error
FROM x, iter
WHERE iter.pos <= (LENGTH(x.error_padded) - LENGTH(REPLACE(x.error_padded, ','))) - 1;

Explanation:

  • The string is padded with commas at the beginning and end (error_padded).
  • A sequence of numbers is generated using ROWNUM from all_objects.
  • INSTR is used twice to find the start and end positions of each delimited item within the padded string, and SUBSTR extracts the item.

Solution 11: Using XMLTABLE with tokenize (Oracle 11g and later)

This approach leverages XMLTABLE with the tokenize function, providing a clean way to split strings.

-- Solution 11: XMLTABLE with tokenize (Oracle 11g+)
SELECT xmltab.txt
FROM XMLTABLE(
  'for $text in tokenize("a,b,c", ",") return $text'
  COLUMNS
    txt VARCHAR2(4000) PATH '.'
) xmltab;

-- For data in a table:
WITH base_data AS (
  SELECT 'a;b;c' AS inpt FROM dual UNION ALL
  SELECT 'd;e;f' AS inpt FROM dual
)
SELECT
  xmltab.txt
FROM base_data base
INNER JOIN XMLTABLE(
  'for $text in tokenize($input, ";") return $text'
  PASSING base.inpt AS "input"
  COLUMNS
    txt VARCHAR2(4000) PATH '.'
) xmltab
  ON 1=1;

Explanation:

  • tokenize($input, ";"): This XQuery function splits the input string by the specified delimiter.
  • XMLTABLE then processes the resulting sequence to create rows.

Solution 12: Using a Recursive Subquery (Oracle 11g and later)

This method uses a recursive subquery to repeatedly find and extract delimited items, similar in concept to CTEs but expressed differently.

-- Solution 12: Recursive Subquery (Oracle 11g+)
CREATE TABLE delimiter_split_example (
    name    NUMBER,
    project VARCHAR2(50),
    error   VARCHAR2(100)
);

INSERT INTO delimiter_split_example (name, project, error) VALUES (108, 'test', 'Err1, Err2, Err3');
INSERT INTO delimiter_split_example (name, project, error) VALUES (109, 'test2', 'Err1');
COMMIT;

WITH table_name_error_bounds ( name, project, error, start_pos, end_pos ) AS (
  SELECT name,
         project,
         error,
         1,
         INSTR( error, ', ', 1 )
  FROM   delimiter_split_example
UNION ALL
  SELECT name,
         project,
         error,
         end_pos + 2,
         INSTR( error, ', ', end_pos + 2 )
  FROM   table_name_error_bounds
  WHERE  end_pos > 0
)
SELECT name,
       project,
       CASE end_pos
       WHEN 0
       THEN SUBSTR( error, start_pos )
       ELSE SUBSTR( error, start_pos, end_pos - start_pos )
       END AS error
FROM   table_name_error_bounds;

Explanation:

  • The CTE finds the start and end positions of each delimited item.
  • The recursive part continues as long as more delimiters are found.
  • SUBSTR is used to extract the actual error string based on the calculated positions.

FAQs on Oracle SQL String Splitting

Q: What is the most common way to split strings in Oracle SQL

ANS: The most frequent methods involve using REGEXP_SUBSTR in conjunction with hierarchical queries (CONNECT BY) or the XMLTABLE function. These offer a good balance of performance and readability for many common scenarios.

Q: Can I split strings without using regular expressions

ANS: Yes, it is possible. You can achieve string splitting using combinations of SUBSTR, INSTR, and either hierarchical queries (CONNECT BY) or recursive CTEs, as demonstrated in some of the solutions provided.

Q: Which method is best for Oracle 12c and later versions

ANS: For Oracle 12c and newer, JSON_TABLE provides a very efficient and modern approach to splitting delimited strings by treating them as JSON arrays.

Q: How do I handle different delimiters

ANS: Most of the provided solutions can be easily adapted to different delimiters. For instance, when using regular expressions, simply change the delimiter in the pattern. For INSTR and XMLTABLE with tokenize, update the delimiter character in the function calls.

Q: Is there a way to improve the performance of pipelined functions for splitting

ANS: Yes, Oracle provides mechanisms to associate statistics with pipelined table functions. By providing cardinality estimates, you can help the optimizer create more efficient execution plans, as shown in Solution 5.

We hope these diverse methods provide a solid foundation for handling delimited strings in your Oracle SQL projects.
