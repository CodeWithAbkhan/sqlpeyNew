“Efficient SQL Server Number Sequence Generation Methods Compared”

Generating sequences of numbers in SQL Server is a common task, whether for populating test data, creating series for reports, or supporting complex queries. Different methods offer varying performance characteristics and code complexity. This post examines several popular techniques, providing code examples, performance insights, and practical considerations for choosing the best approach for your needs.

Method 1: Basic Looping (Slow)

This method uses a WHILE loop to insert numbers one by one. It’s straightforward but notoriously slow for larger datasets.

Performance: Averages around 13.01 seconds for 100,000 rows.

-- Method 1: Slow Looping
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
CREATE TABLE NumbersTest(Number INT IDENTITY(1,1));
SET NOCOUNT ON;
WHILE COALESCE(SCOPE_IDENTITY(), 0) < 100000
BEGIN
    INSERT INTO dbo.NumbersTest DEFAULT VALUES;
END;
SET NOCOUNT OFF;
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE()) / 1000.0) + ' seconds';
SELECT COUNT(*) FROM NumbersTest;

Method 2: Optimized Looping (Faster)

A slightly improved looping approach that maintains the iterative structure but can be more efficient than the most basic loop.

Performance: Averages around 1.1658 seconds for 10,000 rows.

-- Method 2: Optimized Looping
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
CREATE TABLE NumbersTest (Number INT NOT NULL);
DECLARE @i INT = 1;
SET NOCOUNT ON;
WHILE @i <= 10000
BEGIN
    INSERT INTO dbo.NumbersTest(Number) VALUES (@i);
    SET @i = @i + 1;
END;
SET NOCOUNT OFF;
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE()) / 1000.0) + ' seconds';
SELECT COUNT(*) FROM NumbersTest;

Method 3: Common Table Expression (CTE) Recursion

This approach uses a recursive CTE to generate the number sequence, which is generally more performant than simple loops for generating a large number of rows.

Performance: Averages around 488.6 milliseconds for 10,000 rows.

-- Method 3: CTE Recursion
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
CREATE TABLE NumbersTest (Number int NOT NULL);
WITH Nums(Number) AS
(
    SELECT 1 AS Number
    UNION ALL
    SELECT Number + 1 FROM Nums WHERE Number < 10000
)
INSERT INTO NumbersTest(Number)
    SELECT Number FROM Nums OPTION (MAXRECURSION 10000);
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE())) + ' milliseconds';
SELECT COUNT(*) FROM NumbersTest;

Method 4: “Semi-Looping” with GO Batch Separator

This method leverages the GO batch separator to efficiently replicate rows. It’s a clever technique but requires careful handling of the batch separator.

Performance: Averages around 348.3 milliseconds for ~16,384 rows.

-- Method 4: Semi-Looping with GO
DROP TABLE IF EXISTS NumbersTest;
DROP TABLE IF EXISTS #RunDate;
CREATE TABLE #RunDate (RunDate datetime);
INSERT INTO #RunDate VALUES(GETDATE());
CREATE TABLE NumbersTest (Number int NOT NULL);
INSERT NumbersTest values (1);
GO -- Required for batch separation
INSERT NumbersTest SELECT Number + (SELECT COUNT(*) FROM NumbersTest) FROM NumbersTest;
GO 14 -- Will create 16384 total rows
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
SELECT CONVERT(varchar(20), datediff(ms, RunDate, GETDATE())) + ' milliseconds' FROM #RunDate;
SELECT COUNT(*) FROM NumbersTest;

Method 5: Single INSERT with Exponential CTEs (Tally Table)

This highly efficient method uses chained CTEs to exponentially increase the number of rows, creating a large sequence with a single INSERT statement. This is often referred to as a “Tally Table” approach.

Performance: Averages around 92.7 milliseconds for 10,000 rows.

-- Method 5: Single INSERT with Exponential CTEs
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
CREATE TABLE NumbersTest (Number int NOT NULL);
;WITH
  Pass0 as (select 1 as C union all select 1), -- 2 rows
  Pass1 as (select 1 as C from Pass0 as A, Pass0 as B), -- 4 rows
  Pass2 as (select 1 as C from Pass1 as A, Pass1 as B), -- 16 rows
  Pass3 as (select 1 as C from Pass2 as A, Pass2 as B), -- 256 rows
  Pass4 as (select 1 as C from Pass3 as A, Pass3 as B), -- 65536 rows
  Tally as (select row_number() over(order by C) as Number from Pass4)
INSERT NumbersTest
        (Number)
    SELECT Number
        FROM Tally
        WHERE Number <= 10000;
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE())) + ' milliseconds';
SELECT COUNT(*) FROM NumbersTest;

Method 6: Single INSERT using master..spt_values

This method leverages the system table master..spt_values and a CROSS JOIN to quickly generate a large number of rows for the sequence.

Performance: Averages around 82.3 milliseconds for 10,000 rows.

-- Method 6: Single INSERT using master..spt_values
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
CREATE TABLE NumbersTest (Number int NOT NULL);
INSERT INTO NumbersTest(Number)
SELECT TOP 10000 row_number() over (order by t1.number) as N
FROM master..spt_values t1
    CROSS JOIN master..spt_values t2;
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE())) + ' milliseconds';
SELECT COUNT(*) FROM NumbersTest;

Method 7: IDENTITY with sys.objects

This approach uses the IDENTITY property combined with a CROSS JOIN on sys.objects to generate the sequence efficiently.

Performance: Averages around 56.3 milliseconds for 10,000 rows.

-- Method 7: IDENTITY with sys.objects
DROP TABLE IF EXISTS NumbersTest;
DECLARE @RunDate datetime = GETDATE();
SELECT TOP 10000 IDENTITY(int,1,1) AS Number
    INTO NumbersTest
    FROM sys.objects s1 -- use sys.columns if you don't get enough rows returned
    CROSS JOIN sys.objects s2; -- use sys.columns if you don't get enough rows returned
ALTER TABLE NumbersTest ADD CONSTRAINT PK_NumbersTest PRIMARY KEY CLUSTERED (Number);
PRINT CONVERT(varchar(20), datediff(ms, @RunDate, GETDATE())) + ' milliseconds';
SELECT COUNT(*) FROM NumbersTest;

Method 8: Optimized IDENTITY with User-Defined Values

An optimization of Method 7, this version uses custom VALUES clauses with BIT or BIGINT data types for potentially faster generation, independent of sys.objects content.

Performance: Can achieve around 10-20ms for 10,000 rows, faster than relying on sys.objects.

-- Method 8: Optimized IDENTITY with User-Defined Values

IF OBJECT_ID('tempdb..#TALLY') IS NOT NULL DROP TABLE #TALLY;

    INTO #TALLY
    FROM (SELECT @BIT [X] UNION ALL SELECT @BIT) [T2]

    CROSS JOIN (SELECT @BIT [X] UNION ALL SELECT @BIT) [T16]
    CROSS JOIN (SELECT @BIT [X] UNION ALL SELECT @BIT) [T32]
    CROSS JOIN (SELECT @BIT [X] UNION ALL SELECT @BIT) [T64]

Method 9: Incremental Inserts into a Permanent Table

This method involves creating a permanent “numbers” table and then incrementally inserting values by doubling the existing set. This is efficient for creating a large table once.

Performance: Cost is amortized over multiple uses; initial creation can be done efficiently.

-- Method 9: Incremental Inserts into a Permanent Table
DROP TABLE IF EXISTS numbers;
CREATE TABLE numbers (n integer PRIMARY KEY);
INSERT INTO numbers VALUES (0);
INSERT INTO numbers SELECT n + 1 FROM numbers; -- Continue doubling inserts as needed
INSERT INTO numbers SELECT n + 2 FROM numbers;
INSERT INTO numbers SELECT n + 4 FROM numbers;
INSERT INTO numbers SELECT n + 8 FROM numbers;
INSERT INTO numbers SELECT n + 16 FROM numbers;
INSERT INTO numbers SELECT n + 32 FROM numbers;

Method 10: Avoiding System Dependencies

This approach emphasizes creating a dedicated numbers table rather than relying on system objects like sys.objects, offering more control and predictability.

Method 11: GENERATE_SERIES Function (SQL Server 2022+)

For modern SQL Server versions (2022 and later), GENERATE_SERIES provides a clean and efficient way to create number sequences.

Performance: Very efficient for its purpose.

-- Method 11: GENERATE_SERIES
SELECT * FROM GENERATE_SERIES(1, 10000);

Method 12: Performance Benchmarking Script

This script allows you to benchmark various number generation algorithms directly on your system, comparing their performance for different sequence lengths. It highlights methods like those from Philip Kelley and Mladen Prajdic as strong contenders.

-- Method 12: Performance Benchmarking Script
SET NOCOUNT ON;

DECLARE @NumberOfNumbers INT = 1000000; -- Adjust as needed
DECLARE @TestIteration INT = 0;
DECLARE @MaxIterations INT = 10;
DECLARE @MethodName VARCHAR(128);

DROP TABLE IF EXISTS #TimingTest;
CREATE TABLE #TimingTest (
    MethodName VARCHAR(128),
    TestIteration INT,
    StartDate DATETIME2,
    EndDate DATETIME2,
    ElapsedTime DECIMAL(38, 0),
    ItemCount DECIMAL(38, 0),
    MaxNumber DECIMAL(38, 0),
    MinNumber DECIMAL(38, 0)
);

WHILE @TestIteration < @MaxIterations
BEGIN
    SET @TestIteration += 1;

    -- Philip Kelley's Algorithm
    SET @MethodName = 'PhilKelley';
    DROP TABLE IF EXISTS [Numbers].[Test];
    CREATE TABLE [Numbers].[Test] (Number INT NOT NULL);
    INSERT INTO #TimingTest(MethodName, TestIteration, StartDate) SELECT @MethodName, @TestIteration, GETDATE();
    ; WITH
    RowSet0 as (select 1 as Item union all select 1),
    RowSet1 as (select 1 as Item from RowSet0 as A, RowSet0 as B),
    RowSet2 as (select 1 as Item from RowSet1 as A, RowSet1 as B),
    RowSet3 as (select 1 as Item from RowSet2 as A, RowSet2 as B),
    RowSet4 as (select 1 as Item from RowSet3 as A, RowSet3 as B),
    RowSet5 as (select 1 as Item from RowSet4 as A, RowSet4 as B),
    Tally as (select row_number() over (order by Item) as Number from RowSet5)
    INSERT INTO [Numbers].[Test] (Number) SELECT o.Number FROM Tally o WHERE o.Number <= @NumberOfNumbers;
    ALTER TABLE [Numbers].[Test] ADD CONSTRAINT PK_Numbers_Test_Number PRIMARY KEY CLUSTERED (Number);
    UPDATE tt SET EndDate = GETDATE() FROM #TimingTest tt WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;
    UPDATE tt SET ItemCount = results.ItemCount, MaxNumber = results.MaxNumber, MinNumber = results.MinNumber FROM #TimingTest tt CROSS JOIN (SELECT COUNT(Number) as ItemCount, MAX(Number) as MaxNumber, MIN(Number) as MinNumber FROM [Numbers].[Test]) results WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;

    -- Mladen Prajdic Answer
    SET @MethodName = 'MladenPrajdic';
    DROP TABLE IF EXISTS [Numbers].[Test];
    CREATE TABLE [Numbers].[Test] (Number INT NOT NULL);
    INSERT INTO #TimingTest(MethodName, TestIteration, StartDate) SELECT @MethodName, @TestIteration, GETDATE();
    INSERT INTO [Numbers].[Test](Number) SELECT TOP (@NumberOfNumbers) row_number() over(order by t1.number) as N FROM master..spt_values t1 CROSS JOIN master..spt_values t2;
    ALTER TABLE [Numbers].[Test] ADD CONSTRAINT PK_Numbers_Test_Number PRIMARY KEY CLUSTERED (Number);
    UPDATE tt SET EndDate = GETDATE() FROM #TimingTest tt WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;
    UPDATE tt SET ItemCount = results.ItemCount, MaxNumber = results.MaxNumber, MinNumber = results.MinNumber FROM #TimingTest tt CROSS JOIN (SELECT COUNT(Number) as ItemCount, MAX(Number) as MaxNumber, MIN(Number) as MinNumber FROM [Numbers].[Test]) results WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;

    -- Single INSERT using sys.objects
    SET @MethodName = 'SingleInsertSysObjects';
    DROP TABLE IF EXISTS [Numbers].[Test];
    SELECT TOP (@NumberOfNumbers) IDENTITY(int,1,1) AS Number INTO [Numbers].[Test] FROM sys.objects s1 CROSS JOIN sys.objects s2;
    ALTER TABLE [Numbers].[Test] ADD CONSTRAINT PK_Numbers_Test_Number PRIMARY KEY CLUSTERED (Number);
    INSERT INTO #TimingTest(MethodName, TestIteration, StartDate) SELECT @MethodName, @TestIteration, GETDATE();
    UPDATE tt SET EndDate = GETDATE() FROM #TimingTest tt WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;
    UPDATE tt SET ItemCount = results.ItemCount, MaxNumber = results.MaxNumber, MinNumber = results.MinNumber FROM #TimingTest tt CROSS JOIN (SELECT COUNT(Number) as ItemCount, MAX(Number) as MaxNumber, MIN(Number) as MinNumber FROM [Numbers].[Test]) results WHERE tt.MethodName = @MethodName AND tt.TestIteration = @TestIteration;
END

UPDATE tt SET ElapsedTime = DATEDIFF(MICROSECOND, StartDate, EndDate) FROM #TimingTest tt;

SELECT
    MethodName,
    AVG(CAST(ElapsedTime AS FLOAT)) / AVG(CAST(ItemCount AS FLOAT)) AS TimePerRecord_us,
    CAST(AVG(ItemCount) AS BIGINT) AS SequenceLength,
    MAX(ElapsedTime) AS MaxTime_us,
    MIN(ElapsedTime) AS MinTime_us,
    MAX(MaxNumber) AS MaxNumber,
    MIN(MinNumber) AS MinNumber
FROM #TimingTest
GROUP BY MethodName
ORDER BY TimePerRecord_us ASC, MaxTime_us ASC, MinTime_us ASC;

Method 13: Basic WHILE loop with controlled range

A simple WHILE loop that allows direct control over the lower and upper bounds of the generated sequence, without relying on primary keys or identity constraints during generation.

-- Method 13: Basic WHILE loop with controlled range
CREATE TABLE Numbers(N INT);

DECLARE @lower_range INT = 1;
DECLARE @upper_range INT = 10000;

WHILE(@lower_range <= @upper_range)
BEGIN
    INSERT INTO Numbers(N) VALUES(@lower_range);
    SET @lower_range = @lower_range + 1;
END;

SELECT * FROM Numbers ORDER BY N;

Considerations for Choosing a Method:

  • Performance: For generating large sequences quickly, methods using CTEs (like Method 5 and 7), master..spt_values (Method 6), or GENERATE_SERIES (Method 11) are typically the most efficient.
  • SQL Server Version: GENERATE_SERIES is only available in newer versions. Older methods remain relevant for compatibility.
  • Control: Methods allowing specific range control (Method 13) or custom sequences are valuable.
  • Readability: Simpler methods like basic loops (though slow) are easier to grasp initially. CTEs and system function usage require more familiarity.
  • Reusability: Creating a permanent “numbers” table (Method 9) is beneficial if you frequently need a sequence.

FAQs on SQL Server Number Sequence Generation

Q: What is the fastest way to generate a million numbers in SQL Server

ANS: For generating a million numbers efficiently in SQL Server, methods utilizing advanced CTEs like the Tally Table approach (Method 5), using master..spt_values with CROSS JOIN (Method 6), or the IDENTITY property with sys.objects (Method 7) are generally the quickest. For SQL Server 2022+, GENERATE_SERIES is a highly optimized built-in option.

Q: Can I generate a sequence with a specific start and end number

ANS: Yes, methods like the basic WHILE loop (Method 13) or adjusting the TOP clause or WHERE clause in CTE-based approaches (like Method 5) allow you to define the specific start and end values for your number sequence.

Q: Which method is best for older SQL Server versions

ANS: If you are using older versions of SQL Server that do not support GENERATE_SERIES, methods like the CTE-based Tally Table approach (Method 5), using master..spt_values (Method 6), or the IDENTITY property with sys.objects (Method 7) are excellent alternatives that provide good performance.

Q: Is it better to create a permanent numbers table

ANS: Creating a permanent numbers table (as shown in Method 9) is advantageous if you frequently require sequences for reporting or data generation. The initial cost of creation is amortized over many uses, making it a reusable and efficient resource.

Q: What are the downsides of using loops for number generation

ANS: Looping methods (Method 1 and 2) are generally much slower for generating large sequences compared to set-based approaches. Each iteration typically involves a separate insert operation, leading to increased overhead and slower execution times, especially over WAN connections.

Q: How does GENERATE_SERIES compare to CTEs

ANS: GENERATE_SERIES (Method 11) is a built-in function optimized by Microsoft for creating sequences, offering a clean syntax. CTE-based methods (like Method 5) are powerful and flexible, often matching or exceeding GENERATE_SERIES performance depending on the SQL Server version and specific implementation.
