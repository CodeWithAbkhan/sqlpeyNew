“SQL Server: Effective Strategies for Removing Duplicate Rows”

Encountering duplicate data within your SQL Server tables is a common challenge that can impact data integrity, query performance, and reporting accuracy. Effectively identifying and purging these redundant records is crucial for maintaining a clean and reliable database. This post delves into various proven methods for eliminating duplicate rows, providing practical SQL code examples and explanations for each approach.

Method 1: Using CTE and ROW_NUMBER() to Identify and Delete

A widely adopted and efficient method involves utilizing Common Table Expressions (CTEs) in conjunction with the ROW_NUMBER() window function. This approach assigns a unique sequential integer to each row within a partition, allowing for easy identification of duplicates.

The PARTITION BY clause is key here. It divides the rows into partitions based on the columns that define a duplicate. The ORDER BY clause then determines the sequence within each partition. By ordering by the same columns, the first instance of a duplicate set gets ROW_NUMBER() = 1, and subsequent duplicates receive higher numbers.

Example Scenario: Keeping One Instance

Consider a table dbo.Table1 with columns col1 through col7. To remove duplicates based on col1, keeping the first occurrence:

WITH DuplicateCTE AS (
    SELECT
        col1,
        col2,
        col3,
        col4,
        col5,
        col6,
        col7,
        ROW_NUMBER() OVER (PARTITION BY col1 ORDER BY col1) AS RowNum
    FROM
        dbo.Table1
)
DELETE FROM DuplicateCTE
WHERE RowNum > 1;

Explanation:

  • The CTE DuplicateCTE selects all columns and assigns a RowNum to each row.
  • PARTITION BY col1 groups rows with the same value in col1.
  • ORDER BY col1 ensures a consistent ordering within each partition.
  • The DELETE statement then removes rows where RowNum is greater than 1, effectively keeping only the first occurrence of each col1 value.

Method 2: CTE with RANK() for Grouping Duplicates

An alternative to ROW_NUMBER() is using RANK(). This function assigns the same rank to rows with identical values in the ORDER BY clause.

Example: Keeping Original Rows

WITH DuplicateCTE AS (
    SELECT
        *,
        ROW_NUMBER() OVER (PARTITION BY col1, col2, col3 ORDER BY col1, col2, col3) AS RN
    FROM MyTable
)
DELETE FROM DuplicateCTE
WHERE RN <> 1;

Example: Without Keeping Original Rows (using RANK)

This approach identifies groups of duplicates and then deletes all records belonging to those groups where more than one instance exists.

WITH RankCTE AS (
    SELECT
        *,
        RANK() OVER (ORDER BY col1, col2, col3) AS R
    FROM MyTable
)
DELETE FROM RankCTE
WHERE R IN (SELECT R FROM RankCTE GROUP BY R HAVING COUNT(*) > 1);

Method 3: Using MAX() with GROUP BY (Without CTEs)

For scenarios where CTEs might be less preferred or for a more direct approach, GROUP BY with the MAX() function can be effective, particularly if you have a unique identifier column (like ID). This method keeps the row with the highest ID for each group of duplicates.

Example:

DELETE FROM MyDuplicateTable
WHERE ID NOT IN (
    SELECT MAX(ID)
    FROM MyDuplicateTable
    GROUP BY DuplicateColumn1, DuplicateColumn2, DuplicateColumn3
);

Method 4: Creating a New Table with Distinct Rows

If your table does not have foreign key constraints referencing it, a straightforward method is to create a new table containing only distinct rows, then replace the original table.

Steps:

  1. Select distinct rows into a new table.
  2. Drop the original table.
  3. Rename the new table to the original table’s name.

Example:

SELECT DISTINCT col1, col2, col3, col4, col5, col6, col7
INTO NewTable
FROM OldTable;

-- Then, in SQL Server Management Studio or via script:
-- DROP TABLE OldTable;
-- EXEC sp_rename 'NewTable', 'OldTable';

Method 5: Keeping the Minimum ID

Similar to Method 3, this approach uses MIN(id) to retain the row with the lowest identifier for each set of duplicate records. This is a common technique and can work across different SQL dialects, including PostgreSQL.

Example:

DELETE FROM YourTable
WHERE id NOT IN (
   SELECT MIN(id)
   FROM YourTable
   GROUP BY col1, col2, col3, col4, col5, col6, col7
);

Method 6: Handling Duplicates with Specific Criteria (e.g., URL)

This advanced example shows how to delete duplicate records based on a url column, while also handling cases where duplicates might appear only once (HAVING COUNT(*) = 1).

Example:

DELETE FROM SearchTable
WHERE id NOT IN (
   SELECT MIN(id)
   FROM SearchTable
   GROUP BY url
   HAVING COUNT(*) = 1

   UNION

   SELECT MIN(id)
   FROM SearchTable
   GROUP BY url
   HAVING COUNT(*) > 1
);

Method 7: MySQL Specific Approaches (DELETE JOIN and Intermediate Table)

For MySQL users, two prominent methods are available:

A) Using DELETE JOIN Statement

This method directly joins the table to itself to identify and delete duplicates.

To delete duplicates, keeping the row with the lowest ID:

DELETE t1
FROM contacts t1
INNER JOIN contacts t2
WHERE t1.id < t2.id AND t1.email = t2.email;

To delete duplicates, keeping the row with the highest ID:

DELETE c1
FROM contacts c1
INNER JOIN contacts c2
WHERE c1.id > c2.id AND c1.email = c2.email;

B) Using an Intermediate Table

This involves creating a temporary table, populating it with distinct rows, and then replacing the original table.

  1. Create a copy: 
    CREATE TABLE source_copy LIKE source;
  2. Insert distinct rows: 
    INSERT INTO source_copy
SELECT * FROM source
GROUP BY col; -- Replace 'col' with the column defining duplicates
  3. Drop original and rename copy: 
    DROP TABLE source;
ALTER TABLE source_copy RENAME TO source;

Method 8: Using ROW_NUMBER() with Table Aliases

This is another variation of the ROW_NUMBER() method, demonstrating its application within a subquery for deletion.

Example:

-- Sample data setup
DECLARE @SampleTable TABLE (
    col1 VARCHAR(10), col2 INT, col3 INT, col4 INT, col5 INT, col6 INT, col7 INT
);
INSERT INTO @SampleTable VALUES
('john', 1, 1, 1, 1, 1, 1),
('john', 1, 1, 1, 1, 1, 1),
('sally', 2, 2, 2, 2, 2, 2),
('sally', 2, 2, 2, 2, 2, 2);

-- Deletion query
DELETE aliasName
FROM (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY col1, col2, col3, col4, col5, col6, col7 ORDER BY col1) AS RowNum
    FROM @SampleTable
) AS aliasName
WHERE RowNum > 1;

SELECT * FROM @SampleTable; -- View remaining records

Note: If all columns are used in PARTITION BY, the ORDER BY clause within ROW_NUMBER() might have less significance.

This example provides a full demonstration, including creating a sample table, inserting data, and then using a CTE with ROW_NUMBER() to remove duplicates based on first_name, last_name, and email.

CREATE TABLE contacts (

    first_name NVARCHAR(100) NOT NULL,

WITH cte AS (

WHERE row_num > 1;

Method 10: Temporary Table and Distinct Rows

A straightforward approach for many scenarios involves selecting distinct rows into a temporary table, clearing the original table, and then repopulating it from the temporary table.

Example:

-- Select distinct rows into a temporary table
SELECT DISTINCT * INTO #tmpUniqueRecords
FROM YourTableName;

-- Truncate the original table
TRUNCATE TABLE YourTableName;

-- Insert unique records back into the original table
INSERT INTO YourTableName
SELECT * FROM #tmpUniqueRecords;

-- Drop the temporary table
DROP TABLE #tmpUniqueRecords;

-- Verify the result
SELECT * FROM YourTableName;

Alternative using CTE:

WITH CTE_Duplicates AS (
    SELECT
        id,
        name,
        ROW_NUMBER() OVER (PARTITION BY id, name ORDER BY id, name) AS RowNum
    FROM YourTable
)
DELETE FROM CTE_Duplicates
WHERE RowNum != 1;

Method 11: Using ROW_NUMBER() for Specific Columns

This example demonstrates using ROW_NUMBER() partitioned by a single column, linkorder.

SELECT
    linkorder,
    ROW_NUMBER() OVER (PARTITION BY linkorder ORDER BY linkorder DESC) AS RowNum
FROM u_links;

Method 12: Microsoft’s Recommended Approach (SET ROWCOUNT)

Microsoft provides a guide (KB 139444) suggesting a method using SET ROWCOUNT. This is particularly useful for small-scale duplicate removal.

Example:

SET ROWCOUNT 1; -- Set to the number of duplicates minus one
DELETE FROM YourTable WHERE myprimarykey = 1; -- Replace with actual PK and value

Note: Adjust SET ROWCOUNT based on the number of duplicate rows you intend to keep (e.g., SET ROWCOUNT 2 to keep one out of three duplicates).

Method 13: CTE for Specific Column Duplicates

This example uses a CTE to identify and delete duplicates based on productName.

WITH ProductDupCTE AS (
    SELECT
        productName,
        ROW_NUMBER() OVER (PARTITION BY productName ORDER BY slno) AS DuplicateMarker
    FROM productDetails

DELETE FROM ProductDupCTE

Method 14: Handling Very Large Tables with Iterations

For extremely large tables, a phased approach can be more manageable and less resource-intensive. This involves creating a new table with appropriate constraints, then copying data in batches.

Steps:

  1. Drop dependencies: Remove any views or constraints referencing the large table.
  2. Rename: Rename the original table (e.g., LargeSourceTable to LargeSourceTable_Temp).
  3. Create new table: Recreate the table with a primary key and WITH (IGNORE_DUP_KEY = ON) if applicable, or simply define the structure.
  4. Recreate views.
  5. Batch insert: Use a loop or cursor to copy data in manageable chunks from the temporary table to the new table.

Method 15: CTE with ORDER BY (SELECT 0)

This method uses ROW_NUMBER() with a less conventional ORDER BY (SELECT 0). While it works for partitioning, relying on ORDER BY (SELECT 0) might not guarantee consistent results across different SQL Server versions or configurations compared to ordering by a specific column.

-- This query will keep only one instance of a duplicate record.
;WITH CTE_Partition AS (
    SELECT
        ROW_NUMBER() OVER (PARTITION BY col1, col2, col3 -- Define your duplicate criteria here
                                       ORDER BY (SELECT 0)) AS RN
    FROM Mytable
)
DELETE FROM CTE_Partition
WHERE RN > 1;

Method 16: Using MIN(Id) with GROUP BY and JOIN

This approach involves finding the minimum Id for duplicate groups and then joining back to the original table to delete records whose Id does not match the minimum Id.

Example:

DELETE FROM prg.Person
WHERE Id IN (
    SELECT dublicateRow.Id
    FROM (
        SELECT MIN(Id) AS MinId, NationalCode
        FROM prg.Person
        GROUP BY NationalCode
        HAVING COUNT(NationalCode) > 1
    ) AS GroupSelect
    JOIN prg.Person dublicateRow ON dublicateRow.NationalCode = GroupSelect.NationalCode
    WHERE dublicateRow.Id <> GroupSelect.MinId
);

Method 17: Bulk Insert into Temp Table for Large Datasets

For very large tables, performing bulk inserts into a temporary table with unique records is often more efficient than direct deletion.

Method 18: Simple JOIN for Duplicate Deletion

A concise method for deleting duplicates, especially when you have a unique identifier.

Example:

DELETE t1
FROM YourTable t1
INNER JOIN YourTable t2
WHERE t1.id > t2.id AND t1.col1 = t2.col1;

Method 19: Multi-Step Process with Temporary Tables (Microsoft KB Reference)

This approach, referenced in Microsoft’s knowledge base, involves several steps using temporary tables to isolate unique records before deleting duplicates.

  1. Identify duplicate rows and insert them into a temporary table (#tableAll).
  2. Select distinct (non-duplicate) rows into another temporary table (#tableUnique).
  3. Delete duplicates from the source table by joining with #tableAll.
  4. Insert unique records back into the source table from #tableUnique.
  5. Drop the temporary tables.

Method 20: Adding a RowID for Large Table Deletion

This method is suitable for large tables and involves adding a temporary identity column to facilitate deletion.

  1. Add a temporary row identifier: 
    ALTER TABLE dbo.DUPPEDTABLE ADD RowID INT NOT NULL IDENTITY(1,1);
  2. Delete based on MIN(RowID) within groups: 
    DELETE b
FROM dbo.DUPPEDTABLE b
WHERE b.RowID NOT IN (
    SELECT MIN(RowID) AS RowID
    FROM dbo.DUPPEDTABLE a WITH (NOLOCK)
    GROUP BY a.ITEM_NUMBER, a.CHARACTERISTIC, a.INTVALUE, a.FLOATVALUE, a.STRINGVALUE -- Adjust columns as needed
);
  3. Verify results: 
    SELECT ITEM_NUMBER, CHARACTERISTIC, INTVALUE, FLOATVALUE, STRINGVALUE, COUNT(*)
FROM dbo.DUPPEDTABLE
GROUP BY ITEM_NUMBER, CHARACTERISTIC, INTVALUE, FLOATVALUE, STRINGVALUE
ORDER BY COUNT(*) DESC;
  4. Drop the temporary column: 
    ALTER TABLE dbo.DUPPEDTABLE DROP COLUMN RowID;

Method 21: Aggregating ID with MAX() and GROUP BY (Simplified)

A simpler, albeit potentially less performant for very large datasets, approach uses MAX(id) within a GROUP BY clause to identify rows to delete. Be aware that this might require multiple executions if a single group has more than two duplicates.

DELETE FROM YourTable
WHERE col1 IN (
    SELECT MAX(id)
    FROM YourTable
    GROUP BY col1 -- Adjust grouping column(s)
    HAVING COUNT(col1) > 1
);

A concise MySQL-like syntax for deleting duplicates.

Method 23: Using the DISTINCT Keyword (for Selection)

While DISTINCT is used for selecting unique rows, it doesn’t directly delete duplicates. However, it’s fundamental when creating new tables with unique data (as seen in Method 4).

SELECT DISTINCT ColumnOne, ColumnTwo, ColumnThree
FROM YourTable;

Method 24: Removing Duplicates in Azure SQL Server

Azure SQL Server supports similar methods, including the use of ROW_NUMBER() with a specific syntax.

DELETE T
FROM (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY key_value ORDER BY (SELECT NULL)) AS DupRank -- 'key_value' defines duplicates
    FROM original_table
) AS T

Method 25: Keeping Minimum Field Length

This method targets duplicates and aims to keep a record based on the minimum length of a specific field (field_kept) within duplicate groups.

DELETE FROM duplicated_table t1
JOIN (
    SELECT t2.duplicated_field, MIN(LEN(t2.field_kept)) AS min_field_kept
    FROM duplicated_table t2
    GROUP BY t2.duplicated_field HAVING COUNT(*) > 1
) t3
ON t1.duplicated_field = t3.duplicated_field
AND LEN(t1.field_kept) = t3.min_field_kept;

Method 26: DENSE_RANK() vs. ROW_NUMBER() for Deletion

This example demonstrates using both DENSE_RANK() and ROW_NUMBER() with NEWID() or a specific column for ordering, showing how to delete duplicates based on these functions.

DECLARE @TB TABLE(NAME VARCHAR(100));
INSERT INTO @TB VALUES ('Red'),('Red'),('Green'),('Blue'),('White'),('White');

-- Delete using DENSE_RANK (randomly keeps one instance)
;WITH CTE_DenseRank AS (
    SELECT NAME, DENSE_RANK() OVER (PARTITION BY NAME ORDER BY NEWID()) AS ID
    FROM @TB
)
DELETE FROM CTE_DenseRank WHERE ID > 1;

-- Delete using ROW_NUMBER (keeps the first based on order)
;WITH CTE_RowNum AS (
    SELECT NAME, ROW_NUMBER() OVER (PARTITION BY NAME ORDER BY NAME) AS ID
    FROM @TB
)
DELETE FROM CTE_RowNum WHERE ID > 1;

Method 27: Deleting Duplicates by Excluding Max ID

This method targets duplicates by selecting IDs that are not the maximum ID within their respective duplicate groups.

DELETE FROM TBL1
WHERE ID IN (
    SELECT ID
    FROM TBL1 a
    WHERE ID != (
        SELECT MAX(ID)
        FROM TBL1
        WHERE DUPVAL = a.DUPVAL -- Grouping column for duplicates
        GROUP BY DUPVAL
        HAVING COUNT(DUPVAL) > 1
    )
);

Method 28: Replacing Table with Distinct Records (No Foreign Keys)

When foreign keys are not a concern, this simple approach recreates the table with distinct records.

-- Example for databases supporting CREATE OR REPLACE TABLE
CREATE OR REPLACE TABLE table_x AS SELECT DISTINCT * FROM table_x;

Method 29: Using a Temporary Table for Clean Insertion

This is a variation of Method 10, emphasizing the temporary table approach for a clean data transfer.

-- Select distinct records into a temporary table
SELECT DISTINCT * INTO #temptable
FROM YourTableName;

-- Truncate the original table
TRUNCATE TABLE YourTableName;

Choosing the right method depends on your specific database structure, the size of your tables, the presence of foreign keys, and your performance requirements. Always back up your data before performing mass deletions.

FAQs on SQL Server Duplicate Row Removal

Q: What is the most efficient way to remove duplicate rows in SQL Server

ANS: Using Common Table Expressions (CTEs) with the ROW_NUMBER() window function is generally considered one of the most efficient and flexible methods for removing duplicate rows in SQL Server. This approach allows precise control over which duplicate record to keep.

Q: Can I remove duplicates without using CTEs

ANS: Yes, you can remove duplicates without CTEs by using methods like creating a new table with distinct records, or employing self-joins with GROUP BY and MAX() or MIN() functions. An example is DELETE FROM MyDuplicateTable WHERE ID NOT IN (SELECT MAX(ID) FROM MyDuplicateTable GROUP BY DuplicateColumn1, DuplicateColumn2, DuplicateColumn3).

Q: How do I handle duplicates in very large tables

ANS: For very large tables, it’s often more performant to insert distinct rows into a temporary table, then truncate the original table, and finally re-insert the unique rows from the temporary table. Alternatively, a phased approach of creating a new table and copying data in batches can be effective.

Q: How do I determine which columns define a duplicate row

ANS: You define which columns determine duplicates by including them in the PARTITION BY clause of the ROW_NUMBER() function or in the GROUP BY clause of your aggregate functions (like MAX() or MIN()).

Q: Is it safe to delete duplicate rows

ANS: Deleting duplicate rows is safe and often beneficial for data integrity, as long as you have a clear strategy for which rows to keep and you have a reliable backup of your data before performing the deletion.
