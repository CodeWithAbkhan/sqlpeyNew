Q How to install the tablefunc extension in PostgreSQL

ANS: To install the tablefunc extension, which provides the crosstab() function, execute the following command in your PostgreSQL database:

CREATE EXTENSION IF NOT EXISTS tablefunc;

This command ensures the extension is available for use within your database. If it’s already installed, IF NOT EXISTS prevents an error. For more details on PostgreSQL extensions, refer to the official PostgreSQL documentation .

Q What is the difference between the 1-parameter and 2-parameter crosstab functions

ANS: The crosstab function in PostgreSQL has two main forms:

  • 1-parameter crosstab(text): This form requires a SQL query that returns exactly three columns: row_name, category, and value. The output columns are inferred from the order of these values. If there are missing attribute values, this form can lead to incorrect results as it fills values left-to-right and discards excess.
  • 2-parameter crosstab(text, text): This form is more flexible. The first parameter is the SQL query (similar to the 1-parameter form), and the second parameter is a SQL query that returns the distinct category values, defining the output columns. This allows for explicit control over column mapping and handles missing attributes more predictably, assigning each input value to its designated column.

For a deeper dive into these differences and usage, consult the PostgreSQL tablefunc documentation .

Q How does crosstab handle duplicate input rows

ANS: The behavior of crosstab with duplicate input rows depends on the function’s parameterization:

  • 1-parameter crosstab: Duplicate rows for the same (row_name, category) combination are processed by filling available value columns from left to right. Excess values are discarded, and earlier input rows take precedence.
  • 2-parameter crosstab: Each input value is assigned to its specific column, overwriting any previous assignment for that column. Later input rows win in cases of duplicates.

It’s crucial to adjust your ORDER BY clauses in the input query to manage duplicates according to your specific requirements and document this behavior.

Q Can crosstab output columns of different data types

ANS: Yes, the crosstab(text, text) function supports output columns with different data types. This is achievable as long as the text representation of the value column can be validly cast to the target data type. This allows you to pivot attributes that might have varying data formats, such as text, dates, or numeric values. The PostgreSQL manual provides examples illustrating this capability.

When working with relational databases, transforming data from a row-based format to a column-based format, a process often referred to as “pivoting,” is a common requirement. PostgreSQL offers several robust methods to achieve this, with the crosstab() function from the tablefunc extension being a prominent tool. This guide explores various approaches to pivot your data in PostgreSQL, ensuring clarity and efficiency.

How to Pivot Data in PostgreSQL

Pivoting transforms unique values from one column into multiple columns in the output, summarizing data across categories. This is particularly useful for generating reports and analyzing trends.

Solution 1: Using crosstab(text) (Simple Form)

The simplest form of crosstab requires a query that returns section, status, and ct (count), ordered appropriately.

Improved Test Case:

CREATE TABLE tbl (
   section   text
 , status    text
 , ct        integer  -- 'count' is a reserved word in standard SQL
);

INSERT INTO tbl VALUES
  ('A', 'Active', 1), ('A', 'Inactive', 2),
  ('B', 'Active', 4), ('B', 'Inactive', 5),
  ('C', 'Inactive', 7);  -- ('C', 'Active') is missing

Pivoting Query (Simple Form):

SELECT *
FROM   crosstab(
   'SELECT section, status, ct
    FROM   tbl
    ORDER  BY 1,2'  -- Requires "ORDER BY 1,2"
   ) AS ct ("Section" text, "Active" int, "Inactive" int);

Solution 2: Using crosstab(text, text) (Safe Form)

This more robust form uses a second parameter to explicitly define the categories, ensuring correct data placement.

Pivoting Query (Safe Form):

SELECT *
FROM   crosstab(
   'SELECT section, status, ct
    FROM   tbl
    ORDER  BY 1,2'  -- Can also be "ORDER BY 1"
  , $$VALUES ('Active'::text), ('Inactive')$$ -- Defines output columns
   ) AS ct ("Section" text, "Active" int, "Inactive" int);

Expected Output:

| Section | Active | Inactive | | :

select mt.section, mt1.count as Active, mt2.count as Inactive
from mytable mt
left join (select section, count from mytable where status='Active')mt1
on mt.section = mt1.section
left join (select section, count from mytable where status='Inactive')mt2
on mt.section = mt2.section
group by mt.section,
         mt1.count,
         mt2.count
order by mt.section asc;
select m.typeID, m1.highBid, m2.lowAsk, m1.highBid - m2.lowAsk as diff, 100*(m1.highBid - m2.lowAsk)/m2.lowAsk as diffPercent
from mktTrades m
   left join (select typeID,MAX(price) as highBid from mktTrades where bid=1 group by typeID)m1
   on m.typeID = m1.typeID
   left join (select typeID,MIN(price) as lowAsk  from mktTrades where bid=0 group by typeID)m2
   on m1.typeID = m2.typeID
group by m.typeID, 
         m1.highBid, 
         m2.lowAsk
order by diffPercent desc;
