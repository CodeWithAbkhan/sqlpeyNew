“PostgreSQL Identifier Case Sensitivity Explained: Querying and Best Practices”

When working with PostgreSQL, a common point of confusion arises around the case sensitivity of identifiers like table names, column names, and schema names. Unlike some other database systems, PostgreSQL’s behavior with identifiers depends heavily on whether they are enclosed in double quotes.

How PostgreSQL Handles Identifiers

In PostgreSQL, identifiers (such as column names, table names, and schema names) that are not enclosed in double quotes are automatically folded to lowercase. This means that if you create a column named firstName, PostgreSQL will store and treat it as firstname.

However, if an identifier is enclosed in double quotes, it preserves its exact casing and any syntax violations. These quoted identifiers must then be referenced using double quotes throughout their lifetime.

Let’s break down the implications:

  • Unquoted Identifiers:

    • first_Name becomes first_name (uppercase ‘N’ folded to lowercase ’n’).
    • 1st_Name results in a syntax error because identifiers cannot start with a digit without quoting.
    • AND (a reserved keyword) results in a syntax error when unquoted, as it’s treated as a command.

  • Quoted Identifiers:

    • "first_Name" preserves the uppercase ‘N’. To query this column, you must use "first_Name".
    • "1st_Name" preserves the leading digit. This is a valid quoted identifier.
    • "AND" preserves the reserved keyword. This is a valid quoted identifier.

String literals (values) are always enclosed in single quotes, e.g., 'xyz'.

Querying with Case Sensitivity

When a column name has mixed or uppercase letters, it must be double-quoted when referenced in a query.

Consider this example:

-- Creating a table with a double-quoted column name
CREATE TABLE users (
    "UserID" INT,
    "UserName" VARCHAR(100)
);

-- Inserting data
INSERT INTO users ("UserID", "UserName") VALUES (1, 'Alice');

Now, let’s see how querying works:

  • SELECT "UserID" FROM users; – This will work correctly.
  • SELECT UserID FROM users; – This will result in an error: ERROR: column "userid" does not exist. PostgreSQL folded UserID to userid, but the table was created with the quoted "UserID".
  • SELECT "UserName" FROM users; – This will work correctly.
  • SELECT UserName FROM users; – This will also result in an error: ERROR: column "username" does not exist.

Best Practices for Identifier Naming

While PostgreSQL supports quoted identifiers, it is generally recommended for portability and simplicity to exclusively use legal, lowercase names for your identifiers. This avoids the need for double-quoting and reduces the risk of errors.

  • Convention: Stick to snake_case for all your schema, table, and column names.

Alternative Approaches and Solutions

If you have an existing database with case-sensitive identifiers and need to manage them, here are some strategies:

  1. Renaming Identifiers: You can use ALTER TABLE statements to rename schemas, tables, and columns to a consistent lowercase format.

    • Rename Schema:

      ALTER SCHEMA "OldSchemaName" RENAME TO oldschemaname;

    • Rename Table:

      ALTER TABLE oldschemaname."OldTableName" RENAME TO oldtablename;

    • Rename Column:

      ALTER TABLE oldschemaname.oldtablename RENAME COLUMN "OldColumnName" TO oldcolumnname;

    You can query system catalogs like pg_stat_all_tables and pg_attribute to identify existing names.

    SELECT
    psat.schemaname,
    psat.relname,
    pa.attname,
    psat.relid
FROM
    pg_catalog.pg_stat_all_tables psat,
    pg_catalog.pg_attribute pa
WHERE
    psat.relid = pa.attrelid;

  2. Using Quoted Identifiers Consistently: If you must use mixed or uppercase identifiers, ensure you always double-quote them in every query, DDL statement, and application code that references them. This includes situations where you might expect case insensitivity, as PostgreSQL’s behavior is based on quoting.

    For example, if you have CREATE TABLE "MyTable" ("MyCol" INT);, you must always use SELECT "MyCol" FROM "MyTable";.

  3. Application-Level Naming: Some frameworks, like Java Persistence API (JPA), might have their own conventions for mapping database identifiers. In such cases, it’s crucial to configure JPA correctly to match your database’s naming strategy or to adjust your database schema to align with JPA’s preferred lowercase naming.

Example of Creating Tables with Quoted Identifiers

Here’s how you might create tables with capitalized identifiers, demonstrating the need for quoting:

-- SQL Example
CREATE TABLE "Products" (
    "ProductID" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "ProductName" VARCHAR(255)
);

And in a C# context using a string for the SQL command:

// C# Example
string createTableCommand = @"
CREATE TABLE ""UpperCaseTable"" (
    ""IdColumn"" INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ""NameColumn"" VARCHAR(255)
);";

Notice the double-double quotes ("") in the C# string literal to represent a single double quote within the SQL string itself.

Key Takeaways:

  • Unquoted PostgreSQL identifiers are folded to lowercase.
  • Double-quoted identifiers preserve their case and syntax.
  • Always double-quote identifiers if they contain uppercase letters or reserved words.
  • For simplicity and consistency, adopting a lowercase naming convention (snake_case) is highly recommended.

FAQs on PostgreSQL Identifier Case Sensitivity

Q PostgreSQL Identifiers Folded to Lowercase When Unquoted

ANS: Yes, in PostgreSQL, any identifier (like table or column names) that is not enclosed in double quotes is automatically converted to lowercase. For instance, MyColumn becomes mycolumn.

Q Are PostgreSQL Column Names Case Sensitive

ANS: PostgreSQL column names are case-sensitive only when they are created using double quotes. If created without quotes, they are folded to lowercase and are therefore not case-sensitive in practice.

Q How Do I Query a Case-Sensitive Column in PostgreSQL

ANS: To query a column that was created with double quotes (e.g., "MyColumn"), you must also use double quotes around the column name in your SQL query: SELECT "MyColumn" FROM your_table;. Using SELECT MyColumn FROM your_table; will likely fail.

Q What's the Recommended Way to Name PostgreSQL Identifiers

ANS: The recommended approach for naming PostgreSQL identifiers is to use legal, lowercase names exclusively (e.g., snake_case). This avoids the need for double-quoting and prevents potential case-sensitivity issues.

Q Can Identifiers Start with Numbers in PostgreSQL

ANS: Identifiers in PostgreSQL cannot start with a number unless they are enclosed in double quotes. For example, 1st_Column will cause a syntax error, but "1st_Column" is valid.

Q How Do I Change an Existing Uppercase Column Name to Lowercase in PostgreSQL

ANS: You can rename an existing column using the ALTER TABLE statement: ALTER TABLE your_table_name RENAME COLUMN "OldUpperCaseColumn" TO newlowercasecolumn;.

Q Does PostgreSQL Follow the SQL Standard for Identifier Casing

ANS: PostgreSQL deviates from the SQL standard. While the standard often implies unquoted identifiers are folded to uppercase, PostgreSQL folds them to lowercase. Quoted identifiers in PostgreSQL preserve their case, making them case-sensitive.
