“SQL Data Transposition: UNPIVOT, PIVOT, and Dynamic SQL Solutions”

Effectively restructuring data from a row-oriented format to a column-oriented one is a common requirement in database operations. This process, often referred to as data transposition, can be achieved through various SQL techniques. Several methods exist, ranging from static UNPIVOT and PIVOT operations to more flexible dynamic SQL approaches, each offering distinct advantages depending on your data’s structure and whether you know the column and row labels beforehand.

Setting Up Sample Data

To illustrate the different solutions, let’s start with a sample table:

CREATE TABLE yourTable (
    [color] VARCHAR(5),
    [Paul] INT,
    [John] INT,
    [Tim] INT,
    [Eric] INT
);

INSERT INTO yourTable ([color], [Paul], [John], [Tim], [Eric])
VALUES
    ('Red', 1, 5, 1, 3),
    ('Green', 8, 4, 3, 5),
    ('Blue', 2, 2, 9, 1);

This table has a color column and several columns representing individuals’ names with associated integer values. The goal is to transform this into a format where names are rows, colors are columns, and the values are aggregated.

Solution 1: UNION ALL, Aggregate, and CASE for UNPIVOT/PIVOT

When UNPIVOT and PIVOT functions are not available, or for a more fundamental approach, you can simulate these operations using UNION ALL to unpivot the data, followed by an aggregate function with a CASE statement to achieve the pivot.

SELECT
    name,
    SUM(CASE WHEN color = 'Red' THEN value ELSE 0 END) AS Red,
    SUM(CASE WHEN color = 'Green' THEN value ELSE 0 END) AS Green,
    SUM(CASE WHEN color = 'Blue' THEN value ELSE 0 END) AS Blue
FROM (
    SELECT color, Paul AS value, 'Paul' AS name FROM yourTable
    UNION ALL
    SELECT color, John AS value, 'John' AS name FROM yourTable
    UNION ALL
    SELECT color, Tim AS value, 'Tim' AS name FROM yourTable
    UNION ALL
    SELECT color, Eric AS value, 'Eric' AS name FROM yourTable
) AS src
GROUP BY name;

In this method, the UNION ALL clause effectively transforms the Paul, John, Tim, and Eric columns into separate rows. Subsequently, the SUM() aggregate function combined with CASE statements reconstructs the desired pivoted columns for each color.

Solution 2: Static UNPIVOT and PIVOT Functions

For SQL Server versions that support UNPIVOT and PIVOT, a more direct approach can be used if all column and row labels are known in advance.

SELECT
    name,
    [Red],
    [Green],
    [Blue]
FROM (
    SELECT
        color,
        name,
        value
    FROM yourTable
    UNPIVOT (
        value FOR name IN ([Paul], [John], [Tim], [Eric])
    ) AS unpiv
) AS src
PIVOT (
    SUM(value)
    FOR color IN ([Red], [Green], [Blue])
) AS piv;

The inner UNPIVOT operation performs the same row transformation as the UNION ALL method. The outer PIVOT then arranges these rows into the final columnar structure.

Solution 3: Dynamic PIVOT for Unknown Columns

When the number of columns to be pivoted or the values within them are not known beforehand, dynamic SQL is necessary. This approach constructs the query string at runtime based on the table’s schema.

DECLARE @colsUnpivot AS NVARCHAR(MAX),
        @query  AS NVARCHAR(MAX),
        @colsPivot as  NVARCHAR(MAX);

-- Get list of columns to unpivot (all columns except 'color')
SELECT @colsUnpivot = STUFF((
    SELECT ',' + QUOTENAME(C.name)
    FROM sys.columns AS C
    WHERE C.object_id = OBJECT_ID('yourTable') AND C.name <> 'color'
    FOR XML PATH('')), 1, 1, '');

-- Get list of distinct colors for pivoting
SELECT @colsPivot = STUFF((
    SELECT ',' + QUOTENAME(color)
    FROM yourTable
    FOR XML PATH(''), TYPE
).value('.', 'NVARCHAR(MAX)'), 1, 1, '');

SET @query =
    'SELECT name, ' + @colsPivot + '
     FROM (
         SELECT color, name, value
         FROM yourTable
         UNPIVOT (
             value FOR name IN (' + @colsUnpivot + ')
         ) unpiv
     ) src
     PIVOT (
         SUM(value)
         FOR color IN (' + @colsPivot + ')
     ) piv';

EXEC(@query);

This dynamic solution queries sys.columns to build the list of columns for UNPIVOT and selects distinct colors for the PIVOT clause, making it adaptable to changing data.

Solution 4: Using a Stored Procedure for Dynamic Transposition

A stored procedure can encapsulate the dynamic SQL logic, making it reusable and easier to manage. The following procedure, SQLTranspose, dynamically handles the transposition based on provided table and field names.

ALTER PROCEDURE [dbo].[SQLTranspose]
    @TableName NVARCHAR(MAX) = '',
    @FieldNameTranspose NVARCHAR(MAX) = ''
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @colsUnpivot AS NVARCHAR(MAX),
            @query  AS NVARCHAR(MAX),
            @queryPivot  AS NVARCHAR(MAX),
            @colsPivot as  NVARCHAR(MAX),
            @columnToPivot as NVARCHAR(MAX),
            @tableToPivot as NVARCHAR(MAX),
            @colsResult as xml;

    SELECT @tableToPivot = @TableName;
    SELECT @columnToPivot = @FieldNameTranspose;

    -- Build the UNPIVOT column list
    SELECT @colsUnpivot = STUFF((
        SELECT ',' + QUOTENAME(C.name)
        FROM sys.columns AS C
        WHERE C.object_id = OBJECT_ID(@tableToPivot) AND C.name <> @columnToPivot
        FOR XML PATH('')), 1, 1, '');

    -- Build the PIVOT column list
    SET @queryPivot = 'SELECT @colsResult = (SELECT  '',''
                        + QUOTENAME('+@columnToPivot+')
                      FROM '+@tableToPivot+' t
                      WHERE '+@columnToPivot+' <> ''''
              FOR XML PATH(''''), TYPE)';

    EXEC sp_executesql @queryPivot, N'@colsResult xml out', @colsResult OUT;

    SELECT @colsPivot = STUFF(@colsResult.value('.', 'NVARCHAR(MAX)'), 1, 1, '');

    -- Construct the final query
    SET @query =
        'SELECT name, rowid, ' + @colsPivot + '
         FROM (
             SELECT ' + @columnToPivot + ' , name, value, ROW_NUMBER() OVER (PARTITION BY ' + @columnToPivot + ' ORDER BY ' + @columnToPivot + ') AS rowid
             FROM ' + @tableToPivot + '
             UNPIVOT (
                 value FOR name IN (' + @colsUnpivot + ')
             ) unpiv
         ) src
         PIVOT (
             SUM(value)
             FOR ' + @columnToPivot + ' IN (' + @colsPivot + ')
         ) piv
         ORDER BY rowid';

    EXEC(@query);
END;

-- Example usage:
-- EXEC SQLTranspose 'yourTable', 'color';

This stored procedure provides a robust solution for dynamic transposition.

Solution 5: Adapting Dynamic SQL for Specific Data Types

When dealing with tables that contain multiple data types, you might need to refine the dynamic SQL to only transpose numeric columns. This can be achieved by filtering based on system_type_id.

-- Modify the @colsUnpivot population in Solution 3 or 4 like this:
SELECT @colsUnpivot = STUFF((
    SELECT ','+QUOTENAME(C.name)
    FROM sys.columns AS C
    WHERE C.object_id = OBJECT_ID(@tableToPivot) AND
          C.name <> @columnToPivot AND
          C.system_type_id = 56 -- 56 is the system_type_id for INT
    FOR XML PATH('')), 1, 1, '');

-- To find other system_type_id's, run:
-- SELECT name, system_type_id FROM sys.types ORDER BY name;

This ensures that only integer columns (or columns with other specified types) are included in the unpivot operation.

Solution 6: Converting Columns to Rows Using Dynamic SQL

An alternative method converts all data from specified fields (columns) into records (rows) using dynamic SQL and a temporary table.

DECLARE @TableName NVARCHAR(128);
DECLARE @ExecStr NVARCHAR(MAX);
DECLARE @Where NVARCHAR(MAX);

SET @TableName = 'yourTable';
SET @Where = ''; -- Enter filtering if exists

DROP TABLE IF EXISTS #tmp_Col2Row;

CREATE TABLE #tmp_Col2Row (
    Field_Name NVARCHAR(128) NOT NULL,
    Field_Value NVARCHAR(MAX) NULL
);

SET @ExecStr = N'INSERT INTO #tmp_Col2Row (Field_Name, Field_Value) ';

SELECT @ExecStr += (
    SELECT N'SELECT ''' + C.name + ''' ,Convert(nvarchar(max),' + QUOTENAME(C.name) + ') FROM ' + QUOTENAME(@TableName) + @Where + CHAR(10) + ' UNION ALL '
    FROM sys.columns AS C
    WHERE (C.object_id = OBJECT_ID(@TableName))
    FOR XML PATH('')
);

SET @ExecStr = LEFT(@ExecStr, LEN(@ExecStr) - LEN(' UNION ALL '));

EXEC(@ExecStr);

SELECT * FROM #tmp_Col2Row;

This script iterates through columns, converts their values to NVARCHAR(MAX), and inserts them into a temporary table with Field_Name and Field_Value columns.

Solution 7: CTE with UNPIVOT and PIVOT

Using a Common Table Expression (CTE) can help structure the UNPIVOT and PIVOT operations, enhancing readability.

WITH cte AS (
    SELECT 'Paul' AS Name, color, Paul AS Value FROM yourTable
    UNION ALL
    SELECT 'John' AS Name, color, John AS Value FROM yourTable
    UNION ALL
    SELECT 'Tim' AS Name, color, Tim AS Value FROM yourTable
    UNION ALL
    SELECT 'Eric' AS Name, color, Eric AS Value FROM yourTable
)
SELECT Name, [Red], [Green], [Blue]
FROM (
    SELECT * FROM cte
) AS src
PIVOT (
    MAX(Value)
    FOR color IN ([Red], [Green], [Blue])
) AS Dtpivot;

This approach first unions the data into a CTE and then applies the PIVOT operation on the CTE.

Solution 8: Stored Procedure for Transposing Split Text

This stored procedure, TransposeSplit, is designed to transpose data that originates from a split text string, using a delimiter. It leverages dynamic SQL and a temporary table.

CREATE PROCEDURE TransposeSplit
    @InputToSplit VARCHAR(8000),
    @Delimiter VARCHAR(8000) = ','
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @colsUnpivot AS NVARCHAR(MAX),
            @query AS NVARCHAR(MAX),
            @queryPivot AS NVARCHAR(MAX),
            @colsPivot AS NVARCHAR(MAX),
            @columnToPivot AS NVARCHAR(MAX),
            @tableToPivot AS NVARCHAR(MAX),
            @colsResult AS XML;

    SET @tableToPivot = '#tempSplitedTable';
    SET @columnToPivot = 'col_value'; -- Assuming the split values go into a column named 'col_value'

    -- Create a temporary table to hold split values
    CREATE TABLE #tempSplitedTable (
        col_number INT,
        col_value VARCHAR(8000)
    );

    -- Insert split values into the temporary table
    -- Note: Requires a function like [DB].[ESCHEME].[fnSplit] to exist
    INSERT INTO #tempSplitedTable (col_number, col_value)
    SELECT ROW_NUMBER() OVER (ORDER BY (SELECT 100)) AS RowNumber, item
    FROM [DB].[ESCHEME].[fnSplit](@InputToSplit, @Delimiter); -- Replace with your actual split function

    -- Build the UNPIVOT column list (excluding the split value column)
    SELECT @colsUnpivot = STUFF((
        SELECT ',' + QUOTENAME(C.NAME)
        FROM tempdb.sys.columns AS C
        WHERE C.object_id = OBJECT_ID('tempdb..' + @tableToPivot)
            AND C.NAME <> @columnToPivot
        FOR XML PATH('')), 1, 1, '');

    -- Build the PIVOT column list
    SET @queryPivot = 'SELECT @colsResult = (SELECT  '',''
                        + QUOTENAME(' + @columnToPivot + ')
                      FROM ' + @tableToPivot + ' t
                      WHERE ' + @columnToPivot + ' <> ''''
              FOR XML PATH(''''), TYPE)';

    EXEC sp_executesql @queryPivot, N'@colsResult xml out', @colsResult OUT;
    SELECT @colsPivot = STUFF(@colsResult.value('.', 'NVARCHAR(MAX)'), 1, 1, '');

    -- Construct the final query for transposition
    SET @query = 'SELECT name, rowid, ' + @colsPivot + '
        FROM (
            SELECT ' + @columnToPivot + ' , name, value, ROW_NUMBER() OVER (partition by ' + @columnToPivot + ' order by ' + @columnToPivot + ') as rowid
            FROM ' + @tableToPivot + '
            UNPIVOT (
            value FOR name IN (' + @colsUnpivot + ')
            ) unpiv
        ) src
        PIVOT (
            MAX(value)
            FOR ' + @columnToPivot + ' IN (' + @colsPivot + ')
        ) piv
        ORDER BY rowid';

    EXEC(@query);

    DROP TABLE #tempSplitedTable;
END;
GO

-- Example usage:
-- DECLARE @Input VARCHAR(8000) = 'hello|beautiful|world';
-- EXEC TransposeSplit @Input, '|';

This procedure requires a custom fnSplit function.

Solution 9: Addressing Permissions for Dynamic SQL

A common challenge with dynamic SQL solutions that create and drop temporary tables is managing permissions. If the SQL account used by an application lacks DROP TABLE privileges, alternative strategies are needed. One solution involves creating a dedicated schema for temporary objects and granting the user account schema-specific permissions.

-- Execute from a sysadmin account:
-- CREATE SCHEMA ro AUTHORIZATION dbo;

-- Then, refer to temporary tables with the schema:
-- DROP TABLE ro.tmpoutput;

This allows the user to create and manage tables within a specific schema without needing broad DROP TABLE rights.

        ';

    -- Gets the headers (columns except the first one)
    DECLARE @UNP VARCHAR(1000) = STUFF((
        SELECT ',' + QUOTENAME(name) FROM tempdb.sys.columns
        WHERE object_id = OBJECT_ID('tempdb.dbo.' + @TBL)

FAQs on SQL Data Transposition

Q: What is the primary purpose of transposing data in SQL

ANS: Transposing data in SQL involves restructuring it from a row-based format to a column-based format, often to make it easier for analysis, reporting, or specific application requirements.

Q: Can UNPIVOT and PIVOT handle unknown column names

ANS: Static UNPIVOT and PIVOT functions require you to know the column names beforehand. For unknown or dynamic column names, dynamic SQL is necessary.

Q: What is the benefit of using dynamic SQL for transposition

ANS: Dynamic SQL allows your transposition queries to adapt to changes in your data structure, such as new columns being added, without requiring manual query modifications.

Q: Are there performance considerations when transposing data

ANS: Yes, especially with methods like cursors which can be less performant. Dynamic SQL, while flexible, can also have performance implications depending on how it’s written and executed. UNPIVOT and PIVOT are generally optimized for this task.

Q: How can I transpose data when UNPIVOT and PIVOT are not available

ANS: You can simulate UNPIVOT and PIVOT using UNION ALL for the unpivoting step and then SUM with CASE statements for the pivoting step.
