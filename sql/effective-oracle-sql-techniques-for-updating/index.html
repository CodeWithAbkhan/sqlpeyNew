“Effective Oracle SQL Techniques for Updating One Table Based on Another”

Here are proven approaches to execute an UPDATE statement drawing data from another table.

Method 1: Correlated Update with EXISTS Clause

A direct approach involves using a correlated subquery within the SET clause, combined with an EXISTS check to ensure the update only runs where a match is present in the source table (table2). This is often termed a correlated update.

UPDATE table1 t1
   SET (name, description) = (
       SELECT t2.name, t2.description
       FROM table2 t2
       WHERE t1.id = t2.id
   )
WHERE EXISTS (
    SELECT 1
    FROM table2 t2
    WHERE t1.id = t2.id
);

Alternative Syntax for Correlated Update

If the join result is guaranteed to produce a key-preserved view (meaning the join condition on the primary key yields only one row per match), you can sometimes update a derived view directly.

UPDATE (
    SELECT 
        t1.id AS table1_id, 
        t1.name AS name1,
        t1.description AS desc1,
        t2.name AS name2,
        t2.description AS desc2
    FROM table1 t1
    JOIN table2 t2 ON t1.id = t2.id
) derived_view
   SET name1 = name2,
       desc1 = desc2;

Method 2: Utilizing the MERGE Statement

The SQL standard MERGE statement is highly versatile for both inserting new rows and updating existing ones based on a source. When only updating matched rows, this syntax is very clean.

MERGE INTO table1 t1
USING
(
    -- Use subqueries or CTEs for complex criteria before merging
    SELECT id, name, description FROM table2
) t2
ON (t1.id = t2.id)
WHEN MATCHED THEN
    UPDATE SET
        t1.name = t2.name,
        t1.description = t2.description;

Method 3: Subqueries in SET with IN Clause

This method updates columns individually by using separate scalar subqueries in the SET block, constrained by an IN clause that identifies all relevant IDs from the source table.

UPDATE Table1 T1
SET
    T1.name = (SELECT T2.name FROM Table2 T2 WHERE T2.id = T1.id),
    T1.description = (SELECT T2.description FROM Table2 T2 WHERE T2.id = T1.id)
WHERE T1.id IN (SELECT T2.id FROM Table2 T2); -- Simplified check, though the original used correlation

Note on Scalar Subqueries: Be cautious; if any subquery in the SET clause returns more than one row for a given T1.id, an ORA-01427: single-row subquery returns more than one row error will occur.

Method 4: PL/SQL Cursor Loop for Row-by-Row Update

When complex, row-specific logic is required, or when other SQL constructs fail due to database version constraints or specific data issues, a PL/SQL block utilizing a FOR loop provides an explicit, iterative solution. While often slower than set-based operations, it can be robust for certain scenarios.

If you need to update table2 based on table1 (reversing the flow from the initial description, but illustrating the mechanism):

BEGIN
    FOR rec IN (SELECT id, name, description FROM table1)
    LOOP
        UPDATE table2 t2
        SET 
            t2.name = rec.name, 
            t2.description = rec.description
        WHERE t2.id = rec.id;
    END LOOP;
END;
/

Method 5: Multi-Column Update with Tuples and IN

For databases supporting tuple comparison (Oracle supports this in certain contexts), you can compare pairs of columns in the WHERE clause. This is useful when the join key comprises multiple columns.

If updating fp_active from fp_detail based on matching (client, code) pairs:

UPDATE fp_active fa
SET 
    STATE = 'E', 
    LAST_DATE_MAJ = SYSDATE 
WHERE (fa.client, fa.code) IN (
    SELECT fd.client, fd.code 
    FROM fp_detail fd
    WHERE fd.valid = 1
);

Method 6: Direct Join Syntax (Oracle 23c Ai+)

Recent versions of Oracle (23ai and later) introduce syntax that resembles the UPDATE FROM common in SQL Server or PostgreSQL, allowing direct joins within the UPDATE statement for both updates and deletes.

Example setup:

CREATE TABLE t1 (c1 INT, c2 INT);
CREATE TABLE t2 (c1 INT, c2 INT);

INSERT INTO t1 VALUES (1, 10), (2, 20);
INSERT INTO t2 VALUES (1, 42); -- Target row for update

Update using the direct join syntax:

UPDATE t1
SET t1.c2 = t2.c2
FROM t2
WHERE t1.c1 = t2.c1;

-- Result: t1 now has (1, 42) and (2, 20)

Method 7: Conditional Update Using MINUS for Delta Changes

If the requirement is strict: only update rows in t1 where the values actually differ from t2, you can use the MINUS operator within a derived table selection to find the specific rows that require modification before applying the update to the joined view. This leverages Oracle’s automatic aliasing of duplicate columns in the joined view (e.g., col1_1).

UPDATE (
    SELECT 
        t1.id, 
        t1.col1 AS col1_orig, 
        t1.col2 AS col2_orig, 
        t2.col1 AS col1_new, 
        t2.col2 AS col2_new 
    FROM t1 
    JOIN t2 ON t2.id = t1.id
    WHERE t1.id IN (
        -- Identify IDs where data differs
        SELECT id FROM (
            SELECT id, col1, col2 FROM t2
            MINUS
            SELECT id, col1, col2 FROM t1
        )
    )
)
SET 
    col1_orig = col1_new, 
    col2_orig = col2_new;

FAQs on Effective Oracle SQL Techniques for Updating

Q: What is the main benefit of using the MERGE statement for table synchronization

ANS: The MERGE statement offers a single, atomic SQL command to handle both updates and inserts (UPSERT functionality), often leading to clearer, more efficient execution plans than separate IF/THEN logic or procedural loops.

Q: Why might a correlated subquery update fail with ORA-01427

ANS: This error occurs because the subquery in the SET clause is expected to return exactly one value for the row being updated, but it returned zero or multiple rows during execution.

Q: Is the PL/SQL loop solution (Method 4) generally the fastest approach

ANS: No, row-by-row processing via a PL/SQL loop is typically the slowest method for large datasets compared to native set-based operations like MERGE or correlated UPDATE statements, due to context switching between SQL and PL/SQL engines.

Q: Can I use UPDATE FROM syntax in older Oracle versions

ANS: The direct UPDATE t1 SET ... FROM t2 WHERE ... syntax is natively supported starting in Oracle Database 23ai. Older versions require techniques like correlated updates or the MERGE statement.
