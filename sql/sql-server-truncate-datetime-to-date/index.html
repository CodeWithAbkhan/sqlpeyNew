“SQL Server: Efficiently Truncate DATETIME to Date”

When working with SQL Server, you frequently encounter the need to extract only the date component from a DATETIME or DATETIME2 data type, effectively removing the time component. This is crucial for tasks like grouping data by day, comparing dates without time interference, or simplifying date-based calculations. Fortunately, SQL Server provides several effective methods to achieve this.

The Current Recommended Approach (SQL Server 2008+)

For SQL Server 2008 and later versions, the most straightforward and readable method is to CAST the DATETIME value directly to the DATE data type.

SELECT CAST(GETDATE() AS DATE) AS TruncatedDate;

This approach is clean, expresses the intent clearly, and leverages the dedicated DATE data type, which is optimized for date-only storage.

Older but Still Valid Methods

Before the introduction of the DATE data type, developers relied on other techniques. These are still useful to know, especially when working with older SQL Server versions or specific scenarios.

1. Using DATEDIFF and DATEADD (The “Correct Way - Old”)

This method is robust, ANSI-standard compliant, and adaptable for truncating to other granularities like months, hours, or minutes. It works by calculating the number of full days since a reference point (day 0, which is ‘1900-01-01’) and then adding that number of days back to the same reference point.

SELECT DATEADD(dd, DATEDIFF(dd, 0, GETDATE()), 0) AS TruncatedDateOld;

This technique is reliable as it doesn’t depend on implementation details and handles different locales correctly.

2. Using DATEDIFF and DATEADD for Other Intervals

You can adapt the DATEDIFF and DATEADD pattern to truncate to minutes, hours, or any other date part. For example, to truncate to the minute:

SELECT DATEADD(minute, DATEDIFF(minute, 0, GETDATE()), 0) AS TruncatedToMinute;

Remember that the ‘0’ represents the base date ‘1900-01-01’. For truncating to smaller units like seconds or milliseconds, using a base date closer to your target date can prevent potential overflows, though this is less common for simple date truncation.

3. The “Fast Way” (Implementation Dependent)

This method leverages the internal binary representation of DATETIME values in SQL Server. By casting to FLOAT, flooring the value, and then casting back to DATETIME, the time portion is effectively removed.

SELECT CAST(FLOOR(CAST(GETDATE() AS FLOAT)) AS DATETIME) AS FastTruncatedDate;

While often very fast due to its bitwise nature, this approach relies on an undocumented implementation detail. Microsoft could theoretically change this in future updates, making it less portable and predictable than the CAST( ... AS DATE) or DATEDIFF/DATEADD methods. It’s generally recommended to favor the DATE data type for clarity and stability unless extreme performance tuning is required.

Methods to Avoid

Some methods, while they might produce the correct output, are significantly less efficient and can cause issues.

1. The “Wrong Way” (String Conversion)

Converting the DATETIME to a string and then back to DATETIME is an inefficient approach. It can also be prone to locale-specific formatting errors.

-- Example of a less efficient method to avoid
SELECT CAST(CONVERT(CHAR(11), GETDATE(), 113) AS DATETIME) AS AvoidThisDate;

This method is generally orders of magnitude slower than the other techniques and should be avoided.

2. String Manipulation

While possible to extract date parts using string functions like SUBSTRING and DATENAME, these methods are typically less efficient and more verbose than dedicated date functions.

DECLARE @SomeDate DATETIME = '2009-05-28 16:30:22';
SELECT CAST(SUBSTRING(CONVERT(VARCHAR(12), @SomeDate, 111), 0, 12) AS DATETIME) AS SubstringDate;

Advanced Techniques and Considerations

SQL Server 2022’s DATETRUNC

SQL Server 2022 introduced the DATETRUNC function, which is a powerful and flexible way to truncate dates to various specified parts, similar to other database systems.

DECLARE @d DATETIME2 = '2021-12-08 11:30:15.1234567';
SELECT DATETRUNC(day, @d) AS TruncatedToDay;

DATETRUNC supports truncating to year, quarter, month, week, day, hour, minute, second, millisecond, and microsecond.

Custom Functions

For older versions of SQL Server that lack DATETRUNC, you can create a user-defined function to encapsulate the truncation logic. This promotes reusability and consistency.

Here’s an example of a function that mimics DATETRUNC functionality for common date parts:

CREATE FUNCTION dbo.TRUNCATE_DATETIME
(
    @inputDatetime DATETIME,
    @datePart VARCHAR(10)
)
RETURNS DATETIME
AS
BEGIN
    IF UPPER(@datePart) = 'YEAR'
        RETURN DATEADD(YEAR, DATEDIFF(YEAR, 0, @inputDatetime), 0);
    ELSE IF UPPER(@datePart) = 'MONTH'
        RETURN DATEADD(MONTH, DATEDIFF(MONTH, 0, @inputDatetime), 0);
    ELSE IF UPPER(@datePart) = 'DAY'
        RETURN DATEADD(DAY, DATEDIFF(DAY, 0, @inputDatetime), 0);
    ELSE IF UPPER(@datePart) = 'HOUR'
        RETURN DATEADD(HOUR, DATEDIFF(HOUR, 0, @inputDatetime), 0);
    ELSE IF UPPER(@datePart) = 'MINUTE'
        RETURN DATEADD(MINUTE, DATEDIFF(MINUTE, 0, @inputDatetime), 0);
    ELSE
        RETURN @inputDatetime; -- Return original if part not recognized
END
GO

-- Example Usage:
SELECT dbo.TRUNCATE_DATETIME(GETDATE(), 'DAY') AS FunctionTruncatedDate;

Performance and Best Practices

While various methods exist, it’s generally best to avoid truncating DATETIME values within the database whenever possible. Performance bottlenecks often occur at the database layer. Instead, consider performing this operation in your application logic if the data doesn’t strictly need to be truncated for database-level operations like grouping or indexing. If you must group by date, consider adding a computed column that stores the date-truncated value or manage this logic within your application code.

For scenarios requiring grouping by date, having an index on a computed column that stores the date-truncated value can significantly improve query performance.

FAQs on SQL Server DATETIME Truncation

Q: What is the simplest way to get the date part from a datetime in SQL Server

ANS: For SQL Server 2008 and newer, use CAST(GETDATE() AS DATE).

Q: Can I truncate datetime to other parts like month or year

ANS: Yes, the DATEADD(datepart, DATEDIFF(datepart, 0, GETDATE()), 0) pattern can be adapted for months, years, hours, and minutes. SQL Server 2022 also offers the DATETRUNC function for this.

Q: Is the CAST(FLOOR(CAST(GETDATE() AS FLOAT)) AS DATETIME) method reliable

ANS: It’s generally fast but relies on internal implementation details. The CAST(... AS DATE) or DATEADD/DATEDIFF methods are more robust and recommended for predictability.

Q: Should I truncate datetime in the database or application

ANS: It’s often better to handle date truncation in your application logic to keep database operations lean, unless it’s specifically for database-level grouping or indexing.

Q: What does DATETRUNC do in SQL Server 2022

ANS: DATETRUNC allows you to truncate a datetime value to a specified date part like year, month, day, hour, or minute.
