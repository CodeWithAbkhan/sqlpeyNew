“Oracle SQL String Aggregation: LISTAGG, XMLAGG, and More”

This question delves into various techniques for concatenating strings from multiple rows into a single string, a common requirement in database operations. We will examine several Oracle SQL functions and clauses, providing practical examples for each.

String Aggregation Methods in Oracle SQL

Several methods exist for aggregating strings in Oracle SQL, each with its own advantages and use cases.

1. LISTAGG Function

The LISTAGG function, available from Oracle 11g Release 2, is a modern and often preferred method for string aggregation. It allows for ordered concatenation of strings.

Basic Usage:

SELECT pid, LISTAGG(description, ' ') WITHIN GROUP (ORDER BY seq) AS aggregated_description
FROM B
GROUP BY pid;

This query concatenates the description column from table B, separated by a space, and orders them by seq for each pid. LISTAGG primarily works with VARCHAR2 columns out-of-the-box. For more details on string aggregation techniques, refer to Oracle Base’s article on String Aggregation Techniques .

Handling Long Strings with LISTAGG (Oracle 12c Release 2 and later):

A common challenge with LISTAGG is the ORA-01489: result of string concatenation is too long error when the aggregated string exceeds the VARCHAR2 limit (4000 characters). Oracle 12c Release 2 introduced the ON OVERFLOW clause to manage this:

  • ON OVERFLOW TRUNCATE: Limits the output to 4000 characters without an error.
  • ON OVERFLOW TRUNCATE 'Contd..' (or any custom string): Appends a specified string after truncation.
  • ON OVERFLOW TRUNCATE '': Truncates without any trailing characters.
  • ON OVERFLOW TRUNCATE WITH COUNT: Appends the total character count after truncation (e.g., ...(5512)).
  • ON OVERFLOW ERROR: Behaves as the default, raising the ORA-01489 error.

Example with ON OVERFLOW TRUNCATE:

SELECT pid, LISTAGG(description, ' ' ON OVERFLOW TRUNCATE) AS aggregated_description
FROM B
GROUP BY pid;

2. XMLAGG Function

For Oracle versions prior to 11.2, XMLAGG offers an alternative for string aggregation. It utilizes XML elements to achieve concatenation.

Example:

SELECT XMLAGG(XMLELEMENT(E, ename || ',')).EXTRACT('//text()') AS "Result"
FROM employee_names;

This query creates an XML element for each ename, concatenates them, and then extracts the text content. Ensure SERVEROUTPUT is enabled with SET SERVEROUT ON SIZE 6000 for some XMLAGG uses.

Another Example:

SELECT XMLAGG(XMLELEMENT(E, suplr_suplr_id || ',')).EXTRACT('//text()') AS "SUPPLIER"
FROM SUPPLIERS;

Conditional Aggregation with XMLAGG:

SELECT XMLAGG(XMLELEMENT(E, fieldname || ',')).EXTRACT('//text()') AS "FieldNames"
FROM FIELD_MASTER
WHERE FIELD_ID > 10 AND FIELD_AREA != 'NEBRASKA';

3. SYS_CONNECT_BY_PATH (Hierarchical Queries)

SYS_CONNECT_BY_PATH is typically used with hierarchical queries but can be adapted for string aggregation, particularly in older Oracle versions.

Example (Joining Table A and B):

SELECT a.pid, SUBSTR(MAX(SYS_CONNECT_BY_PATH(b.description, ', ')), 3) AS all_descriptions
FROM table_a a
LEFT JOIN table_b b ON a.pid = b.pid
START WITH b.pid IS NOT NULL -- Or a condition that identifies the first row for each group
CONNECT BY PRIOR b.pid = b.pid AND PRIOR b.seq = b.seq - 1 -- Adjusting connect by for order
GROUP BY a.pid
ORDER BY a.pid;

Example (Single Table B):

SELECT pid, SUBSTR(MAX(SYS_CONNECT_BY_PATH(description, ', ')), 3) AS all_descriptions
FROM (
    SELECT ROW_NUMBER() OVER (PARTITION BY pid ORDER BY pid, seq) rnum, pid, description
    FROM table_b
)
START WITH rnum = 1
CONNECT BY PRIOR rnum = rnum - 1 AND PRIOR pid = pid
GROUP BY pid
ORDER BY pid;

Concatenating All Values from a Table:

SELECT SUBSTR(MAX(SYS_CONNECT_BY_PATH(description, ', ')), 3) AS all_descriptions
FROM (
    SELECT ROW_NUMBER() OVER (PARTITION BY '1' ORDER BY pid, seq) rnum, description
    FROM table_b
)
START WITH rnum = 1
CONNECT BY PRIOR rnum = rnum - 1;

Refer to Oracle Base for more on hierarchical queries .

4. SQL Model Clause

The SQL Model clause provides a powerful way to perform row-by-row calculations and aggregations.

Example:

SELECT pid, ltrim(sentence) AS sentence
FROM (
    SELECT pid, seq, sentence
    FROM b
    MODEL
        PARTITION BY (pid)
        DIMENSION BY (seq)
        MEASURES (description, CAST(NULL AS VARCHAR2(100)) AS sentence)
        (
            sentence[ANY] ORDER BY seq DESC
            = description[CV()] || ' ' || sentence[CV()+1]
        )
)
WHERE seq = 1;

This example demonstrates how the SQL Model clause can build concatenated strings iteratively.

5. User-Defined Functions (UDFs)

For complex logic or specific requirements, creating a user-defined SQL function can be an effective solution.

Example (Conceptual SQL Server syntax, adaptable for Oracle PL/SQL):

-- SQL Function (Conceptual)
SELECT PID, dbo.MyConcat(PID) AS ConcatenatedDescriptions
FROM TableA;

-- PL/SQL Function (Oracle)
CREATE OR REPLACE FUNCTION MyConcat (p_pid IN VARCHAR2)
RETURN VARCHAR2
IS
    l_result VARCHAR2(4000) := '';
BEGIN
    FOR rec IN (SELECT description FROM TableB WHERE PID = p_pid ORDER BY seq)
    LOOP
        IF l_result IS NOT NULL THEN
            l_result := l_result || ',';
        END IF;
        l_result := l_result || rec.description;
    END LOOP;
    RETURN l_result;
END;
/

This approach encapsulates the aggregation logic within a reusable function.

6. COLLECT and TO_STRING

For scenarios where sorting is not critical, COLLECT followed by TO_STRING can offer better performance.

Example (Unsorted):

SELECT pid, TO_STRING(CAST(COLLECT(description) AS varchar2_ntt)) AS Vals
FROM B
GROUP BY pid;

Example (Sorted):

SELECT pid, TO_STRING(CAST(COLLECT(description ORDER BY description) AS varchar2_ntt)) AS Vals
FROM B
GROUP BY pid;

The performance of LISTAGG is generally superior when explicit ordering is required, while COLLECT excels when order is not a concern.

Performance Considerations

  • LISTAGG: Typically offers the best performance when ordered aggregation is needed.
  • COLLECT: Outperforms LISTAGG when sorting is not a requirement.
  • SYS_CONNECT_BY_PATH and XMLAGG can be slower compared to LISTAGG for simple string aggregation.
  • User-defined functions add overhead but provide flexibility.

FAQs on Oracle SQL String Aggregation

Q: Which Oracle SQL method offers the best performance for string aggregation

ANS: LISTAGG generally provides the best performance when ordered aggregation is required. If sorting is not a concern, COLLECT can be faster.

Q: How to avoid ORA-01489 error with LISTAGG

ANS: In Oracle 12c Release 2 and later, use the ON OVERFLOW clause (e.g., ON OVERFLOW TRUNCATE) within LISTAGG to prevent the error when the aggregated string exceeds the VARCHAR2 limit.

Q: Can XMLAGG be used for string concatenation in older Oracle versions

ANS: Yes, XMLAGG is a viable option for string aggregation in Oracle versions prior to 11.2.

Q: What is the purpose of SYS_CONNECT_BY_PATH in string aggregation

ANS: SYS_CONNECT_BY_PATH is primarily used in hierarchical queries but can be adapted to concatenate strings by leveraging its path-building capability, especially in older Oracle versions.

Q: Is WM_CONCAT recommended for string aggregation in Oracle

ANS: WM_CONCAT is undocumented and unsupported by Oracle, so it is not recommended for use in production systems.
