“Efficient SQL: Inserting Data From One Table to Another”

When working with relational databases, a common task involves populating one table with data from another. This process, often referred to as transferring or copying data, can be achieved through several SQL constructs. The fundamental approach utilizes the INSERT statement in conjunction with a SELECT query. This allows you to specify which columns from the source table should be inserted into the target table, and you can also apply conditions to filter the data being transferred.

The standard ANSI SQL syntax for this operation is quite consistent across many database management systems (DBMS). Here’s the general structure:

INSERT INTO target_table (column1, column2, ...)
SELECT column1, column2, ...
FROM source_table
WHERE condition;

Let’s explore various accepted methods and their nuances, covering different scenarios and database specificities.

Solution 1: Standard ANSI SQL Insertion

This is the most widely compatible method, adhering to the ANSI SQL standard. It’s suitable for inserting specified columns from a source table to a target table.

INSERT INTO table1 (column1)
SELECT col1
FROM table2;

This syntax is supported by a vast array of DBMS, including:

  • Oracle
  • MS SQL Server
  • MySQL
  • PostgreSQL
  • SQLite v3
  • Teradata
  • DB2
  • Sybase
  • Vertica
  • HSQLDB
  • H2
  • AWS RedShift
  • SAP HANA
  • Google Spanner

For a deeper dive into SQL, explore What is SQL .

Solution 2: Inserting Multiple Columns and Filtering

This approach, as demonstrated by Claude Houle, allows for the insertion of multiple columns, additional literal values, and uses a WHERE clause for targeted data retrieval.

INSERT INTO table1 (column1, column2, someInt, someVarChar)
SELECT table2.column1, table2.column2, 8, 'some string etc.'
FROM table2
WHERE table2.ID = 7;

This syntax is known to function well with:

  • Access
  • SQL Server (2000/2005/Express)
  • MySQL
  • PostgreSQL
  • SQLite3

Solution 3: Inserting a Single Value from a Subquery in SQLite3

For SQLite3, you can insert a specific value from a subquery into a particular column.

INSERT INTO column_1 (val_1, val_from_other_table)
VALUES ('val_1', (SELECT val_2 FROM table_2 WHERE val_2 = 'something'));

Solution 4: Informix Specifics and Standard SQL

Informix, like many other DBMS, supports the standard INSERT INTO ... SELECT ... syntax. The key difference often lies in table identification, especially when dealing with cross-database or cross-DBMS operations.

The general syntax for Informix is:

INSERT INTO target_table[(column_list)] SELECT ... FROM ...;

Informix allows flexible table naming conventions:

[dbase[@server]:][owner.]table

This translates to various forms like:

table
"owner".table
dbase:table
dbase:owner.table
dbase@server:table
dbase@server:owner.table

It’s important to note how owner names are handled, especially in MODE ANSI databases where they are typically converted to uppercase unless enclosed in double quotes, which then act as delimited identifiers. Microsoft SQL Server uses square brackets [] for delimited identifiers, which is a departure from the SQL standard.

-- Informix example for specifying table with owner
INSERT INTO "myowner".my_table (column1)
SELECT source_column FROM another_table;

Solution 5: Handling Single and Multiple Row Subqueries

This method differentiates between scenarios where a SELECT subquery returns a single row versus multiple rows.

For a single row subquery:

INSERT INTO <table_name> (<field1>, <field2>, <field3>)
VALUES ('DUMMY1', (SELECT <field> FROM <table_name> WHERE some_condition), 'DUMMY2');

For multiple rows or the general case:

INSERT INTO <table_name> (<field1>, <field2>, <field3>)
SELECT 'DUMMY1', <field>, 'DUMMY2' FROM <source_table>;

The second approach is more versatile and can accommodate both single and multiple row results from the SELECT statement.

Solution 6: Inserting Specific Data with a Subquery

This example shows how to insert a value from a subquery into a specific column while providing other static values.

INSERT INTO TABLE1 (COLUMN1, COLUMN2, COLUMN3, COLUMN4)
VALUES ('value1', 'value2',
        (SELECT COLUMN_TABLE2 FROM TABLE2 WHERE COLUMN_TABLE2 LIKE 'blabla'),
        'value4');

Solution 7: Direct SELECT Insertion

When the column structure of the source and target tables match exactly, you can omit the column list in the INSERT statement.

INSERT INTO table1 (column1, column2, column3)
SELECT col1, col2, col3 FROM table2;

Solution 8: Generic INSERT INTO ... SELECT

Most databases adhere to a fundamental INSERT INTO ... SELECT ... structure.

INSERT INTO TABLE_NAME
SELECT COL1, COL2, ...
FROM TABLE_YOU_NEED_TO_TAKE_FROM;

This pattern is common across DB2, SQL Server, MySQL, and PostgreSQL.

Solution 9: Inserting All Columns or Specific Columns

If the number of columns and their order in the SELECT statement perfectly matches the target table, you can use SELECT *.

Inserting all columns:

INSERT INTO table1
SELECT col1, col2
FROM table2;

Attempting to insert fewer columns than exist in the target:

-- This would fail if table1 has more than one column and col2 is not selected
INSERT INTO table1
SELECT col1
FROM table2;

This behavior is confirmed for MS SQL Server.

Solution 10: Using Parentheses for Subquery in VALUES

This method uses parentheses around the SELECT clause when it’s part of the VALUES list.

INSERT INTO Table1 (col1, col2, desired_value_from_select, col3)
VALUES (
   'col1_value',
   'col2_value',
   (SELECT col_Table2 FROM Table2 WHERE IdTable2 = 'your_satisfied_value_for_col_Table2_selected'),
   'col3_value'
);

Solution 11: Inserting Literal Values with SELECT

This example demonstrates inserting a literal string and an integer along with data from a SELECT statement.

INSERT INTO table1(description, id, email)
SELECT 'Hello World', 3, email FROM table2 WHERE ...;

Solution 12: Bulk Insertion with Column Specification

This covers several scenarios for bulk insertion, including cases where column sequences match or when only specific columns are targeted.

Insert into all columns (sequence known):

INSERT INTO Table1
VALUES(1, 2, ...); -- Assuming Table1 has columns matching this order and types

Insert into specific columns:

INSERT INTO Table1 (col2, col4)
VALUES (1, 2);

Bulk insert when selected columns match target table’s sequence:

INSERT INTO Table1 {Column sequence}
SELECT * -- Column sequence should be identical.
FROM #table2; -- Using a temporary table example

Bulk insert into desired columns:

INSERT INTO Table1 (Column1, Column2, ..., Desired_Column_from_Table1)
SELECT Column1, Column2, ... desired column from #table2
FROM #table2;

Solution 13: Inserting from Multiple Tables

When data needs to be combined from multiple source tables, you can use joins within the SELECT statement.

INSERT INTO cesc_pf_stmt_ext_wrk (
  PF_EMP_CODE, PF_DEPT_CODE, PF_SEC_CODE, PF_PROL_NO,
  PF_FM_SEQ, PF_SEQ_NO, PF_SEP_TAG, PF_SOURCE
)
SELECT
  PFl_EMP_CODE, PFl_DEPT_CODE, PFl_SEC, PFl_PROL_NO,
  PF_FM_SEQ, PF_SEQ_NO, PFl_SEP_TAG, PF_SOURCE
FROM cesc_pf_stmt_ext, cesc_pfl_emp_master
WHERE pfl_sep_tag LIKE '0'
  AND pfl_emp_code = pf_emp_code(+); -- Oracle's outer join syntax example

COMMIT;

Solution 14: Many-to-Many Mapping Table Insertion

For scenarios involving relationships, like a many-to-many mapping table, you can select IDs from related tables based on descriptive criteria.

insert into StudentCourseMap (StudentId, CourseId)
SELECT Student.Id, Course.Id FROM Student, Course
WHERE Student.Name = 'Paddy Murphy' AND Course.Name = 'Basket weaving for beginners';

Solution 15: Creating a New Table and Populating It (SELECT INTO)

Some systems, like SQL Server, offer a shorthand to create a new table and populate it simultaneously.

SELECT *
INTO Table2
FROM Table1;

This statement creates Table2 with the structure and data from Table1.

Solution 16: SQL Server 2008 SELECT INTO with Joins

SQL Server 2008 and later versions allow creating and populating a new table using SELECT INTO with joins, selecting specific columns and literal values.

SELECT Table1.Column1, Table1.Column2, Table2.Column1, Table2.Column2, 'Some String' AS SomeString, 8 AS SomeInt
INTO Table3
FROM Table1 INNER JOIN Table2 ON Table1.Column1 = Table2.Column3;

This method bypasses the explicit INSERT statement by directly creating and populating the target table.

Solution 17: Simple INSERT SELECT

A concise way to insert all columns when the structure matches.

insert into table1 select * from table2;

This syntax is noted as being different from Oracle’s typical approach.

Solution 18: General INSERT ... SELECT

This is a universally applicable format for inserting columns from a source to a target.

INSERT INTO yourtable (fieldA, fieldB, fieldC)
SELECT fielda, fieldb, fieldc
FROM donortable;

This works across most DBMS.

Solution 19: Understanding MS SQL Server Syntax with INSERT and SELECT

Microsoft SQL Server’s syntax can be detailed, with options for common table expressions (CTEs), TOP clauses, and various source types for insertion. Referring to official documentation like MSDN is recommended. The core concept involves INSERT INTO {object} {column_list} {derived_table | execute_statement | dml_table_source}.

-- Example structure from MSDN for SQL Server
[ WITH <common_table_expression> [ ,...n ] ]
INSERT
{
    [ TOP ( expression ) [ PERCENT ] ]
    [ INTO ]
    { <object> | rowset_function_limited
      [ WITH ( <Table_Hint_Limited> [ ...n ] ) ]
    }
    {
        [ ( column_list ) ]
        [ <OUTPUT Clause> ]
        { VALUES ( { DEFAULT | NULL | expression } [ ,...n ] ) [ ,...n     ]
        | derived_table       /* Using a SELECT statement */
        | execute_statement
        | <dml_table_source>
        | DEFAULT VALUES
        }
    }
}
[;]

Solution 20: INSERT ... SELECT with a WHERE Clause

This is a straightforward method to insert specific data based on a condition.

INSERT INTO FIRST_TABLE_NAME (COLUMN_NAME)
SELECT COLUMN_NAME
FROM ANOTHER_TABLE_NAME
WHERE CONDITION;

Solution 21: Advanced INSERT ... SELECT with Joins and Conditions

This flexible approach allows for insertions using SELECT statements that incorporate joins, WHERE clauses, and other SQL constructs.

INSERT INTO dbo.Users
            ( UserID, Full_Name, Login_Name, Password )
SELECT      UserID, Full_Name, Login_Name, Password
FROM        Users_Table
            (INNER JOIN / LEFT JOIN ...) -- Specify join type
            (WHERE CONDITION...)         -- Specify filtering conditions
            (OTHER CLAUSE);              -- Additional clauses like ORDER BY

This is highly adaptable for complex data transfer scenarios.

Solution 22: SQL Server SELECT * INTO and IDENTITY_INSERT

SQL Server offers SELECT * INTO for creating and populating a new table. To insert into an existing table with identity columns, you need to manage IDENTITY_INSERT.

Creating and populating a new table:

SELECT *
INTO tmp
FROM orders;

Inserting into an existing table with identity columns:

SET IDENTITY_INSERT tmp ON;

INSERT INTO tmp
(OrderID, CustomerID, EmployeeID, OrderDate, RequiredDate, ShippedDate, ShipVia, Freight, ShipName, ShipAddress, ShipCity, ShipRegion, ShipPostalCode, ShipCountry)
SELECT OrderID, CustomerID, EmployeeID, OrderDate, RequiredDate, ShippedDate, ShipVia, Freight, ShipName, ShipAddress, ShipCity, ShipRegion, ShipPostalCode, ShipCountry
FROM orders;

SET IDENTITY_INSERT tmp OFF;

Solution 23: Inserting Without Explicit Column Names (if structure matches)

If the columns in the SELECT statement precisely match the order and data types of the target table’s columns, you can omit the column list in the INSERT statement.

INSERT INTO CUSTOMER_INFO
   (SELECT CUSTOMER_NAME, MOBILE_NO, ADDRESS
    FROM OWNER_INFO cm);

This assumes CUSTOMER_INFO has columns CUSTOMER_NAME, MOBILE_NO, ADDRESS in that order, and OWNER_INFO provides data for them.

Solution 24: Multi-Row VALUES Syntax (MySQL Specific Example)

MySQL supports a concise syntax for inserting multiple rows using the VALUES clause, where each row is a comma-separated tuple enclosed in parentheses.

INSERT INTO `receiving_table`
  (id, first_name, last_name)
VALUES
  (1002, 'Charles', 'Babbage'),
  (1003, 'George', 'Boole'),
  (1001, 'Donald', 'Chamberlin'),
  (1004, 'Alan', 'Turing'),
  (1005, 'My', 'Widenius');

Using this format correctly prevents “Column count doesn’t match value count” errors.

Solution 25: Creating a Copy Table

This method creates a new table as an exact copy of another table, including its structure and data.

SELECT * INTO TableYedek FROM Table;

This is distinct from inserting into an existing table.

Solution 26: Informix INSERT ... VALUES

While the primary focus is INSERT ... SELECT, it’s worth noting that the standard INSERT ... VALUES syntax is also supported in Informix for single-row insertions.

INSERT INTO table (column1, column2)
VALUES (value1, value2);

Solution 27: PostgreSQL Table Creation with SELECT

PostgreSQL offers a concise way to create a new table and populate it with data from an existing table.

CREATE TABLE company.monitor2 AS SELECT * FROM company.monitor;

This creates monitor2 mirroring the structure and content of monitor.

Solution 28: Cross-Database Compatibility and Variations

The INSERT ... SELECT statement is broadly compatible, but nuances exist:

  • MySQL and PostgreSQL: Support INSERT ... SELECT directly.
  • SQL Server and Oracle: Require explicit column lists if the SELECT columns don’t perfectly match the INSERT columns. Oracle might use INSERT ALL for multiple-row inserts.
  • DB2: Supports the format but might require query optimizer tuning.

A general example:

INSERT INTO target_table (column1, column2, etc)
SELECT column1, column2, etc FROM source_table WHERE condition;

-- Specific example: archiving sales employees
INSERT INTO archived_employees (id, name, department, salary)
SELECT id, name, department, salary FROM employees
WHERE department = 'Sales';

FAQs on Inserting Data From One Table to Another

Q: What is the most common way to insert data from one SQL table to another

ANS: The most common and widely compatible method is using the INSERT INTO target_table (column_list) SELECT column_list FROM source_table; syntax.

Q: Can I insert only specific columns from a source table

ANS: Yes, by explicitly listing the desired columns in both the INSERT INTO and SELECT statements.

Q: How do I insert data if the source and target tables have different column orders

ANS: You must explicitly list the columns in both the INSERT INTO clause and the SELECT clause to ensure data maps correctly.

Q: What happens if the data types of columns don't match

ANS: Most database systems will attempt implicit conversion if possible. However, it’s best practice to ensure data types are compatible or to use explicit casting functions to avoid errors or unexpected results.

Q: Can I insert data from multiple tables at once

ANS: Yes, you can use joins within the SELECT statement to combine data from multiple source tables before inserting it into a single target table.

Q: How to insert data from a table with an identity column

ANS: If the target table has an identity column and you need to preserve those values, you’ll often need to use a database-specific command like SET IDENTITY_INSERT ON (in SQL Server) before the insert operation.

Q: Is the INSERT ... SELECT syntax supported across all SQL databases

ANS: While the basic INSERT ... SELECT syntax is standard, specific features or syntax variations might differ between database systems like MySQL, PostgreSQL, SQL Server, Oracle, and DB2.
