Q: How to get top 5 rows per group in MySQL 8+

ANS: In MySQL 8 and later versions, you can leverage window functions like ROW_NUMBER(), RANK(), or DENSE_RANK() for this task. The choice depends on how you want to handle ties. ROW_NUMBER() assigns a unique number to each row within a partition, RANK() assigns the same rank to rows with equal values and skips the next rank, while DENSE_RANK() assigns the same rank to tied rows but does not skip ranks.

Here’s an example using ROW_NUMBER():

SELECT
    pkid,
    catid,
    value,
    ROW_NUMBER() OVER (PARTITION BY catid ORDER BY value DESC) AS n
FROM
    your_table_name
WHERE
    n <= 5;

This query partitions the data by catid, orders it by value in descending order, assigns a row number, and then filters for rows where the row number is 5 or less.

Q: What is the approach for older MySQL versions (pre-8.x)?

ANS: For MySQL versions prior to 8.x, which lack window function support, you can simulate ranking using self-joins and aggregate functions. This method involves counting rows that meet certain criteria to determine the rank.

To achieve results similar to RANK():

SELECT
    t.pkid,
    t.catid,
    t.value,
    COUNT(b.value) + 1 AS rank
FROM
    your_table_name t
LEFT JOIN
    your_table_name b ON b.catid = t.catid AND b.value > t.value
GROUP BY
    t.pkid, t.catid, t.value
HAVING
    COUNT(b.value) + 1 <= 5
ORDER BY
    t.catid, t.value DESC, t.pkid;

To mimic DENSE_RANK(), change COUNT(b.value) to COUNT(DISTINCT b.value). To mimic ROW_NUMBER(), adjust the join condition: ON b.catid = t.catid AND (b.value > t.value OR (b.value = t.value AND b.pkid < t.pkid)). You can explore more on introduction to MySQL .

Q: Can GROUP_CONCAT be used for this purpose?

ANS: Yes, GROUP_CONCAT can be a viable solution, especially when you need to aggregate values within a group into a single string. You can then use FIND_IN_SET to determine the position of an element within this concatenated string.

The process involves grouping by the identifier and concatenating the relevant values ordered by the ranking criteria:

SELECT
    yt.*
FROM
    your_table yt
INNER JOIN (
    SELECT
        id,
        GROUP_CONCAT(year ORDER BY rate DESC) AS grouped_year
    FROM
        your_table
    GROUP BY id
) AS group_max ON yt.id = group_max.id
                 AND FIND_IN_SET(year, grouped_year) BETWEEN 1 AND 5
ORDER BY
    yt.id, yt.year DESC;

Be aware of the GROUP_CONCAT length limit, which makes this approach suitable for fetching a limited number of records per group. If multiple rows share the same rate, consider using GROUP_CONCAT(DISTINCT year ORDER BY rate DESC).

Q: What about the SUBSTRING_INDEX method?

ANS: The SUBSTRING_INDEX function, when combined with GROUP_CONCAT, offers a concise way to extract the top N values. It allows you to specify a delimiter and a count to get a portion of the string.

For instance, to get the top 1 for each group:

SELECT
    *
FROM
    your_table
WHERE
    id IN (
        SELECT
            SUBSTRING_INDEX(GROUP_CONCAT(id ORDER BY rate DESC), ',', 1) AS id
        FROM
            your_table
        GROUP BY year
    )
ORDER BY rate DESC;

Q: How do window functions handle different ranking scenarios?

ANS: Window functions provide flexible ways to rank data. ROW_NUMBER() assigns a distinct rank to each row within a partition, useful when you need exactly N rows regardless of ties. RANK() gives identical ranks to rows with the same value in the ordering column and skips the next rank(s). DENSE_RANK() also assigns identical ranks to ties but does not skip subsequent ranks, ensuring a contiguous sequence of ranks.

Consider this example for ROW_NUMBER():

SELECT year, id, rate
FROM (
    SELECT
        year, id, rate,
        ROW_NUMBER() OVER (PARTITION BY id ORDER BY rate DESC) AS row_num
    FROM
        your_table_h
    WHERE
        year BETWEEN 2000 AND 2009
        AND id IN (SELECT rid FROM table2)
    GROUP BY id, year
    ORDER BY id, rate DESC
) AS subquery
WHERE row_num <= 5;

Q: Are there solutions using user-defined variables?

ANS: Yes, user-defined variables can be employed to simulate row numbering within groups. This approach requires careful initialization and updating of variables as you iterate through the ordered rows.

An example demonstrating this:

SET @row_number := 0, @current_id := '';
SELECT
    year, id, rate,
    @row_number := IF(@current_id = id, @row_number + 1, 1) AS row_num,
    @current_id := id
FROM (
    SELECT
        year, id, rate
    FROM
        your_table_h
    WHERE
        year BETWEEN 2000 AND 2009
        AND id IN (SELECT rid FROM table2)
    ORDER BY id, rate DESC
) AS temp_h
WHERE @row_number < 5;

Q: How to construct virtual columns for ranking?

ANS: In databases that support correlated subqueries in the SELECT list, you can create a virtual column to count rows within the same group that have a higher or equal ranking value.

Here’s how it might look:

SELECT
    t3.year, t3.id, t3.rate
FROM (
    SELECT
        t1.*,
        (SELECT COUNT(*) FROM your_table t2 WHERE t1.rate <= t2.rate AND t1.id = t2.id) AS rownum
    FROM
        your_table t1
) t3
WHERE rownum <= 3
ORDER BY id, rate DESC;

Q: What about solutions that avoid subqueries?

ANS: Solutions that avoid subqueries are generally preferred for performance, as they can sometimes lead to better query plans and index utilization. One technique involves using GROUP_CONCAT in conjunction with SUBSTRING_INDEX and a LEFT JOIN to filter the results.

Consider this approach:

SELECT
    h.year, h.id, h.rate
FROM (
    SELECT
        id,
        SUBSTRING_INDEX(GROUP_CONCAT(CONCAT(id, '-', year) ORDER BY rate DESC), ',', 5) AS l
    FROM
        your_table_h
    WHERE
        year BETWEEN 2000 AND 2009
    GROUP BY id
    ORDER BY id
) AS h_temp
LEFT JOIN
    your_table_h h ON h.id = h_temp.id
    AND SUBSTRING_INDEX(h_temp.l, CONCAT(h.id, '-', h.year), 1) != h_temp.l;

Q: How can stored procedures help with this task?

ANS: Stored procedures offer a way to encapsulate logic, which can be particularly useful for complex operations like fetching top N rows per group, especially when dealing with performance concerns or needing to iterate through a set of groups.

A stored procedure can loop through distinct groups and apply a LIMIT clause to fetch the top records for each.

DELIMITER $$
CREATE PROCEDURE GetTopNRecordsPerGroup()
BEGIN
    DECLARE counter INT DEFAULT 0;
    DECLARE limitReached INT DEFAULT 0;
    DECLARE currentDomain VARCHAR(250);
    DECLARE domainCursor CURSOR FOR SELECT DISTINCT domain FROM your_db.your_table;

    OPEN domainCursor;

    SELECT COUNT(DISTINCT domain) INTO limitReached
    FROM your_db.your_table;

    domain_loop: LOOP
        FETCH domainCursor INTO currentDomain;
        SET counter = counter + 1;

        INSERT INTO your_db.target_table (col1, col2, col3, rank_count, last_updated)
        SELECT * FROM (
            SELECT col1, col2, col3, COUNT(ObjectKey) AS titleCount, NOW()
            FROM your_db.your_table
            WHERE book = currentDomain
            GROUP BY col2, col3
            ORDER BY book, titleCount DESC
            LIMIT 200
        ) a ON DUPLICATE KEY UPDATE rank_count = titleCount, last_updated = NOW();

        IF counter = limitReached THEN
            LEAVE domain_loop;
        END IF;
    END LOOP domain_loop;
    CLOSE domainCursor;
END $$

Q: How to implement a 'top operation' in MySQL?

ANS: A straightforward “top operation” in MySQL can be achieved by using user-defined variables to rank rows within ordered groups. This involves assigning a rank based on changes in the grouping column.

Here’s the code:

SELECT id, year, rate
FROM (
    SELECT
        id, year, rate,
        @last_id,
        IF(@last_id = id, @row_counter := @row_counter + 1, @row_counter := 0) AS ztop,
        @last_id := id AS update_last_id
    FROM
        your_table_h
    ORDER BY id, rate DESC, year DESC
) AS t2
WHERE ztop < 5;

Q: What are the considerations for ties in ranking?

ANS: When ties occur in the ranking criteria (e.g., multiple rows have the same ‘rate’), the choice of window function or method matters. ROW_NUMBER() will assign distinct numbers, potentially including or excluding ties based on arbitrary order. RANK() and DENSE_RANK() handle ties by assigning the same rank, but RANK() will skip subsequent ranks while DENSE_RANK() will not. If you need to include all tied rows that fall within the top N, you might need to adjust your logic or use RANK() or DENSE_RANK() appropriately.
