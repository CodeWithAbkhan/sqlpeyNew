“SQL: Split Comma-Separated Values into Rows”

When working with relational databases, you might encounter a common scenario where a column contains multiple values separated by a delimiter, typically a comma. This format, often referred to as comma-separated values (CSV) within a single field, can hinder efficient querying and data analysis. The challenge lies in transforming these delimited strings into separate rows, with each value occupying its own row, linked back to its original record. This process is fundamental for normalized data structures and effective data manipulation in SQL.

Several approaches can achieve this transformation, each with its own characteristics regarding performance, complexity, and compatibility across different database systems. We will examine various SQL techniques, including hierarchical queries (CONNECT BY), recursive Common Table Expressions (CTEs), built-in XML and JSON functions, and PL/SQL functions, providing practical code examples and insights into their efficiency.

Solution 1: CONNECT BY with REGEXP_SUBSTR

A common method involves using the CONNECT BY clause in conjunction with REGEXP_SUBSTR to iteratively extract substrings based on the comma delimiter.

SELECT DISTINCT
    id,
    TRIM(REGEXP_SUBSTR(value, '[^,]+', 1, LEVEL)) AS value,
    LEVEL AS item_order
FROM
    tbl1
CONNECT BY
    REGEXP_SUBSTR(value, '[^,]+', 1, LEVEL) IS NOT NULL
ORDER BY
    id, item_order;

  • Output Example:

    | id | value | item_order | | :– | :

To avoid performance degradation with large datasets, especially when a single id has many comma-separated values, it’s crucial to prevent excessive row generation. The following variation adds conditions to the CONNECT BY clause to ensure that the hierarchical traversal is tied to the specific id and avoids infinite loops, a common pitfall.

SELECT
    id,
    TRIM(REGEXP_SUBSTR(value, '[^,]+', 1, LEVEL)) AS value,
    LEVEL AS item_order
FROM
    tbl1
CONNECT BY
    REGEXP_SUBSTR(value, '[^,]+', 1, LEVEL) IS NOT NULL
    AND PRIOR id = id
    AND PRIOR SYS_GUID() IS NOT NULL
ORDER BY
    id, item_order;

Solution 2: Recursive CTE Approach

A more ANSI-SQL compliant method utilizes a recursive Common Table Expression (CTE). This approach breaks down the string iteratively.

WITH ValueSplitter AS (
    -- Anchor member: Select the first element and prepare for recursion
    SELECT
        id,
        TRIM(REGEXP_SUBSTR(value, '[^,]+', 1, 1)) AS split_value,
        1 AS item_order,
        value AS remaining_string
    FROM tbl1
    WHERE REGEXP_SUBSTR(value, '[^,]+', 1, 1) IS NOT NULL

    UNION ALL

    -- Recursive member: Extract the next element
    SELECT
        id,
        TRIM(REGEXP_SUBSTR(remaining_string, '[^,]+', 1, item_order + 1)) AS split_value,
        item_order + 1,
        remaining_string
    FROM ValueSplitter
    WHERE REGEXP_SUBSTR(remaining_string, '[^,]+', 1, item_order + 1) IS NOT NULL
)
SELECT
    id,
    split_value,
    item_order
FROM
    ValueSplitter
ORDER BY
    id, item_order;

Solution 3: Recursive Approach without Regular Expressions

Another recursive method avoids regular expressions, relying on INSTR and SUBSTR for string manipulation, which can sometimes offer better performance on certain database versions.

WITH StringSplit AS (
    -- Anchor: Initialize with the first segment
    SELECT
        id,
        value,
        1 AS start_pos,
        INSTR(value, ',', 1) AS end_pos
    FROM tbl1

    UNION ALL

    -- Recursive step: Find subsequent segments
    SELECT
        id,
        value,
        end_pos + 1 AS start_pos,
        INSTR(value, ',', end_pos + 1) AS end_pos
    FROM StringSplit
    WHERE end_pos > 0
)
SELECT
    id,
    SUBSTR(value, start_pos, DECODE(end_pos, 0, LENGTH(value) + 1, end_pos) - start_pos) AS value_segment
FROM StringSplit
ORDER BY id, start_pos;

Solution 4: TABLE Function with MULTISET and REGEXP_SUBSTR

This solution leverages Oracle’s TABLE function with MULTISET and REGEXP_SUBSTR to transform the delimited string into a collection, which can then be unnested into rows. This method is often considered cleaner as it avoids explicit recursion management within the SQL itself.

SELECT
    t.id,
    v.COLUMN_VALUE AS value_item
FROM
    tbl1 t,
    TABLE(
        CAST(
            MULTISET(
                SELECT TRIM(REGEXP_SUBSTR(t.value, '[^,]+', 1, LEVEL))
                FROM DUAL
                CONNECT BY LEVEL <= REGEXP_COUNT(t.value, '[^,]+')
            ) AS SYS.ODCIVARCHAR2LIST
        )
    ) v;

To include the order or index of each split element, you can use ROW_NUMBER() or a User-Defined Type (UDT).

    ROW_NUMBER() OVER (PARTITION BY t.id ORDER BY ROWNUM) AS item_index
FROM
    tbl1 t,

        CAST(
            MULTISET(
                SELECT TRIM(REGEXP_SUBSTR(t.value, '[^,]+', 1, LEVEL))
                FROM DUAL
                CONNECT BY LEVEL <= REGEXP_COUNT(t.value, '[^,]+')
            ) AS SYS.ODCIVARCHAR2LIST

    ) v;

        )
    ) v;

Solution 5: PL/SQL Function Approach

Creating a user-defined function in PL/SQL provides a reusable and often more readable way to handle string splitting. The function returns a collection type, which can then be queried in SQL.

First, create the collection type:

CREATE TYPE string_list_type IS TABLE OF VARCHAR2(4000);
/

Then, create the splitting function:

CREATE OR REPLACE FUNCTION split_string_by_comma (
    p_input_string IN VARCHAR2
) RETURN string_list_type DETERMINISTIC
AS
    l_string_list string_list_type := string_list_type();
    l_start_pos NUMBER := 1;
    l_end_pos   NUMBER;
    l_string_len CONSTANT NUMBER := LENGTH(p_input_string);
    l_delim_len CONSTANT NUMBER := LENGTH(',');
BEGIN
    IF l_string_len > 0 THEN
        l_end_pos := INSTR(p_input_string, ',', l_start_pos);
        WHILE l_end_pos > 0 LOOP
            l_string_list.EXTEND;
            l_string_list(l_string_list.COUNT) := SUBSTR(p_input_string, l_start_pos, l_end_pos - l_start_pos);
            l_start_pos := l_end_pos + l_delim_len;
            l_end_pos := INSTR(p_input_string, ',', l_start_pos);
        END LOOP;
        -- Add the last element
        IF l_start_pos <= l_string_len + 1 THEN
            l_string_list.EXTEND;
            l_string_list(l_string_list.COUNT) := SUBSTR(p_input_string, l_start_pos, l_string_len - l_start_pos + 1);
        END IF;
    END IF;
    RETURN l_string_list;
END;
/

Finally, call the function in your SQL query:

SELECT
    t.id,
    v.column_value AS value_item
FROM
    tbl1 t,
    TABLE(split_string_by_comma(t.value)) v;

If you need to retain the order of the split elements, you could modify the function to return a collection of objects containing both the index and the value, similar to the UDT approach.

Solution 6: MODEL Clause Approach

The MODEL clause offers a powerful way to perform complex data transformations. This solution simulates row generation by iterating through the string using the MODEL clause.

SELECT
    main.id,
    main.value_segment
FROM
    (
        SELECT
            indx,
            value AS value_segment,
            val_elements
        FROM
            (
                SELECT
                    0 AS indx,
                    REPLACE(col1, ', ', ',') AS value,
                    TRIM(LENGTH(REPLACE(col1, ' ', ''))) - TRIM(LENGTH(TRANSLATE(REPLACE(col1, ', ', ','), 'A,', 'A'))) + 1 AS val_elements
                FROM
                    (SELECT 'aaa,bbb,ccc' AS col1, 'qq,ww,ee' AS col2 FROM DUAL) -- Example data
            )
        MODEL
            DIMENSION BY (0 AS indx)
            MEASURES(value, val_elements, CAST('' AS VARCHAR2(4000)) AS current_str, CAST('' AS VARCHAR2(4000)) AS value_segment)
            RULES ITERATE (10) -- Adjust iteration count based on expected max elements
            (
                val_elements[ITERATION_NUMBER + 1] = val_elements[0], -- Carry over total count
                current_str[0] = value[CV()],
                current_str[ITERATION_NUMBER + 1] = SUBSTR(current_str[ITERATION_NUMBER], INSTR(current_str[ITERATION_NUMBER], ',', 1) + 1),
                value_segment[ITERATION_NUMBER + 1] = SUBSTR(current_str[ITERATION_NUMBER], 1, CASE WHEN INSTR(current_str[ITERATION_NUMBER], ',') <> 0 THEN INSTR(current_str[ITERATION_NUMBER], ',') - 1 ELSE LENGTH(current_str[ITERATION_NUMBER]) END)
            )
    )
WHERE
    indx > 0 AND indx <= val_elements;

CREATE OR REPLACE FUNCTION split_String(
  i_str    IN  VARCHAR2,
  i_delim  IN  VARCHAR2 DEFAULT ','
) RETURN SYS.ODCIVARCHAR2LIST DETERMINISTIC
AS
  p_result       SYS.ODCIVARCHAR2LIST := SYS.ODCIVARCHAR2LIST();
  p_start        NUMBER(5) := 1;
  p_end          NUMBER(5);
  c_len CONSTANT NUMBER(5) := LENGTH( i_str );
  c_ld  CONSTANT NUMBER(5) := LENGTH( i_delim );
BEGIN
  IF c_len &gt; 0 THEN
    p_end := INSTR( i_str, i_delim, p_start );
    WHILE p_end &gt; 0 LOOP
      p_result.EXTEND;
      p_result( p_result.COUNT ) := SUBSTR( i_str, p_start, p_end - p_start );
      p_start := p_end + c_ld;
      p_end := INSTR( i_str, i_delim, p_start );
    END LOOP;
    IF p_start &lt;= c_len + 1 THEN
      p_result.EXTEND;
      p_result( p_result.COUNT ) := SUBSTR( i_str, p_start, c_len - p_start + 1 );
    END IF;
  END IF;
  RETURN p_result;
END;
/

FROM   TBL1 t,

Solution 7: XML and JSON Table Functions

Modern database systems offer built-in XML and JSON processing capabilities that can be cleverly repurposed for string splitting. These methods are often efficient for well-formed delimited strings.

  • Using XMLTABLE:

    SELECT
    t.id,
    TRIM(xmlcast(column_value AS VARCHAR2(100))) AS value_item
FROM
    tbl1 t,
    XMLTABLE('/r/v'
        PASSING XMLTYPE('<r><v>' || REPLACE(t.value, ',', '</v><v>') || '</v></r>')
        COLUMNS v VARCHAR2(100) PATH '.'
    );

  • Using JSON_TABLE:

    SELECT
    t.id,
    TRIM(v.value_item) AS value_item
FROM
    tbl1 t,
    JSON_TABLE(
        '["' || REPLACE(t.value, ',', '","') || '"]',
        '$[*]' COLUMNS (value_item VARCHAR2(100) PATH '$')
    );

These methods construct temporary XML or JSON structures on the fly, which are then parsed into rows. Proper handling of special characters within the delimited values is important for these approaches to work reliably.

Performance Considerations

Performance can vary significantly based on the dataset size, the number of elements per string, the database version, and the specific SQL dialect.

  • Recursive CTEs and CONNECT BY are generally efficient but can have varying performance characteristics. The CONNECT BY approach, especially when optimized with PRIOR id = id, tends to perform well.
  • PL/SQL Functions offer encapsulation and can be highly optimized, but there’s an overhead associated with function calls.
  • XMLTABLE and JSON_TABLE can be very fast for simple data structures, but the overhead of XML/JSON parsing might become noticeable with very complex or deeply nested data.
  • MODEL clause is powerful but can be less intuitive to write and optimize compared to other methods.

Extensive testing with representative data is crucial to determine the optimal solution for your specific environment. For instance, a study involving a 30,000-row dataset indicated that recursive methods without regex often provided the best performance, sometimes outperforming CONNECT BY by a significant margin.

FAQs on SQL String Splitting

Q: How to split a comma separated string in SQL

ANS: You can split a comma-separated string in SQL using various methods. Popular techniques include using hierarchical queries with CONNECT BY and REGEXP_SUBSTR, recursive Common Table Expressions (CTEs), built-in XMLTABLE or JSON_TABLE functions, or custom PL/SQL functions. Each method has trade-offs in terms of performance and compatibility.

Q: Which SQL string splitting method is fastest

ANS: The fastest method depends heavily on your database system, data volume, and the specific structure of your delimited strings. Benchmarking with your actual data is the most reliable way to determine the optimal solution. Generally, optimized recursive queries or built-in table functions like XMLTABLE or JSON_TABLE tend to perform well.

Q: Can I split a string without using regular expressions in SQL

ANS: Yes, you can split strings without regular expressions by using functions like INSTR to find delimiters and SUBSTR to extract segments. Recursive CTEs or CONNECT BY clauses can be adapted to use these functions for iterative string splitting.

Q: How to get the order of split values in SQL

ANS: To get the order of split values, you can include a counter or use window functions like ROW_NUMBER() during the splitting process. For example, when using CONNECT BY, the LEVEL pseudocolumn provides the order. When using CTEs or table functions, you can maintain a counter in the recursive step or use ROW_NUMBER() OVER (PARTITION BY id ORDER BY ROWNUM).

Q: What are the limitations of splitting strings in SQL

ANS: Limitations can include performance degradation on very large datasets or strings with many delimiters, complexity in handling edge cases like empty values between delimiters or leading/trailing delimiters, and the need for specific database features or functions (like REGEXP_SUBSTR or JSON/XML support) which might not be universally available.
