“Oracle SQL Multiple Row Inserts: Efficient Strategies Explained”

When working with Oracle databases, inserting numerous records into a table is a frequent task. Efficiently handling these operations can significantly impact application performance. This discussion explores several effective strategies for inserting multiple rows into an Oracle table, catering to different scenarios and data volumes.

Solution 1: INSERT ALL Statement (Pre-Oracle 23c)

For inserting multiple rows with individual value sets, the INSERT ALL statement is a versatile option. This method allows you to specify multiple INTO clauses, each defining a row to be inserted.

Consider a table t with columns col1, col2, and col3. The syntax for inserting multiple rows would be:

INSERT ALL
   INTO t (col1, col2, col3) VALUES ('value1_1', 'value1_2', 'value1_3')
   INTO t (col1, col2, col3) VALUES ('value2_1', 'value2_2', 'value2_3')
   INTO t (col1, col2, col3) VALUES ('value3_1', 'value3_2', 'value3_3')
   -- ... continue for more rows
SELECT 1 FROM DUAL;

Solution 1.1: INSERT INTO ... VALUES ..., ... (Oracle 23c and later)

Oracle Database 23c introduced a more concise syntax for inserting multiple rows, making it simpler and often more performant for large datasets compared to the INSERT ALL or UNION ALL approaches.

The simplified syntax is:

INSERT INTO t(col1, col2, col3) VALUES
('value1_1', 'value1_2', 'value1_3'),
('value2_1', 'value2_2', 'value2_3'),
('value3_1', 'value3_2', 'value3_3');

This new syntax is particularly beneficial for inserting a large number of rows, offering superior speed over older methods. However, it’s advisable to avoid inserting more than approximately 1000 rows in a single statement to prevent potential parse time increases.

Solution 2: UNION ALL with SELECT FROM DUAL

Another common approach for inserting multiple rows involves using UNION ALL with SELECT statements from the DUAL pseudo-table. This method is compatible with older Oracle versions.

To insert rows into a pager table with columns PAG_ID, PAG_PARENT, PAG_NAME, and PAG_ACTIVE, you can use:

insert into pager (PAG_ID, PAG_PARENT, PAG_NAME, PAG_ACTIVE)
          select 8000, 0, 'Multi Row 8000', 1 from dual
union all select 8001, 0, 'Multi Row 8001', 1 from dual;

The key here is the consistent use of FROM DUAL for each row you are selecting.

Solution 3: SQL*Loader

For bulk data loading from external files, SQL*Loader is a powerful and efficient utility. It requires a control file to define the data format and the target table. This is an excellent choice for one-off large imports or recurring batch data loading.

1. Create the Target Table:

SQL> create table ldr_test (id number(10) primary key, description varchar2(20));
Table created.
SQL>

2. Prepare the Data File (e.g., ldr_test.csv):

1,Apple
2,Orange
3,Pear

3. Create the SQL*Loader Control File (e.g., ldr_test.ctl):

load data
 infile 'ldr_test.csv'
 into table ldr_test
 fields terminated by "," optionally enclosed by '"'
 ( id, description )

4. Execute SQL*Loader:

sqlldr <username> control=ldr_test.ctl
Password:

5. Verify the Insert:

SQL> select * from ldr_test;

        ID DESCRIPTION

Solution 4: PL/SQL Block with a Local Procedure

A PL/SQL block can be structured with a local procedure to encapsulate the insert logic for multiple rows. This approach offers flexibility, especially when inserting data with complex logic or deriving values programmatically.

declare
   procedure insert_exchange_rate (
       p_exch_wh_key INTEGER,
       p_exch_nat_key INTEGER,
       p_exch_date DATE,
       p_exch_rate NUMBER,
       p_from_curcy_cd VARCHAR2,
       p_to_curcy_cd VARCHAR2,
       p_exch_eff_date DATE,
       p_exch_eff_end_date DATE,
       p_exch_last_updated_date DATE
   )
   is
   begin
      insert into tmp_dim_exch_rt
      (exch_wh_key, exch_nat_key, exch_date, exch_rate, from_curcy_cd,
       to_curcy_cd, exch_eff_date, exch_eff_end_date, exch_last_updated_date)
      values
      (p_exch_wh_key, p_exch_nat_key, p_exch_date, p_exch_rate, p_from_curcy_cd,
       p_to_curcy_cd, p_exch_eff_date, p_exch_eff_end_date, p_exch_last_updated_date);
   end;
begin
   insert_exchange_rate(1, 1, DATE'2008-08-28', 109.49, 'USD', 'JPY', DATE'2008-08-28', DATE'2008-08-28', DATE'2008-08-28');
   insert_exchange_rate(2, 1, DATE'2008-08-28', 0.54, 'USD', 'GBP', DATE'2008-08-28', DATE'2008-08-28', DATE'2008-08-28');
   insert_exchange_rate(3, 1, DATE'2008-08-28', 1.05, 'USD', 'CAD', DATE'2008-08-28', DATE'2008-08-28', DATE'2008-08-28');
   insert_exchange_rate(4, 1, DATE'2008-08-28', 0.68, 'USD', 'EUR', DATE'2008-08-28', DATE'2008-08-28', DATE'2008-08-28');

Solution 5: INSERT INTO ... SELECT

If the data to be inserted already exists in another table, the INSERT INTO ... SELECT statement is the most efficient method.

INSERT INTO a_table (column_a, column_b)
SELECT column_a, column_b FROM b_table;

For situations where data is not in another table, you can combine multiple single-row inserts and submit them in bulk, which works across both Oracle and MySQL.

Solution 6: Loop with INSERT INTO ... SELECT FROM DUAL

For inserting a dynamic number of rows, such as random values up to a certain limit, a loop construct within PL/SQL can be utilized.

BEGIN
    FOR x IN 1 .. 1000 LOOP
         INSERT INTO MULTI_INSERT_DEMO (ID, NAME)
         SELECT x, 'Demo Name ' || x FROM dual;
    END LOOP;
END;

Solution 7: Cursors (Generally Inefficient for Bulk Inserts)

While cursors can be used for row-by-row processing, they are generally less efficient for bulk inserts compared to set-based operations. For more on cursor usage, refer to discussions on insert and update using cursors in Oracle .

Solution 8: Advanced INSERT ALL with WITH Clause

The INSERT ALL statement can be combined with Common Table Expressions (CTEs) using the WITH clause for sophisticated data insertion scenarios, including conditional inserts into multiple tables.

INSERT ALL
/* Insert all rows into the people table */
WHEN 1=1 THEN
INTO people (person_id, given_name, family_name, title)
VALUES (id, given_name, family_name, title)
/* Insert into patients table only if admission_date is not null */
WHEN admission_date IS NOT NULL THEN
INTO patients (patient_id, last_admission_date)
VALUES (id, admission_date)
/* Insert into staff table only if hired_date is not null */
WHEN hired_date IS NOT NULL THEN
INTO staff (staff_id, hired_date)
VALUES (id, hired_date)
  WITH person_data AS (
    SELECT 4 id, 'Ruth' given_name, 'Fox' family_name, 'Mrs' title,
           NULL hired_date, DATE'2009-12-31' admission_date
    FROM   dual UNION ALL
    SELECT 5 id, 'Isabelle' given_name, 'Squirrel' family_name, 'Miss' title ,
           NULL hired_date, DATE'2014-01-01' admission_date
    FROM   dual UNION ALL
    SELECT 6 id, 'Justin' given_name, 'Frog' family_name, 'Mr' title,
           NULL hired_date, DATE'2015-04-22' admission_date
    FROM   dual UNION ALL
    SELECT 7 id, 'Lisa' given_name, 'Owl' family_name, 'Dr' title,
           DATE'2015-01-01' hired_date, NULL admission_date
    FROM   dual
  )
  SELECT * FROM person_data;

Solution 9: INSERT INTO ... SELECT with Sequence and Hardcoded Values

When inserting data into a table where some columns require sequence-generated values and others are static, you can use the INSERT INTO ... SELECT statement.

INSERT INTO table_a (
    id,
    column_a,
    column_b
)
    SELECT
        table_a_seq.NEXTVAL,
        b.name,
        123 -- A hardcoded value
    FROM
        table_b b;

This would result in records like:

ID: NAME: CODE:
1, JOHN, 123
2, SAM, 123
3, JESS, 123

FAQs on Oracle Multiple Row Inserts

Q How do I insert many rows into an Oracle table

ANS You can use methods like INSERT ALL, INSERT INTO … VALUES …, UNION ALL with SELECT FROM DUAL, SQL*Loader, PL/SQL loops, or INSERT INTO … SELECT statements depending on your data source and Oracle version.

Q What is the fastest way to insert multiple rows in Oracle

ANS For Oracle 23c and later, the INSERT INTO ... VALUES (), (), () syntax is highly efficient. For earlier versions or specific bulk loading needs, SQL*Loader or INSERT ALL with a WITH clause can also offer excellent performance.

Q Can I insert rows from one table to another in Oracle

ANS Yes, you can use the INSERT INTO target_table SELECT ... FROM source_table; statement for this purpose.

Q Is there a limit to how many rows I can insert at once in Oracle

ANS While Oracle doesn’t impose a hard limit on the number of rows per INSERT statement, performance can degrade with very large batches due to parsing overhead. It is generally recommended to insert up to around 1000 rows at a time with modern syntax, or use SQL*Loader for significantly larger datasets.
