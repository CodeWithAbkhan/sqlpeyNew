“Oracle SQL: Efficiently Search for Values Across All Tables and Columns”

When faced with the task of locating a particular piece of data across your entire Oracle database, especially when the exact table and column are unknown, a systematic approach is crucial. Directing a broad search requires careful construction of SQL or PL/SQL statements to query metadata and then dynamically execute checks.

Initial Approach: Querying Metadata

A common starting point involves querying Oracle’s data dictionary views to identify candidate tables and columns. The ALL_TAB_COLUMNS view is instrumental here, providing details about all columns accessible to the current user.

If you have a general idea of the column naming convention, you might begin with a query like this:

SELECT owner, table_name, column_name
FROM all_tab_columns
WHERE column_name LIKE '%DTN%';

However, this only helps if you can guess the column name. The true challenge arises when the column name is unknown, or the target value might reside in columns with diverse names. Furthermore, a column name is not a direct container for a value; it’s the data within that column that holds your interest.

A more robust strategy involves iterating through columns, checking their data types, and then performing a conditional search.

Advanced Search Techniques: PL/SQL Iteration

For a more thorough search, particularly for character-based data, you can leverage PL/SQL to construct and execute dynamic SQL statements. This allows you to programmatically check each relevant column.

Solution 1: Iterating Through Character Columns

This PL/SQL block iterates through all character-type columns (excluding those owned by SYS) and counts occurrences of a specified search string.

SET SERVEROUTPUT ON SIZE 100000

DECLARE
  match_count INTEGER;
BEGIN
  FOR t IN (SELECT owner, table_name, column_name
              FROM all_tab_columns
              WHERE owner <> 'SYS' AND data_type LIKE '%CHAR%') LOOP

    EXECUTE IMMEDIATE
      'SELECT COUNT(*) FROM ' || t.owner || '.' || t.table_name ||
      ' WHERE '||t.column_name||' = :1'
      INTO match_count
      USING '1/22/2008P09RR8'; -- Replace with your search string

    IF match_count > 0 THEN
      dbms_output.put_line(t.table_name ||' '||t.column_name||' '||match_count );
    END IF;

  END LOOP;
END;
/

Optimization Considerations:

  • Data Type Filtering: You can significantly improve performance by filtering columns based on their data types. For instance, if you’re searching for a string, you can exclude NUMBER, DATE, or BLOB columns.

  • Table-Level Queries: Instead of one query per column, you could construct a single, larger query per table that checks multiple columns using OR conditions. This can sometimes be more efficient, depending on the number of columns per table.

    SELECT * FROM table1
  WHERE column1 = 'value'
     OR column2 = 'value'
     OR column3 = 'value'
     ...
     ;

Solution 2: Targeted Search by Owner

If you know the owner of the tables you want to search, you can refine the search by specifying the owner, data type, and search string as variables.

SET SERVEROUTPUT ON SIZE 100000

DECLARE
  match_count INTEGER;
  v_owner VARCHAR2(255) := 'ENTER_USERNAME_HERE'; -- Specify the schema owner
  v_data_type VARCHAR2(255) := 'VARCHAR2';       -- Specify the data type
  v_search_string VARCHAR2(4000) := 'string to search here...'; -- Your target string
BEGIN
  FOR t IN (SELECT table_name, column_name FROM all_tab_cols where owner=v_owner and data_type = v_data_type) LOOP
    EXECUTE IMMEDIATE
    'SELECT COUNT(*) FROM ' || t.table_name || ' WHERE ' || t.column_name || ' = :1'
    INTO match_count
    USING v_search_string;

    IF match_count > 0 THEN
      dbms_output.put_line(t.table_name ||' '||t.column_name||' '||match_count );
    END IF;
  END LOOP;
END;
/

Solution 3: SQL-Based Search with XMLTYPE

For those preferring a pure SQL approach, dynamic SQL can be combined with XMLTYPE and DBMS_XMLGEN to search for values. This method can be more complex but avoids explicit PL/SQL loops for the primary search logic.

-- Search for a character type
SELECT DISTINCT SUBSTR (:val, 1, 11) "Searchword",
  SUBSTR (table_name, 1, 14) "Table",
  SUBSTR (column_name, 1, 14) "Column"
FROM cols,
  TABLE (xmlsequence (dbms_xmlgen.getxmltype ('select '
  || column_name
  || ' from '
  || table_name
  || ' where upper('
  || column_name
  || ') like upper(''%'
  || :val
  || '%'')' ).extract ('ROWSET/ROW/*') ) ) t
ORDER BY "Table";

-- Example usage:
-- variable val varchar2(10)
-- exec :val := 'KING'

This approach constructs a query for each column and then uses XML processing to flatten the results.

Solution 4: Case-Insensitive Search with LOWER

To perform a case-insensitive search, you can incorporate the LOWER function in your dynamic SQL.

DECLARE
  match_count INTEGER;
  v_owner VARCHAR2(255) := 'USER'; -- Specify the owner
  v_data_type VARCHAR2(255) := 'VARCHAR2'; -- Specify the data type
  v_search_string VARCHAR2(4000) := 'Test'; -- Your target string
BEGIN
  dbms_output.put_line( 'Starting the search...' );
  FOR t IN (SELECT table_name, column_name FROM all_tab_cols where owner=v_owner and data_type = v_data_type) LOOP
    EXECUTE IMMEDIATE
    'SELECT COUNT(*) FROM '||t.table_name||' WHERE LOWER('||t.column_name||') LIKE :1'
    INTO match_count
    USING LOWER('%'||v_search_string||'%'); -- Case-insensitive search
    IF match_count > 0 THEN
      dbms_output.put_line( t.table_name ||' '||t.column_name||' '||match_count );
    END IF;
  END LOOP;
END;

Solution 5: Enhanced PL/SQL for Detailed Output

This more elaborate PL/SQL procedure not only counts matches but also retrieves and displays the actual matching rows, making the search results more informative. It utilizes DBMS_SQL for dynamic cursor handling.

SET SERVEROUTPUT ON SIZE 100000

DECLARE
  v_owner VARCHAR2(255) := 'ENTER_USERNAME_HERE'; -- Specify the owner
  v_data_type VARCHAR2(255) := 'VARCHAR2';       -- Specify the data type
  v_search_string VARCHAR2(4000) := 'string to search here...'; -- Your target string

BEGIN
  FOR t IN (
    SELECT DISTINCT table_name, column_name
    FROM all_tab_cols
    WHERE owner = v_owner
      AND UPPER(data_type) = UPPER(v_data_type)
  ) LOOP
    DECLARE
      match_count INTEGER;
    BEGIN
      -- Count matching rows
      EXECUTE IMMEDIATE
        'SELECT COUNT(*) FROM "' || v_owner || '"."' || t.table_name || '" WHERE "' || t.column_name || '" = :1'
        INTO match_count
        USING v_search_string;

      IF match_count > 0 THEN
        dbms_output.put_line('Table: ' || t.table_name || ', Column: ' || t.column_name || ', Matches: ' || match_count);
        dbms_output.put_line('*************************************************************');

        -- Fetch and display matching rows
        DECLARE
          cursor_handle   INTEGER;
          col_cnt         INTEGER;
          desc_tab        DBMS_SQL.DESC_TAB2;
          v_status        INTEGER;
          v_row_output    VARCHAR2(32767);
        BEGIN
          cursor_handle := DBMS_SQL.OPEN_CURSOR;

          DBMS_SQL.PARSE(cursor_handle,
            'SELECT * FROM "' || v_owner || '"."' || t.table_name || '" WHERE "' || t.column_name || '" = :1',
            DBMS_SQL.NATIVE);

          DBMS_SQL.BIND_VARIABLE(cursor_handle, ':1', v_search_string);
          DBMS_SQL.DESCRIBE_COLUMNS2(cursor_handle, col_cnt, desc_tab);

          FOR i IN 1 .. col_cnt LOOP
            IF desc_tab(i).col_type = 2 THEN -- NUMBER
              DBMS_SQL.DEFINE_COLUMN(cursor_handle, i, TO_NUMBER(NULL));
            ELSIF desc_tab(i).col_type = 12 THEN -- DATE
              DBMS_SQL.DEFINE_COLUMN(cursor_handle, i, TO_DATE(NULL));
            ELSE -- Default to VARCHAR2
              DBMS_SQL.DEFINE_COLUMN(cursor_handle, i, TO_CHAR(NULL), 4000);
            END IF;
          END LOOP;

          v_status := DBMS_SQL.EXECUTE(cursor_handle);

          WHILE DBMS_SQL.FETCH_ROWS(cursor_handle) > 0 LOOP
            v_row_output := '';
            FOR i IN 1 .. col_cnt LOOP
              IF desc_tab(i).col_type = 2 THEN
                DECLARE v_num NUMBER; BEGIN DBMS_SQL.COLUMN_VALUE(cursor_handle, i, v_num); v_row_output := v_row_output || desc_tab(i).col_name || ': ' || TO_CHAR(v_num) || ', '; END;
              ELSIF desc_tab(i).col_type = 12 THEN
                DECLARE v_date DATE; BEGIN DBMS_SQL.COLUMN_VALUE(cursor_handle, i, v_date); v_row_output := v_row_output || desc_tab(i).col_name || ': ' || TO_CHAR(v_date, 'YYYY-MM-DD HH24:MI:SS') || ', '; END;
              ELSE
                DECLARE v_str VARCHAR2(4000); BEGIN DBMS_SQL.COLUMN_VALUE(cursor_handle, i, v_str); v_row_output := v_row_output || desc_tab(i).col_name || ': ' || v_str || ', '; END;
              END IF;
            END LOOP;
            v_row_output := RTRIM(v_row_output, ', ');
            dbms_output.put_line(v_row_output);
          END LOOP;
         dbms_output.put_line('

## Solutions
');
          DBMS_SQL.CLOSE_CURSOR(cursor_handle);
        EXCEPTION
          WHEN OTHERS THEN
            IF DBMS_SQL.IS_OPEN(cursor_handle) THEN DBMS_SQL.CLOSE_CURSOR(cursor_handle); END IF;
            RAISE;
        END;
      END IF;
    EXCEPTION
      WHEN NO_DATA_FOUND THEN NULL;
      WHEN OTHERS THEN dbms_output.put_line('Error processing ' || t.table_name || '.' || t.column_name || ': ' || SQLERRM);
    END;
  END LOOP;
END;
/

Alternative Strategies and Tools

Solution 6: Generating SELECT Statements

You can script the generation of SELECT statements that check each column for a given value. This output can then be fed into a SQL client.

echo "select table_name from user_tables;" | sqlplus -S user/pwd | grep -v "^--" | grep -v "TABLE_NAME" | grep "^[A-Z]" | while read sw;
do echo "desc $sw" | sqlplus -S user/pwd | grep -v "\-\-\-\-\-\-" | awk -F' ' '{print $1}' | while read nw;
do echo "select * from $sw where $nw='val'";
done;
done;

This generates SQL like select * from TBL1 where DESCRIPTION='val'.

Solution 7: Oracle’s LIKE Operator

The LIKE operator is fundamental for pattern matching within string data in Oracle SQL.

  • %: Matches any sequence of zero or more characters. 
    SELECT last_name
   FROM   customer_tab
   WHERE  last_name LIKE '%A%'; -- Finds names containing 'A'
  • _: Matches any single character. 
    SELECT last_name
   FROM   customer_tab
   WHERE  last_name LIKE 'A_t'; -- Finds names starting with 'A', then any character, then 't'

Solution 8: Third-Party Tools and GUI Clients

Tools like Toad, PL/SQL Developer, or free utilities such as DB Search (requiring an Oracle ODBC driver and DSN) offer integrated search functionalities that can simplify this process, often with a user-friendly interface.

Important Considerations for Performance:

  • Schema Scope: Limit your search to specific schemas if possible, rather than the entire database, to reduce query execution time.
  • Data Type Restrictions: As mentioned, filtering by data_type (e.g., focusing on VARCHAR2 or CHAR types) is a critical performance tuning step.
  • Indexing: While direct indexing for full-text search across all columns isn’t standard, ensuring that columns frequently queried have appropriate indexes can indirectly speed up related operations.
  • Database Load: Running extensive search queries across a large database can impact performance. It’s best to execute these during off-peak hours.

Finding data across an entire database schema is a common but potentially resource-intensive task. By employing dynamic SQL with careful filtering and optimization, you can effectively locate your data.

FAQs on Oracle SQL Search

Q: How to find a specific string in all columns of an Oracle schema

ANS: Use PL/SQL to iterate through ALL_TAB_COLUMNS, construct dynamic SELECT COUNT(*) statements for character-based columns, and execute them. You can also leverage DBMS_XMLGEN with XMLTYPE for a SQL-centric approach. For case-insensitivity, employ the LOWER function.

Q: Can I search for numbers across all tables in Oracle

ANS: Yes, modify the PL/SQL or SQL scripts to target NUMBER data types and use equality (=) or range comparisons instead of LIKE.

Q: Is there a performance impact when searching all columns

ANS: Yes, performing a full table scan across many columns and tables can be I/O intensive and affect database performance. It’s advisable to filter by owner and data type, and run during off-peak hours.

Q: What if the value is in a LOB or BLOB column

ANS: Searching within LOB (Large Object) or BLOB (Binary Large Object) columns is more complex. For text within LOBs, you might need functions like DBMS_LOB.SUBSTR or INSTR within your dynamic SQL. Searching binary data in BLOBs typically requires specialized tools or custom logic.

Q: How to find a value without knowing the table name

ANS: Query ALL_TAB_COLUMNS or USER_TAB_COLUMNS to get a list of all tables and columns, then dynamically build and execute queries against each candidate.
