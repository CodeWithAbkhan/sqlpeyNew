The primary ways to achieve this are through the CASE statement and, in newer versions of SQL Server, the IIF function. Let’s delve into how these work and when to use them.

SQL Conditional Logic: CASE vs. IIF for IF-THEN-ELSE Statements

The CASE Statement: Your Versatile Conditional Tool

The CASE statement is a standard SQL construct that provides robust conditional logic. It can handle multiple conditions and offers two main forms:

  1. Simple CASE: This form compares a variable or expression against a series of specific values.

    SELECT CASE <variable>
           WHEN <value1> THEN <result1>
           WHEN <value2> THEN <result2>
           ELSE <default_result>
       END AS <new_column_name>
FROM <your_table>;

  2. Extended CASE: This form evaluates a series of boolean expressions.

    SELECT CASE
           WHEN <condition1> THEN <result1>
           WHEN <condition2> THEN <result2>
           ELSE <default_result>
       END AS <new_column_name>
FROM <your_table>;

CASE statements are incredibly flexible. They can be embedded within other CASE statements and even used within aggregate functions, making them powerful for complex data manipulation.

Practical Example (Extended CASE):

Imagine a Product table where you want to determine if a product is “Saleable” based on whether it’s not obsolete (Obsolete = 'N') or if it’s in stock (InStock = 'Y').

SELECT
    CASE
        WHEN Obsolete = 'N' OR InStock = 'Y' THEN 1
        ELSE 0
    END AS Saleable,
    *
FROM Product;

If you prefer a boolean output rather than an integer (1 or 0), you can cast the result:

SELECT CAST(
    CASE
        WHEN Obsolete = 'N' OR InStock = 'Y' THEN 1
        ELSE 0
    END AS BIT
) AS Saleable, *
FROM Product;

Example with Multiple Conditions:

This example demonstrates how CASE can be used to derive a value based on different conditions, such as assigning a specific contact based on a regulating agency.

SELECT
    CASE RegulatingAgencyName
        WHEN 'Region 1' THEN ContactState
        WHEN 'Region 2' THEN ContactState
        WHEN 'Region 3' THEN ContactState
        WHEN 'DEPT OF AGRICULTURE' THEN ContactAg
        ELSE (
            CASE IsContract
                WHEN 1 THEN ContactCounty
                ELSE ContactState
            END
        )
    END AS [County Contact Name]
FROM Inventory
JOIN CountyStateAgContactInfo ON Inventory.AgencyID = CountyStateAgContactInfo.AgencyID;

The IIF Function: A Concise Alternative (SQL Server 2012+)

For SQL Server 2012 and later versions, the IIF function provides a more concise way to express simple IF-THEN-ELSE logic. It takes three arguments: a condition, a value if the condition is true, and a value if the condition is false.

SELECT IIF(<condition>, <true_value>, <false_value>) AS <new_column_name>;

Practical Example using IIF:

Using the same “Saleable” product scenario:

SELECT IIF(Obsolete = 'N' OR InStock = 'Y', 1, 0) AS Saleable, *
FROM Product;

Key Considerations for IIF vs. CASE:

  • Conciseness: IIF is often shorter for simple, single conditions.
  • Readability: For multiple nested conditions, CASE tends to be more readable and maintainable.
  • Standardization: CASE is standard SQL and supported across most database systems, while IIF is specific to SQL Server (and some other platforms like Access).
  • Execution Flow Control: Neither CASE nor IIF can control the flow of execution of Transact-SQL statements, blocks, functions, or procedures. For that, you would use the procedural IF keyword.

Procedural IF for Statement Control

If you need to control the execution flow of entire SQL statements based on a condition, you must use the procedural IF keyword. This is typically used within stored procedures, functions, or batches.

DECLARE @IncludeExtendedInformation BIT = 1;

IF @IncludeExtendedInformation = 1
BEGIN
    SELECT ColumnA, ColumnB, ColumnC, ColumnX, ColumnY, ColumnZ
    FROM YourTable;
END
ELSE
BEGIN
    SELECT ColumnA, ColumnB, ColumnC
    FROM YourTable;
END
GO

Alternative Approaches

While CASE and IIF are the most common, other methods exist:

  • Bitwise Logic: For specific scenarios, bitwise operators can be employed, especially when dealing with boolean-like representations.

    -- Example showing bitwise logic for Saleable status
WITH Cte AS (
    SELECT
        'CheckIfInstock'  = CAST(ISNULL(NULLIF(p.[Instock], 'Y'), 1) AS BIT),
        'CheckIfObsolote' = CAST(ISNULL(NULLIF(p.[Obsolete], 'N'), 0) AS BIT),
        p.*
    FROM Product p
)
SELECT
    'Saleable' = c.[CheckIfInstock] & ~c.[CheckIfObsolote],
    c.*
FROM Cte c;

    This approach uses NULLIF to convert values to 1 or 0, then bitwise AND (&) and NOT (~) to achieve the desired logic, effectively simulating IF-THEN-ELSE.

  • Table-Driven Logic: For very complex or frequently changing conditional mappings, a separate “lookup” table can be used with JOIN operations.

    SELECT P.*, ISNULL(Stmt.Saleable, 0) AS Saleable
FROM Product P
LEFT JOIN (
    VALUES ('N', 'Y', 1)
) AS Stmt (Obsolete, InStock, Saleable)
ON P.InStock = Stmt.InStock OR P.Obsolete = Stmt.Obsolete;

    This method uses a VALUES clause to define the “rules” and joins them to the main table, offering a clean way to manage complex conditions.

Three-Valued Logic in SQL

It’s important to remember that SQL uses three-valued logic (TRUE, FALSE, and UNKNOWN/NULL). When combining conditions with OR or AND, the presence of NULL values can lead to unexpected NULL results if not handled carefully.

For instance, Obsolete = 'N' OR InStock = 'Y' might evaluate to NULL if either Obsolete or InStock is NULL. To manage this, you can explicitly handle NULLs within your CASE statement.

SELECT
    CASE
        WHEN Obsolete = 'N' OR InStock = 'Y' THEN 'true'
        WHEN NOT (Obsolete = 'N' OR InStock = 'Y') THEN 'false'
        ELSE 'unknown' -- Explicitly handle NULL results
    END AS Saleable
FROM Product;

-- Treating NULLs as 'false'
SELECT
    CASE
        WHEN Obsolete = 'N' OR InStock = 'Y' THEN 'true'
        ELSE 'false' -- Catches both FALSE and NULL
    END AS Saleable
FROM Product;

Whether you choose CASE or IIF often depends on the complexity of your condition and the SQL Server version you are using. For most scenarios, CASE offers the greatest flexibility and compatibility.

FAQs on SQL Conditional Logic

Q: What is the primary SQL construct for implementing IF-THEN-ELSE logic in SELECT statements

ANS: The CASE statement is the primary and most versatile SQL construct for implementing IF-THEN-ELSE logic within SELECT statements. It supports multiple conditions and a default ELSE clause.

Q: When was the IIF function introduced in SQL Server

ANS: The IIF function was introduced in SQL Server 2012.

Q: Can CASE or IIF control the execution flow of SQL statements

ANS: No, neither the CASE statement nor the IIF function can control the execution flow of Transact-SQL statements, blocks, functions, or procedures. For that, you need to use the procedural IF keyword.

Q: Is IIF a standard SQL feature

ANS: No, IIF is not a standard SQL feature. The CASE statement is the standard SQL way to handle conditional logic.

Q: How does SQL handle conditions involving NULL values

ANS: SQL uses three-valued logic (TRUE, FALSE, UNKNOWN/NULL). Conditions involving NULL might evaluate to UNKNOWN. You need to explicitly handle NULLs, often by using IS NULL checks or by deciding how to treat NULL in your CASE or IIF statements.
