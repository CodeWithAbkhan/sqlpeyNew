“PostgreSQL: Split String to Rows with Ordinal Position”

When working with PostgreSQL, you often encounter scenarios where a column contains delimited strings (like comma-separated values) that need to be transformed into individual rows. Crucially, you might also need to preserve the original order of these elements and assign an ordinal position to each. This question delves into various methods for achieving this, covering different PostgreSQL versions and offering practical code examples.

Core Problem: De-normalizing Delimited Strings

The fundamental challenge is to take a single row with a string like 'apple,banana,cherry' and convert it into multiple rows, each containing one element and its position:

| id | elem | nr | | :– | :

Solutions

– | :- | | 123 | apple | 1 | | 123 | banana | 2 | | 123 | cherry | 3 |

Solution 1: string_to_table() with WITH ORDINALITY (Postgres 14+)

For PostgreSQL 14 and later, the string_to_table() function offers a direct and efficient way to split strings. Combined with WITH ORDINALITY, it elegantly handles the positional numbering.

SELECT
    t.id,
    a.elem,
    a.nr
FROM
    your_table t
LEFT JOIN LATERAL
    string_to_table(t.elements, ',') WITH ORDINALITY AS a(elem, nr) ON true;
  • string_to_table(t.elements, ','): This function splits the elements column by the comma delimiter, producing a set of rows.
  • WITH ORDINALITY AS a(elem, nr): This appends a generated column nr (starting from 1) to the output of string_to_table, effectively providing the ordinal position.
  • LEFT JOIN LATERAL ... ON true: This ensures that all rows from the original table are retained, even if the elements column is empty or NULL.

Solution 2: unnest() and string_to_array() with WITH ORDINALITY (Postgres 9.4+)

For PostgreSQL versions 9.4 and above, the unnest() function, when used with string_to_array(), provides a robust solution. The WITH ORDINALITY clause is key here for obtaining the position.

SELECT
    t.id,
    a.elem,
    a.nr
FROM
    your_table AS t
LEFT JOIN LATERAL
    unnest(string_to_array(t.elements, ',')) WITH ORDINALITY AS a(elem, nr) ON true;

Alternative Syntax (Implicit CROSS JOIN LATERAL)

If preserving all rows from the left table is not a strict requirement, a more concise syntax can be used:

SELECT
    t.id,
    a.elem,
    a.nr
FROM
    your_table t,
    unnest(string_to_array(t.elements, ',')) WITH ORDINALITY a(elem, nr);

Working with Actual Array Columns

If your data is already stored as an array in a column (e.g., arr), the process is even simpler:

SELECT
    t.id,
    a.elem,
    a.nr
FROM
    your_table t,
    unnest(t.arr) WITH ORDINALITY a(elem, nr);

For even more brevity, you can let PostgreSQL use default aliases:

SELECT
    id,
    a,
    ordinality
FROM
    your_table,
    unnest(arr) WITH ORDINALITY a;

Or, using a.* to select all columns from the unnested result:

SELECT
    id,
    a.*
FROM
    your_table,
    unnest(arr) WITH ORDINALITY a;

The last example will select all columns from your_table plus the generated elem and ordinality columns from the unnest operation.

Solution 3: regexp_split_to_table() with row_number() (Postgres 9.4+)

Another approach for versions 9.4 and later involves using regexp_split_to_table() in a subquery and then applying the row_number() window function. This method is useful if you need to ensure row numbering based on a specific ordering, although it can be less direct than WITH ORDINALITY.

SELECT
    t.id,
    a.elem,
    ROW_NUMBER() OVER (PARTITION BY t.id ORDER BY a.elem) AS nr
FROM
    (SELECT id, regexp_split_to_table(elements, ',') AS elem FROM your_table) t
LEFT JOIN LATERAL
    unnest(string_to_array(t.elements, ',')) WITH ORDINALITY AS a(elem, nr) ON true; -- This part is illustrative; row_number() is the primary focus here

Important Note on ORDER BY: While omitting ORDER BY in ROW_NUMBER() might appear to work due to implementation details, PostgreSQL does not guarantee row order without an explicit ORDER BY clause.

Guaranteed Ordinal Numbers for Space-Separated Strings

To strictly guarantee ordinal numbers for space-separated strings, you can combine string_to_array() with generate_subscripts():

SELECT
    id,
    arr[nr] AS elem,
    nr
FROM
    (
        SELECT
            id,
            arr,
            generate_subscripts(arr, 1) AS nr
        FROM
            (SELECT id, string_to_array(elements, ' ') AS arr FROM your_table) AS subquery_alias
    ) AS main_query_alias;

For actual array columns, this simplifies to:

SELECT
    id,
    arr[nr] AS elem,
    nr
FROM
    (SELECT id, arr, generate_subscripts(arr, 1) AS nr FROM your_table) AS t;

Solution 4: Using Subscript Generating Functions (Postgres 9.4+)

PostgreSQL’s subscript generating functions provide a powerful way to handle array elements. You can use generate_subscripts() in conjunction with splitting the string into an array.

SELECT
    id,
    elements[i] AS elem,
    i AS nr
FROM
    (
        SELECT
            id,
            elements,
            generate_subscripts(elements, 1) AS i
        FROM
            (SELECT id, string_to_array(elements, ',') AS elements FROM your_table) AS foo
    ) AS bar;

A more concise version of this pattern:

SELECT
    id,
    unnest(elements) AS elem,
    generate_subscripts(elements, 1) AS nr
FROM
    (SELECT id, string_to_array(elements, ',') AS elements FROM your_table) AS foo;

Solution 5: Custom unnest Function (Older Postgres Versions)

For PostgreSQL versions prior to 8.4, built-in functions like unnest() or generate_subscripts() were not available. In such cases, you would typically create a user-defined function. Here’s an example of a function that mimics unnest with ordinality:

CREATE FUNCTION unnest2(anyarray)
  RETURNS SETOF record  AS
$BODY$
  SELECT $1[i], i
  FROM   generate_series(array_lower($1,1),
                         array_upper($1,1)) i;
$BODY$ LANGUAGE sql IMMUTABLE;

You would then use this function in your queries, similar to how you’d use the built-in unnest:

-- Example usage (assuming you have created the unnest2 function)
-- SELECT id, rec.val, rec.ordinality FROM (SELECT id, unnest2(arr) AS rec FROM your_table_with_array) t;

Solution 6: Advanced De-pivoting with UNNEST() (Postgres 9.4+)

Solution 5 in the original content showcases a more complex scenario using UNNEST() with correlated subqueries and multiple arrays for a de-pivoting operation. This is particularly useful for transforming structured data into a flatter format, associating multiple pieces of information with each original row.

WITH _students AS (
    SELECT * FROM
        (   SELECT 'jane'::TEXT ,'doe'::TEXT , 1::INT
            UNION
            SELECT 'john'::TEXT ,'doe'::TEXT , 2::INT
            UNION
            SELECT 'jerry'::TEXT ,'roe'::TEXT , 3::INT
            UNION
            SELECT 'jodi'::TEXT ,'roe'::TEXT , 4::INT
        ) s ( fn, ln, id )
)
SELECT s.id, ax.fanm, ax.anm, ax.val, ax.num
FROM _students s
,UNNEST
    (
        ( SELECT ARRAY[ fn, ln ]::text[] AS anm
            FROM _students s2 WHERE s2.id = s.id
         )
        ,( SELECT ARRAY[ 'first name', 'last name' ]::text[] AS fanm )
        ,( SELECT ARRAY[ '9','8','7'] AS val)
        ,( SELECT ARRAY[ 1,2,3,4,5   ] AS num)
    ) ax ( anm, fanm, val, num );

This query effectively de-pivots student data, creating rows for each combination of name types, values, and sequential numbers.

FAQs on PostgreSQL String Splitting

Q: What is the most efficient way to split a string into rows in PostgreSQL?

ANS: For PostgreSQL 14 and later, string_to_table() WITH ORDINALITY is generally the most efficient and concise method. For older versions, unnest(string_to_array(...)) WITH ORDINALITY is a strong alternative.

Q: How can I get the original position of elements when splitting a string in PostgreSQL?

ANS: Use the WITH ORDINALITY clause when using string_to_table() or unnest() with string_to_array(). This automatically adds an ordinal number column. Alternatively, generate_subscripts() can be used with arrays.

Q: Can I split a string into rows without preserving the order?

ANS: Yes, if the order is not critical, you can use unnest(string_to_array(...)) without WITH ORDINALITY. However, if you need a numbered list and order doesn’t matter, ROW_NUMBER() OVER (PARTITION BY id) can assign sequential numbers, though their specific order might vary without an explicit ORDER BY clause.

Q: What are the differences between string_to_table and unnest(string_to_array)?

ANS: string_to_table() is a more direct function for splitting strings into rows and is available from PostgreSQL 14. unnest(string_to_array()) achieves a similar result by first converting the string into an array and then expanding that array into rows, available since PostgreSQL 9.4.

Q: How does LATERAL JOIN work with unnest in PostgreSQL?

ANS: LATERAL JOIN allows a subquery or function in the FROM clause to reference columns from preceding FROM items. When used with unnest, it effectively applies unnest to each row of the preceding table, enabling the splitting of delimited strings or arrays on a per-row basis. The LEFT JOIN LATERAL ... ON true pattern is common for ensuring all original rows are kept.

CREATE FUNCTION f_unnest_ord(anyarray, OUT val anyelement, OUT ordinality integer)
  RETURNS SETOF record
  LANGUAGE sql IMMUTABLE AS
'SELECT $1[i], i - array_lower($1,1) + 1
 FROM   generate_series(array_lower($1,1), array_upper($1,1)) i';
CREATE FUNCTION f_unnest_ord_idx(anyarray, OUT val anyelement, OUT ordinality int, OUT idx int)
  RETURNS SETOF record
  LANGUAGE sql IMMUTABLE AS
'SELECT $1[i], i - array_lower($1,1) + 1, i
 FROM   generate_series(array_lower($1,1), array_upper($1,1)) i';

SELECT id, arr, (rec).*
FROM  (
   SELECT *, f_unnest_ord_idx(arr) AS rec
   FROM  (
      VALUES
        (1, '{a,b,c}'::text[])  --  short for: '[1:3]={a,b,c}'
      , (2, '[5:7]={a,b,c}')
      , (3, '[-9:-7]={a,b,c}')
      ) t(id, arr)
   ) sub;
