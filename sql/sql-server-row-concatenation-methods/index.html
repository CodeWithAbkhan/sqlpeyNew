“SQL Server Techniques for Concatenating Multiple Rows into a Single String”

How can a database professional efficiently aggregate values from multiple related rows into a single delimited string column within a SQL query, avoiding performance pitfalls associated with traditional cursor operations? Several established and modern techniques exist depending on the SQL Server version.

Primary Concatenation Methods by SQL Server Version

The approach to string aggregation has evolved significantly across SQL Server releases.

Solution 1: Leveraging FOR XML PATH (SQL Server 2005+)

For versions preceding SQL Server 2017, the widely accepted non-cursor method involves using FOR XML PATH('') within a subquery, often paired with the STUFF function to remove the initial delimiter.

Consider relating Vehicle and Location tables where we need a comma-separated list of City values for each VehicleID:

-- Aggregation using FOR XML PATH and STUFF to clean the leading separator
SELECT
    V.[VehicleID],
    V.[Name],
    (STUFF((SELECT CAST(', ' + L.[City] AS VARCHAR(MAX)) 
     FROM [Location] L
     WHERE (L.VehicleID = V.VehicleID) 
     FOR XML PATH (''), TYPE).value('.', 'NVARCHAR(MAX)'), 1, 2, '')) AS Locations
FROM [Vehicle] V;

If only a leading comma needs removal, an alternative structure avoids the TYPE casting:

-- Streamlined FOR XML PATH approach
SELECT
    V.[VehicleID],
    V.[Name],
    (STUFF((SELECT ', ' + L.[City] 
     FROM [Location] L
     WHERE (L.VehicleID = V.VehicleID) 
     FOR XML PATH ('')), 1, 2, '')) AS Locations
FROM [Vehicle] V;

Self-correction note: Some implementations of this method can result in an extra trailing comma if not carefully managed, often requiring the external use of COALESCE logic (as detailed in Solution 2) or adjusting how STUFF is applied (as shown in Solution 5).

Solution 2: The Modern STRING_AGG Function (SQL Server 2017+)

For SQL Server 2017 and later, or Azure SQL Database, STRING_AGG offers a simpler, more performant, and direct way to achieve the same result. It inherently handles the separator without needing STUFF or complex XML manipulation.

-- Preferred method for modern SQL Server versions
SELECT
    V.[VehicleID],
    V.[Name],
    (SELECT STRING_AGG(L.[City], ', ') -- Second parameter defines the separator
     FROM [Location] L
     WHERE VehicleID = V.VehicleID) AS Locations
FROM   [Vehicle] V;

The flexibility here is that the separator (e.g., ', ' or ' | ') is explicitly defined as the second argument.

Solution 3: Handling List Aggregation without FOR XML (Pre-2017 Alternative)

Before STRING_AGG, one could aggregate strings using a variable within a procedural block, though this is typically limited to a single aggregation result or requires complex session state management if used in a multi-row result set scenario.

A simple example demonstrating variable accumulation (useful for a single group or script execution):

DECLARE @AllCities VARCHAR(MAX) = '';
SELECT @AllCities = COALESCE(@AllCities + ', ', '') + City
FROM Locations; -- Aggregates all cities globally

SELECT @AllCities AS GlobalCityList;

Caution: This script accumulates all cities across all records, not grouping them per VehicleID like the correlated subqueries above.

Solution 4: Recursive Common Table Expression (CTE)

A technically intricate way to perform row concatenation without relying on XML functionality involves using recursive CTEs. This method explicitly manages the ordering and incremental joining of strings:

-- Setup for recursive CTE (requires ranking of locations per vehicle)
WITH RankedLocations AS (
  SELECT
    VehicleID,
    City,
    ROW_NUMBER() OVER (
        PARTITION BY VehicleID 
        ORDER BY City
    ) AS [Rank]
  FROM
    Locations
),
-- Recursive part to build the strings incrementally
Concatenations AS (
  -- Anchor member: Select the first ranked location
  SELECT
    VehicleID,
    CONVERT(nvarchar(MAX), City) AS Cities,
    [Rank]
  FROM
    RankedLocations
  WHERE
    [Rank] = 1

  UNION ALL

  -- Recursive member: Join to the next ranked item
  SELECT
    c.VehicleID,
    (c.Cities + ', ' + l.City) AS Cities,
    l.[Rank]
  FROM
    Concatenations c
    INNER JOIN RankedLocations l ON
        l.VehicleID = c.VehicleID 
        AND l.[Rank] = c.[Rank] + 1
),
-- Final ranking to select only the longest (fully concatenated) string
RankedConcatenations AS (
  SELECT
    VehicleID,
    Cities,
    ROW_NUMBER() OVER (
        PARTITION BY VehicleID 
        ORDER BY [Rank] DESC -- Descending rank ensures the longest string (final result) is Rank 1
    ) AS [FinalRank]
  FROM 
    Concatenations
)
-- Final selection joining back to the Vehicle table
SELECT
  v.VehicleID,
  v.Name,
  c.Cities
FROM
  Vehicles v
  INNER JOIN RankedConcatenations c ON 
    c.VehicleID = v.VehicleID 
    AND c.[FinalRank] = 1;

Solution 5: Refining FOR XML PATH with Leading Delimiter Removal

If the goal is specifically to concatenate values but ensure no leading delimiter exists (addressing the issue where STUFF might miss the first character if the subquery returns an empty set, or simply cleaning up a leading separator), prepending the separator and then removing the first instance works well:

-- Example using a leading comma ',' and then stripping the first character
stuff(
    (select ',' + Column -- Always prepends a comma before the actual value
     from RelatedTable
     where RelatedTable.Id = OuterTable.Id 
     for xml path('')), 
    1, 1, '' -- Start at position 1, remove 1 character, replace with empty string
) AS Values

Solution 6: Utilizing FOR JSON PATH (SQL Server 2016+)

SQL Server 2016 introduced FOR JSON PATH, which offers an XML-free way to serialize related data. While its primary use is JSON output, it can be manipulated back into a string.

-- Example for SQL Server 2016 using JSON serialization tricks
SELECT per.ID,
       Emails = JSON_VALUE(
           REPLACE(
               (SELECT _ = em.Email FROM Email em WHERE em.Person = per.ID FOR JSON PATH),
               '}, {"_":"', ', '), -- Replace JSON structure break with separator
               '$[0]._' -- Extract the root element of the resulting array string
           )
       )
FROM Person per;

This method is robust against invalid XML characters that might trip up the FOR XML approach.

Solution 7: Creating a Scalar User-Defined Function (UDF)

For repeated use across queries, encapsulating the logic inside a scalar UDF is practical, especially in older SQL Server versions (2000/2005/2008) where built-in functions like STRING_AGG are absent. This UDF typically uses the COALESCE technique internally for concatenation per ID.

CREATE FUNCTION dbo.fnConcatCitiesByVehicle(@VehicleId SMALLINT)
RETURNS VARCHAR(1000) AS
BEGIN
  DECLARE @csvCities VARCHAR(1000);
  
  SELECT @csvCities = COALESCE(@csvCities + ', ', '') + COALESCE(City, '')
  FROM Locations 
  WHERE VehicleId = @VehicleId; 
  
  RETURN @csvCities;
END;

-- Usage:
SELECT 
    VehicleID,
    dbo.fnConcatCitiesByVehicle(VehicleId) AS Locations
FROM Vehicles;

Note on UDFs: While clean, scalar UDFs can sometimes negatively impact performance due to execution plan compilation overhead if used heavily in large queries. See performance discussions around SQL Server scalar functions.

Solution 8: General Purpose Delimited String Function

A generalized function accepting the delimiter and a filtering condition allows for reuse across different tables, though it requires careful SQL injection management if the @whereClause is user-provided (here it is simplified).

CREATE FUNCTION [dbo].[JoinTexts]
(
  @delimiter VARCHAR(20) ,
  @filterValue VARCHAR(50) -- Simplified filter column value
)
RETURNS VARCHAR(MAX)
AS 
BEGIN
    DECLARE @Texts VARCHAR(MAX);

    -- Concatenation logic inside the function
    SELECT  @Texts = COALESCE(@Texts + @delimiter, '') + T.Texto
    FROM    SomeTable AS T
    WHERE   T.FilterColumn = @filterValue; -- Assumes 'FilterColumn' exists and matches @filterValue scope

    RETURN @Texts;
END;
GO
-- Example Call:
SELECT dbo.JoinTexts(' | ', 'SpecificCategory') AS ResultingString;

Solution 9: Using DISTINCT with FOR XML PATH

If duplicate city entries within the Location table for the same vehicle should be ignored, applying DISTINCT inside the correlated subquery using FOR XML PATH is necessary:

SELECT [VehicleID],
       [Name],
       STUFF((SELECT DISTINCT ',' + CONVERT(VARCHAR,City) 
         FROM [Location] 
         WHERE (VehicleID = Vehicle.VehicleID) 
         FOR XML PATH ('')), 1, 1, '') AS Locations -- Note: using 1,1 to remove just the leading comma
FROM [Vehicle];

Solution 10: Custom CLR Aggregate Function

For highly complex aggregation logic, or when targeting SQL Server 2005 compatibility where other methods fail, a .NET Common Language Runtime (CLR) User-Defined Aggregate function can be implemented in C#. This requires enabling CLR integration on the SQL Server instance.

The key adjustments focus on ensuring the delimiter is not appended automatically in the Accumulate step, allowing custom control (e.g., appending | via dbo.CONCATENATE(column1 + '|')).

C# Snippet Logic Modification:

Instead of: this.intermediateResult.Append(value.Value).Append(','); Use: this.intermediateResult.Append(value.Value);

And instead of removing the trailing character in Terminate(): Use: output = this.intermediateResult.ToString();

This delegates delimiter control to the SQL call site: SELECT dbo.CONCATENATE(column1 + '|') from table1

Solution 11: Aggregating Metadata (Non-Data Specific Example)

This technique demonstrates the power of FOR XML PATH by applying it to system tables (like INFORMATION_SCHEMA.COLUMNS) to produce a comma-separated list of column names per table, proving the method’s generality:

SELECT
    Tables.Table_Name,
    STUFF((
        SELECT ',' + Columns.Column_Name
        FROM INFORMATION_SCHEMA.Columns AS Columns
        WHERE Tables.Table_Name = Columns.Table_Name
        ORDER BY Column_Name
        FOR XML PATH (''), 1, 1, '' -- Strips leading comma
    ) AS ColumnsList
FROM INFORMATION_SCHEMA.Columns AS Tables
GROUP BY TABLE_NAME;

Solution 12: Complex REPLACE Manipulation of XML Output

This less conventional approach manually cleans the XML tags generated by FOR XML PATH('') using nested REPLACE functions to substitute tag boundaries with the desired separator.

SELECT v.VehicleId, v.Name, ll.LocationList
FROM Vehicles v 
LEFT JOIN 
    (SELECT 
        VehicleId,
        REPLACE(
            REPLACE(
                REPLACE(
                    (SELECT City AS c 
                     FROM Locations x 
                     WHERE x.VehicleID = l.VehicleID FOR XML PATH('')),    
                    '&lt;/c&gt;&lt;c&gt;',', ' -- Replaces closing/opening tag pair
                 ),
             '&lt;c&gt;','' -- Removes opening tag artifact
            ),
        '&lt;/c&gt;', '' -- Removes closing tag artifact
        ) AS LocationList
    FROM Locations l
    GROUP BY VehicleId -- Important for the outer JOIN context
    ) ll ON ll.VehicleId = v.VehicleId;

FAQs on SQL Server Row Concatenation Methods

Q: Which method is best for string aggregation in SQL Server 2019

ANS: The STRING_AGG function (Solution 2) is the most modern, readable, and typically the highest-performing option available in SQL Server 2017 and newer.

Q: How to remove the trailing comma from FOR XML PATH output

ANS: Use the STUFF function to remove characters from the beginning (Solution 1, 5, 9, 11) or ensure the internal logic in a UDF (Solution 7) handles separation using COALESCE correctly.

Q: Can I use COALESCE logic to join strings across multiple rows in a single query

ANS: Yes, you can use the COALESCE(@variable + @delimiter, '') + value pattern, but this usually requires procedural logic or a variable assignment, making it difficult to correlate results back to other columns in the main query row scope unless encapsulated in a scalar UDF (Solution 7).

Q: Are there performance differences between STRING_AGG and FOR XML PATH

ANS: Generally, STRING_AGG is designed specifically for string concatenation and often outperforms the XML-based method (FOR XML PATH) due to lower overhead.
