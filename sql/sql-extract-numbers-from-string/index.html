“SQL Techniques for Isolating Numeric Data From Alphanumeric Strings”

How can one effectively purge non-digit characters from character strings within a SQL database, presenting only the sequential numeric components? Several advanced techniques exist for this common data cleaning task, ranging from procedural User-Defined Functions (UDFs) to set-based Recursive Common Table Expressions (RCTEs) and specific functions available in different SQL dialects like MySQL or Oracle.

Here we examine multiple accepted solutions providing robust ways to isolate numerical sequences.

Approach 1: Iterative Removal using a T-SQL UDF (User-Defined Function)

This approach creates a function that repeatedly finds and removes the first non-digit character until only digits remain.

Function Definition (T-SQL):

CREATE FUNCTION dbo.udf_FilterNonDigits
(
  @strInput VARCHAR(256)
)
RETURNS VARCHAR(256)
AS
BEGIN
  DECLARE @intAlphaPos INT
  SET @intAlphaPos = PATINDEX('%[^0-9]%', @strInput)
  
  BEGIN
    WHILE @intAlphaPos > 0
    BEGIN
      -- Remove the offending character
      SET @strInput = STUFF(@strInput, @intAlphaPos, 1, '' )
      -- Find the next non-digit character
      SET @intAlphaPos = PATINDEX('%[^0-9]%', @strInput )
    END
  END
  
  -- Final cleanup to ensure output integrity, returning 0 if the result is effectively empty or not purely numeric after trimming/casting attempts
  RETURN CASE WHEN LEN(COALESCE(TRIM(CAST(ISNULL(@strInput, '0') AS INT)),'0')) > 0 
              THEN COALESCE(TRIM(CAST(ISNULL(@strInput, '0') AS INT)),'0') 
              ELSE '0' 
         END
END
GO

Usage Example:

To apply this logic across a table:

SELECT 
    SourceColumn,
    dbo.udf_FilterNonDigits(SourceColumn) AS ExtractedNumber
FROM 
    YourDataTable;

Note: The return type in the original sample was complex; this version aims for a clear numeric string representation or ‘0’.

Approach 2: Positional Extraction using SUBSTRING and PATINDEX (Finding the Start)

This method focuses on locating the first digit and then extracting from that point, though its success depends on whether you want all subsequent digits or just the initial contiguous block of digits. The following query finds the first digit and extracts characters until the first non-digit appears afterward.

T-SQL Query Example (Extracts initial numeric block):

DECLARE @temp TABLE (
      input_string NVARCHAR(50)
)

INSERT INTO @temp (input_string)
VALUES 
    ('003Preliminary Examination Plan'),
    ('Coordination005'),
    ('Balance1000sheet')

SELECT 
    LEFT(substring_from_pos, PATINDEX('%[^0-9]%', substring_from_pos + 'X') - 1) AS ExtractedBlock
FROM (
    SELECT 
        substring_from_pos = SUBSTRING(input_string, pos, LEN(input_string))
    FROM (
        SELECT 
            input_string, 
            pos = PATINDEX('%[0-9]%', input_string) -- Position of the first digit
        FROM @temp
    ) d
    WHERE pos > 0 -- Ensure a digit was found
) t;

Solutions

| | 003 | | 005 | | 1000 |

Approach 3: Extracting a Contiguous Block Between Non-Digits

If the requirement is specifically to capture a numeric sequence situated between non-numeric characters (assuming one sequence per string for this specific pattern):

T-SQL Query Example:

DECLARE @temp TABLE (
    input_string NVARCHAR(50)
)

INSERT INTO @temp (input_string)
VALUES 
    ('003Preliminary Examination Plan'),
    ('Coordination005'),
    ('Balance1000sheet')

SELECT 
    SUBSTRING(
        input_string, 
        PATINDEX('%[0-9]%', input_string), 
        PATINDEX('%[0-9][^0-9]%', string_padded + 'Z') - PATINDEX('%[0-9]%', input_string) + 1
    ) AS ExtractedNumber
FROM @temp
CROSS APPLY (SELECT string_padded = input_string) AS a;

A ‘Z’ or ’t’ is appended to the string to ensure PATINDEX finds a terminating non-digit marker, even if the number is at the string’s end.

Approach 4: Using TRANSLATE (SQL Server 2017+)

For modern SQL Server versions, the TRANSLATE function offers a concise, set-based method to substitute unwanted characters with spaces, followed by REPLACE to eliminate those spaces. This requires knowing all characters to remove.

T-SQL Example (Removing lowercase ASCII letters):

DECLARE @T TABLE (string varchar(50) NOT NULL);

INSERT @T (string)
VALUES 
    ('Data003Text'),
    ('Process005Info'),
    ('Final1000Value');

SELECT 
    result =
        REPLACE(
            TRANSLATE(
                T.string COLLATE Latin1_General_CI_AI, 
                'abcdefghijklmnopqrstuvwxyz', 
                REPLICATE(' ', 26)), -- Replace each letter with a space
            ' ', 
            '') -- Remove all spaces
FROM @T AS T;

Approach 5: Recursive CTE for High Performance Filtering (Set-Based)

A recursive CTE can iterate over the string character by character, building the resulting string only from digits. This often outperforms iterative UDFs in large datasets due to set-based execution plans.

T-SQL Recursive CTE Example (Extracts all digits):

DECLARE @SourceData AS TABLE (id INT PRIMARY KEY, value NVARCHAR(MAX));

INSERT INTO @SourceData
VALUES
    (1, N'Text123Then45'),
    (2, N'Coordination005'),
    (3, N'Balance1000sheet');

WITH CharacterSplitter (id, iteration, current_char, remaining_string) AS (
    -- Anchor Member: Start at character 1
    SELECT
        id,
        1 AS iteration,
        SUBSTRING(value, 1, 1) AS current_char,
        CAST(SUBSTRING(value, 2, LEN(value)) AS NVARCHAR(MAX)) AS remaining_string
    FROM
        @SourceData
    WHERE
        LEN(value) > 0

    UNION ALL

    -- Recursive Member: Process the next character
    SELECT
        s.id,
        t.iteration + 1,
        SUBSTRING(s.value, t.iteration + 1, 1),
        CAST(SUBSTRING(s.value, t.iteration + 2, LEN(s.value)) AS NVARCHAR(MAX))
    FROM
        CharacterSplitter AS t
        JOIN @SourceData AS s ON t.id = s.id
    WHERE
        t.iteration < LEN(s.value)
)
SELECT
    id,
    STRING_AGG(current_char, N'') WITHIN GROUP (ORDER BY iteration ASC) AS AllDigits
FROM
    CharacterSplitter
WHERE
    current_char LIKE '[0-9]' -- Filter condition: keep only digits
GROUP BY
    id
ORDER BY
    id;

Approach 6: Iterative Replacement UDF (Simple Loop)

A streamlined UDF that uses a WHILE loop to iteratively replace any character that is not a digit ([^0-9]) with an empty string.

T-SQL UDF Example:

CREATE FUNCTION dbo.udf_GetNumbersSimple (@string VARCHAR(MAX))
RETURNS VARCHAR(MAX)
AS
BEGIN
    -- Loop as long as a non-digit character exists in the string
    WHILE  @string LIKE '%[^0-9]%'
    BEGIN
        -- Replace the first found non-digit character with nothing
        SET    @string = REPLACE(@string, SUBSTRING(@string, PATINDEX('%[^0-9]%', @string), 1), '')
    END
    RETURN @string
END

Approach 7: Oracle SQL Solution using Regex Functions

For environments like Oracle, regular expression functions provide the most idiomatic solution for this filtering task.

Oracle SQL Example (Extracts all digits):

SELECT
    REGEXP_REPLACE(
        'CodeA123B456C', 
        '[^0-9]', -- Pattern: Match anything that is NOT a digit (0-9)
        ''        -- Replacement: Replace with nothing
    ) AS ExtractedNumbers
FROM DUAL;
-- Output: 123456

Approach 8: MySQL Solution using REGEXP_REPLACE (8.0+)

Similar to Oracle, modern MySQL leverages powerful regex capabilities.

MySQL Query Example:

SELECT REGEXP_REPLACE(
    'ProjectV99Status', 
    '[^0-9]', 
    ''
) AS NumericResult;
-- Output: 99

Approach 9: PostgreSQL Solution for Character-by-Character Filtering

PostgreSQL often uses array manipulation or regexp_replace for text processing.

PostgreSQL Query Example (Extracts all digits):

SELECT regexp_replace(
    'Data-ID-789XYZ', 
    '[^0-9]', 
    '', 
    'g' -- 'g' flag ensures global replacement
);
-- Output: 789

CREATE FUNCTION dbo.udf_GetNumeric
(
  @strAlphaNumeric VARCHAR(256)
)
RETURNS VARCHAR(256)
AS
BEGIN
  DECLARE @intAlpha INT
  SET @intAlpha = PATINDEX('%[^0-9]%', @strAlphaNumeric)
  BEGIN
    WHILE @intAlpha &gt; 0
    BEGIN
      SET @strAlphaNumeric = STUFF(@strAlphaNumeric, @intAlpha, 1, '' )
      SET @intAlpha = PATINDEX('%[^0-9]%', @strAlphaNumeric )
    END
  END
  RETURN LEN(COALESCE(TRIM(CAST(ISNULL(@strAlphaNumeric, 0) AS INT)),0))&gt;0 then COALESCE(TRIM(CAST(ISNULL(@strAlphaNumeric, 0) AS INT)),0) else 0 end
END
GO

FAQs on SQL Numeric Extraction

Q: Which SQL approach is generally fastest for extracting all digits

ANS: The Recursive CTE (Approach 5) or a highly optimized UDF (Approach 1 or 6) are often faster in T-SQL than row-by-row iterative methods for very large datasets, as they leverage set-based operations, though specific database indexing and data volume dictate the true winner. For databases with native REGEXP_REPLACE (like Oracle, MySQL 8+, Postgres), that function is usually the most performant and cleanest.

Q: Why do some solutions only extract the first group of numbers

ANS: Solutions relying on finding the start position of the first digit (PATINDEX('%[0-9]%') and then stopping at the next non-digit boundary (like Approach 2 or 3) will only capture the initial contiguous sequence of numbers present in the string. To get all digits, you need iterative removal (UDFs) or global regex replacement.

Q: Can I extract decimals using these methods

ANS: The techniques shown primarily filter for [0-9]. To include decimals, modify the pattern to include the period, e.g., change [^0-9] to [^0-9.] in regex functions or the logic in UDFs, though this requires careful handling of multiple decimal points.

Q: What if I cannot create functions in SQL Server

ANS: If UDF creation is restricted, set-based approaches like the Recursive CTE (Approach 5) or the TRANSLATE method (Approach 4, if on SQL Server 2017+) are the best alternatives.
