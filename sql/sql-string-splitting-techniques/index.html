“SQL String Splitting Techniques: Functions and Methods”

When working with databases, a common requirement is to parse a single string containing multiple values separated by a delimiter into individual rows or elements. This process, often referred to as string splitting, is crucial for data manipulation and analysis. There are several approaches in SQL Server to achieve this, ranging from custom-built functions to more modern, built-in functionalities. Each method offers different performance characteristics and flexibility.

Solution 1: User-Defined Function (UDF) using a WHILE Loop

One traditional method involves creating a table-valued function that iteratively processes the string. This approach uses a WHILE loop and string manipulation functions like CHARINDEX and SUBSTRING.

CREATE FUNCTION dbo.splitstring ( @stringToSplit VARCHAR(MAX) )
RETURNS
 @returnList TABLE ([Name] [nvarchar] (500))
AS
BEGIN

 DECLARE @name NVARCHAR(255)
 DECLARE @pos INT

 WHILE CHARINDEX(',', @stringToSplit) > 0
 BEGIN
  SELECT @pos  = CHARINDEX(',', @stringToSplit)  
  SELECT @name = SUBSTRING(@stringToSplit, 1, @pos-1)

  INSERT INTO @returnList 
  SELECT @name

  SELECT @stringToSplit = SUBSTRING(@stringToSplit, @pos+1, LEN(@stringToSplit)-@pos)
 END

 INSERT INTO @returnList
 SELECT @stringToSplit

 RETURN
END

To utilize this function, you can query it like a table:

SELECT * FROM dbo.splitstring('91,12,65,78,56,789');

A slight modification to the loop condition can eliminate the need for a final INSERT outside the loop, as shown in Solution 7.

Solution 2: Using the Built-in STRING_SPLIT Function (SQL Server 2016+)

For SQL Server 2016 and later versions, Microsoft introduced the STRING_SPLIT function, which is highly efficient and straightforward.

SELECT * FROM STRING_SPLIT('a,b', ',');

This function simplifies string splitting considerably, outperforming many older methods. For performance comparisons and deeper insights, refer to articles discussing STRING_SPLIT performance. You can find more on string manipulation in SQL at sqlpey.com .

Solution 3: Set-Based UDF using System Tables or Recursive CTEs

This method offers a set-based approach, often performing better than row-by-row processing. It leverages either system tables (like sys.all_columns) to generate a sequence of numbers or a recursive Common Table Expression (CTE).

Using System Tables (for SQL Server 2008 and later):

CREATE FUNCTION dbo.SplitString
(
  @List     nvarchar(max),
  @Delim    nvarchar(255)
)
RETURNS TABLE
AS
  RETURN ( SELECT [Value] FROM 
  ( 
    SELECT [Value] = LTRIM(RTRIM(SUBSTRING(@List, [Number],
      CHARINDEX(@Delim, @List + @Delim, [Number]) - [Number])))
    FROM (SELECT Number = ROW_NUMBER() OVER (ORDER BY name)
      FROM sys.all_columns) AS x WHERE Number <= LEN(@List)
      AND SUBSTRING(@Delim + @List, [Number], DATALENGTH(@Delim)/2) = @Delim
    ) AS y
  );
GO

Using Recursive CTE:

CREATE FUNCTION dbo.SplitString
(
  @List     nvarchar(max),
  @Delim    nvarchar(255)
)
RETURNS TABLE WITH SCHEMABINDING
AS
   RETURN ( WITH n(n) AS (SELECT 1 UNION ALL SELECT n+1 
       FROM n WHERE n <= LEN(@List))
       SELECT [Value] = SUBSTRING(@List, n, 
       CHARINDEX(@Delim, @List + @Delim, n) - n)
       FROM n WHERE n <= LEN(@List)
      AND SUBSTRING(@Delim + @List, n, DATALENGTH(@Delim)/2) = @Delim
   );
GO

Note that recursive CTEs might require OPTION (MAXRECURSION 0) for longer strings. For more advanced string splitting, explore resources on sqlpey.com .

Solution 4: XML Method

The XML approach is a concise way to transform a delimited string into rows. It involves converting the string into an XML structure.

Splitting a single string:

DECLARE @String varchar(100) = 'String1,String2,String3';
DECLARE @Delimiter CHAR = ',';    

SELECT LTRIM(RTRIM(Split.a.value('.', 'VARCHAR(100)'))) 'Value' 
FROM  
(     
     SELECT CAST ('<M>' + REPLACE(@String, @Delimiter, '</M><M>') + '</M>' AS XML) AS Data            
) AS A 
CROSS APPLY Data.nodes ('/M') AS Split(a);

Splitting strings from a table:

DECLARE @Delimiter CHAR = ',';

SELECT ID, LTRIM(RTRIM(Split.a.value('.', 'VARCHAR(100)'))) 'Value' 
FROM  
(     
     SELECT ID, CAST ('<M>' + REPLACE(VALUE, @Delimiter, '</M><M>') + '</M>' AS XML) AS Data            
     FROM TABLENAME -- Replace TABLENAME with your actual table name
) AS A 
CROSS APPLY Data.nodes ('/M') AS Split(a);

Solution 5: Inline Ad-Hoc Modification

For quick, one-off tasks, you can use inline SQL to modify strings. This example removes a trailing ‘+’ from a zip code.

This can be adapted for various string manipulations.

Solution 6: XML with Special Character Handling

When dealing with strings containing XML-sensitive characters, you need to ensure they are properly escaped. This solution uses FOR XML PATH('') for robust handling.

DECLARE @Dummy TABLE (ID INT, SomeTextToSplit NVARCHAR(MAX))
INSERT INTO @Dummy VALUES
 (1,N'A&B;C;D;E, F')
,(2,N'"C" & ''D'';<C>;D;E, F');

DECLARE @Delimiter NVARCHAR(10)=';';

WITH Casted AS
(
    SELECT *
          ,CAST(N'<x>' + REPLACE((SELECT REPLACE(SomeTextToSplit,@Delimiter,N'§§Split$me$here§§') AS [*] FOR XML PATH('')),N'§§Split$me$here§§',N'</x><x>') + N'</x>' AS XML) AS SplitMe
    FROM @Dummy
)
SELECT Casted.ID
      ,x.value(N'.',N'nvarchar(max)') AS Part 
FROM Casted
CROSS APPLY SplitMe.nodes(N'/x') AS A(x);

Solution 8: Efficient XML-Based Set-Based Function

This function provides a performant set-based approach using XML.

(

)

Solution 9: General Delimiter Function with Index

This function splits strings based on a customizable delimiter and also provides the index of each split value.

CREATE FUNCTION [dbo].[SplitString] 
    ( @string nvarchar(4000)
    , @delim nvarchar(100) )
RETURNS
    @result TABLE 
        ( [Value] nvarchar(4000) NOT NULL
        , [Index] int NOT NULL )
AS
BEGIN
    DECLARE @str nvarchar(4000)
          , @pos int 
          , @prv int = 1

    SELECT @pos = CHARINDEX(@delim, @string)
    WHILE @pos > 0
    BEGIN
        SELECT @str = SUBSTRING(@string, @prv, @pos - @prv)
        INSERT INTO @result SELECT @str, @prv

        SELECT @prv = @pos + LEN(@delim)
             , @pos = CHARINDEX(@delim, @string, @pos + 1)
    END

    INSERT INTO @result SELECT SUBSTRING(@string, @prv, 4000), @prv
    RETURN
END

Solution 10: CTE-Based String Splitting

A recursive CTE can also be used for string splitting, offering a different approach to parsing.

declare @StringToSplit varchar(100) = 'Test1,Test2,Test3';
declare @SplitChar varchar(10) = ',';

with StringToSplit as (
  select 
      ltrim( rtrim( substring( @StringToSplit, 1, charindex( @SplitChar, @StringToSplit ) - 1 ) ) ) Head
    , substring( @StringToSplit, charindex( @SplitChar, @StringToSplit ) + 1, len( @StringToSplit ) ) Tail

  union all

  select
      ltrim( rtrim( substring( Tail, 1, charindex( @SplitChar, Tail ) - 1 ) ) ) Head
    , substring( Tail, charindex( @SplitChar, Tail ) + 1, len( Tail ) ) Tail
  from StringToSplit
  where charindex( @SplitChar, Tail ) > 0

  union all

  select
      ltrim( rtrim( Tail ) ) Head
    , '' Tail
  from StringToSplit
  where charindex( @SplitChar, Tail ) = 0
    and len( Tail ) > 0
)
select Head from StringToSplit;

Solution 18: CTE-Based Table-Valued Function

A CTE-based function for splitting strings, providing an ID for each item.

ALTER FUNCTION [dbo].[CUST_SplitString]
(
    @String NVARCHAR(4000),
    @Delimiter NCHAR(1)
)
RETURNS TABLE 
AS
RETURN 
(
    WITH Split(stpos,endpos) 
    AS(
        SELECT 0 AS stpos, CHARINDEX(@Delimiter,@String) AS endpos
        UNION ALL
        SELECT endpos+1, CHARINDEX(@Delimiter,@String,endpos+1) 
        FROM Split
        WHERE endpos > 0
    )
    SELECT 'Id' = ROW_NUMBER() OVER (ORDER BY (SELECT 1)),
        'Data' = SUBSTRING(@String,stpos,COALESCE(NULLIF(endpos,0),LEN(@String)+1)-stpos)
    FROM Split
);

Solution 19: Double Splitter Function

This function handles splitting with two different delimiters.

CREATE FUNCTION uft_DoubleSplitter 
(   
    @String VARCHAR(4000), 
    @Splitter1 CHAR,
    @Splitter2 CHAR
)
RETURNS @Result TABLE (Id INT,MId INT,SValue VARCHAR(4000))
AS
BEGIN
DECLARE @FResult TABLE(Id INT IDENTITY(1, 1), SValue VARCHAR(4000));
DECLARE @SResult TABLE(Id INT IDENTITY(1, 1), MId INT, SValue VARCHAR(4000));
SET @String = @String + @Splitter1;

WHILE CHARINDEX(@Splitter1, @String) > 0
    BEGIN
       DECLARE @WorkingString VARCHAR(4000) = NULL;
       SET @WorkingString = SUBSTRING(@String, 1, CHARINDEX(@Splitter1, @String) - 1);
       INSERT INTO @FResult SELECT CASE WHEN @WorkingString = '' THEN NULL ELSE @WorkingString END;
       SET @String = SUBSTRING(@String, LEN(@WorkingString) + 2, LEN(@String));
    END;

IF ISNULL(@Splitter2, '') != ''
    BEGIN
       DECLARE @OStartLoop INT, @OEndLoop INT;
       SELECT @OStartLoop = MIN(Id), @OEndLoop = MAX(Id) FROM @FResult;
       WHILE @OStartLoop <= @OEndLoop
          BEGIN
             DECLARE @iString VARCHAR(4000), @iMId INT;
             SELECT @iString = SValue + @Splitter2, @iMId = Id FROM @FResult WHERE Id = @OStartLoop;
             WHILE CHARINDEX(@Splitter2, @iString) > 0
                BEGIN
                    DECLARE @iWorkingString VARCHAR(4000) = NULL;
                    SET @IWorkingString = SUBSTRING(@iString, 1, CHARINDEX(@Splitter2, @iString) - 1);
                    INSERT INTO @SResult SELECT @iMId, CASE WHEN @iWorkingString = '' THEN NULL ELSE @iWorkingString END;
                    SET @iString = SUBSTRING(@iString, LEN(@iWorkingString) + 2, LEN(@iString));
                END;
             SET @OStartLoop = @OStartLoop + 1;
          END;
       INSERT INTO @Result SELECT MId AS PrimarySplitID, ROW_NUMBER() OVER (PARTITION BY MId ORDER BY Mid, Id) AS SecondarySplitID , SValue FROM @SResult;
    END
ELSE
    BEGIN
       INSERT INTO @Result SELECT Id AS PrimarySplitID, NULL AS SecondarySplitID, SValue FROM @FResult;
    END;
RETURN;
END;

Usage examples:

-- First Split
SELECT * FROM uft_DoubleSplitter('ValueA=ValueB=ValueC=ValueD==ValueE&ValueA=ValueB=ValueC===ValueE&ValueA=ValueB==ValueD===','&',NULL);

-- Second Split
SELECT * FROM uft_DoubleSplitter('ValueA=ValueB=ValueC=ValueD==ValueE&ValueA=ValueB=ValueC===ValueE&ValueA=ValueB==ValueD===','&','=');

-- Get second value of each split
SELECT fn.SValue
FROM uft_DoubleSplitter('ValueA=ValueB=ValueC=ValueD==ValueE&ValueA=ValueB=ValueC===ValueE&ValueA=ValueB==ValueD===', '&', '=')AS fn
WHERE fn.mid = 2;

Solution 20: Recursive CTE for Path Splitting

This CTE approach is useful for parsing hierarchical paths.

declare @T table (iden int identity, col1 varchar(100));
insert into @T(col1) values
       ('ROOT/South America/Lima/Test/Test2')
     , ('ROOT/South America/Peru/Test/Test2')
     , ('ROOT//South America/Venuzuala ')
     , ('RtT/South America / ') 
     , ('ROOT/South Americas// '); 
declare @split char(1) = '/';

with cte as 
(  select t.iden, case when SUBSTRING(REVERSE(rtrim(t.col1)), 1, 1) = @split then LTRIM(RTRIM(t.col1)) else LTRIM(RTRIM(t.col1)) + @split end  as col1, 0 as pos                             , 1 as cnt
   from @T t
   union all 
   select t.iden, t.col1                                                                                                                              , charindex(@split, t.col1, t.pos + 1), cnt + 1 
   from cte t 
   where charindex(@split, t.col1, t.pos + 1) > 0 
)
select t1.*, t2.pos, t2.cnt
     , ltrim(rtrim(SUBSTRING(t1.col1, t1.pos+1, t2.pos-t1.pos-1))) as bingo
from cte t1 
join cte t2 
  on t2.iden = t1.iden 
 and t2.cnt  = t1.cnt+1
 and t2.pos > t1.pos 
order by t1.iden, t1.cnt;

Solution 24: String Splitting Function with Trailing Character Handling

This function ensures proper splitting even when the string ends with the delimiter.

CREATE FUNCTION SplitString
(    
   @Input NVARCHAR(MAX),
   @Character CHAR(1)
)
RETURNS @Output TABLE (
    Item NVARCHAR(1000)
)
AS
BEGIN
  DECLARE @StartIndex INT, @EndIndex INT;
  SET @StartIndex = 1;
  IF SUBSTRING(@Input, LEN(@Input) - 1, LEN(@Input)) <> @Character
  BEGIN
        SET @Input = @Input + @Character;
  END;

  WHILE CHARINDEX(@Character, @Input) > 0
  BEGIN
        SET @EndIndex = CHARINDEX(@Character, @Input);
        INSERT INTO @Output(Item)
        SELECT SUBSTRING(@Input, @StartIndex, @EndIndex - 1);
        SET @Input = SUBSTRING(@Input, @EndIndex + 1, LEN(@Input));
  END;
  RETURN;
END;
GO

Solution 25: XML-Based Function with Special Character Handling

This function uses XML conversion and handles special characters appropriately.

CREATE FUNCTION [dbo].[fn_SplitString]
(@CSV VARCHAR(MAX), @Delimeter VARCHAR(100) = ',')
RETURNS @retTable TABLE 
(
    [value] VARCHAR(MAX) NULL
)AS
BEGIN
DECLARE @vCSV VARCHAR (MAX) = @CSV,
       @vDelimeter VARCHAR (100) = @Delimeter;

IF @vDelimeter = ';'
BEGIN
    SET @vCSV = REPLACE(@vCSV, ';', '~!~#~');
    SET @vDelimeter = REPLACE(@vDelimeter, ';', '~!~#~');
END;

SET @vCSV = REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(@vCSV, '&', '&amp;'), '<', '&lt;'), '>', '&gt;'), '''', '&apos;'), '"', '&quot;');

DECLARE @xml XML;
SET @xml = '<i'>' + REPLACE(@vCSV, @vDelimeter, '</i'><i'>') + '</i'>';

INSERT INTO @retTable
SELECT
       x.i.value('.', 'varchar(max)') AS COLUMNNAME
  FROM @xml.nodes('//i')AS x(i);
 RETURN;
END;

FAQs on SQL String Splitting Techniques

Q: What is the most efficient way to split strings in SQL Server

ANS: For SQL Server 2016 and later, the built-in STRING_SPLIT function is generally the most efficient. For older versions, well-optimized set-based user-defined functions using XML or CTEs often outperform loop-based functions.

Q: Can I split strings using multiple delimiters

ANS: Yes, some custom functions, like the uft_DoubleSplitter (Solution 19), are designed to handle multiple delimiters. Alternatively, you might need to preprocess the string to replace secondary delimiters with the primary one before splitting.

Q: How do I handle strings with special characters when splitting

ANS: When using methods like XML conversion, special characters within the string need to be properly escaped (e.g., using &amp; for &). Some functions are designed to handle this more robustly.

Q: What are the performance differences between methods

ANS: STRING_SPLIT is optimized for performance. Set-based approaches (XML, CTEs) are generally faster than loop-based UDFs for large datasets. Inline ad-hoc solutions are quick for simple, one-off tasks but not scalable.

Q: Can I get the position of each split item

ANS: Yes, some custom functions, such as Solution 9 and Solution 11, are designed to return an index or position along with the split value.
