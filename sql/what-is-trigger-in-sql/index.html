Trigger is a special type of stored procedure that is executed automatically in response to certain events on a database table Triggers are used to enforce business rules, maintain data integrity, and perform tasks such as auditing.

Triggers can be activated by various events, such as INSERT , UPDATE , DELETE , or SELECT statements on a table, or by direct invocation using the EXECUTE or CALL statement. Triggers can also be activated by database events such as logon, logoff, or server startup.

How to Create Trigger in SQL?

To create a trigger in SQL, you can use the CREATE TRIGGER statement. The general syntax for creating a trigger is as follows:

Syntax of Trigger:

CREATE TRIGGER trigger_name
    {BEFORE | AFTER} {INSERT | UPDATE | DELETE}
    ON table_name
    [FOR EACH ROW]
    [WHEN condition]
BEGIN
    -- trigger code goes here
END;

BEFORE and AFTER of Trigger in SQL

In SQL, the BEFORE and AFTER keywords determine when a trigger will be executed relative to the triggering event (e.g. INSERT, UPDATE, or DELETE).

  • BEFORE, the trigger will be executed before the triggering event is performed. This means that the trigger code will be executed first, and then the triggering event will be performed.

  • AFTER, the trigger will be executed after the triggering event is performed. This means that the triggering event will be performed first, and then the trigger code will be executed.

if the trigger were specified as BEFORE UPDATE, the trigger code would be executed first, and then the UPDATE statement would be performed. This can be useful if you want to modify the values being updated or perform some other action before the update takes place.

Write Trigger in SQL using Student Database Example

Step 1. Database creation:

To create a database for storing student information, you could use the following SQL statement:

CREATE DATABASE student_db;

Step 2. Table creation:

To create a table for storing student information, you could use the following SQL statement:

CREATE TABLE students (
  student_id INT PRIMARY KEY,
  first_name VARCHAR(255),
  last_name VARCHAR(255),
  gpa DECIMAL(3,2),
  status VARCHAR(255)
);

Step 3. Trigger creation:

To create a trigger that updates the status column of the students table whenever a student’s gpa falls below 2.0, you could use the following SQL statement:

CREATE TRIGGER update_student_status
AFTER UPDATE ON students
FOR EACH ROW
BEGIN
    IF NEW.gpa < 2.0 THEN
        SET NEW.status = 'on probation';
    END IF;
END;

Trigger in SQL Server

In Microsoft SQL Server, triggers are created using the CREATE TRIGGER statement . Triggers can be defined to execute in response to INSERT, UPDATE, DELETE, or MERGE statements on a table. For example, the following trigger would log a message to the system log table whenever an update is made to the customers table:

CREATE TRIGGER log_update ON customers
FOR UPDATE
AS
    INSERT INTO system_log (message)
    VALUES ('A record was updated in the customers table');

What are the advantages of Trigger in SQL?

Triggers are a special type of stored procedure in a database management system that is automatically executed in response to certain events. Triggers offer several advantages in SQL:

Enforce business rules and integrity constraints

Triggers can be used to enforce business rules and integrity constraints, ensuring that the data in the database remains consistent and accurate.

Maintain data integrity and consistency

Triggers can be used to maintain data integrity and consistency by performing cascading updates, deletions, or insertions across multiple tables.

Automate complex processes

Triggers can be used to automate complex processes that cannot be easily expressed using standard SQL statements.

Audit and log changes

Triggers can be used to audit and log changes to the database, making it easier to track changes and detect any problems.

Send notifications and alerts

Triggers can be used to send notifications or alerts to users or administrators when certain events occur in the database.

Improve performance

Triggers can improve the performance of the database by offloading certain tasks from the application to the database.

However, it is important to use triggers carefully, as they can also negatively impact database performance if not used correctly. Triggers should be used only when necessary, and their code should be well-optimized to avoid any performance issues.
