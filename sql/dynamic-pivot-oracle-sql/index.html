“Dynamic PIVOT in Oracle SQL: Strategies and Solutions”

When working with relational databases, transforming rows into columns is a common requirement, often achieved using the PIVOT clause in SQL. However, situations arise where the columns you need to pivot on are not fixed and can change based on data. This is where dynamic pivoting becomes essential. This post delves into various approaches to tackle dynamic pivoting in Oracle SQL, presenting multiple accepted solutions with practical code examples.

Understanding the Challenge of Dynamic Pivoting

The standard PIVOT clause in Oracle SQL requires you to explicitly list the values that will become new column headers within the IN clause. When these values are dynamic, meaning they are determined by the data itself, a direct application of PIVOT is not possible. This leads to the need for techniques that can construct the SQL query dynamically based on the available data.

Solutions

Solution 1: Constructing the IN Clause String

One common method involves generating the IN clause string dynamically before executing the PIVOT statement. This is particularly useful when the number of distinct values to pivot on is manageable and fits within string length limits.

Scenario: You have a table with numerical values and corresponding categories, and you want to pivot the values based on these categories.

Dynamic IN Clause Generation:

This involves using LISTAGG to create a comma-separated string of the distinct category values, formatted for the PIVOT statement.

CLEAR COLUMNS
COLUMN temp_in_statement NEW_VALUE str_in_statement
SELECT DISTINCT
    LISTAGG('''' || myLetter || ''' AS ' || myLetter, ',')
        WITHIN GROUP (ORDER BY myLetter) AS temp_in_statement
    FROM (SELECT DISTINCT myLetter FROM myTable);

The generated str_in_statement would look like: 'A' AS A,'B' AS B,'C' AS C.

PIVOT Query:

SELECT * FROM
    (SELECT myNumber, myLetter, myValue FROM myTable)
    PIVOT (SUM(myValue) AS val FOR myLetter IN (&str_in_statement));

Output:

MYNUMBER | A_VAL | B_VAL | C_VAL

  v_recordset SYS_REFCURSOR;
  v_sql       VARCHAR2(32767);
  v_cols      VARCHAR2(32767);

  SELECT LISTAGG( 'SUM(  CASE  WHEN job_title =  '''||job_title||'''  THEN  1  ELSE  0  END )  AS  &quot;'||job_title||'&quot;' , ',' )
                 WITHIN GROUP ( ORDER BY job_title )
    INTO v_cols
    FROM ( SELECT DISTINCT job_title
             FROM jobs j );

  v_sql :=
  'SELECT &quot;HIRE YEAR&quot;,'|| v_cols ||
  '  FROM
     (
      SELECT TO_NUMBER(TO_CHAR(hire_date,''YYYY'')) AS &quot;HIRE YEAR&quot;, job_title
        FROM employees e
        JOIN jobs j

Solution 2: Leveraging PIVOT XML

When the number of dynamic columns exceeds the string limits or for a more robust solution, PIVOT XML offers an alternative. This method allows a subquery to provide the pivoting values.

Syntax:

SELECT xmlserialize(content t.B_XML) FROM t_aa
PIVOT XML(
  SUM(A) FOR B IN (ANY) -- 'ANY' signifies dynamic columns
) t;

Using a Subquery for Columns:

You can also specify a subquery to define the columns for pivoting:

SELECT xmlserialize(content t.B_XML) FROM t_aa
PIVOT XML(
  SUM(A) FOR B IN (SELECT cl FROM t_bb) -- Subquery to define columns
) t;

This approach is powerful for generating XML output that can then be parsed or transformed as needed. You can find a demonstration on SQL Fiddle .
