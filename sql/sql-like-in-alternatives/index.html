“SQL Query Alternatives for Combining LIKE and IN Operations”

Is there a direct SQL syntax in T-SQL (SQL Server) or PL/SQL (Oracle) that permits combining the filtering power of the LIKE operator with the list-matching capability of the IN operator to search a single column against multiple distinct patterns (e.g., WHERE column IN ('pattern1%', '%pattern2', 'pattern3%'))?

The direct combination of LIKE within an IN clause is generally unsupported in standard SQL dialects like T-SQL or PL/SQL. When facing this requirement, several robust database-specific and general SQL techniques provide viable substitutes.

Primary Recommended Approaches

1. Leveraging Full-Text Search (FTS)

For text searching across large datasets where performance is critical, Full-Text Search (FTS) is the established best practice, provided the column is properly indexed for FTS. The specific syntax varies slightly between major vendors:

  • Oracle FTS: Utilizes the CONTAINS keyword. The search terms are combined using standard boolean logic.

    -- Example search for values containing 'bla', 'foo', or 'batz'
SELECT t.*
FROM YourTable t
WHERE CONTAINS(t.something, 'bla OR foo OR batz', 1) > 0;

  • SQL Server FTS: Also uses CONTAINS, but requires quoted phrases, often with wildcards (*) for partial matches.

    -- Example search for values containing substrings related to 'bla', 'foo', or 'batz'
SELECT t.*
FROM YourTable t
WHERE CONTAINS(t.something, '"bla*" OR "foo*" OR "batz*"');

    Prerequisite: The column being queried must have a Full-Text Index applied. For more on SQL Server FTS, consult the official Microsoft documentation .

2. Using OR Predicates (The Simplest Workaround)

If the number of patterns is small, explicitly using multiple OR conditions remains the most portable and often the fastest solution, especially if FTS is not configured.

-- Standard approach using multiple LIKE clauses
SELECT something
FROM mytable
WHERE something LIKE 'bla%'
   OR something LIKE '%foo%'
   OR something LIKE 'batz%';

3. Regular Expressions (REGEXP_LIKE)

For Oracle (10g onwards) and other RDBMS supporting strong regular expression functions, REGEXP_LIKE can consolidate multiple OR conditions into a single function call. Note: While syntactically clean, this method can degrade performance compared to simple LIKE statements or FTS because regex parsing is computationally intensive.

Consider this setup data (Oracle example):

-- Setup for REGEXP_LIKE demonstration
CREATE TABLE mytable (something VARCHAR2(50));
INSERT INTO mytable VALUES ('blabla');
INSERT INTO mytable VALUES ('notbla');
INSERT INTO mytable VALUES ('ofooof');
INSERT INTO mytable VALUES ('ofofof');
INSERT INTO mytable VALUES ('batzzz');

The consolidated query:

SELECT something
FROM mytable
WHERE regexp_like(something, '^bla|foo|^batz');

In Oracle, you can also test for string inclusion using the OR operator within the regex pattern itself, as demonstrated here:

-- Oracle REGEXP_LIKE equivalence check
SELECT 'Success !!!' AS result
FROM dual
WHERE REGEXP_LIKE('three', 'one|two|three|four|five');
-- This evaluates as: 'three' = 'one' OR 'three' = 'two' OR ...

Advanced Pattern Matching Techniques

When dealing with many patterns, repeating OR statements becomes impractical. These solutions help externalize the pattern list.

4. Joining Against a List of Patterns (Set-Based Logic)

This method involves creating a derived table or temporary structure containing your patterns and joining the main table to it using LIKE. This is highly effective for dynamic pattern sets.

Using a Derived Table (Common in SQL Server/MySQL):

SELECT DISTINCT y.*
FROM YourTable y
INNER JOIN (
    SELECT 'bla%' AS Pattern
    UNION ALL SELECT '%foo%'
    UNION ALL SELECT 'batz%'
) AS t ON y.something LIKE t.Pattern;

Using EXISTS (To prevent row duplication):

Using EXISTS is often preferred over INNER JOIN when you only need to verify existence and avoid returning duplicate rows if a main table record matches multiple patterns.

-- SQL Server Example using table variables
DECLARE @filter TABLE (searchtext VARCHAR(50));
INSERT INTO @filter VALUES ('lazy'), ('hotness'), ('cupcakes');

SELECT e.*
FROM @example e
WHERE EXISTS (
    SELECT 1
    FROM @filter f
    WHERE e.sampletext LIKE '%' + f.searchtext + '%'
);

5. Utilizing Database-Specific Set Syntax (LIKE ANY/LIKE ALL)

Some modern or specific RDBMS versions natively support syntax similar to IN for pattern matching.

  • PostgreSQL: Supports LIKE ANY or ILIKE ANY (case-insensitive) combined with an array:

    -- PostgreSQL specific syntax
SELECT id, name
FROM tb_organisation
WHERE name ILIKE ANY (ARRAY['%wembley%', '%south%']);

  • Teradata: Supports LIKE ANY syntax directly:

    -- Teradata specific syntax
SELECT *
FROM Random_Table A
WHERE Lower(A.TRAN_1_DSC) LIKE ANY
(
    '%american%express%centurion%bank%',
    '%bofi%federal%bank%',
    '%american%express%bank%fsb%'
);

6. Pattern Splitting via Functions or Dynamic SQL

When the list of patterns is passed as a comma-delimited string, you must split the string before applying the LIKE comparisons.

  • SQL Server (2016+): Use the built-in STRING_SPLIT function, then join or iterate:

    DECLARE @dashboard nvarchar(50) = 'P1%,P7%';
SELECT p.*
FROM Project p
JOIN STRING_SPLIT(@dashboard, ',') AS sp ON p.ProjectNumber LIKE sp.value;

  • User-Defined Functions (UDFs): For older SQL Server versions or custom needs, a user-defined split function can be created to turn the delimited string into a table format, which can then be joined against (similar to Solution 4).

  • Dynamic SQL (SQL Server): For extreme flexibility or when patterns are derived from other tables, Dynamic SQL allows you to construct the full OR chain programmatically.

    -- Conceptual Dynamic SQL Construction in T-SQL
-- Generates the WHERE clause: (PersonName like 'FirstA%' OR PersonName like 'FirstB%')
DECLARE @subWhere nvarchar(MAX);
SET @subWhere = STUFF(
  (
    SELECT ' OR PersonName like ''' + [NameToSelect] + '%'''
    FROM [NamesToSelect] t FOR XML PATH('')
  ), 1, 4, ''); -- Removes leading ' OR '

7. Oracle Collection Types

In Oracle, you can employ SQL collection types within an EXISTS clause to check patterns against a temporary, in-memory collection:

-- Using a pre-defined collection type (like ku$_vcnt)
WHERE EXISTS (
    SELECT 1
    FROM TABLE(ku$_vcnt('bla%', '%foo%', 'batz%'))
    WHERE something LIKE column_value
);

FAQs on SQL Query Alternatives for Combining LIKE and IN

Q: Can I use the IN operator directly with multiple LIKE patterns

ANS: No, standard SQL dialects like T-SQL and PL/SQL do not permit the direct use of wildcards within an IN clause as IN expects discrete, exact values.

Q: Which method offers the best performance for many LIKE conditions

ANS: Full-Text Search (FTS) is generally the highest performing solution if the data is indexed appropriately. Failing that, using multiple OR predicates or the EXISTS pattern with a derived table often outperforms regex solutions for high volumes.

Q: Is REGEXP_LIKE supported across all major RDBMS

ANS: REGEXP_LIKE is common in Oracle and PostgreSQL. SQL Server uses functions like PATINDEX or relies on more complex CLR functions or newer regex support, but the syntax shown here is specific to Oracle.

Q: How do I avoid duplicate rows when using JOINs with multiple LIKE patterns

ANS: Employ the WHERE EXISTS clause instead of an INNER JOIN. EXISTS stops searching as soon as one match is found for the main row, preventing duplication that a standard join might cause if one record matches two different patterns.
