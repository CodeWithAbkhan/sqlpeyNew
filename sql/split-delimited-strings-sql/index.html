“SQL: Efficiently Split Delimited Strings into Name and Surname”

When working with data that contains full names in a single field, such as “Cleo, Smith”, you often need to separate the first name and last name into distinct columns. SQL Server doesn’t have a built-in SPLIT function that directly returns multiple columns, but there are several effective methods to achieve this. Let’s examine some of the most efficient and practical approaches.

Solution 1: Using SUBSTRING and CHARINDEX

This is a direct approach using SQL’s built-in string manipulation functions. It involves finding the position of the delimiter (the comma in this case) and then extracting the parts of the string before and after it.

SELECT
    Value,
    SUBSTRING(FullName, 1, CHARINDEX(',', FullName) - 1) AS Name,
    SUBSTRING(FullName, CHARINDEX(',', FullName) + 1, LEN(FullName)) AS Surname
FROM
    Table1;

This query selects the Value and then uses CHARINDEX to locate the comma. SUBSTRING then extracts the characters before the comma for the Name and the characters after the comma for the Surname.

Solution 2: Creating a User-Defined Function (UDF)

For reusability and cleaner queries, you can encapsulate the splitting logic within a User-Defined Function (UDF). This approach is particularly useful if you perform this operation frequently.

CREATE FUNCTION Split (
      @InputString VARCHAR(8000),
      @Delimiter VARCHAR(50)
)
RETURNS @Items TABLE (
      Item VARCHAR(8000)
)
AS
BEGIN
      IF @Delimiter = ' '
      BEGIN
            SET @Delimiter = ','
            SET @InputString = REPLACE(@InputString, ' ', @Delimiter)
      END

      IF (@Delimiter IS NULL OR @Delimiter = '')
            SET @Delimiter = ','

      DECLARE @Item VARCHAR(8000)
      DECLARE @ItemList VARCHAR(8000)
      DECLARE @DelimIndex INT

      SET @ItemList = @InputString
      SET @DelimIndex = CHARINDEX(@Delimiter, @ItemList, 0)

      WHILE (@DelimIndex != 0)
      BEGIN
            SET @Item = SUBSTRING(@ItemList, 0, @DelimIndex)
            INSERT INTO @Items VALUES (@Item)

            SET @ItemList = SUBSTRING(@ItemList, @DelimIndex + 1, LEN(@ItemList) - @DelimIndex)
            SET @DelimIndex = CHARINDEX(@Delimiter, @ItemList, 0)
      END

      IF @Item IS NOT NULL
      BEGIN
            SET @Item = @ItemList
            INSERT INTO @Items VALUES (@Item)
      END
      ELSE
            INSERT INTO @Items VALUES (@InputString)

      RETURN
END;
GO

Once created, you can use this function like so:

SELECT
    t.Value,
    s.Item AS Name
FROM
    Table1 t
CROSS APPLY
    Split(t.FullName, ',') s
WHERE s.Item = LEFT(t.FullName, CHARINDEX(',', t.FullName) - 1); -- Example to get the first item

Note: To get both name and surname, you might need to call the function twice or adapt it to return multiple columns, or use a technique like PIVOT.

Solution 3: Utilizing XML Functions

SQL Server’s XML capabilities offer a concise way to parse delimited strings. By converting the string to XML, you can then use .nodes() and .value() to extract individual elements.

WITH Split_Names AS (
    SELECT
        Value,
        CONVERT(XML, '<Names><name>' + REPLACE(Name, ',', '</name><name>') + '</name></Names>') AS xmlname
    FROM
        tblnames
)
SELECT
    Value,
    xmlname.value('(/Names/name/text())[1]', 'VARCHAR(100)') AS Name,
    xmlname.value('(/Names/name/text())[2]', 'VARCHAR(100)') AS Surname
FROM
    Split_Names;

This method is quite efficient for splitting strings into a fixed number of known segments. For more on XML in SQL, explore XML Data in SQL Server .

Solution 4: Employing PARSENAME

The PARSENAME function, typically used for parsing four-part SQL Server object names, can be cleverly repurposed for delimited strings if you replace the delimiter with a period.

SELECT
    Value,
    PARSENAME(REPLACE(String, ',', '.'), 2) AS Name,
    PARSENAME(REPLACE(String, ',', '.'), 1) AS Surname
FROM
    your_table_name;

This approach is straightforward for two-part splits. For a deeper dive into PARSENAME, refer to Parsing and Rotating Delimited Data in SQL Server .

Solution 5: Using CROSS APPLY with String Functions

CROSS APPLY can be combined with string functions like CHARINDEX and SUBSTRING to achieve the split. This offers flexibility, especially when dealing with more complex string structures or when you need to perform multiple operations within a single logical step.

SELECT
    ParsedData.*
FROM
    MyTable mt
CROSS APPLY (SELECT str = mt.String + ',,') AS f1
CROSS APPLY (SELECT p1 = CHARINDEX(',', str)) AS ap1
CROSS APPLY (SELECT p2 = CHARINDEX(',', str, p1 + 1)) AS ap2
CROSS APPLY (
    SELECT
        Name = SUBSTRING(str, 1, p1 - 1),
        Surname = SUBSTRING(str, p1 + 1, p2 - p1 - 1)
) AS ParsedData;

This method breaks down the splitting process into distinct steps using CROSS APPLY for clarity.

Solution 6: Leveraging STRING_SPLIT (SQL Server 2016+)

If you are using SQL Server 2016 or later, the STRING_SPLIT function is the most modern and often the most efficient built-in solution. It returns a table with a single column named value.

-- Ensure your database compatibility level is 130 or higher
-- ALTER DATABASE YourDatabaseName SET COMPATIBILITY_LEVEL = 130;

SELECT
    cs.id,
    ss.value AS SplitValue
FROM
    commasep cs
CROSS APPLY
    STRING_SPLIT(cs.string, ',');

This function is ideal for splitting strings into rows. If you need to pivot these rows into columns for name and surname, you can combine it with PIVOT or conditional aggregation. For more on this, see Using STRING_SPLIT in SQL Server .

Solution 7: Advanced UDFs and Techniques

Many other UDFs and techniques exist, each with its own advantages. For instance, a UDF that converts a delimited string into a table (fn_CSVToTable) can be very useful.

-- Example of a UDF to parse CSV to a table
CREATE FUNCTION [dbo].[fn_CSVToTable]
(
    @CSVList VARCHAR(MAX)
)
RETURNS @Table TABLE (ColumnData VARCHAR(100))
AS
BEGIN
    IF RIGHT(@CSVList, 1) <> ','
        SELECT @CSVList = @CSVList + ',';

    DECLARE @Pos BIGINT, @OldPos BIGINT
    SELECT @Pos = 1, @OldPos = 1;

    WHILE @Pos < LEN(@CSVList)
    BEGIN
        SELECT @Pos = CHARINDEX(',', @CSVList, @OldPos)
        INSERT INTO @Table SELECT LTRIM(RTRIM(SUBSTRING(@CSVList, @OldPos, @Pos - @OldPos)));
        SELECT @OldPos = @Pos + 1;
    END
    RETURN;
END;
GO

-- Usage example:
-- SELECT * FROM dbo.fn_CSVToTable('Cleo, Smith');

The DelimitedSplit8K function by Jeff Moden is another highly optimized option for splitting strings, often used with CROSS APPLY and PIVOT for transforming split results into columns. You can find discussions and implementations of such advanced functions on SQL Server community sites. Choosing the Right Method

The best method depends on your SQL Server version, performance requirements, and the complexity of the data.

  • For SQL Server 2016+, STRING_SPLIT is often the preferred choice for its simplicity and efficiency when combined with pivoting techniques.
  • For older versions or when more control is needed, UDFs using SUBSTRING/CHARINDEX or XML methods are robust.
  • PARSENAME is a quick trick for simple two-part splits but has limitations with periods in the data.

We encourage you to experiment with these solutions to find the one that best fits your specific needs and environment.

FAQs on Splitting Delimited Strings in SQL

Q: How do I split a full name like 'John Doe' into first name and last name columns in SQL

ANS: You can use functions like SUBSTRING and CHARINDEX to find the comma and extract the parts, or use XML functions, PARSENAME after replacing the delimiter with a period, or create a User-Defined Function (UDF) for more complex scenarios. For SQL Server 2016+, STRING_SPLIT is a good option.

Q: Is there a built-in SPLIT function in SQL Server

ANS: SQL Server 2016 introduced STRING_SPLIT, which returns a table of split values. Prior to that, there isn’t a direct built-in function that returns multiple columns from a single split operation; you typically use string manipulation functions, XML, or UDFs.

Q: Can PARSENAME handle names with periods in them

ANS: No, PARSENAME is designed for four-part object names delimited by periods. If your delimited string contains periods within its segments (e.g., “Dr. John Doe”), using PARSENAME might lead to incorrect results or NULL values. It’s best to use alternative methods like UDFs or XML for such cases.

Q: Which method is most performant for splitting strings in SQL

ANS: Generally, STRING_SPLIT (SQL Server 2016+) is highly optimized. For older versions, XML-based methods or well-written UDFs like Jeff Moden’s DelimitedSplit8K tend to offer good performance. Direct SUBSTRING and CHARINDEX can also be efficient for simple, two-part splits. Performance can vary based on the data size and complexity.

Q: How can I split a string with multiple delimiters

ANS: If you have multiple delimiters or complex patterns, a custom UDF that handles more intricate logic or multiple passes of string manipulation functions would be necessary. You might also preprocess the string to normalize delimiters before splitting.
