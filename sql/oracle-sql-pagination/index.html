“Oracle SQL Pagination: Efficiently Limit and Offset Query Results”

When working with large datasets in Oracle databases, retrieving all records at once can be inefficient. Implementing pagination, which involves fetching data in smaller, manageable chunks, is crucial for performance and user experience. This post delves into various Oracle SQL methods for limiting and offsetting query results, covering both older and newer Oracle versions.

Solution 1: Using Subqueries with ROWNUM

A classic approach for limiting results in older Oracle versions involves nested subqueries and the ROWNUM pseudocolumn.

SELECT *
FROM (
    SELECT emp.*
    FROM emp
    ORDER BY sal DESC
)
WHERE ROWNUM <= 5;

This query first sorts the emp table by salary in descending order within an inner subquery. The outer query then selects the top 5 rows based on the ROWNUM assigned before the outer query’s filter is applied.

For scenarios requiring both a lower and upper bound (e.g., retrieving rows 11-20), the query becomes more intricate:

SELECT *
FROM (
    SELECT a.*, ROWNUM rnum
    FROM (
        -- Your query with ORDER BY goes here
        SELECT *
        FROM emp
        ORDER BY sal DESC
    ) a
    WHERE ROWNUM <= 20 -- Upper limit
)
WHERE rnum >= 11; -- Lower limit

This method assigns a sequential number (rnum) to each row after the initial ordering and then filters based on this assigned number.

Solution 2: Leveraging the FETCH FIRST Clause (Oracle 12c and later)

Oracle 12c introduced the SQL:2008 standard FETCH FIRST clause, providing a more concise and readable syntax for row limiting and pagination.

To retrieve the first 10 results:

SELECT *
FROM sometable
ORDER BY name
FETCH FIRST 10 ROWS ONLY;

To retrieve rows starting from a specific offset and limiting the count:

SELECT *
FROM sometable
ORDER BY name
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;

This statement skips the first 20 rows and then retrieves the next 10 rows, effectively achieving pagination. For more details on this syntax, refer to the Oracle SQL Reference .

Solution 3: Performance Comparisons of Limiting Techniques

When evaluating different approaches, performance can vary significantly, especially with large datasets. The “AskTom” method (nested ROWNUM subqueries) and analytical approaches (using analytic functions) generally show better performance than simpler, less optimized methods when dealing with large tables and specific row ranges.

  • AskTom Method: Typically performs well due to its structured filtering.
  • Analytical Method: Using functions like ROW_NUMBER() can be efficient.
  • Short Alternative: Often less performant for complex pagination.

Performance tests on tables with millions of records indicate that the AskTom method often leads, with analytical methods closely following, especially for retrieving specific ranges.

Solution 4: Analytic Functions for Row Limiting

Analytic functions, such as ROW_NUMBER(), RANK(), and DENSE_RANK(), offer another flexible way to manage row ordering and selection.

To fetch rows 10 through 20:

SELECT *
FROM (
   SELECT t.*, ROW_NUMBER() OVER (ORDER BY name) AS MyRow
   FROM sometable t
)
WHERE MyRow BETWEEN 10 AND 20;

Using RANK() or DENSE_RANK() might include tied rows if the ordering column has duplicate values, potentially returning more rows than expected if not handled carefully.

Solution 5: Oracle 12c Row Limiting Clause Details

As highlighted in Solution 2, the OFFSET and FETCH NEXT syntax is the modern standard for pagination in Oracle 12c and later. It directly addresses the need to skip rows and retrieve a specific quantity.

SELECT *
FROM sometable
ORDER BY name
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;

This method is generally preferred for its clarity and adherence to SQL standards.

Solution 6: Understanding ROWNUM Behavior

It’s critical to understand how ROWNUM works in Oracle. ROWNUM is assigned to a row after it passes the query’s filter predicates but before aggregation or sorting. It is incremented only after being assigned. This behavior explains why this query returns no rows:

SELECT *
FROM (
    SELECT *
    FROM some_table
    ORDER BY some_column
)
WHERE ROWNUM <= 4 AND ROWNUM > 1;

The ROWNUM > 1 condition fails for the very first row processed because ROWNUM is assigned as 1, and then the condition is evaluated. Since it doesn’t pass, ROWNUM never increments to 2.

The correct way to filter ROWNUM for a range is to use a subquery to assign the ROWNUM first and then filter on that assigned number:

SELECT *
FROM (
    SELECT *, ROWNUM rnum
    FROM (
        SELECT *
        FROM skijump_results
        ORDER BY points
    )
    WHERE ROWNUM <= 4
)
WHERE rnum > 1;

For more in-depth explanations, see articles on Oracle ROWNUM Explained and Top-N and pagination queries .

Solution 7: Internal Expansion of FETCH FIRST Syntax

Internally, Oracle 12c and later versions often expand the FETCH FIRST syntax into queries utilizing analytic functions like ROW_NUMBER() or RANK(). You can verify this using DBMS_UTILITY.EXPAND_SQL_TEXT.

For example, FETCH FIRST 5 ROWS ONLY might expand to:

SELECT "A1"."VAL" "VAL"
FROM  (SELECT "A2"."VAL" "VAL","A2"."VAL" "rowlimit_$_0",
               ROW_NUMBER() OVER ( ORDER BY "A2"."VAL" DESC ) "rowlimit_$$_rownumber"
      FROM "ROWNUM_ORDER_TEST" "A2") "A1"
WHERE "A1"."rowlimit_$$_rownumber" <= 5 ORDER BY "A1"."rowlimit_$_0" DESC;

And FETCH FIRST 5 ROWS WITH TIES might expand using RANK():

SELECT "A1"."VAL" "VAL"
FROM  (SELECT "A2"."VAL" "VAL","A2"."VAL" "rowlimit_$_0",
              RANK() OVER ( ORDER BY "A2"."VAL" DESC ) "rowlimit_$$_rank"
       FROM "ROWNUM_ORDER_TEST" "A2") "A1"
WHERE "A1"."rowlimit_$$_rank" <= 5 ORDER BY "A1"."rowlimit_$_0" DESC

The OFFSET clause is also expanded similarly, incorporating ROW_NUMBER() and range filtering.

Solution 8: Oracle 21c and Simpler Limit Syntax

In Oracle 21c, the syntax for limiting results can be quite straightforward, especially when combined with ROWNUM for basic top-N queries:

select * from course where ROWNUM <= 10;

However, for true pagination with offsets, the OFFSET ... FETCH NEXT ... syntax remains the recommended approach.

Solution 9: Alternative ROWNUM Pagination

A slightly different structure for ROWNUM-based pagination involves assigning the rownum alias in a single nested query:

SELECT *
FROM   (SELECT t.*,
               rownum AS rn
        FROM   shhospede t) a
WHERE  a.rn BETWEEN 10 AND 20; -- Example for rows 10-20

This is cleaner than the multi-nested ROWNUM approaches but still relies on the underlying ROWNUM behavior.

Solution 10: Advanced FETCH FIRST Options

The FETCH FIRST clause offers flexibility beyond simple row counts:

  • FETCH FIRST n ROWS ONLY: Retrieves the top n rows.
  • OFFSET n ROWS FETCH NEXT N1 ROWS ONLY: Skips n rows and fetches the next N1 rows.
  • FETCH FIRST N PERCENT ROWS ONLY: Retrieves a specific percentage of rows.

Example:

SELECT *
FROM XYZ a
ORDER BY a.pqr
FETCH FIRST 10 ROWS ONLY;

Solution 11: Combining ROWNUM with IN and ORDER BY

When performing subqueries for filtering, ensuring correct ordering and limiting is key.

SELECT *
FROM sometable1 so
WHERE so.id IN (
    SELECT so2.id
    FROM sometable2 so2
    WHERE ROWNUM <= 5
)
ORDER BY so.somefield
FETCH FIRST 100 ROWS ONLY; -- or use ROWNUM <= 100 in older versions

Note that ROWNUM within the subquery is applied first, and then the outer query applies its own limiting or ordering.

Solution 12: Pagination with Offset and Fetch Next

The OFFSET and FETCH NEXT syntax is highly effective for implementing pagination logic. By adjusting the OFFSET and FETCH NEXT values, you can control which page of results is displayed.

SELECT "ID", "COL1", "ETC.."
FROM tblTest
WHERE "COL1" = 'test'
ORDER BY "ID" DESC
OFFSET x ROWS
FETCH NEXT y ROWS ONLY;

Here, x represents the number of rows to skip (page number * rows per page), and y is the number of rows per page.

Solution 13: Using ROW_NUMBER() for Range Selection

The ROW_NUMBER() analytic function is versatile for selecting specific ranges of rows.

To get the 5th row:

SELECT *
FROM (
    SELECT ROW_NUMBER() OVER (ORDER BY sal DESC) AS rn, *
    FROM EMP
) EMP
WHERE rn = 5;

To get rows greater than the 5th:

SELECT *
FROM (
    SELECT ROW_NUMBER() OVER (ORDER BY sal DESC) AS rn, *
    FROM EMP
) EMP
WHERE rn > 5;

Solution 14: Handling Duplicate Values in Pagination

When the column used for ordering contains duplicate values, it’s important to ensure consistent ordering. Using ROW_NUMBER() or ensuring a stable sort order is recommended.

SELECT T.*
FROM (
    SELECT *
    FROM Table
    ORDER BY "name" -- Or a combination of columns for stability
) T
OFFSET (1) * 100 ROWS -- Skips first 100 rows for page 2
FETCH NEXT 100 ROWS ONLY;

Solution 15: Alternative with WITH Clause and ROWNUM

A less common but functional approach uses a WITH clause (Common Table Expression) with ROWNUM:

WITH base AS (
    SELECT *
    FROM sometable
    ORDER BY name
),
twenty AS (
    SELECT *
    FROM base
    WHERE rownum < 30
    ORDER BY name
)
SELECT *
FROM twenty
WHERE rownum > 20
ORDER BY name;

This breaks down the logic, first ordering and selecting a broad set, then filtering again. However, the FETCH FIRST syntax is generally more direct.

FAQs on Oracle SQL Pagination

Q: How do I get the top 5 rows in Oracle

ANS: You can use ROWNUM <= 5 in older versions or FETCH FIRST 5 ROWS ONLY in Oracle 12c and later, always with an ORDER BY clause.

Q: What is the difference between ROWNUM and FETCH FIRST

ANS: ROWNUM is an Oracle-specific pseudocolumn assigned before sorting and filtering. FETCH FIRST is a SQL standard clause introduced in Oracle 12c, offering a clearer and more robust way to limit and paginate results.

Q: How to implement pagination for displaying results page by page

ANS: Use the OFFSET x ROWS FETCH NEXT y ROWS ONLY syntax. x is the number of rows to skip (calculated based on current page and items per page), and y is the number of items to display per page.

Q: Can ROWNUM be used for offset

ANS: Directly using ROWNUM for offset is tricky. You need nested queries where the inner query assigns ROWNUM as an alias, and the outer query filters on this alias to achieve an offset effect. The FETCH FIRST clause is much simpler for offsets.

Q: How does Oracle handle ties with FETCH FIRST

ANS: You can use FETCH FIRST n ROWS WITH TIES to include all rows that have the same value in the ORDER BY clause as the last row retrieved. This uses the RANK() analytic function internally.
