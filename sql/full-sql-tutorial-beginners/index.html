SQL Syntax

SELECT Statement

The SELECT statement is used when retrieving data selectively from a database. The selected data is usually returned in a table format, commonly referred to as a result set. The basic syntax for the SELECT statement is as follows:

SELECT <field_name> FROM <table_name>

Using * retrieves data from all fields, or you can specify field names to fetch data from specific fields.

SELECT * FROM Customers
SELECT CustomerID, Country FROM Customers

In many cases, data fields contain duplicate values. You can use the SELECT DISTINCT statement to retrieve rows with unique values, eliminating duplicates.

SELECT DISTINCT Country FROM Customers

WHERE Clause

While the SELECT statement retrieves rows from the data table, the WHERE clause selects columns. It extracts records that meet the conditions specified in the WHERE clause.

SELECT <field_name> FROM <table_name> WHERE <condition>

For example, to retrieve all information about customers from Germany or customers with CustomerID 1:

SELECT * FROM Customers WHERE Country = 'Germany'
SELECT * FROM Customers WHERE CustomerID = 1

The WHERE clause supports various operators:

  • =: Equal
  • <>: Not equal
  • >: Greater than
  • <: Less than
  • >=: Greater than or equal
  • <=: Less than or equal
  • BETWEEN: Between an inclusive range
  • LIKE: Search for a pattern
  • IN: To specify multiple values for a column

AND, OR, and NOT Operators

The WHERE clause allows combining multiple conditions using the AND, OR, and NOT operators to filter data based on various patterns.

SELECT <field_name> FROM <table_name> WHERE <condition1> AND <condition2> AND <condition3>
SELECT <field_name> FROM <table_name> WHERE <condition1> OR <condition2> OR <condition3>
SELECT <field_name> FROM <table_name> WHERE NOT <condition>

For example, retrieving information about customers from Germany whose city is Berlin:

SELECT * FROM Customers WHERE Country='Germany' AND City='Berlin'

To get information about customers who are neither from Germany nor from Korea:

SELECT * FROM Customers WHERE NOT Country='Germany' AND NOT Country='Korea'

ORDER BY for Sorting

When you want to sort the data retrieved by the SELECT statement in ascending or descending order, you use the ORDER BY clause. By default, it sorts in ascending order.

SELECT <field_name> FROM <table_name> ORDER BY <field_name> ASC|DESC

For example, sorting customer information by country in ascending order and customer names in descending order:

SELECT * FROM Customers ORDER BY Country ASC, CustomerName DESC

INSERT INTO Statement

If you can extract data from a database, you can also insert data. The INSERT INTO statement inserts a new record into the specified table. You can either specify field names to insert values into specific fields or provide values for all fields in the table. The order of fields and values must match.

INSERT INTO <table_name> (field_name) VALUES <values>
INSERT INTO <table_name> VALUES <values>

Inserting data into the Customers table for CustomerName, ContactName, Address, City, PostalCode, and Country:

INSERT INTO Customers (CustomerName, ContactName, Address, City, PostalCode, Country)
VALUES ('Namwoo Seo', 'namwoo', 'Bundang-gu', 'Seoul', '13433', 'South Korea')

Null Values

Null Value indicates the absence of a value. The IS NULL and IS NOT NULL operators are used to check for NULL values.

SELECT <field_names> FROM <table_name> WHERE <field_name> IS NULL
SELECT <field_names> FROM <table_name> WHERE <field_name> IS NOT NULL

Retrieve customer information with no address:

SELECT * FROM Customers WHERE Address IS NULL

UPDATE Statement

The UPDATE statement is used to modify existing data in a table. Be cautious, as omitting the WHERE condition updates all records in the specified set.

UPDATE <table_name> SET <field1 = value1, field2 = value2> WHERE <condition>

For example, updating the contact name and city information for a customer with CustomerID 1:

UPDATE Customers SET ContactName='Youngchan', City='Seville' WHERE CustomerID = 1

Updating contact names and addresses for customers not from Germany:

UPDATE Customers SET ContactName='Namwoo', Address='Sinsa' WHERE NOT Country='Germany'

DELETE Statement

Be cautious with the DELETE statement; omitting the WHERE condition deletes all data from the table.

DELETE FROM <table_name> WHERE <condition>

Deleting information for the customer with the name ‘Alfreds Futterkiste’:

DELETE FROM Customers WHERE CustomerName = 'Alfreds Futterkiste'

TOP, LIMIT, and ROWNUM Clauses

The TOP, LIMIT, ROWNUM clauses limit the number of records returned. These are necessary to prevent issues like memory overload when dealing with thousands of records.

/* SQL Server */
SELECT TOP <number> | PERCENT <field_names> FROM <table_name> WHERE <condition>

/* MySQL */
SELECT <field_names> FROM <table_name> WHERE <condition> LIMIT <number>

/* Oracle */
SELECT <field_names> FROM <table_name> WHERE ROWNUM <= <number>

Retrieve the top three records from the Customers table:

SELECT TOP 3 * FROM Customers

Retrieve columns representing 50% of German customer information:

SELECT * FROM Customers WHERE Country='Germany' LIMIT 3

MIN(), MAX() Functions

The MIN() function returns the minimum value from a specified field, and MAX() returns the maximum value.

SELECT MIN(<field_name>) FROM <table_name> WHERE <condition>
SELECT MAX(<field_name>) FROM <table_name> WHERE <condition>

Retrieve the smallest and largest CustomerID:

SELECT MIN(CustomerID) AS smallestID FROM Customers
SELECT MAX(CustomerID) AS biggestID FROM Customers

COUNT(), AVG(), SUM() Functions

COUNT() returns the number of rows or rows that satisfy a condition. AVG() returns the average value, and SUM() returns the total sum of a numeric column.

SELECT COUNT(<field_name>) FROM <table_name> WHERE <condition>
SELECT AVG(<field_name>) FROM <table_name> WHERE <condition>
SELECT SUM(<field_name>) FROM <table_name> WHERE <condition>

SELECT SUM(QuantityPerUnit) AS TotalQuantity FROM Products WHERE CategoryID = 2

GROUP BY Clause

The GROUP BY clause groups rows that have the same values in specified columns into summary rows.

SELECT <field_name(s)>, AGGREGATE_FUNCTION(<field_name>) FROM <table_name> WHERE <condition> GROUP BY <field_name(s)>

For example, calculate the average unit price for each category:

SELECT CategoryID, AVG(UnitPrice) AS AvgPrice FROM Products GROUP BY CategoryID

Count the number of products in each supplier’s product line:

SELECT SupplierID, COUNT(ProductID) AS ProductCount FROM Products GROUP BY SupplierID

HAVING Clause

The HAVING clause is used in combination with the GROUP BY clause to filter the results further.

SELECT <field_name(s)>, AGGREGATE_FUNCTION(<field_name>) FROM <table_name> WHERE <condition> GROUP BY <field_name(s)> HAVING <condition>

For example, find categories with an average unit price greater than 15:

SELECT CategoryID, AVG(UnitPrice) AS AvgPrice FROM Products GROUP BY CategoryID HAVING AVG(UnitPrice) > 15

Count the number of products in each supplier’s product line, only showing suppliers with more than 5 products:

SELECT SupplierID, COUNT(ProductID) AS ProductCount FROM Products GROUP BY SupplierID HAVING COUNT(ProductID) > 5

JOINS

A JOIN clause is used to combine rows from two or more tables based on a related column between them. Common types include INNER JOIN, LEFT JOIN (or LEFT OUTER JOIN), RIGHT JOIN (or RIGHT OUTER JOIN), and FULL JOIN (or FULL OUTER JOIN).

SELECT <fields> FROM <table1> JOIN <table2> ON <table1.column = table2.column>

For example, retrieve orders with customer names:

SELECT Orders.OrderID, Customers.CustomerName FROM Orders INNER JOIN Customers ON Orders.CustomerID = Customers.CustomerID

Retrieve all customers and their orders, including those with no orders:

SELECT Customers.CustomerName, Orders.OrderID FROM Customers LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID

Subqueries

A subquery is a query nested inside another query. It can be used within various clauses, such as SELECT, FROM, WHERE, and more.

For example, find customers who placed orders:

SELECT CustomerID, CustomerName FROM Customers WHERE CustomerID IN (SELECT CustomerID FROM Orders)

Retrieve orders with values greater than the average order value:

SELECT * FROM Orders WHERE OrderValue > (SELECT AVG(OrderValue) FROM Orders)

Views

A view is a virtual table based on the result of a SELECT statement. It allows you to store complex queries that can be referenced as if they were tables.

CREATE VIEW <view_name> AS SELECT <fields> FROM <tables> WHERE <condition>

For example, create a view of customers from Germany:

CREATE VIEW GermanCustomers AS SELECT * FROM Customers WHERE Country = 'Germany'

Once created, you can use the view in queries as if it were a table:

SELECT * FROM GermanCustomers

Indexing

Indexing is a database feature that improves the speed of data retrieval operations on a database table. It is based on a data structure (index) that provides a fast way to look up data.

CREATE INDEX <index_name> ON <table_name> (column1, column2, ...)

For example, create an index on the “ProductID” column of the “Products” table:

CREATE INDEX idx_ProductID ON Products (ProductID)

Transactions

A transaction is a sequence of one or more SQL statements that are executed as a single unit of work. Transactions are used to maintain the integrity of the database by ensuring that the database remains in a consistent state.

BEGIN TRANSACTION
-- SQL statements
COMMIT

For example, transferring money between accounts:

BEGIN TRANSACTION
UPDATE Accounts SET Balance = Balance - 100 WHERE AccountID = 123
UPDATE Accounts SET Balance = Balance + 100 WHERE AccountID = 456
COMMIT

If an error occurs or the transaction needs to be rolled back, you can use the ROLLBACK statement.

ROLLBACK

Transactions help maintain the consistency and reliability of data in a database.

Database Normalization

Database normalization is the process of organizing data in a database to reduce redundancy and improve data integrity. Normalization involves dividing large tables into smaller tables and defining relationships between them.

The most common normalization forms are:

  • First Normal Form (1NF)
  • Second Normal Form (2NF)
  • Third Normal Form (3NF)
  • Boyce-Codd Normal Form (BCNF)
  • Fourth Normal Form (4NF)
  • Fifth Normal Form (5NF)

Each normalization form has specific rules and conditions that must be satisfied.

SQL Best Practices

  1. Use meaningful names for tables and columns.
  2. Avoid using reserved keywords as table or column names.
  3. Normalize your database to reduce redundancy.
  4. Use indexes on columns frequently used in search conditions.
  5. Be cautious with transactions to maintain data integrity.
  6. Regularly back up your database to prevent data loss.
  7. Write efficient queries to improve performance.
  8. Test and optimize queries for large datasets.
  9. Use views to simplify complex queries.
  10. Keep the database schema up to date with the application.

Remember, SQL is a powerful language for managing and manipulating relational databases. Regular practice and continuous learning are essential for mastering SQL and becoming proficient in database management.

### UNION

The `UNION` operator allows you to combine the result sets of two or more `SELECT` statements into a single result set. Each `SELECT` statement must have the same number of selected columns, and the data types being included should be similar. Additionally, each result set should follow the same sorting order.

```sql
SELECT <field_names> FROM <table1> UNION SELECT <field_names> FROM <table2>

UNION ALL

To allow duplicate values during the UNION process, you can use UNION ALL.

SELECT <field_names> FROM <table1> UNION ALL SELECT <field_names> FROM <table2>

Let’s use the UNION operator to fetch and combine all city information from the Customers and Suppliers tables.

SELECT City FROM Customers UNION SELECT City FROM Suppliers ORDER BY City

In the example above, let’s retrieve city information for German customers using the WHERE clause to filter the data. (Allow duplicate values)

SELECT City FROM Customers WHERE Country ='Germany' UNION ALL SELECT City FROM Suppliers WHERE Country ='Germany' ORDER BY City

GROUP BY Clause

The GROUP BY clause is commonly used with aggregate functions like COUNT, MAX, MIN, SUM, and AVG. For instance, if you want to know how many customers there are per country, you would first group the data by country and then count the number of occurrences.

SELECT Country, COUNT(CustomerID) FROM Customers GROUP BY Country ORDER BY COUNT(CustomerID) ASC

Let’s combine the GROUP BY and JOIN clauses. Join the Orders and Shippers tables to find out how many orders each shipping company has.

SELECT Shippers.ShipperName, COUNT(Order.OrderID) FROM Orders LEFT JOIN Shippers ON Orders.ShipperID = Shippers.ShipperID GROUP BY ShipperName

HAVING Clause

The HAVING clause provides a condition for aggregate functions like COUNT, MAX, MIN, SUM, and AVG. It is used in conjunction with the GROUP BY clause and is necessary because WHERE cannot be used with these functions.

Let’s create a table with country-specific customer counts exceeding 5.

SELECT Country, COUNT(CustomerID) FROM Customers GROUP BY Country HAVING COUNT(CustomerID) > 5

Sort the above example by customer count in descending order.

SELECT Country, COUNT(CustomerID) FROM Customers GROUP BY Country HAVING COUNT(CustomerID) > 5 ORDER BY COUNT(CustomerID) DESC

Create a table showing the names and order counts of employees whose received orders exceed 10.

SELECT Employees.LastName, COUNT(Orders.OrderID) AS NumberofOrders FROM Orders INNER JOIN Employees ON Orders.EmployeeID = Employees.EmployeeID GROUP BY LastName HAVING COUNT(Orders.OrderID) > 10

Check if the order count for employees ‘Davolio’ and ‘Fuller’ exceeds 25 and, if so, create a table showing their order counts.

SELECT Employees.LastName, COUNT(Orders.OrderID) AS NumberofOrders FROM Orders INNER JOIN Employees ON Orders.EmployeeID = Employees.EmployeeID WHERE LastName = 'Davolio' or LastName='Fuller' GROUP BY LastName HAVING COUNT(Orders.OrderID) > 25

EXISTS Operator

The EXISTS operator is used to test a subquery. If the subquery returns one or more records, EXISTS returns True. It not only returns True but can also apply the subquery’s condition to the main query.

Let’s return a list of supplier names from the Suppliers table where the price of their products is below 20.

SELECT SupplierName FROM Suppliers WHERE EXISTS (SELECT ProductName FROM Products WHERE SupplierID = Suppliers.SupplierID AND Price < 20)

Return a list of supplier names from the Suppliers table that has a product with a price of exactly 20.

SELECT SupplierName FROM Suppliers WHERE EXISTS (SELECT ProductName FROM Products WHERE SupplierID = Suppliers.SupplierID AND Price = 20)

ANY and ALL Operators

The ANY and ALL operators are used with WHERE and HAVING clauses. ANY returns True if any value in the subquery matches the condition, while ALL returns True if all values in the subquery match the condition.

Let’s check for products with a quantity of 10 in the OrderDetails table and return their names from the Products table using ANY.

SELECT ProductName FROM Products WHERE ProductID = ANY (SELECT ProductID FROM OrderDetails WHERE Quantity = 10)

Return product names from the Products table where the quantity in the OrderDetails table for all orders is 10 using ALL.

SELECT ProductName FROM Products WHERE ProductID = ALL (SELECT ProductID FROM OrderDetails WHERE Quantity = 10)

SELECT INTO Statement

The SELECT INTO statement is used to copy data from one table to another without creating a new table.

SELECT <field_names> INTO <newtable> FROM <oldtable> WHERE <conditions>

Let’s copy all data from the Customers table to a new table called Customerbackup.

SELECT * INTO Customerbackup FROM Customers

Copy customer information from the Customers table for German customers to a new table called CustomerGermany.

SELECT * INTO CustomerGermany FROM Customers WHERE Country = 'Germany'

Perform a LEFT JOIN on the Customers and Orders tables for customers with the same CustomerID, and copy only the customer names and order IDs to a table named Customerbackup.

SELECT Customers.CustomerName, Orders.OrderID INTO Customerbackup FROM Customers LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID

Use the SELECT INTO statement to create an empty table with the same structure as an existing table.

SELECT * INTO <newtable> FROM <oldtable> WHERE 1 = 0

INSERT INTO SELECT Statement

Unlike the SELECT INTO statement, the INSERT INTO SELECT statement copies data from one table to another without creating a new table. The source and target tables must have matching data types.

INSERT INTO <table2> SELECT * FROM <table1> WHERE <conditions>

INSERT INTO <table2> (<field_names>) SELECT <field_names> FROM <table1> WHERE <conditions>

Let’s copy supplier names, cities, and country information from the Suppliers table to the Customers table.

INSERT INTO Customers (CustomerName, City, Country) SELECT SuppliersName, City, County FROM Suppliers

Copy supplier names, cities, and country information from the Suppliers table to the Customers table only for suppliers with the country ‘Germany’.

INSERT INTO Customers (CustomerName, City, Country) SELECT SupplierName, City, Country FROM Suppliers WHERE Country = 'Germany'

  • COALESCE(value1, value2, ...): Returns

the first NON NULL value from the list.

  • ISNULL(expression, value): Used in SQL Server, functionally similar to IFNULL().
  • NVL(expression, value): Used in Oracle, functionally similar to IFNULL().

FAQs on SQL

Q: What is the primary purpose of SQL SELECT queries?

A: The main purpose of SQL SELECT queries is to retrieve data from a database. These queries allow users to specify the columns they want to retrieve and the conditions for selecting the data.

Q: How does the SELECT * statement differ from selecting specific columns?

A: The SELECT * statement retrieves all columns from a table, while selecting specific columns allows users to choose only the relevant fields, improving efficiency and reducing unnecessary data retrieval.

Q: What is the significance of the DISTINCT keyword in SQL SELECT queries?

A: The DISTINCT keyword is used to filter out duplicate values from the result set. It ensures that only unique values are returned, making it useful when working with columns that may contain repetitions.

Q: Can I use SELECT DISTINCT with multiple columns?

A: Yes, SELECT DISTINCT can be applied to multiple columns. It will consider combinations of values from those columns and return unique combinations, ensuring uniqueness across the specified columns.

Q: How does the TOP, LIMIT, and ROWNUM clauses influence SQL queries?

A: The TOP clause (used in some databases) limits the number of rows returned, while LIMIT (used in MySQL) and ROWNUM (used in Oracle) achieve similar results. These clauses are essential for optimizing queries and managing result set sizes.

Q: Are there database systems that do not support the SELECT TOP clause?

A: Yes, not all database systems support the SELECT TOP clause. For instance, MySQL uses LIMIT, and Oracle uses ROWNUM for similar functionality.

Q: How can I count the number of distinct values in a column using SQL?

A: You can count the number of distinct values in a column by using the COUNT and DISTINCT keywords together. For example, SELECT COUNT(DISTINCT column_name) FROM table_name;.
