“ASP.NET Core Large File Upload Limit Configuration: IIS, Kestrel, and Application Settings”

When handling file uploads or large data payloads in ASP.NET Core applications, developers frequently encounter limitations on the maximum request body size. These restrictions are imposed at multiple layers: by the hosting environment (like IIS), by the built-in web server (Kestrel), and within the application’s configuration itself via middleware settings. Overcoming these hurdles requires coordinated adjustments across these areas.

How can one effectively raise or disable the default maximum request body size limit for uploads in an ASP.NET Core environment, accounting for deployment on IIS versus Kestrel alone?

The solutions involve configuring limits for IIS, Kestrel server options, and the FormOptions within the application startup.

Adjusting Limits via Application Code (Startup/Program)

For applications running primarily on Kestrel or needing application-level control, configuration is typically done in Startup.cs (for older projects) or Program.cs (for minimal APIs/modern hosting models).

Global Kestrel Server Configuration

To modify the maximum request body size limit globally for requests handled by Kestrel, adjust the MaxRequestBodySize property within the Kestrel options:

// Example in Program.cs using WebApplication.CreateBuilder
var builder = WebApplication.CreateBuilder(args);

builder.WebHost.ConfigureKestrel(options =>
{
  // Define a large size, e.g., 150 MB (150 * 1024 * 1024 bytes)
  long megabyte = 1048576;
  options.Limits.MaxRequestBodySize = 150 * megabyte; 
});

var app = builder.Build();
app.Run();

Alternatively, setting it to null effectively removes the limit for Kestrel:

// In older Startup.cs ConfigureServices or modern Program.cs setup:
options.Limits.MaxRequestBodySize = null; // Disables Kestrel limit

Configuring Form Options

For form data, especially multipart uploads (files), application limits are governed by FormOptions. Setting these values to int.MaxValue or long.MaxValue for body length can significantly increase the capacity.

In ConfigureServices (or equivalent configuration block):

services.Configure<FormOptions>(o =>
{
    o.ValueLengthLimit = int.MaxValue;
    // Critical for file uploads:
    o.MultipartBodyLengthLimit = long.MaxValue; // Use long.MaxValue here for very large files
    o.MultipartBoundaryLengthLimit = int.MaxValue;
    o.MultipartHeadersLengthLimit = int.MaxValue;
    // Consider these as well for maximum flexibility:
    o.BufferBodyLengthLimit = int.MaxValue;
    o.ValueCountLimit = int.MaxValue;
});

IIS Server Options (When Hosted on IIS)

If the application is behind IIS (using UseIISIntegration), the IIS server options also need tuning:

services.Configure<IISServerOptions>(options =>
{
    options.MaxRequestBodySize = int.MaxValue; // Or a specific large value
});

Adjusting Limits Per Endpoint

For security or specific operational needs, increasing the limit only for necessary endpoints is often preferred over global changes.

Using Attributes on Controller Actions

For MVC controllers, attributes provide granular control:

  1. [RequestSizeLimit(long bytes)]: Sets the maximum body size for the specific action, overriding Kestrel’s global setting for that endpoint.

    [HttpPost("upload-big-data")]
[RequestSizeLimit(100_000_000)] // Allows up to 100MB
public IActionResult MyAction([FromBody] MyViewModel data)
{
    // ... handle data
}

  2. [DisableRequestSizeLimit]: Completely bypasses Kestrel’s request size check for the decorated action or controller.

    [HttpPost("unlimited-upload")]
[DisableRequestSizeLimit] 
public async Task<IActionResult> UploadLargeFile(IFormFile file)
{
    // File reaches here, even if very large
}

  3. [RequestFormLimits]: Fine-tunes limits related to multipart form data, crucial when dealing with large files exceeding default 128MB multipart limits.

    [HttpPost("form-upload")]
[RequestSizeLimit(500 * 1024 * 1024)] // 500MB Kestrel limit
[RequestFormLimits(MultipartBodyLengthLimit = 500 * 1024 * 1024)] // 500MB Form limit
public IActionResult UploadForm([FromForm] SomeViewModel model)
{
    // ...
}

Modifying Limits Mid-Request via Middleware

If the request isn’t hitting an MVC action, or if you need dynamic logic, you can access the IHttpMaxRequestBodySizeFeature within middleware:

app.Use(async (context, next) =>
{
    var feature = context.Features.Get<IHttpMaxRequestBodySizeFeature>();
    if (feature != null)
    {
        // Set to null for unlimited size for this request
        feature.MaxRequestBodySize = null; 
        
        // Alternatively, set a specific value (e.g., 100MB)
        // feature.MaxRequestBodySize = 100_000_000; 
    }
    await next.Invoke();
});

Important Note: This configuration must occur before the request body reading process starts; otherwise, the IsReadOnly property will be true, and an exception will occur.

Adjusting Limits for IIS Hosting

When deploying to IIS, the web server itself imposes a limit via maxAllowedContentLength, which triggers an HTTP Error 413.1 - Request Entity Too Large before the request reaches Kestrel/ASP.NET Core middleware if the size is exceeded.

Web.config Configuration

This setting is managed within the <system.webServer> section of the web.config file, typically inside <requestFiltering>. The value is specified in bytes.

To allow uploads up to 1 GB (1,073,741,824 bytes):

<system.webServer>
  <security>
    <requestFiltering>
      <!-- Sets limit to 1 GB in bytes -->
      <requestLimits maxAllowedContentLength="1073741824" />
    </requestFiltering>
  </security>
</system.webServer>

For version 1.1 projects or when manually creating web.config, ensure the AspNetCoreModule handler configuration is present:

<system.webServer>
    <handlers>
      <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModule" resourceType="Unspecified"/>
    </handlers>
    <!-- Large file limit configuration goes here -->
    <security>
      <requestFiltering>
        <requestLimits maxAllowedContentLength="1073741824" />
      </requestFiltering>
    </security>
</system.webServer>

Placement consideration: For Azure Web Apps or when targeting specific paths under IIS, moving the web.config to the project root (not wwwroot) often ensures IIS picks up the settings correctly. Furthermore, using a <location> tag can scope this limit to only certain paths:

<configuration>
  <location path="SomeController/Upload">
    <system.webServer>
      <security>
        <requestFiltering>
          <!-- 500 Mb limit -->
          <requestLimits maxAllowedContentLength="524288000" />
        </requestFiltering>
      </security>
    </system.webServer>
  </location>
</configuration>

Manually Editing ApplicationHost.config

As a last resort, for global IIS changes that affect all sites, one can modify %windir%\system32\inetsrv\config\applicationhost.config by locating the <requestLimits> node and either removing maxAllowedContentLength or setting a sufficiently large value (e.g., 2,147,483,648 bytes for ~2GB). This requires running Notepad as an administrator.

Alternative Approaches for Very Large Payloads

If the data being sent is JSON or plain text (not an IFormFile) and extremely large (several GBs), buffering it into a standard MemoryStream may fail because MemoryStream capacity is capped at int.MaxValue. In such rare scenarios, building a custom stream implementation capable of handling larger-than-2GB buffers might be necessary, although buffering multi-gigabyte payloads on the server side is generally discouraged for performance and memory stability.

FAQs on ASPNET Core Large File Upload Limit Configuration

Q: What is the default content length limit imposed by IIS

ANS: The default request limit imposed by IIS, specified via maxAllowedContentLength, is typically 30,000,000 bytes (approximately 28.6 MB).

Q: Which configuration controls the limit for Kestrel server

ANS: The limit is controlled by options.Limits.MaxRequestBodySize when configuring Kestrel, often within Program.cs or Startup.cs.

Q: How to disable request size limit just for one MVC endpoint

ANS: Apply the [DisableRequestSizeLimit] attribute to the specific controller action or the entire controller class.

Q: Where should webconfig be placed for IIS to recognize limits

ANS: For reliable pickup by IIS, especially in Azure Web Apps hosting .NET Core MVC apps, the web.config file should be in the project root directory, not inside wwwroot.

Q: What is the difference between RequestSizeLimit and RequestFormLimits attributes

ANS: [RequestSizeLimit] applies to the overall request body size governed by Kestrel, while [RequestFormLimits] specifically adjusts boundaries related to multipart form parsing, such as MultipartBodyLengthLimit.
