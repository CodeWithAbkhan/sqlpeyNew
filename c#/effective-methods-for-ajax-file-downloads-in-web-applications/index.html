“Effective Methods for AJAX File Downloads in Web Applications”

This discussion outlines several proven strategies, ranging from using temporary server storage like TempData to serving files directly from memory streams.

Core Challenge: Serving Files Post-AJAX Request

The fundamental constraint is that an AJAX call is designed for data exchange, not for triggering a browser’s download mechanism directly upon completion. Therefore, the solution requires a two-step process:

  1. Client Action: AJAX post submits parameters to the server.
  2. Server Response & Client Redirection: The server generates the file content (or a reference to it) and sends back a response that instructs the browser to navigate to a separate download endpoint.

Solutions

Strategy 1: Using TempData for In-Memory File Handling (Recommended for MVC)

This approach avoids creating physical files on the server, relying instead on ASP.NET MVC’s TempData to temporarily hold the file’s byte array between requests. TempData is typically backed by Session but is automatically cleared after the subsequent request, offering better memory efficiency than relying solely on Session for high-volume exports.

Server-Side: Posting Parameters and Storing Bytes

The initial action receives the report configuration, generates the file content (using libraries like EPPlus or NPOI for Excel), saves it to a MemoryStream, and stores the resulting byte array in TempData using a unique Guid as the key.

public ActionResult PostReportPartial(ReportVM model)
{
    // 1. Validate inputs and generate report output (e.g., Excel using EPPlus)
    ExcelPackage workbook = new ExcelPackage();
    // ... Populate workbook data ...

    string fileHandle = Guid.NewGuid().ToString();

    using(MemoryStream memoryStream = new MemoryStream())
    {
        workbook.SaveAs(memoryStream);
        memoryStream.Position = 0;
        // Store the byte array in TempData, accessible by the download action
        TempData[fileHandle] = memoryStream.ToArray();
    }      

    // Return the unique reference (GUID) and file name to the AJAX success handler
    return new JsonResult() 
    { 
        Data = new { FileGuid = fileHandle, FileName = "ConfiguredReport.xlsx" }
    };
}

Client-Side: AJAX Submission and Redirection

The AJAX success function parses the JSON response and immediately redirects the browser window to a dedicated download action, passing the temporary handle.

$.ajax({
    cache: false,
    url: '/Report/PostReportPartial',
    data: _form.serialize(), 
    success: function (data) {
         // Ensure data is parsed if not automatically handled by jQuery
         var response = typeof data === 'string' ? JSON.parse(data) : data; 
         
         // Redirect browser to trigger the download
         window.location = '/Report/Download?fileGuid=' + response.FileGuid 
                           + '&filename=' + response.FileName;
    }
});

Server-Side: Serving the Download

The download action retrieves the byte array from TempData using the provided fileGuid, returns an FileResult, and ensures cleanup (which TempData usually handles automatically after this read).

[HttpGet]
public virtual ActionResult Download(string fileGuid, string fileName)
{   
   if(TempData[fileGuid] != null)
   {
        byte[] data = TempData[fileGuid] as byte[];
        // Return file with appropriate MIME type for Excel
        return File(data, "application/vnd.ms-excel", fileName);
   }   
   else
   {
        // Handle case where TempData entry expired or wasn't found
        return new EmptyResult(); 
   }
}

Strategy 2: Direct Memory Stream Return (No Temporary Server Storage)

If the user interaction does not strictly require prior parameter submission via AJAX, a direct navigation to a controller action that generates the file in memory can bypass the two-step redirect process entirely. This is often simpler if the required parameters (like an ID) are available in the URL parameters or route values.

Client-Side: Simple Window Navigation

function getWinnersExcel(drawingId) {
    // Simple navigation directly triggers the controller action to return FileResult
    window.location = "/drawing/drawingwinnersexcel?drawingid=" + drawingId;
}

Server-Side: Generating File in Memory

The controller action uses a MemoryStream to hold the generated Excel file (using tools like GemBox.Spreadsheet or EPPlus), which MVC automatically cleans up.

public FileResult DrawingWinnersExcel(int drawingId)
{
    MemoryStream stream = new MemoryStream(); 
    List<DrawingWinner> winnerList = DrawingDataAccess.GetWinners(drawingId); 
    
    // Assume ExportHelper populates the stream
    ExportHelper.GetWinnersAsExcelMemoryStream(stream, winnerList, drawingId);

    string suggestedFilename = $"Drawing_{drawingId}_Winners.xlsx";
    
    // Use the correct MIME type for modern .xlsx files
    return File(stream, "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet", suggestedFilename);
}

Strategy 3: Handling File Download Directly in AJAX Success (Browser Blob Support)

Modern browsers support creating local file blobs from received binary data, allowing the download prompt to be triggered entirely client-side within the AJAX success handler. This often requires the server to return the raw byte array directly, possibly as application/octet-stream.

Server-Side: Returning Byte Array Directly

Client-Side: Creating Blob and Triggering Download

The success callback processes the response data as an Uint8Array to construct a Blob, creates an ephemeral anchor tag, sets the download attribute, and simulates a click.

$.ajax({
    type: "GET",
    url: "/Home/Export",
    contentType: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    xhrFields: { responseType: 'blob' }, // Crucial: receive response as a Blob
    success: function (data) {
        var a = document.createElement('a');
        var url = window.URL.createObjectURL(data); // Create object URL from the received Blob
        a.href = url;
        a.download = 'List.xlsx';
        a.click();
        window.URL.revokeObjectURL(url); // Clean up the object URL
    }
});

Strategy 4: POST Request with XMLHttpRequest and Blob Response

For cases where parameters are complex or large, or if a simple window.location redirect upon AJAX success is undesirable, using the raw XMLHttpRequest (XHR) object allows precise control over the POST request and the subsequent binary response handling. This is effective for multi-parameter exports.

$("#downloadInvoice").on("click", function() {
    var xhr = new XMLHttpRequest();
    // Open POST request to the controller action that returns FileResult
    xhr.open('POST', "@Html.Raw(Url.Action("DownloadInvoice", "Controller", new { id1 = Model.Id1, id2 = Model.Id2 }))", true);
    xhr.responseType = 'arraybuffer'; // Expect binary response

    xhr.onload = function () {
        if (this.status === 200) {
            var filename = "";
            // Extract filename from Content-Disposition header
            var disposition = xhr.getResponseHeader('Content-Disposition');
            if (disposition && disposition.indexOf('attachment') !== -1) {
                // Regex to safely extract filename
                var filenameRegex = /filename[^;=\n]*=((['"]).*?\2|[^;\n]*)/;
                var matches = filenameRegex.exec(disposition);
                if (matches != null && matches[1]) filename = matches[1].replace(/['"]/g, '');
            }
            
            var type = xhr.getResponseHeader('Content-Type');
            var blob = new Blob([this.response], { type: type });

            // Trigger download using Blob URL
            var URL = window.URL || window.webkitURL;
            var downloadUrl = URL.createObjectURL(blob);

            var a = document.createElement("a");
            a.href = downloadUrl;
            a.download = filename || "downloaded_file.bin"; // Fallback filename
            document.body.appendChild(a);
            a.click();
            
            // Cleanup
            setTimeout(function() {
                URL.revokeObjectURL(downloadUrl);
                // Hide loading indicator
            }, 100); 
        }
    };
    
    xhr.setRequestHeader('Content-type', 'application/x-www-form-urlencoded');
    // Send parameters if necessary, using $.param for simple serialization if using jQuery
    xhr.send($.param(params)); 
});

public class DeleteFileAttribute : ActionFilterAttribute
{
    public override void OnResultExecuted(ResultExecutedContext filterContext)
    {
        filterContext.HttpContext.Response.Flush();

        //convert the current filter context to file and get the file path
        string filePath = (filterContext.Result as FilePathResult).FileName;

        //delete the file after download
        System.IO.File.Delete(filePath);
    }
}

If AJAX is avoided entirely, or if a POST form submission is acceptable (which causes a full page navigation), the server can write the file to a known temporary location and then rely on an Action Filter or cleanup routine to delete it post-download.

The server POST action generates the file and returns the filename:

FAQs on AJAX File Downloads

Q: Why can not I return a file directly from the initial AJAX success function

ANS: Standard AJAX success handlers are designed to process data (JSON, XML, text), not to intercept and handle browser-level file download prompts that require a full navigation or a specific file content disposition header that the browser expects during a direct link click or form submission.

Q: Should I use Session or TempData to hold file bytes temporarily

ANS: TempData is generally preferred over Session for transient data like file references because it is automatically disposed of after the next HTTP request, leading to better memory management, especially under high load or in scaled/distributed environments like Azure.

Q: What is the best MIME type for downloading modern Excel files

ANS: For .xlsx files generated by modern libraries, use "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet". For older .xls files, "application/vnd.ms-excel" is common.

Q: How do I handle large files when using the TempData approach

ANS: If file size is extremely large, consider using a database or distributed cache like Redis instead of TempData/Session to store the file reference and path, returning only the ID to the AJAX client. Strategy 8 using IMemoryCache is a good intermediate step.
