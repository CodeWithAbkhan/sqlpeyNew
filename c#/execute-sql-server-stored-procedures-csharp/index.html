“Execute SQL Server Stored Procedures in C# Examples”

Interacting with SQL Server databases from C# applications often involves executing stored procedures. Stored procedures encapsulate business logic and database operations, offering benefits like improved performance and security. This exploration delves into various methods and code patterns for invoking these procedures from your C# code.

Executing Stored Procedures Without Parameters

A fundamental way to execute a stored procedure that doesn’t require input parameters is by utilizing the SqlConnection and SqlCommand classes. The CommandType property should be set to CommandType.StoredProcedure.

Here’s a basic approach:

// Assuming 'connectionString' holds your valid database connection string
using (var conn = new SqlConnection(connectionString))
{
    using (var command = new SqlCommand("YourStoredProcedureName", conn)
    {
        CommandType = CommandType.StoredProcedure
    })
    {
        conn.Open();
        command.ExecuteNonQuery(); // Use ExecuteNonQuery for procedures that don't return a result set (e.g., INSERT, UPDATE, DELETE)
    }
}

This snippet demonstrates creating a connection, a command object targeting the stored procedure, setting the command type, opening the connection, and executing the procedure. For operations that modify data without returning rows, ExecuteNonQuery is suitable.

Executing Stored Procedures with Input Parameters

When stored procedures require parameters, you need to add them to the SqlCommand object. The Parameters.Add or Parameters.AddWithValue methods are commonly used.

Consider this example for a procedure named CustOrderHist that takes a @CustomerID:

// Assume 'connectionString' and 'custId' are defined
using (SqlConnection conn = new SqlConnection(connectionString))
{
    conn.Open();

    // Create a command object identifying the stored procedure
    SqlCommand cmd = new SqlCommand("CustOrderHist", conn);

    // Specify that the command is a stored procedure
    cmd.CommandType = CommandType.StoredProcedure;

    // Add the input parameter
    cmd.Parameters.AddWithValue("@CustomerID", custId);

    // Execute the command and process results
    using (SqlDataReader rdr = cmd.ExecuteReader())
    {
        while (rdr.Read())
        {
            Console.WriteLine("Product: {0,-35} Total: {1,2}", rdr["ProductName"], rdr["Total"]);
        }
    }
}

In this case, SqlDataReader is used because CustOrderHist likely returns a result set. AddWithValue is convenient for quick parameter additions, though for performance-critical scenarios, explicitly defining SqlDbType can be beneficial.

Another pattern for adding parameters involves using SqlParameter objects directly:

SqlCommand cmd = new SqlCommand("StoredProcedureName", con);
cmd.CommandType = CommandType.StoredProcedure;
cmd.Parameters.Add(new SqlParameter("@value", SqlDbType.VarChar, 50) { Value = txtValue.Text });

con.Open();
int rowAffected = cmd.ExecuteNonQuery();
con.Close();

This explicit parameter definition can offer more control over data types and sizes.

Handling Stored Procedures with Output Parameters

Stored procedures can also return values through output parameters. These need to be declared as output parameters when added to the command.

Here’s how to handle a stored procedure like InsertPerson that returns a new PersonID:

// Stored Procedure Definition (example)
/*
CREATE PROCEDURE [dbo].[InsertPerson]
    @FirstName nvarchar(50),
    @LastName nvarchar(50),
    @PersonID int output
AS
BEGIN
    insert [dbo].[Person](LastName,FirstName) Values(@LastName,@FirstName)
    set @PersonID = SCOPE_IDENTITY()
END
Go
*/

// C# Execution Example
static void InsertPersonInAdapter(String connectionString, String firstName, String lastName)
{
    String commandText = "dbo.InsertPerson";
    using (SqlConnection conn = new SqlConnection(connectionString))
    {
        SqlDataAdapter mySchool = new SqlDataAdapter("Select PersonID,FirstName,LastName from [dbo].[Person]", conn);

        mySchool.InsertCommand = new SqlCommand(commandText, conn);
        mySchool.InsertCommand.CommandType = CommandType.StoredProcedure;

        // Add input parameters
        mySchool.InsertCommand.Parameters.Add(new SqlParameter("@FirstName", SqlDbType.NVarChar, 50, "FirstName"));
        mySchool.InsertCommand.Parameters.Add(new SqlParameter("@LastName", SqlDbType.NVarChar, 50, "LastName"));

        // Add the output parameter
        SqlParameter personId = mySchool.InsertCommand.Parameters.Add(new SqlParameter("@PersonID", SqlDbType.Int, 0, "PersonID"));
        personId.Direction = ParameterDirection.Output;

        DataTable persons = new DataTable();
        mySchool.Fill(persons);

        DataRow newPerson = persons.NewRow();
        newPerson["FirstName"] = firstName;
        newPerson["LastName"] = lastName;
        persons.Rows.Add(newPerson);

        mySchool.Update(persons); // This will execute the InsertPerson stored procedure
        
        // Retrieve the output parameter value after the update
        if (newPerson["PersonID"] != DBNull.Value)
        {
            int newlyInsertedPersonId = Convert.ToInt32(newPerson["PersonID"]);
            Console.WriteLine($"New Person ID: {newlyInsertedPersonId}");
        }
    }
}

This example uses SqlDataAdapter which is effective when you need to populate a DataTable and then use a stored procedure to insert new rows, automatically retrieving output parameters like identity values.

Executing Stored Procedures and Populating DataGridView

For displaying results in a UI control like DataGridView, you can use SqlDataAdapter to fill a DataSet, which can then be assigned as the data source.

// Assuming 'connection' is an open SqlConnection and 'dataGridView1' is a DataGridView control
using (var command = new SqlCommand("YourProcedureName", connection)
{
    // Set command type and add Parameters
    CommandType = CommandType.StoredProcedure,
    Parameters = { new SqlParameter("@parameterName", parameterValue) }
})
{
    // Execute command in Adapter and store to dataset
    var adapter = new SqlDataAdapter(command);
    var dataset = new DataSet();
    adapter.Fill(dataset);
    // Display results in DatagridView
    dataGridView1.DataSource = dataset.Tables[0];
}

This pattern neatly bridges the gap between database results and UI presentation.

Advanced Techniques and Libraries

Dapper is a popular micro-ORM that simplifies database operations, including calling stored procedures. It can significantly reduce boilerplate code.

Calling a stored procedure without parameters using Dapper:

using Dapper;
using System.Data.SqlClient;

using (var cn = new SqlConnection(@"Server=(local);DataBase=master;Integrated Security=SSPI"))
{
    cn.Execute("dbo.YourProcedureName", commandType: CommandType.StoredProcedure);
}

For procedures with multiple parameters:

public void InsertProduct(ProductName obj)
{
    using (SqlConnection connection = new SqlConnection(Connection.GetConnectionString()))
    {
        connection.Open();
        connection.Execute("ProductName_sp", new
        {
            @Name = obj.Name,
            @Code = obj.Code,
            @CategoryId = obj.CategoryId,
            @CompanyId = obj.CompanyId,
            @ReorderLebel = obj.ReorderLebel,
            @logo = obj.logo,
            @Status = obj.Status,
            @ProductPrice = obj.ProductPrice,
            @SellingPrice = obj.SellingPrice,
            @VatPercent = obj.VatPercent,
            @Description = obj.Description,
            @ColourId = obj.ColourId,
            @SizeId = obj.SizeId,
            @BrandId = obj.BrandId,
            @DisCountPercent = obj.DisCountPercent,
            @CreateById = obj.CreateById,
            @StatementType = "Create"
        }, commandType: CommandType.StoredProcedure);
        connection.Close();
    }
}

Crane is another library that aims to simplify database access:

// Using Crane NuGet Package
// Install-Package Crane
SqlServerAccess sqlAccess = new SqlServerAccess("your connection string");
var result = sqlAccess.Command().ExecuteNonQuery("YourStoredProcedureName");

Crane provides an object-oriented approach to SQL execution.

Handling Data Definition Language (DDL)

If your “stored procedure” is actually a DDL statement (like CREATE TABLE), you would typically set CommandType to CommandType.Text instead of CommandType.StoredProcedure.

// For DDL statements
SqlCommand cmd = new SqlCommand("YourDDLStatement", con);
cmd.CommandType = CommandType.Text; // Crucial for DDL
// ... rest of the execution code

Alternative Connection String Management

For managing connection strings, System.Configuration.ConfigurationManager is a standard approach in .NET applications:

// Retrieving connection string from app.config/web.config
string connectionString = ConfigurationManager.ConnectionStrings["YourConnectionStringName"].ConnectionString;

using (conn = new SqlConnection(connectionString))
{
    // ... rest of the code
}

FAQs on Execute SQL Server Stored Procedures in C#

Q: How do I specify the stored procedure name in C#

ANS: You set the CommandText property of the SqlCommand object to the name of your stored procedure, e.g., new SqlCommand("YourProcedureName", conn).

Q: What is CommandType.StoredProcedure

ANS: Setting CommandType to CommandType.StoredProcedure informs the SqlCommand object that it should execute a stored procedure rather than a plain SQL text command.

Q: How do I add parameters to a stored procedure call

ANS: Use SqlCommand.Parameters.Add() or SqlCommand.Parameters.AddWithValue(). For example, cmd.Parameters.AddWithValue("@ParameterName", parameterValue);.

Q: How do I handle output parameters from stored procedures

ANS: When adding an output parameter using SqlParameter, set its Direction property to ParameterDirection.Output. You can then access its value after executing the command.

Q: What is the difference between ExecuteNonQuery and ExecuteReader

ANS: ExecuteNonQuery is used for commands that don’t return a result set (like INSERT, UPDATE, DELETE), returning the number of rows affected. ExecuteReader is used for commands that return a result set, allowing you to read the data row by row using SqlDataReader.

Q: Can I use Dapper to call stored procedures

ANS: Yes, Dapper is a popular library that simplifies executing stored procedures with concise syntax.

Q: How do I execute a stored procedure that performs DDL

ANS: For DDL statements like CREATE TABLE, set the CommandType to CommandType.Text instead of CommandType.StoredProcedure.
