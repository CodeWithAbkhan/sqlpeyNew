“Entity Framework Core Filtered Include: Strategies and Examples”

Entity Framework Core 5 introduced the capability to filter included navigation properties, allowing for more precise data retrieval. This feature enables the application of Where clauses directly within Include and ThenInclude expressions, significantly improving query efficiency by fetching only necessary related entities.

Supported Operations

The filtered Include supports several LINQ operations:

  • Where: To filter entities based on specific conditions.
  • OrderBy / OrderByDescending: To sort included collections.
  • ThenBy / ThenByDescending: For secondary sorting criteria.
  • Skip: To skip a specified number of elements in the included collection.
  • Take: To retrieve a specified number of elements from the included collection.

Usage Examples and Scenarios

When using filtered Include, it’s crucial to adhere to certain guidelines, especially concerning multiple filters on the same navigation property.

Scenario 1: Applying a Filter to a Navigation

If you need to include related entities with specific criteria, you can apply a Where clause directly.

// Fetch customers and their orders, filtering out orders named "Foo"
var customersWithFilteredOrders = await context.Customers
    .Include(c => c.Orders.Where(o => o.Name != "Foo"))
    .ToListAsync();

Scenario 2: Multiple ThenInclude with a Single Filter

When applying multiple ThenInclude operations on the same navigation property, you should apply a single filter to that navigation.

// Include orders filtered by Name, and then include order details and customer for those orders
var customersWithFilteredDetails = await context.Customers
    .Include(c => c.Orders.Where(o => o.Name != "Foo"))
        .ThenInclude(o => o.OrderDetails)
    .Include(c => c.Orders) // Note: This second Include on Orders is allowed but the filter is applied only once
        .ThenInclude(o => o.Customer)
    .ToListAsync();

Alternatively, you can apply the exact same filter to the navigation property again if it makes the intent clearer or is required by the EF Core translation.

// Reapplying the same filter for clarity or specific EF Core translation needs
var customersWithExplicitlyFilteredDetails = await context.Customers
    .Include(c => c.Orders.Where(o => o.Name != "Foo"))
        .ThenInclude(o => o.OrderDetails)
    .Include(c => c.Orders.Where(o => o.Name != "Foo"))
        .ThenInclude(o => o.Customer)
    .ToListAsync();

Scenario 3: Accumulating Filtered Results

Subsequent filtered Include operations on the same context will accumulate their results.

// First include: loads non-deleted orders
var customersWithNonDeletedOrders = await context.Customers
    .Include(c => c.Orders.Where(o => !o.IsDeleted))
    .ToListAsync();

// Second include: loads deleted orders
var customersWithDeletedOrders = await context.Customers
    .Include(c => c.Orders.Where(o => o.IsDeleted))
    .ToListAsync();

// The Customers collection will now contain all orders (both deleted and non-deleted)

This accumulation also happens when related entities are loaded through other means, such as using .Load() for a separate query.

// Load explicitly filtered orders
await context.Orders.Where(o => o.IsDeleted).LoadAsync();

// If a customer's Orders collection was previously loaded with non-deleted orders,
// relationship fixup might add the newly loaded deleted orders to that collection.

Scenario 4: Filter Expression Translation

The filter expression must be translatable into a standalone SQL predicate. This means you cannot directly reference the parent entity within the filter if it’s not available in the scope of the filtered collection.

Incorrect:

// This will fail at runtime as c.Classification is not available in the Order scope
context.Customers.Include(c => c.Orders.Where(o => o.Classification == c.Classification));

Correct:

Rewrite the expression to use a back-reference from the filtered entity to its parent.

// Use a back-reference from Order to Customer
context.Customers.Include(c => c.Orders.Where(o => o.Classification == o.Customer.Classification));

// This allows filtering on Order properties that relate back to the Customer
// This is equivalent to: context.Orders.Where(o => o.Classification == o.Customer.Classification)

This principle ensures that the SQL generated by EF Core can correctly interpret and apply the filter.

Scenario 5: Filtering Reference Navigation Properties

Filtered Include applies only to collections. You cannot filter reference navigation properties directly.

// This code will not compile, as you cannot filter a reference property like Customer
context.Orders.Include(o => o.Customer.Where( ... ));

Filtered Include vs. Filtering the Query

It’s important to distinguish between filtering the Include operation and filtering the main query.

  • Filtered Include: Affects only the related data loaded. The main query still returns all entities matching its Where clause.

    // Returns all customers, but their Orders collection is filtered
await context.Customers.Include(c => c.Orders.Where(o => !o.IsDeleted)).ToListAsync();

  • Filtering the Query: Affects the set of main entities returned. The Include operation then loads related data for those returned entities.

    // Returns only customers with at least one undeleted order, and loads all their orders
await context.Customers
    .Where(c => c.Orders.Any(o => !o.IsDeleted))
    .Include(c => c.Orders)
    .ToListAsync();

To achieve both filtering the main entities and filtering the included related data, combine both approaches:

// Returns customers with undeleted orders, and only loads their undeleted orders
await context.Customers
    .Where(c => c.Orders.Any(o => !o.IsDeleted))
    .Include(c => c.Orders.Where(o => !o.IsDeleted))
    .ToListAsync();

Filtered Include and Projections

Projections using Select generally ignore Include operations, whether they are filtered or not. This means that entities included via Include will not be part of the projected anonymous type unless explicitly selected.

Example 1: Projection Ignores Include

// The SQL generated will not include a join to Orders
var customerNames = await context.Customers
    .Include(c => c.Orders) // Filtered or not, this Include is ignored by Select
    .Select(c => new { c.Name, c.RegistrationDate })
    .ToListAsync();

Example 2: Projection with Filtered Include and Collection Projection

When the projection also selects from the included collection, the behavior can be nuanced. If the entity to which the Include applies is directly part of the projection, the filtered Include might be considered.

// Initially, one might expect OrderDates to only contain dates from undeleted orders,
// but the projection typically bypasses the filtered Include.
var customerData = await context.Customers
    .Include(c => c.Orders.Where(o => !o.IsDeleted))
    .Select(c => new
    {
        c.Name,
        c.RegistrationDate,
        OrderDates = c.Orders.Select(o => o.DateSent) // This Select might load all orders
    })
    .ToListAsync();

However, if the entity itself is projected, the filtered Include can apply to that projected entity.

// Customer entity in projection includes undeleted orders, but OrderDates still contains all.
var customerAndOrders = await context.Customers
    .Include(c => c.Orders.Where(o => !o.IsDeleted))
    .Select(c => new
    {
        Customer = c, // The Customer entity here might benefit from the filtered Include
        OrderDates = c.Orders.Select(o => o.DateSent) // This Select still might load all orders
    })
    .ToListAsync();

Alternative Solutions and Approaches

While EF Core 5+ provides built-in filtered Include, there are other methods and considerations:

1. No Direct Support (Pre-EF Core 5) / Third-Party Libraries

Before EF Core 5, filtered Include was not directly supported. Developers often relied on third-party libraries like EntityFramework.Filters for this functionality.

2. Reversing the Search (LINQ to Entities)

For specific scenarios, you might reverse the query logic using LINQ to Entities.

// Retrieve posts and their associated blogs, filtered by author
var blogsByAuthor = await (from author in context.Author
                           from post in author.posts
                           from blog in post.blogs
                           where blog.Author == "me" // Example filter
                           select blog)
                           .ToListAsync();

3. Single Include with Any for Filtering

In some cases, a single Include combined with a Where clause that uses Any can achieve a similar filtering effect.

// Filter articles based on revisions containing a specific title
var filteredArticles = await context.NewsArticles
    .Include(x => x.NewsArticleRevisions)
    .Where(article => article.NewsArticleRevisions
        .Any(revision => revision.Title.Contains(filter))) // Filter articles that have matching revisions
    .ToListAsync();

4. Using Z.EntityFramework.Plus (Paid Extension)

The Z.EntityFramework.Plus package offers IncludeFilter and IncludeFilterByPath methods that provide robust filtering capabilities for Include operations.

// Using Z.EntityFramework.Plus for filtered includes
var filteredList = context.Blogs
    .IncludeFilter(x => x.Posts.Where(y => !y.IsSoftDeleted))
    .IncludeFilter(x => x.Posts.Where(y => !y.IsSoftDeleted)
        .SelectMany(y => y.Comments.Where(z => !z.IsSoftDeleted)))
    .ToList();

5. Conditional Include Extension Method

You can create an extension method to conditionally apply Include based on a boolean flag.

public static class QueryableExtensions
{
    public static IQueryable<TEntity> IncludeCondition<TEntity, TProperty>(
        this IQueryable<TEntity> query,
        Expression<Func<TEntity, TProperty>> predicate,
        bool? condition) where TEntity : class where TProperty : class
    {
        return condition == true ? query.Include(predicate) : query;
    }
}

// Usage:
// Apply include only if the condition is true
var data = await context.Tables.IncludeCondition(x => x.InnerTable, true).ToListAsync();

6. Two-Query Approach

For complex filtering logic that EF Core might struggle to translate efficiently into a single SQL query, a two-query approach can be more performant. Fetch the main entities first, then load the related data with specific filters.

// Query 1: Fetch employees based on a complex condition
var employeesQuery = _context.Employees.Where(/* complex condition */);
var employees = await employeesQuery.ToListAsync();

// Query 2: Load schedules for these employees with specific date filters
await employeesQuery
    .Include(x => x.Schedules)
    .ThenInclude(x => x.ScheduleDates)
    .SelectMany(x => x.Schedules)
    .Where(s => s.ScheduleDate.Month == /* specific month */ &&
                s.ScheduleDate.Year == /* specific year */)
    .LoadAsync(); // Loads related data into already tracked entities

FAQs on Entity Framework Core Filtered Include

Q: What is filtered Include in EF Core

ANS: Filtered Include in Entity Framework Core allows you to apply a Where clause directly within an Include or ThenInclude statement to selectively load related entities based on specific criteria.

Q: What operations are supported by filtered Include

ANS: Supported operations include Where, OrderBy, OrderByDescending, ThenBy, ThenByDescending, Skip, and Take.

Q: Can I filter reference navigation properties using Include

ANS: No, filtered Include only applies to collection navigation properties. You cannot filter reference navigation properties directly.

Q: Does filtering an Include affect the main query results

ANS: No, filtering an Include only affects the related entities loaded. The main query’s results, based on its own Where clause, remain unchanged.

Q: What happens if I apply multiple filtered Includes on the same navigation

ANS: Subsequent filtered Include operations on the same navigation property will accumulate their results. For example, including orders where IsDeleted is false, followed by including orders where IsDeleted is true, will result in all orders being loaded.

Q: Can I use a filter that references the parent entity in a filtered Include

ANS: Yes, but the reference must be made through a back-reference from the filtered collection entity to its parent, allowing EF Core to translate it correctly into SQL. For example, o => o.Classification == o.Customer.Classification.

Q: Do projections ignore filtered Include operations

ANS: Generally, projections (Select) ignore Include operations. However, if the entity itself is part of the projection, the filtered Include might be considered for that entity.
