Prevent Multiple Application Instances Using Mutex in .NET

How can I ensure only a single instance of my .NET application runs at any given time, preventing users from launching multiple copies that could lead to conflicts or data corruption? This is a common requirement, especially for applications that manage shared resources or maintain a unique state.

The System.Threading.Mutex class in .NET provides a powerful mechanism to achieve this. A Mutex (short for mutual exclusion) is a synchronization primitive that can be used to control access to a shared resource by multiple processes. By creating a uniquely named, global Mutex, you can detect if another instance of your application is already running and take appropriate action.

Let’s explore several proven approaches to implement single-instance application behavior using Mutex.

Solution 1: Direct Mutex Implementation with Timeout and Security Settings

This method directly uses Mutex in the Main method, incorporating security settings for multi-user environments and a timeout for acquiring the mutex.

using System;
using System.Reflection;
using System.Runtime.InteropServices;
using System.Security.AccessControl;
using System.Security.Principal;
using System.Threading;

class Program
{
    static void Main(string[] args)
    {
        // Retrieve the application's GUID for a unique mutex name.
        string appGuid = ((GuidAttribute)Assembly.GetExecutingAssembly()
                                            .GetCustomAttributes(typeof(GuidAttribute), false)
                                            .GetValue(0))
                                            .Value.ToString();

        // Create a unique identifier for the global mutex, prefixed with "Global\" for machine-wide scope.
        string mutexId = $"Global\\{{{appGuid}}}";

        bool createdNew;
        // Define security rules to allow all users full control over the mutex.
        var allowEveryoneRule = new MutexAccessRule(
            new SecurityIdentifier(WellKnownSidType.WorldSid, null),
            MutexRights.FullControl,
            AccessControlType.Allow);

        var securitySettings = new MutexSecurity();
        securitySettings.AddAccessRule(allowEveryoneRule);

        // Create the mutex with specific security settings and check if it was newly created.
        using (var mutex = new Mutex(false, mutexId, out createdNew, securitySettings))
        {
            var hasHandle = false;
            try
            {
                // Attempt to acquire the mutex with a 5-second timeout.
                hasHandle = mutex.WaitOne(5000, false);
                if (!hasHandle)
                {
                    throw new TimeoutException("Timeout waiting for exclusive access.");
                }

                // Your application's main logic goes here.
                Console.WriteLine("Application started. Press Enter to exit.");
                Console.ReadLine();
            }
            catch (AbandonedMutexException)
            {
                // If the mutex was abandoned by a previous instance, we can still acquire it.
                hasHandle = true;
            }
            finally
            {
                // Release the mutex if it was acquired.
                if (hasHandle)
                {
                    mutex.ReleaseMutex();
                }
            }
        }
    }
}

Solution 2: Helper Class for Simplified Mutex Usage

This approach encapsulates the Mutex logic into a reusable SingleGlobalInstance class, allowing for a using statement similar to a lock statement.

Usage Example:

// Within your Main method or application entry point:
using (new SingleGlobalInstance(1000)) // 1000ms timeout
{
    // Code that should only run in a single instance.
    RunApplicationLogic();
}

SingleGlobalInstance Helper Class:

using System;
using System.Reflection;
using System.Runtime.InteropServices;
using System.Security.AccessControl;
using System.Security.Principal;
using System.Threading;

public class SingleGlobalInstance : IDisposable
{
    private bool _hasHandle = false;
    private Mutex _mutex;

    private void InitializeMutex()
    {
        // Obtain the application's GUID for a unique mutex name.
        string appGuid = ((GuidAttribute)Assembly.GetExecutingAssembly()
                                             .GetCustomAttributes(typeof(GuidAttribute), false)
                                             .GetValue(0)).Value;
        string mutexId = $"Global\\{{{appGuid}}}";
        _mutex = new Mutex(false, mutexId);

        // Set access control rules.
        var allowEveryoneRule = new MutexAccessRule(
            new SecurityIdentifier(WellKnownSidType.WorldSid, null),
            MutexRights.FullControl,
            AccessControlType.Allow);

        var securitySettings = new MutexSecurity();
        securitySettings.AddAccessRule(allowEveryoneRule);
        _mutex.SetAccessControl(securitySettings);
    }

    public SingleGlobalInstance(int timeOut)
    {
        InitializeMutex();
        try
        {
            // Attempt to acquire the mutex. Use Timeout.Infinite for no timeout.
            _hasHandle = _mutex.WaitOne(timeOut < 0 ? Timeout.Infinite : timeOut, false);

            if (!_hasHandle)
            {
                throw new TimeoutException("Timeout waiting for exclusive access on SingleInstance.");
            }
        }
        catch (AbandonedMutexException)
        {
            // If abandoned, we can still proceed.
            _hasHandle = true;
        }
    }

    public void Dispose()
    {
        if (_mutex != null)
        {
            if (_hasHandle)
            {
                _mutex.ReleaseMutex();
            }
            _mutex.Close();
        }
    }
}

Solution 3: Early Exit with Timeout

This solution checks for an existing instance and exits gracefully if another is found, using a specific timeout duration.

// Define a constant mutex identifier. Ensure this GUID is unique to your application.
const string MUTEX_ID = "Global\\{B1E7934A-F688-417f-8FCB-65C3985E9E27}";

static void Main(string[] args)
{
    using (var mutex = new Mutex(false, MUTEX_ID))
    {
        try
        {
            // Attempt to acquire the mutex with a 5-second timeout.
            if (!mutex.WaitOne(TimeSpan.FromSeconds(5), false))
            {
                Console.WriteLine("Another instance of this program is already running. Exiting.");
                Environment.Exit(0); // Terminate this instance.
            }
        }
        catch (AbandonedMutexException)
        {
            // If the mutex was abandoned, we can proceed.
        }

        // Application's main execution logic here.
        Console.WriteLine("Application started. Press Enter to exit.");
        Console.ReadLine();

        // Release the mutex when the application exits.
        mutex.ReleaseMutex();
    }
}

Solution 4: Using Semaphore as an Alternative

For scenarios where thread identity restrictions of Mutex might be a concern, Semaphore offers an alternative. A semaphore does not enforce thread identity for release.

Key difference: Mutex can only be released by the thread that acquired it, while Semaphore can be released by any thread.

static class Program
{
    [STAThread]
    static void Main()
    {
        if (SingleApplicationDetector.IsRunning())
        {
            return; // Another instance is running.
        }

        // Run your application's main form.
        Application.Run(new MainForm());

        // Clean up the semaphore when the application exits.
        SingleApplicationDetector.Close();
    }
}

public static class SingleApplicationDetector
{
    private static Semaphore _semaphore;

    public static bool IsRunning()
    {
        string guid = ((GuidAttribute)Assembly.GetExecutingAssembly()
                                            .GetCustomAttributes(typeof(GuidAttribute), false)
                                            .GetValue(0))
                                            .Value.ToString();
        var semaphoreName = @"Global\" + guid;

        try
        {
            // Try to open an existing semaphore.
            _semaphore = Semaphore.OpenExisting(semaphoreName, SemaphoreRights.Synchronize);
            Close(); // Close the existing semaphore handle.
            return true; // Semaphore exists, meaning another instance is running.
        }
        catch (Exception)
        {
            // If opening fails, create a new semaphore.
            _semaphore = new Semaphore(0, 1, semaphoreName);
            return false; // No other instance found.
        }
    }

    public static void Close()
    {
        if (_semaphore != null)
        {
            _semaphore.Close();
            _semaphore = null;
        }
    }
}

Solution 5: WPF Application Specifics with createdNew

This approach is tailored for WPF applications and leverages the createdNew boolean from the Mutex constructor to detect if the current instance is the first one. It also handles security settings and potential AbandonedMutexException more robustly.

WPF App Class Modification:

public class App : Application
{
    private Mutex _mutex;
    private bool _mutexCreated;

    public App()
    {
        string mutexId = $"Global\\{GetType().GUID}";
        // Create a mutex, initially owned, and check if it was newly created.
        _mutex = new Mutex(true, mutexId, out _mutexCreated);
    }

    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);
        if (!_mutexCreated)
        {
            MessageBox.Show("An instance of this application is already running.");
            Shutdown(); // Close the current instance if it's not the first.
        }
    }

    protected override void OnExit(ExitEventArgs e)
    {
        base.OnExit(e);
        _mutex.Dispose(); // Release the mutex resource.
    }
}

Enhanced WPF App Class with SingleApplication Base:

This version creates a base class for easier application of the single-instance logic across multiple WPF applications.

public class SingleApplication : Application
{
    private Mutex _mutex;
    private bool _mutexCreated;

    public SingleApplication()
    {
        string mutexId = $"Global\\{GetType().GUID}";

        // Define access rules for the mutex.
        MutexAccessRule allowEveryoneRule = new MutexAccessRule(
            new SecurityIdentifier(WellKnownSidType.WorldSid, null),
            MutexRights.FullControl,
            AccessControlType.Allow);
        MutexSecurity securitySettings = new MutexSecurity();
        securitySettings.AddAccessRule(allowEveryoneRule);

        // Create the mutex, initially owned.
        _mutex = new Mutex(true, mutexId, out _mutexCreated, securitySettings);
    }

    protected override void OnExit(ExitEventArgs e)
    {
        base.OnExit(e);
        if (_mutexCreated)
        {
            try
            {
                _mutex.ReleaseMutex();
            }
            catch (ApplicationException ex)
            {
                MessageBox.Show(ex.Message, ex.GetType().FullName, MessageBoxButton.OK, MessageBoxImage.Error);
            }
        }
        _mutex.Dispose();
    }

    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);
        if (!_mutexCreated)
        {
            MessageBox.Show("An instance of this application is already running.");
            Shutdown();
        }
    }
}

Solution 6: Demonstrating Mutex Behavior with Console Applications

This console application example clearly illustrates how a named Mutex serializes access. Running multiple instances of this application will show them waiting their turn to acquire and release the mutex. This is useful for understanding how Mutex protects critical sections, such as file writing.

using System;
using System.Threading;

namespace MutexExample
{
    class Program
    {
        // Create a named mutex, not initially owned.
        static Mutex mutex = new Mutex(false, "myUniqueAppMutex");

        static void Main(string[] args)
        {
            Console.WriteLine("Waiting to acquire Mutex...");
            // Wait to acquire ownership of the mutex.
            mutex.WaitOne();
            Console.WriteLine("Mutex acquired. Press Enter to release Mutex.");
            Console.ReadLine();
            // Release the mutex, allowing other waiting processes to proceed.
            mutex.ReleaseMutex();
        }
    }
}

Solution 7: Advanced Mutex Wrapper with Awaiter Pattern

This solution provides a flexible wrapper for global Mutexes, incorporating an Awaiter pattern for more advanced control over timeouts and retry logic. It also includes a static factory method to get the application’s specific mutex.

MutexGlobal Wrapper Class:

using System;
using System.Reflection;
using System.Runtime.InteropServices;
using System.Security.AccessControl;
using System.Security.Principal;
using System.Threading;

namespace HQ.Util.General.Threading
{
    public class MutexGlobal : IDisposable
    {
        public string Name { get; private set; }
        internal Mutex Mutex { get; private set; }
        public int DefaultTimeOut { get; set; }
        public Func<int, bool> FuncTimeOutRetry { get; set; }

        public static MutexGlobal GetApplicationMutex(int defaultTimeOut = Timeout.Infinite)
        {
            // Get the application's GUID for a unique mutex name.
            string appGuid = ((GuidAttribute)Assembly.GetExecutingAssembly()
                                                .GetCustomAttributes(typeof(GuidAttribute), false)
                                                .GetValue(0))
                                                .Value;
            return new MutexGlobal(defaultTimeOut, appGuid);
        }

        public MutexGlobal(int defaultTimeOut = Timeout.Infinite, string specificName = null)
        {
            try
            {
                Name = string.IsNullOrEmpty(specificName) ? Guid.NewGuid().ToString() : specificName;
                Name = $"Global\\{{{Name}}}"; // Ensure global scope.
                DefaultTimeOut = defaultTimeOut;
                FuncTimeOutRetry = DefaultFuncTimeOutRetry;

                // Set access control rules.
                var allowEveryoneRule = new MutexAccessRule(
                    new SecurityIdentifier(WellKnownSidType.WorldSid, null),
                    MutexRights.FullControl,
                    AccessControlType.Allow);
                var securitySettings = new MutexSecurity();
                securitySettings.AddAccessRule(allowEveryoneRule);

                Mutex = new Mutex(false, Name, out bool createdNew, securitySettings);

                if (Mutex == null)
                {
                    throw new Exception($"Unable to create mutex: {Name}");
                }
            }
            catch (Exception ex)
            {
                // Log the exception (assuming a Log class exists).
                // Log.Log.Instance.AddEntry(Log.LogType.LogException, $"Unable to create Mutex: {Name}", ex);
                throw;
            }
        }

        public MutexGlobalAwaiter GetAwaiter(int timeOut)
        {
            return new MutexGlobalAwaiter(this, timeOut);
        }

        public MutexGlobalAwaiter GetAwaiter()
        {
            return new MutexGlobalAwaiter(this, DefaultTimeOut);
        }

        private bool DefaultFuncTimeOutRetry(int timeOutUsed)
        {
            // Example: Log a warning and retry.
            // Log.Log.Instance.AddEntry(Log.LogType.LogWarning, $"Mutex {Name} timeout: {timeOutUsed}.");
            return true; // Retry.
        }

        public void Dispose()
        {
            if (Mutex != null)
            {
                Mutex.ReleaseMutex();
                Mutex.Close();
            }
        }
    }

MutexGlobalAwaiter Class:

using System;

namespace HQ.Util.General.Threading
{
    public class MutexGlobalAwaiter : IDisposable
    {
        private MutexGlobal _mutexGlobal;
        public bool HasTimedOut { get; set; } = false;

        internal MutexGlobalAwaiter(MutexGlobal mutexEx, int timeOut)
        {
            _mutexGlobal = mutexEx;
            do
            {
                HasTimedOut = !_mutexGlobal.Mutex.WaitOne(timeOut, false);
                if (!HasTimedOut) return; // Acquired.
            } while (_mutexGlobal.FuncTimeOutRetry(timeOut));
        }

        // Implement IDisposable pattern.
        private bool disposedValue = false;
        protected virtual void Dispose(bool disposing)
        {
            if (!disposedValue)
            {
                if (disposing)
                {
                    _mutexGlobal.Mutex.ReleaseMutex();
                }
                disposedValue = true;
            }
        }

        public void Dispose()
        {
            Dispose(true);
        }
    }
}

FAQs on Prevent Multiple Application Instances Using Mutex in .NET

Q: What is a Mutex and how does it help prevent multiple application instances

ANS: A Mutex (mutual exclusion) is a synchronization primitive that ensures only one thread or process can access a shared resource or execute a critical section of code at a time. By creating a uniquely named, globally accessible Mutex, an application can detect if another instance is already running by attempting to acquire that Mutex. If acquisition fails due to another instance holding it, the new instance can then exit or perform other defined actions.

Q: How do I generate a unique name for the Mutex

ANS: A common and effective way to generate a unique name for a Mutex is to use the application’s GUID. This is typically retrieved using reflection from the GuidAttribute applied to the assembly (often found in AssemblyInfo.cs). The name is then often prefixed with “Global\” to ensure it’s recognized system-wide. For example: $"Global\\{{{appGuid}}}".

Q: What happens if the application holding the Mutex crashes

ANS: If an application holding a Mutex crashes, the Mutex can become “abandoned.” .NET’s Mutex class handles this scenario through the AbandonedMutexException. In most single-instance implementations, catching this exception and treating it as if the Mutex was successfully acquired allows the new instance to run. The operating system will eventually clean up abandoned Mutexes, but catching the exception ensures the application can continue running.

Q: Can I specify a timeout when waiting for the Mutex

ANS: Yes, the Mutex.WaitOne() method accepts a timeout parameter (in milliseconds or as a TimeSpan). This allows your application to wait for a specific duration for the Mutex to become available before proceeding or exiting if the timeout is reached. This prevents the application from blocking indefinitely.

Q: Is it necessary to release the Mutex

ANS: Yes, it is crucial to release the Mutex when your application is done with its critical section or is exiting. This is typically done using the Mutex.ReleaseMutex() method. In .NET, if you wrap your Mutex usage in a using statement (as demonstrated in several examples), the Dispose() method of the Mutex object will be called automatically, which includes releasing the Mutex. Properly releasing the Mutex allows other waiting instances to acquire it.

Q: What is the difference between Mutex and Semaphore for single-instance applications

ANS: While both can be used for single-instance applications, Mutex is specifically designed for mutual exclusion and enforces that only the thread that acquired it can release it. Semaphore, on the other hand, does not enforce thread identity for its release. For typical single-instance application scenarios, Mutex is often more direct. Semaphore might be preferred if you need more complex signaling or cross-thread release capabilities, but for simple single-instance checks, Mutex is generally the go-to.
