“Best Practices for Saving Game Data: JSON vs. BinaryFormatter”

When developing games, persisting player progress and settings is crucial. While BinaryFormatter might seem like a straightforward option for saving data, it often presents significant challenges and isn’t ideal for game state. This post delves into why BinaryFormatter can be problematic and offers a more reliable approach using JSON serialization and byte arrays.

The Downsides of BinaryFormatter

You’ve heard that BinaryFormatter has issues and isn’t suitable for saving. Let’s elaborate.

BinaryFormatter can indeed cause problems, particularly when dealing with class updates. If you modify a class after saving its data with BinaryFormatter, old saved settings might become inaccessible. This occurs because the serialized class structure no longer matches the current definition, often leading to exceptions when trying to read the saved data.

Furthermore, for platforms like iOS, you might need to configure specific environment variables, such as Environment.SetEnvironmentVariable("MONO_REFLECTION_SERIALIZER", "yes");, to avoid issues with BinaryFormatter. This adds an extra layer of complexity and platform dependency.

A More Robust Approach: JSON with Byte Arrays

For a more robust and flexible solution, saving data using PlayerPrefs and JSON is generally recommended. However, if your requirement specifically mandates saving data as a byte array, you can achieve this by converting your JSON string to a byte array. This method offers better compatibility and resilience against class changes.

This approach involves converting your data object to a JSON string, then encoding that string into a byte array. You can then utilize File.WriteAllBytes and File.ReadAllBytes to manage the persistence of this byte array.

Below is a generic DataSaver class designed for this purpose, utilizing file storage for JSON data instead of PlayerPrefs.

using System;
using System.IO;
using System.Text;
using UnityEngine; // Assuming Unity environment for Application.persistentDataPath and Debug

public class DataSaver
{
    /// <summary>
    /// Saves data to a file in JSON format, encoded as a byte array.
    /// </summary>
    /// <typeparam name="T">The type of data to save.</typeparam>
    /// <param name="dataToSave">The object containing the data to be saved.</param>
    /// <param name="dataFileName">The name of the file to save the data to (without extension).</param>
    public static void SaveData<T>(T dataToSave, string dataFileName)
    {
        // Construct the full path for the data file
        string tempPath = Path.Combine(Application.persistentDataPath, "data");
        tempPath = Path.Combine(tempPath, dataFileName + ".json"); // Using .json extension for clarity

        // Convert the data object to a JSON string
        string jsonData = JsonUtility.ToJson(dataToSave, true);
        // Encode the JSON string into a byte array using ASCII encoding
        byte[] jsonByte = Encoding.ASCII.GetBytes(jsonData);

        // Ensure the directory exists before writing the file
        string directoryPath = Path.GetDirectoryName(tempPath);
        if (!Directory.Exists(directoryPath))
        {
            Directory.CreateDirectory(directoryPath);
        }

        try
        {
            // Write the byte array to the specified file path
            File.WriteAllBytes(tempPath, jsonByte);
            Debug.Log("Saved Data to: " + tempPath.Replace("/", "\\"));
        }
        catch (Exception e)
        {
            Debug.LogWarning($"Failed to save data to: {tempPath.Replace("/", "\\")}");
            Debug.LogWarning($"Error: {e.Message}");
        }
    }

    /// <summary>
    /// Loads data from a file, expecting JSON format encoded as a byte array.
    /// </summary>
    /// <typeparam name="T">The type of data to load.</typeparam>
    /// <param name="dataFileName">The name of the file to load data from (without extension).</param>
    /// <returns>The loaded data object, or default(T) if loading fails or the file/directory doesn't exist.</returns>
    public static T LoadData<T>(string dataFileName)
    {
        // Construct the full path for the data file
        string tempPath = Path.Combine(Application.persistentDataPath, "data");
        tempPath = Path.Combine(tempPath, dataFileName + ".json");

        // Check if the directory and file exist before attempting to load
        if (!Directory.Exists(Path.GetDirectoryName(tempPath)))
        {
            Debug.LogWarning("Directory does not exist.");
            return default(T);
        }

        if (!File.Exists(tempPath))
        {
            Debug.Log("File does not exist.");
            return default(T);
        }

        byte[] jsonByte = null;
        try
        {
            // Read all bytes from the specified file path
            jsonByte = File.ReadAllBytes(tempPath);
            Debug.Log("Loaded Data from: " + tempPath.Replace("/", "\\"));
        }
        catch (Exception e)
        {
            Debug.LogWarning($"Failed to load data from: {tempPath.Replace("/", "\\")}");
            Debug.LogWarning($"Error: {e.Message}");
            return default(T); // Return default if reading fails
        }

        // Decode the byte array back into a JSON string
        string jsonData = Encoding.ASCII.GetString(jsonByte);

        // Deserialize the JSON string back into an object of type T
        // JsonUtility.FromJson returns an object, so we cast it.
        object resultValue = JsonUtility.FromJson<T>(jsonData);
        return (T)Convert.ChangeType(resultValue, typeof(T));
    }

    /// <summary>
    /// Deletes a saved data file.
    /// </summary>
    /// <param name="dataFileName">The name of the file to delete (without extension).</param>
    /// <returns>True if the data was successfully deleted, false otherwise.</returns>
    public static bool DeleteData(string dataFileName)
    {
        bool success = false;

        // Construct the full path for the data file
        string tempPath = Path.Combine(Application.persistentDataPath, "data");
        tempPath = Path.Combine(tempPath, dataFileName + ".json");

        // Check if the directory and file exist before attempting to delete
        if (!Directory.Exists(Path.GetDirectoryName(tempPath)))
        {
            Debug.LogWarning("Directory does not exist.");
            return false;
        }

        if (!File.Exists(tempPath))
        {
            Debug.Log("File does not exist.");
            return false;
        }

        try
        {
            // Delete the file
            File.Delete(tempPath);
            Debug.Log("Data deleted from: " + tempPath.Replace("/", "\\"));
            success = true;
        }
        catch (Exception e)
        {
            Debug.LogWarning($"Failed to delete data: {e.Message}");
        }

        return success;
    }
}

Example Usage

To utilize this DataSaver class, you’ll need a serializable class to hold your game data.

Example Data Class:

[Serializable]
public class PlayerInfo
{
    public List<int> achievementIDs = new List<int>();
    public List<int> currencyAmounts = new List<int>();
    public int playerHealth = 100;
    public float highestScore = 0f;
}

Saving Player Data:

// Create an instance of your data class
PlayerInfo playerDataToSave = new PlayerInfo();
playerDataToSave.playerHealth = 99;
playerDataToSave.highestScore = 40.5f;
playerDataToSave.achievementIDs.Add(101);
playerDataToSave.currencyAmounts.Add(500);

// Save the data using the DataSaver class to a file named "playerProgress"
DataSaver.SaveData(playerDataToSave, "playerProgress");

Loading Player Data:

// Load the data from the "playerProgress" file
PlayerInfo loadedPlayerData = DataSaver.LoadData<PlayerInfo>("playerProgress");

// Check if data was loaded successfully
if (loadedPlayerData == null)
{
    Debug.LogWarning("Could not load player data.");
    return; // Exit if no data was found or loading failed
}

// Access and display the loaded data
Debug.Log($"Player Health: {loadedPlayerData.playerHealth}");
Debug.Log($"Highest Score: {loadedPlayerData.highestScore}");

for (int i = 0; i < loadedPlayerData.achievementIDs.Count; i++)
{
    Debug.Log($"Achievement ID: {loadedPlayerData.achievementIDs[i]}");
}
for (int i = 0; i < loadedPlayerData.currencyAmounts.Count; i++)
{
    Debug.Log($"Currency Amount: {loadedPlayerData.currencyAmounts[i]}");
}

Deleting Player Data:

// Delete the saved player data file
DataSaver.DeleteData("playerProgress");

PlayerPrefs: Use Cases and Limitations

It’s important to distinguish between saving game state and saving player preferences.

PlayerPrefs is primarily intended for storing player preferences, such as volume levels, graphics settings, or control mappings. These are settings that players expect to be able to change and that don’t constitute critical game progression. PlayerPrefs stores data in a plain text format, making it easily accessible and editable by players. For competitive games or titles where save data integrity is paramount, relying solely on PlayerPrefs for game state is not advisable.

For saving actual game progress, such as inventory, character stats, or level completion, using I/O operations with serialization (like JSON) or sending data to a server is a more secure and reliable method. Even when encrypting data, these methods offer a higher degree of protection compared to PlayerPrefs.

Alternative Serialization Options

While JsonUtility is a built-in solution in Unity for JSON serialization, other libraries like Newtonsoft.Json (Json.NET) offer more advanced features and better performance for complex scenarios, especially if you encounter issues with JsonUtility’s limitations. For byte array conversion, standard C# methods are generally sufficient.

FAQs on Saving Game Data

Q: What are the main problems with BinaryFormatter for saving game data

ANS: BinaryFormatter can cause issues with class updates, leading to data corruption or read errors if the class structure changes after data is saved. It also requires specific platform configurations on some systems like iOS.

Q: Why is saving data as a byte array useful

ANS: Saving data as a byte array, especially when derived from JSON, provides a consistent format that can be more robust against certain compatibility issues compared to raw binary serialization. It’s also a common requirement for specific file operations or network transmissions.

Q: Can I use PlayerPrefs to save sensitive game state

ANS: No, PlayerPrefs is not recommended for saving sensitive game state. It stores data in plain text, making it easily viewable and modifiable by players, which can compromise game integrity, especially in competitive environments.

Q: How do I convert JSON to a byte array for saving

ANS: You can convert a JSON string to a byte array using Encoding.ASCII.GetBytes(yourJsonString) and save it using File.WriteAllBytes. To load, read the bytes with File.ReadAllBytes and convert back to a string with Encoding.ASCII.GetString(yourByteArray).

Q: What is the benefit of using JSON for game data persistence

ANS: JSON is human-readable, easily parsable across different platforms and languages, and generally more resilient to minor class definition changes than binary formats. This makes it a flexible choice for game development.
