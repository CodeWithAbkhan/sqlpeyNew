“C# Default Access Modifiers for Types and Members Explained”

When declaring types and their members in C#, what access modifier is implicitly applied if none is explicitly stated? The answer hinges entirely on the context of the declaration—whether it’s a top-level entity within a namespace or a member nested inside another type. The general principle guiding these defaults is selecting the most restricted access permissible for that specific context.

How Does Context Dictate Default Accessibility?

The C# specification outlines distinct default behaviors depending on the declaration location.

For Types Declared Directly in a Namespace (Top-Level Entities):

  • Namespaces: Implicitly possess public declared accessibility. No access modifier is permitted on a namespace declaration itself.
  • Types (Classes, Structs, Interfaces, Delegates): Default to internal. This restricts access to the declaring assembly only, unless public is specified.

For Members Declared Within a Type (Class or Struct Members):

  • Class Members (Methods, Fields, Properties, Nested Types): Default to private. This severely restricts access to only the containing class.
  • Struct Members: Default to private, similar to class members. They cannot use protected or protected internal modifiers as structs do not support inheritance in the same way classes do.
  • Interface Members: Implicitly public. Since interfaces define contracts, members must be accessible externally. No access modifiers are allowed on interface member declarations.
  • Enumeration Members: Implicitly public.

Consider this common scenario within a namespace:

namespace ApplicationCore
{
    class ConfigurationService // Defaults to 'internal class'
    {
        public string SettingsPath { get; private set; } // get is public, set defaults to private

        void Initialize() {} // Defaults to 'private void Initialize()'

        class CacheStore {} // Nested type defaults to 'private class CacheStore'
    }
}

The example above is semantically equivalent to:

namespace ApplicationCore
{
    internal class ConfigurationService
    {
        public string SettingsPath
        {
            get { /* ... */ }
            private set { /* ... */ } // Explicitly setting a more restricted setter than the property's get is permissible.
        }

        private void Initialize() { /* ... */ }

        private class CacheStore { /* ... */ }
    }
}

Important Note on Interface Members: Interface members always default to public, and you cannot specify any access modifier on them; attempting to do so results in a compilation error.

Accessibility Constraints Related to Inheritance

A derived type cannot possess greater accessibility than its base type. For instance, you cannot declare a public class that inherits from an internal base class, as this would inadvertently expose the internal base class members publicly through the derived type.

Furthermore, the type of any member (field, property return type, method parameter types) must have accessibility at least as permissive as the member itself. A public method cannot return a type that is only internal to the assembly.

Alternative Perspective on Defaults

Another way to frame this is by categorizing the defaults based on scope:

  1. Top-Level Types (Classes, Structs, Interfaces in a Namespace): Default is internal.
  2. Member Types (Inside other types): Default is private, with exceptions for members of interfaces and enumerations which are public.

If no constructor is explicitly defined in a class, a public default constructor is automatically generated, provided the class itself is accessible.

FAQs on CSharp Default Access Modifiers

Q: What is the default access modifier for a class declared at the top level of a C# file

ANS: The default access modifier for a class, struct, or interface declared directly within a namespace (top-level) in C# is internal.

Q: What is the default access modifier for members inside a C# class

ANS: The default access modifier for members such as methods, fields, and nested classes within a C# class declaration is private.

Q: Can interface members have an access modifier applied

ANS: No, interface members implicitly have public declared accessibility, and the C# compiler prevents applying any explicit access modifier to them.

Q: Are there any exceptions where nested types default to public

ANS: Yes, enumeration members and interface members declared within another type default to public. For classes and structs, nested types default to private.

Q: How does overriding a property setter accessibility work

ANS: It is permitted to specify a more restricted access modifier for a property’s setter (e.g., private set) than the declared accessibility of the property itself (e.g., public string Name { get; private set; }), provided it is done explicitly.
