“.NET: Convert Unix Timestamp to DateTime & Vice Versa”

A Unix timestamp represents the number of seconds or milliseconds that have elapsed since January 1, 1970, at 00:00:00 Coordinated Universal Time (UTC). This epoch time is frequently used in system logs, data exchange formats, and various programming languages. When working with .NET applications, accurately converting these timestamps to human-readable DateTime objects is a common requirement. Several methods exist within the .NET framework and community-provided extensions to achieve this, catering to different .NET versions and precision needs.

Here are various approaches to convert between Unix timestamps and DateTime objects in .NET, including handling both seconds and milliseconds, and vice-versa.

Solution 1: Manual Conversion (Pre-.NET 4.6)

Before .NET Framework 4.6 introduced built-in support, manual conversion was the standard practice. This involves creating a DateTime object representing the Unix epoch and then adding the specified seconds or milliseconds.

Converting Unix Timestamp (seconds) to DateTime:

This method takes a Unix timestamp in seconds and converts it to a local DateTime object.

public static DateTime UnixTimeStampToDateTime(double unixTimeStamp)
{
    // Unix timestamp is seconds past epoch
    DateTime dateTime = new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc);
    return dateTime.AddSeconds(unixTimeStamp).ToLocalTime();
}

Converting Java Timestamp (milliseconds) to DateTime:

Java’s timestamp is typically in milliseconds. This overload handles that distinction.

public static DateTime JavaTimeStampToDateTime(double javaTimeStamp)
{
    // Java timestamp is milliseconds past epoch
    DateTime dateTime = new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc);
    return dateTime.AddMilliseconds(javaTimeStamp).ToLocalTime();
}

Solution 2: Using DateTimeOffset (Introduced in .NET 4.6)

.NET 4.6 brought native support for Unix time conversions directly within the DateTimeOffset structure. This offers a cleaner and more robust way to handle these conversions.

Unix time in seconds to UTC DateTimeOffset:

DateTimeOffset dateTimeOffset = DateTimeOffset.FromUnixTimeSeconds(1000);

DateTimeOffset to Unix time in seconds:

long unixTimeStampInSeconds = dateTimeOffset.ToUnixTimeSeconds();

Unix time in milliseconds to UTC DateTimeOffset:

DateTimeOffset dateTimeOffset = DateTimeOffset.FromUnixTimeMilliseconds(1000000);

DateTimeOffset to Unix time in milliseconds:

long unixTimeStampInMilliseconds = dateTimeOffset.ToUnixTimeMilliseconds();

To obtain a DateTime representation from DateTimeOffset, you can use its UtcDateTime or LocalDateTime properties:

DateTime dateTime = dateTimeOffset.UtcDateTime;

Solution 3: Converting DateTime to Unix Timestamp

When you need to convert a DateTime object to a Unix timestamp, the following method is effective. It ensures the DateTime is in UTC before calculating the total seconds from the epoch.

public static double DateTimeToUnixTimestamp(DateTime dateTime)
{
    return (TimeZoneInfo.ConvertTimeToUtc(dateTime) -
           new DateTime(1970, 1, 1, 0, 0, 0, 0, System.DateTimeKind.Utc)).TotalSeconds;
}

This approach uses DateTimeOffset to simplify the conversion of a DateTime object to its Unix timestamp representation in seconds.

// To convert Unix timestamp back to a local DateTime:

Solution 5: UTC Conversion for Unix Timestamp

This solution directly calculates the Unix timestamp from the current UTC time.

TimeSpan span = (DateTime.UtcNow - new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc));
double unixTime = span.TotalSeconds;

Solution 6: High Precision Unix Timestamp Conversion

For scenarios requiring precision beyond milliseconds, .NET’s built-in methods might truncate microseconds. These custom extension methods preserve higher precision.

Unix Timestamp (with high precision) to DateTime:

public static DateTime UnixTimestampToDateTime(double unixTime)
{
    DateTime unixStart = new DateTime(1970, 1, 1, 0, 0, 0, 0, System.DateTimeKind.Utc);
    long unixTimeStampInTicks = (long)(unixTime * TimeSpan.TicksPerSecond);
    return new DateTime(unixStart.Ticks + unixTimeStampInTicks, System.DateTimeKind.Utc);
}

DateTime to Unix Timestamp (with high precision):

public static double DateTimeToUnixTimestamp(DateTime dateTime)
{
    DateTime unixStart = new DateTime(1970, 1, 1, 0, 0, 0, 0, System.DateTimeKind.Utc);
    long unixTimeStampInTicks = (dateTime.ToUniversalTime() - unixStart).Ticks;
    return (double)unixTimeStampInTicks / TimeSpan.TicksPerSecond;
}

Solution 7: Using DateTime.UnixEpoch (C# 8.0 / .NET Core 2.1+)

A concise way to handle Unix epoch conversions in modern .NET versions.

Solution 8: EpochTimeExtensions (Community Utility)

The IdentityModel.EpochTimeExtensions class provides convenient extension methods for comprehensive epoch time conversions.

// Extension methods to convert DateTime/DateTimeOffset to and from epoch time
public static class EpochTimeExtensions
{
    /// <summary>
    /// Converts the given date value to epoch time (seconds).
    /// </summary>
    public static long ToEpochTime(this DateTime dateTime)
    {
        var date = dateTime.ToUniversalTime();
        var ticks = date.Ticks - new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc).Ticks;
        var ts = ticks / TimeSpan.TicksPerSecond;
        return ts;
    }

    /// <summary>
    /// Converts the given date value to epoch time (seconds).
    /// </summary>
    public static long ToEpochTime(this DateTimeOffset dateTime)
    {
        var date = dateTime.ToUniversalTime();
        var ticks = date.Ticks - new DateTimeOffset(1970, 1, 1, 0, 0, 0, TimeSpan.Zero).Ticks;
        var ts = ticks / TimeSpan.TicksPerSecond;
        return ts;
    }

    /// <summary>
    /// Converts the given epoch time to a <see cref="DateTime"/> with <see cref="DateTimeKind.Utc"/> kind.
    /// </summary>
    public static DateTime ToDateTimeFromEpoch(this long intDate)
    {
        var timeInTicks = intDate * TimeSpan.TicksPerSecond;
        return new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc).AddTicks(timeInTicks);
    }

    /// <summary>
    /// Converts the given epoch time to a UTC <see cref="DateTimeOffset"/>.
    /// </summary>
    public static DateTimeOffset ToDateTimeOffsetFromEpoch(this long intDate)
    {
        var timeInTicks = intDate * TimeSpan.TicksPerSecond;
        return new DateTimeOffset(1970, 1, 1, 0, 0, 0, TimeSpan.Zero).AddTicks(timeInTicks);
    }
}

Solution 10: Handling Mixed Millisecond/Second Timestamps

This approach intelligently determines whether the provided Unix timestamp is in seconds or milliseconds based on its magnitude, providing a more flexible conversion.

static readonly DateTime UnixEpoch = new DateTime(1970, 1, 1, 0, 0, 0, 0, DateTimeKind.Utc);
static readonly double MaxUnixSeconds = (DateTime.MaxValue - UnixEpoch).TotalSeconds;

public static DateTime UnixTimeStampToDateTime(double unixTimeStamp)
{
   return unixTimeStamp > MaxUnixSeconds
      ? UnixEpoch.AddMilliseconds(unixTimeStamp)
      : UnixEpoch.AddSeconds(unixTimeStamp);
}

Solution 16: Manual Calculation without Local Time Adjustment

This demonstrates a manual calculation of Unix time by directly finding the time span between the target DateTime and the epoch, without an explicit local time adjustment.

DateTime date = new DateTime(2011, 4, 1, 12, 0, 0, 0);
DateTime epoch = new DateTime(1970, 1, 1, 0, 0, 0, 0);
TimeSpan span = (date - epoch);
double unixTime = span.TotalSeconds;

Solution 17: .NET 6.0 DateTime.UnixEpoch (Avoiding 2038 Problem)

Utilizing long with DateTime.UnixEpoch is recommended to avoid the Year 2038 problem.

// Cast the `double` into a `long`, not an `int`, to avoid an overflow after 2038:
long seconds = (long)DateTime.UtcNow.Subtract(DateTime.UnixEpoch).TotalSeconds;

// Convert Unix time back to DateTime.UtcNow
DateTime timestamp = DateTime.UnixEpoch.AddSeconds(seconds);

Solution 21: Handling Timeval Struct (Seconds and Microseconds)

For custom time structures like Timeval, this method preserves precision from seconds and microseconds.

DateTime _epochTime = new DateTime(1970, 1, 1, 0, 0, 0, DateTimeKind.Utc);
private DateTime UnixTimeToDateTime(Timeval unixTime)
{
    return _epochTime.AddTicks(
        unixTime.Seconds * TimeSpan.TicksPerSecond +
        unixTime.Microseconds * TimeSpan.TicksPerMillisecond / 1000);
}

Solution 22: Simple Unix Timestamp to DateTime Conversion

A straightforward static class for converting Unix timestamps to UTC DateTime.

public static class UnixTime
{
    private static readonly DateTime Epoch = new DateTime(1970, 1, 1, 0, 0, 0, 0);

    public static DateTime UnixTimeToDateTime(double unixTimeStamp)
    {
        return Epoch.AddSeconds(unixTimeStamp).ToUniversalTime();

Solution 25: Custom UnixDateTime Class (Comprehensive)

This custom class provides robust FromUnixTimeSeconds, FromUnixTimeMilliseconds, ToUnixTimeSeconds, and ToUnixTimeMilliseconds methods with built-in validation and tests, suitable for .NET 4.6 and later.

public static class UnixDateTime
{
    public static DateTimeOffset FromUnixTimeSeconds(long seconds)
    {
        if (seconds < -62135596800L || seconds > 253402300799L)
            throw new ArgumentOutOfRangeException("seconds", seconds, "");
        return new DateTimeOffset(seconds * 10000000L + 621355968000000000L, TimeSpan.Zero);
    }

    public static DateTimeOffset FromUnixTimeMilliseconds(long milliseconds)
    {
        if (milliseconds < -62135596800000L || milliseconds > 253402300799999L)
            throw new ArgumentOutOfRangeException("milliseconds", milliseconds, "");
        return new DateTimeOffset(milliseconds * 10000L + 621355968000000000L, TimeSpan.Zero);
    }

    public static long ToUnixTimeSeconds(this DateTimeOffset utcDateTime)
    {
        return utcDateTime.Ticks / 10000000L - 62135596800L;
    }

    public static long ToUnixTimeMilliseconds(this DateTimeOffset utcDateTime)
    {
        return utcDateTime.Ticks / 10000L - 62135596800000L;
    }

FAQs on .NET Unix Timestamp Conversion

Q: How do I convert a Unix timestamp in seconds to a DateTime object in .NET

ANS: You can use DateTimeOffset.FromUnixTimeSeconds(unixTimestampInSeconds) introduced in .NET Framework 4.6, or manually create a DateTime from the epoch and add seconds.

Q: What is the difference between Unix time in seconds and milliseconds

ANS: Unix time in seconds counts seconds since January 1, 1970 UTC. Unix time in milliseconds counts milliseconds since the same epoch. Java typically uses milliseconds, while standard Unix timestamps are in seconds.

Q: Can I convert a DateTime object to a Unix timestamp in .NET

ANS: Yes, you can use new DateTimeOffset(yourDateTime).ToUnixTimeSeconds() or new DateTimeOffset(yourDateTime).ToUnixTimeMilliseconds(). Alternatively, calculate the total seconds or milliseconds from the epoch manually.

Q: What is the recommended way to handle Unix timestamps in modern .NET

ANS: Using the DateTimeOffset.FromUnixTimeSeconds and DateTimeOffset.ToUnixTimeSeconds methods (or their millisecond equivalents) is the preferred approach in .NET Framework 4.6 and later versions for clarity and robustness. For .NET Core and later, DateTime.UnixEpoch offers concise alternatives.

Q: How does .NET handle the Year 2038 problem with Unix timestamps

ANS: By using long data types for timestamps and employing DateTimeOffset methods, .NET avoids the Year 2038 problem which affects systems using 32-bit integers for Unix timestamps.
