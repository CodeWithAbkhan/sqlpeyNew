“.NET: Parallel Asynchronous Execution Strategies”

When dealing with collections and the need to process items concurrently and asynchronously in .NET, several robust strategies exist. This exploration delves into various approaches, providing code examples and explanations to help you select the most fitting method for your specific requirements. Whether you need simple parallelism or fine-grained control over concurrent operations, these techniques offer valuable solutions.

Solution 1: Simple Parallelism with ConcurrentBag

For straightforward parallel execution where you need to collect results, ConcurrentBag<T> is an efficient choice. It provides thread-safe add operations, making it suitable for scenarios where multiple tasks contribute to a shared collection.

// Assume myCollection is an IEnumerable<SomeType>
// Assume GetData(item) returns a Task<object>

var resultCollection = new ConcurrentBag<object>();
var processingTasks = myCollection.Select(async item =>
{
    // Pre-processing steps can go here
    var dataResponse = await GetData(item);
    resultCollection.Add(dataResponse);
    // Post-processing steps can go here
});

await Task.WhenAll(processingTasks);
var totalItemsProcessed = resultCollection.Count;

Solution 2: Controlled Parallelism with Parallel.ForEachAsync

Introduced in .NET 6, Parallel.ForEachAsync offers a powerful way to schedule asynchronous work with explicit control over the degree of parallelism. This is ideal for managing resource usage, especially when dealing with I/O-bound operations like network requests.

var websiteUrls = new[]
{
    "https://dotnet.microsoft.com",
    "https://www.microsoft.com",
    "https://stackoverflow.com"
};

using var httpClient = new HttpClient();

var parallelExecutionOptions = new ParallelOptions { MaxDegreeOfParallelism = 2 };

await Parallel.ForEachAsync(websiteUrls, parallelExecutionOptions, async (url, cancellationToken) =>
{
    var cacheFilePath = Path.Combine(Path.GetTempPath(), "http_cache", url.Replace("://", "_"));

    var httpResponse = await httpClient.GetAsync(url, cancellationToken);

    if (httpResponse.IsSuccessStatusCode)
    {
        using var fileStream = File.OpenWrite(cacheFilePath);
        await httpResponse.Content.CopyToAsync(fileStream, cancellationToken);
    }
});

Solution 4: Fine-grained Control with SemaphoreSlim

SemaphoreSlim offers a robust mechanism for controlling the number of concurrent asynchronous operations. By managing its count, you can effectively limit parallelism and prevent overwhelming resources.

var dataItems = myCollection; // Assume this is an IEnumerable<SomeType>
var resultsBag = new ConcurrentBag<object>();
int maximumConcurrentTasks = 20;
var concurrencyThrottler = new SemaphoreSlim(initialCount: maximumConcurrentTasks);

var operationTasks = dataItems.Select(async item =>
{
    await concurrencyThrottler.WaitAsync(); // Acquire a permit
    try
    {
        var processedData = await GetData(item);
        resultsBag.Add(processedData);
    }
    finally
    {
        concurrencyThrottler.Release(); // Release the permit
    }
});

await Task.WhenAll(operationTasks);
var itemCount = resultsBag.Count;

Solution 5: Custom ParallelForEachAsync Extension Method

You can create your own reusable extension method for parallel asynchronous iteration, incorporating SemaphoreSlim for parallelism control and CancellationToken for cancellation support.

public static class ParallelExecutionExtensions
{
    public static async Task ExecuteInParallelAsync<T>(
        this IEnumerable<T> source,
        Func<T, Task> asyncAction,
        int maxDegreeOfParallelism)
    {
        var throttler = new SemaphoreSlim(initialCount: maxDegreeOfParallelism);
        var allTasks = source.Select(async item =>
        {
            await throttler.WaitAsync();
            try
            {
                await asyncAction(item).ConfigureAwait(false);
            }
            finally
            {
                throttler.Release();
            }
        });
        await Task.WhenAll(allTasks);
    }

    // Enhanced version with CancellationToken
    public static async Task ExecuteInParallelAsync<T>(
        this IEnumerable<T> source,
        Func<T, CancellationToken, Task> asyncAction,
        int maxDegreeOfParallelism,
        CancellationToken cancellationToken)
    {
        var throttler = new SemaphoreSlim(initialCount: maxDegreeOfParallelism);
        var allTasks = source.Select(async item =>
        {
            await throttler.WaitAsync(cancellationToken);
            if (cancellationToken.IsCancellationRequested) return;

            try
            {
                await asyncAction(item, cancellationToken).ConfigureAwait(false);
            }
            finally
            {
                throttler.Release();
            }
        });
        await Task.WhenAll(allTasks);
    }
}

// await myCollection.ExecuteInParallelAsync(async item => await GetData(item), 10);

Solution 6: Memory-Efficient Parallel Processing

This implementation focuses on memory efficiency by avoiding the collection of all tasks. It utilizes SemaphoreSlim for throttling and ConcurrentBag for exception aggregation, ensuring a cleaner error-handling strategy.

public static class EfficientParallel
{
    public static async Task ProcessInParallelAsync<T>(
        this IEnumerable<T> items,
        Func<T, Task> processAction,
        int maxConcurrency = 10)
    {
        var concurrencyLimiter = new SemaphoreSlim(maxConcurrency);
        var completionSignal = new TaskCompletionSource<object>();
        var capturedExceptions = new ConcurrentBag<Exception>();
        bool processingFinished = false;

        foreach (T item in items)
        {
            await concurrencyLimiter.WaitAsync();
            processAction(item).ContinueWith(task =>
            {
                concurrencyLimiter.Release();

                if (task.Exception != null)
                {
                    capturedExceptions.Add(task.Exception);
                }

                if (Interlocked.CompareExchange(ref processingFinished, 0, 1) == 1 && concurrencyLimiter.CurrentCount == maxConcurrency)
                {
                    completionSignal.TrySetResult(null);
                }
            });
        }

        Interlocked.Exchange(ref processingFinished, 1);
        await completionSignal.Task;
        if (capturedExceptions.Count > 0)
        {
            throw new AggregateException(capturedExceptions);
        }
    }
}

// Example usage:
// await Enumerable.Range(1, 5000).ProcessInParallelAsync(async i => await GetData(i), maxConcurrency: 50);

Solution 7: Concurrent ForEachAsync with Throttling

This approach provides a flexible ForEachAsyncConcurrent extension method that leverages SemaphoreSlim for managing the degree of parallelism. It allows for optional throttling and graceful handling of task completion.

public static class ConcurrentIteration
{
    public static async Task ForEachAsyncConcurrent<T>(
        this IEnumerable<T> items,
        Func<T, Task> asyncOperation,
        int? maxConcurrentOperations = null)
    {
        if (maxConcurrentOperations.HasValue && maxConcurrentOperations.Value > 0)
        {
            using (var throttler = new SemaphoreSlim(maxConcurrentOperations.Value, maxConcurrentOperations.Value))
            {
                var ongoingTasks = new List<Task>();

                foreach (var item in items)
                {
                    await throttler.WaitAsync();

                    ongoingTasks.Add(Task.Run(async () =>
                    {
                        await asyncOperation(item).ContinueWith(_ => throttler.Release());
                    }));
                }
                await Task.WhenAll(ongoingTasks.ToArray());
            }
        }
        else
        {
            await Task.WhenAll(items.Select(item => asyncOperation(item)));
        }
    }
}

// await myDataCollection.ForEachAsyncConcurrent(async data => await ProcessDataAsync(data), 5);

Solution 8: Simplified Result Collection

This method streamlines the process of collecting results by directly awaiting tasks and accessing their Result property after Task.WhenAll has completed. It avoids the need for a ConcurrentBag if only final results are needed.

await Task.WhenAll(processingTasks);

var finalResults = processingTasks.Select(task => task.Result);

Solution 9: Dataflow Blocks for Complex Pipelines

For more intricate scenarios involving pipelines of asynchronous operations, the Task Parallel Library (TPL) Dataflow offers ActionBlock<T>. This provides fine-grained control over message processing, parallelism, and buffering.

using System.Threading.Tasks.Dataflow;

public static class DataflowProcessor
{
    public static async Task ProcessWithDataflowAsync<T>(
        this IAsyncEnumerable<T> sourceData,
        Func<T, Task> processingLogic,
        int workerCount,
        int? bufferCapacity = null)
    {
        var processingBlock = new ActionBlock<T>(
           processingLogic,
           new ExecutionDataflowBlockOptions
           {
             MaxDegreeOfParallelism = workerCount,
             BoundedCapacity = bufferCapacity ?? workerCount * 3
           });

        await foreach (T item in sourceData)
        {
           await processingBlock.SendAsync(item).ConfigureAwait(false);
        }

        processingBlock.Complete();
        await processingBlock.Completion;
    }
}

// Example Usage:
// await myAsyncEnumerable.ProcessWithDataflowAsync(async item => await DoWork(item), 8);

Solution 10: Nested Parallel.ForEach in Task.Run

A simpler approach for background operations involves nesting Parallel.ForEach within Task.Run. This allows long-running tasks to execute without blocking the main thread, and ParallelOptions manages the concurrency.

// Assume myCollection is an IEnumerable<SomeType>
// Assume DoWork(item) performs an action on an item

var executionSettings = new ParallelOptions { MaxDegreeOfParallelism = 5 };

Task.Run(() =>
{
    Parallel.ForEach(myCollection, executionSettings, item =>
    {
        DoWork(item);
    });
});

// where the initial call needs to return quickly while the operation continues.

FAQs on .NET Parallel Asynchronous Execution Strategies

Q: What is the primary advantage of Parallel.ForEachAsync

ANS: Parallel.ForEachAsync provides built-in control over the number of concurrent operations, making it easier to manage resources compared to simpler Task.WhenAll approaches for large collections.

Q: When should I use SemaphoreSlim for parallel tasks

ANS: Use SemaphoreSlim when you need to manually limit the number of concurrently executing asynchronous operations, offering fine-grained control beyond what built-in methods might provide.

Q: What is the role of ConcurrentBag in parallel processing

ANS: ConcurrentBag is a thread-safe collection ideal for scenarios where multiple threads or tasks need to add items to a shared collection concurrently without race conditions.

Q: How does TPL Dataflow differ from Task.WhenAll

ANS: TPL Dataflow, using blocks like ActionBlock, is designed for building complex, asynchronous data processing pipelines with features like buffering, throttling, and chaining of operations, whereas Task.WhenAll is more for awaiting a set of independent tasks.

Q: Is async void lambda an acceptable pattern for parallel tasks

ANS: No, async void lambdas are generally an anti-pattern because they make exception handling difficult. Prefer async Task or async Task<TResult> delegates.
