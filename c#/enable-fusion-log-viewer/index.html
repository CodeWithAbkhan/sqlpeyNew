“Enable .NET Assembly Binding Log Viewer (Fusion Log Viewer)”

When encountering issues with assembly loading in .NET applications, the Assembly Binding Log Viewer, commonly known as Fusion Log Viewer (Fuslogvw.exe), is an invaluable tool. This utility provides detailed insights into how the .NET runtime searches for and binds to assemblies, helping pinpoint the root cause of FileNotFoundException or BadImageFormatException errors. This post explores various methods to enable and configure Fusion logging.

Solution 1: Direct Registry Configuration

You can enable Fusion logging by directly modifying the Windows Registry. This method involves adding specific DWORD values to the HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Fusion key.

  • ForceLog: Set to 1 to enable logging.
  • LogFailures: Set to 1 to log assembly binding failures.
  • LogResourceBinds: Set to 1 to log resource binding attempts.
  • EnableLog: Set to 1 to generally enable logging.
  • LogPath: A String value specifying the directory where logs will be stored (e.g., C:\FusionLog\). Ensure this folder exists and you include the trailing backslash.

After applying these registry changes, restart the application you are debugging for the new settings to take effect. Remember to disable logging once you have resolved the issue to prevent excessive disk usage.

[HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Fusion]
"ForceLog"=dword:00000001
"LogFailures"=dword:00000001
"LogResourceBinds"=dword:00000001
"EnableLog"=dword:00000001
"LogPath"="C:\\FusionLog\\"

Solution 2: Using Fusion Log Viewer (Fuslogvw.exe)

The Fusion Log Viewer itself provides a user-friendly interface for managing logging settings.

  1. Launch Fusion Log Viewer as an administrator. You can typically find this by searching for “Fusion” in the Start menu, or by running fuslogvw.exe from a Visual Studio command prompt.
  2. Navigate to Settings.
  3. Check the box for Enable custom log path.
  4. Enter your desired log directory, for example, c:\FusionLogs. Ensure this folder is created.
  5. Select the logging level. Log all binds to disk is a good starting point for troubleshooting.
  6. Click OK.
  7. Set the log location option to Custom.

Again, it’s crucial to disable logging after your debugging session.

Solution 3: Leveraging Windows SDK Tools

If you have the Windows SDK installed, the Fusion Log Viewer is readily available.

  1. Locate “Fusion Log Viewer” in your Start menu (often under Microsoft SDK\Tools).
  2. Launch it.
  3. Click the Settings button.
  4. Choose either Log bind failure or Log all binds.
  5. If these options are disabled, right-click the Fusion Log Viewer in the Start menu and select Run as Administrator.

Solution 4: PowerShell Scripting for Enabling/Disabling

For automated management, PowerShell scripts are efficient.

To Enable Fusion Logging:

# Ensure the log directory exists
$logPath = 'C:\FusionLog\'
if (-not (Test-Path $logPath)) {
    New-Item -Path $logPath -ItemType Directory -Force
}

# Set registry values to enable logging
Set-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name ForceLog         -Value 1 -Type DWord -Force
Set-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogFailures      -Value 1 -Type DWord -Force
Set-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogResourceBinds -Value 1 -Type DWord -Force
Set-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogPath          -Value $logPath -Type String -Force
Set-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name EnableLog        -Value 1 -Type DWord -Force

Write-Host "Fusion logging enabled. Logs will be saved to $logPath"

To Disable Fusion Logging:

# Remove registry values to disable logging
Remove-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name ForceLog -ErrorAction SilentlyContinue
Remove-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogFailures -ErrorAction SilentlyContinue
Remove-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogResourceBinds -ErrorAction SilentlyContinue
Remove-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name LogPath -ErrorAction SilentlyContinue
Remove-ItemProperty -Path HKLM:\Software\Microsoft\Fusion -Name EnableLog -ErrorAction SilentlyContinue

Write-Host "Fusion logging disabled."

You can save these scripts as .ps1 files and run them with administrative privileges.

Solution 5: Using a .reg File

A .reg file can be created to quickly enable logging.

Save the following content as FusionEnableLog.reg:

Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Fusion]
"EnableLog"=dword:00000001
"ForceLog"=dword:00000001
"LogFailures"=dword:00000001
"LogResourceBinds"=dword:00000001
"LogPath"="C:\\FusionLog\\"

Run this file from Windows Explorer. You will be prompted with a warning; confirm to merge it into the registry. Ensure the C:\FusionLog\ directory exists.

Solution 6: Fusion++ - An Alternative Viewer

For those seeking a more streamlined experience, Fusion++ is a custom-built alternative viewer available on GitHub. It simplifies the process by automatically managing log paths and parsing logs, offering a more intuitive interface compared to the default Fusion Log Viewer. You can install it via Chocolatey: choco install fusionplusplus.

Solution 8: Enabling Fusion Logging via ETW/xperf

For advanced diagnostics, Fusion logging can be enabled through Event Tracing for Windows (ETW) using xperf. This involves turning on the Microsoft-Windows-DotNETRuntimePrivate provider with the FusionKeyword.

@echo off
echo Press a key when ready to start...
pause
echo .
echo ...Capturing...
echo .

REM Start kernel tracing
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -on PROC_THREAD+LOADER+PROFILE -stackwalk Profile -buffersize 1024 -MaxFile 2048 -FileMode Circular -f Kernel.etl

REM Start CLR session with Fusion logging enabled
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -start ClrSession -on Microsoft-Windows-DotNETRuntime:0x8118:0x5:'stack'+763FD754-7086-4DFE-95EB-C01A46FAF4CA:0x4:0x5 -f clr.etl -buffersize 1024

echo Press a key when you want to stop...
pause
pause
echo .
echo ...Stopping...
echo .

REM Start CLR rundown session
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -start ClrRundownSession -on Microsoft-Windows-DotNETRuntime:0x8118:0x5:'stack'+Microsoft-Windows-DotNETRuntimeRundown:0x118:0x5:'stack' -f clr_DCend.etl -buffersize 1024

timeout /t 15

REM Set environment variable for PDB generation
set XPERF_CreateNGenPdbs=1

REM Stop tracing sessions and merge results
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -stop ClrSession ClrRundownSession
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -stop
"C:\Program Files (x86)\Windows Kits\8.1\Windows Performance Toolkit\xperf.exe" -merge kernel.etl clr.etl clr_DCend.etl Result.etl -compress

REM Clean up temporary files
del kernel.etl
del clr.etl
del clr_DCend.etl

echo Tracing complete. The results are in Result.etl. Open with PerfView.

After running this script, you can open the generated Result.etl file in PerfView to analyze the Fusion data within the Events table.

Solution 9: Batch File for Enabling

A simple batch file can automate the registry modifications for enabling Fusion logging.

@echo off
reg add "HKLM\Software\Microsoft\Fusion" /v EnableLog /t REG_DWORD /d 1 /f
reg add "HKLM\Software\Microsoft\Fusion" /v ForceLog /t REG_DWORD /d 1 /f
reg add "HKLM\Software\Microsoft\Fusion" /v LogFailures /t REG_DWORD /d 1 /f
reg add "HKLM\Software\Microsoft\Fusion" /v LogResourceBinds /t REG_DWORD /d 1 /f
reg add "HKLM\Software\Microsoft\Fusion" /v LogPath /t REG_SZ /d C:\FusionLog\ /f

if not exist "C:\FusionLog\" mkdir "C:\FusionLog\"

echo Fusion logging enabled. Logs will be saved to C:\FusionLog\

Run this batch file as an administrator.

Solution 10: A Word of Caution

It is paramount to disable Fusion logging when it’s no longer needed. Failing to do so can lead to the creation of millions of log files, consuming vast amounts of disk space and severely impacting system performance. One user reported a scenario where forgetting to disable logging resulted in gigabytes of log files, causing file explorer to hang and a lengthy deletion process.

Solution 11: Handling Stale Assemblies

If you encounter errors related to assemblies that you’ve developed, ensure you are not dealing with stale versions. If your application loads assemblies from a directory, and a stale assembly references another assembly whose namespaces or class names have changed, this can lead to binding issues. Carefully examine the error message for namespace and class names; if they don’t appear in your current solution, a stale assembly might be the culprit. Regularly cleaning up and rebuilding your projects is advisable.

Solution 12: Locating FusionLog.exe

The exact location of FusionLog.exe can vary depending on your installed .NET Framework versions and SDKs. Common locations include:

  • C:\Program Files (x86)\Microsoft SDKs\Windows\vX.0A\bin\NETFX Y.Y Tools\x64
  • C:\Program Files (x86)\Microsoft SDKs\Windows\vX.0A\Bin\x64
  • C:\Program Files (x86)\Microsoft SDKs\Windows\vX.0A\bin\NETFX Y.Y Tools
  • C:\Program Files (x86)\Microsoft SDKs\Windows\vX.0A\Bin

Where X.0A refers to the Windows SDK version and Y.Y to the .NET Framework version.

Solution 13: IIS 7.5 Specifics for 64-bit

For Windows 7 64-bit with IIS 7.5, if you’re experiencing issues despite having logging enabled, try this:

  1. Create a new Application Pool.
  2. In the Application Pool’s Advanced Settings, set Enable 32-Bit Applications to True.
  3. Assign your web application to this new Application Pool.

Solution 14: Case Sensitivity in Paths

In some specific scenarios, especially with older systems or configurations, using lowercase drive letters in file paths might resolve issues. For example, using c:\someFolder instead of C:\someFolder could make a difference.

FAQs on Enable .NET Assembly Binding Log Viewer (Fusion Log Viewer)

Q: How do I enable Fusion logging using the registry

ANS: You can enable Fusion logging by adding DWORD values ForceLog, LogFailures, LogResourceBinds, and EnableLog to HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Fusion and setting them to 1. Also, set a LogPath string value for the log directory.

Q: What is the default location of FusionLog.exe

ANS: The location of FusionLog.exe can vary. Common paths include directories within C:\Program Files (x86)\Microsoft SDKs\Windows\ depending on your installed SDK and .NET Framework versions.

Q: Is it safe to leave Fusion logging enabled permanently

ANS: No, it is strongly advised not to leave Fusion logging enabled permanently. It can generate a large number of log files, consuming significant disk space and negatively impacting system performance. Always disable it after debugging.

Q: Can PowerShell be used to manage Fusion logging

ANS: Yes, PowerShell scripts can be used to conveniently enable and disable Fusion logging by modifying the relevant registry keys.

Q: What if the Fusion Log Viewer settings are disabled

ANS: If the settings in the Fusion Log Viewer are disabled, try running the application as an administrator. This usually resolves the issue, allowing you to modify the logging settings.

Q: What are the potential consequences of not disabling Fusion logging

ANS: Not disabling Fusion logging can lead to a massive accumulation of log files, potentially filling up your hard drive and causing severe performance degradation, making your system unresponsive.
