“Handle Multiple Submit Buttons in ASP.NET MVC”

When building web applications with ASP.NET MVC, a common requirement is to present users with multiple submission options within a single form. This could involve actions like “Save,” “Cancel,” “Submit,” or “Update.” The challenge lies in directing these distinct user intentions to the appropriate controller actions. This post delves into various methods for effectively managing multiple submit buttons in ASP.NET MVC, providing practical code examples and considerations for each approach.

Solution 1: Attribute-Based Action Selection

This approach, credited to Maarten Balliauw, utilizes a custom ActionNameSelectorAttribute to differentiate button clicks based on specific attribute arguments.

C# Code Example: MultipleButtonAttribute
[AttributeUsage(AttributeTargets.Method, AllowMultiple = false, Inherited = true)]
public class MultipleButtonAttribute : ActionNameSelectorAttribute
{
    public string Name { get; set; }
    public string Argument { get; set; }

    public override bool IsValidName(ControllerContext controllerContext, string actionName, MethodInfo methodInfo)
    {
        var isValidName = false;
        var keyValue = $"{Name}:{Argument}"; // Using string interpolation for clarity
        var value = controllerContext.Controller.ValueProvider.GetValue(keyValue);

        if (value != null)
        {
            // Ensure RouteData is properly updated for routing
            controllerContext.Controller.ControllerContext.RouteData.Values[Name] = Argument;
            isValidName = true;
        }

        return isValidName;
    }
}
Razor View Markup
<form action="" method="post">
    <input type="submit" value="Save" name="action:Save" />
    <input type="submit" value="Cancel" name="action:Cancel" />
</form>
Controller Actions
[HttpPost]
[MultipleButton(Name = "action", Argument = "Save")]
public ActionResult Save(MessageModel mm)
{
    // Logic for saving
    return View();
}

[HttpPost]
[MultipleButton(Name = "action", Argument = "Cancel")]
public ActionResult Cancel(MessageModel mm)
{
    // Logic for canceling
    return RedirectToAction("Index");
}

Update: Razor Pages offer built-in support for similar functionality, potentially making them a more streamlined choice for new development.

Solution 2: Inspecting Submitted Button Value

A straightforward method involves assigning a common name to all submit buttons and then examining the submitted value within the controller.

Razor View Markup (using Html.BeginForm)
@using (Html.BeginForm("MyAction", "MyController", FormMethod.Post))
{
    <input type="submit" name="submitButton" value="Send" />
    <input type="submit" name="submitButton" value="Cancel" />
}
Controller Action
public class MyController : Controller
{
    public ActionResult MyAction(string submitButton)
    {
        switch (submitButton)
        {
            case "Send":
                return Send();
            case "Cancel":
                return Cancel();
            default:
                // Handle cases where the form is submitted without a specific button
                return View();
        }
    }

    private ActionResult Cancel()
    {
        // Process cancellation
        return View("Cancelled");
    }

    private ActionResult Send()
    {
        // Process sending
        return View("SendConfirmed");
    }
}

For Internationalization: To support localized button text, isolate messages in resource files. Then, compare the submitted button value against these localized resources.

// In the Razor View:
<input type="submit" name="submitButton" value="@Html.Encode(Resources.Messages.Send)" />
<input type="submit" name="submitButton" value="@Html.Encode(Resources.Messages.Cancel)" />

// In the Controller (avoiding switch due to non-constant resources):
if (submitButton == Resources.Messages.Send)
{
    return Send();
}
else if (submitButton == Resources.Messages.Cancel)
{
    return Cancel();
}

Solution 3: Separate Forms and Actions

A cleaner design principle suggests decoupling UI elements from form submission logic. This can be achieved by using separate forms, each submitting to a distinct action. For “Cancel” actions, a simple Html.ActionLink is often sufficient.

Razor View Markup
@using (Html.BeginForm("Send", "MyController", FormMethod.Post))
{
    <input type="submit" name="button" value="Send" />
}

@using (Html.BeginForm("Cancel", "MyController", FormMethod.Post))
{
    <input type="submit" name="button" value="Cancel" />
}

@Html.ActionLink("Cancel", "List", "MyController")

Solution 4: Leveraging Button Names as Parameters

This approach involves naming each submit button and then accepting parameters in the controller action that correspond to these names. The browser only posts a value for the clicked button.

HTML Input Example
<input type="submit" name="SaveButton" value="Save data" />
<input type="submit" name="CancelButton" value="Cancel and go back to main page" />
Controller Action Signature
public ActionResult DoSomeStuff(string SaveButton, string CancelButton, ModelType otherParameters)
{
    if (SaveButton != null)
    {
        // Handle save logic
    }
    if (CancelButton != null)
    {
        // Handle cancel logic
    }
    return View();
}

This method is robust as it relies on button names, which are less likely to change than their display value. For further discussion, see this ASP.NET forum thread .

Solution 5: HttpParamActionAttribute

This custom attribute, similar to Solution 1, uses the parameter name to identify the target action. It provides a clean way to route requests based on submitted form parameters.

C# Attribute Example
public class HttpParamActionAttribute : ActionNameSelectorAttribute
{
    private readonly string _actionName;

    public HttpParamActionAttribute(string actionName)
    {
        _actionName = actionName;
    }

    public override bool IsValidName(ControllerContext controllerContext, string actionName, MethodInfo methodInfo)
    {
        // Check if the current action name matches the method name
        if (actionName.Equals(methodInfo.Name, StringComparison.InvariantCultureIgnoreCase))
            return true;

        // Check if the action name matches the specified parameter action
        if (!actionName.Equals(_actionName, StringComparison.InvariantCultureIgnoreCase))
            return false;

        var request = controllerContext.RequestContext.HttpContext.Request;
        // Check if the method name (as a parameter) exists in the request
        return request[methodInfo.Name] != null;
    }
}
Razor View Markup
@using (Html.BeginForm("Action", "Post"))
{
    <!-- ... form fields ... -->
    <input type="submit" name="saveDraft" value="Save Draft" />
    <input type="submit" name="publish" value="Publish" />
}
Controller Actions
public class PostController : Controller
{
    [HttpParamAction("Action")] // Refers to the generic "Action" in BeginForm
    [AcceptVerbs(HttpVerbs.Post)]
    public ActionResult SaveDraft(/* parameters */)
    {
        // Save draft logic
        return View();
    }

    [HttpParamAction("Action")] // Refers to the generic "Action" in BeginForm
    [AcceptVerbs(HttpVerbs.Post)]
    public ActionResult Publish(/* parameters */)
    {
        // Publish logic
        return View();
    }
}

This attribute doesn’t require explicit parameter names in the attribute itself, and the button names directly map to the method names.

Solution 7: Utilizing the formaction Attribute (HTML5)

For modern browsers (IE 10+), the formaction attribute on input buttons allows specifying a distinct submission URL for each button.

Solution 9: jQuery for Dynamic Form Actions

If cross-browser compatibility for formaction is a concern, or if you prefer a client-side JavaScript solution, jQuery can be employed to dynamically set the form’s action attribute before submission.

jQuery Code
$(document).on('click', '[type="submit"][data-form-action]', function(event) {
    var $this = $(this),
        formAction = $this.attr('data-form-action'),
        $form = $($this.closest('form'));
    $form.attr('action', formAction);
});
HTML Markup
<button type="submit" data-form-action="different/url">Submit</button>

This solution requires jQuery 1.7 or later. For earlier versions, consider using .live() instead of .on().

Solution 10: ActionFilterAttribute for Enum-Based Handling

An ActionFilterAttribute can intercept requests and map button presses to an enum value, providing a structured way to handle multiple actions.

C# Enum and Attribute
public enum ButtonType
{
    Submit,
    Cancel,
    Delete
}

public class MultipleButtonsEnumAttribute : ActionFilterAttribute
{
    public Type EnumType { get; set; }

    public MultipleButtonsEnumAttribute(Type enumType)
    {
        EnumType = enumType;
    }

    public override void OnActionExecuting(ActionExecutingContext filterContext)
    {
        foreach (var key in filterContext.HttpContext.Request.Form.AllKeys)
        {
            if (Enum.IsDefined(EnumType, key))
            {
                var parameterDescriptor = filterContext.ActionDescriptor.GetParameters()
                    .FirstOrDefault(x => x.ParameterType == EnumType);

                if (parameterDescriptor != null)
                {
                    filterContext.ActionParameters[parameterDescriptor.ParameterName] = Enum.Parse(EnumType, key);
                    break; // Assume only one button is clicked
                }
            }
        }
    }
}
Controller Action
[MultipleButtonsEnumAttribute(typeof(ButtonType))]
public ActionResult Manage(ButtonType buttonPressed, ManageViewModel model)
{
    if (buttonPressed == ButtonType.Cancel)
    {
        return RedirectToAction("Index", "Home");
    }
    // Handle other button actions...
    return View(model);
}
Razor View Markup
<input type="submit" value="Button Cancel" name="@ButtonType.Cancel" />
<input type="submit" value="Button Submit" name="@ButtonType.Submit" />

Solution 11: Parameter Mapping with Submit_ Prefix

This strategy involves prefixing submit button names (e.g., Submit_ActionName) and then extracting the action name on the server side. This is particularly useful for image buttons as well.

HTML Markup
<!-- Image button -->
<input id="btnJoin" name="Join" src="/content/images/buttons/btnJoin.png" type="image">

<!-- Text submit buttons -->
<input type="submit" class="ui-button green" name="Submit_Join" value="Add to cart" />
<input type="submit" class="ui-button red" name="Submit_Skip" value="Not today" />
C# Extension Method for FormCollection
public static class FormCollectionExtensions
{
    public static string GetSubmitButtonName(this FormCollection formCollection, bool throwOnError = true)
    {
        var imageButton = formCollection.Keys.OfType<string>().FirstOrDefault(x => x.EndsWith(".x"));
        var textButton = formCollection.Keys.OfType<string>().FirstOrDefault(x => x.StartsWith("Submit_"));

        if (textButton != null)
        {
            return textButton.Substring("Submit_".Length);
        }

        if (imageButton != null)
        {
            return imageButton.Substring(0, imageButton.Length - 2); // Remove ".x"
        }

        if (throwOnError)
        {
            throw new ApplicationException("No submit button found.");
        }
        else
        {
            return null;
        }
    }
}

You would then call this extension method in your controller: var action = formCollection.GetSubmitButtonName();.

Solution 13: Html.ActionButton Helper Method

This approach involves creating a custom HtmlHelper extension method to generate buttons that dynamically set the form’s action and submit.

C# Extension Method
public static class HtmlHelperExtensions
{
    public static MvcHtmlString ActionButton(this HtmlHelper helper, string controller, string action, object routeValues, string buttonValue, string buttonName = "", string buttonId = "")
    {
        var urlHelper = new UrlHelper(helper.ViewContext.RequestContext);
        var actionLink = urlHelper.Action(action, controller, routeValues);
        var onClickScript = $"this.form.action = '{actionLink}'; this.form.submit();";

        var tagBuilder = new TagBuilder("input");
        tagBuilder.MergeAttribute("type", "button");
        tagBuilder.MergeAttribute("onClick", onClickScript);
        tagBuilder.MergeAttribute("value", buttonValue);
        if (!string.IsNullOrEmpty(buttonName)) tagBuilder.MergeAttribute("name", buttonName);
        if (!string.IsNullOrEmpty(buttonId)) tagBuilder.MergeAttribute("id", buttonId);

        return MvcHtmlString.Create(tagBuilder.ToString(TagRenderMode.Normal));
    }
}
Usage in Razor
@Html.ActionButton("MyController", "MyAction", new { id = 1 }, "Button Text")

This generates HTML like: <input type="button" value="Button Text" onclick="this.form.action = '/MyController/MyAction/1'; this.form.submit();">

Solution 15: ActionNameSelectorAttribute with Parameter List

A refined version of Solution 1 could use a List<string> to accept multiple button names for an action.

C# Attribute
public class MultipleButtonActionAttribute : ActionNameSelectorAttribute
{
    private readonly List<string> _acceptedButtonNames;

    public MultipleButtonActionAttribute(params string[] acceptedButtonNames)
    {
        _acceptedButtonNames = acceptedButtonNames.ToList();
    }

    public override bool IsValidName(ControllerContext controllerContext, string actionName, MethodInfo methodInfo)
    {
        foreach (var acceptedButtonName in _acceptedButtonNames)
        {
            var buttonValue = controllerContext.Controller.ValueProvider.GetValue(acceptedButtonName);
            if (buttonValue == null) continue;

            // Store the clicked button name for later use if needed
            controllerContext.Controller.ControllerContext.RouteData.Values["ButtonClicked"] = acceptedButtonName;
            return true;
        }
        return false;
    }
}
Razor View
<input type="submit" value="Save" name="Save" />
<input type="submit" value="Save and Sync" name="Sync" />
Controller Action
[MultipleButtonAction("Save", "Sync")]
public ActionResult Sync(ModelType model)
{
    var clickedButton = this.RouteData.Values["ButtonClicked"] as string;
    // Use clickedButton to determine action
    return View(model);
}

Considerations for Internationalization and UI Coupling

When choosing a method, consider how easily it can be adapted for multilingual support. Solutions that rely on hardcoded button values for logic might become problematic. Separating logic from UI text (e.g., using resource files) is generally a good practice. Also, avoid tightly coupling your controller actions to specific UI elements like button names if possible, favoring more abstract mechanisms like the ActionNameSelectorAttribute.

FAQs on Handling Multiple Submit Buttons in ASP.NET MVC

Q: How can I differentiate which submit button was clicked in ASP.NET MVC

ANS: You can differentiate by giving each submit button a unique name attribute and then checking for the presence of that name in your controller, or by using value attributes and inspecting those. Custom attributes like ActionNameSelectorAttribute or ActionFilterAttribute offer more structured approaches.

Q: Is there a way to handle multiple submit buttons without JavaScript

ANS: Yes, several server-side approaches work without JavaScript. These include using separate forms for each action, or giving unique name attributes to your submit buttons and checking them in the controller. Attribute-based routing (e.g., ActionNameSelectorAttribute) is also a robust server-side solution.

Q: Can I use HTML5 formaction with ASP.NET MVC

ANS: Yes, you can use the HTML5 formaction attribute directly in your Razor views. For older browsers, you might need a JavaScript fallback, potentially using jQuery to dynamically set the form’s action.

Q: What's the best practice for localizing submit button text when handling multiple buttons

ANS: It’s best to use resource files for all display text, including button labels. In your controller, you would then compare the submitted button’s value against the localized text retrieved from the resource file, rather than hardcoding button labels.

Q: Should I use separate forms or a single form with multiple buttons

ANS: Using separate forms can lead to cleaner code separation and better semantic meaning for each action. However, a single form with multiple buttons can simplify the user interface and reduce the number of HTTP requests if the actions are closely related. The choice often depends on the specific requirements and complexity of your application.
