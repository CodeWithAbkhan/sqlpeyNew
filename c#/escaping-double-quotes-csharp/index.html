Can I escape a double quote in a verbatim string literal?

C#
6 min read · Nov 4, 2025

Table of Contents

    • FAQs on Escaping Double Quotes in C#

When working with strings in C#, particularly when those strings contain double quotation marks, proper escaping is crucial to avoid syntax errors and ensure your strings are interpreted correctly. This article delves into various techniques to handle double quotes within your C# code, offering practical examples and explanations for each.

Why is Escaping Necessary?

In C#, the double quote character (") is used to delimit string literals. When you need to include a literal double quote character within a string, the compiler needs a way to distinguish it from the quote that signifies the end of the string. Escaping provides this mechanism.

Method 1: The Duplicated Double Quote

One straightforward way to represent a double quote within a string literal is to simply use two consecutive double quotes. The compiler interprets this pair as a single literal double quote.

Example:

string message = @"This ""word"" is escaped.";
Console.WriteLine(message);

Output:

This "word" is escaped.

This approach is clear and directly addresses the need to include a quote. You can see this in action within our example:

// Demonstrating duplicated double quote escaping
string escapedMessage = @"This ""word"" is escaped.";
Console.WriteLine(escapedMessage);

Method 2: Verbatim String Literals with @

Verbatim string literals, prefixed with the @ symbol, treat their content almost literally, meaning most escape sequences are ignored. This is particularly useful for strings containing backslashes or multiple quotes.

Example:

string verbatimString = @"This ""word"" is escaped using verbatim.";
Console.WriteLine(verbatimString);

Output:

This "word" is escaped using verbatim.

The @ symbol makes handling quotes simpler as you still use the double-double-quote method within the verbatim string.

Method 3: Regular String Literals with Backslash Escaping

For standard string literals (not verbatim), you can use the backslash (\) as an escape character. To include a literal double quote, you precede it with a backslash.

Example:

string regularEscape = "This \"word\" is escaped using a backslash!";
Console.WriteLine(regularEscape);

Output:

This "word" is escaped using a backslash!

While effective, this method can sometimes make strings with many quotes less readable, especially when compared to verbatim strings or raw string literals. This method remains a fundamental way to handle string escapes in C#.

Method 4: C# 11 and Later - Raw String Literals

With the introduction of C# 11, raw string literals offer a more flexible way to embed strings, including those with quotes, without requiring extensive escaping. Raw string literals are delimited by at least three double quotes (""").

Single-line Raw String Literal:

string singleLineRaw = """Anything, including " is supported here without escaping.""";
Console.WriteLine(singleLineRaw);

Output:

Anything, including " is supported here without escaping."

Multi-line Raw String Literal:

Multi-line raw string literals preserve indentation and newlines, making them ideal for embedded code or configurations. The indentation of the closing delimiter determines the indentation removed from each line within the literal.

string multiLineRaw = """
    Any blank after the opening quotes in previous line is discarded.
    This is WYSIWYG, including "quotes" and new lines.
        This line is indented by 4 characters, not 8, because
    the number of characters before the closing quotes
    of the next line are removed from each line.
    """;
Console.WriteLine(multiLineRaw);

Output:

Any blank after the opening quotes in previous line is discarded.
This is WYSIWYG, including "quotes" and new lines.
    This line is indented by 4 characters, not 8, because
the number of characters before the closing quotes
of the next line are removed from each line.

Raw string literals can also be interpolated using the @ prefix:

string propertyName = "myProperty";
int propertyValue = 123;

var interpolatedRaw = @$"
    The value of ""{propertyName}"" is:
    {propertyValue}
    ";
Console.WriteLine(interpolatedRaw);

Output:

    The value of "myProperty" is:
    123

Key Takeaways on String Literal Behavior

The C# compiler interprets escape sequences within string literals.

  • Simple escape sequences (like \n for newline, \t for tab) are converted to their corresponding characters.
  • The quote escape sequence ("") is a special case; it’s always interpreted as a single literal double quote, regardless of whether it’s within a verbatim string or not.
  • In verbatim interpolated strings, brace escape sequences (like {{ and }}) are processed to produce single brace characters, preventing accidental interpolation of curly braces.

Alternative: Interpolation without @

When using regular string literals for interpolation, you still need to escape embedded double quotes if you intend to include them as literal characters within the interpolated string.

Example:

string interpolatedWithEscape = $"This \"word\" is interpolated and escaped.";
Console.WriteLine(interpolatedWithEscape);

Output:

This "word" is interpolated and escaped.

This method works but can become cumbersome with complex strings. Using verbatim or raw string literals often leads to cleaner code.

FAQs on Escaping Double Quotes in C#

Q: What is the simplest way to put a double quote in a C# string

ANS: The simplest way is to use a single escaped double quote with a backslash: "\"". For verbatim strings, you duplicate the double quote: @"\"". With C# 11 raw string literals, you can simply include it: """"""".

Q: Can I use single quotes for strings in C#

ANS: No, C# exclusively uses double quotes (") for string literals. Single quotes (') are used for character literals.

Q: How do verbatim strings handle quotes

ANS: Verbatim strings, prefixed with @, handle embedded double quotes by requiring them to be escaped as a pair of double quotes ("").

Q: Are raw string literals available in all C# versions

ANS: No, raw string literals were introduced in C# 11. They are not available in earlier versions of C#.

Q: What is the difference between verbatim and raw string literals

ANS: Verbatim strings (@"...") treat most characters literally, but still require escaping "" for embedded quotes. Raw string literals (@"""...""" or """...""") offer more flexibility, allowing most characters, including quotes, to be included directly without escaping, and also preserve formatting like newlines and indentation.
