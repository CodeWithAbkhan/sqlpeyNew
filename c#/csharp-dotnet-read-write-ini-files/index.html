“C#/.NET: How to Read and Write INI Files Efficiently”

When developing applications with C# and the .NET framework, managing configuration settings is a common task. While XML and other structured formats are often preferred for modern applications, the need to interact with INI files persists, especially when integrating with legacy systems. The .NET framework doesn’t offer built-in direct support for INI files, meaning you’ll need to implement your own solutions or leverage external tools.

This post explores several effective approaches to reading and writing INI files in C#/.NET, providing practical code examples and discussing their merits. Whether you need a simple reader or a robust handler with write capabilities, you’ll find a suitable method here.

Why Still Use INI Files?

Despite the prevalence of JSON, XML, and other modern configuration formats, INI files remain relevant in certain scenarios:

  • Legacy System Integration: Many older applications rely on INI files for configuration, making direct interaction necessary for compatibility.
  • Simplicity: For straightforward configuration needs, INI files offer a human-readable and easily editable format.
  • Cross-Platform Considerations: While .NET itself is cross-platform, some native Windows APIs used for INI manipulation are not. Solutions that avoid these dependencies are valuable for broader compatibility.

Solution 1: Windows P/Invoke (kernel32.dll)

A common and powerful method involves using Windows API functions via Platform Invocation Services (P/Invoke). This approach directly calls WritePrivateProfileString and GetPrivateProfileString from kernel32.dll, offering native Windows support. This method is supported across most Windows versions.

using System.IO;
using System.Reflection;
using System.Runtime.InteropServices;
using System.Text;

namespace MyProg
{
    class IniFile
    {
        string Path;
        string EXE = Assembly.GetExecutingAssembly().GetName().Name;

        [DllImport("kernel32", CharSet = CharSet.Unicode)]
        static extern long WritePrivateProfileString(string Section, string Key, string Value, string FilePath);

        [DllImport("kernel32", CharSet = CharSet.Unicode)]
        static extern int GetPrivateProfileString(string Section, string Key, string Default, StringBuilder RetVal, int Size, string FilePath);

        public IniFile(string IniPath = null)
        {
            Path = new FileInfo(IniPath ?? EXE + ".ini").FullName;
        }

        public string Read(string Key, string Section = null)
        {
            var RetVal = new StringBuilder(255);
            GetPrivateProfileString(Section ?? EXE, Key, "", RetVal, 255, Path);
            return RetVal.ToString();
        }

        public void Write(string Key, string Value, string Section = null)
        {
            WritePrivateProfileString(Section ?? EXE, Key, Value, Path);
        }

        public void DeleteKey(string Key, string Section = null)
        {
            Write(Key, null, Section ?? EXE);
        }

        public void DeleteSection(string Section = null)
        {
            Write(null, null, Section ?? EXE);
        }

        public bool KeyExists(string Key, string Section = null)
        {
            return Read(Key, Section).Length > 0;
        }
    }
}

Usage Example:

// Creates or loads an INI file in the same directory as your executable named MyProgram.ini
var myIni = new IniFile();

// Or specify a specific name in the current directory
var myIniCustom = new IniFile("Settings.ini");

// Or specify a specific name in a specific directory
var myIniFull = new IniFile(@"C:\AppConfig\Settings.ini");

// Writing values
myIni.Write("DefaultVolume", "100");
myIni.Write("HomePage", "http://www.example.com");

// Reading values
string volume = myIni.Read("DefaultVolume");
string homePage = myIni.Read("HomePage");

// Using sections
myIni.Write("DefaultVolume", "90", "Audio");
myIni.Write("HomePage", "http://www.another-example.com", "Web");

// Checking for key existence and writing if absent
if (!myIni.KeyExists("LoggingEnabled", "Advanced"))
{
    myIni.Write("LoggingEnabled", "true", "Advanced");
}

// Deleting a key or section
myIni.DeleteKey("DefaultVolume", "Audio");
myIni.DeleteSection("Web");

Solution 2: Third-Party NuGet Packages

For a more convenient and often cross-platform compatible approach, consider using established third-party libraries available via NuGet.

  • INI Parser: A popular choice for parsing INI files. You can install it using the NuGet package manager:

    Install-Package IniParser

  • PeanutButter.INI: This library offers read/write capabilities, preserves comments, and is licensed under MIT.

    Install-Package PeanutButter.INI

  • Microsoft.Extensions.Configuration.Ini: If you’re using ASP.NET Core or need to integrate INI files into the Microsoft.Extensions.Configuration system, this package is a good fit.

    Install-Package Microsoft.Extensions.Configuration.Ini

Example using INI Parser:

// Assuming you have installed the IniParser NuGet package
using IniParser;
using IniParser.Model;

// Load or create an INI file
var parser = new FileIniDataParser();
IniData data = parser.ReadFile("config.ini");

// Reading a value (case-insensitive by default)
string siteName = data.ByKey("Site")["Name"];
string maxConnections = data["Database"]["MaxConnections"];

// Writing a value
data["Database"]["MaxConnections"] = "250";
data["Logging"]["Level"] = "Debug";

// Saving changes
parser.WriteFile("config.ini", data);

Solution 3: Custom C# Implementations

If you prefer not to rely on external libraries or need fine-grained control, you can write your own C# parser. These implementations often use System.IO to read the file line by line and System.Text.RegularExpressions for parsing.

Example using LINQ and Dictionaries (case-insensitive):

This approach reads the entire file and stores the data in nested dictionaries, offering case-insensitive access and handling comments starting with ‘;’.

using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;

class IniReader
{
    private readonly Dictionary<string, Dictionary<string, string>> _iniData =
        new Dictionary<string, Dictionary<string, string>>(StringComparer.InvariantCultureIgnoreCase);

    public IniReader(string filePath)
    {
        if (!File.Exists(filePath))
        {
            throw new FileNotFoundException($"INI file not found at: {filePath}");
        }

        var lines = File.ReadAllLines(filePath);
        Dictionary<string, string> currentSection = null;
        string currentSectionName = "";

        foreach (var line in lines)
        {
            var trimmedLine = line.Trim();

            if (string.IsNullOrWhiteSpace(trimmedLine) || trimmedLine.StartsWith(";") || trimmedLine.StartsWith("//"))
            {
                continue; // Skip empty lines and comments
            }

            if (trimmedLine.StartsWith("[") && trimmedLine.EndsWith("]"))
            {
                currentSectionName = trimmedLine.Substring(1, trimmedLine.Length - 2).Trim();
                currentSection = new Dictionary<string, string>(StringComparer.InvariantCultureIgnoreCase);
                _iniData[currentSectionName] = currentSection;
            }
            else if (currentSection != null)
            {
                var separatorIndex = trimmedLine.IndexOf('=');
                if (separatorIndex != -1)
                {
                    var key = trimmedLine.Substring(0, separatorIndex).Trim();
                    var value = trimmedLine.Substring(separatorIndex + 1).Trim();

                    if (!string.IsNullOrEmpty(key))
                    {
                        currentSection[key] = value.Trim('"'); // Remove surrounding quotes if present
                    }
                }
            }
        }
    }

    public string GetValue(string key, string section = null, string defaultValue = null)
    {
        section ??= ""; // Default to the root section if none specified

        if (_iniData.TryGetValue(section, out var sectionDict) && sectionDict.TryGetValue(key, out var value))
        {
            return value;
        }
        return defaultValue;
    }

    public IEnumerable<string> GetKeys(string section = null)
    {
        section ??= "";
        if (_iniData.TryGetValue(section, out var sectionDict))
        {
            return sectionDict.Keys;
        }
        return Enumerable.Empty<string>();
    }

    public IEnumerable<string> GetSections()
    {
        return _iniData.Keys.Where(s => !string.IsNullOrEmpty(s));
    }

    // Add methods for writing if needed
}

Usage Example:

try
{
    var configReader = new IniReader("application.ini");
    string logLevel = configReader.GetValue("LogLevel", "Logging", "Info");
    Console.WriteLine($"Log Level: {logLevel}");

    foreach (var sectionName in configReader.GetSections())
    {
        Console.WriteLine($"\nSection: [{sectionName}]");
        foreach (var keyName in configReader.GetKeys(sectionName))
        {
            Console.WriteLine($"  {keyName} = {configReader.GetValue(keyName, sectionName)}");
        }
    }
}
catch (FileNotFoundException ex)
{
    Console.WriteLine(ex.Message);
}

Simplified Reader (No Sections):

For scenarios without sections, a more streamlined approach using LINQ can be effective.

using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;

public class SimpleConfig
{
    private readonly Dictionary<string, string> _values;

    public SimpleConfig(string filePath)
    {
        _values = File.ReadLines(filePath)
            .Where(line => !string.IsNullOrWhiteSpace(line) && !line.StartsWith("#"))
            .Select(line => line.Split(new[] { '=' }, 2))
            .ToDictionary(parts => parts[0].Trim(), parts => parts.Length > 1 ? parts[1].Trim() : null);
    }

    public string GetValue(string name, string defaultValue = null)
    {
        return _values.TryGetValue(name, out var value) ? value : defaultValue;
    }
}

Usage Example:

var config = new SimpleConfig("appsettings.ini");
string command = config.GetValue("command");
string action = config.GetValue("action", "default_action.php");
bool debugMode = bool.Parse(config.GetValue("debug", "false"));

Solution 4: Using Microsoft.Extensions.Configuration

For modern .NET applications, particularly those built with ASP.NET Core, integrating INI files into the existing configuration system is a clean approach. This leverages the Microsoft.Extensions.Configuration.Ini package.

Usage Example in Startup.cs (or Program.cs for .NET 6+):

// In Program.cs (for .NET 6+):
var builder = Host.CreateDefaultBuilder(args);

builder.ConfigureAppConfiguration((context, config) =>
{
    config.AddIniFile("appsettings.ini", optional: true, reloadOnChange: true);
});

// ... rest of your application setup

You can then access the configuration values through the IConfiguration interface.

Alternative: XML or JSON Configuration

It’s worth reiterating that for new .NET projects, using XML or JSON for configuration is generally recommended due to their robust support within the framework, better type handling, and broader ecosystem integration. Libraries like System.Text.Json and Newtonsoft.Json (for JSON) and System.Xml.Serialization (for XML) provide built-in, powerful ways to serialize and deserialize configuration objects.

Which Method to Choose?

  • Windows-Specific Applications: P/Invoke (Solution 1) is efficient and native to Windows.
  • Cross-Platform or Ease of Use: Third-party NuGet packages (Solution 2) offer convenience and often better cross-platform support.
  • Maximum Control/Learning: Custom C# implementations (Solution 3) give you full control and are good for educational purposes.
  • Modern .NET Applications: Integrating with Microsoft.Extensions.Configuration (Solution 4) is the idiomatic way for ASP.NET Core and modern console apps.

FAQs on C#/.NET: How to Read and Write INI Files Efficiently

Q: What is the most straightforward way to read an INI file in C#

ANS: For a simple, section-less INI file, a custom LINQ-based reader like the SimpleConfig class shown in Solution 3 is quite straightforward. If you need section support and Windows native functionality, the P/Invoke approach in Solution 1 is also direct.

Q: How can I write to an INI file in C#

ANS: The P/Invoke method (Solution 1) and third-party libraries like INI Parser or PeanutButter.INI (Solution 2) provide direct methods for writing to INI files. Custom implementations can also include write methods by constructing the INI format and saving it to a file.

Q: Is there a built-in .NET way to handle INI files

ANS: No, the .NET framework does not have built-in classes specifically for reading or writing INI files. You need to use P/Invoke, third-party libraries, or custom parsing.

Q: What are the alternatives to INI files for configuration in .NET

ANS: For modern .NET applications, XML (System.Xml.Serialization) and JSON (System.Text.Json, Newtonsoft.Json) are the standard and recommended alternatives for configuration management.

Q: Can I use INI files in cross-platform .NET Core or .NET 5+ applications

ANS: Yes, you can use INI files in cross-platform .NET applications. Solutions that avoid Windows-specific P/Invoke calls, such as custom parsers or specific cross-platform NuGet packages, are suitable for this. Microsoft.Extensions.Configuration.Ini is also cross-platform.

Q: How do I handle comments in INI files with C#

ANS: When writing custom parsers, you typically check if a line starts with a designated comment character (like ‘;’ or ‘#’) and ignore it. Some third-party libraries also offer comment handling.

Q: What is the purpose of DllImport in C# for INI files

ANS: DllImport is used with P/Invoke to call functions from unmanaged code, specifically from Windows DLLs like kernel32.dll. For INI files, it allows C# applications to use the native Windows API functions (GetPrivateProfileString, WritePrivateProfileString) for direct interaction with INI files.
