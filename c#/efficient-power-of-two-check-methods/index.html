“Efficient Techniques to Determine if an Integer is a Power of Two”

How can one reliably and efficiently ascertain if a given numeric value, particularly an unsigned long (ulong) or similar integer type, represents a perfect power of two? Various programming paradigms offer distinct solutions, ranging from elegant bit manipulation tricks to mathematical logarithmic checks. What are the most effective and idiomatic ways to implement this check across different languages?

The Canonical Bitwise Approach: x & (x - 1)

The most frequently cited, highly optimized solution relies on the inherent properties of binary representation for powers of two.

A number $x$ is a power of two if and only if it has exactly one bit set to ‘1’ in its binary form (e.g., 4 is 100, 8 is 1000). Subtracting 1 from such a number flips that single ‘1’ bit to ‘0’ and sets all less significant bits to ‘1’ (e.g., $4-1=3$ is 011, $8-1=7$ is 0111).

When performing a bitwise AND (&) operation between $x$ and $(x-1)$, the result is zero if $x$ is a power of two because no ‘1’ bits align.

Initial Implementation (Includes Zero)

This first form is concise but returns true for the input $x=0$, which is generally not considered a power of two.

bool IsPowerOfTwoSimple(ulong x)
{
    // Returns true for x=0, which is often undesirable.
    return (x & (x - 1)) == 0;
}

Excluding Zero

To strictly enforce that the number must be positive, the check is augmented:

bool IsPowerOfTwoPositive(ulong x)
{
    // Ensures x is greater than zero AND satisfies the bitwise property.
    return (x != 0) && ((x & (x - 1)) == 0);
}

Illustrative Example (Using $x=4$):

If $x=4$ (100 in binary):

  1. $x-1 = 3$ (011 in binary).
  2. $4 & 3 \Rightarrow 100 & 011 = 000$ (which is $0$).
  3. The check (0 == 0) evaluates to true.

Alternative Bitwise Forms

Several variations exist that achieve the same result, often through different algebraic interpretations of the bitwise logic:

Variation A (Using Negation/Two’s Complement): This form leverages the property that for a power of two $x$, the expression x & (~x + 1) isolates the lowest set bit, which is $x$ itself.

int IsPowerOfTwoFast(uint x)
{
    // For x=4 (0100), ~x+1 is two's complement negation (-x).
    // (x & -x) == x
    return ((x != 0) && ((x & (~x + 1)) == x));
}

Variation B (Using Negation and Logical NOT): This is a compact form equivalent to the standard positive check:

bool IsPowerOfTwoCompact(ulong x)
{
    // Equivalent to x > 0 && (x & (x - 1)) == 0
    return (x != 0) && !(x & (x - 1));
}

Variation C (Using Bitwise AND with Negative): Observing the results of $x & (-x)$ in two’s complement arithmetic reveals that only powers of two yield the positive value of $x$ when ANDed with its negative counterpart.

// Java/C# interpretation for positive x
if ((x & -x) == x) {
    // x is a power of 2 (assuming x > 0)
}

Leveraging Built-in Functions (Modern Frameworks)

Modern language runtimes often provide intrinsic functions that map directly to CPU instructions (like POPCNT), offering superior performance for counting set bits.

In .NET 6+ (C#): The System.Numerics.BitOperations class is the preferred method.

using System.Numerics;

bool isPowerOfTwoBuiltIn(int value)
{
    // Highly optimized, uses hardware instructions if available.
    return BitOperations.IsPow2(value);
}

// Example usage:
// BitOperations.IsPow2(128) returns true

In C++ (Using std::bitset): Counting set bits is a straightforward implementation, though generally slower than direct bit manipulation unless optimized by the compiler.

#include <bitset>

bool IsPowerOfTwoBitset(unsigned int i)
{
    // Counts the number of set bits; true only if count is exactly 1.
    return std::bitset<32>(i).count() == 1;
}

Iterative and Mathematical Alternatives

While bitwise solutions are typically fastest, other methodologies exist.

Iterative Shifting Approach

This method repeatedly checks the least significant bit and right-shifts until the number becomes zero. If an odd number other than 1 is encountered, it’s not a power of two.

private static bool IsPowerOfTwoShift(ulong number)
{
    while (number != 0)
    {
        if (number == 1)
            return true;

        // If LSB is 1 and number isn't 1, it's odd and not a power of two.
        if ((number & 1) == 1)
            return false;

        number >>= 1; // Right shift by 1
    }
    return false;
}

Mathematical Logarithm Check

This approach involves calculating the base-2 logarithm. If the result is a perfect integer, the original number is a power of two. Caution: This method is susceptible to floating-point precision errors with very large numbers.

public static bool IsPowerOfTwoMath(ulong n)
{
    if (n == 0 || (n % 2 != 0)) return false;

    double exponent = Math.Log(n, 2);
    // Check if the computed exponent has zero fractional part.
    if (exponent != Math.Floor(exponent)) return false;
    
    return Math.Pow(2, exponent) == n;
}

Generalizing to Power of Base $b$

The concept can be extended to check if $n$ is a power of any base $b$ using repeated division:

bool IsPowerOfBase(int n, int b)
{
    if (n <= 1) return n == b; // Handle base cases like b=2, n=1 (2^0)

    while (n % b == 0)
    {
        n /= b;
    }
    return n == 1;
}

C++ Assembly Intrinsics

For extreme optimization, specific compiler intrinsics can be used, such as GCC/Clang built-in functions for finding the position of the least or most significant bit (if available).

// Using GCC/Clang built-ins (may require architecture-specific headers)
bool IsPowerOfTwoIntrinsic(unsigned int x)
{
    // Check if x > 0 and only one bit is set. __builtin_popcount returns the number of set bits.
    return (x != 0) && (__builtin_popcount(x) == 1);
}

Binary Property Exploration (Counting Set Bits Loop)

A technique related to Kernighan’s algorithm involves iteratively clearing the least significant bit until the number becomes zero, counting the steps. If the count is 1 (and the original number was positive), it’s a power of two.

int CountSetBits(int n)
{
    int c = 0;
    while(n > 0)
    {
        // This line clears the rightmost set bit
        n = n & (n - 1); 
        c++;
    }
    return c;
}

bool IsPowerOfTwoByCount(int n)
{        
    // Works correctly for n=0 (returns 0 set bits -> false)
    return (CountSetBits(n) == 1);
}

Advanced Two’s Complement Insight (Solution 11 basis)

The result of $x & (-x)$ isolates the lowest set bit. If $x$ is a power of two, this result equals $x$ itself (provided $x > 0$).

// Java example based on observations from Solution 11
boolean checkPower(int bound) {
    // If bound is positive, (bound & -bound) extracts the lowest set bit.
    // For a power of two, the lowest set bit is the number itself.
    return (bound > 0) && ((bound & -bound) == bound);
}

FAQs on Efficient Power Of Two Check Methods

Q: Does the standard bitwise check (x & (x - 1)) == 0 work for negative integers

ANS: The behavior with negative integers depends heavily on the language’s representation of signed integers (typically two’s complement). In many contexts where this trick is applied (like C++ or C# using unsigned types), negative inputs are undefined or result in unexpected behavior due to wrapping or interpretation of the sign bit. For correctness, positive checks (x > 0) are almost always required.

Q: Which method is generally considered the fastest way to check for power of two

ANS: The bitwise expression (x != 0) && ((x & (x - 1)) == 0) is historically the fastest portable method. However, modern CPUs often have dedicated instructions exposed via intrinsics (like PopCount or specific BitOperations.IsPow2), which can execute faster if the compiler targets them.

Q: Is the mathematical log method reliable for large 64-bit integers

ANS: No, the mathematical logarithm approach (Math.Log(n, 2)) is generally not reliable for large 64-bit integers due to inherent limitations and potential rounding errors in standard double-precision floating-point arithmetic. Bitwise operations are mandatory for robust large integer checks.

Q: Why does the accepted answer treat 0 as a power of two initially

ANS: The raw bitwise expression (x & (x - 1)) == 0 evaluates to true when $x=0$ because $0 & (-1)$ results in $0$. This is a mathematical artifact of the bit pattern manipulation, not a validation that 0 is $2^n$ for some non-negative integer $n$. Explicitly checking x != 0 rectifies this.
