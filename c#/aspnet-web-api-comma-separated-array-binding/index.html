Diverse Approaches for Array Parameter Binding in Web APIs

Developers have devised several distinct techniques to handle the automatic conversion of delimited string inputs into strongly-typed arrays or lists. The best approach often depends on the specific ASP.NET version and whether external tooling like Swagger integration is critical.

1. Utilizing the [FromUri] Attribute for Simple Arrays (Query String Style)

For basic array binding directly from the query string in older Web API versions, explicitly marking the parameter with [FromUri] can sometimes work if the client sends repeated keys.

Endpoint Design:

// Request Example: /Categories?categoryids=1&categoryids=2&categoryids=3
public IEnumerable<Category> GetCategories([FromUri] int[] categoryIds)
{
    // categoryIds will be {1, 2, 3}
    // ... implementation
}

2. Implementing a Custom IModelBinder

A highly customizable solution involves creating a class that implements IModelBinder. This binder explicitly looks for the incoming string value, splits it by a delimiter (like a comma), and converts each segment into the target array element type.

Custom Binder Implementation (CommaDelimitedArrayModelBinder):

This binder is configured to handle comma-separated values for array types.

public class CommaDelimitedArrayModelBinder : IModelBinder
{
    public bool BindModel(HttpActionContext actionContext, ModelBindingContext bindingContext)
    {
        var key = bindingContext.ModelName;
        var val = bindingContext.ValueProvider.GetValue(key);
        if (val == null) return false;

        var s = val.AttemptedValue;
        if (s != null)
        {
            var elementType = bindingContext.ModelType.GetElementType();
            var converter = TypeDescriptor.GetConverter(elementType);
            
            // Split by comma, trim whitespace, and convert each part
            var values = Array.ConvertAll(s.Split(new[] { ","}, StringSplitOptions.RemoveEmptyEntries),
                x => { 
                    return converter.ConvertFromString(x != null ? x.Trim() : x); 
                });

            var typedValues = Array.CreateInstance(elementType, values.Length);
            values.CopyTo(typedValues, 0);
            bindingContext.Model = typedValues;
        }
        else
        {
            // Assign an empty array if input is null/empty string
            bindingContext.Model = Array.CreateInstance(bindingContext.ModelType.GetElementType(), 0);
        }
        return true;
    }
}

Usage in Controller Action:

Apply the binder using the [ModelBinder] attribute. This setup allows requests like /Categories?categoryids=1,2,3,4.

public IEnumerable<Category> GetCategories([ModelBinder(typeof(CommaDelimitedArrayModelBinder))]long[] categoryIds) 
{
    // categoryIds is correctly populated from "1,2,3,4"
    // ...
}

3. Employing an ActionFilterAttribute for Route/Query Parsing

Another pattern involves using an ActionFilterAttribute to intercept the execution before the controller action runs. This filter manually extracts the delimited string from the route data or query string and injects the correctly parsed array into actionContext.ActionArguments.

Action Filter Implementation (ArrayInputAttribute):

public class ArrayInputAttribute : ActionFilterAttribute
{
    private readonly string _parameterName;

    public ArrayInputAttribute(string parameterName)
    {
        _parameterName = parameterName;
        Separator = ',';
    }

    public override void OnActionExecuting(HttpActionContext actionContext)
    {
        if (actionContext.ActionArguments.ContainsKey(_parameterName))
        {
            string parameters = string.Empty;
            // Check RouteData first, then QueryString
            if (actionContext.ControllerContext.RouteData.Values.ContainsKey(_parameterName))
                parameters = (string)actionContext.ControllerContext.RouteData.Values[_parameterName];
            else if (actionContext.ControllerContext.Request.RequestUri.ParseQueryString()[_parameterName] != null)
                parameters = actionContext.ControllerContext.Request.RequestUri.ParseQueryString()[_parameterName];

            // Parse and replace argument with an int array
            actionContext.ActionArguments[_parameterName] = parameters
                .Split(Separator)
                .Select(int.Parse)
                .ToArray();
        }
    }

    public char Separator { get; set; }
}

Usage Example (Route-Bound Array):

If the route is defined to capture the array directly (e.g., /api/Data/1;2;3;4), this filter handles the conversion.

// Request URI: /api/Data/1;2;3;4
[ArrayInput("id", Separator = ';')]
public IEnumerable<Measure> Get(int[] id)
{
    return id.Select(i => GetData(i));
}

4. Receiving Via [FromBody] with POST Requests

When array sizes are large or for operations better suited to POST (like deletions or complex filtering), sending the array directly in the request body as JSON is straightforward, especially when using [FromBody].

Controller (ASP.NET Web API):

public IHttpActionResult Remove([FromBody] int[] categoryIds)
{
    // categoryIds is bound from the JSON body
    // ...
}

Client-Side (jQuery AJAX Example): If using jQuery, $.param can format the data to resemble traditional form encoding, which works well if the body contains multiple values without a root key, but generally, sending standard JSON is preferred.

// Standard JSON Post Body: {"Categories": [1,2,3,4]}
$.ajax({
    type: 'POST',
    data: JSON.stringify({Categories: [1,2,3,4]}),
    contentType: 'application/json',
    url: '/api/categories/Remove',
    // ...
});

5. Using a Custom Type with TypeConverter (ASP.NET Web API)

Microsoft recommends using a TypeConverter for simpler integrations, especially for Swagger/OpenAPI documentation compatibility. You define a custom wrapper class for your list/array and provide a converter to handle the string-to-object transformation.

Custom Type and Converter:

[TypeConverter(typeof(StrListConverter))]
public class StrList : List<string>
{
    public StrList(IEnumerable<string> collection) : base(collection) {}
}

public class StrListConverter : TypeConverter
{
    public override bool CanConvertFrom(ITypeDescriptorContext context, Type sourceType)
    {
        return sourceType == typeof(string) || base.CanConvertFrom(context, sourceType);
    }

    public override object ConvertFrom(ITypeDescriptorContext context, CultureInfo culture, object value)
    {
        if (value is string s && !string.IsNullOrEmpty(s))
        {
            // Convert comma-separated string to StrList object
            return new StrList(s.Split(','));
        }
        return base.ConvertFrom(context, culture, value);
    }
}

Controller Usage:

The controller signature becomes very clean, as the framework uses the registered TypeConverter.

// Input URL: /Categories?categoryIds=val1,val2,val3
public IEnumerable<Category> GetCategories(StrList categoryIds) 
{
    // categoryIds is an instance of StrList containing the split values
    // You can then use categoryIds.Select(int.Parse) if T is int

6. ASP.NET Core Solution: Implementing IParsable<T> (.NET 8+)

For modern ASP.NET Core applications, utilizing the IParsable<T> interface offers a clean, generic, and framework-integrated way to handle string parsing for query parameters, which works excellently with [FromQuery].

Generic Parsable Collection Class:

// Requires System.Diagnostics.CodeAnalysis.NotNullWhen
public class CommaSeparatedList<T> : IParsable<CommaSeparatedList<T>> 
    where T : IParsable<T>
{
    public IEnumerable<T> Items { get; init; } = new List<T>();
    
    public CommaSeparatedList() { }

    private CommaSeparatedList(IEnumerable<T> items)
    {
        Items = items;
    }
    
    public static CommaSeparatedList<T> Parse(string value, IFormatProvider? provider)
    {
        if (!TryParse(value, provider, out var result))
        {
            throw new ArgumentException("Could not parse supplied value.", nameof(value));
        }
        return result;
    }

    public static bool TryParse([NotNullWhen(true)] string? value, IFormatProvider? provider, [MaybeNullWhen(false)] out CommaSeparatedList<T> result)
    {
        if (value == null)
        {
            result = new CommaSeparatedList<T>();
            return true;
        }
        
        string[] segments = value.Split(',', StringSplitOptions.RemoveEmptyEntries 
                                             | StringSplitOptions.TrimEntries);

        var items = new List<T>();
        var success = true;
        
        foreach (string segment in segments)
        {
            if (T.TryParse(segment, provider, out var parsedItem))
            {
                items.Add(parsedItem);
            }
            else
            {
                success = false;
            }
        }
        
        result = new CommaSeparatedList<T>(items);
        return success;
    }
}

Controller Usage (ASP.NET Core):

This approach simplifies the controller signature significantly for query parameters.

[HttpGet("")]
public ActionResult<MyEntity> GetEntities(
    [FromQuery] CommaSeparatedList<int> idsFilter,
    [FromQuery] CommaSeparatedList<string> namesFilter
)
{
    var idsToQuery = idsFilter.Items; // Access the underlying list/array
    // ...
    return Ok();
}
// Client request: /?idsFilter=10,20,30&namesFilter=Alpha,Beta

7. Simplest Option: Manual String Splitting in the Action

If complexity must be minimized and only GET requests are involved, accepting the array parameter as a raw string and manually splitting it inside the action method is the quickest path, although it bypasses model binding mechanisms.

Controller Action:

// Request URL: .../SomeHandler?idsString=123,456,789,012
public IActionResult SomeHandler(string idsString)
{
    if (!string.IsNullOrWhiteSpace(idsString))
    {
        var ids = idsString.Split(',')
                           .Select(x => long.Parse(x.Trim()))
                           .ToArray();

    }
    return Ok();
}

FAQs on ASPNET Web API Array Binding

Q: Which method works best for Swagger documentation in ASPNET Core

ANS: The approach using a custom generic type implementing IParsable<T> (Solution 6) integrates cleanly with Swashbuckle, allowing the query parameter to be documented as a single string field that expects comma-separated values.

Q: Can I use POST requests to send arrays in the body

ANS: Yes, using the [FromBody] attribute on an array or list parameter (int[] or List<int>) in a POST request is a reliable standard method for sending structured data arrays.

Q: How do I bind an array from the URI path segment like /api/items/1,2,3

ANS: This requires custom binding logic, such as an ActionFilterAttribute (Solution 3) or a specific IModelBinder (Solution 2), as standard routing often expects a single segment value.

Q: Is there a simple way to handle comma separated IDs in a GET request

ANS: The simplest direct approach is accepting the parameter as a string and splitting it inside the handler method (Solution 7).
