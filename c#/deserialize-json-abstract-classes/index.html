Deserialize JSON with Abstract Base Classes in C#

When working with JSON data in C#, particularly when dealing with inheritance hierarchies, you might encounter situations where a JSON array contains objects of different derived types, all stemming from a common abstract base class. Deserializing such structures directly can be challenging if the serializer doesn’t inherently know how to instantiate the correct derived type based on the JSON content. This post explores several robust methods for tackling this common problem using Newtonsoft.Json.

Consider a scenario where you have an abstract GalleryItem with derived types GalleryImage and GalleryAlbum, each represented in JSON.

public abstract class GalleryItem
{
    public string id { get; set; }
    public string title { get; set; }
    public string link { get; set; }
    public bool is_album { get; set; }
}

public class GalleryImage : GalleryItem
{
    // Additional properties specific to images
}

public class GalleryAlbum : GalleryItem
{
    public int images_count { get; set; }
    public List<GalleryImage> images { get; set; }
}

The JSON might look like this:

[
    {
        "id": "OUHDm",
        "title": "My most recent drawing. Spent over 100 hours.",
        "link": "http://i.imgur.com/OUHDm.jpg",
        "is_album": false
    },
    {
        "id": "lDRB2",
        "title": "Imgur Office",
        "link": "http://alanbox.imgur.com/a/lDRB2",
        "is_album": true,
        "images_count": 3,
        "images": [
            {
                "id": "24nLu",
                "link": "http://i.imgur.com/24nLu.jpg"
            },
            {
                "id": "Ziz25",
                "link": "http://i.imgur.com/Ziz25.jpg"
            },
            {
                "id": "9tzW6",
                "link": "http://i.imgur.com/9tzW6.jpg"
            }
        ]
    }
]

How can we effectively deserialize this into a List<GalleryItem> where each element is correctly instantiated as either a GalleryImage or GalleryAlbum?

Solution 1: Custom JsonConverter

A common and flexible approach is to create a custom JsonConverter. This converter will inspect the JSON data to determine the actual type of the object being deserialized.

using Newtonsoft.Json;
using Newtonsoft.Json.Linq;
using System;
using System.Collections.Generic;

public class GalleryItemConverter : JsonConverter
{
    public override bool CanConvert(Type objectType)
    {
        return typeof(GalleryItem).IsAssignableFrom(objectType);
    }

    public override object ReadJson(JsonReader reader,
        Type objectType, object existingValue, JsonSerializer serializer)
    {
        JObject jo = JObject.Load(reader);

        // Use nullable bool to safely handle missing "is_album"
        bool? isAlbum = (bool?)jo["is_album"];

        GalleryItem item;
        if (isAlbum.GetValueOrDefault())
        {
            item = new GalleryAlbum();
        }
        else
        {
            item = new GalleryImage();
        }

        // Populate the deserialized object with data from the JObject
        serializer.Populate(jo.CreateReader(), item);

        return item;
    }

    public override bool CanWrite
    {
        get { return false; } // This converter is only for reading
    }

    public override void WriteJson(JsonWriter writer,
        object value, JsonSerializer serializer)
    {
        throw new NotImplementedException("Json writing is not supported by this converter.");
    }
}

To use this converter:

    },

    }
    Console.WriteLine();
}

Solution 2: Using JsonSubtypes Attribute (with a Package)

An alternative, often more concise, method involves using a library that provides attributes to manage polymorphic deserialization. The JsonSubtypes package is a popular choice for this.

First, install the package: Install-Package JsonSubtypes

Then, annotate your base class:

using Newtonsoft.Json;
using JsonSubTypes; // Requires the JsonSubtypes package

[JsonConverter(typeof(JsonSubtypes), "is_album")] // Specify the discriminator property
[JsonSubtypes.KnownSubType(typeof(GalleryAlbum), true)]  // Map 'is_album: true' to GalleryAlbum
[JsonSubtypes.KnownSubType(typeof(GalleryImage), false)] // Map 'is_album: false' to GalleryImage
public abstract class GalleryItem
{
    public string id { get; set; }
    public string title { get; set; }
    public string link { get; set; }
    public bool is_album { get; set; }
}

public class GalleryImage : GalleryItem
{
    // ...
}

public class GalleryAlbum : GalleryItem
{
    public int images_count { get; set; }
    public List<GalleryImage> images { get; set; }
}

With these attributes, a standard JsonConvert.DeserializeObject call will work without needing a custom converter instance. This simplifies the deserialization code considerably.

Solution 3: Advanced Customization with Contract Resolver

In more complex scenarios, especially when dealing with types that have constructors or custom converters, you might need to influence how Newtonsoft.Json resolves contracts. Brian Rogers’ advice to use serializer.Populate() instead of item.ToObject() within a custom converter is key.

If you encounter issues where a base class converter is incorrectly applied to derived types, or when Newtonsoft.Json caches converters, you can extend DefaultContractResolver.

// Assuming DeterminedType is the actual derived type identified
var contract = serializer.ContractResolver.ResolveContract(DeterminedType);
if (converter != null && !typeDeserializer.Type.IsAbstract && converter.GetType() == GetType())
{
    // Prevent the base class converter from being used for derived types
    contract.Converter = null;
}

// Deserialize using the corrected contract
var jTokenReader = new JTokenReader(jObject);
var result = serializer.Deserialize(jTokenReader, DeterminedType);
return result;

This method is particularly useful for recursive structures or when specific derived types require distinct deserialization logic.

Solution 4: Type Property-Based Deserialization

Another pattern involves using a dedicated property in the JSON, often named “type” or similar, to indicate the object’s actual type.

public abstract class BaseClass
{
    // Map your derived types to their corresponding JSON 'type' values
    internal static readonly Dictionary<string, Type> TypesByName = new Dictionary<string, Type>
    {
        { "Subclass1", typeof(Subclass1) },
        { "Subclass2", typeof(Subclass2) },
        { "Subclass3", typeof(Subclass3) }
    };

    // Property to hold the type discriminator from JSON
    [JsonProperty("type", Required = Required.Always)]
    public string JsonObjectType { get; set; }

    public static BaseClass From(JObject obj, JsonSerializer serializer)
    {
        var typeName = (string)obj["type"];
        if (string.IsNullOrEmpty(typeName) || !TypesByName.TryGetValue(typeName, out var type))
        {
            throw new JsonSerializationException($"Unknown or missing type: {typeName}");
        }

        // Deserialize to the specific derived type
        return obj.ToObject(type, serializer) as BaseClass;
    }
}

public class Subclass1 : BaseClass { /* ... */ }
public class Subclass2 : BaseClass { /* ... */ }
public class Subclass3 : BaseClass { /* ... */ }

public class BaseClassConverter : JsonConverter
{
    public override bool CanConvert(Type objectType)
    {
        // Only convert for the base type, not derived ones
        return objectType == typeof(BaseClass);
    }

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        var jObject = JObject.Load(reader);
        return BaseClass.From(jObject, serializer);
    }

    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        serializer.Serialize(writer, value); // Default serialization for writing
    }
}

To deserialize, you’d configure the JsonSerializer with this custom converter:

public static BaseClass Deserialize(string json)
{
    var serializer = new JsonSerializer();
    serializer.Converters.Add(new BaseClassConverter());
    using (var stringReader = new StringReader(json))
    using (var jsonReader = new JsonTextReader(stringReader))
    {
        return serializer.Deserialize<BaseClass>(jsonReader);
    }
}

This pattern is robust when the JSON clearly indicates the type of each object.

Solution 5: Field-Based Type Resolution in Custom Converter

This approach refines the custom converter idea by directly inspecting a field (like is_album) for type determination, avoiding reliance on a specific “type” property. It manually maps JSON properties to the correct derived type.

public class GalleryImageConverter : JsonConverter
{
    public override bool CanConvert(Type objectType)
    {
        return objectType == typeof(GalleryImage) || objectType == typeof(GalleryAlbum);
    }

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        JObject jo = JObject.Load(reader);

        // Dynamically get the property name to avoid magic strings
        var isAlbumPropertyName = nameof(GalleryItem.is_album);
        JToken jt;
        if (!jo.TryGetValue(isAlbumPropertyName, StringComparison.InvariantCultureIgnoreCase, out jt))
        {
            // If 'is_album' is missing, assume it's a GalleryImage
            return jo.ToObject<GalleryImage>();
        }

        var propValue = jt.Value<bool>();
        Type resultType = propValue ? typeof(GalleryAlbum) : typeof(GalleryImage);

        var resultObject = Activator.CreateInstance(resultType);
        var objectProperties = resultType.GetProperties();

        foreach (var objectProperty in objectProperties)
        {
            var propType = objectProperty.PropertyType;
            var propName = objectProperty.Name;
            var token = jo.GetValue(propName, StringComparison.InvariantCultureIgnoreCase);
            if (token != null)
            {
                // Set the property value, handling potential nulls
                objectProperty.SetValue(resultObject, token.ToObject(propType) ?? objectProperty.GetValue(resultObject));
            }
        }
        return resultObject;
    }

    public override bool CanWrite => false; // Not supporting writing
    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }
}

This method offers granular control, mapping JSON fields to specific object properties, which is beneficial when JSON structures might vary slightly.

Solution 6: ContractResolver for Immutable Types with JsonConstructor

For scenarios involving immutable types or those with specific constructor requirements ([JsonConstructor]), Newtonsoft.Json’s caching mechanism for converters can be tricky. Overriding ResolveContractConverter in a custom DefaultContractResolver subclass is a robust strategy.

Consider these immutable DTOs representing a file system:

public enum DtoKind { None = 0, File, Directory }

public abstract class FileSystemDto
{
    protected FileSystemDto(string name, DtoKind kind)
    {
        Name = name ?? throw new ArgumentNullException(nameof(name));
        Kind = kind;
    }

    [JsonProperty("name")]
    public string Name { get; }
    [JsonProperty("kind")]
    public string Kind { get; }
}

public class FileDto : FileSystemDto
{
    [JsonConstructor]
    public FileDto(string name, long length, DtoKind kind)
        : base(name, kind)
    {
        if (kind != DtoKind.File) throw new InvalidOperationException("Incorrect kind for FileDto.");
        Length = length;
    }

    [JsonProperty("length")]
    public long Length { get; }
}

public class DirectoryDto : FileSystemDto
{
    [JsonConstructor]
    public DirectoryDto(string name, DtoKind kind)
        : base(name, kind)
    {
        if (kind != DtoKind.Directory) throw new InvalidOperationException("Incorrect kind for DirectoryDto.");
    }
}

The JSON data might be:

[
    { "name": "foo.txt", "kind": "File", "length": 12345 },
    { "name": "bar.txt", "kind": "File", "length": 12345 },
    { "name": "subdir", "kind": "Directory" }
]

Here’s how to handle it:

  1. Custom JsonConverter for the base type:

    public class MyJsonConverter : JsonConverter<FileSystemDto>
{
    public static MyJsonConverter Instance { get; } = new MyJsonConverter();
    private MyJsonConverter() { }

    public override FileSystemDto? ReadJson(JsonReader reader, Type objectType, FileSystemDto? existingValue, bool hasExistingValue, JsonSerializer serializer)
    {
        if (reader.TokenType == JsonToken.Null) return null;

        JObject jsonObject = JObject.Load(reader);
        var kindProperty = jsonObject.Property("kind")?.Value as JValue;
        var kindValue = kindProperty?.Value?.ToString();

        if (kindValue == "File")
        {
            return jsonObject.ToObject<FileDto>(serializer);
        }
        else if (kindValue == "Directory")
        {
            return jsonObject.ToObject<DirectoryDto>(serializer);
        }
        return null; // Or throw an exception
    }

    public override bool CanWrite => false; // Not writing
    public override void WriteJson(JsonWriter writer, FileSystemDto? value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }
}

  2. Custom DefaultContractResolver:

    public class MyContractResolver : DefaultContractResolver
{
    protected override JsonConverter? ResolveContractConverter(Type objectType)
    {
        if (objectType == typeof(FileSystemDto))
        {
            return MyJsonConverter.Instance;
        }
        // Let base handle derived types or other types
        return base.ResolveContractConverter(objectType);
    }
}

  3. Deserialization:

    public static IReadOnlyList<FileSystemDto> DeserializeFileSystemJsonArray(string json)
{
    var serializer = new JsonSerializer
    {
        ContractResolver = new MyContractResolver()
    };

    using (var strRdr = new StringReader(json))
    using (var jsonRdr = new JsonTextReader(strRdr))
    {
        var list = serializer.Deserialize<List<FileSystemDto>>(jsonRdr);
        return list ?? new List<FileSystemDto>(); // Return empty list if null
    }
}

This layered approach ensures that Newtonsoft.Json uses your custom converter for the base type, correctly directing deserialization to the specific derived types, even with constructor-specific attributes.

“Deserialize JSON with Abstract Base Classes in C#”

Q: How to deserialize JSON with an abstract base class and derived types in C#

ANS: Utilize custom JsonConverter implementations or attribute-based approaches like JsonSubtypes from the JsonSubtypes NuGet package. You can also extend DefaultContractResolver for more complex scenarios.

Q: What is the role of a JsonConverter in polymorphic deserialization

ANS: A JsonConverter allows you to intercept the deserialization process. You can inspect the incoming JSON to determine the specific derived type that should be instantiated, overriding the serializer’s default behavior.

Q: Can I use attributes to handle polymorphic JSON deserialization

ANS: Yes, libraries like JsonSubtypes provide attributes such as [JsonConverter(typeof(JsonSubtypes))] and [JsonSubtypes.KnownSubType] which simplify the process by mapping discriminator properties in the JSON to specific C# types.

Q: When should I use a custom DefaultContractResolver

ANS: A custom DefaultContractResolver is useful when you need to globally influence how types are resolved, particularly with immutable types, constructor-specific deserialization, or when managing converter caching and application for base versus derived types.

Q: How do I handle JSON where the type is specified by a property like 'kind' or 'type'

ANS: Implement a JsonConverter or a custom DefaultContractResolver that reads a designated property (e.g., “kind”, “type”) from the JSON object to identify the target derived type and then deserializes accordingly.
