“C# LINQ Techniques for Removing Duplicates from Collections”

When working with object collections in C#, eliminating duplicate entries based on specific criteria or full object equality is a frequent requirement. Language Integrated Query (LINQ) offers several powerful mechanisms to tackle this challenge. How can one efficiently isolate unique items from a list, especially when uniqueness depends on only a subset of properties?

Several proven approaches exist, ranging from simple Distinct() calls to implementing custom comparison logic.

Method 1: Grouping and Selecting the First Instance

A straightforward technique to obtain unique elements based on a single property, such as an Id, involves using the GroupBy operator followed by selecting the first item from each group.

If you possess a collection named items:

// Retrieve distinct items based solely on the 'Id' property
var distinctItemsById = items.GroupBy(item => item.Id)
                             .Select(group => group.First());

This pattern is also adaptable when grouping by a different field, like title:

var collection = GetMyCollection(); // Assume this returns a collection of objects
var uniqueByTitle = collection.GroupBy(x => x.title)
                              .Select(y => y.FirstOrDefault());

Method 2: Using the Standard Distinct() Operator

The simplest approach, Distinct(), relies on the default equality comparison for the object type. If the Item class implements IEquatable<T> or overrides Equals and GetHashCode, Distinct() will work out-of-the-box based on full object identity.

If you are not overriding these methods, Distinct() will only remove objects that are exactly the same instance or have matching values across all public properties if the type is a struct or anonymous type.

Method 3: Custom Comparison via IEqualityComparer<T>

To define uniqueness based only on a specific set of properties without altering the base class definition, you can supply a custom IEqualityComparer<T> to the Distinct method.

Consider an Item class where you want duplicates defined by the combination of Id, Name, Code, and Price.

Implementing the Custom Comparer

public class DistinctItemComparer : IEqualityComparer<Item>
{
    public bool Equals(Item x, Item y)
    {
        if (x == null || y == null) return false;

        return x.Id == y.Id &&
               x.Name == y.Name &&
               x.Code == y.Code &&
               x.Price == y.Price;
    }

    public int GetHashCode(Item obj)
    {
        if (obj == null) return 0;
        // Combine hash codes for required properties
        return obj.Id.GetHashCode() ^
               obj.Name.GetHashCode() ^
               obj.Code.GetHashCode() ^
               obj.Price.GetHashCode();
    }
}

Applying the Comparer

Use the custom comparer with Distinct():

var distinctItemsByProperties = items.Distinct(new DistinctItemComparer());

Method 4: Leveraging External Libraries or Custom DistinctBy Extensions

For developers seeking a more concise syntax similar to GroupBy().Select(First()) but integrated directly into the Distinct call, the DistinctBy operator is highly valuable. While this is natively available in modern .NET versions (like .NET 6+), prior versions often required external libraries (like MoreLINQ) or custom extension methods.

Using MoreLINQ’s DistinctBy (If external dependencies are permissible)

If you are working with a project where you can incorporate external packages, MoreLinq offers DistinctBy:

// Assuming MoreLinq is referenced
var distinctResults = items.DistinctBy(i => i.Id);

Creating a Universal Extension Method for DistinctBy

You can implement your own efficient extension method that achieves the DistinctBy behavior using a HashSet internally for tracking keys:

public static class EnumerableExtensions
{
    public static IEnumerable<TSource> CustomDistinctBy<TSource, TKey>(
        this IEnumerable<TSource> source, 
        Func<TSource, TKey> keySelector)
    {
        var identifiedKeys = new HashSet<TKey>();
        // HashSet.Add returns true only if the element was new
        return source.Where(element => identifiedKeys.Add(keySelector(element)));
    }
}

Usage of this custom helper:

var outputList = sourceList.CustomDistinctBy(x => x.TargetProperty);

Method 5: Refining GroupBy for Strict Equality

A common pitfall with Method 1 is revealed when duplicate items differ in fields not used for grouping. If you group only by Id, two items with the same Id but different supplementary data will still result in distinct entries after the Select(First()) if the structure of the group selection isn’t careful.

For precise duplicate removal across all relevant fields using GroupBy, the key selector must encompass all discriminating properties:

List<Item> a = new List<Item>
{
    new Item {Id = 1, Name = "Item1", Code = "IT00001", Price = 100},
    new Item {Id = 3, Name = "Item3", Code = "IT00003", Price = 150},
    new Item {Id = 3, Name = "Item3", Code = "IT00004", Price = 250} // Different Price/Code
};

// This correctly identifies the Id=3 entries as distinct due to property variance
var fullyDistinctItems = a.GroupBy(c => new { c.Id, c.Name, c.Code, c.Price })
                          .Select(c => c.First())
                          .ToList();

Method 6: Overriding Equals and GetHashCode in the Class

For cases where the object’s intrinsic definition of equality should always reflect the complete set of properties, override Equals and GetHashCode directly within the Item class. Once this is done, the simple call to items.Distinct() will suffice.

public class Item
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Code { get; set; }
    public int Price { get; set; }

    public override bool Equals(object obj)
    {
        if (obj is Item p)
        {
            return (p.Id == Id && p.Name == Name && p.Code == Code && p.Price == Price);
        }
        return false;
    }

    public override int GetHashCode()
    {
        // A robust way to combine hashes for multiple fields
        return HashCode.Combine(Id, Name, Code, Price);
    }
}

// Usage:
var distinctItems = a.Distinct();

Method 7: Projection to Anonymous Type for Simplicity

If the original list objects are complex and you only need uniqueness based on a small subset of properties (e.g., Id and Name), projecting to an anonymous type before calling Distinct() is a quick fix that avoids custom comparers or class modifications.

// Example data setup
var items = new List<Item>
{
    new Item {Id = 1, Name = "Apple"},
    new Item {Id = 2, Name = "Banana"},
    new Item {Id = 1, Name = "Apple"} // Duplicate Id and Name
};

// 1. Project to anonymous type containing only required keys
// 2. Call Distinct() (anonymous types have correct Equals/GetHashCode implemented)
// 3. Project back to the original Item structure if needed
var uniqueProjections = items.Select(i => new { i.Id, i.Name })
                             .Distinct()
                             .Select(x => new Item { Id = x.Id, Name = x.Name })
                             .ToList();

Method 8: Using Except with Grouped Defaults

While less conventional for simple deduplication, one method involves finding all elements that should be kept (the first instance of each group) and then using Except against the original list. This is more often seen when trying to isolate the actual duplicates rather than the distinct set.

If the goal is to find items that are not the first occurrence based on Name:

List<Employee> employees = /* ... data initialized ... */;

// Select the first employee for every unique Name
var firstOccurrences = employees.GroupBy(i => i.Name)
                                .Select(ss => ss.FirstOrDefault());

// This results in the list of items *not* present in the firstOccurrences set
List<Employee> duplicateEmployees = employees.Except(firstOccurrences).ToList();

Method 9: Deduplication within XML Processing

When dealing with non-standard collections, such as XElement collections derived from XML documents, the principle remains the same: isolate the discriminating attribute or content, apply Distinct(), and then process the remaining elements.

For an XML list (MList) filtered by GRADE="DDR4", if we wish to find unique SPD values:

IEnumerable<XElement> MList = PREF.Descendants("MEMDES")
    .Where(RAMList => (string)RAMList.Attribute("GRADE") == "DDR4");

List<string> uniqueSpds = new List<string>();

foreach (var MEMList in MList)
{
    uniqueSpds.Add((string)MEMList.Attribute("SPD").Value);
}

// Use Distinct on the resulting list of strings
foreach (string slist in uniqueSpds.Distinct())
{
    comboBox1.Items.Add(slist); // Populate UI element
}

FAQs on CSharp LINQ Techniques for Removing Duplicates

Q: How do I remove duplicates based on just one property like Id

ANS: Use the GroupBy operator targeting that property and then select the first element of each resulting group: items.GroupBy(x => x.Id).Select(y => y.First())

Q: What is required for the basic Distinct method to function correctly

ANS: The basic Distinct() relies on the default equality check for the object. You must override Equals and GetHashCode in your class, or the objects must be simple value types or anonymous types where equality is naturally defined across all fields.

Q: Can I avoid modifying the class definition when using complex equality rules

ANS: Yes, you can create a separate class implementing IEqualityComparer<T> and pass an instance of it to the Distinct(comparer) method.

Q: What is the benefit of using a custom DistinctBy extension method over GroupBy Select First

ANS: A custom DistinctBy implementation, often utilizing a HashSet, can sometimes be more performant and is generally syntactically cleaner than chaining GroupBy().Select() when the sole objective is to filter based on a key selector.
