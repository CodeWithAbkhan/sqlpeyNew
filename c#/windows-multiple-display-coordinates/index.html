“Windows Multiple Display Coordinates How to Work With Them”

Working with multiple monitors in a Windows environment presents unique challenges regarding how screen positions and resolutions are calculated and presented to your applications. Understanding these mechanics is crucial for correctly positioning windows, handling UI scaling, and interacting with display-specific functionalities.

When dealing with multiple displays, Windows establishes a concept of a Primary Screen, which is the reference point for all other displays. Programmatically, the primary screen is defined as the display with its upper-left corner at Point(0,0). Displays positioned to the left of this primary screen will have negative X-coordinates, while those to the right will have positive X-coordinates. The Y-coordinate can also become negative for displays in a portrait orientation.

The Virtual Screen encompasses the entire area of all connected displays. Its origin is the left-most screen’s coordinate, and its width is the sum of all screen widths. The height of the virtual screen is determined by the tallest display. SystemInformation.VirtualScreen provides these overall dimensions, while SystemInformation.PrimaryMonitorSize offers the primary screen’s dimensions. You can access detailed information about each connected display using Screen.AllScreens and inspecting individual \\.\DISPLAY[N] properties.

Understanding Display Positioning

  • Displays Left of Primary: These screens have a negative Point.X origin. The Point.X origin for these displays is calculated by summing the widths of all preceding screens and subtracting this sum from the primary screen’s origin.
  • Displays Right of Primary: These screens have a positive Point.X origin. Their Point.X origin is the sum of the primary screen’s width and the widths of all preceding screens to its right, added to the primary screen’s origin Point.X coordinate.

The Impact of DPI Awareness

DPI (Dots Per Inch) awareness significantly influences how screen measurements are interpreted. An application that is not DPI Aware will have its measurements virtualized and scaled by the system to a default of 96 DPI. This means your application receives scaled values from Win32 API functions.

To ensure correct behavior across different display scaling settings, it’s vital to configure your application’s DPI awareness:

  • .NET Framework prior to 4.7.2: Modify the app.manifest file by uncommenting the DpiAware and DpiAwareness sections.
  • .NET Framework 4.7.2 and later: The PerMonitorV2 DPI Awareness mode can be specified in the app.config file for applications running on Windows 10 Creators Edition and later.
  • .NET 6 and later: Update the project file (.csproj) by adding or editing the <ApplicationHighDpiMode> property. For example: 
    <PropertyGroup>
  <ApplicationHighDpiMode>PerMonitorV2</ApplicationHighDpiMode>
</PropertyGroup>
    In this scenario, the app.manifest is primarily used to declare system version support, and app.config is not utilized for DPI settings.

Refer to High DPI Desktop Application Development on Windows for more detailed information. Also, explore DPI and Device-Independent Pixels for a deeper dive into scaling concepts.

Locating a Window within a Display Area

The Screen class in .NET provides several methods to identify which screen a specific window resides on:

  • Screen.FromControl(Control): Returns the Screen object that contains the largest portion of the given control.
  • Screen.FromHandle(IntPtr): Returns the Screen object for the window referenced by its handle.
  • Screen.FromPoint(Point): Identifies the Screen object containing a specific point.
  • Screen.FromRectangle(Rectangle): Returns the Screen object that encloses the largest area of a specified rectangle.
  • Screen.GetBounds(object): Returns a Rectangle structure representing the screen bounds that contain a specific point, rectangle, or control.

To determine the current display of your application’s main form, you can use:

Screen currentScreen = Screen.FromHandle(this.Handle);
// currentScreen.DeviceName will provide the \\.\DISPLAY[N] identifier

For a secondary form, say Form2, positioned at (-1400, 100):

var f2 = new Form2();
f2.Location = new Point(-1400, 100);
f2.Show();
Rectangle screenSize = Screen.GetBounds(f2);
Screen screen = Screen.FromHandle(f2.Handle);
// 'screen' object will represent the properties of the display \\.\DISPLAY3
// 'screenSize' will be equal to the Bounds of \\.\DISPLAY3

Obtaining Monitor Handles and Device Contexts

You can retrieve the hMonitor handle for a Screen object using its GetHashCode() method, which internally calls native Win32 functions. Alternatively, you can directly utilize Win32 API calls like MonitorFromWindow, MonitorFromPoint, and MonitorFromRect.

using System.Runtime.InteropServices;

// ...

// Example of using MonitorFromWindow
[DllImport("User32.dll", SetLastError = true)]
internal static extern IntPtr MonitorFromWindow(IntPtr hwnd, MONITOR_DEFAULTTO dwFlags);

[Flags]
internal enum MONITOR_DEFAULTTO
{
    NULL = 0x00000000,
    PRIMARY = 0x00000001,
    NEAREST = 0x00000002,
}

// ...

// To get the hMonitor for the current form
IntPtr monitorHwnd = MonitorFromWindow(this.Handle, MONITOR_DEFAULTTO.NEAREST);

To draw directly onto a specific screen, you need its device context (hDC). This can be obtained using the CreateDC function from gdi32.dll, where the lpszDriver parameter is the Screen.DeviceName.

using System;
using System.Drawing;
using System.Runtime.InteropServices;

public static class ScreenDrawingHelper
{
    [DllImport("gdi32.dll", SetLastError = true, CharSet = CharSet.Auto)]
    private static extern IntPtr CreateDC(string lpszDriver, string lpszDevice, string lpszOutput, IntPtr lpInitData);

    [DllImport("gdi32.dll", SetLastError = true, EntryPoint = "DeleteDC")]
    private static extern bool DeleteDC([In] IntPtr hdc);

    public static IntPtr CreateDCFromDeviceName(string deviceName)
    {
        return CreateDC(deviceName, null, null, IntPtr.Zero);
    }

    // Example to draw on two screens
    public static void DrawOnScreens()
    {
        Screen[] screens = Screen.AllScreens;
        if (screens.Length < 2) return;

        IntPtr screenDC1 = IntPtr.Zero;
        IntPtr screenDC2 = IntPtr.Zero;

        try
        {
            screenDC1 = CreateDCFromDeviceName(screens[0].DeviceName);
            screenDC2 = CreateDCFromDeviceName(screens[1].DeviceName);

            using (Graphics g1 = Graphics.FromHdc(screenDC1))
            using (Graphics g2 = Graphics.FromHdc(screenDC2))
            using (Pen pen = new Pen(Color.Blue, 5))
            {
                g1.DrawEllipse(pen, new Rectangle(new Point(50, 50), new Size(150, 150)));
                g2.DrawEllipse(pen, new Rectangle(new Point(50, 50), new Size(150, 150)));
            }
        }
        finally
        {
            if (screenDC1 != IntPtr.Zero) DeleteDC(screenDC1);
            if (screenDC2 != IntPtr.Zero) DeleteDC(screenDC2);
        }
    }
}

For detailed information on the MONITORINFOEXW structure and other Win32 API interactions, you might need to consult the Windows API documentation.

Example Scenario

Consider a setup with three monitors:

  • PrimaryScreen (\\.\DISPLAY1): Width: 1920 x 1080
    • Bounds: (0, 0, 1920, 1080) | Left: 0 | Right: 1920 | Top: 0 | Bottom: 1080
  • Secondary Display (Right, \\.\DISPLAY2): Width: 1360 x 768
    • Bounds: (1360, 0, 1360, 768) | Left: 1360 | Right: 2720 | Top: 0 | Bottom: 768
  • Secondary Display (Left, \\.\DISPLAY3): Width: 1680 x 1050
    • Bounds: (-1680, 0, 1680, 1050) | Left: -1680 | Right: 0 | Top: 0 | Bottom: 1050

In this configuration, the Virtual Screen bounds are: (-1680, 0, 3280, 1080) (Left: -1680, Right: 3280, Top: 0, Bottom: 1080).

If the primary screen is switched to \\.\DISPLAY3, the coordinate system recalibrates accordingly.

FAQs on Windows Multiple Display Coordinates

Q What is the primary screen in Windows

ANS The primary screen is the display designated as the main monitor, with its top-left corner typically at coordinates (0,0). All other displays are positioned relative to this primary screen.

Q How are coordinates calculated for screens to the left of the primary display

ANS Screens positioned to the left of the primary display have negative X-coordinates. Their origin’s X value is determined by subtracting the combined widths of all preceding screens from the primary screen’s X origin.

Q How does DPI awareness affect display measurements

ANS If an application is not DPI aware, the system scales all display measurements to a default of 96 DPI, potentially compromising accuracy. Configuring DPI awareness ensures your application receives correct scaled values.

Q What is the virtual screen in Windows

ANS The virtual screen represents the combined area of all connected displays. Its origin is the top-left corner of the left-most screen, and its width is the sum of all display widths.

Q How can I determine which screen a window is on

ANS You can use methods like Screen.FromHandle(windowHandle), Screen.FromPoint(point), or Screen.FromRectangle(rectangle) from the .NET System.Windows.Forms.Screen class.
