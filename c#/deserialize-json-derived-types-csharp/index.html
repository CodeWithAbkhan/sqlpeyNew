“Deserialize JSON to Specific Derived Types with C#”

Dynamic JSON Type Resolution in C#

The core challenge lies in determining the correct derived type to instantiate for each JSON object during deserialization. This typically involves inspecting the JSON content to identify distinguishing features.

Solution 1: Custom JsonCreationConverter

A common and effective method is to create a custom JsonConverter that subclasses JsonCreationConverter<T>. This approach allows you to define logic within the Create method to instantiate the appropriate derived type based on the presence or values of specific JSON properties.

The ReadJson method within this custom converter loads the JSON as a JObject. This JObject is then passed to your custom Create method. Inside Create, you can analyze the JObject to make an informed decision about which derived class to return.

Custom Converter Implementation:

public abstract class JsonCreationConverter<T> : JsonConverter
{
    protected abstract T Create(Type objectType, JObject jObject);

    public override bool CanConvert(Type objectType)
    {
        return typeof(T).IsAssignableFrom(objectType);
    }

    public override bool CanWrite => false;

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        if (reader.TokenType == JsonToken.Null)
            return null;

        JObject jObject = JObject.Load(reader);
        T target = Create(objectType, jObject);
        
        // Utilize a helper to copy reader settings for accurate deserialization
        using (JsonReader jObjectReader = CopyReaderForObject(reader, jObject))
        {
            serializer.Populate(jObjectReader, target);
        }
        return target;
    }

    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }

    /// <summary>Creates a new reader for the specified jObject by copying the settings
    /// from an existing reader.</summary>
    /// <param name="reader">The reader whose settings should be copied.</param>
    /// <param name="jToken">The jToken to create a new reader for.</param>
    /// <returns>The new disposable reader.</returns>
    public static JsonReader CopyReaderForObject(JsonReader reader, JToken jToken)
    {
        JsonReader jTokenReader = jToken.CreateReader();
        jObjectReader.Culture = reader.Culture;
        jObjectReader.DateFormatString = reader.DateFormatString;
        jObjectReader.DateParseHandling = reader.DateParseHandling;
        jObjectReader.DateTimeZoneHandling = reader.DateTimeZoneHandling;
        jObjectReader.FloatParseHandling = reader.FloatParseHandling;
        jObjectReader.MaxDepth = reader.MaxDepth;
        jObjectReader.SupportMultipleContent = reader.SupportMultipleContent;
        return jTokenReader;
    }
}

public class PersonConverter : JsonCreationConverter<Person>
{
    protected override Person Create(Type objectType, JObject jObject)
    {
        if (FieldExists("Skill", jObject))
        {
            return new Artist();
        }
        else if (FieldExists("Department", jObject))
        {
            return new Employee();
        }
        else
        {
            return new Person();
        }
    }

    private bool FieldExists(string fieldName, JObject jObject)
    {
        return jObject[fieldName] != null;
    }
}

Solution 2: Enhancing JsonCreationConverter with Reader Settings

A refinement on Solution 1 addresses a potential issue where the JsonReader created within ReadJson might not inherit the original reader’s configuration values (like Culture, DateParseHandling, etc.). This can lead to unexpected behavior in certain scenarios. The improved version ensures these settings are copied.

Updated ReadJson within JsonCreationConverter:

public override object ReadJson(JsonReader reader,
                                Type objectType,
                                object existingValue,
                                JsonSerializer serializer)
{
    if (reader.TokenType == JsonToken.Null)
        return null;
    JObject jObject = JObject.Load(reader);
    T target = Create(objectType, jObject);

    using (JsonReader jObjectReader = CopyReaderForObject(reader, jObject))
    {
        serializer.Populate(jObjectReader, target);
    }
    return target;
}

Solution 3: Using the KnownType Attribute and Reflection

Leveraging the [KnownType] attribute from System.Runtime.Serialization combined with reflection offers another structured way to handle type discrimination. This approach is particularly useful when you have a clear hierarchy and can annotate your base class with the possible derived types.

Example Usage:

[KnownType(typeof(B))]
public class A
{
   public string Name { get; set; }
}

public class B : A
{
   public string LastName { get; set; }
}

// Deserialize using a custom converter that checks KnownType attributes
string json = "{ Name:\"Something\", LastName:\"Otherthing\" }";
var ret = JsonConvert.DeserializeObject<A>(json, new KnownTypeConverter());

Converter Code:

public class KnownTypeConverter : JsonConverter
{
    public override bool CanConvert(Type objectType)
    {
        return System.Attribute.GetCustomAttributes(objectType).Any(v => v is KnownTypeAttribute);
    }

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        JObject jObject = JObject.Load(reader);
        Attribute[] attrs = System.Attribute.GetCustomAttributes(objectType);

        foreach (var attr in attrs.OfType<KnownTypeAttribute>())
        {
            var props = attr.Type.GetProperties();
            bool found = true;
            foreach (var f in jObject)
            {
                if (!props.Any(z => z.Name == f.Key))
                {
                    found = false;
                    break;
                }
            }

            if (found)
            {
                var target = Activator.CreateInstance(attr.Type);
                serializer.Populate(jObject.CreateReader(), target);
                return target;
            }
        }
        throw new SerializationException("ObjectNotFoundException");
    }

    public override bool CanWrite => false;
    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }
}

Solution 5: Enhanced KnownTypeConverter for Property Matching

This solution builds upon the KnownType attribute concept but refines the property matching logic. It ensures that deserialization accurately reflects JSON properties, even when dealing with [JsonProperty] attributes or casing variations like CamelCasePropertyNamesContractResolver.

The core idea is to match JSON keys against the properties of potential derived types, considering JsonProperty mappings.

Converter Logic:

public class KnownTypeConverter : JsonConverter
{
    public override bool CanConvert(Type objectType)
    {
        return System.Attribute.GetCustomAttributes(objectType).Any(v => v is KnownTypeAttribute);
    }

    public override bool CanWrite => false;

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        JObject jObject = JObject.Load(reader);
        Attribute[] attrs = Attribute.GetCustomAttributes(objectType);

        Type mostSuitableType = null;
        int maxMatchingProperties = -1;

        HashSet<string> jObjectKeys = GetKeys(jObject);
        HashSet<string> objectTypeProps = objectType.GetProperties(BindingFlags.Instance | BindingFlags.Public)
            .Select(p => p.Name)
            .ToHashSet();

        foreach (var attr in attrs.OfType<KnownTypeAttribute>())
        {
            Type knownType = attr.Type;
            if (!objectType.IsAssignableFrom(knownType)) continue;

            var jsonNameFields = knownType.GetProperties(BindingFlags.Instance | BindingFlags.Public)
                .Where(p => !objectTypeProps.Contains(p.Name) && p.CustomAttributes.All(a => a.AttributeType != typeof(JsonIgnoreAttribute)))
                .Select(prop => GetJsonPropertyName(prop));

            HashSet<string> jKnownTypeKeys = new HashSet<string>(jsonNameFields);
            int count = jObjectKeys.Intersect(jKnownTypeKeys).Count();

            if (count == jKnownTypeKeys.Count)
            {
                mostSuitableType = knownType;
                break;
            }

            if (count > maxMatchingProperties)
            {
                maxMatchingProperties = count;
                mostSuitableType = knownType;
            }
        }

        if (mostSuitableType != null)
        {
            object target = Activator.CreateInstance(mostSuitableType);
            using (JsonReader jObjectReader = CopyReaderForObject(reader, jObject))
            {
                serializer.Populate(jObjectReader, target);
            }
            return target;
        }

        throw new SerializationException($"Could not serialize to KnownTypes for {objectType}");
    }

    private string GetJsonPropertyName(PropertyInfo prop)
    {
        var jsonPropertyAttribute = prop.CustomAttributes.FirstOrDefault(a => a.AttributeType == typeof(JsonPropertyAttribute));
        if (jsonPropertyAttribute != null)
        {
            var argument = jsonPropertyAttribute.ConstructorArguments.FirstOrDefault();
            if (argument != null && argument.ArgumentType == typeof(string) && !string.IsNullOrEmpty((string)argument.Value))
                return (string)argument.Value;
        }
        return prop.Name;
    }

    private HashSet<string> GetKeys(JObject obj)
    {
        return new HashSet<string>(obj.Properties().Select(k => k.Name));
    }

    public static JsonReader CopyReaderForObject(JsonReader reader, JObject jObject)
    {
        JsonReader jObjectReader = jObject.CreateReader();
        // Copy relevant reader settings
        jObjectReader.Culture = reader.Culture;
        jObjectReader.DateFormatString = reader.DateFormatString;
        jObjectReader.DateParseHandling = reader.DateParseHandling;
        jObjectReader.DateTimeZoneHandling = reader.DateTimeZoneHandling;
        jObjectReader.FloatParseHandling = reader.FloatParseHandling;
        jObjectReader.MaxDepth = reader.MaxDepth;
        jObjectReader.SupportMultipleContent = reader.SupportMultipleContent;
        return jObjectReader;
    }

    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }
}

Solution 6: Generic Type Resolution with Assembly Scanning

This approach offers a flexible way to resolve types without relying on KnownType attributes. It scans referenced assemblies to discover potential implementations for abstract classes or interfaces. A $type property in the JSON can explicitly specify the type.

Converter:

public class JsonKnownTypeConverter : JsonConverter
{
    public IEnumerable<Type> KnownTypes { get; set; }

    public JsonKnownTypeConverter() : this(ReflectTypes()) { }

    public JsonKnownTypeConverter(IEnumerable<Type> knownTypes)
    {
        KnownTypes = knownTypes;
    }

    protected object Create(Type objectType, JObject jObject)
    {
        if (jObject["$type"] != null)
        {
            string typeName = jObject["$type"].ToString();
            return Activator.CreateInstance(KnownTypes.First(x => typeName == x.Name));
        }
        else
        {
            return Activator.CreateInstance(objectType);
        }
    }

    public override bool CanConvert(Type objectType)
    {
        if (KnownTypes == null) return false;
        return (objectType.IsInterface || objectType.IsAbstract) && KnownTypes.Any(objectType.IsAssignableFrom);
    }

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        JObject jObject = JObject.Load(reader);
        var target = Create(objectType, jObject);
        serializer.Populate(jObject.CreateReader(), target);
        return target;
    }

    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        throw new NotImplementedException();
    }

    // Static helpers for assembly scanning
    static Assembly CallingAssembly = Assembly.GetCallingAssembly();

    static Type[] ReflectTypes()
    {
        List<Type> types = new List<Type>();
        var referencedAssemblies = Assembly.GetExecutingAssembly().GetReferencedAssemblies();
        foreach (var assemblyName in referencedAssemblies)
        {
            Assembly assembly = Assembly.Load(assemblyName);
            types.AddRange(GetTypes(assembly));
        }
        return types.ToArray();
    }

    static Type[] GetTypes(Assembly assembly, bool publicOnly = true)
    {
        return assembly.GetTypes().Where(type =>
            !type.IsEnum && !type.IsInterface && !type.IsGenericTypeDefinition &&
            (!publicOnly || type.IsPublic || (type.IsNested && !type.IsNestedPrivate))
        ).ToArray();
    }
}

Usage:

GlobalConfiguration.Configuration.Formatters.JsonFormatter.SerializerSettings.Converters.Add(new JsonKnownTypeConverter());

Solution 7: Interface-Based Conversion

This approach focuses on deserializing to interfaces, inferring the concrete implementation. It can handle both single objects and collections of interfaces.

Converter:

public class InterfaceConverter : JsonConverter
{
    public override bool CanWrite => false;
    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer) { }

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        var token = JToken.ReadFrom(reader);
        var typeVariable = GetTypeVariable(token);
        Type implementation;

        if (TypeExtensions.TryParse(typeVariable, out implementation)) { }
        else if (!typeof(IEnumerable).IsAssignableFrom(objectType))
        {
            implementation = GetImplimentedType(objectType);
        }
        else
        {
            var genericArgumentTypes = objectType.GetGenericArguments();
            var innerType = genericArgumentTypes.FirstOrDefault();
            if (innerType == null)
            {
                implementation = typeof(IEnumerable);
            }
            else
            {
                Type genericType = null;
                if (token.HasAny())
                {
                    var firstItem = token[0];
                    var genericTypeVariable = GetTypeVariable(firstItem);
                    TypeExtensions.TryParse(genericTypeVariable, out genericType);
                }
                genericType = genericType ?? GetImplimentedType(innerType);
                implementation = typeof(IEnumerable<>).MakeGenericType(genericType);
            }
        }
        return JsonConvert.DeserializeObject(token.ToString(), implementation);
    }

    public override bool CanConvert(Type objectType)
    {
        return !typeof(IEnumerable).IsAssignableFrom(objectType) && objectType.IsInterface ||
               typeof(IEnumerable).IsAssignableFrom(objectType) && objectType.GetGenericArguments().Any(t => t.IsInterface);
    }

    protected Type GetImplimentedType(Type interfaceType)
    {
        if (!interfaceType.IsInterface) return interfaceType;
        var qualifiedName = interfaceType.AssemblyQualifiedName?.Replace(interfaceType.Name, interfaceType.Name.Substring(1));
        return qualifiedName == null ? interfaceType : Type.GetType(qualifiedName) ?? interfaceType;
    }

    protected string GetTypeVariable(JToken token)
    {
        if (!token.HasAny()) return null;
        return token.Type != JTokenType.Object ? null : token.Value<string>("$type");
    }
}

Global Configuration:

{
    Converters = new List<JsonConverter> { new InterfaceConverter() }
};

Solution 8: Advanced KnownTypeConverter for Optional Properties

This solution refines the KnownType approach to intelligently handle cases where derived class properties might be optional or missing in the JSON. It prioritizes types that match the available JSON properties, including those marked with [JsonProperty].

Scenario:

Consider a base Document class with derived OutgoingDocument and IncomingDocument, where OutgoingDocument has optional properties.

[KnownType(typeof(IncomingDocument))]

public class OutgoingDocument : Document { /* ... */ }
public class IncomingDocument : Document { /* ... */ }

Solution 9: JsonCreationConverter Without JObject.CreateReader()

This alternative implementation of JsonCreationConverter avoids JObject.CreateReader() by serializing the JObject to a string and then creating a new JsonTextReader from that string. This mimics the behavior of default deserialization more closely.

Converter Implementation:

public abstract class JsonCreationConverter<T> : JsonConverter
{
    protected abstract T Create(Type objectType, JObject jObject);

    public override bool CanConvert(Type objectType) => typeof(T).IsAssignableFrom(objectType);

    public override object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer)
    {
        if (reader.TokenType == JsonToken.Null) return null;

        JObject jObject = JObject.Load(reader);
        T target = Create(objectType, jObject);

        StringWriter writer = new StringWriter();
        serializer.Serialize(writer, jObject);
        using (JsonTextReader newReader = new JsonTextReader(new StringReader(writer.ToString())))
        {
            // Copy relevant reader settings
            newReader.Culture = reader.Culture;
            newReader.DateParseHandling = reader.DateParseHandling;
            newReader.DateTimeZoneHandling = reader.DateTimeZoneHandling;
            newReader.FloatParseHandling = reader.FloatParseHandling;
            serializer.Populate(newReader, target);
        }
        return target;
    }

    public override void WriteJson(JsonWriter writer, object value, JsonSerializer serializer)
    {
        serializer.Serialize(writer, value);
    }
}

Choosing the Right Approach

The best method depends on your specific needs:

  • JsonCreationConverter: Offers fine-grained control and is suitable for complex logic.
  • [KnownType] Attribute: Provides a declarative way to map types, good for clear hierarchies.
  • JsonSubtypes Library: Simplifies polymorphic deserialization with attributes, ideal for common use cases.
  • Assembly Scanning: Useful for discovering types dynamically without explicit attributes.
  • Interface Converters: Effective when working with interfaces and their implementations.
  • Advanced KnownTypeConverter: Handles optional properties and JsonProperty mapping effectively.

By implementing these strategies, you can reliably deserialize JSON data into the correct derived types in your C# applications, enhancing type safety and code clarity.

FAQs on Deserialize JSON to Specific Derived Types with C#

Q: How to deserialize JSON into derived classes in C#

ANS: You can use custom JsonConverter classes with Newtonsoft.Json. Implement JsonCreationConverter<T> or use attributes like [KnownType] with a custom converter to inspect JSON properties and instantiate the correct derived type. Libraries like JsonSubtypes simplify this process.

Q: What is the role of JsonConverter in polymorphic JSON deserialization

ANS: A JsonConverter allows you to customize the JSON serialization and deserialization process. For polymorphic types, it enables logic to inspect incoming JSON data and decide which concrete derived class to instantiate based on specific properties or attributes.

Q: Can I use attributes to guide JSON deserialization to derived types

ANS: Yes, attributes like [KnownType] (from System.Runtime.Serialization) and custom attributes (used by libraries like JsonSubtypes) can be applied to base classes to specify potential derived types, aiding the deserialization process.

Q: How does JsonSubtypes library work

ANS: The JsonSubtypes library uses attributes like [JsonConverter(typeof(JsonSubtypes))] and [KnownSubTypeWithProperty] applied to a base class. These attributes tell the library which derived types to consider and which property in the JSON determines the correct type.

Q: What if my derived class properties are optional in JSON

ANS: Converters that inspect JSON properties (like advanced KnownTypeConverter solutions) can handle optional properties. They often prioritize a type that matches all mandatory properties and then consider optional ones, selecting the best fit based on available data.
