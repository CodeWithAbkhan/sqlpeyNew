“WPF Conversion Strategies: System.Drawing.Bitmap to BitmapSource Efficiently”

A frequent technical challenge in mixed environments (.NET Framework or older projects interacting with WPF) involves bridging the gap between the System.Drawing.Bitmap class, typically used in WinForms contexts, and the WPF-native imaging types like BitmapSource or BitmapImage. How can we reliably and performantly achieve this conversion within a WPF application? Several expert approaches offer distinct advantages depending on performance needs and memory constraints.

Core Conversion Approaches

Method 1: Utilizing MemoryStream for Intermediate Encoding

One robust technique involves saving the System.Drawing.Bitmap data to an in-memory stream (like MemoryStream) in a suitable format (e.g., PNG) and then loading that stream into a BitmapImage. This ensures the stream source can be safely closed immediately by setting the CacheOption correctly.

Code Example: Loading from MemoryStream

using System.Drawing;
using System.Drawing.Imaging;
using System.IO;
using System.Windows.Media.Imaging;

// Assuming 'bitmap' is your System.Drawing.Bitmap instance
void LoadBitmapFromMemory(Bitmap bitmap)
{
    using (MemoryStream memoryStream = new MemoryStream())
    {
        // Save the GDI+ bitmap to the stream as PNG
        bitmap.Save(memoryStream, ImageFormat.Png);
        memoryStream.Position = 0;

        BitmapImage bitmapImage = new BitmapImage();
        bitmapImage.BeginInit();
        
        // Crucial: Load the data immediately so the stream can be closed
        bitmapImage.CacheOption = BitmapCacheOption.OnLoad;
        bitmapImage.StreamSource = memoryStream;
        bitmapImage.EndInit();
        
        // The stream is disposed here; the image data is safely copied in memory.
        // Assign bitmapImage to your WPF Image control Source property
    }
}

Method 2: Direct HBITMAP Interop (Recommended for Performance)

Leveraging the Windows GDI API via System.Windows.Interop.Imaging.CreateBitmapSourceFromHBitmap offers a direct, high-speed conversion path by sharing the underlying bitmap handle (HBITMAP). This method requires careful management of the unmanaged handle to prevent memory leaks.

Code Example: Creating BitmapSource from HBitmap

using System.Drawing;
using System.Runtime.InteropServices;
using System.Windows.Interop;
using System.Windows.Media.Imaging;

// You need access to GDI functions, often defined separately.
// For simplicity here, we reference the necessary steps:
BitmapSource screenCapture = System.Windows.Interop.Imaging.CreateBitmapSourceFromHBitmap(
   bmp.GetHbitmap(),

For recurring use across a project, encapsulating the HBitmap conversion logic, including the necessary GDI cleanup (DeleteObject), into reusable extension methods is highly beneficial.

This approach centralizes the GDI cleanup within a NativeMethods class to satisfy FxCop rules and ensure the unmanaged handle is released.

internal static class NativeMethods
{
    [DllImport("gdi32.dll")]
    [return: MarshalAs(UnmanagedType.Bool)]
    internal static extern bool DeleteObject(IntPtr hObject);
}

public static class BitmapExtensions
{
    /// Converts a System.Drawing.Image into a WPF BitmapSource.
    public static BitmapSource ToBitmapSource(this Image source)
    {
        System.Drawing.Bitmap bitmap = new System.Drawing.Bitmap(source);
        BitmapSource bitSrc = bitmap.ToBitmapSource();
        bitmap.Dispose();
        return bitSrc;
    }

    /// Converts a System.Drawing.Bitmap into a WPF BitmapSource using GDI interop.
    public static BitmapSource ToBitmapSource(this System.Drawing.Bitmap source)
    {
        BitmapSource bitSrc = null;
        var hBitmap = source.GetHbitmap();

        try
        {
            bitSrc = Imaging.CreateBitmapSourceFromHBitmap(
                hBitmap,
                IntPtr.Zero,
                Int32Rect.Empty,
                BitmapSizeOptions.FromEmptyOptions());
        }
        catch (System.ComponentModel.Win32Exception)
        {
            bitSrc = null;
        }
        finally
        {
            // Release the unmanaged GDI handle
            NativeMethods.DeleteObject(hBitmap);
        }
        return bitSrc;
    }
}

Method 4: Bidirectional Stream Conversion Utilities

If you require conversion both ways (BitmapSource to System.Drawing.Bitmap and vice-versa), utility methods using streams for both directions provide a complete set. When converting from BitmapSource to Bitmap, creating a copy of the resulting bitmap is necessary because the stream must be closed.

Code Example: Bidirectional Converters

using System.Drawing;
using System.Drawing.Imaging;
using System.IO;
using System.Windows.Media.Imaging;

public static class ImageConversionUtilities
{
    // WPF BitmapSource to WinForms Bitmap
    public static Bitmap ToWinFormsBitmap(BitmapSource bitmapsource)
    {
        using (MemoryStream stream = new MemoryStream())
        {
            BitmapEncoder enc = new PngBitmapEncoder();
            enc.Frames.Add(BitmapFrame.Create(bitmapsource));
            enc.Save(stream);

            using (var tempBitmap = new Bitmap(stream))
            {
                // Return a true copy to detach from the stream lifetime requirement
                return new Bitmap(tempBitmap);
            }
        }
    }

    // WinForms Bitmap to WPF BitmapSource
    public static BitmapSource ToWpfBitmap(Bitmap bitmap)
    {
        using (MemoryStream stream = new MemoryStream())
        {
            bitmap.Save(stream, ImageFormat.Png);
            stream.Position = 0;
            
            BitmapImage result = new BitmapImage();
            result.BeginInit();
            result.CacheOption = BitmapCacheOption.OnLoad; // Ensure immediate load
            result.StreamSource = stream;
            result.EndInit();
            result.Freeze();
            return result;
        }
    }
}

Method 5: Using SafeHandle for Automatic GDI Resource Management

A more modern and safer variant of Method 2 involves wrapping the HBITMAP in a custom SafeHandleZeroOrMinusOneIsInvalid class. This utilizes the .NET framework’s resource safety mechanisms (like IDisposable and finalization) to automatically call DeleteObject when the handle goes out of scope, preventing unmanaged leaks.

Code Example: Utilizing SafeHandle for HBitmap

using System.Drawing;
using System.Runtime.InteropServices;
using System.Security;
using System.Windows;
using System.Windows.Interop;
using System.Windows.Media.Imaging;
using Microsoft.Win32.SafeHandles;

public static class SafeBitmapConversion
{
    [DllImport("gdi32")]
    private static extern int DeleteObject(IntPtr o);

    public static BitmapSource ToBitmapSource(this Bitmap source)
    {
        using (var handle = new SafeHBitmapHandle(source))
        {
            return Imaging.CreateBitmapSourceFromHBitmap(
                handle.DangerousGetHandle(),
                IntPtr.Zero, 
                Int32Rect.Empty,
                BitmapSizeOptions.FromEmptyOptions());
        }
    }

    private sealed class SafeHBitmapHandle : SafeHandleZeroOrMinusOneIsInvalid
    {
        [SecurityCritical]
        public SafeHBitmapHandle(Bitmap bitmap)
            : base(true)
        {
            SetHandle(bitmap.GetHbitmap());
        }

        [ReliabilityContract(Consistency.WillNotCorruptState, Cer.Success)]
        protected override bool ReleaseHandle()
        {
            return DeleteObject(handle) > 0;
        }
    }
}

Method 6: Reading Directly from File URI

If the source System.Drawing.Bitmap originates from a known file path or resource embedded within the WPF project, loading the file directly via BitmapImage.UriSource is the simplest option, provided the URI structure is correct.

Code Example: Loading via URI

// Create source using relative or absolute URI
BitmapImage bi = new BitmapImage();
bi.BeginInit();
bi.UriSource = new Uri(@"/YourAssembly;component/Images/my_image.png", UriKind.Relative);
bi.EndInit();
// Assign bi to Image.Source

Method 7: Custom BitmapSource Adapter for Shared Pixel Data

For scenarios demanding zero-copy operations or direct pixel data sharing between the GDI and WPF graphics stacks, creating a custom class inheriting from BitmapSource (like SharedBitmapSource) that manages the underlying System.Drawing.Bitmap directly can be appropriate. This requires implementing the abstract members, including CopyPixels, often involving pixel format translation.

This method is complex but avoids data duplication if you need ongoing manipulation access in both domains, though it introduces manual IDisposable management.

Evaluating Simpler Alternatives

If the source image is readily available via a file path or embedded resource, using BitmapImage.UriSource (as demonstrated in Solution 10) circumvents the need for GDI conversion entirely. If the source image must originate from an existing System.Drawing.Bitmap object, the interop method using CreateBitmapSourceFromHBitmap remains the most performant mechanism.

FAQs on WPF Conversion Strategies Bitmap to BitmapSource

Q: What is the primary advantage of using CreateBitmapSourceFromHBitmap

ANS: It offers a high-performance conversion by directly referencing the underlying Windows GDI handle, avoiding the overhead of copying pixel data through intermediate streams.

Q: Why must I call DeleteObject after using GetHbitmap

ANS: GetHbitmap() creates an unmanaged GDI resource handle. If this handle is not explicitly released (e.g., via DeleteObject), it results in a resource leak in the operating system.

Q: When is MemoryStream conversion superior

ANS: The MemoryStream approach is superior when you must ensure the stream is immediately closed, such as when reading a temporary file into memory, as setting CacheOption = BitmapCacheOption.OnLoad forces the data copy before disposal.

Q: Can I convert BitmapSource back to SystemDrawingBitmap easily

ANS: Yes, typically this is done by encoding the BitmapSource into a stream (e.g., PNG or BMP) and then loading that stream into a new System.Drawing.Bitmap instance, often requiring a deep copy to detach it from the stream’s lifetime.
