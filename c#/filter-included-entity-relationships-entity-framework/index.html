“Filter Included Entity Relationships in Entity Framework: Solutions & Examples”

When querying data with Entity Framework (EF), you often need to retrieve related entities alongside the main entity. However, directly filtering these included relationships can be challenging, especially in older versions of EF or for specific relationship types like many-to-many. This post explores various methods to achieve this filtering, providing practical code examples for both Entity Framework 6 and Entity Framework Core.

EF6 Workarounds for Filtering Included Relationships

For Entity Framework 6, filtering included relationships requires a specific approach as direct filtering within Include isn’t supported.

Solution 1: Projection with AsEnumerable and Relationship Fixup

This method involves projecting the required data into an anonymous type, switching to LINQ to Objects, and then relying on EF’s relationship fixup mechanism.

// Ensure lazy loading is disabled for this approach to work effectively.
// Option 1: Disable Lazy Loading temporarily
Context.Configuration.LazyLoadingEnabled = false;

// Option 2: Disable Proxy Creation for entities incapable of lazy loading
// Context.Configuration.ProxyCreationEnabled = false;

var buses = Context.Busses
    .Where(b => b.IsDriving)
    .Select(b => new
    {
        // Select the main entity
        MainBus = b,
        // Project and filter related passengers
        AwakePassengers = b.Passengers.Where(p => p.Awake)
    })
    .AsEnumerable() // Switch from LINQ to Entities to LINQ to Objects
    .Select(x => x.MainBus) // Select the main entity again after materialization
    .ToList();

// After this, 'buses' will contain buses with only their awake passengers loaded.
// It's important to note that disabling LazyLoadingEnabled will revert
// once enabled again. Disabling ProxyCreationEnabled creates entities
// that won't perform lazy loading even if ProxyCreationEnabled is re-enabled.
// This can be preferable if the context has a longer lifespan.

Important Considerations for EF6:

  • Lazy Loading: This technique relies on lazy loading being disabled. If lazy loading is enabled, EF might load all passengers for each bus when they are accessed during DTO conversion.

  • Relationship Fixup: EF’s relationship fixup correctly associates materialized objects within the context. Without AsEnumerable(), EF might only materialize the final projection, excluding the filtered relationships.

  • Many-to-Many Relationships: Relationship fixup does not work for many-to-many associations. For such scenarios, a manual fix is necessary:

    // Disable lazy loading as before
Context.Configuration.LazyLoadingEnabled = false;
// Or: Context.Configuration.ProxyCreationEnabled = false;

var tempBusesWithPassengers = Context.Busses
    .Where(b => b.IsDriving)
    .Select(b => new
    {
        MainBus = b,
        AwakePassengers = b.Passengers.Where(p => p.Awake)
    })
    .ToList(); // Materialize here

// Manually assign filtered passengers for many-to-many
foreach (var busData in tempBusesWithPassengers)
{
    busData.MainBus.Passengers = busData.AwakePassengers.ToList(); // Assuming Passengers is ICollection<Passenger>
}

var buses = tempBusesWithPassengers.Select(x => x.MainBus).ToList();

Third-Party Libraries for EF6:

  • EntityFramework.DynamicFilters: This library allows defining global filters for entities, which are then applied to all queries.

    // In your DbConfiguration or OnModelCreating
modelBuilder.Filter("AwakePassengers", (Person p) => p.Awake, true);

// Then query normally
var buses = Context.Busses
               .Where(b => b.IsDriving)
               .Include(b => b.People) // The filter will be applied to included People
               .ToList();

    Filters can be enabled or disabled, offering granular control.

  • EntityFramework.Filters: A similar library from the creator of AutoMapper.

EF Core Solutions for Filtering Included Relationships

EF Core offers more direct and streamlined ways to filter included relationships.

Solution 2: Filter in Include (EF Core 2.0.0+)

EF Core 2.0.0 and later versions introduce the ability to filter included entities directly within the Include method.

var buses = _Context.Busses
    .Include(b => b.Passengers.Where(p => p.Awake)) // Filter passengers directly
    .Where(b => b.IsDriving) // Filter the main entity
    .ToList();

Solution 3: EF+ Query IncludeFilter

The Entity Framework Plus library (developed by the author of EF+) provides a powerful IncludeFilter feature.

var buses = Context.Busses
    .Where(b => b.IsDriving)
    .IncludeFilter(x => x.Passengers.Where(p => p.Awake)) // Filter included relationships
    .ToList();

// Refer to the wiki for more details: EF+ Query IncludeFilter

Solution 4: Using Any in a Where Clause

This approach is useful when you need to filter the main entities based on a condition in their included relationships, without necessarily loading the filtered relationship itself.

// Example: Get Initiatives that had an InitiativeYear in 2020
return await _context.Initiatives
    .Where(x => x.InitiativeYears.Any(y => y.Year == 2020 && y.InitiativeId == x.Id))
    .ToListAsync();

// Entity definitions for context:
public class Initiative
{
    public int Id { get; set; }
    public string Name { get; set; }
    public ICollection<InitiativeYear> InitiativeYears { get; set; }
}

public class InitiativeYear
{
    public int Year { get; set; }
    public int InitiativeId { get; set; }
    public Initiative Initiative { get; set; }
}

Solution 5: .Any() within .Include() and .Where()

For filtering parent entities based on conditions within their children, you can combine Include and Where with .Any().

_ctx.Parent
    .Include(t => t.Children) // Include children
    .Where(t => t.Children.Any(child => /* Your filter condition here */)) // Filter parents based on children
    .ToList();

EF Core Global Query Filters

Since EF Core 2.0.0, global query filters are available. These apply predefined filters to entities whenever they are queried. While powerful, current limitations restrict filters from referencing navigation properties directly, focusing instead on the root entity. This feature is expected to evolve in future versions for broader applicability.

FAQs on Filter Included Entity Relationships

Q: How to filter included entities in Entity Framework 6

ANS: In EF6, you can use a projection with Select and AsEnumerable to materialize data before applying LINQ to Objects filters. Alternatively, libraries like EntityFramework.DynamicFilters offer more direct solutions.

Q: Can I filter directly in EF Core's Include method

ANS: Yes, EF Core 2.0.0 and later versions support filtering directly within the Include method using Include(x => x.RelatedEntities.Where(filter)).

Q: What if I have a many-to-many relationship in EF6 and need to filter

ANS: For many-to-many relationships in EF6, relationship fixup doesn’t work automatically. You’ll need to manually assign the filtered related entities after querying them in a projection.

Q: Are there third-party tools for filtering includes

ANS: Yes, libraries such as EntityFramework.DynamicFilters and Entity Framework Plus (with its IncludeFilter feature) can simplify filtering included relationships in both EF6 and EF Core.

Q: What are global query filters in EF Core

ANS: Global query filters in EF Core allow you to define default filters for entities that are applied automatically to queries. However, they currently have limitations regarding referencing navigation properties.
