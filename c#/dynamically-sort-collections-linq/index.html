Dynamically Sort Collections in C# with LINQ

When working with collections in C#, there are often scenarios where you need to sort data based on a property name that is determined at runtime. This is commonly encountered when building user interfaces where users can choose sort criteria, or when processing data from external sources. LINQ provides powerful sorting capabilities, but directly using a string to specify the property for OrderBy or OrderByDescending requires specific techniques.

This post explores various approaches to achieve dynamic sorting of collections in C# using LINQ, covering methods that utilize reflection, Expression Trees, and specialized libraries.

Sorting with Reflection

One fundamental approach involves using reflection to access and sort by properties dynamically. This method works directly with .NET’s reflection capabilities.

Solution 4 and Solution 6 demonstrate this by creating helper methods that retrieve property values using reflection and then applying standard LINQ OrderBy or OrderByDescending.

Example using Reflection (similar to Solution 4):

public static class ReflectionExtensions
{
    public static IEnumerable<T> OrderByProperty<T>(this IEnumerable<T> source, string propertyName)
    {
        return source.OrderBy(item => GetPropertyValue(item, propertyName));
    }

    public static IEnumerable<T> OrderByDescendingProperty<T>(this IEnumerable<T> source, string propertyName)
    {
        return source.OrderByDescending(item => GetPropertyValue(item, propertyName));
    }

    private static object GetPropertyValue(object obj, string propertyName)
    {
        // Get the property by name
        var propertyInfo = obj.GetType().GetProperty(propertyName);
        if (propertyInfo == null)
        {
            throw new ArgumentException($"Property '{propertyName}' not found on type '{obj.GetType().Name}'.");
        }
        // Get the value of the property
        return propertyInfo.GetValue(obj, null);
    }
}

You can then use this extension like so:

List<MyObject> myList = GetData(); // Assume GetData() returns List<MyObject>
string sortField = "Name"; // Dynamic property name
myList = myList.OrderByProperty(sortField).ToList();

Considerations: While reflection is versatile, it can have a performance impact compared to direct property access, especially for very large collections or frequent sorting operations. It’s advisable to benchmark if performance is critical.

Dynamic LINQ Library

For more sophisticated dynamic query capabilities, including complex sorting clauses and filtering, the System.Linq.Dynamic.Core library (a successor to the older System.Linq.Dynamic) is an excellent choice. This library allows you to construct LINQ queries using string expressions that are parsed at runtime.

Solution 2, Solution 9, Solution 10, and Solution 20 highlight the use of this library.

Installation:

You can install System.Linq.Dynamic.Core via NuGet Package Manager Console:

Install-Package System.Linq.Dynamic.Core

Example using System.Linq.Dynamic.Core:

using System.Linq.Dynamic.Core; // Required namespace

// Assume 'myQuery' is an IQueryable<MyObject>
string sortBy = "Year DESC, Make ASC"; // Example sort string
myQuery = myQuery.OrderBy(sortBy);

This approach is very powerful for constructing dynamic queries from user input or configuration.

Expression Trees for Dynamic Sorting

A more advanced technique involves building Expression Trees. This method offers fine-grained control and can be highly performant, especially when working with IQueryable sources that translate to SQL (like Entity Framework or LINQ to SQL).

Solution 1, Solution 7, and Solution 14 provide examples of using Expression Trees to dynamically construct OrderBy and ThenBy clauses.

Example using Expression Trees (similar to Solution 1):

using System.Linq.Expressions;
using System.Reflection;

public static class QueryableExtensions
{
    public static IOrderedQueryable<T> OrderByDynamic<T>(this IQueryable<T> source, string propertyName, bool ascending = true)
    {
        // Handle nested properties like "Address.City"
        string[] props = propertyName.Split('.');
        var type = typeof(T);
        var arg = Expression.Parameter(type, "x");
        Expression expr = arg;

        foreach (var prop in props)
        {
            PropertyInfo pi = type.GetProperty(prop);
            if (pi == null)
            {
                throw new ArgumentException($"Property '{prop}' not found on type '{type.Name}'.");
            }
            expr = Expression.Property(expr, pi);
            type = pi.PropertyType;
        }

        var lambda = Expression.Lambda(expr, arg);

        var method = typeof(Queryable).GetMethods()
            .Single(m => m.Name == (ascending ? "OrderBy" : "OrderByDescending") && m.GetParameters().Length == 2 && m.IsGenericMethodDefinition);

        method = method.MakeGenericMethod(typeof(T), type);

        var result = method.Invoke(null, new object[] { source, lambda });

        return (IOrderedQueryable<T>)result;

Handling Multiple Sort Criteria

For sorting by multiple properties, you can chain ThenBy or ThenByDescending calls. Both the Dynamic LINQ library and Expression Tree methods support this.

Example with Dynamic LINQ:

string sortBy = "Year DESC, Make ASC";
myQuery = myQuery.OrderBy(sortBy);

Example with Expression Trees:

You would typically call the OrderByDynamic method first, and then chain ThenByDynamic calls for subsequent sort criteria.

var query = myDbSet.OrderByDynamic("Year", false); // Order by Year Descending
query = query.ThenByDynamic("Make", true);       // Then by Make Ascending

Sorting IEnumerable vs. IQueryable

It’s important to note the difference when sorting IEnumerable<T> versus IQueryable<T>:

  • IEnumerable<T>: Sorting happens in memory. Methods like OrderBy are directly available.
  • IQueryable<T>: Sorting is translated into an expression tree. For data sources like databases, this expression tree is converted into a SQL query (or similar) and executed by the data provider. This is generally more efficient as sorting is done server-side. If you have an IEnumerable<T> and want to leverage IQueryable’s benefits (e.g., server-side sorting), you can use source.AsQueryable(). Solution 17 touches on this.

Working with DataTable

If you are working with DataTable objects, you can leverage AsEnumerable() and AsDataView() extensions from System.Data.DataSetExtensions to perform dynamic sorting.

Solution 12 demonstrates this:

DataTable contacts = dataSet.Tables["Contact"];
DataView view = contacts.AsDataView();
view.Sort = "LastName desc, FirstName asc"; // Sorting string
bindingSource1.DataSource = view;

FAQs on Dynamically Sort Collections in C# with LINQ

Q: How can I sort a List in C# by a property name given as a string

ANS: You can use LINQ with reflection by creating an extension method that retrieves the property using Type.GetProperty() and then uses it with OrderBy. Alternatively, the System.Linq.Dynamic.Core NuGet package provides a simpler way to achieve this with string-based queries.

Q: What is the System.Linq.Dynamic.Core library

ANS: System.Linq.Dynamic.Core is a NuGet package that extends LINQ with dynamic query capabilities, allowing you to build queries using string expressions for filtering, sorting, and selecting data.

Q: Can I sort by multiple properties dynamically in C#

ANS: Yes, you can sort by multiple properties dynamically. With the System.Linq.Dynamic.Core library, you can provide a comma-separated string like “Property1 ASC, Property2 DESC”. Using Expression Trees, you would chain OrderBy with ThenBy calls dynamically.

Q: Does dynamic sorting work with IQueryable

ANS: Yes, dynamic sorting methods using Expression Trees or libraries like System.Linq.Dynamic.Core are designed to work effectively with IQueryable, translating the sorting logic into SQL for database operations where applicable.

Q: What are the performance implications of using reflection for dynamic sorting

ANS: Reflection can be slower than direct property access, especially in tight loops or on very large datasets. For performance-critical applications, consider using System.Linq.Dynamic.Core or custom Expression Tree implementations, which often optimize better for query providers.
