“C# Command Line Argument Parsing Libraries: A Comparative Review”

When developing console applications in C#, processing command-line arguments efficiently is crucial for user interaction and application control. Several libraries offer robust solutions, each with unique features and approaches. Let’s explore some of the most recommended options, examining their implementation and benefits.

Exploring C# Command Line Parsing Solutions

This section details various libraries and frameworks that facilitate command-line argument parsing in C# .NET applications. Each solution offers distinct ways to define, parse, and manage arguments, often with features like automatic help generation, type conversion, and validation.

Solution 1: NDesk.Options / Mono.Options

This widely used library, also available as Mono.Options with the same API, provides a flexible way to define command-line options.

Key Features:

  • Declarative option definition.
  • Support for named and unnamed arguments.
  • Automatic help message generation.

Example Usage:

// Requires: using NDesk.Options;
//           using System.Collections.Generic;

bool showHelp = false;
var names = new List<string>();
int repeatCount = 1;
int verbosity = 0;

var parser = new OptionSet()
{
    { "n|name=", "Specify the {NAME} of a person.", v => names.Add(v) },
    { "r|repeat=", "Number of {TIMES} to repeat the greeting (integer).", (int v) => repeatCount = v },
    { "v", "Increase debug message verbosity.", v => { if (v != null) verbosity++; } },
    { "h|help", "Display this help message and exit.", v => showHelp = v != null }
};

List<string> remainingArguments;
try
{
    remainingArguments = parser.Parse(args);
}
catch (OptionException e)
{
    Console.Write("Program: ");
    Console.WriteLine(e.Message);
    Console.WriteLine("Try 'Program --help' for more information.");
    return; // Or exit appropriately
}

if (showHelp)
{
    parser.WriteOptionDescriptions(Console.Out);
    return; // Or exit appropriately
}

// Process names, repeatCount, verbosity, and remainingArguments here

For more details, refer to the NDesk.Options documentation .

Solution 2: Command Line Parser Library

This library offers an attribute-driven approach, simplifying the setup of command-line parameters.

Key Features:

  • Attribute-based parameter definition.
  • Automatic help screen generation.
  • Required arguments and help text customization.

Example Usage:

// Requires: using CommandLine;
//           using System.Text;

public class AppOptions
{
    [Option('i', "input", Required = true, HelpText = "Input file to process.")]
    public string InputFile { get; set; }

    [Option(null, "length", HelpText = "Maximum number of bytes to process.")]
    public int MaxLength { get; set; }

    [Option('v', null, HelpText = "Enable verbose output.")]
    public bool Verbose { get; set; }

    [HelpOption(HelpText = "Display this help screen.")]
    public string GetHelpText()
    {
        var usage = new StringBuilder();
        usage.AppendLine("App Utility 1.0");
        usage.AppendLine("Process files with specific options...");
        return usage.ToString();
    }
}

Solution 9: Rug.Cmd

Rug.Cmd is an easy-to-use and expandable command-line argument parser.

Key Features:

  • Supports bool, string, string list, CSV, and enumeration types.
  • Built-in / help mode.
  • Document generation modes (/?D, /?).

Example Usage:

// Requires: using Rug.Cmd;

static void Main(string[] args)
{
    var parser = new ArgumentParser("ArgumentExample", "Example of argument parsing");

    var stringArg = new StringArgument("String", "Example string", "Demonstrates string arguments");
    parser.Add("/", "String", stringArg);

    parser.Parse(args);

    if (!parser.HelpMode)
    {
        if (stringArg.Defined)
        {
            Console.WriteLine("String argument defined:");
            Console.WriteLine(stringArg.Value);
        }
    }
}

Note: This is a personal project; use with consideration.

Solution 11: CommandHandler (Novell Options based)

This handler is designed for interactive console applications, managing commands within a loop.

Example Usage:

// Requires: using YourNamespace.CommandHandler;

static void Main(string[] args)
{
    var handler = new CommandHandler();
    var options = new CommandOptions();

    options.Add("show", handler.Show)
           .Add("connect", v => handler.Connect(v))
           .Add("dir", handler.Dir);

    Console.Write("> ");
    string input = Console.ReadLine();

    while (input != "quit" && input != "exit")
    {
        if (input == "cls" || input == "clear")
        {
            Console.Clear();
        }
        else if (!string.IsNullOrEmpty(input))
        {
            if (!options.Parse(input))
            {
                Console.WriteLine("Command not recognized.");
            }
            else
            {
                Console.WriteLine(handler.OutputMessage);
            }
        }
        Console.Write("> ");
        input = Console.ReadLine();
    }
}

Solution 13: FubuCore

Key Features:

  • Declarative command and parameter definitions using attributes.
  • Automatic usage graph generation.
  • Handles complex command structures.

Example Usage:

Solution 19: Ad Hoc Command Line Parsing Class

A simple, custom class for parsing arguments, supporting default values.

Example Usage:

public class CommandLineArgs
{
    private readonly Dictionary<string, string> _args = new Dictionary<string, string>();

    public static CommandLineArgs Instance { get; } = new CommandLineArgs();

    public string GetStringArg(string argName) => _args.ContainsKey(argName) ? _args[argName] : "";
    public long GetLongArg(string argName) => _args.ContainsKey(argName) ? Convert.ToInt64(_args[argName]) : 0;
    public double GetDoubleArg(string argName) => _args.ContainsKey(argName) ? Convert.ToDouble(_args[argName]) : 0;

    public void Parse(string[] args, string defaultArgs)
    {
        ParseDefaults(defaultArgs);
        foreach (var arg in args)
        {
            var parts = arg.Split('=');
            if (parts.Length == 2)
                _args[parts[0]] = parts[1];
        }
    }

    private void ParseDefaults(string defaultArgs)
    {
        if (string.IsNullOrEmpty(defaultArgs)) return;
        var defaults = defaultArgs.Split(';');
        foreach (var arg in defaults)
        {
            var parts = arg.Split('=');
            if (parts.Length == 2)
                _args[parts[0]] = parts[1];
        }
    }
}

class Program
{
    static void Main(string[] args)
    {
        CommandLineArgs.Instance.Parse(args, "myStringArg=defaultValue;someLong=12");
        Console.WriteLine($"Arg myStringArg: '{CommandLineArgs.Instance.GetStringArg("myStringArg")}'");
        Console.WriteLine($"Arg someLong: '{CommandLineArgs.Instance.GetLongArg("someLong")}'");
    }
}

FAQs on C# Command Line Parsing

Q: What is the simplest way to parse command line arguments in C#

ANS: Libraries like Command Line Parser (Solution 2) or NDesk.Options (Solution 1) offer attribute-based or declarative approaches that are generally considered straightforward for many common use cases.

Q: How do I handle optional and required arguments

ANS: Most libraries provide mechanisms to mark arguments as required or optional. For example, the Required = true attribute in the Command Line Parser library or defining default behavior in NDesk.Options.

Q: Can I generate help messages automatically

ANS: Yes, many libraries like NDesk.Options, Command Line Parser, and BizArk automatically generate help messages based on your argument definitions, saving you manual effort.

Q: Which libraries support complex argument types like lists or arrays

ANS: Libraries like BizArk Framework (Solution 5) and FubuCore (Solution 13) explicitly support argument arrays and complex data structures.

Q: Is it possible to create interactive command-line applications

ANS: Yes, the CommandHandler based on Novell Options (Solution 11) is specifically designed for interactive console applications with command loops.
