“C# SQL Server Table-Valued Parameters: Methods and Examples”

Passing collections of data efficiently to SQL Server stored procedures from C# is a common requirement. Table-valued parameters (TVPs) offer a robust solution for this, allowing you to send multiple rows of data as a single parameter. This approach is generally more performant than passing delimited strings or executing multiple individual inserts.

The core of implementing TVPs in C# involves creating a DataTable or IEnumerable<SqlDataRecord> that matches the structure of your defined TVP in SQL Server. This data is then passed as a SqlParameter with the SqlDbType set to Structured and the TypeName matching your SQL TVP definition.

Implementing TVPs with DataTable and SqlDataRecord

One of the primary methods involves using System.Data.DataTable or System.Data.SqlClient.SqlDataRecord.

SQL Setup:

First, you need a table type and a stored procedure that accepts this TVP.

CREATE TABLE dbo.PageView
(
    PageViewID BIGINT NOT NULL CONSTRAINT pkPageView PRIMARY KEY CLUSTERED,
    PageViewCount BIGINT NOT NULL
);
GO

CREATE TYPE dbo.PageViewTableType AS TABLE
(
    PageViewID BIGINT NOT NULL
);
GO

CREATE PROCEDURE dbo.procMergePageView
    @Display dbo.PageViewTableType READONLY
AS
BEGIN
    MERGE INTO dbo.PageView AS T
    USING @Display AS S
    ON T.PageViewID = S.PageViewID
    WHEN MATCHED THEN UPDATE SET T.PageViewCount = T.PageViewCount + 1
    WHEN NOT MATCHED THEN INSERT VALUES(S.PageViewID, 1);
END
GO

C# Implementation:

Here’s how you can execute this stored procedure, demonstrating both DataTable and IEnumerable<SqlDataRecord> approaches.

using System;
using System.Collections.Generic;
using System.Data;
using System.Data.SqlClient;
using Microsoft.SqlServer.Server; // Required for SqlDataRecord

public static class TvpExample
{
    private static void ExecuteProcedure(bool useDataTable,
                                         string connectionString,
                                         IEnumerable<long> ids)
    {
        using (SqlConnection connection = new SqlConnection(connectionString))
        {
            connection.Open();
            using (SqlCommand command = connection.CreateCommand())
            {
                command.CommandText = "dbo.procMergePageView";
                command.CommandType = CommandType.StoredProcedure;

                SqlParameter parameter;
                if (useDataTable)
                {
                    // Using DataTable
                    parameter = command.Parameters.AddWithValue("@Display", CreateDataTable(ids));
                }
                else
                {
                    // Using IEnumerable<SqlDataRecord>
                    parameter = command.Parameters.AddWithValue("@Display", CreateSqlDataRecords(ids));
                }
                parameter.SqlDbType = SqlDbType.Structured;
                parameter.TypeName = "dbo.PageViewTableType"; // Must match your SQL TYPE definition

                command.ExecuteNonQuery();
            }
        }
    }

    private static DataTable CreateDataTable(IEnumerable<long> ids)
    {
        DataTable table = new DataTable();
        table.Columns.Add("ID", typeof(long)); // Column name must match the TVP definition
        foreach (long id in ids)
        {
            table.Rows.Add(id);
        }
        return table;
    }

    private static IEnumerable<SqlDataRecord> CreateSqlDataRecords(IEnumerable<long> ids)
    {
        SqlMetaData[] metaData = new SqlMetaData[1];
        // Define metadata for each column in the TVP
        metaData[0] = new SqlMetaData("ID", SqlDbType.BigInt); // Column name and type

        // Create a SqlDataRecord with the defined metadata
        SqlDataRecord record = new SqlDataRecord(metaData);
        foreach (long id in ids)
        {
            record.SetInt64(0, id); // Set the value for the first column (index 0)
            yield return record;
        }
    }

    // Example usage:
    public static void Main(string[] args)
    {
        string connString = "Your_Connection_String_Here";
        List<long> sampleIds = new List<long> { 101, 102, 103, 104, 105 };

        Console.WriteLine("Executing with DataTable...");
        ExecuteProcedure(true, connString, sampleIds);
        Console.WriteLine("Execution complete (DataTable).");

        Console.WriteLine("Executing with SqlDataRecord...");
        ExecuteProcedure(false, connString, sampleIds);
        Console.WriteLine("Execution complete (SqlDataRecord).");
    }
}

Handling Multiple Columns and Column Order

When your TVP has multiple columns, or if the column order in your C# DataTable does not match the SQL Server TVP definition, you need to explicitly set the column ordinals.

SQL TVP Definition:

CREATE TYPE NodeFilter AS TABLE (
  ID int not null,
  Code nvarchar(10) not null
);

C# DataTable Column Ordering:

If you create a DataTable with columns in a different order (e.g., Code first, then ID), you must ensure the ordinals are correct for the TVP to be parsed correctly.

DataTable table = new DataTable();
table.Columns.Add("Code", typeof(string)); // Added first
table.Columns.Add("ID", typeof(int));      // Added second

// Set the correct ordinal positions to match the SQL TVP definition
table.Columns["ID"].SetOrdinal(0);    // ID should be the first column
table.Columns["Code"].SetOrdinal(1);  // Code should be the second column

// Populate your table rows here...

Failing to set the correct ordinals can lead to errors like “failed to convert nvarchar to int” if the database expects an integer at a position where a string is provided.

Generic Extension Methods for Convenience

To streamline the process, you can create generic extension methods.

Generic DataTable Extension:

This method simplifies creating a DataTable from any enumerable list, mapping a property to a specific column.

public static class DataTableExtensions
{
    public static DataTable ToTableValuedParameter<T, TProperty>(this IEnumerable<T> list, string columnName, Func<T, TProperty> selector)
    {
        var tbl = new DataTable();
        tbl.Columns.Add(columnName, typeof(TProperty)); // Use the provided column name and inferred property type

        foreach (var item in list)
        {
            tbl.Rows.Add(selector.Invoke(item));
        }
        return tbl;
    }
}

Usage Example:

// Assuming you have a list of objects with an 'Id' property
List<MyObject> myObjects = new List<MyObject> { new MyObject { Id = 1 }, new MyObject { Id = 2 } };
// Use the extension method
DataTable tvpData = myObjects.ToTableValuedParameter("ID", obj => obj.Id);

Extension Method for Adding TVPs Directly:

This is a highly convenient approach for specific TVP types.

public static class SqlParameterCollectionExtensions
{
    // Example for a TVP named 'dbo.tvp_Int' with a single integer column named 'Value'
    public static void AddWithValue_Tvp_Int(this SqlParameterCollection paramCollection, string parameterName, List<int> data)
    {
        if (paramCollection != null)
        {
            var p = paramCollection.Add(parameterName, SqlDbType.Structured);
            p.TypeName = "dbo.tvp_Int"; // Your TVP name
            
            DataTable _dt = new DataTable();
            _dt.Columns.Add("Value", typeof(int)); // Column name and type must match TVP
            data.ForEach(value => _dt.Rows.Add(value));
            
            p.Value = _dt;
        }
    }
}

Usage:

// Assuming listOfIds is a List<int>
cmd.Parameters.AddWithValue_Tvp_Int("@IDValues", listOfIds);

Dynamically Generating Parameters from Objects

For more complex scenarios, you can dynamically create SqlParameter objects by inspecting object properties.

private static SqlParameter GenerateTypedParameter(string name, object typedParameter, string typeName)
{
    DataTable dt = new DataTable();

    var properties = typedParameter.GetType().GetProperties().ToList();
    // Dynamically add columns to DataTable based on object properties
    properties.ForEach(p =>
    {
        // Handle nullable types by getting the underlying type
        dt.Columns.Add(p.Name, Nullable.GetUnderlyingType(p.PropertyType) ?? p.PropertyType);
    });

    // Create a row and populate it with object property values
    var row = dt.NewRow();
    properties.ForEach(p => {
        // Use DBNull.Value for null properties
        row[p.Name] = p.GetValue(typedParameter) ?? DBNull.Value;
    });
    dt.Rows.Add(row);

    return new SqlParameter
    {
        Direction = ParameterDirection.Input,
        ParameterName = name,
        Value = dt,
        SqlDbType = SqlDbType.Structured,
        TypeName = typeName // Pass the TVP type name
    };
}

Usage:

// Assuming 'myObject' is an instance of a class matching your TVP structure
// and 'dbo.MyCustomType' is the corresponding SQL TVP name
SqlParameter tvpParam = GenerateTypedParameter("@MyData", myObject, "dbo.MyCustomType");
command.Parameters.Add(tvpParam);

Calling Table-Valued Functions

TVPs are also used with table-valued functions (TVFs). While not directly passing a TVP as a parameter to the function in the same way as a stored procedure, you can execute a TVF that accepts parameters and process its results.

SQL TVF Definition:

CREATE FUNCTION [dbo].[MyFunc](@PRM1 int, @PRM2 int)
RETURNS TABLE
AS
RETURN
(
    SELECT Column1, Column2 FROM MyTable t
    where t.column1 = @PRM1
    and t.column2 = @PRM2
)

C# Execution:

You can call this TVF from C# by constructing the SQL query string.

public async Task<List<MyModel>> GetFunctionResultsAsync(string connectionString, int? prm1, int? prm2)
{
    List<MyModel> results = new List<MyModel>();

    using (SqlConnection connection = new SqlConnection(connectionString))
    {
        await connection.OpenAsync();

        using (var command = connection.CreateCommand())
        {
            // Construct the query string, ensuring parameters are handled safely (e.g., using SqlCommand.Parameters)
            // for string interpolation like this, ensure proper sanitization if inputs are untrusted.
            command.CommandText = $"SELECT Column1, Column2 FROM [dbo].[MyFunc]({prm1 ?? 0},{prm2 ?? 0})"; // Using ?? to provide defaults if null

            using (var reader = await command.ExecuteReaderAsync())
            {
                if (reader.HasRows)
                {
                    while (await reader.ReadAsync())
                    {
                        MyModel model = new MyModel();
                        // Cast or convert as needed, handling potential DBNull
                        model.Column1 = reader.GetInt32(reader.GetOrdinal("Column1"));
                        model.Column2 = reader.GetInt32(reader.GetOrdinal("Column2"));
                        results.Add(model);
                    }
                }
            }
        }
    }
    return results;
}

(Note: For security, it’s better to use command.Parameters.AddWithValue even for scalar parameters in TVFs to prevent SQL injection.)

FAQs on C# SQL Server Table-Valued Parameters

Q: What are Table-Valued Parameters in SQL Server

ANS: Table-Valued Parameters (TVPs) are a feature in SQL Server that allows you to pass multiple rows of data from a client application to a stored procedure or function as a single parameter. They are defined as user-defined TABLE types in SQL Server.

Q: What C# objects can be used to populate a TVP

ANS: You can use System.Data.DataTable or System.Data.SqlClient.SqlDataRecord to represent the data for a TVP in your C# code.

Q: How do I specify the TVP type in C#

ANS: When adding the SqlParameter for a TVP, you must set its SqlDbType to SqlDbType.Structured and its TypeName property to the name of the user-defined TABLE type in SQL Server.

Q: What happens if my DataTable columns are out of order compared to the SQL TVP

ANS: If the column order in your DataTable does not match the order defined in the SQL Server TVP, you will likely encounter parsing errors. Use the DataColumn.SetOrdinal() method in C# to arrange your DataTable columns to match the TVP’s definition.

Q: Can I use generic methods to create TVPs in C#

ANS: Yes, you can create generic extension methods for IEnumerable<T> to dynamically generate DataTable objects for TVPs, making the process more reusable and cleaner.

Q: Is there a way to simplify adding TVPs to SqlCommand

ANS: Yes, you can create custom extension methods for SqlParameterCollection to encapsulate the logic for adding TVPs with a specific type and column structure, allowing for one-line additions.

Q: How do I pass parameters to SQL Server table-valued functions from C#

ANS: You can call table-valued functions by constructing the SQL query string in your SqlCommand. It is recommended to use SqlParameter objects for the function’s scalar arguments to prevent SQL injection and ensure proper type handling.
