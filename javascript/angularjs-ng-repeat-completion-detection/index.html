“AngularJS ng-repeat Completion Detection Strategies”

How can developers reliably trigger a function or apply post-processing logic once an AngularJS ng-repeat iteration has completely rendered all its elements into the Document Object Model (DOM)? Since ng-repeat constructs elements individually, there isn’t a direct “loop-finished” event. We need techniques leveraging scope properties or custom directives to pinpoint the final element’s creation.

Strategy 1: Utilizing Directive Scope Properties ($last)

A primary method involves creating a directive that runs on every repeated element and checks for the $last scope property. This property is true only for the final iteration of the loop.

Implementation with Nested Directives

This approach uses two directives: one encompassing the repeat to style the whole container, and one inside the repeat to detect the end.

angular.module('myApp', [])
.directive('myRepeatDirective', function() {
  return function(scope, element, attrs) {
    // Apply styles to each element as it's created
    angular.element(element).css('color','blue');
    
    // Execute logic only on the very last element
    if (scope.$last){
      window.alert("I am the final element!");
    }
  };
})
.directive('myMainContainer', function() { // Renamed for clarity
  return function(scope, element, attrs) {
    // Apply styles to the parent container
    angular.element(element).css('border','5px solid red');
  };
});

HTML Structure:

<div ng-controller="Ctrl" my-main-container>
  <div ng-repeat="thing in things" my-repeat-directive>
    thing {{thing}}
  </div>
</div>

Alternative: Directive Checking Parent Scope for Isolated Scope Scenarios

When using isolated scope in directives (scope: { ... }), the $last property might reside on the parent scope. In such cases, access it via $scope.$parent.$last.

angular.module('myApp', [])
.directive('isolatedRepeatHandler', function() {
  return {
    restrict: 'E',
    scope: {
      dataItem: '=' // Assuming data binding
    },
    link: function(scope, element, attrs) {
      angular.element(element).css('color','green');
      
      // Check the parent scope ($parent) which holds the $index properties
      if (scope.$parent.$last){
        window.alert("Isolated scope detected the last item!");
      }
    }
  };
});

Strategy 2: Employing ng-init with $last Check

A concise approach avoids custom directives by checking $last directly within an ng-init expression placed on the repeated element. This executes the desired function (finished()) only when $last is true.

Basic Usage:

<div ng-repeat="thing in things" ng-init="$last && finished()">
    thing {{thing}}
</div>

This requires defining $scope.finished = function() { ... } in your controller.

Handling Empty Arrays with ng-init

To ensure a function runs even if the array is empty, an additional ng-init check placed near the repeat element is helpful:

<!-- Check if array is empty -->
<div style="display:none" ng-init="things.length < 1 && finished()"></div> 

<div ng-repeat="thing in things" ng-init="$last && finished()">
    thing {{thing}}
</div>

A slightly cleaner alternative for the empty array check uses ng-if:

<div ng-if="things.length > 0" ng-init="finished()"></div> 
<div ng-repeat="thing in things" ng-init="$last && finished()">
    thing {{thing}}
</div>

Simplified Ternary Operator Usage

For cleaner expression syntax, use the ternary operator with angular.noop() if no action is needed for non-last elements:

<ul ng-controller="SomeCtrl">
    <li ng-repeat="item in items" 
        ng-init="$last ? doSomethingAfterRepeat() : angular.noop()">
        {{item}}
    </li>
</ul>

Strategy 3: Custom Directive with Event Emitter

If the post-rendering action involves complex DOM manipulation (like initializing jQuery plugins), it is often safer to use a directive that broadcasts an event upon completion, optionally wrapped in a timeout.

Directive to Emit Event on $last

angular.module('MyApp').directive('emitLastRepeaterElement', function() {
    return function(scope) {
        if (scope.$last){
            // Emit an event up the scope chain
            scope.$emit('LastRepeaterElement');
        }
    };
});

Usage in Template:

<div ng-repeat="item in items" emit-last-repeater-element></div>

Listening in Controller/Another Directive:

If the action requires DOM manipulation that must wait for Angular’s rendering cycle to fully settle, combining $timeout with the event listener is a robust pattern.

$scope.$on('LastRepeaterElement', function() {
    $timeout(function() { 
        // Safe DOM manipulation logic here, e.g., initializing tooltips
        $('a[data-toggle="tooltip"]').tooltip({delay: 50});
    }, 0); 
});

Using setTimeout(..., 0) for External Library Integration

When integrating external JavaScript libraries or jQuery plugins, using the native setTimeout(fn, 0) within the completion directive is sometimes preferred over $timeout. This pushes the execution to the very end of the browser’s event queue, ensuring Angular’s digest cycle is finished, and avoids triggering an unnecessary extra digest cycle that $timeout might initiate.

angular.module('myApp', [])
.directive('pluginInitializer', function() {
  return function(scope, element, attrs) {        
    setTimeout(function executePluginLogic(){
      // Execute jQuery code or library initialization here
      $('.materialboxed').materialbox(); 
    }, 0);        
  };
});

Strategy 4: Broadcast Event via ng-init on a Sentinel Element

This strategy uses a final element, often hidden, triggered by ng-init when the loop finishes, which then broadcasts an event.

myModule.controller('MyCtrl', function($scope, $timeout){
    $scope.things = ['Item A', 'Item B', 'Item C'];

    $scope.fireEvent = function(){
        // Use $timeout(0) to ensure the broadcast happens after the digest cycle that processed $last
        $timeout(function(){
            $scope.$broadcast('thingsRendered');
        }, 0);
    };
});

Template:

<div ng-controller="MyCtrl">
    <div ng-repeat="thing in things">
        thing: {{ thing }}
    </div>
    <!-- Sentinel element triggers the event upon final ng-repeat evaluation -->
    <div ng-init="fireEvent()"></div>
</div>

This is mainly useful for one-time initialization tasks after the initial render. For dynamic updates, a directive watching for changes is superior.

FAQs on AngularJS NgRepeat Completion Detection Strategies

Q: What is the significance of scope.$last in ng-repeat execution

ANS: The $last property is a special property provided by the $scope of the current ng-repeat iteration. It is boolean (true) only for the final element being rendered by that specific ng-repeat directive.

Q: Should I use $timeout or setTimeout when calling DOM manipulation code

ANS: If the code is part of the Angular framework logic or needs to run within Angular’s change detection, use $timeout. If you need pure asynchronous execution, pushing the call to the absolute end of the browser’s queue without triggering a digest cycle, native setTimeout(fn, 0) is often chosen, particularly when initializing non-Angular jQuery plugins.

Q: Can I use ng-init if the array being repeated is empty

ANS: The standard $last && finished() check in ng-init will not fire for an empty array. You must introduce a separate check, such as <div ng-if="things.length > 0" ng-init="finished()"></div> positioned near the repeat block to handle the empty state explicitly.

Q: What is the difference between using $eval and $parse in advanced scenarios

ANS: $eval executes an expression string against the current scope. $parse is a lower-level tool used to compile an expression string into a function that can then be invoked, often preferred in complex directive scenarios for better performance or when mimicking AngularJS’s internal compilation mechanisms.
