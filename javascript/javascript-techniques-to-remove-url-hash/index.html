“JavaScript Techniques to Remove URL Hash Fragment Without Page Reload”

How can developers programmatically eliminate the hash fragment (e.g., everything following the # symbol) from the current browser URL without forcing a full page reload? This is a common requirement for Single Page Applications (SPAs) or when cleaning up application state identifiers that are no longer needed in the visible URL.

Numerous solutions exist, evolving with browser capabilities, primarily leveraging the HTML5 History API.

Leveraging the HTML5 History API (pushState and replaceState)

The modern, preferred way to alter the URL in the address bar without navigating or reloading the page is by utilizing history.pushState() or history.replaceState().

Solution Set A: Using history.pushState for Non-Destructive Changes

The history.pushState() method allows us to change the current URL displayed in the browser’s address bar to a new one within the same origin. If you wish to retain the current entry in the browser’s session history, use this.

A straightforward implementation focuses only on the pathname and search query parameters:

function clearBrowserHashViaPushState() { 
    history.pushState("", document.title, window.location.pathname + window.location.search);
}

// Example of running this function
clearBrowserHashViaPushState();

This technique is broadly supported in modern browsers (Chrome 9+, Firefox 4+, Safari 5+, Opera 11.50+).

Handling Legacy Browser Fallbacks for Scroll Position

For older browsers lacking native pushState support, developers must resort to directly setting window.location.hash = "". However, this direct manipulation can cause the viewport to jump to the top of the page. To mitigate this flicker and preserve user context, scroll positions must be manually captured and restored:

function safeRemoveHashWithContextPreservation() {
    var scrollY, scrollX, loc = window.location;
    
    if ("pushState" in history) {
        // Modern method: No reload, clean URL update
        history.pushState("", document.title, loc.pathname + loc.search);
    } else {
        // Legacy fallback: Direct hash manipulation with scroll restoration
        scrollY = window.scrollY || document.documentElement.scrollTop;
        scrollX = window.scrollX || document.documentElement.scrollLeft;

        loc.hash = "";

        // Restore scroll position immediately to avoid visible jump
        window.scrollTo(scrollX, scrollY);
    }
}

Solution Set B: Using history.replaceState to Modify Current History Entry

If the goal is specifically to replace the current entry in the browser history (i.e., the user pressing “back” won’t return to the hash-included URL), history.replaceState() is the appropriate tool.

Alternative 1: Replacing with a Minimal Path

This example replaces the URL with just a path component (often setting it to / or a single character like .):

// Replaces the current URL state with a minimalist path, ignoring the hash
history.replaceState(null, null, ' ');

Alternative 2: Preserving Path/Search and Removing Hash

A cleaner approach using replaceState combines splitting the current URL to isolate the part before the hash:

function replaceHashWithSplit() {
    if (window.location.href.includes('#')) {
        const cleanedUrl = window.location.href.split('#')[0];
        window.history.replaceState(null, null, cleanedUrl);
    }
}

Alternative 3: Using the URL Object

Constructing a URL object provides a programmatic way to manipulate URL parts before applying the change via replaceState:

const currentUrl = new URL(window.location);
currentUrl.hash = ''; // Clears the hash component
history.replaceState(null, document.title, currentUrl);

Alternative 4: Using Regular Expressions

Regular expressions offer a robust pattern-matching way to strip everything from the hash onwards:

function removeHashViaRegex() {
    var urlWithoutHash = window.location.href.replace(/#.*$/, '');
    window.history.replaceState('', document.title, urlWithoutHash); 
}

// Execute immediately upon page load for cleanup
window.addEventListener("load", removeHashViaRegex);

Direct Location Manipulation (Causes Reload or Jumps)

Before the widespread adoption of the History API, manipulating window.location.href was standard, but it forces a full page reload, which is usually undesirable for this specific task.

If you only change window.location.hash (e.g., window.location.hash = ""), the page will not reload, but if the hash corresponded to an element ID, the page will scroll to that element. Setting it to an empty string might cause an unwanted scroll to the top. Setting it to a space (window.location.hash = ' ') is sometimes suggested to prevent the jump, but this leaves a non-empty hash in the URL.

Older methods that trigger a reload:

// Causes a full page reload
var urlWithoutHash = window.location.href.split('#')[0];
window.location.href = urlWithoutHash;

Scroll Restoration After Forced Reload

One advanced, though complex, method attempts to utilize the hash value to trigger a navigation that subsequently gets corrected by pushState, explicitly managing scroll restoration first:

const hashValue = window.location.hash;
// Set scroll restoration behavior to manual before navigation
history.scrollRestoration = 'manual'; 

// Navigate to the hash location (This step causes the initial jump/load based on hash)
window.location.href = hashValue;    

// Immediately correct the URL to remove the hash using pushState
history.pushState('', document.title, window.location.pathname);

FAQs on JavaScript Techniques To Remove URL Hash

Q: Does setting window location hash to an empty string reload the page

ANS: No, setting window.location.hash = "" generally does not trigger a full page refresh, although it might cause the browser window to scroll to the top of the page if an element with an ID matching the previous hash existed.

Q: Which method is best for supporting old browsers without History API

ANS: The best fallback involves capturing document.body.scrollTop and document.body.scrollLeft, setting loc.hash = "", and then restoring those scroll positions immediately afterward.

Q: What is the difference between pushState and replaceState for this task

ANS: history.pushState() adds a new entry to the browser’s history stack, allowing the user to go ‘Back’ to the URL with the hash. history.replaceState() overwrites the current history entry, so ‘Back’ returns to the state before the URL change occurred.
