“JavaScript Techniques to Update or Add URL Query Parameters Safely”

When building dynamic web applications, manipulating the URL query string is a common requirement for state management, deep linking, and filtering. However, doing this reliably—especially while preserving existing parameters and handling URL hash fragments (#)—requires careful coding. This discussion explores several robust JavaScript functions designed to add, update, or remove URL query parameters without causing an undesired page reload.

Method 1: Utilizing Regular Expressions for Direct String Manipulation

One foundational approach involves using regular expressions to locate and replace specific key-value pairs within the URL string. This method offers fine-grained control but can become verbose when accounting for edge cases like URL hashes or the presence of existing query markers (? or &).

Basic Update Function (Solution 1)

This initial function uses regex to either replace an existing parameter or append a new one, using ? or & as the separator if needed.

/**
 * Updates an existing query parameter or adds a new one if it doesn't exist.
 * Handles the initial separator (? or &) appropriately.
 */
function updateQueryStringParameter(uri, key, value) {
  // Regex looks for ? or & followed by the key, then captures surrounding characters
  var re = new RegExp("([?&])" + key + "=.*?(&|$)", "i");
  var separator = uri.indexOf('?') !== -1 ? "&" : "?";
  
  if (uri.match(re)) {
    // Replace existing pair: $1 is the preceding ? or &, $2 is the trailing & or end of string
    return uri.replace(re, '$1' + key + "=" + value + '$2');
  } else {
    // Append new pair
    return uri + separator + key + "=" + value;
  }
}

// Example Usage:
let initialUri = "https://app.example.com/data?id=101";
let updatedUri = updateQueryStringParameter(initialUri, "page", "3"); 
// Result: "https://app.example.com/data?id=101&page=3"

let newUri = updateQueryStringParameter("https://app.example.com/data", "sort", "asc");
// Result: "https://app.example.com/data?sort=asc"

Advanced Regex Handling with Hash Fragments (Solution 3 & 5)

A significant challenge with regex solutions is preserving the URL fragment (the part after the #). More complex regex patterns are needed to isolate and maintain the hash part during query string modification.

Solution 5 provides an enhanced version that correctly handles hash tags during updates and includes logic for removing parameters by passing value === undefined.

/**
 * Updates, adds, or removes a query parameter, correctly managing URL hash anchors.
 * Removal is indicated by passing value === undefined.
 */
function updateQueryStringParameterRobust(uri, key, value) {
  var re = new RegExp("([?&])" + key + "=.*?(&|#|$)", "i");
  
  if( value === undefined ) {
    // Logic for removal
    if (uri.match(re)) {
        // Replace the match with the preceding separator and the following hash/end-of-string
        // Then clean up any resulting leading ? or &
        return uri.replace(re, '$1$2').replace(/[?&]$/, '').replace(/[?&]#/, '#');
    } else {
        return uri;
    }
  } else {
    // Logic for addition or update
    if (uri.match(re)) {
      return uri.replace(re, '$1' + key + "=" + value + '$2');
    } else {
      var hash =  '';
      if( uri.indexOf('#') !== -1 ){
          hash = uri.replace(/.*#/, '#');
          uri = uri.replace(/#.*/, ''); // Strip hash temporarily
      }
      var separator = uri.indexOf('?') !== -1 ? "&" : "?";    
      return uri + separator + key + "=" + value + hash;
    }
  }
}

// Example: Update parameter 'theme' and preserve hash
let urlWithHash = "http://site.com/settings?theme=light#advanced";
let resultHashUpdate = updateQueryStringParameterRobust(urlWithHash, 'theme', 'dark');
// Result: "http://site.com/settings?theme=dark#advanced"

// Example: Remove parameter 'theme'
let resultHashRemove = updateQueryStringParameterRobust(urlWithHash, 'theme', undefined);
// Result: "http://site.com/settings#advanced"

Method 2: Modern Browser API with URLSearchParams

For modern browsers (and environments supporting it, often via polyfills like URL in Node.js or RN), the built-in URLSearchParams interface provides the cleanest, most reliable way to manage query strings. It handles encoding and edge cases automatically.

Setting a Parameter on the Current URL (Solution 4 & 30)

If you intend to modify the current browser URL without reloading the page (e.g., for state management), the History API (history.pushState or history.replaceState) is essential alongside URLSearchParams.

/**
 * Updates a query parameter in the current window.location without reloading the page.
 */
function setQueryParamHistory(key, value) {
  // 1. Construct a URL object from the current location
  const url = new URL(window.location.href);
  
  // 2. Use searchParams to set/update the key
  url.searchParams.set(key, value); 
  
  // 3. Update history without triggering a navigation event
  window.history.replaceState({}, '', url);
}

// Example: Change page number without a full server reload
setQueryParamHistory('pageNumber', 5); 
// Current URL changes from ?pageNumber=4 to ?pageNumber=5 in the address bar.

Generating a New URL with Multiple Parameters (Solution 6)

When building a new URL from a base and a set of parameters, URL and URLSearchParams simplify the process significantly.

/**
 * Creates a new URL string by setting multiple parameters onto a base URL.
 */
const getUriWithParam = (baseUrl, params) => {
  // URL constructor handles parsing the base URL, including any existing search/hash
  const Url = new URL(baseUrl);
  const urlParams = new URLSearchParams(Url.search);
  
  for (const key in params) {
    // Check ensures we only process own properties and skip undefined values if desired
    if (Object.prototype.hasOwnProperty.call(params, key) && params[key] !== undefined) {
      urlParams.set(key, params[key]);
    }
  }
  
  Url.search = urlParams.toString();
  return Url.href;
};

// Example Usage:
const base = "https://shop.com/products?filter=new&limit=10";
const updates = { filter: "sale", sort: "price_asc", page: 2 };

const finalUrl = getUriWithParam(base, updates);
// Expected Result: "https://shop.com/products?filter=sale&limit=10&sort=price_asc&page=2"

Method 3: Utilizing the DOM Anchor Element for Parsing (Solution 24)

Leveraging a temporary <a> element (the DOM URL parser technique) allows JavaScript to parse the components of a URL (protocol, hostname, search, hash) reliably, as demonstrated in Solution 24. This approach avoids complex regex for parsing the initial URL structure, though the assembly still requires care.

var anchorElement = document.createElement('a');

function updatedQueryString(url, param, value) {
    // Ensure the new fragment is properly encoded
    var fragment = encodeURIComponent(param) + '=' + encodeURIComponent(value);

    anchorElement.href = url;

    if (anchorElement.search.length === 0) {
        anchorElement.search = '?' + fragment;
    } else {
        var parts = anchorElement.search.substring(1).split('&');
        var reassembled = [];
        var didReplace = false;
        
        for (var i = 0; i < parts.length; i++) {
            var pieces = parts[i].split('=');
            if (pieces[0] === param) {
                if (!didReplace) {
                    reassembled.push('&' + fragment);
                    didReplace = true;
                }
            } else {
                reassembled.push(parts[i]);
            }
        }

        if (!didReplace) {
            reassembled.push('&' + fragment);
        }

        // Join pieces back together, starting with '&' as the initial split removed '?'
        anchorElement.search = reassembled.join('&');
    }

    return anchorElement.href;
};

Alternative Solution: Modifying Location Search Directly (Simple but Reloads)

If a full page reload is acceptable or desired (for example, when submitting a traditional form that relies on the URL refresh), directly setting window.location.search is the quickest route (Solution 8 & 19). Be cautious: This action forces the browser to request the new URL, causing a page refresh.

// Caution: This causes a page reload.
window.location.search = 'newParam=value&existingParam=old';

FAQs on JavaScript Update URL Query Parameters

Q: How do I update a query parameter without reloading the page

ANS: Use the URL object combined with the History API. Construct the new URL using new URL(window.location.href) and url.searchParams.set(), then apply the change via window.history.replaceState(null, '', url).

Q: Which method is best for handling URL fragments like #section

ANS: Methods utilizing the native URL API (like Solution 30) or specialized regex functions that explicitly isolate the hash component (like Solution 5) handle fragments most reliably during query string updates.

Q: What if URLSearchParams is not available in my target environment

ANS: If modern APIs are unavailable, rely on robust, well-tested regex solutions (like Solution 5 or 26) or older DOM parsing techniques (Solution 24). For Node.js environments lacking the browser URL implementation, installing a polyfill may be necessary.

Q: Can I remove a query parameter using these techniques

ANS: Yes. Many of the advanced solutions support parameter removal. In Solution 5, passing undefined as the value triggers the removal logic within the function. Using URLSearchParams.delete('key') is the native way to achieve this.
