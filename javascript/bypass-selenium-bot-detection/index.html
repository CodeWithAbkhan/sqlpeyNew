“Bypass Selenium Bot Detection: Essential Strategies and Code”

Yes, websites can and often do detect when a browser is being controlled by Selenium WebDriver, particularly with ChromeDriver. This detection is usually implemented to prevent automated access, protect against malicious bots, and ensure fair usage of online resources. The methods range from inspecting JavaScript variables and browser properties to analyzing user behavior patterns.

Several techniques are employed by websites to identify automated browsers:

  • JavaScript Variable Inspection: Detection scripts look for specific JavaScript variables or properties that are unique to the Selenium environment. These might include variables containing “selenium” or “webdriver” in their names, or specific prefixes like $cdc_ or $wdc_.
  • navigator.webdriver Property: The navigator.webdriver property in the browser’s JavaScript environment is a key indicator. In a standard browser, this is undefined, but Selenium typically sets it to true.
  • Browser Fingerprinting: Websites can collect various browser characteristics (e.g., available plugins, installed fonts, screen resolution, WebGL renderer) to create a unique “fingerprint.” Automated browsers often have different or missing fingerprints compared to regular user browsers.
  • User Agent String: While not foolproof, the User-Agent string can sometimes reveal that a browser is running in a headless mode or under automation.
  • Behavioral Analysis: Sophisticated detection systems can analyze user behavior, such as mouse movements, typing speed, and interaction patterns. Actions that are too precise, too fast, or lack natural human variability can flag a session as automated.
  • Specific JavaScript Injections: Some detection methods involve injecting JavaScript code that specifically searches for known Selenium artifacts or modifies browser behavior in ways that are characteristic of automation.

Common Detection Mechanisms:

  • $cdc_ and $wdc_ Prefixes: As noted by an expert, modifications to JavaScript files within chromedriver can hide these prefixes. For instance, changing a detection key from $cdc_asdjflasutopfhvcZLmcfl_ to randomblabla_ can evade detection.
  • Presence of Automation Flags: Certain JavaScript variables and document properties are injected by Selenium. These include __webdriver_evaluate, __selenium_evaluate, __webdriver_script_function, _phantom, __nightmare, and _selenium, among others. The runBotDetection pseudocode example illustrates many of these checks.
  • documentElement.getAttribute('selenium') or 'webdriver': Websites can check for attributes set on the <html> tag.

How Can Selenium Detection Be Circumvented?

Several strategies and code modifications can help evade Selenium’s detection by automated browsers. The core idea is to make the automated browser appear as much like a regular, non-automated browser as possible.

Solution 1: Modifying ChromeDriver Binaries (Hex Editing/Text Replacement)

One direct method involves modifying the chromedriver executable itself to alter or remove the markers that Selenium injects.

  • Using a HEX Editor: Open chromedriver.exe with a HEX editor and replace occurrences of the string $cdc_ with another string of the same length (e.g., randomblabla_). This directly changes the internal identifiers.
  • Using Text Editors with Find/Replace (for sourced or decompiled versions): If you have access to the source code or can decompile it, you can directly edit JavaScript files. For example, in call_function.js, the line var key = '$cdc_asdjflasutopfhvcZLmcfl_'; can be changed to var key = 'randomblabla_';.

Tools for Text Replacement:

  • Vim: 
    vim -b /path/to/chromedriver
:%s/cdc_/dog_/g
:wq!
    The -b flag ensures binary mode editing, preserving file integrity. The string dog_ is an example; any string of the same length as cdc_ will work.
  • Perl: 
    perl -pi -e 's/cdc_/dog_/g' /path/to/chromedriver
    This command performs an in-place replacement of all cdc_ instances with dog_.

Verification: After modification, you can use grep "cdc_" /path/to/chromedriver to ensure no instances remain. If the command returns no output, the replacement was successful.

Solution 2: Modifying navigator.webdriver and Other Navigator Properties

The navigator.webdriver property is a primary indicator. You can override it using JavaScript executed via Selenium.

  • Setting navigator.webdriver to undefined:

    from selenium import webdriver

driver = webdriver.Chrome()
driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {
    "source": """
    Object.defineProperty(navigator, 'webdriver', {
      get: () => undefined
    })
  """
})
driver.get("https://bot.sannysoft.com/") # Example site for testing detection

    This script injects JavaScript to redefine the webdriver property, making it return undefined instead of true.

  • Modifying navigator.plugins and navigator.languages: Websites may also check the length of navigator.plugins or the values in navigator.languages. You can manually set these properties to mimic a regular browser.

    # Example for navigator.languages (Python)
driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {
    "source": """
    Object.defineProperty(navigator, 'languages', {
      get: () => ['en-US', 'en']
    });
  """
})

Solution 3: Manipulating User Agent Strings

Changing the User Agent string can disguise the browser type or indicate a more standard browsing session.

  • Rotating User Agent with fake_useragent:

    from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from fake_useragent import UserAgent

options = Options()
ua = UserAgent()
userAgent = ua.random
print(f"Using User-Agent: {userAgent}")
options.add_argument(f'user-agent={userAgent}')

# Ensure you have the correct path to your ChromeDriver executable
# For newer Selenium versions, service object is preferred
from selenium.webdriver.chrome.service import Service
service = Service(executable_path=r'C:\WebDrivers\ChromeDriver\chromedriver_win32\chromedriver.exe')
driver = webdriver.Chrome(service=service, options=options)

driver.get("https://www.google.com")
driver.quit()

    This code snippet demonstrates how to fetch a random user agent and apply it to the Chrome options.

  • Using Network.setUserAgentOverride (CDP): For more dynamic control, you can use Chrome DevTools Protocol commands.

    from selenium import webdriver

# Ensure you have the correct path to your ChromeDriver executable
service = Service(executable_path=r'C:\WebDrivers\chromedriver.exe')
driver = webdriver.Chrome(service=service)

print(f"Initial User-Agent: {driver.execute_script('return navigator.userAgent;')}")

# Setting a specific user agent
new_user_agent = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/83.0.4103.97 Safari/537.36'
driver.execute_cdp_cmd('Network.setUserAgentOverride', {"userAgent": new_user_agent})

print(f"New User-Agent: {driver.execute_script('return navigator.userAgent;')}")
driver.quit()

Solution 4: Using excludeSwitches

Certain command-line switches can be excluded when launching Chrome to hide automation indicators.

  • Disabling Automation Flags: The --enable-automation flag is often added by default. Excluding it can help. 
    from selenium.webdriver.chrome.options import Options
from selenium.webdriver.chrome.service import Service

options = Options()
options.add_experimental_option("excludeSwitches", ["enable-automation"])
options.add_experimental_option('useAutomationExtension', False)

# Ensure you have the correct path to your ChromeDriver executable
service = Service(executable_path=r'C:\BrowserDrivers\chromedriver.exe')
driver = webdriver.Chrome(service=service, options=options)
driver.get("https://bot.sannysoft.com/")
driver.quit()
    In .NET (C#): 
    var options = new ChromeOptions();
options.AddExcludedArguments(new List<string>() { "enable-automation" });
options.AddAdditionalCapability("useAutomationExtension", false);
// ... create ChromeDriver with these options

Solution 5: Leveraging Libraries like selenium-stealth and undetected-chromedriver

For more robust evasion, specialized libraries are available.

  • selenium-stealth: This Python package applies a variety of stealth patches to make Selenium more undetectable.

    pip install selenium-stealth

    from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from selenium.webdriver.chrome.service import Service
from selenium_stealth import stealth

options = Options()
options.add_argument("start-maximized")
options.add_experimental_option("excludeSwitches", ["enable-automation"])
options.add_experimental_option('useAutomationExtension', False)

service = Service(executable_path=r'C:\BrowserDrivers\chromedriver.exe')
driver = webdriver.Chrome(service=service, options=options)

stealth(driver,
        languages=["en-US", "en"],
        vendor="Google Inc.",
        platform="Win32",
        webgl_vendor="Intel Inc.",
        renderer="Intel Iris OpenGL Engine",
        fix_hairline=True,
      )

driver.get("https://bot.sannysoft.com/")
print("Page loaded with stealth applied.")
driver.quit()

  • undetected-chromedriver: This library patches ChromeDriver to bypass detection mechanisms.

    pip install undetected-chromedriver

    import undetected_chromedriver as uc
import time

# Configure options for stealth
options = uc.ChromeOptions()
options.add_argument('--headless=new') # Use the new headless mode for better compatibility

# Initialize the driver with stealth enabled
driver = uc.Chrome(options=options)

Solution 6: Disabling Blink Features

Some websites specifically check for automation-related features in the browser’s rendering engine.

  • Disabling AutomationControlled: 
    from selenium import webdriver
from selenium.webdriver.chrome.service import Service

options = webdriver.ChromeOptions()
options.add_argument('--disable-blink-features=AutomationControlled')

# Ensure you have the correct path to your ChromeDriver executable
service = Service(executable_path=r'C:\WebDrivers\ChromeDriver\chromedriver_win32\chromedriver.exe')
driver = webdriver.Chrome(service=service, options=options)

driver.get("https://skyscanner.com") # Example site where this was effective
print("Page loaded with blink features disabled.")
driver.quit()
    This approach was found effective against certain detection mechanisms, like those used by Skyscanner.

Solution 7: Headless Mode Configuration

The --headless=new flag (for Chrome 109+) provides a more modern headless implementation that behaves more like a regular browser.

from selenium import webdriver
from selenium.webdriver.chrome.options import Options

options = Options()
# Use '--headless=new' for Chrome 109+
# Use '--headless=chrome' for Chrome 96-108
options.add_argument("--headless=new")
# options.add_argument("--headless=chrome") # for older versions

# Ensure you have the correct path to your ChromeDriver executable
service = Service(executable_path=r'C:\BrowserDrivers\chromedriver.exe')
driver = webdriver.Chrome(service=service, options=options)

driver.get("https://nowsecure.nl/#relax")
print("Headless Chrome with --headless=new flag used.")
driver.quit()

Combining this with undetected-chromedriver or selenium-stealth offers layered protection.

Solution 8: Using User Profiles

Leveraging existing Chrome user profiles can make the automated session appear more legitimate.

import os
from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from selenium.webdriver.chrome.service import Service

username = os.getenv("USERNAME")
userProfile = rf"C:\Users\{username}\AppData\Local\Google\Chrome\User Data\Default"

options = Options()
options.add_argument(f"user-data-dir={userProfile}")
options.add_experimental_option(
    "excludeSwitches",
    [
        "ignore-certificate-errors",
        "safebrowsing-disable-download-protection",
        "safebrowsing-disable-auto-update",
        "disable-client-side-phishing-detection"
    ]
)

chromedriver_path = r"C:\Python27\chromedriver\chromedriver.exe"
service = Service(executable_path=chromedriver_path)
driver = webdriver.Chrome(service=service, options=options)

driver.get("https://www.google.com")
driver.quit()

This method allows Selenium to use your existing Chrome profile, including cookies and settings, potentially making it harder to detect.

Solution 9: Other Browser Options

While ChromeDriver is commonly targeted, other browsers might be less scrutinized.

  • Internet Explorer Driver: Some users have reported that the Internet Explorer driver does not trigger detection mechanisms as frequently. This is less relevant now with IE’s deprecation.

Solution 10: Behavioral Adjustments

Beyond technical configurations, simulating human-like behavior can significantly reduce detection rates.

  • Random Delays: Introduce random delays between actions using time.sleep().
  • Mouse Movements: While not always necessary, simulating natural mouse movements before clicking can sometimes help.
  • Offset Clicks: If direct clicks are detected, using Selenium to click with a small random offset from the target element might bypass certain checks.
  • Avoid Predictable Patterns: Vary interaction sequences and timing to avoid repetitive, bot-like behavior.

Are There Alternative Tools?

If bypassing detection becomes overly complex or unreliable, consider alternatives to Selenium for web scraping:

  • requests with Beautiful Soup/Scrapy: For simpler scraping tasks where JavaScript rendering isn’t critical, using requests for HTTP requests and BeautifulSoup or Scrapy for parsing HTML is often more robust and less detectable. You can pair requests with proxies and rotating user agents.
  • Puppeteer (Node.js): For JavaScript-heavy sites, Puppeteer offers Chrome/Chromium automation and has its own set of stealth plugins.
  • Playwright: Similar to Puppeteer, Playwright supports multiple browsers and offers advanced automation capabilities with built-in stealth features.

Conclusion: Proactive Evasion is Key

Websites continuously update their bot detection mechanisms. What works today might not work tomorrow. Staying updated with Selenium versions, ChromeDriver, and employing libraries like selenium-stealth or undetected-chromedriver is crucial. For persistent challenges, consider adopting alternative scraping tools or focusing on JavaScript-based solutions that are inherently harder to detect as automated.

FAQs on Bypass Selenium Bot Detection

Q How do websites detect Selenium

ANS Websites detect Selenium by looking for specific JavaScript variables (like those with “selenium” or “webdriver” in their names), the navigator.webdriver property being true, unusual browser fingerprints, or patterns in user behavior that deviate from human interaction. Specific internal markers within ChromeDriver, such as $cdc_ variables, are also common detection points.

Q What is the navigator webdriver property

ANS The navigator.webdriver property is a boolean value that indicates whether the browser is being controlled by an automated tool like Selenium. In a normal browser, this property is undefined. Selenium typically sets it to true, which is a primary signal for bot detection.

Q How can I make my Chrome browser undetectable by Selenium

ANS You can make your Chrome browser harder to detect by Selenium by:

  1. Modifying ChromeDriver’s internal strings (e.g., replacing $cdc_).
  2. Setting navigator.webdriver to undefined using JavaScript execution.
  3. Rotating or spoofing the User-Agent string.
  4. Excluding automation-related command-line switches like enable-automation.
  5. Using libraries like selenium-stealth or undetected-chromedriver.
  6. Disabling specific blink features like AutomationControlled.
  7. Utilizing the --headless=new flag for newer Chrome versions.

Q Is modifying chromedriver binary safe

ANS Modifying the chromedriver binary by itself is generally safe in terms of not corrupting your system, but it can lead to unexpected behavior or prevent chromedriver from working if done incorrectly. Always back up the original chromedriver file before making any modifications. Incorrect edits can cause chromedriver to fail to launch or function properly.

Q What is selenium stealth

ANS selenium-stealth is a Python package designed to enhance the stealth capabilities of Selenium. It applies various patches and modifications to the browser and WebDriver to circumvent common bot detection techniques, aiming to make the automated browser appear more like a regular user’s browser.

Q Can I use Python to bypass bot detection

ANS Yes, Python is widely used for bypassing bot detection with Selenium. Libraries like fake_useragent, selenium-stealth, and undetected-chromedriver are all Python-based tools that provide methods to disguise your automated browser and evade detection.
