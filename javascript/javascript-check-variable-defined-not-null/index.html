“JavaScript: Check if a Variable is Defined and Not Null”

How to Safely Check if a JavaScript Variable Exists and Has a Value

Let’s delve into the various approaches to ascertain a variable’s state, from simple existence to ensuring it’s not null or undefined.

Method 1: The typeof Operator for Undefined Checks

The typeof operator is a primary tool for checking if a variable is undefined. It returns a string indicating the type of the operand. A key advantage is that it does not throw a ReferenceError if the variable has not been declared at all.

// Check if 'myVariable' is defined
if (typeof myVariable !== 'undefined') {
    console.log("myVariable is defined.");
    // You can safely use myVariable here
} else {
    console.log("myVariable is not defined.");
}

// Check if 'anotherVariable' is specifically undefined
if (typeof anotherVariable === 'undefined') {
    console.log("anotherVariable is undefined.");
}

Important Consideration: typeof null returns "object". If you need to exclude null from your definition of “defined,” you’ll need an additional check.

if (typeof myVariable === 'undefined' || myVariable === null) {
    console.log("myVariable is undefined or null.");
}

For a more robust check that guarantees the variable is defined and not null, combine typeof with a strict equality check against null:

if (typeof myVariable !== "undefined" && myVariable !== null) {
   console.log("myVariable is defined and not null.");
}

Method 2: Loose Equality (!= null) for undefined or null

A common and often practical approach is using loose equality (== or !=) with null. The expression variable != null evaluates to true if the variable is neither undefined nor null. This is concise and handles both cases effectively.

// Checks if 'myElement' is neither undefined nor null
if (myElement != null) {
    console.log("myElement has a value (not undefined or null).");
    // Suitable for checking DOM elements or function arguments
} else {
    console.log("myElement is undefined or null.");
}

Method 3: Truthiness Check (if (variable))

JavaScript’s truthiness and falsiness can be leveraged for checks, but this requires careful attention to what constitutes “falsy.” A simple if (variable) will evaluate to false for:

  • undefined
  • null
  • 0 (the number zero)
  • '' (an empty string)
  • NaN (Not a Number)
  • false
// This checks for a "truthy" value
if (myValue) {
    console.log("myValue is truthy.");
} else {
    console.log("myValue is falsy (undefined, null, 0, '', NaN, or false).");
}

Caution: This method is less precise if 0, false, or empty strings are considered valid, meaningful values in your context. For example, checking if a user’s input is a string that might contain only spaces:

let userInput = '    '; // A string with spaces

if (userInput) {
    console.log("userInput is truthy."); // This will log, as spaces make it not empty
}

if (typeof userInput === 'string' && userInput.trim()) {
    console.log("userInput is a non-empty string after trimming.");
} else {
    console.log("userInput is empty or only contains whitespace.");
}

Also, empty arrays ([]) and empty objects ({}) are always truthy in JavaScript, so if ([]) will evaluate to true.

Method 4: The in Operator for Property Existence

The in operator checks for the presence of a property (or variable) within an object or its prototype chain. This is particularly useful for checking global variables without triggering a ReferenceError if they aren’t declared.

// Check if a global variable 'myGlobalVar' exists
if ("myGlobalVar" in window) {
    console.log("myGlobalVar is defined globally.");
} else {
    console.log("myGlobalVar is not defined globally.");
}

// You can also check for properties on specific objects
const myObject = { name: "Example" };
if ("name" in myObject) {
    console.log("myObject has a 'name' property.");
}

Note: For checking local variables within the current scope, the in operator isn’t directly applicable in the same way it is for window properties.

Method 5: try...catch for Undefined Variables

A try...catch block can be used to detect ReferenceError exceptions, which occur when trying to access an undeclared variable. This approach allows you to test for a variable’s existence without halting execution.

try {
  // Attempt to access a variable that might not be declared
  undeclaredVariable;
  console.log("undeclaredVariable is declared.");
} catch (error) {
  if (error instanceof ReferenceError) {
    console.log("detected: undeclaredVariable does not exist.");
  } else {
    console.error("An unexpected error occurred:", error);
  }
}
console.log("Code execution continues after the try-catch block.");

This is useful when you suspect a variable might not be present due to external factors, like a library not being loaded.

Method 6: Strict Comparison with undefined and void 0

While typeof variable === 'undefined' is robust, you can also use strict comparison directly with the undefined primitive. However, undefined itself can be reassigned in older JavaScript environments or non-strict modes.

A more reliable way to compare against the primitive undefined is using void 0. The void operator evaluates an expression and returns undefined.

let testVar;

// Using direct comparison (less safe if undefined is reassigned)
if (testVar === undefined) {
  console.log("testVar is strictly undefined.");
}

// Using void 0 (more robust against reassignment of undefined)
if (testVar === void 0) {
  console.log("testVar is strictly undefined (using void 0).");
}

// Example demonstrating the mutability of 'undefined'
var undefined = 'reassignedValue';
let anotherTestVar;

if (anotherTestVar === undefined) {
  console.log("anotherTestVar === reassignedValue"); // This will log
}

if (anotherTestVar === void 0) {
  console.log("anotherTestVar === void 0"); // This will NOT log incorrectly
}

Method 7: Checking Global Variables with window.hasOwnProperty

For global variables declared with var, you can use window.hasOwnProperty() to check if the variable exists as a direct property of the window object.

// Declare a global variable
var globalVar = "I am global";
var anotherGlobal; // Declared but undefined

console.log(window.hasOwnProperty("globalVar"));   // true
console.log(window.hasOwnProperty("anotherGlobal")); // true
console.log(window.hasOwnProperty("nonExistentVar")); // false

Limitation: This method does not work for variables declared with let or const at the global scope, as they do not become properties of the window object.

Method 8: Conditional Assignment with the Ternary Operator

The ternary operator provides a concise way to assign a default value if a variable is undefined.

// Assign 'defaultValue' if 'mySetting' is undefined
const setting = typeof mySetting !== 'undefined' ? mySetting : 'defaultValue';
console.log(setting);

// A common shorthand for providing defaults (handles null, undefined, false, 0, '')
const safeValue = potentialValue || 'default';

Practical Code Examples

Let’s illustrate with more practical scenarios.

Checking for a required parameter in a function:

function greetUser(name) {
    // Use loose equality for a flexible check (handles null and undefined)
    if (name != null) {
        console.log(`Hello, ${name}!`);
    } else {
        console.log("Hello, stranger!");
    }
}

greetUser("Alice");
greetUser(null);
greetUser(undefined);

Safely accessing nested properties:

When dealing with nested objects, you need to ensure each level exists before accessing the next.

const userProfile = {
    personalInfo: {
        address: {
            city: "Metropolis"
        }
    }
};

// Safely get the city name
const userCity = userProfile?.personalInfo?.address?.city || "City not specified";
console.log(userCity); // Outputs: Metropolis

const userZip = userProfile?.personalInfo?.address?.zipCode || "Zip not specified";
console.log(userZip); // Outputs: Zip not specified

Here, the optional chaining operator (?.) gracefully handles missing properties, returning undefined instead of throwing an error. The || "Zip not specified" provides a default value.

Checking if a JavaScript variable is declared within a React component:

In modern frameworks like React, ESLint’s no-undef rule often prevents using undeclared variables. If you must check for a potentially undeclared variable (e.g., from an external script), eval() can be used, but with caution due to security implications.

// Example within a React component context (conceptually)
function MyComponent({ potentiallyUndeclaredVar }) {
    // In a strict environment, directly accessing undeclaredVar would cause an error

    // Using eval to check if 'undeclaredVar' is defined
    if (eval('typeof undeclaredVar !== "undefined"')) {
        console.log("undeclaredVar is defined.");
        // Use undeclaredVar here
    } else {
        console.log("undeclaredVar is not defined.");
    }

    // A safer approach in React is to always pass defined props, even if undefined
    if (typeof potentiallyUndeclaredVar !== 'undefined') {
        console.log("potentiallyUndeclaredVar is defined.");
    } else {
        console.log("potentiallyUndeclaredVar is not defined.");
    }

    return <div>...</div>;
}

Alternative Approaches & Considerations

  • existy function: A common pattern is to create a helper function for clarity: 
    function existy(x) {
    return typeof x !== 'undefined' && x !== null;
}

if (existy(myVariable)) {
    // Variable exists and is not null
}
  • isSet function: For more nuanced checks (e.g., excluding empty strings or arrays), you might create a custom function: 
    const isSet = (val) => {
    switch (typeof val) {
        case 'number': return !isNaN(val);
        case 'string': return val.length > 0;
        case 'undefined': return false;
        case 'object':
            if (val === null) return false;
            return Object.keys(val).length > 0;
        default: return !!val; // Handles booleans and other types
    }
}

FAQs on JavaScript Variable Checks

Q: What is the most reliable way to check if a JavaScript variable is defined

ANS: The most reliable method is typically using typeof variable !== 'undefined'. This operator safely checks for declaration without throwing errors, even if the variable hasn’t been declared at all. For checking if it’s also not null, use typeof variable !== 'undefined' && variable !== null.

Q: Can I check if a variable is defined without using typeof

ANS: Yes, you can use variable != null which checks for both undefined and null. Additionally, the in operator can check for the existence of properties within an object or the window object. A try...catch block can also catch ReferenceError for undeclared variables.

Q: What is the difference between undefined and null in JavaScript

ANS: null represents the intentional absence of any object value and is explicitly assigned. undefined signifies that a variable has been declared but has not yet been assigned a value, or that a property does not exist on an object. Loose comparison (==) treats null and undefined as equal, while strict comparison (===) differentiates them.

Q: Why is typeof null an object in JavaScript

ANS: This is a historical quirk in JavaScript’s design. The typeof operator was implemented early on, and null was intended to represent the absence of an object. Consequently, typeof null returning "object" is a known inconsistency that developers must account for.

Q: How does the 'in' operator work for variable checks

ANS: The in operator checks if a specified property (or variable name, when referring to global scope like window) exists in an object or its prototype chain. For example, "propertyName" in object returns true if the property exists. When checking global variables, you can use "variableName" in window.

Q: What are the falsy values in JavaScript

ANS: The falsy values in JavaScript are false, 0 (number zero), "" (empty string), null, undefined, and NaN (Not a Number). Any other value is considered truthy.
