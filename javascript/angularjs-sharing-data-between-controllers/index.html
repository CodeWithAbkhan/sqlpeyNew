“AngularJS: Sharing Data Between Controllers Effectively”

When building AngularJS applications, a common requirement is to enable communication and data sharing between different controllers. This allows for dynamic updates and consistent user experiences across your application. Several techniques can be employed, each with its own advantages. This post will delve into various practical methods, providing code examples and explanations to help you select the most suitable approach for your needs.

Leveraging AngularJS Services (Factories and Services)

A highly recommended and robust method for sharing data across controllers is by utilizing AngularJS services, specifically factories or services. These act as singletons, ensuring a consistent instance is available throughout your application.

Solution 1: Using a Factory for Product Data

This approach defines a productService factory to manage a list of products.

app.factory('productService', function() {
  var productList = []; // Private array to hold products

  // Function to add a new product
  var addProduct = function(newObj) {
    productList.push(newObj);
  };

  // Function to retrieve all products
  var getProducts = function() {
    return productList;
  };

  // Return the public API of the service
  return {
    addProduct: addProduct,
    getProducts: getProducts
  };
});

// ProductController to add items to the service
app.controller('ProductController', function($scope, productService) {
  $scope.callToAddToProductList = function(currObj) {
    productService.addProduct(currObj);
  };
});

// CartController to display items from the service
app.controller('CartController', function($scope, productService) {
  $scope.products = productService.getProducts();
});

In this example, ProductController adds an item via productService.addProduct(), and CartController retrieves the list using productService.getProducts().

Solution 4: Utilizing a Generic Sharing Service

A more generic shareDataService can be created to manage any type of shared list.

app.service('shareDataService', function() {
  var myList = []; // Private array for shared data

  // Function to add an item to the list
  var addList = function(newObj) {
    myList.push(newObj);
  };

  // Function to retrieve the list
  var getList = function() {
    return myList;
  };

  // Return the public API
  return {
    addList: addList,
    getList: getList
  };
});

Solution 12 & 13: Factory for Shared Scope

A factory can be used to hold a shared object, allowing controllers to interact with the same data.

var app = angular.module("home", []);

app.controller('one', function($scope, ser1){
  $scope.inputText = ser1; // Bind input text to the factory object
});

app.controller('two', function($scope, ser1){
  $scope.inputTextTwo = ser1; // Bind input text to the factory object
});

// Factory to provide a shared object
app.factory('ser1', function(){
  return { o: '' }; // 'o' is the shared property
});

The associated HTML would look like this:

<div ng-app='home'>
  <div ng-controller='one'>
    Type in text:
    <input type='text' ng-model="inputText.o"/>
  </div>
  <br />
  <div ng-controller='two'>
    Type in text:
    <input type='text' ng-model="inputTextTwo.o"/>
  </div>
</div>

This setup allows changes made in one controller’s input to be reflected in the other. For a live demonstration, check this jsfiddle .

Solution 16: Using a Service for Centralized Data

A service can hold a data object that controllers can directly access and modify.

var custApp = angular.module("custApp", []);
custApp.controller('FirstController', FirstController)
  .controller('SecondController', SecondController)
  .service('sharedData', SharedData);

FirstController.$inject = ['sharedData'];
function FirstController(sharedData) {
  this.data = sharedData.data; // Reference to shared data
}

SecondController.$inject = ['sharedData'];
function SecondController(sharedData) {
  this.data = sharedData.data; // Reference to shared data
}

function SharedData() {
  this.data = {
    value: 'default Value' // The shared data object
  };
}

HTML representation:

<div ng-controller="FirstController as vm">
  <input type=text ng-model="vm.data.value" />
</div>

<div ng-controller="SecondController as vm">
  Second Controller<br>
  {{vm.data.value}}
</div>

Event Communication with $rootScope.$broadcast and $scope.$on

Another powerful mechanism is using event broadcasting and listening. A controller can broadcast an event with data, and other controllers can subscribe to these events.

Solution 2: Broadcasting Events for Communication

You can trigger a broadcast from a controller or service.

// From a controller or service
$rootScope.$broadcast('SOME_TAG', 'your value');

The receiving controller would set up a listener:

$scope.$on('SOME_TAG', function(response) {
  // Handle the received data
});

Solution 2 (Extended): Broadcasting from a Service

If you need to broadcast from within a service (since services cannot directly inject $scope), you can inject $rootScope.

app.service('productService', function($rootScope) {
  // ... service logic ...
  // $rootScope.$broadcast('SOME_TAG', 'your value'); // Example broadcast
});

Solution 15: Sending and Listening to Broadcasts

This demonstrates sending data and then listening for it.

// Sending data
$rootScope.$broadcast('SOME_TAG', 'my variable');

// Listening for data
$scope.$on('SOME_TAG', function(event, args) {
  console.log("My variable is", args); // 'args' contains the broadcasted value
});

Solution 6: Simple Event Broadcasting

A basic example of broadcasting an event.

angular.module('testAppControllers', [])
  .controller('ctrlOne', function ($scope) {
    $scope.$broadcast('test'); // Broadcast a 'test' event
  })
  .controller('ctrlTwo', function ($scope) {
    $scope.$on('test', function() {
      // Listener for the 'test' event
    });
  });

Solution 14: Understanding $emit, $broadcast, and $on

Both $scope and $rootScope provide $emit, $broadcast, and $on methods, facilitating a publish/subscribe pattern. Learn more about this pattern in AngularJS.

Using $rootScope for Global Properties

The $rootScope can be used to share properties across all controllers, essentially acting as a global variable. While simple, it’s generally advised to use services for more structured data sharing.

Solution 3: Sharing Properties via $rootScope

var app = angular.module('mymodule',[]);

app.controller('Ctrl1', ['$scope','$rootScope',
  function($scope, $rootScope) {
    $rootScope.showBanner = true; // Set a global property
  }
]);

app.controller('Ctrl2', ['$scope','$rootScope',
  function($scope, $rootScope) {
    $rootScope.showBanner = false; // Modify the global property
  }
]);

In your template, you can access these properties via $root:

<div ng-controller="Ctrl1">
  <div class="banner" ng-show="$root.showBanner"></div>
</div>

Utilizing sessionStorage and $localStorage

For data persistence across browser sessions or for simpler sharing, sessionStorage and $localStorage (via the ngStorage module or similar) are viable options.

Solution 8 & 17: Using sessionStorage

sessionStorage stores data for the duration of the browser session.

// Setting data
$window.sessionStorage.setItem("Mydata", data);

// Retrieving data
$scope.data = $window.sessionStorage.getItem("Mydata");

Solution 9: Using $localStorage

$localStorage provides a persistent way to store data in the browser’s local storage.

// Setting a selected product
app.controller('ProductController', function($scope, $localStorage) {
  $scope.setSelectedProduct = function(selectedObj) {
    $localStorage.selectedObj = selectedObj;
  };
});

// Retrieving the selected product
app.controller('CartController', function($scope, $localStorage) {
  $scope.selectedProducts = $localStorage.selectedObj;
  $localStorage.$reset(); // Optional: to remove the item
});

You can also implement logic to handle cases where data might not exist:

if ($localStorage.selectedObj) {
  $scope.selectedProducts = $localStorage.selectedObj;
} else {
  // Redirect to select product using $location.url('/select-product')
}

Other Data Sharing Patterns

Solution 5: Nested Data Structures

Sharing data can be simplified by using nested objects on the $scope.

// Instead of:
$scope.customer = {};

// Use:
$scope.data = { customer: {} };

The data property, being on a higher scope, is inherited and can be modified by child controllers.

Solution 7: Visitor Pattern for Notifications

This pattern allows one controller to notify another when data changes, without direct broadcasting.

myApp.service('myService', function() {
  var visitors = [];
  var myData = ["some", "list", "of", "data"];

  var registerVisitor = function(visitor) {
    visitors.push(visitor);
  };

  var notifyAll = function() {
    for (var index = 0; index < visitors.length; ++index) {
      visitors[index].visit();
    }
  };

  var setData = function(newData) {
    myData = newData;
    notifyAll(); // Notify all registered visitors
  };

  var getData = function() {
    return myData;
  };

  return {
    registerVisitor: registerVisitor,
    setData: setData,
    getData: getData
  };
});

myApp.controller('firstController', ['$scope', 'myService',
  function($scope, myService) {
    $scope.updateData = function(data) {
      myService.setData(data); // Update data via service
    };
  }
]);

myApp.controller('secondController', ['$scope', 'myService',
  function($scope, myService) {
    myService.registerVisitor(this); // Register this controller as a visitor

    this.visit = function() {
      $scope.data = myService.getData(); // Update scope when data changes
    };

    $scope.data = myService.getData(); // Initial data load
  }
]);

Solution 10: Route-Aware Shared Scope Management

A custom service can manage shared scope based on route paths, automatically destroying shared data when navigating away from a route’s parent path.

.controller('CadastroController', ['$scope', 'RouteSharedScope',
  function($scope, routeSharedScope) {
    var customerScope = routeSharedScope.scopeFor('/Customer'); // Get scope for '/Customer'
    // var indexScope = routeSharedScope.scopeFor('/'); // Example for root path
  }
])

This helps in managing shared data lifecycle tied to specific routes, preventing memory leaks or stale data. You can find a sample at http://plnkr.co/edit/OL8of9 .

Solution 11: Simple Cache Service

A cache service can be implemented to store and retrieve data efficiently.

angular.service('cache', function() {
  var _cache = {};

  var _store = function(data) {
    angular.merge(_cache, data); // Merge data into the cache
  };

  var _set = function(data) {
    _cache = angular.extend({}, data); // Replace cache with new data
  };

  var _get = function(key) {
    if (key == null) {
      return _cache; // Return entire cache if no key is provided
    } else {
      return _cache[key]; // Return specific cached item
    }
  };

  var _clear = function() {
    _cache = {}; // Clear the entire cache
  };

  return {
    get: _get,
    set: _set,
    store: _store,
    clear: _clear
  };
});

FAQs on AngularJS Controller Data Sharing

Q: What is the best way to share data between unrelated controllers

ANS: Using an AngularJS service (factory or service) is generally the most robust and maintainable approach for sharing data between unrelated controllers. Services act as singletons, providing a centralized place to store and manage your data, accessible by any controller that injects it. This avoids tight coupling and promotes cleaner code architecture.

Q: When should I use $rootScope for data sharing

ANS: Using $rootScope for data sharing is suitable for very simple global states or flags that need to be accessed by many parts of your application, like a global loading indicator. However, for complex data structures or business logic, relying on services is preferred due to better organization and testability. Overusing $rootScope can lead to harder-to-debug applications.

Q: How does event broadcasting with $broadcast and $on work

ANS: $rootScope.$broadcast(’eventName’, data) sends an event downwards through the scope hierarchy, and any controller can listen for it using $scope.$on(’eventName’, callback). This is useful for communicating changes or triggering actions between controllers without direct service dependency, adhering to the publish/subscribe pattern.

Q: Can I share data between controllers that are not nested

ANS: Yes, absolutely. Services are the primary mechanism for sharing data between controllers that are not nested. By creating a service, you establish a shared state that can be injected into any controller that needs access to it. Event broadcasting ($broadcast/$on) is another method for non-nested controllers.

Q: What is the difference between AngularJS services and factories

ANS: In practice, there’s very little difference between AngularJS service and factory. Both return a singleton object. A factory is a function that returns an object, and a service is a constructor function whose instance is returned. For most use cases, you can choose either based on your preference.
