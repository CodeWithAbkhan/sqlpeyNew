“JavaScript Circular References: Safely Stringify Objects”

When working with complex JavaScript objects, especially those with nested structures or self-referential properties, you might encounter the frustrating TypeError: cyclic object value. This error typically occurs when JSON.stringify() attempts to serialize an object that contains a circular reference, meaning an object directly or indirectly refers back to itself. Standard JSON serialization cannot handle this, as it would lead to an infinite loop. Fortunately, several strategies and libraries exist to address this challenge, allowing you to serialize such objects effectively.

The core issue is that a circular reference creates an endless loop during serialization. JSON.stringify() is designed to traverse an object’s properties and convert them into a JSON string. When it encounters a reference back to an object already in the serialization path, it doesn’t know how to represent this without infinite repetition.

Here are various approaches to handle circular references during JavaScript object stringification, ranging from built-in methods to external libraries:

Solutions

Solution 1: Using util.inspect in Node.js

For Node.js environments, the built-in util module provides the inspect function, which can gracefully handle circular references by replacing them with [Circular].

How it works: The util.inspect() function is specifically designed for inspecting the properties of JavaScript objects. It has built-in logic to detect and represent circular references, preventing the infinite loop.

Code Example:

import { inspect } from 'util'; // Or: const util = require('util');

// Define an object with a circular reference
const circularObject = {
  id: 1,
  name: "Example",
  link: null
};
circularObject.link = circularObject; // Creating the circular reference

// Inspect the object to stringify it safely
console.log(inspect(circularObject, { showHidden: false, depth: null, colors: true }));

Customization: The inspect function accepts an optional options object to control the output, such as showHidden (to include symbols and non-enumerable properties), depth (to control recursion depth, set to null for infinite depth), and colors (to enable colored output).

import * as util from 'util' // has no default export
import { inspect } from 'util' // or directly
// or 
var util = require('util')
console.log(util.inspect(myObject))
inspect(myObject[, options: {showHidden, depth, colors, showProxy, ...moreOptions}])

Solution 2: Custom Replacer Function with JSON.stringify

You can leverage the second argument of JSON.stringify(), the replacer function, to keep track of visited objects and handle circular references.

How it works: The replacer function is called for each key-value pair during serialization. By maintaining a cache (e.g., a Set or an array) of objects already processed, you can detect and replace circular references with a placeholder.

Code Example (using Set for efficiency):

const circularObject = {
  id: 1,
  data: { value: "test" },
  backlink: null
};
circularObject.backlink = circularObject;

function safeStringify(obj, indent = 2) {
  let cache = new Set();
  const result = JSON.stringify(
    obj,
    (key, value) => {
      if (typeof value === "object" && value !== null) {
        if (cache.has(value)) {
          // Circular reference found, return a placeholder
          return "[Circular Reference]";
        }
        // Store the value in the cache
        cache.add(value);
      }
      return value;
    },
    indent
  );
  cache = null; // Allow garbage collection
  return result;
}

console.log(safeStringify(circularObject));

Note: This approach, like many replacer-based solutions, will also replace duplicate non-circular object references with the same placeholder if they appear multiple times in the object structure.

// Demo: Circular reference
var circ = {};
circ.circ = circ;

// Note: cache should not be re-used by repeated calls to JSON.stringify.
var cache = [];
JSON.stringify(circ, (key, value) =&gt; {
  if (typeof value === 'object' &amp;&amp; value !== null) {
    // Duplicate reference found, discard key
    if (cache.includes(value)) return;

    // Store value in our collection
    cache.push(value);
  }
  return value;
});
cache = null; // Enable garbage collection
var a = {b:1}
var o = {};
o.one = a;
o.two = a;
// one and two point to the same object, but two is discarded:
JSON.stringify(o, ...);
// safely handles circular references
JSON.safeStringify = (obj, indent = 2) =&gt; {
  let cache = [];
  const retVal = JSON.stringify(
    obj,
    (key, value) =&gt;
      typeof value === "object" &amp;&amp; value !== null
        ? cache.includes(value)
          ? undefined // Duplicate reference found, discard key
          : cache.push(value) &amp;&amp; value // Store value in our collection
        : value,
    indent
  );
  cache = null;
  return retVal;
};

Solution 3: Using WeakSet for a More Robust Replacer

A more refined replacer function utilizes WeakSet to store seen objects. WeakSet is beneficial because it doesn’t prevent garbage collection of the objects it holds, which is crucial for long-lived applications.

How it works: WeakSet allows you to store object references. If an object is encountered that is already in the WeakSet, it signifies a circular reference.

Code Example:

const circularRef = { data: "some data", self: null };
circularRef.self = circularRef;

const getCircularReplacer = () => {
  const seen = new WeakSet();
  return (key, value) => {
    if (typeof value === "object" && value !== null) {
      if (seen.has(value)) {
        // Circular reference detected
        return "[Circular]";
      }
      seen.add(value);
    }
    return value;
  };
};

const stringifiedCircular = JSON.stringify(circularRef, getCircularReplacer());
console.log(stringifiedCircular);

Advantage: WeakSet is more memory-efficient than a regular Set for this purpose.

const circularReference = {otherData: 123};
circularReference.myself = circularReference;

Solution 5: Douglas Crockford’s cycle.js

Douglas Crockford, the creator of JSON, also developed a cycle.js utility that provides JSON.decycle and JSON.retrocycle functions.

How it works: JSON.decycle modifies the object to replace circular references with $ref pointers. JSON.JSON.retrocycle can then be used to restore the original object structure.

Code Example:

// Assume cycle.js is included or imported
// const { decycle, retrocycle } = require('cycle');

const circularObject = {
  name: "Root",
  child: {
    name: "Child",
    parent: null
  }
};
circularObject.child.parent = circularObject;

// Decycle the object
const decycledObject = decycle(circularObject);
console.log(JSON.stringify(decycledObject));
// Example output: {"name":"Root","child":{"name":"Child","$ref":"$"}}

// To restore the object (if needed):
// const originalObject = retrocycle(decycledObject);
// console.log(originalObject);

Limitations: As noted, this method might not work seamlessly with DOM nodes without modifications.

JSON.stringifyOnce = function(obj, replacer, indent){
    var printedObjects = [];
    var printedObjectKeys = [];

    function printOnceReplacer(key, value){
        if ( printedObjects.length &gt; 2000){ // browsers will not print more than 20K, I don't see the point to allow 2K.. algorithm will not be fast anyway if we have too many objects
        return 'object too long';
        }
        var printedObjIndex = false;
        printedObjects.forEach(function(obj, index){
            if(obj===value){
                printedObjIndex = index;
            }
        });

        if ( key == ''){ //root element
             printedObjects.push(obj);
            printedObjectKeys.push("root");
             return value;
        }

        else if(printedObjIndex+"" != "false" &amp;&amp; typeof(value)=="object"){
            if ( printedObjectKeys[printedObjIndex] == "root"){
                return "(pointer to root)";
            }else{
                return "(see " + ((!!value &amp;&amp; !!value.constructor) ? value.constructor.name.toLowerCase()  : typeof(value)) + " with key " + printedObjectKeys[printedObjIndex] + ")";
            }
        }else{

            var qualifiedKey = key || "(empty key)";
            printedObjects.push(value);
            printedObjectKeys.push(qualifiedKey);
            if(replacer){
                return replacer(key, value);
            }else{
                return value;
            }
        }
    }
    return JSON.stringify(obj, printOnceReplacer, indent);
};

Solution 6: Simple Iteration and String Concatenation (for basic cases)

For simpler objects where JSON.stringify fails, a basic loop can sometimes provide a string representation, though it won’t produce standard JSON.

How it works: This approach iterates through the object’s properties and concatenates them into a string. It’s a fallback for when structured JSON is not strictly required.

Code Example:

const circularObject = {
  config: "settings",
  loop: null
};
circularObject.loop = circularObject;

let outputString = '';
for (const property in circularObject) {
  if (circularObject.hasOwnProperty(property)) {
    // Basic handling for object properties; deeper nesting isn't properly serialized.
    outputString += `${property}: ${circularObject[property]}; `;
  }
}
console.log(outputString);
// Potential output: "config: settings; loop: [object Object]; "

Caveats: This method is very rudimentary. It does not produce valid JSON and struggles with nested objects or complex data types.

var a = [];

Solution 7: Using Object.assign with a Replacer (Conceptual)

While not a direct replacement for JSON.stringify, one can conceptualize using Object.assign with a custom mechanism to copy properties and avoid circular references, but this is more for deep copying than stringification.

How it works: A custom function could iterate through an object’s properties. If a property is an object, it could be recursively copied, while keeping track of parent objects to avoid infinite loops.

Note: This is generally more complex and less efficient than using dedicated libraries or the util.inspect method for serialization purposes.

const customStringify = function (v) {
  const cache = new Set();
  return JSON.stringify(v, function (key, value) {
    if (typeof value === 'object' &amp;&amp; value !== null) {
      if (cache.has(value)) {
        // Circular reference found
        try {
          // If this value does not reference a parent it can be deduped
         return JSON.parse(JSON.stringify(value));
        }
        catch (err) {
          // discard key if value cannot be deduped
         return;
        }
      }
      // Store value in our set
      cache.add(value);
    }
    return value;
  });
};

Solution 10: treedoc Library

treedoc is a library designed for serializing complex JavaScript objects, including those with circular references, and offers features for viewing the serialized data in a structured, navigable format.

Installation:

yarn add treedoc

Code Example:

import { TD, TDEncodeOption } from 'treedoc';

const obj = { data: "value", circular: null };
obj.circular = obj;

const serialized = TD.stringify(obj);
console.log(serialized);
// Example output: {"data":"value","circular":"$ref:$"}

function newCircularReplacer () {
  const seenValues = []
  return circularReplacer

  function circularReplacer (key, value) {
    if (typeof value === 'object' &amp;&amp; value !== null &amp;&amp; Object.keys(value).length) {
      const stackSize = seenValues.length
      if (stackSize) {
        for (let n = stackSize - 1; seenValues[n][key] !== value; --n) seenValues.pop() // Clean up expired references
        if (seenValues.includes(value)) return '[Circular]'
      }
      seenValues.push(value)
    }
    return value
  }
}

o.b = o // Circular reference

FAQs on JavaScript Circular References

FAQs on JavaScript Circular References

Q: What causes the 'cyclic object value' error in JavaScript

ANS: This error occurs when JSON.stringify() encounters an object that directly or indirectly refers back to itself, creating an infinite loop during serialization.

Q: How does `util.inspect` handle circular references

ANS: util.inspect in Node.js replaces circular references with a placeholder string like [Circular] instead of entering an infinite loop.

Q: Can I use a replacer function with `JSON.stringify` for circular references

ANS: Yes, a replacer function can track visited objects and return a placeholder for any detected circular references. Using WeakSet within the replacer is a memory-efficient approach.

Q: What is the advantage of using `WeakSet` in a replacer

ANS: WeakSet does not prevent garbage collection of the objects it holds, making it more memory-efficient for tracking visited objects during serialization, especially for large or long-running processes.

Q: Are there any npm packages for handling circular references

ANS: Yes, libraries like flatted (successor to circular-json), json-stringify-safe, superserial, and treedoc are specifically designed to serialize objects with circular references.

Q: What is Douglas Crockford's `cycle.js` and how does it work

ANS: Douglas Crockford’s cycle.js provides decycle to replace circular references with $ref pointers and retrocycle to restore the original object structure.

Q: Does `flatted` allow deserialization of objects with circular references

ANS: Yes, flatted not only serializes objects with circular references but also provides a parse function to deserialize them back into their original structure.

Q: What is a simple alternative if I don't need standard JSON output

ANS: For very basic cases, manual iteration and string concatenation can provide a string representation, but it does not produce valid JSON and lacks robustness for complex objects.

Q: How does `superserial` handle circular references

ANS: superserial uses a system of references (e.g., $1, $2) to represent repeated or circular structures, allowing for efficient serialization and deserialization.

Q: Can `treedoc` visualize circular references

ANS: Yes, treedoc can serialize objects with circular references and its accompanying viewer allows for navigating these references within the serialized data.

/**
 * Traverses a javascript object, and deletes all circular values
 * @param source object to remove circular references from
 * @param censoredMessage optional: what to put instead of censored values
 * @param censorTheseItems should be kept null, used in recursion
 * @returns {undefined}
 */
function preventCircularJson(source, censoredMessage, censorTheseItems) {
    //init recursive value if this is the first call
    censorTheseItems = censorTheseItems || [source];
    //default if none is specified
    censoredMessage = censoredMessage || "CIRCULAR_REFERENCE_REMOVED";
    //values that have allready apeared will be placed here:
    var recursiveItems = {};
    //initaite a censored clone to return back
    var ret = {};
    //traverse the object:
    for (var key in source) {
        var value = source[key]
        if (typeof value == "object") {
            //re-examine all complex children again later:
            recursiveItems[key] = value;
        } else {
            //simple values copied as is
            ret[key] = value;
        }
    }
    //create list of values to censor:
    var censorChildItems = [];
    for (var key in recursiveItems) {
        var value = source[key];
        //all complex child objects should not apear again in children:
        censorChildItems.push(value);
    }
    //censor all circular values
    for (var key in recursiveItems) {
        var value = source[key];
        var censored = false;
        censorTheseItems.forEach(function (item) {
            if (item === value) {
                censored = true;
            }
        });
        if (censored) {
            //change circular values to this
            value = censoredMessage;
        } else {
            //recursion:
            value = preventCircularJson(value, censoredMessage, censorChildItems.concat(censorTheseItems));
        }
        ret[key] = value

    }

    return ret;
}
