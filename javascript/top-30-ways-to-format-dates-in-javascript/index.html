“top-30-ways-to-format-dates-in-javascript”

Formatting dates in JavaScript is a common requirement for web development, reporting, and data display. While the native Date object provides fundamental capabilities, achieving specific output formats or handling internationalization can sometimes be complex. This comprehensive guide details a wide array of methods, from built-in browser APIs to popular external libraries, ensuring you can tailor date representations precisely to your needs.

Top Methods to Format Dates in JavaScript

Here are various robust and flexible approaches to format dates in your JavaScript applications:

Method 1: Utilizing Date.prototype.toLocaleDateString for Locale-Specific Formats

The toLocaleDateString() method offers a straightforward way to create standard, locale-specific date renderings. It provides granular control over output through optional locale and options arguments, allowing applications to specify the desired language conventions and customize the display of date components. This method is ideal when you need a balance between formatting flexibility and adherence to international standards without complex manual parsing.

Available Option Keys:

  • day: “numeric” (e.g., 17), “2-digit” (e.g., 03)
  • weekday: “narrow” (e.g., S), “short” (e.g., Sat), “long” (e.g., Saturday)
  • year: “numeric” (e.g., 2016), “2-digit” (e.g., 16)
  • month: “numeric” (e.g., 9), “2-digit” (e.g., 09), “narrow” (e.g., S), “short” (e.g., Sep), “long” (e.g., September)
  • hour: “numeric”, “2-digit”
  • minute: “numeric”, “2-digit”
  • second: “numeric”, “2-digit”
  • hour12: true or false (for 12-hour or 24-hour time format)

All these keys are optional. Adjusting their values determines the presence and representation of each date/time component.

Important Note: If you intend to configure only the content options but still use the current locale, pass undefined (not null) as the first parameter to avoid errors.

Examples with Different Locales:

  • "en-US": For American English
  • "en-GB": For British English
  • "hi-IN": For Hindi (India)
  • "ja-JP": For Japanese

Many more language options are available, catering to diverse global requirements.

// Example using toLocaleDateString
const currentMoment = new Date();

console.log(currentMoment.toLocaleDateString("en-US")); // Example output: 9/17/2023 (format depends on local system time on execution)

const specificOptions = { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' };
console.log(currentMoment.toLocaleDateString("en-US", specificOptions)); // Example output: Sunday, September 17, 2023
console.log(currentMoment.toLocaleDateString("hi-IN", specificOptions)); // Example output: रविवार, 17 सितंबर 2023

The toLocaleString() method can also be used similarly. The key difference is that toLocaleString() provides the time component by default if no options are specified, whereas toLocaleDateString() only focuses on the date.

Method 2: Custom Delimited Formats with Intl.DateTimeFormat.formatToParts

For scenarios demanding highly customized date formats with specific delimiters, pulling out date components from an Intl.DateTimeFormat object is the preferred approach. This object is part of the ECMAScript Internationalization API , providing powerful tools for locale-aware formatting. The formatToParts() method is particularly useful here, as it returns an array of objects representing the formatted date’s parts, allowing you to reconstruct the string with custom separators.

While you could destructure the array, be aware that the output order depends on the chosen locale, making a direct destructuring less robust across different language settings.

// Example 1: Using formatToParts for locale-dependent output
{
   let dateTimeFormatter = new Intl.DateTimeFormat('en');
   let formatPartsResult = dateTimeFormatter.formatToParts();
   console.log(formatPartsResult);
}
// Example 2: Different locale shows different part order
{
   let dateTimeFormatter = new Intl.DateTimeFormat('hi');
   let formatPartsResult = dateTimeFormatter.formatToParts();
   console.log(formatPartsResult);
}

A more robust strategy involves mapping a format array to resultant strings, then joining them with your desired separator.

// Function to join date parts with a custom separator
function constructFormattedDate(targetDate, formatOptions, separatorChar) {
   function getFormattedPart(optionConfig) {
      let partFormatter = new Intl.DateTimeFormat('en', optionConfig);
      return partFormatter.format(targetDate);
   }
   return formatOptions.map(getFormattedPart).join(separatorChar);
}

const customOptionsArray = [{day: 'numeric'}, {month: 'short'}, {year: 'numeric'}];
const formattedCustomJoined = constructFormattedDate(new Date(), customOptionsArray, '-');
console.log(formattedCustomJoined); // Example output: 17-Sep-2023

Using DateTimeFormat#format to pull out parts one by one is also possible, but it’s important to note that, as of March 2020, a known bug existed in some ECMAScript implementations regarding leading zeros on minutes and seconds. The formatToParts approach circumvents this issue.

// Formatting parts one by one with Intl.DateTimeFormat#format
let sampleDate = new Date(2010, 7, 5); // Month is 0-indexed, so 7 is August
let displayYear = new Intl.DateTimeFormat('en', { year: 'numeric' }).format(sampleDate);
let displayMonth = new Intl.DateTimeFormat('en', { month: 'short' }).format(sampleDate);
let displayDay = new Intl.DateTimeFormat('en', { day: '2-digit' }).format(sampleDate);
console.log(`${displayDay}-${displayMonth}-${displayYear}`); // Expected: 05-Aug-2010

When dealing with complex date and time operations, leveraging a well-maintained library (such as Luxon or date-fns ) is generally recommended due to the numerous hidden complexities (e.g., timezones, daylight saving). While moment.js was popular, it is not recommended for new projects.

Note that the ECMAScript Internationalization API used in these solutions might not be supported in older browsers like IE10 (which had a very low global browser market share as of Feb 2020).

Method 3: Simple Custom String Concatenation with Native Date Getters

For quick and fixed date formats, straightforward JavaScript Date object methods like getDate(), getMonth(), getFullYear(), getHours(), and getMinutes() can be used to manually construct the desired string. This method is lightweight and requires no external dependencies, making it suitable for simple, specific formatting tasks.

// Basic date and time formatting
const currentDateTime = new Date();

let simpleFormattedDate = currentDateTime.getDate() + "-" +
    (currentDateTime.getMonth() + 1) + "-" + // Month is 0-indexed
    currentDateTime.getFullYear() + " " +
    currentDateTime.getHours() + ":" +
    currentDateTime.getMinutes();

console.log(simpleFormattedDate); // Example output: 17-9-2023 10:5 (might not have leading zeros)

If you require leading zeros for single-digit values (e.g., 05 instead of 5), you can implement a simple padding technique:

// Date and time formatting with leading zeros
const currentDateTimePadded = new Date();

let paddedFormattedDate = ("0" + currentDateTimePadded.getDate()).slice(-2) + "-" +
    ("0" + (currentDateTimePadded.getMonth() + 1)).slice(-2) + "-" +
    currentDateTimePadded.getFullYear() + " " +
    ("0" + currentDateTimePadded.getHours()).slice(-2) + ":" +
    ("0" + currentDateTimePadded.getMinutes()).slice(-2);

console.log(paddedFormattedDate); // Example output: 17-09-2023 10:05

Method 5: MySQL-Friendly Date Strings (toISOString and Local Adjustments)

When generating date strings for database interactions, particularly for formats like those commonly used in MySQL (e.g., YYYY-MM-DD), JavaScript’s toISOString() method is highly convenient. This method returns a string in ISO 8601 format (YYYY-MM-DDTHH:mm:ss.sssZ), which can then be truncated.

// Generate a MySQL-friendly date string (YYYY-MM-DD)
const dbFriendlyDate = new Date().toISOString().slice(0, 10);
console.log(dbFriendlyDate); // Example output: 2023-09-17

Keep in mind that toISOString() produces a UTC-based string. If your application requires the date to reflect the local timezone offset accurately, especially around midnight, a helper function is beneficial to adjust for the timezone before conversion.

// Function to get a timezone-adjusted local date string in JSON format (YYYY-MM-DD)
function toJSONLocalAdjusted(inputDate) {
    const localDate = new Date(inputDate);
    // Adjust minutes by the timezone offset to get the correct local time
    localDate.setMinutes(localDate.getMinutes() - localDate.getTimezoneOffset());
    return localDate.toJSON().slice(0, 10);
}

const currentDateTimeForDB = new Date();

console.log("UTC JSON:", currentDateTimeForDB.toJSON()); // Shows UTC time
console.log("UTC ISO:", currentDateTimeForDB.toISOString()); // Shows UTC ISO string
console.log("Local Adjusted JSON:", toJSONLocalAdjusted(currentDateTimeForDB)); // Shows local date adjusted for timezone

// Example with a specific date to demonstrate boundary handling
const specificBoundaryDate = new Date('2023-01-01T00:00:00Z'); // UTC start of day
console.log("Boundary date (UTC):", specificBoundaryDate.toISOString());
console.log("Boundary date (Local Adjusted):", toJSONLocalAdjusted(specificBoundaryDate));

Method 6: Custom Formatting Functions and ECMAScript Standard Date Methods

For precise, fixed formats or when you need a reusable utility without external libraries, crafting a custom formatting function is an excellent approach. This offers complete control over the output.

Example 1: Custom YYYY-MM-DD format

// Function to format date to YYYY-MM-DD
function formatAsYearMonthDay(dateInput) {
    const dayValue = dateInput.getDate();
    const monthValue = dateInput.getMonth() + 1; // Month is 0-indexed
    const yearValue = dateInput.getFullYear();
    return `${yearValue}-${(monthValue <= 9 ? '0' + monthValue : monthValue)}-${(dayValue <= 9 ? '0' + dayValue : dayValue)}`;
}

console.log(formatAsYearMonthDay(new Date(2017, 10, 5))); // Expected: 2017-11-05 (Nov 5)

Example 2: Custom DD-Mon-YYYY format (e.g., 05-Nov-2017)

// Function to format date to DD-Mon-YYYY
function formatAsDayMonYear(dateInput) {
    const monthAbbreviations = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec'];
    const dayValue = dateInput.getDate();
    const monthAbbr = monthAbbreviations[dateInput.getMonth()];
    const yearValue = dateInput.getFullYear();
    return `${(dayValue <= 9 ? '0' + dayValue : dayValue)}-${monthAbbr}-${yearValue}`;
}
console.log(formatAsDayMonYear(new Date(2017, 10, 5))); // Expected: 05-Nov-2017

Important consideration: Generally, extending native JavaScript prototypes (e.g., Date.prototype) is not recommended as it can lead to conflicts with other libraries or future JavaScript specifications.

Standard ECMAScript Date Formatting Functions:

Since more recent versions of ECMAScript, the Date class includes several specific formatting functions that provide built-in ways to represent dates:

  • toDateString(): Returns an implementation-dependent string representing only the date part.
    • Example: new Date().toDateString(); // e.g., "Sun Sep 17 2023"
  • toISOString(): Returns a string in ISO 8601 extended format, representing date and time in UTC.
    • Example: new Date().toISOString(); // e.g., "2023-09-17T14:30:00.000Z"
  • toJSON(): Returns a string representation of the date for JSON serialization, typically the same as toISOString().
    • Example: new Date().toJSON(); // e.g., "2023-09-17T14:30:00.000Z"
  • toLocaleDateString(): Returns an implementation-dependent string representing the date in locale-specific format.
    • Example: new Date().toLocaleDateString(); // e.g., "17/09/2023" (depends on locale)
  • toLocaleString(): Returns an implementation-dependent string representing both date and time in locale-specific format.
    • Example: new Date().toLocaleString(); // e.g., "17/09/2023, 14:30:00 PM" (depends on locale)
  • toLocaleTimeString(): Returns an implementation-dependent string representing the time in locale-specific format.
    • Example: new Date().toLocaleTimeString(); // e.g., "02:30:00 PM" (depends on locale)
  • toString(): Returns a generic string representation of the Date object, including timezone information.
    • Example: new Date().toString(); // e.g., "Sun Sep 17 2023 14:30:00 GMT+0000 (Coordinated Universal Time)"

You can often extract specific parts or reformat the output from these standard functions. For example: new Date().toISOString().slice(0,10); will return YYYY-MM-DD.

Practical Snippets:

// Demonstrating standard ECMAScript Date formatting functions
console.log("1) toDateString(): " +  new Date().toDateString());
console.log("2) toISOString(): " +  new Date().toISOString());
console.log("3) toJSON(): " +  new Date().toJSON());
console.log("4) toLocaleDateString(): " +  new Date().toLocaleDateString());
console.log("5) toLocaleString(): " +  new Date().toLocaleString());
console.log("6) toLocaleTimeString(): " +  new Date().toLocaleTimeString());
console.log("7) toString(): " +  new Date().toString());
console.log("8) toISOString().slice(0,10): " +  new Date().toISOString().slice(0,10));

Specifying the Locale for Standard Functions:

toLocaleDateString(), toLocaleTimeString(), and toLocaleString() allow you to specify the locale and options. This is crucial because different cultures use varying date and time formats. By default, they return the format configured on the device running the code, but you can explicitly set the arguments (as per ECMA-402).

  • toLocaleDateString([locales[, options]])
  • toLocaleTimeString([locales[, options]])
  • toLocaleString([locales[, options]])

For instance, new Date().toLocaleDateString('ko-KR'); would format the date for Korean (South Korea). The options parameter enables further specific formatting within the selected locale, such as displaying the month as full text or an abbreviation (e.g., toLocaleString('en-GB', { month: 'short' })).

// Demonstrating locale-specific formatting
console.log("1) US Locale (Date & Time): " +  new Date().toLocaleString('en-US'));
console.log("2) Korean Locale (Date & Time): " +  new Date().toLocaleString('ko-KR'));
console.log("3) Swiss German Locale (Date & Time): " +  new Date().toLocaleString('de-CH'));

console.log("4) UK Locale (24-hour time): " +  new Date().toLocaleString('en-GB', { hour12: false }));
console.log("5) UK Locale (12-hour time): " +  new Date().toLocaleString('en-GB', { hour12: true }));

Good Practices Regarding Locales:

  • Default Locale Preference: Most users prefer dates in their native format. Favor keeping the default locale whenever possible rather than forcing a specific one like ’en-US’ globally.
  • Timezone Conversion: Implementing conversions from/to UTC, especially considering Daylight Saving Time (DST) and timezones not evenly divisible by an hour, can be challenging. For robust solutions, rely on well-tested libraries.
  • Country vs. Locale: Do not assume a direct correlation between a locale and a country; many countries (e.g., Canada, India) have multiple locales.
  • Locale Detection: Avoid non-standard methods for detecting locales (e.g., keyboard layout, geographic location) as they often introduce pitfalls.

Method 10: toLocaleDateString for Specific DD-Mon-YYYY Format

For modern browsers, a straightforward combination of toLocaleDateString with specific options and string manipulation can achieve formats like DD-Mon-YYYY. This method is concise and leverages built-in internationalization capabilities.

// Modern browser method for DD-Mon-YYYY
const currentTimestamp = new Date();
const formattedMonthYear = currentTimestamp.toLocaleDateString('en-GB', {
    day : 'numeric',
    month : 'short',
    year : 'numeric'
}).split(' ').join('-');

console.log(formattedMonthYear); // Example output if executed today: '17-Sep-2023'

This solution is well-supported across most modern browser versions (Chrome 24+, Firefox 29+, Internet Explorer 11, Edge 12+, Opera 15+, Safari nightly build).

Method 11: Regex-Based Date Formatting from toString()

A compact, albeit potentially less robust, approach involves using regular expressions on the output of Date.prototype.toString(). While toString() output can be implementation-dependent, this method works reliably in many major browser environments for common formats.

// Regex-based date formatting
// Note: Date().toString() output can vary by browser/engine.
const rawDateString = (new Date()).toString();
const regexFormattedResult = rawDateString.replace(/\S+\s(\S+)\s(\d+)\s(\d+)\s.*/,'$2-$1-$3');

console.log(regexFormattedResult); // Example output: "17-Sep-2023" (assuming standard toString output)

It is recommended to test this method’s output to confirm it matches expectations in your target JavaScript environment due to the implementation-dependent nature of Date.prototype.toString().

Comprehensive Manual Formatting Function:

If external libraries are not an option, a custom formatDate function can mimic the pattern-based formatting of libraries like Java’s SimpleDateFormat. This involves defining a mapping of pattern characters to date components and then replacing them within a format string.

// Manual Comprehensive Formatting Function
const monthLongNames = [
  "January", "February", "March", "April", "May", "June", "July",
  "August", "September", "October", "November", "December"
];
const dayFullNames = [
  "Sunday", "Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"
];

function padTwoDigits(num) {
    return num < 10 ? "0" + num : num;
}

function customFormatDateTime(dateObj, patternString) {
    if (!patternString) {
        patternString = 'M/d/yyyy'; // Default format
    }
    const day = dateObj.getDate();
    const month = dateObj.getMonth();
    const year = dateObj.getFullYear();
    const hour = dateObj.getHours();
    const minute = dateObj.getMinutes();
    const second = dateObj.getSeconds();
    const milliseconds = dateObj.getMilliseconds();

    const hour12 = hour % 12;
    const hour12Padded = padTwoDigits(hour12);
    const hour24Padded = padTwoDigits(hour);
    const minutePadded = padTwoDigits(minute);
    const secondPadded = padTwoDigits(second);
    const ampmMarker = hour < 12 ? 'AM' : 'PM';
    const fullWeekday = dayFullNames[dateObj.getDay()];
    const shortWeekday = fullWeekday.substring(0, 3);
    const dayPadded = padTwoDigits(day);
    const monthNumeric = month + 1;
    const monthNumericPadded = padTwoDigits(monthNumeric);
    const fullMonthName = monthLongNames[month];
    const shortMonthName = fullMonthName.substring(0, 3);
    const fullYear = year + "";
    const twoDigitYear = fullYear.substring(2, 4);

    let formattedString = patternString
      .replace(/hh/g, hour12Padded).replace(/h/g, hour12.toString())
      .replace(/HH/g, hour24Padded).replace(/H/g, hour.toString())
      .replace(/mm/g, minutePadded).replace(/m/g, minute.toString())
      .replace(/ss/g, secondPadded).replace(/s/g, second.toString())
      .replace(/S/g, milliseconds.toString())
      .replace(/dd/g, dayPadded).replace(/d/g, day.toString())
      .replace(/EEEE/g, fullWeekday).replace(/EEE/g, shortWeekday)
      .replace(/yyyy/g, fullYear)
      .replace(/yy/g, twoDigitYear)
      .replace(/aaa/g, ampmMarker);

    // Handle month names vs. numbers
    if (formattedString.includes('MMM')) {
        formattedString = formattedString
          .replace(/MMMM/g, fullMonthName)
          .replace(/MMM/g, shortMonthName);
    } else {
        formattedString = formattedString
          .replace(/MM/g, monthNumericPadded)
          .replace(/M/g, monthNumeric.toString());
    }
    return formattedString;
}

console.log(customFormatDateTime(new Date())); // Default: M/d/yyyy
console.log(customFormatDateTime(new Date(), 'dd-MMM-yyyy')); // OP's request: 17-Sep-2023
console.log(customFormatDateTime(new Date(), 'EEEE, MMMM d, yyyy HH:mm:ss.S aaa')); // Example: Sunday, September 17, 2023 14:30:23.456 PM
console.log(customFormatDateTime(new Date(), 'EEE, MMM d, yyyy HH:mm')); // Example: Sun, Sep 17, 2023 14:30
console.log(customFormatDateTime(new Date(), 'yyyy-MM-dd HH:mm:ss.S')); // Example: 2023-09-17 14:30:23.456
console.log(customFormatDateTime(new Date(), 'M/dd/yyyy h:mmaaa')); // Example: 9/17/2023 2:30PM

Date and Time Patterns for customFormatDateTime:

  • yy = 2-digit year; yyyy = full year
  • M = digit month; MM = 2-digit month; MMM = short month name; MMMM = full month name
  • EEEE = full weekday name; EEE = short weekday name
  • d = digit day; dd = 2-digit day
  • h = hours am/pm; hh = 2-digit hours am/pm; H = hours (24hr); HH = 2-digit hours (24hr)
  • m = minutes; mm = 2-digit minutes; aaa = AM/PM marker
  • s = seconds; ss = 2-digit seconds
  • S = milliseconds

// Flexible ES6 formatter function
function flexibleDateFormatter(dateObject, formatPattern = 'YYYY-MM-DDThh:mm:ss') {
  const padToTwo = (num) => num.toString().padStart(2, '0');

  const patternMap = {

    return previousString.replace(new RegExp(patternKey, 'g'), value.toString());
  }, formatPattern);
}

FAQs on Top 30 Ways to Format Dates in JavaScript

Q: What is the simplest way to format a date in JavaScript

ANS: For a basic, localized date string, new Date().toLocaleDateString() is often the simplest. If you need a specific YYYY-MM-DD format, new Date().toISOString().slice(0, 10) is very straightforward.

Q: How do I format a date to DD MON YYYY format for example 17 Sep 2023

ANS: You can use new Date().toLocaleDateString('en-GB', { day: 'numeric', month: 'short', year: 'numeric' }).replace(/ /g, '-'). Alternatively, a custom function with an array of month abbreviations can achieve this.

Q: When should I use an external library like Luxon or Dayjs for date formatting

ANS: External libraries are highly recommended for new projects if you need robust date parsing, complex manipulations, timezone handling, or extensive internationalization features. They simplify development and handle many edge cases that custom solutions often miss.

Q: Can I format dates differently for various languages or regions

ANS: Absolutely. The Intl.DateTimeFormat object and Date.prototype.toLocaleDateString() methods are specifically designed for this. You can pass a locale argument (e.g., ’en-US’, ‘de-DE’, ‘hi-IN’) to format dates according to regional conventions.

Q: Is it safe to extend Date prototype for custom date formatting

ANS: Generally, extending native JavaScript prototypes like Date.prototype is discouraged. It can lead to conflicts with other libraries, unexpected behavior with future JavaScript versions, and makes code harder to debug. It is better to create standalone utility functions or use well-established libraries.

Q: How can I format current date to a MySQL compatible string

ANS: The new Date().toISOString().slice(0, 10) will give you YYYY-MM-DD in UTC. For a local time-adjusted version, you might need a helper function that accounts for the timezone offset before slicing, as shown in Method 5.

      let formatter = new Intl.DateTimeFormat('en', option);
      return formatter.format(date);
   }
   return options.map(format).join(separator);
}
