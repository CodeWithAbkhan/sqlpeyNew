“JavaScript ES6 Imports: Curly Braces Explained”

When working with modern JavaScript, particularly ES6 modules, understanding how to import functionality from other files is crucial. A common point of inquiry revolves around the use of curly braces {} within import statements. This post delves into the distinct roles of default and named exports and clarifies precisely when and why curly braces are employed.

The Core Distinction: Default vs. Named Exports

At its heart, the use of curly braces in JavaScript imports hinges on how modules export their contents.

Default Exports: A module can export a single primary value as its “default.” This is the primary item the module is intended to provide. You can only have one default export per module.

Consider a module A.js with a default export:

// A.js
const defaultMessage = "Hello from default export!";
export default defaultMessage;

When importing this default export in another file, say B.js, you do not use curly braces. You can assign any name you wish to this imported value.

// B.js
import myGreeting from './A'; // 'myGreeting' can be any valid identifier
console.log(myGreeting); // Output: Hello from default export!

You can import the default export multiple times with different names, and each will resolve to the same exported value:

// B.js
import A from './A';
import MyA from './A';
import Something from './A';

console.log(A, MyA, Something); // All will show "Hello from default export!"

Named Exports: Modules can export multiple values, such as functions, variables, or classes, using named exports. Each named export must have a specific name.

Let’s modify A.js to include named exports:

// A.js
export const dataValue1 = 42;
export const dataValue2 = "Important String";
export function processData() {
  console.log("Processing...");
}

When importing named exports, you must use curly braces and specify the exact name of the exported item.

// B.js
import { dataValue1, processData } from './A';

console.log(dataValue1);     // Output: 42
processData();              // Output: Processing...

If you attempt to import a named export that doesn’t exist, it will result in an error:

// B.js
import { nonExistentExport } from './A'; // This will cause an error

To resolve this, ensure the named export exists in the source module:

// A.js
export const dataValue1 = 42;
export const dataValue2 = "Important String";
export const nonExistentExport = "This is now exported"; // Added for demonstration
export function processData() {
  console.log("Processing...");
}

Now, the import will succeed:

// B.js
import { dataValue1, processData, nonExistentExport } from './A';

A module can have both a default export and any number of named exports. You can import them together in a single statement.

// A.js
export default { id: 1, name: "Example Object" };
export const utilityFunction = () => console.log("Utility action");

// B.js
import moduleObject, { utilityFunction } from './A';

console.log(moduleObject);    // Output: { id: 1, name: "Example Object" }
utilityFunction();          // Output: Utility action

Aliasing Imports

You can rename named imports during the import process using the as keyword. This is particularly useful to avoid naming conflicts or to use more descriptive names.

// A.js
export const processData = () => console.log("Processing...");
export const dataValue1 = 42;

// B.js
import { processData as processHelper, dataValue1 as firstValue } from './A';

processHelper(); // Output: Processing...
console.log(firstValue); // Output: 42

The Role of Destructuring

The use of curly braces in imports is intrinsically linked to ES6’s destructuring assignment . When you import named exports, you are essentially destructuring the exported object from the module.

Consider this analogy:

If module.js exports an object with several properties:

// module.js
export const greet = (name) => `Hello, ${name}!`;
export const farewell = (name) => `Goodbye, ${name}!`;

Importing like this:

// index.js
import { greet, farewell } from './module.js';

console.log(greet('Alice'));
console.log(farewell('Bob'));

is equivalent to:

// index.js
const { greet, farewell } = require('./module.js'); // Using CommonJS for analogy

The curly braces in the import statement allow you to pick specific properties (named exports) from the module’s export object.

Importing All Named Exports: The Starred Notation

If you need to import all named exports from a module, you can use the starred notation (*). This bundles all named exports into a single object.

// A.js
export const constantValue = 100;
export function helperFunc() { console.log('Helping'); }

// B.js
import * as ModuleAContents from './A';

console.log(ModuleAContents.constantValue); // Output: 100
ModuleAContents.helperFunc();              // Output: Helping

This approach is useful when you want to access multiple exports and keep them grouped under a single namespace.

Why Prefer Named Exports in Certain Scenarios?

While default exports offer a simpler import syntax, named exports are often favored in larger projects, especially in environments like TypeScript .

  • Refactoring: If you rename a default export, only that specific export is affected. However, if you rename a named export, all references importing that specific name will also need to be updated. This can make refactoring safer and more predictable with named exports.
  • Clarity: Named exports make it explicit what is being imported from a module, improving code readability.
  • Utilities: Collections of utility functions or constants are naturally suited for named exports.

Ultimately, the choice between default and named exports can be a matter of team convention or personal preference, but understanding their mechanics is key.

When to Use Curly Braces for ES6 Imports?

  • Use {}: When importing named exports. You must use the exact export name within the braces.
  • Do NOT use {}: When importing a default export. You can assign any name to the imported default value.
  • Use import * as MyModule from './path': To import all named exports into a single namespace object.

FAQs on JavaScript ES6 Imports

Q: When should I use curly braces in JavaScript imports

ANS: You should use curly braces {} when importing named exports from a module. This allows you to selectively import specific variables, functions, or classes that have been given a name during the export process.

Q: What happens if I use curly braces for a default export

ANS: If you try to import a default export using curly braces, it will typically result in an error or unexpected behavior because the import syntax doesn’t match the module’s export type. Default exports are imported without braces.

Q: Can a module have both default and named exports

ANS: Yes, a single JavaScript module can have one default export and multiple named exports. You can import both types in a single import statement, for example: import myDefault, { namedExport1, namedExport2 } from './myModule';

Q: How do I import all exports from a module

ANS: To import all named exports from a module, you can use the import * as AliasName from './modulePath'; syntax. This imports all named exports into a single object aliased as AliasName.

Q: Is there a performance difference between default and named imports

ANS: For modern bundlers like Webpack or Rollup, there’s generally minimal performance difference. However, importing only what you need via named exports can sometimes lead to slightly smaller bundle sizes as the bundler can perform more effective tree-shaking.

Q: How does destructuring relate to named imports

ANS: Named imports in ES6 modules utilize object destructuring. When you import a named export like import { myFunction } from './myModule';, you are essentially destructuring the myFunction property from the object that the module exports.

Q: What is the syntax for renaming an imported named export

ANS: You can rename an imported named export using the as keyword. For instance: import { originalName as newName } from './myModule';.
