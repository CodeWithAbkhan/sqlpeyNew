“Effective Frame Busting Techniques to Prevent Clickjacking”

When building web applications, protecting them from malicious framing, commonly known as clickjacking, is a significant concern. Clickjacking attacks trick users into clicking on something different from what they perceive, often by overlaying disguised links or buttons within an invisible or misleading frame. This can lead to unauthorized actions like transferring funds, changing passwords, or visiting malicious websites.

Several methods exist to defend against these attacks, primarily by preventing your web content from being embedded in frames on other sites. Here are various approaches and code examples that developers have employed to implement effective frame busting.

Solution 1: X-Frame-Options Header

A fundamental server-side defense is the X-Frame-Options HTTP response header. Most modern browsers respect this header to control whether a page can be rendered in a <frame>, <iframe>, <embed>, or <object>.

  • DENY: Prevents any domain from framing the content.
  • SAMEORIGIN: Allows framing only by pages from the same origin.
  • ALLOW-FROM uri: (Deprecated) Allows framing only by the specified URI.

Example Implementation (HTTP Header):

X-Frame-Options: DENY

This directive is effective even when JavaScript is disabled in the browser. For a deeper dive into browser security features, you might find resources on web security basics helpful.

Solution 2: JavaScript-Based Warning and Redirection

If a page detects it’s being framed, it can inform the user and provide a means to break out of the frame. This approach involves using setInterval to periodically check if the page is the top-level window. If not, it can display a warning and offer a link to open the page correctly.

Example Snippet:

if (top !== self) {
    // Display a warning and offer a link to open in a new tab
    var warningDiv = document.createElement('div');
    warningDiv.style.cssText = 'position: fixed; top: 0; left: 0; width: 100%; height: 100%; background-color: rgba(0,0,0,0.8); color: white; z-index: 9999; display: flex; align-items: center; justify-content: center; font-size: 20px; text-align: center;';
    warningDiv.innerHTML = 'You are viewing this page in an unauthorized frame. <a href="' + self.location.href + '" target="_top" style="color: #0f0; text-decoration: underline;">Click here to proceed safely</a>.';
    document.body.appendChild(warningDiv);
}

This method, while requiring JavaScript, can alert users to a potential security issue.

Solution 3: Classic JavaScript Frame Busting

A commonly cited JavaScript technique involves checking the self and top window objects. If they differ, it signifies the page is framed. The script then redirects the top-level window to the current page’s location.

Example Script:

<style>
    body { display: none; } /* Initially hide the body */
</style>
<script type="text/javascript">
    if (self === top) {
        // If not framed, show the body
        document.body.style.display = 'block';
    } else {
        // If framed, redirect the top window
        top.location = self.location;
    }
</script>

This method was a popular defense for a considerable time. You can find more information on JavaScript practices at what is JavaScript .

Solution 4: onbeforeunload and Location Replacement

Another technique involves manipulating the onbeforeunload event and using top.location.replace to force a redirect.

Example Script:

if (top !== self) {
    top.onbeforeunload = function() {}; // Attempt to disable frame buster buster
    top.location.replace(self.location.href);
}

This approach aims to disrupt potential attempts to bypass the frame busting mechanism.

Solution 5: HTML5 sandbox Attribute and Robust JavaScript

The HTML5 sandbox attribute for <iframe> elements provides fine-grained control over iframe capabilities. When used without specific allow-* tokens, it restricts scripts, top-level navigation, and more. Even with these restrictions, robust frame busting is still necessary.

A highly effective JavaScript solution, proposed by researchers, combines hiding the body and redirecting the top window, even against sophisticated bypasses.

Example Script:

<style id="antiClickjack">body { display: none !important; }</style>
<script type="text/javascript">
    if (self === top) {
        // Remove the style if not framed
        var antiClickjackStyle = document.getElementById("antiClickjack");
        antiClickjackStyle.parentNode.removeChild(antiClickjackStyle);
    } else {
        // Redirect if framed
        top.location = self.location;
    }
</script>

This method is considered highly resilient.

Solution 6: window.open with _top Target

A simpler JavaScript approach uses window.open with the _top target to force the current page into the top-level browsing context.

Example Script:

if (top !== self) {
    window.open(location.href, '_top');
}

This can be a straightforward way to break out of a frame.

Solution 7: Content-Security-Policy (CSP) frame-ancestors Directive

The modern and recommended approach for frame busting is utilizing the Content-Security-Policy (CSP) header, specifically the frame-ancestors directive. This directive controls which origins are allowed to embed the resource using <frame>, <iframe>, <object>, <embed>, or <applet>.

Example Implementation (HTTP Header):

Content-Security-Policy: frame-ancestors 'none';

This is the most robust server-side solution. For older browser compatibility, it’s advisable to combine it with the X-Frame-Options header.

Content-Security-Policy: frame-ancestors 'none'
X-Frame-Options: DENY

For a better grasp of HTTP headers and their role in web security, exploring web security fundamentals can be beneficial.

Solution 8: User-Interactive Protection

This solution prioritizes user experience by disabling interactive elements and presenting a warning if framing is detected. It then provides a link to open the page safely in a new window.

Example HTML & JavaScript:

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 3.2 Final//EN">
<html>
<head>
    <title>Protected Page</title>
    <script>
      function replaceAttributeValuesWithActualOnes( array, attributeName, actualValueAttributeName, additionalProcessor ) {
        // ... implementation details ...
      }

      function detectFraming() {
        if ( top !== self ) {
          document.getElementById( "framingWarning" ).style.display = "block";
        } else {
          // Re-enable controls if not framed
          replaceAttributeValuesWithActualOnes( document.links, "href", "acme:href" );
          replaceAttributeValuesWithActualOnes( document.forms, "action", "acme:action", function ( form ) {
            replaceAttributeValuesWithActualOnes( form.elements, "disabled", "acme:disabled" );
          });
        }
      }
    </script>
</head>
<body onload="detectFraming()">
    <div id="framingWarning" style="display: none; border: 4px solid #F00; padding: 6px; background-color: #FFF; color: #F00;">
        <b>SECURITY WARNING</b>: This application is displayed inside another page.
        For your data's safety, interaction has been disabled.<br>
        <a href="safe-page.html" target="_blank" style="color: #090;">Continue safely in a new tab/window</a>
    </div>
    <p>
      Content. <a href="#" acme:href="javascript:window.alert( 'Action performed' );">Do something</a>
    </p>
    <form name="acmeForm" action="#" acme:action="real-action.html">
      <p>Name: <input type="text" name="name" value="" disabled="disabled" acme:disabled=""></p>
      <p><input type="submit" name="save" value="Save" disabled="disabled" acme:disabled=""></p>
    </form>
</body>
</html>

This method offers a balance between security and usability.

Solution 9: Immediate Redirection to about:blank

This aggressive approach immediately redirects the top window and then redirects the current window to about:blank.

Example Script:

if (top !== self) {
  top.location.replace(location);
  location.replace("about:blank");
}

This aims to disrupt any framing attempt decisively.

Solution 10: setInterval with Synchronous XHR

This complex method uses setInterval to repeatedly attempt to redirect the top window, coupled with a synchronous XMLHttpRequest to delay execution in certain browsers, making it harder for frame buster bypasses to succeed.

Example Script:

(function() {
    if (top === self) {
        return;
    }

    setInterval(function() {
        top.location.replace(document.location);
        setTimeout(function() {
            var xhr = new XMLHttpRequest();
            xhr.open('get', 'http://your-site.com/long-loading-resource', false); // Synchronous call
            xhr.send(null);
        }, 0);
    }, 1);
}());

The success of this depends heavily on the execution timing and browser behavior.

Solution 12: AJAX Loading and User Interaction Prompts

This involves detecting framing, potentially disabling content, and then prompting the user to disable JavaScript or click a link to proceed safely.

Ideas:

  • Load content via AJAX only after confirming not being framed.
  • Prompt users to disable JavaScript before navigating to a secure URL.
  • Replace the entire document body with a warning message if framed.

Solution 13: Alert Stalling Technique

Adding an alert() call immediately after the frame busting code can stall the JavaScript execution thread, allowing the intended redirection to take effect before a frame buster buster can intervene.

Example Script:

if (top !== self){
  top.location.replace(self.location.href);
  alert("Security Warning: Page is not allowed to be framed.");
}

This has shown effectiveness in certain browser versions.

Solution 14: Parent Window Manipulation

Directly manipulating the parent window’s onbeforeunload and location properties can be an attempt to override frame busting.

Example Script:

window.parent.onbeforeunload = null;
window.parent.location.replace(self.location.href);
// Or: window.parent.prevent_bust = 0;

The effectiveness of these specific manipulations can vary.

Solution 15: Clearing Intervals

Clearing all possible setInterval and setTimeout IDs can disrupt timing-based frame busting techniques.

Example Script:

for (var j = 0 ; j < 256 ; ++j) clearInterval(j);

This is a brute-force approach to clearing scheduled tasks.

Solution 16: Repeated Frame Busting Calls

Continuously calling the frame busting logic can create a race condition, potentially allowing the legitimate frame buster to win.

Example Script:

(function() {
    if (top !== self) {
        top.location.href = self.location.href;
        setTimeout(arguments.callee, 0);
    }
})();

This recursive pattern aims to maintain the frame busting state.

Solution 18: Interval Counting and Clearing

A more structured approach to clearing intervals involves tracking and clearing a range of setTimeout and setInterval IDs.

Example Script:

var currentInterval = 10000;
currentInterval += setTimeout(gotoHREF, 100);
for (var i = 0; i < currentInterval; i++) top.clearInterval(i);
for (var i = 0; i < currentInterval; i++) top.clearTimeout(i);

function gotoHREF() {
    top.location.href = "http://your.url.here";
}

This aims to preemptively clear any malicious interval timers.

Solution 19: .htaccess for Referer-Based Protection

Server-side configuration using .htaccess can prevent framing by checking the HTTP Referer header. If the referer doesn’t match your domain, the request can be redirected.

Example .htaccess Rules:

RewriteEngine on
RewriteCond %{HTTP_REFERER} !^http://www\.yoursite\.com/ [NC]
RewriteCond %{HTTP_REFERER} !^$
RewriteRule ^(.*)$ /copyrights.html [L]

FAQs on Preventing Clickjacking

Q: What is the most modern and recommended way to prevent clickjacking

ANS: The most modern and recommended approach is using the Content-Security-Policy (CSP) header with the frame-ancestors directive. For older browser support, combine it with the X-Frame-Options: DENY header.

Q: Can JavaScript frame busting be bypassed

ANS: Yes, certain sophisticated “frame buster buster” scripts can attempt to bypass basic JavaScript frame busting techniques. More robust JavaScript solutions and server-side headers are needed for stronger protection.

Q: Does X-Frame-Options work without JavaScript

ANS: Yes, the X-Frame-Options HTTP response header is a server-side control and functions even when JavaScript is disabled in the user’s browser.

Q: What is the purpose of the sandbox attribute in iframes

ANS: The HTML5 sandbox attribute for <iframe> elements allows you to impose restrictions on the content loaded within the iframe, such as preventing script execution, form submissions, or top-level navigation, enhancing security.

Q: Which JavaScript techniques are considered most reliable

ANS: Techniques that combine hiding the body with immediate redirection (top.location = self.location;) or those employing setInterval with careful timing and potentially synchronous requests are generally considered more reliable against bypasses.
