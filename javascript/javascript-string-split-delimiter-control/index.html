“JavaScript String Split Behavior: Keeping or Excluding Delimiters”

Various sophisticated techniques leverage the power of Regular Expressions (Regex) to achieve precise control over the split operation.

Techniques for Splitting Strings While Retaining Delimiters

The behavior of split() changes significantly when the separator is a regular expression that includes capturing groups.

1. Capturing Groups in Regex Separators

If the regular expression used as a separator contains capturing parentheses (), the matched delimiters are inserted into the output array alongside the resulting substrings.

Consider splitting the string "1、2、3" by the Chinese comma 、:

  • Simple Split (Delimiter Removed):

    "1、2、3".split("、") // Results in: ["1", "2", "3"]

  • Capturing the Delimiter (Delimiter Included): Wrapping the delimiter in parentheses captures it.

    "1、2、3".split(/(、)/) 
// Results in: ["1", "、", "2", "、", "3"]

  • Positive Lookahead (Delimiter Kept Before Next Segment): A positive lookahead (?=...) asserts that the delimiter follows, but does not consume it in the match, placing it at the beginning of the next segment.

    "1、2、3".split(/(?=、)/) 
// Results in: ["1", "、2", "、3"]

    Note: This specific example only functions effectively for single-character splits, as noted in original discussions.

  • Negative Lookahead (Delimiter Kept After Previous Segment): A negative lookahead (?!...) splits if the delimiter is not present.

    "1、2、3".split(/(?!、)/) 
// Results in: ["1、", "2、", "3"]

  • Capturing Pattern Groups: More complex capturing patterns can yield varied results, sometimes introducing empty strings depending on where the match starts relative to the string boundaries.

    "1、2、3".split(/(.*?、)/) 
// Results in: ["", "1、", "", "2、", "3"]

For scenarios like splitting file paths while preserving directory separators, a pattern matching segments followed by an optional slash might be appropriate:

var filePath = 'Animation/rawr/javascript.js';
var pathTokens = filePath.match(/[^\/]+\/?|\//g);
// pathTokens might be: ["Animation/", "rawr/", "javascript.js"]

2. Using Positive Lookahead (?=...) for Conditional Splitting

A robust way to split without consuming the delimiter is using a positive lookahead. This is particularly useful for splitting based on a pattern that should remain attached to the following text.

For instance, splitting an HTML string where <br /> should be kept attached to the following entity:

var htmlString = "aaaaaa<br />&dagger; bbbb<br />&Dagger; cccc";
var pattern = /<br \/>(?=&amp;#?[a-zA-Z0-9]+;)/g;
console.log(htmlString.split(pattern)); 
// Output will separate chunks but keep the delimiter attached to the following part if the lookahead matched.

If the goal is to only keep the delimiter after the segment (as in Solution 2), the lookahead asserts its presence after the break:

// Based on Solution 2 logic:
var stringToSplit = "aaaaaa<br />&dagger; bbbb<br />&Dagger; cccc";
console.log(stringToSplit.split(/<br \/>(?=&[a-zA-Z0-9]+;)/g));

3. Keeping Delimiters via Capture Groups (Alternative Structure)

If you specifically want the delimiter to be one of the elements in the resulting array, capturing groups are the direct mechanism, as established by MDN documentation regarding String.prototype.split().

If splitting by <br /> followed by an HTML entity, and you want to capture the <br />:

// Capture group wraps the delimiter:
var result1 = "aaaaaa<br />&dagger; bbbb<br />&Dagger; cccc".split(/(&lt;br \/&gt;)&amp;#?[a-zA-Z0-9]+;/g);
// Returns: ["aaaaaa", "&lt;br /&gt;", "bbbb", "&lt;br /&gt;", "cccc"]

You can refine the capture group content, for example, to capture the entity instead:

// Capture group wraps the entity:
var result2 = "aaaaaa<br />&dagger; bbbb<br />&Dagger; cccc".split(/&lt;br \/&gt;(&amp;#?[a-z\d]+;)/gi);
// Returns: ["aaaaaa", "&dagger;", "bbbb", "&Dagger;", "cccc"]

For more advanced matching, referencing character classes like \d for digits or \w for word characters ([a-zA-Z0-9_]) improves regex readability.

4. Positive Lookbehind Assertions (?<=...)

Introduced more recently in JavaScript engines (ES2018+), lookbehind assertions allow specifying what must precede the split point without including it in the split operation itself. This is excellent for keeping delimiters at the end of the preceding segment.

If splitting sentences by common punctuation [.?!] or newlines, and you want the punctuation attached to the sentence:

var text = 'It is. Is it? It is!';
var sentenceArray = text.split(/(?<=[.?!])/);
/* Result: [ 'It is.', ' Is it?', ' It is!' ] */

// Splitting by multiple characters, including newline:
var multiLineText = 'Hello? This is Bob.\n\nAre you there? what!';
var splitPunctuation = multiLineText.split(/(?<=[\n.!?])/);
/* Result: [ 'Hello?', ' This is Bob.', '\n', '\n', 'Are you there?', ' what!' ] */

This avoids the limitation of Solution 1’s fourth example which only worked for single characters. If you encounter environment compatibility issues, check the modern JS features supported, or look into polyfills or alternative methods like string replacement followed by split (as shown in Solution 7).

5. Custom Splitting Functions for Complex Needs

When standard regex splits do not align with complex requirements (e.g., splitting by multiple arbitrary delimiters and ensuring specific ordering), extending the String.prototype (though generally discouraged in shared libraries) or defining a standalone utility function is necessary.

One advanced implementation provides a function to split based on a specified method ('seperate', 'infront', or 'behind'), including support for splitting by an array of separators sequentially:

// Standalone utility function implementation (adapted from Solution 6)
function splitAndKeep(str, separator, method = 'seperate'){
    let currentStr = str;
    
    function processSplit(s, sep, m){
        if(m === 'seperate'){
            return s.split(new RegExp(`(${sep})`, 'g'));
        } else if(m === 'infront'){
            return s.split(new RegExp(`(?=${sep})`, 'g'));
        } else if(m === 'behind'){
            // Note: Handling filter for empty strings might be needed based on exact regex match behavior
            return s.split(new RegExp(`(.*?${sep})`, 'g')).filter(el => el !== "");
        }
        return [s]; // Default if method is unknown
    }

    if(Array.isArray(separator)){
        let parts = processSplit(currentStr, separator[0], method);
        for(let i = 1; i < separator.length; i++){
            let partsTemp = parts;
            parts = [];
            for(let p = 0; p < partsTemp.length; p++){
                parts = parts.concat(processSplit(partsTemp[p], separator[i], method));
            }
        }
        return parts;
    } else {
        return processSplit(currentStr, separator, method);
    }
};

// Usage Example:
const testString = "first1-second2-third3-last";
const complexSplit = splitAndKeep(testString, ["1", "2", "3"], 'seperate');
console.log(complexSplit); 
// Expected output structure: ["first", "1", "-second", "2", "-third", "3", "-last"]

6. Alternative: Replace and Split

If lookbehind is unavailable or undesired, a pre-processing step can insert a unique, non-occurring character (like a comma) immediately following the desired split points, and then split by that character.

For splitting text based on a wide range of symbols:

var stringValue = '500x500-11*90~1+1';
// Insert a comma immediately before characters in the defined set
stringValue = stringValue.replace(/(?=[$-/:-?{-~!"^_`\[\]])/gi, ",");
var finalResult = stringValue.split(",");
// Result: [ '500x500', '-11', '*90', '~1', '+1' ]

7. Non-Regex Approach for Simple Indexing

When the delimiter is a fixed substring and the goal is simply to extract everything from the first occurrence onward, string methods like indexOf and slice provide a direct, performant alternative without involving regex complexity.

const sentence = "hello world what a great day today balbla";
const searchTerm = "great";
const index = sentence.indexOf(searchTerm);

if (index !== -1) {
    const partStartingAtTerm = sentence.slice(index);
    console.log(partStartingAtTerm); // Output: "great day today balbla"
}

This method successfully isolates the substring starting at the delimiter, effectively “splitting” the string at that point while keeping the delimiter as the first item of the resulting substring. For more information on handling string operations in JavaScript, refer to MDN documentation on String methods .

FAQs on JavaScript String Split Delimiter Control

Q: How does using capturing groups affect String split

ANS: When the separator in string.split() is a regular expression containing capturing parentheses (), the captured matches (the delimiters themselves) are included in the resulting array, interleaved with the segments that were split.

Q: Which regex feature keeps the delimiter attached to the segment that follows it

ANS: The positive lookahead assertion (?=delimiter) splits the string at the position immediately preceding the delimiter without consuming the delimiter, effectively attaching it to the subsequent segment.

Q: Can I split by multiple different characters and keep them all

ANS: Yes, techniques include using positive lookbehind (?<=[char1|char2]) if supported, or using a custom utility function (like Solution 6) that iteratively applies splits based on an array of separators.

Q: Is there a way to split while keeping delimiters without using lookarounds

ANS: Yes, by using capturing groups (delimiter) in the regex passed to split(), the delimiter is returned as a separate element in the array. Alternatively, a pre-processing step using string.replace() to insert a placeholder before splitting can work.
