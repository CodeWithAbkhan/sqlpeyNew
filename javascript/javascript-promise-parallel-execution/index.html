“JavaScript Promise Parallel Execution: Await with Promise.all vs. Individual Awaits”

How do developers effectively initiate and wait for multiple asynchronous functions in JavaScript to run concurrently, ensuring the fastest overall completion time while managing potential rejections? Various techniques exist, each presenting distinct behaviors concerning error propagation and result collection.

The Promise.all() Approach: Fail-Fast Parallelism

The canonical way to achieve true parallelism with Promises is by utilizing Promise.all(). This method accepts an iterable of Promises and returns a single Promise that resolves when all input Promises have resolved, or immediately rejects if any single Promise rejects.

Awaiting Results with Promise.all()

You can use await directly on Promise.all() to pause execution until every operation completes successfully.

// Example function definitions for demonstration
const fastFulfillingPromise = (value, ms) => 
    new Promise(resolve => setTimeout(() => resolve(value), ms));
const slowRejectingPromise = (reason, ms) => 
    new Promise((_, reject) => setTimeout(() => reject(reason), ms));

try {
    // Initiates both calls concurrently. Will reject immediately when the 50ms promise rejects.
    const results = await Promise.all([
        fastFulfillingPromise('Value A', 100), 
        slowRejectingPromise('Error B', 50)
    ]);
    console.log("All resolved:", results);
} catch (error) {
    console.error("Promise.all caught error:", error); // Output: Error B
}

A critical aspect of Promise.all() is its fail-fast nature. As soon as any supplied Promise rejects, the entire Promise.all() rejects, and no further results are processed, even if other Promises might still be executing. Note that successful actions that completed before the rejection are not automatically rolled back; cleanup must be handled manually if required.

Alternative to Fail-Fast: Promise.allSettled()

When you need to know the outcome of every Promise—whether fulfilled or rejected—without the entire process failing upon the first rejection, Promise.allSettled() is the preferred utility.

Note on Support: Promise.allSettled() is a more modern feature, and older environments like Internet Explorer may require a polyfill for native use.

When using Promise.allSettled(), the returned Promise always resolves once all input Promises have settled (either fulfilled or rejected). The resulting array contains status objects detailing the outcome of each operation.

const happyPromise = (value, ms) => new Promise(resolve => setTimeout(() => resolve(value), ms));
const sadPromise = (reason, ms) => new Promise((_, reject) => setTimeout(() => reject(reason), ms));

// Wait for everything to complete, irrespective of success or failure
const settlementResults = await Promise.allSettled([
    happyPromise('Success 100ms', 100), 
    sadPromise('Failure 50ms', 50)
]);

console.log(settlementResults);
/* Output structure:
[ 
  { "status":"fulfilled", "value":"Success 100ms" }, 
  { "status":"rejected", "reason":"Failure 50ms" } 
]
*/

Executing Without Promise.all(): Manual Parallel Tracking

It is possible to achieve parallelism simply by invoking the asynchronous functions immediately and storing the resulting Promises, then awaiting them later, either individually or grouped. This technique starts all tasks instantly.

// Define functions that return Promises
const getDatabaseRecord = () => new Promise(resolve => {
    console.log('Starting DB query...');
    setTimeout(() => resolve({ data: 'Record A' }), 2000);
});

const getExternalServiceData = () => new Promise(resolve => {
    console.log('Starting API call...');
    setTimeout(() => resolve({ service: 'Data X' }), 500);
});

async function manualParallelFetch() {
    const start = Date.now();

    // 1. Start both asynchronous operations immediately; we get Promises back
    const dbPromise = getDatabaseRecord();
    const apiPromise = getExternalServiceData();

    // 2. Await the results. Execution time is dominated by the slowest call (2000ms).
    const recordData = await dbPromise;
    const serviceData = await apiPromise;

    const duration = Date.now() - start;
    console.log(`Total duration: ${duration}ms`);
    console.log("Results:", recordData, serviceData);
}

// In this pattern, if an error occurs in dbPromise, awaiting dbPromise throws, 
// but apiPromise may have already finished or may throw on its await.
// Error handling requires wrapping individual awaits in try/catch blocks.

Caveat Alert: This method differs slightly from Promise.all() in how errors are surfaced if you await them sequentially. If you use this pattern, you must be careful with error propagation, as the second await might throw an error even if the first one resolved successfully (or vice versa), necessitating fine-grained try...catch blocks around each await.

Parallel Execution for Tasks with Internal Logic

When dealing with an array of tasks (e.g., functions that need execution alongside context), you can use Array.prototype.map() to generate an array of Promises, and then pass this array to Promise.all().

function asyncTask(ms, message) {
    console.log(`Initiating task: ${message} (${ms}ms)`);
    return new Promise(resolve => setTimeout(resolve, ms, `Result of ${message}`));
}

const operationList = [
    { delay: 1000, label: 'Moose' },
    { delay: 500, label: 'Taco' },
    { delay: 5000, label: 'Burp' }
];

// Map tasks to executable promises immediately
const executablePromises = operationList.map(task => asyncTask(task.delay, task.label));

// Run all initiated tasks concurrently
const finalOutputs = await Promise.all(executablePromises);

console.log('All tasks finalized:', finalOutputs);
/* 
Example Output Timeline:
Initiating task: Moose (1000ms)
Initiating task: Taco (500ms)
Initiating task: Burp (5000ms)
Result of Taco 
Result of Moose
Result of Burp
All tasks finalized: [ 'Result of Moose', 'Result of Taco', 'Result of Burp' ]
*/

Concurrency Control Beyond Promises

While Promise.all is excellent for waiting on a known set of independent Promises, if you need to manage a large number of asynchronous tasks while limiting how many run concurrently (e.g., to respect API rate limits), external libraries or custom queue implementations are useful. For instance, using a library like async (popular in Node.js) allows setting a fixed concurrency level.

FAQs on JavaScript Promise Parallel Execution

Q: What is the primary difference between Promise all and Promise allSettled

ANS: Promise.all fails immediately upon the first rejection (fail-fast behavior), whereas Promise.allSettled waits for every Promise to complete, regardless of whether it fulfilled or rejected, returning an array describing each outcome.

Q: Does using individual awaits after initiating promises execute them in parallel

ANS: Yes, if you call the asynchronous functions that return Promises before any await keyword is encountered, the operations start concurrently. Awaiting them sequentially only controls when you check their final values.

Q: If a promise rejects in Promise all do the successful promises run to completion

ANS: When Promise.all rejects, it stops waiting for others, but the operations that already started execution continue running in the background until they naturally settle. The successful results are discarded by the rejection handler.

Q: Can I use Promise allSettled in older browsers

ANS: Promise.allSettled is relatively new; support is robust in modern environments, but older browsers like certain versions of Internet Explorer do not support it natively and would require a compatibility shim or polyfill.
