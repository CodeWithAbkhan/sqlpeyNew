“JavaScript Techniques for Detecting HTML Element Size Changes”

How can we reliably track when an arbitrary HTML element, like a div or textarea, changes its width or height, independent of the main browser window resizing? Traditional browser events often only fire on the window object, leaving developers searching for efficient DOM listening mechanisms. Several techniques have emerged to address this challenge, ranging from modern APIs to clever, older workarounds.

Here are the prominent solutions presented for element resize detection:

The Modern Standard: ResizeObserver API

The Resize Observer API is the preferred, contemporary approach for monitoring element dimension changes, offering excellent performance and direct access to the new dimensions.

Implementation Example (Solution 1 & 4):

This solution initializes the observer to continuously report size updates for a target element.

function reportElementSize() {
 // Assumes 'width' and 'height' are bound variables or accessible references
 width.value = textbox.offsetWidth;
 height.value = textbox.offsetHeight;
}

// Initial call
reportElementSize();

// Observe the target element ('textbox' in this example)
new ResizeObserver(reportElementSize).observe(textbox);

HTML Structure for Observation:

<output id="width">0</output><br>
Height: <output id="height">0</output><br>
<textarea id="textbox">Resize me</textarea><br>

Stopping Observation (Solution 4):

You can explicitly stop tracking changes using disconnect():

const myObserver = new ResizeObserver(entries => {
  entries.forEach(entry => {
    console.log('width', entry.contentRect.width);
    console.log('height', entry.contentRect.height);
  });
});

const someEl = document.querySelector('.some-element');

// Start listening
myObserver.observe(someEl);

// Later, stop listening
myObserver.disconnect();

For further details on the API, consult the Mozilla Developer Network documentation for Resize Observer API . Support levels can be verified via caniuse data .

Available Polyfills: If browser compatibility outside of modern environments is a concern, polyfills exist:

  • pelotoncycle/resize-observer
  • que-etc/resize-observer-polyfill
  • juggle/resize-observer (Also referenced in Solution 13)

Event-Based Libraries: Element Query Proxies

Libraries often implement element query concepts by wrapping detection logic in fast, event-based systems, often avoiding inefficient polling loops.

Using MarcJ’s CSS Element Queries Library (Solution 2 & 8):

The library provides a ResizeSensor class which utilizes an event-driven methodology, claimed to be very fast.

// Requires jQuery
new ResizeSensor(jQuery('#divId'), function(){ 
    console.log('content dimension changed');
});

Caution: Avoid plugins relying on setTimeout() with constant DOM property checks (clientHeight/clientWidth) in a loop, as this causes layout thrashing and wastes CPU cycles (Solution 2).

Lightweight Library Alternative (Solution 7):

The javascript-detect-element-resize library offers a lightweight method if other solutions prove cumbersome:

// Include detect-element-resize.js first

    /* execute action */

removeResizeListener(resizeElement, resizeCallback); // For cleanup

Combined MutationObserver and Window Resize Polling

If ResizeObserver is unavailable, a fallback involves monitoring DOM structure changes (MutationObserver) and the window resize event, polling the dimensions in a combined check (Solution 3 & 24).

Combined Monitoring Function (Solution 3 - Multi-element support):

This function establishes watchers for both window resizes and DOM modifications affecting layout.

var onResize = function(element, callback) {
  if (!onResize.watchedElementData) {
    // Initialize watchers and event hooks on first call
    onResize.watchedElementData = [];

    var checkForChanges = function() {
      onResize.watchedElementData.forEach(function(data) {
        if (data.element.offsetWidth !== data.offsetWidth ||
            data.element.offsetHeight !== data.offsetHeight) {
          data.offsetWidth = data.element.offsetWidth;
          data.offsetHeight = data.element.offsetHeight;
          data.callback();
        }
      });
    };

    // 1. Listen to window size changes
    window.addEventListener('resize', checkForChanges);

    // 2. Listen to DOM layout-affecting changes
    var observer = new MutationObserver(checkForChanges);
    observer.observe(document.body, { 
      attributes: true,
      childList: true,
      characterData: true,
      subtree: true 
    });
  }

  // Register the new element to watch
  onResize.watchedElementData.push({
    element: element,
    offsetWidth: element.offsetWidth,
    offsetHeight: element.offsetHeight,
    callback: callback
  });
};

Using Custom Events and MutationObserver on Style Attribute (Solution 10)

For elements that explicitly change their size via inline style attributes (especially if resize: both is active), MutationObserver can track style attribute mutations and dispatch a custom event.

var divElement = document.getElementById('monitoredDiv');
divElement.addEventListener('clientResize', (event) => console.log(event.detail));

function handleStyleChanges (mutations) {
    const el = mutations[0].target;
    const currentW = el.clientWidth;
    const currentH = el.clientHeight;
    
    // Check if dimensions actually differ from stored old values
    const isDimensionAltered = mutations
      .map((m) => m.oldValue + '')
      .some((prev) => prev.indexOf('width: ' + currentW + 'px') === -1 || prev.indexOf('height: ' + currentH + 'px') === -1);

    if (!isDimensionAltered)
      return;

    // Dispatch custom event upon detected change
    const resizeEvent = new CustomEvent('clientResize', {detail: {width: currentW, height: currentH}});
    el.dispatchEvent(resizeEvent);
}

var styleObserver = new MutationObserver(handleStyleChanges); 
styleObserver.observe(divElement, {attributes: true, attributeOldValue: true, attributeFilter: ['style']});

Example HTML Setup:

<style>
#monitoredDiv {width: 100px; border: 1px solid #bbb; resize: both; overflow: hidden;}
</style>

Polling with setInterval (Discouraged)

A less performant, but simple, pure JavaScript alternative involves periodically checking the element’s dimensions using setInterval. This method is generally slower and less accurate than modern observation APIs (Solution 11 & 18).

let storedWidth = 0; 
const pollingInterval = setInterval(function(){
    const currentDiv = document.getElementById("performanceTestDiv");
    
    if(storedWidth <= 0){
        storedWidth = currentDiv.clientWidth;
    } 
    
    if(currentDiv.clientWidth !== storedWidth) {   
      alert('Dimension changed via polling!');
      storedWidth = currentDiv.clientWidth;
    }    
}, 100); // Check every 100ms

Stopping Polling: You must use clearInterval(pollingInterval) when no longer needed to prevent CPU strain.

Using RxJS for Observable Stream Tracking (Solution 23)

For applications using reactive patterns, RxJS interval combined with distinctUntilChanged provides a clean stream for tracking dimension changes, often triggered by external events like window resizing affecting parent elements.

const { interval } = rxjs;
const { distinctUntilChanged, map } = rxjs.operators;

function trackResizeStream() {
  const timer$ = interval(100);
  const targetDiv = document.getElementById('observableTargetDiv');
  const outputSpan = document.getElementById('currentDimension');
  
  timer$
    .pipe(
      map(() => targetDiv ? Math.round(targetDiv.getBoundingClientRect().width) : 0),
      distinctUntilChanged(),
    )
    .subscribe((width) => {        
      outputSpan.innerHTML = width;
    });
}

FAQs on JavaScript Techniques for Detecting HTML Element Size Changes

Q: Can the native JavaScript resize event be directly bound to a standard HTML element like a div

ANS: No The standard ‘resize’ event is specified to fire only on the window object (or objects that function as windows, like iframes). Direct binding to generic elements is not supported natively.

Q: What is the recommended modern solution for element resizing events

ANS: The recommended approach is the Resize Observer API. It offers superior performance and provides the element’s new dimensions directly upon change.

Q: How do techniques like ResizeSensor work internally

ANS: Techniques like ResizeSensor often involve injecting invisible, overlapping divs within the target element. These divs are manipulated (by setting their overflow to trigger scroll events on massive inner containers) to detect size discrepancies, triggering a callback when a scroll event indicates a dimension change.

Q: Is using setInterval for resize checking acceptable

ANS: Using setInterval to poll dimensions is generally discouraged due to performance implications, especially when monitoring many elements. It can cause unnecessary CPU load compared to event-driven solutions like ResizeObserver.

Q: How can MutationObserver help detect size changes

ANS: MutationObserver itself doesn’t directly track size. However, it can monitor changes to element attributes (like the style attribute) or child structure. Developers often combine MutationObserver triggers with checks against previous offsetWidth/offsetHeight values to infer a size change.
