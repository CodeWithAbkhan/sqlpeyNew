“JavaScript Number Type Check: Integer vs Float Methods”

In JavaScript, all numbers are internally represented as 64-bit floating-point values. This means there isn’t a strict, distinct ‘integer’ type like in some other programming languages. However, we often need to check if a numeric value has a fractional component or if it falls within specific ranges. This distinction is crucial for various calculations, data validation, and logic flow. Let’s explore several approaches to differentiate between integers and floats in JavaScript.

Checking for Integers and Floats

Several JavaScript functions and techniques can be employed to ascertain whether a number is an integer or a float. Each method has its nuances and potential edge cases.

Solution 1: Modulo Operator (%)

A common and straightforward method involves using the modulo operator. If a number divided by 1 has a remainder of 0, it’s considered an integer.

function isIntegerModulo(n) {
   return n % 1 === 0;
}

function isFloatModulo(n) {
    return n % 1 !== 0;
}

console.log(isIntegerModulo(5));    // true
console.log(isFloatModulo(5.5));   // true
console.log(isIntegerModulo(5.0)); // true
console.log(isIntegerModulo('5')); // true (coercion)

To handle cases where the input might not be a number, you can add a check using Number():

function isIntegerRobust(n) {
    return Number(n) === n && n % 1 === 0;
}

function isFloatRobust(n) {
    return Number(n) === n && n % 1 !== 0;
}

console.log(isIntegerRobust(10));      // true
console.log(isIntegerRobust('10'));    // false (due to Number(n) === n check)
console.log(isFloatRobust(10.75));    // true

Solution 2: Number.isInteger() and Number.isSafeInteger()

ECMAScript 2015 (ES6) introduced the built-in Number.isInteger() method. This is a modern and often preferred way to check for integers. It returns true if the argument is an integer, and false otherwise. It also handles non-numeric types gracefully.

console.log(Number.isInteger(123));      // true
console.log(Number.isInteger(123.45));   // false
console.log(Number.isInteger('123'));    // false
console.log(Number.isInteger(NaN));      // false
console.log(Number.isInteger(Infinity)); // false

For scenarios involving very large numbers where precision might be lost, Number.isSafeInteger() is valuable. It checks if a number is within the range of integers that can be accurately represented by JavaScript.

console.log(Number.isSafeInteger(100));              // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER)); // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1)); // false

If compatibility with older browsers (especially Internet Explorer) is a concern, a polyfill can be used:

// Polyfill for Number.isInteger
if (!Number.isInteger) {
  Number.isInteger = function(value) {
    return typeof value === 'number' &&
      isFinite(value) &&
      Math.floor(value) === value;
  };
}

// Polyfill for Number.isSafeInteger (requires isInteger polyfill)
if (!Number.isSafeInteger) {
  Number.MAX_SAFE_INTEGER = 9007199254740991; // Math.pow(2, 53) - 1;
  Number.isSafeInteger = function (value) {
     return Number.isInteger(value) && Math.abs(value) <= Number.MAX_SAFE_INTEGER;
  };
}

Solution 3: Bitwise OR Operator (|)

The bitwise OR operator (|) can be a concise way to check for integers. When applied with 0, it effectively truncates any fractional part. If the original number is equal to its bitwise-ORed version, it’s an integer.

function isIntegerBitwise(n) {
    return n === (n | 0);
}

console.log(isIntegerBitwise(7));   // true
console.log(isIntegerBitwise(7.0)); // true
console.log(isIntegerBitwise(7.5)); // false

This method is generally efficient but might not be as readable for developers unfamiliar with bitwise operations.

Solution 4: parseInt() Comparison

Comparing a number to its parseInt() equivalent can also indicate if it’s an integer. If parseFloat(value) == parseInt(value), it suggests no fractional part was removed by parseInt.

function isIntegerParseInt(value){
    return (parseFloat(value) == parseInt(value)) && !isNaN(value);
}

console.log(isIntegerParseInt(42));      // true
console.log(isIntegerParseInt("42"));    // true (due to implicit coercion)
console.log(isIntegerParseInt(42.0));    // true
console.log(isIntegerParseInt(42.5));    // false
console.log(isIntegerParseInt(""));      // false
console.log(isIntegerParseInt("abc"));   // false

This approach can be lenient with string inputs that resemble integers.

Solution 5: Regular Expressions

For validating string inputs that should represent integers, regular expressions are powerful.

function isIntegerRegex(value) {
    const integerRegex = /^-?[0-9]+$/;
    return typeof value === 'string' && integerRegex.test(value);
}

console.log(isIntegerRegex("123"));    // true
console.log(isIntegerRegex("-45"));   // true
console.log(isIntegerRegex("123.45")); // false
console.log(isIntegerRegex("abc"));   // false
console.log(isIntegerRegex(123));     // false (expects string)

This method is ideal when you need to ensure the representation is an integer string, rather than just checking the numeric value.

Solution 6: Math.floor() and Math.ceil() Comparison

A clever way to identify floats is by comparing Math.floor() and Math.ceil(). If a number is an integer, Math.floor(n) and Math.ceil(n) will return the same value.

const isFloatFloorCeil = v => !isNaN(v) && Math.floor(v) !== Math.ceil(v);
const isIntegerFloorCeil = v => !isNaN(v) && Math.floor(v) === Math.ceil(v);

console.log(isFloatFloorCeil(10));     // false
console.log(isIntegerFloorCeil(10));   // true
console.log(isFloatFloorCeil(10.5));   // true
console.log(isIntegerFloorCeil(10.5)); // false

This is an elegant way to distinguish numbers with fractional parts.

Solution 7: isFinite() and Math.floor()

Combining isFinite() with Math.floor() provides a robust check for integers, ensuring the value is a number, finite, and has no fractional component.

function isIntegerFiniteFloor(value) {
  return typeof value === 'number' && isFinite(value) && Math.floor(value) === value;
}

console.log(isIntegerFiniteFloor(99));       // true
console.log(isIntegerFiniteFloor(99.0));     // true
console.log(isIntegerFiniteFloor(99.1));     // false
console.log(isIntegerFiniteFloor(Infinity)); // false
console.log(isIntegerFiniteFloor('99'));     // false

Solution 8: String Conversion and .indexOf('.')

For string inputs, checking for the presence of a decimal point after converting to a string can be a simple indicator.

function isIntegerStringNoDecimal(value) {
    const strValue = String(value);
    return strValue.indexOf('.') === -1 && !isNaN(strValue);
}

console.log(isIntegerStringNoDecimal(150));      // true
console.log(isIntegerStringNoDecimal('150'));    // true
console.log(isIntegerStringNoDecimal(150.0));    // true
console.log(isIntegerStringNoDecimal('150.0'));  // true
console.log(isIntegerStringNoDecimal(150.5));    // false
console.log(isIntegerStringNoDecimal('150.5'));  // false
console.log(isIntegerStringNoDecimal('abc'));    // false

This method is effective for string representations but less direct for numeric types.

Solution 9: typeof and Modulo (%)

A concise function combining type checking with the modulo operator:

function isIntegerWithType(n) {
   return ((typeof n === 'number') && (n % 1 === 0));
}

function isFloatWithType(n) {
   return ((typeof n === 'number') && (n % 1 !== 0));
}

console.log(isIntegerWithType(200));     // true
console.log(isFloatWithType(200.5));     // true
console.log(isIntegerWithType('200'));   // false

This approach ensures that the input is strictly a number type before applying the modulo check.

Solution 10: String Concatenation Trick

A less common but interesting approach uses string concatenation and isNaN.

function isIntegerTrick(val) {
    return ["string","number"].indexOf(typeof(val)) > -1 && val !== '' && !isNaN(val+".0");
}

console.log(isIntegerTrick(30));        // true
console.log(isIntegerTrick("30"));      // true
console.log(isIntegerTrick(30.0));      // true
console.log(isIntegerTrick("30.0"));    // true
console.log(isIntegerTrick(30.5));      // false
console.log(isIntegerTrick("30.5"));    // false
console.log(isIntegerTrick(""));        // false
console.log(isIntegerTrick("abc"));     // false
console.log(isIntegerTrick(true));      // false
console.log(isIntegerTrick([1,2]));     // false

This function checks if the value is a string or number, is not empty, and when “.0” is appended, it remains a valid number (meaning the original was an integer or could be interpreted as one).

Important Considerations

  • Type Coercion: Be mindful of JavaScript’s automatic type coercion. Methods like parseFloat() == parseInt() or the modulo operator can sometimes treat string representations of numbers as actual numbers, which might not always be the desired behavior.
  • String vs. Number: If you need to strictly check for the number type, explicitly use typeof or Number.isFinite(). If you need to validate string inputs that represent integers, use regular expressions.
  • Safe Integers: For applications dealing with large numbers, Number.isSafeInteger() is essential to prevent precision errors.

Each of these methods offers a way to distinguish between integers and floats in JavaScript, providing flexibility based on your specific requirements and the nature of your input data.

FAQs on JavaScript Number Type Check

Q: What is the most reliable way to check if a JavaScript number is an integer

ANS: Number.isInteger() is generally the most reliable and readable method for checking if a JavaScript value is an integer. It handles non-numeric types and edge cases like Infinity correctly.

Q: Can JavaScript distinguish between integers and floats

ANS: Internally, JavaScript treats all numbers as floating-point values. However, you can use specific functions and operators like Number.isInteger(), the modulo operator (% 1), or comparisons with Math.floor() and Math.ceil() to determine if a number has a fractional part.

Q: How do I check if a string represents an integer in JavaScript

ANS: For checking if a string represents an integer, using a regular expression like /^-?[0-9]+$/ with the .test() method is a robust approach. Alternatively, you could try parsing it and then checking with Number.isInteger().

Q: What happens if I use the modulo operator with a string in JavaScript

ANS: JavaScript will attempt to coerce the string to a number before performing the modulo operation. If the coercion is successful, the operation will proceed. If not, it might result in NaN. For instance, '5' % 1 might evaluate to 0, but 'abc' % 1 would result in NaN.

Q: What are JavaScript safe integers

ANS: Safe integers in JavaScript are integers that can be represented precisely without loss of precision. They range from Number.MIN_SAFE_INTEGER (-9007199254740991) to Number.MAX_SAFE_INTEGER (9007199254740991). You can check if a number falls within this range using Number.isSafeInteger().
