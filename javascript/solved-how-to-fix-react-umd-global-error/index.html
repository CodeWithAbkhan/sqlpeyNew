Tackling the Error: ‘React refers to a UMD global but the current file is a module’

Having upgraded your project to Create React App 4.0 and started to transition your files to TypeScript, you might confront a puzzling error when your TS files don’t include the import statement for React. This error message reads:

'React' refers to a UMD global, but the current file is a module.
Consider adding an import instead.ts(2686)

The question naturally arises: why is this happening, especially if importing React is supposedly no longer mandatory in new versions? To clarify, let’s dive into the technicalities surrounding this issue.

Nature of the Error

The error occurs because your TypeScript files are treated as modules, and in the absence of a React import, TypeScript cannot correctly associate the global variable React with your code. With the new JSX transform introduced in React 17, the import React from 'react' statement became optional in many scenarios. However, this flexibility is contingent upon your TypeScript setup.

Solutions to Resolve the Error

Solution 1: Ensure Compatibility

To eliminate this TypeScript error while utilizing JSX without needing to import React, confirm that your project meets the following requirements:

  1. TypeScript Version: Ensure you’re using TypeScript version 4.1 or above.
  2. React and React-DOM Versions: You should have at least version 17 of both react and react-dom.
  3. tsconfig.json Configuration: Your tsconfig.json file needs to specify a jsx compiler option set to either react-jsx or react-jsxdev.

Here’s how your tsconfig.json should look:

// tsconfig.json
{
 "compilerOptions": {
  ...
  "jsx": "react-jsx",
  ...
 },
}

This configuration allows TypeScript to utilize the new JSX factories that React 17 provides, effectively resolving the error for module files. For more details, refer to the TypeScript documentation on JSX factories .

Solution 2: Manual Import

If you prefer a straightforward approach or find you’re unable to upgrade your environment right away, you can simply add the following line to your component files to resolve the error:

import React from 'react';

This import statement will satisfy TypeScript’s demand for a module declaration and eliminate the error message.

Practical Example: Correcting a Basic TSX File

To provide clarity, here’s a practical example of a simple TSX component:

// Users.tsx
const Users = () => {
 return <>Teachers aka Users</>;
};

// Ensure the import is made if using a module without compliant tsconfig.
import React from 'react'; 

export default Users;

Alternative Solutions

If you are maintaining older codebases or libraries that expect the classic behavior of React imports, it might be useful to retain this import statement across your components until you are able to ensure all supporting files count on React 17’s capabilities.

FAQs on Solved How to Fix ‘React refers to a UMD global but the current file is a module’ Error in TypeScript

Q: Why do I see the error that mentions 'React' as a UMD global?

A: This error indicates that TypeScript does not recognize React within your module-based file since it hasn’t been imported. To address this, ensure your project is configured correctly, or manually import React where necessary.
