“JavaScript Viewport Dimensions: Cross-Browser Solutions and Best Practices”

When developing responsive web designs, accurately obtaining the browser’s viewport dimensions is crucial. This allows for dynamic adjustments to layout and behavior based on the user’s screen size. However, different browsers and rendering modes can yield varying results, making a consistent approach essential.

Several JavaScript properties and methods can be used to retrieve viewport width and height. Understanding their nuances and browser compatibility is key to implementing reliable solutions.

Solution 1: Using window.innerWidth and window.innerHeight

This approach leverages the window.innerWidth and window.innerHeight properties, which represent the layout viewport. These values typically include scrollbars.

let vw = Math.max(document.documentElement.clientWidth || 0, window.innerWidth || 0);
let vh = Math.max(document.documentElement.clientHeight || 0, window.innerHeight || 0);

console.log(`Viewport Width: ${vw}, Viewport Height: ${vh}`);

Considerations:

  • window.innerWidth and window.innerHeight include scrollbars.
  • Initial scale and zoom settings on mobile devices might affect these values, potentially making them smaller than @media query values.
  • Zoom can introduce 1px discrepancies due to native rounding.
  • These properties are undefined in Internet Explorer 8 and earlier.

Solution 2: Using jQuery Dimension Functions

If you are already using jQuery in your project, its dimension functions offer a convenient way to get viewport size.

$(window).width();
$(window).height();

Solution 3: document.documentElement.clientWidth and clientHeight

These properties return the viewport width and height excluding scrollbars when the document is in standards mode. They align with CSS viewport @media query values in the absence of a scrollbar.

let vw = document.documentElement.clientWidth;
let vh = document.documentElement.clientHeight;

console.log(`Document Element Width: ${vw}, Document Element Height: ${vh}`);

Considerations:

  • These values are accurate when there’s no scrollbar.
  • They are equivalent to jQuery’s $(window).width() which jQuery terms the browser viewport.
  • Inaccurate results can occur if the <!DOCTYPE> declaration is missing (Quirks mode).

Solution 4: A Cross-Browser Snippet (No jQuery)

For browsers that do not support window.innerWidth, or to handle different rendering modes in Internet Explorer, the following snippet is effective. It accounts for both standards mode and quirks mode.

var element = (document.compatMode === "CSS1Compat") ? 
    document.documentElement :
    document.body;

var height = element.clientHeight;
var width = element.clientWidth;

console.log(`Element Width: ${width}, Element Height: ${height}`);

Solution 5: Dynamic Size Detection with Event Listener

This method uses window.innerWidth and document.documentElement.clientWidth to dynamically detect and display page size, updating it whenever the window is resized.

function updatePageSize() {
  let width, height;
  if (window.innerWidth !== undefined && window.innerHeight !== undefined) { 
    width = window.innerWidth;
    height = window.innerHeight;
  } else {  
    width = document.documentElement.clientWidth;
    height = document.documentElement.clientHeight;
  }
  var text = "Page size: width=" + width + ", height=" + height;
  document.getElementById("demo").innerHTML = text;
}

// Initial call on page load
window.onload = updatePageSize;
// Update when the window is resized
window.onresize = updatePageSize;

<!DOCTYPE html>
<html>
  <body onload="updatePageSize()" onresize="updatePageSize()">
   <p>
    Try to resize the page.
   </p>
   <p id="demo">&nbsp;</p>
  </body>
</html>

Solution 6: Adjusting Meta Viewport for Responsive Behavior

This solution addresses scenarios where you need to dynamically set the viewport meta tag, particularly for adapting fixed-width desktop sites to mobile. It checks window.screen.width to decide which viewport configuration to apply.

// Dynamic viewport meta tag adjustment
(function() {
  if (window.screen.width) {
    const setViewport = {
      phoneViewport: 'width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no',
      desktopViewport: 'width=1045,user-scalable=yes', // Adjust 'width' as per your site's fixed width
      currentDeviceWidth: window.screen.width,
      mobileBreakpoint: 560, // Example breakpoint for mobile vs. larger devices
      setMetaTag: function () {
        const viewportContent = (this.currentDeviceWidth <= this.mobileBreakpoint) ? this.phoneViewport : this.desktopViewport; 
        let head = document.getElementsByTagName("head")[0];
        let viewportMeta = document.createElement('meta');
        viewportMeta.setAttribute('name','viewport');
        viewportMeta.setAttribute('content', viewportContent);
        head.appendChild(viewportMeta);
      }
    };
    setViewport.setMetaTag();
  }
})();

Solution 7: A Robust Cross-Browser Viewport Size Function

This function, inspired by “JavaScript: The Definitive Guide,” provides a reliable way to get viewport dimensions, working across various browser modes.

function getViewportSize(win) {
    win = win || window;
    // Works for most modern browsers
    if (win.innerWidth != null) return { width: win.innerWidth, height: win.innerHeight };

    var doc = win.document;
    // For IE in Standards mode
    if (document.compatMode == "CSS1Compat")
        return { width: doc.documentElement.clientWidth,
           height: doc.documentElement.clientHeight };

    // For browsers in Quirks mode
    return { width: doc.body.clientWidth, height: doc.body.clientHeight };
}

console.log('Viewport dimensions:', getViewportSize());

Solution 8: Warning on Mobile Viewport Pixel Accuracy

A note of caution for those seeking virtual pixel measurements on mobile. Standard methods like window.innerHeight or document.documentElement.clientHeight might return unexpected values on iOS and Android, especially concerning landscape/portrait modes and high-density displays. The window.outerWidth property is mentioned as a potentially more accurate, though not universally perfect, solution for mobile virtual width. Further research into specific mobile viewport behavior is recommended. Learn more about viewport concepts .

Solution 9: Concise Viewport Retrieval

An alternative, concise method for retrieving viewport dimensions, checking for window.innerWidth and falling back to document.documentElement or document.body.

function getViewport() {
    var element = window, property = 'inner';
    if (!('innerWidth' in window )) {
        property = 'client';
        element = document.documentElement || document.body;
    }
    return { width : element[ property+'Width' ] , height : element[ property+'Height' ] };
}

console.log('Viewport width: ' + getViewport().width);

Solution 10: window.innerHeight vs. document.documentElement.clientHeight

A key distinction: window.innerHeight includes the height of the horizontal scrollbar, whereas document.documentElement.clientHeight typically does not.

Solution 11: Dynamic Size Detection with window.visualViewport

For real-time detection of viewport size changes, including those caused by virtual keyboards or pinch-zooming, the window.visualViewport API is valuable.

console.log('Initial visual viewport height: ' + window.visualViewport.height);
console.log('Initial visual viewport width: ' + window.visualViewport.width);

window.addEventListener('resize', (event) => {         
      console.log(`Resized visual viewport width: ${event.target.visualViewport.width}px`);
      console.log(`Resized visual viewport height: ${event.target.visualViewport.height}px`);
 });

Solution 12: Canonical Viewport Dimensions

A straightforward approach using document.documentElement.clientWidth and document.documentElement.clientHeight is often sufficient for many cases.

let vw = document.documentElement.clientWidth;
let vh = document.documentElement.clientHeight;

console.log(`Canonical Viewport Width: ${vw}, Canonical Viewport Height: ${vh}`);

For additional resources, check out viewport.moz.one for testing various dimensions.

Solution 13: Using Viewport Units (vw/vh) for Measurement

A standards-compliant method involves creating a temporary div element, setting its dimensions to 100vw and 100vh, and then measuring its offsetWidth and offsetHeight. This leverages modern CSS viewport units.

var tempDiv = document.createElement("div");
tempDiv.style.width  = "100vw";
tempDiv.style.height = "100vh";
document.body.appendChild(tempDiv);
var viewportWidth  = tempDiv.offsetWidth;
var viewportHeight = tempDiv.offsetHeight;
document.body.removeChild(tempDiv);

console.log(`Viewport Width via vw/vh: ${viewportWidth}, Viewport Height via vw/vh: ${viewportHeight}`);

Setting position: "fixed" on the temporary div can also improve compatibility.

Solution 14: A Robust viewportWidth Function

This function aims for broad compatibility, checking window.innerWidth first and then falling back to document.documentElement or document.body client dimensions. It includes logic to handle potential overflow issues by temporarily setting overflow: "hidden".

function getViewportWidth() {
  if (window.innerWidth) return window.innerWidth;
  
  var doc = document;
  var html = doc && doc.documentElement;
  var body = doc && (doc.body || doc.getElementsByTagName("body")[0]);
  
  var getWidthOfElement = function (element) {
    if (!element) return 0;
    
    var style = element.style;
    var originalOverflow = style.overflow;
    style.overflow = "hidden";
    var width = element.clientWidth || 0;
    style.overflow = originalOverflow || ""; // Restore original overflow
    return width;
  };
  
  return Math.max(
    getWidthOfElement(html),
    getWidthOfElement(body)
  );
}

console.log('Viewport Width (Robust): ' + getViewportWidth());

Solution 15: React Hooks for Window Size

For React applications, custom hooks like useWindowSize provide a clean way to manage and access viewport dimensions.

Solution 16: Resizing Event Listener

The window.addEventListener('resize', yourFunction) is a fundamental way to execute code whenever the browser window is resized. Properties like window.innerWidth and document.documentElement.clientWidth are read-only.

Solution 17: Detecting Devices with window.matchMedia()

The window.matchMedia() method allows you to detect device types or screen characteristics based on CSS media queries, offering a reliable way to differentiate between mobile and desktop views.

$(document).ready(function(){
    if(window.matchMedia("(max-width: 767px)").matches){
        // The viewport is less than 768 pixels wide (e.g., mobile)
        alert("This is a mobile device.");
    } else{
        // The viewport is 768 pixels or wider (e.g., tablet or desktop)
        alert("This is a tablet or desktop.");
    }
});

FAQs on JavaScript Viewport Dimensions

Q: What is the difference between window.innerWidth and document.documentElement.clientWidth

ANS: window.innerWidth includes scrollbar width, while document.documentElement.clientWidth typically excludes it and represents the layout viewport in standards mode.

Q: How do I get viewport dimensions without using jQuery

ANS: You can use window.innerWidth and window.innerHeight, or document.documentElement.clientWidth and document.documentElement.clientHeight. For broader compatibility, a combination or a dedicated function like Solution 7 or 9 is recommended.

Q: Why might viewport values differ across devices

ANS: Differences can arise from browser rendering modes (standards vs. quirks), the presence of scrollbars, device pixel ratios, and browser-specific handling of zoom or viewport meta tags.

Q: How can I make my JavaScript code update viewport size dynamically

ANS: Attach an event listener to the window.resize event. Inside your handler function, re-calculate and use the viewport dimensions. For real-time updates that account for pinch-zooms, consider window.visualViewport.

Q: Is there a standard way to measure 100vw in JavaScript

ANS: Yes, you can create a temporary div, set its width to 100vw, append it to the DOM, measure its offsetWidth, and then remove it. This leverages CSS viewport units.
let vw = Math.max(document.documentElement.clientWidth || 0, window.innerWidth || 0)
let vh = Math.max(document.documentElement.clientHeight || 0, window.innerHeight || 0)
