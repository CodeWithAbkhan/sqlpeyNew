How to Effectively Test for Thrown Exceptions in Jest

In the realm of JavaScript testing, one fundamental aspect revolves around ensuring that exceptions are thrown as expected. Working with the Jest testing framework, developers often seek efficient ways to validate the types of exceptions, be they TypeError, ReferenceError, or other varieties.

If you have been transitioning from a different testing framework like AVA to Jest, you may wonder about the best practices for checking thrown exceptions. This guide will explore multiple effective methods to achieve this, ensuring that your code remains robust and your tests are effective.

Method 1: Using expect().toThrow() with Functions

In Jest, a simple yet effective way to test for thrown exceptions is using the expect().toThrow() syntax. This method requires you to pass the function that is expected to throw the error. Here’s a practical example:

test("should throw TypeError when invoked", () => {
    const throwTypeError = () => {
        throw new TypeError("A TypeError occurred");
    };
    expect(throwTypeError).toThrow(TypeError); // Check for the type of error
    expect(throwTypeError).toThrow("A TypeError occurred"); // Check for the error message
});

Method 2: Using Try/Catch with Assertions

For scenarios where you need additional control over the error handling and assertions within the test, you might opt for a try/catch block. Here’s how you can do this:

it("should throw an Error with a specific message", () => {
    expect.assertions(1); // Ensures that the assertion is called
    try {
        throwError(); // Function expected to throw an error
    } catch (e) {
        expect(e.message).toBe("EXPECTED ERROR MESSAGE");
    }
});

In this approach, you can explicitly verify the error message, adding clarity to your tests.

Method 3: Handling Errors with Error Wrappers

To comply with the no-conditional-expect rule within ESLint for Jest, you can create an error wrapper function. This method keeps your tests clean and maintainable while ensuring that the error is handled correctly:

class NoErrorThrownError extends Error {}

const getError = async (call) => {
    try {
        await call(); // Attempt the call, expecting it to throw
        throw new NoErrorThrownError(); // Throws if no error occurred
    } catch (error) {
        return error; // Return the caught error
    }
};

describe("when the request fails", () => {
    it("should capture the error correctly", async () => {
        const error = await getError(async () => {
            // Simulate a failed HTTP request
            throw new Error("Network Error");
        });
        expect(error).not.toBeInstanceOf(NoErrorThrownError); // Ensure an error was thrown
        expect(error.message).toBe("Network Error"); // Validate the error message
    });
});

This pattern is particularly useful in asynchronous tests, handling errors in a structured manner.

Method 4: Asserting Specific Error Properties

Sometimes, you want not just to catch an error but also to verify its properties. For this, you can use a combination of assertions with the error object:

it("should throw an error with the correct statusCode", async () => {
    const error = await getError(async () => {
        throw { statusCode: 404, message: "Not Found" }; // Simulated error
    });
    expect(error).toHaveProperty("statusCode", 404); // Check for specific property in the error object
});

Using this method, you can create comprehensive tests that validate both the type and details of the thrown exceptions.

FAQs on Testing for Thrown Exceptions in Jest

Q: How do I test if a function throws an error in Jest?

A: You can test if a function throws an error by using expect(function).toThrow(ErrorType). This syntax allows you to check both the type of the error and its message.

Q: Can I use try/catch in my Jest tests?

A: Yes, you can use try/catch blocks to handle exceptions in Jest tests, especially when you need to assert on the error message or properties directly.

Q: What is the no-conditional-expect rule in Jest?

A: The no-conditional-expect rule helps enforce that all assertions should be unconditional and executed in every test case. This can be managed effectively using async/await patterns or wrappers.
