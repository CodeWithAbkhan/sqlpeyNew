“JavaScript Techniques for Modifying URL Query Strings”

How can developers effectively manipulate URL query strings—adding new parameters, updating existing ones, or removing them entirely—using modern JavaScript approaches, while also considering browser compatibility and performance trade-offs? Several robust methods exist, leveraging native browser APIs like URL and URLSearchParams, alongside custom function implementations.

Utilizing Native Web APIs for Query String Management

The modern approach favors the built-in URL and URLSearchParams interfaces for reliable query string handling. These APIs abstract away manual string splitting and encoding complexities.

Solution 1: Using the URL Constructor and searchParams

The URL object provides access to the query string via its searchParams property, which is an instance of URLSearchParams. This allows setting parameters either by appending new key/value pairs or by overwriting existing ones.

To append a parameter (even if the key already exists, creating duplicates):

// Constructing a URL object
const initialUrlString = "http://foo.bar/?x=1&y=2";
var url = new URL(initialUrlString);

// Append adds a new parameter, even if 'x' already exists
url.searchParams.append('x', 42); 

// Resulting URL query string will have two 'x' parameters: ?x=1&y=2&x=42
console.log(url.href);

To set a parameter (which overwrites the existing value for that key):

// If your expected result is "http://foo.bar/?x=42&y=2" (overwriting existing 'x')
url.searchParams.set('x', 42); 

console.log(url.href);

You retrieve the modified query string via url.search or the full URL via url.href or url.toString().

Solution 2: Modifying window.location.search Directly

If you are working strictly with the current browser location and need to update it, URLSearchParams can be initialized with the current search string:

// Initialize with current location's query string
const urlParams = new URLSearchParams(window.location.search);

// Set or update a parameter
urlParams.set('order', 'date');

// Apply changes by reloading the page implicitly
window.location.search = urlParams.toString();

Compatibility Note: Be aware that URLSearchParams is not supported in older Internet Explorer versions, although it is widely supported in modern browsers including Edge.

Solution 11: Updating URL Without Reloading (SPA/PWA Context)

For Single Page Applications (SPAs) or scenarios where a full page reload is undesirable, you can update the browser’s history state using window.history.pushState:

function setURLSearchParam(key, value) {
  const url = new URL(window.location.href);
  url.searchParams.set(key, value);
  // Updates the URL in the address bar without triggering a navigation event
  window.history.pushState({ path: url.href }, '', url.href);
}

Solution 7 & 18: Setting or Appending based on Existence

A common requirement is setting a value if the key doesn’t exist, or setting/updating it if it does. URLSearchParams provides methods to check existence (has) and then choose between set (overwrite) or append (add duplicate).

function setOrAppendParam(key, value) {
    // Use window.location.href for absolute URL construction
    const url = new URL(window.location.href);
    
    if (url.searchParams.has(key)) {
        // Overwrite existing value
        url.searchParams.set(key, value);
    } else {
        // Add new key/value pair
        url.searchParams.append(key, value);
    }
    // To update the browser URL without reload (similar to Solution 11)
    window.history.pushState({}, '', url.href); 
}

Custom String Manipulation Approaches

When older browser support is critical, or when dealing with URLs that might not be strictly valid for the URL constructor (like relative paths without a base), manual string manipulation remains a viable strategy.

Solution 3: Iterative String Parsing (Performance Focused)

This solution avoids regular expressions, potentially offering better performance for very long query strings, as noted in the original context. It manually splits the query string by & and iterates to find and replace the key-value pair.

function insertParam(key, value) {
    key = encodeURIComponent(key);
    value = encodeURIComponent(value);

    // Extract query string part, strip leading '?'
    let kvp = document.location.search.substring(1).split('&');
    let i = 0;

    for (; i < kvp.length; i++) {
        if (kvp[i].startsWith(key + '=')) {
            let pair = kvp[i].split('=');
            pair[1] = value; // Update value
            kvp[i] = pair.join('=');
            break;
        }
    }

    // If key was not found, append it
    if (i >= kvp.length) {
        kvp[kvp.length] = [key, value].join('=');
    }

    let params = kvp.join('&');

    // Update the location (reloads the page)
    document.location.search = params;
}

Solution 6: Regex Replacement for Clarity

This method prioritizes legibility over micro-optimization, using regular expressions to either replace an existing parameter or append a new one if no replacement occurs.

/**
* Add a URL parameter (or changing it if it already exists)
*/
var addUrlParam = function(search, key, val){
  var newParam = key + '=' + val,
      params = '?' + newParam;

  if (search) {
    // Try to replace an existing instance, looking for '?' or '&' preceding the key
    params = search.replace(new RegExp('([?&])' + key + '[^&]*'), '$1' + newParam);

    // If nothing was replaced, then add the new param to the end
    if (params === search) {
      // Check if search starts with '?', if not, prepend '?' instead of '&'
      params += (search.startsWith('?') ? '&' : '?') + newParam;
    }
  } else {
      // If no existing search string, start with '?'
      params = '?' + newParam;
  }

  return params;
};

// Usage example: updating the current location
document.location.search = addUrlParam(document.location.search, 'foo', 'bar');

Solution 13: Handling Fragments and Encoding Explicitly

This solution is geared towards robustness, managing URLs that include hash fragments (#) separately from the query string, and ensuring proper URI encoding. It supports adding, updating, or removing parameters based on whether value is supplied.

function updateUrl(url, key, value) {
    if (value !== undefined) {
        value = encodeURI(value);
    }
    
    // Separate hash fragment from the rest of the URL
    var hashIndex = url.indexOf("#") | 0;
    if (hashIndex === -1) hashIndex = url.length | 0;
    
    var urls = url.substring(0, hashIndex).split('?');
    var baseUrl = urls[0];
    var parameters = '';
    var outPara = {};

    if (urls.length > 1) {
        parameters = urls[1];
    }

    // Parse existing parameters
    if (parameters !== '') {
        parameters = parameters.split('&');
        for (let k in parameters) {
            let keyVal = parameters[k].split('=');
            let ekey = keyVal[0];
            let evalue = keyVal.length > 1 ? keyVal[1] : '';
            outPara[ekey] = evalue;
        }
    }

    // Add, update, or delete
    if (value !== undefined) {
        outPara[key] = value;
    } else {
        delete outPara[key];
    }
    
    // Rebuild query string
    parameters = [];
    for (var k in outPara) {
        parameters.push(k + '=' + outPara[k]);
    }

    var finalUrl = baseUrl;
    if (parameters.length > 0) {
        finalUrl += '?' + parameters.join('&'); 
    }

    // Reattach hash fragment
    return finalUrl + url.substring(hashIndex); 
}

Alternative Approaches for Node.js or Specific Environments

When working outside the browser, like in a Node.js backend environment, you can use the built-in url module.

Solution 16: Node.js url Module

In Node.js, you import the URL class to construct and manipulate URLs, similar to the browser API, but you must explicitly import it.

const { URL } = require('url');

// Example setup within Node REPL:
// > const { URL } = require('url');
// > let url = new URL('', 'http://localhost:1989/v3/orders');
// > let fetchAll=true, timePeriod = 30, b2b=false;
// > url.searchParams.append('fetchAll', fetchAll);
// > url.searchParams.append('timePeriod', timePeriod);
// > url.searchParams.append('b2b', b2b);
// > url.href
// 'http://localhost:1989/v3/orders?fetchAll=true&timePeriod=30&b2b=false'

Solution 28: Handling Relative URLs with a Dummy Base

To use the modern URL API on relative URLs within a testing or non-browser environment where the base context is unknown, you can provide a temporary base URL, then strip it from the final output string.

/**
 * updates a relative or absolute
 * by setting the search query with
 * the passed key and value.
 */
export const setQueryParam = (url, key, value) => {
  const dummyBaseUrl = 'https://dummy-base-url.com';
  const result = new URL(url, dummyBaseUrl);
  result.searchParams.set(key, value);
  // Remove the temporary base URL introduced by the constructor
  return result.toString().replace(dummyBaseUrl, '');
};

// Example usage:
// setQueryParam('/some-path', 'ref', 'some-value') returns '/some-path?ref=some-value'

FAQs on JavaScript Techniques for Modifying URL Query Strings

Q: Should I prefer URLSearchParams over manual string splitting

ANS: Generally, yes. URLSearchParams is the modern standard, offers better encoding handling, and leads to cleaner, less error-prone code, provided your target environment supports it (which most modern browsers do).

Q: How do I update a parameter without reloading the page

ANS: Use window.history.pushState('', '', newUrl) or window.history.replaceState({}, '', newUrl) after constructing the modified URL using URL or URLSearchParams.

Q: What happens when I use set versus append on URLSearchParams

ANS: set(key, value) replaces any existing parameter with that key, ensuring only one instance exists. append(key, value) adds the parameter regardless of whether the key already exists, resulting in multiple parameters with the same key.

Q: Does URLSearchParams handle URL encoding automatically

ANS: Yes, when using methods like set() or append(), the values are properly encoded into the search string automatically. If you manually reconstruct the string, you might need to use encodeURIComponent.
