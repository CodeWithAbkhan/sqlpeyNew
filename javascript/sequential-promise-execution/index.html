“JavaScript Promises Sequential Execution: How to Run Promises One After Another”

When working with asynchronous operations in JavaScript, a common requirement is to ensure that a series of promises execute one after another, rather than all at once. This sequential execution is crucial for maintaining data integrity, managing dependent operations, or simply controlling the flow of asynchronous tasks. Directly creating an array of promises and executing them will typically lead to parallel execution, which might not be desired. This post explores various effective techniques to achieve sequential promise execution, covering modern async/await syntax, traditional Promise chaining, and utility functions.

Here are several methods to execute a list of promises in sequence:

Solution 1: Using async/await with a for...of loop

The most straightforward approach in modern JavaScript environments that support async/await is to iterate through an array of asynchronous operations using a for...of loop.

async function processFilesSequentially(files) {
  for (const file of files) {
    await readFile(file); // Assuming readFile returns a Promise
  }
}

This pattern naturally enforces sequential execution because await pauses the execution of the async function until the awaited promise resolves.

Solution 2: Using async/await with an asyncGenerator

An alternative, more advanced pattern using async/await is to employ an async generator. This defers the execution of each promise until it’s explicitly yielded.

async function* readFilesGenerator(files) {
  for (const file of files) {
    yield await readFile(file); // Assuming readFile returns a Promise
  }
}

// To consume:
// for await (const content of readFilesGenerator(files)) { ... }

Solution 3: Promise Chaining with reduce

A classic and robust method for sequential promise execution, especially in environments without async/await, involves using the reduce method. This approach chains promises together, ensuring each subsequent promise only starts after the previous one has completed.

const processFilesWithReduce = (files) => {
  return files.reduce((promiseChain, file) => {
    return promiseChain.then(() => readFile(file)); // Assuming readFile returns a Promise
  }, Promise.resolve()); // Start with an already resolved promise
};

Solution 4: Compact reduce for Sequential Execution

This is a more concise version of the reduce pattern for sequential promise execution.

const serialExecution = (tasks) => {
  return tasks.reduce((promise, taskFunc) =>
    promise.then(() => taskFunc()), // Ensure taskFunc is called to get the promise
    Promise.resolve([]) // Initial value can be an empty array if accumulating results
  );
};

// Example Usage:
// const fileOperations = urls.map(url => () => fetch(url));
// serialExecution(fileOperations).then(console.log);

Solution 5: Bluebird’s Promise.map with concurrency: 1

If you’re using a promise library like Bluebird, it offers convenient methods for managing concurrency. Setting concurrency to 1 effectively achieves sequential execution.

const fs = Promise.promisifyAll(require("fs"));

const processFilesBluebird = (files) => {
  return Promise.resolve(files).map(fs.readFileAsync, { concurrency: 1 });

processFilesBluebird(files).then(allFileContents => {

Solution 6: Manual Promise Chaining with forEach

You can manually build a promise chain by iterating through your tasks and appending them to a promise sequence.

function runTasksSequentially(tasks) {
  let sequence = Promise.resolve();
  tasks.forEach(task => {
    sequence = sequence.then(() => task()); // Assuming task returns a Promise
  });
  return sequence;
}

Solution 7: Recursive Promise Handling (Without async/await)

For environments without async/await support, recursion can be used to process promises sequentially.

function downloadRecursively(filesList, index = 0) {

    return Promise.resolve(); // All files processed
  }

    return downloadRecursively(filesList, index + 1);

This method emphasizes creating an array of functions that return promises, rather than an array of promises themselves. This ensures promises are created and executed only when their turn comes in the reduce chain.

Solution 9: Array.prototype.reduce with Arrow Functions

A clean and modern implementation using reduce and arrow functions.

function processArraySequentially(arr, asyncFunction) {
  return arr.reduce(
    (chain, item) => chain.then(results => asyncFunction(item).then(result => results.concat([result]))),
    Promise.resolve([]) // Start with a promise resolving to an empty array
  );
}

Solution 10: Promise.all with map (for sequential handling, not execution)

Solution 11: Custom Promise.sequence Method

Extending the Promise object with a sequence method provides a reusable way to handle sequential promise execution.

Promise.sequence = function(promiseChain) {
  let results = [];
  const entries = promiseChain.entries ? promiseChain.entries() : promiseChain[Symbol.iterator]();
  return new Promise((resolve, reject) => {
    const next = () => {
      const entry = entries.next();
      if (entry.done) return resolve(results);
      results.push(entry.value[1]().then(next, () => reject(results)));
    };
    next();
  });
};

// Usage:
// const tasks = [() => promise1, () => promise2];
// Promise.sequence(tasks).then(console.log);

Solution 12: Promise.series Utility

A utility function that mimics Promise.all but ensures sequential resolution, returning results in an array.

Promise.series = function(arrayOfPromises) {
  const results = [];
  return arrayOfPromises.reduce((seriesPromise, currentPromise) => {
    return seriesPromise.then(() => currentPromise.then(result => results.push(result)));
  }, Promise.resolve()).then(() => results);
};

// Usage:
// Promise.series([promise1, promise2]).then(results => console.log(results));

Solution 13: Array.prototype.reduce with Immediate Promise Invocation

This approach uses reduce to chain promises, ensuring they are invoked immediately within the chain.

const inSeries = (providers) => {
  if (providers.length < 1) return Promise.resolve(null);
  // providers.shift()(initialVal) starts the first promise, others are chained via reduce
  return providers.reduce((chain, provider) => chain.then(provider), providers.shift()(initialVal));
};

Solution 14: async/await with reduce for Sequential Operations

This method combines async/await within reduce for a clean way to manage sequential asynchronous operations, including potential delays or multiple steps within each operation.

async function sequenceOperations(items, callback) {
  const results = [];
  await items.reduce(async (promise, item) => {
    await promise; // Wait for the previous iteration to complete
    const res = await callback(item);
    results.push(res);
  }, Promise.resolve());
  return results;
}

Solution 16: Recursive Promise Chaining with Parameter Handling

This approach provides a flexible Promise.sequence that can handle tasks with varying parameters and contexts.

Promise.sequence = function(tasks, parameters = [], context = null) {
  return new Promise((resolve, reject) => {
    if (tasks.length === 0) return resolve([]);

    let currentPromise = tasks[0].apply(context, parameters[0]);
    const results = new Array(tasks.length);
    let errorOccurred = false;

    for (let i = 1; i < tasks.length; i++) {
      currentPromise = currentPromise.then(res => {
        results[i - 1] = res;
        return tasks[i].apply(context, parameters[i]);
      }, err => {
        results[i - 1] = err;
        errorOccurred = true;
        return tasks[i].apply(context, parameters[i]); // Continue even on error
      });
    }

    currentPromise.then(res => {
      results[tasks.length - 1] = res;
      errorOccurred ? reject(results) : resolve(results);
    }).catch(err => {
      results[tasks.length - 1] = err;
      reject(results);
    });
  });
};

const readFilesSequentially = (files) => {

Solution 25: TypeScript async/await with reduce

A TypeScript implementation showcasing async/await within reduce for robust sequential processing.

export const sequentially = async <T, P>(
  toPromise: (element: T) => Promise<P>,
  elements: T[]
): Promise<P[]> => {
  const results: P[] = [];
  await elements.reduce(async (sequence, element) => {
    await sequence; // Wait for the previous step
    results.push(await toPromise(element));
  }, Promise.resolve());
  return results;
};

FAQs on JavaScript Promise Sequential Execution

Q: Why is sequential execution of promises important

ANS: Sequential execution is important when the order of operations matters, such as when one task depends on the result of a previous one, or when you need to control the rate of asynchronous operations to avoid overwhelming resources.

Q: Can async await be used for sequential promise execution

ANS: Yes, async/await with a for...of loop is one of the most straightforward and readable ways to achieve sequential promise execution in modern JavaScript.

Q: What happens if I map an array of promises directly without chaining

ANS: If you map an array of promises without proper chaining, all promises will likely start executing in parallel as soon as they are created, rather than sequentially.

Q: How does Array reduce help in sequential promise execution

ANS: The reduce method is powerful because it allows you to chain promises. Each promise’s execution is made dependent on the resolution of the previous one in the chain, effectively creating a sequential flow.

Q: Is there a difference between sequential promise execution and sequential promise handling

ANS: Yes, sequential promise execution means each asynchronous operation starts only after the previous one has finished. Sequential promise handling means that even if operations run in parallel, their results are processed one after another in a defined order.
