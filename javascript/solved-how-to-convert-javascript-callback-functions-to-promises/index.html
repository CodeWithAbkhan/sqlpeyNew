“Solved: How to Convert JavaScript Callback Functions to Promises”

This guide explores various techniques to convert existing callback-based functions into promise-returning functions, enhancing code readability and maintainability.

How Promises Function

Promises represent the eventual completion or failure of an asynchronous operation and its resulting value. They possess distinct states:

  • Pending: The initial state, neither fulfilled nor rejected.
  • Fulfilled: The operation completed successfully, and the promise holds a resulting value.
  • Rejected: The operation failed, and the promise holds an error reason.

A crucial principle is that functions designed to return a promise should never throw synchronously. Instead, they should return a rejected promise to signal failure, ensuring consistent error handling. Mixing try...catch with .catch on promises can complicate your asynchronous flow. For a deeper dive into asynchronous JavaScript patterns, consider exploring various Node.js resources (though the link is for .NET, the principle applies).

Method 1: Converting One-Time Events and Basic Callbacks to Promises

This method focuses on common scenarios like DOM content loading or functions with simple success/fail callbacks.

1.1 DOM Ready or Single Event Handling

For events that occur once, such as the window.onload event or a specific element’s first click, Promises provide a clean wrapper.

Using Native ES6 Promises:

/**
 * Creates a promise that resolves when the window has fully loaded.
 * @returns {Promise<void>} A promise that fulfills on window load.
 */
function pageContentReady() {
    return new Promise(function(resolve, reject) {
        // Resolve the promise once the 'load' event fires on the window.
        window.onload = resolve; 
    });
}

// Consume the promise:
pageContentReady().then(function() {
    console.log("DOM and all resources are loaded!");
    // Execute actions after the entire page has loaded.
});

Using Libraries like jQuery Deferred (Alternative):

Libraries like jQuery offer their own promise-like implementations called Deferred objects, which can be useful when working within those ecosystems.

/**
 * Creates a Deferred object that resolves on window load using jQuery.
 * @returns {jQuery.Promise} A jQuery Promise that fulfills when window loads.
 */
function obtainPageLoadDeferred() {
    var deferredInstance = $.Deferred();
    window.onload = function() { deferredInstance.resolve(); };
    return deferredInstance.promise();
}

// Example usage:
obtainPageLoadDeferred().then(function() {
    console.log("jQuery Deferred: Page content is ready!");
});

/**
 * Creates a Deferred object that resolves on a single click event on a specific element.
 * @returns {jQuery.Promise} A jQuery Promise that fulfills after the first click.
 */
function firstClickEventPromise() {
    var clickDeferred = $.Deferred();
    // Assuming '#myTargetButton' exists and supports a 'once' event.
    $("#myTargetButton").one("click", function() {
        clickDeferred.resolve();
    });
    return clickDeferred.promise();
}

// Consume the promise:
firstClickEventPromise().then(function() {
    console.log("jQuery Deferred: Target button clicked for the first time!");
});

1.2 Converting Functions with Plain Callbacks

Many older JavaScript APIs rely on plain callbacks, often providing separate callbacks for success and failure.

Using Native ES6 Promises:

/**
 * Original callback-style function to fetch user data.
 * @param {string} userId Identifier of the user.
 * @param {function(Object): void} successCb Callback for successful data retrieval.
 * @param {function(Error): void} errorCb Callback for failed data retrieval.
 */
function fetchUserProfile(userId, successCb, errorCb) {
    // Simulate an async operation, e.g., an API call
    setTimeout(() => {
        if (userId === 'user123') {
            successCb({ id: userId, name: 'Jane Doe', email: 'jane@example.com' });
        } else {
            errorCb(new Error(`User with ID ${userId} not found.`));
        }
    }, 500);
}

/**
 * Converts fetchUserProfile to a promise-based function.
 * @param {string} userId Identifier of the user.
 * @returns {Promise<Object>} A promise that resolves with user data or rejects with an error.
 */
function fetchUserProfileAsync(userId) {
    return new Promise(function(resolve, reject) {
        // Map the success and error callbacks directly to resolve and reject.
        fetchUserProfile(userId, resolve, reject);
    });
}

// Promise-based usage:
fetchUserProfileAsync('user123')
    .then(profile => console.log('User Profile:', profile))
    .catch(error => console.error('Error fetching profile:', error.message));

fetchUserProfileAsync('user999')
    .then(profile => console.log('User Profile:', profile))
    .catch(error => console.error('Error fetching profile:', error.message));

Using jQuery Deferred for Plain Callbacks:

/**
 * Converts a plain callback function to a jQuery Deferred based function.
 * @param {string} userId Identifier of the user.
 * @returns {jQuery.Promise} A jQuery Promise for the user data.
 */
function getCustomerDataDeferred(userId) {
    var deferred = $.Deferred();
    // Map callbacks to deferred.resolve and deferred.reject
    fetchUserProfile(userId, function(resultData) { deferred.resolve(resultData); }, function(errData) { deferred.reject(errData); });
    return deferred.promise();
}

// jQuery Deferred with $.Deferred(fn) form (more concise):
/**
 * Converts a plain callback function using the $.Deferred(fn) constructor.
 * @param {string} userId Identifier of the user.
 * @returns {jQuery.Promise} A jQuery Promise for the user data.
 */
function getCustomerDataDeferredConcise(userId) {
    return $.Deferred(function(dfrd) {
        fetchUserProfile(userId, dfrd.resolve, dfrd.reject);
    }).promise();
}

// Use with jQuery:
getCustomerDataDeferredConcise('user456')
    .then(data => console.log('Customer Data (jQuery):', data))
    .catch(error => console.error('Error Customer Data (jQuery):', error.message));

Note: jQuery Deferred’s resolve and reject methods are “detachable,” meaning they can be passed as callbacks directly. This feature is not universal across all promise or deferred libraries.

1.3 Node.js Style Callbacks (Nodebacks)

Node.js-style callbacks (nodebacks) have a specific signature: the callback is always the last argument, and its first parameter is an Error object (or null if successful).

Manual Promisification for Nodebacks:

/**
 * Original Node-style callback function to retrieve data.
 * @param {string} itemName Name of the item to retrieve.
 * @param {function(Error|null, Object): void} callback Node-style callback.
 */
function retrieveItemDetails(itemName, callback) {
    // Simulate an async file read or DB fetch
    setTimeout(() => {
        if (itemName === 'widget') {
            callback(null, { id: 'W001', name: 'Widget Pro', price: 29.99 });
        } else {
            callback(new Error(`Item '${itemName}' not found.`));
        }
    }, 300);
}

/**
 * Converts a Node-style callback function to a promise.
 * @param {string} itemName Name of the item.
 * @returns {Promise<Object>} A promise for the item details.
 */
function retrieveItemDetailsAsync(itemName) {
    return new Promise(function(resolve, reject) {
        retrieveItemDetails(itemName, function(error, data) {
            if (error !== null) {
                reject(error); // Reject on error
            } else {
                resolve(data); // Resolve with data
            }
        });
    });
}

// Usage:
retrieveItemDetailsAsync('widget')
    .then(details => console.log('Item details:', details))
    .catch(err => console.error('Failed to get item:', err.message));

Using Library/Native promisify Methods:

Many promise libraries and Node.js itself provide built-in utilities for promisifying nodebacks. This is the preferred approach as it’s more concise and less error-prone.

// Example using Bluebird (a popular promise library)
// var retrieveItemDetailsPromised = Promise.promisify(retrieveItemDetails);

// Example using Q (another promise library)
// var retrieveItemDetailsPromised = Q.denodeify(retrieveItemDetails);

// Using Node.js's built-in util.promisify (Node.js 8+)
const { promisify } = require('util');
const retrieveItemDetailsPromised = promisify(retrieveItemDetails);

// Usage with built-in promisify:
retrieveItemDetailsPromised('gadget')
    .then(details => console.log('Gadget details:', details))
    .catch(err => console.error('Failed to get gadget:', err.message));

1.4 Promisifying an Entire Library

While promisifying functions one by one is feasible, some libraries offer bulk promisification.

Using Bluebird’s promisifyAll:

// Example with a hypothetical callback-based API object
// (In a real scenario, this would be `const fs = require('fs');` or similar)
const LegacyApiModule = {
    fetchUserData(id, cb) { setTimeout(() => cb(null, { userId: id, name: 'Legacy User' }), 100); },
    saveConfig(data, cb) { setTimeout(() => cb(null, { status: 'saved' }), 50); },
    // ... many more callback functions
};

// If using Bluebird:
// Promise.promisifyAll(LegacyApiModule);
// Now LegacyApiModule.fetchUserDataAsync(), LegacyApiModule.saveConfigAsync() are available.
// LegacyApiModule.fetchUserDataAsync('U1').then(data => console.log(data));

Using Native Promises in Node.js (Manual Bulk):

For native Node.js environments, you can manually iterate and promisify functions within an API object.

const { promisify } = require('util');

// Our example LegacyApiModule from above
const ModernApiModule = {};

// Convert each callback function in LegacyApiModule to a promise-returning one
Object.entries(LegacyApiModule).forEach(([key, func]) => {
    // Check if the property is a function and should be promisified
    if (typeof func === 'function') {
        ModernApiModule[`${key}Promised`] = promisify(func);
    }
});

// Using the newly promisified functions
ModernApiModule.fetchUserDataPromised('U101')
    .then(user => console.log('Modern API fetched user:', user))
    .catch(err => console.error('Modern API error:', err));

Important Notes:

  • Promise Chaining: Inside a .then() handler, returning a new promise is standard practice; the outer promise will resolve or reject based on the returned promise’s state. Throwing an error within a .then() handler is also a good pattern, as it will cause the promise chain to reject, leveraging promise throw safety.
  • DOM Events: For production, prefer document.addEventListener over window.onload for event handling, as it allows multiple handlers for the same event and is generally more flexible.

Method 2: Straightforward Promise Conversion with Async/Await

This method demonstrates the most basic conversion from a plain callback function to a promise, highlighting the benefits of async/await for sequential code execution.

2.1 Basic Conversion Example

Let’s convert a simple division function.

Original Callback-Style:

/**
 * Performs division with callbacks for success or error.
 * @param {number} dividend The number to be divided.
 * @param {number} divisor The number to divide by.
 * @param {function(number): void} successCb Callback for successful division.
 * @param {function(Error): void} errorCb Callback for division error.
 */
function calculateDivision(dividend, divisor, successCb, errorCb) {
    if (divisor === 0) {
        return errorCb(new Error("Cannot divide by zero."));
    }
    successCb(dividend / divisor);
}

Promise-Based Conversion:

/**
 * Performs division and returns a Promise.
 * @param {number} dividend The number to be divided.
 * @param {number} divisor The number to divide by.
 * @returns {Promise<number>} A promise that resolves with the result or rejects on error.
 */
function calculateDivisionPromised(dividend, divisor) {
    return new Promise(function (resolve, reject) {
        if (divisor === 0) {
            return reject(new Error("Division by zero is not permitted."));
        }
        resolve(dividend / divisor);
    });
}

// Example usage:
calculateDivisionPromised(10, 2)
    .then(result => console.log('Division result:', result))
    .catch(error => console.error('Division error:', error.message));

calculateDivisionPromised(5, 0)
    .then(result => console.log('Division result:', result))
    .catch(error => console.error('Division error:', error.message));

2.2 Using Async/Await with Promises

The async/await syntax in ES2017 (ES8) makes working with Promises feel more like synchronous code.

/**
 * Returns a Promise that resolves with a name after a delay.
 * @returns {Promise<string>} A promise that resolves with a fixed name.
 */
function fetchUserName() {
    return new Promise(function (fulfill, reject) {
        const userName = "Alice Wonderland";
        // Simulate a network delay
        setTimeout(() => {
            fulfill(userName);
        }, 3000); // Wait for 3 seconds
    });
}

/**
 * An async function demonstrating await with fetchUserName.
 */
async function displayUserName() {
    console.log("Fetching user name...");
    // Awaits for the Promise to fulfill before proceeding.
    const fetchedName = await fetchUserName();
    console.log("User name obtained:", fetchedName); // Logs "Alice Wonderland" after 3 seconds
}

displayUserName(); // Initiate the async operation

2.3 Alternative: Using .then() with Promises

Promises can also be chained using .then() for handling resolved values.

// Using the same fetchUserName() from above

console.log("Fetching user name with .then()...");
// The console logs "Alice Wonderland" after 3 seconds
fetchUserName().then(function(userName) { 
    console.log("User name via .then():", userName); 
});

2.4 Hybrid Callback and Promise Method

Sometimes, you need to support both traditional callback users and modern Promise-based consumers.

/**
 * Performs division, supporting both callbacks and Promises.
 * @param {number} dividend The number to be divided.
 * @param {number} divisor The number to divide by.
 * @param {function(Error|null, number=): void=} callback Optional Node-style callback.
 * @returns {Promise<number>} A promise that resolves with the result or rejects on error.
 */
function calculateDivisionHybrid(dividend, divisor, callback) {
    return new Promise(function (fulfill, reject) {
        if (divisor === 0) {
            let err = new Error("Hybrid: Division by zero.");
            callback && callback(err); // Call callback if provided
            return reject(err); // Reject the promise
        }

        let divisionResult = dividend / divisor;
        callback && callback(null, divisionResult); // Call callback with result
        fulfill(divisionResult); // Fulfill the promise
    });
}

// Usage with Promise:
calculateDivisionHybrid(15, 3)
    .then(res => console.log('Hybrid Promise Result:', res))
    .catch(err => console.error('Hybrid Promise Error:', err.message));

// Usage with Callback:
calculateDivisionHybrid(20, 4, (err, res) => {
    if (err) console.error('Hybrid Callback Error:', err.message);
    else console.log('Hybrid Callback Result:', res);
});

Method 3: Converting HTTP Request Callbacks to Promises

This method demonstrates converting a common asynchronous pattern: an HTTP request that uses callbacks. This is especially relevant in Node.js backend development.

3.1 Before and After Promisification

Consider a simple HTTP GET request using a library like request (though node-fetch or native http modules are often preferred now).

Callback-Based Request:

const httpRequest = require('request'); // Simplified HTTP request client.

/**
 * Wrapper for HTTP GET request using callbacks.
 * @param {string} url The URL to request.
 * @param {function(Error|null, Object=): void} callback Callback with error or response.
 */
function fetchHttpResource(url, callback) {
    httpRequest.get(url, function (err, response) {
        if (err) {
            callback(err);
        } else {
            callback(null, response);
        }
    });
}

// Using the callback-style function:
// fetchHttpResource('http://example.com/api/data', function (err, res) {
//     if (err) console.error('Callback request failed:', err);
//     else console.log('Callback request successful:', res.statusCode);
// });

Promise-Based Request:

const httpRequest = require('request');

/**
 * Wrapper for HTTP GET request, returning a Promise.
 * @param {string} url The URL to request.
 * @returns {Promise<Object>} A promise that resolves with the response or rejects with an error.
 */
function fetchHttpResourcePromised(url) {
    return new Promise(function (resolve, reject) {
        httpRequest.get(url, function (err, response) {
            if (err) {
                reject(err); // Reject the promise on error
            } else {
                resolve(response); // Resolve the promise with the response
            }
        });
    });
}

// Using the promise-based function:
fetchHttpResourcePromised('http://localhost:8080/api/endpoint/1')
    .then(function(response) {
        console.log('Promise request successful! Status:', response.statusCode);
        // Process response data here
    })
    .catch(function(error) {
        console.error('Promise request failed:', error.message);
        // Handle the error
    });

3.2 Handling Multiple Requests with Promise.all()

When you need to fetch multiple resources concurrently and wait for all of them to complete, Promise.all() is invaluable.

const allRequestPromises = [];
allRequestPromises.push(fetchHttpResourcePromised('http://localhost:8080/api/data/1'));
allRequestPromises.push(fetchHttpResourcePromised('http://localhost:8080/api/data/2'));
allRequestPromises.push(fetchHttpResourcePromised('http://localhost:8080/api/data/5'));

Promise.all(allRequestPromises).then(function (results) {
    console.log('All requests completed:', results.map(res => res.statusCode));
    // `results` will be an array containing the responses from each resolved promise.
}).catch(function (err) {
    console.error('One of the requests failed:', err.message);
    // This catches the error of the first promise that rejects.
});

Method 4: Node.js util.promisify() for Nodebacks

Node.js v8.0.0 and later versions include util.promisify(), a built-in API specifically designed to wrap standard Node.js callback-style functions into functions that return Promises. This is the recommended approach for Node.js modules that follow the (error, data) callback convention.

const fileSystemModule = require('fs');
const utilitiesModule = require('util');

// Promisify the fs.readFile function
const readTextFile = utilitiesModule.promisify(fileSystemModule.readFile);

// Now, readTextFile returns a Promise:
readTextFile('/path/to/your/document.txt', 'utf8') // Specify encoding for text files
    .then((fileData) => {
        console.log('File content:', fileData.substring(0, 50) + '...'); // Log first 50 chars
    })
    .catch((err) => {
        console.error('Error reading file:', err.message);
    });

// For more information, refer to the official Node.js documentation on `util.promisify`.

Method 5: Robust DOM Ready Promise (Addressing window.onload Flaws)

The window.onload event only fires once all resources (images, scripts, etc.) are fully loaded, and if you attach a handler after the event has already fired, it won’t execute. For scenarios where you need to run code when the DOM is ready (even if it’s already complete), DOMContentLoaded is superior.

/**
 * Returns a promise that resolves when the DOM is fully loaded and parsed.
 * This is more reliable than window.onload as it accounts for cases where the DOM is already ready.
 * @returns {Promise<void>} A promise that resolves when the DOMContentLoaded event fires or is already complete.
 */
function ensureDOMIsReady() {
    return new Promise(function(resolve) {
        // If the document is already in a 'complete' state, resolve immediately.
        if (document.readyState === "complete" || document.readyState === "interactive") {
            return resolve();
        }
        // Otherwise, wait for the DOMContentLoaded event.
        document.addEventListener("DOMContentLoaded", resolve);
    });
}

// Use the robust promise:
ensureDOMIsReady().then(function() {
    console.log("DOM is ready for interaction!");
    // Your initialization logic goes here
    // For example, initApplicationFeatures();
});

Method 6: Creating a Custom Generic Promisify Function

You can write your own generic promisify helper for functions that adhere to the Node.js callback convention ((err, data) as the last arguments).

/**
 * A generic function to convert a callback-based function to a promise-based one.
 * Assumes the callback has the signature (error, data).
 * @param {function} originalFunc The function to promisify.
 * @param {...any} funcArgs Arguments to pass to the original function, excluding the callback.
 * @returns {Promise<any>} A promise that resolves with data or rejects with an error.
 */
const customPromisify = (originalFunc, ...funcArgs) => {
  return new Promise((resolve, reject) => {
    // Call the original function, appending our custom callback.
    originalFunc(...funcArgs, (err, data) => {
      if (err) {
        return reject(err); // If an error occurs, reject the promise.
      }
      resolve(data); // Otherwise, resolve with the data.
    });
  });
};

// Example Usage:
// Define a simple callback-based sum function for demonstration.
const calculateSumWithCallback = (a, b, callback) => {
    // Simulate async operation
    setTimeout(() => {
        if (typeof a !== 'number' || typeof b !== 'number') {
            return callback(new Error("Inputs must be numbers."));
        }
        callback(null, a + b);
    }, 100);
};

// Promisify and use it
customPromisify(calculateSumWithCallback, 5, 3)
    .then(sumResult => console.log('Custom Promisify Sum:', sumResult)) // Output: 8
    .catch(error => console.error('Custom Promisify Error:', error.message));

customPromisify(calculateSumWithCallback, 'a', 3)
    .then(sumResult => console.log('Custom Promisify Sum:', sumResult))
    .catch(error => console.error('Custom Promisify Error:', error.message)); // Output: Inputs must be numbers.

This custom utility helps illustrate the internal mechanism of how promisification works.

Method 8: Real-World Chaining with Promisified Requests (Node.js/Express)

This example showcases how to chain multiple promisified API calls to achieve a sequential data flow, common in backend services. It uses Express.js for a web server and the request module.

const expressServer = require('express');
const httpClient = require('request'); // Simplified HTTP request client.

const appInstance = expressServer();

/**
 * Promisifies an HTTP GET request.
 * @param {string} resourceUrl The URL to fetch.
 * @returns {Promise<string>} A promise resolving with the response body (JSON string) or rejecting with an error.
 */
function fetchRemoteData(resourceUrl) {
    return new Promise(function (resolve, reject) {
        httpClient.get(resourceUrl, function (err, res, body) {
            if (!err && res.statusCode === 200) {
                resolve(body); // Resolve with the response body
            } else {
                reject(err || new Error(`Request failed with status: ${res.statusCode}`));
            }
        });
    });
}

// Define an API endpoint
appInstance.get('/listUserAlbums', function (req, res) {
    // 1. Get a specific post by ID (e.g., post 100)
    fetchRemoteData('https://jsonplaceholder.typicode.com/posts/100')
        .then(function (postResult) {
            const parsedPost = JSON.parse(postResult);
            // 2. Use the userId from the post to fetch related albums
            return fetchRemoteData(`https://jsonplaceholder.typicode.com/users/${parsedPost.userId}/albums`);
        })
        .catch(function (chainError) {
            console.error('Error in promise chain:', chainError);
            res.status(500).send('Failed to retrieve data.');
            // Re-throw or return a rejected promise to continue chain if needed
            throw chainError; 
        })
        .then(function (albumsResult) {
            // 3. Send the albums data back to the client
            res.status(200).send(albumsResult);
        })
        .catch(finalError => { // Catch any errors from the last .then() or re-thrown errors
            console.error('Final chain error handler:', finalError);
            if (!res.headersSent) { // Prevent setting headers twice
                res.status(500).send('An unexpected error occurred.');
            }
        });
});

const activeServer = appInstance.listen(8081, function () {
    const host = activeServer.address().address;
    const port = activeServer.address().port;
    console.log(`Web service listening at http://${host}:${port}`);
});

// To test: access http://localhost:8081/listUserAlbums in your browser.

Method 9: Vanilla JavaScript Promisify for Browser-side XMLHttpRequest

For client-side applications without Node.js util.promisify, you can create a custom promisify for XMLHttpRequest (XHR), the traditional way to make HTTP requests in browsers.

/**
 * Makes an HTTP GET request using XMLHttpRequest with a callback.
 * @param {string} url The URL to request.
 * @param {function(XMLHttpRequest|null, Object|null): void} callback Callback for response.
 */
function fetchDataViaXHR(url, callback) {
    var xhrObj = new XMLHttpRequest();
    xhrObj.open('GET', url);
    xhrObj.addEventListener('readystatechange', function () {
        if (xhrObj.readyState === 4) { // Request finished and response is ready
            if (xhrObj.status === 200) {
                console.log('XHR successful, calling callback...');
                callback(null, JSON.parse(xhrObj.responseText));
            } else {
                console.log('XHR error, calling callback with error...');
                callback(xhrObj, null); // Pass XHR object as error for more context
            }
        }
    });
    xhrObj.send();
}

/**
 * Converts a callback-based function (like fetchDataViaXHR) to a promise-returning one.
 * @param {function} funcToPromisify The callback-based function.

Method 18: A Custom P Function Promisifier

This custom P function provides a concise way to promisify functions that strictly follow the callback(error, result) signature.

/**
 * A custom promisifier function that wraps a callback-based method.
 * Assumes the method's callback has the signature (error, result).
 * @param {function} targetMethod The callback-based function to promisify.
 * @param {...any} methodParams Parameters for the targetMethod, excluding the callback.
 * @returns {Promise<any>} A promise that resolves with the result or rejects with an error.
 */
var promisifyGeneric = function() {
  var selfContext = this; // Capture 'this' context
  var targetMethod = arguments[0];
  var methodParams = Array.prototype.slice.call(arguments, 1);

  return new Promise((resolve, reject) => {
    if (targetMethod && typeof(targetMethod) === 'function') {
      // Append our custom callback to the method's parameters.
      methodParams.push(function(err, state) {
        if (!err) return resolve(state); // Resolve if no error
        else return reject(err); // Reject if an error occurs
      });
      // Invoke the original method with captured context and modified parameters.
      targetMethod.apply(selfContext, methodParams);
    } else {
      return reject(new Error('Invalid function provided for promisification.'));
    }
  });
};

                },
            ];
            // Invoke the original callback API with the new list of arguments.
            yourCallbackApi(...newArgsWithCallback);
        });
    };
}

Method 24: promesify with Chained .then().catch() Syntax Simulation

This interesting approach creates a promesify function that, instead of returning a native Promise directly, returns an object with then and catch methods, simulating the promise chaining syntax. This can be an educational way to understand promise mechanics.

/**
 * A custom promisifier that returns an object mimicking Promise chain.
 * This is for demonstration and not a standard Promise implementation.
 * It assumes the original function takes success and error callbacks as its last arguments.
 * @param {function} callbackFn The original function with (..., successCb, errorCb).
 * @returns {Object} An object with .then() and .catch() methods.
 */
const customPromiseLikeWrapper = fn => {
  return (...paramsForFn) => ({
    then: onResolveCallback => ({
      catch: onRejectCallback => {
        // Call the original function, mapping its callbacks to our promise-like callbacks.
        fn(...paramsForFn, onResolveCallback, onRejectCallback);
      }
    })
  });
};

// Example original function with separate success/error callbacks:
function performApiAction(actionId, successCallback, errorCallback) {
  setTimeout(() => {
    if (actionId === 'validAction') {
      successCallback({ status: 'API Action Completed' });
    } else {
      errorCallback(new Error('Invalid API action ID.'));
    }
  }, 100);
}

// Use the custom promise-like wrapper:
const apiActionPromisified = customPromiseLikeWrapper(performApiAction);

apiActionPromisified('validAction')
  .then(res => console.log('Custom Promise-like Success:', res))
  .catch(err => console.error('Custom Promise-like Error:', err.message));

  .then(res => console.log('Custom Promise-like Success:', res))
  .catch(err => console.error('Custom Promise-like Error:', err.message));

FAQs on Solved How to Convert Javascript Callback Functions to Promises

Q: What is a Javascript Promise

ANS: JavaScript Promises provide a structured way to handle asynchronous operations, allowing you to define actions for when an operation completes successfully (fulfilled) or fails (rejected).

Q: Why convert callbacks to promises

ANS: Converting callbacks to promises helps avoid “callback hell” or deeply nested code, leading to more readable, maintainable, and sequential asynchronous code, especially when using async await syntax.

Q: Can I use util promisify in browsers

ANS: No util promisify is a Nodejs specific API and is not available in web browsers For browser environments you would typically use custom promise wrappers or libraries like es6-promisify.

Q: What is promise all used for

ANS: Promise all is used to run multiple promises concurrently and wait for all of them to resolve or for any one of them to reject It is useful for aggregating results from independent asynchronous operations.

Q: What are the states of a Promise

ANS: A Promise can be in one of three states pending fulfilled or rejected Pending is the initial state fulfilled means the operation completed successfully and rejected means the operation failed.
