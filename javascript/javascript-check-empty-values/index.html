“JavaScript: Check for Undefined, Null, or Empty Values”

When developing in JavaScript, it’s a common requirement to determine if a variable holds a meaningful value or if it’s considered “empty” in some context. This can range from checking if a variable has been assigned a value at all (i.e., not undefined or null), to verifying if a string is empty, a number is zero, or a collection contains no elements.

This post delves into various methods and best practices for performing these checks, offering multiple solutions with code examples to illustrate each approach. We’ll also discuss the nuances of JavaScript’s truthy and falsy values to provide a robust understanding.

Evaluating Variable States

JavaScript has a distinct set of values that are considered “falsy.” These include: null, undefined, NaN, 0, "" (empty string), and false. Any other value is considered “truthy.” Understanding this dichotomy is crucial for many conditional checks.

Solution 1: Basic Truthy/Falsy Check

The most straightforward way to check if a variable holds a value that isn’t one of the falsy ones is a simple conditional check:

if (value) {
  // This block executes if 'value' is truthy.
  // It means 'value' is NOT null, undefined, NaN, "", 0, or false.
}

For situations where a variable might not even be declared, you should first check its type:

if (typeof foo !== 'undefined') {
  // 'foo' has been declared and has a value (could still be falsy).
}

Combining these, if you are certain a variable is declared, the truthy/falsy check is often sufficient:

// If 'value' is declared and truthy
if (value) {
  // Do something with the value
}

// If 'foo' might not be declared
if (typeof foo !== 'undefined') {
  // 'foo' is defined, now check its truthiness
  if (foo) {
    // Proceed with operations
  }
}

JavaScript differentiates between “nullish” values (null and undefined) and the broader category of “falsy” values.

Checking for Nullish Values ( undefined or null ):

Several methods achieve this:

// Using loose equality (==) - a special case handles undefined and null
if (value == null) { /* value is nullish */ }

// Using strict equality (===) for explicit checks
if (value === undefined || value === null) { /* value is nullish */ }

// Another loose equality check
if (value == undefined) { /* value is nullish */ }

// Using the nullish coalescing operator
if ((value ?? null) === null) { /* value is nullish */ }

To check if a value is not nullish:

// Using loose inequality (!=)
if (value != null) { /* value is not nullish, but could be falsy */ }

// Using strict inequality (!==)
if (value !== undefined && value !== null) { /* value is not nullish, but could be falsy */ }

// Another strict inequality check
if (value != undefined) { /* value is not nullish, but could be falsy */ }

// Using the nullish coalescing operator
if ((value ?? null) !== null) { /* value is not nullish, but could be falsy */ }

Checking for Falsy Values:

Use the logical NOT operator (!):

if (!value) { /* value is falsy */ }

Checking for Truthy Values:

Simply use the value directly in a conditional:

if (value) { /* value is truthy */ }

Data Validation Nuances:

It’s important to note that truthy/falsy or nullish checks alone aren’t always sufficient for data validation. For example, 0 is falsy but a valid age. You’ll need to add specific logic:

// Checking if a number is not nullish and is non-negative
[null, -1, 0, 1].forEach(num => {
  if (num != null && num >= 0) {
    console.log(`%o is valid`, num);
  } else {
    console.log(`%o is invalid`, num);
  }
});

// Checking if a string has non-whitespace characters
[null, "", " ", "hello"].forEach(str => {
  if (str && /\S/.test(str)) {
    console.log(`%o has content`, str);
  } else {
    console.log(`%o is empty or whitespace`, str);
  }
});

// Checking if an array has elements
[null, [], [1]].forEach(arr => {
  if (arr?.length) { // Using optional chaining for safety
    console.log(`%o has items`, arr);
  } else {
    console.log(`%o is empty or nullish`, arr);
  }
});

Solution 3: Custom isEmpty Functions

Creating a reusable isEmpty function can streamline your code. Here are a few variations:

// Checks for null, undefined, empty string, or zero-length array/function
function isEmptySimple(value) {
  return (value == null || value.length === 0);
}

// Checks for null, undefined, or empty string
function isEmptyOrBlankString(value) {
  return (value == null || value === '');
}

// Checks for null, undefined, or whitespace-only string
function isEmptyOrWhitespace(value) {
  return (value == null || value.trim().length === 0);
}

Solution 4: Strict Type and Value Check

A robust check combines type verification with value assessment:

if (typeof value !== 'undefined' && value) {
  // 'value' is declared, not null, not NaN, not empty string, not 0, and not false.
}

Solution 5: Nullish Coalescing Operator (??)

The ?? operator provides a concise way to fall back to a default value for null or undefined inputs:

let result = potentialValue ?? defaultValue;
// Equivalent to:
// let result = (potentialValue !== null && potentialValue !== undefined) ? potentialValue : defaultValue;

Solution 6: Comprehensive isEmpty Logic

This approach considers null, undefined, empty arrays, and objects with no keys:

function isTrulyEmpty(value) {
  return (
    // null or undefined
    (value == null) ||

    // has length and it's zero (e.g., [], '', function)
    (value.hasOwnProperty('length') && value.length === 0) ||

    // is an Object and has no own enumerable keys
    (value.constructor === Object && Object.keys(value).length === 0)
  );
}

Solution 7: Advanced Type Detection

For more granular checks, a typeOf utility function can be helpful:

Solution 8: Double Negation (!!)

A double negation converts any value to its boolean equivalent:

if (!!value) {
  // 'value' is truthy
}

Solution 9: Handling Undefined Variables Safely

Accessing an undeclared variable directly will cause a ReferenceError. Use typeof to prevent this:

if (typeof declaredOrNotVariable !== "undefined" && declaredOrNotVariable) {
  // Variable is declared AND truthy
}

Solution 10: The Philosophy of “Vacuousness”

This perspective argues against generic “emptiness” checks. Instead, it advocates for type-specific validation. For instance, instead of isEmpty(value), use checks like isStringEmpty(value) or isArrayEmpty(value).

// Helper to check type and direct instance
const isType = (value, Cls) =>
  value != null && Object.getPrototypeOf(value).constructor === Cls;

// Example: Check for a non-empty string
if (isType(myVar, String) && myVar.length > 0) {
  // myVar is a non-empty string
}

// Example: Check for a non-zero number
if (isType(myVar, Number) && myVar !== 0) {
  // myVar is a non-zero number
}

Solution 11: Minimal Null/Undefined Check

If your definition of “empty” is strictly null or undefined:

function isNullOrUndefined(value) {
  return typeof value === "undefined" || value === null;
}

Solution 12: The Power of !

The ! operator concisely checks for all falsy values:

function isFalsy(value) {
  return !value;
}

Solution 13: Loose Equality (==) for Simplicity

Combining loose equality with specific checks can be effective:

// Checks for null, undefined, or empty string
const isNullishOrEmptyString = val => val == null || val === '';

// More explicit check for null, undefined, empty string, or empty array
const isNullishOrEmpty = val =>
  val === undefined || val === null || val === '' || (Array.isArray(val) && val.length === 0);

Solution 14: Whitespace Handling for Strings

Ensure strings with only whitespace are also considered empty:

function isWhitespaceEmpty(value) {
  return value ? value.trim().length === 0 : true;
}

Solution 15: Lodash/Underscore _.isEmpty Equivalent

A common utility function checks for empty arrays, strings, objects, and other collections:

function customIsEmpty(value) {
  if (!value) return true;
  if (Array.isArray(value) || typeof value === 'string') {
    return !value.length;
  }
  for (const key in value) {
    if (Object.prototype.hasOwnProperty.call(value, key)) {
      return false;
    }
  }
  return true;
}

Solution 20: Type-Specific Emptiness Checks

A function that handles numbers, strings, arrays, and objects specifically:

const isEmptyValue = value => {
  if (typeof value === 'number') return false;
  if (typeof value === 'string') return value.trim().length === 0;
  if (Array.isArray(value)) return value.length === 0;
  if (typeof value === 'object') return value == null || Object.keys(value).length === 0;
  if (typeof value === 'boolean') return false;
  return !value; // Handles undefined, null, NaN, false
};

FAQs on JavaScript Empty Value Checks

Q: What is the simplest way to check if a JavaScript variable is not empty

ANS: The simplest way is to use a truthy check: if (value) { ... }. This works for most cases where you want to exclude null, undefined, 0, "", NaN, and false.

Q: How do I differentiate between null, undefined, and an empty string in JavaScript

ANS: You can use strict equality checks: value === null, value === undefined, and value === ''. Alternatively, value == null checks for both null and undefined.

Q: Can I check if a variable is declared before checking its value in JavaScript

ANS: Yes, use the typeof operator: if (typeof myVar !== 'undefined') { ... }. This prevents ReferenceError exceptions.

Q: What are JavaScript's falsy values

ANS: The falsy values in JavaScript are false, 0, "" (empty string), null, undefined, and NaN.

Q: Is there a modern JavaScript operator for handling null or undefined values

ANS: Yes, the nullish coalescing operator (??) provides a default value if the left-hand operand is null or undefined. For example, variable ?? defaultValue.

Q: How do I check if an object or array is empty in JavaScript

ANS: For arrays, check array.length === 0. For objects, check Object.keys(object).length === 0. Remember to also check if the variable itself is not null or undefined first.
