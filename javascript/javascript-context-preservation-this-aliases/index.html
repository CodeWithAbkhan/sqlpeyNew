“JavaScript Context Preservation: Why Use ’this’ Aliases Like ‘self’ or ’that’”

The idiom var self = this; (or variations like var that = this;) serves a specific historical and functional purpose within JavaScript’s execution model, primarily related to how the this keyword behaves within nested functions and closures.

The Core Issue: Changing Context in Nested Functions

In JavaScript, the value of this is determined by how a function is called. When a regular function is executed, this usually refers to the global object (or undefined in strict mode). When a function is a method of an object, this refers to that object.

However, when you place a function inside another context—like an event handler or a callback—the inner function often receives a different this context, typically referring to the element that triggered the event or the global object, losing the reference to the outer object’s this.

Developers use an alias (like self or that) to capture the intended this from the outer scope before the context shifts. Inner functions maintain access to variables declared in the outer scope due to closures.

For instance, consider an object constructor needing to reference its own property inside an asynchronous event listener:

function ApplicationService(config) {
  this.endpointUrl = config.url || "/api/default";
  this.isInitialized = false;

  // Capture the instance's 'this' into 'that'
  let that = this;

  // Set up an event listener where 'this' would normally change
  document.getElementById("startButton").addEventListener('click', function(event) {
    // Inside here, 'this' refers to the button element, not ApplicationService instance.
    // We use 'that' to securely access the instance property.
    if (that.isInitialized) {
      console.log(`Accessing property via captured context: ${that.endpointUrl}`);
    }
  });

  this.initialize = function() {
    this.isInitialized = true;
  };
  this.initialize();
}

new ApplicationService({ url: "https://api.example.com/v1" });

This technique ensures the nested function can reliably operate on the properties (this.someprop) of the original object instance.

Conflicts and Discouragement of self

A significant point of contention arises because modern browser environments (both standard windows and WebWorkers) define a global property named self, which points to the global object itself (equivalent to window).

Overwriting this global variable with var self = this; can lead to confusion or unexpected behavior, particularly in codebases or environments where window.self is expected to maintain its global reference. Because of this potential conflict, using self for context aliasing is often discouraged now. Alternative variable names like that, _this, or oThis are frequently preferred for clarity and safety, as noted in community discussions.

Modern Alternatives: ES6 Arrow Functions

The necessity of the var self = this; idiom has substantially diminished with the adoption of ES6 Arrow Functions (=>).

Arrow functions lexically bind this. This means they do not create their own this context; instead, they inherit the this value from the immediately enclosing non-arrow function scope.

Compare the older approach with the modern ES6 implementation:

Pre-ES6 (Requiring Context Capture):

function DataProcessor(id) {
    this.dataId = id;
    var self = this; // Context capture required

    document.getElementById("logButton").addEventListener("click", function() {
        console.log(`Processor ID: ${self.dataId}`); // Use captured 'self'
    });
}

ES6+ (Using Arrow Function for Lexical this):

class DataProcessor {
    constructor(id) {
        this.dataId = id;
        
        // Arrow function inherits 'this' from the constructor scope
        document.getElementById("logButton").addEventListener("click", () => {
            console.log(`Processor ID: ${this.dataId}`); // 'this' works directly
        });
    }
}

The arrow function simplifies the code significantly by automatically handling the context inheritance, making the explicit aliasing unnecessary in many modern scenarios.

Other Context Preservation Strategies

Beyond aliasing and arrow functions, other methods exist for managing context:

  1. Function.prototype.bind(): This creates a new function whose this value is permanently set to the value provided, regardless of how it’s called later.

    class Timer {
    constructor() {
        this.count = 0;
        // Bind the handler method to the current 'this' context
        this.tick = this.tick.bind(this); 
    }

    start() {
        setInterval(this.tick, 1000);
    }

    tick() {
        this.count++;
        console.log(`Tick: ${this.count}`);
    }
}

  2. Proxy/Wrapper Functions (.apply or .call): As seen in libraries like jQuery’s $.proxy(), one can wrap the target function, explicitly executing it later using the desired context via .apply() or .call().

    A simplified concept:

    function createProxiedFunction(originalFunction, context) {
  return function(...args) {
    // Calls originalFunction, forcing 'this' to be 'context'
    return originalFunction.apply(context, args); 
  };
}

    While powerful, this pattern is often more verbose than arrow functions or .bind() for simple method binding.

FAQs on JavaScript Context Preservation This Aliases

Q: What is the primary function of using var self = this in older JavaScript

ANS: It captures the value of this from the outer function scope before an inner function (like an event handler or closure) changes the context, allowing the inner function to reference the original object instance.

Q: Should I still use var self = this in new projects

ANS: It is generally advised against due to potential conflict with the global window.self. Prefer ES6 arrow functions or using .bind(this) instead.

Q: How do arrow functions resolve the this context issue

ANS: Arrow functions feature lexical scoping for this, meaning they inherit this from their nearest enclosing non-arrow function scope, negating the need for manual context capture aliases.

Q: What variable names are often suggested as alternatives to self

ANS: Common suggested alternatives include that, _this, or oThis to avoid shadowing the global self variable.
function MyConstructor(options) {
  let that = this;

  this.someprop = options.someprop || 'defaultprop';

  document.addEventListener('click', (event) =&gt; {
    alert(that.someprop);
  });
}

new MyConstructor({
  someprop: "Hello World"
});
