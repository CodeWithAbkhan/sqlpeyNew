How can you effectively retrieve the previous URL in JavaScript?

Navigating the web efficiently requires knowing where you have come from, particularly when you want a smooth transition between pages. While there might be an intuitive expectation to easily fetch the previous URL in JavaScript, it doesn’t offer straightforward access to the URL history due to privacy and security concerns. However, there are several methods for achieving this goal, each with its own advantages.

Method 1: Use document.referrer

A straightforward solution to obtain the previous URL is to utilize the document.referrer property. This property returns the URL of the last page that linked to the current page, provided the user arrived via a hyperlink. Here’s an example:

const previousURL = document.referrer;
if (previousURL) {
    alert("The previous URL is: " + previousURL);
} else {
    alert("No referrer available.");
}

This method adheres to the DOM Level 2 specification and is well-documented by the Mozilla Developer Network (MDN) . However, note that this approach may not work if a user directly types the URL into the address bar or navigates to the page via bookmarks or another method.

Practical Considerations

The previous URL captured may not always be reliable for navigation scenarios, especially on form submission or direct link access. In such cases, leveraging session management techniques becomes vital.

Method 2: Utilizing the History API

For moments when you want to navigate backward without needing to know the specific URL, the HTML5 History API offers powerful methods to manage browser history. Here’s a succinct example:

function goBack() {
    window.history.back();
}

function goForward() {
    window.history.forward();
}

function goToSessionIndex(index) {
    window.history.go(index);
}

These methods allow for streamlined navigation between pages within the user’s browser history without explicitly needing the previous URL. More information about this API can be found in the MDN documentation on manipulating browser history .

Important Notes

While this approach provides robust navigation options, keep in mind that it doesn’t grant access for directly manipulating the URL stack across different domains, adhering to web security protocols.

Method 3: Alternative Strategies

If both document.referrer and the History API are insufficient for your specific requirements, you may consider implementing custom solutions such as:

  • Storing the URL in Cookies: Save the current URL before navigating to a new one, allowing retrieval at a later time.

    document.cookie = "lastURL=" + window.location.href;

function getLastURL() {
    const cookies = document.cookie.split('; ');
    const lastURL = cookies.find(row => row.startsWith('lastURL='));
    return lastURL ? lastURL.split('=')[1] : null;
}

alert("The last URL was: " + getLastURL());

  • Using URL Parameters: Append the previous URL as a query parameter in the URL.

Implementing a Comprehensive Solution

Combining these techniques allows you to create a more resilient system for managing page transitions. For example, you can set cookies or URL parameters as needed while relying on document.referrer for immediate transitions.

FAQs on Top 3 Methods to Retrieve the Previous URL in JavaScript

Q: What is document.referrer?

A: The document.referrer property in JavaScript provides the URL of the document that linked to the current page, allowing developers to track navigation paths within a site.

Q: Can I access the full history of URLs visited by the user?

A: No, the browser’s history stack is restricted for security reasons. You can only navigate through it or capture the last referrer URL.

Q: How do cookies help in capturing the previous URL?

A: By storing the current URL as a cookie before navigating away from the page, you can retrieve the last visited URL equipped with JavaScript when needed.
