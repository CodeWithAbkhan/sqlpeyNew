“Extending jQuery :contains Selector for Case-Insensitive Text Matching”

The native jQuery :contains(text) selector performs a case-sensitive match on the text content of elements. When developers require searching through text content without regard to casing, extending jQuery’s expression module becomes necessary. This exploration details several established approaches to implement custom, case-insensitive containment selectors, noting compatibility across various jQuery releases.

Implementing a Custom Case-Insensitive :Contains Selector

The primary mechanism involves using jQuery.extend or jQuery.expr.createPseudo to inject a new expression into jQuery.expr[':'].

Approach for Older jQuery Versions (e.g., jQuery 1.2)

For older environments, extending the property directly with a string expression was feasible:

jQuery.extend(
    jQuery.expr[':'], { 
        Contains : "jQuery(a).text().toUpperCase().indexOf(m[3].toUpperCase())>=0" 
});

This sets up a custom selector, :Contains (with a capital ‘C’), to perform a case-insensitive check. Note that the original :contains remains case-sensitive.

Function-Based Implementation (jQuery 1.3+)

As of jQuery 1.3, defining selectors using string expressions becomes deprecated. Implementing the logic as a function is the required pattern:

jQuery.expr[':'].Contains = function(a, i, m){
     return jQuery(a).text().toUpperCase().indexOf(m[3].toUpperCase())>=0;
};

Performance Note: Directly accessing DOM properties like a.textContent or a.innerText might offer a performance benefit over repeatedly calling jQuery(a).text() within the selector function, especially when processing large DOM trees:

// Potentially faster DOM text retrieval
return (a.textContent || a.innerText || "").toUpperCase().indexOf(m[3].toUpperCase())>=0;

Modern Approach for jQuery 1.8+ using createPseudo

For jQuery versions 1.8 and newer, the recommended way to create custom pseudo-selectors is via jQuery.expr.createPseudo:

jQuery.expr[":"].Contains = jQuery.expr.createPseudo(function(arg) {
    return function( elem ) {
        return jQuery(elem).text().toUpperCase().indexOf(arg.toUpperCase()) >= 0;
    };
});

Creating an Optional Case-Insensitive Selector (:containsi)

If the goal is to introduce a new selector name (like :containsi) that is explicitly case-insensitive, rather than overriding the native one, you can define it alongside the original:

$.extend($.expr[':'], {
  'containsi': function(elem, i, match, array)
  {
    // Use textContent/innerText fallback and convert both search term and element text to lower case
    return (elem.textContent || elem.innerText || '').toLowerCase()
    .indexOf((match[3] || "").toLowerCase()) >= 0;
  }
});
// Usage: $("p:containsi('search term')")

This method avoids interfering with the native :contains behavior, which is generally safer.

Utilizing Regular Expressions for Enhanced Searching

A more powerful alternative involves using regular expressions within the custom selector, allowing for complex matching patterns while maintaining case-insensitivity ('i' flag). This can significantly improve search capability beyond simple substring matching.

We can define a selector, for instance, :containsCI:

jQuery.extend (
    jQuery.expr[':'].containsCI = function (a, i, m) {
        // Faster text acquisition
        var sText   = (a.textContent || a.innerText || "");     
        // Create a case-insensitive RegExp object from the argument (m[3])
        var zRegExp = new RegExp (m[3], 'i');
        return zRegExp.test (sText);
    }
);

This enables usage like searching for whole words or patterns:

// Matches "Up" or "up", but excludes "upper" or "wakeup"
$("p:containsCI('\\bup\\b')").css("font-weight", "bold"); 

// Matches "red state" or "Blue state"
$("div:containsCI('(?:Red|Blue) state')").addClass("highlight");

Deconstructing Selector Parameters (a and m[3])

When defining custom selectors, jQuery provides specific contextual variables:

  • r: The array of elements currently being checked.
  • i: The index of the current element being evaluated within array r.
  • a: The DOM element currently under scrutiny. The function must return true to select it.
  • m[2]: The node name or * appearing to the left of the colon (e.g., in :mySelector(param)).
  • m[3]: The parameter passed inside the parentheses of the selector, such as an index or a string argument.

Alternative: Filtering Without Extending Selectors

If modifying the jQuery expression engine is undesirable, a functional approach using .filter() provides equivalent, explicit control:

var searchString = "String you want to match".toLowerCase();

// Select initial elements, then filter them based on the function logic
var matchedElements = $("elementsYouNeed").filter(function () {
    // Compare lowercased text content against the lowercased search string
    return $(this).text().toLowerCase().indexOf(searchString) > -1;
});

This approach isolates the case-insensitive logic within the application code, leaving the core jQuery selectors untouched.

Avoiding Native Selector Override

To ensure the default, case-sensitive :contains remains operational, it is prudent to assign the case-insensitive function to a distinct name, such as :MyCaseInsensitiveContains:

$.extend($.expr[":"], {
    "MyCaseInsensitiveContains": function(elem, i, match, array) {
        return (elem.textContent || elem.innerText || "").toLowerCase().indexOf((match[3] || "").toLowerCase()) >= 0;
    }
});
// Usage: $("div:MyCaseInsensitiveContains('test')")

Attribute Selector Workaround

In some scenarios, especially when dealing with specific attributes rather than pure text nodes, utilizing attribute selectors like *= (contains) can be useful, although they are usually case-sensitive by default in HTML attributes unless specified otherwise by the browser implementation:

// Check if the 'data' attribute contains "flac" (case-dependent based on browser/HTML standard interpretation)
$('div.story span.Quality:not([data*="flac"])').css("background-color", 'yellow');

For fine-grained text node traversal, filtering contents directly with a RegExp test is highly effective:

$('div.story span.Quality').contents().filter(function()
{
  // Test nodeValue against a case-insensitive regex for "flac"
  return !/flac/i.test(this.nodeValue);
}).parent().css("background-color", 'yellow');

FAQs on Extending jQuery Contains Selector Case Insensitive

Q: How do I use a custom case insensitive selector in jQuery 1 8

ANS: Use jQuery.expr.createPseudo to define your custom selector function, ensuring you return a function that performs the case-insensitive string comparison against the element’s text content.

Q: Should I override the native jQuery contains selector

ANS: It is generally advised to define a new selector name (e.g., :icontains or :containsCI) rather than overriding the native :contains to prevent unexpected side effects with existing code expecting case-sensitive behavior.

Q: Why use RegExp in the custom contains selector

ANS: Using a Regular Expression with the case-insensitive flag (i) allows for more complex pattern matching than simple substring checks, such as enforcing word boundaries or matching multiple options.
