“JavaScript Object Property Picking Techniques Explained”

When working with JavaScript objects, you often need to extract a subset of properties to create a new object. This task, commonly referred to as “picking” properties, can be achieved through several methods, each with its own advantages in terms of conciseness, readability, and compatibility. Let’s delve into various approaches that developers have employed to accomplish this.

The Challenge of Picking Object Properties

The core problem is to take an existing object and construct a new object containing only a specified set of its properties. For instance, if you have an object representing a user with many attributes, you might only want to select their id and username for a particular display.

Solution 1: Parameter Destructuring (Concise ES6)

A streamlined approach utilizes parameter destructuring directly within an arrow function. This method is particularly elegant for simple cases where the property names are known and don’t need renaming.

const pickIdAndTitle = ({ id, title }) => ({ id, title });

const originalObject = { id: 1, title: "Example", description: "A detailed description" };
const pickedObject = pickIdAndTitle(originalObject);

console.log(pickedObject); // Output: { id: 1, title: "Example" }

Solution 2: Object.assign with map and Computed Property Names

This method offers a more general solution, allowing you to pick an arbitrary number of properties. It uses Object.assign to merge properties into a new object, and computed property names ([prop]) to dynamically set the property keys.

function pick(sourceObject, ...propertiesToPick) {
  return Object.assign({}, ...propertiesToPick.map(prop => ({ [prop]: sourceObject[prop] })));
}

const data = { name: 'Gadget', color: 'silver', size: 'medium', weight: 250 };
const selectedData = pick(data, 'name', 'weight');

console.log(selectedData); // Output: { name: 'Gadget', weight: 250 }

To preserve property attributes like configurability and getters/setters, and to handle non-enumerable properties, a more robust implementation is required:

function pickWithAttributes(sourceObject, ...propertiesToPick) {
  const hasEnumerableProperty = prop => sourceObject.propertyIsEnumerable(prop);
  const getPropertyDescriptor = prop => Object.getOwnPropertyDescriptor(sourceObject, prop);

  return Object.defineProperties({},
    Object.assign({}, ...propertiesToPick
      .filter(prop => hasEnumerableProperty(prop))
      .map(prop => ({ [prop]: getPropertyDescriptor(prop) }))
    )
  );
}

Solution 3: Array.prototype.reduce for Selective Property Extraction

The reduce method provides a functional way to build the new object iteratively. You can start with an empty object and add properties one by one based on a provided array of keys.

Method 3a: Standard reduce

function pickWithReduce(sourceObject, ...keysToPick) {
  return keysToPick.reduce((accumulator, currentKey) => {
    if (sourceObject.hasOwnProperty(currentKey)) {
      accumulator[currentKey] = sourceObject[currentKey];
    }
    return accumulator;
  }, {});
}

const item = { model: 'Sedan', brand: 'AutoCorp', year: 2022, mileage: 15000 };
const basicInfo = pickWithReduce(item, 'model', 'brand');

console.log(basicInfo); // Output: { model: 'Sedan', brand: 'AutoCorp' }

Method 3b: reduce with Spread Syntax (ES6+)

A more modern variation uses the spread syntax within reduce for immutability and a concise syntax.

const selectProperties = (sourceObject, ...keysToSelect) =>
  keysToSelect.reduce((result, key) => ({
    ...result,
    [key]: sourceObject[key]
  }), {});

const car = { make: 'Velocity', model: 'X1', year: 2023, color: 'red' };
const modelAndYear = selectProperties(car, 'model', 'year');

console.log(modelAndYear); // Output: { model: 'X1', year: 2023 }

Solution 4: Array.prototype.reduce with Comma Operator

This is a highly compact variation of the reduce method, leveraging the comma operator to chain operations within the reducer function.

const pickCompact = (sourceObject, ...keysToPick) =>
  keysToPick.reduce((accumulator, currentKey) => (accumulator[currentKey] = sourceObject[currentKey], accumulator), {});

const product = { id: 'PROD-007', name: 'Widget', price: 19.99, inStock: true };
const idAndPrice = pickCompact(product, 'id', 'price');

console.log(idAndPrice); // Output: { id: 'PROD-007', price: 19.99 }

Solution 5: Object.fromEntries with Object.entries and filter (ES2019+)

This approach converts the object into an array of key-value pairs, filters that array, and then converts it back into an object. It’s very readable and efficient for modern JavaScript environments.

const pickModern = (sourceObject, keysToInclude) =>
  Object.fromEntries(
    Object.entries(sourceObject)
    .filter(([key]) => keysToInclude.includes(key))
  );

const configuration = { setting1: 'value1', setting2: 'value2', enabled: true, disabled: false };
const relevantSettings = pickModern(configuration, ['setting1', 'enabled']);

console.log(relevantSettings); // Output: { setting1: 'value1', enabled: true }

Solution 6: Object Rest/Spread Properties (Proposed Feature)

While not fully standardized for picking in all cases, the object rest/spread properties proposal offers a glimpse into future, more concise syntax for object manipulation. The rest syntax (...z) collects remaining properties.

// Example demonstrating rest syntax (not directly for picking specific properties)
let { x, y, ...remainingProps } = { x: 1, y: 2, a: 3, b: 4 };
// remainingProps will be { a: 3, b: 4 }

This syntax is primarily for destructuring and collecting unpicked properties, rather than explicitly picking a subset.

Solution 7: Destructuring for Renaming and Assignment

You can use object destructuring to extract properties and assign them to variables, which can then be used to construct a new object. This is useful when you also need to rename properties.

const personData = {
  firstName: 'Alice',
  lastName: 'Smith',
  age: 30,
  occupation: 'Engineer'
};

let newPersonDetails = {};
({ firstName: newPersonDetails.name, age: newPersonDetails.years } = personData);

console.log(newPersonDetails); // Output: { name: 'Alice', years: 30 }

An older, generally discouraged method involves the with statement. This is extremely limited as it’s forbidden in strict mode JavaScript, making it impractical for most modern development.

Solution 9: Re-usable pick and pick2 Functions

Creating reusable functions enhances code maintainability. These examples provide flexible ways to pick properties, with pick2 even allowing for renaming.

const pick = (sourceObject, ...props) =>
  props.reduce((result, prop) =>
    prop in sourceObject ? { ...result, [prop]: sourceObject[prop] } : result, {});

const pickWithRename = (sourceObject, ...expressions) =>
  expressions.reduce((result, expression) => {
    const [originalKey, newKey] = expression.split(":").map(part => part.trim());
    return originalKey in sourceObject ? { ...result, [newKey || originalKey]: sourceObject[originalKey] } : result;
  }, {});

const sampleData = { a: "val_a", b: "val_b", c: "val_c", d: "val_d" };
console.log(pick(sampleData, "a", "c", "e"));      // Output: { a: "val_a", c: "val_c" }
console.log(pickWithRename(sampleData, "a: alpha", "b: beta", "c")); // Output: { alpha: "val_a", beta: "val_b", c: "val_c" }

Solution 10: Conditional Picking with Object.assign

This variation of Object.assign includes a check to ensure the property exists in the source object before attempting to pick it.

function pickIfAvailable(sourceObject, ...propsToPick) {
  return Object.assign({}, ...propsToPick.map(prop => {
    if (sourceObject[prop] !== undefined) { // Checks for existence, handles falsy values correctly
      return { [prop]: sourceObject[prop] };
    }
    return {}; // Return an empty object if the prop is not found
  }));
}

const userProfile = { username: 'coder', level: 5, avatar: null };
const displayInfo = pickIfAvailable(userProfile, 'username', 'level', 'email');

console.log(displayInfo); // Output: { username: 'coder', level: 5 }

Solution 11: Object.entries, filter, Object.fromEntries Example

This demonstrates the ES2019 approach again, this time with a clear example of filtering based on an array of desired keys.

const originalObject = { itemCode: 'XYZ789', itemName: 'Tool', quantity: 50, price: 12.50 };
const keysToKeep = ["itemName", "quantity"];

const filteredObject = Object.fromEntries(
  Object.entries(originalObject).filter(([key]) => keysToKeep.includes(key))
);

console.log(filteredObject); // Output: { itemName: 'Tool', quantity: 50 }

Solution 12 & 13: TypeScript Generics for Type Safety

For TypeScript projects, creating generic functions ensures type safety. These solutions define pick functions that infer types and prevent picking non-existent properties at compile time.

Solution 12: Generic pick Function

function pick<T extends object, K extends keyof T>(source: T, ...props: K[]): Pick<T, K> {
    const obj: any = {};
    for (const prop of props) {
        obj[prop] = source[prop];
    }
    return obj as Pick<T, K>;
}

const typeSafeObj = { a: 1, b: 2, c: true };
// const compileError = pick(typeSafeObj, "a", "d"); // TypeScript error: Argument of type '"d"' is not assignable to parameter of type '"a" | "b" | "c"'.
const newObj = pick(typeSafeObj, "a", "c");
// newObj is typed as { a: number; c: boolean; }
console.log(newObj); // Output: { a: 1, c: true }

Solution 13: Generic pick and omit (TypeScript)

This provides both a pick function and an omit function using TypeScript generics. The omit function also includes a more performant implementation.

const pickTyped = <T extends object, K extends keyof T>(
    obj: T,
    ...keys: K[]
): Pick<T, K> =>
    keys.reduce<any>((result, key) => {
        result[key] = obj[key];
        return result;
    }, {});

// A performant omit function
const omitPerformant = <T extends object, K extends keyof T>(
    obj: T,
    ...keys: K[]
): Omit<T, K> => {
    let result: any = {};
    let keyCount = keys.length;
    while (keyCount--) {
        const key = keys[keyCount];
        result[key] = obj[key];
    }
    return result;
};

const dataSet = { id: 101, name: "Alpha", value: 500, status: "Active" };
const pickedSubset = pickTyped(dataSet, "name", "status");
console.log(pickedSubset); // Output: { name: "Alpha", status: "Active" }

const omittedSubset = omitPerformant(dataSet, "id", "value");
console.log(omittedSubset); // Output: { name: "Alpha", status: "Active" }

Solution 14: reduce with Spread and Comma Operator Variations

These are concise, functional approaches leveraging reduce for building the new object, offering slight variations in syntax.

const pickReduceSpread = (source, keys) => keys.reduce((acc, key) => ({ ...acc, [key]: source[key] }), {});

const pickReduceComma = (obj, keys) => keys.reduce((acc, key) => ((acc[key] = obj[key]), acc), {});

const vehicle = { model: 'F40', manufacturer: 'Ferrari', productionYear: 1987 };
console.log(pickReduceSpread(vehicle, ['model', 'productionYear']));      // Output: { model: 'F40', productionYear: 1987 }
console.log(pickReduceComma(vehicle, ['manufacturer', 'productionYear'])); // Output: { manufacturer: 'Ferrari', productionYear: 1987 }

Frequently Asked Questions

FAQs on JavaScript Object Property Picking

Q: What is the most concise way to pick properties in modern JavaScript

ANS: For modern JavaScript environments (ES2019+), using Object.fromEntries combined with Object.entries and filter offers a clean and readable solution. For example:

const pickModern = (sourceObject, keysToInclude) =>
  Object.fromEntries(
    Object.entries(sourceObject)
    .filter(([key]) => keysToInclude.includes(key))
  );

Q: How can I pick properties and rename them simultaneously

ANS: You can achieve this by creating a custom function that splits the desired property expression (e.g., “originalKey: newKey”) and then uses reduce or Object.assign with computed property names. The pickWithRename function in Solution 9 demonstrates this:

const pickWithRename = (sourceObject, ...expressions) =>
  expressions.reduce((result, expression) => {
    const [originalKey, newKey] = expression.split(":").map(part => part.trim());
    return originalKey in sourceObject ? { ...result, [newKey || originalKey]: sourceObject[originalKey] } : result;
  }, {});

Q: Are there performance differences between these methods

ANS: Yes, performance can vary. Methods involving multiple iterations or creating intermediate arrays (like Object.entries or complex reduce operations) might be slightly less performant than direct property access or Object.assign in certain scenarios. However, for most common use cases, the differences are negligible, and readability often takes precedence. TypeScript generics (Solutions 12 & 13) offer compile-time safety which is highly beneficial. For highly optimized scenarios, direct property assignment within a loop or carefully crafted reduce functions might be preferred.

Q: What are the alternatives to picking specific properties

ANS: If you need to extract all properties except a few, you would look into “omitting” properties. Techniques for omitting include using object destructuring with the rest syntax (...rest) to gather unneeded properties, or custom functions that filter out specific keys. For instance, in TypeScript, Omit<T, K> utility type or a custom omit function can be used.

Q: Why is the 'with' statement discouraged in JavaScript

ANS: The with statement can lead to ambiguous variable lookups and hinders static analysis, making code harder to read, debug, and optimize. It’s also disallowed in strict mode, which is the standard for modern JavaScript development. Therefore, its use is highly discouraged.
