How to Safely Execute Multiple Promises and Capture All Outcomes?

When working with asynchronous operations in JavaScript, particularly with Promise.all, a single rejected promise causes the entire Promise.all to fail immediately, often without providing details about other promises that might have also failed or succeeded. This can lead to silent failures or the inability to process partial results. How can we execute multiple promises concurrently and ensure that we capture the outcome of every promise, whether it resolves successfully or rejects?

Solution 1: Leveraging Native Promise.allSettled

The most direct and modern approach is to use the built-in Promise.allSettled method, introduced in ECMAScript 2020. This method waits for all provided promises to either fulfill or reject and then returns an array of objects, each describing the outcome of a corresponding promise.

// Example using native Promise.allSettled
const promise1 = Promise.resolve('First promise resolved');
const promise2 = Promise.reject(new Error('Second promise rejected'));
const promise3 = Promise.resolve('Third promise resolved');

Promise.allSettled([promise1, promise2, promise3])
  .then(results => {
    results.forEach(result => {
      if (result.status === 'fulfilled') {
        console.log(`Fulfilled: ${result.value}`);
      } else {
        console.error(`Rejected: ${result.reason}`);
      }
    });
  });

Output:

Fulfilled: First promise resolved
Rejected: Error: Second promise rejected
Fulfilled: Third promise resolved

For older environments that don’t support Promise.allSettled, a polyfill can be used.

Solution 2: Custom reflect Function with Promise.all

Before Promise.allSettled was standardized, a common pattern was to create a reflect function that wraps each promise. This function ensures that the promise itself never rejects; instead, it resolves with an object indicating its status (fulfilled or rejected) and the corresponding value or reason.

// Custom reflect function
const reflect = p => p.then(
  v => ({ status: 'fulfilled', value: v }),
  e => ({ status: 'rejected', reason: e })
);

const promisesToSettle = [
  Promise.resolve('Success 1'),
  Promise.reject(new Error('Failure 1')),
  Promise.resolve('Success 2')
];

Promise.all(promisesToSettle.map(reflect))
  .then(results => {
    results.forEach(result => {
      if (result.status === 'fulfilled') {
        console.log(`Result: ${result.value}`);
      } else {
        console.error(`Error: ${result.reason}`);
      }
    });
  });

Output:

Result: Success 1
Error: Error: Failure 1
Result: Success 2

Solution 3: Catching Errors Individually within Promise.all

Another approach is to attach a .catch() handler to each promise within the Promise.all mapping. This handler can return the error itself or a specific error object, allowing Promise.all to complete.

const promiseA = Promise.resolve(1);
const promiseB = Promise.reject(new Error('Error B'));
const promiseC = Promise.resolve(3);

Promise.all([promiseA, promiseB.catch(e => e), promiseC])
  .then(results => {
    console.log(results); // [1, Error: Error B, 3]
    results.forEach(result => {
      if (result instanceof Error) {
        console.error(`Caught Error: ${result.message}`);
      } else {
        console.log(`Resolved Value: ${result}`);
      }
    });
  });

Output:

1
Caught Error: Error B
3

Solution 4: Using an Intermediate catchHandler

This method involves creating a handler that transforms rejected promises into objects with a specific structure, such as { payload: error, resolved: false }. This makes it easier to distinguish between successful results and errors.

const processPromise = p =>
  p.then(
    result => ({ payload: result, resolved: true }),
    error => ({ payload: error, resolved: false })
  );

const promises = [Promise.resolve('Data 1'), Promise.reject('Error 2')];

Promise.all(promises.map(processPromise))
  .then(results => {
    console.log(results);
    results.forEach(res => {
      if (res.resolved) {
        console.log(`Success: ${res.payload}`);
      } else {
        console.error(`Failure: ${res.payload}`);
      }
    });
  });

Output:

[ { payload: 'Data 1', resolved: true },
  { payload: 'Error 2', resolved: false } ]

Solution 5: Custom Promise.settle Implementation

A custom function can be built to mimic Promise.allSettled’s behavior. This involves iterating through the promises and resolving a new promise only after all input promises have completed, regardless of their success or failure.

Promise.settle = function(promises) {
  let results = [];
  let doneCount = promises.length;

  if (doneCount === 0) {
    return Promise.resolve([]);
  }

  return new Promise(resolve => {
    promises.forEach((promise, index) => {
      Promise.resolve(promise) // Ensure we're dealing with a promise
        .then(value => {
          results[index] = { status: 'fulfilled', value: value };
        })
        .catch(reason => {
          results[index] = { status: 'rejected', reason: reason };
        })
        .finally(() => {
          doneCount--;
          if (doneCount === 0) {
            resolve(results);
          }
        });
    });
  });
};

// Example usage:
Promise.settle([Promise.resolve('Val 1'), Promise.reject('Err 2')])
  .then(console.log);

Output:

[ { status: 'fulfilled', value: 'Val 1' },
  { status: 'rejected', reason: 'Err 2' } ]

Solution 6: Capturing the Last Rejection

This approach uses a shared variable to store any encountered error. Promise.all waits for all promises to settle, and then the stored error (if any) is re-thrown. This effectively returns the last encountered rejection.

let sharedError;
Promise.all([
  Promise.resolve('Ok 1').catch(err => { sharedError = err; }),
  Promise.reject('Bad 2').catch(err => { sharedError = err; }),
  Promise.resolve('Ok 3').catch(err => { sharedError = err; })
]).then(() => {
  if (sharedError) {
    throw sharedError; // Re-throw the captured error
  }
  console.log('All operations completed without a critical failure.');
}).catch(err => console.error(`Final error: ${err}`));

Output:

Final error: Bad 2

Solution 7: Sequential Execution with Retries (Conceptual)

While not strictly Promise.allSettled, this pattern demonstrates how to handle failures by retrying specific operations. The core idea is to wrap each promise with a handler that, on rejection, returns a new promise that retries the operation after a delay.

// Conceptual example - requires a Promise implementation with retry logic
const retryFetch = (url, timeout = 1000) => {
  return fetch(url) // Assuming fetch returns a Promise
    .then(response => response.json())
    .catch(error => {
      console.warn(`Fetch failed for ${url}. Retrying...`);
      return new Promise(resolve => setTimeout(() => resolve(retryFetch(url, timeout)), timeout));
    });
};

const tasks = [retryFetch('/api/data1'), retryFetch('/api/data2')];

Promise.all(tasks).then(results => {
  console.log('All tasks completed:', results);
});

Solution 8: ES2020 Polyfill for Promise.allSettled

For environments needing compatibility with the ES2020 Promise.allSettled standard, a polyfill can be implemented. This version ensures that promises resolve with an object indicating their status (fulfilled or rejected) and either value or reason.

if (!Promise.allSettled) {
  Promise.allSettled = promises =>
    Promise.all(
      promises.map(p =>
        Promise.resolve(p).then(
          v => ({ state: 'fulfilled', value: v }),
          r => ({ state: 'rejected', reason: r })
        )
      )
    );
}

// Usage remains the same as native Promise.allSettled

Solution 9: Resolving with Success/Error Objects

This strategy involves modifying the promise’s behavior so that it always resolves, but the resolved value indicates whether the original operation was successful. Rejected promises are caught and resolved with an object detailing the error.

const createSettledPromise = arg =>
  new Promise((resolve) => {
    setTimeout(() => {
      try {
        if (arg !== 2) {
          resolve({ success: true, data: arg });
        } else {
          throw new Error(`Error for ${arg}`);
        }
      } catch (e) {
        resolve({ success: false, error: e, data: arg });
      }
    }, 500);
  });

Promise.all([1, 2, 3].map(createSettledPromise))
  .then(results => console.log(results));

Solution 10: Standardized Error Handling with instanceof Error

This approach ensures that all errors, even those rejected as plain strings, are standardized as Error objects. This allows for consistent checking using instanceof Error to differentiate between successful results and errors.

const handlePromiseOutcome = async (promise) => {
  try {
    const result = await promise;
    return result;
  } catch (error) {
    if (error instanceof Error) {
      return error; // Return the actual Error object
    }
    return new Error(String(error)); // Wrap non-Error rejections
  }
};

async function testOutcomes() {
  const promises = [
    Promise.resolve("Good"),
    Promise.reject("Bad string error"),
    Promise.resolve("Also good"),
    Promise.reject(new Error("Specific error")),
  ];
  const results = await Promise.all(promises.map(handlePromiseOutcome));
  console.log(results);
  results.forEach(r => console.log(r instanceof Error ? "Error occurred" : "Success"));
}

testOutcomes();

Success
Error occurred
Success
Error occurred

Solution 11: Differentiating Fast vs. Slow Failures

This method highlights the difference between Promise.all’s default behavior (fast fail on first rejection) and a modified approach that allows all promises to settle. The latter requires explicitly catching errors within each promise to prevent Promise.all from short-circuiting.

const p1 = new Promise(resolve => setTimeout(() => resolve('p1 resolved'), 2000));
const p2 = Promise.reject(new Error('p2 immediate rejection'));

// Default Promise.all behavior (fast fail)
async function fastFail() {
  try {
    await Promise.all([p1, p2]);
  } catch (err) {
    console.error('Fast fail:', err); // Logs 'p2 immediate rejection'
  }
}

// Modified to allow settling (slow fail)
async function slowFail() {
  try {
    const results = await Promise.all([
      p1.catch(error => error), // Catch and return error
      p2.catch(error => error)  // Catch and return error
    ]);
    console.log('Slow fail results:', results); // Logs both outcomes
  } catch (err) {
    console.error('This catch is unlikely to be hit here.');
  }
}

fastFail();
slowFail();

Output:

Fast fail: Error: p2 immediate rejection
Slow fail results: [ 'p1 resolved', Error: 'p2 immediate rejection' ]

Solution 13: Custom settledPromiseAll Logic

This custom function mimics Promise.all but ensures all promises complete. It captures the first error encountered and throws it only after all promises have settled, otherwise returning all results.

const settledPromiseAll = (promisesArray) => {
  let firstError;
  const handleError = error => {
    if (!firstError) firstError = error;
  };
  const wrappedPromises = promisesArray.map(p => Promise.resolve(p).catch(handleError));

  return Promise.all(wrappedPromises).then(() => {
    if (firstError) throw firstError;
    return Promise.all(promisesArray); // Re-run if no error, or adjust to return cached results
  });
};

// Example usage
settledPromiseAll([Promise.resolve('data'), Promise.reject('issue')])
  .then(results => console.log('All settled results:', results))
  .catch(err => console.error('Final error:', err));

Output:

Final error: issue

Solution 17: TypeScript promiseExecuteAll Logic

This approach, demonstrated in TypeScript, iterates through promises and captures their results along with a success status (isSuccess). It returns a single promise that resolves with an array of these status objects once all input promises have completed.

// Conceptual TypeScript implementation
interface PromiseResult {
  data: any;
  isSuccess: boolean;
}

function promiseExecuteAll(promisesList: Promise<any>[]): Promise<PromiseResult[]> {
  if (promisesList.length === 0) {
    return Promise.resolve([]);
  }

  return new Promise<PromiseResult[]>(resolve => {
    const results: PromiseResult[] = [];
    let count = 0;

    promisesList.forEach((promise, index) => {
      promise.then(
        data => {
          results[index] = { data, isSuccess: true };
        },
        data => { // Catches rejection
          results[index] = { data, isSuccess: false };
        }
      ).finally(() => {
        count++;
        if (count === promisesList.length) {
          resolve(results);
        }
      });
    });
  });
}

// Example usage
const p1 = Promise.resolve("OK");
const p2 = Promise.reject(new Error(":-("));
const p3 = Promise.resolve(1000);

promiseExecuteAll([p1, p2, p3]).then((data: PromiseResult[]) => {
  data.forEach(value => console.log(`${value.isSuccess ? 'Resolved' : 'Rejected'} >> ${value.data}`));
});

Output:

Resolved >> OK
Rejected >> Error: :-(
Resolved >> 1000

Solution 20: Using allSettled from Promise Libraries

Many promise libraries predate the native Promise.allSettled and offer similar functionality. If you’re using a library like Bluebird or Q, you can leverage their specific methods for handling unsettled promises.

“Handle Promise Rejection Gracefully with Promise.allSettled Alternatives”

Q: What is the main problem with Promise all

ANS: The primary issue with Promise.all is that it rejects immediately as soon as any of the input promises reject. This means you don’t get results from other promises that might have already resolved or are still pending. It fails fast.

Q: How does Promise allSettled differ from Promise all

ANS: Promise.allSettled waits for all promises in the iterable to settle (either fulfill or reject) and returns a promise that resolves with an array of objects. Each object describes the outcome of the corresponding promise, indicating its status (‘fulfilled’ or ‘rejected’), and either its value or reason. Promise.all rejects as soon as one promise rejects.

Q: Can I use Promise allSettled in older JavaScript environments

ANS: For environments that do not natively support Promise.allSettled (introduced in ECMAScript 2020), you can use a polyfill. Several polyfill implementations are available, or you can write your own, often by mapping promises with a reflect function.

Q: What is a 'reflect' function in Promise contexts

ANS: A reflect function, in the context of JavaScript promises, is a utility that wraps a promise. It ensures that the wrapped promise always resolves, returning an object that describes the original promise’s outcome (fulfilled with a value or rejected with a reason) rather than letting the rejection propagate.

Q: How can I capture all results, including errors, without a polyfill

ANS: You can achieve this by mapping each promise in your array to a new promise that includes a .catch() handler. This handler should return the error value (or an object representing the error) instead of re-throwing it. This way, Promise.all will receive consistently resolving promises.

Q: What are the benefits of using Promise allSettled

ANS: The main benefit is robustness. It allows you to process the results of all asynchronous operations, even if some fail. This is crucial for scenarios where you need to gather as much data as possible or perform cleanup actions regardless of individual operation success.
