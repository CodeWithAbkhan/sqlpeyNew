“jQuery Mobile Page Events: $(document).ready vs. pageinit Explained”

When developing with jQuery Mobile, especially versions prior to 1.4, understanding how and when your JavaScript executes is crucial. The transition from traditional DOM manipulation with $(document).ready() to jQuery Mobile’s specific page events like pageinit is a common point of consideration. This exploration delves into these nuances, providing clarity on their differences and optimal usage.

The Challenge with $(document).ready() in jQuery Mobile

In standard web development, $(document).ready() ensures your code runs only after the entire Document Object Model (DOM) has been fully loaded and parsed. This is generally a safe approach. However, jQuery Mobile employs AJAX to load page content as users navigate through your application. This means $(document).ready() might execute before a specific page’s content is available in the DOM. Consequently, any JavaScript intended for that page will run prematurely, leading to potential bugs that can be elusive and difficult to reproduce, often manifesting as erratic behavior.

Consider this classic jQuery syntax:

$(document).ready(function() {
    // Code intended for DOM manipulation
});

This works perfectly when the entire page is loaded at once. But in a dynamic, multi-page environment like jQuery Mobile, it falls short.

Introducing jQuery Mobile’s Page Events: pageinit and Beyond

To address the limitations of $(document).ready(), jQuery Mobile introduced page events. These are special events triggered at specific points during a page’s lifecycle. The pageinit event is particularly important; it fires when a page is initialized and ready for interaction, but before it’s necessarily shown for the first time.

A more robust way to handle DOM manipulation within jQuery Mobile is to use pageinit:

$(document).on('pageinit', function() {
    // Code to execute when any page is initialized
});

Targeting Specific Pages with pageinit

You can further refine your code execution by targeting specific pages using their IDs. If you have a page with data-role="page" and an id="index":

<div data-role="page" id="index">
    <div data-theme="a" data-role="header">
        <h3>First Page</h3>
        <a href="#second" class="ui-btn-right">Next</a>
    </div>
    <div data-role="content">
        <a href="#" data-role="button" id="test-button">Test button</a>
    </div>
    <div data-theme="a" data-role="footer" data-position="fixed">
    </div>
</div>

You can bind pageinit specifically to this page:

$('#index').on('pageinit', function() {
    // Code that should only run when the 'index' page is initialized
});

Important Note: pageinit is designed to trigger only once per page. This is analogous to $(document).ready() for the entire document, but scoped to individual jQuery Mobile pages. If you need code to execute every time a page is visited, consider using the pagebeforeshow event instead.

For a practical demonstration of the $(document).ready() versus pageinit issue, this jsFiddle example illustrates the problem.

Organizing Your JavaScript

For better code organization and maintainability, especially in larger jQuery Mobile applications, it’s recommended to separate your custom JavaScript logic into distinct files.

The mobileinit Event

Before jQuery Mobile even starts its initialization process, it triggers a mobileinit event on the document object. This is the ideal place to override default settings, such as disabling AJAX page transitions or modifying the default loading indicator.

$(document).on("mobileinit", function() {
  // Apply your custom configuration overrides here
});

Understanding the Page Event Transition Order

When navigating between pages in jQuery Mobile, a specific sequence of events fires. Understanding this order is key to correctly placing your event handlers:

  • Page Load & Initialization:
    • pagebeforeload: Fired before an external page is loaded.
    • pageload: Fired when an external page successfully loads.
    • pageloadfailed: Fired if an external page fails to load.
  • Page Creation & Initialization:
    • pagebeforecreate: Fired just before a page’s content is processed.
    • pagecreate: Fired after a page’s content is created.
    • pageinit: Fired when a page is ready for initialization.
  • Page Transition:
    • pagebeforehide: Fired before the current page starts to hide.
    • pagebeforechange: Fired before a page transition begins.
    • pagehide: Fired after the current page has finished hiding.
    • pagebeforeshow: Fired before the new page starts to show.
    • pageshow: Fired after the new page has finished showing.
  • Page Removal:
    • pageremove: Fired when a page is removed from the DOM.

You can find a complete list of jQuery Mobile events in the official API documentation .

A useful tool for observing this sequence is by logging these events to the console. You can use the following JavaScript snippet:

$(document).on('pagebeforecreate', function() { console.log('pagebeforecreate'); });
$(document).on('pagecreate', function() { console.log('pagecreate'); });
$(document).on('pageinit', function() { console.log('pageinit'); });
$(document).on('pagebeforehide', function() { console.log('pagebeforehide'); });
$(document).on('pagebeforeshow', function() { console.log('pagebeforeshow'); });
$(document).on('pageremove', function() { console.log('pageremove'); });
$(document).on('pageshow', function() { console.log('pageshow'); });
$(document).on('pagehide', function() { console.log('pagehide'); });
$(window).load(function () { console.log("window loaded"); });
$(function () { console.log('document ready'); });

// For debugging 'unload':
// $(window).unload(function () { debugger; console.log("window unloaded"); });

This can help you visualize the flow and debug timing-related issues.

Preventing Page Transitions

Under certain conditions, you might need to prevent a page transition. This can be achieved by intercepting the pagebeforechange event:

$(document).on('pagebeforechange', function(e, data) {
    var toPage = data.toPage;
    var fromPage = data.options.fromPage;

    if (typeof toPage === 'string') {
        var url = $.mobile.path.parseUrl(toPage);
        toPage = url.hash || '#' + url.pathname.substring(1);
        if (fromPage) fromPage = '#' + fromPage.attr('id');

        if (fromPage === '#index' && toPage === '#second') {
            alert('Transition from #index to #second is blocked!');
            e.preventDefault();
            e.stopPropagation();

            // Optional: Remove active state from buttons if transition was button-initiated
            $.mobile.activePage.find('.ui-btn-active').removeClass('ui-btn-active ui-focus ui-btn');
        }
    }
});

This code prevents navigation from #index to #second.

Avoiding Multiple Event Bindings

A common pitfall in jQuery Mobile is inadvertently binding event handlers multiple times, especially when using pagebeforeshow. Each time a page is shown, the event handler might re-bind itself.

Consider this problematic example:

$(document).on('pagebeforeshow', '#index', function(e, data) {
    $(document).on('click', '#test-button', function(e) {
        alert('Button clicked!');
    });
});

Navigating to and from #index multiple times will result in the click event being attached repeatedly to #test-button.

Here are several strategies to prevent this:

Solution 1: Use pageinit

As mentioned, pageinit fires only once per page, making it the preferred method for initial event binding:

$(document).on('pageinit', '#index', function() {
    $(document).on('click', '#test-button', function(e) {
        alert('Button clicked!');
    });
});

A working example demonstrating this best practice can be found here .

Solution 2: Unbind Before Binding

You can use .off() to remove existing event handlers before re-binding them:

$(document).on('pagebeforeshow', '#index', function() {
    $(document).off('click', '#test-button').on('click', '#test-button', function(e) {
        alert('Button clicked!');
    });
});

See this jsFiddle for a demonstration. While effective, this might have slight performance overhead compared to pageinit.

Solution 3: Event Filter (External)

While not part of the core jQuery library, event filter plugins can help manage event bindings. Information can be found here .

Solution 4: Flagging Handled Events

A clever approach is to use a flag to ensure an event handler executes only once:

$(document).on('pagebeforeshow', '#index', function() {
    $(document).on('click', '#test-button', function(e) {
        if (e.handled !== true) {
            alert('Clicked');
            e.handled = true;
        }
    });
});

This technique, credited to sholsinger, is demonstrated in this jsFiddle .

pagechange Event Quirks

Occasionally, the pagechange event might trigger twice. This can occur when passing additional parameters to $.mobile.changePage. For instance, a link like this:

<a data-role="button" data-icon="arrow-r" data-iconpos="right" href="#care-plan-view?id=9e273f31-2672-47fd-9baa-6c35f093a800&amp;name=Sat">
    <h3>Sat</h3>
</a>

can sometimes lead to the event firing more than once. Using the appropriate page event (as outlined in the event order) can help mitigate this.

Page Transition Timing

A typical page transition in jQuery Mobile involves several steps: initiating the change, loading the new page, enhancing its content, and finally, executing the visual transition. Benchmarks show that the transition itself often consumes the majority of the execution time (e.g., ~604ms out of a total ~670ms).

Data and Parameter Manipulation Between Pages

Passing data between jQuery Mobile pages can be accomplished in several ways:

Solution 1: Using changePage Options

The changePage method allows you to pass data directly:

$.mobile.changePage('page2.html', {
    dataUrl : "page2.html?parameter=123",
    data : { 'parameter' : '123' },
    reloadPage : true,
    changeHash : true
});

You can then access this data within the pagebeforeshow event of the target page:

$(document).on('pagebeforeshow', "#second", function (event, data) {
    var url = $(this).data("url");
    if (url && url.indexOf("?") !== -1) {
        var params = url.split("?")[1];
        var parameterValue = params.replace("parameter=", "");
        alert(parameterValue);
    }
});

A complete example for this approach is available here .

Solution 2: Persistent JavaScript Object

If AJAX page loading is consistently used (without hard page reloads), a persistent JavaScript object can serve as a simple data store:

var sharedData = {
    firstName : '',
    lastName : ''
};

Solution 3: Accessing prevPage

The data object in page events includes a prevPage property, which refers to the previous page element:

$(document).on('pagebeforeshow', '#index', function (e, data) {
    if (data.prevPage) {
        alert('Previous page ID: ' + data.prevPage.attr('id'));
    }
});

Solution 4: localStorage (HTML5)

For data that needs to persist across sessions and page refreshes, localStorage is a viable option (though it has compatibility notes with older iOS versions):

if (typeof(Storage) !== "undefined") {
    localStorage.setItem('userFirstName', 'Dragan');
    localStorage.setItem('userLastName', 'Gaic');
}

Deprecation of .live(), .bind(), .delegate()

It’s important to note that methods like .live(), .bind(), and .delegate() are older and largely superseded by the more efficient and flexible .on() method. .live() was particularly slow due to its reliance on event bubbling up to the document object. Benchmarking studies (e.g., jsPerf comparison ) consistently show .on() to be significantly faster. Always prefer .on() for event handling in modern jQuery development.

FAQs on jQuery Mobile Page Events

Q: When should I use pageinit versus document ready in jQuery Mobile

ANS: Use pageinit when your JavaScript needs to interact with a specific jQuery Mobile page’s content, as it fires after the page is loaded via AJAX. Use $(document).ready() for code that needs to run once the entire DOM is loaded, which is less common for page-specific logic in jQuery Mobile.

Q: How can I pass data between jQuery Mobile pages

ANS: You can pass data using the data option in $.mobile.changePage, store it in a persistent JavaScript object as long as AJAX loading is used, access the previous page via data.prevPage, or utilize localStorage for persistent storage.

Q: What is the purpose of the mobileinit event

ANS: The mobileinit event is triggered on the document before jQuery Mobile initializes. It’s the designated place to customize or override global jQuery Mobile settings.

Q: Why might a pagechange event trigger twice

ANS: The pagechange event can sometimes trigger twice if you’re passing additional parameters through $.mobile.changePage in a way that causes recursive calls or if the toPage is not a fully enhanced DOM object. Ensure correct parameter handling.

Q: How to prevent event handlers from being bound multiple times

ANS: The most effective method is to bind events within the pageinit event, as it fires only once per page. Alternatively, use $(document).off('event', selector).on('event', selector, handler) or employ flags like e.handled = true to prevent re-execution.
