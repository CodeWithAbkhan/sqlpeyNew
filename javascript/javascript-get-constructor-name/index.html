“JavaScript: How to Get Constructor Name of an Object?”

How to Get Constructor Name in JavaScript?

JavaScript’s dynamic nature allows for flexible object creation, but this flexibility can sometimes complicate the process of identifying an object’s origin. Several approaches exist, each with its own advantages and limitations.

Solution 1: Leveraging constructor.name (ES2015+)

With the advent of ECMAScript 2015 (ES2015), the name property on constructor functions became a standard way to access the constructor’s name. For any given object thing, thing.constructor.name will often yield the desired string.

Example:

class MyCustomClass {
  constructor() {
    this.id = 123;
  }
}

const myInstance = new MyCustomClass();
console.log(myInstance.constructor.name); // Output: MyCustomClass

const arr = [1, 2, 3];
console.log(arr.constructor.name); // Output: Array

const func = function() {};
console.log(func.name); // Output: "" (for anonymous functions in some environments)

Solution 2: A Direct constructor.name Approach

A more concise application of the constructor.name property can be seen in this snippet:

const getVariableType = (val) => val.constructor.name.toLowerCase();

const dateObj = new Date();
const type1 = getVariableType(dateObj); // 'date'

const numberPrimitive = 42;
const type2 = getVariableType(numberPrimitive); // 'number' (due to auto-boxing)

const arrowFunc = () => {};
const type3 = getVariableType(arrowFunc); // 'arrowfunction' or empty string depending on env.

This approach is straightforward for many common cases.

Solution 3: Adding a Helper Property to Object.prototype

For a more universal solution, you can augment Object.prototype with a getName method. This allows any object to call .getName() to retrieve its constructor’s name. However, modifying built-in prototypes is generally discouraged due to potential conflicts.

Example (Use with Caution):

Object.prototype.getName = function() {
   const funcNameRegex = /function (.{1,})\(/;
   const results = (funcNameRegex).exec((this).constructor.toString());
   return (results && results.length > 1) ? results[1] : "";
};

const myArray = [1, 2, 3];
console.log(myArray.getName()); // Output: Array

// Note: This hack might have unintended consequences and is generally not recommended.

An improved version addresses some potential issues and is often cited:

if (Function.prototype.name === undefined && Object.defineProperty !== undefined) {
    Object.defineProperty(Function.prototype, 'name', {
        get: function() {
            const funcNameRegex = /function\s+([^\s(]+)\s*\(/;
            const results = (funcNameRegex).exec((this).toString());
            return (results && results.length > 1) ? results[1] : "";
        },
        set: function(value) {} // Read-only
    });
}

Solution 4: Utilizing Object.prototype.toString.call()

The Object.prototype.toString.call() method provides a robust way to get a string representation of an object’s internal type. This is particularly useful for distinguishing between built-in types.

Example:

function getObjType(obj) {
    return Object.prototype.toString.call(obj).slice(8, -1);
}

console.log(getObjType('hello'));      // Output: String
console.log(getObjType([1, 2]));       // Output: Array
console.log(getObjType(/abc/));       // Output: RegExp
console.log(getObjType(new Date()));    // Output: Date

// For user-defined types, it generally returns 'Object'
function MyObj() {}
console.log(getObjType(new MyObj())); // Output: Object

A helper function can make this cleaner:

function typeHelper(obj) {
    return Object.prototype.toString.call(obj).slice(8, -1);
}

console.log(typeHelper('test')); // String

Solution 5: The instanceof Operator

The instanceof operator checks if an object is an instance of a specific constructor. While it doesn’t directly give the constructor’s name, it’s fundamental for type checking.

Example:

const arr = [1, 2, 3];
console.log(arr instanceof Array);   // Output: true
console.log(arr instanceof Object);  // Output: true

// Note: Does not work for primitive literals directly
console.log(3 instanceof Number);    // Output: false
console.log(new Number(3) instanceof Number); // Output: true

Solution 6: thing.constructor.toString() with Regex

For cases where constructor.name might be absent or unreliable, you can parse the constructor.toString() output.

Example:

function SomeConstructor() {
  this.prop = 'value';
}

const instance = new SomeConstructor();
const constructorString = instance.constructor.toString();
const constructorName = constructorString.match(/function\s(\w*)\s*\(/)[1];
console.log(constructorName); // Output: SomeConstructor

A more refined version might look like this:

Object.prototype.getConstructorName = function () {
   const str = (this.prototype ? this.prototype.constructor : this.constructor).toString();
   const cname = str.match(/function\s(\w*)/)[1];
   const aliases = ["", "anonymous", "Anonymous"];
   return aliases.indexOf(cname) > -1 ? "Function" : cname;
};

console.log(new Array().getConstructorName());  // Output: Array
console.log((function() {}).getConstructorName()); // Output: Function

Solution 7: A Comprehensive getTypeInfo Function

For a robust solution that handles primitives, functions (including arrow functions), classes, and objects across different environments, a more involved function is often necessary. This approach combines several techniques.

/**
 * Describes the type of a variable.
 */
class VariableType {
    type;
    name;

    constructor(type, name = null) {
        this.type = type;
        this.name = name;
    }

    toString() {
        let result;
        switch (this.type) {
            case "function":
            case "class":
            case "object":
                result = "a ";
                break;
            default:
                return this.type;
        }
        result += this.type;
        if (this.name !== null) {
            result += " named " + this.name;
        }
        return result;
    }
}

const functionNamePattern = /^function\s+([^(]+)?\(/;
const classNamePattern = /^class(\s+[^{]+)?{/;

function getTypeInfo(value) {
    if (value === null) return new VariableType("null");
    const typeOfValue = typeof value;
    const isPrimitive = typeOfValue !== "function" && typeOfValue !== "object";
    if (isPrimitive) return new VariableType(typeOfValue);

    const objectToString = Object.prototype.toString.call(value).slice(8, -1);
    const valueToString = value.toString();

    if (objectToString === "Function") {
        const indexOfArrow = valueToString.indexOf("=>");
        const indexOfBody = valueToString.indexOf("{");
        if (indexOfArrow !== -1 && (indexOfBody === -1 || indexOfArrow < indexOfBody)) {
            return new VariableType("function"); // Arrow function
        }
        const functionName = functionNamePattern.exec(valueToString);
        if (functionName && functionName[1]) {
            return new VariableType("function", functionName[1].trim());
        }
        const className = classNamePattern.exec(valueToString);
        if (className && className[1]) {
            return new VariableType("class", className[1].trim());
        }
        return new VariableType("function"); // Anonymous function
    }
    if (objectToString === "Array") return new VariableType("array");

    const classInfo = getTypeInfo(value.constructor);
    return new VariableType("object", classInfo.name);
}

// Usage:
const obj = { greet: () => console.log("Hello!") };
console.log("Type Info:", getTypeInfo(obj)); // Type Info: an object named Object

function UserDefined() {}
console.log("Type Info:", getTypeInfo(new UserDefined())); // Type Info: an object named UserDefined

Solution 8: Cross-Frame and Cross-Window Type Checking

When dealing with objects from different frames or windows, instanceof and constructor checks can fail because each frame has its own scope for built-in constructors. A custom isInstance function is needed, which involves obtaining the object’s window context.

function getType(o) {
    return Object.prototype.toString.call(o).match(/^\[object\s(.*)\]$/)[1];
}

function isInstance(obj, type) {
    let ret = false;
    const isTypeAString = getType(type) === "String";
    let functionConstructor, context;

    if (!isTypeAString && getType(type) !== "Function") {
        throw new TypeError("type argument must be a string or function");
    }

    if (obj !== undefined && obj !== null && obj.constructor) {
        functionConstructor = obj.constructor;
        // Traverse up the constructor chain to find the root window's Function
        while (functionConstructor !== functionConstructor.constructor) {
            functionConstructor = functionConstructor.constructor;
        }
        context = functionConstructor === Function ? self : functionConstructor("return window")();

        if (isTypeAString) {
            // Resolve nested types like "window.some.Type"
            for (const typeArray = type.split("."), i = 0, l = typeArray.length; i < l && context; i++) {
                context = context[typeArray[i]];
            }
        } else {
            context = type(context); // Type is a function that returns a constructor
        }

        if (context) {
            ret = obj instanceof context;
            // Special handling for primitives that might be wrapped
            if (!ret && (type === "Number" || type === "String" || type === "Boolean")) {
                ret = obj.constructor === context;
            }
        }
    }
    return ret;
}

// Example usage:
console.log(isInstance([], "Array")); // true
console.log(isInstance(new Date(), "Date")); // true

function Animal() {}
function Dog() {}
Dog.prototype = new Animal();
console.log(isInstance(new Dog(), "Dog")); // true
console.log(isInstance(new Dog(), "Animal")); // true

Solution 9: Custom getName for Functions

A clean way to get the name of a function, even when the name property is missing, is to add a method to Function.prototype.

Function.prototype.getName = function() {
  if (typeof this.name !== 'undefined') {
    return this.name;
  } else {
    // Fallback using regex to extract name from toString()
    const match = this.toString().match(/function (.+)\(/);
    return match ? match[1] : '';
  }
};

function MyNamedFunction() {}
console.log(MyNamedFunction.getName()); // Output: MyNamedFunction

const anonymousFunc = function() {};
console.log(anonymousFunc.getName()); // Output: (empty string or specific name if available)

Solution 10: The kind Function from Agave.JS

This utility function provides a consistent way to identify the “kind” of a JavaScript value, including primitives and special cases like NaN.

const kind = function(item) {
    const getPrototype = (item) => Object.prototype.toString.call(item).slice(8, -1);
    let kind;
    if (item === null) {
        kind = 'null';
    } else {
        if (item === undefined) {
            kind = 'undefined';
        } else {
            const prototype = getPrototype(item);
            if ((prototype === 'Number') && isNaN(item)) {
                kind = 'NaN';
            } else {
                kind = prototype;
            }
        }
    }
    return kind;
};

console.log(kind(37));          // Output: Number
console.log(kind(NaN));         // Output: NaN
console.log(kind("hello"));     // Output: String
console.log(kind([1, 2]));      // Output: Array
console.log(kind(function() {})); // Output: Function
console.log(kind(null));        // Output: null
console.log(kind(undefined));   // Output: undefined

Solution 11: Robust getTypeInfo Implementation

This advanced getTypeInfo function, presented as a class VariableType, offers detailed type information, distinguishing between primitive types, arrays, functions (named, anonymous, arrow), classes, and generic objects. It is designed for clarity and extensibility.

function getTypeInfo(value) {
    if (value === null) return new VariableType("null");
    const typeOfValue = typeof value;

        }

        if (functionName && functionName[1]) {

        if (className && className[1]) {
            return new VariableType("class", className[1].trim());
        }
        return new VariableType("function"); // Anonymous function
    }
    if (objectToString === "Array") return new VariableType("array");

    const classInfo = getTypeInfo(value.constructor);
    return new VariableType("object", classInfo.name);
}

Solution 15: typeof Operator Limitations

The typeof operator is simple but limited, often returning "object" for custom types. It’s best for distinguishing primitives from objects, functions, and undefined.

Solution 16: Generic getType and checkType Functions

These utility functions provide a convenient way to get the lowercase type name of any entity and to compare it against a target type.

function getType(entity) {
    const x = Object.prototype.toString.call(entity);
    return x.split(" ")[1].split(']')[0].toLowerCase();
}

function checkType(entity, type) {
    return getType(entity) === type;
}

console.log(getType([1, 2]));          // Output: array
console.log(checkType({ a: 1 }, 'object')); // Output: true

Solution 17: getTypeName for Common Cases

This function handles primitives, errors, null, and uses toString with a regex for other object types.

const getTypeName = (thing) => {
  const name = typeof thing;
  if (name !== 'object') return name;
  if (thing instanceof Error) return 'error';
  if (!thing) return 'null';
  // Regex to extract type name from [object Type]
  return ({}).toString.call(thing).match(/\s([a-zA-Z]+)/)[1].toLowerCase();
};

console.log(getTypeName(123));       // Output: number
console.log(getTypeName(new Error())); // Output: error
console.log(getTypeName(null));      // Output: null
console.log(getTypeName([1, 2]));    // Output: array

Solution 18: jQuery-Compatible getClassName

// Ensure Object.prototype.getClassName is defined and compatible
if (!Object.prototype.hasOwnProperty('getClassName')) {

            const results = (funcNameRegex).exec((this).constructor.toString());
            return (results && results.length > 1) ? results[1] : "";
        },
        configurable: true, // Allows redefinition if needed
        writable: true // Allows modification
    });
}

As mentioned in Solution 12, for ES6 classes and modern JavaScript functions, the .name property is the standard and most direct way.

Considerations and Best Practices

  • ES2015+ constructor.name: This is the most idiomatic and readable approach for modern JavaScript environments.
  • Object.prototype.toString.call(): A reliable fallback for older environments or when constructor.name might be missing or ambiguous. It’s excellent for identifying built-in types.
  • Avoid Modifying Object.prototype: Unless absolutely necessary and with careful consideration for potential conflicts, avoid adding methods to built-in prototypes.
  • Cross-Frame/Window Issues: For these scenarios, a custom function like the isInstance example is essential.
  • Primitives: Be mindful that methods like instanceof might require wrapping primitives in their object counterparts (e.g., new Number(5)). However, direct property access like 3..constructor.name often works due to auto-boxing.
  • Anonymous Functions: The .name property for anonymous functions might be an empty string or a descriptive name depending on the JavaScript engine and environment.

The choice of method depends on the target environment, the complexity of your object creation patterns, and the level of robustness required.

FAQs on JavaScript Constructor Name

Q: What is the simplest way to get a JavaScript object's constructor name

ANS: For objects created in ES2015+ environments, object.constructor.name is the most straightforward method. For example, const arr = []; console.log(arr.constructor.name); will output “Array”.

Q: How can I get the type name for primitive values like numbers or strings

ANS: Primitive values don’t have constructors in the same way objects do. However, when accessed with methods like object.constructor.name or Object.prototype.toString.call(), JavaScript often auto-boxes them into their object wrappers, allowing you to retrieve their type (e.g., “Number”, “String”). For example, (5).constructor.name yields “Number”.

Q: Why does instanceof fail for primitive types

ANS: The instanceof operator checks the prototype chain. Primitive types (like 3, "hello", true) are not objects and thus do not have a prototype chain in the same way objects do. To use instanceof with them, you must first convert them into their corresponding object wrappers, such as new Number(3), new String("hello"), or new Boolean(true).

Q: How can I reliably get the constructor name across different browser windows or iframes

ANS: When dealing with objects originating from different frames or windows, standard instanceof and constructor checks can fail due to separate global scopes. You’ll need a more robust solution, like the isInstance function discussed in Solution 8, which accounts for the object’s window context.

Q: Is it safe to modify Object.prototype to add a getName method

ANS: Modifying built-in prototypes like Object.prototype is generally discouraged. It can lead to unexpected behavior or conflicts if other libraries or future JavaScript features do the same. It’s better to use helper functions or rely on standard, non-intrusive methods.

Q: What is the difference between typeof and Object.prototype.toString.call

ANS: The typeof operator is basic and returns strings like “object”, “number”, “string”, “function”, etc. It’s less precise for distinguishing between different types of objects (e.g., Array vs. Object). Object.prototype.toString.call() provides a more detailed string representation like “[object Array]” or “[object Object]”, allowing for more accurate type identification.
