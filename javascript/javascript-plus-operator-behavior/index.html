JavaScript’s Curious ‘+’ Operator Behavior Explained

Have you ever encountered perplexing results when using the + operator in JavaScript with arrays or objects? This inquiry delves into those often surprising outcomes, drawing from the ECMA-262 standard and practical examples to illuminate JavaScript’s unique type coercion mechanisms.

When the addition operator (+) is employed, JavaScript first attempts to convert both operands into primitive values before performing the operation. For objects, this conversion typically involves calling their toString() or valueOf() methods.

Let’s dissect some common scenarios:

  • [] + []: When an empty array [] is involved with the addition operator, it’s first converted to its primitive representation. According to the standard (§9.1), an object’s default primitive value, when it has a valid toString() method, is the result of calling object.toString(). For arrays, this is equivalent to calling array.join() (§15.4.4.2). An empty array, when joined, results in an empty string. Therefore, [] + [] becomes "" + "", yielding an empty string.

  • [] + {}: Similar to the previous case, both [] and {} are converted to their primitive forms. For an object like {} (unless it has a custom toString or valueOf), the toString() method returns "[object Object]" (§15.2.4.2). Thus, [] + {} becomes "" + "[object Object]", resulting in "[object Object]".

  • {} + []: This scenario presents a subtle difference. If {} appears at the beginning of a statement, JavaScript might interpret it as an empty block rather than an object literal. However, when used with the unary + operator (as implicitly happens here or when forced as an expression like +[]), the curly braces are treated as an object. The unary + operator (§11.4.6) converts its operand to a number after attempting primitive conversion. For [], the primitive conversion is an empty string, which then converts to the number 0 (§9.3.1). Thus, +[] evaluates to 0.

  • {} + {}: Following the logic above, the first {} is interpreted as an empty block. The expression then becomes + {}. As established, +obj attempts to convert the object to a primitive, then to a number. The primitive conversion of {} yields "[object Object]". Attempting to convert this string to a number, according to §9.3.1, results in NaN (Not a Number) because "\[object Object\]" is not a valid numeric literal.

  • Array(16).join("wat" - 1): Here, Array(16) creates an array with 16 empty slots. The join() method concatenates array elements. The expression "wat" - 1 involves the subtraction operator, which strictly operates on numbers. JavaScript attempts to convert "wat" to a number, resulting in NaN (§9.3.1). Since any arithmetic operation involving NaN results in NaN (§11.6.2, step 7), the join() method receives NaN as its argument. The Array.prototype.join() method (§15.4.4.5) converts its argument to a string if it’s not a string. The string representation of NaN is "NaN". Thus, the array is joined with "NaN" repeated 15 times (since there are 16 elements, 15 separators are used).

  • Array(16).join("wat" + 1): In this case, the addition operator + is used with "wat" and 1. As per the addition algorithm (§11.6.1), if one operand is a string, the other is also converted to a string, and string concatenation occurs. So, 1 is converted to "1", and "wat" + 1 becomes "wat1". The join() method then concatenates the array elements using "wat1" as the separator.

Alternative Interpretations and Fixes

The behavior, particularly the {} parsing, can be influenced by context. When an expression like ({} + []) is enclosed in parentheses, the {} is explicitly treated as an object literal, unlike when it starts a line. This distinction is crucial for understanding JavaScript’s parsing rules and the potential for unexpected behavior.

For clearer and more predictable code, especially when dealing with objects and potential type coercion, explicit type conversions are often recommended. For instance, using String({}) or Number([]) can make your intentions explicit.

Consider the following JavaScript code snippet demonstrating these behaviors using eval() to execute strings as code. Note that using eval() is generally discouraged in production code due to security and performance concerns, but it’s illustrative here.

function logOperation(code) {
    function formatOutput(value) {
        // Check if the value is a string for JSON stringification
        return typeof value === "string" ?
            JSON.stringify(value) : value;
    }
    console.log(`>>> ${code}`);
    try {
        console.log(formatOutput(eval(code)));
    } catch (e) {
        console.error(`Error executing "${code}": ${e.message}`);
    }
}

console.log("<pre>");
logOperation('[] + []');
logOperation('[] + {}');
logOperation('{} + []'); // Demonstrating object literal interpretation
logOperation('{} + {}');
logOperation('Array(5).join("wat" - 1)'); // Using a smaller array for brevity
logOperation('Array(5).join("wat" + 1)');
logOperation('Array(5).join("wat" - 1) + " Batman!"');
console.log("</pre>");

FAQs on JavaScript’s ‘+’ Operator Behavior

Q: How does JavaScript convert arrays to strings for the '+' operator

ANS: JavaScript converts arrays to strings by calling their join() method. An empty array results in an empty string, while an array with elements joins them with commas by default. For the + operator, if one operand is a string, the other is also converted to a string for concatenation.

Q: Why does {} + [] result in 0

ANS: When {} starts a statement or is used with the unary + operator, it’s often treated as an object. The +[] part converts the empty array to an empty string, then to the number 0. The + operator then attempts to add 0 to the primitive representation of {} (which is "[object Object]"), and then converts that to a number, resulting in NaN. However, in some contexts, especially when {} is interpreted as a block, it’s the +[] part that dominates, yielding 0.

Q: What happens when a string is not a valid number in arithmetic operations

ANS: If a string cannot be interpreted as a valid number during an arithmetic operation (like subtraction or multiplication), JavaScript converts it to NaN. Any subsequent arithmetic operation involving NaN will also result in NaN.

Q: Explain the difference between {} + [] and ({}) + []

ANS: In {} + [], the first {} might be parsed as an empty block, leaving + [] to be evaluated. +[] converts the empty array to 0. In ({}) + [], the parentheses () ensure that {} is explicitly parsed as an object literal, leading to the "[object Object]" conversion.

Q: How does JavaScript handle operands of mixed types with the '+' operator

ANS: The + operator in JavaScript exhibits flexible behavior. If one operand is a string, it defaults to string concatenation, converting the other operand to a string. If both operands are numbers, it performs numeric addition. If neither is a string and they cannot be reliably converted to numbers for addition, the result might be NaN or other unexpected outcomes due to type coercion.
