“JavaScript Script Loading: Async vs Defer Execution Order Explained”

When integrating external JavaScript files into an HTML document, the placement and attributes assigned to the <script> tag significantly influence page rendering speed and script execution sequence. How does the browser process these scripts when they are marked async, defer, or are included without these modifiers?

What is the effect of using a standard, modifier-less <script> tag?

By default, when the browser encounters a <script src="path/to/script.js"></script> tag:

  1. Blocking Behavior: The HTML parser pauses its process immediately.
  2. Downloading and Execution: The browser fetches the script file and executes it synchronously.
  3. Rendering Stoppage: DOM construction and subsequent rendering are blocked until the script finishes downloading and running.
  4. Order Guarantee: Scripts execute strictly in the order they appear in the document.

This blocking mechanism can delay initial page paint, making the user experience slower.

How do async and defer attributes modify script loading and execution?

Both async and defer attributes instruct the browser to download the script file without blocking HTML parsing. However, the crucial distinction lies in when the script is executed.

The async Attribute (<script async src="..."></script>)

The async attribute provides asynchronous loading and execution:

  • Download: The script downloads in parallel while the HTML parser continues building the DOM.
  • Execution Timing: The script executes immediately upon completion of its download, at the first available opportunity, which can be before the DOM is fully parsed, and potentially before other scripts have finished downloading or executing.
  • Execution Order: No guarantee is made regarding the order of execution. An async script declared later in the document might execute before one declared earlier if it finishes downloading first.

Use Case: async is best suited for independent scripts that do not rely on other scripts or the fully constructed DOM, such as analytics trackers (e.g., Google Analytics).

The defer Attribute (<script defer src="..."></script>)

The defer attribute ensures scripts execute only after HTML parsing is complete but before the DOMContentLoaded event fires:

  • Download: Similar to async, the script downloads in parallel, without blocking the parser.
  • Execution Timing: Defer scripts wait until the entire HTML document has been parsed.
  • Execution Order: Guaranteed order. Defer scripts execute in the exact sequence they are declared in the document.

Use Case: defer is ideal for scripts that depend on the complete DOM structure (DOM manipulation) or scripts that rely on the successful execution of preceding scripts (dependency chaining).

Practical Scenarios and Code Examples

To illustrate the differences, consider these three script declarations:

<!-- Scenario Example -->
<head>
    <!-- 1. Standard Sync Script (Blocks everything) -->
    <script src="critical-setup.js"></script>

    <!-- 2. Async Script (Downloads in parallel, executes ASAP, order uncertain) -->
    <script async src="analytics-tracker.js"></script>

    <!-- 3. Defer Script (Downloads in parallel, executes after parsing, order guaranteed) -->
    <script defer src="dom-manipulator.js"></script>
</head>
<body>
    <!-- ... page content ... -->
    
    <!-- Alternative placement for standard/blocking scripts: Right before </body> -->
    <!-- Placing scripts here avoids blocking initial rendering, but defers execution until the parser reaches this point. -->
</body>

When to Place Scripts at the Bottom of <body>?

A traditional performance practice involves placing all standard (non-async/defer) scripts just before the closing </body> tag.

Benefit: This allows the browser to construct the DOM quickly for faster initial visual display across all browsers, even older ones lacking full defer support.

Caveat: If scripts are placed at the end of the <body>, defer offers less tangible benefit because the DOM parsing work is mostly complete by the time execution begins, though it still maintains execution order integrity.

Handling Script Dependencies

If scriptB.js relies on functionality provided by scriptA.js (e.g., scriptA.js loads jQuery):

  • Using async is risky: If scriptB.js executes before scriptA.js finishes loading and running, the page will likely break or show unexpected results. Coordination code would be needed.
  • Using defer is safe: Because defer guarantees execution order, scriptA.js will run, followed by scriptB.js.

For scenarios requiring dependency order without immediate execution, use defer.

Advanced Technique: Async Download with Ordered Execution

For maximum performance, one advanced technique attempts to achieve asynchronous downloading while preserving execution order by dynamically injecting scripts in the <head> and explicitly setting async = false:

[
    '//external-cdn.com/library_v1.js', // First script in queue
    'local_init.js'                     // Second script, dependent on first
].forEach(function(scriptSource) {
    var scriptElement = document.createElement('script');
    scriptElement.src = scriptSource;
    // Setting async=false (or omitting it on dynamically created scripts, which default to async=true behavior unless modified) 
    // effectively queues them similar to standard DOM order, but they download non-blockingly if they are not parsed immediately.
    scriptElement.async = false; 
    document.head.appendChild(scriptElement);
});
// Note: Scripts added this way are queued for execution in order, but their download starts immediately, optimizing resource discovery.

For superior resource discovery by browser preload scanners, linking these resources using <link rel="subresource" href="..."> might be employed, though this requires declaring the scripts twice (once in <link> and again in <script>).

FAQs on JavaScript Script Loading Async Vs Defer

Q: What happens to DOM construction when using the defer attribute

ANS: When using defer, the browser downloads the script file concurrently while continuing to construct the DOM. The script execution is postponed until after the HTML parsing is complete.

Q: Can I use async and defer on the same script tag

ANS: No, a script tag cannot simultaneously have both the async and defer attributes. Only one or neither can be present.

Q: Which attribute preserves script execution order

ANS: The defer attribute guarantees that scripts will execute in the same order they appear in the HTML document. The async attribute does not guarantee order.

Q: Are async and defer attributes applied to inline scripts

ANS: No, the async and defer attributes only apply to external scripts referenced via the src attribute. They have no effect on inline script blocks.
