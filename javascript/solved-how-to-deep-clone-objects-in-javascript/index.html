“Solved: How to Deep Clone Objects in JavaScript”

Method 1: Utilizing the Native structuredClone() Function

Modern JavaScript environments offer a built-in structuredClone(value) function, which is the most robust and recommended way to perform deep cloning. This function is supported across all major browsers and Node.js versions 17 and above. For compatibility with older systems, a polyfill can be used.

Implementation:

const originalData = {
  textVal: 'hello',
  numVal: 42,
  flag: true,
  nestedObj: {
    prop1: 'valueA',
    prop2: [1, 2, 3]
  },
  creationDate: new Date(),
  pattern: /xyz/i,
  dataSet: new Set([10, 20]),
  binaryBlob: new Blob(['binary content'])
};

// Perform a deep clone using structuredClone
const clonedDataNative = structuredClone(originalData);

console.log('Original Object:', originalData);
console.log('Cloned Object (Native):', clonedDataNative);
console.log('Are they the same object?', originalData === clonedDataNative); // Expected: false
console.log('Is nestedObj the same reference?', originalData.nestedObj === clonedDataNative.nestedObj); // Expected: false

Polyfill for Older Environments:

If you need to support older environments that lack structuredClone, you can import a polyfill:

import structuredClone from '@ungap/structured-clone';

// Then use structuredClone(value) as shown above

Important Considerations and Limitations:

While powerful, structuredClone() has specific limitations:

  • Function Objects: Functions cannot be duplicated. Attempting to clone an object containing functions will result in a DataCloneError exception.
  • DOM Nodes: Cloning DOM nodes similarly throws a DataCloneError exception.
  • Property Descriptors: Metadata-like features such as property descriptors (e.g., writable, enumerable, configurable), setters, and getters are not preserved. A read-only property in the original will be read/write in the clone by default.
  • Prototype Chain: The prototype chain of the source object is not walked or duplicated in the clone.

Method 2: Rapid Cloning with Data Transformation (JSON.parse(JSON.stringify()))

For basic JavaScript objects that do not contain complex data types, the JSON.parse(JSON.stringify(object)) technique offers a straightforward one-liner for deep cloning.

Usage:

const complexSource = {
  strProperty: 'test string',
  numProperty: 12345,
  booleanStatus: false,
  nullValue: null,
  creationTimestamp: new Date(), // This will be stringified
  undefinedValue: undefined, // This will be lost
  infiniteNum: Infinity, // This will become null
  regexPattern: /abc.*/, // This will be lost
};

console.log('Original Object:', complexSource);
console.log('Original date type:', typeof complexSource.creationTimestamp); // Output: object (Date object)

const jsonClonedObject = JSON.parse(JSON.stringify(complexSource));

console.log('JSON Cloned Object:', jsonClonedObject);
console.log('Cloned date type:', typeof jsonClonedObject.creationTimestamp); // Output: string (ISO string)

Limitations of JSON.parse(JSON.stringify()):

This method is fast for simple JSON-serializable objects but comes with significant data loss for certain types:

  • Unsupported Types: It cannot handle Date objects (converts them to ISO strings), functions, undefined values (they are lost), Infinity (becomes null), RegExp objects (lost), Maps, Sets, Blobs, FileLists, ImageDatas, sparse Arrays, or Typed Arrays.
  • Circular References: Objects with circular references will cause a TypeError.
  • Performance Note: While often perceived as fast for simple cases, benchmarks have shown JSON.parse(JSON.stringify(obj)) can be slower than other deep cloning methods, especially when compared to native structuredClone in modern environments, or optimized library functions. Referencing benchmarks like jsben.ch can provide more details.

Method 3: Reliable Cloning Using Third-Party Libraries

When dealing with complex objects, circular references, or a need for broader compatibility, relying on well-tested libraries is often the most pragmatic approach. These libraries provide robust deep cloning functions that handle many edge cases gracefully.

Popular Library Options:

  • Lodash: The _.cloneDeep function is widely recognized as a robust solution for deep cloning. It can be imported as a standalone module (lodash.clonedeep). 
    // Assuming Lodash is imported as '_'
const initialData = { key: 'value', nested: { id: 123 } };
const clonedWithLodash = _.cloneDeep(initialData);

console.log('Lodash Cloned Object:', clonedWithLodash);
console.log('Are keys strictly equal?', clonedWithLodash.nested === initialData.nested); // Expected: false
  • Ramda: Provides a R.clone function for deep copying data structures.
  • AngularJS: The angular.copy utility function is available within the AngularJS framework.
  • jQuery: While $.clone() only duplicates DOM elements, jQuery.extend(true, {}, oldObject) can perform a deep copy of JavaScript objects. 
    // Using jQuery's extend for deep copy
const oldJsObject = { detail: { name: 'ItemA', quantity: 5 } };
const newJsObject = jQuery.extend(true, {}, oldJsObject);

console.log('jQuery Deep Copy:', newJsObject);
console.log('Are details strictly equal?', newJsObject.detail === oldJsObject.detail); // Expected: false
  • Just library: just-clone is part of a collection of zero-dependency npm modules, each designed to perform a single specific task.

Method 4: Implementing a Custom Recursive Deep Clone Function

For scenarios where a custom solution is preferred or necessary (e.g., specific optimizations, handling unique object types not covered by structuredClone or JSON.parse), writing a recursive function is an option.

Example of a Basic Recursive Clone (Handles primitive types, arrays, and objects):

This approach can be faster than JSON.parse(JSON.stringify()) for certain object structures, especially if you control the object’s complexity.

function performDeepCopy(sourceValue) {
  // Handle primitives and null/undefined values
  if (sourceValue === null || typeof sourceValue !== 'object') {
    return sourceValue;
  }

  // Handle Date objects
  if (sourceValue instanceof Date) {
    return new Date(sourceValue.getTime());
  }

  // Handle Arrays
  if (Array.isArray(sourceValue)) {
    const copiedArray = [];
    for (let i = 0; i < sourceValue.length; i++) {
      copiedArray[i] = performDeepCopy(sourceValue[i]);
    }
    return copiedArray;
  }

  // Handle Objects
  const copiedObject = {};
  for (const key in sourceValue) {
    if (Object.prototype.hasOwnProperty.call(sourceValue, key)) {
      copiedObject[key] = performDeepCopy(sourceValue[key]);
    }
  }
  return copiedObject;
}

const originalProduct = {
  id: 'PROD001',
  details: {
    name: 'Fancy Gadget',
    price: 99.99,
    features: ['wireless', 'portable'],
    releaseDate: new Date('2023-01-15T10:00:00Z')
  }
};

const productClone = performDeepCopy(originalProduct);

console.log('Original Product:', originalProduct);
console.log('Cloned Product (Custom):', productClone);
console.log('Are details objects the same?', originalProduct.details === productClone.details); // Expected: false
console.log('Are features arrays the same?', originalProduct.details.features === productClone.details.features); // Expected: false
console.log('Is releaseDate the same object?', originalProduct.details.releaseDate === productClone.details.releaseDate); // Expected: false

Alternative Recursive Method (with isActiveClone for circular references prevention):

A more advanced recursive method can be devised to handle circular references, albeit with some temporary modifications to the original object during cloning.

function duplicateRecursive(dataItem) {
    if (dataItem === null || typeof (dataItem) !== 'object' || 'isBeingCloned' in dataItem)
        return dataItem;

    let tempDuplicate;
    if (dataItem instanceof Date)
        tempDuplicate = new dataItem.constructor(); // or new Date(dataItem);
    else
        tempDuplicate = dataItem.constructor();

    for (const propKey in dataItem) {
        if (Object.prototype.hasOwnProperty.call(dataItem, propKey)) {
            dataItem['isBeingCloned'] = null; // Mark to prevent infinite loop
            tempDuplicate[propKey] = duplicateRecursive(dataItem[propKey]);
            delete dataItem['isBeingCloned']; // Remove mark
        }
    }
    return tempDuplicate;
}

const itemA = { identifier: 'ItemX' };
itemA.selfRef = itemA; // Create a circular reference

const copiedItemA = duplicateRecursive(itemA);
console.log('Copied Item with Circular Ref:', copiedItemA);
console.log('Self-reference check:', copiedItemA.selfRef === copiedItemA); // Expected: true (if handled)

Performance Considerations for Custom Loops: JavaScript trace engines sometimes struggle with optimizing for...in loops, especially when combined with hasOwnProperty checks. For performance-critical “hot loops” with known object structures, manually constructing the object can offer significant performance gains.

// Manual clone for maximum speed with known structure
const originalSettings = {
  settingA: sourceObject.settingA,
  settingB: sourceObject.settingB,
  settingC: sourceObject.settingC.nestedValue
};

Method 5: Shallow Copy Techniques (Important Distinction)

While this article focuses on deep cloning, it’s crucial to distinguish it from shallow copying, as these methods are often confused. Shallow copies only duplicate the first level of an object’s properties. Nested objects or arrays will still share references with the original.

  • Object.assign({}, obj): This ES6 method copies values of all enumerable own properties from one or more source objects to a target object. It performs a shallow copy.

    const baseObject = { valA: 1, nestedB: { id: 2 } };
const shallowAssignment = Object.assign({}, baseObject);

console.log('Original:', baseObject);
console.log('Shallow Copy:', shallowAssignment);
console.log('Is nestedB the same reference?', baseObject.nestedB === shallowAssignment.nestedB); // Expected: true

baseObject.nestedB.id = 99; // Modifies both baseObject and shallowAssignment
console.log('Modified Original:', baseObject);
console.log('Impact on Shallow Copy:', shallowAssignment); // Shows modified nestedB

    A polyfill exists for Object.assign to support older browsers.

  • Spread Operator ({ ...obj } for objects, [ ...arr ] for arrays): The spread syntax creates a new array or object with the elements/properties of the original. This also performs a shallow copy.

    const productItem = { itemName: 'Tablet', specs: { weight: '500g' } };
const clonedProductSpread = { ...productItem };

console.log('Original Item:', productItem);
console.log('Spread Cloned Item:', clonedProductSpread);
console.log('Is specs object the same?', productItem.specs === clonedProductSpread.specs); // Expected: true

Other Approaches and Libraries

  • Object.create(): This method creates a new object, using an existing object as the prototype of the newly created object. It effectively creates a shallow copy, where the new object inherits properties from the original. Modifications to the new object’s own properties won’t affect the original, but changes to shared prototype properties will. 
    function createPrototypeClone(prototypeObject) {
    function DummyConstructor() {}
    DummyConstructor.prototype = prototypeObject;
    return new DummyConstructor();
}

const oldCfg = { configA: 5, configB: { value: 10 } };
const newCfg = createPrototypeClone(oldCfg);

console.log('New Configuration (Prototype):', newCfg.configA); // Accesses inherited property
console.log('Has own property (configA)?', newCfg.hasOwnProperty('configA')); // Expected: false
  • Third-party clone library: A library named “clone” is available on npm that offers comprehensive recursive cloning, including support for circular references. 
    // Example usage after npm install clone
const clone = require('clone');
const systemSettings = { id: 1, user: { name: 'Alice' } };
const duplicatedSettings = clone(systemSettings);
// duplicatedSettings is a deep clone

Benchmarking and Performance

When choosing a deep cloning method, performance can be a significant factor, especially for large or frequently cloned objects. Benchmarking tools like jsben.ch (and similar platforms) allow you to compare the execution speed of different approaches across various environments.

Generally, structuredClone is the most performant and reliable native solution for suitable data types. For JSON-serializable objects, JSON.parse(JSON.stringify()) can be quick but carries limitations. Custom recursive functions, if optimized for specific data structures and avoiding for...in and hasOwnProperty in hot loops, can sometimes outperform general library solutions.

FAQs on Solved How to Deep Clone Objects in JavaScript

Q: What is deep cloning

ANS: Deep cloning creates an entirely new object with copies of all properties, including nested objects and arrays. This means changes to the cloned object will not affect the original object.

Q: When to use structuredClone

ANS: You should use structuredClone() when working in modern environments (browsers, Nodejs 17+) and your object does not contain functions, DOM nodes, or require specific preservation of property descriptors or the prototype chain. It is the most robust native option.

Q: Can JSON parse stringify handle all data types

ANS: No, JSON.parse(JSON.stringify()) cannot handle all data types. It will lose functions, undefined values, RegExp objects, Map and Set objects, and convert Date objects to ISO strings. It also fails with circular references.

Q: Is Object assign for deep copy

ANS: No, Object.assign() performs a shallow copy. It only copies the top-level properties. If your object contains nested objects or arrays, Object.assign() will copy their references, meaning changes to the nested structures in the copy will also affect the original.

Q: Which JavaScript library helps with deep cloning

ANS: Popular JavaScript libraries like Lodash (_.cloneDeep), Ramda (R.clone), and jQuery (jQuery.extend(true, {}, obj)) provide robust functions for deep cloning that handle complex scenarios, including circular references.
