“JavaScript NaN Check: Reliable Methods Explained”

Encountering “Not a Number” (NaN) values in JavaScript is a common scenario, often arising from invalid mathematical operations or parsing errors. Accurately detecting these NaN values is crucial for robust code. While JavaScript provides the built-in isNaN() function, it can sometimes yield unexpected results due to its type coercion behavior. This post delves into various methods to reliably identify NaN, offering practical code examples and exploring alternative approaches.

Why is isNaN() Not Always Reliable?

The global isNaN() function attempts to convert its argument to a number before performing the check. This means that non-numeric values that can be coerced into NaN will also return true. For instance, isNaN('hello') returns true because 'hello' converts to NaN. This can lead to confusion when you intend to check specifically for the NaN value itself, not just anything that evaluates to NaN.

Reliable Methods for Identifying NaN

Several techniques offer more precise checks for the NaN value.

1. The value !== value Approach

A fundamental property of NaN is that it is the only JavaScript value that is not equal to itself. This characteristic forms the basis of a highly reliable check.

function isTrulyNaN(value) {
  return value !== value;
}

console.log(isTrulyNaN(NaN)); // true
console.log(isTrulyNaN('hello')); // false
console.log(isTrulyNaN(undefined)); // false
console.log(isTrulyNaN(123)); // false

This method directly checks the unique inequality of NaN with itself, avoiding the type coercion issues of the global isNaN().

2. Using Number.isNaN() (ECMAScript 6+)

Introduced in ECMAScript 2015 (ES6), Number.isNaN() provides a more stringent check. It returns true only if the provided value is a number and is NaN. It does not perform type coercion.

console.log(Number.isNaN(NaN)); // true
console.log(Number.isNaN('hello')); // false
console.log(Number.isNaN(123)); // false
console.log(Number.isNaN(undefined)); // false

For environments supporting ES6 and later, Number.isNaN() is a preferred and clean solution.

3. Using Object.is() (ECMAScript 6+)

Object.is() is another ES6 method that determines whether two values are the same value. It treats NaN as equal to NaN, unlike the standard equality operators.

let result = 3 / 'bar'; // result is NaN
console.log(Object.is(result, NaN)); // true

let anotherResult = 'hello';
console.log(Object.is(anotherResult, NaN)); // false

This method is excellent for comparing values, including checking if a value is precisely NaN.

4. Using parseFloat() and isNaN() with Caution

While parseFloat() can parse a string into a floating-point number, it stops parsing when it encounters a non-numeric character after a valid numeric sequence. Combining this with isNaN() can still be tricky, as shown in the original examples:

console.log(isNaN(parseFloat('1.2geoff'))); // false, because parseFloat returns 1.2
console.log(isNaN(parseFloat('geoff'))); // true, because parseFloat returns NaN

To use parseFloat more reliably for validation, one might combine it with stricter checks or use Number() for a stricter conversion.

5. The Number() Constructor for Strict Conversion

The Number() constructor attempts to convert its argument to a number. If the conversion fails for reasons other than implicit coercion to NaN (like undefined or null), it directly results in NaN.

console.log(isNaN(Number('1.2geoff'))); // true
console.log(isNaN(Number('geoff')));   // true
console.log(isNaN(Number(undefined))); // true
console.log(isNaN(Number(null)));      // true (null converts to 0)
console.log(isNaN(Number('')));        // true (empty string converts to 0)

When used with isNaN(), Number() offers a more predictable behavior for identifying values that truly cannot be represented as numbers.

6. Polyfilling Number.isNaN() for Older Environments

If you need to support environments that do not have ES6 features, you can polyfill Number.isNaN():

// Polyfill from MDN
if (Number.isNaN === undefined) {
  Number.isNaN = function(value) {
    return typeof value === "number" && value !== value;
  };
}

// Or a more concise version:
if (Number.isNaN === undefined) {
  Number.isNaN = function(value) {
    return value !== value;
  };
}

This ensures consistent behavior across different JavaScript runtimes.

Practical Code Snippets

Here are some of the most effective code examples for checking NaN:

Checking if a variable is strictly NaN:

function checkStrictNaN(variable) {
  return Number.isNaN(variable);
}

console.log(checkStrictNaN(NaN)); // true
console.log(checkStrictNaN("NaN")); // false

Checking if a value can be parsed to a number, and if not, it’s NaN:

function parseAndCheckNaN(value) {
  return isNaN(Number(value));
}

console.log(parseAndCheckNaN("123"));    // false
console.log(parseAndCheckNaN("abc"));    // true
console.log(parseAndCheckNaN(undefined));// true

A robust check that handles potential type issues:

function robustNaNCheck(value) {
  // First, ensure it's a number type.
  // Then, check if it's not equal to itself.
  return typeof value === 'number' && value !== value;
}

console.log(robustNaNCheck(NaN)); // true
console.log(robustNaNCheck(0/0)); // true
console.log(robustNaNCheck("NaN")); // false

This combination ensures that you’re only evaluating actual numeric NaN values and not strings or other types that might coerce.

Alternatives and Considerations

  • value != value vs. value !== value: Both achieve the same for NaN. The strict inequality (!==) is generally preferred in JavaScript for avoiding unexpected type coercion.
  • parseFloat vs. Number: Use Number() when you need a strict conversion to a number. parseFloat() is more lenient and stops parsing at the first invalid character.
  • External Libraries: Libraries like Lodash offer utilities like _.isNaN() which provide reliable checks similar to Number.isNaN(). If you’re already using such a library, it might be convenient to use its implementation. You can learn more about JavaScript NaN properties in this MDN article .

FAQs on JavaScript NaN Check

Q: What is the most reliable way to check for NaN in JavaScript

ANS: The most reliable methods are Number.isNaN(value) (for ES6+) or the value !== value check, as they do not perform type coercion and specifically target the NaN value.

Q: Why does isNaN('hello') return true

ANS: The global isNaN() function attempts to convert its argument to a number first. Since ‘hello’ cannot be converted to a valid number, it coerces to NaN, causing isNaN() to return true.

Q: Is Number.isNaN() better than the global isNaN()

ANS: Yes, Number.isNaN() is generally better because it only returns true if the value is a number and is NaN. It does not perform type coercion, making it more precise for checking the NaN value itself.

Q: Can I use equality operators to check for NaN

ANS: No, you cannot use standard equality operators (== or ===) to check for NaN. NaN === NaN will always evaluate to false.

Q: How does the value !== value check work for NaN

ANS: NaN is the only JavaScript value that is not equal to itself. Therefore, checking if a value is not strictly equal to itself (value !== value) is a definitive way to identify if it is NaN.
