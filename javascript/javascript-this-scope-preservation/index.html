“JavaScript ’this’ Scope Preservation Solutions Using Aliases”

A frequent challenge in JavaScript development involves the dynamic nature of the this keyword, especially when execution context shifts within nested functions (like callbacks or inner functions). When a new function is invoked, this often defaults to the global scope (or undefined in strict mode), losing the reference to the object or element from the outer scope. How can developers reliably capture and reuse the original this value?

Technique 1: Aliasing ’this’ with a Descriptive Variable

One common pattern involves immediately assigning the outer function’s this value to a local, persistent variable. While historically named that, a more descriptive name enhances code readability.

Consider this scenario where we need to retain a reference to the clicked element inside an forEach loop:

const availableColours = ['crimson', 'forestgreen', 'royalblue'];
document.getElementById('menu-trigger').addEventListener('click', function() {
    // 'this' correctly refers to the 'menu-trigger' element here
    const clickedElementRef = this; 

    availableColours.forEach(function() {
        // Inside forEach, 'this' is likely undefined or global
        // clickedElementRef still accurately points to the 'menu-trigger' element
    });
});

This concept applies equally well when mixing native JavaScript event listeners with libraries like jQuery:

// jQuery Example
$('#element-anchor').on('click', function() {
    // 'this' is the jQuery wrapped element clicked
    const anchorElement = this; 

    $('.item-list').each(function() {
        // 'this' here is the current item in the list iteration
        // anchorElement preserves the reference to the initial anchor clicked
    });
});

The purpose of this alias is to “bake in” the required scope before the context potentially changes inside the inner function.

Technique 2: Douglas Crockford’s Conventional Private ’that'

Following conventions popularized by Douglas Crockford, creating a variable named that serves as a recognizable convention to rescue the correct object context from inner functions that erroneously reset this. This addresses the ECMAScript specification quirk where this behaves unexpectedly for inner function calls.

Examine the difference when dealing with constructor functions:

// Function where 'this' context is lost
function AttemptedClass(name) {
    this.instanceName = name;

    function retrieveContext() {
        return this; // Scope points incorrectly after inner call
    }

    return {
        getContext : retrieveContext
    }
}

// Function where 'this' context is preserved via alias
function StableClass(name) {
    var that = this; // Preserve outer 'this'
    this.instanceName = name;

    function retrieveContext() {
        return that; // Scope correctly preserved
    }

    return {
        getContext : retrieveContext
    }
}

const unstableInstance = new AttemptedClass('ErrorProne');
const stableInstance = new StableClass('Reliable');

// If run outside strict mode, unstableInstance.getContext().instanceName might be global property or undefined
console.log(`Stable result: ${stableInstance.getContext().instanceName}`); // Output: Reliable
// console.log(`Unstable result: ${unstableInstance.getContext().instanceName}`); // Likely results in error or unexpected value

Technique 3: Context Preservation in Object Methods

When defining a function as a property of an object (a method), and then defining another function inside that method, the inner function’s this reverts to the global object, not the parent object. Using an alias like that allows the inner function access to the parent object’s properties.

const componentConfig = {
    settings: { isActive: false },

    initialize: function() {
        // 'this' refers to componentConfig
        this.settings.isActive = false;
        const outerContext = this; // Alias established

        const executeInitialization = function() {
            // 'this' here refers to the global object
            // outerContext.settings.isActive accesses the correct state
            outerContext.settings.isActive = true; 
        };

        executeInitialization();
    }
};

Technique 4: Alternative Method Using call() or apply()

Instead of creating a persistent variable alias, you can explicitly set the this context for the inner function invocation using the built-in methods call() or apply(). This forces the inner function to use the context provided as the first argument.

const vehicleCar = {
    engine: { isRunning: false },

    startSequence: function() {
        this.engine.isRunning = false;

        const innerActivator = function() {
            // Normally 'this' is lost here
            this.engine.isRunning = true; // Will succeed if context is bound
        };

        // Explicitly bind 'this' from startSequence to innerActivator
        innerActivator.apply(this); 
    }
};

Technique 5: Constructor Adjustments and Explicit Return

In situations involving object construction, particularly when attaching methods to be used in DOM events, this inside the method might refer to the DOM element rather than the object instance. Capturing this in the constructor scope solves this:

// Using 'that' to bind the instance scope
const ShapeConstructor = function(label) {
  this.label = label;
  var that = this; // Bind instance

  this.displayLabel = function() {
    // If invoked via DOM event, 'that.label' remains correct
    alert(that.label); 
  };
};

const myShape = new ShapeConstructor('Square');
const buttonElement = document.getElementById('label-button');

// Even when triggered by the button event, 'that' preserves 'myShape' context
buttonElement.addEventListener('click', myShape.displayLabel);

An alternative, though one that bypasses standard prototype inheritance, is to create and return a plain object, ensuring all internal references use the local that variable:

const SimpleObjectFactory = function(id) {
  var that = {}; // Create a plain object context
  that.id = id;
  
  that.reportId = function() {
    alert(`Reported ID: ${that.id}`);
  };
  return that; // Return the aliased object
};

Technique 6: Context Shifting in Iterators (jQuery Example)

When iterating over elements, the value of this shifts with each iteration. If you need to reference the original element that triggered the event while looping through other elements, aliasing becomes essential.

In the provided jQuery example, the initial handler binds this to the clicked anchor. Inside the subsequent .each() loop, this changes to the current element being processed in the loop. By saving the initial event target reference as that, we can manipulate the original element later:

$(document).on('ready', function() {
    let lastClickedItem = null;
    
    $(".work-selector > a").click(function(e) {
        e.preventDefault();
        const currentItemHtml = $(this).html();
        const originalAnchorRef = this; // Save initial context

        if (currentItemHtml === lastClickedItem) {
            lastClickedItem = null;
            $('.detail-pane').show();
        } else {
            lastClickedItem = currentItemHtml;
            $('.detail-pane').each(function() {
                // Here, 'this' is the '.detail-pane'
                const currentPaneAlt = $(this).find('img').attr('alt'); 
                
                if (currentPaneAlt !== currentItemHtml) {
                    $(this).hide();
                } else {
                    $(this).show();
                    // Use the saved reference to style the original clicked anchor
                    $(originalAnchorRef).css("border", "2px solid yellow"); 
                }
            });
        }
    });
});

We rely on originalAnchorRef (that in the original content) to remember the element that initiated the entire sequence, even when iterating deep inside other loops.

FAQs on JavaScript This Scope Preservation

Q: Why does 'this' change inside nested JavaScript functions

ANS: In JavaScript, the value of ’this’ is determined dynamically based on how a function is called. When an inner function is called, its ’this’ defaults to the global object (or is undefined in strict mode), breaking the expected reference from the outer scope.

Q: Is using 'that' the only way to save the context

ANS: No, alternative methods include using the Function methods ‘call()’ or ‘apply()’ to explicitly set the context for the inner function call, or using modern ES6 arrow functions which inherently retain the ’this’ of their surrounding lexical scope.

Q: What is the benefit of using a descriptive alias like clickedEl instead of 'that'

ANS: A descriptive alias like ‘clickedEl’ makes the code self-documenting. It clearly communicates which element or object the variable refers to, which is much clearer than the generic, conventional name ’that’ in complex function chains.
