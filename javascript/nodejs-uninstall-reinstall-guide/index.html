How to Completely Uninstall Node.js and NPM on macOS

The process of removing Node.js and its associated package manager, NPM, can sometimes be more involved than a simple drag-to-trash. Hidden files, conflicting installations, and improper PATH configurations can leave remnants that interfere with future setups. Here are several strategies commonly used by the community:

Solution 1: Manual Removal of Node.js Files

This method involves systematically deleting Node.js related directories and files across your system. It’s crucial to be careful with sudo rm -rf commands, as they permanently delete files.

  • Targeted Deletion: Identify and remove directories like /usr/local/{lib/node{,/.npm,_modules},bin,share/man} and ~/.npm, ~/.node-gyp.
  • Specific File Removal: Also target executables and man pages in /usr/local/bin/npm, /usr/local/share/man/man1/node*, and /usr/local/lib/dtrace/node.d.
  • Alternative Paths: Be aware of potential installations in /opt/local/ if you’ve used MacPorts.
# Comprehensive manual removal
sudo rm -rf \
  /usr/local/{lib/node{,/.npm,_modules},bin,share/man}/{npm*,node*,man1/node*}
sudo rm -rf \
  /usr/local/bin/npm \
  /usr/local/share/man/man1/node* \
  /usr/local/lib/dtrace/node.d \
  ~/.npm \
  ~/.node-gyp
sudo rm -rf /opt/local/bin/node /opt/local/include/node /opt/local/lib/node_modules
sudo rm -rf /usr/local/bin/npm /usr/local/share/man/man1/node.1 /usr/local/lib/dtrace/node.d
  • NVM PATH Adjustment: Remember that Node Version Manager (NVM) modifies your $HOME/.bashrc or $HOME/.zshrc. You’ll need to revert these changes manually after uninstalling.

Solution 2: Using Homebrew for Uninstall and Reinstall

If you installed Node.js via Homebrew, this is often the cleanest approach.

  • Uninstall: 
    brew uninstall node
# For a more forceful removal of all versions:
# brew uninstall --force node
brew cleanup
rm -f /usr/local/bin/npm /usr/local/lib/dtrace/node.d # Clean up lingering files
rm -rf ~/.npm # Remove npm cache
  • Reinstall: 
    brew install node
# Verify installation
which node
# Optionally set NODE_PATH for specific scenarios
# export NODE_PATH='/usr/local/lib/node_modules'

Solution 3: Comprehensive File System Cleanup

This solution targets a broader range of Node.js related files and configurations, offering a more thorough cleanup.

# Remove npm cache and configuration
sudo rm -rf ~/.npm ~/.nvm ~/node_modules ~/.node-gyp ~/.npmrc ~/.node_repl_history

# Remove node and npm executables and related files
sudo rm -rf /usr/local/bin/npm /usr/local/bin/node-debug /usr/local/bin/node /usr/local/bin/node-gyp
sudo rm -rf /usr/local/share/man/man1/node* /usr/local/share/man/man1/npm*
sudo rm -rf /usr/local/include/node /usr/local/include/node_modules
sudo rm -rf /usr/local/lib/node /usr/local/lib/node_modules /usr/local/lib/dtrace/node.d
sudo rm -rf /opt/local/include/node /opt/local/bin/node /opt/local/lib/node
sudo rm -rf /usr/local/share/doc/node
sudo rm -rf /usr/local/share/systemtap/tapset/node.stp

# Homebrew cleanup if applicable
brew uninstall node
brew doctor
brew cleanup --prune-prefix

Solution 4: Using lsbom for Package Bom Removal

This method leverages the lsbom command to list files installed by a package receipt, allowing for precise removal.

  • For Intel Macs (10.11.x and above): 
    lsbom -f -l -s -pf /var/db/receipts/org.nodejs.node.pkg.bom >> ~/filelist.txt
cat ~/filelist.txt | while read f; do sudo rm /usr/local/${f}; done
sudo rm -rf /usr/local/lib/node /usr/local/lib/node_modules /var/db/receipts/org.nodejs.*
  • For Intel Macs (10.10.x and below), or older Node.js versions: 
    lsbom -f -l -s -pf /var/db/receipts/org.nodejs.pkg.bom | while read f; do sudo rm /usr/local/${f}; done
sudo rm -rf /usr/local/lib/node /usr/local/lib/node_modules /var/db/receipts/org.nodejs.*

Solution 5: Simplified Homebrew Uninstall Steps

A more streamlined approach for Homebrew users, focusing on essential cleanup.

brew uninstall node;
which node; # Identify node's location
sudo rm -rf /usr/local/bin/node; # Remove the node executable
sudo rm -rf /usr/local/lib/node_modules/npm/; # Remove npm's global modules
brew doctor;
brew cleanup --prune-prefix;

Solution 6: Clean Uninstall for macOS Monterey and Big Sur

These solutions are tailored for recent macOS versions and address specific file path variations.

  • Monterey 12.0.1: 
    # Navigate to directories and remove node-related folders
cd /usr/local/include && sudo rm -R node
cd ../lib && sudo rm -R node_modules
cd ../bin && sudo rm -R node
# Verify removal
node -v # Should report "command not found"
  • Big Sur 11.2.3: Pay close attention to the receipts file name. 
    # Option 1: Using lsbom with the correct receipt filename
lsbom -f -l -s -pf /var/db/receipts/org.nodejs.node.pkg.bom | while read f; do sudo rm /usr/local/${f}; done
sudo rm -rf /usr/local/lib/node /usr/local/lib/node_modules /var/db/receipts/org.nodejs.*

# Option 2: Manual directory cleanup
cd /var/db/receipts/ && sudo rm -rf org.nodejs.*
cd /usr/local/lib && sudo rm -rf node*
cd /usr/local/include && sudo rm -rf node*
cd /usr/local/bin && sudo rm -rf /usr/local/bin/npm /usr/local/bin/node
# Additional cleanup
sudo rm -rf /usr/local/share/man/man1/node.1 /usr/local/lib/dtrace/node.d ~/.npm

Solution 7: Addressing Specific Version Conflicts (e.g., node@8)

Sometimes, older versions installed via Homebrew can cause conflicts.

# Check which node version is active
which node
# Example output: /usr/local/bin/node@8

# Uninstall the specific version
brew uninstall node@8

Solution 8: Using whereis for Location Identification

A quick way to find executables and their paths before removal.

whereis node
whereis npm
whereis nvm
# Then manually remove identified directories and restart your terminal

Solution 9: Docker as an Alternative Environment

For a truly isolated Node.js experience, consider Docker. This keeps your system clean and allows for managing multiple Node.js versions effortlessly. Learn more about Node.js on Docker .

Reinstalling Node.js After Cleanup

Once you’ve thoroughly removed the old installation, it’s time to set up a fresh environment.

Reinstalling with Node Version Manager (NVM)

NVM is highly recommended for managing multiple Node.js versions.

  1. Install NVM: 
    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.1/install.sh | bash
    Follow any on-screen instructions, which might include adding NVM to your shell’s profile (.zshrc or .bashrc). You might need to create or update ~/.zshrc or ~/.bashrc with: 
    touch ~/.zshrc
# Ensure NVM sourcing is in your .zshrc or .bashrc
  2. Install Node.js: 
    # Install the latest stable version
nvm install node

# Or install a specific version (e.g., LTS)
nvm install --lts
nvm install 14.7.0 # Or any other desired version
  3. Use a Node.js Version: 
    nvm use node # Use the latest installed version
nvm use 14.7.0 # Switch to a specific version
  4. List Installed Versions: 
    nvm ls

Reinstalling with Homebrew

If you prefer Homebrew:

brew install node

If you encounter linking errors during Homebrew installation, it indicates existing files conflicting with the new installation. You might need to manually remove these conflicting files as identified by Homebrew’s error messages.

  • Troubleshooting Linking Errors: 
    # Example: Remove a conflicting file identified by brew
rm '/usr/local/share/systemtap/tapset/node.stp'
# Then retry linking or installation
brew link --overwrite node

Reinstalling from the Official Node.js Installer Package

You can also download the .pkg installer directly from the official Node.js website . This is a straightforward method that typically handles environment variables and PATH updates automatically.

Managing NPM Packages After Reinstallation

After successfully reinstalling Node.js, you may need to reinstall any globally installed npm packages. If you kept a list of your global packages before uninstalling, you can reinstall them using:

npm install -g <package_name>

If you previously configured your global npm packages to be installed in a specific directory (e.g., ~/.npm-packages), ensure this directory is correctly added to your PATH environment variable.

# Example: Add global npm packages to PATH in .bash_profile or .zshrc
echo 'export PATH="$HOME/.npm-packages/bin:$PATH"' >> ~/.bash_profile
# Or for zsh users:
echo 'export PATH="$HOME/.npm-packages/bin:$PATH"' >> ~/.zshrc
source ~/.bash_profile # or source ~/.zshrc

Why Use NVM?

NVM is invaluable for developers working on multiple projects that might require different Node.js versions. It provides a simple way to switch between these versions, preventing compatibility issues and streamlining your workflow. For instance, one project might depend on an older Node.js version for compatibility, while a new project benefits from the latest features. NVM handles this seamlessly.

FAQs on Node.js Uninstall and Reinstall

Q: How do I check if Node.js is completely uninstalled

ANS: After performing the uninstallation steps, you can verify by opening a new terminal window and running node -v. If Node.js is not found, it should output an error message like -bash: node: command not found. You can also use which node to see if any Node.js executables are still in your system’s PATH.

Q: What is the best method to uninstall Node.js

ANS: The best method often depends on how you initially installed Node.js. If you used Homebrew, brew uninstall node followed by cleanup is usually effective. For manual installations or complex scenarios, a combination of manual file deletion and potentially lsbom can ensure thorough removal. Using NVM for installation and uninstallation is also highly recommended for version management.

Q: Can I uninstall Node.js without using sudo

ANS: Many of the core Node.js files are installed in system directories that require administrator privileges to modify. Therefore, sudo is typically necessary for complete uninstallation. However, if you only installed Node.js in your user directory and not system-wide, you might be able to remove it without sudo.

Q: I uninstalled Node.js but still get errors

ANS: This often indicates that some files or PATH configurations were not removed. Double-check that you’ve followed all the steps for manual cleanup, particularly looking for leftover directories in /usr/local/lib, /usr/local/bin, and your home directory (~/.npm, ~/.node-gyp, etc.). Also, ensure your shell’s PATH variable has been updated.

Q: How do I reinstall Node.js after a clean uninstall

ANS: After ensuring Node.js is fully removed, the recommended approach is to use a version manager like NVM. Install NVM first, then use nvm install node to get the latest version or nvm install <version> for a specific one. Alternatively, you can use brew install node if you prefer Homebrew.

Solutions

Experiencing Node.js issues can be frustrating, but with these methods, you can achieve a clean slate. Always back up important data and proceed with caution when using terminal commands that modify system files.
