“JavaScript Seedable Random Number Generation Alternatives to Math.random”

A recurring necessity in development, particularly for simulations, testing, or game development, is generating random numbers from a known starting point—a seed. The native JavaScript function, Math.random(), inherently lacks this feature. Why is this the case, and what robust alternatives exist?

Is it Possible to Seed Math.random()?

The direct answer is no. The ECMAScript specification intentionally leaves the underlying algorithm for Math.random() implementation-dependent, meaning there is no standardized mechanism to provide it with an initial seed state. Browsers and runtime environments are free to use whatever method they deem appropriate, often favoring cryptographic security over reproducibility.

This limitation necessitates creating custom Pseudorandom Number Generator (PRNG) functions that do accept a seed.

Techniques for Initializing Custom PRNGs

When implementing a custom PRNG, the initial seed state quality is crucial. Sparse or overly simple seeds (like 1 or 2) can result in poor entropy, leading to observable correlations or undesirable patterns in the initial sequence of generated numbers.

To address this, two primary strategies emerge for obtaining a high-quality initial state for your custom generator:

1. Utilizing String Hashing for Seed Generation

Hash functions are excellent tools for transforming short input strings into seemingly random, well-distributed numerical outputs. This resultant hash can then be used to initialize the PRNG state.

The cyrb128 function below generates a 128-bit hash, yielding four 32-bit components perfect for seeding generators requiring multiple state variables, such as sfc32.

/**
 * A 128-bit hash function suitable for generating initial PRNG states from strings.
 * NOTE: Primarily designed for seed generation, not necessarily for robust general-purpose hashing.
 */
function cyrb128(str) {
    let h1 = 1779033703, h2 = 3144134277,
        h3 = 1013904242, h4 = 2773480762;
    for (let i = 0, k; i < str.length; i++) {
        k = str.charCodeAt(i);
        h1 = h2 ^ Math.imul(h1 ^ k, 597399067);
        h2 = h3 ^ Math.imul(h2 ^ k, 2869860233);
        h3 = h4 ^ Math.imul(h3 ^ k, 951274213);
        h4 = h1 ^ Math.imul(h4 ^ k, 2716044179);
    }
    h1 = Math.imul(h3 ^ (h1 >>> 18), 597399067);
    h2 = Math.imul(h4 ^ (h2 >>> 22), 2869860233);
    h3 = Math.imul(h1 ^ (h3 >>> 17), 951274213);
    h4 = Math.imul(h2 ^ (h4 >>> 19), 2716044179);
    return [h1 >>> 0, h2 >>> 0, h3 >>> 0, h4 >>> 0];
}

const stringSeed = "GameLevel_Map_1A";

2. Seed Padding and State Advancement

A simpler approach involves using a base seed (perhaps derived from Date.now()) and padding it with known, well-distributed constants (like transcendental numbers, e.g., digits of $\phi$ or $\pi$, often called “nothing-up-my-sleeve numbers”). After initializing the state, you advance the generator by calling it a set number of times (e.g., 15 to 20 iterations) to thoroughly mix the initial state before using the output for actual randomness.

Solutions

High-Performance Seedable PRNG Implementations

These implementations are designed to be fast, utilizing 32-bit integer arithmetic directly supported by JavaScript’s bitwise operations (| 0 forces 32-bit coercion, which is faster than full float operations). The final division by 4294967296 (which is $2^{32}$) converts the raw 32-bit unsigned integer into a float in the range $[0, 1)$, mimicking Math.random().

sfc32 (Simple Fast Counter)

This generator features a 128-bit state and is noted for its high speed and compliance with the PractRand testing suite.

/**
 * SFC32: Simple Fast Counter PRNG with 128-bit state.
 */
function sfc32(a, b, c, d) {
  return function() {
    a |= 0; b |= 0; c |= 0; d |= 0;
    let t = (a + b | 0) + d | 0;
    d = d + 1 | 0;
    a = b ^ b >>> 9;
    b = c + (c << 3) | 0;
    c = (c << 21 | c >>> 11);
    c = c + t | 0;
    // (t >>> 0) converts to unsigned 32-bit, then normalizes to [0, 1)
    return (t >>> 0) / 4294967296; 
  }
}

// Practical Initialization Example:
const seedGenerator = () => (Math.random() * 2**32) >>> 0;
const sfc32Rand = sfc32(seedGenerator(), seedGenerator(), seedGenerator(), seedGenerator());

console.log("SFC32 Sample:", sfc32Rand());

splitmix32

A very efficient 32-bit state generator derived from the mixing function used in MurmurHash3.

/**
 * SplitMix32 PRNG with 32-bit state.
 */
function splitmix32(a) {
 return function() {
   a |= 0;
   a = a + 0x9e3779b9 | 0; // Add incrementor based on golden ratio
   let t = a ^ a >>> 16;
   t = Math.imul(t, 0x21f0aaad);
   t = t ^ t >>> 15;
   t = Math.imul(t, 0x735a2d97);
   t = t ^ t >>> 15;
   return (t >>> 0) / 4294967296;
  }
}

// Practical Initialization Example:
const initial32BitSeed = (Math.random() * 2**32) >>> 0;
const splitmixRand = splitmix32(initial32BitSeed);

console.log("SplitMix32 Sample:", splitmixRand());

mulberry32

Known for its simplicity and speed, this 32-bit state generator is often suitable for general applications, although it has a potential statistical concern where it may repeat previous numbers after exhausting its $4.3$ billion possibilities (unlike the generators above).

/**
 * Mulberry32 PRNG with simple 32-bit state.
 */
function mulberry32(a) {
  return function() {
    let t = a += 0x6D2B79F5;
    t = Math.imul(t ^ t >>> 15, t | 1);
    t ^= t + Math.imul(t ^ t >>> 7, t | 61);
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  }
}

// Practical Initialization Example:
const mulberryRand = mulberry32((Math.random() * 2**32) >>> 0);

console.log("Mulberry32 Sample:", mulberryRand());

xoshiro128**

Part of the Xorshift family, this is the fastest generator offering a 128-bit state, often used under the hood in various Math.random implementations.

/**
 * xoshiro128** PRNG with 128-bit state.
 */
function xoshiro128ss(a, b, c, d) {
  return function() {
    let t = b << 9, r = b * 5;
    r = (r << 7 | r >>> 25) * 9;
    c ^= a;
    d ^= b;
    b ^= c;
    a ^= d;
    c ^= t;
    d = d << 11 | d >>> 21;
    return (r >>> 0) / 4294967296;
  }
}

// Practical Initialization Example:
const xoshiroRand = xoshiro128ss(seedGenerator(), seedGenerator(), seedGenerator(), seedGenerator());

console.log("Xoshiro128** Sample:", xoshiroRand());

jsf32 (Jenkins’ Small Fast)

Another fast 32-bit generator developed by Bob Jenkins, known to pass PractRand tests.

/**
 * JSF32 (Small Fast) PRNG with 32-bit state.
 */
function jsf32(a, b, c, d) {
  return function() {
    a |= 0; b |= 0; c |= 0; d |= 0;
    let t = a - (b << 27 | b >>> 5) | 0;
    a = b ^ (c << 17 | c >>> 15);
    b = c + d | 0;
    c = d + t | 0;
    d = a + t | 0;
    return (d >>> 0) / 4294967296;
  }
}

const jsf32Rand = jsf32(seedGenerator(), seedGenerator(), seedGenerator(), seedGenerator());

Alternative Seed Implementation Patterns

Several other effective patterns exist for creating reusable, seeded functions:

Using Math.sin with External State (Solution 3/5/22)

A simpler, though potentially less statistically robust method, involves repeatedly using Math.sin() on an evolving seed value. This approach sacrifices raw statistical rigor for brevity and simplicity, though testing (like with PractRand mentioned in the source material) shows that techniques relying heavily on sin() can introduce biases.

A cleaner, functional approach derived from this idea returns the generator function itself:

/**
 * Returns a seedable random function, inspired by Antti Sykäri's approach.
 */
Math.seedFn = function(s) {
    return function() {
        // Note: Using Math.sin might introduce statistical weaknesses compared to dedicated PRNGs.
        s = Math.sin(s) * 10000; 
        return s - Math.floor(s);
    };
};

// Usage for independent, repeatable streams:
var streamA = Math.seedFn(42);
var streamB = Math.seedFn(streamA()); // Seed B based on A's first output
console.log("Stream A output:", streamA());
console.log("Stream B output:", streamB());

Linear Congruential Generator (LCG)

LCGs, rooted in the work of John von Neumann, are classic and fast, especially when avoiding JavaScript’s floating-point limitations:

/**
 * Simple LCG using 32-bit arithmetic constraints.
 */
function lcgRNG(seed) {
    const M_LCG = 2**35 - 31; // Modulus M
    const A_LCG = 185852;     // Multiplier A
    let state = seed % M_LCG;
    
    return function () {
        // State update: s = (s * a) mod m
        state = (state * A_LCG) % M_LCG;
        // Normalize to [0, 1)
        return state / M_LCG;
    }
}

// Overriding Math.random globally (use with caution):
// Math.random = lcgRNG(Date.now());

For higher precision needing 53-bit integers, LCGs must use BigInt, which incurs a significant performance penalty (Solution 6).

Using External Libraries for Advanced Needs

For maximum flexibility, including various statistical distributions (uniform, normal, Poisson, etc.) or adherence to specific established seeds (like Java’s Random), external libraries are the preferred solution:

  1. seedrandom: A highly popular module that patches Math.random globally with a seeded PRNG, often based on an ISAAC variant. See Solution 16 and 18.
  2. ran: Offers numerous distributions alongside seeded core functionality (Solution 11).
  3. java-random: Useful for matching output exactly between Java and JavaScript environments (Solution 17).

For example, using seedrandom to ensure deterministic dataset splitting:

// npm install seedrandom
const seedrandom = require('seedrandom');

const deterministicShuffle = (data, seedValue) => {
  // Overwrites Math.random() temporarily for deterministic sorting
  const rng = seedrandom(seedValue, { global: true });
  
  const shuffled = data.slice().sort(() => 0.5 - rng());
  
  // Restore original Math.random if global overwrite was used (optional cleanup)
  // Note: If using Node.js requires, seedrandom might manage context better.
  
  return shuffled;
};

FAQs on JavaScript Seedable Random Number Generation

Q: Why is Mathrandom considered insufficient for simulations

ANS: Because its output is not reproducible; given the same input conditions, you cannot guarantee the same sequence of ‘random’ numbers unless you control the seed, which Math.random() does not allow.

Q: Are there performance differences between PRNGs

ANS: Yes. Simple LCGs or sine-based methods are often very fast but may lack statistical quality. Generators like sfc32 and splitmix32 balance high speed with better statistical properties by leveraging efficient 32-bit integer operations.

Q: What is the purpose of the | 0 in some function examples

ANS: The | 0 operator coerces the JavaScript number (which is normally a 64-bit float) into a signed 32-bit integer. This signals the JS engine to perform faster bitwise arithmetic operations.

Q: What is a CSPRNG

ANS: A Cryptographically Secure Pseudorandom Number Generator. These are designed specifically to resist prediction, even if previous outputs are known, and should be used for security-sensitive tasks, unlike the general-purpose PRNGs discussed here. ISAAC is mentioned as an example of a seedable CSPRNG.

Q: How do I get a random integer instead of a float

ANS: After getting a float $R$ in $[0, 1)$ from your generator, scale it by the desired maximum value $M$ and truncate: $\lfloor R \times M \rfloor$. If you need an inclusive range $[0, M]$, use $\lfloor R \times (M+1) \rfloor$.
