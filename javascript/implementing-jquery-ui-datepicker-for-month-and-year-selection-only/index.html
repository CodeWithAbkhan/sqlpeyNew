“Implementing jQuery UI Datepicker for Month and Year Selection Only”

How can a developer effectively configure the standard jQuery UI Datepicker widget to allow users to select only the month and year, completely hiding the day selection grid, while ensuring robust functionality across various use cases, including clearing values and maintaining state across multiple instances?

The default jQuery UI Datepicker is designed for date selection. Transforming it into a dedicated Month/Year picker requires specific customizations, often involving CSS manipulation and careful handling of the onClose and beforeShow callbacks. Several tested approaches address this requirement, ranging from simple CSS hacks to custom plugin extensions.

Solution Set: Hiding the Calendar and Setting Month/Year Format

Many accepted solutions focus on hiding the .ui-datepicker-calendar element using CSS while leveraging the showButtonPanel: true, changeMonth: true, and changeYear: true options.

Approach 1: Basic HTML/JS Setup (Hiding Calendar via CSS)

This initial approach sets the desired dateFormat and relies on CSS to suppress the day table.

Key Configuration:

  • dateFormat: 'MM yy' (or similar month/year format).
  • CSS rule: .ui-datepicker-calendar { display: none; }.
  • onClose callback to correctly format the output using the selected month and year values from the control panel.

Example Implementation (Based on Solution 1):

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
<head>
    <script src="http://ajax.googleapis.com/ajax/libs/jquery/1.4.1/jquery.js"></script>
    <script type="text/javascript" src="http://ajax.googleapis.com/ajax/libs/jqueryui/1.7.2/jquery-ui.min.js"></script>
    <link rel="stylesheet" type="text/css" media="screen" href="http://ajax.googleapis.com/ajax/libs/jqueryui/1.7.2/themes/base/jquery-ui.css">
    <style>
    .ui-datepicker-calendar {
        display: none; /* Hides the day selection grid */
    }
    </style>
</head>
<body>
    <label for="startDate">Date (MM YYYY) :</label>
    <input name="startDate" id="startDate" class="date-picker" />

    <script type="text/javascript">
        $(function() {
            $('.date-picker').datepicker( {
                changeMonth: true,
                changeYear: true,
                showButtonPanel: true,
                dateFormat: 'MM yy', // Output format: e.g., "July 2024"
                onClose: function(dateText, inst) { 
                    // Set the date object to the 1st of the selected month/year
                    $(this).datepicker('setDate', new Date(inst.selectedYear, inst.selectedMonth, 1));
                }
            });
        });
    </script>
</body>
</html>

Note on clearing values: A common complaint with basic implementations is the inability to clear the input field after selection. Solutions often involve adding a custom “clear” link or button adjacent to the input field.

Approach 2: Improved Month/Year Value Retrieval and Positioning (Solution 2)

This method refines how the month/year is captured upon closing the picker, explicitly querying the dropdowns within the datepicker overlay, and repositions the picker for better focus alignment.

$(document).ready(function()
{   
    $(".monthPicker").datepicker({
        dateFormat: 'MM yy',
        changeMonth: true,
        changeYear: true,
        showButtonPanel: true,
        
        onClose: function(dateText, inst) {
            // Retrieve selected month index and year directly from the opened panel
            var month = $("#ui-datepicker-div .ui-datepicker-month :selected").val();
            var year = $("#ui-datepicker-div .ui-datepicker-year :selected").val();
            // Format the output using datepicker utility
            $(this).val($.datepicker.formatDate('MM yy', new Date(year, month, 1)));
        }
    });

    $(".monthPicker").focus(function () {
        // Hide calendar and reposition the panel relative to the input element
        $(".ui-datepicker-calendar").hide();
        $("#ui-datepicker-div").position({
            my: "center top",
            at: "center bottom",
            of: $(this)
        });
    });
});

Approach 3: Plugin Extension for Robust Handling (Solution 4)

To avoid repeating boilerplate initialization code, extending jQuery UI by creating a custom plugin function ($.fn.monthYearPicker) offers a reusable pattern. This solution also addresses the need for a “clear” action.

$.fn.monthYearPicker = function(options) {
    options = $.extend({
        dateFormat: "MM yy",
        changeMonth: true,
        changeYear: true,
        showButtonPanel: true,
        showAnim: ""
    }, options);

    function hideDaysFromCalendar() {
        var thisCalendar = $(this);
        $('.ui-datepicker-calendar').detach(); // Detach calendar table
        
        // Fix click event on 'Done' button to use selected values
        $('.ui-datepicker-close').unbind("click").click(function() {
            var month = $("#ui-datepicker-div .ui-datepicker-month :selected").val();
            var year = $("#ui-datepicker-div .ui-datepicker-year :selected").val();
            thisCalendar.datepicker('setDate', new Date(year, month, 1));
            thisCalendar.datepicker("hide"); // Ensure it closes immediately
        });
    }
    
    // Initialize datepicker and attach focus handler
    $(this).datepicker(options).focus(hideDaysFromCalendar);
    
    // Return the jQuery object for chaining
    return this;
}

// Invocation
$('input.monthYearPicker').monthYearPicker();

Approach 4: Context-Specific Class Toggling (Solution 11 & 19)

When multiple datepickers exist on the same page—some needing day selection and others needing only month/year—globally hiding .ui-datepicker-calendar is problematic. A cleaner method is to add a specific class to the datepicker DIV (inst.dpDiv) upon opening and use CSS scoped to that class.

JavaScript Initialization (Solution 11 refined):

$('.date-picker').datepicker({
    dateFormat: 'MM yy',
    changeMonth: true,
    changeYear: true,
    showButtonPanel: true,
    
    beforeShow: function (input, inst) {
        var $this = $(this);
        // Dynamically adjust format for parsing if input value exists
        var dateFormatWithDay = 'd ' + $this.datepicker('option', 'dateFormat');
        
        try {
            // Attempt to parse the existing value by adding a dummy day ('1')
            var date = $.datepicker.parseDate(dateFormatWithDay, '1 ' + $this.val());
            $this.datepicker('option', 'defaultDate', date);
            $this.datepicker('setDate', date);
        } catch (ex) {
            // If parsing fails (e.g., empty field or invalid input), do nothing here
            return;
        }
        
        // Add a unique class to the dialog div for scoped styling
        inst.dpDiv.addClass('datepicker-month-year');
    },
    onClose: function (dateText, inst) {
        // Check if 'Done' button was pressed to avoid unwanted updates on click-away
        var isDonePressed = inst.dpDiv.find('.ui-datepicker-close').hasClass('ui-state-hover');
        if (!isDonePressed) return;

        var month = inst.dpDiv.find('.ui-datepicker-month').find(':selected').val(),
            year = inst.dpDiv.find('.ui-datepicker-year').find(':selected').val();

        $(this).datepicker('setDate', new Date(year, month, 1)).change();
        // Focus out to close the picker smoothly
        $('.date-picker').focusout(); 
    }
});

Scoped CSS:

.datepicker-month-year .ui-datepicker-calendar {
    display: none;
}

Approach 5: Utilizing Alternative Plugins or HTML5 Input (External References)

If deep modification of jQuery UI source code (as detailed in Solution 16) seems too invasive, relying on specialized plugins or native HTML5 features is a viable alternative:

  1. HTML5 <input type="month">: For modern browsers, this is the simplest way to get a month/year selector, though styling and cross-browser consistency can be challenging. 
    <input type="month" name="your_field_name" />
  2. Dedicated Plugins: Libraries like jquery.ui.monthpicker (referenced in Solution 17) or others designed specifically for this purpose often provide cleaner integration without source code patches.

FAQs on jQuery UI Datepicker Month Year Implementation

Q: Why does the calendar grid still flash briefly when using CSS to hide it

ANS: This often happens because the datepicker HTML is generated first, then hidden by CSS. Techniques like using setTimeout in the onClose callback (Solution 17) or using custom positioning methods (.focus() handler in Solution 4) help mitigate this visual artifact by ensuring the element is detached or hidden before the fade-out sequence completes.

Q: How do I ensure the date is set correctly when using the month/year panel

ANS: Rely on the onClose callback. Use inst.selectedYear and inst.selectedMonth from the instance object to construct a new Date object, usually setting the day to 1, and then use $(this).datepicker('setDate', new Date(year, month, 1));.

Q: Can I use month picker and standard date picker on the same page

ANS: Yes, if you scope the CSS hiding rule. By adding a unique class to the datepicker dialog wrapper (e.g., .datepicker-month-year) during beforeShow (Solution 11), you can selectively hide the calendar table only for the month/year pickers, leaving standard date pickers unaffected.

Q: What is the benefit of the plugin extension approach over simple initialization

ANS: The plugin extension (Solution 4) centralizes initialization logic, allows easy addition of features like a dedicated ‘clear’ button, and ensures consistent behavior across all elements targeted by that specific month/year picker implementation.
