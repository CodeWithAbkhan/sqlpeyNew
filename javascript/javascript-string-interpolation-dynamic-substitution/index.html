“JavaScript String Interpolation Without New Function or Eval”

How can one perform variable interpolation within a plain JavaScript string that uses ${variable} syntax, mimicking template literals, especially when seeking alternatives to the security risks associated with eval or the dynamic code generation of new Function()? The core challenge arises when the variables need to be accessed dynamically from a passed object context, which standard template literals handle implicitly by being evaluated in their lexical scope.

The consensus across several approaches suggests that achieving true dynamic evaluation—where the expression inside ${...} references variables outside the substitution mechanism’s immediate scope (like accessing caller’s local variables)—necessitates dynamic code execution, similar in power to eval. However, several methods exist to safely substitute known properties from a provided data map.

Techniques for Dynamic Template String Replacement

Here are various methods proposed to substitute values into strings containing placeholder syntax like ${key}:

1. ES6 String.prototype.interpolate using new Function (Dynamic Scope Injection)

This method creates a new function dynamically, using the keys from the parameter object as formal arguments, which are then used within a backtick-enclosed template string. This allows referencing variables passed in the object directly by name.

String.prototype.interpolate = function(params) {
  const names = Object.keys(params);
  const vals = Object.values(params);
  // Creates a function like: new Function('text', 'return `Example text: ${text}`;')
  return new Function(...names, `return \`${this}\`;`)(...vals);
}

const templateStringES6 = 'Example text: ${text} and a computed value: ${1 + 1}';
const resultES6 = templateStringES6.interpolate({
  text: 'Foo Boo'
});
console.log(resultES6); // Output: Example text: Foo Boo and a computed value: 2

Alternative Perspective: If runtime reference to local variables outside the parameters object is required (e.g., accessing a variable b defined in the outer scope, as shown in some original inquiries), this approach, or one relying on eval, is often necessary.

// Example using Function constructor to access outer scope variables if explicitly named
const outerVar = 42;
const msg = "The answer is ${outerVar}.";
// Note: This relies on 'outerVar' being accessible in the scope where the constructed function is called, or by being passed in.
console.log(new Function('outerVar', `return \`${msg}\`;`)(outerVar));

2. Using eval for Direct Template String Execution

The most direct, but least secure, path to evaluate backticks (\``) containing expressions that reference surrounding scope variables is eval`.

let dynamicString = 'b:${b}';
let b = 10; // Variable accessible in the scope
let tplEval = eval('`' + dynamicString + '`');
console.log(tplEval); // Output: b:10

Caution: Using eval is strongly discouraged in production code due to security vulnerabilities if the template string originates from untrusted sources.

3. Pre-compiling Template Function with Caching (The “King Maker” Pattern)

To improve performance for frequently used templates, one can convert the string into a specialized function that expects a map of variables. This is safer than eval as it only looks for defined properties on the map argument. A cache ensures the function is generated only once per unique template string.

The improvement over the original gist ensures the generated function is stored in the cache:

/**
 * Produces a function which uses template strings for simple interpolation from objects, with caching.
 */
var generateTemplateStringCached = (function(){
    var cache = {};

    function generateTemplate(template){
        var fn = cache[template];

        if (!fn){
            // Sanitize placeholders to reference 'map.<property>'
            var sanitized = template
                .replace(/\$\{([\s]*[^;\s\{]+[\s]*)\}/g, function(_, match){
                    return `\$\{map.${match.trim()}\}`;
                })
                // Remove malformed or unmapped placeholders
                .replace(/(\$\{(?!map\.)[^}]+\})/g, '');

            // Cache the resulting function
            fn = cache[template] = Function('map', `return \`${sanitized}\``);
        }

        return fn;
    }

    return generateTemplate;
})();

var kingMaker = generateTemplateStringCached('${name} is now the king of ${country}!');
console.log(kingMaker({ name: 'Bryan', country: 'Scotland'}));
// Logs: Bryan is now the king of Scotland!

4. Simple Regex Replacement (Safest for Property Mapping)

For substitution where only direct properties of a context object are needed (no complex expressions inside ${}), iterative replacement using regular expressions is the safest and most compatible approach.

A. Iterative String.prototype.replace (Solution 11 Adaptation)

This method iterates over the known keys in the parameters object and performs a global search-and-replace for each specific placeholder.

String.prototype.interpolateRegex = function(params) {
  let template = this.toString();
  for (let key in params) {
    // Creates a RegExp like /\$\{text\}/g
    const placeholderRegex = new RegExp(`\\$\\{${key}\\}`, 'g');
    template = template.replace(placeholderRegex, params[key]);
  }
  return template;
}

const simpleTemplate = 'Hello, ${name}! Today is ${dayOfWeek}.';
const valuesSimple = { name: "John Doe", dayOfWeek: "Tuesday" };

console.log(simpleTemplate.interpolateRegex(valuesSimple));
// Output: Hello, John Doe! Today is Tuesday.

B. Single Pass Regex with Property Path Traversal (Solution 9 Adaptation)

A more sophisticated regex approach can find all ${...} patterns in one go and use a helper function to look up nested properties from the context object.

const interpolatePath = (template, variables, fallback = '') => {
    // Regex captures content between ${ and } non-greedily
    const regex = /\${[^{]+}/g; 

    // Helper to safely traverse nested object paths (e.g., 'user.address.city')
    const getObjPath = (path, obj, fb) => {
        return path.split('.').reduce((res, key) => {
            // If res becomes undefined or null, use fallback
            const next = res ? res[key] : undefined;
            return next !== undefined ? next : fb;
        }, obj);
    };

    return template.replace(regex, (match) => {
        const path = match.slice(2, -1).trim(); // Remove ${ and }
        const result = getObjPath(path, variables, fallback);
        // If fallback was used, return the original placeholder, otherwise the value
        return result !== fallback ? result : match; 
    });
};

const complexTemplate = 'User: ${user.name}, City: ${user.address.city}, Status: ${status}';
const contextData = {
    user: { name: 'Alice', address: { city: 'Metropolis' } }
};

console.log(interpolatePath(complexTemplate, contextData, '[MISSING]'));
// Output: User: Alice, City: Metropolis, Status: [MISSING]

5. Using String.raw with Parts and Parameters (Solution 5 Adaptation)

This approach leverages String.raw by splitting the template into textual segments and extracting the placeholder names separately, then passing them as spread arguments.

function parseStringTemplateES6(str, obj) {
    // 1. Split by placeholders, capturing text segments (e.g., ["Hello, ", "! Are you ", " years old?"])
    let parts = str.split(/\$\{(?!\d)[\wæøåÆØÅ]*\}/);
    
    // 2. Extract property names from placeholders (e.g., ["name", "age"])
    let args = str.match(/[^{\}]+(?=})/g) || [];
    
    // 3. Map property names to their values from the object
    let parameters = args.map(argument => obj[argument] ?? ""); // Use nullish coalescing for undefined checks
    
    // 4. Use String.raw to reconstruct the string
    return String.raw({ raw: parts }, ...parameters);
}

let templateRaw = "Greeting: ${greeting}! Item count: ${count}.";
let valuesRaw = { greeting: "Salutations", count: 5 };

console.log(parseStringTemplateES6(templateRaw, valuesRaw));
// Output: Greeting: Salutations! Item count: 5.

6. Node.js vm Module for Controlled Execution (Server-Side Only)

On the server side (Node.js), the vm module allows running code in a sandboxed context, providing better isolation than raw eval. You execute the template string within backticks in a new context, explicitly passing in the context data and helper functions.

const vm = require('vm');

let serverTemplate = 'Hours worked: ${context.hours}. Average difference: ${Math.abs(context.diff)}%';
let serverContext = {
  hours: 10,
  diff: -2.5
};

function templateItServer(contextData, templateStr) {
  const script = new vm.Script('`' + templateStr + '`');
  // Provide context and helpers explicitly to the sandbox
  return script.runInNewContext({ context: contextData });
}

console.log(templateItServer(serverContext, serverTemplate));
// Output: Hours worked: 10. Average difference: 2.5%

FAQs on JavaScript String Interpolation Dynamic Substitution

Q: Why is dynamic evaluation unsafe in JavaScript

ANS: Methods like eval() execute arbitrary strings as code in the current scope, allowing malicious input strings to read local variables, perform network requests, or alter the program state uncontrollably.

Q: Can template literals access local variables directly

ANS: Yes, template literals (strings using backticks ) evaluate expressions inside `${}` within their originating lexical scope at runtime, which is why solutions involving `new Function('return \`...\ work.

Q: Which method avoids both eval and new Function

ANS: Solutions relying purely on String.prototype.replace with carefully constructed regular expressions (like Solution 4A and 4B) avoid dynamic code execution entirely, making them the most secure for property substitution.

Q: Do template literals work in older browsers like IE11

ANS: No, template literals (backticks and ${}) are ES6 features. For IE11 compatibility, approaches using standard replace methods or older Function constructor syntax (Solution 17) are required.

Q: Can I use template literals without a dynamic function call

ANS: If you only need basic string interpolation where variables are known at the time of writing the code, you use backticks directly: `Value is ${myVar}`. Dynamic substitution is needed when the template string itself is loaded dynamically.
