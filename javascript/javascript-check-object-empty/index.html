“JavaScript: How to Check if an Object is Empty?”

When working with JavaScript, a common task is to determine if an object contains any properties. This might seem straightforward, but there are several nuances to consider, including performance, browser compatibility, and what precisely constitutes an “empty” object. This post delves into various approaches to efficiently check if a JavaScript object is empty.

Solution 1: Using Object.hasOwn (ECMAScript 2022+)

A modern and robust method involves using a for...in loop combined with Object.hasOwn. This approach iterates through the object’s properties and returns false as soon as the first own property is found.

function isEmpty(obj) {
  for (const prop in obj) {
    if (Object.hasOwn(obj, prop)) {
      return false; // Found an own property, so not empty
    }
  }
  return true; // No own properties found, so empty
}

For scenarios where you need to differentiate between truly empty objects (like {}) and other objects that might not have own properties but have a different prototype (e.g., Object.create(null) or instances of custom classes), you can add type checks:

function isEmptyObject(value) {
  // Handle null or undefined values
  if (value == null) {
    return false;
  }

  // Ensure it's an object and not a primitive type
  if (typeof value !== 'object') {
    return false;
  }

  const proto = Object.getPrototypeOf(value);

  // Consider objects created with Object.create(null) or other prototypes
  if (proto !== null && proto !== Object.prototype) {
    return false;
  }

  return isEmpty(value); // Reuse the isEmpty function
}

Important Note: Avoid using Object.keys(obj).length. This method creates an intermediate array of property names, which can be less efficient (O(N)) compared to iterating directly (O(1)).

Solution 2: For Older JavaScript Environments (Pre-ECMAScript 2022)

If you need to support older JavaScript environments that might not have Object.hasOwn, you can use Object.prototype.hasOwnProperty.call():

function isEmpty(obj) {
  for (var prop in obj) {
    if (Object.prototype.hasOwnProperty.call(obj, prop)) {
      return false; // Found an own property
    }
  }
  return true; // No own properties found
}

Solution 3: Using Object.keys() (ECMAScript 5+)

A commonly used method for environments supporting ECMAScript 5 and later is Object.keys(). This returns an array of an object’s own enumerable property names. If the array’s length is zero, the object is considered empty.

function isEmpty(obj) {
    return Object.keys(obj).length === 0;
}

Solution 4: Using Object.entries() or Object.values()

Similar to Object.keys(), Object.entries() and Object.values() (both introduced in ECMAScript 2017) also return arrays. Checking the .length property of these arrays can also indicate an empty object.

// Using Object.entries()
function isEmptyEntries(obj) {
    return Object.entries(obj).length === 0;
}

// Using Object.values()
function isEmptyValues(obj) {
    return Object.values(obj).length === 0;
}

Solution 5: Using JSON.stringify()

This method converts the object to a JSON string and checks if it matches '{}'. While broadly compatible, it can be less performant and has a significant caveat.

function isEmptyObject(obj){
    return JSON.stringify(obj) === '{}';
}

Caveat: JSON.stringify() will not correctly identify objects with functions or undefined properties as non-empty, as these are omitted from the stringified output. For example, { a: undefined } would be stringified to {}.

Solution 6: Using Library Functions

Many popular JavaScript libraries provide utility functions for this purpose:

  • jQuery: jQuery.isEmptyObject(obj)
  • Lodash/Underscore: _.isEmpty(obj)

These functions abstract away the implementation details and often offer robust handling for various edge cases.

// Example with jQuery
// Ensure jQuery is loaded before this code
// $.isEmptyObject({}); // true
// $.isEmptyObject({ foo: "bar" }); // false

// Example with Lodash
// Ensure Lodash is loaded before this code
// _.isEmpty({}); // true
// _.isEmpty({ foo: "bar" }); // false

Solution 7: Checking Own Property Names and Symbols

For a more precise check that excludes inherited properties and considers symbols, you can combine Object.getOwnPropertyNames() and Object.getOwnPropertySymbols(). An object is considered truly empty if it has no own properties (enumerable or non-enumerable) and no own symbols.

function isTrulyEmpty(obj) {
  return (
    Object.getOwnPropertyNames(obj).length === 0 &&
    Object.getOwnPropertySymbols(obj).length === 0 &&
    Object.getPrototypeOf(obj) === Object.prototype // Ensure it's a plain object
  );
}

Performance Considerations

Performance tests often indicate that methods utilizing a for...in loop (especially with hasOwnProperty or Object.hasOwn) tend to be the fastest across different JavaScript engines. JSON.stringify() is generally the slowest. Object.keys() and its counterparts (.entries(), .values()) offer a good balance of readability and performance.

FAQs on JavaScript Object Empty Check

Q: What is the most performant way to check if a JavaScript object is empty

ANS: Generally, using a for...in loop with Object.hasOwn (or hasOwnProperty.call for older environments) is the most performant method as it stops iteration as soon as the first own property is found.

Q: Can I use Object keys to check if an object is empty

ANS: Yes, Object.keys(obj).length === 0 is a common and readable way to check if an object is empty, provided you are targeting environments that support ECMAScript 5 or later.

Q: Does JSON stringify work for checking empty objects

ANS: JSON.stringify(obj) === '{}' can work for simple objects, but it’s not reliable for objects containing functions or undefined values, as these are omitted during stringification, potentially leading to false positives.

Q: How do libraries like jQuery or Lodash help with checking empty objects

ANS: Libraries like jQuery ($.isEmptyObject) and Lodash (_.isEmpty) provide convenient, well-tested utility functions that abstract away the implementation details and often handle edge cases robustly.

Q: What's the difference between checking for own properties vs. all properties

ANS: Checking for “own properties” (using hasOwnProperty or Object.hasOwn) ensures you’re only considering properties directly defined on the object, excluding those inherited from its prototype chain. A for...in loop without hasOwnProperty iterates over all enumerable properties, including inherited ones.

  // before `Map` support, an empty object as well as `{}`
  if (proto !== null &amp;&amp; proto !== Object.prototype) {
    return false;
  }

  return isEmpty(value);
}
