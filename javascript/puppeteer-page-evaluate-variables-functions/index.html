“Puppeteer page.evaluate passing variables and functions”

When working with Puppeteer for browser automation, page.evaluate() is a crucial method for executing JavaScript within the context of a browser page. However, passing data or executable code from your Node.js environment to the browser’s isolated JavaScript world can be a point of confusion. This post explores various methods and best practices for passing variables and functions to page.evaluate.

Passing Variables

The primary mechanism for passing variables into page.evaluate is by providing them as arguments to the page.evaluate call itself. These arguments are then accessible within the function executed by page.evaluate.

Solution 1: Direct Argument Passing

This is the most straightforward approach. You pass the variable as a second argument (or subsequent arguments) to page.evaluate.

const Puppeteer = require('puppeteer');

(async () => {
  const browser = await Puppeteer.launch();
  const page = await browser.newPage();
  await page.goto('about:blank'); // Navigate to a blank page for demonstration

  const evalVar = 'Hello from Node.js!'; // Variable from Node.js environment

  const result = await page.evaluate((evalVar) => {
    console.log(evalVar); // This will log 'Hello from Node.js!' in the browser console
    return `Received: ${evalVar}`;
  }, evalVar); // Pass evalVar as an argument

  console.log(`Result from page.evaluate: ${result}`);

  await browser.close();
})();

When passing multiple variables, you can continue to list them as arguments.

await page.evaluate((a, b, c) => {
  console.log(a, b, c); // Logs the values of a, b, and c
}, variableA, variableB, variableC);

Important Note on Serialization: Arguments passed to page.evaluate must be serializable as JSON or be JSHandles of in-browser objects. For detailed information on this, refer to the Puppeteer API documentation for page.evaluate .

Solution 2: Destructuring Object for Readability

For improved readability, especially when passing multiple variables, you can bundle them into an object and use destructuring within the page.evaluate function.

const Puppeteer = require('puppeteer');

(async () => {
  const browser = await Puppeteer.launch();
  const page = await browser.newPage();
  await page.goto('about:blank');

  const userData = {
    name: 'Alice',
    age: 25,
    location: 'Wonderland'
  };

  await page.evaluate((data) => {
    const { name, age, location } = data; // Destructure the passed object
    console.log(`Name: ${name}, Age: ${age}, Location: ${location}`);
    return `User ${name} processed.`;
  }, userData); // Pass the userData object

  await browser.close();
})();

Solution 3: Concise Variable Passing

This solution reiterates the simplicity of passing single or multiple variables.

  • Single Variable:

    await page.evaluate(singleVar => {
  console.log(singleVar);
}, mySingleVariable);

    Note that parentheses around singleVar are not required here.

  • Multiple Variables:

    await page.evaluate((var1, var2) => {
  console.log(var1, var2);
}, myVariable1, myVariable2);

    Enclosing variables in {} for multiple arguments is unnecessary.

Understanding console.log within page.evaluate

A common pitfall is expecting console.log statements within page.evaluate to appear in your Node.js terminal. This is because the code runs in the browser’s context, not Node.js.

Solution 4: Console Output Location

// Code executed within page.evaluate runs in the browser.
// console.log(someValue); // This logs to the browser's developer console.

If you are running Puppeteer in headless mode, you won’t see this output directly. To debug, you can:

  • Launch Puppeteer with devtools: true to open the browser’s devtools.
  • Capture console messages using page.on('console', msg => console.log(...msg.args())).

For more on debugging Puppeteer, see this guide .

Passing Functions

Passing functions requires a slightly different approach, as functions themselves are not directly serializable.

Solution 5: Executing Functions within the Browser Context

There are two main strategies for executing functions:

  1. Define the function within the evaluation context: You can define the function directly on the window object within page.evaluate. Then, call it in another page.evaluate call.

    // First, define the function in the browser's scope
await page.evaluate(() => {
  window.browserSideFunction = function(message) {
    console.log(`Browser says: ${message}`);
  };
});

// Then, call the function from another page.evaluate
const callResult = await page.evaluate(() => {
  const func = window.browserSideFunction;
  func('Hello from Node.js, called from browser!');
  return 'Function executed.';
});
console.log(callResult);

  2. Transform the function to a serializable string: You can convert the function to its string representation and then parse it back into a function in the browser context.

    const Puppeteer = require('puppeteer');

(async () => {
  const browser = await Puppeteer.launch();
  const page = await browser.newPage();
  await page.goto('about:blank');

  const nodeJsFunction = function(arg1, arg2) {
    console.log('Node.js function logic executed in browser.');
    console.log('Arg1:', arg1);
    console.log('Arg2:', arg2);
    return `Processed ${arg1} and ${arg2}`;
  };

  const contextData = {
    arg1: 'data1',
    arg2: 123
  };

  const result = await page.evaluate((funcString, data) => {
    // Recreate the function from its string representation
    const browserFunc = new Function(`return ${funcString}.apply(null, arguments)`);
    // Call the recreated function with arguments
    return browserFunc(data.arg1, data.arg2);
  }, nodeJsFunction.toString(), contextData); // Pass function string and context data

  console.log(`Result: ${result}`);

  await browser.close();
})();

    This method allows for more complex function logic to be passed. The use of apply(null, arguments) ensures that arguments passed to the new Function constructor are correctly forwarded to the original function.

Solution 6: TypeScript Example for Function Passing

For TypeScript users, the approach is similar, emphasizing type safety.

// In your TypeScript file
const myFunction = async (url: string, regex: RegExp, querySelector: string): Promise<string[]> => {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  // ... navigate and perform actions ...

  const elements = await page.evaluate(
    (url: string, regex: RegExp, querySelector: string) => {
      // Browser-side logic here, e.g., extracting data
      const elementTexts: string[] = [];
      document.querySelectorAll(querySelector).forEach((el: Element) => {
        const text = el.textContent;
        if (text && regex.test(text)) {
          elementTexts.push(text);
        }
      });
      return elementTexts;
    },
    url,
    regex,
    querySelector
  );
  console.log(elements);
  await browser.close();
  return elements;
};

Solution 7: Reusable Utility Functions

For more advanced scenarios, you can pass utility functions to page.evaluate by serializing them as strings and then reconstructing them within the browser context. This promotes code reusability.

// Utility functions defined in your Node.js environment
const pipe = (...fns) => initialVal => fns.reduce((acc, fn) => fn(acc), initialVal);
const pluck = key => obj => obj[key] || null;
const map = fn => item => fn(item);

// Inside your async Puppeteer logic
const elementSelector = '#some-element';
const utilFunctions = {
  pipe: pipe.toString(),
  pluck: pluck.toString(),
  map: map.toString()
};

const processedValue = await page.evaluate(
  ([selector, utils]) => {
    // Reconstruct utilities in the browser context
    const { pipe, map, pluck } = utils;
    const pipeFn = new Function(`return ${pipe}`)();
    const mapFn = new Function(`return ${map}`)();
    const pluckFn = new Function(`return ${pluck}`)();

    // Use the reconstructed utilities
    return pipeFn(
      s => document.querySelector(s),
      pluck('textContent'),
      map(text => text.trim()),
      map(date => Date.parse(date))
    )(selector);
  },
  [elementSelector, utilFunctions]
);

console.log('Processed value:', processedValue);

Important Consideration for Utility Functions: When using functions within pipe, ensure they are structured correctly for the context. For instance, pipe(document.querySelector) won’t work directly; it needs to be pipe(s => document.querySelector(s)).

FAQs on Puppeteer page evaluate passing variables and functions

Q: How do I log output from page evaluate to the Node console

ANS: You cannot directly log to the Node.js console from within page.evaluate as the code runs in the browser’s isolated context. To capture or view this output, you should use page.on('console', msg => console.log(...msg.args())) or launch Puppeteer with devtools: true.

Q: Can I pass any JavaScript variable to page evaluate

ANS: Not all JavaScript variables can be passed directly. They must be serializable as JSON (e.g., strings, numbers, booleans, arrays, plain objects) or be JSHandles. Functions require special handling as shown in the solutions above.

Q: Is it better to pass variables individually or as an object

ANS: Passing variables individually is simpler for one or two items. For multiple variables, passing them as a single object and using destructuring within page.evaluate enhances code readability and organization.

Q: How do I execute a Node.js function in the browser context

ANS: You can achieve this by converting the Node.js function to its string representation (function.toString()) and then creating a new function from this string within the page.evaluate context using new Function().

Q: What are JSHandles in Puppeteer

ANS: JSHandles are objects that represent an object or primitive value in the browser context. They can be passed to and from page.evaluate and allow interaction with browser-side objects.
