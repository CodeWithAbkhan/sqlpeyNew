“Execute Multiple NPM Scripts Concurrently: Best Cross-Platform Techniques”

Running multiple background processes concurrently from a single NPM script definition in package.json presents a common challenge, especially when maintaining cross-platform compatibility (Windows vs. Unix-like shells). Several effective solutions emerge, ranging from dedicated packages to leveraging shell-specific features.

Utilizing Dedicated NPM Packages for Parallel Execution

Third-party modules offer robust, often cross-platform, ways to manage concurrent scripts, giving fine-grained control over startup and termination.

1. Employing concurrently

The concurrently package is a popular choice for running multiple commands in parallel while aggregating their output streams, often prefixing lines for clarity.

To implement this:

  1. Installation: Install concurrently as a development dependency.

    npm install concurrently --save-dev

  2. Configuration Example: Define the development task to run both start-watch and wp-server. Using the npm: prefix allows concurrently to reference existing package scripts directly.

    "scripts": {
    "start-watch": "nodemon run-babel index.js",
    "wp-server": "webpack-dev-server",
    "dev": "concurrently \"npm:start-watch\" \"npm:wp-server\""
}

    A slightly more verbose alternative that ensures clear output attribution uses quoted commands:

    "dev": "concurrently \"npm run start-watch\" \"npm run wp-server\""

    Another example demonstrating wildcard usage:

    "scripts": {
    "start:build": "tsc -w",
    "start:run": "nodemon build/index.js",
    "start": "concurrently  npm:start:*"
}

2. Leveraging npm-run-all

npm-run-all provides similar parallel execution capabilities and offers useful flags for managing process lifecycles.

  1. Installation:

    npm install npm-run-all --save-dev

  2. Parallel Execution (--parallel or -p):

    "scripts": {
    "dev": "npm-run-all --parallel start-watch wp-server"
}

    If installed globally (npm i -g npm-run-all), you could also run:

    npm-run-all --parallel server watch

    where "server": "live-server index.html" and "watch": "node-sass scss/style.scss --watch".

  3. Race Mode (-r or --race): A significant advantage of npm-run-all is the ability to terminate all tasks immediately when one task exits successfully (exit code zero). This is invaluable when one process (like a build watcher) finishes, and you need the parallel processes (like a server) to shut down.

    "scripts": {
    "test:static-server": "cross-env NODE_ENV=test node server/testsServer.js",
    "test:jest": "cross-env NODE_ENV=test jest",
    "test": "run-p -r test:static-server \"test:jest -- {*}\" --",
    "test:coverage": "npm run test -- --coverage",
    "test:watch": "npm run test -- --watchAll"
}

    Note: run-p is a shortcut for npm-run-all --parallel.

Native Shell Solutions (Less Portable)

These methods rely on specific shell syntax, making them less reliable across Windows and Unix-like environments unless carefully structured.

3. Unix-like Shell Forking (&)

In Bash or Zsh, the ampersand (&) forks a command into the background, allowing the next command to start immediately.

"scripts": {
    "dev": "npm run start-watch & npm run wp-server"
}

Caveat: This approach often lacks good cleanup control; processes might persist after the primary command terminates, unlike package-based solutions.

For Unix-like systems, if you need to track the background process ID (PID) for later termination:

"scripts": {
    "bundle": "watchify -vd -p browserify-hmr index.js -o bundle.js",
    "serve":  "http-server -c 1 -a localhost",
    "serve-bundle": "npm run bundle & echo \"$!\" > build/bundle.pid && npm run serve & echo \"$!\" > build/serve.pid & npm run open-browser"
}

Here, $! retrieves the PID of the most recently executed background command.

4. Windows CMD Specific Usage (start)

The Windows Command Prompt requires the start command to launch processes concurrently in separate windows.

"dev": "start npm run start-watch && start npm run wp-server"

If you wish to launch them non-blocking in the same window context where possible, use /b:

"dev": "start /b npm run bg-task1 && start /b npm run bg-task2 && npm run main-task"

5. Hybrid Cross-Platform Shell Command

A method exists to attempt compatibility by grouping commands separated by the shell OR operator (||), where the first group is for Windows CMD and the second for Bash:

"scripts": {
    "start-watch": "nodemon run-babel index.js",
    "wp-server": "webpack-dev-server",
    // CMD first group (using 'start' and '&&'), Bash second group (using '&' and '&&')
    "dev": "(start npm run start-watch && start npm run wp-server) || (npm run start-watch & npm run wp-server)",
    "start": "npm run dev"
}

Node.js Native Approach (Forking)

For complete control and zero external dependencies (beyond Node.js itself), you can write a small wrapper script utilizing the child_process module to fork processes. This is inherently cross-platform.

Example fork-runner.js:

const { fork } = require('child_process');

const scriptsToRun = [
    'some-script.js', 
    'some-other-script.js'
];

const runningProcesses = [];

scriptsToRun.forEach(scriptPath => {
    // Forking executes the script in a new Node.js instance
    const child = fork(scriptPath); 

    // Optional: Wire up stdout/stderr streams for visibility
    child.stdout.on('data', (data) => console.log(`[${scriptPath}]: ${data}`));
    child.stderr.on('data', (data) => console.error(`[${scriptPath} ERROR]: ${data}`));
    
    child.on('close', (code) => {
        console.log(`Process ${scriptPath} exited with code ${code}`);
    });

    runningProcesses.push(child);
});

// Example: Logic to kill all children after a period or specific event
// setTimeout(() => {
//     runningProcesses.forEach(p => p.kill());
// }, 10000);

To run this, you would set your package script: "dev": "node fork-runner.js".

Alternative Context Management

Using pre and post Hooks

You can chain scripts using lifecycle hooks. If you run npm run dev, predev executes first, then dev. Using & in predev can start the watcher, and dev can run the server.

"scripts": {
    "predev": "nodemon run-babel index.js &", // Starts watcher in background
    "dev": "webpack-dev-server" // Runs server
}

Project Structure Execution (--prefix)

If you have separate repositories for a client and API, you can invoke scripts from different package roots:

"dev": "npm run --prefix react start & npm run --prefix express start"

This uses the shell’s native backgrounding (&) but scopes the execution context using npm --prefix.

FAQs on Execute Multiple NPM Scripts Concurrently

Q: Which method is best for combining a watcher and a server script

ANS: The concurrently package or npm-run-all --parallel are generally recommended for development workflows because they centralize output streams and offer superior control over process termination compared to raw shell operators like &.

Q: How do I stop all parallel npm processes easily

ANS: Packages like npm-run-all support the -r or --race flag, which automatically terminates all parallel tasks when one finishes successfully (exit code 0).

Q: Can I run scripts in different subdirectories using NPM

ANS: Yes, you can use npm run --prefix <path/to/package> <script-name> to execute scripts defined within sub-project package.json files, often combined with shell operators like &.

Q: Is using '&' in package.json scripts always reliable

ANS: No, using & is effective in Unix-like shells but fails or behaves unexpectedly on standard Windows command prompts unless explicitly handled by the start command or a dedicated module.
