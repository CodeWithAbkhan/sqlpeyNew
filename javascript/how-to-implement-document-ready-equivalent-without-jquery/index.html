Have you ever wanted to replace jQuery’s $(document).ready without compromising functionality?

If you’re like many developers, you may have found yourself in a scenario where your script utilizes $(document).ready, but you don’t require any other functionality that jQuery provides. Removing jQuery from your project not only reduces file size but also enhances performance. But how can you implement your own document ready functionality without resorting to jQuery’s heavyweight library?

Exploring the Alternatives

While window.onload waits for all elements, including images and frames, to load, there’s an efficient way to ensure your script runs as soon as the DOM is fully constructed. Below, we’ll explore a few options that serve as standards-compliant alternatives to jQuery’s $(document).ready.

Solution 1: Using DOMContentLoaded

The most straightforward solution involves utilizing the DOMContentLoaded event. This event is triggered when the HTML document has been completely loaded and parsed, allowing scripts to run as soon as the DOM becomes available.

Here’s how you can set it up:

document.addEventListener("DOMContentLoaded", function(event) { 
    // Your code here
    console.log("DOM fully loaded and parsed");
});

This method is widely supported across modern browsers, including this compatibility table .

Solution 2: A Comprehensive Ready Function

Another effective way involves creating a reusable ready function, which can handle different scenarios including older versions of Internet Explorer that may not support DOMContentLoaded. Below is an implementation that covers these cases:

function ready(fn) {
    // Handle the scenario where the document is already ready
    if (document.readyState !== 'loading') {
        fn();
        return;
    }
    document.addEventListener('DOMContentLoaded', fn);
}

// Usage
ready(function() {
    console.log("DOM is ready!");
});

An Abbreviated One-Liner

For a more concise approach, you can use the following one-liner, which employs ES6 arrow function syntax:

const ready = fn => document.readyState !== 'loading' ? fn() : document.addEventListener('DOMContentLoaded', fn);

// Example usage
ready(() => {
    console.log("Hello world!");
});

Another Viable Approach

You might also consider implementing the following functional pattern, ensuring maximum compatibility with IE and other browsers:

function customReady(callback){
    if (document.readyState !== 'loading') {
        callback();
    } else if (document.addEventListener) {
        document.addEventListener('DOMContentLoaded', callback);
    } else {
        document.attachEvent('onreadystatechange', function() {
            if (document.readyState === 'complete') callback();
        });
    }
}

customReady(function(){
    alert('It works!');
});

This version ensures that your function runs both in modern browsers and in older Internet Explorer versions by employing attachEvent.

Practical Example

Here’s how you can use a ready function to ensure your scripts only run when the DOM is fully ready:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Document Ready Example</title>
    <script>
        function customReady(callback) {
            if (document.readyState !== 'loading') {
                callback();
            } else if (document.addEventListener) {
                document.addEventListener('DOMContentLoaded', callback);
            } else {
                document.attachEvent('onreadystatechange', function() {
                    if (document.readyState === 'complete') callback();
                });
            }
        }

        customReady(function(){
            console.log('DOM is ready to be manipulated!');
        });
    </script>
</head>
<body>
    <div>Hello, World!</div>
</body>
</html>

This HTML example demonstrates how you can structure your scripts using the customReady function, thus avoiding jQuery altogether.

FAQs on How to Implement Document Ready Equivalent Without jQuery

Q: What is the main difference between `DOMContentLoaded` and `window.onload`?

A: The DOMContentLoaded event fires as soon as the DOM is ready, while window.onload waits for all content, including images, to fully load.

Q: What browsers support `DOMContentLoaded`?

A: The DOMContentLoaded event is supported in all modern browsers. However, it is not supported in IE8 and earlier versions.

Q: Can I use these methods in my existing projects?

A: Yes, these methods can be integrated into your existing JavaScript projects to replace jQuery’s loading functionality and reduce dependencies.
