“JavaScript Techniques for Submitting Multiple Forms Concurrently”

How can a web developer reliably trigger the submission of two distinct HTML forms using a single user interaction, given that standard synchronous submission mechanisms usually result in only the last request completing?

A fundamental constraint in browser behavior is that a standard HTML form submission navigates the browser window to the form’s action URL. If one attempts to trigger form1.submit() followed immediately by form2.submit() synchronously via a single event handler, the first submission initiates navigation, and any subsequent calls (including the second submit) are typically aborted or ignored by the browser runtime within that execution slice. Therefore, methods must involve asynchronous operations or entirely bypass the standard navigation flow for at least one form.

Solution Path 1: Asynchronous Submission for the First Form

The accepted strategy often involves submitting the initial form asynchronously via AJAX (or fetch), allowing the browser context to remain active so that the second form can be submitted traditionally (synchronously) afterward.

Legacy XMLHttpRequest Approach

This technique serializes the first form’s data and sends it via XMLHttpRequest without waiting for a response before triggering the second form’s direct submission.

// Selecting the form likely named 'updateDB'
const dbUpdateForm = document.forms.updateDB;
let postDataArray = [];

// Manual serialization of form elements
for (let i = 0; i < dbUpdateForm.elements.length; i++) {
    const element = dbUpdateForm.elements[i];
    postDataArray.push(
        encodeURIComponent(element.name) + "=" + encodeURIComponent(element.value)
    );
}

const xhr = new XMLHttpRequest();
xhr.open("POST", "mypage.php", true); // true for asynchronous
xhr.setRequestHeader("Content-type", "application/x-www-form-urlencoded");
xhr.send(postDataArray.join("&"));

// Immediately proceed to submit the second form (e.g., named 'payPal')
document.forms.payPal.submit();

Modern fetch Implementation (Fire and Forget)

For a more contemporary approach, the fetch API can be used. If the goal is truly simultaneous submission without dependencies, we do not await the fetch call.

function fireAndForgetSubmit() {
    const { updateDB, payPal } = document.forms;

    // Submit updateDB form asynchronously using fetch
    fetch(updateDB.action, {
        method: updateDB.method,
        headers: { "content-type": updateDB.enctype },
        body: new FormData(updateDB),
    });
    // Note: No 'await' is used here, so the execution continues immediately.

    // Submit the second form directly
    payPal.submit();
}

Modern fetch Implementation (Sequential with Error Checking)

If you require confirmation that the first operation succeeded before proceeding to the second, you must sequence the calls using async/await. If the first request fails (!res.ok), an error is thrown, and the second submission is halted.

async function sequentialSubmit() {
    const { updateDB, payPal } = document.forms;

    try {
        const res = await fetch(updateDB.action, {
            method: updateDB.method,
            headers: { "content-type": updateDB.enctype },
            body: new FormData(updateDB),
        });

        if (!res.ok) {
            const error = new Error(`DB Update Failed! Status: ${res.status}`);
            const contentType = res.headers.get("content-type") || "";
            
            // Attempt to extract body content for better debugging
            error.body = await (contentType.includes("application/json") ? res.json() : res.text());
            throw error;
        }

        // Only submit the second form upon successful completion of the first
        payPal.submit();

    } catch (error) {
        console.error("Submission sequence interrupted:", error);
        // Logic here to display error message to the user about the DB update failure
    }
}

Solution Path 2: Triggering Submits via Button Click Handlers (ID/Name Based)

If the forms are known by their ID or name, JavaScript functions can be explicitly called upon a non-standard submit button click (e.g., type="button").

If forms possess unique IDs (e.g., form1 and form2):

<input type="button" value="Process Both" onclick="submitFormsById()" />

<script>
function submitFormsById(){
    document.getElementById("form1").submit();
    document.getElementById("form2").submit();
}
</script>

Note: This synchronous approach suffers from the same core limitation mentioned initially—only the last successful standard submission will typically complete its navigation. This is best used when combining one standard submit with one asynchronous update, as in Solution Path 1.

If forms are accessed by name attribute:

function submitFormsByName(){
    document.forms["form1"].submit();
    document.forms["form2"].submit();
}

Solution Path 3: Sequential Submission via Event Listener and Deferred Handling (jQuery Example)

Using a library like jQuery simplifies chaining asynchronous calls. Here, we prevent the default submission of the first form, serialize and post its data, and only submit the second form within the success callback of the first post.

// Assuming jQuery is loaded
$('#form1').submit(function(event1) {
    event1.preventDefault(); // Stop immediate navigation
    event1.stopPropagation();
    
    const $form1 = $(this);
    
    // Post the first form data asynchronously
    const postForm1 = $.post($form1.attr('action'), $form1.serialize());

    postForm1.done(function(result) {
        // Success feedback placeholder for form1 result
        console.log("Form 1 data processed.");
        
        // Now submit the second form
        $('#form2').submit();
    });
});

Solution Path 4: Delayed Submission using setTimeout

This approach uses JavaScript timers to introduce delays, ensuring that submissions happen sequentially rather than within the same execution block. This effectively circumvents the browser’s synchronous request abortion mechanism but results in sequential page navigations, potentially opening subsequent forms in new windows if target="_blank" is set.

<script>
function staggeredSubmission() {
    // Submit form1 after 3 seconds
    setTimeout(function(){ 
        document.getElementById("form1").submit();
    }, 3000);   
    
    // Submit form2 after 6 seconds
    setTimeout(function(){ 
        document.getElementById("form2").submit();
    }, 6000);   
}
</script>

<form target="_blank" id="form1">...</form>
<form target="_blank" id="form2">...</form>

Caveat: Modern browsers frequently block pop-up windows initiated by delayed timers unless they are directly chained to a user-initiated event, often requiring the user to permit pop-ups for the site.

Browser Behavior Observation

In environments like Chrome or IE9, attempting successive synchronous submits within one JS slice typically leads to the browser discarding all but the final request, only allowing the last one to establish a network connection. Relying on asynchronous techniques like XMLHttpRequest or fetch for the initial action is necessary to maintain control over the flow.

The most robust architectural recommendation is often to consolidate the logic into a single server request, handling both sets of data transactionally on the backend, instead of relying on two separate browser submissions. For server-side handling of multi-part data or distinct actions, review web framework capabilities for handling multiple POST requests in a single transaction.

FAQs on JavaScript Techniques for Submitting Multiple Forms Concurrently

Q: Why does submitting two forms synchronously fail

ANS: Browsers detect multiple submissions initiated in the same JavaScript execution context and typically abort all but the last pending request, as the first submission initiates a navigation event that interrupts the flow.

Q: Can I use fetch API to submit both forms simultaneously

ANS: Yes, you can use the fetch API for the first form submission without awaiting its result. This keeps the JavaScript thread open, allowing the second form to be submitted directly via its native submit method.

Q: Is it better to use AJAX for one form or use setTimeout for both

ANS: Using AJAX (like fetch) for the first form ensures that the submission is genuinely asynchronous, preventing navigation interruption. Using setTimeout only delays sequential navigation attempts, which might still lead to unexpected pop-up blocking or user experience issues.
