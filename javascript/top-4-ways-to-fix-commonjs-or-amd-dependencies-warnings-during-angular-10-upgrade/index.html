How to Resolve CommonJS or AMD Dependencies Warnings When Upgrading to Angular 10?

Upgrading an Angular application can sometimes lead to unexpected warnings, particularly related to dependencies that come in CommonJS or AMD formats. Recently, while transitioning my Angular 9 application to Angular 10, I encountered the following warning:

WARNING in calendar.reducer.ts depends on lodash/keys. CommonJS or AMD dependencies can cause optimization bailouts.

This message indicates that the current dependency, lodash, could negatively affect the optimization capabilities of the application, potentially increasing the bundle size significantly. Despite adding the following line to my angular.json file:

"allowedCommonJsDependencies": ["lodash"]

the issue persisted. What practical solutions can be implemented to resolve such warnings effectively?

Solutions to Address the Warning

1. Switching to an ES Module Version

The primary cause of such warnings is that the lodash library is not designed as an ECMAScript module, which can hinder tree-shaking—resulting in larger bundle sizes. A recommended solution is to switch to the ES module variant of lodash, known as lodash-es.

Here’s how to transition:

  1. Install lodash-es using npm:

    npm install --save lodash-es

  2. Update your import statements throughout your application:

    import { keys } from 'lodash-es';

By doing so, the Angular compiler can effectively optimize by eliminating unused symbols, which is crucial for maintaining a compact bundle.

2. Allowing CommonJS Dependencies

If an ES module version is unavailable or the change is not feasible, you may decide to allow certain CommonJS dependencies in your configuration file. This method, while straightforward, could lead to increased bundle sizes since tree-shaking will be less effective. Modify the angular.json file as shown:

"architect": {
   "build": {
       "builder": "@angular-devkit/build-angular:browser",
       "options": {
           "allowedCommonJsDependencies": ["lodash"]
       }
   }
}

Note: Since Angular CLI version 10.0.1, you can also use globs in allowedCommonJsDependencies. If you specify lodash, it will also apply to its sub-paths (like lodash/keys).

For a deeper dive, refer to the official documentation on CommonJS dependencies .

3. Utilize Alternative Libraries

If your use of lodash is primarily for a particular function, consider exploring alternative libraries that may already be optimized for ES modules. For example, smaller utilities like Ramda or native JavaScript functions can replace some lodash functionalities, reducing dependency footprint.

4. Evaluate Tree-shaking Capabilities

As a best practice, ensure your project is set to leverage tree-shaking to eliminate unused code at the build stage. Use tools like Webpack to analyze and visualize your bundles and understand where CommonJS modules might be impacting performance.

Practical Example

Suppose you’re utilizing the keys function from lodash in your code. Here’s how to refactor it:

// Instead of this
import { keys } from 'lodash'; // CommonJS import

// Use this
import { keys } from 'lodash-es'; // ES Module import

Such a transition not only resolves the warning but also optimizes your bundle.

FAQs on Top 4 Ways to Fix CommonJS or AMD Dependencies Warnings During Angular 10 Upgrade

Q: What does the warning about CommonJS or AMD dependencies mean?

A: This warning indicates that your application is relying on libraries that utilize CommonJS or AMD formats, which can hinder optimization efforts during the build process, leading to larger bundle sizes.

Q: How can I determine if a library supports ES modules?

A: You can check the library’s documentation or repository on platforms like npm or GitHub. Libraries that support ES modules usually mention it explicitly in their installation instructions or README files.

Q: What is tree-shaking?

A: Tree-shaking is a term used in JavaScript bundling practices that refers to the elimination of unused code from the final output bundle, resulting in a smaller file size and improved performance.

Q: Are there performance impacts by allowing CommonJS dependencies?

A: Yes, allowing CommonJS dependencies can lead to larger bundle sizes as the optimization features like tree-shaking won’t be as effective, potentially impacting application performance.
