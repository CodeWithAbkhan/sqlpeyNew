“Bash Indirect Expansion Explained: ${!var} vs ${!prefix*} Syntax”

When working with shell parameters in Bash, variable indirection provides a powerful mechanism to access a variable’s value using the value of another variable as its name. However, specific usages, like appending an asterisk (*), alter this behavior significantly. How does Bash process constructs like ${!N*} versus the standard indirect expansion ${!NAME}? Let’s dissect the official documentation and practical examples to clarify these distinct functionalities.

The Standard Indirect Expansion: Using a Variable’s Value as a Name

The fundamental purpose of indirect expansion, introduced by the leading exclamation mark (!), is to substitute the value of the variable specified by the rest of the parameter.

If a parameter’s first character is !, Bash interprets the subsequent characters as the name of a second variable. The value of this second variable is then used in the substitution.

Example of True Indirection:

Consider setting up a two-level reference:

export BASE_SETTING="configuration_value"
export configuration_value="System Ready"

# Normal expansion: references the value of BASE_SETTING
echo "Normal Expansion: ${BASE_SETTING}"

# Indirect expansion: references the value pointed to by BASE_SETTING
echo "Indirect Expansion: ${!BASE_SETTING}"

Executing this sequence yields:

Normal Expansion: configuration_value
Indirect Expansion: System Ready

In this scenario, ${!BASE_SETTING} resolves to ${!configuration_value}, resulting in System Ready.

The Exception: Pattern Matching with ${!prefix*}

The Bash manual explicitly states exceptions to the standard indirect expansion rule. Specifically, patterns ending in *, such as ${!prefix*}, behave differently. Instead of performing indirection, this form expands to the names of existing variables that begin with the specified prefix. These names are separated by the first character of the IFS (Internal Field Separator) special variable.

If you encounter ${!N*}, where N is the prefix, Bash lists all variable names starting with N.

Example Demonstrating Prefix Matching:

export VAR_ALPHA="data1"
export VAR_BETA="data2"
export VAR_ALPHA_MORE="data3"

# Prefix is VAR_
echo "Variables starting with VAR_:"
echo ${!VAR_*}

Output would list the variable names:

Variables starting with VAR_:
VAR_ALPHA VAR_ALPHA_MORE VAR_BETA

If the prefix itself is used alone within the indirection context without the * (e.g., ${!N}), standard indirection applies, provided a variable named N exists. If N does not exist, it might expand to nothing or cause unexpected behavior depending on context, but ${!prefix*} is definitively for listing matching names.

Advanced Technique: Bash Namerefs (declare -n)

Beyond simple parameter expansion, Bash versions 4.3 and later offer namerefs using declare -n (or local -n inside functions). A nameref creates an alias or reference to another variable, allowing you to read and write to the target variable through the reference name.

Using Namerefs for Direct Manipulation:

TARGET_SETTING="Initial Value"
declare -n refName=TARGET_SETTING

echo "Value via reference: ${refName}"

# Modify the target variable through the reference
refName="New Value Set via Alias"

echo "Value of original variable: ${TARGET_SETTING}"

Output:

Value via reference: Initial Value
Value of original variable: New Value Set via Alias

Namerefs are particularly effective within functions because they allow functions to directly modify variables outside their local scope by name, offering dynamic scope manipulation far more controlled than traditional indirection in certain complex operations, such as parsing time formats from ps output:

# Function demonstrating nameref use for reading attributes
showVarDetail() {
    local varName=$1
    declare -n varRef="$varName"
    # Displaying name, length, attributes, and value
    printf 'Name: %s | Length: %d | Flags: [%s] | Content: %q\n' \
        "$varName" "${#varRef}" "${varRef@a}" "${varRef}"
}

declare -r FINAL_ANSWER=42
showVarDetail FINAL_ANSWER

# Example showing modification and iteration (similar to moving characters)
move1char() {
    local -n srcStr=$1 tgtVar=$2
    [[ -z "$srcStr" ]] && return 1
    # Move first character of srcStr to end of tgtVar
    tgtVar+="${srcStr::1}"
    srcStr="${srcStr:1}"
}

SOURCE_DATA="ProcessData"
PROCESSED_OUTPUT=""

This use of declare -n provides robust ways to inspect variable attributes (like read-only r or integer i) and manipulate string content dynamically.

Summary of Syntax Distinctions

The key difference hinges on the trailing asterisk (*):

  1. ${!VAR} (No *): True indirection. Uses the value of VAR as the name of the variable to retrieve.
  2. ${!PREFIX*} (With *): Name listing. Returns the names of all variables starting with PREFIX, separated by IFS. This is an exception where indirection is bypassed in favor of glob-like matching across variable names.

For authoritative details on parameter expansion rules in Bash, refer to the official GNU documentation on Shell Parameter Expansion .

FAQs on Bash Variable Indirection Explained

Q: What is the primary difference between ${!VAR} and ${!VAR*} in Bash

ANS: ${!VAR} performs true indirection, accessing the variable whose name is the value of VAR. ${!VAR*} lists the names of all variables whose names begin with the string stored in VAR, separated by the first character of the IFS variable.

Q: How does nameref syntax 'declare -n' differ from ${!VAR}

ANS: declare -n ref=VARNAME creates an alias (ref) that can be used to read or modify the original variable (VARNAME). ${!VAR} only allows reading the value dynamically; it does not easily support assigning back to the indirect variable name without further complex parameter expansion or command substitution.

Q: Can ${!prefix*} be used to list environment variables only

ANS: No, ${!prefix*} lists all shell variables matching the prefix, including local and environment variables, based on what is currently set in the shell’s symbol table.
