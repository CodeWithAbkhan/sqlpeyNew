“Bash Shell Globbing Check: How to Verify if Wildcards Match Files”

Let’s dive into different approaches to tackle this.

Bash Shell Globbing Verification

When using wildcards like * or ? in the Bash shell, you often need to confirm if these patterns actually resolve to any existing files before proceeding with operations. This prevents errors like “no such file or directory” or ensures your scripts are robust.

Solution 1: Using compgen -G

The compgen -G <glob-pattern> command is specifically designed for generating matches for glob patterns. Its exit status indicates success or failure: 0 for one or more matches, and 1 for no matches.

Key Aspects:

  • Concise: A straightforward way to check for matches.
  • Exit Status: Provides a clear signal of whether files were found.
  • Standard Output: Lists the matching files.

Practical Example:

# Define your glob pattern
FILE_PATTERN="/tmp/my_app_data_*.log"

# Check if any files match the pattern
if compgen -G "$FILE_PATTERN" > /dev/null; then
    echo "Found files matching '$FILE_PATTERN'."
    # Process the files found
    # For example: ls -l $FILE_PATTERN
else
    echo "No files found matching '$FILE_PATTERN'."
fi

Solution 2: shopt -s nullglob and find or stat

The nullglob shell option is a Bash-specific feature that causes glob patterns to expand to nothing if they don’t match any files. This can be combined with other commands.

Using find for Portability:

The find command is a powerful and portable utility for locating files. Using -maxdepth 1 restricts the search to the current directory, and -print -quit makes it efficiently stop after finding the first match.

# Example using find
SEARCH_PATTERN="config_*.yaml"

if test -n "$(find . -maxdepth 1 -name "$SEARCH_PATTERN" -print -quit)"; then
    echo "Files matching '$SEARCH_PATTERN' were found using find."
else
    echo "No files matching '$SEARCH_PATTERN' found using find."
fi

Using stat for Efficiency (when find feels like overkill):

If the number of potential matches is small, stat can be a quicker alternative.

# Example using stat
GLOB_PATTERN="report_2023_*.csv"

if stat -t "$GLOB_PATTERN" >/dev/null 2>&1; then
    echo "Files matching '$GLOB_PATTERN' were found using stat."
else
    echo "No files matching '$GLOB_PATTERN' found using stat."
fi

Solution 3: Custom Function exists()

Creating a simple function can enhance readability and provide a clean way to check.

exists() {
    # The pattern is expanded by the shell before being passed to the function.
    # The [ -e "$1" ] check evaluates the first argument.
    [ -e "$1" ]
}

# Example usage
if exists *.conf; then
    echo "Configuration files (*.conf) are present."
else
    echo "No configuration files found."
fi

Important Note: This function checks the first argument it receives. If the glob expands to multiple files, only the existence of the first one is directly tested by [ -e "$1" ]. However, the expansion itself implies that at least one file matched. Be mindful of potential edge cases with very large numbers of files.

Solution 4: Globbing to an Array with nullglob

When shopt -s nullglob is active, a glob that matches nothing will result in an empty array.

#!/bin/bash

# Enable nullglob
shopt -s nullglob

# Define a glob pattern
MATCHING_FILES=(data_v*.json)

# Check the number of elements in the array
if [ "${#MATCHING_FILES[@]}" -ge 1 ]; then
    echo "${#MATCHING_FILES[@]} JSON files found."
    # You can now iterate through the array:
    # for file in "${MATCHING_FILES[@]}"; do echo "  - $file"; done
else
    echo "No JSON files found matching the pattern."
fi

If nullglob is not set, and no files match, the array will contain the literal glob pattern as its single element.

Solution 5: Using shopt -s failglob

Setting shopt -s failglob causes the script to exit immediately if a glob pattern doesn’t match anything. This is a more drastic approach, useful when a missing file should halt execution.

#!/bin/bash

# Enable failglob
shopt -s failglob

# Attempt to assign matching files to a variable
# If no files match, the script will exit with an error
# To check without exiting, you can use a subshell or conditional logic
echo "Checking for *.bak files..."
files_with_bak=(*.bak)

if [ "${#files_with_bak[@]}" -gt 0 ]; then
    echo "Found *.bak files."
else
    echo "No *.bak files found."
fi

# To use failglob safely in a check:
# (shopt -s failglob; : *.bak) && echo "Found" || echo "Not found"

Solution 6: Handling Broken Symbolic Links

The standard -e test might consider broken symbolic links as non-existent. A more robust check can include -L to also test for the existence of the link itself.

globexists() {
  # Check if the file exists OR if it's a symbolic link
  test -e "$1" -o -L "$1"
}

if globexists backup_*.tar.gz; then
    echo "Backup files found (including potentially broken links)."
else
    echo "No backup files found."
fi

Solution 7: String Comparison with echo

A simple string comparison can also work, especially with nullglob enabled.

#!/bin/bash

# Enable nullglob
shopt -s nullglob

if [ "$(echo *.config)" != "" ]; then
    echo "At least one .config file exists."
else
    echo "No .config files found."
fi

This relies on the echo command returning an empty string if nullglob causes the glob to expand to nothing.

Solution 8: Using find with Brace Expansion

For more complex globs, including brace expansion, find is a reliable tool.

# Example with brace expansion for different directory paths
TARGET_DIRS="/var/log /opt/app/logs"
GLOB_PATTERN="*-error.log"

# Check if any log files exist in any of the specified directories
if find $TARGET_DIRS -maxdepth 1 -name "$GLOB_PATTERN" -quit 2>/dev/null; then
    echo "Error logs found in specified directories."
else
    echo "No error logs found."
fi

Solution 9: Array Assignment and First Element Check

Assigning the glob result to an array and checking the first element can be effective.

# Assign glob result to an array
MY_FILES=(*.tmp)

# Check if the first element exists (only works reliably if files exist or if nullglob is NOT set)
if [ -e "${MY_FILES[0]}" ]; then
    echo "Found temporary files."
else
    echo "No temporary files found."
fi

This method is simpler but can be less robust than others if nullglob is not considered.

Solution 10: for Loop with Break Condition

You can use a for loop and check within the loop if the item is actually a file.

echo "Checking for script files (*.sh)..."
found_script=false
for script_file in *.sh; do
    # If the glob didn't match, $script_file will be the literal pattern.
    # Check if it's a regular file.
    if [[ -f "$script_file" ]]; then
        echo "Found script: $script_file"
        found_script=true
        # Break if you only need to know if at least one exists
        break
    fi
done

if ! $found_script; then
    echo "No .sh files found."
fi

Solution 11: set -- for Portability

The set -- command can be used to re-initialize positional parameters.

# Set positional parameters with the glob
set -- ./data_*.csv

# Check if the first parameter is a file
if [ -f "$1" ]; then
    echo "Data CSV files exist."
else
    echo "No data CSV files found."
fi

This method is efficient and works across POSIX-compliant shells.

Solution 12: Counting Matches with nullglob

Combining nullglob with a counter is another way to see how many matches you have.

#!/bin/bash

# Enable nullglob
shopt -s nullglob

match_count=0
for file in /var/log/syslog*; do
    match_count=$((match_count + 1))
done

if [ "$match_count" -gt 0 ]; then
    echo "Found $match_count syslog-related files."
else
    echo "No syslog-related files found."
fi

Solution 13: Differentiating Match Counts with compgen -W

This approach leverages compgen -W and checks the exit status for different scenarios.

shopt -s nullglob # Recommended for clean behavior

PATTERN="important_*.txt"
compgen -W "$PATTERN" &>/dev/null

case $? in
    0) echo "Exactly one match found for '$PATTERN'." ;;
    1) echo "Multiple matches found for '$PATTERN'." ;;
    2) echo "No matches found for '$PATTERN'." ;;
esac

Solution 14: printf for List Generation

printf is excellent for generating lists of files in a predictable format, especially for piping.

FILTER="/etc/*.conf"

# Safely read matches into an array
readarray -t config_files < <(printf '%s\n' $FILTER)

if (( ${#config_files[@]} > 0 )); then
    echo "Found ${#config_files[@]} .conf files in /etc."
    # Process the files:
    # for cfg in "${config_files[@]}"; do echo " - $cfg"; done
else
    echo "No .conf files found in /etc."
fi

This method is robust, handling filenames with spaces correctly when used with readarray.

Solution 15: ls and grep Combination

While not the most efficient for large directories, this is quite readable.

if ls /tmp/backup_*.zip 2>/dev/null | grep -q ".zip"; then
    echo "Found .zip backup files."
else
    echo "No .zip backup files found."
fi

This uses ls to list potential files and grep -q to quietly check if any output is produced. Redirecting stderr (2>/dev/null) suppresses “No such file or directory” errors from ls.

Solution 16: ls with Exit Code Check

A more direct way to use ls is by checking its exit status.

if ls /var/www/html/index.* >/dev/null 2>/dev/null; then
    echo "HTML index files found."
else
    echo "No HTML index files found."
fi

If ls finds files, its exit status is 0. If it doesn’t find any, it returns a non-zero exit status.

Solution 17: Extended Globs with bash -c

For advanced patterns using Bash’s extglob features, you can use bash -c.

# Example: Check for files ending in .ts or .mp4 using extglob
PATTERN="@(*.ts|*.mp4)"
EXIT_STATUS=$(bash -c$'shopt -s extglob; compgen -G "'"$PATTERN"'" &>/dev/null; echo $?')

if [ "$EXIT_STATUS" -eq 0 ]; then
    echo "Found video files matching '$PATTERN'."
else
    echo "No video files found matching '$PATTERN'."
fi

FAQs on Bash Shell Globbing

Q Check if any file matches a bash glob pattern

ANS: You can use compgen -G "<glob-pattern>". It returns an exit status of 0 if matches are found, and 1 otherwise. Alternatively, enable shopt -s nullglob and check if the glob expands to a non-empty string or array.

Q What does shopt nullglob do in bash

ANS: When shopt -s nullglob is enabled, if a glob pattern does not match any files, it expands to nothing rather than the literal pattern itself. This simplifies checks as an empty result clearly indicates no matches.

Q How to handle filenames with spaces when globbing

ANS: It’s best to use arrays and readarray or mapfile with printf '%s\n' to capture filenames. For example: readarray -t files < <(printf '%s\n' *.txt). Always quote variables like "${files[@]}" when using them.

Q Is there a portable way to check for glob matches

ANS: Using set -- glob* and then checking [ -f "$1" ] is a POSIX-compliant method that doesn’t rely on Bash-specific options like nullglob or failglob.

Q How to check for existence and broken symbolic links

ANS: Use a function like globexists() { test -e "$1" -o -L "$1"; }. The -e checks for general existence, and -L specifically checks if it’s a symbolic link.
