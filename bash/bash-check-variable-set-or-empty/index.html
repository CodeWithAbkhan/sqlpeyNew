“Bash: How to Reliably Check if a Shell Variable is Set or Empty”

When writing shell scripts, a common requirement is to check if a variable has been assigned a value, is empty, or is entirely unset. While seemingly straightforward, Bash offers several ways to approach this, each with subtle differences that can be crucial for robust scripting. This post delves into these methods, highlighting their effectiveness and potential pitfalls.

Distinguishing Between Unset and Empty Variables

A key distinction in shell scripting is between a variable that is unset (has never been assigned a value) and a variable that is set but empty (assigned an empty string, ""). Understanding this difference is vital in scenarios where defaulting to a non-empty value is necessary if a variable isn’t explicitly provided, versus cases where an empty string signifies a deliberate absence of a value.

Solution 1: The Precise Check with ${var+x}

The most accurate way to determine if a variable is set (regardless of whether it’s empty or not) is by using the ${var+x} parameter expansion.

if [ -z ${var+x} ]; then
  echo "var is unset"
else
  echo "var is set to '$var'"
fi

Explanation:

  • ${var+x}: This is a parameter expansion that evaluates to x if var is set (even if it’s empty), and to nothing if var is unset.
  • [ -z ... ]: This tests if the expanded string is zero-length.

Why quotes can be omitted: The syntax ${var+x} guarantees that the expansion will either be x (which contains no word breaks) or nothing. Therefore, quotes are not strictly necessary here, though using [ -z "${var+x}" ] is also perfectly valid and might be preferred for consistency, with a negligible performance impact.

The “Wrong Way” (and why):

A common but often incorrect approach is [ -z "$var" ].

if [ -z "$var" ]; then
  echo "var is blank"
else
  echo "var is set to '$var'"
fi

This method fails to differentiate between an unset variable and a variable set to an empty string. If var='' (set but empty), this condition evaluates to true, leading to the same output as an unset variable.

Solution 2: Checking for Non-Empty with ${var:-} or test -n

To check if a variable is set and not empty, the test -n operator combined with parameter expansion is highly effective.

if test -n "${var:-}"; then
  echo "var is set and not empty."
else
  echo "var is unset or empty."
fi

Explanation:

  • ${var:-}: If var is unset or null, this expands to an empty string. If var is set and not null, it expands to the value of var.
  • test -n: Returns true if the string is not empty.

This approach is POSIX-compliant and works across various shells.

Solution 3: Bash 4.2+ Feature: -v Operator

For Bash versions 4.2 and later, the [[ -v variable_name ]] construct provides a direct way to test for variable presence.

if [[ -v MY_VARIABLE ]]; then
  echo "MY_VARIABLE is set."
else
  echo "MY_VARIABLE is unset."
fi

Explanation:

  • [[ -v MY_VARIABLE ]]: This checks if the variable MY_VARIABLE is set. It does not care about its value (empty or not).

This is often considered the cleanest and most modern approach in newer Bash versions. It also handles set -u gracefully without errors.

Practical Use Cases:

  • Providing a default value if unset or empty:

    MY_VAR="${MY_VAR:-default_value}"

    If MY_VAR is unset or empty, it will be set to default_value.

  • Exiting with an error if unset:

    # This script requires the 'VERSION' environment variable to be set.
VERSION="${1:?Error: Please provide the version number as an argument.}"

    If 1 (the first argument) is unset, the script will exit with the specified error message.

Solution 5: Checking Positional Parameters ($#)

When dealing with command-line arguments or function parameters, checking the count of arguments is often more reliable than checking individual parameters directly.

if [ $# -gt 0 ]; then
  echo "At least one argument was provided."
else
  echo "No arguments were provided."
fi

Explanation:

  • $#: Represents the number of positional parameters passed to the script or function.
  • [ $# -gt 0 ]: Tests if the number of arguments is greater than zero.

Alternatively, you can check if a specific parameter is non-empty:

if [ -n "$1" ]; then
  echo "The first parameter (\$1) has a value."
else
  echo "The first parameter (\$1) is unset or empty."
fi

Advanced Techniques and Considerations

  • declare -p: The declare -p variable_name command outputs the declaration of a variable. If the variable is set, it returns an exit status of 0. If unset, it returns 1. This is a robust method for checking variable existence, especially when dealing with different variable types.

    if declare -p MY_VARIABLE &>/dev/null; then
    echo "MY_VARIABLE is declared."
else
    echo "MY_VAR is not declared."
fi

    The &>/dev/null redirects both standard output and standard error to /dev/null, so only the exit status is used.

  • set -u (nounset): When set -u is active, referencing an unset variable directly will cause the script to exit. This is why methods like ${var:-} are crucial for safely handling potentially unset variables in such environments.

  • Arrays: Checking array elements requires different approaches. For instance, ${#array[@]} checks the number of elements in an array.

Summary of Reliable Checks:

  • To check if a variable is SET (defined, can be empty):

    if [ -n "${var+x}" ]; then echo "Set"; fi
# Or (Bash 4.2+):
if [[ -v var ]]; then echo "Set"; fi

  • To check if a variable is SET and NOT EMPTY:

    if [ -n "$var" ]; then echo "Set and not empty"; fi
# Or POSIX compliant:
if test -n "${var:-}"; then echo "Set and not empty"; fi

  • To check if a variable is UNSET or EMPTY:

    if [ -z "$var" ]; then echo "Unset or empty"; fi
# Or POSIX compliant, handling unset safely:
if test -z "${var:-}"; then echo "Unset or empty"; fi

Choosing the right method depends on your specific needs: whether you need to distinguish between unset and empty, your target Bash version, and whether set -u is in effect.

FAQs on Bash Variable Checks

Q: How do I check if a Bash variable is set but can be empty

ANS: Use the ${var+x} parameter expansion within a test. For instance: if [ -n "${var+x}" ]; then echo "Variable is set"; fi. This checks for the variable’s existence, regardless of its value. For Bash 4.2+, [[ -v var ]] is a more direct way.

Q: What's the difference between an unset and an empty Bash variable

ANS: An unset variable has never been assigned a value. An empty variable has been assigned an empty string (""). Standard checks like [ -z "$var" ] treat both as empty. To differentiate, you can use ${var+x} to detect if it’s set at all.

Q: How to provide a default value if a Bash variable is unset or empty

ANS: Utilize parameter expansion: NEW_VAR="${EXISTING_VAR:-default_value}". If EXISTING_VAR is unset or empty, NEW_VAR will be assigned default_value.

Q: Can I check if a Bash variable is set safely when using set u

ANS: Yes, when set -u is active, directly referencing an unset variable causes an error. Use parameter expansion with a default, like [ -z "${var:-}" ] or [ -n "${var+x}" ], which safely handles unset variables without error.

Q: What is the most reliable way to check for variable presence in Bash

ANS: For modern Bash (4.2+), [[ -v var_name ]] is highly reliable. For broader POSIX compatibility or older Bash versions, [ -n "${var+x}" ] is a robust method to check if a variable is set.
