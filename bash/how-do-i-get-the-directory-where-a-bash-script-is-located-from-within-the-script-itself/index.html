How to Reliably Get the Directory of a Bash Script

When writing shell scripts, a common requirement is to locate the directory from which the script itself resides. This is crucial for tasks such as referencing configuration files, loading libraries, or accessing other resources relative to the script’s location. However, achieving this reliably across different invocation methods, including symbolic links and sourcing, can be surprisingly complex. This post explores various techniques and provides practical examples to ensure you can accurately determine your Bash script’s directory.

We’ll cover several effective solutions, each with its own nuances, allowing you to choose the best approach for your specific needs.

Solutions

Solution 1: The One-Liner for Simple Cases

For straightforward scenarios where the script isn’t heavily involved with symbolic links, a concise one-liner can often suffice.

SCRIPT_DIR=$( cd -- "$( dirname -- "${BASH_SOURCE[0]}" )" &> /dev/null && pwd )

This command first determines the directory of the current script using ${BASH_SOURCE[0]} (explained below) and then changes to that directory (cd) to get its absolute path using pwd. The redirection &> /dev/null suppresses any output from cd and pwd.

Solution 2: Handling Symbolic Links Recursively

When your script might be invoked through a chain of symbolic links, a more robust, multi-line approach is necessary to resolve the actual script’s location.

get_script_dir() {
    local SOURCE_PATH="${BASH_SOURCE[0]}"
    local SYMLINK_DIR
    local SCRIPT_DIR
    # Resolve symlinks recursively
    while [ -L "$SOURCE_PATH" ]; do
        # Get symlink directory
        SYMLINK_DIR="$( cd -P "$( dirname "$SOURCE_PATH" )" >/dev/null 2>&1 && pwd )"
        # Resolve symlink target (relative or absolute)
        SOURCE_PATH="$(readlink "$SOURCE_PATH")"
        # Check if candidate path is relative or absolute
        if [[ $SOURCE_PATH != /* ]]; then
            # Candidate path is relative, resolve to full path
            SOURCE_PATH=$SYMLINK_DIR/$SOURCE_PATH
        fi
    done
    # Get final script directory path from fully resolved source path
    SCRIPT_DIR="$(cd -P "$( dirname "$SOURCE_PATH" )" >/dev/null 2>&1 && pwd)"
    echo "$SCRIPT_DIR"
}

echo "get_script_dir: $(get_script_dir)"

This function, get_script_dir, iteratively follows symbolic links until it finds the actual file. It then extracts the directory path. This method is highly reliable for complex scenarios.

Solution 3: Detailed Explanation of Link Resolution

To gain a deeper insight into how symbolic links are resolved, consider this more verbose script. It prints intermediate steps to illustrate the process.

SOURCE=${BASH_SOURCE[0]}
while [ -L "$SOURCE" ]; do # resolve $SOURCE until the file is no longer a symlink
  TARGET=$(readlink "$SOURCE")
  if [[ $TARGET == /* ]]; then
    echo "SOURCE '$SOURCE' is an absolute symlink to '$TARGET'"
    SOURCE=$TARGET
  else
    DIR=$(dirname "$SOURCE")
    echo "SOURCE '$SOURCE' is a relative symlink to '$TARGET' (relative to '$DIR')"
    SOURCE=$DIR/$TARGET # if $SOURCE was a relative symlink, we need to resolve it relative to the path where the symlink file was located
  fi
done
echo "SOURCE is '$SOURCE'"
RDIR=$(dirname "$SOURCE")
DIR=$(cd -P "$( dirname "$SOURCE" )" >/dev/null 2>&1 && pwd)
if [ "$DIR" != "$RDIR" ]; then
  echo "DIR '$RDIR' resolves to '$DIR'"
fi
echo "DIR is '$DIR'"

This script provides a step-by-step breakdown of resolving symbolic links, which can be invaluable for debugging.

Solution 4: Using dirname and $0

A more basic approach involves utilizing the $0 special variable, which holds the script’s name as it was invoked.

echo "The script you are running has:"
echo "basename: [$(basename "$0")]"
echo "dirname : [$(dirname "$0")]"
echo "pwd     : [$(pwd)]"

The dirname "$0" command will provide the directory component of $0. However, its output is relative to the current working directory (pwd) and might not be the absolute path of the script if it’s called from a different location.

Solution 5: dirname with readlink -f

Combining dirname with readlink -f offers a robust way to get the absolute path, resolving symbolic links along the way.

dirname -- "$( readlink -f -- "$0"; )";

This command first uses readlink -f to get the canonical, absolute path of the script (resolving all symlinks) and then pipes that path to dirname to extract the directory. This is generally considered a reliable method.

Solution 6: The pushd and popd Method

For a comprehensive solution that handles various edge cases, including sourced scripts and symlinks, the pushd and popd commands can be employed.

pushd . > '/dev/null';
SCRIPT_PATH="${BASH_SOURCE[0]:-$0}";

while [ -h "$SCRIPT_PATH" ];
do
    cd "$( dirname -- "$SCRIPT_PATH"; )";
    SCRIPT_PATH="$( readlink -f -- "$SCRIPT_PATH"; )";
done

cd "$( dirname -- "$SCRIPT_PATH"; )" > '/dev/null';
SCRIPT_PATH="$( pwd; )";
popd  > '/dev/null';

This script ensures that the SCRIPT_PATH variable holds the absolute path to the script, regardless of how it was invoked or if it’s a symbolic link.

Solution 7: A Concise realpath Approach

A clean and often effective method uses realpath to resolve the script’s path.

DIR="$( dirname "$(realpath "$0")" )"

This approach is straightforward and handles symbolic links effectively. Ensure realpath is available on your system (it’s part of GNU coreutils).

Solution 8: Leveraging BASH_SOURCE

The ${BASH_SOURCE[0]} variable is specifically designed to provide the source filename, which is particularly useful when scripts are sourced rather than executed directly.

scriptdir="$( dirname -- "$BASH_SOURCE"; )";

This requires using #!/bin/bash as the shebang, as $BASH_SOURCE is a Bash-specific extension.

Solution 9: readlink -f with BASH_SOURCE

Combining readlink -f with ${BASH_SOURCE[0]} provides a robust way to get the absolute path, even with symlinks and sourcing.

actual_path=$(readlink -f "${BASH_SOURCE[0]}")
script_dir=$(dirname "$actual_path")

This method is highly recommended for its reliability across various invocation scenarios.

Solution 10: Handling Spaces and Special Characters

When script directories might contain spaces or other special characters, proper quoting is essential.

cd "$( `dirname `"$0"` )"

This ensures that directory names with spaces are correctly parsed.

Solution 11: Cross-Platform Compatibility

For solutions that aim for broader compatibility across different Unix-like systems, avoiding Bash-specific features can be beneficial.

SCRIPT_PATH=`dirname "$0"`; SCRIPT_PATH=`eval "cd \"$SCRIPT_PATH\" && pwd"`

This uses eval to correctly handle the cd command and pwd to get the absolute path.

Solution 12: The pwd After cd Method

Another reliable method involves changing the directory to the script’s location and then using pwd.

DIRECTORY=$(cd `dirname $0` && pwd)
echo $DIRECTORY

This is a clean and effective approach that works on most platforms.

Solution 13: POSIX Compliant Symlink Resolution

For a POSIX-compliant way to handle symbolic links, you can use a loop with readlink.

PRG="$0"
while [ -h "$PRG" ] ; do
   PRG=`readlink "$PRG"`
done
scriptdir=`dirname "$PRG"`

This loop iteratively resolves symbolic links until it finds the actual script file.

Solution 14: Using which and dirname

The which command can help locate the executable in the system’s PATH, and then dirname can extract its directory.

path="$( dirname "$( which "$0" )" )"

This is useful when the script might be in a directory listed in the $PATH environment variable.

Solution 15: The $_ Variable in Bash

In Bash, the $_ variable often holds the last argument of the previous command, which can sometimes be the script path itself.

DIR="$( dirname "$_" )"

This method is concise but must be the very first statement in your script for reliability.

Solution 16: Detailed Symlink and Path Extraction with realpath

For comprehensive path and filename extraction, including handling symlinks and extracting file extensions, realpath is a powerful tool.

FULL_PATH_TO_SCRIPT="$(realpath "${BASH_SOURCE[0]}")"
SCRIPT_DIRECTORY="$(dirname "$FULL_PATH_TO_SCRIPT")"
SCRIPT_FILENAME="$(basename "$FULL_PATH_TO_SCRIPT")"
SCRIPT_FILENAME_STEM="${SCRIPT_FILENAME%.*}"        # withOUT the extension
SCRIPT_FILENAME_EXTENSION="${SCRIPT_FILENAME##*.}"  # JUST the extension

echo "FULL_PATH_TO_SCRIPT:       $FULL_PATH_TO_SCRIPT"
echo "SCRIPT_DIRECTORY:          $SCRIPT_DIRECTORY"
echo "SCRIPT_FILENAME:           $SCRIPT_FILENAME"
echo "SCRIPT_FILENAME_STEM:      $SCRIPT_FILENAME_STEM"
echo "SCRIPT_FILENAME_EXTENSION: $SCRIPT_FILENAME_EXTENSION"

This provides a complete set of information about the script’s location and name.

Solution 17: Linux-Specific /proc Filesystem

On Linux systems, you can leverage the /proc filesystem to find the resolved path of the running script.

resolved="$(readlink /proc/$$/fd/255 && echo X)" && resolved="${resolved%$'\nX'}"
dir=$(dirname -- "$resolved" && echo x) && dir=${dir%?x}
file=$(basename -- "$resolved" && echo x) && file=${file%?x}

This method is efficient on Linux but not portable to other operating systems.

Solution 18: Cross-Compatible cd and pwd with BASH_SOURCE

A highly portable and reliable method combines cd, pwd, and ${BASH_SOURCE[0]}.

CWD="$(cd -P -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)"

This approach is recommended for its robustness and compatibility.

### FAQs on How to Get Bash Script Directory

Q: What is the most reliable way to get the Bash script's directory

ANS: The most reliable methods often involve readlink -f combined with ${BASH_SOURCE[0]} or a recursive loop to handle symbolic links, such as actual_path=$(readlink -f "${BASH_SOURCE[0]}") followed by script_dir=$(dirname "$actual_path").

Q: How does BASH_SOURCE differ from $0

ANS: $0 represents the command as it was invoked, which might be a relative path or just the script name. ${BASH_SOURCE[0]} provides the actual path to the script file, which is crucial for sourcing scripts or when the script is called indirectly.

Q: Can these methods handle spaces in directory names

ANS: Yes, by ensuring that all path components are properly quoted, such as in cd "$( dirname -- "${BASH_SOURCE[0]}" )".

Q: What if the script is a symbolic link

ANS: Methods using readlink -f or a loop that explicitly resolves symbolic links will correctly determine the actual script’s directory even if it’s invoked through a symlink.
