“Shell Scripting: Techniques for Dynamic Terminal Output Progress Bars and Spinners”

Creating visually engaging feedback during lengthy processes in a shell environment is crucial for user experience. How can developers implement dynamic progress indicators, such as updating text on a single line, displaying spinners, or rendering sophisticated progress bars in Bash or POSIX-compliant shells? This collection presents various effective solutions for achieving real-time terminal output manipulation.

Overwriting Output with Carriage Return (\r)

A fundamental technique for in-place line updates relies on the carriage return character (\r). This special character moves the cursor to the beginning of the current line without advancing to the next line, allowing subsequent output to overwrite previous content.

Simple Percentage Progress Update (Solution 1)

To create an updating percentage indicator, output the progress indicator followed by \r. Ensure you use echo -ne to prevent the automatic newline insertion and to allow interpretation of escape sequences like \r. A final echo -ne '\n' is needed once the process is complete to move the cursor to the next line cleanly.

A known issue arises when a shorter status message overwrites a longer one; the trailing characters from the long message remain visible. The fix involves explicitly padding the shorter message with spaces to match or exceed the length of the longest possible message.

Demo Example for Percentage Update:

# Initializing the update process
echo -ne 'Processing... (0%)\r'
sleep 1

# Update 1 (33%)
echo -ne 'Processing... (33%)\r'
sleep 1

# Update 2 (66%) - Note the explicit spacing to clear previous output visually if needed, though \r handles the start position
echo -ne 'Processing... (66%)\r'
sleep 1

# Update 3 (100%) - Finalize and move to a new line
echo -ne 'Processing... (100%)\r'
echo -e '\nOperation Complete!'

Implementing Dynamic Load Spinners (Solution 2, Solution 23, Solution 29)

Spinners provide a simple visual cue that a process is active, especially when absolute progress percentage is hard to calculate.

Basic Bash Spinner using String Slicing (Solution 2)

A simple spinner cycles through a set of characters (/-\|). The key is using \b (backspace) or \r to return the cursor one position or to the start of the line, respectively, before printing the next character.

# Basic Bash Spinner Implementation
i=1
sp="/-\|"
echo -n ' Loading: '
while true
do
    # Print the next character from the string, cycling through indices
    printf "\b${sp:i++%${#sp}:1}"
    sleep 0.1
done

POSIX Equivalent Spinner (Solution 2 Alternative):

A more POSIX-friendly approach avoids specific Bash string manipulation features:

sp='/-\|'
printf ' Loading: '
while true; do
    printf '\b%.1s' "$sp"
    # Rotate the string: move the first character to the end
    sp=${sp#?}${sp%???}
    sleep 0.1
done

Spinner within a Loop with Function Abstraction (Solution 2)

For integration into larger loops, abstracting the spinner logic into reusable functions (spin and endspin) is effective:

sp="/-\|"
sc=0
spin() {
   printf "\b${sp:sc++:1}"
   ((sc==${#sp})) && sc=0
}
endspin() {
   printf "\r%s\n" "$@"
}

# Example usage within a loop
# while work_is_not_done; do
#    spin
#    perform_some_task ...
# done
# endspin "Task finished"

Advanced Spinner with UTF-8 Braille Characters (Solution 2, Part 2)

High-resolution console output can be achieved using UTF-8 characters, such as Braille patterns, for a visually richer spinner. This often involves using specific hexadecimal Unicode escapes like \U28XX.

# Example using growing snake pattern with braille characters
spinner(){
    local pnt=0 
    # Sequence of hex values for braille characters
    local shs=( 01 08 10 20 80 40 04 02 09 18 30 a0 c0 44 06 03 ... ) 
    printf '\e7' # Save cursor position
    while ! read -sn 1 -t .2 _; do
        # Print the corresponding UTF-8 character, cycling through the array
        printf %b\e8  \U28${shs[pnt++%${#shs[@]}]}
    done
}

Spinner Tied to a Background Process (Solution 2)

A spinner can monitor the activity of another background process (PID) using kill -0 to check if the process is still alive.

function spinner() {
  local PID="$1"
  local str="${2:-Processing!}"
  local delay="0.1"
  while ( kill -0 $PID 2>/dev/null ); do
      # Cycle through visual indicators, updating status periodically
      printf "\r[...$str...]"
      sleep "$delay"
  done
  printf "\r[ Done! ]\n"
}

# Usage:
sleep 20 &amp; # Run a long task in background
spinner $! 'Working on data' # Monitor the background process $!

Creating Percentage Progress Bars

For applications where total work is known, progress bars offer precise feedback.

Fixed-Length ASCII Progress Bar (Solution 8, Solution 12)

A common pattern is to calculate the number of characters needed for the filled portion of the bar based on the current progress percentage against a fixed bar width.

PROGRESS_BAR_WIDTH=50

draw_progress_bar() {
  local __value=$1
  local __max=$2
  local __unit=${3:-""}
  
  # Calculate percentage (integer arithmetic)
  local __percentage=$(( (100 - ($__max*100 - $__value*100) / $__max) ))

  # Determine how many characters to fill
  local __num_bar=$(( $__percentage * $PROGRESS_BAR_WIDTH / 100 ))

  printf "["
  # Print filled characters
  for b in $(seq 1 $__num_bar); do printf "#"; done
  # Print remaining space characters
  for s in $(seq 1 $(( $PROGRESS_BAR_WIDTH - $__num_bar ))); do printf " "; done
  
  printf "] $__percentage%% ($__value / $__max $__unit)\r"
}

Custom Function with UTF-8 High-Resolution Blocks (Solution 5)

For finer granularity, advanced solutions utilize UTF-8 block characters (e.g., Unicode \U2588 for full block) and calculate fractional parts to render blocks that are partially filled (e.g., quarters or eighths of a character width).

Custom Function with Floating Point Percentage (Solution 5)

To calculate percentages with high precision, integer arithmetic must be augmented, often by multiplying by a large factor (like 10000) before division to emulate floating-point math.

# Function to compute pseudo-floating point percentage for high-res display
percent(){
    local p=00$(($1*100000/$2))
    # Format p to X.XX format using parameter expansion
    printf -v "$3" %.2f ${p::-3}.${p: -3}
}

Simple Time-Based Progress Bar (Solution 6, Solution 25)

If the duration of an operation is known, progress can be tracked simply based on elapsed time, independent of the actual work units.

# Simple time-based bar (duration in seconds)
progress_bar() {
  local duration=$1
  for (( elapsed=1; elapsed<=$duration; elapsed++ )); do
      # Calculate filled portion based on elapsed time vs total duration
      local done_count=$(( elapsed * 20 / duration )) # Example width of 20 chars
      local remain_count=$(( 20 - done_count ))
      
      printf "\r[%s%s] | %s%%" \
        "$(printf '#%.0s' $(seq 1 $done_count))" \
        "$(printf ' %.0s' $(seq 1 $remain_count))" \
        "$(( (elapsed * 100) / duration ))"
      sleep 1
  done
  printf "\n"
}
# Usage: progress_bar 100

APT-Style Persistent Progress Bar (Solution 9)

For output that must persist at the bottom of the terminal without interfering with standard program output, terminal control sequences (tput or ANSI escape codes) are necessary to manage the scrolling region.

This technique saves the cursor position, sets a limited scroll region (usually excluding the last line), draws the bar on the bottom line, and restores the cursor, ensuring subsequent output appears below the bar area.

Using External Utilities for Pipeline Monitoring

Several external command-line utilities are designed specifically for monitoring data flowing through pipelines:

  • pv (Pipe Viewer): Displays transfer rate, elapsed time, and a progress bar. It is often used inline with commands like dd or tar. (Solution 4, Solution 11, Solution 17, Solution 26)

    # Example using pv to monitor data transfer:
tar -cf - ./large_directory | pv -l -s $(find ./large_directory | wc -l) | gzip > backup.tar.gz

  • bar: Another utility similar to pv, capable of monitoring file stream progress, sometimes with process substitution. (Solution 17)

  • tqdm (Python): A powerful Python library that can wrap iterables or monitor pipeline input streams, providing highly customizable progress bars directly from standard output streams. (Solution 20)

    # Monitor tar output if it produces line-by-line data
7z a -r -bd newZipFile myFolder | tqdm --total $(find myFolder -type f | wc -l) >> /dev/null

Monitoring External Process Progress

When a command like cp or dd runs in the background, monitoring its progress requires checking filesystem attributes or using signals.

Using lsof to Check File Offset (Solution 7)

For commands interacting with files (like wc or dd), lsof can report the current read pointer offset for a file descriptor, allowing for manual percentage calculation against the source file size.

Using dd Signals (Solution 30)

On systems where dd supports it (often Linux), sending a SIGUSR1 signal to the dd process ID causes it to print its current transfer statistics to standard error. A wrapper script can poll the PID and read these updates.

Graphical Feedback in Desktop Environments

For GUI-integrated scripts, tools offering native desktop integration are preferred:

  • dialog: Used heavily in installer scripts, it supports a --gauge parameter to display percentage values within a text-mode user interface (TUI) widget. (Solution 21)

    for i in {1..100}; do sleep 0.1; echo $i | dialog --gauge "Waiting..." 7 50; done

  • zenity: Provides graphical dialog boxes for shell scripts in GNOME environments, including a --progress feature driven by piped input. (Solution 22)

    ( echo "25"; sleep 1; echo "50" ) | zenity --progress --title="File Operation"
