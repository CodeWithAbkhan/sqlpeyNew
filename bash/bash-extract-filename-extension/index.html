“Bash Scripting: Efficiently Extract Filenames and Extensions”

When working with file paths in Bash scripts, a common requirement is to isolate the filename itself, or to separate the filename from its extension. This can become tricky with filenames that contain multiple dots, hidden files (starting with a dot), or no extension at all. Fortunately, Bash offers powerful parameter expansion capabilities, and several other command-line utilities can also achieve this. Let’s explore various methods to tackle this task effectively.

Solution 1: Using basename and Parameter Expansion

This approach first extracts the filename with its extension using basename and then uses Bash’s parameter expansion to remove the extension.

#!/bin/bash

# Assume a full path is stored in the variable
fullfile="/path/to/some/directory/example.document.txt"

# Get the filename with extension
filename_with_ext=$(basename -- "$fullfile")

# Remove the extension to get the base filename
base_filename="${filename_with_ext%.*}"

# You can also get the extension separately
extension="${filename_with_ext##*.}"

echo "Full path: $fullfile"
echo "Filename with extension: $filename_with_ext"
echo "Base filename: $base_filename"
echo "Extension: $extension"

Alternative within Solution 1: If you only need the filename and want to avoid relying on the extension being present (e.g., for files without extensions), you can directly use parameter expansion on the fullfile variable.

#!/bin/bash

fullfile="/path/to/another/file" # No extension

# Get the filename without the path
filename_only="${fullfile##*/}"

# Get the filename without the extension (if any)
base_filename_only="${filename_only%.*}"

echo "Full path: $fullfile"
echo "Filename only: $filename_only"
echo "Base filename only: $base_filename_only"

For a deeper dive into shell parameter expansion, consult the Bash manual’s “Parameter Expansion” section .

Solution 2: Pure Bash Parameter Expansion (Handling Multiple Dots)

Bash’s parameter expansion offers a concise way to handle filenames with multiple extensions.

#!/bin/bash

FILE="archive.tar.gz"

# Get the filename without the longest suffix starting with a dot
echo "Filename without last extension: ${FILE%%.*}" # Output: archive.tar

# Get the filename without any suffix starting with a dot
echo "Filename without all extensions: ${FILE%.*}" # Output: archive.tar

# Get the extension
echo "Last extension: ${FILE##*.}" # Output: gz

Caveat: If a filename starts with a dot and has no other dots (e.g., .bashrc), %%.* might behave unexpectedly. A more robust approach for such cases is shown in Solution 5.

Solution 3: Using basename with a Specified Extension

The basename command can also remove a specific suffix if provided. This is useful if you know the exact extension to remove.

#!/bin/bash

# Example with a known extension
full_path="/path/to/data.csv"
extension_to_remove=".csv"

# Get the filename without the specified extension
file_base=$(basename "$full_path" "$extension_to_remove")

echo "Original path: $full_path"
echo "Filename base: $file_base"

This method is straightforward when the extension is predictable, as often seen with archive files like .tar.gz.

Solution 4: Advanced Bash Parameter Expansion for Robustness

This solution addresses some edge cases that simpler parameter expansions might miss, such as filenames without extensions or hidden files.

#!/bin/bash

for fullpath in "$@"
do
    # Extract the filename from the full path
    filename="${fullpath##*/}"

    # Determine the directory part
    # This calculates the length of the full path minus the length of the filename
    dir="${fullpath:0:${#fullpath} - ${#filename}}"

    # Strip the shortest match of '.plus_at_least_one_non_dot_char' from the end for the base
    base="${filename%.[^.]*}"

    # Extract the extension
    ext="${filename:${#base} + 1}"

    # Handle cases like ".bashrc" where filename is also the base
    if [[ -z "$base" && -n "$ext" ]]; then
        base=".$ext"
        ext=""
    fi

    printf "%s:\n\tdir  = \"%s\"\n\tbase = \"%s\"\n\text  = \"%s\"\n" "$fullpath" "$dir" "$base" "$ext"
done

Example Usage:

./script_name.sh /home/user/documents/report.pdf /etc/nginx/nginx.conf ./my_script.sh

This provides a more reliable way to parse path components.

Solution 5: Using sed for Pattern-Based Extraction

sed is a powerful stream editor that can use regular expressions to extract components.

#!/bin/bash

FILE="example.archive.tar.gz"

# Extract filename without the last two extensions (e.g., .tar.gz)
echo "$FILE" | sed -r 's/\.[^.]*$//' # Removes the last extension only
echo "$FILE" | sed -r 's/\.[^.]*\.[^.]*$//' # Removes the last two extensions

# Extract the last extension
echo "$FILE" | sed -r 's/^.*\.//'

The -r flag enables extended regular expressions, making the patterns more readable. The first sed command (s/\.[^.]*$//) removes the last dot followed by any non-dot characters until the end of the string. The second (s/\.[^.]*\.[^.]*$//) is more specific for double extensions. The third (s/^.*\.//) captures everything from the start up to the last dot.

Solution 6: Using awk for Advanced Parsing

awk is another versatile tool for text processing, capable of sophisticated parsing.

#!/bin/bash

f='/path/to/complex/file.1.0.1.tar.gz'

# Extract the filename (basename)
echo "$f" | awk -F'/' '{print $NF}'

# Extract the last extension (e.g., gz)
echo "$f" | awk -F'[.]' 'NF>1 {print $NF}'

# Extract the filename without the last extension
echo "$f" | awk '{gsub(/.*[/]|(\.[^.]*$)/, "", $0)} 1'

awk uses field separators (-F) to break down strings, allowing for targeted extraction.

Solution 7: Mimicking Python’s os.path.splitext

For those familiar with Python, Bash can replicate the behavior of os.path.splitext.

#!/bin/bash

path="path/to/archive.tar.gz"

# Split into root and extension
root="${path%.*}"
ext="${path#"$root"}"

echo "Root: $root" # Output: path/to/archive.tar
echo "Extension: $ext" # Output: .gz

This method isolates the last extension, including the leading dot, and provides the rest of the path as the root.

Solution 8: A Robust Bash Function

For recurring needs, encapsulating the logic into a Bash function offers reusability and clarity.

#!/bin/bash

# Function to split a path into directory, basename, root, and extension
# Usage: splitPath '/path/to/file.ext' dir_var base_var root_var ext_var
splitPath() {
  local _sp_dirname= _sp_basename= _sp_basename_root= _sp_suffix=
  (( $# >= 2 )) || { echo "Usage: splitPath <path> <dir_var> [base_var] [root_var] [ext_var]" >&2; return 1; }

  local fullpath="$1"
  _sp_dirname=$(dirname "$fullpath")
  _sp_basename=$(basename "$fullpath")

  # Determine suffix, if any
  _sp_suffix=$([[ "$_sp_basename" == *.* ]] && printf ".${_sp_basename##*.}" || printf '')

  # Determine basename root (filename without suffix)
  if [[ "$_sp_basename" == "$_sp_suffix" ]]; then # Handles hidden files like .bashrc
    _sp_basename_root=$_sp_basename
    _sp_suffix=''
  else
    _sp_basename_root=${_sp_basename%$_sp_suffix}
  fi

  # Assign to output variables
  [[ -n "$2" ]] && printf -v "$2" "$_sp_dirname"
  [[ -n "$3" ]] && printf -v "$3" "$_sp_basename"
  [[ -n "$4" ]] && printf -v "$4" "$_sp_basename_root"
  [[ -n "$5" ]] && printf -v "$5" "$_sp_suffix"
  return 0
}

# Example usage:
test_path="/home/user/data/report_v2.1.txt"
splitPath "$test_path" parent_dir filename_only base_name extension

echo "Original Path: $test_path"
echo "Parent Directory: $parent_dir"
echo "Filename Only: $filename_only"
echo "Base Name: $base_name"
echo "Extension: $extension"

This function is designed to handle various edge cases, including dotfiles and trailing slashes, offering a robust solution for complex path manipulations.

Solution 9: Using cut for Simple Extension Removal

The cut command can also be used, though it’s generally less flexible than parameter expansion or sed for intricate patterns.

#!/bin/bash

FILE="image.jpg"

# Remove the last extension using cut
# The --complement option selects all fields except the specified ones.
# -f2- means fields starting from the second one.
echo "$FILE" | cut -d'.' --complement -f2-

This works well for simple cases but can falter with multiple extensions or filenames without extensions.

Solution 10: Using rev and cut

A clever approach involves reversing the string, using cut to isolate the reversed extension, and then reversing it back.

#!/bin/bash

FILE="document.backup.zip"

# Reverse the string, cut the first field (reversed extension), reverse back
echo "$FILE" | rev | cut -d'.' -f2- | rev

This method effectively isolates parts of the string based on the delimiter.

FAQs on Bash Filename and Extension Extraction

Q: How to get just the filename without the path using Bash

ANS: You can use Bash parameter expansion: filename_only="${full_path##*/}". This removes the longest match of */ from the beginning of the string.

Q: What is the Bash parameter expansion to remove the file extension

ANS: To remove the last extension (e.g., .txt from file.txt), use ${filename%.*}. If the filename has multiple extensions (e.g., archive.tar.gz), ${filename%.*} would yield archive.tar.

Q: How to extract the file extension in Bash

ANS: Use Bash parameter expansion: extension="${filename##*.}". This removes the shortest match of *. from the beginning, leaving the extension. For example, ${myfile.tar.gz##*.} yields gz.

Q: Can Bash handle filenames with multiple dots like archive.tar.gz

ANS: Yes, Bash parameter expansion can handle this. ${filename%%.*} removes the longest match of .* from the end, effectively getting archive.tar. To get just the last extension, use ${filename##*.} which would give gz.

Q: How to handle filenames without extensions using Bash parameter expansion

ANS: Parameter expansions like ${filename%.*} will return the original filename if no dot is present, which is generally the desired behavior for filenames without extensions.
