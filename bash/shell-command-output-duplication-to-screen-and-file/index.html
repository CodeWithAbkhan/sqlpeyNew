“Shell Command Output Duplication to Screen and File Using Tee”

Executing long-running shell commands often necessitates seeing the live progress on the terminal while preserving the complete execution transcript in a file. Standard redirection (>) captures the output but silences the console view. What is the most robust technique for duplicating both standard output (stdout) and standard error (stderr) streams to both the screen and a persistent log file?

Primary Technique: Leveraging the tee Utility

The Unix utility tee is specifically designed for this purpose: reading from standard input and writing simultaneously to standard output and one or more files.

Capturing Only Standard Output (stdout)

To pipe the standard output of a command to both the screen and a specified file:

my_process_command --options | tee console_and_log.txt

For example, listing directory contents while logging only the output:

ls -a | tee directory_listing.log

Including Standard Error (stderr)

When a process generates errors (stderr) that you also need captured alongside stdout, you must first merge the stderr stream into the stdout stream before piping to tee. This is achieved using the redirection 2>&1.

The structure for merging and piping both streams:

long_running_script.sh arguments 2>&1 | tee combined_output.log

This syntax directs file descriptor 2 (stderr) to file descriptor 1 (stdout), ensuring both flow into the pipe, where tee then splits them to the console and combined_output.log.

Appending Output Instead of Overwriting

If the goal is to add the new output to the end of an existing file rather than replacing its contents, use the -a (append) flag with tee:

system_check.py --verbose 2>&1 | tee -a persistent_log.txt

This is critical when aggregating output from multiple executions into a single record.

Alternative Redirection Syntaxes

While 2>&1 | tee is common, shell features offer slightly cleaner syntax in some environments.

Using |& in Bash/Zsh (Shorthand for Merging Streams)

In modern Bash or Zsh shells, the sequence |& serves as a concise shorthand for 2>&1 |. It directly pipes both stdout and stderr through the pipe.

database_migration.py |& tee migration_details.log

This syntax is often preferred for its brevity, as noted in the GNU Bash manual:

If ‘|&’ is used, command1’s standard error, in addition to its standard output, is connected to command2’s standard input through the pipe; it is shorthand for 2>&1 |.

This worked well for capturing Java process logs concurrently:

./run_java_application.sh |& tee application.log

Addressing Stream Buffering Issues

A significant challenge when monitoring long-running processes that send sporadic output is stream buffering. If output isn’t immediately flushed by the originating program, the user might see nothing on the screen for extended periods, even if data is accumulating in the pipe buffer.

The unbuffer utility, part of the expect package, can resolve this by forcing pseudo-terminal behavior, which typically mandates immediate flushing of stdout and stderr:

unbuffer long_task_script.sh 2>&1 | tee monitor.log

This ensures that output appears on the screen and in the file nearly instantaneously, keeping streams synchronized, though compatibility with unbuffer can vary across different Unix distributions like Fedora or Red Hat.

Advanced Scenarios

Executing Commands as Another User

When needing to write the output directly to a file owned by a different user (and requiring elevated permissions), use sudo with tee -a. Critically, the redirection must be part of the tee command, not the initial command, because standard shell redirection (>) is processed by the current shell before sudo takes effect.

echo "System status update" | sudo -u service_account tee -a /var/log/secure_service.log

In this case, echo runs as the current user, but tee executes as service_account, granting the necessary file write permission.

Duplicating Output Within a Script Structure

For scenarios where you want this behavior applied globally to an entire shell script without modifying every command line, a header block can be placed at the top of the script:

#!/usr/bin/env bash

# Check if this is the initial execution or the restarted execution (using null byte trick)
test x$1 = x$'\x00' && shift || { 
    # Setup pipefail, merge stderr to stdout, execute the script again via tee
    set -o pipefail ; 
    ( exec 2>&1 ; "$0" $'\x00' "$@" ) | tee execution_trace.log ; 
    exit $? ; 
}

Non-tee Alternative (Using /dev/tty)

In specific environments where tee might be unavailable or if you need precise control over where stdout goes, you can explicitly direct output to both the terminal device (/dev/tty) and the log file using multiple redirections:

echo "Important status" > /dev/tty > logfile_only.txt

Here, /dev/tty receives the standard output, which appears on the screen, and then the output is immediately overwritten to logfile_only.txt. Note that this method only handles stdout by default; stderr still requires merging (2>&1).

Simple Concatenation (Less Recommended)

A highly manual approach involves redirecting output to a file first, and then using cat to display the file contents while appending them back to the terminal output stream:

ls -lr / > output_temp | cat output_temp

This is inefficient as it involves intermediate file I/O for real-time viewing.

FAQs on Shell Command Output Duplication

Q: What is the primary utility for showing output while saving it

ANS: The primary utility for simultaneously displaying command output to the console and writing it to a file is tee.

Q: How do I ensure both errors and normal output are logged

ANS: Merge standard error (stderr) into standard output (stdout) using 2>&1 before piping the result to tee, for example: command 2>&1 | tee log.txt.

Q: What flag should I use with tee to avoid overwriting an existing log file

ANS: Use the -a flag with tee to append output to the existing file: command | tee -a log.txt.

Q: Is there a shorter way to merge stdout and stderr in Bash

ANS: Yes, using the |& operator is a shorthand for 2>&1 | when piping to the next command, like command |& tee log.txt.

Q: How can I solve issues where output appears delayed when using tee

ANS: Delayed output often results from stream buffering. Using the unbuffer command before the pipe can force immediate flushing: unbuffer command 2>&1 | tee log.txt.
