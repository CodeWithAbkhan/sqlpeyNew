“Bash Dynamic Variable Names: Techniques and Best Practices”

In Bash scripting, there are several effective ways to manage situations where you need to construct variable names dynamically. This is often useful when processing lists of items, configuration files, or when dealing with system state where parts of variable names might change. Let’s explore these methods and their nuances.

Understanding Dynamic Variable Names in Bash

The core challenge is to use a string, which is itself a variable or an expression, to determine which variable to read from or write to. This is commonly referred to as “indirect expansion” or “variable variables.”

Solutions

Methods for Dynamic Variable Access

Here are various techniques to achieve dynamic variable naming in Bash, ranging from older, widely compatible methods to more modern and robust approaches.

Solution 1: Indirect Expansion with ${!var}

This is a fundamental Bash feature allowing you to use the value of one variable as the name of another.

Scenario: You have a suffix and want to create a variable named prefix_ followed by that suffix.

suffix=bzz
declare prefix_${suffix}=mystr  # Creates a variable named prefix_bzz with value mystr

varname=prefix_${suffix}
echo ${!varname}              # Outputs: mystr

Explanation:

  • declare prefix_${suffix}=mystr: This line creates a variable. The ${suffix} part is expanded first, so it’s equivalent to declare prefix_bzz=mystr.
  • varname=prefix_${suffix}: Here, varname stores the string prefix_bzz.
  • echo ${!varname}: This is the indirect expansion. Bash sees ${!varname}, takes the value of varname (which is prefix_bzz), and then expands that to get the value of the variable named prefix_bzz.

Reference: For a deeper dive into parameter expansion, consult the BashFAQ on Indirection .

Solution 2: Associative Arrays (Bash 4+)

Associative arrays offer a more structured way to handle dynamic key-value pairs, where the keys can be arbitrary strings.

Scenario: Storing results of operations mapped to command names.

# Requires Bash 4+
declare -A magic_variable=()

function grep_search() {
    # Sets a variable inside the associative array
    magic_variable["$1"]=$(ls | tail -1)
    echo ${magic_variable["$1"]}
}

# Example usage:
grep_search my_file_var # 'my_file_var' becomes a key in the associative array
echo ${magic_variable["my_file_var"]}

For older Bash versions (pre-4): You can simulate this using declare and indirect expansion.

# For Bash < 4
function grep_search_old() {
    declare "magic_variable_$1=$(ls | tail -1)"
    var="magic_variable_$1"
    echo "${!var}"
}

# Example usage:
grep_search_old another_var
echo ${!another_var} # This would access the dynamically created variable

Solution 3: eval Command (Use with Caution)

The eval command executes its arguments as a shell command. While powerful, it can be dangerous if not used carefully, as it can execute arbitrary code.

Scenario: Aliasing a variable named var_37.

i=37
name="var_$i"

# Reading the value
echo "${!name}"  # Outputs: lolilol (assuming var_37 is set to lolilol)

# Assigning a value safely using printf (preferred over eval for assignment)
value='babibab'
printf -v "$name" '%s' "$value"
echo "$var_37"   # Outputs: babibab

# Assigning with eval (less safe, requires careful escaping)
# eval "$name"='$value'  # Use printf -v instead for safer assignment

Downsides of eval:

  • Can execute unintended code if input is not sanitized.
  • Makes code harder to read and debug.
  • Potential security risks.

Solution 4: printf -v for Safe Assignments

This is generally the safest and recommended method for assigning values to dynamically named variables.

Scenario: Assigning a value to a variable whose name is constructed from parts.

i=37
name="var_$i"
value='babibab'

printf -v "$name" '%s' "$value"
echo "$var_37" # Outputs: babibab

Explanation:

  • printf -v target_variable 'format_string' value: The -v option tells printf to assign the formatted output to target_variable instead of printing it to standard output.
  • "$name": The variable name (e.g., var_37) is passed directly.

Solution 5: declare -n (Bash 4.3+) for Name References

This is a modern and elegant solution that creates a “name reference” to another variable. It’s like a pointer in C but for variable names.

Scenario: Referencing environment variables based on a runtime branch name.

# Assuming BRANCH_NAME is set, e.g., BRANCH_NAME="DEV"

# Creates a reference named _AWS_ACCESS_KEY_ID_REF that points to AWS_ACCESS_KEY_ID_DEV
declare -n _AWS_ACCESS_KEY_ID_REF=AWS_ACCESS_KEY_ID_${BRANCH_NAME}

# Accessing the referenced variable's value
echo ${_AWS_ACCESS_KEY_ID_REF}

Benefits:

  • Clean syntax.
  • Handles both reading and assignment directly.
  • More robust than eval.

Caution: Ensure your Bash version supports declare -n (version 4.3 and later).

Solution 6: Using envsubst

The envsubst command substitutes environment variables in a template. You can use it to indirectly resolve variable names.

Scenario: Constructing a variable name with a dynamic part.

dynamic_part="my_setting"
# Create a temporary file or use echo to provide the template
temp_var_name='$'"magic_variable_${dynamic_part}" # Note the quoting to prevent early expansion

newvar=$(echo "$temp_var_name" | envsubst)
echo "$newvar" # Outputs: magic_variable_my_setting

This method primarily helps in constructing the variable name string itself, which can then be used with other indirect methods.

Solution 7: Simple Concatenation and eval (KISS Approach)

For very simple cases, direct string concatenation followed by eval can work, but still carries the risks of eval.

Scenario: Creating a variable like bam1.

a=1
c="bam"
eval "$c$a"=4 # Creates variable bam1 with value 4
echo $bam1     # Outputs: 4

Solution 8: Using export with env (for specific cases)

If you are defining variables that need to be available in subprocesses, using export with a dynamic name can be useful.

Scenario: Dynamically exporting a variable.

function dynamic(){
  export a_$1="bla" # Creates and exports variable like a_2
}

dynamic 2
echo $a_2 # Outputs: bla

Note: This method relies on export and might not be suitable for all internal script logic. It also has limitations with spaces in arguments.

Solution 9: Zsh-Specific Syntax ${(P)var}

If you are using Zsh, it offers a more direct way to handle indirect expansion using the (P) flag.

real_var="holaaaa"
aux_var="real_var"
echo ${(P)aux_var} # Outputs: holaaaa

This is specific to Zsh and won’t work in Bash.

Solution 10: POSIX Compliant Method with set -a and Temporary Files

For maximum portability across POSIX-compliant shells, you can leverage temporary files and the set -a option.

Scenario: Defining variables from a file.

#!/bin/sh
ENV_FILE="/tmp/$(date +%s)_vars" # Unique temp file name

MY_KEY=foo
MY_VALUE=bar

echo "$MY_KEY=$MY_VALUE" >> "$ENV_FILE"

# Make variables in the file exportable
set -a
. "$ENV_FILE" # Source the file
set +a      # Turn off export attribute
rm "$ENV_FILE" # Clean up

echo "$foo" # Outputs: bar

Explanation:

  • set -a (or set -o allexport): Marks all subsequent variables created or modified as exported.
  • . "$ENV_FILE" (or source "$ENV_FILE"): Executes commands from the specified file in the current shell. When combined with set -a, it exports the variables defined in the file.
suffix=bzz
declare prefix_$suffix=mystr
varname=prefix_$suffix
echo ${!varname}

Risks and Best Practices

While dynamic variables can be powerful, they come with inherent risks:

  • Code Injection: Using eval or similar methods with unsanitized input can lead to arbitrary code execution. Always validate and sanitize inputs used to construct variable names.
  • Readability: Overuse of dynamic variables can make scripts difficult to understand, debug, and maintain. Consider if arrays or functions offer a cleaner alternative.
  • Cyclic References: Be cautious not to create situations where a variable indirectly refers to itself, which can lead to infinite loops or unpredictable behavior.

Recommendations:

  • Prefer declare -n (Bash 4.3+) or printf -v: These are generally safer and more readable options for modern Bash scripting.
  • Use Associative Arrays: For collections of dynamically named data, associative arrays are idiomatic and robust.
  • Avoid eval when possible: If eval is necessary, ensure meticulous input validation and escaping.
  • Consider Functions: Often, a function can achieve the same result as dynamic variables more cleanly.
# Requires bash 4, though
declare -A magic_variable=()

function grep_search() {
    magic_variable[$1]=$( ls | tail -1 )
    echo ${magic_variable[$1]}
}
declare "magic_variable_$1=$(ls | tail -1)"
var="magic_variable_$1"
echo "${!var}"

FAQs on Bash Dynamic Variables

Q: What is indirect expansion in Bash

ANS: Indirect expansion in Bash uses the syntax ${!variable} to access the value of the variable whose name is stored in variable.

Q: How to assign a value to a dynamic variable name in Bash

ANS: The printf -v varname '%s' value command is a safe and recommended way to assign a value to a variable whose name is stored in varname. Bash 4.3+ also offers declare -n ref=varname which allows direct assignment to the referenced variable.

Q: Are associative arrays supported in all Bash versions

ANS: Associative arrays were introduced in Bash version 4.0. For older versions, you need to use indirect expansion or simulate them.

Q: What are the security risks of using eval in Bash

ANS: Using eval with untrusted input can lead to arbitrary code execution, making your scripts vulnerable to attacks. It’s crucial to sanitize any input used with eval.

Q: Is there a POSIX compliant way to handle dynamic variables

ANS: Yes, using set -a to enable the export attribute and then sourcing a temporary file containing variable assignments (. temp_file) is a POSIX-compliant approach.

Q: How does declare -n differ from indirect expansion

ANS: declare -n creates a name reference, acting like a pointer. When you access or assign to the reference, Bash automatically resolves it to the target variable. Indirect expansion ${!var} requires the variable name itself to be constructed first, and then expanded. declare -n is generally cleaner for assignments.

function guillemots {
  declare -n var=&quot;$1&quot;
  var=&quot;«${var}»&quot;
}

arr=( aaa bbb ccc )
guillemots 'arr[1]'  # modifies the second cell of the array, as expected
guillemots 'arr[$(date&gt;&gt;date.out)1]'  # writes twice into date.out
            # (once when expanding var, once when assigning to it)
function guillemots {
  # var is intended to be local to the function,
  # aliasing a variable which comes from outside
  declare -n var=&quot;$1&quot;
  var=&quot;«${var}»&quot;
}
