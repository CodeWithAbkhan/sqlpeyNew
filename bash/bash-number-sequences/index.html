“Bash Scripting: Efficiently Generate Number Sequences in Shell”

When scripting in Bash, a common requirement is to iterate over a sequence of numbers. While the {start..end} brace expansion is intuitive for static ranges, using variables with this syntax often falls short. This post explores various methods for generating numeric sequences in Bash, discussing their intricacies, performance, and portability.

The core challenge often lies in dynamically creating a sequence where the start and end points are determined by variables. Let’s examine the different approaches presented, from straightforward utilities to more advanced Bash constructs.

Solution 1: The seq Command

A widely recognized and simple method for generating sequences is the seq command. It’s part of the GNU Coreutils package, making it readily available on most Linux systems.

END=10
for i in $(seq 1 $END); do echo $i; done

This command iterates from 1 up to the value of END, printing each number on a new line. The user edit notes a preference for seq due to its memorability.

Solution 2: Bash’s Built-in C-style Loop

Bash offers a more integrated approach with its C-style for loop, eliminating the need for external commands like seq. This method leverages Bash’s internal arithmetic evaluation.

END=5
for ((i=1; i<=END; i++)); do
    echo $i
done
# Outputs:
# 1
# 2
# 3
# 4
# 5

The for ((expr1; expr2; expr3)) construct is treated as arithmetic, similar to C and other languages. This avoids the overhead of creating a subshell for seq.

Solution 3: Enhanced Bash Loops with Integer Arithmetic

Building on the C-style loop, explicit integer declaration using typeset -i can improve clarity and prevent unexpected behavior with non-integer values. The while loop combined with arithmetic expansion is also a robust option.

# Using while with integer arithmetic
typeset -i i END
let END=5
i=1
while ((i<=END)); do
    echo $i
    let i++
done

# Using C-style loop with explicit integer types
typeset -i i END
for ((i=1; i<=END; ++i)); do echo $i; done

The eval echo "{1..$END}" approach uses command substitution with eval to overcome the limitation of brace expansion not working with variables directly. However, it requires a fork() for the command substitution, even though eval and echo are built-ins.

END=7
for i in $(eval echo "{1..$END}"); do
    echo $i
done

Solution 4: POSIX Compliance and Portability

For maximum portability across different shells, adhering to POSIX standards is recommended. This often means avoiding Bash-specific extensions.

#!/bin/sh

limit=4

# Using a POSIX-compliant while loop
i=1
while [ $i -le $limit ]; do
  echo $i
  i=$(($i + 1)) # Arithmetic expansion is POSIX
done

# Alternative using seq (if available and portability is not paramount)
# for i in $(seq 1 $limit); do
#   echo $i
# done

The provided explanation highlights that brace expansion ({a..b}) is strictly textual and evaluated before parameter expansion in Bash, hence its limitation with variables. Shells are described as hybrids of macro processors and programming languages, with optimizations leading to certain limitations.

Solution 5: The POSIX-Compliant while Loop

This solution offers a strictly POSIX-compliant method for generating number ranges, emphasizing clarity and avoiding common Bash extensions.

i=2
end=5
while [ $i -le $end ]; do
    echo $i
    # POSIX arithmetic expansion
    i=$(($i+1))
done
# Output:
# 2
# 3
# 4
# 5

It also clarifies which constructs are not POSIX: (( )) without $, [[ ]] (while [ is POSIX), for ((;;)), seq, {start..end} with variables, and let. The let command itself is not part of POSIX 7.

Solution 6: seq for Simple Sequences

A concise recap of using seq for straightforward numeric sequences.

END=8
for i in $(seq $END); do echo $i; done

Solution 7: eval with Brace Expansion

A direct method to enable brace expansion with variables using eval.

for i in $(eval echo {1..$END}); do
    # ... your code here ...
done

Solution 8: Performance Considerations and Benchmarking

An insightful analysis compares the performance of various looping mechanisms. The key takeaway is that seq and {..} (brace expansion) are generally fast, while for and while loops, especially with command substitutions $( ) or extensive arithmetic operations, can be slower.

The benchmarks presented illustrate that for large ranges, the overhead of external commands and repeated arithmetic can accumulate. However, for most typical scripting scenarios, the performance differences might be negligible.

Solution 9: Zero-Padding Numbers

For cases requiring zero-padded output, printf combined with sed can achieve this.

for ((i=7; i<=12; i++)); do echo `printf "%2.0d\n" $i |sed "s/ /0/"`;done
# Output:
# 07
# 08
# 09
# 10
# 11
# 12

Solution 10: seq and Brace Expansion Variations

This section provides a good overview of both seq and brace expansion syntax, including increment values and character ranges.

# Using seq with an increment
seq 1 2 10  # Outputs: 1 3 5 7 9

# Using brace expansion with an increment
echo {1..10..2} # Outputs: 1 3 5 7 9

# Brace expansion for characters
echo {a..z} # Outputs: a b c ... z

Solution 11: jot on BSD/OS X

For users on BSD or macOS, jot serves as an alternative to seq.

for i in $(jot $END); do echo $i; done

Solution 12: Bash while Loop with [[ ]]

A concise and readable Bash while loop utilizing the [[ ]] conditional construct.

END=5
i=1
while [[ $i -le $END ]] ; do
    echo $i
    ((i = i + 1)) # Bash arithmetic
done

Solution 13: Korn Shell (ksh93) Superiority

A comparison is drawn with ksh93, which natively supports brace expansion with variables, a feature lacking in standard Bash.

# In ksh93:
i=5
for x in {1..$i}; do echo "$x"; done
# Output: 1 2 3 4 5

Solution 14: Bridging Brace Expansion with Variables

This method uses a subshell to invoke Bash itself to interpret brace expansion with variables.

end=5
for i in $(bash -c "echo {1..${end}}"); do echo $i; done

Solution 15: bash-tricks range.bash Script

This solution introduces a helper script, range.bash, designed to provide a more robust and user-friendly range function, supporting variables and handling invalid ranges gracefully. It aims to mimic the {a..b} syntax with fewer “gotchas”.

# Assuming range.bash is sourced
source range.bash
one=1
ten=10

range {$one..$ten} # Supports variables and native syntax

The author emphasizes benefits like avoiding subshells, relying only on Bash language features, and better handling of non-numeric ranges compared to some other methods.

Solution 16: Handling Non-Numeric Ranges and Pipelining

This approach demonstrates how to generate non-numeric sequences (like characters) by constructing and executing a Bash command string within a pipeline.

RANGE_START=a
RANGE_END=z
# Construct the command string and pipe it to bash
echo -e "for i in {$RANGE_START..$RANGE_END}; do echo \\${i}; done" | bash

# Store the output in a variable
VAR=$(echo -e "for i in {$RANGE_START..$RANGE_END}; do echo \\${i}; done" | bash)

This method creates a new Bash instance, suitable for intensive operations.

Solution 17: Alternative C-style Loop Syntax

A variation on the C-style loop, using separate variables for start and end points.

tmpstart=0
tmpend=4

for (( i=$tmpstart; i<=$tmpend; i++ )) ; do
echo $i
done
# Output:
# 0
# 1
# 2
# 3
# 4

Solution 18: Pipelined seq with xargs

A functional approach using seq piped to xargs for processing each element.

seq 1 $END | xargs -I {} echo {}

Solution 19: echo and bash for Dynamic Brace Expansion

For environments where seq or eval might be unavailable, this workaround constructs a string and executes it with Bash.

a=1
b=5
# Construct the command string and pipe to bash
d='for i in {'$a'..'$b'}; do echo -n "$i"; done;'
echo "$d" | bash

Solution 20: Generic Number Range Function

A reusable Bash function num_range is presented to generate sequences, supporting both ascending and descending orders.

function num_range {
   # Return a range of whole numbers from beginning value to ending value.
   # >>> num_range start end
   # start: Whole number to start with.
   # end: Whole number to end with.
   typeset s e v
   s=${1}
   e=${2}
   if (( ${e} >= ${s} )); then
      v=${s}
      while (( ${v} <= ${e} )); do
         echo ${v}
         ((v=v+1))
      done
   elif (( ${e} < ${s} )); then
      v=${s}
      while (( ${v} >= ${e} )); do
         echo ${v}
         ((v=v-1))
      done
   fi
}

# Example usage:
num_range 1 5
num_range 5 1

Solution 21: POSIX-Compliant while with Decrementing Counter

A POSIX-compliant while loop that decrements a counter within the test condition.

i=5
while test "$((i = i - 1))" -ge 0; do
   echo "Hello World."
done

This efficiently counts down without needing a separate increment/decrement statement outside the while condition.

FAQs on Bash Number Sequences

Q: What is the most portable way to generate a number sequence in Bash

ANS: For maximum portability, use a POSIX-compliant while loop with arithmetic expansion:

i=1
limit=5
while [ $i -le $limit ]; do
  echo $i
  i=$(($i + 1))
done

This avoids Bash-specific features like (( )) or brace expansion with variables. Check out POSIX shell scripting for more on portable scripting.

Q: Why doesn't brace expansion {1..$VAR} work in Bash

ANS: Brace expansion in Bash is a textual macro operation performed early in the parsing phase, before parameter expansion. Therefore, it cannot interpret shell variables directly. Methods like eval echo {1..$VAR} or using external commands like seq are needed to achieve this. For more on Bash expansions, see the Bash Manual .

Q: Is seq deprecated

ANS: While seq is a very useful and common tool, its status as “deprecated” is not universally declared by GNU Coreutils. However, relying on Bash’s built-in arithmetic or brace expansion (with eval) can offer more portability and avoid external dependencies. For performance insights, compare seq with native Bash loops as shown in Solution 8 .

Q: Which loop is fastest in Bash

ANS: Benchmarks suggest that seq and brace expansion {..} are generally faster for generating sequences, especially for large ranges, compared to for ((...)) loops or while loops that involve repeated arithmetic expansion or external command calls for each iteration. However, for typical use cases, the difference is often negligible. See Solution 8 for detailed performance comparisons.

Q: How to loop through characters like a to z in Bash

ANS: Brace expansion directly supports character ranges:

for char in {a..z}; do echo $char; done

This is a clean and efficient Bash feature. For dynamic character ranges, eval can be used:

START_CHAR="b"
END_CHAR="e"
for char in $(eval echo "{$START_CHAR..$END_CHAR}"); do echo $char; done

This mirrors the behavior seen with numeric ranges.
