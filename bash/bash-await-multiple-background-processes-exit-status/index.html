“Bash: How to Await Multiple Background Processes and Check Individual Exit Statuses”

How can one effectively manage numerous concurrently running background jobs, ensure the main script waits for all of them, and accurately record the return code from each individual execution?

Here are several proven architectural patterns and solutions for handling this common requirement in shell scripting.

Solution Pattern 1: Storing PIDs and Iterative Waiting (The Explicit Approach)

This pattern involves explicitly capturing the Process ID ($!) immediately after launching each background command and then looping through the collected PIDs to call wait on each one. This allows for checking the exit status ($?) immediately after each wait.

Example Implementation:

Suppose you have an array of commands defined by $n_procs and an array of executables ./procs.

#!/bin/bash

# Initialize an array to hold PIDs
pids=()

# Launch processes and record their PIDs
for i in $(seq 1 "$n_procs"); do
    # Replace with your actual command execution
    ./procs[${i}] &amp; 
    pids[${i}]=$!
done

echo "All background processes launched."

# Loop through collected PIDs to wait and check status
for pid in "${pids[@]}"; do
    # Wait for the specific PID
    wait "$pid"
    return_code=$?
    echo "Process with PID $pid finished. Exit Code: $return_code"
done

echo "All background processes are finalized."

Alternative Structure for Status Tracking (Solution 4 variation):

To determine if any process failed, you can use a result flag:

#!/bin/bash

pids=""
overall_result=0

# Launch processes
for i in $(seq 0 9); do
   # Replace 'doCalculations' with your actual command
   doCalculations "$i" &amp; 
   pids="$pids $!"
done

# Wait on each PID sequentially to check status
for pid in $pids; do
    wait "$pid" || let "overall_result=1"
done
 
if [ "$overall_result" == "1" ]; then
   echo "One or more calculations failed."
   exit 1
else
   echo "All tasks succeeded."
fi

Solution Pattern 2: Using jobs -p and Iterative Wait (Simpler Collection)

A potentially cleaner way to gather the PIDs of all current background jobs is using jobs -p. This is simpler if you don’t need fine-grained control over which PID corresponds to which command index, only that you wait for all of them.

#!/bin/bash

# Launch some background tasks
sleep 10 &amp;
sleep 20 &amp;
sleep 15 &amp;

echo "Waiting for all background jobs to complete..."

# Collect PIDs of current background jobs
# Note: jobs -p may omit PIDs of processes that exited right before the command runs.
job_pids=$(jobs -p)

for pid in $job_pids; do
    wait "$pid"
    exit_status=$?
    echo "Job PID $pid returned status $exit_status"
done

A concise alternative shown in one solution involves redirecting jobs -p output directly to wait:

# Execution setup (example)
sleep 10 &amp;
sleep 20 &amp;
sleep 10 &amp;

# Wait using job output pipe
wait < <(jobs -p)

(Self-Correction Note: While the command wait < < <(jobs -p) is syntactically valid, relying on wait without arguments is generally preferred for waiting on all jobs, as shown in other samples.)

Solution Pattern 3: Utilizing GNU Parallel (External Tool)

If system tools like parallel are available, they abstract away PID management entirely, offering robust status reporting based on the number of failures.

If doCalculations is a shell function:

# Export the function so 'parallel' can see it
export -f doCalculations 

# Pipe input to parallel; it handles running concurrently
seq 0 9 | parallel doCalculations {}

GNU Parallel provides distinct exit codes: 0 for all success, 1-253 indicating the count of failed jobs, 254 for too many failures, and 255 for internal errors.

Solution Pattern 4: Real-time Notification via trap CHLD (Advanced Event Handling)

For scenarios where you need immediate notification (without constant polling) when any child process terminates, you can use the CHLD signal trap in conjunction with job control (set -o monitor).

This requires iterating over the known PIDs inside the trap handler and using kill -0 to check if the PID still exists, then calling wait on finished ones to collect status.

#!/bin/bash
set -o monitor # Enable job control

# Define the commands to run in the background
sleep 3 &amp;
sleep 5 &amp;&amp; exit 1 &amp; # This one fails
sleep 2 &amp;

# Capture initial PIDs
pids=$(jobs -p)

check_pids() {
    echo "

## Solutions
Child termination detected

run processes and store pids in array

pids=() for i in $n_procs; do ./procs[${i}] & pids[${i}]=$! done

wait for all pids

for pid in ${pids[*]}; do wait $pid done


"
    for pid in $pids; do
        # Check if PID still exists
        if kill -0 "$pid" 2>/dev/null; then
            echo "PID $pid is still alive."
        else
            # PID terminated; capture status
            wait "$pid"
            exit_status=$?
            if [ $exit_status -ne 0 ]; then
                echo "PID $pid exited with FAILURE status: $exit_status"
            else
                echo "PID $pid exited successfully."
            fi
        fi
    done
    echo "

#!/bin/bash

FAIL=0

echo “starting”

./sleeper 2 0 & ./sleeper 2 1 & ./sleeper 3 0 & ./sleeper 2 0 &

for job in jobs -p do echo $job wait $job || let “FAIL+=1” done

echo $FAIL

if [ “$FAIL” == “0” ]; then echo “YAY!” else echo “FAIL! ($FAIL)” fi


-"
}

# Set the trap to execute the handler on CHLD signal
trap check_pids CHLD

# Wait for the main script to finish waiting on all background jobs
wait

Solution Pattern 5: Bash 5.1+ Utilizing wait -n -p

For recent Bash versions (5.1 and newer), the wait built-in received enhancements that simplify this process significantly by allowing notification of which specific PID terminated.

#!/usr/bin/env bash

#

$ sleep 10 & $ sleep 10 & $ sleep 20 & $ sleep 20 & $ wait < <(jobs -p) $ sleep 20 && true || tee fail & $ sleep 20 && false || tee fail & $ wait < <(jobs -p) $ test -f fail && echo Calculation failed.

pids=""

for i in seq 0 9; do doCalculations $i & pids="$pids $!" done

pids="" RESULT=0

for i in seq 0 9; do doCalculations $i & pids="$pids $!" done

for i in {1..5}; do
    secs=$((RANDOM % 5 + 1)); code=$((RANDOM % 2)) # Random exit code 0 or 1
    (sleep ${secs}; exit ${code}) &amp;
    echo "Started job $! (sleep: ${secs}s, code: ${code})"
done

overall_success=0
# Loop until 'wait -n' finds no more background jobs
while true; do
    # -n waits for ANY child; -p stores the exited PID in 'pid_var'
    wait -n -p pid_var; code=$?
    
    # If pid_var is empty, no more background jobs exist
    [[ -z "${pid_var}" ]] &amp;&amp; break
    
    echo "Job ${pid_var} finished with code ${code}"
    
    # Update overall status if any job fails
    (( code != 0 )) &amp;&amp; overall_success=1
done

echo "All jobs done. Overall status: $overall_success"
exit $overall_success

Solution Pattern 6: Using Temporary Files for Status Logging (Portability)

If real-time notification or advanced Bash features are unavailable, a highly portable method is to have each subprocess write its PID and exit status to a shared temporary file before exiting. The main script then waits for all processes (wait) and reads the file afterward.

#!/bin/bash
TMP_RESULTS=$(mktemp)
trap 'rm -f "$TMP_RESULTS"' EXIT # Ensure cleanup on script exit

JOB_ID=0

# Function to execute and log results
run_and_log() {
    local job_index=$1
    # Simulate work that might fail
    if [ "$job_index" == "3" ]; then
        sleep 1; exit 10; # Simulate failure
    fi
    sleep 1; exit 0;
}

# Launch jobs
for i in {1..5}; do
    JOB_ID=$i
    # Each job runs its command, traps EXIT to log PID:$? to temp file, then runs the command
    ( trap "echo \"$JOB_ID:\$?\"; rm -f /tmp/is_running_$JOB_ID" EXIT; run_and_log "$JOB_ID" &amp; echo "is_running" > /tmp/is_running_$JOB_ID ) &amp;
done

# Wait for all jobs to finish their execution phase
wait 

echo "Processing collected results from $TMP_RESULTS:"
# Read results from the temporary file
while read line; do
    PID_AND_STATUS=$(echo "$line" | cut -d':' -f1)
    STATUS_CODE=$(echo "$line" | cut -d':' -f2)
    echo "Job $PID_AND_STATUS returned $STATUS_CODE"
done < <(sort "$TMP_RESULTS")

FAQs on Bash Await Multiple Background Processes Exit Status

Q: What is the shell special variable $! used for

ANS: The special variable $! holds the Process ID (PID) of the most recently executed command that was started in the background.

Q: Can I check the exit status of a background process after it has already finished

ANS: Yes, if you call the wait <PID> command on a process ID that has already terminated, it will return the exit status of that terminated process.

Q: What happens if I call wait without any arguments

ANS: When invoked without arguments, wait blocks execution until all currently active child processes launched by the shell have terminated.

Q: Is using the CHLD signal trap reliable for tracking status

ANS: Relying solely on trap CHLD can miss signals if multiple children terminate simultaneously. For robust status tracking, actively polling PIDs with wait or using Bash 5.1’s wait -p is more dependable.
