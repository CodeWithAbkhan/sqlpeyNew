SQL Server String Splitting Functions and Methods

The core challenge is to transform a single string containing multiple values, separated by a specific character or string, into a table format where each value resides in its own row. This facilitates easier querying, aggregation, and manipulation of the data.

Here are several methods discussed, each with its own advantages and considerations:

Solution 1: Recursive CTE for String Splitting

This method utilizes a Common Table Expression (CTE) with recursion to iteratively find and extract substrings based on a delimiter. It’s a clean approach for SQL Server 2005 and later.

CREATE FUNCTION dbo.Split(@sep CHAR(1), @s VARCHAR(512))
RETURNS TABLE
AS
RETURN (
    WITH Pieces(pn, start, stop) AS (
      SELECT 1, 1, CHARINDEX(@sep, @s)
      UNION ALL
      SELECT pn + 1, stop + 1, CHARINDEX(@sep, @s, stop + 1)
      FROM Pieces
      WHERE stop > 0
    )
    SELECT pn,
      SUBSTRING(@s, start, CASE WHEN stop > 0 THEN stop-start ELSE 512 END) AS s
    FROM Pieces
  );

Explanation: The CTE Pieces identifies the starting and stopping points of each substring based on the delimiter. The SUBSTRING function then extracts these pieces.

Solution 2: XML-Based String Splitting

An alternative, often efficient method leverages XML parsing. This technique can handle longer delimiters and avoids recursion, which can sometimes be a performance bottleneck.

CREATE FUNCTION [dbo].[Split] (@sep VARCHAR(32), @s VARCHAR(MAX))
RETURNS TABLE
AS
    RETURN
    (
        SELECT r.value('.', 'VARCHAR(MAX)') as Item
        FROM (SELECT CONVERT(XML, N'<root><r>' + REPLACE(REPLACE(REPLACE(@s,'& ','&amp; '),'<','&lt;'), @sep, '</r><r>') + '</r></root>') as valxml) x
        CROSS APPLY x.valxml.nodes('//root/r') AS RECORDS(r)
    );

Invocation Example:

create function [dbo].[Split] ( @string nvarchar(4000), @delimiter nvarchar(10) ) returns @table table ( [Value] nvarchar(4000) ) begin declare @nextString nvarchar(4000) declare @pos int, @nextPos int

set @nextString = ''
set @string = @string + @delimiter

set @pos = charindex(@delimiter, @string)
set @nextPos = 1
while (@pos &lt;&gt; 0)
begin
    set @nextString = substring(@string, 1, @pos - 1)

    insert into @table
    (
        [Value]
    )
    values
    (
        @nextString
    )

    set @string = substring(@string, @pos + len(@delimiter), len(@string))
    set @nextPos = @pos
    set @pos = charindex(@delimiter, @string)
end
return

end


--

Note on XML Method: While powerful, directly embedding values that might contain XML special characters (&, <, >) requires proper encoding (e.g., REPLACE(@s,'& ','&amp; '), REPLACE('<','&lt;')) before conversion to XML to prevent parsing errors.

Solution 3: Iterative Splitting with Table Variable (SQL Server 2005+)

This approach uses a table variable to store the split string parts. It iteratively searches for the delimiter, extracts the substring, and inserts it into the table variable.

create function [dbo].[Split]
(
    @string nvarchar(4000),
    @delimiter nvarchar(10)
)
returns @table table
(
    [Value] nvarchar(4000)
)
begin
    declare @nextString nvarchar(4000)
    declare @pos int, @nextPos int

    set @nextString = ''
    set @string = @string + @delimiter

    set @pos = charindex(@delimiter, @string)
    set @nextPos = 1
    while (@pos <> 0)
    begin
        set @nextString = substring(@string, 1, @pos - 1)

        insert into @table
        (
            [Value]
        )
        values
        (
            @nextString
        )

        set @string = substring(@string, @pos + len(@delimiter), len(@string))
        set @nextPos = @pos
        set @pos = charindex(@delimiter, @string)
    end
    return
end

Solution 4: Using sys.dm_fts_parser for Word Splitting (SQL Server 2008+)

For specific scenarios like splitting strings into words for analysis, SQL Server’s Full-Text Search parser can be employed. This is demonstrated with an example showing word frequency.

WITH testTable AS
(
SELECT 1 AS Id, N'how now brown cow' AS txt UNION ALL
SELECT 2, N'she sells sea shells upon the sea shore' UNION ALL
SELECT 3, N'red lorry yellow lorry' UNION ALL
SELECT 4, N'the quick brown fox jumped over the lazy dog'
)
SELECT display_term, COUNT(*) As Cnt
 FROM testTable
CROSS APPLY sys.dm_fts_parser('"' + txt + '"', 1033, 0,0)
GROUP BY display_term
HAVING COUNT(*) > 1
ORDER BY Cnt DESC;

Solution 5: Recursive CTE with Variable Delimiter Length

A modification of the recursive CTE approach to correctly handle delimiters of varying lengths.

create FUNCTION dbo.fn_Split2 (@sep nvarchar(10), @s nvarchar(4000))
RETURNS table
AS
RETURN (
    WITH Pieces(pn, start, stop) AS (
      SELECT 1, 1, CHARINDEX(@sep, @s)
      UNION ALL
      SELECT pn + 1, stop + (datalength(@sep)/2), CHARINDEX(@sep, @s, stop + (datalength(@sep)/2))
      FROM Pieces
      WHERE stop > 0
    )
    SELECT pn,
      SUBSTRING(@s, start, CASE WHEN stop > 0 THEN stop-start ELSE 4000 END) AS s
    FROM Pieces
  );

Note on datalength(): Using datalength() is important here as LEN() can misreport lengths with trailing spaces.

Solution 6: Pre-SQL Server 2005 Compatible Split Function

For environments running older SQL Server versions (prior to 2005), a different approach is needed. This function uses a loop and CHARINDEX for compatibility.

CREATE FUNCTION dbo.Split(@data nvarchar(4000), @delimiter nvarchar(100))
RETURNS @result table (Id int identity(1,1), Data nvarchar(4000))
AS
BEGIN
    DECLARE @pos   INT
    DECLARE @start INT
    DECLARE @len   INT
    DECLARE @end   INT

    SET @len   = LEN('.' + @delimiter + '.') - 2
    SET @end   = LEN(@data) + 1
    SET @start = 1
    SET @pos   = 0

    WHILE (@pos < @end)
    BEGIN
        SET @pos = CHARINDEX(@delimiter, @data, @start)
        IF (@pos = 0) SET @pos = @end

        INSERT @result (data) SELECT SUBSTRING(@data, @start, @pos - @start)
        SET @start = @pos + @len
    END

    RETURN
END

Solution 7: CLR Integration for Performance

For the utmost performance and flexibility, leveraging the .NET Common Language Runtime (CLR) allows for the creation of custom functions written in languages like C#. This can be significantly faster than T-SQL equivalents for complex string operations.

using System;
using System.Collections;
using System.Data.SqlTypes;
using System.Text.RegularExpressions;
using Microsoft.SqlServer.Server;

public class UDF
{
    [SqlFunction(FillRowMethodName="FillRow")]
    public static IEnumerable RegexSplit(SqlString s, SqlString delimiter)
    {
        return Regex.Split(s.Value, delimiter.Value);
    }

    public static void FillRow(object row, out SqlString str)
    {
        str = new SqlString((string) row);
    }
}

Performance Note: While CLR offers performance benefits, it’s noted that even CLR functions can be slower than native implementations in other database systems like PostgreSQL for specific tasks (e.g., regexp_split_to_table).

Solution 8: Simple SUBSTRING and CHARINDEX (Limited Use)

For very simple cases with a known, small number of delimited items, one could repeatedly use SUBSTRING and CHARINDEX to extract each part. However, this quickly becomes unwieldy and inefficient for more than a couple of items.

SELECT substring(commaSeparatedTags,0,charindex(',',commaSeparatedTags)) -- For the first tag

This is generally not recommended for robust solutions.

Solution 9: Handling Large Text Fields (VARCHAR(MAX))

When dealing with TEXT data types or very large strings, specific considerations are needed. This solution attempts to manage large text fields, though direct manipulation of TEXT can be less efficient than VARCHAR(MAX).

ALTER Function [dbo].[SplitStr] (
        @txt text
)
Returns @tmp Table
        (
                value varchar(127)
        )
as
BEGIN
        declare @str varchar(8000)
                , @Beg int
                , @last int
                , @size int

        set @size=datalength(@txt)
        set @Beg=1

        set @str=substring(@txt,@Beg,8000)
        IF len(@str)<8000 set @Beg=@size
        ELSE BEGIN
                set @last=charindex(',', reverse(@str))
                set @str=substring(@txt,@Beg,8000-@last)
                set @Beg=@Beg+8000-@last+1
        END

        declare @workingString varchar(25)
                , @stringindex int

        while @Beg<=@size Begin
                WHILE LEN(@str) > 0 BEGIN
                        SELECT @StringIndex = CHARINDEX(',', @str)

                        SELECT
                                @workingString = CASE
                                        WHEN @StringIndex > 0 THEN SUBSTRING(@str, 1, @StringIndex-1)
                                        ELSE @str
                                END

                        INSERT INTO
                                @tmp(value)
                        VALUES
                                (cast(rtrim(ltrim(@workingString)) as varchar(127)))
                        SELECT @str = CASE
                                WHEN CHARINDEX(',', @str) > 0 THEN SUBSTRING(@str, @StringIndex+1, LEN(@str))
                                ELSE ''
                        END
                END
                set @str=substring(@txt,@Beg,8000)

                if @Beg=@size set @Beg=@Beg+1
                else IF len(@str)<8000 set @Beg=@size
                ELSE BEGIN
                        set @last=charindex(',', reverse(@str))
                        set @str=substring(@txt,@Beg,8000-@last)
                        set @Beg=@Beg+8000-@last+1

                END
        END

        return
END

Solution 10: XML Splitting with DISTINCT and Type Casting

A variation of the XML method, this version includes the DISTINCT keyword and explicitly casts the split items to INT, which can be beneficial for numerical identifiers.

CREATE FUNCTION [dbo].Split
(
    @sep VARCHAR(32),
    @s VARCHAR(MAX)
)
RETURNS
    @result TABLE (
        Id INT NULL
    )
AS
BEGIN
    DECLARE @xml XML
    SET @XML = N'<root><r>' + REPLACE(@s, @sep, '</r><r>') + '</r></root>'

    INSERT INTO @result(Id)
    SELECT DISTINCT r.value('.', 'int') as Item
    FROM @xml.nodes('//root//r') AS RECORDS(r)

    RETURN
END

Solution 11: Looping with CHARINDEX and SUBSTRING (Another Iterative Approach)

This is another iterative method that continuously finds the delimiter, extracts the preceding substring, and updates the source string. It’s a straightforward, albeit potentially less performant for very large strings compared to XML or CLR.

create function [dbo].[Split](@string varchar(max), @separator varchar(10))
returns @splited table ( stringPart varchar(max) )
with execute as caller
as
begin
    declare @stringPart varchar(max);
    set @stringPart = '';

    while charindex(@separator, @string) > 0
    begin
        set @stringPart = substring(@string, 0, charindex(@separator, @string));
        insert into @splited (stringPart) values (@stringPart);
        set @string = substring(@string, charindex(@separator, @string) + len(@separator), len(@string) + 1);
    end

    return;
end
go

Comparing the Solutions

  • Readability & Simplicity: Recursive CTEs (Solution 1) and XML parsing (Solution 2) are generally considered quite readable.
  • Performance: CLR (Solution 7) often provides the best performance for complex or high-volume operations. XML parsing (Solution 2) is also typically very performant. Older T-SQL looping methods can be slower on large datasets.
  • Compatibility: Solutions 1, 3, 6, and 11 are generally compatible with earlier versions of SQL Server, with Solution 6 specifically designed for pre-2005 environments.
  • Delimiter Flexibility: XML parsing (Solution 2) and CLR (Solution 7) can handle longer or more complex delimiters easily. Recursive CTEs and looping methods are also adaptable.

When choosing a method, consider the SQL Server version you are using, the expected size of the strings, the complexity of the delimiters, and your performance requirements. For general-purpose splitting, the XML method (Solution 2) or a well-written recursive CTE (Solution 1) are excellent starting points. For performance-critical applications, investigate CLR integration.

FAQs on SQL Server String Splitting

Q: What is the most efficient way to split strings in SQL Server

ANS: For many scenarios, the XML-based method (Solution 2) offers a good balance of performance and readability. For extreme performance needs, especially with very large datasets or complex patterns, a CLR function (Solution 7) can be significantly faster.

Q: Can I split strings by multiple delimiters in SQL Server

ANS: While the provided examples focus on single delimiters, the XML method (Solution 2) can be adapted by using multiple REPLACE calls before converting to XML to handle multiple delimiters. For complex multi-delimiter scenarios, CLR functions offer the most flexibility.

Q: Which SQL Server versions support these splitting methods

ANS: Recursive CTEs (Solution 1) are supported from SQL Server 2005 onwards. The XML method (Solution 2) is also generally available from SQL Server 2005+. Solution 6 is specifically for versions prior to SQL Server 2005. CLR integration (Solution 7) is available in most modern SQL Server versions.

Q: What are the limitations of the CTE splitting method

ANS: Recursive CTEs can have performance limitations with extremely long strings due to the recursion depth and overhead. The maximum recursion depth in SQL Server is 32,767, but practical limits may be encountered sooner.

Q: How does the XML splitting method handle special characters

ANS: The XML splitting method requires special characters within the string to be properly escaped (e.g., & to &amp;, < to &lt;) before conversion to XML to prevent parsing errors. Solution 2 demonstrates how to do this.

CREATE FUNCTION dbo.Split(@data nvarchar(4000), @delimiter nvarchar(100))  
RETURNS @result table (Id int identity(1,1), Data nvarchar(4000)) 
AS  
BEGIN 
    DECLARE @pos   INT
    DECLARE @start INT
    DECLARE @len   INT
    DECLARE @end   INT

    SET @len   = LEN('.' + @delimiter + '.') - 2
    SET @end   = LEN(@data) + 1
    SET @start = 1
    SET @pos   = 0

    WHILE (@pos &lt; @end)
    BEGIN
        SET @pos = CHARINDEX(@delimiter, @data, @start)
        IF (@pos = 0) SET @pos = @end

        INSERT @result (data) SELECT SUBSTRING(@data, @start, @pos - @start)
        SET @start = @pos + @len
    END

    RETURN
END
