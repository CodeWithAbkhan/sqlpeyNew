“Solved: How to Remove Space Between Inline-Block Elements”

The core question often is: “How can one effectively remove the space between inline-block elements, preferably with a CSS-only solution that avoids altering the HTML source?”

While completely robust CSS-only fixes can be elusive for all scenarios and older browsers, several effective strategies exist. This guide explores various approaches, from modern layout techniques to classic workarounds, to help you achieve pixel-perfect inline-block layouts.

Top 15 Methods to Eliminate Whitespace Between Inline-Block Elements

Let’s delve into practical solutions, including contemporary and traditional techniques.

Method 1: Embrace Flexbox (Recommended Modern Approach)

For most contemporary web development, CSS Flexbox is the go-to solution for achieving complex layouts, including managing spacing between elements. It’s designed specifically for one-dimensional layouts (row or column) and natively handles spacing with incredible flexibility, negating the inline-block whitespace issue entirely.

Practical Example:

Instead of display: inline-block on children, apply display: flex to their parent container. This automatically aligns children without the inter-element space.

<section class="flex-container">
  <div class="flex-item">Alpha</div>
  <div class="flex-item">Beta</div>
</section>

.flex-container {
  display: flex;
  /* Additional Flexbox properties for alignment if needed, e.g., justify-content: space-between; */
}

.flex-item {
  width: 110px; /* Example width */
  background: tomato;
  font-size: 28px;
  color: white;
  text-align: center;
  padding: 10px;
}

Backward Compatibility with Prefixes:

For wider browser compatibility, particularly with older versions, you might include vendor prefixes:

.legacy-flex-container {
  display: -webkit-box;    /* Old WebKit (Safari 3.1–6, Chrome 4–20) */
  display: -webkit-flex;   /* New WebKit (Safari 6.1+, Chrome 21+) */
  display: -ms-flexbox;    /* IE 10 */
  display: flex;           /* Standard */
}

.legacy-flex-item {
  float: left; /* Fallback for very old browsers, but flexbox overrides this */
  display: inline-block; /* Fallback if flexbox not supported */
  width: 110px;
  background: steelblue;
  font-size: 28px;
  color: white;
  text-align: center;
  padding: 10px;
}

This method is highly recommended due to its robustness and widespread support (over 98% as of 2017). You can explore more about Flexbox with resources like MDN’s guide on Using CSS flexible boxes and A Complete Guide to Flexbox on CSS-Tricks .

Method 2: Manipulate HTML Whitespace (Pragmatic Approach)

This is perhaps the most straightforward and universally supported method, though it requires altering your HTML source code. The concept is simple: remove the literal whitespace between the inline-block elements in your markup.

How it works:

Instead of:

<div>Element A</div>
<div>Element B</div>

Use:

<div>Element A</div><div>Element B</div>

This can be achieved in several ways:

  1. No Whitespace:

    <ul>
    <li>Widget 1</li><li>Widget 2</li><li>Widget 3</li>
</ul>

  2. Line Break Immediately After Closing Tag:

    <ul>
    <li>Widget 1</li
    ><li>Widget 2</li
    ><li>Widget 3</li>
</ul>

  3. HTML Comments Between Elements: This is often preferred for maintaining readable HTML indentation, especially when elements are generated dynamically (e.g., via server-side templating like JSP, PHP, or Python frameworks).

    <ul>
    <li>Widget 1</li><!--
    --><li>Widget 2</li><!--
    --><li>Widget 3</li>
</ul>

  4. Server-Side Language Tags (e.g., PHP): If using a server-side language, its tags can consume whitespace.

    <ul>
    <li>Widget 1</li><?php
    ?><li>Widget 2</li><?php
    ?><li>Widget 3</li>
</ul>

  5. Omit Certain Closing Tags (HTML5 Specific): For some elements like <li>, HTML5 allows omitting closing tags, which naturally removes inter-element whitespace. Use with caution as it can impact maintainability for others.

    <ul>
    <li>Widget 1
    <li>Widget 2
    <li>Widget 3
</ul>

This technique is effective universally because it addresses the root cause of the spacing.

Method 3: font-size: 0 on Parent Element

This CSS-only workaround sets the parent container’s font-size to 0, effectively collapsing the whitespace character’s width. Then, you re-declare a sensible font-size on the children elements.

Practical Example:

.parent-container-zero-font {
  font-size: 0;
}

.parent-container-zero-font > span {
  display: inline-block;
  background: firebrick;
  font-size: 16px; /* Re-declare font-size for children */
  color: white;
  text-align: center;
  padding: 8px;
}

<p class="parent-container-zero-font">
  <span>App item A</span>
  <span>App item B</span>
</p>

Considerations:

  • Browser Compatibility: Works well in most modern browsers and IE8+, but had issues with Safari 5.
  • Font Scaling: Can be tricky to manage if you rely heavily on em units for font sizing, as em is relative to the parent’s font size. It requires careful planning to ensure children’s font-size scales correctly.
  • Accessibility: Some argue that setting font-size: 0 can affect accessibility tools that rely on text rendering. Also, users with minimum font size preferences in their browsers might negate this effect.

Method 4: Utilize letter-spacing or word-spacing

These CSS properties can manipulate the spacing between characters or words. By applying a large negative value to the parent, you can negate the whitespace, then reset it to normal for the children.

letter-spacing Approach:

.wrapper-gap-fix {
  letter-spacing: -4px; /* Adjust value as needed; -0.3em or -0.31em also common */
}

.wrapper-gap-fix > * {
  letter-spacing: normal; /* Reset for children */
  display: inline-block;
}

<ul class="wrapper-gap-fix">
   <li>Nav Item One</li>
   <li>Nav Item Two</li>
   <li>Nav Item Three</li>
</ul>

word-spacing Approach:

While word-spacing: -100% theoretically should work (shortening inter-word spaces by 100%), browser support has historically been inconsistent and it’s marked ‘at risk’ in the CSS Text Module Level 3 specification.

A more reliable word-spacing variant is word-spacing: -1ch; (where 1ch is the width of the ‘0’ character). This works in Firefox 10+, Chrome 27+, and almost works in IE9+.

.parent-word-spacing {
  word-spacing: -1ch; /* Or a fixed pixel value like -5px */
}

.parent-word-spacing > span {
  display: inline-block;
  word-spacing: normal; /* Reset for children */
  background: purple;
  color: white;
  padding: 5px;
}

<div class="parent-word-spacing">
  <span>Part Uno</span>
  <span>Part Dos</span>
</div>

Considerations:

  • Browser Differences: Behavior can vary slightly across browsers (e.g., Chrome vs. Firefox vs. Edge) for specific negative values, especially with letter-spacing. Experimentation is often needed to find the optimal value (-4px, -0.3em, -0.31em).
  • Content Impact: This method might inadvertently affect text rendering if the children elements themselves contain spaces or if you have complex typographic needs.

Method 5: Leverage CSS Grid Layout

Similar to Flexbox, CSS Grid is a powerful modern layout system that offers precise control over element placement and spacing. It’s ideal for two-dimensional layouts (rows and columns) and naturally addresses the inline-block whitespace issue by allowing you to define grid-column-gap and grid-row-gap (which default to 0).

Practical Example:

.grid-container {
  display: grid;
  grid-template-columns: 120px 120px; /* Example: two columns of 120px each */
  grid-column-gap: 0; /* Explicitly set to 0, though often default */
  grid-row-gap: 0;    /* Explicitly set to 0 */
  background: lightgray;
  padding: 10px;
}

.grid-unit {
  background: darkorange;
  padding: 15px;
  color: white;
  text-align: center;
}
.grid-unit:nth-child(even) {
  background: darkgreen;
}

<div class="grid-container">
  <div class="grid-unit">Section A</div>
  <div class="grid-unit">Section B</div>
</div>

Advantages:

  • Modern and Robust: Excellent for complex layouts without the inline-block quirks.
  • Explicit Gaps: Provides clear control over spacing with gap properties.
  • High Support: Widely supported across modern browsers (with -ms- prefix for IE).

Method 6: display: table-cell on Elements

By treating inline-block elements as table cells, you can leverage table layout behavior to eliminate the whitespace. The parent element might need display: table;.

Practical Example:

.table-like-parent {
  display: table;
  width: auto; /* Or specific width */
}

.table-like-parent > span {
  display: table-cell;
  width: 100px;
  background: blueviolet;
  color: white;
  text-align: center;
  padding: 10px;
  border: 1px solid silver; /* For visualization */
}

<p class="table-like-parent">
  <span>Widget One</span>
  <span>Widget Two</span>
</p>

Considerations:

  • Semantic Use: While it works visually, using table display properties for non-tabular data might be considered a semantic compromise, though less severe than actual HTML tables for layout.
  • Layout Limitations: Table layouts have their own set of behaviors and limitations compared to Flexbox or Grid.

Method 7: Use float: left on Elements

Floating elements effectively remove them from the normal document flow and prevent the whitespace issue. This is an older, but still functional, method.

Practical Example:

.float-group > span {
  float: left; /* Pulls elements to the left, removing whitespace */
  display: inline-block; /* Still technically inline-block for its own properties */
  width: 100px;
  background: navy;
  font-size: 28px;
  color: white;
  text-align: center;
  padding: 10px;
}

.float-group::after {
  content: "";
  display: table;
  clear: both; /* Clear floats on parent */
}

<p class="float-group">
  <span>Module A</span>
  <span>Module B</span>
</p>

Considerations:

  • Clearfix: You must clear the floats on the parent container (e.g., using a clearfix hack) to ensure it correctly encloses its floated children.
  • Layout Impact: Floats can affect the layout of subsequent elements, requiring careful management. Generally, Flexbox or Grid are preferred for new layouts.

Method 8: Negative margin-right

A simple, direct CSS hack involves applying a negative margin-right to the inline-block elements. The typical value is around -4px or -0.25em to counteract the default browser-added space.

Practical Example:

.inline-item-with-negative-margin {
  display: inline-block;
  margin-right: -4px; /* Or -0.25em */
  background: olivedrab;
  color: white;
  padding: 7px;
}

<div>
  <span class="inline-item-with-negative-margin">First Item</span>
  <span class="inline-item-with-negative-margin">Second Item</span>
  <span class="inline-item-with-negative-margin">Third Item</span>
</div>

Considerations:

  • Precision: The exact negative value might vary slightly depending on the browser, font, and default font spacing.
  • Font Size Dependency: If using em units for margin-right, the effect depends on the element’s font-size.
  • Semantic “Hack”: While effective, it’s a “hack” that manipulates spacing rather than solving the underlying layout issue.

Method 9: white-space: nowrap on Parent

Applying white-space: nowrap to the parent container forces its content to stay on a single line, effectively collapsing the whitespace between inline-block children.

Practical Example:

.container-no-wrap {
  vertical-align: top; /* Important for alignment */
  white-space: nowrap; /* Collapses all whitespace */
}

.container-no-wrap > .column-element {
  float: left; /* Often used with this approach */
  display: inline-block;
  width: 48%; /* Example width, adjust as needed */
  background: teal;
  color: white;
  padding: 12px;
}

<div class="container-no-wrap">
    <div class="column-element">Content Column 1</div>
    <div class="column-element">Content Column 2</div>
</div>

Considerations:

  • Overflow: If the combined width of children exceeds the parent, content will overflow horizontally, as white-space: nowrap prevents wrapping.
  • Vertical Alignment: May require vertical-align: top; on the parent if children have different heights.

Method 10: Custom Zero-Width Space Font

This is a more advanced and niche solution. It involves creating or using a custom font that defines a zero-width space character. You then apply this font to the parent container and revert to a standard font for the child elements. The browser renders the whitespace with the zero-width font, effectively making it invisible.

Practical Example:

@font-face {
    font-family: 'NoVisSpace'; /* Unique font name */
    src: url('../fonts/zerowidth.eot'); /* Example path to your font file */
    src: url('../fonts/zerowidth.eot?#iefix') format('embedded-opentype'),
         url('../fonts/zerowidth.woff2') format('woff2'),
         url('../fonts/zerowidth.woff') format('woff'),
         url('../fonts/zerowidth.ttf') format('truetype'),
         url('../fonts/zerowidth.svg#NoVisSpace') format('svg');
}

body {
    font-family: 'OpenSans', sans-serif; /* Default body font */
}

.blocky-wrapper {
    font-family: 'NoVisSpace'; /* Apply the zero-width font here */
}

.blocky-wrapper > * {
    display: inline-block;
    font-family: 'OpenSans', sans-serif; /* Revert to normal font for children */
    background-color: lightcoral;
    color: white;
    padding: 10px;
}

<section class="blocky-wrapper">
    <span>First Content</span>
    <span>Second Content</span>
</section>

Considerations:

  • Complexity: Requires font creation/management and proper @font-face declaration.
  • File Size: Adds an extra font file to your project.
  • Specificity: Needs careful management of font-family inheritance.

Method 11: text-space-collapse: discard (Future CSS Property)

The CSS Text Module Level 4 specification introduces text-space-collapse: discard, which aims to directly control how whitespace inside and around an element is processed. When discard is used, all whitespace at the beginning and end of a line, and consecutive whitespace, would be removed.

Conceptual Example:

.parent-element {
  text-space-collapse: discard; /* Discards whitespace */
}

Current Status:

As of late 2023, this property is not yet implemented in any major browser. While it’s the most semantically correct CSS solution for this problem, it’s not a practical solution today.

Method 12: JavaScript Intervention

If CSS-only solutions are not a strict requirement, JavaScript can programmatically remove whitespace text nodes. This is generally less preferred for layout fixes due to potential performance impacts or reliance on JS, but it offers full control.

Practical Example:

document.querySelectorAll('.js-container').forEach(parentEl => {
  parentEl.childNodes.forEach(node => {
    if (node.nodeType === 3 && node.nodeValue.trim() === '') { /* Node.TEXT_NODE === 3 */
      parentEl.removeChild(node);
    }
  });
});

.js-container > span {
  display: inline-block;
  width: 100px;
  background-color: darkgoldenrod;
  color: white;
  padding: 8px;
  text-align: center;
}

<div class="js-container">
  <span>JS Block 1</span>
  <span>JS Block 2</span>
</div>

Considerations:

  • FOUC (Flash of Unstyled Content): Layout might briefly appear with gaps before JavaScript executes.
  • Performance: Can be impactful on very large DOMs.
  • Dependency: Relies on JavaScript being enabled.

Method 13: margin-right: -0.25em (Simplified)

A specific application of negative margin, often cited as a simple fix without needing to touch the parent element’s font size. It works best when the inline-block element’s font-size is not explicitly defined (i.e., it inherits from the parent).

.simple-item-margin {
  display: inline-block;
  margin-right: -0.25em; /* Default word-spacing offset */
  background: indianred;
  color: white;
  padding: 6px;
}

<div>
  <span class="simple-item-margin">Data Piece A</span>
  <span class="simple-item-margin">Data Piece B</span>
</div>

Note: 0.25em is typically the default word-spacing value. Refer to W3Schools - word-spacing property for more.

Method 14: font-size: 0.01em (IE7 Workaround)

For compatibility with very old browsers like Internet Explorer 7, where font-size: 0; might be ignored or cause rendering issues, a tiny font-size like 0.01em can be a workaround.

.old-ie-parent {
  font-size: 0.01em; /* Tiny font size for old IE compatibility */
}

.old-ie-parent > span {
  display: inline-block;
  font-size: 14px; /* Restore actual font size */
  background: #32CD32; /* LimeGreen */
  color: white;
  padding: 9px;
}

<div class="old-ie-parent">
  <span>Retro Item 1</span>
  <span>Retro Item 2</span>
</div>

This is a specific hack for legacy browser support scenarios.

Method 15: Utility Classes for letter-spacing

Similar to Method 4, this involves creating re-usable utility classes to apply the letter-spacing fix across your project, making it easier to manage.

/* Parent wrapper for inline-block elements */
.inline-items-container,
.inline-items-container > .inline-items-container { /* Accommodate nested wrappers */
  letter-spacing: -4px; /* Adjust value as needed */
}

/* Children elements inside the wrapper */
.inline-items-container > * {
  letter-spacing: normal; /* Reset text spacing */
  display: inline-block;
}

<ul class="inline-items-container">
   <li>List Item X</li>
   <li>List Item Y</li>
   <li>List Item Z</li>
</ul>

This promotes maintainability as you only need to apply class="inline-items-container" to the parent element, rather than defining new CSS rules for each new set of inline-blocks.

FAQs on Solved How to Remove Space Between Inline Block Elements

Q: Why do spaces appear between inline block elements

ANS: Spaces appear between inline-block elements because web browsers treat any whitespace (like spaces, tabs, or newlines) in the HTML source code between these elements as actual visible space characters, similar to how they handle spaces between words in a sentence.

Q: What is the recommended way to remove inline block spaces

ANS: The most recommended modern approach is to use Flexbox or CSS Grid by applying display: flex; or display: grid; to the parent container. These layout modules are designed to manage spacing inherently and provide robust solutions without resorting to hacks.

Q: Can I remove inline block spaces with only CSS

ANS: Yes, it is possible to remove inline-block spaces using only CSS. Common CSS-only methods include setting font-size: 0; on the parent and then re-declaring font size on children, or using negative letter-spacing on the parent with normal letter-spacing on children. However, these methods sometimes come with their own set of caveats regarding cross-browser compatibility or font scaling.

Q: Is Flexbox suitable for solving inline block spacing

ANS: Flexbox is highly suitable and recommended for solving inline-block spacing. By setting display: flex; on the parent, Flexbox automatically arranges child elements without the whitespace issue, providing powerful alignment and distribution capabilities.

Q: How do HTML comments help with inline block spacing

ANS: HTML comments <!-- --> can help remove inline-block spacing by placing them directly between the closing tag of one inline-block element and the opening tag of the next. This effectively consumes the whitespace in the HTML source code without affecting the visual layout or adding extra visible characters.

Q: What is the font size zero trick

ANS: The font-size: 0 trick involves setting font-size: 0; on the parent element of your inline-block children. This collapses the width of the whitespace character. You then set a desirable font-size back on the children elements to make their text visible again.

Q: What is the letter spacing trick

ANS: The letter-spacing trick involves applying a negative letter-spacing value (e.g., -4px or -0.3em) to the parent container of inline-block elements. This compresses the space between characters. To ensure the text within the children remains readable, letter-spacing: normal; is then applied to the children elements.

Q: What about CSS Grid for layout

ANS: CSS Grid is an excellent modern alternative for layout, including resolving inline-block spacing. By setting display: grid; on the parent, you can define columns and rows, and explicitly control the gaps between grid items using grid-column-gap and grid-row-gap (which default to 0), effectively eliminating unwanted spaces.
