“Solved: How to Set CSS Height with Percentage Values Correctly”

Encountering issues with CSS height property when using percentages? You’re not alone. This common CSS challenge arises because percentage heights are intrinsically linked to the height of their containing block. If that reference point is not explicitly defined, your percentage height will default to auto, meaning its size will be determined by its content and other CSS properties, rather than the intended relative measurement.

The official CSS specification clarifies this behavior:

“percentage: Specifies a percentage height. The percentage is calculated with respect to the height of the generated box’s containing block. If the height of the containing block is not specified explicitly and this element is not absolutely positioned, the value computes to ‘auto’.”

This means for your percentage-based heights to reliably calculate, every parent element in the hierarchy, all the way up to the html and body elements, must have an explicit height defined. Crucially, min-height or max-height will not suffice; the height property itself must be set.

FAQs on Solved How to Set CSS Height with Percentage Values Correctly

Q: Why does my CSS height percentage not work

ANS: CSS percentage heights are calculated relative to the height of their containing block. If the containing block (parent element) doesn’t have an explicitly defined height, the percentage height will default to ‘auto’ and not render as expected. Ensure all parent elements, including html and body, have a defined height property.

Q: How can I make percentage heights work in CSS

ANS: To make CSS percentage heights work, you must define an explicit height for every parent element in the DOM tree, starting from the html and body elements, all the way up to the element you want to apply the percentage height to. For example, html, body { height: 100%; }.

Q: What is the alternative to using percentage heights

ANS: A common and often simpler alternative to percentage heights is using viewport units, specifically vh (viewport height). height: 100vh; will make an element take up the full height of the browser’s viewport, eliminating the need to manage parent element heights.

Q: When is height 100vh better than height 100 percent

ANS: height: 100vh; is generally preferred when you want an element to span the entire height of the browser window, regardless of its parent elements. height: 100%; requires a carefully structured hierarchy of parent elements with defined heights to function correctly.

Demonstrating the Challenge and Solutions

Let’s illustrate with examples how percentage heights behave and how to correct them.

Consider this scenario: you want a div to occupy 50% of its parent’s height.

Scenario 1: The Problematic Structure (Will Not Work as Expected)

If the parent elements lack explicit heights, the height: 50% will not resolve correctly.

<article>
    <section>
        <div style="height: 50%;">This div's height will likely be determined by its content.</div>
    </section>
</article>

Even setting a parent’s height is insufficient if the root elements don’t have a defined height:

<article>
    <section style="height: 100%;">
        <div style="height: 50%;">This still might not work as intended.</div>
    </section>
</article>

And this also fails without the crucial html and body heights:

<article style="height: 100%;">
    <section style="height: 100%;">
        <div style="height: 50%;">The reference point is still missing.</div>
    </section>
</article>

The browser’s default body height is auto. Without explicit height on html and body, the percentage calculation is based on an undefined value.

<body style="height: 100%;">
    <article style="height: 100%;">
        <section style="height: 100%;">
            <div style="height: 50%;">This remains problematic.</div>
        </section>
    </article>
</body>

Scenario 2: The Working Solutions

Solution A: Defining Heights Up the Chain

To make height: 50% work, you need to set explicit heights for all ancestor elements, including html and body.

<html style="height: 100%;">
    <body style="height: 100%;">
        <article style="height: 100%;">
            <section style="height: 100%;">
                <div style="height: 50%;">This div will now be 50% of its parent section's height.</div>
            </section>
        </article>
    </body>
</html>

Alternatively, if you have a specific pixel height defined for a parent, a child’s percentage height will work relative to that:

<article>
    <section style="height: 500px;">
        <div style="height: 50%;">This div will be 250px high (50% of 500px).</div>
    </section>
</article>

It’s important to note that min-height does not establish a reference for percentage calculations:

<article>
    <section style="min-height: 500px;">
        <div style="height: 50%;">This div will not be 50% of 500px because min-height doesn't count.</div>
    </section>
</article>

Solution B: Employing Viewport Height (vh)

A more straightforward approach to achieving full-height elements without complex parent height management is to use the vh unit. 1vh is equal to 1% of the viewport’s height.

Example using vh for responsive layout:

<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Responsive Layout with Viewport Units</title>
  <style>
    #wrapper {
      height: 60vh; /* Wrapper takes 60% of viewport height */
      display: flex; /* Using flexbox for layout */
      gap: 2%;      /* Space between columns */
    }
    #tabs {
      width: 48%; /* Approximately 50% minus gap */
      height: 100%; /* Takes full height of wrapper */
      overflow-y: auto; /* Allows scrolling if content exceeds height */
      overflow-x: hidden;
    }
    #leaflet_map {
      width: 48%; /* Approximately 50% minus gap */
      height: 100%; /* Takes full height of wrapper */
      overflow-y: auto; /* Allows scrolling */
      overflow-x: hidden;
    }
  </style>
</head>
<body>
  <div id="wrapper">
    <div id="tabs" ng-controller="TabsDataCtrl">
      <!-- Content for tabs -->
      <p>Tab Content 1</p>
      <p>Tab Content 2</p>
      <p>Tab Content 3</p>
    </div>

    <div id="leaflet_map" ng-controller="iPortMapJobController">
      <!-- Content for map -->
      <p>Map Placeholder</p>
    </div>
  </div>
</body>
</html>

In this example, #wrapper is set to 60vh, meaning it will always occupy 60% of the browser window’s height. Both #tabs and #leaflet_map are set to height: 100%, making them fill the available height of the #wrapper, ensuring they are also 60% of the viewport height without needing to specify their heights directly in relation to the viewport.

For a direct application of viewport height:

height: 90vh; /* This element will be 90% of the viewport height */
