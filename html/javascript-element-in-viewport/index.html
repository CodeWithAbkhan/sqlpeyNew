“JavaScript: How to Determine if an Element is Visible in the Viewport”

Accurately determining if an HTML element is visible within the browser’s viewport is a common requirement for various web development tasks. This includes features like lazy loading images, triggering animations as elements appear, or pausing/resuming video playback based on visibility. While the concept seems straightforward, achieving reliable and performant detection across different browsers and scenarios can be challenging.

This guide explores multiple JavaScript solutions, leveraging the getBoundingClientRect() method and the more modern Intersection Observer API, to help you accurately pinpoint element visibility. We’ll cover different approaches, discuss their advantages and disadvantages, and provide practical code examples.

Core Concepts: getBoundingClientRect() and Viewport Dimensions

The getBoundingClientRect() method is fundamental to most solutions. It returns a DOMRect object providing information about the size of an element and its position relative to the viewport. Key properties include:

  • top: The distance from the top edge of the viewport to the top edge of the element.
  • bottom: The distance from the top edge of the viewport to the bottom edge of the element.
  • left: The distance from the left edge of the viewport to the left edge of the element.
  • right: The distance from the left edge of the viewport to the right edge of the element.
  • width: The width of the element.
  • height: The height of the element.

To determine if an element is within the viewport, we compare these values against the viewport’s dimensions: window.innerHeight and window.innerWidth, or document.documentElement.clientHeight and document.documentElement.clientWidth for better cross-browser compatibility (as these account for potential scrollbars more consistently).

Solution 1: The Recommended getBoundingClientRect() Approach

This method is widely considered the modern best practice due to its accuracy and broad browser support. It efficiently checks if the element’s bounding rectangle falls within the viewport’s boundaries.

/**
 * Checks if an element is entirely visible within the viewport.
 * @param {Element|jQuery} el The element to check.
 * @returns {boolean} True if the element is in the viewport, false otherwise.
 */
function isElementInViewport(el) {
    // Handle jQuery objects by returning the first element
    if (typeof jQuery === "function" && el instanceof jQuery) {
        el = el[0];
    }

    if (!el) {
        return false; // Element not found or invalid
    }

    var rect = el.getBoundingClientRect();

    // Check if the element's rectangle is within the viewport dimensions
    return (
        rect.top >= 0 &&
        rect.left >= 0 &&
        rect.bottom <= (window.innerHeight || document.documentElement.clientHeight) &&
        rect.right <= (window.innerWidth || document.documentElement.clientWidth)
    );
}

/**
 * Creates a visibility change handler for an element.
 * @param {Element} el The element to monitor.
 * @param {Function} callback The function to execute when visibility changes.
 * @returns {Function} The handler function.
 */
function onVisibilityChange(el, callback) {
    var oldVisibilityState; // Stores the previous visibility state

    return function() {
        var isVisible = isElementInViewport(el);
        if (isVisible !== oldVisibilityState) {
            oldVisibilityState = isVisible;
            if (typeof callback === 'function') {
                callback(); // Execute the callback if it's a function
            }
        }
    }
}

Key considerations for this approach:

  • Performance: Attaching scroll event listeners can sometimes lead to performance issues if not handled carefully. Debouncing or throttling the visibilityHandler can optimize this.
  • DOM Modifications: If you dynamically change the DOM, you might need to manually call visibilityHandler() to re-evaluate the element’s visibility.
  • Initial Load: Ensure your code runs after the DOM is fully loaded and styled. Using DOMContentLoaded or load events is crucial. Avoid running such checks inside $(document).ready() alone, as CSS might not have been applied yet.

Solution 2: The offset() and scroll() Based Approach (jQuery)

This method, often found in older discussions, relies on calculating element offsets and comparing them with the window’s scroll position. While functional, it’s generally less performant and precise than getBoundingClientRect().

/**
 * Checks if an element is entirely visible within the current viewport using offsets.
 * @param {Element} el The element to check.
 * @returns {boolean} True if the element is fully in the viewport, false otherwise.
 */
function elementInViewportStrict(el) {
  var top = el.offsetTop;
  var left = el.offsetLeft;
  var width = el.offsetWidth;
  var height = el.offsetHeight;

  // Traverse up the offsetParents to get the total offset
  while (el.offsetParent) {
    el = el.offsetParent;
    top += el.offsetTop;
    left += el.offsetLeft;
  }

  // Check if the element's total offset falls within the viewport
  return (
    top >= window.pageYOffset &&
    left >= window.pageXOffset &&
    (top + height) <= (window.pageYOffset + window.innerHeight) &&
    (left + width) <= (window.pageXOffset + window.innerWidth)
  );
}

/**
 * Checks if any part of an element is visible within the current viewport using offsets.
 * @param {Element} el The element to check.
 * @returns {boolean} True if any part of the element is in the viewport, false otherwise.
 */
function elementInViewportPartial(el) {
  var top = el.offsetTop;
  var left = el.offsetLeft;
  var width = el.offsetWidth;
  var height = el.offsetHeight;

  // Traverse up the offsetParents
  while (el.offsetParent) {
    el = el.offsetParent;
    top += el.offsetTop;
    left += el.offsetLeft;
  }

  // Check if the element overlaps with the viewport
  return (
    top < (window.pageYOffset + window.innerHeight) &&
    left < (window.pageXOffset + window.innerWidth) &&
    (top + height) > window.pageYOffset &&
    (left + width) > window.pageXOffset
  );
}

Why this is less preferred:

  • Performance: Iteratively traversing offsetParent can be slow, especially for deeply nested elements.
  • Accuracy: It can be less accurate with complex CSS positioning or transformations compared to getBoundingClientRect().

Solution 3: The Intersection Observer API (Modern and Performant)

The Intersection Observer API offers a significantly more performant and declarative way to detect when an element enters or leaves the viewport (or another specified element). It works asynchronously and efficiently, avoiding the need for manual scroll event listeners.

// Select the element you want to observe
const targetElement = document.querySelector('#your-target-element-id'); // Replace with your element's selector

if (targetElement) {
    // Options for the observer (e.g., threshold for intersection)
    const observerOptions = {
        root: null, // Use the viewport as the root
        rootMargin: '0px', // No margin around the root
        threshold: 0.1 // Trigger when at least 10% of the element is visible
    };

    // Callback function to execute when intersection changes
    const intersectionCallback = ([entry]) => {
        if (entry.isIntersecting) {
            console.log('Element is visible!');
            // Add your logic here, e.g., load an image, start an animation
            // You might want to unobserve the element after it's visible if it's a one-time action
            // observer.unobserve(targetElement);
        } else {
            console.log('Element is not visible.');
            // Add logic for when the element leaves the viewport
        }
    };

    // Create a new IntersectionObserver instance
    const observer = new IntersectionObserver(intersectionCallback, observerOptions);

    // Start observing the target element
    observer.observe(targetElement);

    // Example: Styling for demonstration
    document.body.style.height = '300vh'; // Make the page scrollable
    targetElement.style.marginTop = '100vh'; // Position the target element
    targetElement.style.padding = '20px';
    targetElement.style.backgroundColor = 'lightblue';
    targetElement.textContent = 'Observe me!';
} else {
    console.error("Target element not found.");
}

Advantages of Intersection Observer:

  • Performance: Highly optimized for detecting visibility changes, reducing the need for manual scroll event handling.
  • Declarative: Easier to define conditions for visibility detection (e.g., percentage visible).
  • Cross-domain iframes: Can work with elements in cross-domain iframes.
  • Obscuring elements: Can detect if an element is obstructed by other elements.

Browser Support: Supported in modern browsers (Chrome 51+, Edge 15+, Firefox 55+). A polyfill is available for older browsers.

Solution 4: Checking for Corner Visibility (More Robust getBoundingClientRect variations)

This solution refines the getBoundingClientRect() approach by checking if any of the element’s four corners are within the viewport. This can be useful in scenarios where simply checking the overall bounding box might yield false positives or negatives, especially with complex layouts or CSS properties like z-index or overflow.

/**
 * Checks if an element is visible within the viewport, considering potential obstructions.
 * @param {Element} el The element to check.
 * @returns {boolean} True if any corner is visible, false otherwise.
 */
function isElementVisible(el) {
    var rect = el.getBoundingClientRect();
    var viewportWidth = window.innerWidth || document.documentElement.clientWidth;
    var viewportHeight = window.innerHeight || document.documentElement.clientHeight;

    // Function to get the element at specific coordinates
    var elementFromPoint = function(x, y) {
        return document.elementFromPoint(x, y);
    };

    // Check if the element is outside the viewport entirely
    if (rect.right < 0 || rect.bottom < 0 || rect.left > viewportWidth || rect.top > viewportHeight) {
        return false;
    }

    // Check if any of its four corners are visible and the element contains that point
    return (
        el.contains(elementFromPoint(rect.left, rect.top)) ||
        el.contains(elementFromPoint(rect.right, rect.top)) ||
        el.contains(elementFromPoint(rect.right, rect.bottom)) ||
        el.contains(elementFromPoint(rect.left, rect.bottom))
    );
}

// Example Usage:
var testElement = document.getElementById('another-element-id');
if (testElement) {
    // You'd typically call this within a scroll event handler or similar
    console.log("Is element visible (corner check)?", isElementVisible(testElement));
}

Limitations:

  • This method might incorrectly report an element as hidden if another element with a lower z-index is positioned in front of it, even if the front element doesn’t obscure the tested element.

Solution 5: Simpler getBoundingClientRect() Checks for Partial Visibility

Several variations focus on checking if any part of the element is visible, which can be useful for scenarios like infinite scrolling or lazy loading where an element appearing partially is sufficient.

5a: Basic Partial Visibility Check

This function checks if the element’s bottom edge is above the viewport’s bottom, and its top edge is below the viewport’s top.

/**
 * Checks if any part of an element is visible in the viewport (vertical check).
 * @param {Element} el The element to check.
 * @returns {boolean} True if any part is visible, false otherwise.
 */
function isElementPartiallyVisibleY(el) {
    var rect = el.getBoundingClientRect();
    var viewportHeight = window.innerHeight || document.documentElement.clientHeight;

    // Check if the element overlaps with the viewport vertically
    return rect.bottom > 0 && rect.top < viewportHeight;
}

5b: Horizontal and Vertical Partial Visibility

This expands on the previous check to include horizontal visibility.

/**
 * Checks if any part of an element is visible in the viewport (horizontal and vertical).
 * @param {Element} el The element to check.
 * @returns {boolean} True if any part is visible, false otherwise.
 */
function isElementPartiallyVisibleXY(el) {
    var rect = el.getBoundingClientRect();
    var viewportWidth = window.innerWidth || document.documentElement.clientWidth;
    var viewportHeight = window.innerHeight || document.documentElement.clientHeight;

    // Check if the element overlaps with the viewport horizontally and vertically
    return rect.bottom > 0 &&
           rect.right > 0 &&
           rect.left < viewportWidth &&
           rect.top < viewportHeight;
}

5c: inViewport Function (Commonly Used Variation)

This is a concise function that checks for any part of the element being in the viewport.

/**
 * Checks if an element is at least partially visible in the viewport.
 * @param {Element} element The element to check.
 * @returns {boolean} True if the element is partially visible, false otherwise.
 */
function isElementInView(element) {
  if (!element) return false; // Handle cases where element might not exist
  if (1 !== element.nodeType) return false; // Ensure it's a valid DOM node

  var html = document.documentElement;
  var rect = element.getBoundingClientRect();

  // Check if the element's rectangle intersects with the viewport
  return !!rect &&
    rect.bottom >= 0 &&
    rect.right >= 0 &&
    rect.left <= html.clientWidth &&
    rect.top <= html.clientHeight;
}

Solution 6: Handling Scrollable Parent Containers

A common oversight in many visibility checks is handling elements nested within scrollable containers. The following solutions address this by recursively checking the element’s visibility against its ancestors.

6a: Recursive Parent Check (Y-Axis)

This function checks if an element is visible within its parent’s scrollable area, focusing on the vertical axis.

/**
 * Checks if an element is visible within its parent's viewport (Y-axis).
 * @param {Element} el The element to check.
 * @returns {boolean} True if visible within the parent, false otherwise.
 */
var isElementVisibleInParentY = function(el){
    var elementTop = el.getBoundingClientRect().top;
    var parentElement = el.parentNode;

    do {
        if (!parentElement) return false; // Reached the top without finding a scrollable parent

        var parentRect = parentElement.getBoundingClientRect();

        // If the element's top is below the parent's bottom, it's out of view
        if (elementTop <= parentRect.bottom === false) {
            return false;
        }

        // If the parent has overflow scroll, this check is relevant
        // We stop if we reach the document body
        if (parentElement === document.body) {
            // Ensure it's also within the main document viewport
            return elementTop <= document.documentElement.clientHeight;
        }

        parentElement = parentElement.parentNode;
    } while (parentElement);

    return false; // Should not reach here if logic is correct
};

6b: Recursive Parent Check (Full Visibility)

This approach checks for full visibility within all parent containers, making it more robust for complex layouts.

/**
 * Checks if an element is fully visible within all its parent containers.
 * @param {Element} el The element to check.
 * @param {boolean} [fullyVisible=true] Whether to check for full or partial visibility.
 * @returns {boolean} True if the element is fully visible in all parents, false otherwise.
 */
function isReallyVisible(el, fullyVisible = true) {
    if (!el || el.tagName === "HTML") {
        return true; // Base case: reached the HTML element or element is null/undefined
    }

    var parentRect = el.parentNode.getBoundingClientRect();
    var elementRect = el.getBoundingClientRect();
    var isVisibleInParent = true;

    // Check visibility against the parent's boundaries
    if (fullyVisible) {
        isVisibleInParent =
            elementRect.top >= parentRect.top &&
            elementRect.left >= parentRect.left &&
            elementRect.bottom <= parentRect.bottom &&
            elementRect.right <= parentRect.right;
    } else {
        // Partial visibility check (overlap)
        isVisibleInParent =
            (elementRect.bottom > parentRect.top) &&
            (elementRect.right > parentRect.left) &&
            (elementRect.top < parentRect.bottom) &&
            (elementRect.left < parentRect.right);
    }

    // If not visible in the current parent, return false immediately
    if (!isVisibleInParent) {
        return false;
    }

    // Recursively check the parent element
    return isReallyVisible(el.parentNode, fullyVisible);
}

Note: These recursive checks can be resource-intensive if not managed properly, especially with deep DOM structures.

Solution 7: The Intersection Observer API for More Precise Control

The Intersection Observer API excels here as well. It can be configured to observe intersection ratios, allowing you to define precisely how much of an element needs to be visible.

// Example: Using Intersection Observer to detect when an element is visible
const target = document.querySelector('#observed-element');

if (target) {
    const observer = new IntersectionObserver(([entry]) => {
        // entry.isIntersecting is true if the target is at least partially visible
        if (entry.isIntersecting) {
            console.log('Target element is now visible!');
            // You can also check entry.intersectionRatio for percentage
            // console.log(`Intersection ratio: ${entry.intersectionRatio}`);
            // If you only need to know once, you can unobserve:
            // observer.unobserve(target);
        } else {
            console.log('Target element is no longer visible.');
        }
    }, {
        root: null, // Viewport
        threshold: [0, 0.25, 0.5, 0.75, 1] // Observe at different intersection levels
    });

    observer.observe(target);
}

Solution 8: jQuery Plugin for Visibility Checks

For those heavily invested in jQuery, creating a reusable plugin simplifies visibility checks.

/**
 * jQuery plugin to check if an element is fully within the viewport.
 * Extends jQuery.fn with an 'inView' method.
 */
(function($) {
    $.fn.inView = function() {
        if (!this.length) {
            return false; // Return false if the jQuery object is empty
        }

        var element = this.get(0); // Get the first DOM element
        var rect = element.getBoundingClientRect();
        var windowHeight = window.innerHeight || document.documentElement.clientHeight;
        var windowWidth = window.innerWidth || document.documentElement.clientWidth;

        // Check if the element's rectangle is fully within the viewport
        return (
            rect.top >= 0 &&
            rect.left >= 0 &&
            rect.bottom <= windowHeight &&
            rect.right <= windowWidth
        );
    };

    // Example of a related plugin: checking if ALL elements in a selection are in view
    $.fn.allInView = function() {
        var allVisible = true;
        this.each(function() {
            if (!$(this).inView()) {
                allVisible = false;
                return false; // Exit loop early if one element is not in view
            }
        });
        return allVisible;
    };
})(jQuery);

// Usage Example:
$(window).on('scroll', function() {
    if ($('footer').inView()) {
        console.log("Footer is in view!");
        // Perform actions when the footer becomes visible
    }

    // Example with multiple elements
    $('.some-class').filter(function() {
        return $(this).inView(); // Select elements that are in view
    }).css('opacity', 1); // Make them visible
});

Solution 9: More Robust Visibility Checks for Specific Scenarios

9a: Handling Zoom and Visual Viewport

Mobile browsers and zoom features can affect getBoundingClientRect() results. The visualViewport API can provide more accurate dimensions in these cases.

/**
 * Checks if an element is within the visual viewport, accounting for zoom.
 * @param {HTMLElement} element The element to check.
 * @returns {boolean} True if the element is vertically within the visual viewport.
 */
const isElementInVisualViewportY = (element) => {
    if (!element) return false;

    var rect = element.getBoundingClientRect();
    var elementTop = rect.top;
    var elementBottom = rect.bottom;
    var viewportHeight = window.innerHeight || document.documentElement.clientHeight;

    // Adjust for visualViewport offsets if available
    if (window.visualViewport) {
        elementTop -= window.visualViewport.offsetTop;
        elementBottom -= window.visualViewport.offsetTop;
        viewportHeight = window.visualViewport.height;
    }

    // Check if the element is vertically within the adjusted viewport
    return elementTop >= 0 && elementBottom <= viewportHeight;
};

9b: Checking Element Visibility Based on Parent Viewport

This function specifically checks if an element is visible within its direct parent’s viewport.

/**
 * Checks if an element is visible within its parent's viewport boundaries.
 * @param {Element} el The element to check.
 * @param {Element} [pa=el.parentNode] The parent element to check against. Defaults to the element's parent node.
 * @returns {boolean} True if the element is visible within the parent, false otherwise.
 */
function isElementVisibleInParent(el, pa = el.parentNode) {
    if (!el || !pa) return false;

    var elementRect = el.getBoundingClientRect();
    var parentRect = pa.getBoundingClientRect();

    // Check if the element's bounding box overlaps with the parent's bounding box
    return (
        elementRect.bottom >= parentRect.top &&
        elementRect.right >= parentRect.left &&
        elementRect.top <= parentRect.bottom &&
        elementRect.left <= parentRect.right
    );
}

9c: Detailed Viewport Information

This function provides a comprehensive object detailing various visibility states of an element relative to the viewport.

/**
 * Returns detailed viewport placement information for an element.
 * @param {Element} el The element to get information for.
 * @returns {object} An object containing various visibility properties.
 */
function getElementViewportInfo(el) {
    let info = {};
    let rect = el.getBoundingClientRect();
    let windowHeight = window.innerHeight || document.documentElement.clientHeight;
    let windowWidth  = window.innerWidth || document.documentElement.clientWidth;

    // Basic intersection checks
    let insideX = rect.left >= 0 && rect.left + rect.width <= windowWidth;
    let insideY = rect.top >= 0 && rect.top + rect.height <= windowHeight;
    info.isInsideViewport = insideX && insideY; // Fully inside viewport

    let aroundX = rect.left < 0 && rect.left + rect.width > windowWidth;
    let aroundY = rect.top < 0 && rect.top + rect.height > windowHeight;
    info.isAroundViewport = aroundX && aroundY; // Completely covers viewport

    // Edge intersection checks
    let onTop    = rect.top < 0 && rect.top + rect.height > 0;
    let onRight  = rect.left < windowWidth && rect.left + rect.width > windowWidth;
    let onLeft   = rect.left < 0 && rect.left + rect.width > 0;
    let onBottom = rect.top < windowHeight && rect.top + rect.height > windowHeight;

    let intersectsY = insideY || aroundY || onTop || onBottom;
    let intersectsX = insideX || aroundX || onLeft || onRight;

    info.isOnTopEdge    = onTop && intersectsX;
    info.isOnRightEdge  = onRight && intersectsY;
    info.isOnBottomEdge = onBottom && intersectsX;
    info.isOnLeftEdge   = onLeft && intersectsY;
    info.isOnEdge = info.isOnLeftEdge || info.isOnRightEdge || info.isOnTopEdge || info.isOnBottomEdge;

    // General viewport intersection
    let isInX = insideX || aroundX || info.isOnLeftEdge || info.isOnRightEdge;
    let isInY = insideY || aroundY || info.isOnTopEdge || info.isOnBottomEdge;
    info.isInViewport = isInX && isInY; // Partially or fully in viewport

    // Specifically partially visible (must be in viewport and intersect an edge)
    info.isPartiallyInViewport = info.isInViewport && info.isOnEdge;

    return info;
}

Solution 10: Advanced Visibility with Overlapping and Parent Clipping

This advanced solution tackles visibility considering parent clipping and provides options for checking partial or full visibility, even for elements larger than the viewport. It uses document.elementFromPoint to check which element is at specific coordinates.

/**
 * Checks if an element is visible, considering parent clipping and scroll.
 * @param {Element} element The element to check.
 * @param {Element} [parent=element.parentNode] The parent element for clipping checks.
 * @param {boolean} [crossSearchAlgorithm=false] Enable advanced check for elements larger than viewport.
 * @returns {boolean} True if the element is visible, false otherwise.
 */
function isElementPreciselyVisible(element, parent = element.parentNode, crossSearchAlgorithm = false) {
    if (!element) return false;

    var elementRect = element.getBoundingClientRect();
    var parentRect = parent ? parent.getBoundingClientRect() : element.parentNode.getBoundingClientRect();

    // Basic check: if element is completely outside parent's bounds
    if (elementRect.right < parentRect.left || elementRect.bottom < parentRect.top ||
        elementRect.left > parentRect.right || elementRect.top > parentRect.bottom) {
        return false;
    }

    var flag = false;
    var elementFromPoint = (x, y) => document.elementFromPoint(x, y);

    // Check border pixels from left to right
    for (var x = elementRect.left; x < elementRect.right; x++) {
        if (element.contains(elementFromPoint(elementRect.top, x)) ||
            element.contains(elementFromPoint(elementRect.bottom, x))) {
            flag = true;
            break;
        }
    }

    // Check border pixels from top to bottom if not already flagged
    if (!flag) {
        for (var y = elementRect.top; y < elementRect.bottom; y++) {
            if (element.contains(elementFromPoint(rect.left, y)) ||
                element.contains(elementFromPoint(rect.right, y))) {
                flag = true;
                break;
            }
        }
    }

    // Advanced algorithm for elements larger than viewport
    if (crossSearchAlgorithm && !flag) {
        let x = elementRect.left;
        let y = elementRect.top;
        // Check from top-left to bottom-right
        while (x < elementRect.right || y < elementRect.bottom) {
            if (element.contains(elementFromPoint(x, y))) {
                flag = true;
                break;
            }
            if (x < elementRect.right) x++;
            if (y < elementRect.bottom) y++;
        }
        // Check from top-right to bottom-left if not flagged
        if (!flag) {
            x = elementRect.right;
            y = elementRect.top;
            while (x > elementRect.left || y < elementRect.bottom) {
                if (element.contains(elementFromPoint(x, y))) {
                    flag = true;
                    break;
                }
                if (x > elementRect.left) x--;
                if (y < elementRect.bottom) y++;
            }
        }
    }
    return flag;
}

// Example Usage with a scrollable container:
document.getElementById('container').addEventListener("scroll", function() {
    var elements = document.getElementsByClassName("element");
    var consoleOutput = document.getElementById('console');

FAQs on JavaScript Element Visibility

Q: What is the most efficient way to check if an element is in the viewport

ANS: The most efficient and recommended method is using the Intersection Observer API. It’s performant and designed specifically for this purpose. If browser support is a concern, getBoundingClientRect() combined with careful scroll event handling is a solid alternative.

Q: How does getBoundingClientRect work for visibility checks

ANS: getBoundingClientRect() provides an element’s size and its position relative to the viewport. By comparing these values (top, bottom, left, right) against the viewport’s dimensions (window.innerHeight, window.innerWidth), you can determine if the element is within the visible area.

Q: Can I detect when an element becomes visible or disappears

ANS: Yes, you can achieve this by attaching event listeners (like scroll, resize, load) to trigger your visibility check function. For a more efficient approach, use the Intersection Observer API, which provides callbacks for intersection status changes.

Q: Does the Intersection Observer API work in older browsers

ANS: The Intersection Observer API is supported in modern browsers (Chrome 51+, Edge 15+, Firefox 55+, Safari 12.1+). For older browsers, you can use a polyfill like the one provided by polyfill.io.

Q: How to handle elements inside scrollable containers

ANS: To correctly detect visibility within scrollable containers, you need to consider the scrollable parent’s boundaries. Recursive functions that check against parent getBoundingClientRect() values or the Intersection Observer API (which can be configured with a specific root element) are effective solutions.
