“Python += vs +: Understanding In-Place vs. New Object Creation”

When working with Python, you’ve likely encountered the += and + operators. While they both perform addition-like operations, their behavior with different data types, particularly lists, can lead to distinct outcomes. This divergence stems from the underlying special methods that Python objects implement.

The Core Difference: __iadd__ vs. __add__

The fundamental distinction lies in how Python handles these operators for objects that support them.

  • The += operator attempts to invoke the __iadd__ special method. This method is designed for in-place addition, meaning it modifies the object directly without creating a new one.
  • The + operator, conversely, utilizes the __add__ special method. This method is responsible for returning a new object that is the result of the addition, leaving the original objects unchanged.

When += is applied to an object with a defined __iadd__, the object is mutated. If __iadd__ is absent, Python falls back to using __add__, which results in a new object being created.

This behavior is why mutable types like lists see their values altered directly with +=. For immutable types such as tuples, strings, and integers, += effectively becomes a shorthand for a = a + b, generating a new object.

It’s crucial to recognize that when a type supports both __iadd__ and __add__, the operations are not interchangeable. a += b mutates a via __iadd__, whereas a = a + b creates a fresh object and reassigns it to a.

Consider these examples:

>>> list_a = [1, 2]
>>> list_b = [1, 2]
>>>
>>> # Using += (in-place modification via __iadd__)
>>> list_a += [3]
>>>
>>> # Using = ... + ... (new object creation via __add__)
>>> list_b = list_b + [3]
>>>
>>> print(f"list_a: {list_a}")
list_a: [1, 2, 3]
>>> print(f"list_b: {list_b}")
list_b: [1, 2, 3]
>>>
>>> # Now let's look at references
>>> original_list_a = [1, 2]
>>> original_list_b = [1, 2]
>>>
>>> id_a_before = id(original_list_a)
>>> original_list_a += [3]
>>> id_a_after = id(original_list_a)
>>> print(f"ID of original_list_a before and after +=: {id_a_before}, {id_a_after}")
ID of original_list_a before and after +=: 140396838386496, 140396838386496
>>>
>>> id_b_before = id(original_list_b)
>>> original_list_b = original_list_b + [3]
>>> id_b_after = id(original_list_b)
>>> print(f"ID of original_list_b before and after = ... + ...: {id_b_before}, {id_b_after}")
ID of original_list_b before and after = ... + ...: 140396838387136, 140396838387328

In essence, for immutable types, a += b and a = a + b are functionally equivalent because the lack of an __iadd__ method forces the creation of a new object anyway. This design choice allows += to be used with immutable types like numbers.

extend() and += for Lists

For lists specifically, += acts as a shorthand for the extend() method. The extend() function appends all elements from an iterable to the list in place.

When you use foo += something, you are modifying the foo list directly. The reference foo points to the same list object, but its contents are altered. In contrast, foo = foo + something creates an entirely new list object, and the foo reference is updated to point to this new object.

>>> my_list = []
>>> initial_id = id(my_list)
>>> print(f"Initial ID: {initial_id}")
Initial ID: 139687448120384
>>>
>>> my_list += [3]
>>> updated_id_plus_equals = id(my_list)
>>> print(f"ID after += [3]: {updated_id_plus_equals}")
ID after += [3]: 139687448120384
>>>
>>> my_list = my_list + [3]
>>> updated_id_equals_plus = id(my_list)
>>> print(f"ID after = ... + [3]: {updated_id_equals_plus}")
ID after = ... + [3]: 139687448120576

Notice how the id() remains the same after +=, but changes after the = ... + ... operation.

Class vs. Instance Attributes and +=

A common pitfall arises when += is used with class attributes versus instance attributes. If bar is a class attribute, modifying it in place using += within an instance method will affect all instances of that class. This is because all instances share the same class attribute. However, if you reassign self.bar (e.g., self.bar = self.bar + [x]), you create an instance-specific attribute, isolating the change from other instances.

Consider these class definitions:

class FooWithClassAttribute:
    bar = []  # Class attribute

    def __init__(self, x):
        # Modifies the class attribute in-place
        self.bar += [x]

class FooWithInstanceAttribute:
    def __init__(self, x):
        # Creates an instance attribute
        self.bar = [x]

In FooWithClassAttribute, self.bar += [x] translates to FooWithClassAttribute.bar.__iadd__([x]). This modifies the shared class attribute.

In FooWithInstanceAttribute, self.bar = [x] creates a new list specific to each instance.

A more explicit way to achieve the desired behavior with class attributes might look like this:

class FooAlternative:
    bar = []

# To modify the class attribute directly:
# FooAlternative.bar = [x] # This would overwrite the existing list

When += is applied to a class attribute that is a mutable object, and then that attribute is accessed via an instance, the change is visible across all instances because they all refer to the same underlying object. However, if you later assign a new object to instance.attribute, that instance will then have its own separate object, distinct from the class attribute.

Let’s illustrate this with the foo and foo2 examples from the original content:

class foo:
    bar = []

    def __init__(self, x):
        self.bar += [x] # Modifies the class attribute in-place

class foo2:
    bar = []

    def __init__(self, x):
        self.bar = self.bar + [x] # Creates a new list and assigns it to the instance

  • foo Class:

    • f = foo(1): foo.bar becomes [1], and f.bar also points to [1].
    • g = foo(2): foo.bar becomes [1, 2], and g.bar also points to [1, 2]. All instances share the same list.
    • f.bar += [3]: The shared list foo.bar (and thus f.bar and g.bar) becomes [1, 2, 3].
    • f.bar = f.bar + [4]: A new list [1, 2, 3, 4] is created. f.bar now points to this new list, while g.bar still points to [1, 2, 3].

  • foo2 Class:

    • f = foo2(1): A new list [1] is created, and f.bar points to it. foo2.bar remains [].
    • g = foo2(2): A new list [2] is created, and g.bar points to it. foo2.bar remains []. Each instance has its own list.

You can verify object identity using id(). For example:

f_instance = foo(1)
g_instance = foo(2)

print(f"ID of foo.bar: {id(foo.bar)}")
print(f"ID of f_instance.bar: {id(f_instance.bar)}")
print(f"ID of g_instance.bar: {id(g_instance.bar)}")

f_instance.bar += [3]
print(f"After f_instance.bar += [3]:")
print(f"ID of foo.bar: {id(foo.bar)}")
print(f"ID of f_instance.bar: {id(f_instance.bar)}")
print(f"ID of g_instance.bar: {id(g_instance.bar)}")

f_instance.bar = f_instance.bar + [4]
print(f"After f_instance.bar = f_instance.bar + [4]:")
print(f"ID of foo.bar: {id(foo.bar)}")
print(f"ID of f_instance.bar: {id(f_instance.bar)}")
print(f"ID of g_instance.bar: {id(g_instance.bar)}")

Augmented Assignments PEP 203

The Python Enhancement Proposal (PEP) 203, “Augmented Assignments,” clarifies the intent behind operators like +=. It states that these operators implement the same operation as their binary counterparts but perform the action “in-place” when the left-hand operand’s object supports it. Crucially, the left-hand side is evaluated only once. The core idea is that augmented assignment signals to the object that it should operate on itself, rather than creating a modified copy.

Illustrative Examples with Mutable Objects

When dealing with lists, += can lead to unexpected behavior if you’re not mindful of object identity and modification.

>>> nested_list = [[1], [2], [3]]
>>> subset_list = []
>>>
>>> subset_list += nested_list[0:1]
>>> print(f"subset_list after +=: {subset_list}")
subset_list after +=: [[1]]
>>> print(f"nested_list: {nested_list}")
nested_list: [[1], [2], [3]]
>>>
>>> # Modifying an element within the nested list
>>> subset_list[0][0] = 'changed'
>>> print(f"nested_list after modification: {nested_list}")
nested_list after modification: [['changed'], [2], [3]]

Here, subset_list += nested_list[0:1] appends a reference to [1] from nested_list. When you modify subset_list[0][0], you are actually altering the original list within nested_list because both variables point to the same inner list object.

Similarly, consider the aliasing effect:

>>> list_a = [1, 2, 3, 4]
>>> list_b = list_a # list_b is now an alias for list_a
>>>
>>> list_a += [5] # Modifies list_a in-place
>>> print(f"list_a: {list_a}, list_b: {list_b}")
list_a: [1, 2, 3, 4, 5], list_b: [1, 2, 3, 4, 5]
>>>
>>> list_c = [1, 2, 3, 4]
>>> list_d = list_c # list_d is an alias for list_c
>>>
>>> list_c = list_c + [5] # Creates a new list and reassigns list_c
>>> print(f"list_c: {list_c}, list_d: {list_d}")
list_c: [1, 2, 3, 4, 5], list_d: [1, 2, 3, 4]

In the first case, += modifies the original list, so both list_a and list_b reflect the change. In the second case, list_c = list_c + [5] creates a new list, and list_c is updated, but list_d continues to refer to the original, unmodified list.

Immutable vs. Mutable Object Behavior

When an operation is performed on an immutable object (like an integer), Python doesn’t modify the existing object. Instead, it creates a new object with the result.

>>> num_a = 89
>>> id_a_initial = id(num_a)
>>> print(f"Initial ID of num_a: {id_a_initial}")
Initial ID of num_a: 140396838373632
>>>
>>> num_a = num_a + 1 # Creates a new object for 90
>>> print(f"num_a after addition: {num_a}")
num_a after addition: 90
>>> id_a_after = id(num_a)
>>> print(f"ID of num_a after addition: {id_a_after}")
ID of num_a after addition: 140396838373808 # Different ID!

The id() changes confirm that a new integer object was created.

With mutable objects like lists, the behavior is different:

>>> mutable_list_x = [1, 2, 3]
>>> id_x_initial = id(mutable_list_x)
>>> print(f"Initial ID of mutable_list_x: {id_x_initial}")
Initial ID of mutable_list_x: 140396838375360
>>>
>>> mutable_list_y = mutable_list_x # y is an alias
>>> id_y_initial = id(mutable_list_y)
>>> print(f"ID of mutable_list_y: {id_y_initial}")
ID of mutable_list_y: 140396838375360 # Same ID as x
>>>
>>> mutable_list_y += [4] # Modifies mutable_list_x in-place
>>> id_x_after_plus_equals = id(mutable_list_x)
>>> print(f"ID of mutable_list_x after y += [4]: {id_x_after_plus_equals}")
ID of mutable_list_x after y += [4]: 140396838375360 # Still the same ID
>>>
>>> print(f"mutable_list_x: {mutable_list_x}, mutable_list_y: {mutable_list_y}")
mutable_list_x: [1, 2, 3, 4], mutable_list_y: [1, 2, 3, 4]
>>>
>>> id_y_after_plus_equals = id(mutable_list_y)
>>> print(f"ID of mutable_list_y after y += [4]: {id_y_after_plus_equals}")
ID of mutable_list_y after y += [4]: 140396838375360 # Still the same ID

This demonstrates how in-place operations (+=) on mutable objects maintain the object’s identity, affecting all references to it. For further details on how object identity works in Python, you might find discussions on shallow copy vs. deep copy informative.

FAQs on Python += vs +

Q: What is the primary difference between Python's + and += operators

ANS: The + operator calls the __add__ method, which returns a new object. The += operator calls the __iadd__ method for in-place modification; if __iadd__ is not available, it falls back to __add__.

Q: How does += affect mutable objects like lists

ANS: For mutable objects like lists, += typically uses the __iadd__ method, modifying the list in place without creating a new object. This is often equivalent to using the extend() method.

Q: What happens when += is used with immutable objects like integers

ANS: When += is used with immutable objects, __iadd__ is not available. Python then uses __add__ and reassigns the result to the variable, effectively creating a new object, similar to a = a + b.

Q: In Python, why does modifying a list through one reference affect another reference

ANS: If multiple variables reference the same mutable object (like a list), modifying the object through one variable will be reflected in all other variables referencing that same object. This is due to how Python handles object references.

Q: How do class attributes differ from instance attributes in Python with +=

ANS: Modifying a class attribute with += in an instance method affects all instances sharing that attribute. Modifying an instance attribute with += only affects that specific instance.
