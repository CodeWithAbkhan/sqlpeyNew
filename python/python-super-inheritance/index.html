“Python super(): When and Why to Use It for Inheritance”

When working with object-oriented programming in Python, understanding how to properly call methods from parent classes is crucial, especially when dealing with inheritance. The super() function plays a key role in this, offering a flexible and robust way to interact with the inheritance hierarchy. But what exactly does super() do, and when should you prefer it over directly calling a parent class’s method?

Let’s delve into the mechanics and benefits of using super().

The Core Difference: Direct Call vs. super()

At its heart, the distinction lies in how you reference the parent class’s method.

When you write:

SomeBaseClass.__init__(self)

This directly calls the __init__ method of SomeBaseClass. You are explicitly stating which parent class’s method to invoke.

Conversely, when you use:

super().__init__()

This tells Python to call the __init__ method of the next class in the instance’s Method Resolution Order (MRO). This “next” class is determined by the order in which classes are inherited and can change if the inheritance structure is modified.

Why Prefer super()? Simplicity and Forward Compatibility

One of the primary advantages of super() is that it simplifies your code and makes it more resilient to changes. As Bob Martin suggests, good architecture allows for deferring decisions. super() embodies this by allowing your class to work correctly even if its inheritance chain changes later.

For example, if your class inherits from SomeBaseClass, and you later decide to introduce another base class, say AnotherBaseClass, between SomeBaseClass and your current class, using super() ensures that the appropriate __init__ (or any other method) is called without you needing to manually update the code.

Consider this:

class SomeBaseClass:
    def __init__(self):
        print('SomeBaseClass init called')

class UnsuperChild(SomeBaseClass):
    def __init__(self):
        print('UnsuperChild init called')
        SomeBaseClass.__init__(self) # Hardcoded call

class SuperChild(SomeBaseClass):
    def __init__(self):
        print('SuperChild init called')
        super().__init__() # Uses super()

Now, imagine we introduce an InjectMe class:

class InjectMe(SomeBaseClass):
    def __init__(self):
        print('InjectMe init called')
        super().__init__()

class UnsuperInjector(UnsuperChild, InjectMe):
    pass

class SuperInjector(SuperChild, InjectMe):
    pass

print("Testing UnsuperInjector:")
obj_unsuper = UnsuperInjector()

print("\nTesting SuperInjector:")
obj_super = SuperInjector()

Expected Output:

Testing UnsuperInjector:
UnsuperChild init called
SomeBaseClass init called

Testing SuperInjector:
SuperChild init called
InjectMe init called
SomeBaseClass init called

The UnsuperInjector fails to incorporate InjectMe’s behavior because UnsuperChild explicitly calls SomeBaseClass.__init__. However, SuperInjector correctly integrates InjectMe due to the dynamic nature of super().

Python 2 vs. Python 3 super()

While super(Child, self).__init__() works in both Python 2 and 3, the Python 3 version super().__init__() is generally preferred now. It automatically infers the class and instance from the current scope, making it cleaner.

Handling Multiple Inheritance and MRO

The true power of super() becomes apparent in multiple inheritance scenarios. Python uses the C3 linearization algorithm to determine the Method Resolution Order (MRO), which dictates the sequence in which base classes are searched for a method.

Consider this hierarchy:

    A
   / \
  B   C
   \ /
    D

The MRO for D in Python 3 is typically (D, B, C, A, object).

When you call super().method(), Python traverses this MRO. The behavior can change significantly based on where super() is called within a method.

class A:
    def m(self):
        print('A')

class B(A):
    def m(self):
        print('B start')
        super().m()
        print('B end')

class C(A):
    def m(self):
        print('C start')
        super().m()
        print('C end')

class D(B, C):
    def m(self):
        print('D start')
        super().m()
        print('D end')

d = D()
d.m()

Output:

D start
B start
C start
A
C end
B end
D end

Notice how super().m() in D calls B.m(), which in turn calls C.m() (due to super() in C), and finally A.m(). This predictable traversal through the MRO is a key benefit.

Working with Different Method Types (__init__, classmethod, staticmethod)

super() is versatile and can be used with instance methods, class methods, and static methods.

Instance Methods (__init__)

When calling __init__ or other instance methods, super() handles passing the instance implicitly in Python 3.

class Base:
    def __init__(self):
        print("initializing Base")

class ChildA(Base):
    def __init__(self):
        print("initializing ChildA")
        Base.__init__(self) # Explicit call

class ChildB(Base):
    def __init__(self):
        print("initializing ChildB")
        super().__init__() # Using super()

class Grandchild(ChildA, ChildB):
    def __init__(self):
        print("initializing Grandchild")
        super().__init__() # Calls ChildA then ChildB's super()

print("Grandchild with super():")
Grandchild()

Output:

Grandchild with super():
initializing Grandchild
initializing ChildA
initializing ChildB
initializing Base

Using super().__init__() in ChildB ensures that if ChildB were part of a more complex multiple inheritance, its parent’s __init__ would be correctly invoked according to the MRO.

Class Methods

For class methods, super() correctly passes the class reference (cls).

class A:
    @classmethod
    def alternate_constructor(cls):
        print(f"A.alternate_constructor called for {cls.__name__}")
        return cls()

class B(A):
    @classmethod
    def alternate_constructor(cls):
        print(f"B.alternate_constructor called for {cls.__name__}")
        return super().alternate_constructor()

print("Using super() with class methods:")
b_instance = B.alternate_constructor()

Output:

Using super() with class methods:
B.alternate_constructor called for B
A.alternate_constructor called for B

Static Methods

Similarly, super() can be used with static methods, with cls being passed explicitly.

class BaseWithNew:
    def __new__(cls, *args, **kwargs):
        print(f"BaseWithNew.__new__ called for {cls.__name__}")
        return super(BaseWithNew, cls).__new__(cls)

class ChildNew(BaseWithNew):
    def __new__(cls, *args, **kwargs):
        print(f"ChildNew.__new__ called for {cls.__name__}")
        return super().__new__(cls)

print("Using super() with __new__:")
child_obj = ChildNew()

Output:

Using super() with __new__:
ChildNew.__new__ called for ChildNew
BaseWithNew.__new__ called for ChildNew

Handling Differing Signatures with **kwargs

A robust way to handle inheritance chains where methods might have different signatures is to use **kwargs and pass all received arguments up the chain.

class SuperObject:
    def __init__(self, **kwargs):
        print('SuperObject init')
        # Ensures that object.__init__ is called correctly
        super().__init__()

class A(SuperObject):
    def __init__(self, **kwargs):
        print("A init")
        super().__init__(**kwargs)

class B(SuperObject):
    def __init__(self, **kwargs):
        print("B init")
        super().__init__(**kwargs)

class C(A):
    def __init__(self, age, **kwargs):
        print(f"C init with age={age}")
        super().__init__(age=age, **kwargs)

class D(B):
    def __init__(self, name, **kwargs):
        print(f"D init with name={name}")
        super().__init__(name=name, **kwargs)

class E(C, D):
    def __init__(self, name, age, *args, **kwargs):
        print(f"E init with name={name}, age={age}")
        super().__init__(name=name, age=age, *args, **kwargs)

print("Testing complex inheritance with **kwargs:")
instance_e = E(name='Py', age=3)

Output:

Testing complex inheritance with **kwargs:
E init with name=Py, age=3
C init with age=3
A init
D init with name=Py
B init
SuperObject init

This pattern ensures that all arguments are passed along, and the __init__ methods cooperate effectively.

When Direct Calls Might Seem Simpler (But Aren’t Always Better)

For single inheritance, the difference between SomeBaseClass.__init__(self) and super().__init__() might seem minimal. However, super() offers a layer of indirection that provides forward compatibility. If you later refactor your inheritance, code using super() is less likely to break. It decouples your class from the explicit naming of its immediate parent.

Key Takeaways on super():

  • Dynamic Parent Referencing: super() refers to the next class in the MRO, not a statically known parent.
  • Multiple Inheritance: Essential for correctly chaining calls in complex inheritance hierarchies.
  • Forward Compatibility: Makes your code more adaptable to future changes in inheritance.
  • Argument Handling: Use **kwargs for flexible argument passing across different method signatures.
  • Python 3 Preference: super().__init__() is the modern, concise way.

By embracing super(), you build more maintainable and flexible Python code, particularly as your projects grow and inheritance structures evolve.

FAQs on Python super()

Q: What is the primary benefit of using super compared to direct parent calls

ANS: The primary benefit is forward compatibility and flexibility. super() calls the next method in the Method Resolution Order (MRO), which adapts to changes in inheritance, unlike direct calls that are hardcoded to a specific parent.

Q: Does super work with single inheritance

ANS: Yes, super() works with single inheritance. While the benefits are less pronounced than in multiple inheritance, it still offers cleaner code and better future-proofing by avoiding hardcoded parent references.

Q: How does super handle multiple inheritance

ANS: super() is crucial for multiple inheritance. It correctly navigates the Method Resolution Order (MRO) to call methods from all relevant parent classes in the defined sequence, ensuring proper initialization and behavior chaining.

Q: Should I use super() with arguments or without

ANS: In Python 3, super().__init__() (without arguments) is generally preferred. It automatically infers the class and instance context, making the code cleaner and more readable. The version with arguments, super(ClassName, self).__init__(), is more explicit and works in Python 2 but is less common in modern Python.

Q: How to manage different method signatures using super

ANS: To manage different method signatures, especially in __init__, accept **kwargs in your methods and pass all received keyword arguments to super().__init__(**kwargs). This allows methods to handle varying parameters gracefully across the inheritance chain.

Q: Is super() needed for classmethods and staticmethods

ANS: Yes, super() can be used with class methods and static methods to call the parent’s implementation of those methods, following the same MRO-based logic.
