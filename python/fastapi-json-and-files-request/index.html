“FastAPI: Sending JSON and Files in Same Request”

When developing web APIs with FastAPI, a common requirement is to send both structured data (like JSON) and files within a single HTTP request. However, the HTTP protocol has a constraint: you generally cannot send multipart/form-data (used for files) and application/json in the same request body. So, how can you achieve this with FastAPI? This question delves into various effective strategies and provides clear code examples.

The core issue stems from how web servers interpret request bodies. When a request specifies multipart/form-data, the body is structured as a series of parts, each with its own headers and content, separated by a boundary. JSON data, on the other hand, is typically sent as a single block with the Content-Type header set to application/json. Attempting to mix these directly leads to parsing conflicts.

FastAPI, being a web framework built on ASGI and leveraging Pydantic for data validation, offers flexible ways to handle this. The key is to package your JSON data in a way that it can be sent as part of the multipart/form-data payload.

Let’s explore several methods to accomplish this:

Method 1: Using Form and File Parameters

This is a direct approach recommended by the FastAPI documentation. You can declare fields that expect form data using Form(...) and files using File(...).

Prerequisite: Ensure you have python-multipart installed:

pip install python-multipart

Here’s how you can set up your FastAPI application:

# app.py
from fastapi import Form, File, UploadFile, Request, FastAPI
from typing import List
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates

app = FastAPI()
templates = Jinja2Templates(directory="templates")

@app.post("/submit")
def submit(
    name: str = Form(...),
    point: float = Form(...),
    is_accepted: bool = Form(...),
    files: List[UploadFile] = File(...),
):
    return {
        "JSON Payload": {"name": name, "point": point, "is_accepted": is_accepted},
        "Filenames": [file.filename for file in files],
    }

@app.get("/", response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse("index.html", {"request": request})

And a corresponding HTML template (templates/index.html):

<!DOCTYPE html>
<html>
<body>
    <form method="post" action="http://127.0.0.1:8000/submit" enctype="multipart/form-data">
        name : <input type="text" name="name" value="foo"><br>
        point : <input type="text" name="point" value=0.134><br>
        is_accepted : <input type="text" name="is_accepted" value=True><br>
        <label for="files">Choose file(s) to upload</label>
        <input type="file" id="files" name="files" multiple>
        <input type="submit" value="submit">
    </form>
</body>
</html>

You can test this via the OpenAPI docs at /docs, or using Python’s requests library:

# test.py
import requests

url = 'http://127.0.0.1:8000/submit'
files_to_upload = [('files', open('test_files/a.txt', 'rb')), ('files', open('test_files/b.txt', 'rb'))]
form_data = {"name": "foo", "point": 0.13, "is_accepted": False}
resp = requests.post(url=url, data=form_data, files=files_to_upload)
print(resp.json())

Note: Make sure to create a test_files directory with a.txt and b.txt for this test.

Method 2: Using Pydantic Models with Depends

This approach leverages Pydantic models for structured data and injects them into your endpoint using FastAPI’s dependency injection system.

# app.py
from fastapi import Form, File, UploadFile, Request, FastAPI, Depends
from typing import List, Optional
from fastapi.responses import HTMLResponse
from pydantic import BaseModel
from fastapi.templating import Jinja2Templates

app = FastAPI()
templates = Jinja2Templates(directory="templates")

class Base(BaseModel):
    name: str
    point: Optional[float] = None
    is_accepted: Optional[bool] = False

@app.post("/submit")
def submit(base: Base = Depends(), files: List[UploadFile] = File(...)):
    return {
        "JSON Payload": base,
        "Filenames": [file.filename for file in files],
    }

@app.get("/", response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse("index.html", {"request": request})

The HTML template needs a slight adjustment to send data as query parameters when using Depends() without explicit Form:

<!-- templates/index.html -->
<!DOCTYPE html>
<html>
<body>
    <form method="post" id="myForm" onsubmit="transformFormData();" enctype="multipart/form-data">
        name : <input type="text" name="name" value="foo"><br>
        point : <input type="text" name="point" value=0.134><br>
        is_accepted : <input type="text" name="is_accepted" value=True><br>
        <label for="files">Choose file(s) to upload</label>
        <input type="file" id="files" name="files" multiple>
        <input type="submit" value="submit">
    </form>
    <script>
        function transformFormData() {
            var myForm = document.getElementById('myForm');
            var qs = new URLSearchParams(new FormData(myForm)).toString();
            myForm.action = 'http://127.0.0.1:8000/submit?' + qs;
        }
    </script>
</body>
</html>

Testing with requests:

# test.py
import requests

url = 'http://127.0.0.1:8000/submit'
files_to_upload = [('files', open('test_files/a.txt', 'rb')), ('files', open('test_files/b.txt', 'rb'))]
query_params = {"name": "foo", "point": 0.13, "is_accepted": False}
resp = requests.post(url=url, params=query_params, files=files_to_upload)
print(resp.json())

Method 3: JSON String as a Form Parameter

You can send your JSON data as a single string within a form field and then parse it on the server side.

# app.py
from fastapi import FastAPI, status, Form, UploadFile, File, Depends, Request
from pydantic import BaseModel, ValidationError
from fastapi.exceptions import HTTPException
from fastapi.encoders import jsonable_encoder
from typing import Optional, List
from fastapi.templating import Jinja2Templates
from fastapi.responses import HTMLResponse

app = FastAPI()
templates = Jinja2Templates(directory="templates")

class Base(BaseModel):
    name: str
    point: Optional[float] = None
    is_accepted: Optional[bool] = False

def checker(data: str = Form(...)): # Expecting the JSON string in a form field named 'data'
    try:
        return Base.model_validate_json(data)
    except ValidationError as e:
        raise HTTPException(
            detail=jsonable_encoder(e.errors()),
            status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
        )

@app.post("/submit")
def submit(base: Base = Depends(checker), files: List[UploadFile] = File(...)):
    return {"JSON Payload": base, "Filenames": [file.filename for file in files]}

@app.get("/", response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse("index.html", {"request": request})

The client side (using requests) would send the JSON data as a string:

# test.py
import requests
import json

url = 'http://127.0.0.1:8000/submit'
files_to_upload = [('files', open('test_files/a.txt', 'rb')), ('files', open('test_files/b.txt', 'rb'))]
# The JSON data is sent as a string under the 'data' key in the form data
data_payload = {'data': json.dumps({"name": "foo", "point": 0.13, "is_accepted": False})}
resp = requests.post(url=url, data=data_payload, files=files_to_upload)
print(resp.json())

Method 4: Using Pydantic’s Json Type with Form (Pydantic V2+)

For Pydantic version 2 and later, you can use the Json type directly within a Form field.

# app.py
from typing import Annotated
from fastapi import FastAPI, File, Form, UploadFile
from pydantic import Json

app = FastAPI()

@app.post("/myendpoint")
async def myendpoint(
    file: Annotated[UploadFile, File()],
    metadata: Annotated[Json[dict[str, str]] | None, Form()] = None,
):
    print(metadata) # This will be a Python dictionary
    return {"received_metadata": metadata, "filename": file.filename}

Client-side example using requests:

# test.py
import requests
import json

url = "http://localhost:8000/myendpoint"
file_content = ("data.txt", open("test_files/a.txt", "rb"), "text/plain")
json_data_string = json.dumps({"data": "value", "foo": "bar"})

# The JSON data must be in a form field named 'metadata'
request_data = {"metadata": json_data_string}

resp = requests.post(url, data=request_data, files={"file": file_content})
print(resp.json())

Method 5: Using model_validator for Automatic Parsing

This method involves defining a Pydantic model with a validator that automatically parses a string input (expected to be JSON) into the model.

# app.py
from fastapi import FastAPI, File, Body, UploadFile, Request
from pydantic import BaseModel, model_validator
from typing import Optional, List
from fastapi.templating import Jinja2Templates
from fastapi.responses import HTMLResponse
import json

app = FastAPI()
templates = Jinja2Templates(directory="templates")

class Base(BaseModel):
    name: str
    point: Optional[float] = None
    is_accepted: Optional[bool] = False

    @model_validator(mode='before')
    @classmethod
    def validate_to_json(cls, value):
        if isinstance(value, str):
            return cls(**json.loads(value))
        return value

@app.post("/submit")
def submit(data: Base = Body(...), files: List[UploadFile] = File(...)):
    return {"JSON Payload": data, "Filenames": [file.filename for file in files]}

@app.get("/", response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse("index.html", {"request": request})

For testing this, you can use the same test.py as in Method 3, as it sends JSON data as a string in a form field named ‘data’, which Body() can then interpret correctly due to the model_validator.

Method 6: Base64 Encoding Files (Less Recommended)

While technically possible, encoding file content into Base64 strings and sending them as part of a JSON payload is generally not recommended for larger files due to increased data size and processing overhead.

# app.py
from fastapi import FastAPI, Request, HTTPException
from typing import List
from fastapi.responses import HTMLResponse
from pydantic import BaseModel
from fastapi.templating import Jinja2Templates
import base64
import binascii

app = FastAPI()
templates = Jinja2Templates(directory='templates')

class Bas64File(BaseModel):
    filename: str
    owner: str
    bas64_str: str

@app.post('/submit')
def submit(files: List[Bas64File]):
    for file in files:
        try:
            contents = base64.b64decode(file.bas64_str.encode('utf-8'))
            with open(file.filename, 'wb') as f:
                f.write(contents)
        except binascii.Error: # More specific exception
            raise HTTPException(
                400, detail='There was an error decoding the base64 string'
            )
        except Exception:
            raise HTTPException(
                500, detail='There was an error uploading the file(s)'
            )
    return {'Filenames': [file.filename for file in files]}

@app.get('/', response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse('index.html', {'request': request})

Client-side example using requests:

# test.py
import requests
import os
import glob
import base64

url = 'http://127.0.0.1:8000/submit'
paths = glob.glob('test_files/*') # Assuming files are in test_files/
payload = []

for p in paths:
    if os.path.isfile(p):
        with open(p, 'rb') as f:
            bas64_str = base64.b64encode(f.read()).decode('utf-8')
        payload.append({'filename': os.path.basename(p), 'owner': 'me', 'bas64_str': bas64_str})

resp = requests.post(url=url, json=payload)
print(resp.json())

This method requires careful handling of Base64 decoding and potential performance implications.

Choosing the Right Method

  • Method 1 (Form/File): Straightforward and generally recommended for typical use cases.
  • Method 2 (Pydantic + Depends): Provides better structure and validation for your JSON data, especially with complex nested structures.
  • Method 3 (JSON String in Form): A flexible workaround that isolates JSON parsing logic, useful if you need to reuse parsing logic across multiple endpoints.
  • Method 4 (Pydantic Json Type): The most modern and idiomatic way in Pydantic V2+ for handling JSON within form data.
  • Method 5 (model_validator): Elegant for Pydantic models, as it hides the parsing logic within the model itself.
  • Method 6 (Base64): Useful for small binary data or very specific scenarios, but usually less efficient for general file uploads.

Remember to install necessary dependencies like python-multipart and uvicorn for running FastAPI applications. You can find more about FastAPI’s request handling, including file uploads, in the official documentation .

FAQs on Sending JSON and Files in FastAPI Requests

Q: Can I send JSON and files in the same FastAPI POST request

ANS: Yes, you can send both JSON data and files in the same POST request to FastAPI. The standard HTTP protocol doesn’t allow mixing application/json and multipart/form-data directly in the body. However, FastAPI provides methods to package your JSON data as part of a multipart/form-data request, typically by sending the JSON as a string within a form field.

Q: What is the primary challenge when sending JSON and files together

ANS: The main challenge is that HTTP requests typically use either application/json for JSON data or multipart/form-data for files and other form fields. Sending both simultaneously in their native formats is not standard. FastAPI helps overcome this by allowing you to send your JSON data as a string within a multipart/form-data payload.

Q: Which FastAPI methods are suitable for sending JSON and files

ANS: Several methods work well: using Form and File parameters directly, employing Pydantic models with Depends, sending JSON as a string in a Form parameter and parsing it server-side, or using Pydantic’s Json type with Form in Pydantic V2+.

Q: Do I need to install any packages for file uploads in FastAPI

ANS: Yes, for handling multipart/form-data requests, which are used for file uploads and form data, you need to install the python-multipart package: pip install python-multipart.

Q: How does FastAPI handle JSON data sent as a string in a form field

ANS: When JSON data is sent as a string within a form field (e.g., data: str = Form(...)), you can use Python’s json.loads() or Pydantic’s parse_raw() or model_validate_json() within your endpoint or a dependency function to convert the string back into a Python dictionary or a Pydantic model instance.

Q: Is Base64 encoding files a good approach for FastAPI

ANS: Encoding files to Base64 strings and sending them within JSON is generally not recommended for large files. It increases data size by about 33% and requires Base64 decoding on both client and server, adding computational overhead. This approach is better suited for very small binary data.
