“Creating Single-File Python Executables Alternatives to py2exe”

How can developers reliably package a Python application into a single, self-contained executable file for easy distribution, avoiding the need for users to install Python or manage dependency files? Several established and emerging tools offer pathways to achieve this goal, each with specific configurations and trade-offs.

Leveraging py2exe for Bundled Output

The traditional approach using py2exe offers fine-grained control over bundling using the bundle_files and zipfile options within the setup.py script.

Achieving a Single Compressed File with py2exe

To create a truly single, compressed file using py2exe, specific settings must be applied in the setup configuration:

  1. Set bundle_files to 1: This instructs py2exe to bundle everything, including the Python interpreter itself.
  2. Set compressed to True.
  3. Set zipfile to None: This critical step ensures that files are bundled directly within the executable instead of being placed in a separate library.zip file.

Here is an example setup.py demonstrating this configuration:

from distutils.core import setup
import py2exe, sys, os

# Ensure py2exe is called correctly
sys.argv.append('py2exe')

setup(
    options = {'py2exe': {'bundle_files': 1, 'compressed': True}},
    windows = [{'script': "single_app_entry.py"}],
    zipfile = None,
)

The official py2exe documentation clarifies the bundle_files values:

  • 3 (Default): Do not bundle dependencies.
  • 2: Bundle everything except the core Python interpreter.
  • 1: Bundle everything, including the Python interpreter.

Embedding Resources Directly Using Patches and Custom Options

For applications requiring embedded data files (like images or configuration files), modifying the py2exe script itself or submitting patches might be necessary if standard options fall short. One advanced user detailed a method involving embedding resources directly as file or other resources by patching py2exe.py.

This approach involves adding new parameters to the setup() call, such as file_resources and other_resources, which requires editing the underlying py2exe.py file or applying a patch (like the one referenced on SourceForge for aid=3334760).

In a customized setup.py relying on such a patch, resource strings for images could be dynamically generated:

# This setup relies on a modified py2exe where file_resources is accepted
# ... setup for py2exe_options ...

bitmap_string = '' 
resource_string = ''
index = 0

print "Compiling image list"                          

for image_name in os.listdir('images/'):
    if image_name.endswith('.jpg'):
        # Construct arguments for file_resources
        bitmap_string += f"({index+1},'images/{image_name}'),"
        resource_string += f"{image_name} "
        index += 1

print "Starting build\n"

# Dynamically executing setup with embedded resource definitions
exec f"setup(console=[{{'script': 'launcher.py', 'icon_resources': [(0, 'ICON.ico')], \
      'file_resources': [{bitmap_string[:-1]}], 'other_resources': [(u'INDEX', 1, '{resource_string[:-1]}')]}}],\
      options={{'py2exe': py2exe_options}},\
      zipfile = None )"

print "Removing Trash"
os.system("rmdir /s /q build")
os.system("del /q *.pyc")
print "Build Complete"

Note on Resource Access: If resources are embedded this way, the application code must be adapted to load them from memory (e.g., using Windows API calls like LoadResource) rather than accessing the file system directly when running in the bundled state.

Alternative Tool: PyInstaller

PyInstaller provides a highly effective, often simpler, route to creating single executables without requiring manual patching of the packaging tool itself.

The --onefile flag is the direct mechanism for this functionality:

pyinstaller --onefile your_script_name.py

PyInstaller handles packing necessary shared libraries and dependencies into the monolithic executable. Upon execution, it unpacks these components into a temporary location before running the main script. This offers dependency isolation and a clean user experience, similar to the behavior described for advanced py2exe setups. For complex dependencies including PyQt, PyQwt, and NumPy, PyInstaller is often cited as robust.

Installer Generation for Complex Deployments

Even when a single executable is created, distributing it might benefit from a formal installer. Tools like InnoSetup can wrap the generated executable and any required auxiliary files (if a single-file output wasn’t chosen) into a professional, installable, and uninstallable package. This is particularly relevant for applications using frameworks like PyGTK, where external data directories (lib, share) must be kept alongside the executable for runtime loading.

Other Noteworthy Freezing Utilities

Beyond the major players, other tools exist for creating standalone applications:

  • bbfreeze: Mentioned as a newer alternative to py2exe capable of producing a single .EXE.
  • cx_freeze: Another utility noted for its ability to create good standalone packages.

Considerations for Non-Single File Output

If the strict single-file requirement is relaxed, py2exe by default creates an executable directory containing the .exe alongside necessary libraries (e.g., library.zip). A standard configuration might look like this:

from distutils.core import setup
import py2exe

setup(console=['application_entry_point'])
# This generates dist/application_entry_point.exe and supporting files

A key preparatory step for any py2exe deployment is ensuring that any dependencies packaged as .egg files are unzipped, as py2exe may not correctly include zipped eggs. Refer to the official py2exe documentation for details on pre-processing eggs.

FAQs on Generating Standalone Python Executables

Q: What is the primary option in PyInstaller to create just one executable file

ANS: Use the --onefile command-line option when running PyInstaller on your main Python script.

Q: How does py2exe bundle all files into one executable

ANS: Set bundle_files to 1 in the py2exe options and set zipfile to None in the setup() call.

Q: Can I use py2exe to embed external data files like JPGs

ANS: Yes, but it often requires advanced customization, such as modifying the py2exe.py file or applying submitted patches to utilize options like file_resources.

Q: Why might a single EXE from py2exe fail with PyGTK applications

ANS: GTK+ frameworks often rely on external data files (like themes or locales) located relative to the executable. A pure single-file executable can disrupt this path resolution, making an installer package advisable.
