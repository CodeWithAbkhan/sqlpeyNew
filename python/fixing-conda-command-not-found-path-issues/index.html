“Fixing ‘conda: command not found’ After Anaconda Installation”

When setting up a new environment with Anaconda or Miniconda, receiving the error -bash: conda: command not found (or similar on other shells) indicates that the installation directory for the conda executable is not correctly included in your system’s PATH environment variable. This prevents the shell from locating and executing the command.

How can one reliably configure the system’s PATH to make conda accessible from the terminal across various operating systems and shell configurations?

Established Techniques for PATH Configuration

Several strategies exist to integrate the Anaconda binary directory into the shell’s execution path. The correct approach often depends on the operating system, the shell being used (e.g., Bash, Zsh), and the Anaconda version.

Method 1: Direct Temporary Export (Session Scope)

For immediate testing within the current terminal session, you can use the export command. This change vanishes when the terminal window is closed.

For Anaconda 2:

export PATH=~/anaconda2/bin:$PATH
conda --version

For Anaconda 3 (Common Linux/macOS):

export PATH=~/anaconda3/bin:$PATH
conda --version

For Generic Anaconda Install (Older/Specific Setups):

export PATH=$PATH:$HOME/anaconda/bin
conda --version

If this works temporarily, you should proceed to make the change persistent.

Method 2: Permanent PATH Modification via Shell Initialization Files

To ensure conda is available every time a new shell starts, the export command must be added to the appropriate startup file: .bashrc, .bash_profile, or .zshrc.

For Bash Users (Linux/Older macOS): Editing .bashrc is often the solution.

  1. Use a text editor like nano or vim to open the configuration file: 
    nano ~/.bashrc
  2. Append the relevant export line (e.g., for Anaconda 3) to the end of the file: 
    export PATH=~/anaconda3/bin:$PATH
  3. Save and close the file (in nano, press Ctrl+X, then Y, then Enter).
  4. Apply the changes to the current session: 
    source ~/.bashrc

For Zsh Users (Modern macOS Catalina+): You should modify .zshrc.

  1. Open the Zsh configuration file: 
    vim ~/.zshrc
  2. Insert the persistent path definition: 
    export PATH=$PATH:$HOME/anaconda3/bin
  3. Source the file: 
    source ~/.zshrc

Important Note on macOS/iTerm2: If you use Zsh, the installer might only update .bash_profile. If you are seeing system Python instead of Anaconda Python after installing iTerm2, ensure the correct Anaconda path is explicitly added to your ~/.zshrc file. In some scenarios on older macOS systems, you might need to point to /Users/yourusername/anaconda2/bin:$PATH instead.

Method 3: Utilizing conda init (Recommended for Conda v4.4.0+)

The official recommendation, especially for newer Conda versions, is to use the conda init command. This tool correctly identifies your shell and automatically inserts the necessary initialization scripts into the appropriate configuration file, which is less error-prone than manual editing.

Running this command initializes Conda for the current shell environment.

After running conda init, you must launch a new shell or source the modified initialization file for the changes to take effect.

Safety Precaution: Before running conda init, you can check what changes it would make by using the dry-run flag:

./anaconda3/bin/conda init --dry-run -v

If you see conflicting or unwanted entries related to Conda in your shell configuration files, it is wise to clear them before re-running conda init. Conda v4.6.9 introduced a --reverse flag to help automate the removal of these initializations.

Method 4: Alternative Script Sourcing (Conda Initialization File)

Instead of modifying the PATH directly, newer Conda installations suggest sourcing a specific initialization script located within the installation structure. This method is preferred as it delegates environment setup to Conda’s internal scripts.

For Anaconda 2 setups, place this line in your .bashrc or .bash_profile:

. ~/anaconda2/etc/profile.d/conda.sh
conda activate

The . is equivalent to source. Adding conda activate immediately after sourcing the script can set up the environment context immediately upon shell startup.

Method 5: Windows Environment Variable Configuration

On Windows systems, especially when using the standard Command Prompt or PowerShell, PATH adjustments are managed through the System Properties dialog.

  1. Navigate to System Properties > Advanced tab > Environment Variables.
  2. Edit the Path variable under System Variables.
  3. Add the path to the Scripts directory (often Scripts instead of bin in modern Windows installations, e.g., C:\Program Files (x86)\Microsoft Visual Studio\Shared\Anaconda3_64\Scripts).
  4. Restart the terminal session after modification.

Note for Windows Git Bash: Git Bash requires using the export syntax, often referencing the USERPROFILE:

export PATH=$USERPROFILE/AppData/Local/Continuum/anaconda3/Scripts/:$PATH

Addressing Specific Installation Anomalies

  • Reinstalling: In rare cases where previous setup attempts have corrupted files, completely removing the Anaconda directory and performing a clean reinstallation (ensuring you follow all prompts correctly) resolves persistent issues.
  • Executable Permissions (Linux): If the PATH is set correctly but you still see errors, verify permissions within the binary folder: 
    chmod +x ~/anaconda3/bin/*
  • Windows (Scripts vs. bin): Be acutely aware that recent Anaconda versions on Windows often place executables under the Scripts subdirectory, not bin.

Quick Checks and Verification

After applying any persistent fix, always perform these checks:

  1. Close and reopen the terminal application entirely.
  2. Execute the command to confirm the path is active: 
    conda --version
  3. Verify that you can run core commands, such as listing environments: 
    conda list
  4. If you wish to create a new environment: 
    conda create --name new_experiment_env python=3.10
source activate new_experiment_env

PATH=$PATH:$HOME/anaconda/bin

FAQs on Fixing Conda Command Not Found

Q: Why does my PATH change disappear after closing the terminal

ANS: The export PATH=... command executed directly modifies the PATH only for the active shell process. To make it permanent, you must add the same command to your shell’s startup file, such as .bashrc or .zshrc, and then source that file or open a new terminal.

Q: Should I use bin or Scripts for the Anaconda path on Windows

ANS: For modern Anaconda installations on Windows, the executables are usually located in the Scripts folder (e.g., Anaconda3\Scripts), whereas older or Linux/macOS setups typically use the bin folder. Always check your specific installation directory.

Q: What is the benefit of using conda init over manual PATH editing

ANS: conda init automatically writes shell-specific initialization code to your configuration files, managing complexity, shell compatibility (like correctly handling Zsh), and ensuring future Conda updates are properly integrated without manual intervention.

Q: I added the path but still get conda command not found

ANS: Ensure you have sourced the configuration file (source ~/.bashrc) or restarted your terminal. If the problem continues, verify the exact installation location path used in your export command matches the actual location on your file system, or check if executable permissions are set correctly on Linux systems.

Q: How do I undo the changes made by conda init

ANS: Conda version 4.6.9 and newer support the --reverse flag, which can automate the removal of the initialization commands inserted into your shell configuration files.
