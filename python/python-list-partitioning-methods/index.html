“Python: Efficiently Partitioning a List Based on a Condition”

How can one elegantly and efficiently divide an existing Python sequence (mylist) into two separate lists—one containing elements that satisfy a specific condition (goodvals), and the other containing the rest—while ensuring the condition is evaluated only once per element? Various approaches exist, ranging from simple list comprehensions to functional programming constructs and specialized library functions.

Let’s consider a scenario where we have a list of file tuples, structured like [ ('file1.jpg', 33L, '.jpg'), ('file2.avi', 999L, '.avi'), ... ], and we want to separate image files from others based on their extension.

# Example data structure
files = [ ('photo_alpha.jpg', 330, '.jpg'), ('video_beta.avi', 9990, '.avi'), ('logo_gamma.png', 120, '.png') ]
IMAGE_TYPES = ('.jpg','.jpeg','.gif','.bmp','.png')

# The condition for an item 'f' to be an image
def is_image(f):
    return f[2].lower() in IMAGE_TYPES

What are the best methods to achieve this two-way split?

Solution Approaches for List Partitioning

Several accepted strategies prioritize either readability, raw performance, or functional purity.

1. The Direct, Readable Loop (Single Pass)

A standard, explicit for loop guarantees a single pass over the data, which is often favored for clarity, especially when adding complex logic later.

def partition_with_loop(data_list, condition_set):
    good_list, bad_list = [], []
    for item in data_list:
        if item in condition_set:
            good_list.append(item)
        else:
            bad_list.append(item)
    return good_list, bad_list

# Usage example, leveraging a set for fast lookups
good_set = set(goodvals)
good_result, bad_result = partition_with_loop(mylist, good_set)

An even more concise version of this single-pass loop uses a ternary operator assignment within the loop:

good_result, bad_result = [], []
for item in my_list:
    # Assign to the correct list reference in one line
    (good_result if item in good_set else bad_result).append(item)

2. Dual List Comprehensions (Two Passes)

The most idiomatic Python approach often involves two list comprehensions, but this necessitates iterating over the source list twice.

good_result = [x for x in mylist if x in goodvals]
bad_result  = [x for x in mylist if x not in goodvals]

# For the file example:
images = [f for f in files if is_image(f)]
anims  = [f for f in files if not is_image(f)]

A slight variation, which avoids re-evaluating the negative condition, is using the results of the first comprehension:

images = [f for f in files if is_image(f)]
# Requires elements to be hashable and order preservation might be slightly less direct
anims  = [f for f in files if f not in images]

3. Utilizing Sets for Membership Testing

When the check is purely about membership (x in goodvals), converting the lookup list (goodvals) to a set provides significant speed benefits (O(1) average time complexity for lookups versus O(N) for a list or tuple).

mylist = [1, 2, 3, 4, 5, 6, 7]
goodvals = [1, 3, 7, 8, 9]

my_set = set(mylist)
good_set = set(goodvals)

# Partitioning using set operations
print(f"Intersection (True): {list(my_set.intersection(good_set))}")
print(f"Difference (False): {list(my_set.difference(good_set))}")

# Using sets in the standard loop approach is highly recommended for performance.

4. Lazy Evaluation with itertools.tee and Generators

For very large or infinite sequences, returning lazy generators is crucial. The itertools.tee function can duplicate an iterator, allowing both conditions to pull from the same source without fully materializing intermediate lists.

from itertools import tee

def split_on_condition_lazy(sequence, condition_func):
    # Tee duplicates the input iterator
    l1, l2 = tee((condition_func(item), item) for item in sequence)
    # Generator 1: True results
    true_gen = (i for p, i in l1 if p)
    # Generator 2: False results
    false_gen = (i for p, i in l2 if not p)
    return true_gen, false_gen

# Example usage (generates results only when consumed)
primes_gen, non_primes_gen = split_on_condition_lazy(count(), is_prime)
# Consume the first 5 of each:
# print("Primes:", list(islice(primes_gen, 5)))

Note: For finite lists, the performance penalty of managing the internal buffers in tee might make a direct loop faster than this lazy approach.

5. Functional Style with functools.reduce

A highly condensed, single-pass approach can be achieved using reduce by abusing the fact that .append() returns None.

from functools import reduce

def split_functional(predicate, iterable, truthy_value=1, falsy_value=0):
    # The accumulator starts as ([], [])
    # For each element 'e', it appends 'e' to index [predicate(e)]
    # The 'or res' ensures the accumulator (res) is returned instead of None from .append()
    return reduce(
        lambda res, e: res[predicate(e)].append(e) or res,
        iterable,
        ([], [])
    )

# Example: Splitting numbers into even (0) and odd (1) lists
all_numbers = list(range(10))
odd_list, even_list = split_functional(lambda x: x % 2, all_numbers)
# Output: odd_list = [1, 3, 5, 7, 9], even_list = [0, 2, 4, 6, 8]

6. Using External Libraries (e.g., toolz, more_itertools)

Libraries often provide optimized, pre-built functions for common operations like partitioning, which adhere to the “single-pass, lazy evaluation” criteria.

Using the widely adopted more_itertools library:

# pip install more-itertools
from more_itertools import partition

# partition(predicate, iterable) returns (true_generator, false_generator)
image_gen, other_gen = partition(is_image, files)

Performance Considerations

Benchmarking reveals that solutions involving a single pass and fast membership checking (like using a set for lookups) are typically the fastest. The highly optimized loop methods (like Solution 1, especially with a set lookup) frequently outperform the more syntactically complex methods that involve multiple full iterations (like dual list comprehensions) or internal iterator mechanics (tee). Using sets for the goodvals lookup is a critical optimization step.

FAQs on Python List Partitioning Methods

Q: Which method is generally the fastest for splitting a list into two

ANS: Methods employing a single for loop iteration combined with checking membership against a pre-built set of criteria values tend to yield the best performance benchmarks in Python.

Q: Can list comprehension be used efficiently for partitioning

ANS: Yes, using two separate list comprehensions is very readable, but it requires traversing the source list twice, which can be slower than a single-pass loop for very large lists.

Q: How do I ensure the condition function is only called once per element

ANS: Employing itertools.tee to duplicate the iterator before applying filtering logic, or using a single for loop where the condition is evaluated once per iteration, ensures single evaluation.

Q: Are there functions in standard libraries for partitioning

ANS: The standard library does not have a direct partition function comparable to those in external libraries, but itertools.tee combined with generator expressions provides a basis for building one.
