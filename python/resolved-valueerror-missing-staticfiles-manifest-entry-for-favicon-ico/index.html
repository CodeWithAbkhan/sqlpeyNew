How to Fix the ValueError: Missing Staticfiles Manifest Entry for ‘favicon.ico’ in Django

Are you encountering a ValueError when running your Django tests? If your project, for instance, named fellow_go, involves an app called pickup, and you’re facing the error below while executing python manage.py test, you’re in the right place!

ValueError: Missing staticfiles manifest entry for 'favicon.ico'

This issue arises after a recent commit to Django: Fixed #24452 - Corrected HashedFilesMixin . Let’s break down the traceback and recognize potential reasons for this Problem.

Understanding the Traceback

The traceback points to the error in various lines of code that involve rendering your templates and serving static files. Below is the snippet that reveals a part of the error context:

File "/Users/sunqingyao/PycharmProjects/fellow_go/pickup/tests/test_view.py", line 10, in test_view_url_exists_at_desired_location
 resp = self.client.get('/', follow=True)

The root cause is that Django’s static files system couldn’t find an entry for favicon.ico in the staticfiles manifest when running your tests.

Review of Your Setup

Settings Configuration

Ensure that your settings are appropriately structured:

# fellow_go/settings.py

STATIC_ROOT = os.path.join(BASE_DIR, 'staticfiles')
STATIC_URL = '/static/'
STATICFILES_DIRS = [
    os.path.join(BASE_DIR, "static"),
]
STATICFILES_STORAGE = 'whitenoise.django.GzipManifestStaticFilesStorage'

URL Patterns

Additionally, verify your URL patterns:

# fellow_go/urls.py

urlpatterns = i18n_patterns(
    url(r'^$', HomePageView.as_view(), name='index'),
    url(r'^pickup/', include('pickup.urls')),
    url(r'^accounts/', include('django.contrib.auth.urls')),
    url(r'^admin/', admin.site.urls),
    prefix_default_language=False
) + static(settings.STATIC_URL, document_root=settings.STATIC_ROOT)

View Class

The view serving your homepage is straightforward:

# fellow_go/pickup/views.py

class HomePageView(TemplateView):
    template_name = 'index.html'

HTML Template

Your template’s HTML reference to favicon.ico is as follows:

<!-- fellow_go/templates/index.html -->

<link rel="icon" href="{% static 'favicon.ico' %}">

Solution to the Problem

To resolve this error, follow these steps:

Step 1: Collect Static Files

Run the manage.py collectstatic command to gather your static files:

python manage.py collectstatic

If the test passes now, you may need to adjust the STATICFILES_STORAGE setting. The previous setting may be problematic due to changes in Whitenoise:

Solution 1: Adjust Storage Setting

Change to the following, which has been recommended from version 4 onwards:

STATICFILES_STORAGE = 'whitenoise.storage.CompressedManifestStaticFilesStorage'

For more details about this, check out the Django documentation .

Alternative Configuration

If you are not reliant on hashing for your static files, consider using a more straightforward storage approach:

STATICFILES_STORAGE = 'django.contrib.staticfiles.storage.StaticFilesStorage'

This is suitable for development but will require revisiting for production environments.

Why Does This Not Happen During Runserver?

Interestingly, the error only occurs during testing and not while running the server:

GET /static/favicon.ico HTTP/1.1 200 766

This suggests that the static files are correctly served when the server is running but not appropriately referenced during tests.

FAQs on ValueError Missing Staticfiles Manifest Entry for ‘favicon.ico’

Q: What does the ValueError Missing staticfiles manifest entry for 'favicon.ico' mean?

A: This error occurs when Django’s static files system cannot find an entry for ‘favicon.ico’ in the collected static files manifest, especially during test execution.

Q: How can I prevent this error?

A: You can resolve this error by running python manage.py collectstatic and ensuring that your STATICFILES_STORAGE is correctly configured as shown above.

Q: Why is there no error when using runserver?

A: The error does not appear during runserver because the static files may be served directly from development settings, while tests require manifest integrity.
