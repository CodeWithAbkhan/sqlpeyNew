How to Print the Actual SQL Query in SQLAlchemy

Printing out the actual SQL queries generated by SQLAlchemy, along with their corresponding values rather than just bind parameters, can be a common need during the debugging process. There are several methods to achieve this, each serving different use cases and preferences. Below, we will detail various solutions, including practical code examples to facilitate your understanding of how to implement these methods in your applications.

Solution 1: Enable SQL Echoing

For simple debugging purposes, you can enable SQL echoing in your SQLAlchemy engine. This can be accomplished by setting echo=True when you create your engine:

from sqlalchemy import create_engine

engine = create_engine(
    "mysql://scott:tiger@hostname/dbname",
    encoding="latin1",
    echo=True,
)

You might want to enable this just for specific requests; hence, you can also toggle the echo setting at runtime:

engine.echo = False  # Set to True to log statements

For applications using Flask, you can similarly set:

app.config["SQLALCHEMY_ECHO"] = True

Reference: SQLAlchemy Engine Configuration

Solution 2: Create a Custom Dialect for Literal Values

If you need a more refined solution, particularly to literalize various types of data, you can define a custom dialect. It is compatible across Python 2 and Python 3:

from sqlalchemy.engine.default import DefaultDialect
from sqlalchemy.sql.sqltypes import String, DateTime, NullType

class StringLiteral(String):
    def literal_processor(self, dialect):
        super_processor = super(StringLiteral, self).literal_processor(dialect)
        
        def process(value):
            if isinstance(value, int):
                return str(value)
            if not isinstance(value, str):
                value = str(value)
            result = super_processor(value)
            if isinstance(result, bytes):
                result = result.decode(dialect.encoding)
            return result
        return process

class LiteralDialect(DefaultDialect):
    colspecs = {
        String: StringLiteral,
        DateTime: StringLiteral,
        NullType: StringLiteral,
    }

def literalquery(statement):
    import sqlalchemy.orm
    if isinstance(statement, sqlalchemy.orm.Query):
        statement = statement.statement
    return statement.compile(
        dialect=LiteralDialect(),
        compile_kwargs={'literal_binds': True},
    ).string

## Example usage
from sqlalchemy.sql import table, column, select
from datetime import datetime
from decimal import Decimal

def test():
    mytable = table('mytable', column('mycol'))
    values = (5, 'snowman: ☃', Decimal('3.14159'), datetime.now())
    
    statement = select([mytable]).where(mytable.c.mycol.in_(values)).limit(1)
    print(literalquery(statement))

if __name__ == '__main__':
    test()

Solution 3: Use the Compile Method

One effective approach is to use the compile method, allowing you to render SQL statements with bound parameters inlined:

from sqlalchemy.sql import text
from sqlalchemy.dialects import postgresql

stmt = text("SELECT * FROM users WHERE users.name BETWEEN :x AND :y").bindparams(x="m", y="z")
compiled_stmt = stmt.compile(dialect=postgresql.dialect(), compile_kwargs={"literal_binds": True})

print(compiled_stmt)

This generates output similar to:

SELECT * FROM users WHERE users.name BETWEEN 'm' AND 'z'

Solution 4: Create a Pretty-Printable Function

For a user-friendly display of SQL queries, consider implementing a function that formats the SQL output:

import sqlparse
import sqlalchemy.orm

def prettyprintable(statement, dialect=None, reindent=True):
    if isinstance(statement, sqlalchemy.orm.Query):
        if dialect is None:
            dialect = statement.session.get_bind().dialect
        statement = statement.statement

    compiled = statement.compile(dialect=dialect, compile_kwargs={'literal_binds': True})
    return sqlparse.format(str(compiled), reindent=reindent)

## Usage
## prettyprintable(your_statement)

Installation Note: You might need to install the sqlparse library if you choose this method:

pip install sqlparse

Solution 5: Utilize Python Logging for SQL Queries

Instead of using the echo=True flag, you can control logging more granularly:

import logging

logging.basicConfig()
logging.getLogger('sqlalchemy.engine').setLevel(logging.INFO)

Alternative Methods

There are several other alternatives as well, including using the print function with raw SQL statements or overriding the Process class in SQLAlchemy. Each method has its advantages depending on your specific needs, especially in terms of security and usability while debugging.

Examples of Printing Queries

For quick debugging, here’s yet another example of printing a SQL query directly:

def raw_query(query):
    q = str(query.compile())
    p = query.compile().params
    for k in p.keys():
        v = p.get(k)
        if isinstance(v, (int, float)):
            q = q.replace(f":{k}", f"{v}")
        else:
            q = q.replace(f":{k}", f"'{v}'")
    print(q)

## Example usage
from sqlalchemy import select

select_query = select([some_table]).where(some_table.c.some_column == some_value)
raw_query(select_query)

FAQs on How to Print the Actual SQL Query in SQLAlchemy

Q: Why would I want to print the actual SQL query?

A: Printing the SQL query is useful for debugging to understand what SQL statements are being generated and executed, particularly when results are not as expected.

Q: Is it safe to use inlined queries from user input?

A: No, inlining user input in SQL queries can lead to SQL injection vulnerabilities. Always use parameterized queries for user input.

Q: Can I log SQL queries during unit tests?

A: Yes, you can configure logging to output SQL queries during your tests, which helps diagnose issues during testing.
