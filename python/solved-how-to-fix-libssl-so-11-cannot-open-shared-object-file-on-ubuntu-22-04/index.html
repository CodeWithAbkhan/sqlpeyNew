How to Fix libssl.so.11 Cannot Open Shared Object File on Ubuntu 22.04

If you’ve recently updated to Ubuntu 22.04 LTS, you may have encountered a frustrating issue where certain libraries, especially those relying on OpenSSL, have suddenly stopped functioning. This is primarily due to the transition to OpenSSL version 3.0. One notable case is with the Python package manager poetry, which fails to run and throws the following error message:

Traceback (most recent call last):
 File "/home/robz/.local/bin/poetry", line 5, in <module>
 from poetry.console import main
 ...
ImportError: libssl.so.1.1: cannot open shared object file: No such file or directory

Is there a straightforward solution to this dilemma? Can we obtain libssl.so.1.1 without the need to downgrade OpenSSL 3? If you’re facing this problem, you’re not alone, and thankfully, there are actionable solutions.

Solutions to Resolve the Issue

Solution 1: Installing libssl1.1 Manually

The first approach to resolving the libssl.so.1.1 file error involves manually downloading and installing the appropriate package. Here are the steps:

  1. Start by downloading the required .deb package directly from the Ubuntu archives:

    wget http://nz2.archive.ubuntu.com/ubuntu/pool/main/o/openssl/libssl1.1_1.1.1f-1ubuntu2.23_amd64.deb

  2. Install the downloaded package using the following command:

    sudo dpkg -i libssl1.1_1.1.1f-1ubuntu2.23_amd64.deb

  3. If you encounter an expired link, keep an eye on Ubuntu OpenSSL archive for a valid link.

Solution 2: Creating a Symlink

If you’re unable to find the proper package for libssl.so.1.1, another possible solution is to create a symbolic link from the existing OpenSSL shared library to mimic the required version. Use the following steps:

  1. Verify the available OpenSSL version:

    ls /usr/lib/x86_64-linux-gnu/libssl.so*

  2. Create a symlink to redirect calls from libssl.so.1.1 to whatever version you have:

    sudo ln -s /usr/lib/x86_64-linux-gnu/libssl.so.3 /usr/lib/x86_64-linux-gnu/libssl.so.1.1

Note: This method may not be ideal, as it could lead to compatibility issues with other applications expecting libssl.so.1.1.

Practical Example of Usage

After successfully installing libssl.so.1.1, you should be able to run poetry or any other application that depends on this library without any errors:

poetry install

This command will install all the dependencies defined in your pyproject.toml file, reflecting the successful restoration of your Python environment.

Alternative Solutions

While the solutions outlined above resolve the immediate issue, consider the following alternatives:

  • Explore Docker: If compatibility continues to be a problem, containerizing your application using Docker could help isolate dependencies.

  • Set Up a Virtual Environment: Create a clean Python virtual environment and install necessary packages freshly. This can often solve unexpected compatibility issues.

  • Upgrade Dependencies: Keep libraries updated to their latest versions, as maintainers may add support for the new OpenSSL version over time.

FAQs on Fixing libssl.so.11 Issue

Q: What is `libssl.so.1.1`?

A: libssl.so.1.1 is a shared library file associated with OpenSSL used for cryptographic operations in applications, particularly in Python packages.

Q: Why did I encounter this issue after updating Ubuntu?

A: The issue arises due to the upgrade to OpenSSL version 3.0 in Ubuntu 22.04, which is incompatible with older software expecting libssl.so.1.1.

Q: Is it safe to create a symlink for `libssl.so.1.1`?

A: While it may temporarily resolve the problem, creating a symlink can lead to instability and unexpected behavior in software relying on the specific version of the library.

Q: What steps should I take if my problem persists?

A: Consider reinstalling the affected software, creating a new virtual environment, or switching to a Docker container for cleaner dependency management.
