“Python Dictionary Values to List: Performance Comparisons”

In Python 3, calling the .values() method on a dictionary returns a dynamic view object (dict_values) rather than an immediate list. When development requires a static list structure from these values—perhaps for indexing, sorting, or passing to functions expecting a list—several conversion techniques exist. How do these techniques compare in terms of speed and clarity, especially when dealing with datasets of varying sizes?

This exploration focuses on the practical implementations and performance differences between common methods for obtaining a list from dictionary values.

Primary Methods for List Conversion

What are the most direct ways to force the dict_values view into a concrete list object?

Technique 1: Direct Casting with list()

The most idiomatic and explicit approach involves casting the view directly using the built-in list() constructor.

my_data = {'id_45': 'Widget A', 'id_99': 'Gadget B'}
values_list = list(my_data.values())
# Result: ['Widget A', 'Gadget B']

Technique 2: Unpacking with the Asterisk Operator (*)

The unpacking operator (*) can be used inside a list literal ([]) to spread the elements from the view object directly into a new list structure.

my_data = {'id_45': 'Widget A', 'id_99': 'Gadget B'}
unpacked_list = [*my_data.values()]
# Result: ['Widget A', 'Gadget B']

Technique 3: Using Unpacking Assignment

A less common but highly concise method for immediate assignment to a variable uses the unpacking assignment syntax, often employed when the goal is to immediately bind the unpacked content to a variable name.

my_data = {'id_45': 'Widget A', 'id_99': 'Gadget B'}
*values_tuple, = my_data.values()
# Note: This assigns to a tuple if only *values, is used.
# To strictly get a list via unpacking assignment:
values_list_assignment, = [list(my_data.values())] # Less practical for direct values unpacking

# A more direct assignment yielding a list structure:
*values_list_via_unpack, = my_data.values() # This creates a list if the context implies list assignment, otherwise it's often treated as tuple unpacking. For guaranteed list output, Technique 1 or 2 is safer.

Alternative Modification: Overwriting values Behavior

For scenarios where the developer wishes for the dictionary’s .values() method to always return a list (mimicking Python 2 behavior), one can subclass dict and override the method.

class ListDict(dict):
    # Override values to return a list instead of dict_values
    values = lambda self: [*super().values()]

data_store = ListDict({'key_x': 100, 'key_y': 200})
result = data_store.values()
# Result: [100, 200]
print(f"Type when using ListDict: {type(result)}")
