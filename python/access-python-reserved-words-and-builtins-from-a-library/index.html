Solved: How to Access Python Reserved Words and Builtins from a Library

If you’re working on a Python project and want to identify whether a string matches any Python reserved words or builtins, you might wonder: is there a library that provides this information? The short answer is yes. Let’s explore the built-in ways to retrieve these lists and learn how to handle them effectively.

How Can You Access Reserved Words in Python?

Python provides the keyword module, which contains a list of all the reserved words in the current Python version. Reserved words are those that are part of the language’s syntax and cannot be used as identifiers.

Here’s how to use the keyword module:

Example Code: Accessing Reserved Words

import keyword

# Get the list of all reserved words
reserved_words = keyword.kwlist

print("Python Reserved Words:", reserved_words)

# Check if a word is reserved
word_to_check = "class"
if keyword.iskeyword(word_to_check):
    print(f"'{word_to_check}' is a reserved word!")
else:
    print(f"'{word_to_check}' is not a reserved word.")

Output:

Python Reserved Words: ['False', 'None', 'True', 'and', 'as', 'assert', ...]
'class' is a reserved word!

How Can You Access Built-in Identifiers?

Python’s builtins (e.g., len, list, print) are also predefined but are accessible via the builtins module. You can retrieve them programmatically as shown below:

Example Code: Accessing Builtins

import builtins

# Get the list of all built-in names
builtins_list = dir(builtins)

print("Python Builtins:", builtins_list)

# Check if a name is a builtin
name_to_check = "print"
if name_to_check in builtins_list:
    print(f"'{name_to_check}' is a builtin function!")
else:
    print(f"'{name_to_check}' is not a builtin function.")

Output:

Python Builtins: ['ArithmeticError', 'AssertionError', 'AttributeError', ...]
'print' is a builtin function!

Combining Reserved Words and Builtins

If you need to validate an identifier against both reserved words and builtins, you can merge these lists. Here’s how:

Example Code: Checking Both Reserved Words and Builtins

import keyword
import builtins

# Combine reserved words and builtins into a single set
reserved_and_builtins = set(keyword.kwlist + dir(builtins))

def is_reserved_or_builtin(identifier):
    return identifier in reserved_and_builtins

# Test the function
identifier = "def"
if is_reserved_or_builtin(identifier):
    print(f"'{identifier}' is either a reserved word or a builtin!")
else:
    print(f"'{identifier}' is safe to use.")

Practical Use Case: Avoiding Naming Conflicts

When writing Python code, you may want to append an underscore (_) to avoid naming conflicts with reserved words or builtins. Here’s an example function to handle this:

Example Code: Avoiding Naming Conflicts

import keyword
import builtins

# Merge reserved words and builtins
reserved_and_builtins = set(keyword.kwlist + dir(builtins))

def safe_identifier(name):
    """Appends an underscore if the name is reserved or builtin."""
    if name in reserved_and_builtins:
        return f"{name}_"
    return name

# Test the function
identifiers = ["class", "len", "my_var"]
safe_names = [safe_identifier(name) for name in identifiers]

print("Safe Identifiers:", safe_names)

Output:

Safe Identifiers: ['class_', 'len_', 'my_var']

Alternatives for Validating Python Identifiers

If you’re looking for more robust ways to validate Python identifiers, consider the following:

  1. str.isidentifier()
    Checks if a string is a valid Python identifier:

    name = "my_var"
if name.isidentifier():
    print(f"'{name}' is a valid identifier.")

  2. Custom Validation Using Regular Expressions
    Write a regex to match Python’s identifier rules:

    import re

def is_valid_identifier(name):
    pattern = r"^[^\d\W]\w*\Z"
    return bool(re.match(pattern, name))

print(is_valid_identifier("valid_name"))  # True

FAQs on Accessing Python Reserved Words and Builtins

Q: Can Python reserved words be redefined?

A: No, reserved words are part of the Python syntax and cannot be redefined. Attempting to use them as identifiers will result in a syntax error.

Q: Are builtins safe to override?

A: While technically possible, overriding builtins like len or print is discouraged as it can cause confusion and unexpected behavior in your code.

Q: How to keep code compatible with future Python versions?

A: Regularly update your Python installation and check the keyword.kwlist to ensure no new reserved words conflict with your code.
