How to Add Custom Fields to Python Logging Format

When working with Python’s logging module, you may find the need to include custom fields in your log messages for clearer debugging and tracking within your applications. This post provides an in-depth look into various methods to achieve that, illustrating the intricacies of customization and providing practical examples.

import logging

## Initializing a basic logging format
formatter = logging.Formatter('%(asctime)s : %(message)s')

## Customizing format to include 'app_name'
formatter = logging.Formatter('%(asctime)s %(app_name)s : %(message)s')
## Assuming you have set up a logging handler
logger.addHandler(syslog)

You’re likely seeking ways to pass the app_name value dynamically into the logger format string. Here’s a summary of effective solutions that can enhance your logging strategy:

Method 1: Using LogRecordFactory

Since Python 3.2, you can augment your log messages using a custom record factory. This method allows you to define unique attributes for each log record.

import logging

logging.basicConfig(format="%(custom_attribute)s - %(message)s")
old_factory = logging.getLogRecordFactory()

def record_factory(*args, **kwargs):
    record = old_factory(*args, **kwargs)
    record.custom_attribute = "my-attr"
    return record

logging.setLogRecordFactory(record_factory)

logging.info("hello")

This results in:

my-attr - hello

This method eliminates the need to modify existing log messages and works seamlessly with third-party libraries.

Method 2: Using extra in Logging Calls

You can directly pass additional information to the logger using the extra parameter. This is straightforward and effective:

import logging

logging.basicConfig(format="%(foo)s - %(message)s")
logging.warning('test', extra={'foo': 'bar'})

Output:

bar - test

However, remember to include the extra dictionary in all logging calls; otherwise, you might encounter a KeyError.

Method 3: Custom LoggerAdapter

Creating a custom LoggerAdapter allows you to encapsulate common prefixes or additional information within your logging framework.

class LoggerAdapter(logging.LoggerAdapter):
    def __init__(self, logger, prefix):
        super(LoggerAdapter, self).__init__(logger, {})
        self.prefix = prefix

    def process(self, msg, kwargs):
        return '[%s] %s' % (self.prefix, msg), kwargs

logger = logging.getLogger(__name__)
myHandler = logging.StreamHandler()
myFormatter = logging.Formatter('%(asctime)s %(message)s')
myHandler.setFormatter(myFormatter)
logger.addHandler(myHandler)
logger.setLevel(logging.INFO)

adapted_logger = LoggerAdapter(logger, 'myapp')
adapted_logger.info('This is a log message.')

The output format reflects the prefix:

2023-04-21 12:00:00 [myapp] This is a log message.

Method 4: Environmental Variables in Logging

In scenarios like using AWS Lambda, where you may want to log values based on environment variables, you can leverage them within your logging framework.

import logging
import os

LOG_FORMAT = '%(asctime)s %(message)s ClaimID: %(claim_id)s'

class AppLogger(logging.Logger):
    def info(self, msg, *args, **kwargs):
        return super(AppLogger, self).info(msg, extra={"claim_id": os.getenv("claim_id", "")})

def get_logger(name):
    logging.setLoggerClass(AppLogger)
    logging.basicConfig(level=logging.INFO, format=LOG_FORMAT)
    logger = logging.getLogger(name)
    return logger

LOGGER = get_logger(__name__)
os.environ["claim_id"] = "12334"
LOGGER.info("Hey")

Method 5: Default Extra Mapping with LoggerAdapter

Using a LoggerAdapter enables you to merge a default extra dictionary with messages as needed. This is particularly useful for maintaining a core logging structure across various components.

import logging

class DefaultExtrasAdapter(logging.LoggerAdapter):
    def __init__(self, logger, extra):
        super(DefaultExtrasAdapter, self).__init__(logger, extra)

    def process(self, msg, kwargs):
        if "extra" in kwargs:
            copy = dict(self.extra).copy()
            copy.update(kwargs["extra"])
            kwargs["extra"] = copy
        else:
            kwargs["extra"] = self.extra
        return msg, kwargs

## Usage Example
logger = logging.getLogger("my-logger")
LOG = DefaultExtrasAdapter(logger, {"python": sys.version_info[0], "pid": os.getpid()})
LOG.info("<-- Log message with defaults")

This way, you gain access to consistent logging attributes easily across your application.

Method 6: Logger Method Overriding

In a simpler approach, you can override logging methods to accept additional parameters within your logger class, facilitating custom behaviors directly when logging.

class CustomLogger(logging.Logger):
    def info(self, msg, app_name, *args, **kwargs):
        extra = {'app_name': app_name}
        self._log(logging.INFO, msg, args, extra=extra, **kwargs)

logger = CustomLogger('CustomLogger', logging.DEBUG)
logger.info('Log with custom app name', 'myapp')

Alternative Solutions

Beyond the methods discussed, you may explore various third-party libraries that wrap around Python’s logging. Libraries such as loguru or structlog may offer more contemporary options for structuring logs and handling context-specific information.

FAQs on How to Add Custom Fields to Python Logging Format

Q: What is the purpose of custom fields in logging?

A: Custom fields in logging allow developers to attach contextual information to log messages, enhancing their ability to monitor and debug applications effectively.

Q: Can I use external libraries for logging?

A: Yes, libraries like loguru or structlog can enhance and simplify how logging is handled in Python applications, providing more functionality and ease of use.
