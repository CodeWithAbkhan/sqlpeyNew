“Python Print Duplication: Redirecting stdout and stderr Simultaneously to Console and File”

There are several methods to achieve this duplication, ranging from simple class implementations that override sys.stdout to more robust solutions utilizing Python’s built-in logging module or advanced file descriptor manipulation.

Technique 1: Custom Class Redirecting sys.stdout (The Tee Approach)

A straightforward way to duplicate output is by creating a custom class that intercepts calls to write() on sys.stdout. This object should write to both the original standard output stream and the target file.

Example based on Solution 1 (A basic Tee object):

This implementation requires careful management of sys.stdout restoration.

import sys

class CustomTee:
    """Redirects output from sys.stdout to a file and the original stdout."""
    def __init__(self, filename, mode):
        self.file = open(filename, mode)
        self.original_stdout = sys.stdout
        sys.stdout = self  # Redirect stdout to this instance

    def write(self, data):
        """Writes data to both the file and the original terminal."""
        self.file.write(data)
        self.original_stdout.write(data)

    def flush(self):
        """Ensures buffered data is written."""
        self.file.flush()

    def __del__(self):
        """Restores stdout upon object destruction (use with caution)."""
        sys.stdout = self.original_stdout
        self.file.close()

# Usage Example:
# with CustomTee("output_log_1.txt", "w") as t:
#     print("This appears on screen and in output_log_1.txt")
# print("This appears only on screen.") 
# Note: For proper restoration, context managers are preferred over relying on __del__.

Alternative using Context Manager (Solution 16 & 18):

Using context managers (with statements) is safer as they guarantee restoration of sys.stdout even if exceptions occur.

import sys

class ContextDuplicator:
    """A context manager to temporarily duplicate stdout."""
    def __init__(self, path):
        self.original_stream = sys.stdout
        self.path = path
        self.log_file = None
    
    def write(self, s):
        self.original_stream.write(s)
        self.log_file.write(s)

    def __enter__(self):
        self.log_file = open(self.path, "w")
        sys.stdout = self
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        sys.stdout = self.original_stream
        self.log_file.close()

# Practical Use for stdout only:
with ContextDuplicator("console_and_file.log"):
    print("Captured output line.")
print("Uncaptured output line.")

Technique 2: Leveraging the logging Module (Recommended Alternative)

For structured logging, Python’s built-in logging module is the superior choice. You configure a logger with multiple handlers: one for the console (StreamHandler) and one for the file (FileHandler).

Example based on Solution 4 & 7:

import logging
import sys

# 1. Configure the root logger or a named logger
LOG_FILENAME = 'application_stream.log'

logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s - %(levelname)s - %(message)s',
    handlers=[
        logging.FileHandler(LOG_FILENAME, mode='a'),
        logging.StreamHandler(sys.stdout) # Output to console
    ]
)

logger = logging.getLogger('app_logger')

# Log messages will now go to both the file and stdout
logger.info("System initialized.")
print("This print statement still goes to console only.") # Standard print bypasses logger unless redirected

# To capture standard print() calls via logging, you need to redirect sys.stdout/stderr 
# to a file-like object that calls the logger (as shown in Solution 7).

Technique 3: System-Level Redirection using os.dup2 (Advanced/Cross-Platform)

For scenarios requiring capture of output from external processes spawned by Python (a “hard case” mentioned in the source material), manipulating file descriptors using os.dup2 combined with pipes and threading offers the most powerful, albeit complex, solution. Solution 11 presents a cross-platform StreamCapture class that accomplishes this by setting up pipes and redirecting file descriptors, handling Windows-specific issues via monkeypatching.

Cross-Platform Stream Capture (Solution 11):

This robust approach captures output even from subprocesses like os.system().

import os
import sys
import threading

class CrossPlatformStreamCapture:
    """Captures stream output by using OS pipes and threads."""
    def __init__(self, stream, writer, echo=True):
        self.writer = writer
        self.stream = stream
        self.fd = stream.fileno()
        self.echo = echo
        (r, w) = os.pipe()
        self.pipe_read_fd = r
        self.pipe_write_fd = w
        self.dup_fd = os.dup(self.fd) # Save original descriptor
        os.dup2(w, self.fd) # Point original descriptor to pipe write end
        
        # Thread to read from pipe read end and write to writer/original descriptor
        t = threading.Thread(target=self.printer)
        t.start()
        
    def printer(self):
        while True:
            data = os.read(self.pipe_read_fd, 100000)
            if not data:
                self.writer.close()
                os.close(self.dup_fd)
                os.close(self.pipe_read_fd)
                return
            self.writer.write(data)
            if self.echo:
                os.write(self.dup_fd, data) # Write back to console/original stream

    def close(self):
        os.dup2(self.dup_fd, self.fd) # Restore original descriptor
        os.close(self.pipe_write_fd)
        # Note: thread termination logic needed for clean exit
        
    def __enter__(self):
        return self
    def __exit__(self, a, b, c):
        self.close()

# Usage for capturing stdout to 'process_log.bin' (binary write 'wb')
# with CrossPlatformStreamCapture(sys.stdout, open('process_log.bin', 'wb')):
#     print("Output captured during this block.")
#     os.system('echo Shell command output captured')

Technique 4: Duplicating sys.stderr and sys.stdout using multifile (Solution 17)

If you need to redirect both standard streams using a non-inheriting wrapper object, the multifile approach is very clean for directing multiple streams to the same destinations.

import sys
# Assuming multifile class from Solution 5 is available globally

class DualRedirector:
    def __init__(self, path_log, mode="w", encoding="utf-8"):
        h = open(path_log, mode, encoding=encoding)
        
        # Redirect both stdout and stderr to the list containing original and new file handle
        sys.stdout = multifile([sys.stdout, h])
        sys.stderr = multifile([sys.stderr, h])
        self.log_handle = h

    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        # Restoration is tricky without saving sys.__stdout__/__stderr__ references 
        # (See Solution 17 for detailed restoration via __del__)
        pass

FAQs on Python Print Duplication

Q: Why does print not call my custom write method when redirecting sys.stdout

ANS: If your custom class inherits directly from file (or io.TextIOBase in Python 3), Python’s print statement might sometimes bypass your overridden write method by optimizing calls for genuine file objects. The recommended technique is to use a simple object that only implements write, flush, etc., but does not inherit from file or io.TextIOBase.

Q: Which method captures output from spawned external processes

ANS: Manipulating file descriptors using os.dup2 (as seen in the advanced StreamCapture in Solution 11) is generally required to capture output from external processes started via os.system or subprocess calls, as these often inherit the parent process’s file descriptors.

Q: How to ensure stdout is restored after an exception

ANS: Use a context manager (with statement) implementation (Solutions 16, 18). The __exit__ method is guaranteed to run, allowing you to safely restore the original sys.stdout reference and close the log file.

Q: Can I redirect stdout and stderr separately using the logging module

ANS: Yes, you can configure two separate loggers or two handlers on one logger, directing one handler to sys.stdout and the other to a file, but standard print() statements will still bypass the logging system unless you wrap sys.stdout itself (Solution 7).
