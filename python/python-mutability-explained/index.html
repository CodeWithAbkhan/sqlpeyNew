“Python Mutability Explained: Mutable vs Immutable Objects”

In Python, the concept of mutability is fundamental to how objects behave and how data is manipulated. Understanding the difference between mutable and immutable objects can prevent unexpected behavior and lead to more robust code.

At its core, mutability refers to whether an object’s state can be changed after it’s created.

  • Mutable Objects: These objects can be modified “in place” after they are created. Changes made to a mutable object through one variable will be reflected when accessed through another variable referencing the same object.
  • Immutable Objects: These objects cannot be changed after creation. Any operation that appears to modify an immutable object actually creates a new object with the desired changes, and the original object remains unaltered.

How Do Operations Like += Work?

You might see operations like x = 5.0 followed by x += 7.0, which results in 12.0. This might seem like x is being mutated. However, for immutable types like floats and strings, this operation creates a new object. The variable x is then reassigned to refer to this new object.

Consider this:

# Immutable behavior with strings
s = 'hello'
print(f"Initial string: {s}, ID: {id(s)}")
s += ' world'
print(f"After concatenation: {s}, ID: {id(s)}")

The output will show that the id() of the string changes, indicating a new string object was created.

Contrast this with a mutable object like a list:

# Mutable behavior with lists
my_list = [1, 2, 3]
print(f"Initial list: {my_list}, ID: {id(my_list)}")
my_list.append(4)
print(f"After append: {my_list}, ID: {id(my_list)}")

Here, the id() of the list remains the same, demonstrating that the modification happened “in place.”

Key Differences in Behavior

The distinction between mutable and immutable types becomes most apparent when multiple variables reference the same object or when objects are passed to functions.

Scenario 1: Multiple Variables Referencing the Same Object

If two variables point to the same mutable object, modifying the object through one variable will affect the other.

# Mutable example
list1 = [10, 20]
list2 = list1  # list2 now refers to the same list object as list1

print(f"list1: {list1}, ID: {id(list1)}")
print(f"list2: {list2}, ID: {id(list2)}")

list2.append(30) # Modify the list through list2

print(f"After modifying list2:")
print(f"list1: {list1}, ID: {id(list1)}") # list1 also reflects the change
print(f"list2: {list2}, ID: {id(list2)}")

For immutable objects, this doesn’t happen. Reassigning one variable doesn’t affect another that initially pointed to the same immutable object.

# Immutable example
str1 = "initial"
str2 = str1  # str2 refers to the same string object as str1

print(f"str1: {str1}, ID: {id(str1)}")
print(f"str2: {str2}, ID: {id(str2)}")

str2 = "changed" # str2 is reassigned to a new string object

print(f"After reassigning str2:")
print(f"str1: {str1}, ID: {id(str1)}") # str1 remains unchanged
print(f"str2: {str2}, ID: {id(str2)}")

Scenario 2: Passing Objects to Functions

When mutable objects are passed to functions, the function can modify the original object directly.

def modify_data(data):
    data.append("modified")
    print(f"Inside function: {data}")

my_mutable_list = ["a", "b"]
print(f"Before function call: {my_mutable_list}")
modify_data(my_mutable_list)
print(f"After function call: {my_mutable_list}")

For immutable objects passed to functions, any “modifications” within the function create a new object, and the original remains unchanged unless the function’s return value is reassigned.

def attempt_to_modify(data):
    data += " appended"
    print(f"Inside function: {data}")
    return data # Important to return the new object

my_immutable_string = "original"
print(f"Before function call: {my_immutable_string}")
my_immutable_string = attempt_to_modify(my_immutable_string) # Reassign to the returned value
print(f"After function call: {my_immutable_string}")

Identifying Mutable and Immutable Types in Python

Understanding which data types fall into each category is crucial.

Common Immutable Types:

  • Numbers: int, float, complex, bool
  • Sequences: str, tuple, bytes, range
  • frozenset

Common Mutable Types:

  • Sequences: list, bytearray
  • Mappings: dict
  • Sets: set
  • User-defined classes (unless specifically designed to be immutable)

A helpful way to test mutability is by using the built-in id() function. If the id() of an object changes after an operation that appears to modify it, the object is likely immutable. If the id() remains the same, the object is likely mutable.

# Using id() to check mutability
immutable_int = 10
print(f"Initial int ID: {id(immutable_int)}")
immutable_int += 5
print(f"After +=, int ID: {id(immutable_int)}") # ID changes

mutable_list = [1, 2]
print(f"Initial list ID: {id(mutable_list)}")
mutable_list.append(3)
print(f"After append, list ID: {id(mutable_list)}") # ID remains the same

Why Does Mutability Matter?

  1. Predictable Behavior: Knowing whether an object is mutable helps you predict how changes in one part of your code will affect other parts. This is especially important when dealing with shared data structures or passing data between functions.
  2. Performance: Immutable objects can sometimes be more efficient. For instance, Python may intern (reuse) immutable objects with the same value, saving memory. For example, small integers and short strings are often interned.
  3. Hashing: Mutable objects cannot be used as keys in dictionaries or elements in sets because their contents can change, which would alter their hash value. Immutable objects, on the other hand, are hashable.

Examples of Operations and Mutability

  • Reassignment (=): This operation always reassigns a variable to point to an object, regardless of mutability. It doesn’t change the object itself.
  • Augmented Assignment (+=, -= etc.): For immutable types, this creates a new object. For mutable types, it can modify the object in place (e.g., list.extend()).
  • Item Assignment (obj[index] = value): This is only possible for mutable sequence types like lists. Attempting this on immutable sequences like strings or tuples will raise a TypeError.

Best Practices and Considerations

  • When you need to modify a sequence and want to preserve the original, create a copy first. For lists, new_list = old_list.copy() or new_list = list(old_list) works well.
  • Be mindful of default mutable arguments in function definitions, as they can lead to unexpected shared state across function calls.
  • When working with data structures that should not be changed, prefer immutable types like tuples and frozensets.

By understanding and applying these principles, you can write cleaner, more predictable, and more efficient Python code.

FAQs on Python Mutability

Q: How do I know if a Python object is mutable or immutable

ANS: You can often infer this from its type. Built-in immutable types include integers, floats, strings, and tuples. Mutable types include lists, dictionaries, and sets. You can also test this by observing if an object’s id() changes after an apparent modification; a changing id() indicates immutability. For more on this, check out the Python data model .

Q: Is string mutable in Python

ANS: No, strings in Python are immutable. While operations like concatenation (+=) can change the value a string variable refers to, they actually create a new string object. You cannot change individual characters within an existing string.

Q: What happens when I assign a mutable object to another variable

ANS: When you assign a mutable object to another variable (e.g., list2 = list1), both variables refer to the same object in memory. Any changes made through list2 will be reflected when accessing list1, and vice-versa. This is known as passing by reference.

Q: Can I change a float object in place

ANS: No, float objects in Python are immutable. Operations that seem to modify a float, such as addition (+=), create a new float object, and the variable is updated to point to this new object.

Q: Why are dictionaries mutable

ANS: Dictionaries are mutable because they are designed to store key-value pairs, and you can add, remove, or update these pairs after the dictionary has been created. This modification happens “in place” without creating a new dictionary object. You can explore more about Python dictionaries and their behavior.

Q: What is the difference between list and tuple mutability

ANS: Lists are mutable, meaning you can change their elements, add new elements, or remove elements in place. Tuples, on the other hand, are immutable; once created, their contents cannot be changed. If you need to “modify” a tuple, you must create a new tuple. For more detail, see our introduction to Python data structures .
