Every time I configure something with AWS CLI, I encounter the error message:

“The config profile (myname) could not be found.”

This issue comes up while running commands such as aws configure. I am using Python 3.4 and I aim to utilize AWS CLI Keyring to encrypt my credentials.

To resolve this error, here are the detailed solutions:

Top 5 Solutions to Resolve AWS CLI Profile Not Found Error

1. Unset Environment Variables

When transitioning to a new machine, I faced this issue after carrying over my AWS_DEFAULT_PROFILE environment variable without copying my ~/.aws directory. Thus, I could not execute any awscli commands until I performed one of the following:

  • Verify AWS-specific environment variables in your session:

    env | grep AWS_

  • If AWS_DEFAULT_PROFILE or AWS_PROFILE isn’t listed, this might not apply to you.

  • To temporarily remove the default profile, execute:

    unset AWS_DEFAULT_PROFILE
unset AWS_PROFILE

  • Configure the required profile:

    aws --profile myname configure

  • Restart your shell session:

    exec $SHELL

  • Verify your setup:

    aws iam get-user

2. Ensure Proper Configuration File

Profiles in AWS CLI necessitate a configuration file located by default at ~/.aws/config or specified with AWS_CONFIG_FILE. An example configuration file might look like this:

[profile myname]
output=json
region=us-west-1
aws_access_key_id=your_access_key
aws_secret_access_key=your_secret_key

Ensure that the environment variable AWS_PROFILE accurately directs AWS CLI to the profile in use. If AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY are simultaneously set, they will take precedence.

3. Validate the Config File Structure

Examine your ~/.aws/config file for any invalid section. It might appear something like this:

[default]
region=us-west-2
output=json

[myname]
region=us-east-1
output=text

If an error arises, simply remove the [myname] section along with its containing content.

4. Clear Outdated Environment Variables

If the environment variable AWS_PROFILE is set to an outdated value, you can rectify the issue by modifying or unsetting it as previously mentioned.

5. Use Docker Considerations

If you are utilizing the Docker method for the AWS CLI, ensure you have made your credentials directory accessible within the Docker container. Modify your command as:

docker run --rm -it -v ~/.aws:/root/.aws amazon/aws-cli:latest aws command args...

6. Correct User Configurations

For specific user setups, follow AWS’s setup guide , which explains how to configure a default user and add additional ones. Incomplete setups can result in your profile not being created.

7. Explore Additional Resources

A similar issue has been discussed in-depth on ServerFault , where the importance of distinguishing between configuration-related information and credential files was emphasized.

8. Virtual Environment Awareness

Double-check that you are operating within the correct virtual environment. After updating your development tools, ensure the terminal aligns with your crucial configurations.

9. Headless Server Challenges

If you’re facing this issue on a CI runner or headless server, verify that the service starts with the user who has access to the AWS configuration files. You can also set your credentials appropriately to enable commands to run successfully.

10. Modify Configuration Formatting

If your configuration files appear corrupted or wrongly formatted (like incorrect file extensions), ensure that they are adequately structured as previously illustrated.

Practical Example of Generating RDS Tokens

You can generate an IAM RDS token using the following Python code:

import boto3
import os

S3_KEY = os.environ['aws_access_key']
S3_SECRET = os.environ['aws_secret_access_key']

def generate_iam_rds_token(server, region, port, user, S3_KEY, S3_SECRET):
    s3_conn = boto3.client('rds', region_name=region,
                            aws_access_key_id=S3_KEY,
                            aws_secret_access_key=S3_SECRET)
    return s3_conn.generate_db_auth_token(server, port, user, Region=region)

## Call the method to get a token
server = 'https://example.com'
region = 'ap-west-3'
port = 'port_number'
user = 'db_user_name'
pwd_token = generate_iam_rds_token(server, region, port, user, S3_KEY, S3_SECRET)

SQLALCHEMY_DATABASE_URI = 'postgresql+psycopg2://{user}:{pwd}@{host}:{port}/{db}'.format(user=user, host='db_host', port=port, db='database_name', pwd=pwd_token)

Please ensure your configurations and permissions are set accurately.

### FAQs on AWS CLI Profile Not Found

Q: What should I do if I keep getting the profile not found error even after following these solutions?

A: Ensure that your configuration files are not corrupted and verify that your environment variables are correctly set. If issues persist, consider checking your AWS setup or file permissions.

Q: How can I manage multiple AWS profiles?

A: You can manage multiple profiles by creating different sections in your config file and using the --profile flag when executing AWS CLI commands.

Q: Can I reset my AWS CLI configuration?

A: Yes, you can delete or rename your existing configuration files located in ~/.aws and re-run the aws configure command to start fresh.
