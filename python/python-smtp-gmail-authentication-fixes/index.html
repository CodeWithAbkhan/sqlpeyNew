“Python SMTP: Resolving Gmail Connection and Authentication Issues with smtplib”

When configuring Python applications to send emails through Gmail’s Simple Mail Transfer Protocol (SMTP) server, developers frequently encounter connection initialization hurdles or authentication failures. Resolving these issues typically involves correct port selection, ensuring proper TLS negotiation, and, crucially in modern configurations, using the appropriate authentication methods like App Passwords instead of primary account credentials.

What are the established methods and required steps to reliably configure smtplib for sending emails using a Gmail account?

Established Methods for smtplib Configuration

The primary methods revolve around standard SMTP communication using port 587 (requiring explicit starttls()) or secure SMTP over SSL using port 465 (requiring SMTP_SSL). Modern security requirements often necessitate using App Passwords.

Method 1: Standard SMTP with Port 587 and Explicit TLS Handshake

This approach establishes a connection and then upgrades it to a secure channel using starttls(). It is vital to call server.ehlo() before server.starttls().

import smtplib

def send_email_tls(user, pwd, recipient, subject, body):
    """Sends email using SMTP on port 587 with STARTTLS."""
    FROM = user
    # Handle single recipient or list of recipients
    TO = recipient if isinstance(recipient, list) else [recipient]
    SUBJECT = subject
    TEXT = body

    # Construct the raw message format expected by older SMTP servers
    message_content = f"""From: {FROM}
To: {', '.join(TO)}
Subject: {SUBJECT}

{TEXT}
"""
    try:
        # Connect using port 587
        server = smtplib.SMTP("smtp.gmail.com", 587)
        server.ehlo()  # Identify ourselves to the server
        server.starttls() # Secure the connection
        server.ehlo() # Re-identify after upgrade (sometimes needed)
        server.login(user, pwd)
        server.sendmail(FROM, TO, message_content)
        server.close()
        print('Successfully sent the mail via Port 587 (TLS)')
    except Exception as e:
        print(f"Failed to send mail via Port 587: {e}")

# Alternative: Proper message formatting with headers and CRLF separators
def send_email_proper_headers(sender_email, password, recipient_email, subject, message_body):
    import smtplib
    
    msg_parts = [
        f"From: {sender_email}",
        f"To: {recipient_email}",
        f"Subject: {subject}",
        "", # Blank line separates headers from body
        message_body
    ]
    # Use CRLF (\r\n) as line endings for robustness
    message = "\r\n".join(msg_parts)
    
    try:
        server = smtplib.SMTP('smtp.gmail.com', 587)
        server.ehlo()
        server.starttls()
        server.login(sender_email, password)
        server.sendmail(sender_email, recipient_email, message)
        server.close()
        print('Email sent with correct RFC formatting.')
    except Exception as e:
        print(f"Error sending formatted email: {e}")

Method 2: Secure Connection with SMTP_SSL on Port 465

When using port 465, the connection is established as SSL from the start; therefore, starttls() should not be called.

import smtplib

def send_email_ssl(user, pwd, recipient, subject, body):
    """Sends email using SMTP_SSL on port 465."""
    FROM = user
    TO = recipient if isinstance(recipient, list) else [recipient]
    SUBJECT = subject
    TEXT = body
    
    message_content = f"""From: {FROM}
To: {', '.join(TO)}
Subject: {SUBJECT}

{TEXT}
"""
    
    try:
        # Connect directly using SMTP_SSL
        server_ssl = smtplib.SMTP_SSL("smtp.gmail.com", 465)
        server_ssl.ehlo() # Optional but good practice
        server_ssl.login(user, pwd)  
        server_ssl.sendmail(FROM, TO, message_content)
        server_ssl.close()
        print('Successfully sent the mail via Port 465 (SSL)')
    except Exception as e:
        print(f"Failed to send mail via Port 465: {e}")

Addressing Authentication Failures (Critical for Modern Gmail)

Many modern issues stem from Google’s deprecation of “Less Secure App Access” or lack of proper credential handling when 2-Step Verification (2SV) is active.

Solution A: Using Google App Passwords (Recommended for 2SV)

If 2-Step Verification is enabled on your Google account, you must generate an App Password. Standard account passwords will result in SMTPAuthenticationError: (535, '5.7.8 Username and Password not accepted.') or error code 534.

  1. Enable 2-Step Verification on your Google Account security settings.
  2. Navigate to the App Passwords section .
  3. Generate a 16-digit password for the “Mail” application (or a custom name).
  4. Use this generated App Password in place of your regular Gmail password in the script.
import smtplib

GMAIL_EMAIL = 'your_sending_email@gmail.com'
# USE THE 16-DIGIT APP PASSWORD HERE
GMAIL_APP_PASSWORD = 'your_generated_16_digit_app_password'

def send_authenticated_email_app_password(recipient, subject, content):
    
    email_message = f"Subject: {subject}\n\n{content}"
    
    try:
        # Using SMTP_SSL (Port 465) is often preferred with App Passwords
        smtpserver = smtplib.SMTP_SSL('smtp.gmail.com', 465)
        smtpserver.ehlo()
        smtpserver.login(GMAIL_EMAIL, GMAIL_APP_PASSWORD)

        smtpserver.sendmail(GMAIL_EMAIL, recipient, email_message)
        smtpserver.close()
        print('Email sent successfully using App Password.')
    except Exception as e:
        print(f"Authentication error with App Password: {e}")

Solution B: Using Standard Library yagmail (Abstraction Layer)

For simpler configuration, external libraries often abstract away the complexities of connection setup and header formatting. yagmail is one such tool that works seamlessly with App Passwords.

# Installation: pip install yagmail
import yagmail

SENDER_EMAIL = 'your_sending_email@gmail.com'
APP_PASSWORD = 'your_generated_16_digit_app_password' 

def send_email_yagmail(recipient, subject, body):
    try:
        # Initialization configures Gmail settings automatically
        yag = yagmail.SMTP(SENDER_EMAIL, APP_PASSWORD)
        yag.send(
            to=recipient,
            subject=subject,
            contents=body
        )
        print('Email sent successfully via yagmail.')
    except Exception as e:
        print(f"Yagmail error: {e}")

# Example usage
# send_email_yagmail('another_recipient@test.org', 'Yagmail Test', 'This is much easier!')

Solution C: Using redmail for Enhanced Features

The redmail library provides an object-oriented approach and simplifies configuration, especially when dealing with HTML content and attachments, while still relying on the App Password mechanism for Gmail.

# Installation: pip install redmail
from redmail import gmail

gmail.user_name = 'your_sending_email@gmail.com'
# Set the App Password
gmail.password = '<YOUR APPLICATION PASSWORD>'

def send_email_redmail(recipient, subject, text_body, html_body=None):
    try:
        gmail.send(
            subject=subject,
            receivers=[recipient],
            text=text_body,
            html=html_body # Optional HTML content
        )
        print('Email sent successfully via redmail.')
    except Exception as e:
        print(f"Redmail error: {e}")

Alternative Approach: Utilizing the Gmail API (Non-SMTP)

For applications where direct SMTP connection is blocked or asynchronous operations are preferred (e.g., web servers), the Gmail API offers a robust, non-blocking alternative, though it requires setting up OAuth 2.0 credentials in the Google Cloud Console. This method bypasses smtplib entirely.

FAQs on Python SMTP Gmail Authentication Fixes

Q: What is the correct port for secure Gmail SMTP connection

ANS: The standard secure port for Gmail SMTP using SMTP_SSL is 465. For standard SMTP requiring starttls(), the port is 587.

Q: Why am I getting SMTPAuthenticationError 535 with my correct password

ANS: This usually means Google has blocked your login attempt because you are not using an App Password, especially if you have 2-Step Verification enabled. You must generate and use a 16-digit App Password.

Q: Must I call server ehlo before server starttls

ANS: Yes, it is highly recommended to call server.ehlo() before initiating the server.starttls() command when using port 587 with smtplib.SMTP.

Q: Is 'Allow less secure apps' still a valid fix

ANS: No, Google phased out support for “Less Secure App Access” starting in May 2022. App Passwords are the required replacement for non-browser applications when 2-Step Verification is active.

Q: How do I send an email to multiple recipients in smtplib

ANS: When calling server.sendmail(fromaddr, toaddrs, msg), the toaddrs argument should be a list of email addresses.
