“Python Subprocess: Best Practices for Writing to Child Process Stdin”

When executing external commands via Python’s subprocess module, supplying data to the child process’s standard input (stdin) requires careful handling to prevent issues like deadlocks or incorrect data serialization. What are the most robust and modern techniques for achieving this interaction?

Replacing os.popen* with Modern subprocess Calls

The legacy os.popen* functions are generally discouraged. Replacing them with subprocess.Popen necessitates correctly configuring pipes for I/O streams.

If you intend to supply input to stdin, you must instantiate Popen with stdin=PIPE. Similarly, receiving output requires stdout=PIPE and/or stderr=PIPE.

The Critical Role of communicate()

A key warning when dealing with Popen: Avoid mixing direct calls like stdin.write(), stdout.read(), or stderr.read(). These manual calls can cause buffer exhaustion in the operating system pipes, leading to the parent process blocking indefinitely (a deadlock) while waiting for the child process, or vice-versa.

The recommended function to avoid these pitfalls is p.communicate(). This method sends all input data provided via its input argument and reads all output until the stream closes, handling the synchronization required to prevent deadlocks.

Example using Popen and communicate() (Binary Data Requirement):

If using communicate() in Python 2 or needing explicit control, the input provided must be a bytes object.

from subprocess import Popen, PIPE, STDOUT

# Command to search for lines containing 'f'
command_args = ['grep', 'f']
input_data = b'one\ntwo\nthree\nfour\nfive\nsix\n'

process = Popen(
    command_args,
    stdout=PIPE,
    stdin=PIPE,
    stderr=STDOUT
)
    
# Send data via input argument, retrieve output as the first element of the tuple
grep_output_bytes = process.communicate(input=input_data)[0]
print(grep_output_bytes.decode('utf-8'))

# Expected Output excerpt:
# -> four
# -> five
# ->

Alternative: Utilizing subprocess.run() (Python 3.5+)

For synchronous execution where you wait for the command to finish before proceeding, subprocess.run() is often cleaner, especially in Python 3.5 and newer. It integrates input provision, execution, and result capture into a single call.

Example using subprocess.run() with String Input:

In Python 3.6+, the encoding argument (or text=True in 3.7+) allows passing a standard string directly to input, which the function automatically encodes.

from subprocess import run, PIPE

command_args = ['grep', 'f']
input_string = 'one\ntwo\nthree\nfour\nfive\nsix\n'

# Using encoding for Python 3.5+ compatibility
result = run(
    command_args, 
    stdout=PIPE,
    input=input_string, 
    encoding='ascii' # Explicitly state the encoding used for the string input
)

print(f"Exit Code: {result.returncode}")
print(f"Output:\n{result.stdout}")

# Expected Output:
# Exit Code: 0
# Output:
# four
# five
#

Encoding String Data for communicate()

If you must use Popen directly (e.g., for long-running interactive processes), remember that stdin.write() expects byte strings. If you have a Python string, it must be explicitly encoded before transmission.

from subprocess import Popen, PIPE

p = Popen(['grep', 'f'], stdout=PIPE, stdin=PIPE, stderr=PIPE)
string_to_send = 'one\ntwo\nthree\nfour\nfive\nsix\n'

# Encode the string before sending it to stdin
out_bytes, err_bytes = p.communicate(input=string_to_send.encode('utf-8'))
print(out_bytes.decode('utf-8'))

Using check_output with Input (Python 3.4+)

The subprocess.check_output function is excellent for capturing output when you know the command succeeds. Since Python 3.4, it supports the input argument for piping data to stdin.

Sending Bytes:

import subprocess

output_bytes = subprocess.check_output(
    ["sed", "s/foo/bar/"],
    input=b"foo" # Input must be bytes
)
print(output_bytes)
# b'bar'

Sending Strings (Python 3.7+):

Using text=True (or universal_newlines=True in older 3.x versions) allows check_output to accept a string directly and return a string.

import subprocess

output_string = subprocess.check_output(
    ["sed", "s/foo/bar/"],
    input="foo",
    text=True # Automatically handles encoding/decoding
)
print(output_string)
# 'bar'

Alternative: Low-Level File Descriptors with os.pipe()

For situations where you need low-level control over the pipe before passing the file descriptor to a subprocess, os.pipe() provides a direct mechanism. This creates read and write ends of a pipe. You write to the write end, close it, and pass the read end to the subprocess’s stdin.

import os
import subprocess

# Create pipe: read_fd and write_fd
read_fd, write_fd = os.pipe()
data_to_write = "stdin input here\n".encode('utf-8')

# Write data to the pipe
os.write(write_fd, data_to_write)

# Crucially, close the write end so the subprocess sees EOF when done reading
os.close(write_fd)

# Execute command, using the read end of the pipe as stdin
try:
    subprocess.check_call(['cat'], stdin=read_fd) # Using 'cat' to echo input
finally:
    # Close the read end in the parent process
    os.close(read_fd)

Utilizing Temporary Files for Large Inputs

If the input data (s in communicate(input=s)) is exceedingly large, buffering the entire input in the parent process before forking the child can lead to memory exhaustion (OSError: Cannot allocate memory).

In such extreme cases, writing the input to a temporary file and instructing the subprocess to read from that file path might be necessary. Alternatively, using Python’s tempfile.SpooledTemporaryFile can sometimes offer a managed file-like object suitable for use as stdin.

from subprocess import Popen, PIPE
from tempfile import SpooledTemporaryFile as tempfile

# Create a temporary file object that acts like a file
f = tempfile()
f.write('one\ntwo\nthree\nfour\nfive\nsix\n')
# Rewind to the beginning so the subprocess can read from the start
f.seek(0) 

# Pass the file object directly to stdin
process = Popen(['/bin/grep','f'], stdout=PIPE, stdin=f)
output = process.stdout.read()
f.close()

print(output.decode('utf-8'))

Managing Interactive Sessions with pexpect

For processes that require complex, continuous back-and-forth dialogue (like ftp or shell scripts that prompt for input based on previous output), the standard subprocess tools can be cumbersome. The external library pexpect (or its Windows equivalent, wexpect) is specifically designed for these interactive dialogues by waiting for specific output patterns before sending the next command.

import pexpect

# Spawn a simple grep process expecting interactive input
child = pexpect.spawn('grep f', timeout=10)
child.sendline('text to match') # Sends data followed by newline

# Wait for output and print what was received before the prompt/EOF
print(child.before.decode('utf-8')) 

# Example for FTP interaction
child_ftp = pexpect.spawn('ftp ftp.openbsd.org')
child_ftp.expect('Name .*: ')
child_ftp.sendline('anonymous')
child_ftp.expect('Password:')
child_ftp.sendline('[email protected]')
child_ftp.expect('ftp> ')
child_ftp.sendline('ls /pub/OpenBSD/')
child_ftp.expect('ftp> ')
print(child_ftp.before)
child_ftp.interact() # Transfer control to the user

FAQs on Python Subprocess Write To Stdin

Q: Why should I prefer communicate over direct stdin write read calls

ANS: Direct calls like stdin.write() or stdout.read() can cause the parent process and child process to deadlock because one might fill its input/output buffer while the other is blocked waiting to read/write, leading to indefinite waiting. p.communicate() manages this synchronization internally.

Q: Does subprocess run always wait for the process to complete

ANS: Yes, subprocess.run() is a blocking call; it waits for the command to terminate before returning a CompletedProcess object. Use Popen if you need non-blocking execution or continuous interaction.

Q: What data type is required for the input argument in Popen communicate

ANS: In general, p.communicate(input=...) requires a bytes object (b'data'). If you are using subprocess.run or subprocess.check_output with text=True (Python 3.7+), you can safely pass a standard string.
