When developing Python packages, a common concern arises regarding the inclusion of non-Python files, such as licenses, readme files, or additional data required for your application. How can you effectively include these files when using setup.py? This post explores various methods to seamlessly include non-Python files in your Python package, ensuring they are accessible post-installation.

How to Include Non-Python Files in Your Python Package with setup.py

To include files that are not Python code—like a license or documentation files—while maintaining control over their placement within the installed package structure, you can follow a series of steps. This approach will ensure that your package behaves consistently across different operating systems.

Step 1: Create a MANIFEST.in File

Begin by creating a MANIFEST.in file in the same directory as your setup.py. This file specifies which additional files to include in the source distribution. Here’s an example of what your MANIFEST.in might look like:

include LICENSE.txt
include README.md
recursive-include docs *.txt
recursive-include assets *

This configuration will ensure that the specified files and directories are included in your source distribution.

Step 2: Modify setup.py

Next, you’ll need to modify your setup.py file to ensure that these files are installed correctly. You can achieve this by using the include_package_data=True argument in the setup() function. Here’s how your setup.py might look:

from setuptools import setup

setup(
    name='my_package',
    version='0.1.0',
    packages=['my_package'],
    include_package_data=True,
    package_data={
        'my_package': ['../LICENSE.txt'],  # Adjust the path as necessary
    },
)

Various Solutions to Include Non-Python Files

Over time, several methods have been proposed for including non-Python files. Below, we detail various approaches that have proven effective:

Solution 1: Use setuptools_scm

Using setuptools_scm allows you to automatically include versioned files within your project without manual configuration. Simply add the following lines to your setup.py:

setup(
    setup_requires=['setuptools_scm'],
    include_package_data=True,
)

Solution 2: Utilize recursive includes

If your non-Python files are organized in directories, you could also leverage recursive-include in MANIFEST.in:

recursive-include assets *
recursive-include data *

This allows automatic inclusion of all files under specified directories.

Solution 3: Define specific package_data

You can specify package-specific data files directly within the setup.py, which grants you more targeted control over what gets included:

package_data={
    'my_package': ['data/*.json', 'config/*.yml'],
},

Solution 4: Custom build commands

For complete customization, you can define custom build commands. Here’s how to create a custom setup that copies files during installation:

import os
from setuptools import setup
from setuptools.command.build_py import build_py
from shutil import copyfile

class CustomBuildCommand(build_py):
    def run(self):
        build_py.run(self)
        # Custom file copying logic
        copyfile('LICENSE.txt', os.path.join(self.build_lib, 'my_package/LICENSE.txt'))

setup(
    cmdclass={'build_py': CustomBuildCommand},
    ...
)

Alternative Methods

  • Using setup.cfg: Specify files in a setup.cfg alongside setup.py for a cleaner configuration.

  • Post-installation scripts: For complex scenarios where files need to be moved post-installation, consider adding hooks or scripts to automate this process.

To delve deeper into these solutions, you might want to reference the official setuptools documentation or the Python packaging guides .

FAQs on How to Include Non-Python Files with setup.py

Q: Why do I need MANIFEST.in?

A: The MANIFEST.in file is essential for specifying which non-Python files should be included in your source distribution, allowing them to be packaged correctly.

Q: What happens if I forget to add include_package_data=True?

A: If you do not set include_package_data=True, only Python files (e.g., *.py) will be included, and your non-Python files will be omitted from the final package.

Q: Can I include files from directories outside my package?

A: Including files outside of your package’s structure is typically discouraged, as they may not be installed correctly. Instead, keep your non-Python files within the package directory or properly specify them in MANIFEST.in.

Q: Does using setuptools_scm impact the inclusion of non-code files?

A: Not directly; setuptools_scm focuses on versioning management but allows you to include files that are tracked by version control. You still need to specify non-code files in MANIFEST.in or setup.py.
