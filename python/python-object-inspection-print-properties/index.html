“Python Object Inspection: Best Ways to Print All Properties and Values”

When working with complex data structures or debugging unexpected object behavior in Python, developers frequently seek reliable methods to print all the current properties (attributes and their values) of an object. There is no single, universally perfect built-in function for this task, as the desired output often depends on whether you need instance attributes, inherited attributes, methods, or calculated properties.

How can one effectively inspect the complete state of a Python object to display its attributes and associated values?

Core Built-in Approaches: vars() and dir()

Two fundamental tools often discussed are vars() and dir(). It is crucial to distinguish their distinct roles.

Using vars() for Instance Dictionary

The vars() function, when applied to an object instance, returns the object’s __dict__ attribute, which contains its writable attributes (instance variables).

Practical Application: Combine vars() with pprint for cleaner output.

from pprint import pprint

    def __init__(self, host, port):

Limitation Highlight: If an object uses __slots__ (like the example below, which omits __dict__), vars() will raise a TypeError because no __dict__ exists. Furthermore, vars() does not show inherited attributes or methods.

class SlottedObject:
    __slots__ = ('value_a', 'value_b')
    def __init__(self):
        self.value_a = 100

slotted = SlottedObject()
# vars(slotted) will raise an error if __dict__ is not present or accessible

Using dir() for Attribute Names

The dir() function provides an alphabetized list of names belonging to the object, including methods, inherited attributes, and instance attributes. It only lists the names, not their values.

Exploring Module Contents (Alternative Use Case): dir() is excellent for seeing what an entire module makes available.

Since neither vars() nor dir() alone provides the comprehensive view needed, combining them with getattr() or inspecting internal dictionaries is necessary.

Solution B: Customizing Attribute Filtering with inspect

To filter out unwanted elements like built-in methods or properties that might be expensive to calculate, the inspect module is invaluable.

A refined function can aim to show only data attributes, excluding methods and properties.

from inspect import getmembers
from types import FunctionType
from pprint import pprint

def get_instance_data_members(obj):
    """Returns a dictionary of attributes, excluding methods and properties."""
    
    # Identify names of methods and properties defined on the type object
    disallowed_names = {
      name for name, value in getmembers(type(obj)) 
      if isinstance(value, (FunctionType, property))
    }
    
    data_attributes = {}
    for name in dir(obj):
        # Exclude private/protected names starting with '_'
        if name.startswith('_') or name in disallowed_names:
            continue
        
        # Ensure attribute is present before attempting getattr
        if hasattr(obj, name):
            data_attributes[name] = getattr(obj, name)
            
    return data_attributes

Alternative Serialization Methods

For complex, nested objects, standard printing often yields unhelpful object references (<object at 0x...>). Serialization formats like JSON or specialized libraries offer recursive viewing.

1. Using json.dumps with a Custom Serializer

If an object is purely composed of serializable types (or objects whose values can be extracted via vars()), json.dumps can recursively traverse it.

import json

def recursive_dump_json(obj, indent=4):
    """Attempts a recursive dump using vars() for object content."""
    try:
        # The default function tells json how to serialize objects it doesn't natively support
        print(json.dumps(obj, default=lambda o: vars(o), indent=indent))
    except TypeError as e:
        print(f"JSON serialization failed for part of the structure: {e}")

4. Defining Representation Methods (__str__ and __repr__)

For instances of custom classes, implementing __repr__ or __str__ provides controlled output when you simply print the object or use repr(). __repr__ is preferred for debugging as it aims to be an unambiguous, often reconstructible, representation.

class SimpleContainer:
    def __init__(self, data):
        self.data = data
    
    def __repr__(self):
        # Clear, informational representation
        return f"<SimpleContainer object containing: {self.data!r}>"

container = SimpleContainer([1, 2, {'key': 'value'}])
print(f"\n

FAQs on Python Object Inspection Print Properties

Q: What is the main difference between vars and dir for object inspection

ANS: vars(obj) returns a dictionary (__dict__) containing only the writable instance attributes, while dir(obj) returns a list of all accessible attribute names, including methods and inherited members.

Q: Can vars() work on objects using __slots__

ANS: Generally no, if the object does not explicitly define a __dict__ in its slots or implicitly inherits one, calling vars() will result in a TypeError.

Q: How to see inherited attributes and their values

ANS: You must iterate over dir(obj) and use getattr(obj, name) for each name returned, as vars() ignores inherited attributes. Be prepared to handle methods and properties as well.

Q: Is there a built-in function that recursively prints everything

ANS: No single built-in function exists that perfectly and recursively dumps all attributes, ignoring methods, while also handling properties correctly across all object types without external libraries or custom code.
