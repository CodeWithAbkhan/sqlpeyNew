I have a SQLAlchemy query object, and my goal is to extract the text of the compiled SQL statement, inclusive of the bound parameters. This means I want the SQL query to appear without placeholders like %s or any other variable delays that would typically remain before execution by the SQLAlchemy expression compiler or the database dialect engine.

When I call str() on the query, I see output resembling the following:

SELECT id WHERE date_added <= %s AND date_added >= %s ORDER BY count DESC

Despite inspecting query._params, this dictionary appears empty. My attempts to use a custom compiler, inspired by various documentation examples including the sqlalchemy.ext.compiler.compiles decorator, still leave placeholders in the output.

It seems that SQLAlchemy prefers to keep the generated queries hidden, possibly to maintain the abstraction it provides over various database APIs. Nevertheless, I’m keen on identifying the query being executed, whether or not it has run yet; thus, I sought out a few solutions.

Method 1: Utilize SQLAlchemy Dialects

A promising solution to obtain the exact SQL query can be derived from Nicolas Cadou’s blog post . The distilled guidance offers the following solution to execute:

from sqlalchemy.dialects import postgresql

query = DBSession.query(model.Name).distinct(model.Name.value).order_by(model.Name.value)
print(str(query.statement.compile(dialect=postgresql.dialect())))

Method 2: Implement a Custom Compile Function

For those using SQLAlchemy version 0.6 or later, another approach involves defining a custom compile function as follows:

from sqlalchemy.sql import compiler
from psycopg2.extensions import adapt as sqlescape

def compile_query(query):
    dialect = query.session.bind.dialect
    statement = query.statement
    comp = compiler.SQLCompiler(dialect, statement)
    comp.compile()
    enc = dialect.encoding
    params = {}
    for k, v in comp.params.items():
        if isinstance(v, str):
            v = v.encode(enc)
        params[k] = sqlescape(v)
    return (comp.string.encode(enc) % params).decode(enc)

Method 3: Understanding Query-Data Separation

It is important to recognize that SQLAlchemy separates the SQL query from its respective data. The query is sent as a standalone request, and parameters are delivered separately. If desired, manual interpolation could be applied:

print(query.statement)
print(query.statement.compile())  # Outputs: SELECT field_1, field_2 FROM table WHERE id=:id_1
print(query.statement.compile().params)  # Outputs parameter values in a dictionary

Method 4: MySQLdb Backend Customization

For users on the MySQLdb backend, an adapted compilation snippet could look like this:

def compile_query(query):
    from sqlalchemy.sql import compiler
    from MySQLdb.converters import conversions, escape

    dialect = query.session.bind.dialect
    statement = query.statement
    comp = compiler.SQLCompiler(dialect, statement)
    comp.compile()
    enc = dialect.encoding
    params = []
    for k in comp.positiontup:
        v = comp.params[k]
        if isinstance(v, str):
            v = v.encode(enc)
        params.append(escape(v, conversions))
    return (comp.string.encode(enc) % tuple(params)).decode(enc)

Method 5: Execute with Events

Listening for executing events, such as do_execute, can also facilitate SQL query extraction while suppressing execution:

import sqlalchemy

class QueryDebugger:
    def __init__(self, engine, query):
        with engine.connect() as connection:
            try:
                sqlalchemy.event.listen(engine, "do_execute", self.receive_do_execute)
                connection.execute(query)
            finally:
                sqlalchemy.event.remove(engine, "do_execute", self.receive_do_execute)

    def receive_do_execute(self, cursor, statement, parameters, context):
        self.statement = statement
        self.parameters = parameters
        self.query = cursor.mogrify(statement, parameters)
        return True

Method 6: Craft an Expression Language Query

With SQLAlchemy’s Expression Language at your fingertips, you can craft and compile queries effectively. Here’s a summarized pattern:

Define your ORM model first.

from sqlalchemy import Column, Integer, String
from sqlalchemy.ext.declarative import declarative_base

Base = declarative_base()

class Foo(Base):
    __tablename__ = 'foo'
    id = Column(Integer, primary_key=True)
    name = Column(String(80), unique=True)
    value = Column(Integer)

## Creating a query statement
from sqlalchemy.sql import select
statement = select([Foo.name, Foo.value]).where(Foo.value > 0)
compiled_query = statement.compile()

## Specify dialect if required
from sqlalchemy.dialects import postgresql
query = statement.compile(dialect=postgresql.dialect())

Method 7: Handle Connection Context for PostgreSQL

When using specific environments like Flask with Flask-SQLAlchemy, ensure the right dialect integration:

import sqlalchemy.dialects.postgresql.psycopg2
from flask import current_app

def query_to_string(query):
    dialect = sqlalchemy.dialects.postgresql.psycopg2.dialect()
    compiled_query = query.statement.compile(dialect=dialect)
    sqlalchemy_connection = current_app.db.session.connection()
    context = dialect.execution_ctx_cls._init_compiled(
        dialect,
        sqlalchemy_connection,
        sqlalchemy_connection.connection,
        compiled_query,
        None
    )
    mogrified_query = sqlalchemy_connection.connection.cursor().mogrify(
        context.statement,
        context.parameters[0]
    )
    return mogrified_query.decode()

Method 8: Using Events for Profiling Queries

Another efficient way to capture the executing SQL is by utilizing SQLAlchemy’s event listeners, focusing on before_cursor_execute to log queries before execution:

@event.listens_for(Engine, "before_cursor_execute")
def before_cursor_execute(conn, cursor, statement, parameters, context, executemany):
    logger.debug(f"Query: {statement} | Params: {parameters}")

FAQs on Extracting Raw Compiled SQL Queries from SQLAlchemy Expressions

Q: How can I include parameters in the raw SQL query output?

A: To include parameters in your compiled SQL query, you can implement methods which replace placeholders with actual values, such as using the mogrify() method or a custom compilation function that formats the SQL string with parameters.

Q: Is it safe to print raw SQL queries in production?

A: It’s generally advisable to avoid logging raw SQL queries in production due to potential security risks, especially concerning SQL injection vulnerabilities. Consider only printing queries in a secure testing environment.
