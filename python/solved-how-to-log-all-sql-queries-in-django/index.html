How can one successfully log every SQL query executed by a Django application, including those generated from the Django admin interface? If you’re seeking to capture all SQL statements into a logging file (e.g., all-sql.log), you’re likely familiar with the connection.queries attribute found in Django. However, many developers feel challenged when it comes to where and how this should be implemented in their settings.

In this guide, we’ll explore various approaches to achieve comprehensive SQL logging in Django. Below are a few methods that can be employed:

Method 1: Configure Logging in settings.py

To start logging SQL queries in your Django application, you should modify the settings.py file. Insert the following configuration within your settings:

if DEBUG:
    import logging
    logger = logging.getLogger('django.db.backends')
    logger.setLevel(logging.DEBUG)
    logger.addHandler(logging.StreamHandler())

LOGGING = {
    'version': 1,
    'disable_existing_loggers': False,
    'filters': {
        'require_debug_false': {
            '()': 'django.utils.log.RequireDebugFalse'
        }
    },
    'handlers': {
        'mail_admins': {
            'level': 'ERROR',
            'filters': ['require_debug_false'],
            'class': 'django.utils.log.AdminEmailHandler'
        },
        'console': {
            'level': 'DEBUG',
            'class': 'logging.StreamHandler',
        },
    },
    'loggers': {
        'django.request': {
            'handlers': ['mail_admins'],
            'level': 'ERROR',
            'propagate': True,
        },
        'django.db.backends': {
            'level': 'DEBUG',
            'handlers': ['console'],
        },
    }
}

For further details, refer to Django’s official logging documentation .

Method 2: SQL Logging in Tests

If you want to log SQL queries during unit testing, ensure that you enable the django.db.backends logger and apply the @override_settings(DEBUG=True) decorator. Here’s how you can set up your test case:

from django.contrib.auth.models import User
from django.test import TestCase, override_settings

class UserTests(TestCase):

    @override_settings(DEBUG=True)
    def test_create_user(self):
        User.objects.create(username='testuser', password='testpassword')

This setup will ensure that SQL queries run during your tests are visible in the logs. You can find more about testing configurations in the Django testing documentation .

Method 3: Utilize the Django Debug Toolbar

If you’re looking for a visual representation of SQL queries generated by your application, consider using the Django Debug Toolbar . This tool displays all SQL queries executed during a request and even provides stack traces for deeper analysis.

Method 4: Middleware for Global Query Logging

An alternative approach is to implement a middleware that records every SQL query for every request. A simple middleware example might look like this:

import logging

class QueryLoggingMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response
        self.logger = logging.getLogger('query_logger')

    def __call__(self, request):
        response = self.get_response(request)
        # Here, log the queries after the view
        for query in connection.queries:
            self.logger.debug(query)
        return response

You would then need to add this middleware in your MIDDLEWARE setting.

Method 5: Manual Query Logging Using QueryLogger

You can create a custom logger class that captures all executed queries and their execution times. Here’s a quick implementation:

import time
from django.db import connection

class QueryLogger:
    def __init__(self):
        self.queries = []

    def __call__(self, execute, sql, params, many, context):
        current_query = {"sql": sql, "params": params, "many": many}
        start = time.monotonic()
        try:
            result = execute(sql, params, many, context)
            current_query["status"] = "ok"
        except Exception as e:
            current_query["status"] = "error"
            current_query["exception"] = str(e)
            raise
        finally:
            duration = time.monotonic() - start
            current_query["duration"] = duration
            self.queries.append(current_query)
        return result

For practical usage, you might execute wrapper calls within Django Shell to analyze SQL queries as needed.

Method 6: Enable SQL Query Logging Based on Settings

If you desire a toggle for logging SQL queries based on a specific setting, you can modify your settings.py file accordingly:

if LOG_DB_QUERIES:
    LOGGING['handlers']['console'] = {
        'level': 'DEBUG', 
        'class': 'logging.StreamHandler'
    }
    LOGGING['loggers']['django.db.backends'] = {
        'level': 'DEBUG', 
        'handlers': ['console']
    }

Method 7: Log SQL Queries in Django Admin

If you require SQL logging specifically within Django Admin, consider overriding the save_model method in your admin class:

from django.contrib import admin
from .models import Person
from django.db import connection

@admin.register(Person)
class PersonAdmin(admin.ModelAdmin):
    def save_model(self, request, obj, form, change):
        obj.save()
        for query in connection.queries:
            print(query)

This setup will print all SQL queries executed during the save operation of the Person model.

FAQs on Solved How to Log All SQL Queries in Django

Q: How do I log SQL queries during tests?

A: You can log SQL queries in tests by enabling the django.db.backends logger and using the @override_settings(DEBUG=True) decorator.

Q: Can I log SQL queries in Django Admin?

A: Yes, you can override the save_model method in your admin class to print logged SQL queries.

Q: What is Django Debug Toolbar and how can it help me?

A: The Django Debug Toolbar is a tool that provides a visual interface for inspecting SQL queries generated by your application on a per-request basis.

Q: How can I log SQL queries to a file?

A: You can achieve this by configuring a file handler in the LOGGING settings in settings.py.
