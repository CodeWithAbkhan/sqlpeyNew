“Python: Assignment vs. Shallow vs. Deep Copy Explained”

When working with Python, especially with mutable data structures like lists or dictionaries, it’s crucial to grasp the distinctions between simple assignment, shallow copies, and deep copies. These methods of handling objects in memory have significant implications for how your data behaves when modified. Let’s delve into each, supported by practical examples.

Understanding Object References

Before diving into the copying mechanisms, it’s important to recall how Python handles objects. When you create a variable, you’re essentially creating a reference (a name) that points to an object in memory. Assignment operations simply create a new reference that points to the same object.

Assignment (Reference Copy)

Assignment is the most straightforward way to handle objects. When you assign one variable to another using the = operator, you’re not creating a new object. Instead, you’re creating a new name that points to the exact same object in memory.

Consider this:

# Original list
original_list = [1, 2, [3, 4]]

# Assignment
assigned_list = original_list

print(f"Original list: {original_list}")
print(f"Assigned list: {assigned_list}")

# Both refer to the same object in memory
print(f"IDs are the same: {id(original_list) == id(assigned_list)}") # True
print(f"Inner list IDs are the same: {id(original_list[2]) == id(assigned_list[2])}") # True

# Modifying the assigned list affects the original list
assigned_list.append(5)
assigned_list[2].append(5)

print(f"Original list after modification: {original_list}")
print(f"Assigned list after modification: {assigned_list}")

As you can see, changing assigned_list also changes original_list because they both point to the same underlying list object. This is because assigned_list is merely another label for the identical memory location.

Shallow Copy

A shallow copy creates a new compound object and then populates it with references to the objects found in the original. This means the top-level structure is new, but any nested objects (like sub-lists or dictionaries) are still shared references to the original.

The copy module in Python provides the copy.copy() function for shallow copying.

import copy

# Original list with nested structure
original_list = [1, 2, [3, 4]]

# Shallow copy
shallow_copied_list = copy.copy(original_list)

print(f"Original list: {original_list}")
print(f"Shallow copied list: {shallow_copied_list}")

# The top-level lists have different IDs, but inner lists share IDs
print(f"Original list ID: {id(original_list)}")
print(f"Shallow copied list ID: {id(shallow_copied_list)}")
print(f"Outer IDs are different: {id(original_list) != id(shallow_copied_list)}") # True

print(f"Original inner list ID: {id(original_list[2])}")
print(f"Shallow copied inner list ID: {id(shallow_copied_list[2])}")
print(f"Inner list IDs are the same: {id(original_list[2]) == id(shallow_copied_list[2])}") # True

# Modifying a top-level element in the shallow copy does NOT affect the original
shallow_copied_list.append(5)
print(f"Original list after appending to shallow copy: {original_list}")
print(f"Shallow copied list after appending: {shallow_copied_list}")

# Modifying a nested element in the shallow copy DOES affect the original
shallow_copied_list[2].append(5)
print(f"Original list after modifying inner list of shallow copy: {original_list}")
print(f"Shallow copied list after modifying inner list: {shallow_copied_list}")

Notice how appending 5 to shallow_copied_list doesn’t alter original_list. However, when we modify the inner list (shallow_copied_list[2].append(5)), both lists reflect this change. This is because the inner list itself is still a shared reference.

Deep Copy

A deep copy creates a completely new object and then, recursively, inserts copies of the objects found in the original into the new object. This means both the top-level structure and all nested structures are independent copies.

The copy module’s copy.deepcopy() function performs this operation.

import copy

# Original list with nested structure
original_list = [1, 2, [3, 4]]

# Deep copy
deep_copied_list = copy.deepcopy(original_list)

print(f"Original list: {original_list}")
print(f"Deep copied list: {deep_copied_list}")

# All objects, including nested ones, have different IDs
print(f"Original list ID: {id(original_list)}")
print(f"Deep copied list ID: {id(deep_copied_list)}")
print(f"Outer IDs are different: {id(original_list) != id(deep_copied_list)}") # True

print(f"Original inner list ID: {id(original_list[2])}")
print(f"Deep copied inner list ID: {id(deep_copied_list[2])}")
print(f"Inner list IDs are different: {id(original_list[2]) != id(deep_copied_list[2])}") # True

# Modifying the deep copy does NOT affect the original, even for nested elements
deep_copied_list.append(5)
deep_copied_list[2].append(5)

print(f"Original list after modification: {original_list}")
print(f"Deep copied list after modification: {deep_copied_list}")

With a deep copy, changes made to deep_copied_list, including modifications to its nested elements, have no impact on original_list. Each is a completely independent entity.

Immutable vs. Mutable Objects

The concept of copying is most relevant for mutable objects (like lists, dictionaries, sets) which can be altered after creation. For immutable objects (like integers, strings, tuples), copying is often unnecessary. Python typically reuses the same object in memory for immutable types because their values cannot change. When you perform an “assignment” on an immutable object, you’re just creating another reference to that existing, unchangeable value.

For instance:

# Immutable objects
num1 = 10
num2 = num1
str1 = "hello"
str2 = str1

print(f"ID of num1: {id(num1)}, ID of num2: {id(num2)}") # IDs will be the same
print(f"ID of str1: {id(str1)}, ID of str2: {id(str2)}") # IDs will be the same

# If you try to "change" them, you get new objects
num1 = num1 + 5
str1 = str1 + " world"

print(f"New ID of num1: {id(num1)}, ID of num2: {id(num2)}") # IDs will likely differ
print(f"New ID of str1: {id(str1)}, ID of str2: {id(str2)}") # IDs will likely differ

Alternatives for Shallow Copying Lists

Besides copy.copy(), you can also achieve a shallow copy of a list using slicing:

original_list = [1, 2, [3, 4]]
sliced_list = original_list[:] # This creates a shallow copy

print(f"Original list: {original_list}")
print(f"Sliced list: {sliced_list}")

# Similar behavior to copy.copy() regarding nested elements
sliced_list[2].append(5)
print(f"Original list after modifying inner list of sliced copy: {original_list}")
print(f"Sliced list after modifying inner list: {sliced_list}")

FAQs on Python Copying Behavior

Q: What is the primary difference between assignment and copying in Python

ANS: Assignment creates a new reference to an existing object, meaning both variables point to the same memory location. Copying (shallow or deep) creates a new object, either sharing references to nested objects (shallow) or duplicating them recursively (deep).

Q: When should I use shallow copy versus deep copy

ANS: Use a shallow copy when your object contains only immutable types or when you want nested objects to remain shared between the original and the copy. Use a deep copy when you need complete independence between the original object and its copy, ensuring that changes to nested mutable objects in the copy do not affect the original.

Q: Does Python copy immutable objects like strings and numbers

ANS: For immutable objects, Python typically doesn’t create new copies when you perform assignment or operations that seem like copying. Instead, it reuses the existing object in memory because its value cannot change. You’re just creating new references to the same immutable value.

Q: Can assignment create a new list object

ANS: No, assignment using the = operator does not create a new list object. It only creates a new name that points to the existing list object in memory.

Q: How does list slicing relate to copying

ANS: List slicing, like my_list[:], creates a shallow copy of the list. It generates a new list object, but the elements within that new list are references to the same objects as in the original list.

Q: What happens if I modify a nested list within a shallow copy

ANS: If you modify a nested mutable object (like a sub-list) within a shallow copy, the changes will be reflected in both the original object and the shallow copy. This is because the shallow copy only duplicated the outer structure, not the nested objects themselves.

Q: What happens if I modify a nested list within a deep copy

ANS: If you modify a nested mutable object within a deep copy, the changes will only affect the deep copy. This is because a deep copy recursively duplicates all nested objects, creating fully independent copies.
