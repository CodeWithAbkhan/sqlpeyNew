“Specifying Python Package Installation Directory with Pip”

When deploying Python applications or managing isolated environments, the default installation location (site-packages) dictated by pip often isn’t suitable. How can developers precisely control the destination directory for installed Python packages and their associated files? Several options exist, each offering distinct control over the final placement.

Utilizing the --target Switch for Absolute Control

The -t or --target switch provides a straightforward way to specify a directory where packages should be installed.

Key Behavior of --target:

  • It directs all installation artifacts (packages and dependencies) directly into the specified directory.
  • By default, it won’t overwrite pre-existing files or folders in the target location. Using --upgrade modifies existing packages within that directory.
  • Crucially, after using --target, you must ensure that this custom directory is included in your Python runtime’s PYTHONPATH environment variable for Python to locate and import the modules.

Practical Example:

To install a hypothetical package named data_fetcher into a custom path outside the standard system locations:

pip install --target /opt/custom_python_libs/ data_fetcher

Alternatively, if you are in the desired location:

pip install mylibraryName -t .

If you combine --user with --target, you will encounter an error. To proceed with --target while overriding the user settings, employ --no-user:

pip install pandas -t C:\Users\user\Desktop\Family\test --no-user

Employing --prefix for Structured Installation Layouts

The --prefix option mimics traditional installation layouts by placing files relative to a specified base path, usually resulting in subdirectories like lib/pythonX.Y/site-packages.

Behavior of --prefix:

  • It checks if dependencies are already installed elsewhere.
  • For Python 3.5+ and recent pip versions, you can specify the prefix directly:
PREFIX_PATH=/app/new_install
pip install --prefix=${PREFIX_PATH} package_name
  • Older versions or specific scenarios might require using --install-option with --prefix if --prefix alone isn’t recognized by newer pip versions supporting it natively (as seen in Solution 11):
pip install --install-option="--prefix=$PREFIX_PATH" package_name

Leveraging PYTHONUSERBASE for User-Specific Customization

Setting the PYTHONUSERBASE environment variable before invoking pip install --user allows you to redefine the base directory for user-specific installations, usually $HOME/.local.

How PYTHONUSERBASE Alters --user Installation:

This method directs the standard --user installation structure (creating bin, lib, share directories) into the path defined by the environment variable, bypassing the default user home location.

Example Scenario (using Bash):

If you wish to install dependencies for a specific project version under /opt/mysterypackage-1.0/python-deps:

export PYTHONUSERBASE=/opt/mysterypackage-1.0/python-deps
pip install --user --upgrade numpy scipy

To make these packages available for import and execution:

# Adjusting paths based on system (e.g., lib64 for CentOS 6 Python 2.6)
export PYTHONPATH=/opt/mysterypackage-1.0/python-deps/lib64/python2.6/site-packages:$PYTHONPATH
export PATH=/opt/mysterypackage-1.0/python-deps/bin:$PATH

Fine-Grained Control with --install-option

The --install-option flag passes arguments directly to the underlying setup.py install script. This offers granular control, such as specifying the exact location for pure Python files (--install-purelib).

Installing Pure Python Files Only:

If a package contains only Python source files and you want them in a specific spot:

pip install --install-option="--install-purelib=/python/packages" package_name

You can persist this setting by editing your ~/.pip/pip.conf file under the [install] section:

[install]
install-option=--install-purelib=/python/packages

Distinguishing Installation Options

Different flags yield different results regarding dependency handling and path inclusion:

| Option | Primary Effect | Dependency Handling | Path Management Required | | :

Solutions

pip install --target d:\somewhere\other\than\the\default package_name
pip install -U pip

| :

Considerations for Specific Environments

Homebrew Installations on macOS

If using Python installed via Homebrew, standard options like --target or --user might be disabled due to Homebrew’s configuration managing distutils.cfg. A workaround involves using the -m flag with pip and explicitly setting --install-option:

python -m pip install --user --install-option="--prefix=" <package-name>

Alternative: Using Virtual Environments

It is widely recommended that for most isolation and dependency management needs, using Python’s built-in virtual environments remains the cleanest and most predictable solution, circumventing the need for complex path manipulation or non-standard installations. Check out resources on venv for robust isolation.

Updating Pip

If older versions of pip lack certain switches (like --target availability in very old versions), an upgrade is advisable.

On Linux/OSX:

pip install -U pip

On Windows (to avoid potential issues):

python -m pip install -U pip

Interplay with --python

Recent versions of pip (21.3+) introduce the --python flag, which directs installation to the site-packages directory associated with a specific Python interpreter executable, rather than a generic custom location (--target). Both can be combined:

# Installing Pillow into C:\env\env1 using the interpreter located at C:\programs\python
pip --python c:\programs\python\python.exe install pillow --target C:\env\env1

pip install mylibraryName -t .

FAQs on Specifying Python Package Installation Directory with Pip

Q: What is the primary command to install a package to a specific directory

ANS: The primary command utilizes the target switch: pip install --target /path/to/dir package_name.

Q: Do I need to modify PYTHONPATH when using --target

ANS: Yes, you absolutely must add the target directory to your PYTHONPATH environment variable so the Python interpreter can locate the installed modules at runtime.

Q: Can I use --user and --target in the same pip command

ANS: No, combining --user and --target results in an error. You should use --no-user if you intend to use --target.

Q: How does --prefix differ from --target

ANS: --target installs everything directly into the specified folder, requiring manual path setup. --prefix installs into a standard library hierarchy beneath the specified prefix path (e.g., into /prefix/lib/pythonX.Y/site-packages).

Q: What configuration file can set default installation options

ANS: You can configure persistent options, such as --install-purelib, by editing the [install] section in your ~/.pip/pip.conf file.
