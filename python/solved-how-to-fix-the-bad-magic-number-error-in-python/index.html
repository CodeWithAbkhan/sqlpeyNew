What is the “Bad Magic Number” Error in Python and How Can You Resolve It?

The “Bad magic number” error in Python manifests when there’s an issue with the compatibility of the .pyc files that Python uses for optimized bytecode. This usually occurs after compiling .py files into .pyc files, particularly when these files are executed with the wrong version of Python.

Common Causes of the Error

Typically, this issue arises due to:

  • Misalignment between Python versions (e.g., using a .pyc file generated by Python 3 with Python 2).
  • Corrupted or outdated .pyc files.
  • Missing __init__.py files in packages.

Steps to Fix the Bad Magic Number Error

Here are proven methods to troubleshoot and resolve this perplexing error:

1. Remove All .pyc Files

The simplest and often most effective solution is to delete all .pyc files. You can do this using the following command:

find . -name "*.pyc" -delete

This command searches for .pyc files starting from your current directory and removes them.

2. Verify Python Version Compatibility

Ensure that you are not mixing .pyc files generated by different Python versions. Loading a file compiled in Python 3 with Python 2 will lead to this error.

3. Inspect Bytecode with a Hex Editor

For deeper investigation, you can check the first two bytes of the .pyc file to verify the magic number. Use a Hex editor like HexEdit :

  1. Open the .pyc file.
  2. Note the first two bytes.
  3. Convert these hex values to their decimal representation using a calculator.

The magic number corresponds to a specific Python version. For example:

  • Python 3.5: 03 f3 (Decimal: 2031)
  • Python 3.6: 03 f4 (Decimal: 2032)

4. Create Missing __init__.py Files

If you’ve created new directories for your Python modules, ensure you include an __init__.py file within those directories. Not adding this file can lead to import errors such as:

ImportError: bad magic number in 'APPNAME.tests': b'\x03\xf3\r\n'

5. Regenerate Translation Files

If the error stems from outdated .mo files after renaming modules, work through these commands:

find . -name "*.po" -execdir sh -c 'msgfmt "$0" -o `basename $0 .po`.mo' '{}' \;

Before running this, make sure to back up your files.

6. Check for Incorrectly Named .pyc Files

If you manually renamed a file with a .pyc extension, ensure it has not affected how Python attempts to load that file.

7. Rename Problematic Module Files

In rare cases, the error may stem from naming collisions. For instance, if you experience the “Bad magic number” error tied to a specific module name (like sms.py), renaming the module can resolve the issue.

8. Efficiently Delete pyc Files

For a more efficient cleanup, especially if you have many .pyc files in different directories, run:

find {directory-of-.pyc-files} -name "*.pyc" -print0 | xargs -0 rm -rf

Replace {directory-of-.pyc-files} with the path where your .pyc files are located.

9. Confirm the Correct Python DLL Files (Windows)

On Windows platforms, ensure you have the correct python27.dll file installed. If not, reinstall the version of Python to rectify this.

10. Remove Problematic Compiled Files

If you get a bad magic number error affecting critical tools (like dnf on Fedora), delete specific .pyc files, such as:

sudo rm /usr/bin/six.pyc

11. Clean Up the Entire Environment

Run the deletion command in all relevant paths in your Python environment. For instance:

find /usr/lib/python3.6/ -name "*.pyc" -delete
find /usr/local/lib/python3.6/dist-packages -name "*.pyc" -delete

12. Check the Python Interpreter Path

If you’ve cloned a library that defaults to a specific Python interpreter, make sure that it correctly points to the intended version. Mismatched environments (like Python 2 and Python 3) often lead to these errors.

#!/usr/bin/env python

Make sure the shebang matches the version you intend to use.

13. Resolve Errors from Specific Third-Party Libraries

Sometimes, installing packages such as mysql-connector generates the error. To fix it:

pip uninstall mysql-connector
pip uninstall mysql-connector-python
pip install mysql-connector-python

14. Back Off Before Deleting .pyc Files

If you are uncertain, first locate a backup of working .pyc files before executing bulk deletions.

### FAQs on Fixing Bad Magic Number Error in Python

Q: What does the bad magic number error mean?

A: This error indicates that Python is trying to load a compiled bytecode file (.pyc) that was generated with a different Python version than the one currently executing the script.

Q: How can I tell which version of Python a .pyc file was compiled from?

A: You can open the .pyc file in a Hex editor to check the first two bytes, which represent the magic number for the Python version used to compile it.

Q: What should I do if I keep experiencing this error?

A: If you repeatedly face this issue, ensure all your environment paths are cleared of incompatible .pyc files and consider verifying the compatibility of the files with your Python interpreter.
