Top 10 Methods to View Raw SQL Queries Executed by Django

Is there a way to view the raw SQL queries that Django executes during various ORM operations? If you find yourself needing to inspect the exact SQL queries for debugging, performance optimization, or learning purposes, there are several effective methods available. This article outlines a comprehensive list of techniques to achieve this.

Method 1: Using Django Extensions

One of the simplest ways to see the raw SQL queries is to utilize the Django Extensions package. You can enable SQL printing in the Django shell with the following command:

./manage.py shell_plus --print-sql

Once in the shell, all executed queries will be displayed. For example, when fetching a user by primary key:

User.objects.get(pk=1)

The output will show the executed SQL along with its execution time:

SELECT "auth_user"."id", "auth_user"."username"
FROM "auth_user"
WHERE "auth_user"."id" = 1;
Execution time: 0.002466s

Method 2: Utilizing Debug Toolbar

The Django Debug Toolbar is an invaluable tool for debugging and inspecting SQL queries. To get started, install it using pip:

pip install django-debug-toolbar

Once set up in your Django project, the toolbar automatically shows SQL queries for each request. For more information, refer to the official documentation .

Method 3: Accessing Query in Models API

If you’re looking for a programmatic way to access raw SQL, you can retrieve the underlying SQL from a QuerySet in the following manner:

q = User.objects.values('id', 'username')
print(q.query)

This outputs the SQL representation of the QuerySet.

Method 4: Checking Database Logs

Accessing your database’s logs provides a complete view of the raw SQL being executed. If you’re using PostgreSQL on Linux, you can monitor the logs like so:

sudo su postgres
tail -f /var/log/postgresql/postgresql-12-main.log

Each database has its own logging procedure, but this method ensures you know not just the SQL but also the context of connections and transactions.

Method 5: Logging SQL Queries

To log SQL queries directly, you can configure Django’s logging in settings.py. This allows you to capture queries in the console output:

LOGGING = {
    'version': 1,
    'disable_existing_loggers': False,
    'handlers': {
        'console': {
            'class': 'logging.StreamHandler',
        },
    },
    'loggers': {
        'django.db.backends': {
            'handlers': ['console'],
            'level': 'DEBUG',
        },
    },
}

When the level is set to DEBUG, all executed SQL statements will be printed to the console whenever you interact with the ORM.

Method 6: Code Snippet for Viewing SQL in Context

You can also create a reusable function to print SQL when needed. For example:

from django.db import connection

def log_sql_queries(view_func):
    def wrapper(*args, **kwargs):
        reset_queries()
        result = view_func(*args, **kwargs)
        for query in connection.queries:
            print(query)
        return result
    return wrapper

@log_sql_queries
def my_view(request):
    # Your view logic here
    pass

Method 7: Catching Executed SQL Statements

Another effective approach to view executed SQL statements involves a context manager. Use the following implementation:

from django.db import reset_queries, connection

class ShowSQL:
    def __enter__(self):
        reset_queries()
        return self

    def __exit__(self, *args):
        for sql in connection.queries:
            print(f'Time: {sql["time"]}\nSQL: {sql["sql"]}')

## Usage
with ShowSQL():
    User.objects.all()

Method 8: Using Django SQL Sniffer

Django SQL Sniffer is a tool specifically created for monitoring SQL queries without altering your source code. You can find it on GitHub .

Just attach it to your running process to see executed queries printed in the console. This tool offers on-demand SQL logging without needing to restart your Django application.

Method 9: Generating SQL for CRUD Operations

You can generate SQL for create, update, and delete operations in Django easily. Here’s an example on how to construct the SQL for an update:

def generate_update_sql(queryset, update_kwargs):
    query = queryset.query.clone(QuerySet)
    query.add_update_values(update_kwargs)
    compiler = query.get_compiler(queryset.db)
    sql, params = compiler.as_sql()
    return sql % params

Method 10: Fetching SQL Using Connection Queries

Lastly, you can directly fetch SQL queries from connection.queries. This is particularly useful after executing a series of operations in a view:

from django.db import connection
from .models import User

def test_sql_view(request):
    User.objects.create(name="John")
    User.objects.filter(name="John").update(name="Tom")

    for query in connection.queries:
        print(query)
    return HttpResponse("Queries logged.")

Each query executed in this view will be printed to the console.

FAQs on Top 10 Methods to View Raw SQL Queries Executed by Django

Q: How can I view raw SQL queries in Django?

A: You can view raw SQL queries in Django using Django Extensions, Debug Toolbar, accessing query models directly, examining database logs, or implementing logging in your settings.py.

Q: Is using Debug Toolbar suitable for production environments?

A: No, Debug Toolbar is primarily intended for development use due to potential performance issues. It’s advisable to use logging or database query monitoring in production.

Q: Can I filter the SQL queries I track?

A: Yes, you can implement custom logging or monitoring solutions to filter specific types of queries or queries coming from certain views or models.

Q: How do I ensure Django logs SQL in production?

A: You can set up logging in your Django settings to log queries, ensuring the logging level is set appropriately for your environment (e.g., DEBUG or INFO).
