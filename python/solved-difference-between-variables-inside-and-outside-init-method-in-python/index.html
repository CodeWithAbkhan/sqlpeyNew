In the realm of Python programming, understanding the difference between class variables and instance variables is crucial, especially with respect to how and where these variables are defined. This post will explore the nuances of these variables, particularly focusing on the implications of declaring variables inside and outside of the __init__ method. Here, we investigate various scenarios and examples to illustrate these concepts.

The Core Question

Is there any distinction in behavior when using class or instance variables based on their placement in the class definition? Consider the following two classes:

class WithClass:
    def __init__(self):
        self.value = "Bob"
    
    def my_func(self):
        print(self.value)

class WithoutClass:
    value = "Bob"
    
    def my_func(self):
        print(self.value)

Here, we have WithClass, which initializes value as an instance variable, and WithoutClass, which declares value as a class variable. What differences arise from these definitions, especially when creating instances of these classes?

Implications of Placement

Solution 1: Understanding Scope with Examples

Let’s create two instances to demonstrate how assignments affect variable scope.

Without Using self: Here we define a class variable.

class Foo:
    x = 'original class'

c1, c2 = Foo(), Foo()
c1.x = 'changed instance'
print(c2.x)  # Output: 'original class'

Changing c1.x does not affect c2.x since x in c1 now points to a new instance variable.

However, altering the class variable impacts all instances:

Foo.x = 'changed class'
print(c2.x)  # Output: 'changed class'

Using self: When we declare x inside the __init__ method:

class Foo:
    def __init__(self):
        self.x = 'original self'

c1 = Foo()
Foo.x = 'changed class'
print(c1.x)  # Output: 'original self'

This demonstrates that changing a class variable does not affect instance variables created with self.

Key Differences to Note

  1. Class Variables (defined outside __init__):

    • Shared across all instances.
    • Can be accessed using ClassName.variable_name.

  2. Instance Variables (defined inside __init__ and prefixed with self):

    • Unique to each instance.
    • Accessed through the instance reference.

Practical Examples

To solidify our understanding, here’s a practical example involving class and instance variables:

class User:
    email = 'none'
    firstname = 'none'
    lastname = 'none'

    def __init__(self, email=None, firstname=None, lastname=None):
        self.email = email
        self.firstname = firstname
        self.lastname = lastname

    @classmethod
    def print_var(cls, obj):
        print("obj.email, obj.firstname, obj.lastname")
        print(obj.email, obj.firstname, obj.lastname)
        print("cls.email, cls.firstname, cls.lastname")
        print(cls.email, cls.firstname, cls.lastname)

u1 = User(email='abc@xyz', firstname='first', lastname='last')
User.print_var(u1)

Alternative Ways to Manage Variables

  1. Using Class Methods: Class methods can facilitate changes to class variables shared across instances.
class Employee:
    company = "mycompany.com"

    @classmethod
    def change_company(cls, new_name):
        cls.company = new_name
  1. Utilizing property Decorators: Python properties can enable controlled access to instance variables while providing a syntax that appears as simple attribute access.

FAQs on Difference Between Variables Inside and Outside of __init__

Q: What are class variables?

A: Class variables are variables that are shared among all instances of a class and are defined outside any methods.

Q: What are instance variables?

A: Instance variables are unique to each instance of a class and are typically defined within the __init__ method using self.

Q: Can class variables be modified?

A: Yes, class variables can be modified, and changes will be reflected across all instances unless overridden by an instance variable with the same name.

Q: How can I avoid conflicts between class and instance variables?

A: To avoid conflicts, always refer to class variables using the class name itself instead of self when possible.
