“Python: Elegant Single-Pass Methods for Partitioning Lists Based on Condition”

When working with sequences in Python, the frequent requirement arises to divide elements into two distinct groups based on whether they satisfy a specific boolean condition. While simple list comprehensions offer readability, they typically result in two passes over the source data. The core technical query here centers on discovering methods that achieve this separation in a single pass, maintaining performance and clarity.

Given an initial list mylist and a set of values defining the “good” items, goodvals, how can we elegantly partition mylist into good and bad lists, ensuring the conditional check happens just once per item?

For a concrete example involving file types, suppose we have a list of file tuples: files = [ ('file1.jpg', 33L, '.jpg'), ('file2.avi', 999L, '.avi'), ('file3.gif', 123L, '.gif'), ('data.txt', 50L, '.txt') ] And a definition for image types: IMAGE_TYPES = ('.jpg','.jpeg','.gif','.bmp','.png')

We aim to separate files into images (where the extension is in IMAGE_TYPES) and anims (everything else).

Evaluation of Common Partitioning Strategies

Several approaches were presented, each carrying trade-offs in readability, performance, and how many times the predicate (the condition check) is evaluated.

1. Two Separate List Comprehensions (Two Passes)

This is immediately readable but scans the list twice:

# Two passes over mylist
good = [x for x in mylist if x in goodvals]
bad  = [x for x in mylist if x not in goodvals]

2. Manual Iteration (Single Pass, Clear Logic)

A traditional for loop ensures a single pass and is highly explicit about the logic.

good, bad = [], []
for item in mylist:
    if item in goodvals:
        good.append(item)
    else:
        bad.append(item)

This method is often favored for its guaranteed single pass and excellent readability, even when the condition logic becomes complex (e.g., adding checks like if f[1] == 0: continue inside the loop).

3. Using Tuple Indexing for Conditional Append (Single Pass, Concise)

This technique uses the boolean result of the condition as an index into a tuple containing the target lists.

good, bad = [], []
# (bad_list, good_list)[condition_is_true]
for x in mylist:
    (bad, good)[x in goodvals].append(x)

This is very compact and achieves a single pass. Performance benchmarks suggest this is very competitive.

4. Utilizing Sets for Faster Lookups

When checking membership (x in goodvals), converting goodvals (or good_list) to a set drastically improves lookup time from $O(N)$ to $O(1)$ on average, leading to significant speed increases, especially for large lists.

If goodvals is large, pre-calculating the set is key:

good_list_set = set(good_list)  # Essential speed optimization
good, bad = [], []
for item in my_origin_list:
    if item in good_list_set:
        good.append(item)
    else:
        bad.append(item)

A slightly more concise variant of the single-pass loop:

good_list_set = set(good_list)
good, bad = [], []
for item in my_origin_list:
    # Direct assignment to the correct list reference
    out = good if item in good_list_set else bad
    out.append(item)

5. Itertools: Lazy, Single-Pass Partitioning

For scenarios demanding lazy evaluation or handling infinite iterators, the itertools module offers sophisticated solutions.

Using itertools.tee and Filtering

This approach evaluates the condition once per item and yields two separate generators.

from itertools import tee

def split_on_condition(seq, condition):
    # Creates two independent iterators from the sequence
    l1, l2 = tee((condition(item), item) for item in seq)
    # Generator for True results
    true_gen = (i for p, i in l1 if p)
    # Generator for False results
    false_gen = (i for p, i in l2 if not p)
    return true_gen, false_gen

# Example usage with a lazy infinite sequence:
from itertools import count, islice
def is_prime(n):
    return n > 1 and all(n % i for i in range(2, int(n**0.5) + 1))

primes, not_primes = split_on_condition(count(), is_prime)
# Consuming the generators only pulls items from count() as needed
print("First 10 primes", list(islice(primes, 10)))

Using itertools.filter or filterfalse with tee

A variation that relies on standard filter tools:

from itertools import tee, filterfalse

def partition_lazy(pred, iterable):
    'Partitions entries into false entries and true entries (lazy generators)'
    t1, t2 = tee(iterable)
    # filterfalse yields items where pred is False; filter yields items where pred is True
    return filterfalse(pred, t1), filter(pred, t2)

6. Functional Programming Style with reduce

This method is extremely compact but sacrifices readability for conciseness, iterating only once.

from functools import reduce

# Example: Splitting numbers into even/odd based on x % 2 == 0 (index 0 for even, index 1 for odd)
arr = list(range(10))
# The key to correctness is `or res` because list.append returns None
even, odd = reduce(
    lambda res, next_item: res[next_item % 2].append(next_item) or res, 
    arr, 
    ([], []) # Initial state: (list_for_false, list_for_true)
)

7. Categorization into Multiple Bins using defaultdict

If the need expands beyond two partitions (e.g., categorizing files by extension type rather than just image/non-image), a dictionary-based approach is superior.

from collections import defaultdict

def splitter(data_list, mapper_func):
    """Splits an iterable into multiple partitions based on a mapper function's result."""
    results = defaultdict(list)
    for x in data_list:
        key = mapper_func(x)
        results[key].append(x)
    return results

# Example: Partitioning by parity (True for even, False for odd)
l = [1, 2, 3, 4, 5, 6]
split = splitter(l, lambda x: x % 2 == 0)
print(dict(split)) 
# Output: {False: [1, 3, 5], True: [2, 4, 6]}

Performance Insight: The Fastest Contenders

Benchmark analysis strongly indicates that single-pass methods involving efficient lookups (using set) are the fastest. The method that combines a single loop with set lookups (set_if_else in the provided tests) consistently outperforms list comprehensions that scan twice.

The structure that yielded the highest throughput in benchmarks for two partitions was:

# Optimized single-pass approach using sets
good_list_set = set(good_list)
good, bad = [], []
for item in my_origin_list:
    if item in good_list_set:
        good.append(item)
    else:
        bad.append(item)

FAQs on Python Single Pass List Partitioning

Q: Which method is generally best for splitting a list into two parts

ANS: The single-pass manual iteration loop, especially when combined with pre-calculating membership checks using a set for the criteria list, offers the optimal balance of performance and clear code structure.

Q: Can list comprehensions be used in a single pass

ANS: Standard list comprehensions require two passes. Techniques simulating a single pass with comprehensions often rely on side effects (like appending to an external list during comprehension evaluation), which is generally discouraged due to poor readability and potential confusion.

Q: Are lazy iterator solutions good for large files

ANS: Yes, solutions employing itertools.tee and generators (like Solution 5) are excellent for very large datasets or infinite streams, as they avoid loading the entire sequence into memory at once.

Q: How much faster are sets compared to lists/tuples for membership checks

ANS: Converting the membership list (goodvals) to a set can yield performance improvements of 40% or more over checking against a list or tuple during the partitioning loop.
good, bad = [], []
for x in mylist:
    (bad, good)[x in goodvals].append(x)

Your selection of method should depend on whether you prioritize absolute performance (use sets and a single loop), lazy evaluation (use itertools.tee), or absolute clarity (use a standard for loop).
