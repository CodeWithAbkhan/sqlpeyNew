“Python Arbitrary Base Conversion: Implementing Custom Number Systems Beyond Base 36”

When dealing with number systems in programming, standard built-in functions or simple formatting often limit conversion to common bases like 2 (binary), 8 (octal), 16 (hexadecimal), or up to base 36 (using 0-9 and a-z). What happens when requirements dictate conversion to a base larger than 36, such as base 577, or when specific custom character sets are needed for encoding?

This compilation gathers various expert-level Python solutions demonstrating how to implement general-purpose functions for converting a base-10 integer to any arbitrary base $B$ (where $B \ge 2$) and, in some cases, the reverse operation.

Implementing Base Conversion for Unrestricted Bases (B $\ge$ 2)

The core challenge is creating a mapping or algorithm that doesn’t rely on predefined alphabets limited to 36 or 62 characters. The following methods focus on returning the digits as a list of numerical values or a string constructed from a specific alphabet.

Solution 1: Pure Mathematical List Output (Arbitrary Base)

This initial approach avoids character representation and returns the digits in base $B$ as a list of integers. This is the simplest method for handling extremely large bases like 577.

def number_to_digits_list(n, b):
    """Converts a non-negative integer n to a list of digits in base b."""
    if n == 0:
        return [0]
    digits = []
    while n:
        digits.append(int(n % b))
        n //= b
    return digits[::-1]

# Example use with a very large base (B=577)
huge_number = 67854 ** 15 - 102
base_577_representation = number_to_digits_list(huge_number, 577)
print(f"Base 577 Digits for Huge Number: {base_577_representation}")
# Output provides the list of numeric digits: [4, 473, 131, ..., 455]

Why does this work for any base? This method relies solely on the modulo (%) and integer division (//) operations, which are mathematically sound for any positive integer base $B$.

Solution 2: Iterative String Conversion with Custom/Extended Alphabet

For string output where the base might exceed 36, a custom character set (digs) must be defined that contains at least $B$ unique characters. This iterative approach builds the string from right to left.

import string

# Define an alphabet large enough for bases > 36. For B=64, we need 64 chars.
ALPHABET_64 = string.digits + string.ascii_letters + string.punctuation[:10] # At least 64 unique symbols

def int_to_base_custom_string(x: int, base: int, alphabet: str = ALPHABET_64) -> str:
    """Converts integer x to a string representation in the given base using a provided alphabet."""
    if base < 2 or base > len(alphabet):
        raise ValueError(f"Base {base} is out of range for the defined alphabet size ({len(alphabet)})")
    
    if x == 0:
        return alphabet[0]

    sign = ""
    if x < 0:
        sign = "-"
        x = -x
    
    digits = []
    while x:
        # Use x % base to get the index into the alphabet string
        digits.append(alphabet[x % base])
        x //= base # Use floor division for correct integer division in Python 3

    return sign + ''.join(reversed(digits))

# Example: Using base 40
BASE_40_CHARS = string.digits + string.ascii_lowercase + '!'*6
print(f"Base 40 Conversion of 10000: {int_to_base_custom_string(10000, 40, BASE_40_CHARS)}")

Solution 3: Recursive Approach (Similar to Solution 2, but Recursive)

A recursive implementation can also achieve this, provided the alphabet is sufficiently long.

ALPHABET_36 = "0123456789abcdefghijklmnopqrstuvwxyz"

def recursive_int_to_base(number: int, base: int, numerals: str = ALPHABET_36) -> str:
    """Recursive base conversion supporting up to base=len(numerals)."""
    if number < 0:
        return "-" + recursive_int_to_base(-number, base, numerals)
    
    if number < base:
        return numerals[number]
    
    # Recurse: build the left part first, then append the current remainder's character
    return recursive_int_to_base(number // base, base, numerals) + numerals[number % base]

# Note: This can hit Python's recursion limit for extremely large numbers.
print(f"Recursive Base 16 (Hex): {recursive_int_to_base(255, 16)}")

Solution 4: Library Approach - basencode for Advanced Features

For scenarios requiring complex operations, handling floating-point numbers, or custom digit management with high bases, external libraries offer robust solutions. The basencode library handles bases up to 64 natively and allows digit overrides.

# Requires: pip install basencode
from basencode import Number, Integer, Float

# Example: Base 577 using custom digits provided as a list of strings
large_base = 577
custom_digits_577 = [str(i) for i in range(large_base)]
n2 = Number(67854 ** 15 - 102)

# The 'l' mode requests a list output, matching Solution 1's format
representation_list = n2.repr_in_base(large_base, digits=custom_digits_577, mode="l")
print(f"Basencode Base {large_base} (List): {representation_list[:5]}...")

# Example: Base 64 encoding with custom symbols
n1 = Number(12345)
# Override default digits for base 2 using '-' for 0 and '+' for 1
binary_custom = n1.repr_in_base(2, digits=list('-+')) 
print(f"Base 2 with custom digits ('-','+'): {binary_custom}")

Built-in Functions (Limited Bases)

Python provides quick methods for specific, low bases, though they are not suitable for arbitrary bases > 36.

decimal_value = 100

# Base 2 (Binary)
binary_str = f"{decimal_value:b}" # Or use format(decimal_value, 'b')
print(f"Base 2 (100): {binary_str}")

# Base 16 (Hexadecimal)
hex_str = f"{decimal_value:x}"
print(f"Base 16 (100): {hex_str}")

# Base 8 (Octal)
octal_str = f"{decimal_value:o}"
print(f"Base 8 (100): {octal_str}")

# NumPy Alternative (Base up to 36)
try:
    import numpy as np
    numpy_base_36 = np.base_repr(decimal_value, base=36)
    print(f"NumPy Base 36 (100): {numpy_base_36}")
except ImportError:
    pass

Handling Conversion Between Two Arbitrary Bases

If you need to convert from base $A$ to base $B$ where neither $A$ nor $B$ is 10, the standard procedure is to convert the input from base $A$ to base 10 first, and then convert the base 10 result to base $B$.

Note: Solutions requiring base $A$ input (e.g., radix_to_dec in Solution 30) must assume the input number format respects the characters available in base $A$.

# Using components from Solution 30
def radix_to_decimal(input_str: str, from_radix: int) -> int:
    """Converts a number represented as a string in from_radix to base 10 integer."""
    # Basic implementation assumes input_str contains only digits 0-9
    if from_radix > 10:
        # For bases > 10, this simple approach fails if input uses letters (e.g., '1F' in base 16)
        raise NotImplementedError("Simple string digit parsing only supports base <= 10 here.")
        
    return sum(int(digit) * (from_radix ** power) for power, digit in enumerate(str(input_str)[::-1]))

def decimal_to_radix(input_dec: int, to_radix: int) -> str:
    """Converts a base 10 integer to a string representation in to_radix."""
    if input_dec == 0:
        return "0"
    
    digits = "0123456789abcdefghijklmnopqrstuvwxyz" # Up to base 36
    if to_radix > len(digits):
        raise ValueError("Target base too large for this alphabet.")

    result = ''
    while input_dec > 0:
        remainder = input_dec % to_radix
        result = digits[remainder] + result
        input_dec //= to_radix
    return result

def convert_a_to_b(number_str: str, from_base: int, to_base: int) -> str:
    """Converts number represented as string from_base to string in to_base."""
    if from_base == 10:
        decimal_val = int(number_str)
    else:
        # Complex base A to 10 conversion would require knowing the alphabet of base A
        decimal_val = radix_to_decimal(number_str, from_base) # Simplified base 10 check
        
    return decimal_to_radix(decimal_val, to_base)

# Example: 1A (Base 16) -> Base 8
# 1A_16 = 26_10. 26_10 = 32_8
# Note: This requires a full alphabet-aware conversion routine for non-decimal inputs.
# If we manually say 26 (base 10) needs to go to base 8:
print(f"26 (Base 10) to Base 8: {decimal_to_radix(26, 8)}") # Output: 32

Addressing Performance and Recursion Limits

For truly massive integers (e.g., those with thousands of digits), iterative solutions (like Solutions 1, 2, 9, 15, 16, 22, 26, 27) are generally preferred over recursive ones (Solutions 3, 4, 28, 29, 30) to prevent hitting the RecursionError: maximum recursion depth exceeded. Solutions employing divmod iteratively are often performant as they combine the modulo and division steps into a single operation.

Which technique offers the best route for production deployment depends heavily on the base required:

  • List of Digits (Solution 1): Best for extremely high bases where character mapping is impractical or irrelevant.
  • Iterative String Building (Solutions 2, 16): Excellent balance of speed and flexibility, requiring only a sufficiently long alphabet string for the target base.

FAQs on Python Arbitrary Base Conversion Custom Digits

Q: How to convert an integer to base 577 in Python

ANS: Use an iterative or recursive function that relies only on modulo and integer division, as shown in Solution 1, which returns a list of numeric digits compatible with any base B.

Q: Which base conversion method avoids recursion depth errors

ANS: Iterative approaches, such as Solution 2 (string building using a while loop and reversed()) or Solution 1 (list building), avoid Python’s recursion depth limits, making them safer for extremely large input numbers.

Q: Can built-in Python formatting handle bases beyond 36

ANS: No, standard f-string formatting (:b, :x, :o) and format() support up to base 36 (using ‘0’-‘9’ and ‘a’-‘z’). For bases higher than 36, custom logic or libraries like basencode are required.

Q: Why do some solutions only work for bases less than or equal to 36

ANS: These solutions implicitly or explicitly rely on standard character sets like ASCII letters (a-z) or hexadecimal notation, which only provide 36 unique symbols (10 digits + 26 letters).
