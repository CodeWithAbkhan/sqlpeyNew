“Optimizing File Upload Performance in FastAPI: Streaming vs. Standard Methods”

When dealing with large files in web applications built with frameworks like FastAPI, the default handling of UploadFile can introduce performance bottlenecks due to intermediate file spooling. This exploration details three primary techniques for processing multipart/form-data uploads, contrasting raw stream processing with built-in framework features.

Initial Considerations for File Uploads

Before diving into the specialized solutions, it is worth noting that older libraries like requests-toolbelt require explicit setting of the Content-Type header with the correct boundary, which is crucial for correct multipart encoding.

A basic example using MultipartEncoder from requests-toolbelt to ensure correct header setting:

from requests_toolbelt import MultipartEncoder
import requests

# Note: requests-toolbelt has not seen a new release recently.
filename = 'initial_data.bin'
multipart_data = MultipartEncoder(
    fields={'upload_field': (filename, open(filename, 'rb'))}
)

response = requests.post(
    url="your_upload_url", 
    data=multipart_data, 
    headers={'Content-Type': multipart_data.content_type}
)
print(response.request.headers)

For modern Python HTTP clients, httpx offers superior asynchronous support and better handling of streaming data, often eliminating the need for external toolbelt libraries.

Option 1: Efficient Single File Uploads via Raw Request Streaming

The standard FastAPI approach using UploadFile often relies on Starlette’s internal mechanism, which utilizes a SpooledTemporaryFile. For files under 1MB (the default max_size), data resides in memory; exceeding this size triggers writing to a temporary file on disk. This disk I/O significantly slows down the upload process for large files.

To bypass this spooling delay, we can access the request body directly as a stream using request.stream(). This allows processing incoming bytes chunk-by-chunk without memory accumulation or immediate disk writing until explicitly handled.

This method is fast but only handles raw byte streams and cannot automatically parse traditional multipart/form-data fields (like text data); metadata must be passed via headers.

FastAPI Endpoint (Stream Only)

This server example reads raw chunks and saves them to disk, utilizing aiofiles for asynchronous file operations. Filenames are passed via headers, requiring client-side URL encoding/decoding for safety.

# app_stream_only.py
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates
from urllib.parse import unquote
import aiofiles
import os

app = FastAPI()
templates = Jinja2Templates(directory="templates")

@app.post('/upload')
async def upload(request: Request):
    try:
        # Retrieve filename from headers and decode (must be encoded client-side)
        filename = request.headers.get('filename', 'default_file')
        filename = unquote(filename)
        filepath = os.path.join('./uploads', os.path.basename(filename))
        
        # Ensure upload directory exists
        os.makedirs('./uploads', exist_ok=True)
        
        async with aiofiles.open(filepath, 'wb') as f:
            async for chunk in request.stream():
                await f.write(chunk)
    except Exception as e:
        raise HTTPException(status_code=500, detail=f'Upload failure: {e}')
     
    return {"message": f"Successfully streamed upload: {filename}"}
    
@app.get("/", response_class=HTMLResponse)
async def main(request: Request):
    return templates.TemplateResponse(request=request, name="index_stream.html")

Option 2: Fast Multipart Parsing with streaming-form-data

For scenarios requiring both files and accompanying form data (JSON-like payloads) processed efficiently without waiting for the entire request, the external streaming-form-data library is highly effective. It parses the incoming multipart stream in real-time as chunks arrive.

This solution uses the raw Request object and integrates the parser with FileTarget (for files saved to disk) and ValueTarget (for form data kept in memory).

Size Validation Integration

A key advantage here is the ability to implement validation, such as limiting the total request body size, before the entire request completes—a capability missing when using UploadFile. We introduce custom validators for file size and total body size constraints.

# app_streaming_parser.py
from fastapi import FastAPI, Request, HTTPException, status
from streaming_form_data import StreamingFormDataParser
from streaming_form_data.targets import FileTarget, ValueTarget
from streaming_form_data.validators import MaxSizeValidator
import streaming_form_data
from starlette.requests import ClientDisconnect
from urllib.parse import unquote
import os

# Define limits: 4GB file size, slightly more for body overhead
MAX_FILE_SIZE = 1024 * 1024 * 1024 * 4  
MAX_REQUEST_BODY_SIZE = MAX_FILE_SIZE + 2048 

app = FastAPI()

class BodySizeExceeded(Exception):
    def __init__(self, current_length: int):
        self.current_length = current_length

class BodySizeValidator:
    """Checks total length of received bytes against a maximum."""
    def __init__(self, max_size: int):
        self.body_len = 0
        self.max_size = max_size

    def __call__(self, chunk: bytes):
        self.body_len += len(chunk)
        if self.body_len > self.max_size:
            raise BodySizeExceeded(body_len=self.body_len)
 
@app.post('/upload')
async def upload_streamed_form(request: Request):
    body_validator = BodySizeValidator(MAX_REQUEST_BODY_SIZE)
    
    # Assume filename is passed via header for file targeting
    filename_header = request.headers.get('filename')
    
    if not filename_header:
        raise HTTPException(status_code=status.HTTP_422_UNPROCESSABLE_ENTITY, 
            detail='Filename header required')
            
    try:
        filename = unquote(filename_header)
        filepath = os.path.join('./uploads', os.path.basename(filename)) 
        os.makedirs('./uploads', exist_ok=True)

        # Setup targets for parsing
        file_target = FileTarget(filepath, validator=MaxSizeValidator(MAX_FILE_SIZE))
        data_target = ValueTarget() # For accompanying form data field named 'data'
        
        parser = StreamingFormDataParser(headers=request.headers)
        parser.register('file', file_target)
        parser.register('data', data_target)
        
        async for chunk in request.stream():
            body_validator(chunk)
            parser.data_received(chunk)
            
    except ClientDisconnect:
        print("Client Disconnected during streaming.")
    except BodySizeExceeded as e:
        raise HTTPException(status_code=status.HTTP_413_REQUEST_ENTITY_TOO_LARGE, 
           detail=f'Request body limit ({MAX_REQUEST_BODY_SIZE} bytes) surpassed.')
    except streaming_form_data.validators.ValidationError:
        raise HTTPException(status_code=status.HTTP_413_REQUEST_ENTITY_TOO_LARGE, 
            detail=f'File size limit ({MAX_FILE_SIZE} bytes) exceeded.') 
    except Exception:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 
            detail='Error processing upload stream.') 
   
    if not file_target.multipart_filename:
        raise HTTPException(status_code=status.HTTP_422_UNPROCESSABLE_ENTITY, detail='File part not found in stream.')

    # Access parsed form data and filename from targets
    print(f"Form Data Received: {data_target.value.decode() if data_target.value else 'None'}")
    print(f"Actual File Name: {file_target.multipart_filename}")
        
    return {"message": f"Streamed form upload successful for {filename}"}

Option 2b: Multiple File Streaming with Dynamic Headers

Handling multiple files requires ensuring each file part in the multipart stream is uniquely identifiable, as the parser needs a pre-defined target path for each file. We achieve this by sending numbered headers (filename0, filename1, etc.) from the client and registering corresponding fields (file0, file1) on the parser.

FastAPI Endpoint (Multiple Files)

# app_multi_stream.py (Excerpt of upload endpoint changes)
# ... imports remain similar ...

@app.post('/upload_multi')
async def upload_multiple_streamed(request: Request):
    try:
        parser = StreamingFormDataParser(headers=request.headers)
        data_target = ValueTarget()
        parser.register('data', data_target) # Register form field

        headers = dict(request.headers)
        received_filenames = []
        i = 0
        while True:
            # Look for numbered filename headers sent by client
            filename_header = headers.get(f'filename{i}', None)
            if filename_header is None:
                break
            
            filename = unquote(filename_header)
            received_filenames.append(filename)
            filepath = os.path.join('./uploads', os.path.basename(filename)) 
            
            file_target = FileTarget(filepath)
            parser.register(f'file{i}', file_target) # Register file target matching expected part name
            i += 1

        async for chunk in request.stream():
            parser.data_received(chunk)
    except Exception:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 
            detail='Error processing multi-file upload.') 

    print(f"Form Data: {data_target.value.decode()}")
    return {"message": f"Successfully uploaded files: {received_filenames}"}

Option 2c: Handling JSON Data within Multipart Stream

If the non-file data accompanying the file upload is expected to be JSON (rather than standard form URL-encoded data), the approach must be modified. The JSON string must be serialized and included as a field in the multipart request. On the server, we use Form(...) to retrieve the string payload, then attempt to deserialize and validate it using Pydantic.

# app_json_payload.py (Changes to Option 2 endpoint)
from fastapi import Form, status
# ... other imports from Option 2 ...
from pydantic import BaseModel, ValidationError
from fastapi.encoders import jsonable_encoder

class PayloadSchema(BaseModel):
    name: str
    point: float = 0.13
    is_accepted: bool = False
  
def validate_json_form_data(data_str: str = Form(...)):
    try:
        # Expects the data field to contain a JSON string
        return PayloadSchema.model_validate_json(data_str)
    except ValidationError as e:
        raise HTTPException(detail=jsonable_encoder(e.errors()), 
                            status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
                            detail="JSON validation failed for payload.")
        

@app.post('/upload_json')
async def upload_with_json(request: Request):
    # ... streaming setup (parser, targets, validation) as in Option 2 ...
    
    # After streaming loop finishes (parser.data_received(chunk) completes):
    
    # Retrieve the 'data' target value and pass it to the validator function
    if data_target.value:
        validated_model = validate_json_form_data(data_target.value.decode())
        print(f"Validated Model: {validated_model.model_dump()}")

Option 3: Standard UploadFile and Form (Slower Approach)

This approach relies on FastAPI/Starlette’s default handling for UploadFile and Form. As previously discussed, this is typically slower for large files because the entire file must be fully read and spooled to disk before the endpoint logic executes.

# app_standard_slow.py
from fastapi import FastAPI, File, UploadFile, Form, HTTPException, status
import aiofiles
import os

CHUNK_SIZE = 1024 * 1024 
app = FastAPI()

@app.post("/upload_standard")
async def upload_standard(file: UploadFile = File(...), data: str = Form(...)):
    # Execution begins only AFTER the entire request body (file + form data) is received
    try:
        filepath = os.path.join('./uploads', os.path.basename(file.filename))
        async with aiofiles.open(filepath, 'wb') as f:
            while chunk := await file.read(CHUNK_SIZE):
                await f.write(chunk)
    except Exception:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 
            detail='File system error during write.')
    finally:
        await file.close()

    return {"message": f"Standard upload completed for {file.filename}. Form data: {data}"}

Client Timeout Adjustment for Slow Uploads

Since this method waits for the entire upload before processing begins, large files can easily exceed default HTTP client timeouts (like httpx’s 5-second default). You must configure a read timeout:

# test_standard_slow.py
import httpx
import time
import os

URL = 'http://127.0.0.1:8000/upload_standard'
FILE_TO_SEND = 'huge_archive.zip'
if not os.path.exists(FILE_TO_SEND):
     with open(FILE_TO_SEND, 'wb') as f: f.write(os.urandom(1024 * 1024 * 20)) # 20MB dummy

data_payload = {'data': 'Slow transfer test'}
files_payload = {'file': open(FILE_TO_SEND, 'rb')}

# Increase read timeout significantly, or set to None for no timeout (use cautiously)
# We set read timeout to 180 seconds.
custom_timeout = httpx.Timeout(None, read=180.0) 

with httpx.Client(timeout=custom_timeout) as client:
    start_time = time.time()
    r = client.post(url=URL, data=data_payload, files=files_payload)
    end_time = time.time()
    
    print(f'Time elapsed: {end_time - start_time:.2f}s')
    print(f"Status: {r.status_code}, Response: {r.json()}")

@app.post('/upload')
async def upload(request: Request):
    try:
        parser = StreamingFormDataParser(headers=request.headers)
        data = ValueTarget()
        parser.register('data', data)

        headers = dict(request.headers)
        filenames = []
        i = 0
        while True:
            filename =  headers.get(f'filename{i}', None)
            if filename is None:
                break
            filename = unquote(filename)
            filenames.append(filename)
            filepath = os.path.join('./', os.path.basename(filename)) 
            file_ = FileTarget(filepath)
            parser.register(f'file{i}', file_)
            i += 1

        async for chunk in request.stream():
            parser.data_received(chunk)
    except ClientDisconnect:
        print(&quot;Client Disconnected&quot;)
    except Exception:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 
            detail='There was an error uploading the file') 

    print(data.value.decode())
    return {&quot;message&quot;: f&quot;Successfuly uploaded {filenames}&quot;}

from fastapi import FastAPI, File, UploadFile, Form, HTTPException, status
import aiofiles
import os

CHUNK_SIZE = 1024 * 1024  # adjust the chunk size as desired
app = FastAPI()

@app.post(&quot;/upload&quot;)
async def upload(file: UploadFile = File(...), data: str = Form(...)):
    try:
        filepath = os.path.join('./', os.path.basename(file.filename))
        async with aiofiles.open(filepath, 'wb') as f:
            while chunk := await file.read(CHUNK_SIZE):
                await f.write(chunk)
    except Exception:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 
            detail='There was an error uploading the file')
    finally:
        await file.close()

    return {&quot;message&quot;: f&quot;Successfuly uploaded {file.filename}&quot;}
