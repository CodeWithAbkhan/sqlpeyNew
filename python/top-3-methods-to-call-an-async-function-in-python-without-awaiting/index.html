How can I call an async function without await

In modern asynchronous Python programming, particularly when developing web applications with frameworks such as aiohttp, there are instances when you might want to invoke an async function without halting your application’s flow. This raises an important question: How can you effectively call an async function without using the await keyword? Below, we will explore several methods to achieve this, illustrated with practical code examples.

Context of the Problem

Imagine you have a controller action in your aiohttp application that handles a request. Within this handler, you invoke an async function, perform_message, that processes some information, but you don’t want the request handler to wait for perform_message to complete before returning a response.

Here is a simplified version of such a handler:

async def handler_message(request):
    try:
        content = await request.json()
        perform_message(x, y, z)  # This call needs to be non-blocking.
    except RuntimeError:
        print("Error occurred in perform_message")
    finally:
        return web.Response(text="Done")

In this example, the perform_message function is an async function, yet it does not run as expected since no event-loop task is created for it.

Solution 1: Utilizing asyncio.create_task

A straightforward method to handle this is by employing the asyncio.create_task function, which schedules the perform_message function to run concurrently with your handler’s main execution flow:

import asyncio
from aiohttp import web

async def handler_message(request):
    try:
        content = await request.json()
        asyncio.create_task(perform_message(content['x'], content['y'], content['z']))
    except RuntimeError:
        print("Error occurred in perform_message")
    finally:
        return web.Response(text="Done")

With this approach, perform_message is scheduled to run in the event loop without blocking the returning of the HTTP response.

Note on Python Versions

As of Python 3.10, using asyncio.get_event_loop() is considered deprecated. If you’re ensuring compatibility with this version or later, incorporate asyncio.get_running_loop() to retrieve the current running loop:

async def handler_message(request):
    content = await request.json()
    
    loop = asyncio.get_running_loop()  # Correct method for async loop retrieval
    loop.create_task(perform_message(content['x'], content['y'], content['z']))
    
    return web.Response(text="Done")

Solution 2: Using asyncio.run()

If your scenario allows it, asyncio.run() can be used to run the async function in a fresh event loop. However, this method is more appropriate when you are certain that no other async tasks are running:

async def handler_message(request):
    content = await request.json()
    
    # Using asyncio.run should be done carefully
    asyncio.run(perform_message(content['x'], content['y'], content['z']))
    
    return web.Response(text="Done")

This method sets up and tears down the event loop but should ideally only be used in scripts or in places where you’re not in an existing async context.

Practical Example

Here’s how you might implement the perform_message function, which could be performing an HTTP request, for instance:

async def perform_message(x, y, z):
    # Simulating an async operation, such as sending an HTTP request
    await asyncio.sleep(1)  # Simulates delays for async operation
    print(f"Processed message with data: {x}, {y}, {z}")

Alternative Approaches

While the above solutions are effective, consider incorporating:

  • Threaded Execution: For blocking operations, using concurrent.futures to run blocking calls in separate threads can maintain the responsiveness of your aiohttp handler.

  • Task Queues: For more complex workflows, explore libraries like Celery for handling background tasks efficiently.

FAQs on Top 3 Methods to Call an Async Function in Python Without Awaiting

Q: Why should I use asyncio.create_task?

A: Using asyncio.create_task allows you to schedule an async function to run concurrently, making it ideal for non-blocking operations in web applications.

Q: Is asyncio.run always a good choice for calling async functions?

A: asyncio.run should be used cautiously as it creates a new event loop and is best suited for executing standalone async functions without any prior loop running.

Q: Can I run blocking code within an async function?

A: Yes, you can use concurrent.futures to run blocking functions in a thread or process pool to keep your async handlers responsive.
