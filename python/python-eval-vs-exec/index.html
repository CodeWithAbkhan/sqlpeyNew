“Python eval vs exec: Key Differences and Usage”

In Python, eval() and exec() are powerful built-in functions that allow for the dynamic execution of code. While they both operate on strings containing Python code, they serve distinct purposes and have crucial differences in how they handle expressions versus statements. This exploration aims to clarify these distinctions and provide practical insights.

The Core Distinction: Expressions vs. Statements

At their heart, the fundamental difference between eval() and exec() lies in what they are designed to process:

  • eval(): Primarily used to evaluate a single, dynamically generated Python expression. It expects a piece of code that can produce a value, much like anything you’d find on the right-hand side of a variable assignment. eval() then returns the computed value of that expression.

  • exec(): Designed to execute dynamically generated Python code, which can include entire code blocks or sequences of statements. Its focus is on the side effects of the code rather than a direct return value. Consequently, exec() always returns None.

Key Differences in Detail

Let’s break down the specific ways eval() and exec() differ:

  1. Code Structure:

    • eval() is limited to a single expression. Attempting to pass statements (like assignments, loops, or conditional blocks) to eval() will result in a SyntaxError.
    • exec() can handle any valid Python code, including multiple statements, function definitions, class definitions, loops, and conditional blocks.

  2. Return Value:

    • eval() returns the result of the evaluated expression.
    • exec() does not return the result of the executed code; it always returns None.

  3. Historical Context (Python 2 vs. Python 3):

    • In Python 2.x, exec was a statement, whereas eval was a built-in function.
    • In Python 3.x, both exec and eval are built-in functions. The behavior regarding their core functionality remains consistent.

Practical Examples

To illustrate these points, consider these examples:

Using eval() for Expressions:

# eval() evaluates a single expression and returns its value
variable_a = 10
expression_string = '37 + variable_a'
result = eval(expression_string)
print(f"Result of eval('{expression_string}'): {result}") # Output: Result of eval('37 + variable_a'): 47

# Attempting to use a statement with eval() raises a SyntaxError
try:
    eval('variable_a = 47')
except SyntaxError as e:
    print(f"Error with eval on a statement: {e}")
# Output: Error with eval on a statement: invalid syntax

Using exec() for Statements and Code Blocks:

# exec() executes statements and can modify variables
variable_b = 5
exec('37 + variable_b') # The result of this expression is ignored
print(f"variable_b after exec('37 + variable_b'): {variable_b}") # Output: variable_b after exec('37 + variable_b'): 5

exec('variable_b = 47') # This statement modifies variable_b
print(f"variable_b after exec('variable_b = 47'): {variable_b}") # Output: variable_b after exec('variable_b = 47'): 47

# exec() can handle multi-line code blocks
program_block = """
for i in range(3):
    print(f"Iteration {i}")
"""
exec(program_block)
# Output:
# Iteration 0
# Iteration 1
# Iteration 2

# exec() returns None
return_value = exec('print("This is exec")')
print(f"Return value of exec: {return_value}") # Output: Return value of exec: None

Working with Compiled Code

Both eval() and exec() can also accept compiled code objects, which can sometimes offer performance benefits if the same code snippet is executed multiple times. This is where the compile() built-in function becomes relevant.

The compile() function takes a source string and a mode ('eval', 'exec', or 'single') and returns a code object.

  • compile(source, filename, 'eval'): Creates a code object for a single expression. This is equivalent to passing the source string directly to eval().
  • compile(source, filename, 'exec'): Creates a code object for any number of Python statements. This is equivalent to passing the source string directly to exec().

Example using compile():

import dis # For disassembly, to see bytecode

# Compiling an expression for eval()
code_expr = compile('42', '<string>', 'eval')
print(f"eval(compiled_expression): {eval(code_expr)}") # Output: eval(compiled_expression): 42
dis.dis(code_expr)
# Output (bytecode may vary slightly):
#   1           0 LOAD_CONST               0 (42)
#               2 RETURN_VALUE

# Compiling statements for exec()
code_statements = compile('a = 10\nprint(a)', '<string>', 'exec')
exec(code_statements) # Executes the statements, output '10' is printed
# Output: 10
dis.dis(code_statements)
# Output (bytecode may vary slightly):
#   1           0 LOAD_CONST               0 (10)
#               2 STORE_NAME               0 (a)
#
#   2           4 LOAD_NAME                0 (a)
#               6 PRINT_EXPR
#               8 LOAD_CONST               1 (None)
#              10 RETURN_VALUE

# Passing a compiled 'exec' mode code object to eval()
# eval() will execute it but still return None, as exec mode code returns None
code_exec_mode_for_eval = compile('print("Hello from eval with exec code")', '<string>', 'exec')
result_from_exec_mode = eval(code_exec_mode_for_eval)
print(f"Result from eval(exec mode code): {result_from_exec_mode}")
# Output: Hello from eval with exec code
# Output: Result from eval(exec mode code): None

# Passing a compiled 'eval' mode code object to exec()
# exec() will execute it but discard the return value
code_eval_mode_for_exec = compile('42 * 2', '<string>', 'eval')
return_from_eval_mode = exec(code_eval_mode_for_exec)
print(f"Return from exec(eval mode code): {return_from_exec_mode}") # Note: This line actually prints the result of the previous eval, not exec. Corrected below.
# Corrected output for exec(eval mode code):
return_from_eval_mode_corrected = exec(code_eval_mode_for_exec) # This executes the code, but the return value is discarded by exec
print(f"Return from exec(eval mode code): {return_from_exec_mode_corrected}") # Output: Return from exec(eval mode code): None

Security Considerations

It’s crucial to exercise extreme caution when using eval() and exec() with untrusted input. Because they can execute arbitrary Python code, they pose significant security risks if not handled properly. Malicious input could lead to data corruption, unauthorized access, or denial-of-service attacks. Always sanitize and validate any external input before passing it to these functions.

For safer dynamic code execution, consider libraries like ast.literal_eval which only evaluates literal Python expressions, or structure your code to use exec with restricted namespaces.

Alternative Scenarios and Usage

  • Capturing Variables: Both eval() and exec() can accept globals and locals dictionaries. This allows you to control the execution environment and capture variables created or modified by the executed code.

    global_scope = {}
local_scope = {}

exec('a = 123; b = 456', global_scope, local_scope)

print(f"Global scope: {global_scope.get('a')}") # Output: Global scope: 123
print(f"Local scope: {local_scope.get('b')}")   # Output: Local scope: 456

  • Python 2 exec Statement Syntax: While Python 3 uses exec() as a function, Python 2 had an exec statement with syntax like exec 'print 42' in globals(), locals(). The function-like exec(code, globals, locals) syntax was also supported for backward compatibility and forward compatibility with Python 3.
