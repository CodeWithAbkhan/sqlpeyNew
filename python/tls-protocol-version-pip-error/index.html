“Fixing Python ‘TLSV1 ALERT PROTOCOL VERSION’ Pip Install Error”

This post dives deep into various scenarios and provides actionable solutions, complete with practical code examples, to help you overcome this common pip installation hurdle.

Why Does This Error Occur?

The core of the issue lies in the TLS (Transport Layer Security) protocol versions supported by your Python installation’s underlying SSL library, often OpenSSL. As python.org sites and PyPI have phased out support for TLS 1.0 and 1.1, any system using these older protocols will fail to establish secure connections, leading to the TLSV1 ALERT PROTOCOL VERSION error.

This can stem from:

  • Outdated OpenSSL: Your operating system’s OpenSSL library might be an older version that doesn’t support TLS 1.2.
  • Older Python Versions: Python versions prior to 2.7.9 (for Python 2) and 3.4 (for Python 3) had SSL modules compiled against older OpenSSL versions, lacking native TLS 1.2 support.
  • Virtual Environment Configuration: Sometimes, virtual environments might inherit or be configured with older SSL settings.

Let’s explore the proven methods to resolve this.

Solution 1: Upgrade Pip Using the Official Bootstrap Script

The most direct approach is to use the official get-pip.py script to upgrade pip. This script is designed to handle the bootstrapping process correctly.

curl https://bootstrap.pypa.io/get-pip.py | python

Important Considerations:

  • sudo Requirement: If you are not in a virtual environment and encountering permission errors, you might need to prepend sudo:

    sudo curl https://bootstrap.pypa.io/get-pip.py | sudo python

  • Virtual Environments (PyCharm Example): For users in virtual environments, ensure you activate it first:

    1. Activate your virtual environment (e.g., source ./venv/bin/activate).
    2. Run the upgrade command: curl https://bootstrap.pypa.io/get-pip.py | python.
    3. Restart your IDE or shell session.

    A combined example for virtual environments:

    source ./venv/bin/activate
curl https://bootstrap.pypa.io/get-pip.py | python

Why not pip install --upgrade pip? Attempting to upgrade pip using pip itself can lead to a “chicken-and-egg” problem if pip is already broken due to TLS issues. The bootstrap script bypasses this by using a more fundamental method.

Solution 2: Verify and Address TLS/OpenSSL Compatibility

If the curl command fails, or the error persists after upgrading pip, it indicates a deeper issue with your system’s SSL/TLS capabilities.

Checking Your SSL Version:

You can inspect your Python environment’s SSL capabilities directly:

import ssl
print(ssl.OPENSSL_VERSION)
try:
    ssl.PROTOCOL_TLSv1_2
    print("TLSv1.2 is supported")
except AttributeError:
    print("TLSv1.2 is NOT supported")

If ssl.PROTOCOL_TLSv1_2 raises an AttributeError, your Python’s SSL module, compiled against an older OpenSSL, lacks the necessary support.

Addressing Compatibility:

  • Install Extra Python Packages: For a solution without a full Python upgrade, a detailed guide on Stack Overflow provides steps to manually install necessary Python packages that offer enhanced SSL support. This often involves leveraging libraries that can bridge the gap.
  • System-Level OpenSSL Upgrade: Ensure your system’s OpenSSL library is up-to-date. For Debian/Ubuntu based systems, this might involve: 
    sudo apt-get update && sudo apt-get install openssl libssl-dev
    Check your system’s package manager for equivalent commands if you’re not on a Debian-based system. Remember that curl, pip, and wget all rely on the system’s OpenSSL library.

Solution 3: Manual Pip Installation from Source

If network-based upgrades are problematic, a manual installation of a specific pip version can be effective.

  1. Download Pip Package: Visit the pip distribution page on PyPI in your browser and download the latest tar.gz (or .zip) archive.
  2. Extract and Install:
    • Extract the downloaded archive.
    • Navigate into the extracted directory using your terminal.
    • Run the installation locally: 
      pip install ./pip-9.0.3/
      (Replace pip-9.0.3/ with the actual directory name of the extracted package).

Solution 4: Specifying Python Executable for Upgrade

In complex environments or when sudo doesn’t resolve path issues, explicitly pointing to your Python executable during the get-pip.py execution can help.

curl https://bootstrap.pypa.io/get-pip.py | sudo /Users/{your user name}/{path to python}/bin/python

Replace {your user name} and {path to python} with your actual user directory and the path to your specific Python executable. This ensures the upgrade script uses the intended Python interpreter.

Solution 5: User-Specific Pip Upgrade

If your Python installation or packages reside within your home directory, using the --user flag can be beneficial.

curl https://bootstrap.pypa.io/get-pip.py | python - --user

This method installs pip in a user-specific location, potentially avoiding system-wide permission issues.

Solution 6: Using brew for Python 2 on macOS

For macOS users on older Python 2 versions, brew can be a reliable way to install a compatible Python version and pip.

brew install python2

This command will install the latest Python 2 version available via Homebrew, which typically includes an updated pip.

Solution 7: TLS Version Check and System Upgrade (Python 2)

For Python 2 users, explicitly checking the TLS version used for HTTP requests is informative.

python2 -c "import urllib2,json; print(json.loads(urllib2.urlopen('https://www.howsmyssl.com/a/check').read())['tls_version'])"

If the output indicates a TLS version less than 1.2, a system-level upgrade of OpenSSL and related development libraries is recommended. On Debian/Ubuntu systems:

sudo apt-get update && sudo apt-get install openssl libssl-dev

Private Python Package Repository: As an alternative, consider setting up your own private Python package repository. This allows you to host packages and manage dependencies independently of external SSL requirements. Learn more about Private Python Package Repository .

Solution 8: Python 3 and pip3 Considerations

If you are primarily using Python 3, ensure you use python3 and pip3 commands consistently.

curl https://bootstrap.pypa.io/get-pip.py | sudo python3
pip3 install pandas --user

This ensures that the upgrade process targets your Python 3 installation.

Solution 9: Prepending sudo to python

A straightforward adjustment, sometimes overlooked, is simply prepending sudo if the script execution fails due to permissions.

curl https://bootstrap.pypa.io/get-pip.py | sudo python

Solution 10: Python 2 Windows 10 Reinstallation

For Python 2 users on Windows 10 facing persistent issues, a clean reinstallation can resolve underlying conflicts:

  1. Uninstall Python Thoroughly: Remove all Python 2 installations and associated folders.
  2. Install Latest Python 2: Download and install the latest python-2.7.msi (e.g., version 2.7.15) from the official Python website. This usually includes pip.
  3. Verify Environment: Ensure your system’s PATH environment variable correctly points to the new Python 2 installation.
  4. Test Pip: Attempt to install packages again.

Solution 11: macOS Package Installation (Python 2)

Similar to Solution 10, for macOS users struggling with Python 2, reinstalling via a downloaded .pkg file from python.org/downloads/mac-osx/ can be an effective fix. This ensures a clean installation with compatible components.

Solution 12: Manually Copying SSL Files (Windows Python 2)

If upgrading Python 2 on Windows is not feasible, you can manually “upgrade” the SSL layer by copying specific files from a newer, compatible Python 2 installation (e.g., 2.7.15) to your existing one:

  • Lib\ssl.py
  • libs\_ssl.lib
  • DLLs\_ssl.dll

This replacement can enable pip to function correctly again.

Solution 13: Manual Pip Installation via setup.py

If the bootstrap script fails with errors like Could not fetch URL https://pypi.org/simple/pip/ or SSLError("Can't connect to HTTPS URL because the SSL module is not available."), a manual setup.py install is required:

  1. Download Pip Distribution: Get the pip source archive (tar.gz or .zip) from PyPI .
  2. Extract: Unpack the archive locally.
  3. Navigate and Install: Change your directory to the unpacked pip folder and run: 
    python setup.py install

Solution 14: Specifying Python Path for Pip Upgrade (macOS)

This is a variation of Solution 4, emphasizing the explicit path for Python executables on macOS:

curl https://bootstrap.pypa.io/get-pip.py | sudo /Users/{your user name}/{path to python}/bin/python

After a successful pip upgrade, installing libraries like ciscoconfparse should proceed without the TLS error.

Solution 15: Downloading get-pip.py Manually

For some environments, especially older systems or specific configurations, downloading get-pip.py directly from packaging.python.org/tutorials/installing-packages/ and then running it locally is the most reliable method.

python get-pip.py

This process also installs or upgrades setuptools and wheel. To ensure these are also up-to-date:

python -m pip install --upgrade pip setuptools wheel

Solution 16: Resetting pip.ini on Windows

On Windows, a corrupted or incorrectly modified pip.ini configuration file can lead to installation failures, manifesting as “No matching distribution found.”

  1. Locate pip.ini: This file is typically found in C:\ProgramData\pip.
  2. Reset Configuration: If the file has been modified, reset it to its default configuration. You might need to back up the current file before making changes.
  3. Retry Installation: Run your pip install command again.

Solution 17: Library Renaming and PyPI Checks

Occasionally, the issue might not be with pip or TLS, but with the library itself. A library might have been renamed or a specific version you’re trying to install is no longer available or has been superseded.

  • Check PyPI: Always verify the library’s presence and latest version on PyPI . For instance, a library like airflow might have been renamed or undergone significant changes.
  • Search Strategy: If you encounter “No matching distribution found,” consider searching PyPI for variations of the library name or looking for related projects.

FAQs on Fixing Python TLSV1 Alert Protocol Version Pip Install Error

Q: What causes the TLSV1 ALERT PROTOCOL VERSION error when installing Python packages

ANS: This error occurs because PyPI, the Python Package Index, now requires TLS 1.2 or higher for secure connections. Older Python installations or systems with outdated OpenSSL libraries might not support these newer TLS versions, leading to connection failures during pip install.

Q: How can I upgrade pip to fix TLS issues

ANS: The recommended method is to use the official bootstrap script: curl https://bootstrap.pypa.io/get-pip.py | python. If you encounter permission errors, try prepending sudo. For virtual environments, ensure it’s activated before running the command.

Q: My curl command fails, what's the next step

ANS: If curl fails, it likely means your system’s OpenSSL library is too old. You can check your Python SSL version using import ssl in an interpreter. Solutions involve upgrading your system’s OpenSSL (sudo apt-get install openssl libssl-dev on Debian/Ubuntu) or manually installing compatible Python packages.

Q: Can I fix this without upgrading my entire Python installation

ANS: Yes, there are several ways. Solutions include upgrading pip via the bootstrap script, manually installing pip from source, or in specific cases on Windows, replacing SSL-related library files. For Python 2, installing a newer version from sources like Homebrew on macOS or downloading .pkg files can also work.

Q: I'm using Python 2, does this affect the solutions

ANS: Yes, Python 2 versions before 2.7.9 are particularly susceptible. Solutions specific to Python 2 include reinstalling Python 2.7.15 on Windows, using brew install python2 on macOS, or ensuring your system’s OpenSSL is updated for Python 2 to utilize TLS 1.2. Always use python2 and pip2 commands where applicable.

Q: What if I can't use the command line due to my environment

ANS: If command-line access is restricted, you might need to download the get-pip.py script or the pip source archive manually using a web browser on a different machine and transfer it to your environment. Then, attempt to run python get-pip.py or python setup.py install locally.
