I recently faced a frustrating issue while trying to run my FastAPI application. Upon executing the command:

uvicorn api:app --reload --host 0.0.0.0

I was met with the following error:

Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
Started reloader process [23445]
Error loading ASGI app. Could not import module "api".
Stopping reloader process [23445]

So, how can we solve this perplexing problem? Here’s a comprehensive exploration of common solutions that have helped many developers, including myself.

Method 1: Correct Import Syntax

One frequent cause of this error is using the incorrect syntax when invoking uvicorn. For instance, using:

uvicorn src/main:app --reload

instead of the correct format:

uvicorn src.main:app --reload

Be sure to note that we’re using a dot (.) to separate the directories, rather than a slash (/). It’s essential to confirm that your directory structure follows this example:

project_folder/
├── some_folder
├── src
│   └── main.py
└── tests
    ├── test_xx.py
    └── test_yy.py

Furthermore, ensure that your FastAPI instance in main.py is declared as follows:

from fastapi import FastAPI

app = FastAPI()

And execute the command from the project_folder:

(venv) <username>@<pcname>:~/PycharmProjects/project_folder$ uvicorn src.main:app --reload

Method 2: Adding Package Name in the Import

If you’ve faced similar issues, adding the package name before main may resolve the problem. Try executing:

uvicorn src.main:app --reload

Method 3: Naming the Python File Correctly

Make sure your Python script is named main.py. The command uvicorn main:app refers to:

  1. main: the name of your Python file (module).
  2. app: the FastAPI object defined inside that file.
  3. --reload: enables auto-reloading during development.

For additional clarification, you can refer to the FastAPI Documentation .

Method 4: Avoid Circular Imports

If there are circular imports in your project, you may also encounter this error. For instance, main.py referencing something in another file which also references back to it can cause issues. Here’s a simple example:

main.py

from tools import validator

class GlobalException(Exception):
    pass

tools/validator.py

from main import GlobalException

Method 5: Check Your Directory and Object References

Beginner mistakes often involve directory paths. If your project structure has a file fast-api.py, then run the command:

cd path_to_your_code
uvicorn fast-api:main --reload

Make sure you’re in the correct directory when invoking this command.

Method 6: File Naming Matters

Having your main file named main.py is crucial. Also, ensure no other process is using the same port (like Jupyter Notebook). If you need to run Jupyter, let the API server start first or change the port:

uvicorn main:app --reload --port 8889

Method 7: Terminal Location and File Checks

  1. Use the command ls to confirm that your main file exists in the current terminal directory.
  2. Use pwd to verify that you are in the right directory.
  3. Ensure the object you reference is named correctly. For example, if your FastAPI object is named app, use:
uvicorn main:app --reload

If the object is named differently (e.g., app1), adjust the command:

uvicorn main:app1 --reload

Method 8: Save Your Work

Sometimes forgetting to save your file in an IDE like VS Code can cause issues. Always hit the save button!

Method 9: Running Uvicorn from the Module Context

Modify your main.py as follows to ensure it runs correctly:

import uvicorn
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def index():
    return {"Hello": "World"}

if __name__ == '__main__':
    uvicorn.run("main:app", host="127.0.0.1", port=8888, reload=True)

Method 10: Load Application from Different Locations

To run your application from a location outside your project directory, you can use a couple of methods. For instance, with this directory structure:

/home/my_user/project_folder/
├── some_folder
├── src
│   └── main.py
└── tests
    ├── test_xx.py
    └── test_yy.py

You can run:

uvicorn --app-dir ./my_user/project_folder/src main:app --reload

Or:

uvicorn my_user.project_folder.src.main:app --reload

Method 11: Configure IDE for Proper Project Structure

In integrated environments like PyCharm, ensure that your source directories are set correctly. If your main file is nested in folders, navigate to:

Preferences > Project > Project Structure > Sources and set your source folder.

Method 12: Avoid Naming Conflicts

If you have folders or files that share the same name, you may encounter issues. For example, if the folder is named test_app and also has a test_app.py, renaming either will help prevent conflicts.

Method 13: Clear Naming Conflicts in Docker Environments

When working with Docker, incorrect directory structures can lead to issues. Be sure to verify folder structures in your docker-compose.yml file.

Method 14: Use FastAPI CLI

If you’re using a more recent version of FastAPI, you can use its built-in CLI to run applications:

fastapi run <file or package where your FastAPI app instance is>

This utility simplifies many common tasks for you!

FAQs on Solving FastAPI ASGI App Loading Issues

Q: Why does FastAPI say it cannot import the module?

A: This usually results from incorrect syntax in your import path or naming issues in your project structure. Ensure the syntax follows the correct format and that the files are named appropriately.

Q: How can I determine if my FastAPI app is running?

A: After running the uvicorn command, you should see an output indicating the server is running, typically on http://127.0.0.1:8000 unless configured otherwise. You can verify by opening this address in a web browser.

Q: What if multiple processes are trying to use the same port?

A: If you receive a port conflict error, ensure no other application is using that port or run your FastAPI server on a different port by changing the --port parameter in your command.
