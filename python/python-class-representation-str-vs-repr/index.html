“Python Class Representation str vs repr Explained”

When working with Python classes, how do you ensure your objects display in a readable and informative way, especially when printing or inspecting them? This question delves into the core mechanisms Python uses for object representation: the __str__ and __repr__ methods. Understanding these dunder methods is crucial for effective debugging and presenting your objects clearly.

Let’s explore how these methods influence what you see when you interact with class instances.

The Role of __str__ and __repr__

In Python, __str__ and __repr__ are special methods that define how an object is converted into a string.

  • __str__: This method is intended to provide a human-readable, informal string representation of an object. It’s what you typically see when you use the print() function or str() constructor on an instance.
  • __repr__: This method aims to produce an unambiguous, official string representation of an object. Ideally, it should be an expression that, if evaluated, would recreate the object with the same state. This is what you see when you inspect an object directly in the interactive interpreter or when you use the repr() function.

If a __str__ method is not defined for a class, Python will fall back to using the __repr__ method when print() or str() is called. If neither is defined, Python provides a default representation that usually includes the class name and memory address.

Solution 1: Basic __str__ and __repr__ Implementation

A straightforward way to control your class’s string output is by defining both __str__ and __repr__ methods.

class DeviceConfiguration:
    def __init__(self, device_id: str, ip_address: str, status: str):
        self.device_id = device_id
        self.ip_address = ip_address
        self.status = status

    def __repr__(self) -> str:
        # Provides an unambiguous representation, useful for debugging
        return f"DeviceConfiguration(device_id='{self.device_id}', ip_address='{self.ip_address}', status='{self.status}')"

    def __str__(self) -> str:
        # Provides a more user-friendly string for printing
        return f"Device ID: {self.device_id} | IP: {self.ip_address} | Status: {self.status}"

# Example Usage
config = DeviceConfiguration("DEV001", "192.168.1.100", "Active")

# Using print() calls the __str__ method
print(config)

# Inspecting directly or using repr() calls the __repr__ method
print(repr(config))

When you run this code:

Device ID: DEV001 | IP: 192.168.1.100 | Status: Active
DeviceConfiguration(device_id='DEV001', ip_address='192.168.1.100', status='Active')

This clearly shows how print() uses __str__ for a friendly output, while repr() provides a more technical, reconstructible representation.

Solution 2: __repr__ for Reconstructibility

Chris Lutz highlights that __repr__ is key for creating a string that can be used to recreate the object. This is particularly useful for serialization or debugging.

class ServerNode:
    def __init__(self, hostname: str, region: str, availability_zone: str):
        self.hostname = hostname
        self.region = region
        self.availability_zone = availability_zone

    def __repr__(self) -> str:
        # Formatted string that can potentially be used with eval()
        return f"<ServerNode hostname='{self.hostname}', region='{self.region}', az='{self.availability_zone}'>"

    def __str__(self) -> str:
        # A simpler string for displaying node status
        return f"Node {self.hostname} in {self.region}-{self.availability_zone}"

# Example Usage
node = ServerNode("web-01", "us-east-1", "us-east-1a")

print(f"Node details: {node}")
print(f"Node representation: {repr(node)}")

# Demonstrating eval() with __repr__
try:
    recreated_node = eval(repr(node))
    print(f"Recreated node object: {recreated_node}")
    print(f"Is recreated object same as original? {recreated_node == node}") # Note: Equality requires __eq__
except Exception as e:
    print(f"Could not recreate object: {e}")

Output:

Node details: Node web-01 in us-east-1-us-east-1a
Node representation: <ServerNode hostname='web-01', region='us-east-1', az='us-east-1a'>
Recreated node object: <ServerNode hostname='web-01', region='us-east-1', az='us-east-1a'>
Is recreated object same as original? False

Note: For eval(repr(obj)) to create an identical object, the __repr__ must be a valid Python expression that constructs the object, and the class would also typically need an __eq__ method defined for comparison.

Solution 3: Accessing Instance Attributes with __dict__

For debugging purposes, directly inspecting an object’s attributes can be very insightful. The __dict__ attribute holds an object’s writable attributes.

class UserProfile:
    def __init__(self, username: str, user_id: int, email: str):
        self.username = username
        self.user_id = user_id
        self.email = email
        self._internal_state = {"last_login": None}

# Example Usage
user = UserProfile("coder123", 4567, "coder@example.com")

# Directly print the __dict__ for debugging
print(user.__dict__)

Output:

{'username': 'coder123', 'user_id': 4567, 'email': 'coder@example.com', '_internal_state': {'last_login': None}}

Solution 4: Generic __str__ Using __dict__

A generic approach involves converting the __dict__ into a string within the __str__ method.

class DataRecord:
    def __init__(self, record_id: str, timestamp: str, value: float):
        self.record_id = record_id
        self.timestamp = timestamp
        self.value = value

    def __str__(self) -> str:
        # Returns a string representation including the class name and attributes
        return f"{self.__class__.__name__}: {self.__dict__}"

# Example Usage
record = DataRecord("REC005", "2023-10-27T10:00:00Z", 123.45)
print(record)

Output:

DataRecord: {'record_id': 'REC005', 'timestamp': '2023-10-27T10:00:00Z', 'value': 123.45}

Solution 5: Enhanced __str__ for Readability

To improve the readability of the __dict__ output, you can format it more nicely.

class InventoryItem:
    def __init__(self, item_name: str, quantity: int, price_per_unit: float):
        self.item_name = item_name
        self.quantity = quantity
        self.price_per_unit = price_per_unit

    def __str__(self) -> str:
        # Formats the attributes for better readability
        return f"{self.__class__.__name__}\n" + '\n'.join(
            (f"{attr} = {value}" for attr, value in self.__dict__.items())
        )

# Example Usage
item = InventoryItem("Widget", 50, 10.50)
print(item)

Output:

InventoryItem
item_name = Widget
quantity = 50
price_per_unit = 10.5

Solution 6: Reusable Printable Base Class

For consistency across multiple classes, a base class that handles representation can be highly effective. Python’s pprint module is excellent for this.

from pprint import pformat

class PrintableBase:
    def __repr__(self) -> str:
        # Uses pformat for a structured, readable representation of object's attributes
        return f"<{type(self).__name__}> {pformat(vars(self), indent=4, width=70)}"

# Example Usage with a derived class
class UserSession(PrintableBase):
    def __init__(self, session_id: str, user_id: int, start_time: str):
        self.session_id = session_id
        self.user_id = user_id
        self.start_time = start_time

session = UserSession("sess_abc123", 9876, "2023-10-27 11:00:00")
print(session)

Output:

<UserSession> {   'session_id': 'sess_abc123',
    'start_time': '2023-10-27 11:00:00',
    'user_id': 9876}

Solution 7: __repr__ for eval() Compatibility

As per the official Python documentation, a good __repr__ should be an evaluable expression.

class DataPoint:
    def __init__(self, x_value: float, y_value: float):
        self._x = x_value
        self._y = y_value

    def __str__(self) -> str:
        return f"Point at ({self._x}, {self._y})"

    def __repr__(self) -> str:
        # Represents the object as a constructor call
        return f'DataPoint({repr(self._x)}, {repr(self._y)})'

# Example Usage
point = DataPoint(10.5, 20.1)

print(f"Readable: {str(point)}")
print(f"Representation: {repr(point)}")

# Using eval to recreate the object
try:
    recreated_point = eval(repr(point))
    print(f"Recreated readable: {str(recreated_point)}")
    print(f"Recreated representation: {repr(recreated_point)}")
except Exception as e:
    print(f"Error during eval: {e}")

Output:

Readable: Point at (10.5, 20.1)
Representation: DataPoint(10.5, 20.1)
Recreated readable: Point at (10.5, 20.1)
Recreated representation: DataPoint(10.5, 20.1)

Solution 8: Simple __repr__ Implementation

A basic __repr__ can simply return a descriptive string.

class PipelineStage:
    """Represents a stage in a data processing pipeline."""

    def __init__(self, name: str):
        self.name = name

    def __repr__(self) -> str:
        return f"PipelineStage('{self.name}')"

# Example Usage
stage = PipelineStage("DataIngestion")
print(stage)

Output:

PipelineStage('DataIngestion')

Solution 9: Using objprint for Easy Formatting

For situations where you want a pretty-printed output without manually writing __str__ or __repr__ for every class, libraries like objprint offer a convenient solution.

from objprint import add_objprint

class NetworkInterface:
    def __init__(self, name: str, ip: str, mac: str):
        self.name = name
        self.ip = ip
        self.mac = mac

@add_objprint
class Server:
    def __init__(self, server_name: str, interfaces: list[NetworkInterface]):
        self.server_name = server_name
        self.interfaces = interfaces

# Example Usage
eth0 = NetworkInterface("eth0", "192.168.1.50", "00:1A:2B:3C:4D:5E")
eth1 = NetworkInterface("eth1", "10.0.0.10", "00:1A:2B:3C:4D:5F")
server_instance = Server("app-server-01", [eth0, eth1])

print(server_instance)

Solution 10: Python Dataclasses for Automatic Representation

Since Python 3.7, dataclasses provide a very convenient way to auto-generate __repr__ (and other methods) for your classes.

from dataclasses import dataclass, field

@dataclass
class TaskItem:
    task_name: str
    priority: int = 5 # Default priority
    is_completed: bool = field(default=False, repr=False) # Hide from repr

# Example Usage
task1 = TaskItem("Write report", 3)
task2 = TaskItem("Review code")

print(task1)
print(task2)

Output:

TaskItem(task_name='Write report', priority=3)
TaskItem(task_name='Review code', priority=5)

Solution 11: Instantiating Classes for print()

A subtle but important point, often overlooked, is that print() expects an instance of a class, not the class definition itself. The parentheses are crucial for instantiation.

class Resource:
    def __init__(self, resource_id: str, type: str):
        self.resource_id = resource_id
        self.type = type

    def __str__(self) -> str:
        return f"Resource: {self.resource_id} ({self.type})"

# Example Usage - Correct Instantiation
resource_instance = Resource("RES999", "Database")
print(resource_instance)

# Incorrect: Trying to print the class directly
# print(Resource) # This would show <class '__main__.Resource'>

Output:

Resource: RES999 (Database)

FAQs on Python Class Representation

Q: What is the primary difference between __str__ and __repr__ in Python

ANS: The __str__ method provides a user-friendly, readable string representation of an object, often used with print(). The __repr__ method aims for an unambiguous, developer-focused representation, ideally an expression that could recreate the object, used in interactive sessions or with repr(). If __str__ is absent, Python uses __repr__.

Q: How does Python determine which string representation to use when printing an object

ANS: When you use print(obj), Python first checks if obj.__str__ is defined. If it is, __str__ is called. If __str__ is not defined, Python falls back to calling obj.__repr__.

Q: Can __repr__ be used to recreate an object

ANS: Yes, ideally. A well-implemented __repr__ should return a string that is a valid Python expression. When this string is evaluated using eval(), it should produce an object identical to the original. This is valuable for debugging and serialization. See Solution 8 for an example.

Q: What happens if neither __str__ nor __repr__ is defined for a class

ANS: If neither method is defined, Python provides a default string representation that typically includes the class name and the object’s memory address, like <__main__.ClassName object at 0x...>.

Q: Is it necessary to define both __str__ and __repr__

ANS: It’s highly recommended. Defining both ensures your objects behave predictably across different contexts: __str__ for user-facing output and __repr__ for developer clarity and debugging. If you only define __repr__, it will be used for both scenarios.

Q: How can I easily get a readable representation of all an object's attributes

ANS: You can implement a __str__ or __repr__ method that iterates through the object’s __dict__ attribute to display its attributes and their values. Libraries like objprint or Python’s dataclasses can also automate this process. Check Solution 9 and Solution 10 .
