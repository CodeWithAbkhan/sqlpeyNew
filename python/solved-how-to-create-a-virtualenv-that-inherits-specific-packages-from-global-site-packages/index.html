Solved: How to Create a Virtualenv that Inherits Specific Packages from Global Site Packages

Creating a virtual environment that selectively inherits specific packages from your global site packages can greatly enhance your workflow, especially when dealing with libraries like Matplotlib that may have complex dependencies. Here are the top strategies to achieve that with practical examples.

Problem Statement

When setting up a virtual environment, the common approach using virtualenv with the --system-site-packages option allows access to globally installed packages. However, if you only want to inherit a specific library, you might be wondering how to do this without manually copying files or risking conflicts with other packages.

Solution 1: Using --system-site-packages with Overinstalling

You can initiate your virtual environment utilizing the command:

virtualenv --system-site-packages myenv

Once created, proceed to overinstall any specific libraries you need. For instance, if you’re looking to add Matplotlib:

source myenv/bin/activate
pip install -U matplotlib

This approach enables your virtual environment to access the global site packages while allowing you to manage it further by adding specific libraries.

Solution 2: Adjusting Your Environment Variables

For users on Ubuntu 20.04, particularly with Python 3.8, you might encounter issues with local installations that interfere with your virtual environment. You can resolve this by setting an environment variable. You can do this by entering the following command in your Bash terminal:

export PYTHONNOUSERSITE="true"

This command will prevent Python from adding the user site directory to sys.path, streamlining your package management and preventing conflicts during installations.

Solution 3: Combining System Site Packages with Package Installation

Another effective strategy is to install your virtual environment as follows:

virtualenv --system-site-packages myenv

Then, update your desired library using:

pip install -U matplotlib

This ensures that you are installing the latest version of Matplotlib available, while also retaining access to the specific packages from your global site packages.

Alternative Methods

If you’re seeking alternative approaches, consider using venv, a module available in Python 3:

python3 -m venv myenv --system-site-packages

This similarly allows inheritance from the global packages, though the virtualenv tool remains popular for its additional features.

Practical Example

Let’s say you would like to set this up without hassle:

  1. Create your virtual environment: 
    virtualenv --system-site-packages myenv
  2. Activate your environment: 
    source myenv/bin/activate
  3. Install Matplotlib: 
    pip install -U matplotlib
  4. Verify installation: 
    python -c "import matplotlib; print(matplotlib.__version__)"

This example illustrates setting up and managing a virtual environment effectively, ensuring you inherit only what’s necessary.

FAQs on Creating a Virtualenv that Inherits Specific Packages from Global Site Packages

Q: Can I inherit only certain packages instead of all?

A: Currently, there isn’t a straightforward way to inherit selective packages alone with virtualenv. Using --system-site-packages allows access to all global packages, but you can control subsequent installations using pip.

Q: Is it possible to use conda with similar functionality?

A: Yes, conda environments support package management and can inherit from the base environment using options similar to --system-site-packages in virtualenv.
