“Calculate Euclidean Distance in Python: Efficient Methods and Examples”

The Euclidean distance, a fundamental metric in mathematics and computer science, represents the straight-line distance between two points in a multi-dimensional space. Calculating this efficiently is crucial for many applications, including machine learning algorithms, data analysis, and scientific simulations. Python, with its rich ecosystem of libraries, offers several powerful methods to achieve this.

Let’s explore various approaches, from straightforward vector operations to specialized library functions.

Solutions for Computing Euclidean Distance

Here are several accepted methods to calculate the Euclidean distance:

Solution 1: Using numpy.linalg.norm

This is a direct and efficient method leveraging NumPy’s linear algebra capabilities. The Euclidean distance is equivalent to the L2 norm.

import numpy

# Assuming 'a' and 'b' are NumPy arrays representing points
# Example:
a = numpy.array([1, 2, 3])
b = numpy.array([4, 5, 6])

dist = numpy.linalg.norm(a - b)
print(f"Distance using linalg.norm: {dist}")

This approach is favored for its conciseness and performance when working with NumPy arrays. For a deeper dive into the mathematical underpinnings, one might consult resources like Introduction to Data Mining .

Solution 2: Utilizing scipy.spatial.distance.euclidean

SciPy provides specialized distance functions, including euclidean, which is optimized for this calculation.

from scipy.spatial import distance

# Example points as tuples
a = (1, 2, 3)
b = (4, 5, 6)

dst = distance.euclidean(a, b)
print(f"Distance using scipy.spatial.distance.euclidean: {dst}")

This method is also highly recommended, especially if you’re already utilizing SciPy for other spatial operations.

Solution 3: Performance Comparison with perfplot and einsum

For scenarios involving large datasets and a need for optimal performance, comparing different implementations is key. The einsum function in NumPy offers a flexible way to perform these calculations, often yielding significant speedups when data is organized optimally.

The fastest variant identified in performance tests often involves organizing data into a shape like (3, n) and using einsum.

import numpy
import perfplot
from scipy.spatial import distance

# Example of an optimized calculation using einsum
def calculate_distance_einsum(a, b):
    a_min_b = a - b
    return numpy.sqrt(numpy.einsum("ij,ij->i", a_min_b, a_min_b))

# Setup for perfplot (demonstration purposes)
def setup_perfplot(n):
    a = numpy.random.rand(n, 3)
    b = numpy.random.rand(n, 3)
    out0 = numpy.array([a, b]) # (2, n, 3)
    out1 = numpy.array([a.T, b.T]) # (2, 3, n)
    return out0, out1

# Example usage of the optimized function
a_data = numpy.array([[1, 2, 3], [4, 5, 6]])
b_data = numpy.array([[7, 8, 9], [10, 11, 12]])
dist_einsum = calculate_distance_einsum(a_data, b_data)
print(f"Distances using einsum: {dist_einsum}")

Solution 4: Optimized Function Calls and Avoiding sqrt

Python function call overhead can impact performance. Optimizing by passing functions as default arguments and, more importantly, by comparing squared distances can significantly speed up operations, especially in loops or when sorting.

import numpy

# Optimized function call
def distance_optimized(pointA, pointB, _norm=numpy.linalg.norm):
    return _norm(pointA - pointB)

# Example: Avoiding sqrt for comparisons
def distance_sq(left, right):
    """Returns the square of the distance between left and right."""
    return numpy.sum((left - right)**2)

# Example usage for sorting or range checks
origin = numpy.array([0, 0, 0])
points = [numpy.array([1, 1, 1]), numpy.array([2, 2, 2])]

# Sorting based on squared distance
sorted_points = sorted(points, key=lambda p: distance_sq(origin, p))
print(f"Points sorted by squared distance: {sorted_points}")

# Filtering within a range
range_limit = 3
range_sq = range_limit**2
points_in_range = [p for p in points if distance_sq(origin, p) <= range_sq]
print(f"Points within range {range_limit}: {points_in_range}")

Solution 5: Custom Distance Function with numpy.sum and numpy.sqrt

A direct implementation of the Euclidean distance formula using NumPy operations.

import numpy

def dist(x, y):
    return numpy.sqrt(numpy.sum((x - y)**2))

# Example points
a = numpy.array([1, 2, 3])
b = numpy.array([4, 5, 6])

dist_a_b = dist(a, b)
print(f"Distance using custom dist function: {dist_a_b}")

Solution 6: Using math.dist (Python 3.8+)

Python 3.8 introduced math.dist for direct Euclidean distance calculation, making it highly accessible.

import math

# Example points as tuples or lists
point1 = (1, 2, 6)
point2 = (-2, 3, 2)

distance_math = math.dist(point1, point2)
print(f"Distance using math.dist: {distance_math}")

list_point1 = [1, 2, 6]
list_point2 = [-2, 3, 2]

print(f"Distance using math.dist with lists: {distance_math_list}")

This is often the most straightforward method for basic use cases. For more details, refer to the Python 3.8 math module documentation .

Solution 7: Pure Python Calculation (No NumPy)

For environments where NumPy is not available, a pure Python implementation using zip and sqrt is possible, though generally less performant.

from math import sqrt

# Example points as tuples
a = (1, 2, 3)
b = (4, 5, 6)

# Note: This requires points to be iterable and of the same length
# print(sqrt(sum((a - b)**2 for a, b in zip(a, b)))) # This would fail as tuples don't support direct subtraction

# Corrected pure Python approach:
dist_pure_python = sqrt(sum((x - y)**2 for x, y in zip(a, b)))
print(f"Distance using pure Python: {dist_pure_python}")

Solution 10 & 11: Dot Product Approach

Leveraging the dot product property where dot(v, v) = ||v||^2 for a vector v.

import numpy

a = numpy.array([1, 2, 3])
b = numpy.array([4, 5, 6])

# Using dot product
tmp = a - b
sum_squared = numpy.dot(tmp.T, tmp)
result_dot = numpy.sqrt(sum_squared)
print(f"Distance using dot product (1): {result_dot}")

# Alternative dot product notation
distance_dot_alt = (numpy.dot(a - b, a - b))**0.5
print(f"Distance using dot product (2): {distance_dot_alt}")

Solution 15: List Comprehension for Pure Python

A more Pythonic way to implement the pure Python distance calculation.

    return sum([(x-y)**2 for (x,y) in zip(v1,v2)])**(0.5)

v1 = [1, 2, 3]
v2 = [4, 5, 6]

Solution 16: math.hypot for 3D

math.hypot can be chained for 3D calculations, providing robustness against underflow/overflow.

import math

xa, ya, za = 1, 2, 3
xb, yb, zb = 4, 5, 6

dist_hypot = math.hypot(math.hypot(xa-xb, ya-yb), za-zb)
print(f"Distance using chained math.hypot: {dist_hypot}")

Solution 18: Handling Integer Dtypes and Overflow/Underflow

When working with integer arrays (e.g., image data with uint8), standard subtraction can lead to incorrect results due to overflow. Using np.maximum and np.minimum, or casting to float, provides safer calculations. OpenCV’s cv2.norm is also an option for image data.

import numpy
# import cv2 # Uncomment if using OpenCV

a1 = numpy.array([1], dtype='uint8')
a2 = numpy.array([2], dtype='uint8')

# Incorrect subtraction leading to overflow
# print(numpy.linalg.norm(a1 - a2))

# Safer calculation for uint8
dist_uint8 = numpy.linalg.norm(numpy.maximum(a1, a2) - numpy.minimum(a1, a2))
print(f"Safe distance for uint8: {dist_uint8}")

# For signed integers, cast to float
signed_int_a = numpy.array([-1, 2], dtype='int8')
signed_int_b = numpy.array([1, -2], dtype='int8')
dist_signed_float = numpy.linalg.norm(signed_int_a.astype("float") - signed_int_b.astype("float"))
print(f"Safe distance for signed int (cast to float): {dist_signed_float}")

# Using OpenCV
# dist_cv2 = cv2.norm(a1, a2, cv2.NORM_L2)

Solution 23: SciPy cdist for Distance Matrices

When computing distances between all pairs of points from two collections, SciPy’s cdist is highly efficient. NumPy broadcasting offers alternatives but is often slower.

import numpy as np
from scipy.spatial import distance

a_points = [(1, 2, 3), (3, 4, 5), (2, 3, 6)]
b_points = [(1, 2, 3), (4, 5, 6)]

# Using scipy.spatial.distance.cdist
dsts1 = distance.cdist(a_points, b_points)
print("Distances using scipy.spatial.distance.cdist:")
print(dsts1)

# NumPy broadcasting alternatives
dsts2 = np.linalg.norm(np.array(a_points)[:, None] - b_points, axis=-1)
dsts3 = np.sqrt(np.sum((np.array(a_points)[:, None] - b_points)**2, axis=-1))

print(f"Are NumPy alternatives close to cdist? {np.allclose(dsts1, dsts2) and np.allclose(dsts1, dsts3)}")

Solution 24: Element-wise Multiplication and Summation

A step-by-step approach using NumPy operations.

import numpy as np

def findEuclideanDistance(a, b):
    euclidean_distance = a - b
    euclidean_distance = np.sum(np.multiply(euclidean_distance, euclidean_distance))
    euclidean_distance = np.sqrt(euclidean_distance)
    return euclidean_distance

a_vec = np.array([1, 2, 3])
b_vec = np.array([4, 5, 6])
print(f"Distance using element-wise multiply/sum: {findEuclideanDistance(a_vec, b_vec)}")

Solution 25: math.hypot vs. Manual sqrt(sum(square)) for Overflow/Underflow

This solution highlights the numerical stability of math.hypot for extreme values compared to manual calculations which can suffer from overflow or underflow.

import math
import numpy as np

# Test cases for overflow/underflow
i_large, j_large, k_large = 1e+200, 1e+200, 1e+200
i_small, j_small = 1e-200, 1e-200

# math.hypot (robust)
print(f"math.hypot (large): {math.hypot(i_large, j_large, k_large)}")
print(f"math.hypot (small): {math.hypot(i_small, j_small)}")

# Manual calculation (prone to issues)
try:
    print(f"Manual sqrt(sum(square)) (large): {np.sqrt(np.sum(np.array([i_large, j_large, k_large])**2))}")
except RuntimeWarning as e:
    print(f"Manual calculation (large) resulted in: {e}")

print(f"Manual sqrt(sum(square)) (small): {np.sqrt(i_small**2 + j_small**2)}") # Demonstrates underflow to 0.0

Solution 26: numexpr for Performance

For highly optimized numerical expressions, numexpr can offer speed advantages over standard NumPy operations, especially on multi-core processors.

import numexpr as ne
import numpy as np

a_val = np.array([1, 2, 3])
b_val = np.array([4, 5, 6])

a_min_b = a_val - b_val
# Using numexpr for efficient calculation
dist_numexpr = np.sqrt(ne.evaluate("sum((a_min_b)**2)"))

FAQs on Calculate Euclidean Distance in Python

Q: What is the simplest way to calculate Euclidean distance in Python

ANS: For Python 3.8 and later, math.dist(point1, point2) is the most straightforward and recommended method. If you are working with NumPy arrays, numpy.linalg.norm(array1 - array2) is also very concise and efficient.

Q: Which method is fastest for calculating many distances

ANS: For calculating distances between many pairs of points, scipy.spatial.distance.cdist is generally very fast. NumPy’s einsum or numexpr can also offer excellent performance, especially when data is structured appropriately. Benchmarking your specific use case is always advised. You can explore more on Python performance tips .

Q: Can I calculate distance without NumPy

ANS: Yes, you can use pure Python with the math.sqrt function and list comprehensions or zip to iterate through coordinates, as shown in solutions 7 and 15. However, these pure Python methods are typically much slower than NumPy or SciPy for numerical operations. For general Python development, you might find other useful snippets at sqlpey.com .

Q: What happens if my data has large numbers causing overflow

ANS: When dealing with very large or very small numbers that might cause overflow or underflow during intermediate calculations (like squaring), math.hypot or numpy.hypot are more numerically stable options than direct sqrt(sum(square)) calculations. For image data with uint8 dtypes, use np.maximum(x, y) - np.minimum(x, y) before calculating the norm to avoid incorrect results.
