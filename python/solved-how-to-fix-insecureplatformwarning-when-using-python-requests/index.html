Solved: How to Fix the InsecurePlatformWarning When Using Python Requests

When working with Python’s requests module for API calls, you may encounter an error warning titled InsecurePlatformWarning. This warning signifies that a true SSLContext object is not available, which inhibits urllib3 from configuring SSL connections appropriately. This can lead to issues when making secure HTTP requests. The problem often arises in environments using Python versions below 2.7.9, which lack proper SSL configurations.

What Causes the InsecurePlatformWarning?

The root of the InsecurePlatformWarning is primarily linked to using an outdated version of Python (like 2.7.3) along with versions of the requests library that don’t support newer SSL/TLS features. When attempting to execute REST GET requests, your code may throw errors like the following:

import requests

header = {'Authorization': 'Bearer...'}
url = az_base_url + az_subscription_id + '/resourcegroups/Default-Networking/resources?' + az_api_version
r = requests.get(url, headers=header)

The error you might see in your terminal looks like this:

/usr/local/lib/python2.7/dist-packages/requests/packages/urllib3/util/ssl_.py:79:
InsecurePlatformWarning: A true SSLContext object is not available. 
This prevents urllib3 from configuring SSL appropriately and may cause certain SSL connections to fail.
For more information, see https://urllib3.readthedocs.org/en/latest/security.html#insecureplatformwarning.
InsecurePlatformWarning

Top 4 Ways to Solve the InsecurePlatformWarning

If you find yourself encountering the InsecurePlatformWarning, there are several approaches to resolve the issue, particularly if you are bound to use an older version of Python.

Method 1: Upgrade Python (Recommended)

The best solution is to upgrade your Python installation to at least version 2.7.9 or higher. This will ensure that SSL/TLS is supported appropriately. If possible, consider moving to Python 3.x for improved features and security.

Method 2: Downgrade Your Requests Version

If upgrading Python isn’t feasible, you may suppress the warnings by downgrading your requests library to version 2.5.3. This version does not trigger the InsecurePlatformWarning.

pip install requests==2.5.3

This method is a short-term fix, but it’s worth considering if you need a quick resolution without immediate upgrade.

You can find more details about the bug fixes here: Bugfix disclosure and see when the warning was introduced: Request changes .

Method 3: Install Missing Libraries

Another alternative is to ensure you have the necessary libraries installed, which may have been omitted in older setups. For Python 2.7, you can install:

pip install pyOpenSSL ndg-httpsclient pyasn1

This combination can help configure a proper SSL context without downgrading your requests.

Method 4: Suppress the Warning

If none of the above methods are feasible due to constraints, you can choose to suppress the warnings. However, this is not advisable as it might expose you to risks.

import requests
import warnings

warnings.filterwarnings('ignore', message='.*InsecurePlatformWarning.*')

## Your existing request code goes here

While this will mute the warning, make sure to understand the underlying risks involved with ignoring SSL issues.

Practical Example

Here’s a complete example using the second method, showing how to suppress the warning by downgrading:

pip install requests==2.5.3

Then you can use the requests library normally:

import requests

header = {'Authorization': 'Bearer...'}
url = "https://api.example.com/resources"
response = requests.get(url, headers=header)

print(response.content)

This strategy mitigates the SSL context issues while maintaining the usability of the requests library.

FAQs on How to Fix InsecurePlatformWarning When Using Python Requests

Q: What is the InsecurePlatformWarning?

A: The InsecurePlatformWarning is a notification indicating that a proper SSLContext object is not available, which may lead to insecure SSL connections when using the requests library in Python.

Q: How do I upgrade my Python version?

A: You can download the latest version of Python from the official Python website and follow the installation instructions provided there.

Q: Is it safe to suppress the warning?

A: Suppressing the warning might conceal underlying security vulnerabilities. It’s generally safer to address the root cause rather than ignoring it.

Q: What should I do if I cannot upgrade Python?

A: If upgrading is not an option, consider downgrading the requests library, installing necessary SSL packages, or using alternative methods that avoid the issue.
