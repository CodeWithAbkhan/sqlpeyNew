“Python Asynchronous HTTP Requests with Requests Library Alternatives”

How can a Python developer execute multiple HTTP requests concurrently or truly asynchronously when the standard requests library inherently operates synchronously? When dealing with numerous network operations, waiting for each request to complete sequentially becomes a significant performance bottleneck. Several effective strategies and alternative libraries offer solutions for speeding up these I/O-bound tasks.

Leveraging requests with Hooks for Post-Processing (Legacy Approach)

For versions of the requests library prior to v0.13.0, asynchronous mapping could be achieved using the async submodule, which has since been deprecated or moved. The key mechanism involved defining a function to act as an event hook upon response reception.

Important Note: This pattern is historical for the requests library. Modern usage should favor dedicated async libraries or grequests.

To process responses after they arrive asynchronously using this older structure:

  1. Define a Task Function: Create a function that accepts a response object.
  2. Attach as a Hook: Register this function using the 'response' hook in the request call.
  3. Map the Actions: Use async.map on a list of these prepared actions.

Here is an example structure reflecting this legacy usage:

from requests import async
# If using requests > v0.13.0, consider switching to 'grequests' as shown below.

target_urls = [
    'https://www.python-requests.org',
    'https://httpbin.org/get',
    'https://www.python-guide.org',
]

# Function to execute upon receiving a response
def process_url_result(response):
    """Prints the URL of the completed request."""
    print(f"Processed URL: {response.url}")

# List to assemble asynchronous tasks
async_task_list = []

for url in target_urls:
    # Attach the hook; note the function name without parentheses
    action = async.get(url, hooks={'response': process_url_result})
    async_task_list.append(action)

# Execute all tasks concurrently (within the constraints of the older model)
async.map(async_task_list)

Utilizing grequests: The Asynchronous Extension

A widely adopted solution that builds upon the popular requests library is grequests. This package handles the asynchronous execution, often leveraging gevent.

Installation:

pip install grequests

Usage Pattern:

You construct a generator of request objects and then pass this collection to grequests.map().

import grequests
import time

request_targets = [
    'https://www.heroku.com',
    'https://tablib.org',
    'https://httpbin.org/delay/1',  # Introduce a small delay to test concurrency
    'https://www.python-requests.org',
]

start_time = time.time()

# Build the stack of get requests
request_stack = (grequests.get(u, timeout=5) for u in request_targets)

# Send the stack concurrently
responses = grequests.map(request_stack)

end_time = time.time()

print(f"All requests finished in: {end_time - start_time:.2f} seconds")
# Expected output time should be close to 1 second, not 4+ seconds.
print(f"First response status: {responses[0].status_code}")

grequests is often fast but involves dependencies like gevent and potential complexity regarding dependency resolution or “monkey patching.”

True Asynchronicity with aiohttp and asyncio

For Python 3.5+ and true non-blocking I/O, the aiohttp library combined with Python’s built-in asyncio is the preferred robust path. This avoids external patching and offers granular control over concurrency and error handling.

The following implements three scenarios to showcase the performance difference: purely synchronous, synchronous wrapped in asyncio (which remains slow), and genuinely asynchronous using aiohttp.

import time
import asyncio
import requests
import aiohttp
from asgiref import sync

# Helper decorator to time execution
def timed(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        print(f'{func.__name__:<30} started')
        result = func(*args, **kwargs)
        duration = f'{func.__name__:<30} finished in {time.time() - start:.2f} seconds'
        print(duration)
        return result
    return wrapper

@timed
def sync_requests_get_all(urls):
    """Performs synchronous GET requests using requests.Session."""
    with requests.Session() as session:
        return [session.get(url).json() for url in urls]

@timed
def async_requests_get_all_wrapped(urls):
    """Synchronous requests wrapped in asyncio (still slow)."""
    session = requests.Session()
    def blocking_get(url):
        return session.get(url).json()
    
    # Convert blocking call to awaitable
    async_blocking_get = sync.sync_to_async(blocking_get)

    async def run_gather():
        return await asyncio.gather(*[async_blocking_get(url) for url in urls])
    
    return sync.async_to_sync(run_gather)()

@timed
def async_aiohttp_get_all(urls):
    """Truly asynchronous requests using aiohttp."""
    async def fetch_all():
        async with aiohttp.ClientSession() as session:
            async def fetch(url):
                async with session.get(url) as response:
                    return await response.json()
            
            return await asyncio.gather(*[fetch(url) for url in urls])
    
    # Run the async function from sync context
    return sync.async_to_sync(fetch_all)()

if __name__ == '__main__':
    # Using an endpoint that forces a 3-second delay per request

Concurrency via Thread Pooling with concurrent.futures

If avoiding complex async frameworks is preferred, using Python’s standard library concurrent.futures.ThreadPoolExecutor provides a managed way to run blocking I/O tasks (like standard requests.get) in parallel threads, often yielding performance close to grequests without heavy external dependencies.

import requests
import concurrent.futures
import time

url_set = [
    'http://example.com',
    'http://docs.python.org',
    'http://google.com'
]

def fetch_url_content(url, timeout_sec=10):
    """Worker function for the thread pool."""
    try:
        response = requests.get(url, timeout=timeout_sec)
        response.raise_for_status()  # Raise HTTPError for bad responses (4xx or 5xx)
        return f"Success: {url} Status: {response.status_code}"
    except Exception as e:
        return f"Failure: {url} Error: {e}"

max_threads = 10
results_ok = 0
results_err = 0

print(f"Starting threaded requests with {max_threads} workers...")
start = time.time()

with concurrent.futures.ThreadPoolExecutor(max_workers=max_threads) as executor:
    # Submit tasks, mapping the future object back to its URL
    future_to_url = {
        executor.submit(fetch_url_content, u): u for u in url_set
    }
    
    for future in concurrent.futures.as_completed(future_to_url):
        url = future_to_url[future]
        try:
            result = future.result()
            print(result)
            if "Success" in result:
                results_ok += 1
            else:
                results_err += 1
        except Exception as exc:
            print(f'{url} generated an exception during processing: {exc}')
            results_err += 1

print(f"\nCompleted. Total OK: {results_ok}, Total Errors: {results_err}. Time taken: {time.time() - start:.2f}s")

This thread-based approach is often simpler for debugging than deep asyncio stacks while achieving parallelism for I/O waits.

Exploring httpx: The Modern Async/Sync HTTP Client

httpx is a next-generation HTTP client supporting both synchronous and asynchronous operations using the modern async/await syntax natively, similar to aiohttp.

Asynchronous Example with httpx:

import httpx
import asyncio

async def fetch_with_httpx(url):
    """Fetches a URL asynchronously using httpx."""
    async with httpx.AsyncClient(timeout=15.0) as client:
        response = await client.get(url)
        # Perform response processing here
        return response.status_code

async def run_httpx_concurrently(urls):
    # Use asyncio.gather to run coroutines concurrently
    tasks = [fetch_with_httpx(url) for url in urls]
    results = await asyncio.gather(*tasks)
    return results

if __name__ == '__main__':
    urls_to_hit = ["http://google.com", "http://wikipedia.org", "http://example.com"]
    
    # You run the top-level async function using asyncio.run (Python 3.7+)
    try:
        status_codes = asyncio.run(run_httpx_concurrently(urls_to_hit))
        print(f"HTTPX Status Results: {status_codes}")
    except RuntimeError as e:
        # Handles environments where an event loop is already running
        print(f"Could not run asyncio.run directly: {e}. Try wrapping execution.")

For advanced pipeline control, libraries like aiostream can be combined with httpx to manage task limits and complex processing flows, as shown in advanced patterns involving stream.starmap.

Specialized Libraries for Background Processing

Libraries designed for background execution can also simplify this. For instance, requests-futures uses a session object that initiates background threads for each call, returning a Future object immediately.

from requests_futures.sessions import FuturesSession
import time

session = FuturesSession(max_workers=5)

# Requests are initiated in the background immediately
future_alpha = session.get('http://httpbin.org/get?id=alpha')
future_beta = session.get('http://httpbin.org/get?id=beta')

print("Requests launched, now waiting for results...")
time.sleep(0.5) # Allow some time for background work

# .result() blocks only until *that specific* future is complete
response_alpha = future_alpha.result()
print(f"Alpha Status: {response_alpha.status_code}")

response_beta = future_beta.result()
print(f"Beta Status: {response_beta.status_code}")

Finally, for server-like scenarios where you listen for requests and must respond asynchronously without blocking, using grequests.send(req) within a loop allows scheduling requests without waiting for them, triggering a defined callback hook upon completion, akin to Node.js event handling.

FAQs on Python Asynchronous HTTP Requests

Q: What is the main drawback of using grequests

ANS: While fast, grequests often relies on gevent and may introduce performance complexities or dependency conflicts due to its patching approach on standard libraries.

Q: Can I use the requests library async functions now

ANS: The requests.async module is largely deprecated or moved. True async functionality requires libraries like aiohttp or httpx.

Q: Is ThreadPoolExecutor truly asynchronous

ANS: No, ThreadPoolExecutor uses threads to achieve concurrency, running blocking code in parallel threads. It is not the cooperative multitasking of asyncio.

Q: Which solution is best for Python 3.7+

ANS: httpx combined with asyncio.run() is generally recommended for modern, clean, and performant asynchronous network operations.
