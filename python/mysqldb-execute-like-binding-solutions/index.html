“MySQLdb Execute Parameter Binding for LIKE Queries in Python”

When working with Python’s MySQLdb library (or related forks like mysqlclient), supplying parameters to the execute method requires careful attention to formatting, particularly when dealing with string operations like LIKE. Incorrectly formatted arguments lead to errors or unexpected SQL execution.

A common scenario involves querying a database using a LIKE pattern, such as searching for records where an email address contains a specific substring:

Incorrect Attempt (Often seen in older patterns):

# Potential source of issues or unexpected behavior
search_term = "user@example.com"
# Passing the raw string directly as the second argument
cur.execute("SELECT * FROM records WHERE email LIKE '%s'", search_term)

The fundamental requirement for parameterized queries in many DB-API compliant drivers is that all substitution values must be provided as an iterable (like a list or a tuple), even if there is only one value.

Preferred Method: Using a List or Tuple for Single Parameters

The accepted practice dictates passing the variables as a sequence.

Solution Adhering to DB-API Specification:

When using %s placeholders in the SQL string, the driver expects the parameters in the second argument to be a container.

import MySQLdb 

# Assume 'cur' is a valid cursor object
search_value = "partial_domain.net"

# Note: The driver handles the quoting and literal conversion.
# Do NOT include the '%' wildcards in the SQL string placeholder if you intend 
# to pass the full pattern in the parameter, or include them if passing only the base string.

# If you need 'LIKE %substring%', pass the pattern components separately:
pattern_to_search = f"%{search_value}%" 

# Correct execution using a list:
cur.execute("SELECT * FROM records WHERE email LIKE %s", [pattern_to_search]) 

# Alternative using a tuple:
cur.execute("SELECT * FROM records WHERE email LIKE %s", (pattern_to_search,))

Key Insight: The execute method interprets the second argument as a structure holding all necessary substitution values. For a single item, it must still be iterable.

Avoiding Manual String Interpolation and SQL Injection Risks

A critical concern when dealing with dynamic SQL is security. Manually formatting queries using Python’s % operator or f-strings with user-provided input is highly susceptible to SQL Injection Attacks .

Using Parameterization for Safety (Recommended Approach):

Always let the database driver handle the substitution. If you are filtering on a value, place the %s placeholder directly in the query structure.

# Secure way to query based on an exact match (or use LIKE %s as shown above)
user_id = 101
cur.execute("SELECT name, status FROM users_data WHERE id = %s", (user_id,))

For more complex scenarios involving INSERT statements:

user_name = 'AliceSmith'
user_age = 30
user_gender = 'F'
insert_tuple = (user_name, user_age, user_gender)

# Note the data type format specifiers might be implicitly handled by the driver, 
# but using %s is generally safest for all string/text types.
cur.execute("INSERT INTO user_profiles (name, age, sex) VALUES (%s, %s, %s)", insert_tuple)

MySQLdb API Version Dependency: A Historical Look

The strictness regarding the required iterable format has evolved across different versions of MySQLdb (or mysqlclient).

Older versions (e.g., 1.2.3) sometimes tolerated passing a plain string for a single parameter:

# Might work on very old MySQLdb versions, but should be avoided:
# cur.execute("SELECT * FROM foo WHERE bar = %s", 'baz')

Newer versions (e.g., 1.2.5 and above) strictly enforce the iterable requirement:

# Required behavior in modern versions:
cur.execute("SELECT * FROM foo WHERE bar = %s", ['baz'])

If encountering inconsistencies, especially in environments like older Ubuntu releases that ship with specific package versions, forcing the installation of an older, known-good version via PyPI might be an option for legacy codebases:

pip install MySQL-python==1.2.3

Advanced Diagnostics: Literal Conversion

When debugging or exploring the driver’s behavior, you can inspect how the connection object (con) converts Python objects to their literal, database-safe string representations using con.literal().

If you are attempting to build the query string manually (which is discouraged), you might observe that con.literal(search) correctly quotes the input, but you must still ensure the resulting string is correctly integrated into the query execution context.

For example, relying on con.literal without proper execute parameterization can lead to syntax errors if double quotes are introduced inappropriately:

# Example of manual literal application (for inspection, not primary usage)
# search = "test"
# "SELECT * FROM records WHERE email LIKE %s" % con.literal(search) 
# -> Might result in "SELECT * FROM records WHERE email LIKE 'test'" which is correct if %s is expected without quotes.

Standardizing on PEP 8 Alignment

For clean, maintainable code, structure your execution calls clearly by separating the SQL statement and the arguments list, consistent with general Python style guides like PEP 8.

# Clean structure:
db_connection = MySQLdb.connect(...) # Established connection
cursor = db_connection.cursor()

search_filter = "admin%"
sql_statement = "SELECT user_id, username FROM system_users WHERE username LIKE %s;"
arguments = [search_filter]

cursor.execute(sql_statement, arguments)

FAQs on MySQLdb Execute Parameter Binding Solutions

Q: Why does my MySQLdb execute fail when I pass a single string instead of a list

ANS: The DB-API specification requires that parameters passed to cursor.execute() must be an iterable (list or tuple), even for a single value substitution. Providing a raw string violates this iterable requirement in newer driver versions.

Q: Is it safe to use the '%' character in the SQL string placeholder %s for LIKE queries

ANS: Yes, using %s as the placeholder is the secure, parameterized way. The driver replaces %s with the literal value provided in the argument list, automatically handling necessary escaping and quoting, which prevents SQL injection attacks.

Q: What should I include in the argument list for LIKE '%value%'

ANS: You should include the full pattern string you wish to match in the iterable. For example, if searching for ‘data’, you pass ['%data%'] if the SQL is WHERE column LIKE %s.
