“Python Requests: Effective Strategies for Sending Files via POST”

When interacting with APIs using Python’s requests library, constructing a POST request to upload a file requires careful handling of the request body, especially when mixing file data with other form fields. How can developers reliably send files, manage metadata like filenames and content types, and handle large files efficiently?

Here are several proven techniques for file transmission using requests.

Sending Files as Multipart Form Data

The standard approach for sending files alongside other form data involves the files parameter. This signals to requests that the request should be encoded as multipart/form-data.

Scenario 1: Basic File Upload with Other Fields

If you intend upload_file to represent the actual file content alongside metadata like 'DB', 'OUT', and 'SHORT', structure your payload like this:

import requests

URL = 'https://your-api-endpoint.com/upload'
FILE_PATH = 'data_payload.txt'

# Prepare the file payload for multipart encoding
files_payload = {
    'upload_file': open(FILE_PATH, 'rb')
}

# Additional form data fields
form_values = {
    'DB': 'photcat', 
    'OUT': 'csv', 
    'SHORT': 'short'
}

# Execute the POST request
response = requests.post(URL, files=files_payload, data=form_values)
print(f"Status Code: {response.status_code}")

When using the files dictionary, requests automatically sets the appropriate MIME headers. For the file field, the filename is included in the Content-Disposition header:

# Demonstration of how requests formats the multipart body for a file
import requests

# Ensure 'demo_content.txt' exists for this test
with open('demo_content.txt', 'wb') as f:
    pass

files_test = {'upload_file': open('demo_content.txt', 'rb')}
prepared_request = requests.Request('POST', 'http://example.com/test', files=files_test).prepare()

# Output shows the filename embedded in the header
print(prepared_request.body.decode('ascii'))
# Snippet of expected output:
# Content-Disposition: form-data; name="upload_file"; filename="demo_content.txt"

Scenario 2: Controlling Filename and Content Type

For greater control over the metadata transmitted for a specific file part, use a tuple structure within the files dictionary. This tuple can contain the filename, file contents (or file object), and an optional content type.

To set an alternative filename (foobar.txt) and a specific MIME type (text/x-spam):

import requests

FILE_PATH = 'file.txt'

custom_files = {
    'upload_file': ('foobar.txt', open(FILE_PATH, 'rb'), 'text/x-spam')
}

# If the 4th tuple element (extra headers) is omitted, it works fine.
response = requests.post(URL, files=custom_files)

Alternative for Complete Body Content: If the intention is for the entire POST body to consist solely of the file content (without any multipart encoding or other fields), bypass the files parameter and pass the file stream directly to the data parameter. You might need to explicitly set the Content-Type header in this case.

Simple Single File Upload

The requests library simplifies uploading a single file when no auxiliary form data is needed:

API_URL = 'http://httpbin.org/post'

with open('report.xls', 'rb') as report_file:
    files_simple = {'file': report_file}
    
    response = requests.post(API_URL, files=files_simple)
    print(response.text)

Efficient Handling of Large Files (Streaming Uploads)

For very large files, reading the entire content into memory before sending can exhaust resources. requests supports streaming uploads by passing an open file object directly to the data parameter:

# Client Side: Streaming Upload
STREAM_URL = 'http://some.url/streamed'
LARGE_FILE = 'massive-body'

with open(LARGE_FILE, 'rb') as large_f:
    # Pass the file stream directly to 'data' for streaming
    requests.post(STREAM_URL, data=large_f)

Server Side Handling (Example with Flask): To process these large streams without loading the entire file into memory on the server, specialized parsers are necessary. For Flask, utilizing werkzeug.formparser.parse_form_data with a custom stream_factory helps manage memory efficiently, saving parts of the file directly to temporary locations:

# Server Side Example (Flask/Werkzeug)
from werkzeug.formparser import parse_form_data
import tempfile
import flask

def custom_stream_factory(total_content_length, filename, content_type, content_length=None):
    # Creates a temporary file to stream content into
    tmpfile = tempfile.NamedTemporaryFile('wb+', prefix='flaskapp', suffix='.nc')
    flask.current_app.logger.info(f"Start receiving file to: {tmpfile.name}")
    return tmpfile

@flask.app.route("/upload", methods=['POST'])
def upload_file_streamed():
    # Use the custom factory to avoid memory spikes
    stream, form, files = parse_form_data(
        flask.request.environ, 
        stream_factory=custom_stream_factory
    )
    
    for fil in files.values():

        # Process fil.stream.name (the path to the temporary file)
        
    return 'OK', 200

Mixing Files and Metadata: Request vs. Server Interpretation

When sending both files (via files) and accompanying metadata (via data), remember that the server will typically read the metadata from the form data structure, not as JSON.

Client side implementation:

# Client sending both file and form data
files_mix = {'upload_file': open('file.txt','rb')}
metadata = {'DB': 'photcat', 'OUT': 'csv', 'SHORT': 'short'}

requests.post(URL, files=files_mix, data=metadata) 
# NOTE: requests.post(url, files=files, json=values) will NOT work here as 'json=' sends a JSON body, interfering with multipart encoding.

On the receiving Flask server, access form data using request.form. Attempting to use request.get_json() will yield nothing if the request is correctly formatted as multipart/form-data.

# Server Side Interpretation (Flask)
@flask.app.route("/sftp-upload", methods=["POST"])
def process_upload():
    if flask.request.method == "POST":
        # Access form key/value pairs here, as mimetype is multipart, not application/json
        form_data = flask.request.form  
        print(form_data)  # Accesses DB, OUT, SHORT fields
        # request.get_json() would return None
    return 'OK', 200

Alternative Request Methods (PUT)

While POST is common for uploads, some RESTful APIs expect file updates via PUT. When using PUT, if you are sending raw binary content (like an image), avoid the files parameter and pass the binary data directly to the data parameter, ensuring the correct Content-Type header is set for the file type:

# Sending raw binary data via PUT
PUT_URL = 'foobar.com/api/image-1'
BASIC_AUTH = requests.auth.HTTPBasicAuth('someuser', 'password123')
IMAGE_FILE = 'image-1.png'

headers_put = {'Content-Type': 'image/png'} 

with open(IMAGE_FILE, 'rb') as img_data:
    response = requests.put(PUT_URL, auth=BASIC_AUTH, data=img_data, headers=headers_put)

Comprehensive Upload Example with Headers and Metadata

A highly specified upload often requires authentication headers and explicit metadata sent via data:

import requests
import os

API_ROOT = "http://localhost:80"
TOKEN = "sdfJHKsdfjJKHKJsdfJKHJKysdfJKHsdfJKHs" # Placeholder token

def upload_engagement_file(filepath):
    url = API_ROOT + "/api/files"
    
    # Authorization Header
    auth_header = {"Authorization": f"Bearer {TOKEN}"}
    
    with open(filepath, "rb") as fobj:
        file_content = fobj.read()
        file_basename = os.path.basename(filepath)
        
        # Structure the file payload: (filename_on_server, file_bytes)
        file_to_upload = {"file": (str(file_basename), file_content)}
        
        # Additional metadata sent in the 'data' payload
        extra_info = {"fullPath": filepath}
        
        upload_response = requests.post(
            url, 
            headers=auth_header, 
            files=file_to_upload, 
            data=extra_info
        )
        
    return upload_response

Server-Side File Retrieval Context (Django Example)

If the client sends the file, the server needs to know how to retrieve the content stream from the incoming request structure. For instance, in Django, uploaded files are typically accessed via request.FILES:

# Django Server Retrieval Example
from django.http import HttpResponse
import os

# Assuming the client used 'upload_file' as the key in the 'files' dictionary
def receive_file(request):
    if request.method == 'POST' and 'upload_file' in request.FILES:
        uploaded_file = request.FILES['upload_file']
        
        with open('received_' + uploaded_file.name, 'wb') as f:
            # Access the underlying file stream
            f.write(uploaded_file.file.read())
            
        return HttpResponse("OK", status=200)
    return HttpResponse("Bad Request", status=400)

FAQs on Python Requests File Upload Strategies

Q: What is the main difference between using data and files in requests post

ANS: The data parameter sends standard form-encoded or JSON payloads. The files parameter forces the request to use multipart/form-data encoding, essential for sending binary file content and associated metadata correctly.

Q: Can I send JSON data alongside a file upload

ANS: Yes, send the file via the files parameter and the non-file key/value pairs via the data parameter. Do not use the json parameter, as it switches the entire request body encoding away from multipart.

Q: How do I control the filename sent to the server

ANS: When using the tuple format in the files dictionary, the first element of the tuple specifies the filename that appears in the server’s headers, e.g., ('server_name.log', file_object).

Q: Is streaming upload the same as using the files parameter

ANS: No. Streaming uploads, using the file object in the data parameter, are for sending the raw file content as the entire body. The files parameter is for standard HTTP file uploads formatted as multipart/form-data.
