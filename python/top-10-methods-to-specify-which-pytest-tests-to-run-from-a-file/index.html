How can you efficiently specify and run particular tests using pytest from a file?

In scenarios where you’ve got a file such as foo.txt, which lists the specific tests you want to execute (like tests_directory/foo.py::test_001 or tests_directory/bar.py::test_some_other_test), it’s crucial to understand the strategies available for managing test execution using pytest.

Key Questions Surrounding Test Selection

  1. Is there a way to run several tests that don’t share a common pattern, located in different directories? The use of pytest -k <pattern> allows for only one pattern at a time.

  2. Can I specify multiple patterns and individual test files for each one? This flexibility is vital for nuanced testing strategies.

  3. Is it possible to feed a list of exact test paths from a file directly to pytest?

  4. Are there pytest hooks that can facilitate customized test selection using external inputs?

Solution 1: Basics of Running Tests

Pytest provides several methods to specify which tests to run from the command line.

Running Tests in Various Contexts

  • Run All Tests in a Module:

    pytest tests/test_mod.py

  • Run All Tests in a Directory:

    pytest tests/testing/

  • Run Tests by Keyword Expressions:

    pytest -k "MyClass and not method"

    This command executes tests that fit the specified string expression while excluding the indicated tests.

  • Run Specific Tests by Node IDs: Each test has a unique nodeid. To run a specific test:

    pytest tests/test_mod.py::test_func

Solution 2: Granular Test Control

Let’s explore how to refine your test execution based on various requirements:

  • Run All Tests in the Project:

    pytest

  • Run Tests by Directory:

    pytest tests/my-directory/

  • Run Specific Test Functions:

    pytest tests/my-directory/test_demo.py::test_specific_function

  • Execute Test Classes and Methods:

    • For a test class:
    pytest tests/my-directory/test_demo.py::TestClassName
    • For a specific method in a test class:
    pytest tests/my-directory/test_demo.py::TestClassName::test_specific_method

Solution 3: Advanced Test Selection with Keywords

Utilizing keyword expressions can enable complex test selection:

  • Run Tests Based on Name: 
    pytest -v -k "_raises"

This command runs tests with names containing the specified substring, utilizing logic operators like and, or, and not.

Solution 4: Identifying Specific Instances

When test names conflict across classes:

pytest tests.py -k "TestClassName and test_method_name"

This strategy is effective for precision when dealing with overlapping test names.

Solution 5: Utilizing External Test Lists

If you prefer to manage a test list externally, you can execute tests from a file that contains your desired tests:

pytest $(tr '\n' ' ' < foo.txt)

This command allows pytest to parse a list of test paths formatted within your foo.txt.

Solution 6: Hook Functions for Custom Input

Using the pytest_collect_file() function, one can parse content from .txt or .yaml files where tests are specified. For a practical example, check this link .

Solution 7: Simplified Test Execution

From pytest version 8.2 onward, specifying arguments directly from a file can be done as follows:

pytest @foo.txt

This executes all tests detailed within foo.txt.

Solution 8: Running Tests with Symlink Trickery

If test imports require specific directory structures, create a symbolic link to your test files. For example:

ln -s tests_directory/foo.py subset_tests_directory

Then navigate to subset_tests_directory and execute:

pytest

Solution 9: Handling Common Test Cases

To efficiently manage common test names without conflicts, you can remove the file names for clarity:

cut -d : -f 3 foo.txt > FAILED_TESTS.txt
pytest -k "$(awk '$1=$1' RS= OFS=' or ' FAILED_TESTS.txt)"

By using commands like awk, you can format your test execution strings seamlessly.

Solution 10: Consolidation and Alternative Methods

Consider combining symlinking alongside creating a carefully structured test directory to maintain clarity and ease of access.

FAQs on Top 10 Methods to Specify Which Pytest Tests to Run from a File

Q: How can I run multiple tests from different files using pytest?

A: You can specify the exact test paths in a text file and use a command like pytest $(tr '\n' ' ' < your_test_file.txt) to run them.

Q: Can I run tests that have similar names but are in different classes?

A: Yes, by using the -k option, you can specify both the class name and test method together, like so: pytest tests.py -k "TestClassName and test_method_name".

Q: What are pytest hooks, and how can they help?

A: Pytest hooks, like pytest_collect_file(), allow you to customize how tests are collected, enabling you to read test specifications from files in formats like YAML or TXT.

Q: Is it possible to run a specific test function within a class?

A: Absolutely! You can run a specific test function by appending :: followed by the function name to your test command, such as pytest test.py::TestClassName::test_function.

Q: Can I run tests based on patterns?

A: Yes, pytest allows you to run tests based on name patterns using the -k option, enabling the combination of conditions with and, or, and not to filter tests.
