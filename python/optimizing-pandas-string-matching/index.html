High-Performance Methods for Multiple Substring Containment Checks in Pandas

When the goal is to determine if any string in a Pandas Series contains any of the patterns listed in a separate collection, which method yields the best speed?

Method 1: Leveraging Escaped Regex with str.contains()

For retaining a pure-Pandas solution, utilizing regular expressions offers substantial performance gains over iterative str.contains(regex=False). The crucial step here is ensuring that the literal substrings are treated as characters and not as regex meta-characters. This is achieved via the re.escape() function.

  1. Escape Literals: Each string in the search list must be escaped.

    import re
# Assume 'lst' is the list of substrings to find
escaped_patterns = [re.escape(s) for s in lst]

  2. Construct the Pattern: Join the escaped substrings using the regex OR operator (|).

    search_pattern = '|'.join(escaped_patterns)

  3. Apply the Mask: Use df[col].str.contains() once with the compiled pattern, often disabling case sensitivity for broader matching.

    # Assuming 'df' is your DataFrame and 'col' is the target column name
match_mask = df[col].str.contains(search_pattern, case=False)

Performance Insight: In benchmark scenarios involving 50,000 rows (where no matches occurred, forcing a full check), this method was observed to be approximately 2.7x faster than the original iterative approach, clocking in around 1.58 seconds for the test case. This is significantly better than the initial method’s ~4.3 seconds.

Method 2: Utilizing the Aho-Corasick Algorithm for Speed

For maximum speed in multi-pattern searching, the Aho-Corasick algorithm is highly favored. This algorithm builds a finite automaton (a trie structure with failure links) optimized for finding all occurrences of a dictionary of keywords in a text stream simultaneously. The time complexity is near-linear: $O(n + m + p)$, where $n$ is the total length of the search strings, $m$ is the length of the text being searched, and $p$ is the number of matches found.

The Python library pyahocorasick provides an efficient wrapper around a C implementation.

  1. Setup the Automaton: Initialize the automaton and add all lowercased patterns. Building the automaton requires preprocessing time but pays off massively during the search phase.

    import ahocorasick

A = ahocorasick.Automaton(ahocorasick.STORE_INTS)

# Add words to the automaton, generally using a consistent case
for word in lst:
    A.add_word(word.lower())

A.make_automaton() # Finalize structure for searching

  2. Apply to Series: Since the automaton operates on strings, you must apply a function row-wise or preprocess the series to a consistent case before applying the iterator check.

    # Pre-process the column to lower case for case-insensitive search
lower_col = df[col].str.lower()

# Apply the search; convert the iterator output (which yields matches) to a boolean
ahocorasick_mask = lower_col.apply(lambda x: bool(list(A.iter(x))))

Performance Insight: Benchmarks frequently show the Aho-Corasick approach to be substantially faster. In one comparison against the original method, it achieved a speed factor exceeding 30x, completing the 50K-row test in roughly 140 ms.

import numpy as np
import random
import pandas as pd
import ahocorasick
import re

random.seed(321)

def orig(col, lst):
    mask = np.logical_or.reduce([col.str.contains(i, regex=False, case=False) 
                                 for i in lst])
    return mask

def using_regex(col, lst):
    """https://stackoverflow.com/a/48590850/190597 (Alex Riley)"""
    esc_lst = [re.escape(s) for s in lst]
    pattern = '|'.join(esc_lst)
    mask = col.str.contains(pattern, case=False)
    return mask

def using_ahocorasick(col, lst):
    A = ahocorasick.Automaton(ahocorasick.STORE_INTS)
    for word in lst:
        A.add_word(word.lower())
    A.make_automaton() 
    col = col.str.lower()
    mask = col.apply(lambda x: bool(list(A.iter(x))))
    return mask

N = 50000
# 100 substrings of 5 characters
lst = [''.join([chr(random.randint(0, 256)) for _ in range(5)]) for _ in range(100)]

# N strings of 20 characters
strings = [''.join([chr(random.randint(0, 256)) for _ in range(20)]) for _ in range(N)]
# make about 10% of the strings match a string from lst; this helps check that our method works
strings = [_ if random.randint(0, 99) &lt; 10 else _+random.choice(lst) for _ in strings]

col = pd.Series(strings)

expected = orig(col, lst)
for name, result in [('using_regex', using_regex(col, lst)),
                     ('using_ahocorasick', using_ahocorasick(col, lst))]:
    status = 'pass' if np.allclose(expected, result) else 'fail'
    print('{}: {}'.format(name, status))

Alternative: Generating a Binary Vector (0 or 1)

If the required output is a binary vector (1 for match, 0 for no match) instead of a boolean mask, you can adapt the regex approach.

Consider finding occurrences of “at” or “Og” (case-insensitive) in a Pandas Series v:

import re
v = pd.Series(['cAt', 'dog', 'the rat', 'mouse', 'froG'])
pattern = 'at|Og'
v_length = len(v)

# 1. Get the boolean series (True/False)
s = v.str.contains(pattern, flags=re.IGNORECASE, regex=True)

# 2. Create a vector of ones
v_binary_template = [1] * v_length

# 3. Multiply the template by the boolean series (True becomes 1, False becomes 0)
result_vector = v_binary_template * s

print(result_vector)
# Output:
# 0    1
# 1    0  <-- Correction: 'dog' does not contain 'at' or 'Og'.
# 2    1
# 3    0
# 4    1
# dtype: int64

Self-Correction on Example Output: In the original example, dog was listed as outputting 1. However, if the search pattern is strictly 'at|Og', dog should result in 0. The multiplication [1, 1, 1, 1, 1] * [True, False, True, False, True] yields the correct binary result: [1, 0, 1, 0, 1].

FAQs on Optimizing Pandas String Matching

Q: What is the primary benefit of using reescape before joining substrings

ANS: Using re.escape() prevents any special characters within your literal search substrings (like ., *, +, etc.) from being interpreted as regular expression meta-characters, ensuring they are matched literally.

Q: Is Aho-Corasick suitable for very small lists of patterns

ANS: While Aho-Corasick offers asymptotic superiority, for extremely small lists of patterns (e.g., less than 10), the overhead of building the automaton might make the escaped regex approach slightly faster or comparable. Its main advantage shines with hundreds or thousands of patterns.

Q: Can I use str.contains with regex=False for multiple patterns

ANS: Yes, you can pass a list to str.contains(regex=False). However, this performs an iterative check, which is the slowest option—equivalent to the original method benchmarked here. The speed gain comes from compiling the patterns into a single regex string or using an algorithm like Aho-Corasick.
