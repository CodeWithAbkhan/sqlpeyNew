“Configuring Multiple Python Kernels in Jupyter Notebooks: Anaconda and Virtual Environments”

How does an expert technical practitioner establish distinct Python 2 and Python 3 execution environments—specifically IPython kernels—within a Jupyter Notebook server, especially when dealing with Anaconda distributions or isolated virtual environments? Various approaches exist to ensure these different interpreters are selectable upon creating a new notebook.

Approach 1: Leveraging Anaconda’s nb_conda_kernels (Anaconda >= 4.1.0)

For users operating Anaconda version 4.1.0 or newer, the process simplifies significantly due to the integrated nb_conda_kernels package. This utility automatically detects and registers kernels residing in separate Conda environments.

The initial step involves creating the required environments, ensuring ipykernel is specified during creation:

# Create a dedicated Python 2.7 environment with ipykernel
conda create -n py27_env python=2.7 ipykernel

# Create a dedicated Python 3.6 environment with ipykernel
conda create -n py36_env python=3.6 ipykernel

After executing these creation commands, a simple restart of the Jupyter Notebook server should reveal these new environments as selectable kernel options via the graphical interface. Remember that packages must be installed directly into their respective environments post-creation, as detailed in the official Conda documentation on environment management .

Approach 2: Manual Kernel Registration for Older Anaconda or Custom Setups

Users on older Anaconda releases or those preferring explicit control can manually register kernels. This involves activating the environment, installing necessary components, and then registering the kernel specification.

Configuring the Python 2.7 Kernel

# Setup the environment
conda create -n py27_manual python=2.7
conda activate py27_manual

# Install notebook dependencies and register the kernel
conda install notebook ipykernel
ipython kernel install --user --name=py2_spec --display-name="Python 2.7 Manual"

conda deactivate

Configuring the Python 3.6 Kernel

# Setup the environment
conda create -n py36_manual python=3.6
conda activate py36_manual

# Install notebook dependencies and register the kernel
conda install notebook ipykernel
ipython kernel install --user --name=py3_spec --display-name="Python 3.6 Manual"

conda deactivate

To customize the presentation name in the Jupyter interface, the --name (internal spec name) and --display-name (user-facing name) flags for ipython kernel install are useful. Consult ipython kernel install --help for all available parameters.

Approach 3: Utilizing Standalone Virtual Environments (Non-Anaconda)

For environments without Conda, separate Python interpreters (e.g., Python 2 and Python 3 installed system-wide or via other package managers) can be linked to Jupyter using virtualenv. Assume Jupyter itself is installed in an environment accessible to the user.

First, secure the necessary system development packages (Ubuntu example):

sudo apt-get update
sudo apt-get install python2.7-dev python3.6-dev python-pip python3-pip

Next, prepare the environments using virtualenv and register the kernels:

# Install virtualenv utility globally or per user
python3 -m pip install virtualenv --user

Approach 4: Direct Python 2 Kernel Setup from a Running Python 3 Jupyter Session

If the primary Jupyter instance runs under Python 3, one can explicitly instruct the Python 2 executable to install its kernel specification. This often requires having ipykernel accessible via the Python 2 path.

# Execute via the Python 2 interpreter path
python2 -m pip install ipykernel
python2 -m ipykernel install --user --name=py2_direct --display-name="Python 2 via Python 3 Kernel Host"

Refer to the official IPython kernel installation documentation for detailed command references.

Approach 5: Manual kernel.json Specification (Advanced)

For precise control, especially when the execution path is non-standard (like in certain MacPorts setups or specific system installations), manually defining the kernel.json file is an option.

Create the kernel specification directory structure: mkdir -p ~/.ipython/kernels/python3_manual_spec

Then, create the kernel.json file inside this directory with the desired execution arguments. Note the use of python3 as the direct executable call:

{
    "display_name": "IPython (Python 3 Custom)", 
    "language": "python", 
    "argv": [
        "python3", 
        "-c", "from IPython.kernel.zmq.kernelapp import main; main()", 
        "-f", "{connection_file}"
    ], 
    "codemirror_mode": {
        "version": 2, 
        "name": "ipython"
    }
}

Restarting the server makes this custom entry available. This method is useful for ensuring the correct interpreter path is invoked when standard auto-detection fails.

Approach 6: Environment-Specific Registration within Conda Virtual Environments

If working within a Conda environment and nb_conda_kernels is not surfacing the kernel, explicit registration within that environment is required, similar to the manual steps but executed inside the target Conda shell:

# Assuming 'test2' is the active Conda environment name
pip install --user ipykernel
python -m ipykernel install --user --name=test2_kernel --display-name="Test Environment Python"

This command registers the kernel specification associated with the currently active Python executable (python inside the environment).

FAQs on Configuring Multiple Python Kernels in Jupyter

Q: How do I ensure my PyCharm console uses the correct interpreter kernel

ANS: PyCharm typically manages interpreter association based on the Project Interpreter settings. If Python 2 and Python 3 environments are correctly configured as separate interpreters in PyCharm settings, the Python Console will automatically select the corresponding IPython kernel when you switch the Project Interpreter setting between Python 2 and Python 3 configurations.

Q: What is the recommended way to update kernels after adding new packages to an environment

ANS: After installing new packages into an existing virtual environment or Conda environment, you usually need to re-run the ipython kernel install --user command (or equivalent within the environment) to update the kernel specification metadata if package paths or dependencies have changed significantly, although often a simple server restart suffices if the environment integrity remains intact.

Q: Is ipython kernelspec install-self still a viable command

ANS: The command ipython kernelspec install-self is largely deprecated. The contemporary and recommended instruction for installing kernelspecs is ipython kernel install or, when using modern tooling, often python -m ipykernel install.
$ cd /opt/local/Library/Frameworks/Python.framework/Versions/2.7/bin
$ sudo ./ipython kernelspec install-self
$ cd /opt/local/Library/Frameworks/Python.framework/Versions/3.4/bin
$ sudo ./ipython kernelspec install-self
