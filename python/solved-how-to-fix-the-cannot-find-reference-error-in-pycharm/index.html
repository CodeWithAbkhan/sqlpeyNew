Question:

I am currently working on a project using PyCharm, which has the following directory structure:

-- Sources
 |-- __init__.py
 |-- Calculators
 |-- __init__.py
 |-- Filters.py
 |-- Controllers
 |-- __init__.py
 |-- FiltersController.py
 |-- Viewers
 |-- __init__.py
 |-- DataVisualization.py
 |-- Models
 |-- __init__.py
 |-- Data

I have left all __init__.py files—except for the one located at the top of the Sources directory—blank. However, I am receiving multiple warnings that say:

Cannot find reference ‘xxx’ in __init__.py

For instance, in my FiltersController.py, I have the following code:

import numpy.random as npr

bootstrap = npr.choice(image_base.data[max(0, x-2):x+3, max(0, y-2):y+3].flatten(), size=(3, 3), replace=True)

This triggers the warning:

Cannot find reference ‘choice’ in __init__.py

I am trying to understand what this warning means and how to correctly implement my code in Python to avoid such issues.

Solutions:

Solution 1:

One reason for this warning is a small bug in PyCharm. It appears that PyCharm expects referenced modules to be included in an __all__ = [] statement.

Should you include the __all__ statement in your modules for better coding practices? As young Spock once pondered, “It is morally praiseworthy but not morally obligatory.”

To navigate around this, consider disabling the inspection either globally or for specific functions or statements. Here’s how:

  • Position your cursor over the errored reference (‘choice’ in your example).
  • Use the intention menu, typically accessed with Alt+Enter (or your personalized shortcut).
  • Navigate through the submenu to select the appropriate action.

While PyCharm may flag these minor bugs, its advantages generally outweigh such inconveniences. If you’re open to alternatives, you might also consider trying out the Spyder IDE for Python.

Note: I initially thought these warnings were solely related to the __all__ construct, but they generally signal ‘Unresolved References.’ This check can be incredibly beneficial. For flexibility, you can disable inspection at the statement level by employing either the intention menu or adding # noinspection PyUnresolvedReferences before the statement causing the warning.

Solution 2:

To effectively resolve these warnings, it’s advantageous to reference Python’s Importing from a Package . The relevant convention states:

The import statement utilizes a list named __all__ to determine which modules to import when from package import * is executed. It is the responsibility of the package author to maintain this list.

Thus, PyCharm provides warnings to aid authors in managing how modules are imported when their package is called. Rather than viewing this as a glitch, it’s more accurately a helpful feature. You can eliminate these warnings by listing the modules that should be imported in your __all__ declaration, as shown:

In your __init__.py:

from . import MyModule1, MyModule2, MyModule3
__all__ = [MyModule1, MyModule2, MyModule3]

By implementing this, you’ll have the capability to ctrl+click on these imported module names throughout your project, enabling direct navigation to their declarations, which can be very beneficial during development.

Practical Example:

Suppose you have three modules: MathOperations, StringOperations, and FileOperations, you might set your __init__.py like this:

from . import MathOperations, StringOperations, FileOperations
__all__ = ["MathOperations", "StringOperations", "FileOperations"]

Alternative Ways:

Aside from managing the __all__ statement, another way to tackle the warning is by restructuring your imports or ensuring that your project directories are correctly configured to acknowledge your module paths.

FAQs on Solved: How to Fix the ‘Cannot find reference’ Error in PyCharm

Q: Why am I receiving unresolved reference warnings in PyCharm?

A: These warnings usually occur because PyCharm cannot locate the referenced module, often due to missing entries in the __all__ list or misconfigured project directories.

Q: How can I disable warnings for unresolved references?

A: You can disable warnings either globally in the settings or on a case-by-case basis by using the intention menu to suppress specific warnings.

Q: What is the purpose of `__init__.py` files?

A: __init__.py files signal to Python that the directory should be treated as a package. They can also define what modules are imported when the package is loaded.

Q: Is it mandatory to declare `__all__` in Python packages?

A: While it’s not mandatory, declaring __all__ is beneficial for maintaining a clear and manageable import structure within your Python packages.
