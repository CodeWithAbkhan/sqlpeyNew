When managing Python projects, it’s common to encounter the dilemma of generating a requirements.txt file that only reflects the packages essential for your current project. When you execute the command pip freeze > requirements.txt, the output lists all installed packages in your environment, which can lead to unwanted dependencies being included, such as frameworks like Django in projects where they aren’t relevant.

This post explores two effective methods for generating a project-specific requirements file, ensuring that you only include the dependencies needed for your current work. Let’s understand how you can streamline this process.

Method 1: Using pipreqs

pipreqs is a handy tool that scans your project directory for imports and generates a requirements.txt file based on the packages your project uses directly.

Steps to implement pipreqs:

pip install pipreqs

Once installed, navigate to your project directory and run:

pipreqs /path/to/your/project

This command analyzes your Python files, identifies the libraries you’ve imported, and creates a requirements.txt file that accurately reflects these dependencies.

Example

Assuming your project directory structure looks like this:

my_project/
    main.py
    utils.py

If both main.py and utils.py import requests, after running pipreqs, your requirements.txt might look like this:

requests==2.24.0

Method 2: Utilizing pigar

While pipreqs is effective, many developers, including myself, find pigar to be even more powerful. Pigar not only generates a requirements file based on installed packages but also provides extra insights on where each package is utilized in your codebase.

Installing and using pigar:

Start by installing pigar:

pip install pigar

Then, you can generate your requirements file by executing:

pigar

This command will create a requirements.txt similar to pipreqs, but with added information about the import paths of each package, making it easier to troubleshoot dependencies later on.

Example

If your project consists of the following files:

my_other_project/
    app.py
    helper.py

Running pigar might yield:

requests==2.24.0  # Imported in app.py
numpy==1.18.5  # Imported in helper.py

This clarity can be incredibly advantageous for larger projects where managing dependencies becomes complex.

Alternative Approaches to Dependency Management

If you’re frequently dealing with this issue, consider employing a virtual environment. By using virtualenv, you can create isolated environments for each project, containing only the packages you need. Here’s a quick refresher:

  1. Create a virtual environment:
python -m venv myenv
  1. Activate it:
  • On Windows:
myenv\Scripts\activate
  • On macOS/Linux:
source myenv/bin/activate
  1. Install packages specific to your project:

Now, any package you install using pip will only affect this environment, keeping your global installations clean.

FAQs on Top 2 Methods to Generate Project Specific Requirements with Pip

Q: How does pipreqs determine which packages to include in the requirements file?

A: pipreqs analyzes the import statements in your Python files to list only the required packages.

Q: Can I use pipar and pipreqs together?

A: Yes, you can use both tools for different purposes; pipreqs for a straightforward requirements file and pigar for more detailed dependency insights.
