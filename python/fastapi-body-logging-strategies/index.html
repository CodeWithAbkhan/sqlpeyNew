“FastAPI Request/Response Body Logging Strategies: Middleware vs. Custom Route”

When building APIs with frameworks like FastAPI, a common requirement emerges: capturing and logging the full content of incoming requests and outgoing responses. Since HTTP request and response bodies are processed as streams, reading them—for instance, using request.body()—consumes the stream, leaving nothing for the subsequent endpoint handler or response process. How can we reliably inspect and log this data? Below are several accepted technical approaches to tackle this challenge.

Method 1: HTTP Middleware for Global Interception

One approach involves using FastAPI’s built-in middleware system, decorated with @app.middleware("http"). This layer intercepts every request before it hits any endpoint and allows manipulation before returning the response.

Consuming and Preserving the Request Body

If you read the request body inside the middleware (e.g., using await request.body() or await request.stream()), it becomes unavailable downstream.

Crucial Note for FastAPI Versions: Before FastAPI version 0.108.0, a workaround involving recreating the request object (request._receive = receive after setting a new body) was necessary. With FastAPI 0.108.0 and newer, this issue is largely resolved, and often, simply reading the body once is sufficient if you re-pass the request correctly.

For stream validation or when needing chunk-by-chunk processing (especially for large bodies), using await request.stream() and manually assembling the bytes is preferred:

@app.middleware('http')
async def process_body_stream(request: Request, call_next):
    request_chunks = []
    async for chunk in request.stream():
        request_chunks.append(chunk)
    req_body_bytes = b''.join(request_chunks)
    
    # If a workaround for older versions was needed, it would go here.
    
    response = await call_next(request)
    
    # ... Response handling below

Consuming and Rebuilding the Response Body

Similarly, the response body iterator (response.body_iterator) must be consumed to log it. This requires iterating through the chunks, joining them, and then creating a new Response object that uses these captured bytes.

To prevent blocking the user while logging, use a BackgroundTask to execute the logging routine after the response has been sent to the client.

Working Example using Middleware

from fastapi import FastAPI, Response, Request
from starlette.background import BackgroundTask
import logging

app = FastAPI()
logging.basicConfig(filename='app_activity.log', level=logging.INFO)

def execute_logging(request_payload: bytes, response_payload: bytes):
    # Example: Decode and log payloads
    try:
        req_str = request_payload.decode('utf-8')
    except UnicodeDecodeError:
        req_str = str(request_payload)
        
    try:
        res_str = response_payload.decode('utf-8')
    except UnicodeDecodeError:
        res_str = str(response_payload)
        
    logging.info(f"Request Data: {req_str}")
    logging.info(f"Response Data: {res_str}")

@app.middleware('http')
async def logging_middleware(request: Request, call_next):
    # 1. Handle Request Body
    request_bytes = await request.body()
    
    # 2. Process Request
    response = await call_next(request)
    
    # 3. Handle Response Body
    response_chunks = []
    async for chunk in response.body_iterator:
        response_chunks.append(chunk)
    response_bytes = b''.join(response_chunks)
    
    # Schedule logging in the background
    task = BackgroundTask(execute_logging, request_bytes, response_bytes)
    
    # Return a new response using the captured content, attaching the background task
    return Response(
        content=response_bytes, 
        status_code=response.status_code, 
        headers=dict(response.headers), 
        media_type=response.media_type, 
        background=task
    )

@app.post("/data_input")
def process_data(payload: dict):
    return {"received": payload, "status": "processed"}

Caveat: Large Payloads and Streaming

If requests or responses involve very large files or StreamingResponse objects that exceed available server RAM, reading the entire body into memory (as done above) is problematic. For large streams, logging might be infeasible or lead to memory exhaustion or timeouts on the client or reverse proxy side. If you anticipate large transfers, you should specifically exclude those routes from this generic logging middleware, perhaps by checking request.url.path.

Method 2: Custom APIRoute Class for Targeted Logging

If you only need logging on specific endpoints rather than globally, applying middleware to every route is overkill. A more granular solution involves subclassing fastapi.routing.APIRoute and specifying this custom class when initializing an APIRouter. This lets you apply the logic only to routes registered under that specific router.

Implementation via Custom Route Handler

This method overrides get_route_handler to inject custom logic around the original endpoint execution.

Working Example using Custom APIRoute

from fastapi import FastAPI, APIRouter, Response, Request, status
from starlette.background import BackgroundTask
from fastapi.routing import APIRoute
from starlette.responses import StreamingResponse
from typing import Callable
import logging
import httpx

app = FastAPI()
router_with_logging = APIRouter(route_class=LoggingRoute)
logging.basicConfig(filename='route_specific.log', level=logging.INFO)

def log_interaction(req_bytes, res_bytes):
    logging.info(f"Request Log: {req_bytes}")
    logging.info(f"Response Log: {res_bytes}")

class LoggingRoute(APIRoute):
    def get_route_handler(self) -> Callable:
        original_handler = super().get_route_handler()

        async def custom_handler(request: Request) -> Response:
            
            req_body_data = await request.body()
            response = await original_handler(request)
            
            original_background_tasks = response.background

            if isinstance(response, StreamingResponse):
                # Handle StreamingResponse separately: drain iterator before logging
                body_chunks = []
                async for chunk in response.body_iterator:
                    body_chunks.append(chunk)
                res_body_data = b''.join(body_chunks)
                
                # Recreate response object, since body_iterator was consumed
                new_response = Response(
                    content=res_body_data, 
                    status_code=response.status_code, 
                    headers=dict(response.headers), 
                    media_type=response.media_type
                )
            else:
                res_body_data = response.body
                new_response = response
            
            # Attach logging task
            log_task = BackgroundTask(log_interaction, req_body_data, res_body_data)
            
            # Ensure existing background tasks are preserved/added
            if original_background_tasks:
                original_background_tasks.add_task(log_task)
                new_response.background = original_background_tasks
            else:
                new_response.background = log_task
                
            return new_response
            
        return custom_handler

# Route demonstrating the logging mechanism
@router_with_logging.post("/secure_endpoint")
def handle_secure_post(data: dict):
    return {"result": "processed", "data_echo": data}

# Route NOT using the router_with_logging decorator (e.g., using @app) will skip this logging.
@app.get("/")
def health_check():
    return {"service": "running"}

app.include_router(router_with_logging)

Addressing Streaming Responses in Custom Routes

When dealing with StreamingResponse, you must specifically iterate over response.body_iterator to collect the content for logging. As seen in the example above, this consumes the stream, necessitating the creation of a new Response object with the collected content before attaching the background logging task. Routes returning streams (like file downloads or video feeds) should often be excluded from this custom route class if they are very large, as discussed previously.

Method 3: Base Middleware with Reconstructed Streams (Advanced)

For scenarios where strict control over the ASGI lifecycle events is needed, or when dealing with versions or complexities that make standard body reading unreliable, a custom implementation inheriting from starlette.middleware.base.BaseHTTPMiddleware can be employed. This involves manually intercepting and reconstructing the request and response by simulating the underlying message flow (http.request, http.response.start, etc.).

This solution often involves defining a wrapper request class (RequestWithBody) to feed the captured body back into the request stream for downstream handlers:

# Snippet demonstrating the concept for request reconstruction
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.types import Scope, Message

class RequestWithBody(Request):
    def __init__(self, scope: Scope, body: bytes) -> None:
        # Replaces the standard receive function with one that yields the stored body
        super().__init__(scope, self._receive_with_body)
        self._body = body
        self._body_returned = False

    async def _receive_with_body(self) -> Message:
        if self._body_returned:
            return {"type": "http.disconnect"}
        else:
            self._body_returned = True
            return {"type": "http.request", "body": self._body, "more_body": False}

class CustomLoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 1. Capture Request Body
        request_body_bytes = await request.body()
        
        # Reconstruct request so the endpoint handler gets the body data
        reconstructed_request = RequestWithBody(request.scope, request_body_bytes)

        # 2. Process Request
        response = await call_next(reconstructed_request)
        
        # 3. Capture Response Body (requires draining StreamingResponse as in Method 1/2)
        # ... logic to drain response and extract content/status/headers ...
        
        # 4. Log collected data
        # logger.info(f"Request: {request_body_bytes}, Response: {response_content}")

        # 5. Return a new standard Response using the captured data
        return Response(response_content_bytes, response_status, response_headers)

This complex method ensures maximum compatibility but demands careful handling of ASGI message types and stream closure.

Alternative for Timing: Custom Route Handler (See Solution 2)

If the primary goal is only to measure response time, customizing APIRoute (as shown in the second accepted solution example with TimedRoute) is much simpler than logging the full body content, as it only requires inspecting time.time() before and after calling the original handler.

FAQs on FastAPI Request Response Body Logging

Q: Why is request.body() empty after being read once

ANS: HTTP request bodies are transmitted over streams. When you call await request.body() or iterate over request.stream(), the data is pulled from the stream. If another component tries to read it afterwards, the stream is exhausted, resulting in an empty body. Solutions involve caching the body bytes and recreating the request object for downstream use.

Q: Can I use middleware for logging if I have StreamingResponse

ANS: Yes, but you must manually iterate through the response.body_iterator in the middleware to collect all chunks, join them into a single byte object, and then return a new standard Response containing those collected bytes, attaching the original StreamingResponse’s background tasks if they exist.

Q: How to limit body logging to specific endpoints in middleware

ANS: You can implement checks inside the middleware using request.url.path against a list of targeted routes. Alternatively, using a custom APIRoute class tied only to a specific APIRouter instance achieves this route limitation more cleanly.

from fastapi import FastAPI, APIRouter, Response, Request
from starlette.background import BackgroundTask
from starlette.responses import StreamingResponse
from fastapi.routing import APIRoute
from starlette.types import Message
from typing import Callable, Dict, Any
import logging
import httpx


def log_info(req_body, res_body):
    logging.info(req_body)
    logging.info(res_body)

       
class LoggingRoute(APIRoute):
    def get_route_handler(self) -&gt; Callable:
        original_route_handler = super().get_route_handler()

        async def custom_route_handler(request: Request) -&gt; Response:
            req_body = await request.body()
            response = await original_route_handler(request)
            tasks = response.background
            
            if isinstance(response, StreamingResponse):
                chunks = []
                async for chunk in response.body_iterator:
                    chunks.append(chunk)
                res_body = b''.join(chunks)
                
                task = BackgroundTask(log_info, req_body, res_body)
                response = Response(content=res_body, status_code=response.status_code, 
                        headers=dict(response.headers), media_type=response.media_type)
            else:
                task = BackgroundTask(log_info, req_body, response.body)
            
            # check if the original response had background tasks already attached to it
            if tasks:
                tasks.add_task(task)  # add the new task to the tasks list
                response.background = tasks
            else:
                response.background = task
                
            return response
            
        return custom_route_handler


app = FastAPI()
router = APIRouter(route_class=LoggingRoute)
logging.basicConfig(filename='info.log', level=logging.DEBUG)


@router.post('/')
def main(payload: Dict[Any, Any]):
    return payload


@router.get('/video')
def get_video():
    url = 'https://storage.googleapis.com/gtv-videos-bucket/sample/ForBiggerBlazes.mp4'
    
    def gen():
        with httpx.stream('GET', url) as r:
            for chunk in r.iter_raw():
                yield chunk

    return StreamingResponse(gen(), media_type='video/mp4')


app.include_router(router)
