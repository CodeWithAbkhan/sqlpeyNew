Solved: How to Set Environment Variables in Virtualenv for Local Testing

When developing Python applications, especially those designed for cloud platforms like Heroku, managing environment variables is crucial for configuring your application effectively. If you’re using virtualenv to test your app locally, you might wonder how to set the same environment variables that are applied on a remote machine. So, how can you achieve this? Here are some effective methods to set and unset environment variables in your virtualenv setup.

Method 1: Modifying the Activate Script

To set environment variables directly within your virtualenv, you can edit the activate script used to activate your environment.

For Unix systems:

  1. Open the activate script in an editor:

    nano YOUR_ENV/bin/activate

  2. Add your environment variables by appending them to the end of the file:

    export KEY=VALUE

For Windows systems:

  1. Open the corresponding activate script:

    nano YOUR_ENV/Scripts/activate.bat

  2. Similarly, append your variables:

    set KEY=VALUE

This method allows you to set variables every time you activate your virtual environment.

Method 2: Unsetting Variables on Deactivation

If you prefer to also unset your environment variables upon deactivation, you can enhance the deactivate function in the same activate script.

  1. Modify your deactivate function in the script:

    deactivate () {
    ...
    unset MY_SERVER_NAME
    unset MY_DATABASE_URL
}

  2. Set the variables at the script’s end like so:

    export MY_SERVER_NAME="<domain for My Server>"
export MY_DATABASE_URL="<url for database>"

This ensures that your environment variables won’t linger after your virtualenv is deactivated.

Method 3: Using Export Command in Activate Script

You can set environment variables inline using the export command in the activate script anytime you initialize your virtualenv:

export ENVVAR=value

This approach offers a quick way to configure variables as your environment initializes.

Method 4: Utilizing a .env File with Foreman

If you are using Heroku, consider the tool Foreman, which can read a .env file and export all your environment variables automatically when you run your app. First, install Foreman via the Heroku toolbelt:

Heroku Toolbelt

Then create a .env file with the necessary variables. You can run your app with:

foreman start

Method 5: Exporting Variables Using a Local .env File

Another straightforward method involves having a .env file in your virtualenv’s root directory. You can use the following command to load these into your environment:

export $(cat .env)

Method 6: Advanced Management with venv

If you’re using Python’s built-in venv, you can still manage environment variables similarly to virtualenv by editing the activate script located in the env/bin/activate directory. Here’s how to preserve existing variables upon activation and restoration on deactivation:

  1. Update your deactivate function:

    deactivate () {
    ...
    if [ -n "${_OLD_ENV_VARIABLE:-}" ] ; then
        ENV_VARIABLE="${_OLD_ENV_VARIABLE:-}"
        export ENV_VARIABLE
        unset _OLD_ENV_VARIABLE
    else
        unset ENV_VARIABLE
    fi
}

  2. At the bottom of your script, set your desired variable:

    export ENV_VARIABLE="new value of ENV_VARIABLE"

This process allows both setting and retaining previous values effectively.

Method 7: Automatic Loading with Autoenv

For a more automated approach, consider using autoenv . It loads environment variables from a .env file automatically whenever you navigate to the directory containing your virtualenv:

Install autoenv:

pip install autoenv

Then create a .env file that runs the activation script:

echo "source bin/activate" > .env

Method 8: Deploying with Django Dotenv

If you’re developing a Django application, you can utilize django-dotenv to manage environment variables. This method involves creating a .env file and simplistically exporting your variables.

  • Original repository: django-dotenv
  • Enhanced version: django-dotenv-rw for additional features.

FAQs on How to Set Environment Variables in Virtualenv for Local Testing

Q: How do I set environment variables inside a virtualenv?

A: You can set environment variables by editing the activate script of your virtualenv and adding export VARIABLE_NAME=value.

Q: Can I have environment variables load automatically?

A: Yes, you can use tools like autoenv to automatically load variables from a .env file whenever you enter a directory.

Q: What happens to environment variables when I deactivate a virtualenv?

A: If you have not configured unsetting them in the deactivate function, they will persist. You should manage their scope accordingly.
