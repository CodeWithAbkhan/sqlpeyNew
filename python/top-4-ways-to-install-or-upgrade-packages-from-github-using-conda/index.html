Can I install or upgrade packages directly from GitHub using Conda?

When you’re working with Python packages, you might wonder if it’s possible to install or upgrade them from a GitHub repository using Conda, similar to how you would with pip:

pip install git+git://github.com/scrapy/scrapy@master

This command allows you to directly install the Scrapy package from its master branch on GitHub. But is there an equivalent way to accomplish this in Conda?

If directly installing via Conda isn’t feasible, could you consider managing your package installations through pip after installing pip using Conda? Let’s explore some solutions.

Solution 1: Using environment.yml with Conda

Recent developments in conda-env have improved support for package installations from GitHub. You can create an environment file that specifies both Conda and pip dependencies to achieve this:

name: sample_env
channels:
  - defaults
dependencies:
  - requests
  - bokeh>=0.10.0
  - pip:
    - "--editable=git+https://github.com/pythonforfacebook/facebook-sdk.git@8c0d34291aaafec00e02eaa71cc2a242790a0fcc#egg=facebook_sdk-master"

This file allows you to specify a package from GitHub along with other dependencies. To apply this configuration, save the above YAML into a file named environment.yml and then run:

conda env update -f environment.yml

To create a new environment instead of updating the existing one, use:

conda env create -f environment.yml

Solution 2: Using Pip with Conda

While Conda does not natively support installing directly from GitHub (as it primarily focuses on binary installs), you can still leverage pip within your Conda setup. This is especially useful when you want to continuously update a package directly from its source. Here’s how you can do it:

  1. First, create a Conda environment and install pip:
conda create -n myenv pip
conda activate myenv
  1. Then install a GitHub package using pip:
pip install git+https://github.com/pythonforfacebook/facebook-sdk.git

Alternatively, you can also execute setup.py in a cloned repository if you have a local copy of the package on your machine.

Solution 3: Utilizing Conda’s Build System

If you are looking for a more integrated approach, consider utilizing Conda’s build feature. While it may be more complex, it can be beneficial for packaging directly from a Git repository. To do this:

  1. Set up a meta.yaml file to define the recipe for your package.
  2. Use the following command to initiate the build:
conda build .

This is a more advanced technique and typically requires familiarity with creating Conda recipes. More details about building packages can be found in the official Conda documentation .

Solution 4: Directly Installing from GitHub in a New Environment

Another efficient way to include packages from GitHub is by defining them in the environment.yml similarly to Solution 1 but without the editable tag:

name: my_new_env
channels:
  - defaults
dependencies:
  - requests
  - bokeh>=0.10.0
  - pip
  - pip:
    - git+https://github.com/pythonforfacebook/facebook-sdk.git

Run the following command to create the environment:

conda env create -f environment.yml

This allows for a straightforward setup and management of your Conda environments that require specific packages from GitHub.

FAQs on Top 4 Ways to Install or Upgrade Packages from GitHub Using Conda

Q: Can I use pip and conda together?

A: Yes, you can use pip within a Conda environment to install packages from GitHub or other sources, but be cautious about compatibility issues that can arise.

Q: Is conda build necessary for every GitHub package?

A: No, conda build is not necessary for every package. It’s mostly used when creating and distributing Conda packages using recipes.

Q: What happens if the GitHub package is updated?

A: If you installed a package using pip from GitHub, you can simply rerun the pip install command to get the latest version, or use pip install –upgrade.

Q: Can all pip packages be installed with Conda?

A: No, not all pip packages are available through Conda, but you can use pip to install those that aren’t available as Conda packages.
