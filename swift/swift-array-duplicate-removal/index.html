“Swift Array Duplicate Removal: Effective Methods and Code Examples”

Dealing with duplicate entries in arrays is a common task in programming. Swift offers several approaches to achieve this, varying in efficiency, order preservation, and reliance on specific protocols like Hashable or Equatable. Let’s delve into various effective methods with practical code examples.

Solution 1: Using Set Conversion (Order Not Preserved)

The most straightforward method if the original order of elements is not critical is to convert the array to a Set and then back to an Array. Sets inherently store only unique values.

let originals = [1, 4, 2, 2, 6, 24, 15, 2, 60, 15, 6]
let unique = Array(Set(originals))
// Example Output: unique might be [1, 4, 2, 6, 24, 15, 60] (order may vary)

Consideration: This method is efficient but does not guarantee the original order of elements.

Solution 2: Custom uniqued() Extension (Preserves Order)

For scenarios where order preservation is essential, you can implement a custom extension. This approach iterates through the array, keeping track of elements already seen using a Set.

extension Array where Element: Hashable {
    func uniqued() -> [Element] {
        var seen = Set<Element>()
        return filter { seen.insert($0).inserted }
    }
}

let values = [1, 4, 2, 2, 6, 24, 15, 2, 60, 15, 6]
let uniqueOrdered = values.uniqued()
// Example Output: uniqueOrdered will be [1, 4, 2, 6, 24, 15, 60]

This method is O(n) on average due to the efficiency of Set operations.

Solution 3: Using NSOrderedSet (Preserves Order, Swift 3+)

Leveraging NSOrderedSet provides a clean way to remove duplicates while preserving the original order.

let dataArray = [1, 1, 1, 1, 2, 2, 2, 2, 4, 6, 8]
let orderedSet: NSOrderedSet = NSOrderedSet(array: dataArray)
let arrayWithoutDuplicates: [Int] = orderedSet.array as! [Int]
// Example Output: arrayWithoutDuplicates will be [1, 2, 4, 6, 8]

A more concise Swift 5 variation exists:

extension Sequence where Element: Hashable {
    func uniqueWithNSOrderedSet() -> [Element] {
        return Array(NSOrderedSet(array: self as! [Any])) as! [Element]
    }
}

let sequenceData = ["apple", "banana", "apple", "orange", "banana"]
let uniqueSequence = sequenceData.uniqueWithNSOrderedSet()
// Example Output: uniqueSequence will be ["apple", "banana", "orange"]

Solution 4: Custom removeDuplicates() Extension (Preserves Order, Equatable Conformance)

If your array elements conform to Equatable but not necessarily Hashable, you can use a method that manually checks for containment.

extension Array where Element: Equatable {
    func removeDuplicates() -> [Element] {
        var result: [Element] = []
        for element in self {
            if !result.contains(element) {
                result.append(element)
            }
        }
        return result
    }
}

let numbers = [2, 2, 4, 4, 5, 5, 5, 6]
let uniqueNumbers = numbers.removeDuplicates()
// Example Output: uniqueNumbers will be [2, 4, 5, 6]

Performance Note: While this method works for Equatable types, its contains check within the loop leads to O(n^2) complexity, making it less efficient for large arrays compared to Hashable solutions.

Solution 5: Filtering Based on Key Paths (Advanced)

For complex objects where uniqueness is determined by specific properties, key paths offer a powerful solution.

extension RangeReplaceableCollection {
    /// Returns a collection containing, in order, the first instances of
    /// elements of the sequence that compare equally for the keyPath.
    func unique<T: Hashable>(for keyPath: KeyPath<Element, T>) -> Self {
        var unique = Set<T>()
        return filter { unique.insert($0[keyPath: keyPath]).inserted }
    }
}

struct Product {
    let id: Int
    let name: String
}

let products = [
    Product(id: 1, name: "Laptop"),
    Product(id: 2, name: "Keyboard"),
    Product(id: 1, name: "Laptop Special Edition")
]

let uniqueProductsById = products.unique(for: \.id)
// Example Output: uniqueProductsById will contain the first Laptop and the Keyboard.

A mutating version is also available:

extension RangeReplaceableCollection {
    /// Keeps only, in order, the first instances of
    /// elements of the collection that compare equally for the keyPath.
    mutating func uniqueInPlace<T: Hashable>(for keyPath: KeyPath<Element, T>) {
        var unique = Set<T>()
        removeAll { !unique.insert($0[keyPath: keyPath]).inserted }
    }
}

var mutableProducts = [
    Product(id: 1, name: "Laptop"),
    Product(id: 2, name: "Keyboard"),
    Product(id: 1, name: "Laptop Special Edition")
]
mutableProducts.uniqueInPlace(for: \.id)
// mutableProducts will now contain the first Laptop and the Keyboard.

Solution 6: Using the swift-algorithms Package

The swift-algorithms package, developed by the Swift community and endorsed by Apple, provides a uniqued() algorithm. This is a modern and often highly optimized approach.

First, add the package to your project. Then, import it:

import Algorithms

let numbers = [1, 2, 3, 3, 2, 3, 3, 2, 2, 2, 1]
print(numbers.uniqued()) // Prints [1, 2, 3]

Refer to the official documentation for more details on usage and other algorithms.

Solution 7: Preserving Order with enumerated() and firstIndex(of:)

This method iterates through the array with its index and keeps an element only if its first occurrence matches its current index, thus preserving order.

let arrayToFilter = [10, 1, 2, 3, 2, 1, 15, 4, 5, 6, 7, 3, 2, 12, 2, 5, 5, 6, 10, 7, 8, 3, 3, 45, 5, 15, 6, 7, 8, 7]

let uniqueArray = arrayToFilter
    .enumerated()
    .filter { indexAndValue in
        arrayToFilter.firstIndex(of: indexAndValue.element) == indexAndValue.offset
    }
    .map { $0.element }

// Example Output: uniqueArray will be [10, 1, 2, 3, 15, 4, 5, 6, 7, 12, 8, 45]

While this preserves order and works for Equatable types, it can be less performant than Hashable-based solutions due to repeated calls to firstIndex(of:).

Solution 8: Using reduce and contains (Preserves Order)

Another approach to preserve order for Equatable elements uses reduce to build a new array, adding an element only if it’s not already present.

extension Array where Element: Equatable {
    func uniqueOrdered() -> [Element] {
        return reduce([Element]()) { result, element in
            result.contains(element) ? result : result + [element]
        }
    }
}

let sequenceForOrder = ["Ljubljana", "London", "Los Angeles", "Ljubljana"]
print(sequenceForOrder.uniqueOrdered()) // Prints ["Ljubljana", "London", "Los Angeles"]

Similar to Solution 4, this method has O(n^2) time complexity.

Solution 9: Leveraging Set.insert().inserted

This is a highly efficient and concise method that preserves order, leveraging the inserted property of the tuple returned by Set.insert().

extension Array where Element: Hashable {
    var orderedSetValues: [Element] {
        var uniqueElements = Set<Element>()
        return filter { uniqueElements.insert($0).inserted }
    }
}

let dataForUniqueness = [10, 1, 2, 3, 2, 1, 15, 4, 5, 6, 7, 3, 2, 12, 2, 5, 5, 6, 10, 7, 8, 3, 3, 45, 5, 15, 6, 7, 8, 7]
let uniqueOrderedData = dataForUniqueness.orderedSetValues
// Example Output: uniqueOrderedData will be [10, 1, 2, 3, 15, 4, 5, 6, 7, 12, 8, 45]

This is generally considered one of the most performant ways to remove duplicates while maintaining order for Hashable elements.

Solution 10: For Non-Hashable, Non-Equatable Custom Objects

When dealing with custom types that aren’t Hashable or Equatable, you can filter based on a computed property or a combination of properties.

extension Array {
   func filterDuplicate<T: Hashable>(_ keyValue: (Element) -> T) -> [Element] {
      var uniqueKeys = Set<T>()
      return filter { uniqueKeys.insert(keyValue($0)).inserted }
   }
}

// Example usage with a custom struct:
struct Person {
    let name: String
    let age: Int
}

var peopleArray = [
    Person(name: "Alice", age: 30),
    Person(name: "Bob", age: 25),
    Person(name: "Alice", age: 30), // Duplicate based on name and age
    Person(name: "Charlie", age: 30)
]

// Remove duplicates based on a tuple of properties (name and age)
let uniquePeople = peopleArray.filterDuplicate { ($0.name, $0.age) }
// uniquePeople will contain Alice (first occurrence), Bob, and Charlie.

For even more complex scenarios or when dealing with Swift 4.2+, you can use Hasher for custom hashing.

FAQs on Swift Array Duplicate Removal

Q: What is the fastest way to remove duplicates from a Swift array

ANS: For elements conforming to Hashable, converting to a Set and back to an Array is generally fast but doesn’t preserve order. For order preservation with Hashable elements, using filter with a Set to track seen elements (as shown in Solution 2 and 9) is very efficient (O(n) on average).

Q: How do I remove duplicates while keeping the original order

ANS: Methods that use a Set to track seen elements (like uniqued() extensions in Solution 2 and 9) or NSOrderedSet (Solution 3) are excellent for preserving order. Solutions involving manual checks like contains on an array (Solution 4 and 8) also preserve order but are less efficient.

Q: Can I remove duplicates from an array of custom objects

ANS: Yes, if your custom objects conform to Hashable or Equatable. If not, you can create extensions that filter based on specific properties using key paths (Solution 5) or by providing a custom way to generate a hashable value (Solution 10).

Q: What if my array elements are not Hashable

ANS: If your elements conform to Equatable, you can use methods that iterate and check for containment within the resulting array (like Solution 4 and 8). However, be mindful of the performance implications (O(n^2)) for large datasets. For non-Hashable and non-Equatable types, you’ll need to implement custom logic, often based on a specific property, as shown in Solution 5 or 10.

Q: Is there a built-in Swift function for removing duplicates

ANS: Swift’s standard library doesn’t have a direct removeDuplicates() function. However, the swift-algorithms package provides a uniqued() algorithm (Solution 6). For basic duplicate removal without order preservation, Array(Set(yourArray)) is a common idiom.
