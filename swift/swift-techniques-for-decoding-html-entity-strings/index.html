“Swift Techniques for Decoding HTML Entity Strings”

When dealing with data received from web services or stored content, strings often contain HTML character entities (like &amp;, &lt;, or numeric references like &#8216;) that need conversion back into their corresponding plain text characters (like &, <, or ‘). Since there isn’t one universally simple approach across all scenarios or Swift versions, developers have proposed several effective techniques.

How can one reliably transform an HTML-encoded string into a readable string representation in Swift, preserving or stripping HTML markup as needed?

Approach 1: Leveraging NSAttributedString for HTML Parsing (The Standard iOS/macOS Way)

The most common method leverages the framework’s built-in capability to interpret HTML content when initializing an NSAttributedString. This works by treating the input string as HTML data.

Important Caveat: This method generally strips out any surrounding HTML tags (like <strong> or <em>), focusing only on decoding the entities themselves. This operation should ideally be performed on the main thread as it utilizes WebKit internally.

Swift 5+ Implementation via String Extension

This approach creates a direct initializer or a computed property for effortless decoding, often returning the original string if parsing encounters an error.

// Swift 5+ Computed Property Style
extension String {
    var htmlDecodedStandard: String {
        guard let data = self.data(using: .utf8) else { return self }

        let options: [NSAttributedString.DocumentReadingOptionKey: Any] = [
            .documentType: NSAttributedString.DocumentType.html,
            .characterEncoding: String.Encoding.utf8.rawValue
        ]

        guard let attributedString = try? NSAttributedString(data: data, options: options, documentAttributes: nil) else {
            return self
        }
        
        // Result strips tags, only leaving decoded entities.
        return attributedString.string
    }
}

let htmlEncodedString = "The Weeknd &lt;em&gt;&amp;#8216;King Of The Fall&amp;#8217;&lt;/em&gt;"
let decodedText = htmlEncodedString.htmlDecodedStandard // Output: The Weeknd ‘King Of The Fall’
print(decodedText)

Concise Swift 4+ Computed Property

A more minimal implementation for Swift 4 environments:

extension String {
    var swift4HtmlDecoded: String {
        let decoded = try? NSAttributedString(data: Data(utf8), options: [
            .documentType: NSAttributedString.DocumentType.html,
            .characterEncoding: String.Encoding.utf8.rawValue
        ], documentAttributes: nil).string

        return decoded ?? self
    }
}

Swift 4 Initializer Approach

Creating a dedicated initializer for cleaner usage:

extension String {
    init(htmlString: String) {
        self.init()
        guard let encodedData = htmlString.data(using: .utf8) else {
            self = htmlString
            return
        }

        let attributedOptions: [NSAttributedString.DocumentReadingOptionKey : Any] = [
           .documentType: NSAttributedString.DocumentType.html,
           .characterEncoding: String.Encoding.utf8.rawValue
        ]

        do {
            let attributedString = try NSAttributedString(data: encodedData,
                                                          options: attributedOptions,
                                                          documentAttributes: nil)
            self = attributedString.string
        } catch {
            print("Decoding Error: \(error.localizedDescription)")
            self = htmlString
        }
    }
}
// Usage: let cleanString = String(htmlString: encodedString)

Approach 2: Pure Swift Implementation for Entity Preservation (macOS/Linux Compatibility)

The NSAttributedString method is unavailable on platforms like Linux or if you strictly need to preserve HTML tags while only decoding entities (e.g., decoding &amp;lt; to < but keeping <strong...> tags intact). This requires custom parsing logic.

Manual Entity Replacement (Limited Set)

For basic, known entities, direct replacement works well, though it requires listing common entities manually.

extension String {
    func manualEntityDecode() -> String {
        guard !self.isEmpty else { return self }
        var result = self

        let entities: [String: String] = [
            "&amp;quot;": "\"",
            "&amp;amp;": "&",
            "&amp;apos;": "'",
            "&amp;lt;": "<",
            "&amp;gt;": ">",
        ]

        for (entity, character) in entities {
            result = result.replacingOccurrences(of: entity, with: character)
        }
        return result
    }
}

let basicEncoded = "This is so &amp;quot;great&amp;quot; &amp;amp; simple"
let decodedBasic = basicEncoded.manualEntityDecode() // Output: This is so "great" & simple

Advanced Pure Swift Entity Decoder (Handling Numeric Entities)

A more robust pure Swift solution involves iterating through the string, identifying patterns like &#64; (decimal) or &#x20AC; (hexadecimal) and known named entities.

This example provides utility functions to decode numeric entities, keeping HTML tags untouched if they aren’t recognized entities.

private let recognizedEntities: [Substring : Character] = [
    "&amp;quot;": "\"",
    "&amp;amp;": "&",
    "&amp;apos;": "'",
    "&amp;lt;": "<",
    "&amp;gt;": ">",
    "&amp;nbsp;": "\u{00a0}",
    // Include more entities here based on need...
]

extension String {
    var customEntityDecoding: String {
        
        func decodeNumeric(_ value : Substring, base : Int) -> Character? {
            guard let code = UInt32(value, radix: base),
                let uniScalar = UnicodeScalar(code) else { return nil }
            return Character(uniScalar)
        }

        func decodeEntity(_ entity : Substring) -> Character? {
            if entity.hasPrefix("&#x") || entity.hasPrefix("&#X") {
                return decodeNumeric(entity.dropFirst(3).dropLast(), base: 16)
            } else if entity.hasPrefix("&#") {
                return decodeNumeric(entity.dropFirst(2).dropLast(), base: 10)
            } else {
                return recognizedEntities[entity]
            }
        }

        var finalString = ""
        var scanPosition = self.startIndex

        while let ampRange = self[scanPosition...].range(of: "&") {
            finalString.append(contentsOf: self[scanPosition ..< ampRange.lowerBound])
            scanPosition = ampRange.lowerBound

            guard let semiRange = self[scanPosition...].range(of: ";") else {
                break // Incomplete entity
            }
            let entity = self[scanPosition ..< semiRange.upperBound]

            if let character = decodeEntity(entity) {
                finalString.append(character)
                scanPosition = semiRange.upperBound
            } else {
                // Entity invalid or unrecognized, append verbatim
                finalString.append(contentsOf: self[ampRange])
                scanPosition = ampRange.upperBound
            }
        }
        // Append remaining text
        finalString.append(contentsOf: self[scanPosition...])
        return finalString
    }
}

let complexEncoded = "&lt;strong&gt; 4 &amp;lt; 5 &amp;amp; 3 &amp;gt; 2 .&lt;/strong&gt; Price: 12 &amp;#x20ac;.  &amp;#64; &amp;&quot;"
let customDecoded = complexEncoded.customEntityDecoding
// Output: <strong> 4 < 5 & 3 > 2 .</strong> Price: 12 €.  @ "

Approach 3: Third-Party Libraries for Server-Side Swift or Complete Control

For server environments (like Vapor or Kitura) where NSAttributedString dependencies might be absent or performance is critical, external packages offer dedicated solutions.

The HTMLEntities package is often cited for its speed and comprehensive support for HTML4/HTML5 named entities, including encoding functionality as well.

If utilizing this package:

import HTMLEntities // Requires package installation

let entityString = "The Weeknd &amp;#8216;King Of The Fall&amp;#8217;"
let libraryDecoded = entityString.htmlUnescape() 
// Prints: The Weeknd ‘King Of The Fall’

Dealing with Post-Processing Needs

Sometimes, even after entity decoding, residual issues like excess newlines (\n, \r, \t) or apostrophes resulting from entity conversion must be cleaned up, especially if the final output is destined for a plain text field.

let htmlResult = "The Weeknd ‘King Of The Fall’\nwith newlines and 'quotes'"

// Removing whitespace characters and apostrophes
var finalCleaned = String(htmlResult.filter { !"\n\t\r".contains($0) })
finalCleaned = finalCleaned.replacingOccurrences(of: "'", with: "", options: .literal, range: nil)

FAQs on Swift Techniques for Decoding HTML Entity Strings

Q: Does using NSAttributedString strip HTML formatting tags

ANS: Yes, the standard approach utilizing NSAttributedString(data:options:) parses the string as HTML and typically returns only the resultant plain text string, effectively removing formatting tags like <em> or <strong>.

Q: Is the NSAttributedString method safe to use on background threads

ANS: It is generally advised to initialize NSAttributedString from the main thread because it relies on underlying WebKit mechanisms which may have thread confinement requirements.

Q: How to handle both entity decoding and HTML tag removal in one step

ANS: The NSAttributedString method (Approach 1) accomplishes both entity decoding and HTML tag stripping simultaneously by interpreting the input data as HTML.

Q: Are there solutions available for Linux environments

ANS: The NSAttributedString approach is not available on Linux. For cross-platform or server-side Swift, pure Swift implementations (Approach 2) or packages like HTMLEntities (Approach 3) are necessary.

Q: What if I need to decode entities but keep the HTML structure

ANS: You must employ a pure Swift parser (Approach 2) or use a specialized library that can differentiate between entity replacement and tag preservation, as the built-in NSAttributedString approach strips tags.
