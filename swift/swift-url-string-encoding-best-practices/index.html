“Swift URL String Encoding: Best Practices and Solutions”

URL encoding, also known as percent-encoding, is crucial for transforming strings into a format that can be safely transmitted over the internet as part of a URL. This process replaces characters that have special meaning in URLs or are not allowed with a “%” followed by their two-digit hexadecimal representation. For instance, a space character is commonly encoded as “%20”.

Several approaches exist in Swift to achieve this, ranging from built-in methods to custom configurations for specific encoding needs. Let’s delve into the various solutions and best practices.

Swift 3 and Above: addingPercentEncoding

For Swift 3 and later, the primary method for URL encoding is addingPercentEncoding(withAllowedCharacters:). This function takes a CharacterSet to define which characters should not be encoded.

Solution 1: Using .urlHostAllowed

The .urlHostAllowed character set is suitable for encoding components like the host of a URL.

let originalString = "test/test"
let escapedString = originalString.addingPercentEncoding(withAllowedCharacters: .urlHostAllowed)
print(escapedString ?? "Encoding failed")
// Output: test%2Ftest

Solution 2: Custom Character Set for Specific Escaping

You can define your own character set to control precisely which characters are escaped. This is useful when you need to exclude or include specific characters that standard sets might not handle as required.

var originalString = "test/test=42"
// Create a set that excludes common URL characters and then invert it
var customAllowedSet = CharacterSet(charactersIn: #"="+"#%/<>?@\\^`{|}").inverted
var escapedString = originalString.addingPercentEncoding(withAllowedCharacters: customAllowedSet)
print(escapedString ?? "Encoding failed")
// Output: test%2Ftest%3D42

To identify characters not included in a set, you can use a helper function:

func printCharactersNotInSet(set: CharacterSet) {
    var characters = ""
    let invertedSet = set.inverted
    for i: UnicodeScalar in 32..<127 {
        if invertedSet.contains(i) {
            characters.append(Character(i))
        }
    }
    print("Characters not in set: '\(characters)'")
}

printCharactersNotInSet(set: .urlHostAllowed)
// Example Output: Characters not in set: ' !"#$%&''()*+,-./:;<=>?@[]^_`{|}~'

Solution 3: Using .urlQueryAllowed

The .urlQueryAllowed character set is generally recommended for encoding query parameters.

let originalString = "http://www.ihtc.cc?name=htc&title=iOS开发工程师"
// Encodes query parameters
let escapedQueryString = originalString.addingPercentEncoding(withAllowedCharacters: .urlQueryAllowed)
print(escapedQueryString ?? "Encoding failed")
// Output: http://www.ihtc.cc?name=htc&title=iOS%E5%BC%80%E5%8F%91%E5%B7%A5%E7%A8%8B%E5%B8%88

Encoding with .urlHostAllowed would encode more characters, including slashes:

// Encodes the entire URL string, including path and host
let escapedURLString = originalString.addingPercentEncoding(withAllowedCharacters: .urlHostAllowed)
print(escapedURLString ?? "Encoding failed")
// Output: http:%2F%2Fwww.ihtc.cc%3Fname=htc&title=iOS%E5%BC%80%E5%8F%91%E5%B7%A5%E7%A8%8B%E5%B8%88

Swift 4 & 5: Advanced Encoding with URLComponents and Custom Sets

For more nuanced control, URLComponents provides a robust way to build URLs, and custom CharacterSet extensions can refine encoding rules.

Solution 4: Encoding with .alphanumerics

The .alphanumerics set can be useful, but it may encode characters that are technically unreserved in URLs (like -, ., _, ~).

let value = "special characters like & and ="
let urlEncoded = value.addingPercentEncoding(withAllowedCharacters: .alphanumerics)
let url = "http://www.example.com/?name=\(urlEncoded ?? "")"
print(url)
// Output: http://www.example.com/?name=special%20characters%20like%20and%20

A more refined approach using a custom set based on RFC 3986 (unreserved characters):

private let urlAllowed: CharacterSet = .alphanumerics.union(CharacterSet(charactersIn: "-._~"))

extension String {
    var urlEncodedParameter: String? {
        return addingPercentEncoding(withAllowedCharacters: urlAllowed)
    }
}

let value = "special characters like & and ="
let url = "http://www.example.com/?name=\(value.urlEncodedParameter ?? "")"
print(url)
// Output: http://www.example.com/?name=special%20characters%20like%20and%20

Warning: Forcing unwrap (!) on addingPercentEncoding can lead to crashes with invalid Unicode strings. Use optional binding (if let or ??) for safer unwrapping.

Solution 5: Using URLComponents for Query Items

URLComponents is excellent for constructing URLs programmatically, especially when dealing with query parameters. It handles the encoding of individual query items correctly.

let scheme = "https"
let host = "www.google.com"
let path = "/search"
let queryItem = URLQueryItem(name: "q", value: "Formula One")

var urlComponents = URLComponents()
urlComponents.scheme = scheme
urlComponents.host = host
urlComponents.path = path
urlComponents.queryItems = [queryItem]

if let url = urlComponents.url {
    print(url)
    // Output: https://www.google.com/search?q=Formula%20One
}

A convenient initializer can simplify this further:

let query = "Formula One"
// This initializer assumes default scheme/host/path if not provided
if let url = URLComponents(queryItems: [URLQueryItem(name: "q", value: query)]).url {
    print(url)
    // Output: https://www.google.com/search?q=Formula%20One
}

Solution 6: Handling Specific Query Parameter Requirements

For query parameters, certain characters like + might need special handling (often converting spaces to + instead of %20). While URLComponents generally uses %20, custom solutions are sometimes needed.

A common pattern is to create a character set that excludes specific delimiters often found in query strings.

// Swift 4 & 5
var allowedQueryParamAndKey = CharacterSet.urlQueryAllowed
allowedQueryParamAndKey.remove(charactersIn: ";/?:@&=+$, ")
let encodedParam = "some parameter value".addingPercentEncoding(withAllowedCharacters: allowedQueryParamAndKey)
print(encodedParam ?? "Encoding failed")
// Output: some%20parameter%20value

// Swift 2.2 style (for reference)
// var allowedQueryParamAndKey = NSCharacterSet(charactersInString: ";/?:@&=+$, ").invertedSet
// let encodedParam = "some parameter value".stringByAddingPercentEncodingWithAllowedCharacters(allowedQueryParamAndKey)

The example below demonstrates encoding a full URL that might have pre-encoded or non-English characters:

extension String {
    func encodedUrl() -> URL? {
        guard let decodedString = self.removingPercentEncoding,
              let unicodeEncodedString = decodedString.addingPercentEncoding(withAllowedCharacters: .urlAllowedCharacters),
              let components = URLComponents(string: unicodeEncodedString),
              let percentEncodedUrl = components.url else {
            return nil
        }
        return percentEncodedUrl
    }
}

// Extension for a comprehensive set of URL allowed characters
extension CharacterSet {
    static var urlAllowedCharacters: CharacterSet {
        var characters = CharacterSet(charactersIn: "#")
        characters.formUnion(.urlUserAllowed)
        characters.formUnion(.urlPasswordAllowed)
        characters.formUnion(.urlHostAllowed)
        characters.formUnion(.urlPathAllowed)
        characters.formUnion(.urlQueryAllowed)
        characters.formUnion(.urlFragmentAllowed)
        return characters
    }
}

let urlText = "https://www.example.com/폴더/search?q=123&foo=bar&multi=eggs+and+ham&hangul=한글&spaced=lovely%20spam&illegal=<>#top"
if let url = urlText.encodedUrl() {
    print(url)
    // Output: https://www.example.com/%ED%8F%B4%EB%8D%94/search?q=123&foo=bar&multi=eggs+and+ham&hangul=%ED%95%9C%EA%B8%80&spaced=lovely%20spam&illegal=%3C%3E#top
}

Solution 7: RFC 3986 Compliant Encoding

For strict adherence to RFC 3986, especially for query parameters, you might need to customize the character set further. The afURLQueryAllowed set from Alamofire’s URLEncodedFormEncoder is a good reference:

extension CharacterSet {
    /// Creates a CharacterSet from RFC 3986 allowed characters for query strings.
    public static let afURLQueryAllowed: CharacterSet = {
        let generalDelimitersToEncode = ":#[]@" // Excludes "?" and "/" per RFC 3986 - Section 3.4
        let subDelimitersToEncode = "!$&'()*+,;="
        let encodableDelimiters = CharacterSet(charactersIn: "\(generalDelimitersToEncode)\(subDelimitersToEncode)")
        return CharacterSet.urlQueryAllowed.subtracting(encodableDelimiters)
    }()
}

let testString = "6hAD9/RjY+SnGm&B"
let escapedString = testString.addingPercentEncoding(withAllowedCharacters: .afURLQueryAllowed)
print(escapedString ?? "Encoding failed")
// Output: en6hAD9%2FRjY%2BSnGm%26B

Solution 8: CFURLCreateStringByAddingPercentEscapes (Lower-Level)

For very specific control or compatibility with older APIs, the Core Foundation function CFURLCreateStringByAddingPercentEscapes can be used.

var str = CFURLCreateStringByAddingPercentEscapes(
    nil,
    "test/test" as CFString,
    nil,
    "!*'();:@&=+$,/?%#[]" as CFString,
    CFStringBuiltInEncodings.UTF8.rawValue
) as String?
print(str ?? "Encoding failed")
// Output: test%2Ftest

Solution 9: Pre-encoding and Re-encoding

Sometimes, a string might have mixed encoded and unencoded characters. Decoding first and then re-encoding can resolve such issues.

extension String {
    var decodeThenEncodeURL: String {
        removingPercentEncoding?.addingPercentEncoding(withAllowedCharacters: .urlQueryAllowed) ?? self
    }
}

let input = "https://www.google.com/search?q=%5B×××%5D"
let output = input.decodeThenEncodeURL
print(output)
// Output: https://www.google.com/search?q=%5B%C3%97%C3%97%C3%97%5D

Solution 10: Parameter Dictionary to Query String

A practical utility is converting a dictionary of parameters into a URL query string.

extension String {
    func urlEncodedParameter() -> String? {
        addingPercentEncoding(withAllowedCharacters: .urlHostAllowed)
    }

    static func queryStringFromParameters(parameters: [String: String]) -> String? {
        guard !parameters.isEmpty else {
            return nil
        }

        var queryString: String?
        for (key, value) in parameters {
            guard let encodedKey = key.urlEncodedParameter(),
                  let encodedValue = value.urlEncodedParameter() else {
                continue // Skip if encoding fails for key or value
            }

            if queryString == nil {
                queryString = "?"
            } else {
                queryString! += "&"
            }
            queryString! += "\(encodedKey)=\(encodedValue)"
        }
        return queryString
    }
}

let params = ["name": "Swift URL", "version": "5"]
if let query = String.queryStringFromParameters(parameters: params) {
    print(query)
    // Output: ?name=Swift%20URL&version=5
}

Solution 11: Handling Spaces as Plus Signs (+)

For some APIs, spaces in query parameters are expected to be encoded as + instead of %20.

func escapeStringForQuery(string: String, plusForSpace: Bool = false) -> String {
    let unreserved = "*-._"
    let allowed = NSMutableCharacterSet.alphanumeric()
    allowed.addCharacters(in: unreserved)

    var encoded = string.addingPercentEncoding(withAllowedCharacters: allowed as CharacterSet)

    if plusForSpace, let encodedString = encoded {
        encoded = encodedString.replacingOccurrences(of: " ", with: "+")
    }
    return encoded ?? string
}

let query = "Swift URL Encoding Example"
print(escapeStringForQuery(string: query, plusForSpace: true))
// Output: Swift+URL+Encoding+Example

Key Considerations:

  • Context Matters: The correct character set depends on which part of the URL you are encoding (host, path, query, fragment).
  • RFC Standards: Familiarize yourself with RFC 3986 for a deep dive into URL syntax and encoding rules.
  • Optional Handling: Always handle the optional return values of encoding methods gracefully to prevent app crashes.

By understanding these methods and their nuances, you can effectively handle URL string encoding in your Swift projects, ensuring robust and reliable network communication.

FAQs on Swift URL String Encoding

Q: What is URL encoding in Swift

ANS: URL encoding, or percent-encoding, in Swift transforms characters that have special meaning in URLs or are not allowed into a format that can be safely transmitted over the internet. This is typically done by replacing characters with a ‘%’ followed by their hexadecimal representation (e.g., space becomes %20).

Q: How do I encode a URL string in Swift

ANS: The primary method is addingPercentEncoding(withAllowedCharacters:) available on String. You provide a CharacterSet defining which characters should not be encoded. For example, .urlQueryAllowed is common for query parameters.

Q: When should I use URLComponents

ANS: URLComponents is ideal for building URLs programmatically, especially when dealing with multiple query parameters or complex URL structures. It automatically handles the correct encoding for different URL parts.

Q: What is the difference between .urlQueryAllowed and .urlHostAllowed

ANS: .urlQueryAllowed is suitable for encoding query string parameters, while .urlHostAllowed is for encoding the host component of a URL. .urlHostAllowed encodes more characters than .urlQueryAllowed, including the slash (/).

Q: How can I encode spaces as plus signs (+) instead of %20

ANS: You can achieve this by creating a custom character set that includes the space character and then replacing any resulting %20 with +, or by directly replacing spaces with + before encoding, depending on your chosen method.

Q: Is it safe to force unwrap the result of addingPercentEncoding

ANS: No, it’s not safe. The addingPercentEncoding method returns an optional (String?) because encoding can fail for certain invalid inputs. Always use optional binding (e.g., if let or ??) for safe unwrapping.
