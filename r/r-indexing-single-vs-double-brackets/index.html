R Indexing: Single vs. Double Brackets

When working with data structures in R, particularly lists and data frames, a common point of confusion for newcomers and experienced users alike is the precise behavior of single square brackets [] versus double square brackets [[]]. While both are used for accessing elements, their functionalities and the types of objects they return differ significantly. This comprehensive guide delves into these distinctions, providing clear explanations and practical examples to help you confidently navigate R’s indexing system.

For a foundational understanding of R, you might find this resource helpful: What is R? .

The Core Differences: Subsetting vs. Extraction

At their heart, the difference between [] and [[]] boils down to subsetting versus extraction.

  • Single Brackets []: These are used for subsetting. When you use single brackets, you are essentially selecting a portion of your object, and R will return a new object of the same class as the original (or a subset thereof). This means if you subset a list with [], you will get back another list. If you subset a data frame with [], you will get back a data frame.

  • Double Brackets [[]]: These are used for extracting a single element from an object. When you use double brackets, R returns the element itself, stripped of its list or data frame wrapper. The class of the returned object will depend on the actual type of the data contained within that element. This is crucial when you need to perform operations on the raw data, such as using it in conditional statements or mathematical calculations.

Let’s explore these concepts with practical examples.

Understanding R’s Indexing Operators

The R Language Definition offers a formal perspective on these operators, highlighting their syntax and intended use. R provides several indexing operators:

  • x[i]
  • x[i, j]
  • x[[i]]
  • x[[i, j]]
  • x$a
  • x$"a"

While [[ is less common for vectors and matrices compared to [ (though it has subtle semantic differences, like dropping names), its behavior with lists is where the primary distinctions lie.

Demonstrating the Differences with Lists

Consider a simple list named foo:

foo <- list(str = 'R', vec = c(1, 2, 3), bool = TRUE)

Using Single Brackets [] for Extraction

If we try to extract the bool element using single brackets and use it in an if() statement:

if (foo['bool']) {
  print("Hi!")
}

This will result in an error: Error in if (foo["bool"]) { : argument is not interpretable as logical.

Let’s inspect the class of the returned object:

class(foo['bool'])

Output:

[1] "list"

As expected, foo['bool'] returned a list containing the logical value. An if() statement cannot directly process a list.

Using Double Brackets [[]] for Extraction

Now, let’s use double brackets to extract the bool element:

if (foo[['bool']]) {
  print("Hi!")
}

Output:

[1] "Hi!"

And the class of the returned object:

class(foo[['bool']])

Output:

[1] "logical"

This confirms that foo[['bool']] returns the actual logical value, which can be correctly interpreted by the if() statement.

Subsetting with Single Brackets [] for Multiple Elements

A key advantage of single brackets is their ability to select multiple elements or a range of elements.

Consider a new list bar:

bar <- list(mat = matrix(0, nrow = 2, ncol = 2), rand = rnorm(1))

If we try to assign bar to multiple elements of foo using double brackets:

foo[[2:3]] <- bar

This will cause an error: Error in foo[[2:3]] <- bar : more elements supplied than there are to replace. This is because [[]] is restricted to extracting/assigning a single element at a time.

Using single brackets for assignment, however, works as expected:

foo[2:3] <- bar
print(foo)

Output:

$str
[1] "R"

$vec
     [,1] [,2]
[1,]    0    0
[2,]    0    0

$bool
[1] -0.6291121 # Example random number

Notice that even though we assigned two elements, foo[2:3] returned a list, maintaining the structure.

A More Concise View

A helpful way to remember this is:

  • lst[index] returns a list containing the selected element(s).
  • lst[[index]] returns the element itself, unwrapped from its list structure.

Let’s illustrate this with another list, alist:

alist <- list(c("a", "b", "c"), c(1, 2, 3, 4), c(8e6, 5.2e9, -9.3e7))

str(alist[[1]])

Output:

chr [1:3] "a" "b" "c"

Now, with single brackets:

str(alist[1])

Output:

List of 1
 $ : chr [1:3] "a" "b" "c"

And extracting a single element from the first sub-element:

str(alist[[1]][1])

Output:

chr "a"

Recursive Indexing with [[]]

The [[ operator is also capable of recursive indexing. This means you can traverse nested lists by providing a vector of indices.

Consider this deeply nested list:

x <- list(list(list(1), 2), list(list(list(3), 4), 5), 6)
print(x)

Output:

[[1]]
[[1]][[1]]
[[1]][[1]][[1]]
[1] 1

[[1]][[2]]
[1] 2

[[2]]
[[2]][[1]]
[[2]][[1]][[1]]
[[2]][[1]][[1]][[1]]
[1] 3

[[2]][[1]][[2]]
[1] 4

[[2]][[2]]
[1] 5

[[3]]
[1] 6

To access the value 3, you can use a vector of indices:

x[[c(2, 1, 1, 1)]]

Output:

[1] 3

Conversely, attempting to use a vector of indices with [] for assignment might lead to errors if the structure doesn’t align:

r <- list(1:10, foo = 1, far = 2)

# This will cause an error due to incorrect recursive indexing attempt
# r[[1:3]]

# Similarly, with named indices
# r[[c("foo", "far")]]

These examples illustrate how [[ can navigate complex structures, but also how misuse can lead to “recursive indexing failed” or “subscript out of bounds” errors.

Practical Use Cases

Getting the “Bare” Data for Calculations

The [[ operator is invaluable when you need to access the raw data for calculations or comparisons.

# Using a named vector
(x_vec <- c(x = 1, y = 2))
x_vec[1] # Returns a named vector (list-like)
x_vec[[1]] # Returns the value itself

# Using a list
(x_list <- list(x = 1, y = 2, z = 3))
x_list[1] # Returns a list containing the first element
x_list[[1]] # Returns the first element directly

# Using a data frame
(x_df <- data.frame(x = 1, y = 2, z = 3))
x_df[1] # Returns a data frame with the first column
x_df[[1]] # Returns the first column as a vector

# Performing calculations:
2 * x_list[1] # Error: cannot multiply by a list
2 * x_list[[1]] # Works correctly

Extracting Data Frames from Split Lists

When using functions like split() in R, which divides a data frame into a list of smaller data frames based on a key, [[ is essential for accessing these individual data frames.

# Assume 'data' is a data frame with an 'id' column
# Example:
# data <- data.frame(id = c("A", "B", "A"), value = c(10, 20, 15))
# dsplit <- split(data, data$id)

# Check the class of the split object (it's a list)
# class(dsplit) # Output: [1] "list"

# Accessing a subset of the split list
# class(dsplit['A']) # Output: [1] "list"

# Accessing the actual data frame for 'A'
# class(dsplit[['A']]) # Output: [1] "data.frame"

Working with Data Frames

When dealing with data frames, [] and [[ have distinct roles:

  • Single Brackets []: Used to select rows and columns. You provide row and column indices separated by a comma.

    # Using the built-in mtcars dataset
# Select the cell from the first row, second column
mtcars[1, 2]

# Select using row and column names
mtcars["Mazda RX4", "cyl"]

  • Double Brackets [[]]: Primarily used to extract entire columns (as vectors) or specific elements by name or index.

    # Retrieve the ninth column vector of mtcars
mtcars[[9]]

# Retrieve the column named 'am'
mtcars[["am"]]

Alternative Approaches and Considerations

While [] and [[ are the primary methods, R offers other ways to interact with data structures:

  • $ Operator: For lists and data frames, the $ operator is a convenient shorthand for extracting elements by name. my_list$element_name is equivalent to my_list[["element_name"]] when the element name is a valid R symbol.

  • dplyr and tidyverse: For more complex data manipulation, the dplyr package (part of the tidyverse) provides intuitive functions like pull() which extracts a single column as a vector, similar to [[. For instance, data %>% pull(column_name) is a common pattern. You can learn more about the tidyverse ecosystem at tidyverse.org .

Frequently Asked Questions

FAQs on R Indexing Single vs Double Brackets

Q: What is the main difference between R's single and double brackets

ANS: Single brackets [] are for subsetting, returning a new object of the same class (like a sub-list or sub-data frame). Double brackets [[]] are for extraction, returning the actual element itself, stripped of its container, with its original data type.

Q: Can I use single brackets to get the actual value from a list element

ANS: No, single brackets will always return a list, even if it contains only one element. For the actual value, you need to use double brackets.

Q: When should I use double brackets for assignment

ANS: Use double brackets for assignment when you intend to replace a single, specific element within a list or data frame.

Q: What happens if I try to use multiple indices with double brackets

ANS: Attempting to use multiple indices or names with double brackets typically results in an error, such as ‘recursive indexing failed’ or ‘subscript out of bounds’, because [[]] is designed for single element access.

Q: Is the $ operator similar to double brackets

ANS: The $ operator is a shortcut for accessing list or data frame elements by name, similar to using double brackets with a character string name, like my_list$name is akin to my_list[["name"]].

Q: How does indexing differ for vectors and lists in R

ANS: For vectors, both [] and [[]] can extract elements. However, [[]] on vectors is generally less used and has subtle differences. The primary distinction becomes critical when working with lists, where [] preserves the list structure while [[]] extracts the raw element.
