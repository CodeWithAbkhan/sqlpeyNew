“Accessing R Function Source Code: Methods and Examples”

When working with R, you’ll often encounter situations where you need to inspect the underlying code of a function to understand its behavior, debug issues, or learn from its implementation. R offers several mechanisms to access function source code, catering to different types of functions, including those with S3 or S4 method dispatch, and those that call compiled code.

Understanding R’s Method Dispatch Systems (S3 and S4)

R employs sophisticated systems for dispatching functions based on the class of their arguments. These are primarily known as S3 and S4.

The S3 Method Dispatch System

S3 is an older, more informal system. When you call a generic function (like t()), R looks for a method specifically defined for the class of the input object. You can see available methods for a generic function or a specific class.

For example, to see the methods associated with the generic function t():

# List methods for the generic function 't'
methods(t)

This might output:

[1] t.data.frame t.default    t.ts*
   Non-visible functions are asterisked

The asterisk (*) indicates that a function is not exported from its package’s namespace. You can still access these non-visible functions using the ::: operator or the getAnywhere() function. getAnywhere() is particularly useful as it doesn’t require knowing the specific package.

Let’s examine the source code for t.ts using getAnywhere():

# Get the source code for the t.ts method
getAnywhere(t.ts)

The output will display the function definition:

A single object matching ‘t.ts’ was found
It was found in the following places
  registered S3 method for t from namespace stats
  namespace:stats
with value

function (x)
{
    cl <- oldClass(x)
    other <- !(cl %in% c("ts", "mts"))
    class(x) <- if (any(other))
        cl[other]
    attr(x, "tsp") <- NULL
    t(x)
}
<bytecode: 0x294e410>
<environment: namespace:stats>

To view all methods associated with a specific class, like "ts":

# List all methods defined for the 'ts' class
methods(class = "ts")

This will show functions such as aggregate.ts, cbind.ts, diff.ts, etc.

The S4 Method Dispatch System

S4 is a more formal and newer dispatch system. It is characterized by standardGeneric functions and explicit method definitions based on formal class signatures.

When you encounter a standardGeneric, it signifies an S4 function. To see the methods defined for an S4 function, you use showMethods().

# Load the Matrix package for demonstration
library(Matrix)

# Display available methods for chol2inv
showMethods("chol2inv")

The output might look like this, showing methods for different argument types:

Function: chol2inv (package base)
x="ANY"
x="CHMfactor"
x="denseMatrix"
x="diagonalMatrix"
x="dtrMatrix"
x="sparseMatrix"

To retrieve the source code for a specific method, you need to provide the full signature to getMethod():

# Get the source code for the chol2inv method for diagonalMatrix
getMethod("chol2inv", "diagonalMatrix")

This will reveal the implementation:

Method Definition:

function (x, ...)
{
    chk.s(...)
    tcrossprod(solve(x))
}
<bytecode: 0x000000000ea2cc70>
<environment: namespace:Matrix>

Signatures:
        x
target  "diagonalMatrix"
defined "diagonalMatrix"

For functions with more complex signatures, like extract from the raster package, you must provide the complete signature:

# Load the raster package
library(raster)

# Show methods for extract
showMethods(extract)

# Get the source code for extract when y is a SpatialPolygons object
getMethod("extract", signature = c(x = "Raster", y = "SpatialPolygons"))

Attempting to use a partial signature will result in an error:

# This will likely cause an error
getMethod("extract", signature = "SpatialPolygons")

Inspecting Unexported and Compiled Functions

Sometimes, functions rely on internal or unexported functions. You can access these using the ::: operator or getAnywhere(). For instance, ts.union uses unexported functions like .makeNamesTs.

# View the source code of the unexported .makeNamesTs function
stats:::.makeNamesTs

Functions that call compiled code (e.g., using .C, .Call, .Fortran, .External, .Internal, or .Primitive) require a different approach. You’ll need to consult the compiled code’s source files. The pryr::show_c_source() function can be helpful for .Internal and .Primitive calls, directing you to GitHub repositories.

If a compiled function uses an object (like NativeSymbolInfo) instead of a character string to reference the compiled function, printing that object can provide useful details. For example, optim calls stats:::C_optimhess.

Accessing Compiled Code in Packages:

To view compiled code within a package, you need to download the package source. The download.packages() function can fetch the source archive (.tar.gz).

# Download the source code for the Matrix package
download.packages(pkgs = "Matrix",
                  destdir = ".",
                  type = "source")

# Unpack the downloaded source
untar(download.packages(pkgs = "Matrix",
                        destdir = ".",
                        type = "source")[,2])

The compiled C/C++/Fortran code will typically reside in the src directory of the unpacked source files.

Accessing Compiled Code in Base Packages:

Base packages (like base, stats, utils) are part of the R distribution. Their source code is located within the R source tree, usually under /src/library/.

Accessing Code Built into the R Interpreter:

For code built directly into the R interpreter, you’ll need to download and unpack the R source code itself. Alternatively, you can browse the R source online through its Subversion repository or mirrors like Winston Chang’s GitHub mirror. Uwe Ligges’s R news article provides detailed guidance on finding source code for .Internal and .Primitive functions.

Alternative Methods for Viewing Function Source Code

Beyond the system-level methods, R provides several convenient functions for inspecting code:

1. Using getAnywhere() for Direct Access

getAnywhere() is a versatile tool that searches for objects (including functions) across all loaded namespaces and the global environment.

# View source code for 'rfcv' from the randomForest package
getAnywhere('rfcv')

You can also redirect this output to a file for easier editing or processing:

# Save the source code of 'rfcv' to a file
capture.output(getAnywhere('rfcv'), file = 'source_rfcv.r')

2. Employing edit() and View()

  • edit(): This function opens the source code of a function in your default text editor. You can even assign the edited version to a new variable. Using invisible(edit(function_name)) allows you to view the code without cluttering the console.

    # Open the source code of the 'optim' function in an editor
new_optim <- edit(optim)

# View source code without printing to console
invisible(edit(optim))

  • View(): This function (with an uppercase ‘V’) opens the source code in a read-only pane, typically within RStudio.

    # View the source code of the 'mean' function
View(mean)

    In RStudio, you can also simply place your cursor on a function name and press F2, or hold Ctrl (Windows/Linux) or Cmd (macOS) and click the function name.

3. Utilizing body() and print()

For non-primitive R functions, body() extracts the function’s body. capture.output(print(body(function_name))) or deparse(body(function_name)) can return the body as a character vector, useful for programmatic access.

# Get the body of the print.Date function
body(print.Date)

# Capture the body as a character vector
sourceVector <- capture.output(print(body(print.Date)))
cat(paste0("      ", sourceVector, "\n"))

# A more direct way to get the character vector
sourceVector_deparse <- deparse(body(print.Date))

Simply printing a function object will also display its source code.

# Define a simple function
my_func <- function(x) {
  x + 5
}

# Print the function to see its source
print(my_func)

4. Debugging with debug() and debugonce()

The debug() function allows you to step through a function’s execution, revealing its code line by line. debugonce() does the same but only for the first call.

# Enter debugging mode for the 't' function
debug(t)

# Call the function (e.g., t(co2))
t(co2)

When debugging, you’ll see prompts like Browse[2]>, indicating where you can issue R commands to inspect variables or continue execution. Use undebug() to exit debugging mode.

5. Using functionBody()

For functions written purely in R (not C/C++/Fortran), functionBody() directly returns the function’s body.

# Get the body of a function (ensure it's not a primitive)
functionBody(my_func)

6. Handling UseMethod() and .Primitive()

When a function call results in UseMethod("function_name"), it indicates that R is looking for specific methods. Use methods("function_name") to find available methods and then getAnywhere() for the specific method you’re interested in (e.g., getAnywhere("read_xml.character")).

Functions that are .Primitive() (implemented internally in C) cannot have their source code viewed directly through these R commands. For these, debugging or examining the R source code is necessary.

# Example demonstrating UseMethod
library(xml2)
read_xml # Might show UseMethod

# List available methods
methods("read_xml")

# View a specific method's source
getAnywhere("read_xml.character")

# Example of a primitive function
sum

# View the mode of a function (less common for source code)
View(mode)

7. IDE Integrations

Integrated Development Environments (IDEs) like RStudio and IDEs with R plugins (e.g., PyCharm) offer streamlined ways to view function source code:

  • RStudio: F2 key on a function name, or Ctrl/Cmd + Click.
  • PyCharm (with R plugin): Ctrl/Cmd + B on a function name in the editor or console (“Go to Declaration”).

These IDE features are highly efficient but generally won’t work for .Primitive functions.

By employing these diverse methods, you can effectively explore and inspect the source code of R functions, enhancing your programming and debugging capabilities.

FAQs on Accessing R Function Source Code

Q: How can I see the source code of an S3 generic function in R

ANS: Use the methods() function to list available methods for the generic function, and then getAnywhere() or stats::: to view the source of specific methods. For example, methods(t) and then getAnywhere("t.data.frame").

Q: What is the difference between S3 and S4 method dispatch in R

ANS: S3 is an informal system using UseMethod() and function naming conventions (e.g., fun.class). S4 is a formal system with standardGeneric, formal class definitions, and setMethod() for defining methods based on signatures. S4 is generally more robust and explicit.

Q: Can I view the source code of functions implemented in C or Fortran

ANS: No, not directly through R commands. For functions calling compiled code, you need to access the package’s source files or the R interpreter’s source code. pryr::show_c_source() can help locate C code for .Internal and .Primitive functions.

Q: How do I view the source code of an unexported function in R

ANS: You can use the ::: operator (e.g., stats:::.makeNamesTs) or the getAnywhere() function to access and view the source code of unexported functions.

Q: What is the easiest way to view R function source code in RStudio

ANS: Place your cursor on the function name and press F2, or hold Ctrl/Cmd and click on the function name. Alternatively, use View(function_name) or edit(function_name).

Q: How can I get the source code of an R function as a character vector

ANS: For non-primitive functions, use deparse(body(function_name)) or capture.output(print(body(function_name))). This is useful for programmatically processing the code.

Q: What does the asterisk (*) mean next to a function name in `methods()` output

ANS: An asterisk indicates that the function is not exported from its package’s namespace. It’s an internal function that can still be accessed using ::: or getAnywhere().

Q: How do I find out which package a function belongs to in R

ANS: Use the find(function_name) or where(function_name) function. apropos() can also be used to search for objects by name.
