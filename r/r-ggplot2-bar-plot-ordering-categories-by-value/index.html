“R ggplot2 Bar Plot: Ordering Categories by Value in Descending Sequence”

When generating bar plots in R using ggplot2, the default ordering often follows the input data sequence or alphabetical sorting of the factor levels. However, for clearer data visualization, it is frequently necessary to arrange the bars so they descend from the largest value to the smallest. If you have data structured like the sample corr.m dataframe below, how can you reliably enforce this descending order in your plot?

The initial sample data structure for this demonstration involves miRNA correlation values:

corr.m <- structure(list(miRNA = structure(c(5L, 2L, 3L, 6L, 1L, 4L), .Label = c("mmu-miR-139-5p", "mmu-miR-1983", "mmu-miR-301a-3p", "mmu-miR-5097", "mmu-miR-532-3p", "mmu-miR-96-5p"), class = "factor"),
                         variable = structure(c(1L, 1L, 1L, 1L, 1L, 1L), .Label = "pos", class = "factor"),
                         value = c(7L, 75L, 70L, 5L, 10L, 47L)),
                    class = "data.frame", row.names = c("1", "2", "3", "4", "5", "6"))

# Displaying the base structure
print(corr.m)

The goal is to visualize value on the y-axis, categorized by miRNA on the x-axis, sorted from the highest value (75) to the lowest (5).

Solution Pathways for Descending Bar Plot Ordering

Several robust techniques within the ggplot2 ecosystem and the broader tidyverse facilitate this sorting requirement.

Method 1: Using reorder() with a Negative Value Sign

The simplest adjustment to the standard reorder() function within aes() is to prefix the ordering variable with a minus sign (-) if the ordering variable is numeric. This effectively reverses the sorting direction from ascending (default) to descending.

If your initial attempt resulted in an ascending plot:

# Initial (Ascending/Default) attempt - Not shown, but assumed to be low-to-high
# ggplot(corr.m, aes(x = reorder(miRNA, value), y = value, fill = variable)) + 
#   geom_bar(stat = "identity")

Apply the negation to achieve descending order:

library(ggplot2)

# Solution 1: Negating the value inside reorder()
ggplot(corr.m, aes(x = reorder(miRNA, -value), y = value, fill = variable)) + 
  geom_bar(stat = "identity")

This is a direct and often preferred approach for quick visual sorting when using reorder().

Method 2: Employing desc() within reorder() or Pre-sorting Factors

This method utilizes the desc() helper function, which explicitly signals a descending sort, or alternatively, modifies the factor levels of the grouping variable beforehand.

Technique 2a: Using desc() argument with reorder()

This is the declarative counterpart to using the negative sign:

# Solution 2a: Using desc() argument for explicit descending reordering
ggplot(corr.m, aes(x = reorder(miRNA, desc(value)), y = value, fill = variable)) + 
   geom_bar(stat = "identity")

Technique 2b: Pre-sorting Factor Levels via dplyr

This approach manipulates the data frame before plotting by explicitly setting the factor levels of the miRNA column based on the descending order of value. This removes the need for reorder() in the plot call.

library(dplyr)
library(ggplot2)

# Solution 2b: Releveling the miRNA factor before plotting
corr.m_sorted <- corr.m %>%
   arrange(desc(value)) %>%
   # Crucially, update miRNA factor levels based on the new unique order
   mutate(miRNA = factor(miRNA, levels = unique(miRNA))) 

ggplot(corr.m_sorted, aes(x = miRNA, y = value, fill = variable)) + 
   geom_bar(stat = "identity")

Method 3: Explicit Factor Level Creation

This solution creates the required factor ordering directly within the data preparation phase, regardless of the plotting function used. This is useful if you need the sorted factor structure for other analyses or plots.

library(ggplot2)

# Solution 3: Manually creating the factor levels in decreasing order
corr.m$miRNA <- factor(corr.m$miRNA, 
                       levels = corr.m$miRNA[order(corr.m$value, decreasing = TRUE)])

# Plotting now respects the established factor levels
ggplot(corr.m, aes(x=miRNA, y=value, fill=variable)) + 
  geom_bar(stat="identity")

If you needed ascending order (though not the primary goal here), you would set decreasing = FALSE.

Method 4: Utilizing forcats::fct_reorder with geom_col

The forcats package (part of tidyverse) offers fct_reorder, which is generally more versatile than base R’s reorder(). When combining this with geom_col() (which is shorthand for geom_bar(stat = "identity")), you can achieve the descending sort concisely.

We start by ensuring the data is tidy, perhaps using tribble for clean initialization:

# Data initialization using tribble for clarity
library(tibble)
library(ggplot2)
library(forcats)

corr.m_tidy <- tribble(
  ~miRNA,            ~variable, ~value,
  "mmu-miR-532-3p",  "pos",     7,
  "mmu-miR-1983",    "pos",     75,
  "mmu-miR-301a-3p", "pos",     70,
  "mmu-miR-96-5p",   "pos",     5,
  "mmu-miR-139-5p",  "pos",     10,
  "mmu-miR-5097",    "pos",     47
)

# Solution 4: Using forcats::fct_reorder with .desc = TRUE
ggplot(corr.m_tidy,
       aes(x = fct_reorder(miRNA, value, .desc = TRUE), # Explicit descending flag
           y = value, fill = variable)) + 
  geom_col() + # Uses stat="identity" by default
  xlab("miRNA Identifier") +
  ylab("Correlation Value")

In fct_reorder(variable, order_variable, .desc = TRUE), setting .desc = TRUE directly tells the function to order the first argument (miRNA) based on the second argument (value) in descending order.

FAQs on R ggplot2 Bar Plot Ordering

Q: What is the primary difference between reorder and forcats::fct_reorder

ANS: Base R’s reorder() works well for simple factor ordering within plotting functions. forcats::fct_reorder() is more robust, especially when integrating with the pipe operator, and offers explicit arguments like .desc for controlling sort direction, making it generally favored in modern tidyverse workflows.

Q: Can I use geom_col instead of geom_bar stat identity

ANS: Yes, geom_col() is a shorthand function specifically designed for cases where you provide the bar heights directly via the aesthetics (y aesthetic), which is equivalent to calling geom_bar(stat = "identity").

Q: Why does my bar plot order alphabetically after sorting

ANS: If you use Solution 3 (pre-sorting the factor levels) but forget to set decreasing = TRUE in the order() call, R will use the default ascending order, or if the factor levels were reset elsewhere, it might revert to alphabetical sorting. Always verify the factor levels in the data frame if a pre-sorting method is used.
