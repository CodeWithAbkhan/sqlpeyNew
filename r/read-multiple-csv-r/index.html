“Efficiently Read Multiple CSV Files into a Single Data Frame in R”

When working with data analysis in R, it’s a common scenario to encounter numerous CSV files that need to be read and consolidated into a single data frame for further processing. This task can range from simple file aggregation to complex performance optimization depending on the number, size, and structure of the CSV files. Several approaches exist, utilizing base R functions, popular packages like tidyverse and data.table, and even external command-line tools.

Here’s a look at various methods to achieve this, along with code examples and performance considerations.

Solution 1: Base R lapply and do.call

This fundamental approach involves listing all CSV files in a directory, applying a reading function to each, and then combining the resulting data frames.

Scenario: CSV files are in the current working directory, all with the .csv extension.

  • Reading files into a list:

    # List all files ending with .csv in the current directory
temp_files <- list.files(pattern = "\\.csv$")

# Read each file using read.delim and store them in a list
my_files_list <- lapply(temp_files, read.delim)

  • Combining the list into a single data frame: The my_files_list now contains each CSV as a separate data frame. To combine them, you can use do.call(rbind, ...) for base R, or more specialized functions from packages like dplyr or data.table.

    # Combine the list of data frames into one
combined_data_base <- do.call(rbind, my_files_list)

  • Assigning each data frame to a unique object: While generally not recommended for large numbers of files due to potential namespace clutter, you can assign each data frame to a separate object using assign().

    # Assign each file to a distinct object (use with caution)
for (i in 1:length(temp_files)) {
  assign(temp_files[i], read.csv(temp_files[i]))
}

  • Using list2env for object creation: A more structured way to create objects from a list is using list2env. This also allows for cleaning up file names.

    # Clean file names and load into the environment
temp_files <- list.files(pattern = "\\.csv$")

# Create names for the data frames by removing the .csv extension
file_names_cleaned <- make.names(gsub("\\.csv$", "", temp_files))

# Load the data frames into the global environment
list2env(
  lapply(setNames(temp_files, file_names_cleaned), read.csv), 
  envir = .GlobalEnv
)

    Note: It’s generally more efficient and manageable to keep data frames in a list rather than creating individual objects.

Solution 2: tidyverse (readr and dplyr)

The tidyverse ecosystem offers concise and efficient ways to handle data manipulation, including reading multiple files.

  • Using map_df with read_csv: This is a rapid and elegant method for combining multiple CSVs.

    library(tidyverse)

# Read all CSVs and bind them into a single tibble
combined_data_tidyverse <- list.files(pattern = "\\.csv$") %>% 
  map_df(~read_csv(.))

  • Forcing column types: If type casting is problematic, you can force all columns to be characters.

    combined_data_char_types <- list.files(pattern = "\\.csv$") %>% 
  map_df(~read_csv(., col_types = cols(.default = "c")))

  • Reading from subdirectories: To include files from subdirectories, use full.names = TRUE and ensure the path is specified correctly.

    combined_data_subdir <- list.files(path = "./your_subdirectory/",
                                   pattern = "\\.csv$",
                                   full.names = TRUE) %>%
  map_df(~read_csv(., col_types = cols(.default = "c")))

  • Appending original filenames: To keep track of the source file for each row, you can modify the reading function.

    # Function to read and append filename
read_with_filename <- function(file_path) {
  read_csv(file_path) %>%
    mutate(source_filename = file_path)
}

combined_data_with_source <- list.files(pattern = "\\.csv$", full.names = TRUE) %>%
  map_df(~read_with_filename(.))

Solution 3: data.table (fread and rbindlist)

For maximum speed, especially with large datasets, data.table’s fread and rbindlist are highly recommended.

  • fread with lapply and rbindlist: This combination is significantly faster than base R.

    library(data.table)

# Read all CSVs using fread and combine
combined_data_fread <- list.files(pattern = "\\.csv$") %>%
  lapply(fread) %>% 
  rbindlist()

  • fread with map_df: A tidyverse-friendly approach using fread.

    library(tidyverse)
library(data.table)

combined_data_map_fread <- list.files(pattern = "\\.csv$") %>% 
  map_df(~fread(.))

Solution 4: Shell commands with fread

When dealing with a massive number of files, leveraging shell commands directly within R can offer substantial speed improvements.

  • Concatenating files with cat and reading with fread: This is extremely fast for files without headers.

    # For files without headers
combined_data_cat <- fread(cmd = 'cat *.csv', header = FALSE)

  • Handling headers with awk: To include headers only from the first file.

    # For files with headers
combined_data_awk_header <- fread(cmd = "awk 'NR==1||FNR!=1' *.csv", header = TRUE)

  • Using find and xargs for large numbers of files: When the shell glob *.csv might fail due to too many files.

    # If the glob fails due to too many files
combined_data_find_cat <- fread(cmd = 'find . -name "*.csv" | xargs cat', header = FALSE)

# With headers
header_info <- fread(cmd = 'find . -name "*.csv" | head -n1 | xargs head -n1', header = TRUE)
combined_data_find_awk <- fread(cmd = 'find . -name "*.csv" | xargs tail -q -n+2', header = FALSE)
setnames(combined_data_find_awk, names(header_info))

  • Creating a combined file for very large datasets: If the concatenated file itself might exceed memory, create an intermediate file.

    # Create a single combined file first
system('find . -name "*.csv" | xargs cat > combined_all.csv')
combined_data_intermediate <- fread('combined_all.csv', header = FALSE)
    • With headers: 
      system('find . -name "*.csv" | head -n1 | xargs head -n1 > combined_with_header.csv')
system('find . -name "*.csv" | xargs tail -q -n+2 >> combined_with_header.csv')
combined_data_intermediate_header <- fread('combined_with_header.csv', header = TRUE)

  • Custom fread_many function: A utility function can encapsulate these shell operations for convenience.

    # Function to read multiple files efficiently
fread_many <- function(files, header = TRUE, ...) {
  if (length(files) == 0) return(NULL)
  if (!is.character(files)) return(NULL)
  files <- files[file.exists(files)]
  if (length(files) == 0) return(NULL)

  temp_output_file <- tempfile(fileext = ".csv")

  if (header) {
    # Append header from the first file, then data from all files
    system(paste0('head -n1 ', files[1], ' > ', temp_output_file))
    system(paste0("xargs awk 'FNR>1' >> ", temp_output_file), input = files)
  } else {
    # Append data from all files
    system(paste0("xargs awk '1' > ", temp_output_file), input = files)
  }

  dt_result <- fread(file = temp_output_file, header = header, ...)
  file.remove(temp_output_file)
  return(dt_result)
}

Solution 5: Unix cat command (external to R)

If you have access to a Unix-like environment (or Cygwin on Windows), you can pre-process your files.

  • Without headers:

    cat *.csv > all_combined.csv

  • With headers (using grep to exclude header lines): This assumes header lines start with a unique pattern like “Age”.

    cat *.csv | grep -v '^Age' > all_combined_with_headers.csv

    You would then read all_combined.csv or all_combined_with_headers.csv into R using fread() or read.csv().

Solution 6: Creating separate data frames with assign

This method creates individual data frame objects in your R environment, named after the CSV files.

# Specify the path to your CSV files
file_path <- "C:/Users/cfees/My Box Files/Fitness/"
csv_files <- list.files(path = file_path, pattern = "*.csv")

# Loop through files and assign them
for (file in csv_files) {
  # Find the position of the period to separate name from extension
  period_position <- which(strsplit(file, "")[[1]] == ".")
  
  # Clean the filename (remove spaces and extension)
  dataframe_name <- gsub(" ", "", substr(file, 1, period_position - 1))
  
  # Read the CSV and assign it to a new object
  assign(
    x = dataframe_name, 
    value = read.csv(paste(file_path, file, sep = "")),
    envir = .GlobalEnv
  )
}

This function is versatile and can handle various file formats, often leveraging fread internally for speed.

Solution 8: Parallel processing with plyr and doSNOW

For very large numbers of files, parallel processing can dramatically reduce reading times.

library(plyr)
library(data.table)
library(doSNOW) # For parallel execution

# List of CSV files
csv_file_list <- list.files(path = "t:/data", pattern = ".csv$", full.names = TRUE)

# Set up parallel cluster
num_cores <- 4 # Adjust based on your system
cluster <- makeCluster(num_cores)
registerDoSNOW(cluster)

# Progress bar setup
progress_bar <- txtProgressBar(max = length(csv_file_list), style = 3)
update_progress <- function(i) setTxtProgressBar(progress_bar, i)

# Read and combine files in parallel
combined_data_parallel <- setDT(ldply(csv_file_list, 
                                    fread, 
                                    .parallel = TRUE, 
                                    .paropts = list(.options.snow = list(progress = update_progress))))

# Stop the cluster
stopCluster(cluster)

Solution 9: purrr with filename as an identifier

This approach uses purrr to read files and conveniently adds a column identifying the source filename.

library(tidyverse)

data_directory <- "my/directory"
file_paths <- list.files(data_directory, pattern = "csv", full.names = TRUE) %>%
  set_names() # Use filenames as names for map_dfr

# Read and bind, adding filename as a column
combined_data_purrr_id <- file_paths %>% 
  map_dfr(~read_csv(.), .id = "filename")

# To get just the base filename (without path):
combined_data_purrr_base <- combined_data_purrr_id %>% 
  mutate(filename = basename(filename))

Solution 10: Efficient assignment with readr and stringr

Similar to Solution 6, but using readr::read_csv and stringr for cleaner filename manipulation.

Solution 13: Custom read.directory function

A user-defined function can offer flexibility by parameterizing the reader and reducer.

# Function to read directory contents
read_directory <- function(path = '.', 
                           pattern = NULL, 
                           reader = read.csv, 
                           ..., 
                           reducer = function(dfs) do.call(rbind.data.frame, dfs), 
                           recursive = FALSE) {
  
  files_in_dir <- list.files(path, pattern, full.names = TRUE, recursive = recursive)
  
  reducer(lapply(files_in_dir, reader, ...))
}

# Example usage:

#                                        pattern = "\\.csv$", 
#                                        reader = readr::read_csv)

This function allows specifying custom readers (like readr::read_csv or data.table::fread) and reducers.

Solution 14: Parallel processing with doParallel or future.apply

Leveraging multi-core processors for faster data loading.

  • Using doParallel:

    if (!require("pacman")) install.packages("pacman")
pacman::p_load(doParallel, data.table, stringr)

# Get CSV file names
csv_filenames <- dir() %>% str_subset("\\.csv$")

# Set up parallel cluster
core_count <- detectCores()
cluster <- makeCluster(core_count)
registerDoParallel(cluster)

# Read and bind files in parallel
system.time({
  big_dataframe <- foreach(
    i = csv_filenames,
    .packages = "data.table"
  ) %dopar% {
    fread(i, colClasses = "character") # Specify column classes for consistency
  } %>%
    rbindlist(fill = TRUE)
})

# Stop the cluster
stopImplicitCluster(cluster)

  • Using future.apply:

    if (!require("pacman")) install.packages("pacman")
pacman::p_load(future.apply, data.table, stringr)

# Get CSV file names
csv_filenames <- dir() %>% str_subset("\\.csv$")

# Set up parallel processing plan
plan(multiprocess)

# Read and combine using future_lapply
merged_data_table <- future_lapply(csv_filenames, fread, colClasses = "character") %>% 
  rbindlist(fill = TRUE)

Performance Benchmarks

For assessing the speed of these methods, the microbenchmark package is invaluable. Key findings often highlight:

  • data.table::fread is generally the fastest for reading CSVs, especially large ones.
  • tidyverse::read_csv offers a good balance of speed and ease of use.
  • Shell commands (cat, awk, xargs) via fread(cmd=...) can provide the absolute fastest performance for massive datasets with many files, particularly on multi-core systems.
  • Base R methods (read.delim, read.csv, do.call) are often slower but require no external package installations.
  • Parallel processing significantly speeds up tasks involving a large number of files.
  • For very small files or datasets, the overhead of some advanced packages might make base R competitive or even faster.

When choosing a method, consider the size and quantity of your files, your system’s resources (especially CPU cores), and your familiarity with different R packages.

FAQs on Reading Multiple CSV Files in R

Q: How do I read all CSV files from a specific folder in R

ANS: You can use list.files(path = "your/folder/path", pattern = "\\.csv$", full.names = TRUE) to get a list of all CSV file paths. Then, you can iterate through this list using functions like lapply, purrr::map, or data.table::fread in a loop or with a combining function like do.call(rbind, ...) or data.table::rbindlist. For efficient reading, consider purrr::map_df with readr::read_csv or lapply with data.table::fread.

Q: What is the fastest way to read many CSV files in R

ANS: For speed with many CSV files, data.table::fread is highly recommended. Combining it with lapply and rbindlist or using purrr::map_df offers excellent performance. For extremely large numbers of small files, leveraging shell commands like cat or awk through fread(cmd = '...') can provide the greatest speed advantage, especially when coupled with parallel processing.

Q: How can I combine multiple CSV files into one data frame

ANS: After reading each CSV file into a separate data frame (typically stored in a list), you can combine them into a single data frame using do.call(rbind, your_list_of_data_frames) in base R, dplyr::bind_rows() from the tidyverse, or data.table::rbindlist(). Packages like purrr::map_df and readr::read_csv(files, id = "filename") perform reading and binding in one step.

Q: How do I read CSV files into R without loading them all into memory at once

ANS: If you have a very large number of files and memory is a concern, consider reading them in batches. You could iterate through subsets of your list.files output, process each batch, and append to a file or a database. Alternatively, for immense datasets, using out-of-memory data frame solutions like data.table’s fread with cmd arguments that process data as it’s streamed, or packages designed for disk-based data manipulation, might be necessary.

Q: How to read CSVs with different column names or structures

ANS: When CSV files have different structures, directly combining them with rbind or rbindlist will result in errors or unintended column alignment. You’ll need to pre-process each file after reading to ensure a consistent structure. This might involve selecting specific columns, renaming columns to a common standard, or handling missing columns by filling them with NA before combining. Using purrr::map with custom functions for each file type before binding is a robust approach.

Q: Can I read CSV files from subfolders in R

ANS: Yes, you can read CSV files from subfolders by using the recursive = TRUE argument in list.files() or by providing a path that includes subdirectories and setting full.names = TRUE. For example: list.files(path = "your/main_folder", pattern = "\\.csv$", recursive = TRUE, full.names = TRUE). Then, proceed with reading and combining as usual.
