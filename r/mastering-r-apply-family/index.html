R’s Apply Family

When working with R, a fundamental aspect of efficient data manipulation involves applying functions across different data structures. R’s powerful “*apply” family of functions provides elegant solutions for iterating over lists, vectors, matrices, and arrays. This guide will demystify these functions, helping you select the right tool for your specific task.

While the incredibly popular plyr package, as noted by some contributors, covers much of the functionality of the base *apply functions, the base functions themselves remain essential and worth mastering for their efficiency and ubiquity in R code. This guide aims to be a signpost for new R users, directing you to the most appropriate *apply function for your particular problem. The goal is to help you decide which function best suits your situation, after which you can delve deeper into the specific R documentation for more advanced usage. For most scenarios, performance differences between these base functions won’t be the primary deciding factor, but later we’ll touch upon performance considerations.

Core *apply Functions and Their Use Cases

apply(): Operating on Matrix/Array Dimensions

Use apply when you need to apply a function to the rows or columns of a matrix, or to higher-dimensional arrays. Be cautious when applying it to data frames, as it will coerce them into matrices first, potentially leading to unexpected results if data types are mixed.

For quick row or column means or sums on a 2D matrix, consider the highly optimized colMeans, rowMeans, colSums, and rowSums.

Example with a 2D Matrix:

# Create a 4x4 matrix
M <- matrix(seq(1, 16), 4, 4)

# Apply minimum function to each row (MARGIN = 1)
apply(M, 1, min)
# Expected Output: [1] 1 2 3 4

# Apply maximum function to each column (MARGIN = 2)
apply(M, 2, max)
# Expected Output: [1]  4  8 12 16

Example with a 3D Array:

# Create a 4x4x2 array
M_3d <- array(seq(32), dim = c(4, 4, 2))

# Apply sum across each M[*, , ] (summing across the 2nd and 3rd dimensions)
apply(M_3d, 1, sum)
# Expected Output: [1] 120 128 136 144

# Apply sum across each M[*, *, ] (summing across the 3rd dimension)
apply(M_3d, c(1, 2), sum)
# Expected Output:
#      [,1] [,2] [,3] [,4]
# [1,]   18   26   34   42
# [2,]   20   28   36   44
# [3,]   22   30   38   46
# [4,]   24   32   40   48

lapply(): List Processing Powerhouse

lapply is your go-to when you want to apply a function to each element of a list (or vector) and receive a list as the output. It’s a foundational function, often found at the core of many other *apply functions.

Example:

# Create a list with different element types
x <- list(a = 1, b = 1:3, c = 10:100)

# Get the length of each list element
lapply(x, FUN = length)
# Expected Output:
# $a
# [1] 1
#
# $b
# [1] 3
#
# $c
# [1] 91

# Get the sum of each list element
lapply(x, FUN = sum)
# Expected Output:
# $a
# [1] 1
#
# $b
# [1] 6
#
# $c
# [1] 5005

sapply(): Simplifying List Output

Use sapply when you want the output of lapply but prefer a vector or matrix instead of a list. If you find yourself writing unlist(lapply(...)), sapply is likely the more direct solution.

sapply attempts to simplify the output. If the function returns vectors of the same length, it will try to combine them into a matrix. If the function returns matrices of the same dimensions, it can form a multi-dimensional array if simplify = "array" is specified.

Example:

x <- list(a = 1, b = 1:3, c = 10:100)

# Get the length of each list element (returns a vector)
sapply(x, FUN = length)
# Expected Output:
#  a  b  c
#  1  3 91

# Get the sum of each list element (returns a vector)
sapply(x, FUN = sum)
# Expected Output:
#     a    b    c
#     1    6 5005

# Example generating vectors of different lengths
sapply(1:5, function(i) rnorm(3, i))

# Example generating matrices
sapply(1:5, function(i) matrix(i, 2, 2))

# Example generating matrices and simplifying to an array
sapply(1:5, function(i) matrix(i, 2, 2), simplify = "array")

vapply(): Type-Safe and Potentially Faster sapply

vapply is similar to sapply but offers more control and can sometimes yield performance improvements. You provide an example of the expected return value’s type and length (FUN.VALUE), allowing R to validate the output and potentially optimize the process.

Example:

x <- list(a = 1, b = 1:3, c = 10:100)

# Apply length function, expecting an integer of length 1 for each element
vapply(x, FUN = length, FUN.VALUE = 0L)
# Expected Output:
#  a  b  c
#  1  3 91

mapply(): Multivariate Apply

Use mapply when you need to apply a function to corresponding elements from multiple lists or vectors simultaneously. The function you apply must accept multiple arguments, one for each input data structure. It also simplifies the output, similar to sapply.

Example:

# Sum corresponding elements from three vectors
mapply(sum, 1:5, 1:5, 1:5)
# Expected Output: [1]  3  6  9 12 15

# Repeat elements with varying counts
mapply(rep, 1:4, 4:1)
# Expected Output:
# [[1]]
# [1] 1 1 1 1
#
# [[2]]
# [1] 2 2 2
#
# [[3]]
# [1] 3 3
#
# [[4]]
# [1] 4

Map(): List-Oriented mapply

Map is essentially mapply with SIMPLIFY = FALSE, ensuring that the output is always a list, regardless of the function’s return type.

Example:

# Sum corresponding elements from three vectors, returning a list
Map(sum, 1:5, 1:5, 1:5)
# Expected Output:
# [[1]]
# [1] 3
#
# [[2]]
# [1] 6
#
# [[3]]
# [1] 9
#
# [[4]]
# [1] 12
#
# [[5]]
# [1] 15

rapply(): Recursive List Processing

When dealing with nested list structures (lists within lists), rapply is your tool. It applies a function recursively to each element.

Example:

# Custom function to modify list elements
myFun <- function(x) {
  if (is.character(x)) {
    return(paste(x, "!", sep = ""))
  } else {
    return(x + 1)
  }
}

# A nested list structure
l <- list(a = list(a1 = "Boo", b1 = 2, c1 = "Eeek"),
          b = 3,
          c = "Yikes",
          d = list(a2 = 1, b2 = list(a3 = "Hey", b3 = 5)))

# Apply myFun to all elements, resulting in a named vector
rapply(l, myFun)

# Apply myFun to all elements, preserving the nested list structure
rapply(l, myFun, how = "replace")

tapply(): Subsetting and Applying

tapply is designed for applying a function to subsets of a vector, where the subsets are defined by another vector, typically a factor. It’s often described as dealing with “ragged arrays.”

Example:

# A vector of values
x <- 1:20

# A factor defining groups (each letter group has 4 values)
y <- factor(rep(letters[1:5], each = 4))

# Sum values within each group
tapply(x, y, sum)
# Expected Output:
#  a  b  c  d  e
# 10 26 42 58 74

Related Functions and Enhancements

by(): DataFrame-Friendly tapply

The by function can be viewed as a “wrapper” for tapply, especially useful when you need to apply functions to data frames. It dispatches a specific method for the data frame class, allowing functions like summary to work even when the input types or lengths differ across groups.

Example:

# Using the iris dataset
# tapply with summary might struggle with data frames directly
# ct <- tapply(iris, iris$Species, summary) # This would likely error

# by handles data frames gracefully
bywork <- by(iris, iris$Species, summary)
print(bywork)

aggregate(): DataFrame Summaries

aggregate provides another way to work with data frames, similar to tapply but often producing a data frame as output, which can be more convenient. It also supports subsetting via the subset argument and can work with formulas.

Example:

# Using the ToothGrowth dataset
ag <- aggregate(len ~ ., data = ToothGrowth, mean)
print(ag)

# Using the airquality dataset with multiple columns and a formula
ag1 <- aggregate(cbind(Ozone, Temp) ~ Month, data = airquality, mean, na.rm = TRUE)
print(ag1)

ave(): Plugging Results Back into Data Frames

ave is a convenient function that returns results in a format directly pluggable back into a data frame. It’s like a more data-frame-centric version of tapply.

Example:

dfr <- data.frame(a = 1:20, f = rep(LETTERS[1:5], each = 4))

# Using tapply and then manually assigning
means <- tapply(dfr$a, dfr$f, mean)
dfr$m <- means[dfr$f]

# Using ave for a cleaner approach
dfr$m2 <- ave(dfr$a, dfr$f, FUN = mean)
print(dfr)

sweep(): Array Manipulation

The sweep function is useful for applying operations to array margins (rows or columns), such as centering or scaling data.

Example:

dataPoints <- matrix(4:15, nrow = 4)

# Find column means
dataPoints_means <- apply(dataPoints, 2, mean)

# Center the data points column-wise
dataPoints_Trans1 <- sweep(dataPoints, 2, dataPoints_means, "-")
print(dataPoints_Trans1)

# Find column standard deviations
dataPoints_sdev <- apply(dataPoints, 2, sd)

# Normalize the centered data points column-wise
dataPoints_Trans2 <- sweep(dataPoints_Trans1, 2, dataPoints_sdev, "/")
print(dataPoints_Trans2)

outer(): Combinatorial Function Application

outer is powerful for applying a function to all combinations of elements from two vectors. Unlike mapply which pairs elements sequentially, outer creates a grid of operations.

Example:

A <- c(1, 3, 5, 7, 9)
B <- c(0, 3, 6, 9, 12)

# Using mapply for pairwise max
mapply(FUN = pmax, A, B)

# Using outer for all combinations of pmax
outer(A, B, pmax)

eapply(): Environment Iteration

For applying functions to elements within an R environment (like .GlobalEnv), eapply is the tool. It’s less commonly used but can be helpful for introspection and package development.

Example:

# Checking for functions in the global environment
A <- c(1, 3, 5, 7, 9)
B <- c(0, 3, 6, 9, 12)
C <- list(x = 1, y = 2)
D <- function(x) { x + 1 }

eapply(.GlobalEnv, is.function)

Performance Considerations and Modern Alternatives

For computationally intensive tasks, especially with large datasets, specialized packages offer significant performance advantages.

collapse Package: High-Performance dapply and BY

The collapse package provides optimized functions like dapply (for data frame/matrix operations) and BY (for split-apply-combine tasks). It also introduces extremely fast C++ based functions (fmean, fsd, etc.) that perform grouped computations in a single pass, often outperforming even dplyr and data.table on smaller datasets.

Example with collapse:

# Install if you haven't already: install.packages("collapse")
library(collapse)

# Using dapply
dapply(mtcars, log)

# Using BY
BY(iris$Sepal.Length, iris$Species, sum)

# Using fast functions (fmean)
v <- iris$Sepal.Length
f <- iris$Species
fmean(v, f) # Grouped mean
fscale(v, f) # Grouped standardizing

Parallel Processing Packages

For leveraging multi-core processors, consider:

  • parallels package: parApply() offers parallel application of functions.
  • foreach and doParallel: Enable parallel execution of loops and functions.
  • future package: Provides a unified API for asynchronous computation, including parallel execution.
  • purrr package: Integrates with future for parallel mapping.

Example with future and purrr:

# Install if you haven't already: install.packages(c("future", "purrr"))
library(future)
library(purrr)

# Set up parallel processing
plan(multisession, workers = 2)

my_list <- list(1, 2, 3, 4, 5)

my_fun <- function(x) {
  x^2
}

# Parallel map with purrr and future
result <- future_map(my_list, my_fun)
print(result)

FAQs on Mastering R’s Apply Family

Q: What is the main difference between lapply and sapply

ANS: lapply always returns a list, even if the function applied returns a single value. sapply, on the other hand, attempts to simplify the output to a vector or matrix when possible, making it more convenient for straightforward results.

Q: When should I use vapply instead of sapply

ANS: Use vapply when you need more control over the output type or when you want to ensure type consistency and potentially gain a performance boost. This is achieved by specifying the expected return value type and length using the FUN.VALUE argument.

Q: How does mapply differ from Map

ANS: mapply applies a function to corresponding elements of multiple lists/vectors and simplifies the output to a vector or matrix if possible. Map is equivalent to mapply with SIMPLIFY = FALSE, guaranteeing a list output.

Q: Can tapply be used with data frames directly

ANS: Prior to R 4.3.0, tapply primarily worked with vectors. However, in R 4.3.0 and later, tapply supports data frames directly, especially when used with a formula interface for grouping.

Q: What is the purpose of the by function

ANS: The by function is similar to tapply but is particularly useful for applying functions to data frames. It handles mixed data types and lengths within groups more gracefully than tapply did in older R versions.

Q: Which apply function is best for performance

ANS: For large datasets, functions in packages like collapse (dapply, BY, and the fast series like fmean) or optimized solutions using data.table and dplyr often offer superior performance compared to base R *apply functions. Parallel processing packages also significantly boost performance.

Q: How does apply handle matrices versus data frames

ANS: apply is designed for matrices and arrays. When applied to a data frame, it first coerces the data frame into a matrix. This can lead to unexpected results if the data frame contains mixed data types, as the matrix will typically be coerced to a single type (often character).

Q: What is the role of rapply

ANS: rapply is used for recursively applying a function to elements within nested list structures, allowing you to process complex hierarchical data.

Q: Are there alternatives to the apply family for parallel processing

ANS: Yes, packages like parallels (parApply), foreach with doParallel, future, and purrr provide robust mechanisms for parallelizing computations that would typically be handled by the *apply family.
