“R Data Imputation: Multiple Methods for Filling NA Values by Group”

When working with time series or sequential data grouped by identifiers (like houseID in our example), it is frequently necessary to fill missing values (NA) in a specific column (price) using the most recent non-missing value encountered within that group. This technique is known as Last Observation Carried Forward (LOCF).

How can we efficiently implement LOCF imputation grouped by a variable such as houseID across various R packages like tidyr, zoo, data.table, and base R?

The initial data structure serving as the basis for all solutions is defined as follows:

df <- structure(list(houseID = c(1L, 1L, 1L, 1L, 1L, 2L, 2L, 2L, 2L,
  2L, 3L, 3L, 3L, 3L, 3L), year = c(1995L, 1996L, 1997L, 1998L,
  1999L, 1995L, 1996L, 1997L, 1998L, 1999L, 1995L, 1996L, 1997L,
  1998L, 1999L), price = c(NA, 100L, NA, 120L, NA, NA, NA, NA,
  30L, NA, NA, 44L, NA, NA, NA)), .Names = c("houseID", "year",
  "price"), class = "data.frame", row.names = c(NA, -15L))

Solution Family 1: Utilizing tidyr::fill() (The Tidy Approach)

The tidyr package offers a straightforward function specifically designed for this type of propagation.

The tidyr::fill() function facilitates this operation directly after grouping.

# Requires dplyr and tidyr (or tidyverse)
library(dplyr)
library(tidyr)

df %>%
  group_by(houseID) %>%
  fill(price, .direction = "down") %>% # Default direction is "down" (LOCF)
  ungroup()

Solution Family 2: Leveraging the zoo Package with Group Operations

The zoo package provides the highly flexible na.locf() function. To apply this per group, we often combine it with dplyr::group_by()/do() or base R’s by().

Alternative A: dplyr with do() and Custom Wrapper

Since na.locf typically expects a vector, using do() allows application across the grouped data frame subsets. We define a helper that ensures na.rm = FALSE to keep initial NAs if they exist.

library(dplyr)
library(zoo)

# Helper function using na.locf with keep_na=TRUE behavior
na_locf_keep <- function(x) zoo::na.locf(x, na.rm = FALSE)

df %>%
  group_by(houseID) %>%
  do(na_locf_keep(.)) %>%
  ungroup()

Alternative B: dplyr::mutate with zoo::na.locf0

If we only target the specific column and use na.locf0 which behaves slightly differently but serves a similar purpose for propagation within groups:

library(dplyr)
library(zoo)

df %>%
  group_by(houseID) %>%
  mutate(price = zoo::na.locf0(price)) %>%
  ungroup()

Alternative C: Base R by() with do.call(rbind, ...)

Using base R’s split-apply-combine mechanism with zoo:

library(zoo)

# Custom function tailored for 'by' application
na_locf_apply <- function(x) {
  # Apply na.locf on each column vector within the group 'x'
  data.frame(lapply(x, na_locf_keep))
}

do.call(rbind, by(df, df$houseID, na_locf_apply))

Alternative D: Base R ave() with zoo::na.locf0

The ave function applies a function by group:

library(zoo)

df <- transform(df, price = ave(price, houseID, FUN = zoo::na.locf0))

Alternative E: Using read.zoo for Time Series Conversion

zoo can transform the data into a time-series format where houseID becomes a split index, allowing na.locf to operate on the resulting structure:

library(dplyr)
library(zoo)

# Converts to zoo object, splits by houseID (split=1), uses 'year' as index
df %>%
  read.zoo(index = "year", split = "houseID", FUN = identity) %>%
  na_locf_keep() # Use the helper defined earlier if keeping initial NAs

Note: This approach produces a wide-format output, with houseID becoming columns.

Solution Family 3: High-Performance data.table Operations

data.table offers extremely fast ways to perform grouped operations, including nafill.

Alternative A: data.table::nafill (Recommended for data.table)

Since recent versions of data.table (v1.12.4+), nafill is the dedicated tool for this, applied efficiently within a j expression, grouped by i.

library(data.table)
setDT(df) # Convert to data.table in place

# Fill 'price' using LOCF, evaluated per 'houseID' group
df[, price := nafill(price, type = 'locf'), by = houseID]

# Alternatively, use setnafill for modifying multiple columns without returning a result
# setnafill(df, type = 'locf', cols = 'price') # This fills globally unless combined with grouping logic not present here

Alternative B: Rolling Self-Join with data.table

This method relies on filtering out NAs and then performing a “rolling join” to match the current row with the previous available non-NA value for that group.

library(data.table)
setDT(df)
setkey(df, houseID, year) # Keying is essential for fast rolling joins

# Create a subset containing only non-missing prices
df_with_prices <- df[!is.na(price)]

# Perform rolling self-join: match current df row to previous row in df_with_prices by key
# roll=TRUE defaults to 'nearest previous' match
df_joined <- df_with_prices[df, roll = TRUE]
# This requires careful handling of the resulting structure if you need all original columns returned.

Solution Family 4: Pure dplyr Propagation Logic (No zoo or tidyr::fill)

It is possible to achieve LOCF using only dplyr by tracking the blocks of non-missing values using cumsum.

library(dplyr)

df_filled_dplyr <- df %>%
  group_by(houseID) %>%
  # 1. Create a grouping variable based on consecutive non-NA blocks
  mutate(block_id = cumsum(0 + !is.na(price))) %>%
  # 2. Within each block_id group, find the first non-NA price
  group_by(block_id, add = TRUE) %>%
  mutate(price_filled = nth(price, 1)) %>%
  ungroup() %>%
  select(-block_id)

Solution Family 5: Base R using lapply and split

A traditional base R structure applies the zoo::na.locf function after splitting the data frame by the grouping variable.

# Requires zoo package for na.locf
library(zoo)

df$price <- unlist(
  lapply(
    split(df$price, df$houseID),
    function(x) zoo::na.locf(x, na.rm = FALSE)
  )
)
# 'df' is updated in place here

require(data.table)
setDT(df)   ## change it to data.table in place
setkey(df, houseID, year)     ## needed for fast join
df.woNA &lt;- df[!is.na(price)]  ## version without the NA rows

# rolling self-join will return what you want
df.woNA[df, roll=TRUE]  ## will match previous year if year not found

FAQs on R Data Imputation Multiple Methods for Filling NA Values by Group

Q: Which method preserves initial NA values if they occur first in a group

ANS: Both tidyr::fill(price, .direction = "down") and using zoo::na.locf(x, na.rm = FALSE) in wrapper functions (like in Solution Family 2) will preserve initial NA values at the start of a group.

Q: Is there a difference between tidyr::fill and zoo::na.locf

ANS: Yes, tidyr::fill is specifically designed for data frame manipulation with grouping context and often cleaner syntax. zoo::na.locf is more general for time series vectors but requires explicit grouping application when used on a data frame structure.

Q: Can data.table fill NAs in multiple columns simultaneously

ANS: Yes, data.table::setnafill can operate on multiple columns at once without requiring explicit looping per column, though grouped operations are cleaner with nafill(..., by = group_var).

Q: What is the performance ranking for these solutions

ANS: Generally, data.table methods (nafill) offer superior performance for large datasets due to their C-level optimizations, followed by optimized dplyr verbs, while base R lapply/split can be slower.
