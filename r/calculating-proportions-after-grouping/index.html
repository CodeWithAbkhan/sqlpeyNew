“Calculating Proportions After Grouping in R with Dplyr and Alternatives”

When working with tabular data in R, particularly when utilizing packages like dplyr, a common analytical task involves calculating the relative frequency or proportion of observations within specific groupings. If you group by several variables, how does the subsequent calculation of proportions behave, and what are the most effective ways to achieve the desired outcome, especially when that outcome requires rolling up one level of grouping?

This discussion explores various solutions for calculating group-wise proportions, leveraging the mtcars dataset as an example, focusing on calculating proportions based on the gear split within each am category.

How Grouping Order Affects Subsequent Summarization and Mutation

When chaining group_by() calls followed by summarise() and mutate(), the grouping structure evolves. The summarise() operation collapses data according to the current grouping levels. The documentation suggests that each summary “peels off one level of the grouping.”

Query: How do we calculate the frequency (n) grouped by both am and gear, and then calculate the frequency percentage relative to the sum within the primary grouping variable (am)?

Solution 1: Sequential Group Peeling with group_by() and mutate()

This approach relies on the implicit peeling of grouping levels during summarise(). After summarizing by am and gear, the gear level is dropped, leaving the data grouped by am for the subsequent mutate operation, where the sum is calculated across that remaining group.

library(dplyr)

mtcars_results_1 <- mtcars %>%
  group_by(am, gear) %>%
  summarise(n = n(), .groups = "drop_last") %>% # Explicitly drop last group for clarity in older dplyr or specify behavior
  mutate(freq = n / sum(n))

print(mtcars_results_1)
# # A tibble: 4 x 4
#      am  gear     n      freq
#   <dbl> <dbl> <int>     <dbl>
# 1     0     3    15 0.7894737
# 2     0     4     4 0.2105263
# 3     1     4     8 0.6153846
# 4     1     5     5 0.3846154

Observation: As noted, after summarise(), the gear grouping level is removed. The mutate step then calculates the proportion relative to the remaining group (am). To ensure explicitness, one might add an extra group_by(am) before mutate if desired, preventing reliance on the default peeling behavior.

Solution 2: Utilizing the count() Function and Version Dependencies

The count() function simplifies frequency calculation. However, its behavior regarding the grouping structure of the output changed across dplyr versions.

For dplyr version 0.7.1 and newer: count() returns an ungrouped table. You must re-apply grouping to calculate the proportion correctly.

# Dplyr >= 0.7.1 behavior
mtcars_results_2a <- mtcars %>%
  count(am, gear) %>%
  group_by(am) %>% # Re-group by the desired summation level
  mutate(freq = n / sum(n))

For dplyr versions earlier than 0.7.1: count() returned a grouped table. You might need to explicitly ungroup() later if subsequent operations shouldn’t inherit the grouping.

# Dplyr < 0.7.1 behavior (for illustration)
mtcars_results_2b <- mtcars %>%
  count(am, gear) %>%
  mutate(freq = n / sum(n)) # Grouping might persist from count() output

Solution 3: Formatting Results as Percentage Strings

If the final requirement is a formatted percentage string instead of a decimal proportion, string manipulation is necessary.

mtcars_results_3 <- mtcars %>%
  group_by(am, gear) %>%
  summarise(n = n(), .groups = "drop_last") %>%
  mutate(rel_freq_str = paste0(round(100 * n / sum(n), 0), "%"))

print(mtcars_results_3)
# # A tibble: 4 x 4
#      am  gear     n rel_freq_str
#   <dbl> <dbl> <int> < <chr>       
# 1     0     3    15 "79%"       
# 2     0     4     4 "21%"       
# 3     1     4     8 "62%"       
# 4     1     5     5 "38%"

This involves creating helper functions (as.rel_freq and print.rel_freq) to apply percentage formatting during the print stage.

Solution 4: Using prop.table() with Modern dplyr or data.table

The base R function prop.table() is highly efficient for calculating proportions.

Modern dplyr (v >= 1.1.0): The .by argument in mutate() allows specifying the grouping context for the calculation, bypassing explicit group_by() steps for this specific mutation.

library(dplyr)

mtcars_results_4a <- mtcars %>%
  count(am, gear) %>%
  mutate(freq = prop.table(n), .by = am) # Calculate prop.table within the 'am' group

Older dplyr (pre-v1.1.0): This requires using tally() (or summarise(n=n())) followed by group_by() to set the context for prop.table().

mtcars_results_4b <- mtcars %>%
  group_by(am, gear) %>%
  tally() %>% # Renamed to n() in newer versions; tally() exists for compatibility
  mutate(freq = prop.table(n))

Using data.table: This package offers extremely fast operations, leveraging keyby for grouping and direct assignment with by for context-specific calculations.

library(data.table)
cars_dt <- as.data.table(mtcars)
cars_dt[, .(n = .N), keyby = .(am, gear)][, freq := prop.table(n), by = "am"][]

Solution 5: Controlling Grouping Structure with .groups in summarise()

Since dplyr version 1.0.0, the .groups argument in summarise() explicitly controls the resulting grouping structure, offering fine-grained control over peeling behavior.

  • .groups = "drop_last": Drops the last grouping level (mimics pre-1.0.0 default).
  • .groups = "drop": Drops all grouping levels, returning an ungrouped tibble.
  • .groups = "keep": Retains all original grouping levels, even if summarization makes them redundant.
  • .groups = "rowwise": Converts the result to row-wise grouping.

If we use .groups = "drop", the subsequent mutate must re-establish grouping based on am to calculate the proportion correctly across am’s subgroups. If we use .groups = "drop_last", the structure remains grouped by am, allowing direct calculation.

library(dplyr)
library(scales) # For robust percentage formatting

# Using .groups = "drop_last" retains the 'am' group
mtcars_results_5a <- mtcars %>%
  group_by(am, gear) %>%
  summarise(n = n(), .groups = "drop_last") %>%
  mutate(rel.freq = scales::percent(n / sum(n), accuracy = 0.1))

Adding Subtotal Lines: A useful addition is generating subtotal rows for improved readability, typically done by calculating the subtotals separately and using bind_rows().

subtotal_am <- mtcars %>%
  group_by(am) %>%
  summarise(n = n(), gear = NA_real_, rel.freq = 1, .groups = "drop")

final_table_with_totals <- mtcars %>%
  group_by(am, gear) %>%
  summarise(n = n(), .groups = "drop_last") %>%
  mutate(rel.freq_decimal = n / sum(n)) %>%
  bind_rows(subtotal_am) %>%
  arrange(am, gear) %>%
  mutate(rel.freq = scales::percent(rel.freq_decimal, accuracy = 0.1))

Solution 6: Encapsulating Logic into a Reusable Function

For repetitive tasks, creating a helper function is efficient. This function utilizes tally() (or n()) and computes the percentage within the established group.

count_pct <- function(df) {
  return(
    df %>%
      tally() %>%
      mutate(n_pct = 100 * n / sum(n))
  )
}

mtcars %>%
  group_by(cyl) %>%
  count_pct
# # A tibble: 3 x 3
#     cyl     n n_pct
#   <dbl> < <int> < <dbl>
# 1     4    11  34.4
# 2     6     7  21.9
# 3     8    14  43.8

Solution 7: Creating a Generic Function with Non-Standard Evaluation (NSE)

A more flexible function can accept the grouping variables and the variable to be tallied via NSE (enquo and !!). This example generalizes Solution 1/3 logic.

freq_table_generalized <- function(data, group_var_sym, prop_var_sym) {
  group_var_sym <- rlang::enquo(group_var_sym)
  prop_var_sym  <- rlang::enquo(prop_var_sym)
  data %>%
    group_by(!!group_var_sym, !!prop_var_sym) %>%
    summarise(n = n(), .groups = "drop_last") %>%
    mutate(freq = n / sum(n))
}

# Usage: calculate proportion of 'gear' within each 'am' group
freq_table_generalized(mtcars, group_var_sym = am, prop_var_sym = gear)

Solution 8: Using add_count() to Avoid Grouping Ambiguity

The add_count() function can sometimes simplify calculations, especially when weights are involved, as it computes the count and adds it without immediately changing the prior grouping structure in ways that complicate subsequent steps.

mtcars_results_8 <- mtcars %>%
  count(am, gear) %>%
  add_count(am, wt = n, name = "nn") %>% # Sums 'n' weighted by 'n' within each 'am'
  mutate(proportion = n / nn)

Solution 9: Base R Approach with aggregate and ave

For those preferring base R, the combination of aggregate for initial counting and ave (average by) for calculating the running sum within groups provides a clean alternative.

df1_base <- with(mtcars, aggregate(list(n = mpg), list(am = am, gear = gear), length))
# Calculate proportion (prop) by averaging 'n' within the 'am' group
df1_base$prop <- with(df1_base, n / ave(n, am, FUN = sum))

print(df1_base)
#   am gear  n      prop
# 1  0    3 15 0.7894737
# 2  0    4  4 0.2105263
# 3  1    4  8 0.6153846
# 4  1    5  5 0.3846154

# Alternative base R view using cross-tabulation
prop.table(table(mtcars$am, mtcars$gear), margin = 1) # margin=1 calculates row proportions

Solution 10: Percentage Formatting Control with scipen

To avoid scientific notation when calculating percentages directly, adjust R’s numeric display settings temporarily.

# Temporarily increase penalty for scientific notation
original_scipen <- getOption("scipen")
options("scipen" = 10)

mtcars_results_10 <- mtcars %>%
  count(am, gear) %>%
  mutate(freq_percent = (n / sum(n)) * 100)

options("scipen" = original_scipen) # Restore original setting
print(mtcars_results_10)

Solution 11: Reusable Function Using ... for Dynamic Grouping

Leveraging the ... syntax within a function allows the user to pass both the grouping variables for the count AND the variables defining the context for the proportion calculation dynamically. This is highly effective for writing reusable data pipelines.

props_dynamic <- function(data, ...) {
  data %>%
    count(...) %>%
    # The 'by=...' argument in mutate directs 'sum(n)' calculation
    mutate(prop = n / sum(n), .keep = "unused", by = c(...))
}

# Group by cyl and vs, then calculate proportion of gear within that context
mtcars %>%
  group_by(cyl, vs) %>%
  props_dynamic(gear, carb)

FAQs on Calculating Proportions After Grouping in R

Q: How does grouping behavior change when using summarise after group_by in dplyr

ANS: When using summarise() after group_by(var1, var2), the resulting tibble loses the innermost grouping variable (var2) by default in older versions or when .groups is set to "drop_last". The remaining group (var1) is used for subsequent operations like mutate.

Q: What is the impact of dplyr's .groups argument on summarise output

ANS: The .groups argument (e.g., "drop", "keep", "drop_last") explicitly controls how many grouping levels remain after summarise() collapses the data. This provides clarity over behavior seen in earlier versions.

Q: Can I use base R functions to calculate conditional percentages

ANS: Yes, base R functions like aggregate() to compute counts and ave(n, grouping_var, FUN = sum) to compute the group total are effective ways to derive proportions without relying on dplyr.
