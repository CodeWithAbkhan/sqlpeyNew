“R’s ifelse Behavior: Why Does it Compute Both Branches?”

R ifelse Evaluation Mechanics

The accepted behavior for ifelse is that it does compute both its ‘yes’ value expression and its ’no’ value expression, with one specific exception: when the test condition vector consists of entirely TRUE values or entirely FALSE values. In these fully homogenous cases, only the relevant branch is fully evaluated against the vector length.

This behavior contrasts with standard R control flow structures like if/else in base R functions, which typically exhibit short-circuiting for logical tests.

Demonstration via Random Number Generation

We can observe this side effect by leveraging the pseudorandom number generator’s state. By fixing the seed and tracking which random number is drawn next after an ifelse operation, we can deduce how many random numbers were consumed during the execution of the function call.

In the demonstration below, when the test condition mixes TRUE and FALSE results, the process consumes twice as many potential random values as when the test is homogenous, indicating both rnorm(200) calls were executed.

# Setting seed to control randomness
set.seed(1)
# Test Case 1: All TRUE condition consumes the 'yes' vector length
dump_all_true  <- ifelse(rep(TRUE, 200), rnorm(200), rnorm(200))
next_after_all_true <- rnorm(1)

# Test Case 2: All FALSE condition consumes the 'no' vector length
set.seed(1)
dump_all_false <- ifelse(rep(FALSE, 200), rnorm(200), rnorm(200))
next_after_all_false <- rnorm(1)

# Test Case 3: Mixed condition consumes BOTH vector lengths (200 + 200 = 400)
set.seed(1)
dump_mixed <- ifelse(c(FALSE, rep(TRUE, 199)), rnorm(200), rnorm(200))
next_after_mixed <- rnorm(1)

# Reset seed and generate a pool of random numbers to search within
set.seed(1)
r_pool <- rnorm(1000)

# Determine how many random numbers were consumed before the "next" one appeared
cat("Random Numbers Consumed by ifelse:\n")
cat("\tAll True Case:  ", which(r_pool == next_after_all_true) - 1, "\n")
cat("\tAll False Case: ", which(r_pool == next_after_all_false) - 1, "\n")
cat("\tMixed T/F Case: ", which(r_pool == next_after_mixed) - 1, "\n")

Observed Output Interpretation:

When the test is mixed (Mixed T/F Case), the output shows 400 numbers were consumed. This confirms that R calculates the results for both the ‘yes’ branch and the ’no’ branch completely before selecting which results to place into the final output vector.

Evidence in Source Code Structure

The compiled C source code for base R functions confirms this pattern. Portions of the underlying logic show that assignments are prepared for both true and false indices:

// Snippet indicating computation for both branches before selection
if (any(test[!nas]))    
    ans[test & !nas] <- rep(yes, length.out = length(ans))[test & !nas]
if (any(!test[!nas])) 
    ans[!test & !nas] <- rep(no, length.out = length(ans))[!test & !nas]

The key factor concerning efficiency is that the expressions passed as yes and no are computed entirely for their respective lengths, irrespective of the final selection. If yes or no involve computationally intensive operations (like complex simulations, heavy data manipulation, or function calls that involve I/O), this results in unnecessary overhead.

Performance Comparison: ifelse vs. Explicit Indexing

When the arguments to yes and no are complex, the performance penalty becomes measurable. We can compare the standard ifelse approach against an explicit indexing approach that only computes the necessary branches.

We set up sample data where elements are conditionally dependent on the presence of NAs in two vectors, X and Y, ensuring is.na(X) is the inverse of is.na(Y).

library(microbenchmark)

N <- 10000 # Increased sample size for better measurement
set.seed(42)
X <- sample(c(seq(100), rep(NA, 100)), N, replace = TRUE)
# Y is constructed such that if X has a value, Y is NA, and vice versa.
Y <- ifelse(is.na(X), rnorm(N), NA) 

# Method 1: Using standard ifelse (computes both Y+17 and X-17)
yes_ifelse_expr <- quote(sort(ifelse(is.na(X), Y + 17, X - 17)))

# Method 2: Explicit indexing (only computes Y+17 where Y is needed, X-17 where X is needed)
no_indexing_expr  <- quote(sort(c(Y[is.na(X)] + 17, X[!is.na(X)] - 17)))

# Verification that results are identical
stopifnot(identical(eval(yes_ifelse_expr), eval(no_indexing_expr)))

# Benchmark execution
timing_results <- microbenchmark(
  "ifelse_Standard" = eval(yes_ifelse_expr),
  "Indexing_Optimized" = eval(no_indexing_expr),
  times = 50L
)

print(timing_results)
