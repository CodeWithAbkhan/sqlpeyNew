“Rust String vs &str Understanding Owned vs Borrowed Text”

In Rust, managing text data efficiently and safely is paramount. Two core types handle strings: String and &str (pronounced “string slice”). While both represent sequences of characters, their underlying mechanisms, ownership models, and typical use cases diverge significantly. Understanding these distinctions is crucial for writing idiomatic and performant Rust code.

What exactly is a String in Rust?

A String in Rust is a dynamic, heap-allocated, and growable sequence of UTF-8 characters. It’s designed to own its data, meaning it manages its own memory. When a String variable goes out of scope, the memory it occupies on the heap is automatically deallocated. This ownership model makes String suitable for scenarios where you need to create, modify, or pass string data around without worrying about manual memory management.

Think of String as being analogous to std::string in C++ or StringBuilder in C# and Java. It provides flexibility for text manipulation at runtime. Internally, a String is structured similarly to a Vec<u8>, containing a pointer to the heap-allocated buffer, the current length of the data, and the buffer’s total capacity.

Here’s how you might create and use a String:

// Creating a new, empty String
let mut my_string = String::new();
println!("Initial string: '{}'", my_string); // Output: Initial string: ''

// Appending text to a String
my_string.push_str("Hello");
my_string.push(' '); // push a single character
my_string.push_str("Rust!");
println!("Appended string: '{}'", my_string); // Output: Appended string: 'Hello Rust!'

// Creating a String from a string literal
let another_string = String::from("World");
println!("Another string: '{}'", another_string); // Output: Another string: 'World'

// Concatenating Strings
let combined_string = my_string + " " + &another_string;
println!("Combined string: '{}'", combined_string); // Output: Combined string: 'Hello Rust! World'
// Note: The '+' operator consumes the left-hand side String.

What is an &str (String Slice) in Rust?

An &str is a string slice, which is an immutable reference to a sequence of UTF-8 bytes. Unlike String, &str does not own its data. It’s essentially a “view” into existing string data, which can reside in various places:

  • String Literals: These are embedded directly into your program’s binary and have a 'static lifetime, meaning they exist for the entire duration of the program.
  • Heap-allocated Strings: An &str can borrow a portion or all of a String’s content without taking ownership.
  • Stack-allocated byte arrays: You can create an &str from a mutable byte array on the stack, provided the bytes form valid UTF-8.

An &str is often described as a “fat pointer,” consisting of two parts: a pointer to the beginning of the string data and the length of that data in bytes. This makes &str lightweight and efficient for passing string data around when modification isn’t required. It’s analogous to a char* in C (though more sophisticated) or an immutable string in Java/C#.

Consider these examples of &str usage:

// String literal - statically allocated
let static_slice: &'static str = "This is a static string.";
println!("Static slice: '{}'", static_slice);

// Borrowing from a String
let owned_string = String::from("Owned data");
let borrowed_slice: &str = &owned_string; // Borrows the entire String
println!("Borrowed slice from String: '{}'", borrowed_slice);

// Creating a substring slice
let full_string = String::from("abcdefg");
let substring: &str = &full_string[2..5]; // References bytes from index 2 up to (but not including) 5
println!("Substring slice: '{}'", substring); // Output: Substring slice: 'cde'

// Example of creating &str from bytes on the stack
use std::str;
let bytes_data: [u8; 5] = [b'H', b'e', b'l', b'l', b'o'];
match str::from_utf8(&bytes_data) {
    Ok(s) => println!("Slice from bytes: '{}'", s), // Output: Slice from bytes: 'Hello'
    Err(e) => println!("Error converting bytes to string: {}", e),
}

When to Use Which:

  • Use String when:

    • You need to create a new string dynamically at runtime.
    • You need to modify an existing string (append, insert, replace characters).
    • You need to pass ownership of string data to another function or thread.
    • You are collecting input from users or files.

  • Use &str when:

    • You are working with string literals (e.g., "hello").
    • You need to pass string data to a function that only needs to read it (efficiently).
    • You are slicing or referencing a part of an existing String.
    • You want to avoid unnecessary memory allocations when simply reading string content.

It’s common for functions to accept &str as parameters. This allows them to work with both string literals and Strings (by passing a reference to the String, like &my_string). This practice promotes flexibility and efficiency.

Advanced Concepts and Related Types:

  • String as Vec<u8>: A String is fundamentally a specialized Vec<u8> that guarantees its contents are valid UTF-8. You can interact with its underlying byte buffer, but care must be taken to maintain UTF-8 validity.
  • Box<str>: Similar to &str, Box<str> refers to a string slice. However, Box<str> owns the string data on the heap, much like String, but it cannot be resized directly. It’s a way to have a heap-allocated, owned string of a fixed size.
  • Mutability of &str: While &str itself is immutable, you can obtain a mutable string slice (&mut str) if you have mutable access to the underlying data (e.g., from a mutable String). Functions like split_at_mut provide this capability, but modifications must preserve UTF-8 validity.

Code Examples Illustrating Usage:

Passing strings to functions:

fn print_string_info(text: &str) {
    println!("Received: \"{}\", Length: {}", text, text.len());
}

fn main() {
    let literal = "Immutable";
    let owned = String::from("Mutable String");

    print_string_info(literal);         // Passing a literal (&str)
    print_string_info(&owned);          // Passing a reference to a String (&String coerces to &str)

    let mut dynamic_string = String::new();
    dynamic_string.push_str("Dynamically built");
    print_string_info(&dynamic_string);
}

String concatenation:

Rust’s + operator for strings is designed for String concatenation, where the left operand is moved. For more efficient or flexible concatenation, consider format! macro or push_str:

fn main() {
    let s1 = String::from("Hello");
    let s2 = String::from("World");

    // Using format! macro (doesn't consume strings)
    let combined_formatted = format!("{} {}", s1, s2);
    println!("{}", combined_formatted); // Output: Hello World
    println!("Original s1: {}", s1);   // s1 is still valid

    // Using push_str (modifies the String)
    let mut s3 = String::from("Rust ");
    s3.push_str("Programming");
    println!("{}", s3); // Output: Rust Programming
}

FAQs on Rust String vs &str

Q String vs &str difference

ANS: String is heap-allocated, owned, and mutable text. &str is an immutable, borrowed reference to text, which could be a string literal or part of a String.

Q Can &str be modified

ANS: By itself, &str is immutable. However, if you have a mutable reference to the underlying data (like from a String), you can get a &mut str to perform in-place modifications that maintain UTF-8 validity.

Q How to convert String to &str

ANS: You can convert a String to an &str by taking a reference to it: &my_string. Rust automatically handles this coercion when a &String is passed where an &str is expected.

Q How to convert &str to String

ANS: You can convert an &str to a String using the to_string() method or the String::from() function: my_str.to_string() or String::from(my_str). This involves an allocation on the heap.

Q Which is more efficient String or &str

ANS: &str is generally more efficient for passing and reading strings because it avoids heap allocations and simply passes a pointer and length. String involves heap allocation and management, which has a performance cost but allows for mutability and ownership.

Q What is the memory size of String and &str

ANS: On a 64-bit system, &str is typically 16 bytes (a 8-byte pointer and an 8-byte length), while String is typically 24 bytes (8-byte pointer, 8-byte length, and 8-byte capacity).
