“Rust Mutable Slice Indexing: Safe Techniques for Dual Mutable Borrows”

How can one securely acquire mutable references to two distinct elements in a slice or vector in Rust when the standard indexing (&mut v[i], &mut v[j]) fails due to overlapping mutable borrows?

Analyzing the Borrowing Constraint

The core difficulty lies in the compiler’s inability to statically prove that two index accesses, say &mut v[i] and &mut v[j], point to non-overlapping memory locations unless the operation itself enforces this separation. Attempting to create an abstraction that holds a mutable reference while simultaneously mutating another part of the same underlying container is fundamentally what the borrow checker forbids.

If you attempt a pattern that looks like this:

// Hypothetical unsafe pattern the compiler prevents
let guard = something(&mut v[i]); // Borrows v mutably
do_something_else(&mut v[j]);    // Fails if j is not provably different from i
guard.do_job();

The compiler must safeguard against cases where i == j, leading to a violation where one piece of code holds an exclusive reference (guard) while another tries to mutate the same location via v[j].

Here are several robust techniques and alternative approaches to safely handle mutable access to two separate elements:

Solution 1: Utilizing split_at_mut for Known Separations

For scenarios where you can split the slice at a known point between the two indices, split_at_mut() is an excellent, safe built-in tool. It returns two disjoint mutable slices.

If you know index a is less than index b, you can split at a+1 to place a in the first subslice and b in the second (after adjusting b’s relative index). However, the direct application is cleaner if the split index separates the two desired elements:

fn swap_elements(a: &mut i32, b: &mut i32) {
    let temp = *a;
    *a = *b;
    *b = temp;
}

fn apply_split_at_mut_swap() {
    let mut data_vec = vec![10, 20, 30, 40];
    
    // Goal: Swap element at index 0 (value 10) and index 2 (value 30)
    let split_point = 2; // Split before index 2
    
    let (left_slice, right_slice) = data_vec.split_at_mut(split_point); 
    // left_slice: &mut [10, 20]
    // right_slice: &mut [30, 40]
    
    // Element at original index 0 is now left_slice[0]
    let element_a = &mut left_slice[0]; 
    
    // Element at original index 2 is now right_slice[0]
    let element_b = &mut right_slice[0]; 
    
    swap_elements(element_a, element_b);
    
    // data_vec is now [30, 20, 10, 40]
    println!("Vector after split_at_mut swap: {:?}", data_vec);
}

The original example mentioned a pattern for handling three distinct cases (indices equal, out of bounds, or distinct):

enum IndexPair<T> {
    Both(T, T),
    One(T),
    None,
}

fn index_twice<T>(slc: &mut [T], a: usize, b: usize) -> IndexPair<&mut T> {
    if a == b {
        slc.get_mut(a).map_or(IndexPair::None, IndexPair::One)
    } else if a >= slc.len() || b >= slc.len() {
        IndexPair::None
    } else {
        // SAFETY: We have checked bounds and ensured a != b.
        unsafe {
            // Directly casting raw pointers derived from unchecked mutable access is necessary here.
            let ar = &mut *(slc.get_unchecked_mut(a) as *mut _);
            let br = &mut *(slc.get_unchecked_mut(b) as *mut _);
            IndexPair::Both(ar, br)
        }
    }
}

Solution 2: Pattern Matching on Fixed-Size Arrays (Compile-Time Known Indices)

For fixed-size arrays ([T; N]), pattern matching can provide safe extraction of mutable elements if the indices correspond to specific positions in the pattern. This is powerful when indices are known early:

fn perform_array_swap() {
    let mut fixed_array = [50, 60, 70, 80];
    
    // Target: Swap element at index 0 (50) and index 2 (70)
    // We use ref mut to bind the mutable reference to a variable name.
    {
        let [ref mut element_a, _, ref mut element_b, ..] = fixed_array;
        
        // Standard swap logic
        let temp = *element_a;
        *element_a = *element_b;
        *element_b = temp;
    }
    
    assert_eq!(fixed_array, [70, 60, 50, 80]);
    println!("Array after pattern match swap: {:?}", fixed_array);
}

Solution 3: Using get_disjoint_mut (Rust 1.86+)

The get_disjoint_mut method, available on slices, is specifically designed for this purpose. It returns an Option<[&mut T; N]> containing mutable references to N elements specified by the input indices, provided they are within bounds and disjoint (non-overlapping).

fn apply_get_disjoint() {
    let mut data_vec = vec![100, 200, 300];
    
    // Attempt to get disjoint mutable references to indices 0 and 2.
    if let Some([a, b]) = data_vec.get_disjoint_mut([0, 2]) {
        // Safe to modify a and b independently
        *a = 999;
        *b = 777;
    } else {
        panic!("Indices 0 and 2 were not disjoint or out of bounds.");
    }
    
    // data_vec is now [999, 200, 777]
    println!("Vector after get_disjoint_mut: {:?}", data_vec);
}

Solution 4: When Manual Control or Complexity Demands unsafe

When the compiler cannot verify safety (as discussed, this happens when indices are runtime variables and not obviously separate), the underlying mechanisms often rely on unsafe code, as seen in Solution 1. The rationale behind these restrictions is to prevent hard-to-trace errors where internal state (like an Iterator or an owning guard) might be invalidated by an unexpected mutation elsewhere.

If you need to swap elements dynamically, the built-in Vec::swap(i, j) method is the safest and idiomatic way to perform an in-place swap without worrying about managing mutable references:

fn safe_swap_via_method() {
    let mut numbers = vec![5, 10, 15];
    numbers.swap(0, 2); // Swaps elements at index 0 and 2
    assert_eq!(numbers, vec![15, 10, 5]);
}

For general-purpose indexed manipulation requiring multiple mutable access points, exploring libraries that encapsulate safe unsafe logic is often recommended, such as those providing multi-index access wrappers.

Solution 5: Extension Trait via iter_mut()

You can craft an extension trait utilizing iter_mut() combined with nth() to fetch two distinct mutable references. This relies on the iterator advancing past the first element before seeking the second, guaranteeing disjointness by construction.

use std::cmp::Ordering;

pub trait SliceMutExt<T> {
    fn get_two_mut(&mut self, index0: usize, index1: usize) -> (&mut T, &mut T);
}

impl<T> SliceMutExt<T> for [T] {
    fn get_two_mut(&mut self, index0: usize, index1: usize) -> (&mut T, &mut T) {
        match index0.cmp(&index1) {
            Ordering::Less => {
                let mut iter = self.iter_mut();
                // Get the first item
                let item0 = iter.nth(index0).expect("Index 0 out of bounds");
                // Calculate how many steps to jump from the *next* position to reach item1
                let steps_to_item1 = index1 - index0 - 1;
                let item1 = iter.nth(steps_to_item1).expect("Index 1 out of bounds");
                (item0, item1)
            }
            Ordering::Equal => panic!("Indices must be distinct for dual mutable access"),
            Ordering::Greater => {
                // Handle the greater index first if logic dictates, or simply swap logic path
                let mut iter = self.iter_mut();
                let item1 = iter.nth(index1).expect("Index 1 out of bounds");
                let steps_to_item0 = index0 - index1 - 1;
                let item0 = iter.nth(steps_to_item0).expect("Index 0 out of bounds");
                (item0, item1) // Return order based on index0, index1 input order
            }
        }
    }
}

fn apply_extension_trait() {
    let mut data = vec!['A', 'B', 'C', 'D'];
    // Swap 'B' (index 1) and 'D' (index 3)
    let (mut_b, mut_d) = data.get_two_mut(1, 3);
    
    std::mem::swap(mut_b, mut_d);
    
    // data is now ['A', 'D', 'C', 'B']
    println!("Array after custom extension: {:?}", data);
}

Solution 6: Full Mutable Borrow Collection via split_at_mut Looping

If the objective is to obtain a Vec<&mut T> representing mutable access to every element, you can iteratively use split_at_mut until the original vector is exhausted. This yields a collection where each element is borrowed mutably, allowing indexed access later without violating the borrow checker on the original vector, because the original vector itself is fully consumed into slices:

fn borrow_mut_elementwise<'a, T>(v: &'a mut Vec<T>) -> Vec<&'a mut T> {
    let mut result: Vec<&'a mut T> = Vec::new();
    let mut remaining_slice = &mut v[..];
    
    while !remaining_slice.is_empty() {
        // Split off the first element as its own mutable slice
        let (current_part, rest) = remaining_slice.split_at_mut(1);
        
        // Push the reference to the first element of the current part
        result.push(&mut current_part[0]);
        
        // Update the remaining slice for the next iteration
        remaining_slice = rest;
    }
    result
}

fn demonstrate_elementwise_borrow() {
    let mut items = vec![1, 2, 3];
    let mut items_mut_refs = borrow_mut_elementwise(&mut items);
    
    // Now we can mutate items via the collected references
    *items_mut_refs[0] = 99;
    *items_mut_refs[2] = 101;
    
    // items is [99, 2, 101]
    println!("Items after elementwise borrowing: {:?}", items);
}

Solution 8: External Crates for Safe Multi-Index Access

For complex, dynamic index access, relying on well-vetted external crates is often the safest route, as they handle the necessary unsafe verification meticulously. The arref crate, for example, provides macros that perform runtime checks to ensure indices are distinct before performing the raw pointer manipulation:

// Requires adding 'arref' to Cargo.toml
// use arref::array_mut_ref;

/*
fn use_arref_example() {
    let mut data_arr = vec![10, 20, 30, 40];
    
    // If indices are distinct, this is safe:
    let (ref_20, ref_30) = array_mut_ref!(&mut data_arr, [1, 2]);
    
    *ref_20 = 22;
    *ref_30 = 33;
    
    // data_arr is now [10, 22, 33, 40]
}
*/

The underlying sound implementation in arref often looks like this, ensuring a0 != a1 before proceeding:

pub fn array_mut_ref<T>(arr: &mut [T], a0: usize, a1: usize) -> (&mut T, &mut T) {
    assert!(a0 != a1, "Indices must be different for safe, simultaneous mutable access.");
    // SAFETY: Assert guarantees a0 and a1 point to unique locations.
    unsafe {
        (
            &mut *(&mut arr[a0] as *mut _),
            &mut *(&mut arr[a1] as *mut _),
        )
    }
}

FAQs on Rust Mutable Slice Indexing

Q: What is the main reason Rust forbids mutable indexing like &mut v[i] and &mut v[j] simultaneously

ANS: The borrow checker prevents simultaneous mutable borrows because it cannot statically guarantee that the indices i and j are different, which would lead to Undefined Behavior through aliasing mutable references.

Q: Does split_at_mut work if the indices are far apart

ANS: Yes, split_at_mut works by creating two non-overlapping slices based on the split point. You can use it effectively if you can logically separate the two target indices into these two resulting slices.

Q: Is get_disjoint_mut the preferred modern solution

ANS: get_disjoint_mut (since Rust 1.86) is excellent for fetching a fixed, small number of explicitly listed disjoint mutable elements safely.

Q: When should I use Vec swap instead of manual reference juggling

ANS: Use Vec::swap(i, j) whenever you only need to exchange the values at two indices; it is the idiomatic, safest, and simplest approach.
