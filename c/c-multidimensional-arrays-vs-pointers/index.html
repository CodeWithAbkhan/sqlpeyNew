“C Multidimensional Arrays vs. Pointers: Memory Layout and Type Decay”

When dealing with two-dimensional data structures in C, a common point of confusion arises: Is a statically allocated two-dimensional array fundamentally the same as a pointer to a pointer (a int**)?

The definitive answer is no. A standard multidimensional array (int matrix[R][C]) and an array of pointers (int* arr[R]) represent distinct memory layouts and adhere to different type decay rules when passed to functions or dereferenced.

The Nature of Statically Declared Multidimensional Arrays

A true multidimensional array in C, such as int matrix[X][Y], occupies a single, contiguous block of memory. The total size is the product of all dimensions multiplied by the size of the element type. Indexing is purely based on offset arithmetic from the base address.

Addressing Elements

To access an element matrix[x][y], the compiler calculates the offset directly within that single block:

$$\text{Address} = \text{BaseAddress}(\text{matrix}) + x \times (\text{Size of Inner Array}) + y \times \text{sizeof}(\text{int})$$

If the inner dimension size is $C$ (the second dimension), the calculation is essentially:

$$\text{Address} = \text{BaseAddress}(\text{matrix}) + x \times C + y$$ (Using unit sizes as per the original example’s simplification)

Array Decay on Function Calls

When matrix is passed to a function, it decays to a pointer to its first element. The type of the first element (matrix[0]) is an array of $C$ integers, thus the decay results in a pointer to that array type: int (*)[C]. The dimension information ($C$) is preserved in the type signature, which is crucial for correct pointer arithmetic inside the function.

This is why an incorrect cast, like int **ptr = (int**)matrix;, fails. Dereferencing *ptr attempts to read a pointer value stored at the address of matrix, but no such pointer value exists; there is only raw integer data. Furthermore, ptr[x][y] would calculate an address based on the size of a pointer, not the size of the row block, leading to incorrect memory access.

Contrasting with Arrays of Pointers

An array of pointers, like int *arr[R], is fundamentally different. It is an array where each element is a pointer variable itself.

Memory Layout for Array of Pointers

This structure requires two allocation steps:

  1. Allocate space for the array of $R$ pointers (arr).
  2. Manually allocate $R$ separate blocks of memory, each intended to hold the row data, and assign the base address of each block to the corresponding element in arr.

For example:

#define ROWS 3
#define COLS 2
int *ptr_array[ROWS]; // Array of 3 pointers to int

// Manual allocation for jagged or regular arrays
int data_a[COLS] = { 10, 11 }; 
int data_b[COLS] = { 12, 13 }; 
int data_c[COLS] = { 14, 15 };

ptr_array[0] = data_a;
ptr_array[1] = data_b;
ptr_array[2] = data_c;

// Accessing element: ptr_array[1][0] results in 12

Indexing and Type Decay Differences

  1. Indexing: Accessing ptr_array[x][y] works because ptr_array[x] decays to a pointer (int*), which is then indexed by $y$. The address calculation relies on looking up the pointer stored at ptr_array[x] first.
  2. sizeof behavior: sizeof(ptr_array[0]) returns the size of a pointer (sizeof(int*)), not the size of the underlying row array (COLS * sizeof(int)), which is a critical distinction from static arrays.
  3. Flexibility: This approach allows for jagged arrays (rows of different lengths) and dynamic resizing of the row data blocks, something contiguous arrays cannot easily accommodate.

Practical Code Illustration: Distinguishing Layouts

To highlight the memory separation, consider this scenario:

// Solution 1: Contiguous memory block (True 2D Array)
#define C_DIM 4
int matrix[2][C_DIM] = {
    {11, 22, 33, 99},
    {44, 55, 66, 110}
};

// Solution 2: Array of Pointers (Separate allocations)
int row0[] = {100, 200, 300, 400};
int row1[] = {500, 600, 700, 800};
int *ptr_matrix[2] = {row0, row1};

When passing these to a function expecting (int arr[][4]) vs (int** arr), only the correct type signature will allow for correct offset calculations based on the underlying memory structure. Using int** with a static array (where the first element is not a pointer) will result in undefined behavior or crashes.

Alternative: Heap Allocation for 2D Structures

When large volumes of 2D data necessitate heap allocation, the double pointer (int**) pattern is often employed, typically via malloc or calloc for both the array of pointers and the individual rows.

#include <stdlib.h>

int R = 5; 
int C = 10;

// Allocate R pointers
int **heap_matrix = (int **)malloc(R * sizeof(int *));

for (int i = 0; i < R; i++) {
    // Allocate C integers for each row
    heap_matrix[i] = (int *)malloc(C * sizeof(int));
}

// Access: heap_matrix[r][c] works similarly to the array of pointers concept.

// Deallocation is essential:
for (int i = 0; i < R; i++) {
    free(heap_matrix[i]);
}
free(heap_matrix);

While this structure behaves similarly to an array of pointers in terms of access syntax, it is heap-managed. Directly casting a stack-allocated matrix[X][Y] to int** is problematic because the contiguous block does not contain the necessary pointer values at the initial addresses.

FAQs on C Multidimensional Arrays Versus Pointers

Q: Is an int matrix 2 4 considered a double pointer

ANS: No, an int matrix[2][4] is a single contiguous block of memory, not a pointer to a pointer. It decays to int (*)[4].

Q: How does a 2D array decay when passed to a function

ANS: It decays to a pointer to an array of the inner dimension’s size, e.g., int (*)[C], retaining size context.

Q: What is the primary memory difference between int arr[R][C] and int* arr[R]

ANS: int arr[R][C] is one continuous block. int* arr[R] is an array holding R pointers, each pointing to a separate memory block for the rows.
