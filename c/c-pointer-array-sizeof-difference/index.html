“C/C++: Distinguishing sizeof(&str) vs sizeof(str) for char Array”

When working with character arrays in C or C++, the behavior of the sizeof operator applied directly to the array versus its address results in distinct outcomes governed by C’s type system and pointer arithmetic rules. Consider the declaration:

#define N 10
char str2[N] = {"Hello"};

How do sizeof(str2) and sizeof(&str2) differ, and what implications do these differences have on memory representation and pointer operations?

Array Size Versus Address Size

The core distinction lies in what each expression represents:

  1. sizeof(str2): According to the C standard (Section 6.5.3.4), applying sizeof to an array type yields the total number of bytes occupied by the entire array. Since str2 is declared as char str2[10] and char is typically 1 byte, sizeof(str2) evaluates to 10 bytes.

  2. sizeof(&str2): The expression &str2 yields the address of the entire array. Its type is a pointer to an array of 10 characters: char (*)[10]. Therefore, sizeof(&str2) returns the size of this pointer type on the specific platform. On a 32-bit system, this is often 4 bytes, and on a 64-bit system, it is usually 8 bytes.

Type Discrepancy

The types reveal the structural difference:

  • Type of str2 is char[10] (an array of 10 characters).
  • Type of &str2 is char (*)[10] (a pointer to an array of 10 characters).

Value Equivalence vs. Semantic Difference

While value-wise, str2 (which decays to the address of the first element) and &str2 (the address of the array) might yield the same numerical address for the start of the memory block, their semantics are critically different, particularly when used in pointer arithmetic.

Consider this memory layout example (assuming str2 starts at address 201):
