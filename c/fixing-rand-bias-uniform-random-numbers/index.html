“Fixing rand() Bias: Achieving Uniform Random Number Generation”

How can we accurately generate random integers within a specific range, avoiding the distribution skew inherent in simple modulo operations?

Addressing rand() Bias for Uniformity

The core of the problem lies in how rand() produces numbers. It’s generally assumed that rand() provides a sequence that is uniformly distributed across its output interval, [0, RAND_MAX]. However, when we use rand() % N to constrain this output to a smaller range [0, N-1], if RAND_MAX + 1 is not perfectly divisible by N, the higher numbers in the range [0, N-1] will be underrepresented.

Consider the assumption that rand() produces numbers with a Poisson distribution: any two non-overlapping subintervals of the same size are equally likely and independent. For a finite set of values, this implies a uniform distribution. The challenge is to map these uniformly distributed outputs to a desired, potentially smaller, range without introducing bias.

Solutions for Uniform Random Number Generation

Several methods exist to achieve a more uniform distribution. These often involve discarding certain rand() outputs or using more sophisticated arithmetic.

Solution 1: Binning with Rejection Sampling (using random())

This approach divides the output range of random() (which is generally preferred over rand() for its better distribution) into equal-sized “bins” corresponding to the desired output range. If a generated number falls outside these bins, it’s discarded, and a new number is generated.

#include <stdlib.h> // For random(), RAND_MAX

// Assumes 0 <= max <= RAND_MAX
// Returns in the closed interval [0, max]
long random_at_most(long max) {
  unsigned long
    num_bins = (unsigned long)max + 1,
    num_rand = (unsigned long)RAND_MAX + 1,
    bin_size = num_rand / num_bins,
    defect   = num_rand % num_bins;

  long x;
  do {
    x = random();
  }
  // This is carefully written not to overflow
  while (num_rand - defect <= (unsigned long)x);

  // Truncated division is intentional
  return x / bin_size;
}

This method ensures that each desired outcome has an equal probability of being selected. For generating numbers outside the default [0, RAND_MAX] range, one could devise a function that pulls multiple bits and then applies random_at_most. To obtain values in a range [min, max], the formula min + random_at_most(max - min) can be used.

Solution 2: Iterative Binning for a Specific Interval

This is a refined version of the binning concept, tailored to return values within a specified [min, max] interval.

#include <cstdlib> // For rand(), RAND_MAX

unsigned int rand_interval(unsigned int min, unsigned int max) {
    // Ensure max >= min and 1 + max - min < RAND_MAX for this specific implementation's bounds
    // In a real-world scenario, more robust error handling or alternative methods might be needed for larger ranges.
    if (min > max) {
        // Swap min and max if they are in the wrong order
        unsigned int temp = min;
        min = max;
        max = temp;
    }

    const unsigned int range = 1 + max - min;
    const unsigned int buckets = RAND_MAX / range;
    const unsigned int limit = buckets * range;

    /* Create equal size buckets all in a row, then fire randomly towards
     * the buckets until you land in one of them. All buckets are equally
     * likely. If you land off the end of the line of buckets, try again. */
    int r;
    do {
        r = rand();
    } while (r >= limit);

    return min + (r / buckets);
}

This iterative approach is efficient and aims to minimize the number of rejections.

Solution 3: Direct Formula (with potential bias)

A commonly seen, though potentially biased, formula is:

int r = (rand() % (max + 1 - min)) + min;

This formula maps rand()’s output to the desired range. However, as noted, it can introduce bias if RAND_MAX + 1 is not divisible by (max + 1 - min).

Solution 4: Floating-Point Scaling

Another approach uses floating-point arithmetic to scale the output of rand():

unsigned int randr(unsigned int min, unsigned int max) {
    double scaled = (double)rand() / RAND_MAX;
    return (max - min + 1) * scaled + min;
}

While mathematically plausible, this method can be susceptible to floating-point precision and rounding errors, and its suitability may depend on the specific implementation and required accuracy.

Solution 5: Simple Modulo for Specific Cases (e.g., Dice Roll)

For common scenarios like simulating a dice roll (1 to 6), the direct modulo approach is often used, though it carries the known bias:

#include <cstdlib> // For rand()
#include <ctime>   // For time()

// Seed the random number generator (typically once at the start of the program)
// srand(time(NULL)); 
int r = (rand() % 6) + 1;

Here, rand() % 6 yields numbers from 0 to 5. Adding 1 shifts this to the desired 1 to 6 range.

Solution 6: High-Precision Fixed-Point Synthesis

This method iteratively synthesizes a high-precision fixed-point random number to reduce bias, especially when the desired range is much smaller than RAND_MAX.

// For a desired range of [0, n-1]
int r = n / 2; // Initialize intermediate value
r = (rand() * n + r) / (RAND_MAX + 1);
r = (rand() * n + r) / (RAND_MAX + 1);
// ... repeat as needed for higher precision

This process effectively increases the number of bits used for the random value, leading to a more uniform distribution.

Solution 7: Refined Interval Generation

A more robust version of the binning approach, handling inclusivity and potential RAND_MAX limitations:

#include <cstdint> // For uint32_t, uint64_t
#include <cstdlib> // For rand()

// Begin and end are *inclusive*; => [begin, end]
uint32_t getRandInterval(uint32_t begin, uint32_t end) {
    uint32_t range = (end - begin) + 1;
    // Calculate the largest multiple of 'range' less than or equal to RAND_MAX + 1
    uint32_t limit = ((uint64_t)RAND_MAX + 1) - (((uint64_t)RAND_MAX + 1) % range);

    uint32_t randVal = rand();
    while (randVal >= limit) {
        randVal = rand(); // Discard and retry if outside the valid range
    }

    // Map the valid random value to the desired range
    return (randVal % range) + begin;
}

This example illustrates how randVal % range correctly picks a bucket, and + begin shifts it to the target interval.

Solution 8: Using arc4random_uniform (if available)

On systems that provide arc4random_uniform, it’s a highly recommended and efficient way to get uniformly distributed random numbers:

Solution 10: Bit Masking for Uniformity

This method masks off bits from rand() to create a value within a power-of-two range, which can then be more reliably mapped to the desired range.

#include <cstdint>
#include <cstdlib> // For rand()

static uint32_t randomInRange(uint32_t a, uint32_t b) {
    uint32_t v;
    uint32_t range;
    uint32_t upper, lower;
    uint32_t mask = 0;

    if (a == b) return a;

    if (a > b) { upper = a; lower = b; }
    else { upper = b; lower = a; }

    range = upper - lower;

    // Create a mask that's the smallest power of 2 greater than or equal to 'range'
    // This ensures that rand() & mask has a predictable power-of-2 range
    while (mask < range) {
        mask = (mask << 1) | 1;
    }

    // Generate a random value using the mask and retry if it exceeds the desired range
    while (true) {
        v = rand() & mask;
        if (v <= range) {
            return lower + v;
        }
    }
}

Solution 11: Generating a Floating-Point Random Number [0, 1]

A simple way to get a random floating-point value between 0 and 1:

#define rand01() (((double)random())/((double)(RAND_MAX)))

This can be a building block for other random number generation strategies.

FAQs on Fixing rand() Bias

Q: Why does rand() % N cause bias

ANS: The bias arises because the range of rand() (0 to RAND_MAX) might not be an exact multiple of your desired range size N. Numbers in the higher part of the rand() output that don’t fit neatly into the N bins are discarded, disproportionately affecting the distribution of the remaining numbers.

Q: What is the best practice for generating random numbers in C++

ANS: For more critical applications, consider using the C++ <random> library, which offers various distributions (e.g., std::uniform_int_distribution) and high-quality random number engines (e.g., std::mt19937) designed to avoid bias and provide better statistical properties than rand().

Q: Is it ever okay to use rand() N

ANS: For non-critical applications where perfect uniformity is not paramount (e.g., simple game simulations, quick prototyping), rand() % N might be acceptable due to its simplicity. However, for security-sensitive or statistically rigorous tasks, it’s best avoided.

Q: How does the rejection sampling method work

ANS: Rejection sampling generates random numbers and discards any that fall outside a specified “acceptable” range. By carefully defining these acceptable ranges to be of equal size and probability, the resulting numbers within the accepted ranges will have a uniform distribution.

Q: What's the difference between rand() and random()

ANS: random() (available in POSIX systems) generally offers a better quality of randomness and a larger output range than rand(). It’s often preferred when available for achieving more uniform distributions.
