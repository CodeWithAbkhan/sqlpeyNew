“C Pointer Modification: Why Pass a Pointer to a Pointer?”

This behavior necessitates a technique known as “multiple indirection,” most commonly achieved by passing a pointer to a pointer. This allows a function to directly manipulate the address stored in the original pointer variable.

Why Multiple Indirection?

Let’s consider a common scenario: allocating memory for a data structure and having that allocation reflected back in the calling function.

Scenario: List Manipulation

Imagine you have a linked list structure. When adding a new node to the beginning of the list, you need to update the head pointer of the list.

Here’s an example of a function barPush that aims to add a Bar element to the beginning of a BarList:

Solution 1: Using a Pointer to a Pointer

In this approach, the barPush function accepts a pointer to a BarList pointer (BarList **list). This allows the function to modify the list pointer itself.

#include <stdio.h>
#include <stdlib.h>

// Assume Bar and BarList structures are defined elsewhere
typedef struct Bar {
    int data;
} Bar;

typedef struct BarList {
    Bar *val;
    struct BarList *nextBar;
} BarList;

#define EMPTY_LIST NULL

void barPush(BarList **list, Bar *bar) {
    // Ensure a valid pointer to the list pointer is provided
    if (list == NULL) {
        return;
    }

    // If no bar element to add, return early
    if (bar == NULL) {
        return;
    }

    // Allocate space for the new node
    BarList *newNode = (BarList *)malloc(sizeof(BarList));
    if (newNode == NULL) {
        perror("Memory allocation failed for new node");
        return; // Or handle error appropriately
    }

    // Assign the bar element to the new node
    newNode->val = bar;

    // Link the new node to the current head of the list
    newNode->nextBar = *list;

    // Update the head pointer of the list to point to the new node
    *list = newNode;
}

int main() {
    BarList *myList = EMPTY_LIST;
    Bar b1 = {10};
    Bar b2 = {20};

    // Pass the address of the myList pointer
    barPush(&myList, &b1);
    barPush(&myList, &b2);

    // Now myList points to the newly added nodes
    BarList *current = myList;
    while (current != NULL) {
        printf("Node value: %d\n", current->val->data);
        current = current->nextBar;
    }

    // Clean up allocated memory (simplified for demonstration)
    current = myList;
    while (current != NULL) {
        BarList *temp = current;
        current = current->nextBar;
        free(temp); // Free the node itself
        // Note: Freeing the 'Bar' elements (b1, b2) depends on ownership
    }

    return 0;
}

Usage Example:

BarList *l;

l = EMPTY_LIST;
barPush(&l, &b1); // Pass the address of 'l'
barPush(&l, &b2);

Alternative: Returning the New Head

An alternative suggested by Jonathan Leffler involves modifying the function to return the new head of the list.

#include <stdio.h>
#include <stdlib.h>

// Assume Bar and BarList structures are defined elsewhere
typedef struct Bar {
    int data;
} Bar;

typedef struct BarList {
    Bar *val;
    struct BarList *nextBar;
} BarList;

#define EMPTY_LIST NULL

BarList *barPushReturn(BarList *list, Bar *bar) {
    // If no bar element to add, return the unmodified list
    if (bar == NULL) {
        return list;
    }

    // Allocate space for the new node
    BarList *newNode = (BarList *)malloc(sizeof(BarList));
    if (newNode == NULL) {
        perror("Memory allocation failed for new node");
        return list; // Return original list on failure
    }

    // Assign the bar element to the new node
    newNode->val = bar;

    // Link the new node to the current head of the list
    newNode->nextBar = list;

    // Return the new head of the list
    return newNode;
}

int main() {
    BarList *myList = EMPTY_LIST;
    Bar b1 = {10};
    Bar b2 = {20};

    // Reassign myList with the returned new head
    myList = barPushReturn(myList, &b1);
    myList = barPushReturn(myList, &b2);

    // Now myList points to the newly added nodes
    BarList *current = myList;
    while (current != NULL) {
        printf("Node value: %d\n", current->val->data);
        current = current->nextBar;
    }

    // Clean up allocated memory (simplified for demonstration)
    current = myList;
    while (current != NULL) {
        BarList *temp = current;
        current = current->nextBar;
        free(temp); // Free the node itself
        // Note: Freeing the 'Bar' elements (b1, b2) depends on ownership
    }

    return 0;
}

Usage Example:

BarList *l;

l = EMPTY_LIST;
l = barPushReturn(l, &b1); // Reassign 'l' with the new head
l = barPushReturn(l, &b2);

The Underlying Principle: Pass by Value

In C, all arguments are passed by value. This fundamental rule is the reason behind needing mechanisms like pointers to pointers.

  • Passing a pointer: When you pass ptr (a pointer) to a function, the function receives a copy of ptr. Any changes to this copy do not affect the original ptr.
  • Passing a pointer to a pointer: When you pass &ptr (the address of ptr) to a function, the function receives a copy of the memory address where ptr is stored. By dereferencing this address (*ptrPtr), the function can access and modify the original ptr variable.

This is akin to passing a variable by reference in other languages, allowing functions to alter the state of variables declared in the caller’s scope.

Understanding Multiple Indirection

Multiple indirection involves using pointers that point to other pointers, or even pointers to pointers to pointers, and so on. Each additional asterisk (*) in a pointer declaration increases the level of indirection.

  • int *p; : p is a pointer to an integer.
  • int **pp; : pp is a pointer to a pointer to an integer.
  • int ***ppp; : ppp is a pointer to a pointer to a pointer to an integer.

Dereferencing a pointer moves you one step closer to the actual data:

  • *p gives you the int value.
  • *pp gives you the int * value (the pointer p).
  • **pp gives you the int value (by dereferencing pp once to get p, and then dereferencing p).

To modify the original pointer ptrMain in the main function, the trueAllocater function needs to accept int **ptrTrueAllocater. This means ptrTrueAllocater points to the memory location of ptrMain. When *ptrTrueAllocater = malloc(...) is executed, it’s actually modifying the value of ptrMain in the main function, making it point to the newly allocated memory.

Example: noIndirection.c vs. withIndirection.c

Consider the difference in behavior between these two conceptual examples:

noIndirection.c (Illustrating the problem):

#include <stdio.h>
#include <stdlib.h>

void allocater(int *ptrTempAllctr) {
    // This malloc allocates memory, but ptrTempAllctr is a copy
    // of the pointer passed from main. The original pointer in main
    // remains unchanged.
    ptrTempAllctr = (int *)malloc(sizeof(int));
    if (ptrTempAllctr == NULL) {
        perror("in allocater() memory allocation error");
        exit(EXIT_FAILURE);
    }
}

int main() {
    int *ptrMain = NULL;
    allocater(ptrMain); // Passing ptrMain by value

    if (ptrMain == NULL) {
        printf("ptrMain is points to NULL\n"); // This will be printed
    }
    return 0;
}

In noIndirection.c, allocater receives a copy of ptrMain. The malloc inside allocater assigns a new address to this temporary copy. When allocater finishes, its local ptrTempAllctr is discarded, and ptrMain in main still points to NULL.

withIndirection.c (Illustrating the solution):

#include <stdio.h>
#include <stdlib.h>

void trueAllocater(int **ptrTrueAllocater) {
    // Dereferencing ptrTrueAllocater allows modification of the original pointer
    *ptrTrueAllocater = (int *)malloc(sizeof(int));
    if (*ptrTrueAllocater == NULL) {
        perror("in trueAllocater() memory allocation error");
        exit(EXIT_FAILURE);
    }
}

int main(void) {
    int *ptrMain = NULL;
    trueAllocater(&ptrMain); // Passing the address of ptrMain

    if (ptrMain == NULL) {
        printf("memory not allocated\n"); // This will not be printed if allocation succeeds
    } else {
        printf("Memory allocated and assigned to ptrMain from trueAllocater\n");
    }

    free(ptrMain); // Free the allocated memory
    return EXIT_SUCCESS;
}

In withIndirection.c, trueAllocater receives the address of ptrMain. By dereferencing ptrTrueAllocater (which is ptrTrueAllocater), the function directly modifies ptrMain itself, making it point to the memory allocated by malloc.

Further Considerations

  • Generic Programming: Multiple indirection is also a key concept for writing generic functions that can operate on various data types and modify pointers to those types.
  • Array Manipulation: This technique is crucial when functions need to dynamically allocate or reallocate memory for arrays and have those changes reflected in the caller.
  • Readability: While powerful, excessive levels of indirection can make code harder to read and debug. Consider clarity when designing function interfaces.

The fundamental takeaway is that to alter a pointer variable in a calling function from a called function in C, you must pass the address of that pointer variable (i.e., a pointer to a pointer).

FAQs on C Pointer to Pointer Modification

Q: Why do I need to pass a pointer to a pointer in C to modify a pointer in a function

ANS: In C, arguments are passed by value. When you pass a pointer to a function, the function receives a copy of that pointer. To modify the original pointer variable in the calling scope, you need to pass its memory address, effectively passing a pointer to that pointer. This allows the function to dereference the pointer-to-pointer and change where the original pointer points.

Q: What is the primary use case for passing a pointer to a pointer

ANS: The primary use case is to enable a function to modify a pointer variable that is declared in the calling scope. This is essential for operations like dynamic memory allocation (e.g., using malloc or realloc) where the pointer needs to be updated to point to the newly allocated memory, or for functions that need to change which data structure a pointer refers to.

Q: Can I achieve the same result by returning the new pointer value from the function

ANS: Yes, an alternative approach is for the function to return the new pointer value. The caller then needs to reassign its pointer variable with the returned value. For example, a function that allocates memory might return a void* pointer, which the caller then casts and assigns to its specific pointer type.

Q: How does multiple indirection help in memory allocation functions

ANS: In memory allocation functions (like malloc), the goal is often to assign a newly allocated memory address to a pointer variable in the calling scope. By passing a pointer to that pointer (e.g., int **ptr), the allocation function can use *ptr = malloc(...) to change where the original pointer points, thus successfully updating the caller’s pointer.

Q: What happens if I pass a pointer to a function and try to reassign it without using a pointer to a pointer

ANS: If you pass a pointer T *p to a function and try to reassign it using p = ... inside the function, you are only changing the local copy of the pointer. The original pointer in the calling scope remains unaffected. The memory allocated or pointed to by the new assignment within the function will be lost when the function returns, potentially leading to memory leaks or incorrect program behavior.
