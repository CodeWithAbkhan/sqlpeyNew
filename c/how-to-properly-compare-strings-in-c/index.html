“Solved: How to Properly Compare Strings in C Using strcmp”

When you’re working with strings in C, a common pitfall for beginners is attempting to compare them directly using the == or != operators. If you’ve encountered this, you’ve likely discovered that this method doesn’t compare the content of the strings but rather their memory addresses. This leads to unexpected results and logical errors in your code. This guide will walk you through the correct approach to string comparison in C, focusing on the indispensable strcmp function.

Why == and != Fail for String Comparison

In C, strings are essentially arrays of characters terminated by a null character (\0). When you use == or != with character arrays, you are comparing the memory addresses where these arrays are stored, not the actual sequence of characters they hold.

Consider this scenario:

char string1[50];
char string2[50];

// Assume string1 and string2 are populated with the same characters, e.g., "hello"
// However, they are stored at different memory locations.

if (string1 == string2) {
    // This block will likely not execute because addresses are different
    printf("Strings are equal!\n");
} else {
    // This block will execute
    printf("Strings are not equal!\n");
}

The if condition here evaluates to false because string1 and string2 represent the memory addresses of the first element of each array, and these addresses are distinct, even if the character data at those locations is identical.

The Correct Way: Using strcmp

The standard C library provides a robust function for comparing strings: strcmp. This function, found in the <string.h> header, compares two strings character by character.

How strcmp Works:

  • It returns 0 if the two strings are identical.
  • It returns a negative value if the first string lexicographically precedes the second string.
  • It returns a positive value if the first string lexicographically follows the second string.

Solution 1: Basic strcmp Usage

The most straightforward way to use strcmp in a loop is to continue as long as the strings are not equal, which means strcmp does not return 0.

#include <stdio.h>
#include <string.h> // Required for strcmp

int main() {
    char input_buffer[100];
    char sentinel_value[] = "quit"; // The string to exit the loop

    printf("Enter text (type 'quit' to exit):\n");
    // Using fgets is safer than gets as it prevents buffer overflows.
    // It also includes the newline character if space permits.
    fgets(input_buffer, sizeof(input_buffer), stdin);

    // Remove the trailing newline character if present from fgets
    input_buffer[strcspn(input_buffer, "\n")] = 0;

    // Loop until the input matches the sentinel value
    while (strcmp(input_buffer, sentinel_value) != 0) {
        printf("You entered: %s\n", input_buffer);
        printf("Enter text (type 'quit' to exit):\n");
        fgets(input_buffer, sizeof(input_buffer), stdin);
        input_buffer[strcspn(input_buffer, "\n")] = 0;
    }

    printf("Exiting program. Goodbye!\n");

    return 0;
}

In this example, the while loop continues as long as strcmp(input_buffer, sentinel_value) is not equal to 0.

Solution 2: Alternative strcmp Condition

You can also leverage the fact that any non-zero integer evaluates to true in a boolean context in C. Therefore, while (strcmp(check, input)) is a valid and common idiom.

#include <stdio.h>
#include <string.h>

int main() {
    char target_word[] = "success";
    char user_guess[50];

    printf("Guess the secret word:\n");
    scanf("%49s", user_guess); // Read up to 49 characters to prevent overflow

    // Continue looping as long as the user's guess does NOT match the target word.
    // strcmp returns 0 when strings match.
    while (strcmp(target_word, user_guess)) {
        printf("Incorrect guess. Try again:\n");
        scanf("%49s", user_guess);
    }

    printf("Congratulations! You guessed the word.\n");

    return 0;
}

This concise form while (strcmp(target_word, user_guess)) is equivalent to while (strcmp(target_word, user_guess) != 0).

Solution 3: Manual String Comparison Function

While strcmp is the standard and recommended approach, you can implement your own string comparison function for educational purposes or specific needs. This involves iterating through both strings character by character.

#include <stdio.h>
#include <stdbool.h> // For bool type

// Function to compare two strings character by character
bool compare_strings(const char str1[], const char str2[]) {
    int i = 0;
    while (str1[i] != '\0' || str2[i] != '\0') {
        if (str1[i] != str2[i]) {
            return false; // Mismatch found
        }
        // If characters match, move to the next pair
        i++;
    }
    // If loop finishes, both strings are identical up to their null terminators
    return true;
}

int main() {
    char initial_prompt[] = "start";
    char user_response[60];

    printf("Type '%s' to proceed:\n", initial_prompt);
    scanf("%59s", user_response);

    while (!compare_strings(initial_prompt, user_response)) {
        printf("Incorrect input. Please type '%s' to continue:\n", initial_prompt);
        scanf("%59s", user_response);
    }

    printf("Proceeding...\n");

    return 0;
}

This custom compare_strings function returns true (or 1) if the strings match and false (or 0) if they don’t. The loop condition !compare_strings(initial_prompt, user_response) ensures the loop continues as long as the strings are different.

Important Considerations: fgets and the Newline Character

When using fgets to read strings, it often includes the newline character (\n) at the end of the buffer if there’s enough space. If you’re comparing the input to a string literal that doesn’t have a newline, the comparison will fail.

It’s good practice to remove the trailing newline character before performing comparisons:

// After reading with fgets:
input_buffer[strcspn(input_buffer, "\n")] = 0;

strcspn(input_buffer, "\n") finds the index of the first occurrence of \n. By setting the character at that index to 0 (the null terminator), you effectively remove the newline.

FAQs on How to Properly Compare Strings in C Using strcmp

Q: Why does using == or != with strings in C not work as expected

ANS: The == and != operators in C compare the memory addresses of variables. When used with arrays (like strings), they compare the addresses where those arrays start in memory, not the actual character content of the strings themselves. Therefore, even if two strings have identical characters, they will be considered unequal by these operators if they are stored at different memory locations.

Q: What is the correct function to compare strings in C

ANS: The standard and correct function to compare strings in C is strcmp(), which is part of the <string.h> library. It compares strings character by character and returns 0 if they are identical.

Q: How does the strcmp function determine if strings are equal

ANS: The strcmp function compares strings lexicographically. It returns 0 if the two strings are identical. If the strings differ, it returns a negative value if the first string comes before the second alphabetically, and a positive value if the first string comes after the second.

Q: What header file is needed for strcmp

ANS: You need to include the <string.h> header file to use the strcmp function.

Q: Is it safe to use gets() for string input in C

ANS: No, the gets() function is considered unsafe because it does not perform bounds checking, making it vulnerable to buffer overflow attacks. It’s highly recommended to use fgets() instead, which allows you to specify the maximum number of characters to read, thus preventing overflows.

Q: Why should I remove the newline character when using fgets

ANS: fgets() typically includes the newline character (\n) in the buffer if it fits. If you compare a string read by fgets() to a literal string without a newline (e.g., “hello” vs. “hello\n”), strcmp() will report them as different. Removing the newline ensures accurate comparisons.
