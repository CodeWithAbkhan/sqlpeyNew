“C/C++ Array Function Parameter Passing Behavior: Decay to Pointer or Reference?”

When working with C-style arrays, how exactly are they transmitted to a function? If you declare a function expecting an array, like void arraytest(int a[]), what is happening under the hood, and why does modifying the parameter inside the function affect the original array in the calling scope?

The core behavior revolves around array decay. Let’s dissect this fundamental aspect of C/C++ array handling when used as function arguments.

The Identity of Array Parameter Declarations

It is a consistent feature in C (and C++) that when an array type is used as a function parameter, it automatically adjusts—or “decays”—to a pointer to its element type.

Consider these function signature declarations:

void arraytest(int a[]);
void arraytest(int *a);

These two declarations are functionally identical. In both cases, the parameter a inside arraytest is treated as an int * (a pointer to an integer).

This automatic adjustment extends to declarations that include size specifications:

void arraytest_size_zero(int a[0]);     // Decays to int *
void arraytest_size_one(int a[1]);      // Decays to int *
void arraytest_size_hundred(int a[1000]); // Decays to int *

In all these instances, the parameter decays to an int *. The integer values specified in the brackets (like [0], [1], or [1000]) serve only for documentation; they do not enforce size checking by the compiler during the call. This is why you can call such functions without warnings, even with strict compiler flags like -Wall -Wextra -Werror, provided you pass a valid pointer or array.

Practical Implications: Modification of Original Data

Because the array name decays to a pointer to its first element, the function receives the memory address of the array’s start.

This means arrays are effectively passed by reference (via the pointer copy of the address), not by value. Any write operation performed on the array elements inside the function modifies the contiguous block of memory owned by the caller.

Example of In-Place Modification:

If we define a main function and the decaying function:

void modify_array(int data_slice[]) {
    // data_slice is equivalent to int *data_slice
    data_slice[0] = 999; // Modifies the original array
    *(data_slice + 1) = 888;
}

int main() {
    int original_data[2] = {10, 20};
    
    // original_data decays from type int[2] to int *
    modify_array(original_data); 
    
    // original_data is now {999, 888}
    // Check values: printf("%d, %d\n", original_data[0], original_data[1]);
    
    return 0;
}

This confirms that you are modifying the value located at the memory location pointed to by the array’s base address. Remember that C syntax uses the identity a[i] being equivalent to *(a + i).

Alternative Method: Forcing Type Safety via Explicit Pointers to Arrays

While standard array passing results in decay to a pointer, there is a mechanism to enforce size specificity, particularly useful for multi-dimensional arrays, by passing the address of the entire array object, which results in a pointer-to-array type.

For a 1D array like int my_array[2];, taking its address yields a type int (*)[2], which reads as “pointer to an array of 2 integers.”

We can define a function parameter to explicitly accept this specific pointer-to-array type:

// The parameter 'a' is a pointer to an array of exactly 2 integers.
void strictly_typed_array_test(int (*a)[2]) 
{
    // Access is still valid:
    (*a)[0] = 500;
    // Or using pointer arithmetic: *(*(a) + 0) = 500;
}

int main() {
    int specific_size_array[2] = {1, 2};
    
    // SUCCESS: Pass the address of the array object (&)
    strictly_typed_array_test(&specific_size_array); 
    
    // FAILURE (Warning/Error): Passing 'specific_size_array' decays to int *, 
    // which is incompatible with expected int (*)[2].
    // strictly_typed_array_test(specific_size_array); 
    
    return 0;
}

When compiled with error checking (-Werror), the call without the address operator (&) fails compilation because int * is incompatible with the expected int (*)[2]. This approach prevents decay and forces the compiler to check the size at compile time.

Distinguishing int (*a)[N] from int *a[N]

A common pitfall is confusing the pointer-to-array syntax with an array-of-pointers syntax.

  • int (*a)[2]: Declares a as a pointer to an array of 2 integers. (Used above for type safety).
  • int *a[2]: Declares a as an array of 2 pointers to integers.

Handling Multi-Dimensional Arrays

For multi-dimensional arrays, the concept of decay still applies, but specifying the function signature becomes crucial for accessing elements correctly. You cannot simply substitute a 2D array with a int ** (pointer-to-pointer) if it was declared as a fixed-size C-style array.

For a 2D array defined as arr[ROWS][COLS], the function signature must specify all dimensions except the outermost one:

// Accepts any array where the second dimension (columns) is fixed at 5.
void process_fixed_column_array(int (*arr)[5], const int rows) {
    for (int i = 0; i < rows; i++) {
        for (int j = 0; j < 5; j++) {
            arr[i][j] = 0; // Equivalent to *(*(arr + i) + j) = 0;
        }
    }
}

int data[3][5]; // Valid call: process_fixed_column_array(data, 3);

int jagged_data[3][6]; // Invalid call for the function above!

To generalize for N dimensions, you must specify the size of every dimension except the first one. For a 3D array arr[D1][D2][D3], the signature would look like void func(int (*arr)[D2][D3], int D1, int D2, int D3).

If you need maximum flexibility for N dimensions without complex pointer casting, using standard library containers like std::vector<std::vector<int>> in C++ is often preferred, as they manage size information dynamically and avoid the complexities of C-style array dimension constraints. For C, dynamic allocation using a pointer-to-pointer structure (int **) is the typical alternative, though it requires different memory setup than fixed arrays.

Special Cases Where Array Names Do Not Decay

Array decay is nearly universal, but there are three primary contexts where an array name retains its full array type information, rather than decaying to a pointer:

  1. When used as the operand for the sizeof operator (e.g., sizeof(array_name)).
  2. When used as the operand for the unary address-of operator & (e.g., &array_name, resulting in a pointer-to-array type).
  3. When used in an initializer for an array variable (e.g., char b[] = "string";).

These exceptions allow inspecting the true size of the array or obtaining a pointer-to-array type, as demonstrated in the type-safe example above.

FAQs on C Array Function Passing Behavior

Q: Does passing an array to a C function copy the entire array data

ANS: No, C arrays are never passed by value to functions. The array name decays to a pointer to the first element, meaning only the memory address is passed.

Q: How can I prevent an array from decaying when passed to a function

ANS: You must use the address-of operator (&) when calling the function and declare the function parameter as a pointer to an array type, such as int (*a)[SIZE].

Q: Is void func(int a[]) the same as void func(int *a)

ANS: Yes, for function parameters, the compiler treats int a[] exactly the same as int *a; both result in the parameter being a pointer to int.

Q: Can I use int ** to pass a 2D array safely

ANS: Not directly if the 2D array was allocated statically or with contiguous memory. Using int ** implies a structure built from arrays of pointers, which differs from how standard 2D arrays are laid out in memory.
