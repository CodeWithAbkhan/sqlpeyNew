“C Programming: Demystifying Pointer to Pointer Usage and Mechanics”

A fundamental concept in low-level programming, particularly in languages like C, involves understanding the hierarchy of indirection. If a simple pointer (T*) holds the memory address of a variable of type T, then a pointer to a pointer (T**) holds the memory address of another pointer variable.

  1. Single Pointer (const char *c): If we declare const char *c = "hello";, the pointer c stores the starting address of the string, which is 63. Assuming c itself is stored at address 58, then c holds the value 63.
  2. Pointer to Pointer (const char **cp): If we declare const char **cp = &c;, the variable cp stores the address of the pointer c. If c is at address 58, then cp holds the value 58.
  3. Triple Pointer (const char ***cpp): Following the chain, const char ***cpp = &cp; means cpp holds the address of cp. If cp is at address 60, then cpp holds the value 60.

This structure allows modification of the initial pointer from deeper scopes.

// Visualizing the hierarchy based on the conceptual memory map:
// Address 63 starts "hello\0"
// Address 58 holds the value 63 (where 'c' is stored)
// Address 60 holds the value 58 (where 'cp' is stored)

const char *c = "hello";   // c holds 63
const char **cp = &c;      // cp holds the address of c (58)
const char ***cpp = &cp;   // cpp holds the address of cp (60)

Primary Motivations for Utilizing T**

Why introduce this layer of indirection? The core reason is the necessity to modify a pointer variable declared in an outer scope from within a function call.

1. Modifying Caller-Scope Pointers (Passing by Reference for Pointers)

If a function needs to dynamically allocate memory and assign that new address to a pointer owned by the calling routine, passing the pointer’s address is essential.

Scenario: Allocating 1024 bytes on the heap and making the caller’s pointer point to it.

#include <stdlib.h>

/**
 * Allocates memory on the heap and updates the pointer passed in.
 * @param p A pointer to an integer pointer (int**).
 * @return 0 on success, -1 on failure.
 */
int allocate_heap_memory(int **p) {
    // *p dereferences the double pointer, accessing the address stored in the caller's 'p_out'
    *p = (int*)malloc(1024 * sizeof(int)); 
    if (*p == NULL) {
        return -1; // Allocation failed
    }
    return 0; // Success
}

// Usage in main:
// int *p_out;
// allocate_heap_memory(&p_out); 
// Now p_out points to the 1024 allocated integers.

Contrast this with a function that only reads the pointer:

int set_value_to_five(int *p_in) {
  *p_in = 5; // Modifies the integer the pointer points to.
  return 1;
}

// Usage:
// int x;
// set_value_to_five(&x); // x is now 5.

2. Handling Arrays and Strings

The representation of multi-dimensional arrays often naturally involves pointers to pointers.

  • An array of basic types (T[]) decays to a pointer to the first element (T*).
  • An array of strings (char*[]) is conceptually an array where each element is a char*. Therefore, an array of character pointers is typified as char**. This is exactly how argv in the main function (int main(int argc, char **argv)) is structured—it’s an array of strings (character pointers).

3. Simplifying Linked List Operations

Linus Torvalds famously emphasized the elegance of using pointers to pointers for safely removing nodes from singly-linked lists without special casing the head node.

Traditional (Conditional) Removal: Requires tracking both the current entry and the previous entry (prev) to handle the removal of the head node separately.

// Simplified traditional approach snippet
if (prev) {
    prev->next = entry->next; // Modify previous node's next pointer
} else {
    head = entry->next;       // Special case: Modify the list head itself
}

Pointer-to-Pointer Approach (Eliminates Conditionals): By using a pointer to the pointer that points to the node being examined (pp), we can always use the same dereference operation to modify the forward link.

typedef struct list_entry {
    int val;
    struct list_entry *next;
} list_entry;

void remove_entry_elegant(list_entry **pp, int to_remove) {
    list_entry *entry = *pp;
    
    while (entry != NULL) {
        if (entry->val == to_remove) {
            // *pp points to the 'next' field of the preceding node 
            // (or the address of 'head' if it's the first node).
            *pp = entry->next; 
            // entry is now effectively unlinked, we don't advance pp here.
        } else {
            // Advance pp to point to the 'next' field of the current node.
            pp = &entry->next; 
        }
        entry = *pp; // Move to the next element referenced by the updated pp
    }
}

// Initialization: Start pp pointing to the address of the list head
// list_entry *head = ...;
// remove_entry_elegant(&head, 42);

This technique ensures that *pp = entry->next; correctly overwrites either the previous node’s next pointer or the head variable itself, unifying the removal logic.

Distinguishing Pointers to Pointers from Pointers to Arrays

While related to multi-dimensional data, a pointer to a pointer (T**) is distinct from a pointer to a fixed-size multi-dimensional array (T (*)[ROWS][COLUMNS]).

If you know the exact dimensions beforehand, a pointer to a 2D array is more specific:

#define ROWS 10
#define COLUMNS 5

double matrix[ROWS][COLUMNS];
// Pointer that specifically targets the structure of matrix
int (*myPointerTo2DimArray)[ROWS][COLUMNS] = &matrix;

// sizeof(matrix[0]) would be columns * sizeof(double)
// sizeof(((*myPointerTo2DimArray)[0])) would also be columns * sizeof(double)

However, if the dimensions of the inner arrays are variable (dynamic allocation), the T** (pointer to an array of pointers) structure becomes necessary, as seen in handling dynamically constructed 2D structures or arrays of dynamically sized buffers.

Alternative Perspectives

  1. Handle Concept: A pointer to a pointer is frequently referred to as a “handle.” This is useful when the underlying object (the one the single pointer points to) might be moved in memory (e.g., during garbage collection or memory relocation), requiring the handle to be updated to reflect the new location.
  2. Dynamic Array Construction: Functions often use T** parameters to construct and return arrays whose size is determined at runtime, allowing the caller to receive the starting address of the newly allocated block (see Solution 12 in the source material).

FAQs on C Demystifying Pointer to Pointer Usage

Q: What is the fundamental difference between T* and T**

ANS: T* holds the memory address of a variable of type T. T** holds the memory address of a variable of type T*, meaning it points to another pointer.

Q: When must I use T** instead of T*

ANS: You must use T** when you need a function to modify the address held by a pointer variable declared in the calling function’s scope, such as when dynamically allocating memory and assigning the resulting address back to the caller’s pointer.

Q: Is using *pp = entry->next atomic in linked list removal

ANS: No, the expression *pp = entry->next is composed of multiple C operations (dereferencing and assignment) and is not guaranteed to be atomic in standard C.

Q: How does argv relate to pointers to pointers

ANS: The argv parameter in the main function is defined as char **argv, representing an array of pointers to character strings, where each string is a command-line argument.
