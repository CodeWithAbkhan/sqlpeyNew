“Implementing Power Functions: Integer, Floating Point, and Fixed-Point Arithmetic”

How can we implement the exponentiation operation ($x^y$) effectively when dealing with different numeric representations, specifically 32-bit integers (signed and unsigned), and custom fixed-point formats? Different mathematical contexts necessitate distinct algorithmic approaches for accurate and performant computation.

Integer Exponentiation ($a^b$ where $a \ge 0, b \ge 0$)

For non-negative integer bases and exponents, the exponentiation operation is typically calculated using the exponentiation by squaring method. This approach significantly reduces the number of required multiplications compared to naive iteration.

For unsigned 32-bit integers (DWORD), the implementation relies on examining the bits of the exponent ($b$):

DWORD pow_unsigned_unsigned(DWORD a, DWORD b)
{
    int i, bits = 32;
    DWORD d = 1;
    for (i = 0; i < bits; i++)
    {
        d *= d; // Square the running result (d = d^2)
        if (DWORD(b & 0x80000000)) // Check the most significant bit (MSB)
            d *= a; // If the bit is set, multiply by the base 'a'
        b <<= 1; // Shift exponent left to check the next bit
    }
    return d;
}

Signed Integer Exponentiation ($a^b$ where $b \ge 0$)

When the base $a$ can be negative, but the exponent $b$ remains non-negative, we handle the sign based on the parity of $b$. A negative result occurs only if the base is negative AND the exponent is odd.

int pow_signed_unsigned(int a, DWORD b)
{
    int sign_flag = 0;
    if ((a < 0) && (DWORD(b & 1))) // Check if a < 0 and b is odd
    {
        sign_flag = 1;
        a = -a; // Work with the positive base
    }
    
    int result = pow_unsigned_unsigned(a, b); // Use the unsigned power routine
    
    if (sign_flag)
        result = -result;
        
    return result;
}

Handling Negative Integer Exponents ($a^b$ where $b < 0$)

If the exponent $b$ is negative, $a^b$ equals $1 / a^{-b}$. Since the result will almost certainly not be an integer, this scenario requires either returning a floating-point value or employing a scaling factor if pure integer arithmetic is mandatory (e.g., for preserving precision in financial calculations).

float pow_float_from_integer_exp(int a, int b)
{
    if (b < 0)
    {
        // Calculate 1.0 / a^(-b), casting the result to float
        return 1.0f / static_cast<float>(pow_signed_unsigned(a, -b));
    }
    else
    {
        // For non-negative exponents, return the integer result cast to float
        return static_cast<float>(pow_signed_unsigned(a, b));
    }
}

Floating-Point Exponentiation

For general floating-point powers, $\text{pow}(x, y) = x^y$, the computation often leverages logarithmic and exponential functions, frequently employing the identity: $x^y = \exp(y \cdot \ln(x))$. For fractional exponents, the relationship relies on base-2 components: $x^y = 2^{y \cdot \log_2(x)}$.

Integer Exponentiation with Fractional Exponents ($a^{1/bb}$)

Calculating powers with fractional exponents, such as $a^{1/bb}$ (which is the $bb$-th root of $a$), necessitates iterative root-finding techniques, such as binary search, analogous to how square roots are found.

To find $c = a^{1/bb}$, we search for $c$ such that $c^{bb} \le a$.

First, a helper function to determine the magnitude of an unsigned integer:

int count_bits(DWORD p) // Counts the number of significant bits in p
{
    DWORD mask = 0x80000000; 
    int b = 32;
    for (; mask; mask >>= 1, b--)
        if (p >= mask)
            break;
    return b;
}

DWORD sqrt_unsigned(const DWORD &x)
{
    DWORD m, a = 0;
    // Determine the starting MSB mask for the result (roughly half the bits of x)
    int start_bit_pos = (count_bits(x) >> 1);
    if (start_bit_pos > 0)
        m = 1 << start_bit_pos;
    else
        m = 1;
        
    for (; m; m >>= 1)
    {
        a |= m; // Tentatively set the bit
        // Check if a*a exceeds x. Overflow can be a concern here if x is large.
        if ((a * a) > x) 
            a ^= m; // If too large, clear the bit
    }
    return a;
}

To generalize this to an arbitrary integer root ($bb$-root), the check if (a*a > x) becomes if (pow_unsigned_unsigned(a, bb) > x), and the initialization of the search mask $m$ must be adjusted based on the required root degree $bb$.

Implementing Power in Fixed-Point Arithmetic (32-bit Signed)

Fixed-point arithmetic simulates floating-point behavior using integers, preserving precision by dedicating a fixed number of bits to the fractional part. Here, we define a 32-bit format with 16 fractional bits (_fx32_fract_bits = 16).

Key constants for the 32-bit signed fixed-point format:

const int _fx32_bits = 32;
const int _fx32_fract_bits = 16;
const int _fx32_one = 1 << _fx32_fract_bits; // 2^16, represents 1.0
const float _fx32_onef = static_cast<float>(_fx32_one);

// Conversion utilities
float fx32_get(int x) { return static_cast<float>(x) / _fx32_onef; }
int fx32_set(float x) { return static_cast<int>(x * _fx32_onef); }

Fixed-Point Multiplication (fx32_mul)

Multiplication involves standard integer multiplication, followed by a right shift to re-establish the fixed-point scaling (dividing by $2^{16}$). Assembly is often used here to ensure 64-bit intermediate results to prevent overflow during the initial product.

int fx32_mul(const int &x, const int &y) // x*y
{
    int a = x, b = y;
    asm
    {
        mov eax, a
        mov ebx, b
        mul eax, ebx             // (edx,eax) = a * b (64-bit result)
        mov ebx, _fx32_one       // ebx = 2^16
        div ebx                  // eax = (a*b) >> 16
        mov a, eax;
    }
    return a;
}

Fixed-Point Division (fx32_div)

Division requires shifting the numerator left by the fractional bits before division to maintain precision: $(x \cdot 2^{16}) / y$.

int fx32_div(const int &x, const int &y) // x/y
{
    int a = x, b = y;
    asm
    {
        mov eax, a
        mov ebx, _fx32_one       // ebx = 2^16
        mul eax, ebx             // (edx,eax) = a << 16
        mov ebx, b
        div ebx                  // eax = (a << 16) / b
        mov a, eax;
    }
    return a;
}

Fixed-Point Absolute Square Root (fx32_abs_sqrt)

Similar to the unsigned integer approach, adapted for the fixed-point format using fx32_mul for comparison.

Fixed-Point Power (fx32_pow(x, y))

This function implements $x^y$ where both $x$ and $y$ are in the fixed-point format, requiring careful sign handling and combining exponentiation by squaring (for the integer part of $y$) and iterative rooting (for the fractional part of $y$).

int fx32_pow(int x, int y)
{
    // ... Special case handling (y=0, x=0, y=-1, y=1) ...
    
    // Sign separation
    int sx = (x < 0) ? 1 : 0;
    if (sx) x = -x;

    int sy = (y < 0) ? 1 : 0;
    if (sy) y = -y;

    int y_frac = y & _fx32_fract_mask; // Fractional part of exponent
    int y_integ = y & _fx32_integ_mask; // Integer part of exponent
    
    int result_a = _fx32_one; // Initialize result to 1.0
    
    // 1. Exponentiation by Squaring (Integer part of y)
    if (y_integ)
    {
        // Find mask for the highest significant bit of y_integ
        int m = _fx32_uMSB_mask; 
        for (; (m > _fx32_one) && (m > y_integ); m >>= 1);
        
        for (; m >= _fx32_one; m >>= 1)
        {
            result_a = fx32_mul(result_a, result_a);
            if (int(y_integ & m))
                result_a = fx32_mul(result_a, x);
        }
    }

    // 2. Rooting (Fractional part of y)
    if (y_frac)
    {
        int b = x;
        // Iteratively calculate roots: x^(1/2^N) where N is the bit position
        for (int m = _fx32_one >> 1; m; m >>= 1)
        {
            b = fx32_abs_sqrt(b); // b = b^(1/2)
            if (int(y_frac & m))
                result_a = fx32_mul(result_a, b); // Multiply if the corresponding fractional bit is set
        }
    }

    // 3. Final Sign Adjustments
    if (sy) // If original exponent y was negative (result = 1 / result_a)
    {
        if (result_a)
            result_a = fx32_div(_fx32_one, result_a);
        else
            result_a = 0; // Underflow error handling
    }
    
    if (sx) // If original base x was negative
    {
        if (y_frac)
            result_a = 0; // Negative base raised to non-integer power is undefined/error in real domain
        else if (int(y_integ & _fx32_one)) // Check if the integer part of the exponent was odd
            result_a = -result_a;
    }
    
    return result_a;
}

A common test setup involves comparing the fixed-point result (c1) against the standard library pow result (c0):

float a, b, c0, c1, diff;
int x, y;

for (a = 0.0f, x = fx32_set(a); a <= 10.0f; a += 0.1f, x = fx32_set(a))
    for (b = -2.5f, y = fx32_set(b); b <= 2.5f; b += 0.1f, y = fx32_set(b))
    {
        if (!x || !y) continue; // Avoid points where standard pow has issues or input is exactly zero
        
        c0 = powf(a, b);
        c1 = fx32_get(fx32_pow(x, y));
        
        // Calculate difference metric
        if (fabs(c1) < 1e-3)
            diff = c1 - c0;
        else
            diff = (c0 / c1) - 1.0f;
            
        if (fabs(diff) > 0.1f)
            // Breakpoint here to investigate significant inconsistencies
            diff = diff; 
    }

Note that fixed-point precision limits accuracy; deviations are expected compared to native float or double computations.

FAQs on Implementing Power Functions

Q: How does fixed point multiplication avoid overflow with 32-bit integers

ANS: Fixed-point multiplication $x \cdot y$ involves multiplying two 32-bit numbers, resulting in a 64-bit intermediate value before the necessary right shift (division by $2^{16}$) is applied to restore the 32-bit fixed-point result. This requires accessing the upper 32 bits of the product, often done via architecture-specific assembly instructions like MUL on x86 which places the high part in EDX.

Q: What is the significance of the _fx32_one constant in fixed point math

ANS: The _fx32_one constant, typically $2^{16}$ (or $1 \ll 16$), represents the value $1.0$ in the fixed-point integer domain. It is crucial for scaling conversions between floating-point values and their fixed-point integer representations, and for re-scaling intermediate results in multiplication and division operations.

Q: Why is binary search suitable for calculating integer roots like x^(1/bb)

ANS: Binary search is effective because the function $f(c) = c^{bb}$ is monotonically increasing for non-negative $c$. This allows us to efficiently narrow down the search space for the root $c$ by repeatedly checking if the test value $c$ raised to the power $bb$ is less than or greater than the radicand $a$.
