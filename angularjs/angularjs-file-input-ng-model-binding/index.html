“AngularJS File Input ng-model Binding Solutions”

The standard ng-model directive in AngularJS does not inherently support input type="file" elements for binding file data directly. This limitation prevents features like ng-change, ng-required, and ng-form from working seamlessly with file inputs. However, several custom directive solutions can bridge this gap, enabling robust file handling within your AngularJS applications. These methods focus on capturing file information and making it accessible within your scope, often by reading file contents as data URLs or by providing access to the FileList object.

Here are various approaches to achieve ng-model binding for file inputs:

Solution 1: Simple File DataURL Capture

This approach utilizes a directive to read the selected file as a data URL and assign it to a scope variable.

.directive("fileread", [function () {
    return {
        scope: {
            fileread: "="
        },
        link: function (scope, element, attributes) {
            element.bind("change", function (changeEvent) {
                var reader = new FileReader();
                reader.onload = function (loadEvent) {
                    scope.$apply(function () {
                        scope.fileread = loadEvent.target.result;
                    });
                }
                reader.readAsDataURL(changeEvent.target.files[0]);
            });
        }
    }
}]);

Usage:

<input type="file" fileread="vm.uploadme" />

This assigns the data URL of the selected file to vm.uploadme.

Solution 2: Advanced File Handling with Promises

For more complex scenarios, including handling multiple files and using promises for asynchronous operations, consider this directive. It leverages $q to manage file reading operations.

angular.module('appFilereader', []).directive('appFilereader', function($q) {
    var slice = Array.prototype.slice;

    return {
        restrict: 'A',
        require: '?ngModel',
        link: function(scope, element, attrs, ngModel) {
                if (!ngModel) return;

                ngModel.$render = function() {};

                element.bind('change', function(e) {
                    var element = e.target;

                    $q.all(slice.call(element.files, 0).map(readFile))
                        .then(function(values) {
                            if (element.multiple) ngModel.$setViewValue(values);
                            else ngModel.$setViewValue(values.length ? values[0] : null);
                        });

                    function readFile(file) {
                        var deferred = $q.defer();

                        var reader = new FileReader();
                        reader.onload = function(e) {
                            deferred.resolve(e.target.result);
                        };
                        reader.onerror = function(e) {
                            deferred.reject(e);
                        };
                        reader.readAsDataURL(file);

                        return deferred.promise;
                    }

                });
            }
    };
});

Usage:

<input type="file" ng-model="editItem._attachments_uri.image" accept="image/*" app-filereader />

This directive populates the specified ngModel with the file’s data URI. For a live demonstration, refer to http://plnkr.co/CMiHKv2BEidM9SShm9Vv .

Solution 3: Direct File List Binding

This directive directly binds the selected files to ngModel, enabling the use of ng-change and other model-related directives.

angular.module("app",[]);

angular.module("app").directive("selectNgFiles", function() {
  return {
    require: "ngModel",
    link: function postLink(scope,elem,attrs,ngModel) {
      elem.on("change", function(e) {
        var files = elem[0].files;
        ngModel.$setViewValue(files);
      })
    }
  }
});

Usage:

<body ng-app="app">
  <h1>AngularJS Input `type=file` Demo</h1>
  <input type="file" select-ng-files ng-model="fileArray" multiple>

  <code>
    <table ng-show="fileArray.length">
      <tr>
        <td>Name</td><td>Date</td><td>Size</td><td>Type</td>
      </tr>
      <tr ng-repeat="file in fileArray">
        <td>{{file.name}}</td>
        <td>{{file.lastModified | date : 'MMMdd,yyyy'}}</td>
        <td>{{file.size}}</td>
        <td>{{file.type}}</td>
      </tr>
    </table>
  </code>
</body>

This allows you to work with the FileList object directly in your scope, supporting multiple file selections.

Solution 4: Handling Scope Issues with Objects

When using directives that modify scope values, particularly primitives, child scope issues can arise. Using an object to hold the file data can resolve this.

Controller Modification:

$scope.uploadme = {};
$scope.uploadme.src = "";

HTML:

<input type="file" fileread="uploadme.src"/>
<input type="text" ng-model="uploadme.src"/>

This ensures that changes made within the directive’s scope are correctly reflected in the parent scope.

Solution 6: Custom Upload Element Directive

This directive creates a custom element for file uploads, allowing you to specify the scope attribute for the file data.

.directive('myUpload', function() {
    return {
        link: function postLink(scope, element, attrs) {
            element.find("input").bind("change", function(changeEvent) {
                var reader = new FileReader();
                reader.onload = function(loadEvent) {
                    scope.$apply(function() {
                        scope[attrs.key] = loadEvent.target.result;
                    });
                }
                if (typeof(changeEvent.target.files[0]) === 'object') {
                    reader.readAsDataURL(changeEvent.target.files[0]);
                };
            });

        },
        controller: 'FileUploadCtrl',
        template:
                '<span class="btn btn-success fileinput-button">' +
                '<i class="glyphicon glyphicon-plus"></i>' +
                '<span>Replace Image</span>' +
                '<input type="file" accept="image/*" name="files[]" multiple="">' +
                '</span>',
        restrict: 'E'

    };
});

Usage:

<myUpload key="file"></myUpload>

This custom element provides a cleaner way to integrate file inputs with scope variables.

Solution 7: Multiple File Reading with Underscore/Lodash

If you’re using libraries like Lodash or Underscore, this directive efficiently handles multiple file selections, pushing each file’s data URL into an array.

.directive("fileread", [function () {
    return {
        scope: {
            fileread: "="
        },
        link: function (scope, element, attributes) {
            element.bind("change", function (changeEvent) {
                return _.map(changeEvent.target.files, function(file){
                  scope.fileread = [];
                  var reader = new FileReader();
                  reader.onload = function (loadEvent) {
                      scope.$apply(function () {
                          scope.fileread.push(loadEvent.target.result);
                      });
                  }
                  reader.readAsDataURL(file);
                });
            });
        }
    }
}]);

This approach is particularly useful when you need to process multiple files simultaneously.

Solution 8: Simple File Assignment Directive

This directive provides a straightforward way to assign the first selected file to a scope variable using $parse.

function filesModelDirective(){
  return {
    controller: function($parse, $element, $attrs, $scope){
      var exp = $parse($attrs.filesModel);
      $element.on('change', function(){
        exp.assign($scope, this.files[0]);
        $scope.$apply();
      });
    }
  };
}
app.directive('filesModel', filesModelDirective);

Usage:

<input type="file" files-model="myFile" />

This assigns the selected file object to $scope.myFile.

Solution 9: Multiple File Data Array Handling

This directive, an extension of Solution 3, ensures all files are read and their data URLs are collected into an array. It synchronizes the scope update only after all files have been processed.

.directive("fileread", function () {
    return {
      scope: {
        fileread: "="
      },
      link: function (scope, element, attributes) {
        element.bind("change", function (changeEvent) {
          var readers = [] ,
              files = changeEvent.target.files ,
              datas = [] ;
          for ( var i = 0 ; i < files.length ; i++ ) {
            readers[ i ] = new FileReader();
            readers[ i ].onload = function (loadEvent) {
              datas.push( loadEvent.target.result );
              if ( datas.length === files.length ){
                scope.$apply(function () {
                  scope.fileread = datas;
                });
              }
            }
            readers[ i ].readAsDataURL( files[i] );
          }
        });

      }
    }
  });

This is beneficial for applications requiring processing of multiple uploaded files.

Solution 10: Enhanced Multiple File Object Details

This enhanced version of Solution 9 provides not only the data URL but also metadata for each file, including lastModified, lastModifiedDate, name, size, and type. It also includes a fix for deselection issues.

 .directive("fileread", function () {
        return {
            scope: {
                fileread: "="
            },
            link: function (scope, element, attributes) {
                element.bind("change", function (changeEvent) {
                    var readers = [] ,
                        files = changeEvent.target.files ,
                        datas = [] ;
                    if(!files.length){
                        scope.$apply(function () {
                            scope.fileread = [];
                        });
                        return;
                    }
                    for ( var i = 0 ; i < files.length ; i++ ) {
                        readers[ i ] = new FileReader();
                        readers[ i ].index = i;
                        readers[ i ].onload = function (loadEvent) {
                            var index = loadEvent.target.index;
                            datas.push({
                                lastModified: files[index].lastModified,
                                lastModifiedDate: files[index].lastModifiedDate,
                                name: files[index].name,
                                size: files[index].size,
                                type: files[index].type,
                                data: loadEvent.target.result
                            });
                            if ( datas.length === files.length ){
                                scope.$apply(function () {
                                    scope.fileread = datas;
                                });
                            }
                        };
                        readers[ i ].readAsDataURL( files[i] );
                    }
                });

            }
        }
    });

This provides a rich dataset for each file.

Solution 11: Decorator for Input Directive

For a more integrated approach within AngularJS core, you can decorate the inputDirective to add type=file support. This method requires AngularJS 1.4.x or later and relies on the File API, meaning it won’t work in IE9.

(function() {
    'use strict';

    angular
        .module('yourModuleNameHere')
        .decorator('inputDirective', myInputFileDecorator);

    myInputFileDecorator.$inject = ['$delegate', '$browser', '$sniffer', '$filter', '$parse'];
    function myInputFileDecorator($delegate, $browser, $sniffer, $filter, $parse) {
        var inputDirective = $delegate[0],
            preLink = inputDirective.link.pre;

        inputDirective.link.pre = function (scope, element, attr, ctrl) {
            if (ctrl[0]) {
                if (angular.lowercase(attr.type) === 'file') {
                    fileInputType(
                        scope, element, attr, ctrl[0], $sniffer, $browser, $filter, $parse);
                } else {
                    preLink.apply(this, arguments);
                }
            }
        };

        return $delegate;
    }

    function fileInputType(scope, element, attr, ctrl, $sniffer, $browser, $filter, $parse) {
        element.on('change', function (ev) {
            if (angular.isDefined(element[0].files)) {
                ctrl.$setViewValue(element[0].files, ev && ev.type);
            }
        })

        ctrl.$isEmpty = function (value) {
            return !value || value.length === 0;
        };
    }
})();

This approach integrates file handling directly into AngularJS’s input directives but has limitations regarding older browser support.

These solutions offer various ways to manage file inputs in AngularJS, catering to different needs regarding data representation and browser compatibility.

FAQs on AngularJS File Input ng-model Binding Solutions

Q: Can ngModel directly bind to input type file

ANS: No, the standard ngModel directive does not directly bind to input type file elements to capture file content. Custom directives are required to achieve this functionality.

Q: What does a custom directive typically do for file inputs

ANS: Custom directives usually intercept the ‘change’ event of the file input, read the selected file(s) using the FileReader API, and then assign the file data (often as a data URL or FileList object) to a scope variable bound via ngModel.

Q: How does Solution 3 bind files to ngModel

ANS: Solution 3’s selectNgFiles directive directly calls ngModel.$setViewValue(files) when the file input’s value changes, effectively binding the FileList object to the ngModel.

Q: What is the purpose of Solution 4's object approach

ANS: Solution 4 addresses potential scope inheritance issues in AngularJS. By storing the file data in an object property (e.g., $scope.uploadme.src) rather than a primitive, it ensures that changes made by a child scope directive are correctly propagated to the parent scope.

Q: Which solution is best for handling multiple files

ANS: Solutions 3, 7, 9, and 10 are designed to handle multiple file selections, typically by collecting the files into an array. Solution 10 offers the most detailed information per file.

Q: Does Solution 11 work in older browsers like IE9

ANS: No, Solution 11, which uses a decorator, relies on the File API and therefore does not support older browsers like Internet Explorer 9 that lack this API.

Q: Can I get file metadata like name and size

ANS: Yes, Solution 10 specifically captures and provides file metadata such as name, size, type, and modification details along with the file data.
