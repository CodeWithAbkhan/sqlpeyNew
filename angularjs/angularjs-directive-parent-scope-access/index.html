“AngularJS Directive Scope: Accessing Parent Scope Methods and Properties”

Accessing parent scope data from an AngularJS directive hinges on how the directive manages its own scope. The primary factors are the scope and transclude options within the directive’s definition. Understanding these settings is key to effectively bridging the communication gap between directives and their parent scopes.

The core principle revolves around scope inheritance. When a directive doesn’t create its own scope, it shares the parent’s scope directly. When it creates a new scope, the inheritance model dictates how it can access parent properties and functions.

Directive Scope Configurations and Parent Scope Interaction

Let’s break down how different scope configurations influence parent scope access:

  1. scope: false (Default):

    • Behavior: The directive does not create a new scope. It directly uses the parent’s scope. There is no scope inheritance in this scenario; they are the same scope.
    • Access: You can directly access parent scope properties and methods within the directive’s link function using the scope parameter.
    app.directive('mySharedScopeDirective', function() {
  return {
    restrict: 'E',
    link: function(scope, element, attrs) {
      // Accessing parent scope property directly
      console.log("Parent scope data:", scope.parentData);

      // Calling a parent scope function
      scope.parentFunction('called from directive');
    }
  };
});

  2. scope: true:

    • Behavior: The directive creates a new child scope that prototypically inherits from the parent scope. Properties defined on the parent scope are accessible to this child scope.
    • Caution: Be mindful when assigning to primitive properties in the directive’s scope. This will create a new property on the directive’s scope, hiding the parent’s property of the same name rather than modifying the parent’s value.
    • Access: Similar to scope: false, you can access parent scope properties and functions through the scope object in the link function due to prototypal inheritance.
    app.directive('myChildScopeDirective', function() {
  return {
    restrict: 'E',
    scope: true, // Creates a new child scope
    link: function(scope, element, attrs) {
      // Accessing parent scope property
      console.log("Parent scope data (inherited):", scope.parentData);

      // Modifying a primitive property - creates a new property on directive's scope
      scope.primitiveProperty = 'directive value'; // This hides parent's primitiveProperty
    }
  };
});

  3. scope: { ... } (Isolate Scope):

    • Behavior: The directive creates a new isolated scope. This scope does not prototypically inherit from the parent scope.
    • Access: To interact with the parent scope, you must explicitly define how data or functions are passed in via attributes using =, @, or &.
      • = (Two-way binding): For sharing mutable data.
      • @ (One-way binding): For passing string values.
      • & (Expression binding): For executing functions defined in the parent scope.
    • Accessing $parent: While possible, directly using $parent from an isolate scope is generally discouraged as it breaks the encapsulation intended by isolated scopes.
    app.directive('myIsolateScopeDirective', function() {
  return {
    restrict: 'E',
    scope: {
      // Pass parentData from parent scope to directive's isolate scope
      parentData: '=sharedData',
      // Execute parentFunction defined in parent scope
      onAction: '&triggerAction'
    },
    link: function(scope, element, attrs) {
      // Accessing data passed via isolate scope binding
      console.log("Isolated scope data:", scope.parentData);

      // Triggering parent scope function
      scope.onAction({ someValue: 'data from isolated scope' });
    }
  };
});

    HTML Usage:

    <div ng-controller="ParentController">
  <my-isolate-scope-directive shared-data="controllerData" trigger-action="handleAction(someValue)"></my-isolate-scope-directive>
</div>

  4. transclude: true:

    • Behavior: When transclude is true, the directive gets a transcluded scope. This transcluded scope prototypically inherits from the parent scope.
    • Interaction with Isolate Scope: If the directive also defines an isolate scope, the transcluded scope becomes a child of the isolate scope (in AngularJS v1.3+). Before v1.3, they were siblings. The $parent property of the transcluded scope will reference either the isolate scope or the original parent scope depending on the AngularJS version.

Watching Parent Scope Properties

To react to changes in parent scope properties, you can use $watch or $watchCollection:

  • For scope: false or scope: true: You can watch attributes directly, or use $parse for more complex expressions.

    // Watching a direct property 'prop1'
scope.$watch(attrs.attr1, function(newValue, oldValue) {
  console.log("Attr1 changed:", newValue);
});

// Watching an object property 'obj.prop2' using $parse
var modelParser = $parse(attrs.attr2);
scope.$watch(modelParser, function(newValue, oldValue) {
  console.log("Attr2 changed:", newValue);
});

  • For Isolate Scopes: Watch the property name defined in the isolated scope.

    scope: {
  localName3: '@attr3', // @ for string
  dataFromParent: '=attr4' // = for two-way binding
},
link: function(scope, element, attrs) {
  scope.$watch('localName3', function(newValue) {
    console.log("Attr3 (localName3) changed:", newValue);
  });
  scope.$watch('dataFromParent', function(newValue) {
    console.log("Attr4 (dataFromParent) changed:", newValue);
  });
}

Accessing Controller Methods

Accessing parent scope methods is similar to accessing properties, especially when using scope: true or scope: false. For isolated scopes, the & binding is the standard approach.

Option 1: Through Object Literal and Directive HTML (using &)

This method involves defining a callback function in the parent scope and passing it to the directive using the & binding. The directive then invokes this callback when needed.

  • HTML: 
    <div ng-controller="MainCtrl">
  <sd-items-filter
    selected-items="selectedItems"
    selected-items-changed="selectedItemsChanged(selectedItems)"
    items="items">
  </sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItemsReturnedFromDirective}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      items: '=',
      selectedItems: '=',
      selectedItemsChanged: '&' // Using & to bind a function
    },
    templateUrl: "itemfilterTemplate.html"
  };
});
  • Template (itemfilterTemplate.html): 
    <select
  ng-model="selectedItems"
  multiple="multiple"
  style="height: 200px; width: 250px;"
  ng-change="selectedItemsChanged({selectedItems:selectedItems})"
  ng-options="item.id as item.name group by item.model for item in items | orderBy:'name'">
  <option>--</option>
</select>
  • Controller (app.js): 
    app.controller('MainCtrl', function($scope) {
  $scope.selectedItems = ["allItems"];
  $scope.selectedItemsChanged = function(selectedItems1) {
    $scope.selectedItemsReturnedFromDirective = selectedItems1;
  };
  // ... items data
});

Option 2: Through Function Reference and Directive Link/Scope (using &)

This variation ensures the parent function is called correctly, even if defined within the directive’s link function, using the & binding.

  • HTML: 
    <div ng-controller="MainCtrl">
  <sd-items-filter
    selected-items="selectedItems"
    selected-items-changed="selectedItemsChanged(selectedItems)"
    items="items">
  </sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItemsReturnedFromDirective}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      items: '=',
      selectedItems: '=',
      selectedItemsChanged: '&'
    },
    templateUrl: "itemfilterTemplate.html",
    link: function (scope, element, attrs){
      // Define a local function in the directive's scope
      scope.selectedItemsChangedDir = function(){
        // Call the parent function via the bound expression
        scope.selectedItemsChanged({selectedItems:scope.selectedItems});
      }
    }
  };
});
  • Template (itemfilterTemplate.html): 
    <select
  ng-model="selectedItems"
  multiple="multiple"
  style="height: 200px; width: 250px;"
  ng-change="selectedItemsChangedDir()" // Call the directive's local function
  ng-options="item.id as item.name group by item.model for item in items | orderBy:'name'">
  <option>--</option>
</select>
  • Controller (app.js): (Same as Option 1)

Option 3: Through Function Reference and Directive HTML (using &)

Here, the callback defined in the parent is directly invoked from the directive’s template.

  • HTML: 
    <div ng-controller="MainCtrl">
  <sd-items-filter
    selected-items="selectedItems"
    selected-items-changed="selectedItemsChanged"
    items="items">
  </sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItemsReturnFromDirective}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      items: '=',
      selectedItems:'=',
      selectedItemsChanged: '&' // Bind the function
    },
    templateUrl: "itemfilterTemplate.html"
  };
});
  • Template (itemfilterTemplate.html): 
    <select
  ng-model="selectedItems"
  multiple="multiple"
  style="height: 200px; width: 250px;"
  ng-change="selectedItemsChanged()(selectedItems)" // Execute the bound function
  ng-options="item.id as item.name group by item.model for item in items | orderBy:'name'">
  <option>--</option>
</select>
  • Controller (app.js): 
    app.controller('MainCtrl', function($scope) {
  $scope.selectedItems = ["allItems"];
  $scope.selectedItemsChanged = function(selectedItems1) {
    $scope.selectedItemsReturnFromDirective = selectedItems1;
  };
  // ... items data
});

Option 4: Through Function Reference and Directive Link/Scope (using &)

Similar to Option 2, but the function call is managed within the directive’s link function.

  • HTML: 
    <div ng-controller="MainCtrl">
  <sd-items-filter
    selected-items="selectedItems"
    selected-items-changed="selectedItemsChanged"
    items="items">
  </sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItemsReturnedFromDirective}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      items: '=',
      selectedItems: '=',
      selectedItemsChanged: '&'
    },
    templateUrl: "itemfilterTemplate.html",
    link: function (scope, element, attrs){
      scope.selectedItemsChangedDir = function(){
        // Execute the bound function reference

  • Template (itemfilterTemplate.html): 
    <select

  <option>--</option>
</select>
  • Controller (app.js): (Same as Option 3)

Option 5: Through ng-model and Two-Way Binding

In scenarios where you only need to update parent scope variables, using ng-model on the directive and two-way binding within the directive’s isolate scope is a clean approach. This bypasses the need to explicitly call parent functions for simple data synchronization.

  • HTML: 
    <div ng-controller="MainCtrl">
  <sd-items-filter ng-model="selectedItems" items="items"></sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItems}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      items: '=',
      selectedItems: '=ngModel' // Binds to ng-model
    },
    templateUrl: "itemfilterTemplate.html"
  };
});
  • Template (itemfilterTemplate.html):

Option 6: Through $watch and $watchCollection for Parent Scope Properties

This option is for observing changes in parent scope properties or objects from within a directive, especially when not directly tied to ng-model or & bindings for reactive updates.

  • HTML: 
    <div ng-controller="MainCtrl">
  <table style="margin-left:50px">
    <tr>
      <td>Id:</td>
      <td><input type="text" ng-model="id" /></td>
    </tr>
    <tr>
      <td>Name:</td>
      <td><input type="text" ng-model="name" /></td>
    </tr>
    <tr>
      <td>Model:</td>
      <td><input type="text" ng-model="model" /></td>
    </tr>
  </table>
  <button type="button" ng-click="addItem()">Add Item</button>
  <p>Directive Contents</p>
  <sd-items-filter
    ng-model="selectedItems"
    current-item="currentItem"
    name="{{name}}"
    selected-items-changed="selectedItemsChanged"
    items="items">
  </sd-items-filter>
  <p style="color:red">Selected Items (in parent controller) set to: {{selectedItems}}</p>
</div>
  • Directive (app.js): 
    app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      name: '@', // Attribute binding for string
      currentItem: '=', // Two-way binding for object
      items: '=',
      selectedItems: '=ngModel'
    },
    template: '<select multiple="multiple" style="height: 140px; width: 250px;"' +
      'ng-options="item.id as item.name group by item.model for item in items | orderBy:\'name\'" ng-model="selectedItems">' +
      '<option>--</option> </select>',
    link: function(scope, element, attrs) {
      // Watch for changes in the 'currentItem' object
      scope.$watchCollection('currentItem', function(newItem) {
        console.log("Current item changed:", JSON.stringify(newItem));
      });
      // Watch for changes in the 'name' attribute
      scope.$watch('name', function(newName) {
        console.log("Name attribute changed:", JSON.stringify(newName));
      });
    }
  };
});
  • Controller (app.js): 
    app.controller('MainCtrl', function($scope) {
  $scope.user = 'World';
  $scope.id = 'newId';
  $scope.name = 'New Item';
  $scope.model = 'DefaultModel';

  $scope.addItem = function() {
    $scope.items.push({
      id: $scope.id,
      name: $scope.name,
      model: $scope.model
    });
    // Update currentItem to trigger the watchCollection
    $scope.currentItem = {
      id: $scope.id,
      name: $scope.name,
      model: $scope.model
    };
  };

  $scope.selectedItems = ["allItems"];
  $scope.currentItem = {}; // Initialize currentItem

  $scope.items = [
    { "id": "allItems", "name": "All Items", "order": 0 },
    { "id": "CaseItem", "name": "Case Item", "model": "PredefinedModel" },
    { "id": "Application", "name": "Application", "model": "Bank" }
  ];
});

A Trick for Accessing Parent Scope Properties (Hack)

For instances where other methods prove complex, a more direct, albeit less conventional, approach involves assigning a parent scope attribute to the directive’s scope within the template itself.

{{ currentDirective.attr = parentDirective.attr; '' }}

The '' at the end suppresses any output in the template, as Angular evaluates all expressions. Use this method judiciously, as it bypasses the cleaner, intended mechanisms for scope interaction.

Accessing Parent Scope from Directive Controller

If you are using controllerAs syntax with ES6 classes, accessing the parent scope might require a slight adjustment. The vm alias, commonly used for the controller instance, can be accessed via the scope object.

myApp.directive('name', function() {
  return {
    // No scope definition needed if inheriting
    link : function(scope, element, attrs, ngModel) {
        // Accessing parent controller's method via vm alias
        scope.vm.someParentFunction();
    }
  };
});

Alternative: Dummy Directive for Scope Access

A less common but functional method involves a “container” directive that exposes its scope, which a nested directive can then require.

// Directive to hold and expose the scope
module.directive('myDirectiveContainer', function () {
    return {
        controller: function ($scope) {
            this.parentScope = $scope; // Expose the scope
        }
    };
});

// Directive that requires the container's controller
module.directive('myDirective', function () {
    return {
        require: '^myDirectiveContainer', // Require the parent directive's controller
        link: function (scope, element, attrs, containerController) {
            // Access parent scope through the controller
            console.log("Accessing parent scope via dummy directive:", containerController.parentScope);
        }
    };
});

HTML Structure:

<div my-directive-container>
    <div my-directive></div>
</div>

FAQs on AngularJS Directive Scope

Q: What is the difference between scope: true and scope: false in AngularJS directives

ANS: When scope: false, the directive shares the parent scope directly. With scope: true, the directive creates a new child scope that inherits prototypically from the parent, allowing access to parent properties.

Q: How does an AngularJS directive with isolate scope access parent scope data

ANS: Directives with isolate scopes do not inherit prototypically. Access is managed through attribute bindings: = for two-way data binding, @ for string values, and & for passing and executing parent scope functions.

Q: Can I call a parent controller's method from an AngularJS directive with an isolate scope

ANS: Yes, you can use the & binding in the directive’s isolate scope definition to pass a function reference from the parent scope. The directive can then invoke this function.

Q: What is the purpose of $parent in AngularJS scopes

ANS: $parent is a reference to the immediate parent scope. While it can be used to access parent scope properties or methods, relying on it heavily, especially with isolate scopes, is discouraged as it weakens encapsulation.

Q: When should I use scope: false vs scope: true

ANS: Use scope: false when the directive simply enhances an existing element and needs direct access to the parent’s context without creating its own scope. Use scope: true when you need a distinct scope for the directive but still want it to inherit data and behavior from its parent. For encapsulation and reusability, isolate scopes (scope: { ... }) are generally preferred.
&lt;div my-dir attr1=&quot;prop1&quot;&gt;&lt;/div&gt;

app.directive('sdItemsFilter', function() {
  return {
    restrict: 'E',
    scope: {
      name: '@',
      currentItem: '=',
      items: '=',
      selectedItems: '=ngModel'
    },
    template: '&lt;select ng-model="selectedItems" multiple="multiple" style="height: 140px; width: 250px;"' +
      'ng-options="item.id as item.name group by item.model for item in items | orderBy:\'name\'"&gt;' +
      '&lt;option&gt;--&lt;/option&gt; &lt;/select&gt;',
    link: function(scope, element, attrs) {
      scope.$watchCollection('currentItem', function() {
        console.log(JSON.stringify(scope.currentItem));
      });
      scope.$watch('name', function() {
        console.log(JSON.stringify(scope.name));
      });
    }
  }
})
