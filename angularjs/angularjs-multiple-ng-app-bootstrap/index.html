“AngularJS Multiple ng-app Instances Per Page Bootstrap Strategies”

A common scenario in legacy or complex web development involves the need to host several independent AngularJS applications within one HTML document. The standard ng-app directive is designed to initialize only one application automatically per document. When you attempt to include multiple elements marked with ng-app, only the first one encountered is bootstrapped automatically. How can developers manage and bootstrap subsequent applications successfully?

This deep dive explores various proven solutions for bootstrapping multiple AngularJS instances, primarily relying on the manual invocation of angular.bootstrap().

The Core Constraint: Single Automatic Bootstrap

The fundamental limitation is that the framework’s automatic discovery mechanism halts after finding the initial ng-app. To overcome this, we must explicitly tell Angular where to start the other applications.

Solution Set 1: Manual Bootstrapping of Separate Modules

The most direct path involves defining distinct modules for each application segment and then manually bootstrapping them using angular.bootstrap(), targeting specific DOM elements.

Example Scenario: Shopping Cart and Names List

Consider two separate functionalities: a shopping cart widget and a simple user name list. Each requires its own isolated scope and controller logic.

We define two modules, shoppingCart and namesList, and then use angular.bootstrap() to attach them to their respective containers (#App1 and #App2). Note that for the first application, while we can define ng-app for context, the explicit bootstrap ensures control.

// Define the Shopping Cart Module
var shoppingCartModule = angular.module("shoppingCart", []);
shoppingCartModule.controller("ShoppingCartController",
  function($scope) {
    $scope.items = [{
      product_name: "Premium Widget",
      price: 50.00
    }, {
      product_name: "Basic Service",
      price: 20.00
    }, {
      product_name: "Exclusive Item",
      price: 180.00
    }];
    $scope.remove = function(index) {
      $scope.items.splice(index, 1);
    }
  }
);

// Define the Names List Module
var namesModule = angular.module("namesList", []);
namesModule.controller("NamesController",
  function($scope) {
    $scope.names = [{
      username: "TechWriter"
    }, {
      username: "ExpertUser"
    }];
  }
);

// Manual Bootstrap for the second application element
// The first app might use ng-app, but we explicitly bootstrap both for consistency
// or just bootstrap the second one if the first uses ng-app="shoppingCart"
angular.bootstrap(document.getElementById("App1"), ['shoppingCart']); // Bootstrapping App 1
angular.bootstrap(document.getElementById("App2"), ['namesList']); // Bootstrapping App 2

The corresponding HTML structure:

<script src="https://ajax.googleapis.com/ajax/libs/angularjs/1.5.3/angular.min.js"></script>

<!-- Application 1: Shopping Cart -->
<div id="App1" ng-controller="ShoppingCartController">
  <h1>Your Order Details</h1>
  <div ng-repeat="item in items">
    <span>{{item.product_name}}</span>
    <span>{{item.price | currency}}</span>
    <button ng-click="remove($index);">Remove Item</button>
  </div>
</div>

<!-- Application 2: Names List -->
<div id="App2" ng-controller="NamesController">
  <h1>User Directory</h1>
  <div ng-repeat="_name in names">
    <p>User: {{_name.username}}</p>
  </div>
</div>

Alternative: Relying on ng-app for One and Bootstrapping Others

If one application is designated as the primary one (using ng-app), it gets initialized automatically. All others require manual bootstrapping targeting their respective root elements:

// Assuming the first element has ng-app="myFirstModule"

// Manually bootstrap the second module targeting its container 'module2'
angular.bootstrap(document.getElementById("module2"), ['mySecondModule']);

This works because only one application can be auto-instantiated. Subsequent manual calls ensure the other DOM sections become active AngularJS scopes.

Solution Set 2: Using angular.element(document).ready()

Timing can sometimes be crucial. If the bootstrapping code executes before the target DOM elements are fully available, initialization might fail. Wrapping the manual bootstrap calls within angular.element(document).ready() guarantees execution only after the DOM is prepared, offering more stability.

angular.element(document).ready(function() {
  // Manually start the application attached to element ID 'app2'
  angular.bootstrap(document.getElementById("app2"), ["app2ModuleIdentifier"]);
});

Solution Set 3: Creating a Root Module to Aggregate Dependencies

Instead of multiple top-level ng-app definitions (which is disallowed for auto-bootstrapping), one can define a single root application element (e.g., on the <body> tag) and make its module depend on all other necessary sub-modules.

If Module A and Module B are needed, create a rootApp that lists them as dependencies:

// Define sub-modules (which won't have ng-app in HTML)
var myApp1 = angular.module('myApp1', []);
myApp1.controller('myCtrl', function($scope) {
  $scope.firstName = 'John';
  $scope.lastName = 'Doe';
});

var myApp2 = angular.module('myApp2', []);
myApp2.controller('namesCtrl', function($scope) {
  $scope.first = 'Jane';
});

// Define the root module depending on both
var rootApp = angular.module('rootApp', ['myApp1', 'myApp2']);

HTML structure:

<script src="...angular.min.js"></script>
<script src="namesController.js"></script> <!-- Where myApp2 is defined -->
<script src="myController.js"></script>     <!-- Where myApp1 is defined -->
<script>var rootApp = angular.module('rootApp', ['myApp1','myApp2'])</script>
<!-- The entire body is managed by rootApp -->
<body ng-app="rootApp">

<div ng-controller="myCtrl">
    Full Name: {{firstName + " " + lastName}}
</div>

<div ng-controller="namesCtrl">
    <p>Name: {{first}}</p>
</div>

</body>

In this approach, only one ng-app="rootApp" is present, resolving the multi-app issue elegantly by dependency injection at the root level.

Solution Set 4: Using a Custom Directive to Invoke Bootstrap

Manually invoking angular.bootstrap() couples your initialization logic directly to the DOM IDs or selectors, making the separation less clean. An alternative suggests creating a custom directive (e.g., ng-module) that internally calls angular.bootstrap().

This approach mimics the declarative nature of ng-app while allowing multiple instances to be specified. The custom directive would look for its attribute value (the module name) and bootstrap the containing element against that module.

For instance, the implementation described references an external script angular.ng-modules.js that provides this ng-module directive functionality:

<!-- Example using the hypothetical ng-module directive -->
<div ng-modules="MyModuleA, MyModuleB">
    <div ng-controller="MyControllerA">
        {{name}}
    </div>
    <div ng-module="MyModuleB"> <!-- Specific element bootstrapped with Module B -->
        <div ng-controller="MyControllerB">
            {{name}}
        </div>
    </div>
</div>

This method abstracts the angular.bootstrap() call into the markup structure.

Solution Set 5: Nested Applications with Dependency Inclusion

It is possible to have a parent application (ng-app) and then manually bootstrap a child application, potentially making the child dependent on the parent’s module. This is useful when modular parts need to share context but must remain independently instantiable.

In one example, a parent module (shoppingCartParentModule) is created, which lists the independent modules (shoppingCart and namesList) as its dependencies:

// Define independent modules first (shoppingCart, namesList)...

// Create the parent module that bundles them
angular.module("shoppingCartParentModule", ["shoppingCart", "namesList"]);

The HTML then uses one top-level ng-app="shoppingCartParentModule" and utilizes controllers from both bundled modules within its scope. Subsequent manual bootstraps can then target elements outside the main scope if needed, referencing their specific modules.

Solution Set 6: Running Multiple Controllers Under One ng-app

If the requirement is not truly for separate AngularJS applications but rather for distinct controllers operating within the same scope hierarchy (sharing the same $scope hierarchy defined by one root ng-app), then simply applying multiple ng-controller directives to sibling or nested elements under one ng-app suffices.

If all controllers belong to the same module, they share scope data:

<div ng-app="mainApp">
    <!-- Controller 1 -->
    <div ng-controller="studentController1">
        <input type="text" ng-model="student.firstName">
    </div>

    <!-- Controller 2 -->
    <div ng-controller="studentController2">
        <input type="text" ng-model="student.firstName"> <!-- This scope is different! -->
    </div>
</div>

Crucially, if controllers are defined at the same level under one ng-app, they operate on separate $scope instances inherited from their respective parent scopes defined by the ng-controller. They are not truly separate applications unless explicitly bootstrapped separately.

Summary of Bootstrapping Techniques

The decision boils down to whether you need true application isolation or merely scope separation:

  1. Pure Isolation: Use angular.bootstrap(element, [moduleNames]) for every application instance beyond the first one discovered via ng-app.
  2. Timing Stability: Wrap manual bootstraps in angular.element(document).ready().
  3. Consolidated Root: Define a single ng-app on a high-level element (like body) and use module dependency injection to combine logic from multiple internal modules.
  4. Declarative Abstraction: Use a custom directive (like ng-module) that wraps angular.bootstrap for cleaner markup.

These methods allow developers to deploy specialized AngularJS features side-by-side on the same page without conflicts, leveraging the framework’s extensibility.

FAQs on AngularJS Multiple Ng App Bootstrap

Q: Why does only the first ng-app work automatically

ANS: The AngularJS framework is configured to automatically bootstrap only the first ng-app directive it finds in the document structure. Subsequent instances are ignored by the auto-initialization process.

Q: How to force bootstrapping of a second application

ANS: You must manually invoke the angular.bootstrap(element, [modules]) function, passing the DOM element corresponding to the second application’s root and an array containing the required module names.

Q: Can I use two ng-app directives in the same HTML file

ANS: You can place multiple ng-app directives, but only the first one will trigger automatic initialization. You must manually bootstrap all others using angular.bootstrap.

Q: What is the benefit of using angularbootstrap over ng-app

ANS: Manual bootstrapping via angular.bootstrap grants precise control over which element initiates an application and which modules it loads, bypassing the single automatic detection limit. However, using ng-app often provides better declarative visibility of scope boundaries.
