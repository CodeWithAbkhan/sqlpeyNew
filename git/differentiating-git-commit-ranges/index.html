“Differentiating Git Log and Diff Commit Ranges: Double Dot ‘..’ vs Triple Dot ‘…’”

The distinction between using two dots (..) and three dots (...) in Git revision selection is a common source of confusion, as their precise behavior shifts depending on whether you are using git log or git diff.

Examining git log with Commit Ranges

When employed with git log, these ranges define sets of commits reachable from the specified revisions.

Double Dot (A..B) in git log

The notation git log A..B yields all commits that are reachable from commit B but not reachable from commit A. It effectively shows the changes introduced uniquely in branch B relative to A.

If you visualize branches A and B in a Venn diagram of their commit histories, this returns the non-overlapping section of B.

Triple Dot (A...B) in git log

The triple-dot notation git log A...B calculates the symmetric difference between the two commit sets. This means it returns all commits that are reachable from either A or B, but not from both (i.e., commits unique to A plus commits unique to B). It filters out the shared commit history.

This is defined formally as commits reachable from A or B but not from their merge base (git merge-base A B).

Visualizing git log Results

Consider a commit structure where A and B are branches diverging from a common ancestor.

  • git log A..B: Shows commits present only in B (the unique additions to B).
  • git log A...B: Shows commits unique to A and commits unique to B.

For enhanced clarity when viewing the symmetric difference with git log, you can use the --left-right option to indicate provenance:

# Show commits unique to 'master' (<) versus those unique to 'origin/master' (>)
git log --oneline --decorate --left-right --graph master...origin/master

This output prefixing is highly valuable:

  • <: Commit belongs only to the left side (e.g., master).
  • >: Commit belongs only to the right side (e.g., origin/master).

Exploring git diff with Commit Ranges

The behavior reverses or changes significantly when these notations are applied to git diff.

Double Dot (A..B) in git diff

In the context of git diff, git diff A..B is largely equivalent to git diff A B. It calculates the difference between the snapshots of commit A and commit B, showing the net changes required to transform the state of A into the state of B.

Triple Dot (A...B) in git diff

This range is designed to show the changes introduced on one branch since it diverged from another. git diff A...B is equivalent to:

git diff $(git merge-base A B) B

It finds the last common ancestor of A and B and then compares that ancestor’s snapshot to the snapshot of B. This effectively shows only the changes present in branch B that were not present in the shared history.

Summary of Mental Models

A simple way to retain the difference, especially noting the swap in diff versus log behavior:

Solutions

git log A..B
git log A...B
$ git log --oneline --decorate --left-right --graph master...origin/master
&lt; 1794bee (HEAD, master) Derp some more

| :

git diff [--options] &lt;commit&gt;...&lt;commit&gt; [--] [&lt;path&gt;...]

      This form is to view the changes on the branch containing and up to
      the second &lt;commit&gt;, starting at a common ancestor of both
      &lt;commit&gt;. "git diff A...B" is equivalent to "git diff
      $(git-merge-base A B) B". You can omit any one of &lt;commit&gt;, which
      has the same effect as using HEAD instead.

| | git log | A..B | Commits in B, excluding those in A. | | git log | A...B | Commits unique to A OR unique to B (symmetric difference). | | git diff | A..B | Diffs the content snapshot of A against B. | | git diff | A...B | Diffs the common ancestor of A and B against B. |
