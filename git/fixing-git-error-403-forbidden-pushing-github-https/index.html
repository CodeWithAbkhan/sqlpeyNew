“Fixing Git Error 403 Forbidden When Pushing to GitHub via HTTPS”

How can one resolve the persistent “The requested URL returned error: 403 Forbidden” when pushing commits to a GitHub repository using HTTPS?

This issue commonly arises from how Git authenticates over HTTPS, especially following changes to GitHub’s security requirements, such as deprecating password authentication in favor of Personal Access Tokens (PATs). Several paths exist to restore push functionality.

Protocol Switching: Moving from HTTPS to SSH

A direct approach favored by some users when HTTPS authentication proves troublesome is transitioning the remote configuration to use the SSH protocol, which relies on key pairs for authentication rather than passwords or tokens.

Mechanism: Modify the remote URL defined for origin within your local repository configuration.

  1. Locate Configuration: Navigate to your repository directory and edit the .git/config file.
  2. Update URL: Find the [remote "origin"] section and locate the url= entry.
  3. Conversion Example: Change the existing HTTPS URL to its SSH equivalent.

If your current HTTPS URL is:

url=https://github.com/derekerdmann/lunch_call.git

Transform it to:

url=ssh://git@github.com/derekerdmann/lunch_call.git

Alternative Command: Instead of manual file editing, the git remote set-url command offers a cleaner method:

git remote set-url origin ssh://git@github.com/derekerdmann/lunch_call.git

This change requires you to have properly configured SSH keys set up with your GitHub account.

Re-establishing HTTPS Authentication Methods

If staying with HTTPS is necessary (e.g., due to network restrictions blocking SSH), the focus shifts entirely to ensuring correct authentication credentials are provided.

1. Using GitHub Personal Access Tokens (PATs)

Since July 2020, GitHub mandates the use of Personal Access Tokens (PATs) instead of traditional passwords for command-line HTTPS operations.

Process:

  1. Generate a new PAT from your GitHub profile settings, ensuring you grant the necessary repo scope (read/write permissions).

  2. Update the remote URL to embed your username, preparing for the token prompt:

    git remote set-url origin https://<YOUR_USERNAME>@github.com/user/repo.git

  3. When git push prompts for a password, enter the PAT you generated, not your regular GitHub login password.

2. Ensuring Username Inclusion in HTTPS URL

In older Git versions, or when credential managers cache improperly, explicitly including the username in the remote URL can force the authentication prompt.

Action: Set the remote URL to include the username directly before the @ symbol.

# Example using the correct HTTPS format with username inclusion
git remote set-url origin https://your_username@github.com/username/repo.git

Another variation suggests prepending the username before the domain:

git remote set-url origin https://<username>@github.com/Path_to_repo.git

3. Handling Stale or Incorrect Credentials Caching

Operating systems (Windows Credential Manager, macOS Keychain Access) often cache Git credentials, which can lead to the 403 error if the cached password or token is invalid or associated with an old account.

  • Windows: Access the Credential Manager via the Control Panel, locate generic credentials related to github.com, and delete the stored entry. Git will then prompt for fresh credentials upon the next push.
  • macOS: Open Keychain Access, search for github.com, and delete the associated “internet password” entry.

Configuration and Permission Checks

Sometimes the issue lies not in the protocol, but in local configuration or repository permissions.

Repository Forking and Collaboration Status

The 403 error strongly suggests a permissions issue. If the repository is not yours:

  • Forking Workflow: Ensure you have properly forked the upstream repository to your own account before cloning and pushing. The error can occur if you try to push directly to a repository where you only have read access. A common fix involves reconfiguring the remote URL to point to your fork:

    git remote -v  # Verify current remote URL
git remote set-url origin https://github.com/YOUR_USERNAME/OTHERREPOSITORY.git

  • Collaborator Status: Verify explicitly that the user account attempting the push has write access. On GitHub, navigate to Settings -> Collaborators for the specific repository and confirm the user has been added and accepted the invitation.

Git Configuration Clean-up

If multiple accounts are configured or existing credential helpers interfere, resetting them might clear the blockage.

# Unset credential helpers globally and locally
git config --global --unset-all credential.helper
git config --unset-all credential.helper

For system-wide cache issues (requires administrator rights):

git config --system --unset-all credential.helper

Updating Git Client

Outdated Git clients might lack the necessary security protocols to communicate effectively with modern GitHub servers over HTTPS. Checking the official documentation often suggests upgrading Git as a remediation step, particularly for very old versions (e.g., Git 1.7.0.4 failing where 1.8.5.2 succeeded).

Utilizing GitHub CLI for Modern Authentication

For a structured approach, especially on macOS or Linux systems where Homebrew is available, leveraging the official GitHub CLI (gh) can simplify the HTTPS authentication flow by automating the browser-based login sequence.

brew install gh
gh auth login

During gh auth login, select HTTPS as the preferred protocol. This process generates tokens and configures Git securely without manual URL editing or credential deletion.

FAQs on Fixing Git Error 403 Forbidden Pushing GitHub HTTPS

Q: What does the 403 Forbidden error mean in Git push operations

ANS: The 403 Forbidden error signifies that the server (GitHub) successfully received your request but explicitly denies authorization to perform the requested action, usually due to incorrect authentication credentials or lack of write permissions for that repository.

Q: Should I use my password or a token when prompted by HTTPS push

ANS: You should use a Personal Access Token (PAT) generated from your GitHub settings, as standard passwords are no longer accepted for command-line Git operations over HTTPS since 2020.

Q: How do I switch from HTTPS remote URL to SSH remote URL

ANS: Use the command git remote set-url origin ssh://git@github.com/user/repo.git or manually edit the url entry in the .git/config file under the [remote "origin"] section.

Q: Where are Windows Git credentials stored for GitHub

ANS: Windows stores cached Git credentials in the Credential Manager under Windows Credentials as generic items associated with GitHub.

Q: What if I have permission but still get the 403 error

ANS: If permissions are confirmed, the issue is likely stale credentials cached by your OS or an incorrect local configuration. Try clearing the cached credentials or verifying your global Git user settings (user.name and user.email).
