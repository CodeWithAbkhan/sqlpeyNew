“Effective Git Commands to List Files in a Specific Commit”

When working with version control, retrieving a precise list of files modified, added, or deleted within a specific Git commit is a frequent requirement, especially for scripting or automated analysis. How can one extract only the filenames associated with a commit hash, and what are the distinctions between the various available Git commands for this task?

This exploration details several proven methods to achieve this, focusing on scriptability, output cleanliness, and utility.

Preferred Methods for Scriptable File Extraction

For programmatic use, commands that behave like “plumbing” tools are generally favored over “porcelain” commands designed for human interaction.

Method 1: Leveraging git diff-tree (Plumbing Approach)

The git diff-tree command is highly suitable for scripting as it offers fine-grained control over output.

Extracting only filenames:

# Example using commit hash bd61ad98
git diff-tree --no-commit-id --name-only bd61ad98 -r

Output Example:

index.html
javascript/application.js
javascript/ie6.js

Key Options Explained:

  • --no-commit-id: Prevents outputting the commit ID, ensuring cleaner data.
  • --name-only: Displays only the names of the files changed. If you require status information (Added, Modified, Deleted), substitute this with --name-status.
  • -r: Recursively inspects changes within sub-trees.

Alternative (Porcelain Approach - Less preferred for strict scripting): While git show provides similar data, its default output includes extra metadata, requiring further processing:

git show --pretty="" --name-only bd61ad98

The --pretty="" argument strips the commit header cruft.

Method 2: Listing Files within a Commit or Tree Structure

If the goal is strictly to list the contents of a tree object (a commit), different commands apply:

To get the list of files present in the tree pointed to by a commit (<commit-ish>):

git ls-tree --name-only -r <commit-ish>

To see the files that were actually changed relative to its parent(s) within that commit structure:

git diff-tree --no-commit-id --name-only -r <commit-ish>

Generating Diff Information Between Commits

When comparing two points in history (START_COMMIT and END_COMMIT), git diff is often the clearest tool.

Listing only file names between two commits:

git diff --name-only START_COMMIT..END_COMMIT

Listing file names along with their modification status (A, M, D):

git diff --name-status START_COMMIT..END_COMMIT

A method using git show that achieves similar results, often requiring sorting and deduplication if used across multiple commits:

git show --pretty="format:" --name-only START_COMMIT..END_COMMIT | sort | uniq

For changes relative to the preceding commit:

git diff HEAD~1 --name-only

Utilizing git show for Detailed or Summary Views

The git show command is versatile for inspecting a single commit (<sha>).

To get a summary including insertion/deletion counts:

git show --stat <SHA1>

To get file names and modification statistics:

git show --stat --name-only <SHA1>

If you prefer a compact, one-line summary that also includes the file status (M/A/D):

git show --name-status --oneline <commit-hash>

Advanced Techniques and Aliases

Customizing Output with Aliases

Creating a Git alias can simplify frequently used complex commands. This alias, named changed, executes the plumbing command for file listing:

git config --global alias.changed 'show --pretty="format:" --name-only'

Usage Examples:

  • Last commit: git changed HEAD
  • Specific commit: git changed bAda55
  • Range: git changed bAda55..ff0021

Inspecting Log History with File Details

If you need to step through commits sequentially while viewing affected files, git log is appropriate.

To list commit messages and affected files for the last 3 commits:

git log -n3 --name-only

For an all-in-one view showing commit ID, message, and status of files:

git log --name-status

Handling Merge Commits

To accurately list files changed in a merge commit, use the -m flag to treat each merge change as a separate diff:

# List names only for a merge commit
git log -m -1 --name-only --pretty="format:"

Viewing the Tree Directly

A distinct approach is to reference the commit hash followed by a colon (:), which instructs Git to display the contents of that specific tree object, effectively showing the state after the commit.

# Shows the state of the entire repository tree at that commit
git show 9d3a52c474:

FAQs on Git List Changed Files

Q: What is the best command to script file listings from a commit

ANS: The command git diff-tree --no-commit-id --name-only <commit-hash> -r is highly recommended as it is a low-level plumbing command designed for clean, programmatic output.

Q: How do I show file status (Added Modified Deleted) alongside names for a commit

ANS: Use --name-status instead of --name-only. For instance: git diff-tree --no-commit-id --name-status <commit-hash> -r or git show --name-status --oneline <commit-hash>.

Q: Can I list all files present in a commit regardless of parent changes

ANS: Yes, use git ls-tree --name-only --full-tree <commit-hash> to list every file tracked in the tree object of that commit.

Q: How to see files changed between the two most recent commits

ANS: You can use the relative reference HEAD~1 to represent the parent of HEAD. Execute: git diff --name-only HEAD^ HEAD.
