“Fixing Git ‘Permission Denied (publickey)’ When Pushing to GitHub”

Troubleshooting SSH Authentication Failures with Git

The core issue typically stems from GitHub not recognizing the local SSH key offered by your Git client. Here is a compilation of proven resolutions.

1. Verify and Associate Your SSH Public Key

GitHub relies on matching a public key you provide with one registered on your account.

  • Check for Existing Public Key: First, confirm the presence of your public key file in your home directory’s .ssh folder. For standard RSA keys on Linux/macOS, the command is:

    cat ~/.ssh/id_rsa.pub

    If this fails, inspect the ~/.ssh/ directory for any files ending with .pub.

  • Register Key with GitHub: Copy the entire output (the public key string) from the command above. Navigate to your GitHub settings: Profile Photo -> Settings -> SSH and GPG keys -> New SSH key (or Add SSH key), paste the key content, and provide a descriptive title.

2. Activate and Add Keys to the SSH Agent

Even if keys exist, the ssh-agent must be running and aware of them.

  • Start the Agent: Initialize the SSH agent if it’s not running:

    eval `ssh-agent -s`

  • Load the Key: Explicitly add your private key to the running agent. Replace id_rsa with your specific key filename if necessary (e.g., id_ed25519.pub for the corresponding public key).

    # Example using default private key name
ssh-add ~/.ssh/id_rsa 

# Alternative example if you use ed25519 key
ssh-add ~/.ssh/id_ed25519

    Alternative for macOS Sierra/later: If you are on macOS and have set a passphrase, use ssh-add -K to store the passphrase in the keychain.

3. Explicitly Configure Key Usage with an SSH Config File

If you manage multiple SSH keys (e.g., one for GitHub, one for an enterprise Git server), Git might be trying the wrong key first. You must create or edit the ~/.ssh/config file to specify which key to use for github.com.

Create or modify the file with content similar to this:

Host github.com 
    IdentityFile ~/.ssh/github_rsa

This explicitly tells the system to use github_rsa (the private key corresponding to the public key uploaded to GitHub) when connecting to github.com.

4. Review and Correct the Remote Repository URL

The error can sometimes mask an issue where the remote URL is incorrect or configured for HTTPS when you intended to use SSH (or vice-versa).

  • Check Current Remotes: See what URL Git is currently using:

    git remote -v

    For SSH, the URL should look like git@github.com:YourUsername/YourRepo.git.

  • Switch to HTTPS (Alternative to SSH): If dealing with SSH complexities is undesirable, switching to HTTPS is GitHub’s recommended approach. Use the HTTPS URL found on the repository page.

    # Replace the existing SSH remote URL with the HTTPS one
git remote set-url origin https://github.com/YourUsername/YourRepo.git

# Push using the new URL
git push -u origin master

  • Resetting the Remote URL (if corrupted): If the origin is completely broken, remove and re-add it:

    git remote rm origin
git remote -v # Verify removal
git remote add origin git@github.com:YOUR-GIT/YOUR-REPO.git

5. Addressing User Context and Permissions

Authentication issues can sometimes arise from who is executing the Git command.

  • Avoid sudo for Git Operations: Running sudo git push origin master often causes Git to look for SSH keys in the root user’s home directory (/home/root/.ssh/), not yours. If you must use sudo, use the -E flag to preserve your environment variables, including the correct $HOME path:

    sudo -E git clone git@your_repo

  • Check File Permissions: Ensure your private key file has restricted permissions. Incorrect permissions can cause the SSH client to refuse to use the key.

    chmod 600 ~/.ssh/id_rsa
chmod 644 ~/.ssh/id_rsa.pub

  • Root User Key Generation (If running system services): In some specific setups (e.g., older Linux systems or specific daemon configurations), Git might execute under the root user. If so, you might need to generate keys within the root user’s context:

    sudo su
ssh-keygen -t rsa -C "[email protected]"
# Follow prompts, then copy the public key shown via 'cat ~/.ssh/id_rsa.pub'

6. Key Naming Conventions

GitHub documentation suggests that if you don’t explicitly point to a key in the config file, it expects specific default names. If you generated a custom name like ar-2022-ssh, Git might ignore it unless configured. Standard successful names include id_rsa.pub, id_ecdsa.pub, or id_ed25519.pub. Rename your key pair if needed and repeat Step 2.

7. Configuration Helper for HTTPS Authentication

If you opt for the HTTPS URL method (Solution 4) but are frequently prompted for credentials, you can configure Git to store them temporarily:

git config --global --add credential.helper store

This will save your username and password after the next successful push, preventing repeated prompts (though using Personal Access Tokens is the modern, more secure approach instead of passwords).

FAQs on Fixing Git Permission Denied Publickey Github

Q: Why am I getting Permission Denied publickey when using SSH

ANS: This means the SSH client on your machine failed to present a valid public key that GitHub recognizes and has associated with your account settings. Verify key generation, agent loading, and key registration on GitHub.

Q: How do I check which SSH key Git is currently offering

ANS: Run ssh-add -l in your terminal. This lists the fingerprints of the keys currently loaded into your running SSH agent. Verify this fingerprint matches a key registered on your GitHub profile.

Q: Should I use SSH or HTTPS URL for GitHub access

ANS: GitHub generally recommends using the HTTPS URL as it simplifies setup for most users, utilizing passwords or Personal Access Tokens. SSH is preferred by developers who rely heavily on SSH keys for other services or who need passwordless authentication via key pairs.

Q: What if I generated a new SSH key and it still doesn't work

ANS: Ensure you have added the new public key content to your GitHub SSH keys settings, started the ssh-agent, and used ssh-add to load the corresponding private key into the agent.
