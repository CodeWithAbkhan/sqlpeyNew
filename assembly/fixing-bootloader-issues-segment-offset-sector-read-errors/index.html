“Fixing Bootloader Issues: Segment Offset and Sector Read Errors”

When developing bootloaders, particularly in 16-bit x86 assembly, several subtle issues can prevent your code from executing correctly. Two common hurdles involve how the kernel is loaded into memory (segment:offset) and the correct parameters for reading sectors from disk using BIOS interrupt INT 13h.

The Segment:Offset Conundrum

A fundamental aspect of 16-bit memory addressing is the segment:offset pair. Memory is accessed using a 20-bit physical address, derived from a 16-bit segment register and a 16-bit offset. The formula is Physical Address = (Segment * 16) + Offset. In assembly, multiplying a segment by 16 is equivalent to a left bit shift by 4 (segment << 4).

Consider this problematic code snippet:

mov bx, 0x7E00  ; Load 7E00h into BX
mov es, bx      ; Set ES to 0x7E00
xor bx, bx      ; Clear BX, making it 0x0000

Here, the intention is likely to load the kernel to the memory address 0x0000:0x7E00. However, the code sets ES to 0x7E00 and BX to 0x0000. This results in a physical address calculation of (0x7E00 << 4) + 0x0000, which equals 0x7E000. The correct physical address for a typical bootloader loaded by the BIOS is 0x7C00, meaning the segment CS should be 0x07C0 and the offset IP should be 0x0000. If the goal is to load into 0x7E00 physical address, then ES should be 0x07E0 and BX (as offset) should be 0x0000.

Corrected Approach for Segment Setup:

To ensure proper memory segment and stack initialization, the following pattern is recommended early in your bootloader:

; Set up Data Segment (DS) and Extra Segment (ES)
xor ax, ax      ; Clear AX to 0
mov ds, ax      ; Set DS to segment 0
mov es, ax      ; Set ES to segment 0 (or another desired segment)

; Set up Stack Segment (SS) and Stack Pointer (SP)
mov bx, 0x8000  ; Choose a safe segment for the stack
cli             ; Disable interrupts to prevent race conditions
mov ss, bx      ; Set SS to the chosen stack segment
mov sp, ax      ; Set SP to 0 (stack grows downwards from 0xFFFF)
sti             ; Re-enable interrupts

cld             ; Set Direction Flag for string operations (forward)

This setup initializes DS and ES to segment 0, and establishes a stack in a known memory region, preventing conflicts with the BIOS or your own code. For more on 16-bit memory management, exploring resources on x86 real mode memory addressing can be beneficial.

Precision in Sector Reading with INT 13h

Another common pitfall lies in correctly invoking the BIOS disk services via INT 13h. Specifically, the parameters for reading sectors need careful attention.

Consider this code block:

mov ah, 0x02  ; Function: Read sectors
mov al, 0x01  ; Number of sectors to read
mov ch, 0x00  ; Track number
mov cl, 0x02  ; Sector number
mov dh, 0x00  ; Head number
int 0x13

The issue here is with mov cl, 0x02. The CL register specifies the starting sector number. Sectors are typically numbered starting from 1, not 0. If you intend to read the second sector of a track, then CL should indeed be 0x02. However, if the first data sector (after the boot sector itself) is intended, and assuming the boot sector is sector 1, then the next sector is sector 2. If the intention was to read only one sector, and that sector is the first one on the track, then CL should be 0x01. The original code aims to read the second sector, which is correct if that’s the target.

Corrected INT 13h Usage (Example for Sector 2):

To read a single sector (sector 2) from drive 0, head 0, track 0 into the buffer at ES:BX:

mov ah, 0x02      ; Function: Read Sectors from Drive
mov al, 0x01      ; Number of sectors to read (1)
mov ch, 0x00      ; Track number (0)
mov cl, 0x02      ; Sector number (2)
mov dh, 0x00      ; Head number (0)
; ES:BX should point to the buffer where data will be read
int 0x13          ; Call BIOS disk service

Important Considerations for Bootloaders:

  • Initial Register State: When the BIOS transfers control to your bootloader at 0x7C00, you cannot assume the state of segment registers (CS, DS, ES, SS) or the stack pointer (SP). You must explicitly set them. The boot drive number is guaranteed to be in DL.

  • Stack Management: The BIOS might use a default stack in the first megabyte of RAM. It’s best practice to set up your own stack in a known, safe memory region using SS and SP, as demonstrated above.

  • Direction Flag: For string instructions like MOVSB, LODSB, etc., the Direction Flag (DF) dictates whether the source/destination index registers (SI/DI) increment or decrement. Use CLD (clear direction flag) to ensure forward movement, which is typical when loading data.

  • Jumping to the Kernel: When transferring control to a loaded kernel, a FAR JMP is crucial. This ensures that both the Code Segment (CS) and Instruction Pointer (IP) are correctly set for the kernel’s entry point.

    NASM Syntax:

    jmp 0x07E0:0x0000 ; Example: Jump to segment 0x07E0, offset 0x0000

    Manual Encoding for Assemblers Without Direct Far Jmp Support:

    db 0x0EA     ; Far Jump Opcode
dw 0x0000    ; New IP (Offset)
dw 0x07E0    ; New CS (Segment)

    GNU Assembler:

    ljmpw $0x07E0,$0x0000

  • Processor-Specific Features: Avoid using 32-bit registers (EAX, EBX, etc.) if your bootloader targets older processors like the 8086/8088, which lack them. Similarly, FS and GS segment registers are specific to the 80386 and later. Stick to 16-bit registers and instructions for broader compatibility.

  • USB Boot with FDD Emulation: If booting from USB media using floppy disk emulation, you might need a BIOS Parameter Block (BPB) in your boot sector. Refer to resources detailing the BPB structure for compatibility.
