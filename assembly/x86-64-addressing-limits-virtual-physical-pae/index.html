“x86-64 Addressing Limits: Virtual vs. Physical Space via PAE”

When operating systems run in 64-bit mode on modern CPUs, the mechanism used to translate virtual addresses to physical addresses is heavily influenced by the Physical Address Extension (PAE). This feature, initially designed to expand the addressable memory space beyond the 4GB barrier for 32-bit systems, introduces a multi-level table structure essential for handling the vast 64-bit address space. Why, then, are we currently restricted in our visible virtual address space?

The Role of PAE and Multi-Level Paging

The transition to 64-bit addressing necessitates extensive metadata for address translation. If we strictly used 4KiB pages across the entire theoretical 64-bit space ($2^{64}$ bytes), the required translation tables would be prohibitively large.

PAE addresses this through a sparse approach utilizing several levels of indexing tables. For the AMD64 architecture, this implementation typically involves four levels of tables.

Address Division Structure

The virtual address space division dictates the depth of the paging structure. Each level in the hierarchy uses a 9-bit index to point to the next table level. Starting from bit 12 (the offset within a page), the indices map out as follows:

  • Level 1 Index: Bits 12 through 20 (9 bits)
  • Level 2 Index: Bits 21 through 29 (9 bits)
  • Level 3 Index: Bits 30 through 38 (9 bits)
  • Level 4 Index: Bits 39 through 47 (9 bits)

This precise segmentation results in the current practical limit of 48 bits for the virtual address space observable at the instruction level when using this PAE structure. It is vital to note that the instruction level, dealing with logical addresses before segmentation translation, retains full 64-bit address support, as does the segmentation stage itself (translating logical to linear addresses). The constraint surfaces directly from the PAE paging implementation.

A common observation posits that AMD may have moved quickly to market with their 64-bit implementation, adapting and extending PAE with an extra level of indirection, leading to this 48-bit restriction. Both Intel and AMD architectures retain room for growth, potentially supporting 52-bit virtual addresses in the future by adding more table levels.

Physical Address Limitations and Page Table Entries

While the virtual address space is limited to 48 bits in this current scheme, the maximum supported physical address space is capped at 52 bits by both manufacturers. What dictates this physical limit, and why is a full 64/64 bit translation seemingly unavailable with the existing Instruction Set Architecture (ISA)?

Evolution of Page Table Entries (PTEs)

In older 32-bit systems, Page Table Entries (PTEs) were 32 bits wide, directly facilitating 32-bit virtual-to-physical translation. Unused low bits were marked as “Ignored” or “Available” for OS use.

When PAE introduced 36-bit physical addressing, the logical expansion was to double the size of the PTEs to 64 bits. This provided ample space for flags and the increased physical address bits. However, this space has been gradually utilized by newer features:

  1. Protection Keys: A relatively recent addition requiring bits within the entry.
  2. XD/NX Bit (Execute Disable/No Execute): A critical security feature occupying space.

The current format of 64-bit PAE PTEs shows that a full 64-bit physical address translation is not feasible without altering the fundamental layout, even if huge pages offer localized workarounds. The fact that high bits in PTEs were not reserved strongly suggests that hardware architects anticipated a future ISA evolution rather than extending the current paging mechanism indefinitely.

The Tradeoff: Reserved vs. Ignored Bits

The constraint on physical addressing is also tied to the reserved/ignored bits within the PTEs.

  • Ignored Bits: Bits the OS can utilize for its own bookkeeping, potentially speeding up OS operations if custom data is stored there.
  • Reserved Bits: Bits that must be set to zero by the OS, reserved for future hardware expansion of physical address space.

If fewer bits are ignored, the OS has less custom space. If fewer bits are reserved, the hardware must redesign the PTE format sooner when the physical address limit is reached.

Intel’s introduction of 5-level paging increases the virtual address space to $2^{57}$ bits (up to 57 bits is possible, with documentation suggesting a projection up to 52 bits for physical addresses with this structure). Their documentation indicates that processors supporting 5-level paging enumerate a maximum physical address size up to 52 bits, suggesting they also do not plan to immediately change the page table format beyond that.

AMD’s architecture manual currently supports up to 40-bit addresses (1 Terabyte physical space) in their current mode but confirms the mechanism can be extended to support 52-bit physical addresses.

The consensus leans toward pragmatic engineering: the current paging structure is strained, and approaching the 52-bit limit will likely coincide with a significant hardware revision in memory management, making over-engineering the existing strained format unnecessary.

FAQs on x86-64 Addressing Limits Virtual Physical Space PAE

Q: Why is the virtual address space limited to 48 bits in standard x86-64 operation

ANS: This limitation stems from the current implementation of Physical Address Extension (PAE) paging, which divides the address into four levels, each indexed by 9 bits (plus the page offset), resulting in a maximum addressable range of $2^{48}$ bytes.

Q: What is the maximum physical address space currently supported or planned for x86-64

ANS: Both Intel and AMD have set a hard limit of 52 bits for the physical address space supported by extensions to the current paging mechanisms, although current deployed processors often support less (e.g., 40 bits for AMD in some modes).

Q: Can the OS utilize unused bits in 64-bit Page Table Entries

ANS: Yes, some lower bits in 64-bit PTEs are marked as “Ignored” by the CPU specification, which the Operating System is permitted to use for its own data storage purposes, trading this space for fewer reserved bits.

Q: How does 5-level paging affect addressing limits

ANS: Intel’s 5-level paging increases the potential virtual address space significantly, with documentation suggesting physical address enumeration may reach up to 52 bits under this newer structure.
