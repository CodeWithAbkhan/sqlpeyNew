How can I efficiently convert strings to integers and integers back to strings using assembly language, focusing on common x86 architectures and performance?

When working with low-level programming and assembly language, the conversion between string representations of numbers and their integer equivalents is a frequent task. This process requires careful handling of character encoding and arithmetic operations to ensure correctness and efficiency. Let’s delve into how this can be achieved, examining different approaches and optimizations.

Solution 1: Basic String and Integer Conversion Routines

This solution provides fundamental routines for converting ASCII decimal strings to integers and integers back to ASCII decimal strings.

String to Integer Conversion (string_to_int)

This function takes a pointer to a null-terminated string and its length, returning the integer value.

; Input:
; ESI = pointer to the string to convert
; ECX = number of digits in the string (must be > 0)
; Output:
; EAX = integer value
string_to_int:
  xor ebx, ebx    ; Clear EBX for accumulating the integer value
.next_digit:
  movzx eax, byte [esi] ; Load the current character into EAX (zero-extended)
  inc esi               ; Move to the next character in the string
  sub al, '0'           ; Convert the ASCII digit to its numerical value
  imul ebx, 10          ; Multiply the current accumulated value by 10
  add ebx, eax          ; Add the current digit's value to the accumulated total
  loop .next_digit      ; Decrement ECX and loop if ECX is not zero
  mov eax, ebx          ; Move the final integer value to EAX for return
  ret
Integer to String Conversion (int_to_string)

This function converts an integer value back into a null-terminated ASCII string.

; Input:
; EAX = integer value to convert
; ESI = pointer to a buffer to store the string (must have room for at least 10 bytes)
; Output:
; EAX = pointer to the first character of the generated string
int_to_string:
  add esi, 9            ; Move to the end of the buffer to store characters in reverse
  mov byte [esi], STRING_TERMINATOR ; Place the null terminator at the end

  mov ebx, 10           ; Set the divisor to 10 for decimal conversion
.next_digit:
  xor edx, edx          ; Clear EDX before division (EDX:EAX / EBX)
  div ebx               ; Divide EAX by 10. Quotient in EAX, Remainder in EDX
  add dl, '0'           ; Convert the remainder (digit) to its ASCII representation
  dec esi               ; Move the buffer pointer backward
  mov [esi], dl         ; Store the ASCII digit in the buffer
  test eax, eax         ; Check if the quotient (EAX) is zero
  jnz .next_digit       ; If not zero, continue dividing
  mov eax, esi          ; Set EAX to the start of the generated string
  ret
STRING_TERMINATOR equ 0 ; Define the null terminator character
Example Usage
; String to integer example
lea esi, [thestring]  ; Load address of "1234"
mov ecx, 4            ; Specify string length as 4
call string_to_int    ; EAX will now contain the integer 1234

; Integer to string example
lea esi, [buffer]     ; Load address of the buffer
call int_to_string    ; EAX will contain a pointer to the generated string "1234"
                      ; which can be used with system calls like sys_write.

thestring: db "1234", 0  ; The string to convert
buffer: resb 10          ; Buffer to hold the converted string

Important Considerations:

  • These routines lack robust error checking, such as validating if input characters are actual digits (‘0’-‘9’).
  • They do not handle signed numbers. Enhancements for these features would require additional logic.

Solution 2: Optimized String to Integer Conversion with Error Handling

This approach focuses on optimizing the string-to-integer conversion, incorporating better handling of non-digit characters and utilizing more efficient instructions.

Optimized base10string_to_int

This function converts a null-terminated or non-digit-terminated ASCII decimal string to an unsigned integer. It advances the pointer to the first non-digit character.

; args: pointer in RDI to ASCII decimal digits, terminated by a non-digit
; clobbers: RCX (used internally for temporary digit storage)
; returns: EAX = atoi(RDI)  (base 10 unsigned)
;          RDI = pointer to first non-digit
global base10string_to_int
base10string_to_int:

     movzx   eax, byte [rdi]    ; Load the first character into EAX (zero-extended)
     sub     eax, '0'           ; Convert ASCII digit to numerical value
     cmp     al, 9              ; Check if it's a valid decimal digit [0-9]
     jbe     .loop_entry        ; If it's a valid digit, proceed to the loop entry

     ; If the first character is not a digit, return 0 and the original pointer
     xor     eax, eax           ; Zero out EAX for a return value of 0
     ret

  .next_digit:                  ; Start of the conversion loop
     lea     eax, [rax*4 + rax]    ; total = total * 5 (equivalent to total * 10 / 2)
     lea     eax, [rax*2 + rcx]    ; total = (total * 5) * 2 + digit (effectively total * 10 + digit)
     ; The above LEA instructions are a common optimization for multiplication by powers of 2 and addition.
     ; It's a way to achieve `imul eax, 10` and `add eax, ecx` with potentially lower latency.

  .loop_entry:
     inc     rdi                ; Move to the next character in the string
     movzx   ecx, byte [rdi]    ; Load the next character into ECX (zero-extended)
     sub     ecx, '0'           ; Convert ASCII digit to numerical value
     cmp     ecx, 9             ; Check if the character is a valid decimal digit
     jbe     .next_digit        ; If valid, continue the loop; otherwise, exit

     ret                        ; Return with the converted integer in EAX and the updated RDI pointer
Key Optimizations and Design Choices in Solution 2:
  • Loop Peeling and Rotation: The first iteration is often “peeled” (handled separately) to simplify the loop structure, placing the conditional branch at the bottom. This allows for a cleaner do-while loop equivalent and can optimize the initial state.
  • Efficient Multiplication: The use of LEA instructions (e.g., lea eax, [rax*4 + rax]) is a common technique for performing multiplications by powers of two and additions efficiently, often offering lower latency than direct IMUL instructions on certain architectures. [rax*4 + rax] is equivalent to rax * 5. Then [rax*2 + rcx] is (rax*5)*2 + rcx, which results in rax*10 + rcx.
  • Early Exit on Non-Digits: The conversion stops at the first character that is not a valid decimal digit (‘0’-‘9’). This behavior aligns with standard atoi functions in languages like C and helps prevent unexpected behavior with malformed strings.
  • Register Usage (x86-64 ABI): The example uses x86-64 registers (RDI for the first argument, EAX for the return value), adhering to the System V Application Binary Interface for Linux/macOS. For 32-bit x86, register names would need adjustment (e.g., EDI, EAX).
  • Partial Register Stalls: The code aims to minimize potential partial register stalls by using movzx for zero-extension and being mindful of byte-register operations. For example, sub al, '0' is often fine on modern CPUs as reading a byte register does not typically cause stalls if handled correctly.
  • SIMD for High-Performance Scenarios: For scenarios involving very large numbers or requiring extreme performance, Single Instruction, Multiple Data (SIMD) instructions like SSSE3’s pmaddubsw and SSE2’s pmaddwd can be employed for parallel digit processing. However, for typical short numbers, a scalar loop is often more efficient. Alternative Strategies and Further Enhancements

  • Handling Signed Numbers: To support signed integers, you would need to check for a leading ‘-’ or ‘+’ character and adjust the final result accordingly.
  • Error Reporting: For more robust error handling, you could return an error code or set a flag when invalid input is encountered, rather than just returning a partial result.
  • Explicit Length Strings: If you are processing strings with a known length rather than null-terminated ones, you would use a counter in your loop instead of checking for a terminator character.
  • Arbitrary-Length Numbers: For extremely large numbers that exceed native register sizes, you would need to implement multi-precision arithmetic routines, potentially breaking the conversion into smaller chunks. Explore resources like “Conversion of huge decimal numbers (128bit) formatted as ASCII to binary (hex)” for guidance.
  • AT&T Syntax: The provided examples use Intel syntax. If you are working with AT&T syntax (common with the GNU Assembler), the operand order and register prefixes (% for registers, $ for immediate values) would differ. For an example of AT&T syntax, see “Convert from ascii to integer in AT&T Assembly”.

The choice between different assembly implementations depends on your specific requirements for performance, error handling, and the types of inputs you anticipate. For general-purpose use, the optimized scalar routines offer a good balance.

FAQs on Assembly String Integer Conversion

Q: How do I handle signed numbers when converting strings to integers in assembly

ANS: To handle signed numbers, you would typically check for a leading ‘-’ or ‘+’ character at the beginning of the string. If a ‘-’ is found, you would perform the conversion as usual and then negate the final integer result. If a ‘+’ is found, you can simply ignore it.

Q: What is the difference between Intel and AT&T assembly syntax for these conversions

ANS: The primary differences lie in operand order (source, destination in AT&T; destination, source in Intel) and the use of prefixes for registers (e.g., %eax in AT&T vs. eax in Intel) and immediate values (e.g., $10 in AT&T vs. 10 in Intel). The underlying logic for the conversion remains the same.

Q: Can I use system calls for string-to-integer conversion in assembly

ANS: Standard system calls are generally for I/O operations like reading from files or writing to the console, not for direct string-to-integer conversion. You would implement the conversion logic yourself in assembly or call a library function if available.

Q: What are the performance implications of using LEA for multiplication in assembly

ANS: On many x86 processors, LEA instructions can offer lower latency for simple multiplications and additions compared to dedicated IMUL instructions, especially when combined. This is because LEA is designed for address calculation and can often perform these operations in a single cycle.

Q: How do I convert an integer to a string in assembly without a fixed buffer size

ANS: To avoid a fixed buffer size, you would need to first determine the number of digits in the integer. This can be done by repeatedly dividing the integer by 10 until it becomes zero, counting the number of divisions. Then, allocate or use a buffer of that determined size before performing the integer-to-string conversion.
