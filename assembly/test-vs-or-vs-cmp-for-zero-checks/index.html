“Optimal x86 Assembly: TEST Reg,Reg vs. OR Reg,Reg vs. CMP Reg,0 for Zero Checks”

When performing zero checks in x86 assembly, you might encounter different instructions like TEST reg, reg, OR reg, reg, and CMP reg, 0. Do these choices significantly impact performance, and what are the nuances of each? Let’s dive into the technical details to understand which method is most effective.

The primary question is whether there’s a discernible performance difference when comparing a register against zero using these distinct instructions.

TEST reg, reg - The Favored Approach

For comparing a register with zero, TEST reg, reg emerges as a highly efficient option. It correctly sets the processor’s FLAGS register in the same manner as CMP reg, 0. Crucially, it often results in smaller code size and can be at least as fast, if not faster, than other methods.

Benefits of TEST reg, reg:

  • Flag Setting: Identical FLAGS results to CMP reg, 0 for Zero Flag (ZF), Sign Flag (SF), and Parity Flag (PF). It also consistently sets CF and OF to 0, mirroring CMP reg, 0’s behavior when subtracting zero.
  • Code Size: Generally smaller than CMP reg, 0, except for the specific CMP AL, imm8 case.
  • Macro-Fusion: A significant advantage is its ability to macro-fuse with conditional jump instructions (like JL, JG, etc.) into a single micro-operation (uop) on modern x86 CPUs (Intel Core 2 and later). This improves instruction throughput, allowing for up to 5 instructions per cycle instead of 4.
  • UOP Cache Density: The absence of an immediate value can potentially aid UOP cache density by leaving space for other instructions if needed (seen in Sandy Bridge family CPUs).
  • No Register Rewriting Latency: Unlike OR reg, reg, TEST reg, reg does not add latency to the dependency chain for subsequent instructions that need to read the register. It only produces a FLAGS result, which is typically handled efficiently by the processor’s register renaming and out-of-order execution mechanisms.

Example:

    xor eax, eax      ; Initialize EAX to zero
    ; ... some operations that might change EAX ...

    test eax, eax     ; Check if EAX is zero
    jz zero_found     ; Jump if EAX is zero

zero_found:
    ; Continue execution

A Note on cmp reg, 0: While functionally similar, CMP reg, 0 is often slightly larger in code size. It can also prevent macro-fusion in certain scenarios where TEST can fuse, especially with signed conditional branches like JS on some older processors. However, for simple zero checks, the difference is often negligible unless you’re operating on very constrained code size or targeting older architectures.

OR reg, reg - The Less Optimal Choice

Using OR reg, reg to check for zero is generally discouraged due to performance implications.

Drawbacks of OR reg, reg:

  • Register Rewriting Latency: This instruction writes the register back to itself. This introduces an extra cycle of latency in the dependency chain for instructions that need to read the register’s value subsequently. This means if another instruction depends on the value of reg after OR reg, reg, it might stall.
  • No Macro-Fusion: Unlike TEST or CMP, OR reg, reg does not macro-fuse with conditional branches on most modern CPUs. AMD CPUs specifically do not merge OR with JCC.
  • Partial Register Issues (P6 Family): On older P6 family CPUs (pre-Sandy Bridge), using OR AL, AL (for the low 8 bits of EAX) could cause partial-register stalls if EAX was read later, as AL was renamed separately from EAX. TEST AL, AL avoided this.

Historical Context: The OR reg, reg idiom might stem from older architectures like the 8080, which lacked a dedicated TEST instruction, making ORA A (Or Accumulator) a common way to set flags. This habit may have carried over into 8086 assembly and persisted without a thorough performance evaluation on modern hardware.

Example (Illustrative of the less optimal way):

    mov ebx, 10       ; Some value
    ; ... operations ...

    or ebx, ebx       ; Sets flags, but adds latency and no macro-fusion benefit
    jz is_zero

is_zero:
    ; ...

CMP reg, 0 - A Solid Alternative

CMP reg, 0 is a reliable method for zero checks. It sets the flags correctly and is well-understood.

Considerations for CMP reg, 0:

  • Code Size: Slightly larger than TEST reg, reg in most cases.
  • Macro-Fusion: While it macro-fuses with many conditional branches, TEST reg, reg can sometimes fuse in scenarios where CMP cannot (e.g., with JS on certain older CPUs).
  • Memory Operands: When comparing against a value in memory, CMP [mem], 0 might not macro-fuse on Intel CPUs if it includes an immediate and a memory operand. In such cases, loading into a register first (MOV reg, [mem]) and then using TEST reg, reg can be more efficient.

Example:

    mov rcx, 5
    ; ... operations ...

    cmp rcx, 0        ; Compare RCX with 0
    je is_zero_cmp    ; Jump if equal

is_zero_cmp:
    ; Continue execution

Handling Values in Memory

When the value to be checked resides in memory, the approach can differ:

  • CMP dword [mem], 0: This works, but Intel CPUs often do not macro-fuse flag-setting instructions with both an immediate and a memory operand.
  • MOV reg, [mem] then TEST reg, reg: This typically results in 2 front-end uops and can fuse in the back-end. It’s often preferred over CMP [mem], 0 when the value isn’t used later, balancing code size and efficiency.
  • Addressing Modes: Be mindful of addressing modes. For instance, RIP-relative addressing combined with an immediate can prevent micro-fusion in the decoders. Indexed addressing modes can also un-laminate after the uop cache.

Example for memory comparison:

section .data
    my_value dd 0  ; DWORD variable initialized to 0

section .text
    ; ...

    mov eax, [my_value] ; Load the value from memory into EAX
    test eax, eax       ; Test EAX
    jz value_is_zero

value_is_zero:
    ; ...
