**.NET Core Code Coverage Options: A Comparative Overview**

As a developer working with .NET Core, you’re likely looking for reliable code coverage tools to ensure your application is thoroughly tested and maintainable. In this article, we’ll provide an in-depth comparison of popular code coverage options for .NET (and C# specifically), focusing on their features, pricing, and compatibility with .NET Core.

**NCover**

* Supports statement coverage and branch coverage * $480 for “NCover 3 Complete” (older beta versions available for free) * Compatible with .NET Framework, but not specifically designed for .NET Core

**Visual Studio (2008 Pro) | (2005 Team System (Development, Test or Team Suite Editions))**

* Fully integrated into Visual Studio * At least $5,469 (a significant investment)

**PartCover and OpenCover**

* PartCover: No longer under development (moved to OpenCover) * Open source * Supports statement coverage

**OpenCover (successor to PartCover)**

* Open source * Supports branch and statement coverage * 32 and 64-bit support * Silverlight support * Tutorial on The Code Project by the primary developer * No .NET Core support yet

**SD Test Coverage**

* Works with 32 and 64 bits, full C# 4.0 * Handles both small and very large code bases * $250 for single user license

**JetBrains dotCover**

* $100 for Personal License (free for user groups, open source projects, students, and teachers) * Supports statement coverage * Silverlight support

**NCrunch**

* $159 for personal license ($289 for commercial seat license) * Code coverage indicators in Visual Studio * Continuous (near real-time) testing * Visual per-test code coverage * Performance metrics, parallel multi-core test execution

**NDepend**

* $410 for developer license * Can import coverage data from NCover, DotCover, and Visual Studio 2017; 2015, 2013, 2012, 2010, and 2008 Code Coverage files. * Dependency graph * Dependency structure matrix * Visualizing code metrics * Validating code rules

**Conclusion**

While each of these options has its strengths and weaknesses, it’s essential to consider your project’s specific requirements, budget, and .NET Core compatibility. By weighing the pros and cons of each tool, you’ll be better equipped to choose the best code coverage solution for your .NET Core development needs.

**Method 1**

* I use the version of NCover that comes with TestDriven.NET. It allows me to easily right-click on my unit test class library and hit “Test With→Coverage,” pulling up a report.

Method 2

An alternative to NCover can be PartCover , is an open source code coverage tool for .NET very similar to NCover, it includes a console application, a GUI coverage browser, and XSL transforms for use in CruiseControl.NET .

It is a very interesting product.

OpenCover has replaced PartCover.

Method 3

JetBrains (of ReSharper fame) has been working on a coverage tool for a little while called dotCover . It’s showing a great deal of promise.

Method 4

I just tested out NCrunch and have to say I am very impressed. It is a continuous testing tool that will add code coverage to your code in Visual Studio at almost real time. At the time as I write this NCrunch is free. It is a little unclear if it going to be free, cost money or be opened source in the future though.

Method 5

TestCocoon is also pretty nice. It is in active development and has a user community:

  • Open source (GPL 3)
  • Supports C/C++/C# cross platform (Linux, Windows, and Mac)
  • CoverageScanner - Instrumentation during the Generation
  • CoverageBrowser - View, Analysis and Management of Code Coverage Result

However, TestCocoon is no longer developed and its creators are now producing a commercial software for C/C++.

Method 6

There are pre-release (beta) versions of NCover available for free . They work fine for most cases, especially when combined with NCoverExplorer.

Method 7
